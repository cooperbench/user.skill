[AGENT]: Yes, **variants are stored permanently, not just CDN-cached**. Here's how it works: **ActiveStorage Variant Storage:** 1. **`active_storage_variant_records` table** - Tracks which variants have been generated (stores `blob_id` + `variation_digest`) 2. **Actual variant files** - Stored in the same storage backend as originals (Disk in dev, S3/GCS/etc. in production) When a variant is requested: 1. Check if `VariantRecord` exists for that blob + transformation combo 2. If yes → serve the already-generated file from storage 3. If no → generate it with libvips, store it, create the `VariantRecord`, then serve So each unique variant (e.g., `logo.png` at `thumbnail` size) gets: - A new blob stored in your storage provider - A record in `active_storage_variant_records` linking it to the original **The implication:** If someone requests `/media/hero.jpg?size=800x600` and `/media/hero.jpg?size=799x599`, that's two separate stored files. Custom dimension variants could accumulate storage if users request many arbitrary sizes. The predefined variants (`thumbnail`, `small`, `medium`, `large`, `xlarge`) limit this somewhat, but the `WxH` custom format is open-ended.
