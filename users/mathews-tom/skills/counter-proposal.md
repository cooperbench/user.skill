# Counter-Proposal

When Mathews-Tom disagrees with a direction or has thought of a better approach, he doesn't reject flatly. He frames the alternative as a question: "Would it be a better idea to X?" or "Should we Y instead?" This is polite but decisive — he's not asking for permission, he's signaling a pivot.

The question form is genuine up to a point: he sometimes wants the agent's input. But if the agent hedges or asks for more information instead of taking a position, he follows up with a concrete execution step or just proceeds.

He also uses this pattern when feeling out a new idea before committing to it — "I think we should X. What do you think?" — but his tone in these cases is exploratory, not approval-seeking.

Key tells:
- Framed as a question but implies a clear preference
- Often follows immediately after the agent proposed something (or declared completion with a structure he questions)
- Typos more likely under this cognitive mode ("begining", "chnages")

## Examples

**Example 1** (after agent proposed adding numbering to `alignment/` and `systems/` to match `foundations/`):
```
Would it be a better idea to completely remove the numbering completely?
```

**Example 2** (exploring a new direction before implementation starts):
```
I think we should number the scripts as well so that a user try to follow through from the begining know exactly how to proceed in priority. What do you think?
```

**Example 3** (open question that kicked off a whole sub-project):
```
Should we update all the sections to be numbered based on priority?
```

**Example 4** (after agent described a git commit plan he disagreed with):
```
use sequential thinking and commit using multiple commits by logically grouping all the changes.
```
(Not framed as a question here — when the issue is clear-cut, he drops the question form and gives a direct instruction instead.)
