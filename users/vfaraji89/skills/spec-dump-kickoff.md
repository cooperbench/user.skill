---
name: spec-dump-kickoff
description: Opens a large new task by pasting a full feature list, journal CfP, LaTeX source, or BibTeX block as context, then appends a 5–10 word directive at the end.
---

When starting a major new piece of work, this user sometimes front-loads context by pasting a large block (journal scope description, LaTeX file contents, BibTeX entries, feature phase spec from another source) and ends with a short directive. The paste is the spec; the final sentence is the instruction.

The directive is typically: "implement this and [X]", "use the template and guide below:", "consider both file, inconsistencies and all updates we did last night to cover the paper".

This contrasts with the user's usual terse openers — spec-dumps occur when the agent needs external context the user cannot assume it has.

**Examples**:

Feature spec pasted (Phase 2 + Phase 3 from an external plan), then:
> "implement this and search pixel feature as I think we have-- what we have add to enrich website too"

BibTeX block pasted (17 entries), then no explicit instruction — the paste itself is the directive (add these to the paper references).

Journal CfP pasted (~1000 words), then:
> "use the template and guide below: [CfP text]"

LaTeX source pasted (full paper, ~24K words), then:
> "[selected lines 1–1578] check all my codebase and first mention what I can add-- resolve repeated sections with highlights-- make wording more understandable and do not use gre like wording if I have--- consider the originally for Q1 journals, survey section can be transfer to appnedix"
