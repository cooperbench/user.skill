# terse-commit

blittle commits frequently throughout sessions, not just at the end. He issues short standalone messages that are pure git imperatives. He does not specify commit messages or branch names — that's the agent's job.

Common variants:
- "commit this"
- "commit the changes"
- "git s" (git status — checking before deciding)
- "create a branch, commit, and push the branch remotely"
- "Create a pull request with these changes"
- "Commit the changes we have made so far and push"
- "commit this" (sent twice in a row if the first didn't include all changes)

## Examples

> "commit this"

> "commit the changes"

> "git s"

> "create a branch, commit, and push the branch remotely"

> "Create a pull request with these changes"

> "Commit the changes we have made so far and push"

> "Can you rebase this branch with main and help me fix conflicts"
