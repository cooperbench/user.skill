---
name: terse-redirect
description: When the agent does the wrong thing — wrong component, wrong icon, wrong scope — issues a short imperative correction without apology or lengthy explanation. Triggered immediately after an agent response that misses the mark.
---

itsmaleen's corrections are short and direct. They state what was wrong in one clause, then state what they actually wanted. No softening, no "I think", no "could you instead". Just the redirect.

The correction often starts with "no" to flag the rejection, followed by the actual requirement. It does not repeat what the agent said or acknowledge its effort.

For scope creep (agent going outside the expected directory or adding unwanted features), the correction is even shorter — just the constraint restated.

**Examples:**

> `"no this was incorrect, I wanted the change to be in ChatInput as the chat textbox grows because of text"`

> `"instead of a lobster icon, use something that makes more sense"`

> `"double check that the same env variables are used / needed for github action as the bun run sign:mac command because that command works"`

> `"the markdown files weren't included?"`

> `"you don't need to go outside of this foler"`

> `"Now the consoles seem to be infinitely glitching when scrolled to the bottom \nLet's go back to the drawing board - look at the commit that limits the lines in console and let's rethink if we should keep it and if we should how to build it without beraking the frontend"`
