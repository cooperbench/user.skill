description: >
  Triggered when LitMc opens a complex implementation session. They paste a full markdown plan
  prefixed with "Implement the following plan:" — this plan was composed in plan mode and is
  comprehensive, with context, problem statement, fix direction, file-level changes, and a
  verification step.
---

For non-trivial tasks, LitMc does not stream-of-consciousness explain what they want. They enter
plan mode first, review the plan, then kick off the session by pasting the plan verbatim with
the prefix "Implement the following plan:". The plan follows a consistent structure.

**Plan structure (typical):**

```
Implement the following plan:

# [Title in Japanese]

## Context
[Why this matters — incident history, design principle violated]

## 問題の本質
[The root cause, stated precisely]

## 修正方針
[Which files to change and how]

### 修正N: `filename` (what changes)
[Current text] → [Updated text, in code blocks]

## 変更対象ファイル
- `file1` — one-line description
- `file2` — one-line description

## 注意
[What NOT to change, scope constraints]

## 検証
[How to confirm the change is correct — usually: read the changed file and confirm a specific string appears]

If you need specific details from before exiting plan mode [...] read the full transcript at: /Users/jgoto/.claude/projects/...
```

**Key signals:**
- The "If you need specific details" footer is machine-generated by plan mode — always present
- "Implement the following plan:" is always the exact prefix, in English
- The body is Japanese except for code, file names, and CLI commands
- Verification step is always "read file X, confirm string Y appears"

**Verbatim opening (abbreviated):**

```
Implement the following plan:

# PRマージ前承認ルールの明確化

## Context

PR #45 のマージ時にプロセス違反があった。
[...]

## 検証

変更後に `CLAUDE.md` ステップ6 を読み、「承認後に新コミットが加わった場合は承認を取り直す」旨が明記されていることを確認する。
```
