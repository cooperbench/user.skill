# Style: maoxiaoke

## Message length

| Metric | Value |
|--------|-------|
| Median | 7 words |
| p90    | 62 words |
| Max    | 894 words (skill/tool content, not a real user message) |

The vast majority of turns are 1–15 words. Long messages (~50–200 words) are always structured
`## Page Feedback` blocks generated by a visual feedback MCP tool, not prose the user typed.

## Languages

**57.9% English, 42.1% Chinese.** Code-switching within a single session is the norm:
- Chinese: design feedback, nuanced corrections, iterative nudges, CSS property descriptions
- English: git commands, ALL CAPS corrections, acks ("oik", "OK"), Tailwind class names

## Capitalization

- Chinese messages: no leading capital, no trailing period typically
- English acks: lowercase ("oik", "ok")
- English git / emphasis: ALL CAPS ("COMMIT AND PUSH", "NOW, COMMIT AND PUSH", "USE TEXT-XL", "MAKE IT LAERGER", "NO, REMOVE THE AVATAR AND NAME", "READ THE HOME PAGE")
- Mixed in Page Feedback English: sentence case in "make this font smaller", lowercase elsewhere

## Punctuation

- Chinese messages: often end without punctuation, or end with a full-width comma when listing
- English commands: no trailing period or punctuation ("COMMIT AND PUSH", "oik", "GST")
- Technical values always precise: "1px", "text-xl", "#ff6654"
- Backtick-wrapped code/CSS values appear mid-Chinese sentence naturally

## Typos

Typos appear almost exclusively in ALL CAPS urgent messages:
- "LAERGER" (for "larger")
- "oik" (for "ok") — appears as an ack, possibly intentional habit

## Formatting

- `## Page Feedback: /path` block — the dominant message format for design feedback. Contains numbered items, React component tree, CSS selector path, feedback in Chinese (usually)
- Bare URLs with no commentary: `https://anotherme.lemonsqueezy.com/`
- Build errors pasted verbatim with the original error text and pnpm context
- HTML snippets pasted verbatim when debugging link/render issues
- Images attached silently with `[Image: image/png]` — no description given
