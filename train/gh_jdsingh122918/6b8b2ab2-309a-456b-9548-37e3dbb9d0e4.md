## Section 4: WAL Mode, Busy Timeout, and Connection Health **WAL mode** — set once after database creation: ```sql PRAGMA journal_mode=WAL; ``` With the libsql embedded replica, WAL is already the default (replicas use WAL internally). For local-only mode, we set it explicitly at init. **Busy timeout** — prevents `SQLITE_BUSY` errors under contention: ```sql PRAGMA busy_timeout=5000; ``` **Foreign keys** — keep the existing pragma: ```sql PRAGMA foreign_keys=ON; ``` All three PRAGMAs run in a single `init_pragmas()` function called immediately after `Database::build()`, before migrations. **Health check on startup:** ```sql PRAGMA integrity_check; ``` Log a warning if it returns anything other than `"ok"`. Don't fail — a degraded database is better than refusing to start. **Sync interval for embedded replicas:** Default to 60 seconds with `sync_interval(Duration::from_secs(60))` on the builder. ## Section 5: Event Batching Improvements **Current problem:** Up to 49 events lost on crash. Batch flushes only on count threshold (50), using `lock_sync()`. **New design:** Time-based + count-based flushing with a dedicated async task: ```rust // Dedicated flush task using tokio::select! loop { tokio::select! { Some(event) = rx.recv() => { buffer.push(event); if buffer.len() >= 25 { // reduced from 50 flush(&db, &mut buffer).await; } } _ = tokio::time::sleep(Duration::from_secs(2)) => { if !buffer.is_empty() { flush(&db, &mut buffer).await; } } } } ``` **Key changes:** - Batch size reduced from 50 → 25 (worst-case loss halved) - 2-second interval flush catches stragglers - No more `lock_sync()` — uses async `db.execute()` directly since libsql is async-native - Events sent via `tokio::mpsc::channel` (already the likely pattern, just formalized) - Flush on channel close (graceful shutdown drains the buffer) This keeps throughput high while limiting data loss to at most 2 seconds of events.
