what does these two lines mean? export EXPO_PUBLIC_API_BASE_URL="http://10.0.2.2:8080" # Android emulator → host laptop export EXPO_PUBLIC_SITE_ID="site-dev"

> AGENT

Those two lines are setting environment variables that the app reads at build time (via `process.env.EXPO_PUBLIC_*` in `src/config.ts`). **`EXPO_PUBLIC_API_BASE_URL="http://10.0.2.2:8080"`** Tells the app where to POST receipts and product registrations. - `10.0.2.2` is a magic IP that the **Android emulator** maps to your laptop's `localhost`. From inside the emulator, `127.0.0.1` would mean the emulator itself, not your machine — so Google reserved `10.0.2.2` to mean "the host computer running the emulator." - `:8080` is the port your backend (`office-ops-engine`) listens on. Change it if your server runs on a different port. For other setups you'd use a different value: | Where the app runs | What to set | |---|---| | Android emulator → backend on your laptop | `http://10.0.2.2:8080` | | iOS simulator → backend on your laptop | `http://localhost:8080` | | Physical phone (Expo Go) on same Wi-Fi | `http://192.168.X.Y:8080` (your laptop's LAN IP — find via `ipconfig getifaddr en0`) | | Deployed staging server | `https://api-staging.example.com` | **`EXPO_PUBLIC_SITE_ID="site-dev"`** Identifies which physical site this device belongs to (e.g. a specific office, warehouse, gate). The app sends it as the `X-Site-Id` header so the server knows which site's orders/products to scope to. `site-dev` is just a placeholder for local development — in production each device would be provisioned with the real site id. **Why the `EXPO_PUBLIC_` prefix?** Expo only inlines env vars into the JS bundle if they start with `EXPO_PUBLIC_`. Anything without that prefix is treated as server-side / secret and won't reach the device. That's also a warning: never put real secrets (API keys, tokens) in `EXPO_PUBLIC_*` — they ship in the APK. **If you skip them**, `src/config.ts` falls back to `http://10.0.2.2:8080` and `site-dev` defaults, so the app still runs — sync attempts will just fail (visible in the Sync queue screen) until a backend is reachable.
