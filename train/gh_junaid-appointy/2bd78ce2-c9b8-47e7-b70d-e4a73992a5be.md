should I not use --legacy peer deps, is it not needed?

> AGENT

Short answer: **don't use it on this project.** It's the thing that produced the broken lock file in the first place. What it actually does: - npm 7+ default: when a package declares a required peer dep, npm tries to install it automatically and *fails the install if peers can't be satisfied*. - `--legacy-peer-deps`: reverts to npm 6 behavior — npm ignores peer deps entirely. Install "succeeds" but the lock file never records the peer in the tree. That second behavior is exactly what bit you: `react-native-worklets`' required peer `@react-native/metro-config` got silently skipped, the lock file looked fine locally, then `npm ci` on EAS (which does strict consistency checking) rejected it. When the flag *is* legitimately useful: a transitive peer-dep conflict you genuinely cannot resolve (e.g. two libraries demanding incompatible React versions and you've decided the mismatch is safe). Even then, the cleaner move is to pin an `overrides` entry in `package.json` or add the peer explicitly — both are recorded in the lock file, so EAS stays happy. Rule of thumb for this repo: **plain `npm install`**. If it errors on peer deps, fix the conflict (pin the peer, bump a library, add an override) rather than reaching for the flag.
