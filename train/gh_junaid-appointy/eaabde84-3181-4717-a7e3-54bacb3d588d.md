# auxilio-extension

Google **Chrome extension (MV3)** for Auxilio (Office Ops) — the **desktop** surface for registering office visitors directly inside Google Calendar. It is the richer counterpart to the `auxilio-workspace` Calendar add-on: where the add-on is mobile-capable but lives under the CardService "card ceiling," the extension gives a full React UI (realtime guest updates, per-guest invite toggle, template preview, inline edits, intentional auto-nudge).

> Read the umbrella `../CLAUDE.md` for the four constraints and UX rules — they apply here.
> Strategy + approval analysis: `../Planning-docs/2026-06-18_calendar_visitor_chrome_extension_decision.md`.
> Build plan: the approved plan that scaffolded this repo.

## What this is (and isn't)

- **Is:** an MV3 extension (WXT + React 19 + TS) that injects a trigger into Google Calendar (web) and renders the registration flow in the **side panel**. A **channel surface / dumb adapter** — it forwards intent to `office-ops-engine`.
- **Isn't:** a place for business logic. Dedup, draft curation, invite/pass issuance, and lifecycle all live in `office-ops-engine`'s visitor plugin. This repo renders UI and calls the engine.
- **Isn't:** mobile. Extensions are desktop-Chrome only. The `auxilio-workspace` add-on remains the mobile surface. Both key off the same **magic address**.

## Architecture — three MV3 surfaces

- **`entrypoints/background.ts`** (service worker) — the only holder of tokens + network. Mints/caches the Google `id_token` (engine auth) + `access_token` (Calendar read), runs the Calendar API client and the engine `/addon/*` client, keeps per-tab event context, routes messages.
- **`entrypoints/calendar.content.ts`** (content script @ `calendar.google.com`) — a **dumb trigger/observer**: detect open event, decode `eid`, inject the "Register a visitor" button (Phase 1) and the magic-address banner (Phase 2). No tokens, no business logic.
- **`entrypoints/sidepanel/`** (the app) — React + TanStack Query UI. Pure presentation + server state.

```
content script ──msg──> background ──HTTPS(id_token)──> office-ops-engine /api/visitor/calendar/addon/*
side panel    ──msg──> background ──Calendar API(access_token)──> canonical iCalUID + attendees
```

## Hard rules

1. **Calendar-only scopes. Never add Gmail/Drive.** Calendar is *sensitive* (verification, no paid audit). Gmail/Drive are *restricted* → annual CASA assessment. Hard line, same as the add-on.
2. **Engine owns the contract.** The extension calls the existing `/api/visitor/calendar/addon/{draft,preview,send,cancel-guest}` routes (ID-token authed). Do **not** add engine signature/scope changes from here. The only engine-side change is env: add this extension's OAuth client id to `AUXILIO_WORKSPACE_OAUTH_CLIENT_ID` (audience allow-list).
3. **Background is the only secret/network holder.** Content script stays a dumb trigger; side panel stays presentation. Keep the thin-adapter boundary.
4. **Send the canonical `iCalUID`** (from the Calendar API `events.get`, not synthesized) so the extension path converges on the same `calendar_event_links` row as `.ics`/OAuth/add-on.
5. **Design: Material 3 tokens, not its code.** Our own `design/tokens.ts` + `global.css` (primary `#92288E`). No MUI/Tailwind/paper. **Icons: lucide-react only**, no Unicode glyphs/emoji in chrome.
6. **Animations subtle, only where needed** — CSS transitions driven by motion tokens; respect `prefers-reduced-motion`.
7. **Internal-first.** Force-installed/unlisted to our Workspace → no OAuth verification yet. Public/commercial = a later packaging + verification exercise (CWS review + OAuth verification), per the decision doc.

## The mechanism

The "Visitor events needing passes" list is **not** read live from the open event. It comes entirely from a background sync cache:

403	/**
404	 * Button UI manager: injects a native-styled "Manage Visitors" button as a real,
405	 * full-width row in the surface — below the Availability/Visibility section on the
406	 * edit page, at the bottom of the outermost content list in the detail popover (so
407	 * it scrolls with the rest of the UI, never an overlay) — and falls back to a
408	 * floating button only when no anchor is found. `update(show)` decides per render.
409	 */
410	function createButtonUI(onClick: () => void) {
411	  const fab = mountFloating(onClick);
412	  let injected: HTMLElement | null = null;
413	  let retryTimer: ReturnType<typeof setTimeout> | undefined;
414	
415	  // A clean injection anchor: where to drop the button + how far to indent it so
416	  // it lines up with the section's content column (past Google's icon gutter).
417	  // `inline` = sit next to a native button instead of as its own row.
418	  type Anchor = { insert: (el: HTMLElement) => void; inset: number; inline?: boolean };
419	
420	  /** Text/ARIA-based only — never CSS classes — so we stay decoupled from
421	   *  Google's obfuscated markup. Places the button where it reads as part of the
422	   *  form: between Description and the next section on the edit page, and as the
423	   *  last row of the detail popover's content list. Floating only as last resort. */
424	  function findAnchor(): Anchor | null {
425	    // Full-screen edit page → our own row just BELOW the Availability/Visibility
426	    // info section (falling back to above Description).
427	    if (/\/eventedit/.test(location.pathname)) {
428	      const avail = findAvailabilityInfo();
429	      const afterAvail = avail ? rowsListFor(avail) : null;
430	      if (afterAvail) {
431	        const { list, row } = afterAvail;
432	        return { insert: (el) => list.insertBefore(el, row.nextSibling), inset: rowInset(row, list) };
433	      }
434	      const desc = findEditDescription();
435	      const aboveDesc = desc ? rowsListFor(desc) : null;
436	      if (aboveDesc) {
437	        const { list, row } = aboveDesc;
438	        return { insert: (el) => list.insertBefore(el, row), inset: rowInset(row, list) };
439	      }
440	      // Fallback within the edit page: inline, right before the native "Save".
441	      const save = findButtonByText('save');
442	      const parent = save?.parentElement;
443	      if (save && parent) return { insert: (el) => parent.insertBefore(el, save), inset: 0, inline: true };
444	      return null;
445	    }
446	    // Detail popover / modal → BOTTOM of the OUTERMOST content list (after every
447	    // section, including the guest list). Robust whether or not guests exist.
448	    const dialog = document.querySelector<HTMLElement>('[role="dialog"]');
449	    if (dialog) {
450	      const list = findContentList(dialog);
451	      if (list) {
452	        const ref = firstIconLedRow(list);
453	        return { insert: (el) => list.appendChild(el), inset: ref ? rowInset(ref, list) : 0 };
454	      }
455	      // Fallback → bottom of the scrolling content.
456	      const scope = scrollContainer(dialog) ?? dialog;
457	      const l = mainVerticalList(scope) ?? scope;
458	      return { insert: (el) => l.appendChild(el), inset: 0 };
459	    }
460	    return null;
461	  }

463	  function ensureInjected(): boolean {
464	    if (injected && injected.isConnected) return true; // still placed — skip the scan
465	    const anchor = findAnchor();
466	    if (!anchor) return false;
467	    removeInjected();
468	    ensureInjectedStyles();
469	    injected = anchor.inline
470	      ? buildInlineButton(onClick)
471	      : buildInjectedRow(onClick, anchor.inset);
472	    anchor.insert(injected);
473	    return true;
474	  }

476	  function removeInjected() {
477	    injected?.remove();
478	    injected = null;
479	  }
480	
481	  return {
482	    // `allowFab` gates the floating fallback. It's only there to surface the
483	    // panel when we can't inject a native button; with the panel already open
484	    // it's redundant (auto-follow handles the viewed event), and it would flash
485	    // at the corner while a navigated page is still loading. So callers pass
486	    // false when the panel is open.
487	    update(show: boolean, allowFab = true) {
488	      clearTimeout(retryTimer);
489	      if (!show) {
490	        removeInjected();
491	        fab.setVisible(false);
492	        return;
493	      }
494	      // Try to inject now; if the anchor isn't in the DOM / laid out yet (Google
495	      // is still rendering the surface), keep retrying for a few seconds. The
496	      // MutationObserver covers DOM changes, but layout can settle — giving
497	      // elements their width — without a childList mutation, so width-based
498	      // anchor checks can miss that window. This retry guarantees we don't.
499	      let attempts = 0;
500	      const attempt = () => {
501	        const placed = ensureInjected();
502	        // Show the floating fallback only after a short grace period, so on a
503	        // normally-rendering surface the native button just appears — no flash
504	        // of the FAB getting replaced a moment later.
505	        fab.setVisible(allowFab && !placed && attempts >= 3);
506	        if (placed || attempts++ >= 30) return;
507	        retryTimer = setTimeout(attempt, 150);
508	      };
509	      attempt();
510	    },
511	  };
512	}

564	/** The OUTERMOST rows list inside `root`: the shallowest container whose own
565	 *  children include several icon-led section rows. Breadth-first so a nested
566	 *  guest list never wins over the main content list. */
567	function findContentList(root: HTMLElement): HTMLElement | null {
568	  const queue: HTMLElement[] = [];
569	  for (const c of root.children) if (c instanceof HTMLElement) queue.push(c);
570	  while (queue.length) {
571	    const el = queue.shift()!;
572	    if (!isVisible(el)) continue;
573	    if (iconLedRowCount(el) >= 2) return el;
574	    for (const c of el.children) if (c instanceof HTMLElement) queue.push(c);
575	  }
576	  return null;
577	}

591	/** Does this element stack its visible children vertically (a column of rows),
592	 *  rather than laying them out side by side? Geometry, not CSS classes. */
593	function stacksVertically(el: HTMLElement): boolean {
594	  const kids = [...el.children].filter((c): c is HTMLElement => c instanceof HTMLElement && isVisible(c));
595	  if (kids.length < 2) return false;
596	  for (let i = 1; i < kids.length; i++) {
597	    const a = kids[i - 1].getBoundingClientRect();
598	    const b = kids[i].getBoundingClientRect();
599	    if (b.top >= a.bottom - 2) return true; // the next child starts below the previous
600	  }
601	  return false;
602	}

618	 *  Rows must span most of the container's width, which excludes narrow icon
619	 *  clusters like a description formatting toolbar. */

621	  const cw = container.getBoundingClientRect().width;
622	  let n = 0;
623	  for (const c of container.children) {
624	    if (!(c instanceof HTMLElement) || !isVisible(c) || !looksLikeRow(c)) continue;
625	    if (cw > 0 && c.getBoundingClientRect().width < cw * 0.5) continue; // skip toolbars/chips

631	/** From a field/label, climb to the rows list that holds it: the first ancestor
632	 *  whose parent contains several icon-led rows. Returns that list plus the row
633	 *  (a direct child of the list) that contains `el` — so we can insert relative
634	 *  to it. Null if no rows list is recognised. */
635	function rowsListFor(el: HTMLElement): { list: HTMLElement; row: HTMLElement } | null {
636	  let node: HTMLElement = el;
637	  while (node.parentElement && node.parentElement !== document.body) {
638	    const parent = node.parentElement;
639	    if (iconLedRowCount(parent) >= 2) return { list: parent, row: node };
640	    node = parent;
641	  }
642	  return null;
643	}

645	/** The biggest vertically-stacking container inside `root` — the content column
646	 *  whose last child is the visual bottom of the surface. */
647	function mainVerticalList(root: HTMLElement): HTMLElement | null {
648	  let best: HTMLElement | null = null;
649	  let bestArea = 0;
650	  for (const el of root.querySelectorAll<HTMLElement>('*')) {
651	    if (!isVisible(el) || !stacksVertically(el)) continue;
652	    const r = el.getBoundingClientRect();
653	    const area = r.width * r.height;
654	    if (area > bestArea) {
655	      bestArea = area;
656	      best = el;
657	    }
658	  }
659	  return best;

670	/** Left edge of the first painted text inside `el` (skips the decorative icon
671	 *  gutter), or the element's own left if it has none. */
672	function firstTextLeft(el: HTMLElement): number {
673	  const walker = document.createTreeWalker(el, NodeFilter.SHOW_TEXT);
674	  let node: Node | null;
675	  while ((node = walker.nextNode())) {
676	    if (!node.textContent || !node.textContent.trim()) continue;
677	    const range = document.createRange();

553	function formatWhen(start: string, end?: string): string {
554	  const allDay = !start.includes('T');
555	  const s = new Date(start);
556	  const date = s.toLocaleDateString(undefined, { weekday: 'short', day: 'numeric', month: 'short' });
557	  if (allDay) return `${date} · All day`;
558	  const t = (d: Date) => d.toLocaleTimeString(undefined, { hour: 'numeric', minute: '2-digit' });
559	  return end ? `${date} · ${t(s)} to ${t(new Date(end))}` : `${date} · ${t(s)}`;

Google's **incremental** sync only ever returns events that **changed since the token was issued**. Each successful sync advances (consumes) the token. So this sequence permanently hides an event:

1. The event's create/modify delta was consumed by some earlier sync.

## Root cause (confirmed by your log)

`mode: "incremental"`, `itemsReturned: 0`, `markedTotal: 0` told the whole story:

- Google's **incremental** sync only returns events that changed **since the stored token**, and each successful sync **consumes/advances** that token.
- Your event's create/modify delta was consumed by an earlier sync — almost certainly back when an earlier build used a **different magic address** (`.env` = `findajx@gmail.com` vs the example default `visitors@auxilio.app`), so `isMarked` returned false at that moment.
- The token advanced past it. From then on, incremental sync returns `0 items` and the event is **never re-evaluated**, even though the address now matches. `events.get` still works, which is why the panel loads it and only the optimistic DOM nudge fires.

The old code only ever did a full re-scan on a `410` token expiry, which can take a very long time — so the miss was effectively permanent.

## The fix (v0.6.1)

**Self-healing full re-scan** (`calendar-sync.ts`, `background.ts`):
- On every **install/reload/update**, the sync token is cleared (`clearSyncToken` in `onInstalled`) → next sync re-scans the whole forward window. This is what makes a config change like the magic address actually take effect.
- **Periodically** (every 12h) the token is dropped and the window re-scanned, so production drift self-heals without a reload.
- A full re-scan **rebuilds** the marked set from scratch (stale events drop out) but computes "genuinely new" against the *previous* set — so it does **not** fire a notification storm for events you already knew about.

Plus the earlier fixes still in this build:
- **Nameless nudge** → popover title now read from the dialog heading.
- **Sync race** → `runSync` coalesced to one in-flight call.
- **List won't blank** on a transient sync error (serves cached set).
- **Button affordance** kept when the panel is open.
