Honest answer on all three. ## SSE — CPU and 100-user scale **Idle CPU cost is negligible.** SSE = each client holds a long-lived HTTP/1.1 connection. On Bun/Node, an idle connection is one file descriptor in `epoll`/`kqueue`, one TLS session, and a few small JS objects. For 100 connections: - ~10-50 MB RAM total - <1% CPU at rest - ~100 file descriptors This is *nothing*. A single Bun/Node process can hold ~10k idle SSE connections comfortably. 100 is two orders of magnitude under that. **The actual cost is the fan-out on writes.** When a receipt/dispense/correction is inserted, the server needs to push an event to every connected device on that site. Per push: ~200 bytes of JSON, sub-millisecond CPU. Realistic load for you: roughly 200 writes/hour across 100 guards → 20,000 pushes/hour → ~5.5 pushes/second across all connections. Trivial. Peak burst (a delivery being received, 50 scans in 2 minutes): without debouncing, 50 × 100 = 5000 pushes in 2 min.
