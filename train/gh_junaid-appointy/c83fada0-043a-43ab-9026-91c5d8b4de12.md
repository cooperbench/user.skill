how easy would it be to create a build of this app for ios and give it to people to use it?

> AGENT

Technically pretty easy — the stack (Expo SDK 54, vision-camera, expo-sqlite, expo-haptics, expo-network) is all cross-platform, and EAS builds iOS the same way it builds Android (`eas build --profile development --platform ios`). You'd likely just need to add an iOS bundle identifier + camera usage string to `app.json` and you're off. The real friction is **Apple's distribution model**, not the code: - **Apple Developer Program**: $99/year, required before you can sign anything. - **Getting the build onto phones**, pick one: - **TestFlight** — easiest for "give it to people". Up to 10k external testers, but each build expires every 90 days and the first external release needs a (light) Apple review. Internal testers (up to 100) skip review. - **Ad Hoc** — no review, but you must collect every tester's UDID and re-sign, capped at 100 devices/year. Painful past a handful of people. - **Enterprise ($299/yr)** — needs a real D-U-N-S-registered company and Apple's approval; Apple polices misuse heavily. Not worth it for this scale. Practically: TestFlight is the path. Maybe a day of setup (Apple account + App Store Connect app record + bundle ID + first EAS iOS build), then `eas submit` pushes builds to TestFlight and testers install via the TestFlight app with an email invite. One caveat worth flagging given the CLAUDE.md constraints — staff devices are mid/low-end Android, so iOS is presumably for a different audience (stakeholders, management?). Worth confirming who actually needs it before paying the $99 and taking on the 90-day rebuild cadence.
