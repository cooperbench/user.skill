what is worklets core used for?

> AGENT

**`react-native-worklets-core`** is a standalone library by the vision-camera author (mrousavy) that lets you run JS functions on a separate native thread — used primarily for real-time, per-frame processing.

**Where it's used in vision-camera specifically:**

- **Frame Processors** — JS functions marked `'worklet'` that run on every camera frame (e.g. 30/60 fps) on a dedicated thread, not the JS thread. Used for things like:
  - Real-time face detection
  - Object detection / ML inference per frame
  - Custom barcode parsers that work on raw pixel data
  - Color analysis, motion detection, AR overlays

**Why a separate thread?** A frame processor runs ~30 times per second. If it ran on the JS thread it would freeze your UI. Worklets-core spins up a parallel JS runtime so frame work happens off the main thread.

**Example of what needs it:**
```tsx
const frameProcessor = useFrameProcessor((frame) => {
  'worklet'
  const faces = detectFaces(frame)  // runs at 30fps
}, [])

<Camera frameProcessor={frameProcessor} ... />
```

**What does NOT need it:**
- `codeScanner` (what you use) — runs entirely in native code (ML Kit). The barcode result is handed back to JS only when something is detected, not every frame.
- Photo capture, video recording, torch — all native.

**Why it got installed:** likely vision-camera's autolinking or a peer-dependency suggestion. It's safe to remove from `package.json` unless you plan to add frame processors. After removing, run `npm install` and rebuild the dev-client.

**Relation to `react-native-worklets`:** different package. `react-native-worklets` (no `-core`) is the worklet runtime for Reanimated v4 (animation worklets on UI thread). They're separate runtimes from separate authors solving overlapping problems — keeping both installed when only one is needed is a known source of confusion.

That's a fish shell quirk, not a real error. Two things going on:

**The "no matches" error:**
- `fish` shell expands globs *before* running the command. If `$TMPDIR/haste-map-*` matches zero files, fish aborts the whole line with "no matches for wildcard" — unlike bash/zsh, which silently pass the literal string to `rm`.
- Your system simply didn't have any leftover `haste-map-*` files, so the glob expanded to nothing → fish refused to run `rm`.
- It's harmless; nothing needed to be deleted there. The `metro-*` part on the same line *did* expand to real files and got removed before fish hit the failing glob — that's why your cache cleared and the bundler started working.

**How to avoid it in fish next time:**
- Use `set -l globs $TMPDIR/metro-* $TMPDIR/haste-map-*; test (count $globs) -gt 0; and rm -rf $globs`, or
- Just quote it so fish passes the literal pattern to `rm`, which itself ignores no-match silently with `-f`: `rm -rf "$TMPDIR/haste-map-"*` — actually fish still expands that. The cleanest is to prefix with `set -l` or use `find`.
