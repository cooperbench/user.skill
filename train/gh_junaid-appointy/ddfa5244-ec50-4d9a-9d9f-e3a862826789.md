**Clear Local Data** (Settings → button calling `clearAllLocalCache` in `src/db/maintenance.ts:57`) wipes the on-device SQLite caches so the next screen focus re-hydrates from the backend. **What it deletes:** - `stock_levels` — cached inventory counts (re-pulled from `/stock`) - `orders` + `order_items` — cached open POs (re-pulled from `/orders`) - `canonical_products` + `product_barcodes` — admin catalog + learned barcode-to-product mappings (re-pulled from the catalog endpoint) - `products` — legacy local catalog the Scanner consults pre-lookup - `outbox` — pending offline writes; destroyed because after a server wipe they'd most likely target rows that no longer exist **What it preserves:** - `receipts` — local audit of every scan (kept as evidence even if server state changes) - Session token — you stay logged in - App preferences — language, theme After clearing, it immediately calls `syncCanonicalProducts()` + `syncOrders()` so screens don't show empty states while waiting for the next periodic sync. **When to use it:** when an admin resets inventory data on the server. The local device might still hold stale stock counts, deleted orders, or queued writes pointing at now-gone server rows. Clearing forces a clean re-mirror. **When NOT to use it:** as a casual "refresh" — if the outbox has unsynced writes from offline work, this destroys them. There's a separate Sync queue screen for forcing a flush without nuking data.
