## The back-button bug

Here's what your stack looks like after scanning a new product:

```

  Scanner → navigation.replace('RegisterProduct')   (ScannerScreen:168)
```

Every step uses `navigation.replace` instead of `push`, so the intermediate screens are **removed** from history. On top of that, `ReceivingScreen.tsx:300` explicitly wires the AppBar back arrow to `navigation.popToTop()`, which always jumps to Home.

- **Quick:** change Receiving's `onBack={() => navigation.popToTop()}` → `navigation.goBack()`, and switch the `replace` calls along the scan chain to `push`. function similarity(a: string, b: string): number {
```
  const la = a.toLowerCase().replace(/[^a-z0-9]/g, '');
  const lb = b.toLowerCase().replace(/[^a-z0-9]/g, '');
  if (la === lb) return 1;
  if (la.length < 2 || lb.length < 2) return 0;
  const bg = (s: string) => {
    const out = new Set<string>();
    for (let i = 0; i < s.length - 1; i++) out.add(s.slice(i, i + 2));
    return out;
```

**Clear Local Data** (Settings → button calling `clearAllLocalCache` in `src/db/maintenance.ts:57`) wipes the on-device SQLite caches so the next screen focus re-hydrates from the backend.

**What it deletes:**
- `stock_levels` — cached inventory counts (re-pulled from `/stock`)
- `orders` + `order_items` — cached open POs (re-pulled from `/orders`)
- `canonical_products` + `product_barcodes` — admin catalog + learned barcode-to-product mappings (re-pulled from the catalog endpoint)
- `products` — legacy local catalog the Scanner consults pre-lookup
- `outbox` — pending offline writes; destroyed because after a server wipe they'd most likely target rows that no longer exist

**What it preserves:**
- `receipts` — local audit of every scan (kept as evidence even if server state changes)
- Session token — you stay logged in
