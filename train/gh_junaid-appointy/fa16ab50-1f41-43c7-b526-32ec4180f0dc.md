> AGENT

Short answer: yes, it's possible on this Mac, and for **JS-only changes** you already have the fastest possible loop — you don't need to rebuild anything. For **native changes**, local builds are doable but have real setup cost. ## The key distinction Your CLAUDE.md says it explicitly: **95% of changes are JS/TS** and Metro hot-reloads them onto the phone in <1s over USB/Wi-Fi. The dev-client APK only needs rebuilding when you touch: - `app.json` plugins - New `react-native-*` native libs - Android permissions / new-arch flags So before setting up local builds, confirm you're actually rebuilding often. If you're rebuilding for JS changes, the fix is `npm run start:dev-client` + reload — not local Android builds. ## If you genuinely need local native builds **Benefits** - Build time drops from ~15–25 min (EAS queue + build) to ~3–8 min locally on M-series Mac - No queue wait, no network upload of the project tarball - Iterate on native config (permissions, plugins) without burning EAS credits - Works fully offline once set up **Issues / costs** - One-time setup: Java 17 (JDK), Android Studio, Android SDK, `ANDROID_HOME`, `ndk` matching Expo SDK 54's requirement. Expect a few hours and ~10–15 GB disk. - Your CLAUDE.md explicitly says "**This project does not use local Android Studio builds**" — meaning the team standardized on EAS. Local builds may drift from EAS output (different NDK, different Gradle cache, signing differences) and "works on my machine" bugs become real. - Signing: dev-client APKs are debug-signed, fine for your phone, but if you share with teammates they'll hit "app not installed" unless you use a consistent debug keystore or a shared internal keystore. - Node 22 LTS pinning still applies — don't let local tooling pull Node 24. **Distribution to your phone** - USB: `adb install -r …
