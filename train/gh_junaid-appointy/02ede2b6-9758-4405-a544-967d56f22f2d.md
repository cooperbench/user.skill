462	function AutoHideBanner({ show, children }: { show: boolean; children: React.ReactNode }) {
463	  const [visible, setVisible] = useState(false);

465	    if (!show) {

468	    }

644	  const allDay = !start.includes('T');

648	  const t = (d: Date) => d.toLocaleTimeString(undefined, { hour: 'numeric', minute: '2-digit' });

## What you were seeing

The count came from the **preview/confirm sheet and the review button**, which both used `included.length` — *every* included guest (5). That number is right for a **first send** (each included guest gets a new pass), but wrong for an **update**, where only the guest(s) you actually edited change. It also always said "sent"/"Send", even when updating.

## Fix (extension only — the engine count was already correct)

In `VisitPanel.tsx` I compute a real `changeCount`:
- **First send** → `included.length` (every included guest gets a pass), unchanged.
- **Update (managed event)** → newly added guests + pending cancels + the specific guests whose name/phone you edited. So editing one guest of five reads **1**. (A template switch still counts as all included, since that re-renders every guest's email.)

`PreviewSheet` now takes an `update` flag and switches the wording accordingly:
- Send: "1 pass will be sent" / "Send 1 pass"
- Update: "1 pass will be updated" / "Update 1 pass"

The review button's parenthetical count (`Review & update passes (1)`) uses `changeCount` too. Built and type-checked clean; bumped to **0.11.5**.

## One thing worth knowing

The **result banner** after sending (`SendSummary`) already uses the engine's true count — `applyDraft` only reports a pass as `updated` when a field genuinely differs from what's stored (`updateVisitorInvite` diffs internally, `visit-drafts.ts:868`). So that line should already read "1 pass updated."

If you ever see the *result* banner overcount, there's one real edge: background name resolution (People API) fills real names for guests whose passes were issued with email-derived fallback names, and persists them to the draft. On the next update those passes genuinely change too, so they'd legitimately count. Tell me if you hit that and I'll make background name-fills not count against your explicit edits.
