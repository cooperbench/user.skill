## Sysbox + BTRFS: The Root Cause On kernel 6.18, Sysbox uses **ID-mapped mounts** for bind mounts (shiftfs was never upstreamed and dropped from Ubuntu kernels ≥5.19). The problem is that **BTRFS is missing from Sysbox's filesystem blacklist**. In `sysbox-libs/idMap/idMapMount.go` line 42, the blacklist only has: ```go var idMapMountFsBlackList = []int64{ unix.OVERLAYFS_SUPER_MAGIC, 0x65735546, // FUSE_SUPER_MAGIC 0x6a656a63, // FAKEOWNER } ``` Sysbox issue [#535](https://github.com/nestybox/sysbox/issues/535) **documents** that BTRFS is unsupported for ID-mapped mounts, but `BTRFS_SUPER_MAGIC` (`0x9123683E`) was **never added to the blacklist**. So Sysbox happily applies ID-mapped mounts to BTRFS bind mounts, which then fail with EOVERFLOW when: 1.
