Issue created: **https://github.com/thieso2/Sandcastle/issues/37** Here's what the issue covers: **Snapshot model** — a new DB-backed `Snapshot` record that tracks up to four layers per snapshot: container (Docker commit), home dir, data dir, and workspace volume. Each layer is optional and has its own stored size. **BTRFS integration** — three new `BtrfsHelper` operations (`snapshot_subvolume`, `delete_snapshot`, `restore_subvolume`) backed by `sudo btrfs subvolume snapshot/delete`. Storage layout under `$SANDCASTLE_DATA_DIR/snapshots/{user}/{name}/`. Graceful fallback to Docker-only on non-BTRFS hosts. **Data subdir granularity** — when a sandbox has a data mount with multiple BTRFS subvolumes inside, you can snapshot a specific subdir and restore just that subdir without touching the rest. **Clone to new sandbox** — `box create --from-snapshot <name>` with `--restore-layers` flag, plus a matching UI flow that lets you pick which layers to carry into the new box. **UI** — snapshots tab on the sandbox detail page, create modal with layer checkboxes, a global `/snapshots` listing page with bulk delete and clone actions. **CLI** — updated `snapshot` command tree with `create/list/show/delete/restore` plus the `--layers` and `--data-subdir` flags. **Migration path** — existing Docker-image snapshots (`sc-snap-{user}:{name}`) are imported as DB records on first boot so nothing breaks.
