**Root cause:** The Dockyard Docker daemon (Sysbox) shifts UIDs on bind-mounted paths. The `traefik/dynamic` directory ends up owned by Sysbox's subordinate UID (231072) instead of the app UID (220568), making the Rails process unable to write Traefik route configs.

**Fix 1 — `bin/docker-entrypoint`:** On container start, checks if the traefik dynamic dir has wrong ownership and uses passwordless `sudo chown` (already permitted in `Dockerfile.base`) to reclaim it. This runs on every web/worker container start, so new installs and restarts are both covered.

**Fix 2 — `app/services/sandbox_manager.rb`:** Defense in depth — wraps the `prepare_traefik_config` calls in a begin/rescue for `Errno::EACCES`. If writing the Traefik config fails, sandbox provisioning still succeeds (the route will be lazily written on first terminal/VNC open).

**Server fix:** Ran `chown -R 220568:220568` on `/sandcastle/data/traefik/dynamic/` to unblock the running instance immediately.
