Two viable approaches — they differ in whether sandboxes share host keys. **A) Per-sandbox unique keys (recommended — better security).** Delete *all* host keys at image build; the entrypoint's existing `ssh-keygen -q -t ed25519 ...` generates a fresh ed25519 key the first time each container starts. One line added at the end of `Dockerfile.base`: ```dockerfile # openssh-server's postinst generated rsa+ecdsa+ed25519 host keys at build # time. Drop them so each sandbox container generates its own ed25519 key # on first start (see entrypoint.sh). Avoids all sandboxes sharing keys # (which defeats TOFU) and skips the ~1-3s RSA keygen entirely. RUN rm -f /etc/ssh/ssh_host_*_key /etc/ssh/ssh_host_*_key.pub ``` First-start cost of one ed25519 keygen is single-digit ms on any modern CPU — effectively free. Subsequent `docker start` on the same container reuses the generated key. **B) Bake a shared ed25519 key at image build.** Delete rsa/ecdsa, keep ed25519. No per-container keygen; marginally faster first-start. But every sandbox has the same host key, so SSH TOFU gives no protection — a compromised image means every sandbox is MITM-spoofable.
