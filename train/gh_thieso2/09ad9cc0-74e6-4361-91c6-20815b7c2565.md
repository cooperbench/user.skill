# Plan: Replace WeTTY with ttyd (tmux + shell terminals)

## Context
WeTTY requires SSH keypair generation, key injection via `docker exec`, and a sidecar container per terminal session. Replacing it with ttyd running **inside** the sandbox container eliminates all of this complexity. Two ttyd instances run permanently on fixed ports inside each sandbox; Traefik routes directly to them. No sidecars, no keypairs, no background jobs.

## Key architectural facts
- Sandbox containers use `"NetworkMode" => "sandcastle-web"` (SandboxManager:4,65) — they're already on the same Docker network as Traefik and Rails
- ttyd running inside the sandbox is reachable as `http://{sandbox.full_name}:768x` from Traefik without any host port mapping
- ttyd exposes HTTP + WebSocket on the same port (Traefik proxies both transparently, same as WeTTY on port 3000)
- `tmux` is already installed in the sandbox image (Dockerfile:9)

## Ports
- Port **7681** → `tmux new-session -A -s main` (unlimited clients, re-attachable)
- Port **7682** → `bash -l` (plain login shell, one client at a time)

> AGENT

Both are protected by Traefik's `forwardAuth` middleware, which calls back into Rails before allowing the request through.

**Flow for every request to `/terminal/5/tmux` or `/vnc/5/...`:**

1. Browser hits Traefik
2. Traefik calls `http://sandcastle-web:80/terminal/auth` (or `/vnc/auth`) with the original request headers — including the session cookie and `X-Forwarded-Uri`
3. Rails checks the session cookie, extracts the user, verifies sandbox ownership
4. Rails returns **200** → Traefik forwards the request to ttyd/websockify
5. Rails returns **redirect to /login** → Traefik passes the redirect back to the browser (unauthenticated users end up at the login page)
6. Rails returns **401** → wrong user, no sandbox ownership

**The ownership check** in `terminal#auth`:
```ruby
match = forwarded_uri.match(%r{/terminal/(\d+)/(tmux|shell)})
sandbox = Sandbox.active.find_by(id: match[1].to_i)
head(:unauthorized) unless sandbox && (sandbox.user_id == user.id || user.admin?)
```

Same pattern in `vnc#auth`.

**What this means in practice:**
- Unauthenticated → redirected to login, return URL preserved so they land back at the terminal after login
- Authenticated but wrong user → 401
- Authenticated admin → always allowed
- Every WebSocket frame also goes through forwardAuth (Traefik re-checks on upgrade), so there's no way to sneak in after auth

The only weak spot is that forwardAuth re-checks on each HTTP request but the WebSocket connection itself persists — if a session is revoked mid-session the terminal stays open until the WebSocket closes. That's standard behaviour for this pattern.
