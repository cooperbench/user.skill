def auth
  forwarded_uri = request.headers["X-Forwarded-Uri"] || ""
  match = forwarded_uri.match(%r{/vnc/(\d+)/novnc})
  head(:unauthorized) and return unless match

  session_record = find_session_by_cookie
  unless session_record
    proto = request.headers["X-Forwarded-Proto"] || "https"
    host  = request.headers["X-Forwarded-Host"] || request.host_with_port
    original_url = "#{proto}://#{host}#{forwarded_uri}"
    session[:return_to_after_authenticating] = original_url
    redirect_to new_session_url, allow_other_host: true
    return
  end

  user = session_record.user
  sandbox = Sandbox.active.find_by(id: match[1].to_i)
  head(:unauthorized) and return unless sandbox && (sandbox.user_id == user.id || user.admin?)

  head :ok  # Allow Traefik to proceed

  raise Error, "Sandbox has no container" if sandbox.container_id.blank?

def write_traefik_config(sandbox)
  FileUtils.mkdir_p(DYNAMIC_DIR)
  host = ENV.fetch("SANDCASTLE_HOST", "localhost")

### **Critical Configuration Details**

**Network Topology:**
- noVNC container connects to `sandcastle-web` Docker network
- Sandbox container also connected to same network
- Communication: `sc-vnc-{user}-{sandbox}:6080` → `{user}-{sandbox}:5900` (VNC protocol)
- Traefik is entry point, strips URL prefix before forwarding to noVNC

**Container Naming:**
- noVNC: `sc-vnc-{user}-{sandbox}` (e.g., `sc-vnc-thies-quantum-viper`)
- Sandbox: `{user}-{sandbox}` (e.g., `thies-quantum-viper`)
- Label for tracking: `sandcastle.sandbox_id` = sandbox ID, `sandcastle.role` = "novnc"

**Port Usage:**
- Sandbox exposes 5900 (VNC protocol via x11vnc)
- noVNC container listens on 6080 (HTTP server for browser)
- Traefik handles HTTPS termination at 443

**Environment Variables:**
- `SANDCASTLE_VNC_URL` - Override URL for VNC redirect (defaults to `SANDCASTLE_TERMINAL_URL` then relative path)
- `SANDCASTLE_NOVNC_IMAGE` - Docker image for noVNC (default: `gotget/novnc:latest`)
- `SANDCASTLE_DATA_DIR` - Location of Traefik dynamic config (default: `/data`)
- `SANDCASTLE_HOST` - Hostname for Traefik routing rule
- `SANDCASTLE_TLS_MODE` - `selfsigned` or `letsencrypt` (affects Traefik config generation)

**VNC Server Details:**
- Virtual Display: Xvfb at `:99` (1920×1080×24-bit)
- Server: x11vnc running on port 5900
- Flags: `-shared` (multiple connections), `-forever` (persistent), `-nopw` (no password)
- Logs: `/var/log/xvfb.log` and `/var/log/x11vnc.log` in sandbox

Root cause: two bugs in the VNC flow:

**Bug 1 (previous fix):** `VNC_SERVER` env var is silently ignored by `gotget/novnc` — the `launch.sh` script only reads `--vnc HOST:PORT` as a CLI argument. Container was proxying to `localhost:5900` (itself) instead of the sandbox.

**Bug 2 (this fix):** The Traefik `redirectRegex` middleware matches against the **full URL** (scheme + host + path), so `^/vnc/13/novnc/?$` never matched `https://hase.sandcastle.rocks/vnc/13/novnc`. Without the redirect, the browser hit `/vnc/13/novnc` (no trailing slash) → websockify served a directory listing → relative link `vnc.html` resolved to `/vnc/13/vnc.html` → 404.

**Fix:** Removed the broken redirect middleware entirely and changed `vnc_url` to return `/vnc/id/novnc/vnc.html` directly. Traefik's `stripPrefix` removes `/vnc/13/novnc` → noVNC container receives `/vnc.html` → serves the noVNC interface correctly.
