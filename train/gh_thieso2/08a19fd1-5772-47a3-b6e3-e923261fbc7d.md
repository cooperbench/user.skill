This is macOS's aggressive SMB client-side caching. It's serving you a stale cached copy even though the server has a newer version. Quick fix — remount the share: ```bash umount /Volumes/persisted-1 && open "smb://..." ``` Permanent fix — disable macOS SMB caching. Create/edit `~/Library/Preferences/nsmb.conf`: ```ini [default] dir_cache_max_cnt=0 file_ids_off=yes ``` Then remount. This tells the macOS SMB client to stop caching directory listings and file contents.

> DEVELOPER

nothing we can do on teh server side?

> AGENT

Yes — the issue is SMB **oplocks** (opportunistic locks). The server tells macOS "go ahead and cache, I'll notify you of changes." But when files change on the server outside of SMB (e.g. via SSH/editor), no oplock break is sent, so macOS keeps the stale cache. Fix: disable oplocks in the Samba config.

> AGENT

Added `oplocks = no` and `level2 oplocks = no` to the `[global]` section. This disables server-granted caching, so macOS will always fetch fresh content from disk. The tradeoff is slightly more network traffic (no client-side caching), but for a dev sandbox that's fine — correctness matters more than SMB throughput.
