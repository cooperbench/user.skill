**`10.206.192.3` is NOT a standard Tailscale CGNAT IP (`100.x.x.x`)**. It's the sandbox container's private Docker bridge IP on the `sc-ts-net-thies` network. It's only reachable from your local machine through the Tailscale sidecar's **subnet route advertisement**.

## To reach `10.206.192.3` from your local machine, you need:

1. **Tailscale running locally** — `tailscale status` should show it's connected
2. **Logged into the same tailnet** as the Sandcastle sidecar joined
3. **Subnet routes accepted** — either via the Tailscale admin console (approve the `10.206.192.x/24` subnet route) or by running `sudo tailscale up --accept-routes` on your local machine

v0.8.26 is out. Here's what changed and why:

---

**Why the subnet changed after reinstall:**

`subnet_for(user)` first checked the live Docker network. After reinstall, Docker is fresh — no networks exist — so it fell through to generating a **random `/24`** from the pool. Docker's pool allocator picked a different offset than last time.

**Fix — three-level lookup, DB wins:**
1. `user.tailscale_subnet` (new DB column) — checked first, survives reinstall
2. Live Docker network — used on first boot after migration
3. Random `/24` — only on truly first allocation, then saved to DB

**`SANDCASTLE_NAME` → stable Tailscale machine names:**

| Before | After |
|--------|-------|
| `sc-thies` (user name — meaningless in Tailscale admin) | `sc-sandman` (server name — clear which instance) |

- `gen-env` auto-detects from `hostname -s` (e.g. `sandman`)
- Stored in `.env` and `sandcastle.env`
- Existing installs get backfilled on next `installer.sh install`
- `restore_from_state` now passes `--hostname=sc-<name>` to `tailscale up` so it updates on reconnect without re-auth
