Here's a full explanation of every network and IP configured in `sandcastle.env`: --- ## Dockyard daemon settings Sandcastle runs an **isolated Docker daemon** ("dockyard") separate from the host's system Docker. The `DOCKYARD_*` variables configure that daemon, not the system Docker. ### `SANDCASTLE_PRIVATE_NET` (e.g. `10.89.0.0/16`) The master knob. A single RFC 1918 /16 from which all other network ranges are carved. Change this one value to move everything to a different private range (e.g. `172.20.0.0/16` if `10.x.x.x` conflicts with your LAN). --- ### `DOCKYARD_BRIDGE_CIDR` (derived: `10.89.0.1/24`) The **gateway IP + mask** for dockyard's default bridge (`sc_docker0`). This is the equivalent of Docker's `bip` setting — the IP address that the bridge interface on the host gets. Every container connected to the default bridge can reach the host via this IP. Equivalent to: `docker daemon --bip=10.89.0.1/24` ### `DOCKYARD_FIXED_CIDR` (derived: `10.89.0.0/24`) The **container address range** within the bridge. Limits the IPs Docker assigns to containers on the default bridge to this /24. Keeps container IPs predictable and separate from the pool range used by user-defined networks. Equivalent to: `docker daemon --fixed-cidr=10.89.0.0/24` ### `DOCKYARD_POOL_BASE` + `DOCKYARD_POOL_SIZE` (derived: `10.89.0.0/16`, size `24`) The **address pool** from which dockyard allocates subnets for every user-defined Docker network. When you call `docker network create foo` without specifying a subnet, Docker carves a fresh `/24` out of this `/16`. Equivalent to: `docker daemon --default-address-pool base=10.89.0.0/16,size=24` --- ## Docker networks (runtime) These are actual Docker networks created at install/runtime, not config variables. ### `sandcastle-web` Created once by the installer (`docker network create sandcastle-web`). Its subnet is auto-allocated by dockyard from `DOCKYARD_POOL_BASE` (first free /24, e.g. `10.89.1.0/24`). **Who lives here:** - Rails app container (`sandcastle-web`) - WeTTY sidecar containers (`sc-wetty-{user}-{sandbox}`) — need to reach the sandbox over SSH - noVNC containers (`sc-novnc-{sandbox}`) — serve the browser VNC UI - Sandbox containers — …
