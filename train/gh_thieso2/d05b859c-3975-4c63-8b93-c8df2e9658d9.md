Here's the full flow: ## CLI: `sandcastle -v` 1. **`mise run release`** creates a git tag (e.g. `v0.1.15`) and pushes it 2. GitHub Actions `release.yml` triggers on the tag push 3. GoReleaser builds the CLI with **ldflags** (`.goreleaser.yaml:17`): ``` -X github.com/sandcastle/cli/cmd.Version={{ .Version }} ``` GoReleaser's `{{ .Version }}` resolves to the git tag (without the `v` prefix, e.g. `0.1.15`) 4. This overwrites the default `var Version = "dev"` in `vendor/sandcastle-cli/cmd/root.go:10` 5. So `sandcastle version` / `sandcastle -v` prints the release version ## Web footer: `Sandcastle.version` The footer (`app/views/layouts/application.html.erb:32`) calls `Sandcastle.version`, defined in `config/initializers/version.rb`. This does **not** use the git tag at all. It builds a string from: - **git SHA** (short, e.g. `2baffcd`) — from `BUILD_GIT_SHA` env or `git rev-parse --short HEAD` - **dirty flag** — from `BUILD_GIT_DIRTY` env or `git status --porcelain` - **date** — from `BUILD_DATE` env or current date Result looks like: `2baffcd / 2026-02-12` The `deploy:local` mise task sets `BUILD_GIT_SHA`, `BUILD_GIT_DIRTY`, and `BUILD_DATE` as build args. For Kamal deploys, these would come from whatever env is set during the Docker build. ## Key takeaway The git tag version **only flows into the CLI binary** (via GoReleaser ldflags). The **web app footer shows the git SHA + date**, not the semver tag. They're two independent version mechanisms.
