### Key Observations

1. **Server URL Access Pattern**: All commands call `api.NewClient()` which loads the config and extracts `srv.URL`. The URL is stored in `Client.BaseURL`.

2. **Verbose Logging**: The infrastructure for printing server info exists (via `logVerbose()`), but it goes to stderr and is only active with `SANDCASTLE_VERBOSE=1`.

3. **No Consistent Header Pattern**: Only the `create` command prints the server URL. Other commands don't show it by default. Config/server commands show the current server but in a "command-specific" context, not as a universal header.

4. **Table Output Uses tabwriter**: For formatted output with columns, the CLI uses Go's `text/tabwriter` package (initialized with `tabwriter.NewWriter(os.Stdout, 0, 0, 2, ' ', 0)`).

5. **JSON Output**: Only `status` command outputs JSON (pretty-printed with `json.MarshalIndent(status, "", "  ")`).

6. **No Global Flags for Output Control**: Commands don't have flags like `--server` or `--no-header`; everything is derived from `api.NewClient()` reading the config.

   149→	}

   151→	proc := &os.ProcAttr{
   152→		Files: []*os.File{os.Stdin, os.Stdout, os.Stderr},

   156→		return fmt.Errorf("starting ssh: %w", err)
   157→	}
   158→
   159→	state, err := process.Wait()
   160→	if err != nil {
   161→		return err
   162→	}
   163→	if !state.Success() {
   164→		os.Exit(state.ExitCode())
   165→	}
