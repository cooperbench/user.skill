> AGENT

The SSH protocol itself doesn't support passing a remote command via the `ssh://` URL scheme — it's just `ssh://[user@]host[:port]`. The command to run (`tmux attach` or `tmux new-session -A -s main`) is up to the terminal app. However, there are a few approaches: **1. Make tmux the default shell in the sandbox (simplest, works everywhere)** The sandbox entrypoint could set the user's default shell (or `.bashrc`/`.profile`) to auto-attach tmux. That way *any* SSH connection — from any app, URL scheme, or CLI — automatically lands in the tmux session. No special URL parameters needed. **2. App-specific URL schemes** Some apps support command parameters: - **LaTerminal**: `laterminal://open/{user}@{hostname}:{ssh_port}?command=tmux+new-session+-A+-s+main` - **Prompt 3 / Blink**: similar custom scheme support - **iTerm2**: `iterm2://ssh?host={hostname}&port={ssh_port}&user={user}&command=...` But this is fragile and app-dependent. **3. Use `.ssh/rc` or forced command server-side** The sandbox could set up a default `ForceCommand` or `.ssh/rc` that wraps connections in tmux. --- I'd recommend option 1 — it's the most universal. Want me to update the sandbox entrypoint to auto-attach tmux on SSH login? The standard pattern is adding this to the user's `.bashrc`: ```bash if [[ -z "$TMUX" ]] && [[ "$SSH_CONNECTION" != "" ]]; then tmux new-session -A -s main fi ``` This way every SSH connection (from any app, custom link, or CLI) reconnects the tmux session `main` automatically.
