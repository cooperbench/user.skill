## How It Works

### On Server (Installer)
When you run `sudo installer.sh install` on a BTRFS filesystem:
1. Detects BTRFS automatically
2. Creates subvolumes for top-level directories:
   - `/sandcastle/data/users`
   - `/sandcastle/data/sandboxes`
   - `/sandcastle/data/postgres`
   - `/sandcastle/data/wetty`
   - `/sandcastle/data/traefik`
   - `/sandcastle/docker`

### In Rails (Runtime)
When a user creates a sandbox:
1. `BtrfsHelper.create_user_subvolume(username)` creates `/data/users/<username>` as a subvolume
2. If sandbox has a data path, `BtrfsHelper.create_user_data_subvolume(username, path)` creates `/data/users/<username>/data/<path>` as a subvolume
3. Falls back gracefully if BTRFS operations fail

## Benefits

✅ **Per-user snapshots**: Each user directory is an independent subvolume  
✅ **Per-data-path snapshots**: Each data directory can be snapshotted independently  
✅ **Better performance**: BTRFS CoW works optimally with subvolumes  
✅ **Quota support**: Can set quotas per user/data-path  
✅ **Zero configuration**: Auto-detected, no settings needed  
✅ **Graceful fallback**: Works on non-BTRFS filesystems too
