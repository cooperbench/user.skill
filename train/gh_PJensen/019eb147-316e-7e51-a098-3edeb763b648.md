You’re not wrong. The real architectural target is: **One physical world, disconnected spaces allowed, player can alter topology.** That means disconnected dungeon chunks are fine. The mistake is treating disconnection as “outside the floor footprint” or as an instancing problem. It should be normal world geometry: - chunks exist in the same coordinate space - void/rock separates regions - the player can mine/dig through the separator - discovery can come from sound, maps, seams, clues, cave-ins, shafts - generation can create unreachable pockets intentionally - reachability is not a generation invariant anymore; *eventual diggability* is So yes: no instanced dungeons. If there’s a “rat cellar,” “buried shrine,” “sealed vault,” or “old mine,” it should be somewhere in the same coordinate plane, behind matter. Where I’d push back: don’t let disconnected chunks inflate the loaded active floor extents blindly. That’s what was wrong. The pocket helper was using an extent expansion as a content-placement crutch. The deeper version should separate: 1. **Simulation extent / loaded chunks** What chunks are part of this floor’s potential world. 2. **Initial navigable graph** What the player can walk to without digging. 3. **Excavatable topology** What the player can reach by mining through rock/soil/walls. 4. **Discovery affordances** How the player learns “there is something over there.” The next push is probably a `subterranean region graph` or `sealed pocket plan`, not just “pick a spare chunk.” It should produce pockets inside a bounded floor plan, tag them as sealed/disconnected, and guarantee some mineable path thickness between the main graph and the pocket. So my stance: you’re right on the design. The code needs to stop equating “disconnected” with “extent expansion.” Disconnected dungeons are good. Unbounded dungeons are bad.
