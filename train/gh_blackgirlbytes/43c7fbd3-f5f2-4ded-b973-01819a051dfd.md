Here's the research, then the brainstorm. ## What I found — what checkpoints actually are From the quickstart (`entire-docs/quickstart.mdx`) and `cli/checkpoints.mdx` + the command source: **A checkpoint is a record of the prompts, transcript, tool calls, and file changes behind an AI-assisted commit.** Mechanically: - You work with an agent → you `git commit` → Entire attaches the session to that commit automatically. - The checkpoint ID becomes a commit trailer: `Entire-Checkpoint: a3b2c4d5e6f7`. - The data lives on a separate branch (`entire/checkpoints/v1`) so your working branch stays clean — **no extra commits**. - Your commit message becomes the checkpoint's label. **The verbs people actually use** (from the command `Short:` strings): - `checkpoint list` — list checkpoints on the branch - `checkpoint` — "Inspect, rewind, and search checkpoints" - `rewind` — "Browse checkpoints and rewind your session" - `resume` — "Switch to a branch and resume its session" (you *or a coworker*) - `search` — "semantic and keyword matching" over past checkpoints - `recap` — "Summarize recent checkpoint activity" **When someone uses them** (the best-practices section is the gold): *"Make commits at logical stopping points… use meaningful commit messages—they become checkpoint labels… commit before major changes if you want a rewind point."* The payoff is **rewind** (undo to last good state, including session state) and **resume** (pick up a session with full context). ## The key insight for the game The quickstart is literally titled **"create your first checkpoint."** Checkpoints are *the* foundational Entire concept — the first thing a real user does.
