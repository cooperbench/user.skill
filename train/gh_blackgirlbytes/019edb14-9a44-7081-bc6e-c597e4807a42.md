> DEVELOPER

why is this bad All scenes built eagerly on startup.

> AGENT

It’s bad because each level is a pretty heavy Three.js world, and [src/main.js](/Users/goose-guest/Documents/work/planetfall-seed-signalkit/src/main.js:171) creates all of them immediately: - orbit view - Level 1 - Drone Bay - shelved Archive - Level 3 That means on first page load the browser allocates terrain meshes, lights, materials, sprites, textures, labels, particles, and cameras for levels the player may not reach for several minutes, or ever. In this repo, the hidden Archive is especially wasteful because normal play does not use it. Why players feel it: - Slower initial boot: more JS runs before the title/game is fully ready. - Higher memory/GPU pressure: unused scenes still hold geometry/materials/textures. - More risk on MacBook Air/mobile/integrated GPUs: less headroom once a busy level starts. - Harder debugging: hidden views keep state around from startup, so bugs can come from stale level state rather than current play. It is not automatically catastrophic, but for a Three.js game the healthier pattern is lazy creation: build `droneBayView` only when entering Level 2, build `launchView` only when entering Level 3, and either lazy-load or remove the shelved Archive from normal startup.
