Best fit: **not an open-source license**. What you want is a **source-available / proprietary “All Rights Reserved” license**. Open-source licenses like MIT, Apache, GPL, AGPL, etc. all allow people to copy, use, modify, and redistribute the project in some form. Even copyleft licenses stop people from closing the source, but they do **not** stop reuse. For your rule, I’d use: 1. **`LICENSE`**: custom source-available / all-rights-reserved license Allows people to view the repo and fork it for contribution, but prohibits using, copying, distributing, modifying, or republishing it for their own project without written permission. 2. **`CONTRIBUTING.md`**: contribution terms Says that by opening a PR, contributors grant you the right to use, modify, and include their contribution in the project. For anything serious, use a CLA. Important nuance: GitHub public repos can be viewed and forked under GitHub’s terms, but that does **not** automatically give people permission to reuse the code outside what your license allows. GitHub’s own docs say that without a license, default copyright applies and others cannot reproduce, distribute, or make derivatives; GitHub also notes public repos can be viewed/forked on GitHub. Sources: [GitHub licensing docs](https://docs.github.com/articles/licensing-a-repository), [GitHub Terms section 5](https://docs.github.com/site-policy/github-terms/github-terms-of-service), [OSI Open Source Definition](https://opensource.org/osd). So my recommendation is: **All Rights Reserved + explicit contribution permission**, not MIT/Apache/GPL. For strongest protection, have a lawyer review the wording before publishing.

ok whats the tightest open source license

> AGENT

The “tightest” real open-source license is usually **GNU AGPLv3**. It is stricter than GPLv3 because it covers the SaaS/server loophole: if someone modifies your project and runs it as a public network service, they must offer the modified source code to users of that service. OSI describes AGPLv3 as requiring network server operators to provide source for modified versions running there: [OSI AGPLv3](https://opensource.org/license/agpl-3-0). ChooseALicense also calls AGPLv3 the “strongest copyleft” license: [ChooseALicense AGPLv3](https://choosealicense.com/licenses/agpl-3.0/). But: **AGPLv3 still allows copying, reuse, modification, redistribution, commercial use, and forks.** It just forces derivatives to stay open under the same license when distributed or used over a network. My short recommendation: - Want maximum open-source protection: **AGPL-3.0-only** or **AGPL-3.0-or-later** - Want strong copyleft but less scary to companies: **GPL-3.0-only** - Want people to contribute but not reuse/copy: **not open source**, use source-available/all-rights-reserved For your stated goal, AGPLv3 is the closest open-source fit, but it does **not** give you the “don’t reuse this” control.
