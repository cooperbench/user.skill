**Yes, this is a good idea.** Here's why:

**Current code problems:**
- The `tez://`, `phonepe://`, `paytmmp://` URLs work only if that specific app is installed. The 1.5s fallback timer is unreliable — if the app IS installed, both the app URL AND the fallback fire, potentially double-navigating.
- The 3-app picker adds unnecessary friction. Users already know which UPI app they use.

**Why `upi://` + `window.location.href` is better:**
- `upi://pay?...` is the universal UPI standard. Every UPI app (GPay, PhonePe, Paytm, BHIM, any bank app) registers as a handler for it.
- Android shows a native system app picker automatically if multiple UPI apps are installed — no custom picker needed.
- No fallback timer, no double-navigation risk.
- Works in PWA standalone mode correctly.

**One thing to note:** `intent://` links don't exist in your code currently — the grep found nothing. So that's already clean.

**The confirmation flow (pending_confirmation + UTR + farmer manual verify) is exactly right for MVP** — there's no webhook from UPI apps available to web/PWA, so manual confirmation is the only realistic option.

**What will change:**
- Cart.tsx: Replace 3-app picker with one big green "Pay via UPI" button → `window.location.href = 'upi://pay?...'`
- Cart.tsx: After clicking pay, show success/failed buttons + optional UTR field
- orders/page.tsx: Already uses `upi://` href correctly, minor cleanup
- farmer/dashboard/page.tsx: Add 3-button payment status update (Received / Not Received / Pending)
