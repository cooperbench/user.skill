I've got a clear picture of how your app handles payments today. Here's the process, mapped to your actual codebase.

## How payments work now

Your current flow (`orders/place` → `payment-claim`) is **manual**:
- Buyer picks `upi` or `cod`
- For UPI: buyer pays out-of-band, enters a UTR number, then *claims* payment → `payment_status: pending_confirmation` → **farmer manually verifies**

Razorpay replaces that manual UPI path with a **verified, automatic** online payment. COD stays as-is.

## The Razorpay flow (4 steps)

```
1. Buyer checks out  →  your /orders/place creates the order (payment_status: pending)
2. Server creates a Razorpay Order   →  returns razorpay_order_id  (amount in paise)
3. Browser opens Razorpay Checkout   →  buyer pays with test card/UPI
4. Razorpay returns 3 values         →  your server VERIFIES the signature
                                         →  payment_status: 'paid'
```

The non-negotiable security rule: **the secret key never leaves the server, and you must verify the signature server-side.** Never trust the browser's "payment succeeded" — anyone can fake that. The HMAC signature check is what proves Razorpay actually took the money.

## Implementation steps

**1. Keys → `.env.local` (never commit)**
```
NEXT_PUBLIC_RAZORPAY_KEY_ID=rzp_test_xxxxx   # public, safe in browser
RAZORPAY_KEY_SECRET=xxxxx                     # SERVER ONLY — never NEXT_PUBLIC_
```

**2. Install the SDK** — `npm install razorpay`

**3. New server route** `POST /api/orders/[id]/pay` — creates a Razorpay Order for the order's `grandTotal × 100` (paise), saves `razorpay_order_id`, returns it.

**4. New server route** `POST /api/orders/[id]/verify` — receives `razorpay_payment_id`, `razorpay_order_id`, `razorpay_signature`; recomputes the HMAC-SHA256 signature with your secret; if it matches, sets `payment_status: 'paid'` and stores the payment id.

**5. DB migration** — add columns to `orders`: `razorpay_order_id`, `razorpay_payment_id`. (Plus a `'razorpay'`/`'online'` value for `payment_method`.)

**6. Checkout UI** — load `checkout.razorpay.com/v1/checkout.js`, open the modal with the order id, wire the success handler to call your verify route.

**7. CSP header** — `next.config.ts` already has a TODO comment for exactly this. Add the Content-Security-Policy allowlisting Razorpay once checkout works.

**8. (Recommended) Webhook** `POST /api/webhooks/razorpay` — Razorpay calls this server-to-server so a payment is recorded even if the buyer closes their browser before the redirect. More reliable than the client callback alone.
