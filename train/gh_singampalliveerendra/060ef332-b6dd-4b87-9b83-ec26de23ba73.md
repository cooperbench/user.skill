14	// Normalize the raw pickup_slots value into a clean array of slots. Accepts
15	// either the new array shape, the LEGACY single-object shape
16	// ({ days, time_from, time_to }) saved before multi-slot support, or null —
17	// always returns an array. Slots with no chosen days are dropped, so callers
18	// can persist `result.length ? result : null`.
19	export function normalizePickupSlots(raw: unknown): PickupSlot[] {
20	  const list = Array.isArray(raw) ? raw : raw ? [raw] : []
21	  const out: PickupSlot[] = []
22	  for (const s of list) {
23	    if (!s || typeof s !== 'object') continue
24	    const o = s as { days?: unknown; time_from?: unknown; time_to?: unknown }
25	    const days = Array.isArray(o.days)
26	      ? Array.from(new Set(o.days.map((d) => String(d)).filter(Boolean)))
27	      : []
28	    if (days.length === 0) continue
29	    out.push({
30	      days,
31	      time_from: typeof o.time_from === 'string' && o.time_from ? o.time_from : PICKUP_DEFAULT_FROM,
32	      time_to: typeof o.time_to === 'string' && o.time_to ? o.time_to : PICKUP_DEFAULT_TO,
33	    })
34	  }
35	  return out
36	}

## What's built (Swiggy/Zomato-style produce reviews)

**1. Database** — `scripts/produce-reviews-migration.sql` (⚠️ **must be run in Supabase SQL Editor before this works**)
- New `produce_reviews` table, one review per order (verified buyer)
- `rating_avg` + `review_count` cached on `produce_listings`
- RLS: public can read approved reviews; writes only via service-role API

**2. API** — `src/app/api/produce-reviews/route.ts`
- `POST`: a logged-in consumer submits a review for **their** order, only after it's **delivered/picked up**; enforces one-per-order; recomputes the listing's average
- `GET ?listing_id=`: public list of approved reviews + aggregate (for the modal)

**3. Buyer leaves a review** — order detail page (`/consumer/orders/[id]`)
- Once the order is completed, a **"Rate {produce}"** box appears (star picker + optional comment)
- If already reviewed, it shows their submitted rating instead
- Order API now returns `produce_listing_id` + the buyer's existing review

**4. Other buyers see reviews** — consumer browse (`ProduceCard`)
- Each card shows a **`4.5 ★ · 12 reviews`** chip when reviews exist
- Tapping opens a bottom-sheet modal listing all reviews with the rating breakdown

**Kept separate** from the existing farmer-level reviews, exactly as you chose.

**Eligibility flow:** order delivered/picked-up → buyer opens the order → rates the produce → it appears (aggregated) on that produce's card for everyone else.

Two notes:
- The **migration must be run first** — until then the API will error since the table/columns don't exist.
- Reviews are tied to `consumer_id`, so only logged-in buyers (not guest-phone-only orders without a consumer account) can review. That matches the "verified buyer" model.
