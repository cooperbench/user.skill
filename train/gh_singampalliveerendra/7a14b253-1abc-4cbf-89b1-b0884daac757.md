Honest answer: **right now, a farmer who forgot their password cannot recover it themselves.** Here's the current state of the code: - **Login** (`/farmer/login`) is phone + password only. There is **no "Forgot password?" link.** - The only password-change endpoint, `/api/auth/reset-password`, despite its name, is a *change-while-logged-in* flow. It requires **both**: 1. a valid farmer session cookie (`getFarmerSessionFromRequest`), and 2. the **current password** (verified against the stored hash). So a farmer who forgot the password can't log in to get a session, and can't supply the current password → they're locked out. The only recovery today is **manual**: someone updates `farmers.password_hash` in Supabase directly (e.g. a moderator/admin), or via SQL. ## How to actually fix it Farmers authenticate by **phone number**, and Twilio WhatsApp is already on the roadmap — so the natural self-service flow is a **phone OTP reset**: | Step | What happens | |------|-------------| | 1 | Add "Forgot password?" link on `/farmer/login` | | 2 | Farmer enters their 10-digit phone | | 3 | `POST /api/auth/forgot-password` — generate a 6-digit OTP, store it hashed with a short expiry (e.g. `password_resets` table), send via WhatsApp/SMS | | 4 | Farmer enters OTP + new password | | 5 | `POST /api/auth/reset-password-otp` — verify OTP (not expired, not used, rate-limited), then `hashPassword(newPassword)` and update | This reuses `hashPassword` from `src/lib/password.ts` and the `rateLimit` helper already used in the existing route. **Interim option without Twilio:** add an **admin/moderator "reset farmer password"** action that sets a temporary password and shows it once, so support can unlock a farmer over a phone call.
