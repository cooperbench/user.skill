### **Technical Architecture (High-Level)**

**Four decoupled layers communicating exclusively through PostgreSQL:**

```
Ingestion Layer (Docker Hub, GitHub)
    ↓ [INSERT release + River job in single TX — Transactional Outbox]
PostgreSQL + River Queue
    ↓ [FOR UPDATE SKIP LOCKED — exactly-once processing]
Notification Routing (Slack, Discord, webhooks)
    ↓ [Source-level subscriptions notify immediately]
Agent Layer (ADK-Go + Gemini)
    ↓ [Researches releases, produces semantic reports]
Project-Level Subscriptions (AI-generated intelligence → channels)
```

**Key Design Principles:**
- Single binary (Go backend + embedded Next.js frontend)
- Zero-loss eventing (transactional outbox + River)
- Abstracted intelligence (works without LLM, graceful degradation)
- Extensible via interfaces (`IIngestionSource`, `Sender`)
- Project-centric data model (projects own sources, context sources, semantic releases)

     2→  if (!dateStr) return "\u2014";
     3→  const diff = Date.now() - new Date(dateStr).getTime();
     4→  const mins = Math.floor(diff / 60000);
     5→  if (mins < 60) return `${mins}m ago`;
     6→  const hrs = Math.floor(mins / 60);
     7→  if (hrs < 24) return `${hrs}h ago`;
     8→  return `${Math.floor(hrs / 24)}d ago`;

#### 1e. Implement `GetTrend` on `PgStore` in `/Users/pc/web3/ReleaseBeacon/internal/api/pgstore.go`

This is the core SQL logic. The query uses `generate_series` to produce zero-fill buckets, then LEFT JOINs against both `releases` and `semantic_releases`:

```go
func (s *PgStore) GetTrend(ctx context.Context, granularity string) (*TrendResponse, error) {
    var truncUnit string
    var interval string
    var bucketCount int

    switch granularity {
    case "daily":
        truncUnit = "day"
        interval = "29 days"   // 30 buckets including today
        bucketCount = 30
    case "weekly":
        truncUnit = "week"
        interval = "11 weeks"  // 12 buckets including current week
        bucketCount = 12
    case "monthly":
        truncUnit = "month"
        interval = "11 months" // 12 buckets including current month
        bucketCount = 12
    default:
        return nil, fmt.Errorf("invalid granularity: %s", granularity)
    }

    query := fmt.Sprintf(`
        WITH buckets AS (
            SELECT generate_series(
                date_trunc('%s', NOW() - INTERVAL '%s'),
                date_trunc('%s', NOW()),
                INTERVAL '1 %s'
            ) AS period
        ),
        rel_counts AS (
            SELECT date_trunc('%s', COALESCE(released_at, created_at)) AS period,
                   COUNT(*) AS cnt
            FROM releases
            WHERE COALESCE(released_at, created_at) >= date_trunc('%s', NOW() - INTERVAL '%s')
            GROUP BY 1
        ),
        sr_counts AS (
            SELECT date_trunc('%s', created_at) AS period,
                   COUNT(*) AS cnt
            FROM semantic_releases
            WHERE status = 'completed'
              AND created_at >= date_trunc('%s', NOW() - INTERVAL '%s')
            GROUP BY 1
        )
        SELECT b.period::date,
               COALESCE(r.cnt, 0),
               COALESCE(sr.cnt, 0)
        FROM buckets b
        LEFT JOIN rel_counts r  ON r.period = b.period
        LEFT JOIN sr_counts sr ON sr.period = b.period
        ORDER BY b.period
    `, truncUnit, interval, truncUnit, truncUnit,
       truncUnit, truncUnit, interval,
       truncUnit, truncUnit, interval)

    rows, err := s.pool.Query(ctx, query)
    if err != nil {
        return nil, fmt.Errorf("trend query: %w", err)
    }
    defer rows.Close()

    var buckets []TrendBucket
    for rows.Next() {
        var b TrendBucket
        var period time.Time
        if err := rows.Scan(&period, &b.Releases, &b.SemanticReleases); err != nil {
            return nil, fmt.Errorf("scan trend bucket: %w", err)
        }
        b.Period = period.Format("2006-01-02")
        buckets = append(buckets, b)
    }

    return &TrendResponse{
        Granularity: granularity,
        Buckets:     buckets,
    }, nil
}
```

**Important:** Use `fmt.Sprintf` for the `date_trunc` units since they cannot be parameterized in PostgreSQL ($1 params). The granularity value is validated to exactly three string literals before reaching this function, so there is no SQL injection risk.
