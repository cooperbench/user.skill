> AGENT

In dev mode, `next.config.ts` sets `output` to `undefined` — Next.js runs as a normal server with dynamic routing. The server renders each page on-the-fly, so `useParams()` gets the real ID from the request URL. In production, `output: "export"` generates fully static HTML files. The only dynamic page generated is `/projects/0` (from `generateStaticParams`). When the Go server serves `projects/0.html` for `/projects/some-uuid`, the RSC payload embedded in that HTML has `id = "0"` hardcoded. Next.js hydrates from that payload, so `useParams()` returns `"0"` — it never looks at `window.location`. The fix (`getPathSegment`) bypasses Next.js routing entirely and reads from `window.location.pathname`, which always has the real URL regardless of what HTML file was served.
