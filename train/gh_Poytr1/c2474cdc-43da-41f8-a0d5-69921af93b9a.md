# Switch GitHub Source from Atom Feed to REST API

## Context

The GitHub source currently uses the Atom feed (`/releases.atom`) which doesn't include the `prerelease` boolean. To support "Exclude Pre-Releases" for GitHub sources, we need to switch to the GitHub REST API (`/repos/{owner}/{repo}/releases`) which provides `prerelease`, `draft`, `body` (markdown changelog), and richer metadata.

The `prerelease` field will be stored in the release's `raw_data` JSONB as `"prerelease": "true"/"false"`. Users can then use the existing `version_filter_exclude` with a separate mechanism — or we add a dedicated boolean toggle on the source. Since the user's description showed a dedicated "Exclude Pre-Releases" toggle, we'll add an `exclude_prereleases` boolean to the `Source` model.

    46	func (s *GitHubAtomSource) FetchNewReleases(ctx context.Context) ([]IngestionResult, error) {
    47	feedURL := fmt.Sprintf("%s/%s/releases.atom", s.baseURL, s.repository)
    48	
    48	req, err := http.NewRequestWithContext(ctx, http.MethodGet, feedURL, nil)
    49	if err != nil {
    50		return nil, fmt.Errorf("create request: %w", err)
    51	}
    52	
    53	resp, err := s.client.Do(req)
    54	if err != nil {
    55		return nil, fmt.Errorf("fetch atom feed: %w", err)
    56	}
    57	defer resp.Body.Close()
    58	
    59	if resp.StatusCode != http.StatusOK {
    60		return nil, fmt.Errorf("unexpected status: %d", resp.StatusCode)
    61	}
    62	
    63	var feed atomFeed
    64	if err := xml.NewDecoder(resp.Body).Decode(&feed); err != nil {
    64 return nil, fmt.Errorf("decode atom feed: %w", err)
    65	}
    66	
    66	results := make([]IngestionResult, 0, len(feed.Entries))
    67	for _, entry := range feed.Entries {
    68		version := extractVersion(entry.ID)
    69		if version == "" {
    70			continue
    71		}
    72		ts, _ := time.Parse(time.RFC3339, entry.Updated)
    73		results = append(results, IngestionResult{
    74		Repository: s.repository,
    75		RawVersion: version,
    76		Changelog:  entry.Content,
    77		Metadata:   map[string]string{"release_url": entry.Link.Href},
    78		Timestamp:  ts,
    79	})
    80	}
    81	return results, nil
    82	}
    83	
    84	// extractVersion extracts the tag name from an Atom entry ID.
    85	// Format: "tag:github.com,2008:Repository/15452919/v1.17.0" -> "v1.17.0"
    86	func extractVersion(id string) string {
    87	idx := strings.LastIndex(id, "/")
    88	if idx < 0 || idx == len(id)-1 {
    89		return ""
    90	}
    91	return id[idx+1:]
    92	}

    22	}
    23	
    24	// LoadEnabledSources queries all enabled sources and constructs the
    25	// appropriate IIngestionSource for each one based on provider.
    25 func (l *SourceLoader) LoadEnabledSources(ctx context.Context) ([]IIngestionSource, error) {
    26		rows, err := l.pool.Query(ctx,
    27		`SELECT id, provider, repository FROM sources WHERE enabled = true`)
    28		if err != nil {
    29		return nil, fmt.Errorf("query enabled sources: %w", err)
    30		}
    31		defer rows.Close()
    32	
    33		var sources []IIngestionSource
    34		for rows.Next() {
    35		var id string
    36		var sourceType, repository string
    37		if err := rows.Scan(&id, &sourceType, &repository); err != nil {
    38			return nil, fmt.Errorf("scan source row: %w", err)
    39		}
    40	
    41		src := l.buildSource(id, sourceType, repository)
    42		if src == nil {
    43			slog.Warn("unsupported source type, skipping",
    44				"id", id, "type", sourceType, "repo", repository)
    45			continue
    46		}
    47		sources = append(sources, src)
    48		}
    49		return sources, rows.Err()
    50	}

    52	// LookupSourceID finds the source ID for a given (provider, repository) pair.

    55		var id string

   415→## 4. SSE Real-Time Events
   416→
   417→### Endpoint
   418→
   419→| Method | Path               | Description                           |
   420→|--------|--------------------|---------------------------------------|
   421→| `GET`  | `/api/v1/events`   | SSE stream of real-time events        |
   422→
   423→### Architecture
   424→
   425→```
   426→PostgreSQL LISTEN/NOTIFY  →  Go listener goroutine  →  SSE broadcaster  →  connected clients
   427→```
   428→
   429→1. When a release is ingested (transactional outbox commits), a PostgreSQL trigger fires `NOTIFY release_events, '{...}'`
   430→2. A Go goroutine holds a persistent `LISTEN release_events` connection
   431→3. On notification, it broadcasts to all connected SSE clients via the `Broadcaster` (64-buffered channels, non-blocking send skips slow clients)
   432→
   433→### Event Types
   434→
   435→| Event Type | Payload | Triggered When |
   436→|------------|---------|----------------|
   437→| `release` | `{"type": "release", "id": "<uuid>"}` | New release ingested |
   438→| `semantic_release` | `{"type": "semantic_release", "id": "<uuid>"}` | Semantic release completed |
   439→| `connected` | — | Initial SSE handshake |

   444→
   445→### API Key
   446→
   447→Bearer token in the `Authorization` header:
   448→
   449→```
   450→Authorization: bearer [REDACTED]
   451→```
   452→
   453→- Keys prefixed with `rg_live_` (production) or `rg_test_` (development)
   454→- Stored hashed (SHA-256) in the database — raw key shown only once at creation

   456→- Set `NO_AUTH=true` to disable authentication entirely (development mode)

   460→## 6. Middleware Stack
   461→
   462→Applied in order to every `/api/v1/*` request:
   463→
   464→| Order | Middleware    | Responsibility                                                        |
   465→|-------|--------------|-----------------------------------------------------------------------|
   466→| 1     | Request ID   | Generate UUID, set `X-Request-ID` header, inject into `context`       |
   467→| 2     | Logger       | Structured JSON log: request ID, method, path, duration, status code  |
   468→| 3     | Recovery     | Catch panics, return 500 with request ID                              |
   469→| 4     | Rate Limit   | Token bucket per API key (10 rps, 20 burst); returns `Retry-After` header |
   470→| 5     | Auth         | Validate API key, reject 401 if missing/invalid (skip for `/health`, skip entirely when `NO_AUTH=true`) |
   471→
   472→All middleware uses the stdlib `func(http.Handler) http.Handler` pattern. Rate limiting uses Go's `golang.org/x/time/rate` — in-process token bucket keyed by API key, no external dependencies. CORS is applied at the server level.

   794→// EnqueueAgentRun creates an agent_run row and enqueues a River AgentJobArgs.
   795→// This follows the transactional outbox pattern for zero-loss guarantee.
   796→func (s *PgStore) EnqueueAgentRun(ctx context.Context, projectID, trigger, version string) error {
   797→	tx, err := s.pool.Begin(ctx)
   798→	if err != nil {
   799→		return fmt.Errorf("begin tx: %w", err)
   800→	}
   801→	defer tx.Rollback(ctx)
   802→
   803→	var runID string
   804→	err = tx.QueryRow(ctx,
   805→		`INSERT INTO agent_runs (project_id, trigger, version, status)
   806→		 VALUES ($1, $2, $3, 'pending')
   807→		 RETURNING id`, projectID, trigger, version,
   808→	).Scan(&runID)
   809→	if err != nil {
   810→		return fmt.Errorf("insert agent run: %w", err)
   811→	}
   812→
   813→	if s.river != nil {
   814→		_, err = s.river.InsertTx(ctx, tx, queue.AgentJobArgs{
   815→			AgentRunID: runID,
   816→			ProjectID:  projectID,
   817→			Version:    version,
   818→		}, nil)
   819→		if err != nil {
   820→			return fmt.Errorf("enqueue agent job: %w", err)
   821→		}
   822→	}
   823→
   824→	return tx.Commit(ctx)
   825→}

Good question on rate limits. Let me address that while continuing implementation.

**Rate limit comparison: Atom feed vs REST API**

- **Atom feed** (current): Uses unauthenticated web requests to `github.com/{repo}/releases.atom`. GitHub doesn't officially document rate limits for Atom feeds, but they're generally more lenient (~60 req/min unauthenticated).
- **REST API** (new): Unauthenticated = **60 requests/hour**. With `GITHUB_TOKEN` = **5,000 requests/hour**. The implementation already supports `GITHUB_TOKEN` env var for auth.

For this use case (polling at `poll_interval_seconds` default of 86,400 = 1/day per source), even unauthenticated REST API is fine. With 10 GitHub sources polling every hour, that's 240 req/day, well under the 1,440/day unauthenticated limit.

The `GITHUB_TOKEN` support is already baked in — just set the env var and you get 5,000 req/hour. I don't think we need retry-on-429 logic since the polling intervals are so large, but if you'd like me to add it I can.

> AGENT

I'd keep it. They serve different purposes:

- **Source-level version filters** — control what gets ingested/shown globally for that source. Applies to all subscribers.
- **Subscription-level version filter** — lets individual notification channels filter further. One team might only care about major releases, another about everything.

Example: A source includes all non-prerelease versions, but a Slack channel subscription filters to `^\d+\.0\.0$` to only get notified on majors.

Removing the subscription filter would force everyone subscribed to a source to get the same notifications, which loses flexibility. The cost of keeping it is near zero.
