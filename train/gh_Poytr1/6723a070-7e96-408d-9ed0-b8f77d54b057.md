### Automating changelog updates on release

A common approach is to use **conventional commits** (which you're already doing — `feat:`, `fix:`, `docs:`, etc.) combined with a tool that generates changelogs from them. Popular options:

| Tool | How it works |
|------|-------------|
| [`git-cliff`](https://git-cliff.org/) | Rust-based, highly configurable, parses conventional commits into grouped changelog entries. Works great with `Makefile` targets. |
| [`goreleaser`](https://goreleaser.com/) | Go-focused. Generates changelogs *and* builds/publishes binaries in one step. |
| GitHub Actions | Use `git-cliff` or `goreleaser` in a CI workflow triggered on tag push. |

A simple Makefile target example with `git-cliff`:

```makefile
release:
	@test -n "$(VERSION)" || (echo "Usage: make release VERSION=v0.2.0" && exit 1)
	git-cliff --tag $(VERSION) -o CHANGELOG.md
	git add CHANGELOG.md
	git commit -m "docs: update CHANGELOG.md for $(VERSION)"
	git tag -a $(VERSION) -m "$(VERSION)"
```

### Publishing binaries on tag

```yaml
builds:

release:
  github:
    owner: sentioxyz
```

2. Add a GitHub Actions workflow (`.github/workflows/release.yml`):
```yaml
on:
  push:
    tags: ["v*"]
jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-go@v5
        with: { go-version: '1.25' }
      - uses: goreleaser/goreleaser-action@v6
        with:
          args: release --clean
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Then `git push --tags` triggers the full pipeline: build, changelog, and publish.
