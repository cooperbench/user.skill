## Design Section 1: Database Schema New `release_todos` table: ```sql CREATE TABLE release_todos ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), release_id UUID REFERENCES releases(id) ON DELETE CASCADE, semantic_release_id UUID REFERENCES semantic_releases(id) ON DELETE CASCADE, status VARCHAR(20) NOT NULL DEFAULT 'pending', created_at TIMESTAMPTZ DEFAULT NOW(), acknowledged_at TIMESTAMPTZ, resolved_at TIMESTAMPTZ, CHECK ( (release_id IS NOT NULL AND semantic_release_id IS NULL) OR (release_id IS NULL AND semantic_release_id IS NOT NULL) ), UNIQUE(release_id), UNIQUE(semantic_release_id) ); ``` Key points: - **1:1 relationship** — each release or semantic release has at most one TODO (enforced by UNIQUE constraints) - **CHECK constraint** — exactly one of `release_id` or `semantic_release_id` must be set (same pattern as `subscriptions`) - **CASCADE deletes** — if the underlying release is deleted, the TODO is cleaned up - **Status transitions:** `pending` → `acknowledged` → `resolved` (one-directional, though we'll allow re-setting to any state via API) **When are TODOs created?** During notification routing — when the `NotifyWorker` processes a release, it also inserts a `release_todos` row. ## Design Section 5: TODO Creation Flow **When does a TODO get created?** A TODO is created at the same point notifications are sent — in the `NotifyWorker`. This ensures: 1. Every notified release gets a TODO (they're paired) 2. It's transactional — if the worker fails, no orphaned TODOs 3. Filtered/excluded releases don't get TODOs (they never reach the worker) **Source releases:** In `NotifyWorker.Work()`, after fetching the release and before iterating subscriptions, insert a `release_todos` row with `release_id` set. Use `ON CONFLICT DO NOTHING` so re-processing a job doesn't create duplicates (the UNIQUE constraint on `release_id` protects us). **Semantic releases:** The semantic release notification happens in the agent orchestrator after completing a semantic release. At that point, insert a `release_todos` row with `semantic_release_id` set, same `ON CONFLICT DO NOTHING` pattern. **Flow diagram:** ``` New release detected → INSERT release (ingestion) → Enqueue NotifyJobArgs (transactional outbox) → NotifyWorker picks up job → INSERT release_todos (release_id, status='pending') ON CONFLICT DO NOTHING → Get todo ID (for button URLs) → Send notifications with acknowledge/resolve URLs → Check agent rules → maybe enqueue AgentJobArgs Agent completes semantic release → INSERT release_todos (semantic_release_id, status='pending') ON CONFLICT DO NOTHING → Get todo ID → Send semantic release notifications with URLs ``` **Key detail:** The TODO must be inserted _before_ sending notifications, so the todo ID is available for constructing button URLs.
