## Design: Project Logos

### Logo Resolution

A new `ProjectLogo` component that:

1. **Takes a project + its sources** as input
2. **Picks the best source** using priority: GitHub > GitLab > Docker Hub > ECR
3. **Extracts the owner** from the `repository` field (the part before `/` in `owner/repo`)
4. **Constructs the avatar URL** client-side:
   - **GitHub**: `https://github.com/{owner}.png?size=64`
   - **GitLab**: `https://gitlab.com/uploads/-/system/group/avatar/{owner}` — actually GitLab doesn't have a simple public avatar URL pattern, so we'd need to use the GitLab API or skip GitLab avatar resolution and fall back to the initial-based placeholder for GitLab sources
   - **Docker Hub**: No public org avatar endpoint — fall back to placeholder
   - **ECR**: No public org avatar — fall back to placeholder

So in practice, **GitHub is the main logo source**, and GitLab/Docker/ECR fall back to the initial-based placeholder.

### Placeholder

When no avatar URL is available or the image fails to load:
- Colored circle with the **first letter** of the project name
- Color derived deterministically from the project name (hash → hue) so each project gets a consistent, distinct color

### Where It Shows

1. **Projects list page (card view)** — logo next to the project name in each card header
2. **Projects list page (compact view)** — small logo in the name column
3. **Project detail page** — logo next to the project name in the header

### Component Size

- Card view: ~40px
- Compact view: ~24px  
- Detail page header: ~48px

The component accepts a `size` prop to handle these variations.

    38→function formatDuration(startedAt?: string, completedAt?: string): string {
    39→  if (!startedAt) return "--";
    40→  const start = new Date(startedAt).getTime();
    41→  const end = completedAt ? new Date(completedAt).getTime() : Date.now();
    42→  const secs = Math.round((end - start) / 1000);
    43→  if (secs < 60) return `${secs}s`;
    44→  const mins = Math.floor(secs / 60);
    45→  const rem = secs % 60;
    46→  return `${mins}m ${rem}s`;
    47→}
    48→
    49→function truncate(str: string, max: number): string {
    50→  return str.length > max ? str.slice(0, max) + "\u2026" : str;
    51→}

## Getting a Group's `avatar_url` from the GitLab API

### Retrieve via Group Details Endpoint

The `avatar_url` is returned as part of the group details response:

```
GET /groups/:id
```

### Public Access (No Authentication Required)

Yes, there is a public endpoint. As the docs state: "This endpoint can be accessed without authentication if the group is publicly accessible."

So for **public groups**, you can simply call:

```bash
curl --url "https://gitlab.example.com/api/v4/groups/4"
```

The response includes `avatar_url` as a field, e.g.:

```json
"avatar_url": "http://localhost:3000/uploads/group/avatar/1/foo.jpg"
```

### Download the Avatar Directly

There's also a dedicated avatar download endpoint:

```
GET /groups/:id/avatar
```

The docs note this endpoint "can be accessed without authentication if the group is publicly accessible."

```bash
curl --remote-header-name --remote-name \
  --url "https://gitlab.example.com/api/v4/groups/4/avatar"
```

### URL Pattern

Based on the example responses, the avatar URL pattern is:

```
https://<gitlab-instance>/uploads/group/avatar/<group_id>/<filename>
```

Or on GitLab.com:

```
https://<gitlab-instance>/uploads/-/system/group/avatar/<group_id>/<filename>
```

The `avatar_url` field is also included in the **list groups** (`GET /groups`) response, so you can retrieve it for multiple groups at once without authentication (for public groups).
