## Design: GitLab Provider The GitLab provider follows the exact same pattern as the GitHub provider. Here's the design: ### Data Source - **API**: GitLab REST API v4 — `GET /api/v4/projects/:id/releases` ([docs](https://docs.gitlab.com/api/releases/)) - **Base URL**: `https://gitlab.com` (hardcoded, self-hosted later) - **Repository format**: `owner/repo` (URL-encoded as `owner%2Frepo` for the API path) - **Auth**: `GITLAB_TOKEN` env var → `PRIVATE-TOKEN` header - **Pagination**: 20 per page (configurable via `per_page`), keyset/offset pagination - **Filtering**: Exclude drafts (same as GitHub). Support `exclude_prereleases` via the upcoming_release field or release metadata. ### Mapped Fields (GitLab → IngestionResult) | GitLab field | IngestionResult field | |---|---| | `tag_name` | `RawVersion` | | `description` | `Changelog` | | `released_at` | `Timestamp` | | `_links.self` | `Metadata["release_url"]` | | `upcoming_release` | `Metadata["prerelease"]` (for `exclude_prereleases` support) | ### Files Changed 1. **`internal/ingestion/gitlab.go`** — New source implementation (~100 lines, mirrors `github.go`) 2. **`internal/ingestion/gitlab_test.go`** — Unit tests with mock HTTP server 3. **`internal/ingestion/loader.go`** — Add `"gitlab"` case to `BuildSource()` switch 4. **`internal/api/providers.go`** — Add `"gitlab"` to static provider list 5. **`web/components/sources/source-form.tsx`** — Add "GitLab" to provider dropdown, show `exclude_prereleases` for gitlab too 6. **`web/lib/format.ts`** — Add GitLab to repository validation (same `owner/repo` format) ### What doesn't change - Database schema (provider is just a string, no migration needed) - API endpoints (sources API is provider-agnostic) - Orchestrator/polling logic (loads sources dynamically) - Notification flow (works on any source) Does this design look right to you?
