## Approaches

Here are 3 approaches for the discovery section, with trade-offs:

### Approach A: Backend-Proxied Discovery (Recommended)

Add new Go API endpoints (`GET /api/v1/discover/github`, `GET /api/v1/discover/dockerhub`) that fetch trending/popular repos from GitHub Search API and Docker Hub, cache results in-memory (TTL ~1 hour), and return them normalized. The frontend renders a new `DiscoverySection` component at the top of the dashboard with two tabs (GitHub / Docker Hub), showing cards with a one-click "Track" button that creates project + source in one API call.

**Pros:** Clean separation, caching avoids rate limits, normalized data, works with static export (no CORS issues).  
**Cons:** Requires Go backend changes, adds 2 new endpoints.

### Approach B: Client-Side Direct Fetch

The frontend fetches GitHub/Docker Hub APIs directly from the browser. No backend changes needed.

**Pros:** Fastest to build, no Go changes.  
**Cons:** CORS issues (Docker Hub API doesn't support browser CORS), GitHub rate limits (60/hr unauthenticated) hit quickly, can't cache across users, exposes API usage patterns.

func RegisterRoutes(mux *http.ServeMux, deps Dependencies) {
    // Create two middleware chains:
    // 1. Public chain (no auth required)
    publicChain := Chain(RequestID, Logger, Recovery)
    
    // 2. Authenticated chain (includes auth if NoAuth not set)
    chain := publicChain

    }

## 4. Middleware Chain

**File**: `/Users/pc/web3/ReleaseBeacon/internal/api/middleware.go`

Middleware are composable functions that wrap handlers:

```go
// Middleware type definition
type Middleware func(http.Handler) http.Handler

// Chaining function applies multiple middleware in reverse order
func Chain(mws ...Middleware) Middleware {
    return func(final http.Handler) http.Handler {
        for i := len(mws) - 1; i >= 0; i-- {
            final = mws[i](final)
        }
        return final
    }
}

// 1. RequestID middleware - adds UUID and stores in context
func RequestID(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        id := uuid.New().String()
        w.Header().Set("X-Request-ID", id)
        next.ServeHTTP(w, r.WithContext(withRequestID(r.Context(), id)))
    })
}

// 2. Logger middleware - logs request with duration
func Logger(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        sw := &statusWriter{ResponseWriter: w, status: http.StatusOK}
        next.ServeHTTP(sw, r)
        slog.Info("request",
            "request_id", getRequestID(r.Context()),
            "method", r.Method,
            "path", r.URL.Path,
            "status", sw.status,
            "duration_ms", time.Since(start).Milliseconds(),
        )
    })
}

// 3. Recovery middleware - catches panics
func Recovery(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        defer func() {
            if err := recover(); err != nil {
                slog.Error("panic recovered", "request_id", getRequestID(r.Context()), "error", err)
                RespondError(w, r, http.StatusInternalServerError, "internal_error", "Internal server error")
            }
        }()
        next.ServeHTTP(w, r)
    })
}

// 4. Auth middleware - validates API key from Authorization header
func Auth(store KeyStore) Middleware {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            header := r.Header.Get("Authorization")
            if !strings.HasPrefix(header, "Bearer ") {
                RespondError(w, r, http.StatusUnauthorized, "unauthorized", "Missing API key")
                return
            }
            rawKey := strings.TrimPrefix(header, "Bearer ")
            valid, err := store.ValidateKey(r.Context(), rawKey)
            if err != nil || !valid {
                RespondError(w, r, http.StatusUnauthorized, "unauthorized", "Invalid API key")
                return
            }
            go store.TouchKeyUsage(context.Background(), rawKey)  // async usage tracking
            next.ServeHTTP(w, r)
        })
    }
}

// 5. RateLimit middleware - per-key rate limiting (10 RPS, 20 burst)
func RateLimit(rps float64, burst int) Middleware {
    var mu sync.Mutex
    limiters := make(map[string]*rate.Limiter)
    getLimiter := func(key string) *rate.Limiter {
        mu.Lock()
        defer mu.Unlock()
        if lim, ok := limiters[key]; ok {
            return lim
        }
        lim := rate.NewLimiter(rate.Limit(rps), burst)
        limiters[key] = lim
        return lim
    }
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            key := r.RemoteAddr
            if auth := r.Header.Get("Authorization"); strings.HasPrefix(auth, "Bearer ") {
                key = strings.TrimPrefix(auth, "Bearer ")
            }
            lim := getLimiter(key)
            if !lim.Allow() {
                w.Header().Set("Retry-After", "1")
                RespondError(w, r, http.StatusTooManyRequests, "rate_limited", "Too many requests")
                return
            }
            next.ServeHTTP(w, r)
        })
    }
}

// CORS middleware - allows cross-origin requests
func CORS(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Access-Control-Allow-Origin", "*")
        w.Header().Set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
        w.Header().Set("Access-Control-Allow-Headers", "Content-Type, Authorization")
        w.Header().Set("Access-Control-Max-Age", "86400")
        if r.Method == http.MethodOptions {
            w.WriteHeader(http.StatusNoContent)
            return
        }
        next.ServeHTTP(w, r)
    })
}
```

**Key Patterns**:
- Middleware uses `func(http.Handler) http.Handler` signature
- `Chain()` applies middleware in reverse order (last-first execution during request)
- Request ID stored in context and available in all handlers
- Rate limiting is per-key (API key or IP), using `golang.org/x/time/rate.Limiter`
- Auth validates token and touches usage asynchronously

    results, err := ingestionSrc.FetchNewReleases(r.Context())
    if err != nil {
        slog.Error("fetch releases failed", "source", src.ID, "err", err)
        RespondError(w, r, http.StatusBadGateway, "upstream_error", "Failed to fetch releases from upstream")
        return
    }
    
    // 5. Process and persist results
    newCount := 0
    if len(results) > 0 && h.ingestionService != nil {
        for _, result := range results {
            if procErr := h.ingestionService.ProcessResults(r.Context(), src.ID, src.Provider, []ingestion.IngestionResult{result}); procErr != nil {
                slog.Error("process release failed", "source", src.ID, "version", result.RawVersion, "err", procErr)
                continue
            }
            newCount++
        }
    }
    
    // 6. Return results
    RespondJSON(w, r, http.StatusOK, map[string]int{"new_releases": newCount})
}
```

## Issues

### Critical

**1. Query parameter is not URL-encoded -- injection/breakage risk**

In both the `GitHub` and `DockerHub` methods, user-supplied query parameters are interpolated directly into the URL string via `fmt.Sprintf` without URL encoding:

```go
// discover.go line 91
url := fmt.Sprintf("%s/search/repositories?q=%s&sort=stars&order=desc&per_page=25", h.githubURL, searchQ)

// discover.go line 139
url := fmt.Sprintf("%s/v2/search/repositories/?query=%s&page_size=25", h.dockerHubURL, q)
```

If a user passes `q=foo&sort=updated` or `q=foo%26sort=updated`, the attacker can inject arbitrary query parameters into the upstream API call. This also breaks on any query containing spaces, `#`, `&`, or other reserved characters.

**Fix:** Use `net/url.QueryEscape(searchQ)` or build the URL with `url.URL` and `url.Values`.

---

### Important

**2. No validation on the `q` parameter for GitHub endpoint**

The `DockerHub` method defaults `q` to `"nginx"` when empty (line 133), but the `GitHub` method sends an empty string to the GitHub Search API when `q` is missing. An empty query will return a 422 from GitHub's API, which will be proxied as a generic `upstream_error`. This is confusing for callers.

Either return a 400 validation error when `q` is empty, or provide a sensible default as the Docker Hub endpoint does.

**3. `language` parameter is not sanitized**

The `language` query parameter is appended directly into the GitHub search query:

```go
// discover.go line 88
searchQ = fmt.Sprintf("%s language:%s", q, language)
```

An attacker could pass `language=Go+stars:>0+is:public` to inject additional GitHub search qualifiers. While this is proxied to GitHub and not a SQL injection vector, it can be used to manipulate search results in unintended ways. Consider validating `language` against a known set of programming languages or at minimum stripping special GitHub search qualifier characters.

**4. Unbounded cache growth**

The cache is a plain `map[string]cachedResult` that grows without bound. Each unique `(q, language)` combination creates a new entry that is never evicted (expired entries are only skipped on read, never deleted). In a public-facing API, this is a memory leak. Over time, or under targeted abuse, the map will grow indefinitely.

**Fix:** Either (a) evict expired entries in `getCached` when they are stale, (b) add a periodic cleanup goroutine, or (c) cap the map size with an LRU eviction policy.

**5. Discover routes are not registered in `server.go`**

Looking at `/Users/pc/web3/ReleaseBeacon/internal/api/server.go`, the `RegisterRoutes` function has no `discover` routes. The handler is implemented but not wired. This is noted as Task 3 in the plan, so it is expected, but worth calling out: the handler is unreachable in production until the routes are registered.

**6. Missing Docker Hub test**

The test file only covers the GitHub handler. There is no test for `DockerHub`. It appears this is planned as Task 2, but the commit message says "GitHub and Docker Hub search" which implies both are covered. The Docker Hub handler should have parity test coverage, including:

**7. No cache-hit test**

There is no test verifying that the caching mechanism works (i.e., a second request with the same `q` does not hit the upstream mock). This would be easy to add by counting mock server invocations.

**8. Docker Hub URL construction for non-official images**

```go
// discover.go line 162
URL: fmt.Sprintf("https://hub.docker.com/_/%s", repo.RepoName),
```

The `/_/` path prefix is for official images. Non-official images use `/r/<namespace>/<name>`. Currently every Docker Hub result gets the `/_/` URL, which will produce broken links for community/non-official images.

**9. Test uses `Fatalf` instead of `Errorf` for non-terminal assertions**

The test uses `t.Fatalf` for every assertion, which stops the test on the first failure. For the field-level assertions after the response has been decoded (lines 59-66), `t.Errorf` would allow all field checks to run and report all failures at once, making debugging easier.
