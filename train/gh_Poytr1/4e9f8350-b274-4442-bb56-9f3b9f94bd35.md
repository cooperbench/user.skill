## Root Cause Found it. `ReleaseItem.RawData` (line 35) and `GetReleaseDetailOutput.RawData` (line 58) are typed as `json.RawMessage`, which is `type RawMessage []byte`. When ADK-Go's `functiontool` generates the JSON schema from the Go struct, it sees `[]byte` → infers JSON type `"array"` (array of bytes). But the actual database content in `raw_data` is a JSON **object** (e.g., `{"changelog": "...", "release_url": "..."}`). This works fine with the production River worker because the orchestrator just consumes the raw text output. But the ADK launcher validates tool return values against the schema, causing this validation error. **The fix:** Change `json.RawMessage` to `any` (or `map[string]any`) so the schema says "object" or accepts any type. Since `raw_data` can be any JSON shape, `any` is the correct type.
