## Why your opencode is slow

**The #1 bottleneck is NanoGPT as a proxy.** Every single model call routes through `https://nano-gpt.com/api/v1` — that's an extra network hop on every request. And you're using thinking variants (`:thinking`) on most agents, which compounds the latency since thinking tokens take time to generate *and* transmit through the proxy.

**Multi-agent overhead.** Your setup has plan → build → explore → quik agents, each potentially making separate LLM calls. A task that Claude Code handles in one shot (one model, one context) might trigger 2-3 sequential model calls in your opencode setup — each going through NanoGPT.

## Key differences vs Claude Code

| | Claude Code | Your opencode |
|---|---|---|
| **API** | Direct to Anthropic (no proxy) | NanoGPT proxy → various models |
| **Model** | Single Opus/Sonnet (very fast inference) | 10+ models, many thinking variants |
| **Architecture** | One agent, smart tool routing | Multi-agent with handoffs (plan/build/explore/quik) |
| **Context** | 1M context, built-in compression | Varies by model (32k–262k) |
| **Tools** | Native, tightly integrated | Generic via `@ai-sdk/openai-compatible` |

## What I'd focus on to close the gap

1. **Try direct API access** — if any of these model providers offer direct endpoints, skip NanoGPT. The proxy latency stacks up fast.
2. **Reduce agent hops** — Claude Code works well with a single agent because the model is strong enough. If your models are strong enough, consolidating to fewer agents means fewer round-trips.
3. **Be selective with `:thinking`** — only use thinking variants for genuinely complex planning. Your `oh-my-opencode.json` has thinking on almost everything including the librarian and explore agents, which probably don't need deep reasoning.
4. **Smaller context models are fine for subagents** — but the 32k context on `big-pickle` is pretty tight for a coding agent.

### 2. How the Built-in Modes Actually Work (from `opencode agent list` on your machine)

The key difference between **build** and **plan** is purely in permissions:

## Opencode Memory/Persistence System -- Research Findings

### 1. Does opencode have a memory system like Claude Code's CLAUDE.md?

**Yes, and it is directly compatible.** Opencode searches for instruction files in this priority order:

- **`AGENTS.md`** -- opencode's native convention (always loaded)
- **`CLAUDE.md`** -- loaded for Claude Code compatibility (can be disabled via `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT` flag)
- **`CONTEXT.md`** -- listed but marked deprecated

This means opencode reads existing `CLAUDE.md` files from Claude Code projects out of the box.

### 2. How does opencode persist context across sessions?

Opencode uses a **SQLite database** (via Drizzle ORM) to persist sessions, messages, and metadata. Key behaviors:

- **Sessions are fully resumable** -- all message history, file diffs, agent settings, and model selections are persisted to the database and can be restored after restart.
- **Context compaction** -- when context windows fill up, opencode uses a compaction system that summarizes older conversation turns while preserving recent ones verbatim (configurable via `compaction.tail_turns`, `compaction.preserve_recent_tokens`).
- **Snapshots** -- file changes are tracked via an internal git repository, enabling undo/revert within sessions.
- **No automatic cross-session memory** -- there is no equivalent to Claude Code's "auto-memory" that automatically writes learned preferences to a file. Knowledge does not automatically transfer between sessions.

### 3. Is there an AGENTS.md or similar file convention?

**Yes, `AGENTS.md` is opencode's primary instruction file convention.** Key details:

- Files are searched **hierarchically** -- `AGENTS.md` at any directory level is automatically loaded when the agent reads files in that subtree.
- **Global**: `~/.config/opencode/AGENTS.md`
- **Project**: found via `findUp()` from current directory to worktree root; the first match wins (no stacking from ancestor directories).
- **Contextual**: when reading a specific file, opencode walks up from that file's directory and attaches nearby `AGENTS.md` files (deduplicated per message).
- Content should be concise (1-3 lines per learning) and cover non-obvious discoveries.
- Opencode even has a **`/learn` command** (defined at `.opencode/command/learn.md`) that prompts the agent to extract non-obvious discoveries from the current session and write them into appropriately-scoped `AGENTS.md` files.

### 4. How does opencode handle system prompts, project context, and user preferences?

**System prompts** are assembled from multiple layers:

1. **Base prompt** -- built-in text files (`generate.txt`, agent-specific prompts like `explore.txt`, `scout.txt`)
2. **Instruction files** -- `AGENTS.md` / `CLAUDE.md` / `CONTEXT.md` discovered via hierarchy
3. **Config-specified instructions** -- the `instructions` array in `opencode.json` supports file paths, glob patterns (e.g., `.cursor/rules/*.md`), and HTTP URLs
4. **Skills** -- on-demand instruction sets in `SKILL.md` files under `.opencode/skills/<name>/` that agents can load via a `skill` tool
5. **Plugin system** -- plugins can transform system prompts via hooks

**Configuration** merges from 7+ sources (global, project, env vars, remote org config, MDM profiles), with instruction arrays **concatenated** rather than replaced across layers.

**Agents** are defined as:
- Markdown files with YAML frontmatter in `.opencode/agents/` or `~/.config/opencode/agents/`
- JSON in `opencode.json`
- Built-in defaults: `build` (full access), `plan` (read-only), `general`/`explore`/`scout` (subagents)

| Feature | Claude Code | Opencode |
|---|---|---|
| **Instruction file** | `CLAUDE.md` | `AGENTS.md` (also reads `CLAUDE.md` for compatibility) |
| **Auto-memory** | Yes -- Claude Code automatically writes learned preferences to `CLAUDE.md` | **No** -- opencode has a manual `/learn` command but no automatic writing |
| **Hierarchical instructions** | `CLAUDE.md` at project root + subdirectories + `~/.claude/CLAUDE.md` | Same pattern: root + subdirectory + `~/.config/opencode/AGENTS.md` |
| **Session persistence** | SQLite database, sessions resumable | Same -- SQLite via Drizzle, fully resumable |

| **Skills/commands** | Slash commands (built-in) | Both `/commands` (user-defined) and skills (`SKILL.md` -- on-demand instruction sets) |
