1	# Worktree E2E Environment Setup
2	
3	**Date:** 2026-03-30
4	**Context:** Testing a web-only FileList.tsx fix in a fresh git worktree
5	
6	## What I Learned
7	
8	### Fresh worktrees have no .env files
9	
10	Git worktrees are clean copies — `.env` files are gitignored and won't exist. Before running anything:
11	
12	1. Copy `.env` files from the main repo checkout (`../cipher-box/apps/`):
13	   - `apps/api/.env`
14	   - `apps/web/.env`
15	   - `tests/web-e2e/.env`
16	2. Run `pnpm install` — worktrees share the git index but not `node_modules`
17	
18	### For web-only changes, don't start the API locally
19	
20	If the change is web-only (e.g., a React component fix):
21	
22	1. Set `VITE_API_URL=https://api-staging.cipherbox.cc` in `apps/web/.env`
23	2. Start only the web dev server: `pnpm --filter @cipherbox/web dev`
24	3. Run E2E tests with `BASE_URL=http://localhost:5173`
25	
26	Do NOT start a local API — the web app talks directly to staging via `VITE_API_URL`. The Vite proxy (`/api` -> `localhost:3000`) is only used when `VITE_API_URL` is not set.
27	
28	### Playwright auto-starts servers when BASE_URL is localhost
29	
30	The Playwright config (`tests/web-e2e/playwright.config.ts`) has a `webServer` block that auto-starts mock-ipns-routing, the API, and the web app when `BASE_URL` is localhost. This is fine in CI but causes problems locally:
31	
32	- It starts a local API on port 3000 even if you don't want one
33	- If `VITE_API_URL` points at staging but Playwright also starts a local API, the two can conflict (different JWT secrets, different DB state)
34	- The `reuseExistingServer: !process.env.CI` flag means it reuses your running web dev server but still starts its own API
35	
36	This is usually fine — the web app uses `VITE_API_URL` directly and ignores the Playwright-started API. But some tests (e.g., page reload/session restore) may behave differently when the environment is mixed.
37	
38	### Don't overthink it — the simple path works
39	
40	For a web-only fix against staging:
41	
42	```bash
43	# 1. Copy env files
44	cp ../cipher-box/apps/api/.env apps/api/.env
45	cp ../cipher-box/apps/web/.env apps/web/.env
46	cp ../cipher-box/tests/web-e2e/.env tests/web-e2e/.env
47	
48	# 2. Install deps
49	pnpm install
50	
51	# 3. Point web at staging API
52	sed -i '' 's|VITE_API_URL=.*|VITE_API_URL=https://api-staging.cipherbox.cc|' apps/web/.env
53	
54	# 4. Start web dev server
55	pnpm --filter @cipherbox/web dev &
56	
57	# 5. Run the specific failing tests
58	BASE_URL=http://localhost:5173 pnpm --filter @cipherbox/web-e2e exec playwright test tests/<file>.spec.ts --timeout 180000
59	
60	# 6. Revert .env change before committing
61	```
62

64	
65	- Knowing upfront that `.env` files need to be copied from the main checkout
66	- Understanding that `VITE_API_URL` bypasses the Vite proxy entirely — no need to start a local API for web-only changes
67	- A checklist of env files to copy when setting up a worktree
68	
69	## Key Files
70	
71	- `apps/web/.env` — `VITE_API_URL` controls which API the web app talks to
72	- `apps/api/.env` — DB/IPFS/Redis connection config (only needed if running API locally)
73	- `tests/web-e2e/.env` — E2E test credentials
74	- `tests/web-e2e/playwright.config.ts` — webServer auto-start logic
75	- `apps/web/src/lib/api-config.ts` — where `VITE_API_URL` is read
