Full research is in. Here's the synthesis — it both **shrinks** and **sharpens** the scope:

## What Phase 48 already gives us (solid rails)
- `sharedFolderTree` (keyed by shareId), the client shared methods (`renameInSharedFolder`/`deleteFromSharedFolder`/etc.), `adoptSharedFolderResult`, the `sharedFolder:updated` event, and the web projection — all exist.
- The re-encrypt helper `reencryptFileMetadataForFolderChange` is **key-agnostic** (takes source/dest folderKey + fileIpnsPrivateKey) → reusable verbatim. The owner-side `moveItem` (publish-dest → re-key → publish-source → adopt) is the exact template to mirror.

## The real findings
1. **Confirmed gap:** there is no move at any layer for shares. The recipient's `SharedFileBrowser` `ContextMenu` has no `onMove` and there's no shared `MoveDialog`. So #8 is genuinely net-new UI + SDK method.
2. **Central design constraint:** `sharedFolderTree` holds **only one folder depth at a time** (re-seeded on navigation). A cross-subfolder move needs *both* source and destination `folderKey`/`ipnsPrivateKey`/`sequence` at once — so the move op must resolve the **destination** subfolder's keys on-demand from `share_keys` (the same `keyType: 'folder'`/`'folder-ipns'` recipient-unwrap that `navigateToSubfolder` does). It can't just read one state entry.
3. **Recipient write is per-subfolder:** navigation downgrades to read-only when no `folder-ipns` key exists. So a recipient can only move *into* a subfolder they hold a write key for — the picker must reflect that.
4. **`MoveDialog` can't be reused** — it reads the private `useFolderStore` tree, which the shared side doesn't have.
5. **#7 is a clean swap** — `FolderState` already exposes every crypto/data value; `id`/`name`/`parentId` are local. No SDK type change. Caveats to preserve: the web's 3× IPNS-propagation retry (else navigating into a just-created folder can fail), and cloning SDK-owned key buffers into `FolderNode` (use-after-zero on logout). The `ensureFolderLoaded` full-tree re-walk MEDIUM — the todo itself scoped its mitigation as "not needed today," so I'd **defer** that and keep this swap tight.
