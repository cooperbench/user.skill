## 1. FUSE-Related Rust Code Changes (crates/fuse/src/inode.rs)

### The Problem
The `populate_folder()` function in `InodeTable` is called periodically (every ~30s) to refresh folder metadata from IPNS. Before this fix, when processing `FilePointer` entries:

1. If an inode already existed and was marked as `file_meta_resolved=true`, the code preserved the entire `InodeKind` unchanged
2. This meant the CID, encrypted_file_key, iv, and size from the initial resolution were never updated
3. When a file was edited via the web UI (which published a new file metadata IPNS record with a new CID), the FUSE mount would see the folder change but skip re-resolving the file's individual IPNS metadata

### The Solution

**Modified Timestamp Detection (lines 428-459):**

The key change detects remote edits by comparing the incoming `modified_at` timestamp from the `FilePointer` with the existing inode's `mtime`:

```rust
let modified = UNIX_EPOCH + Duration::from_millis(file_pointer.modified_at);

let (was_resolved, existing_kind) = if let Some(existing) = existing_ino
    .and_then(|ino| self.inodes.get(&ino))
{
    match &existing.kind {
        InodeKind::File { file_meta_resolved: true, .. } => {
            // Compare the incoming modified_at with the
            // existing inode's mtime to detect remote edits.
            // Use != rather than > to handle clock skew
            // between clients (a remote edit from a client
            // with a behind clock could produce a smaller
            // modified_at).
            if modified != existing.attr.mtime {
                log::info!(
                    "File '{}': modified_at changed (remote edit detected), marking for re-resolution",
                    file_pointer.name
                );
                // Return (true, None) to signal:
                // - was_resolved=true (we had a resolved inode)
                // - existing_kind=None (don't use the old kind)
                (true, None)
            } else {
                (true, Some(existing.kind.clone()))
            }
        }
        _ => (false, None),
    }
} else {
    (false, None)
};
```

**Key Design Decisions:**
- Uses `!=` instead of `>` to handle clock skew between clients (a remote edit from a behind-clock client could have a smaller timestamp)
- Returns `(true, None)` to signal "had a resolved inode but needs re-resolution"
- Logs the detected change for debugging

**IPNS Key Preservation (lines 466-515):**

When `was_resolved=true` but `existing_kind=None`, the code creates a new **unresolved** `InodeKind::File` that preserves IPNS keys from the existing inode:

```rust
let kind = if let Some(existing_kind) = existing_kind {
    existing_kind
} else if was_resolved {
    // File was resolved but modified_at changed -- keep IPNS
    // keys from existing inode but mark as unresolved, unless
    // the FilePointer identity (IPNS name) changed, which
    // means this is a different file reusing the same name.
    let existing = existing_ino.and_then(|ino| self.inodes.get(&ino));
    let (prev_ipns_key, prev_ipns_key_enc_hex, prev_ipns_name, same_pointer) = 
        match existing.map(|e| &e.kind) {
            Some(InodeKind::File {
                file_ipns_private_key,
                file_ipns_key_encrypted_hex,
                file_meta_ipns_name,
                ..
            }) => {
                let same = file_meta_ipns_name.as_deref() == 
                    Some(file_pointer.file_meta_ipns_name.as_str());
                (
                    file_ipns_private_key.clone(),
                    file_ipns_key_encrypted_hex.clone(),
                    file_meta_ipns_name.clone(),
                    same,
                )
            }
            _ => (None, None, None, false),
        };
    
    InodeKind::File {
        cid: String::new(),                              // CLEARED - triggers re-resolution
        encrypted_file_key: String::new(),               // CLEARED
        iv: String::new(),                               // CLEARED
        size: 0,                                          // CLEARED
        encryption_mode: "GCM".to_string(),
        file_meta_ipns_name: if same_pointer {
            prev_ipns_name.or(Some(file_pointer.file_meta_ipns_name.clone()))
        } else {
            Some(file_pointer.file_meta_ipns_name.clone())
        },
        file_meta_resolved: false,                       // MARK AS UNRESOLVED
        file_ipns_private_key: if same_pointer { 
            prev_ipns_key                                // PRESERVE if same pointer
        } else { 
            None 
        },
        file_ipns_key_encrypted_hex: if same_pointer {
            prev_ipns_key_enc_hex                        // PRESERVE if same pointer
        } else {
            file_pointer.ipns_private_key_encrypted.clone()
        },
        versions: None,
    }
};
```

**Why This Works:**
1. Clears `cid`, `encrypted_file_key`, `iv`, `size` so the file is marked unresolved
2. Sets `file_meta_resolved=false` explicitly
3. Preserves `file_ipns_private_key` and `file_ipns_key_encrypted_hex` if the IPNS name is the same (same file pointer)
4. Updates IPNS name if the pointer changed (file was replaced)
5. This unresolved state triggers `drain_refresh_completions()` to spawn an async IPNS resolution for this file, picking up the new CID

## 3. Sync/Polling Mechanism

### How the Sync Works

**Desktop FUSE Mount:**
1. Metadata cache has a **30-second TTL**
2. After 30s, `readdir()` triggers a background refresh of folder metadata
3. `populate_folder()` is called with the refreshed metadata
4. **NEW:** It detects `modified_at` changes and marks files as unresolved
5. `drain_refresh_completions()` spawns async IPNS resolution for unresolved files
6. The new CID is fetched and stored in the inode
7. Subsequent reads use the new CID

**Web UI Edit Flow:**
1. User edits file in web UI
2. New content is encrypted and uploaded to IPFS (new CID)
3. Per-file IPNS metadata record is published with the new CID
4. Folder metadata is republished with updated `modified_at` for the FilePointer
5. Desktop FUSE mount detects the folder metadata change within ~30s

**Expected Sync Time:** ~30-60 seconds
- Up to 30s: FUSE metadata cache TTL
- Up to 30s: Per-file IPNS resolution after unresolved marking

/// Cached decrypted file content entry with LRU tracking.
struct CachedContent {
    data: Vec<u8>,
    accessed_at: Instant,
    size: usize,
}

impl Drop for CachedContent {
    fn drop(&mut self) {
        self.data.zeroize();
    }
}

/// In-memory LRU cache for decrypted file content, keyed by CID.
///
/// Evicts least-recently-accessed entries when total size exceeds `MAX_CACHE_SIZE`.
/// Content is decrypted plaintext -- never persisted to disk.
pub struct ContentCache {
    entries: HashMap<String, CachedContent>,
    current_size: usize,
}

impl ContentCache {
    pub fn new() -> Self {
        Self {
            entries: HashMap::new(),
            current_size: 0,
        }
    }

    /// Get cached content, updating the access time for LRU tracking.
    ///
    /// Returns `None` if the CID is not in cache.
    pub fn get(&mut self, cid: &str) -> Option<&[u8]> {
        // Two-phase to satisfy borrow checker: check then update
        if self.entries.contains_key(cid) {
            let entry = self.entries.get_mut(cid).unwrap();
            entry.accessed_at = Instant::now();
            Some(&entry.data)
        } else {
            None
        }
    }

    /// Store decrypted content in the cache, evicting LRU entries if over budget.
    pub fn set(&mut self, cid: &str, data: Vec<u8>) {
        let size = data.len();

        // Remove existing entry for this CID if present (to update size tracking)
        if let Some(old) = self.entries.remove(cid) {
            self.current_size = self.current_size.saturating_sub(old.size);
        }

        // Evict LRU entries until we have room
        while self.current_size + size > MAX_CACHE_SIZE && !self.entries.is_empty() {
            self.evict_lru();
        }

        // If a single item exceeds the budget, still cache it (will be evicted next insertion)
        self.current_size += size;
        self.entries.insert(
            cid.to_string(),
            CachedContent {
                data,
                accessed_at: Instant::now(),
                size,
            },
        );
    }

    /// Evict the least recently accessed entry from the cache.
    fn evict_lru(&mut self) {
        if let Some(oldest_key) = self
            .entries
            .iter()
            .min_by_key(|(_, v)| v.accessed_at)
            .map(|(k, _)| k.clone())
        {
            if let Some(evicted) = self.entries.remove(&oldest_key) {
                self.current_size = self.current_size.saturating_sub(evicted.size);
            }
        }
    }

    /// Current total size of cached content in bytes.
    #[allow(dead_code)]
    pub fn current_size(&self) -> usize {
        self.current_size
    }

    /// Clear all cached content entries, zeroizing each one via Drop.
    /// Used during FUSE destroy() for defense-in-depth cleanup.
    pub fn clear(&mut self) {
        self.entries.clear(); // Each CachedContent::drop() zeroizes data
        self.current_size = 0;
    }

Good question. It's **both** — the test script has the immediate bug, but the FUSE layer has a real limitation too. Here's the full picture:

**Why the test needs `ls`:** The kernel caches file attributes for 60s (`FILE_TTL`). During that window, `stat`/`cat` might not even reach the FUSE layer. Directory TTL is 0s, so `ls` (readdir) always reaches FUSE.

**Why it mostly works in practice:** File managers (Finder, Explorer, Nautilus) continuously do `readdir` on visible directories, which triggers the refresh. So users browsing via a file manager would see updates within ~30-60s automatically.

**What doesn't work:** CLI users doing `cat file.txt` or editors polling with `stat` — they won't trigger refresh until the 60s kernel cache expires, and even then `lookup`/`getattr` don't check for stale metadata.

The proper FUSE fix is to also check metadata staleness in `handle_lookup`, so any file access after the metadata TTL expires can spawn a background refresh. Let me implement that.
