## Issue 1: "4 factors active" When Should Be 3 (Stale Device Factor)

**Root Cause Location**: `apps/web/src/hooks/useMfa.ts`, lines 45-58

The factor count comes **directly from Web3Auth Core Kit's `getKeyDetails().totalFactors`**, which returns the count of all factors stored in the TSS (Threshold Signature Scheme) system:

```typescript
const checkMfaStatus = useCallback((): {
  isMfaEnabled: boolean;
  totalFactors: number;
  threshold: number;
} => {
  if (!coreKit || coreKit.status !== COREKIT_STATUS.LOGGED_IN) {
    return { isMfaEnabled: false, totalFactors: 0, threshold: 0 };
  }
  try {
    const details = coreKit.getKeyDetails();
    const enabled = details.totalFactors > 2;  // <-- Direct from Core Kit
    useMfaStore.getState().setFactorDetails(details.totalFactors, details.threshold);
    return {
      isMfaEnabled: enabled,
      totalFactors: details.totalFactors,  // <-- NO CLEANUP OF STALE FACTORS
      threshold: details.threshold,
    };
  } catch {
    return { isMfaEnabled: false, totalFactors: 0, threshold: 0 };
  }
}, [coreKit]);
```

**Display Location**: `SecurityTab.tsx`, lines 79-82:
```typescript
{isMfaEnabled && factorCount > 0 && (
  <p className="security-tab-factor-info">
    {factorCount} factors active, {threshold}/{factorCount} threshold
  </p>
)}
```

**The Problem**: When a device is revoked/deleted (via `deleteFactor()` in lines 208-216 of useMfa.ts), the Web3Auth MPC-Core-Kit updates the TSS system. However, if there's a bug in Web3Auth's cleanup, or if the deletion doesn't fully propagate before a new `getKeyDetails()` call, the stale factor remains in `totalFactors`.

There is **no validation or deduplication logic** that checks whether each counted factor still has:
- A corresponding entry in `shareDescriptions` 
- A matching device in the `device-registry.store`
- Valid status in the Core Kit

  // Build a map from deviceId to registry entry for quick lookup
  const registryMap = new Map<string, { name: string; lastSeenAt: number }>();
  if (registry?.devices) {

          name: device.name,
          lastSeenAt: device.lastSeenAt,

      }
    }

  return deviceShareFactors.map((factor) => {
