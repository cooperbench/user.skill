### **API ENDPOINTS (apps/api/src/shares/)**

**Shares Controller** defines 10 REST endpoints:

1. **POST /shares** - Create share
   - Re-wraps item key with recipient's public key (ECIES)
   - Supports batch child key creation for folder descendants
   - Returns shareId, encryptedKey, itemType

2. **GET /shares/received** - List received shares
   - Non-hidden, active shares only (revokedAt IS NULL)
   - Returns sharerPublicKey, ipnsName, itemName, encryptedKey

3. **GET /shares/sent** - List sent shares
   - Active shares created by current user
   - Returns recipientPublicKey, ipnsName, itemName

4. **GET /shares/lookup?publicKey=0x04...** - User existence check
   - Returns `{ exists: true }` or 404
   - Used to verify recipient is registered before sharing

5. **GET /shares/pending-rotations** - Revoked shares awaiting key rotation
   - Lists shares where revokedAt IS NOT NULL
   - Used to detect lazy rotation needs before folder modification

6. **GET /shares/:shareId/keys** - Get re-wrapped child keys
   - Returns all descendant keys (files + subfolders)
   - Accessible by sharer or recipient

7. **POST /shares/:shareId/keys** - Add re-wrapped child keys
   - Sharer only; upserts keys by (shareId, keyType, itemId)
   - Used when new files/folders added to shared folder

8. **DELETE /shares/:shareId** - Revoke share (soft delete)
   - Sets revokedAt timestamp
   - Sharer only; keys kept for lazy rotation

9. **PATCH /shares/:shareId/hide** - Hide share from recipient view
   - Sets hiddenByRecipient=true
   - Recipient only

10. **PATCH /shares/:shareId/encrypted-key** - Update share key after rotation
    - Used after lazy key rotation
    - Sharer only

11. **DELETE /shares/:shareId/complete-rotation** - Hard delete after rotation
    - Removes share and all associated ShareKey records
    - Called after sharer rotates folder key
