### 3. **What the TEE Worker Does**

**Primary Function:** Decrypts IPNS private keys and signs IPNS records with automatic re-encryption for epoch migration.

**Routes:**
1. **GET /health** (public) - Returns health status, mode (simulator/cvm), current epoch, and uptime
2. **GET /metrics** (public) - Prometheus metrics (entry counts by result status)
3. **GET /public-key** (auth required) - Returns 65-byte uncompressed secp256k1 public key for a given epoch
4. **POST /republish** (auth required) - Batch IPNS signing endpoint
   - Accepts up to 100 entries per batch
   - Decrypts IPNS keys with epoch fallback (current → previous for grace period)
   - Signs records with 48-hour lifetime (vs 24h default)
   - Re-encrypts keys if upgraded to newer epoch
   - Zeros all key material immediately after signing
5. **POST /migrate** (auth required) - CID migration between providers
6. **POST /connection-test** (auth required) - Server-side IPFS endpoint connection testing

**Key Management:**
- **Simulator mode** (development): HKDF-SHA256 from fixed seed, deterministic per epoch
- **CVM mode** (production): Phala dstack SDK for hardware-backed key derivation
- **Epoch system:** Sequential integer epochs (one per ~4 weeks), caching up to 100 epochs
- **Private key derivation:** secp256k1, 32-byte private key → 65-byte uncompressed public key (0x04 prefix)

**Security:**
- Bearer token auth (`Authorization: Bearer {TEE_WORKER_SECRET}`)
- Constant-time token comparison (timing attack protection)
- All private keys immediately zeroed after use
- No key material in logs or error messages
- SSRF validation for outbound requests in migration/connection-test

**Epoch key impact**: The Phala CVM derives keys via hardware-backed dstack SDK. Switching to simulator mode uses HKDF from a fixed seed — different keys.
