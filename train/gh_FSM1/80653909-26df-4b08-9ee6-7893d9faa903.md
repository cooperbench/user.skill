You're right — the recovery is **Linux-only**. In `apps/desktop/src-tauri/src/fuse/mod.rs`, both `recover_stale_mount` (`:98`) and `create_mount_point_dir` (`:105`) are `#[cfg(target_os = "linux")]`; macOS and Windows fall through to a plain `std::fs::create_dir_all` (`:108`) with no detect-and-recover.

That's deliberate, because the failure is **kernel-FUSE-specific**: when the FUSE daemon dies without unmounting, the Linux kernel keeps the mount in the table but *disconnected* — `stat()` returns ENOTCONN so `Path::exists()` lies, and `create_dir_all` then returns EEXIST. Clearing it needs `fusermount3 -u`, and detection is via `/proc/self/mountinfo`. None of those mechanics (ENOTCONN-disconnected mount, `/proc`, fusermount3) exist off Linux — the todo itself was scoped "...on Linux startup."

The two other platforms are genuinely different, not just untouched:

**Windows (WinFsp) — not applicable, self-heals.** WinFsp's FSD auto-evicts the volume when the hosting process dies, and on drop the host runs `FspFileSystemStopDispatcher + FspFileSystemRemoveMountPoint` (`windows/mod.rs:459-480`). A crash releases the mount; they already note the host is "replaced on each mount so remount after unmount works correctly." No stale mount blocks remount → no recovery needed.

**macOS (FUSE-T + SMB) — a *possible* unhandled gap, unverified.** FUSE-T presents an in-process SMB/NFS-backed mount, so a crash can leave a stale mount that needs `umount` / `diskutil unmount force` to clear (a classic stale-NFS-mount situation). That unmount logic exists in `macos::unmount_filesystem`, but it only runs on **graceful shutdown** — there's no startup detect-and-recover, and no `/proc` equivalent (you'd parse `mount` / `diskutil info` instead). The symptom would be a hung/`EIO` mountpoint or `fuser::mount2` failing on a busy path — not the Linux EEXIST/ENOTCONN signature. This wasn't reproduced or tested in Phase 46 (the macOS dev host couldn't even exercise the Linux path, per the manual-UAT flag).

+/// Returns true if `mount_path` appears as a mount point in the given
+/// `mount(8)` output.
+///
+/// Pure function over the `mount` text + target path so it is unit-testable
+/// without spawning `mount`. Each line has the form
+/// `<source> on <mountpoint> (<type>, <opts>)`; the mount point is the text
+/// between " on " and the trailing " (". macOS prints mount-point paths
+/// literally (no octal escaping), so spaces are compared as-is.
+pub(crate) fn mount_output_contains_mountpoint(mount_output: &str, mount_path: &Path) -> bool {
+    for line in mount_output.lines() {
+        if let Some((_, rest)) = line.split_once(" on ") {
+            if let Some((mountpoint, _)) = rest.rsplit_once(" (") {
+                if Path::new(mountpoint) == mount_path {
+                    return true;
+                }
+            }
+        }
+    }
+    false
