   - When migration data is present: update the FilePointer in local state and fire-and-forget a folder metadata re-publish to persist the wrapped key

**Design choices:**
- **Fire-and-forget**: Migration re-publish doesn't block the main operation. If it fails, it retries on the next file interaction
- **Sequence number update**: On successful re-publish, the folder's sequence number is updated in the store to prevent stale sequence issues
- **Gradual migration**: Every time a user opens/updates/restores/deletes a version of a legacy file, that file's IPNS key gets migrated
