> AGENT

From what I understand of the architecture, writable shares are deferred because they fundamentally conflict with the single-writer IPNS model:

1. **IPNS ownership** — Each folder's IPNS keypair is derived from the owner's vault key via HKDF. Only the owner can sign IPNS publishes. For Bob to write to Alice's folder, he'd need either Alice's IPNS private key (breaks zero-knowledge) or a proxy signing mechanism.

2. **Optimistic concurrency** — The sequence number conflict detection assumes a single writer. Two writers publishing to the same IPNS name would race, and the loser's update gets silently dropped.

3. **TEE republishing** — The TEE holds encrypted IPNS keys for auto-republishing. Multi-writer would mean multiple people's keys need to be enrolled for the same IPNS name.

4. **Folder metadata conflicts** — Two people adding files to the same folder simultaneously would produce divergent `children` arrays in the folder metadata blob.
