   114→## 🔑 Encryption Hierarchy
   115→
   116→CipherBox implements layered, zero-knowledge encryption where **all user data is encrypted client-side before leaving the device**. The server and storage layer never see plaintext — not file contents, not file names, not folder names, not timestamps, not file sizes.

   119→
   120→Two paths produce the same `VaultKey` (a secp256k1 keypair):
   121→
   122→```text

   129→│        ↓                │  2. Normalize signature (low-S, EIP-2)   │

   131→│        ↓                │     salt  = "CipherBox-ECIES-v1"         │
   132→│  secp256k1 keypair      │     info  = wallet address (lowercase)   │

   271→Each file key is protected by multiple nested layers. An attacker must break through all layers to access any file content:
   272→

    41→## Critical Architecture Patterns
    42→
    43→### Two-Phase Authentication Model
    44→
    45→CipherBox uses a **mandatory two-phase auth flow** that must be understood before implementing any auth-related features:
    46→
    47→1. **Phase 1 (Web3Auth):** User authenticates → Web3Auth derives ECDSA secp256k1 keypair via threshold cryptography
    48→2. **Phase 2 (CipherBox Backend):** Client authenticates with backend using either:
    49→   - **Option A:** Web3Auth ID token (JWT) validated via JWKS endpoint
    50→   - **Option B:** SIWE-like signature flow (nonce-based)
    51→
    52→**Key Insight:** The ECDSA keypair from Phase 1 is the user's identity. Web3Auth's "group connections" feature ensures that Google OAuth, email/password, magic links, and external wallet auth all derive the **same keypair** for the same user.
    53→
    54→### Zero-Knowledge Key Hierarchy
    55→
    56→```
    57→User Auth → Web3Auth → ECDSA Private Key (client RAM only, never transmitted)
    58→                    ├─ Used for ECIES decryption of all data keys
    59→                    ├─ Used to decrypt IPNS signing keys (Ed25519)
    60→                    └─ Destroyed on logout
    61→
    62→ECDSA Public Key (stored on server, identifies user)
    63→    └─ Used to encrypt (ECIES):
    64→        ├─ Root Folder Key (AES-256, stored encrypted on server)
    65→        ├─ Subfolder Keys (AES-256, stored encrypted in parent IPNS metadata)
    66→        └─ File Keys (AES-256, stored encrypted in folder IPNS metadata)
    67→```
    68→
    69→**Critical Rule:** Never log, persist to disk, or transmit the ECDSA private key. It exists ONLY in client memory during the session.

   207→## Common Pitfalls & Anti-Patterns
   208→
   209→### ❌ Never Do This
   210→
   211→1. **Storing keys in plaintext localStorage**
   212→
   213→   ```typescript
   214→   // WRONG
   215→   localStorage.setItem('privateKey', privateKeyHex);
   216→   ```
   217→
   218→2. **Logging sensitive data**
   219→
   220→   ```typescript
   221→   // WRONG
   222→   console.log('User private key:', privateKey);
   223→   console.log('Decrypted file:', fileContent);
   224→   ```
   225→
   226→3. **Sending plaintext to server**
   227→
   228→   ```typescript
   229→   // WRONG
   230→   await api.post('/vault/upload', { fileContent: file });
   231→   ```
   232→
   233→4. **Using sync crypto in main thread**
   234→   ```typescript
   235→   // WRONG (blocks UI for large files)
   236→   const encrypted = aesEncryptSync(largeFile, key);
   237→   ```
   238→

   240→
   241→1. **Store keys in memory, clear on logout**
   242→

   244→   // React context for session-scoped state
   245→   const [ecdsaPrivateKey, setEcdsaPrivateKey] = useState<Uint8Array | null>(null);
   246→

   248→     setEcdsaPrivateKey(null); // Cleared from memory
   249→     // No disk persistence
   250→   };
   251→   ```

   253→2. **Use Web Workers for large file encryption**
   254→
   255→   ```typescript
   256→   const worker = new Worker('./crypto-worker.js');
   257→   worker.postMessage({ fileData, key });
   258→   worker.onmessage = (e) => {
   259→     const encrypted = e.data;
   260→   };
   261→   ```

   263→3. **Always validate IPNS signatures client-side**
   264→   ```typescript
   265→   const messageHash = await sha256(signedEntry.encryptedMetadata);
