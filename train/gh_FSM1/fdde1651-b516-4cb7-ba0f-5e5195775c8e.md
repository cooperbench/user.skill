87	## 1.5. Closed-Phase Gate (#3569)
88	
89	The init JSON includes `phase_status` — one of `Pending | Planned | In Progress | Executed | Complete | Needs Review`. `Complete` means the phase has all summaries AND a `VERIFICATION.md` with `status: passed`. Replanning a closed phase silently rewrites plan docs that no longer match the shipped code, so the workflow must hard-stop here unless the operator explicitly overrides.
90	
91	Parse `phase_status` from the init JSON, then:
92	
93	```bash
94	FORCE_REPLAN=false
95	if [[ "$ARGUMENTS" =~ (^|[[:space:]])--force([[:space:]]|$) ]]; then
96	  FORCE_REPLAN=true
97	fi
98	
99	if [ "${phase_status}" = "Complete" ]; then
100	  if [[ "$ARGUMENTS" =~ (^|[[:space:]])--reviews([[:space:]]|$) ]]; then
101	    # --reviews on a closed phase is never legitimate — concerns belong in a
102	    # new phase or issue against the closed phase's commits.
103	    cat <<EOF >&2
104	Phase ${phase_number} (${phase_name}) is already CLOSED (VERIFICATION status: passed).
105	/gsd-plan-phase --reviews cannot replan a closed phase. If the review surfaced
106	real concerns, open a follow-up phase or file an issue against the closed
107	phase's commits. There is no --force override for --reviews on a closed phase.
108	EOF
109	    exit 1
110	  fi
111	  if [ "$FORCE_REPLAN" != "true" ]; then
112	    cat <<EOF >&2
113	Phase ${phase_number} (${phase_name}) is already CLOSED (VERIFICATION status: passed).
114	Replanning a closed phase will overwrite plan docs that no longer match the
115	shipped code. If you intentionally want to replan over closed work, re-run
116	with: /gsd-plan-phase ${phase_number} --force
117	
118	Otherwise, to view what shipped, see: ${verification_path}
119	EOF
120	    exit 1
121	  fi
122	  # FORCE_REPLAN=true: continue, but emit a banner so the operator sees the
123	  # decision in the transcript and in any committed plan docs.
124	  echo "WARNING: Replanning CLOSED phase ${phase_number} under --force. Verify the closeout was wrong before committing new plan docs." >&2
125	fi
126	```
127

1629

1631	decision captured by discuss-phase in CONTEXT.md `<decisions>` is referenced

1640	```bash
