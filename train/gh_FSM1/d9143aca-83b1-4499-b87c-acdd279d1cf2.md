### Problem Summary

The API Docker build is failing in the `tag-staging-release` workflow because the `Dockerfile` is missing a critical `COPY` command for the newly added `@cipherbox/crypto` workspace dependency.

### Root Cause


### How This Breaks the Build

The Docker build process in `/Users/michael/Code/cipher-box/apps/api/Dockerfile` follows this sequence:

**Current problematic flow:**

1. **Line 8:** Copies workspace configuration files only:
   ```dockerfile

   ```

2. **Line 9:** Copies only API's package.json:

### Technical Context: Why This Matters

The `pnpm deploy --legacy` flag is used to create a flat `node_modules` directory without symlinks (required for production Docker containers). The legacy mode **requires the source files of workspace dependencies** to be present because:

1. pnpm needs to read the source `package.json` of `@cipherbox/crypto`
2. With `--legacy`, it cannot use symlinks to the original workspace location
3. It must physically copy/include the built artifacts from the dependency

### Related Changes That Exacerbated the Problem

**Recent crypto build configuration changes** (in the same commit):

The `packages/crypto/tsup.config.ts` was split into two separate build configurations:

The CJS bundle bundles all dependencies (including ESM-only packages like `@libp2p/crypto`, `ipns`, `multiformats`) to work with NestJS's CommonJS module system. This creates a large bundled output that the Docker build needs to work with correctly.
