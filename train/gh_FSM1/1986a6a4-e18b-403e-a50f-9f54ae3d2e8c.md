**Summary of the fix:**

The recovery E2E test was failing because of a protobuf field number bug in `recovery.html`. The `extractCidFromIpnsRecord()` function looked for the IPFS path in protobuf **field 2** (which is `signatureV1`), when it should have been **field 1** (`value`). This meant delegated routing responses from mock-ipns-routing were fetched successfully but never parsed correctly, causing all IPNS resolution to fail.

Additionally, the resolution order was inverted — trying the slow IPFS gateway first (15-30s timeout when Kubo can't resolve) before the fast delegated routing API. Swapping the order makes resolution instant in CI.
