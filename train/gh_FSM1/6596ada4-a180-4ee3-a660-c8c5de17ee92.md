- `.claude/gsd-migration-journal/` is the GSD installer's safety net. During the update it writes a journal JSON plus a full snapshot of your pre-update `get-shit-done/` tree, so it can roll the migration back if it fails mid-run (`installer-migrations.cjs:513`). On success the journal is just kept as an audit record.
- Future installer runs decide what's already applied from `gsd-install-state.json`'s `appliedMigrations` list (matched by migration id) — they don't read the journal. The `journal:` field in install state is only a provenance pointer, and journal cleanup is explicitly "best-effort" in the code, so a missing journal won't break anything.
- The 2.9MB snapshot it contains is your old GSD tree, which is already fully recoverable from git history.

So committing those 105 files adds nothing: git is a strictly better rollback mechanism for a tracked install. My recommendation — add `.claude/gsd-migration-journal/` to `.gitignore` and unstage it (keep or delete it on disk, doesn't matter; do keep `gsd-install-state.json`, the installer needs that to skip already-applied migrations).
