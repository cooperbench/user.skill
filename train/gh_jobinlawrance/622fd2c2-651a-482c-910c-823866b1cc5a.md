## Bugs Found on ravencloak.org

### 1. Keycloak `check-sso` fails behind Cloudflare (deployed code)
The deployed code uses `onLoad: 'check-sso'` with a silent iframe. Cloudflare strips third-party cookies, so the silent SSO check always fails. This makes the app think the user is unauthenticated even when they have a valid Keycloak session.

**Result:** Every `requiresAuth` route triggers `auth.login()`, which hardcodes `redirectUri: '/dashboard'` — so **every deep link bounces back to `/dashboard`**.

**Fix (already on this branch):** Switch to `onLoad: 'login-required'` which does a full redirect flow instead of iframe.

### 2. `login()` hardcodes redirect to `/dashboard`
Even after fixing SSO, the `login()` function always sends users back to `/dashboard` after auth, losing the original URL.

**Fix:** Changed to `window.location.href` to preserve deep links.

### 3. JWT access token missing ALL user claims  
The access token only has `scope: "openid"` — missing `profile`, `email`, `raven-org`. The token contains zero user-identifying claims (no `sub`, `email`, `preferred_username`, `org_id`, `org_role`). Even the userinfo endpoint only returns `sub`.

**Root cause:** The Keycloak server's `raven-frontend` client doesn't have the default scopes properly assigned. The realm JSON has the correct config, but `--import-realm` only runs on first boot — any subsequent changes to the JSON aren't picked up.

**Frontend fix:** Auth store now tries ID token claims -> access token claims -> `loadUserProfile()` fallback. **Server fix needed:** You need to manually assign `profile`, `email`, and `raven-org` as default scopes for the `raven-frontend` client in the Keycloak admin console at `https://auth.ravencloak.org/admin`.

### 4. Sidebar hardcodes `/orgs/_/` placeholder
All org-scoped nav links use literal `_` instead of the user's actual org ID.

**Fix:** Sidebar now uses a computed `orgPrefix` from the auth store's `user.orgId`.

### 5. Redirect URIs missing production domain
The `raven-frontend` client's `redirectUris` only had `raven-frontend.pages.dev`. Added `www.ravencloak.org`.
