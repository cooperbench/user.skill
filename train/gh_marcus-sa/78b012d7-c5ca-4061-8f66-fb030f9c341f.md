## 8. KEY ASSUMPTIONS & BEHAVIORS

### Conversation-Level, Not Message-Level:
- Branching operates at **conversation scope**, not individual messages
- A branch inherits context entities (not messages) from parent
- All new messages in a branch contribute their own extraction to the branch's context

### Context Inheritance Strategy:
- **Only on sparse extraction:** If branch has < 5 entities after first few messages, inherited entities fill the gap
- **No redundancy:** Inherited entities already present in branch are skipped (deduped by entity ID)
- **First message bias:** System prompt on first message includes inherited context, biasing LLM discussion
- **Automatic population:** `contextEntityIds: []` triggers auto-load from parent's 30 most recent extracted entities

### Sidebar Nesting Rules:
- **Only root conversations** are grouped by project (touched_by edges)
- **Branches excluded** from grouping (have `parentId`)
- **Recursive attachment** means branches can have sub-branches (multi-level nesting possible)
- **Both contexts:** Branches appear nested under parents in both project groups AND unlinked sections

### Edge Direction:
- `branched_from` edge: **`in` = branch, `out` = parent**
- **Forward traversal** (`SELECT out FROM branched_from WHERE `in` = B`) finds parent
- **Backward traversal** (`SELECT `in` FROM branched_from WHERE out = A`) finds all branches of A

**3a. `loadBranchChain`** -- Walks the `branched_from` edges from a conversation up to the root, returning an ordered array of branch links.

```typescript
import { RecordId, type Surreal } from "surrealdb";

export type BranchLink = {
  conversationId: string;
  parentConversationId: string;
  branchPointMessageId: string;
  branchPointCreatedAt: Date;
};

export async function loadBranchChain(
  surreal: Surreal,
  conversationId: string,
): Promise<BranchLink[]> {
  const chain: BranchLink[] = [];
  let current = conversationId;

  // Depth limit prevents infinite loops from data corruption
  for (let depth = 0; depth < 10; depth++) {
    const conversationRecord = new RecordId("conversation", current);
    const [rows] = await surreal
      .query<[Array<{
        out: RecordId<"conversation", string>;
        branch_point_message: RecordId<"message", string>;
      }>]>(
        "SELECT out, branch_point_message FROM branched_from WHERE `in` = $conversation AND branch_point_message != NONE LIMIT 1;",
        { conversation: conversationRecord },
      )
      .collect<[...]>();

    if (rows.length === 0) break;

    const edge = rows[0];
    const msg = await surreal.select<{ createdAt: Date | string }>(edge.branch_point_message);
    if (!msg) {
      throw new Error(`branch point message not found: ${edge.branch_point_message.id as string}`);
    }

    chain.unshift({
      conversationId: current,
      parentConversationId: edge.out.id as string,
      branchPointMessageId: edge.branch_point_message.id as string,
      branchPointCreatedAt: msg.createdAt instanceof Date
        ? msg.createdAt
        : new Date(msg.createdAt as string),
    });

    current = edge.out.id as string;
  }

  return chain;
}
```

The chain is ordered root-to-current:
- `chain[0].parentConversationId` is the root conversation
- `chain[chain.length-1].conversationId` equals the input `conversationId`

**3b. `loadMessagesWithInheritance`** -- Uses the chain to load all messages (inherited + own) in chronological order.

```typescript
export type InheritableMessage = {
  id: string;
  role: "user" | "assistant";
  text: string;
  createdAt: Date | string;
  suggestions?: string[];
  inherited: boolean;
};

export async function loadMessagesWithInheritance(
  surreal: Surreal,
  conversationId: string,
  limit: number,
): Promise<InheritableMessage[]> {
  const chain = await loadBranchChain(surreal, conversationId);

  if (chain.length === 0) {
    // Not a message-level branch (root or legacy branch)
    const messages = await queryConversationMessages(surreal, conversationId, limit);
    return messages.map((m) => ({ ...m, inherited: false }));
  }

  const allMessages: InheritableMessage[] = [];

  // 1. Root conversation messages up to first branch point
  const rootConvId = chain[0].parentConversationId;
  const rootMessages = await queryConversationMessagesUpTo(
    surreal, rootConvId, chain[0].branchPointCreatedAt,
  );
  allMessages.push(...rootMessages.map((m) => ({ ...m, inherited: true })));

  // 2. Intermediate ancestor messages between branch points
  for (let i = 0; i < chain.length - 1; i++) {
    const intermediateMessages = await queryConversationMessagesUpTo(
      surreal, chain[i].conversationId, chain[i + 1].branchPointCreatedAt,
    );
    allMessages.push(...intermediateMessages.map((m) => ({ ...m, inherited: true })));
  }

  // 3. Current conversation's own messages
  const ownMessages = await queryConversationMessages(surreal, conversationId, limit);
  allMessages.push(...ownMessages.map((m) => ({ ...m, inherited: false })));

  return allMessages;
}
```

### Edge Cases and Risks

1. **Orphaned branch points**: If a message is deleted from a parent conversation after branching, `loadBranchChain` will throw ("branch point message not found"). This is correct per the fail-fast convention in AGENTS.md. Messages should not be deleted from conversations that have branches. A future enhancement could add a check before message deletion.

2. **Deep chains**: The depth limit of 10 in `loadBranchChain` prevents infinite loops. 10 levels of branching is well beyond practical usage.

3. **Performance**: Each level of branching adds 2 queries (one for the edge, one for the message's createdAt). For 3 levels of branching, that is 6 extra queries on conversation load. This is acceptable given branching depth is typically 1-2 levels. The message loading queries themselves use the existing `message_conversation_createdAt` index.

4. **CreatedAt ordering assumption**: The `createdAt <= $upTo` filter assumes messages within a conversation have monotonically increasing `createdAt` values. This holds because messages are created sequentially within a conversation.

5. **Concurrent messages**: If two messages are created at the exact same timestamp, the `<=` filter includes both. This is acceptable behavior.

# Message-Level Conversation Branching

## Context

Currently branching creates a new conversation from an entire parent conversation. The user wants ChatGPT-style branching where you branch from a specific message checkpoint — inheriting all messages up to that point, with the branch continuing independently from there.

**Key design choice**: Virtual inheritance (no message copying). Inherited messages are loaded dynamically by walking the `branched_from` chain at read time.

## 3. New Module: Branch Chain Walking

**New file**: `app/src/server/chat/branch-chain.ts`

Two exported functions:

### `loadBranchChain(surreal, conversationId) → BranchLink[]`
Walks `branched_from` edges from conversation up to root. Returns ordered array (root-first) of `{ conversationId, parentConversationId, branchPointMessageId }`. Depth-limited to 10 to prevent loops.

### `loadMessagesWithInheritance(surreal, conversationId, limit) → InheritableMessage[]`
Uses `loadBranchChain` to assemble the full message history:

1. If no chain (root conversation) → load own messages, mark `inherited: false`
2. Otherwise:
   - **Root segment**: Load messages from root conversation up to and including the assistant response following the first branch point user message
   - **Intermediate segments**: For each intermediate branch, load its own messages up to the next branch point (same logic)
   - **Current conversation**: Load all own messages, mark `inherited: false`
3. Return combined array in chronological order

**Loading up to a branch point**: The `branch_point_message` stores the user message ID. To include its assistant response, query the next message in that conversation after the branch point's `createdAt`. If it's an assistant message, include up to that `createdAt`. This is done in application code (two queries per segment, not subqueries).
