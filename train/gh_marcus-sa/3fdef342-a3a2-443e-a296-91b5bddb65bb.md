how do we enforce DCO Sign-Off in github

> AGENT

The standard approach is the **DCO GitHub App** — used by CNCF, Linux Foundation, and most projects that require sign-off. **Setup (2 minutes):** 1. Install the [DCO App](https://github.com/apps/dco) on your repo — it's a free GitHub App by probot 2. It automatically runs as a status check on every PR, verifying each commit has `Signed-off-by` 3. Add it as a required status check in **Settings > Branches > Branch protection rules** for `main`: - Check "Require status checks to pass before merging" - Search for and select `DCO` That's it. PRs with unsigned commits get a failing check with instructions on how to fix (either `git commit --amend -s` or `git rebase --signoff`). The app is smart enough to handle squash merges and allows a "remediation commit" where a contributor can add sign-off retroactively in a comment if they can't rewrite history on a fork.

To your follow-up about **signed commits on GitHub**: GitHub supports two levels: 1. **Vigilant mode** (Settings > SSH and GPG keys > "Flag unsigned commits as unverified") — shows a warning badge on unsigned commits but doesn't block them. 2. **Require signed commits** (branch protection rule) — under Settings > Branches > protection rule for `main`, check "Require signed commits". This rejects any push with unsigned commits. For enforcement, you'd combine: - **DCO App** — checks for `Signed-off-by` (legal agreement) - **Require signed commits** branch protection — checks for GPG/SSH signature (identity verification) They're orthogonal: DCO proves you *agreed* to the CLA, GPG proves you *are who you say you are*. Most projects enforce DCO. Requiring GPG signatures is stricter — it can create friction for new contributors who haven't set up signing. Up to you whether you want both.
