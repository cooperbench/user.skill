## What Claude Code sends

From the coding agent internals research (Finding 6): the loop terminates when `stop_reason: "end_turn"` — but that ends a single **interaction**, not a **session**. A Claude Code session spans the entire conversation (could be hours). There's no wire-level signal saying "I'm done, closing the session."

What Claude Code *does* send is `metadata.user_id` containing `session_<uuid>` — this identifies which session a request belongs to, but there's no explicit close.

## What Vercel AI SDK sends

Nothing session-related. Each `generateText()` / `streamText()` call is independent. There's no session concept in the SDK at all. A marketing agent built with Vercel AI SDK would just make individual LLM calls with no session envelope.

## What this means for the proxy

The debounce timeout isn't a fallback — **it's the primary mechanism**. No mainstream LLM client SDK sends session-end signals.

Three tiers of session detection:

| Client type | Session ID source | End detection |
|---|---|---|
| Claude Code (via `brain init`) | `metadata.user_id` → `session_<uuid>` | Inactivity timeout |
| Brain-aware agent (custom header) | `X-Brain-Session` header | Inactivity timeout OR explicit `X-Brain-Session-End: true` |
| Unknown agent (no Brain integration) | Derived from API key + IP hash | Inactivity timeout only |

The `X-Brain-Session-End` header is something **we define** — `brain init` could inject a shutdown hook in Claude Code that sends a final lightweight request with this header. But it's an optimization, not a requirement.

## Revised design

```
Primary: Inactivity timeout (2h default, per-workspace configurable)
  → Background sweep finds stale sessions → sets ended_at → EVENT fires

Optional: Explicit end signal (X-Brain-Session-End header)
  → Proxy sets ended_at immediately → EVENT fires
```
