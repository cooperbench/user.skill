     1→# Wave Decisions -- Tool Registry UI (DISCUSS)
     2→
     3→## Decision 1: Tab-based navigation vs separate pages
     4→
     5→**Decision**: Single page with tab navigation (Tools, Providers, Accounts, Access)
     6→**Rationale**: Follows existing Brain UI patterns (Policies uses list/detail). Tool Registry is a single bounded context with shared data across views. Tabs minimize navigation friction and keep shared context visible. Four tabs is within Hick's Law limit (5-7 items).
     7→**Alternatives considered**: Separate routes per section (/tools/providers, /tools/accounts). Rejected because cross-tab consistency is simpler with shared query cache in a single page component.
     8→
     9→## Decision 2: Story splitting from US-11
    10→
    11→**Decision**: Split XL story US-11 into 8 right-sized stories (US-UI-01 through US-UI-08)
    12→**Rationale**: Original US-11 had 7 sub-capabilities and would take 2+ weeks as a single story. Elephant Carpaccio: each slice delivers a verifiable behavior. Walking skeleton (5 stories) delivers the end-to-end admin+member journey. Release 1 adds OAuth2 and dashboard. Release 2 adds governance. Each story is 1-2 days.
    13→**Traceability**: US-UI-01..08 all trace to US-11 from the parent feature.
    14→
    15→## Decision 3: MCP Server Discovery deferred
    16→
    17→**Decision**: Defer MCP Server Discovery UI to a separate deliverable
    18→**Rationale**: US-2 backend (MCP server discovery via tools/list) was explicitly noted as "not in walking skeleton scope" in the evolution doc. Building UI for a non-existent backend is premature. The 8 stories cover all implemented backend capabilities.
    19→**Impact**: No story for discovery UI in this DISCUSS wave. When US-2 backend is implemented, a follow-up DISCUSS wave will add the discovery UI story.
    20→
    21→## Decision 4: OAuth2 flow -- same-window redirect
    22→
    23→**Decision**: Use same-window redirect (not popup) for OAuth2 authorization
    24→**Rationale**: Popups are blocked by default in many browsers. Same-window redirect is the standard pattern for OAuth2 on web. The callback URL redirects back to the Providers tab. State parameter provides CSRF protection.
    25→**Trade-off**: User briefly leaves Brain during authorization. Pre-redirect dialog with scope summary provides context before departure.
    26→
    27→## Decision 5: Admin vs member permissions in UI
    28→
    29→**Decision**: UI renders all tabs for all users; admin-only actions (register provider, grant access, attach governance) are disabled or hidden for non-admin members
    30→**Rationale**: Members benefit from seeing the full tool registry (browse tools, view providers) even if they cannot modify it. This follows progressive disclosure: visible but disabled is more discoverable than hidden. Backend enforces authorization regardless of UI.
    31→**Note**: Specific permission model (admin role check) deferred to DESIGN wave.
    32→
    33→## Decision 6: JTBD reuse -- no new JTBD artifacts
    34→
    35→**Decision**: Reuse existing JTBD artifacts from docs/ux/mcp-tool-registry/
    36→**Rationale**: The four jobs (J1-J4) and four forces analysis were completed during the backend DISCUSS wave. The UI serves J1 and J2 exclusively. No new jobs discovered during UI journey mapping. Creating redundant JTBD artifacts would violate single source of truth.

export function useLearnings(): UseLearningsReturn {
  const workspaceId = useWorkspaceState((s) => s.workspaceId);
  const [learnings, setLearnings] = useState<LearningSummary[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<string | undefined>();
  const [filters, setFilters] = useState<LearningFilters>({});

  const fetchLearnings = useCallback(async () => {
    if (!workspaceId) return;
    setIsLoading(true);
    setError(undefined);
    
    try {
      const url = buildLearningsUrl(workspaceId, filters);
      const response = await fetch(url);
      if (!response.ok) throw new Error(await response.text());
      const data = (await response.json()) as { learnings: LearningSummary[] };
      setLearnings(data.learnings);
    } catch (err) {
      setError(err instanceof Error ? err.message : "Failed to load learnings");
    } finally {
      setIsLoading(false);
    }
  }, [workspaceId, filters]);

  useEffect(() => {
    if (!workspaceId) return;
    void fetchLearnings();
  }, [workspaceId, filters, fetchLearnings]);

  const refresh = useCallback(() => {
    void fetchLearnings();
  }, [fetchLearnings]);

  return { learnings, isLoading, error, filters, setFilters, refresh };
}

export function buildLearningsUrl(workspaceId: string, filters: LearningFilters): string {
  const base = `/api/workspaces/${encodeURIComponent(workspaceId)}/learnings`;

  const query = params.toString();

}

      setErrors((prev) => {
        const next = { ...prev };
        if (field === "title") delete next.title;
        // ... clear related errors
        delete next.submit;
        return next;
      });
    },
    [],
  );

  const handleSubmit = useCallback(async () => {
    const validationErrors = validateForm(form);
    if (hasErrors(validationErrors)) { setErrors(validationErrors); return; }

    setIsSubmitting(true);
    setErrors({});

    try {
      const url = `/api/workspaces/${workspaceId}/policies`;
      const response = await fetch(url, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(buildRequestBody(form)),
      });

      if (!response.ok) {
        const text = await response.text();
        const message = tryParseJsonError(text);
        setErrors({ submit: message || "Failed to create policy" });
        return;
      }

      const data = (await response.json()) as { policy_id: string };
      setForm(createInitialFormState());
      setErrors({});
      onClose();
      void navigate({ to: "/policies/$policyId", params: { policyId: data.policy_id } });
    } catch (err) {
      setErrors({ submit: err instanceof Error ? err.message : "Failed to create policy" });
    } finally {
      setIsSubmitting(false);
    }
  }, [form, workspaceId, onClose, navigate]);

  return (
    <Dialog open={open} onOpenChange={(o) => { if (!o) handleClose(); }}>
      <DialogContent className="sm:max-w-lg">
        <DialogHeader>
          <DialogTitle>Create Policy</DialogTitle>
        </DialogHeader>
        
        {/* Form fields with error display */}
        <div className="flex flex-col gap-3">
          {errors.submit && <p className="text-sm text-destructive">{errors.submit}</p>}
          
          {/* Field groups with labels, inputs, error messages */}
        </div>

        <DialogFooter>
          <Button variant="outline" onClick={handleClose} disabled={isSubmitting}>Cancel</Button>
          <Button onClick={handleSubmit} disabled={isSubmitting}>Create Policy</Button>
        </DialogFooter>
      </DialogContent>
    </Dialog>
  );
}

### 13. KEY ARCHITECTURAL DECISIONS

1. **No React Query** — manual fetch + useState per hook. Simpler, no cache conflicts.
2. **Single dialog state on page** — routes all actions through one union type.
3. **Filters trigger refetch** — added to dependency array of useCallback/useEffect.
4. **Cards emit actions to parent** — parent determines dialog, manages API calls.
5. **Separate data and action hooks** — keeps concerns isolated.
6. **Pure validation/request-building functions** — testable, reusable.
7. **Workspace ID context root** — all URLs scoped to workspace, never null in authenticated routes.
8. **No shared request state** — each hook manages its own loading/error to prevent cross-contamination.

 */

 */
export function consumeOAuthState(state: string): OAuthStateEntry | undefined {
  const entry = pendingStates.get(state);
  if (!entry) return undefined;

  pendingStates.delete(state);

  const elapsed = Date.now() - entry.createdAt;
  if (elapsed > STATE_TTL_MS) return undefined;

  return entry;
}

/**
 * AES-256-GCM encryption adapter for credential secrets.
 *
 * Each encrypted value = base64(IV || ciphertext || authTag).
 * 12-byte random IV per encryption. 16-byte auth tag.
 * Key must be a 256-bit (32-byte) hex string.
 *
 * Pure functions with no side effects beyond crypto randomness.
 * ADR-066, ADR-068.
 */
import { createCipheriv, createDecipheriv, randomBytes } from "node:crypto";

const ALGORITHM = "aes-256-gcm";
const IV_LENGTH = 12;
const AUTH_TAG_LENGTH = 16;

/**
 * Encrypt plaintext using AES-256-GCM.
 * Returns base64-encoded string containing IV + ciphertext + authTag.
 */
export function encryptSecret(plaintext: string, keyHex: string): string {
  const key = Buffer.from(keyHex, "hex");
  if (key.length !== 32) {
    throw new Error("Encryption key must be 256 bits (64 hex characters)");
  }

  const iv = randomBytes(IV_LENGTH);
  const cipher = createCipheriv(ALGORITHM, key, iv, { authTagLength: AUTH_TAG_LENGTH });

  const encrypted = Buffer.concat([
    cipher.update(plaintext, "utf8"),
    cipher.final(),
  ]);

  const authTag = cipher.getAuthTag();

  // Pack: IV || ciphertext || authTag
  const packed = Buffer.concat([iv, encrypted, authTag]);
  return packed.toString("base64");
}

Scope\n\n### In scope\n- **Providers tab**: list, create, delete credential providers (oauth2, api_key, bearer, basic)\n- **Accounts tab**: list connected accounts, connect new account (static credentials or OAuth2 redirect), revoke account\n- **Tools tab**: list registered MCP tools with toolkit grouping, view tool detail (schema, risk level, grants, governance)\n- **Tool detail panel**: expandable row or slide-over showing input_schema, linked provider, `can_use` grants, `governs_tool` policies\n- **OAuth2 callback handler**: backend route to complete the authorization code exchange\n- **Tool CRUD endpoints**: backend routes to list/create/update tools (schema exists, routes do not)\n- **Grant management endpoints**: backend routes to create/revoke `can_use` edges\n\n### Out of scope\n- Tool execution / invocation UI (already handled by chat agent tool pipeline)\n- Governance policy CRUD (already exists at `/policies`)\n- `governs_tool` edge creation (use existing policy UI; tools tab is read-only for governance)\n- Bulk import/export of tools or providers\n\n## 3. Component Architecture\n\n```\n/integrations (IntegrationsPage)\n├── Tab: Providers\n│   ├── ProviderTable (list view)\n│   ├── CreateProviderDialog (form: name, display_name, auth_method, conditional fields)\n│   └── DeleteProviderConfirm (confirmation dialog)\n├── Tab: Accounts\n│   ├── AccountTable (list view with provider name, status, credential indicators)\n│   ├── ConnectAccountDialog (select provider → auth_method-specific form OR OAuth2 redirect)\n│   └── RevokeAccountConfirm (confirmation dialog)\n└── Tab: Tools\n    ├── ToolTable (grouped by toolkit, columns: name, risk_level, status, provider, grants count)\n    └── ToolDetailPanel (expandable: description, input_schema JSON viewer, grants list, governance policies)\n```\n\n### File layout\n\n```\napp/src/client/\n  routes/integrations-page.tsx          # Page component with tab state\n  components/integrations/\n    ProviderTable.tsx                    # Provider list table\n    CreateProviderDialog.tsx             # Create provider form dialog\n    AccountTable.tsx                     # Connected accounts list\n    ConnectAccountDialog.tsx             # Connect account flow (static + OAuth2)\n    ToolTable.tsx                        # MCP tools list grouped by toolkit\n    ToolDetailPanel.tsx                  # Tool detail with schema, grants, governance\n  hooks/\n    use-providers.ts                     # Fetch/mutate credential providers\n    use-accounts.ts                      # Fetch/mutate connected accounts\n    use-tools.ts                         # Fetch MCP tools with grants/governance counts\n```\n\n## 4. The callback handler:\n\n1. Extracts `code` and `state` from query params\n2. Calls `consumeOAuthState(state)` — returns `{ providerId, identityId, workspaceId }` or rejects if expired/missing\n3. Loads provider record via `getProviderById()`\n4. Calls `exchangeCodeForTokens(provider, code, redirectUri)` to get access/refresh tokens\n5. Encrypts tokens via `encryptSecret()`\n6. Creates `connected_account` record via `createConnectedAccount()`\n7. Redirects (302) to `/integrations?tab=accounts&status=connected`\n\nError cases redirect to `/integrations?tab=accounts&status=error&reason=<code>`.\n\n### 4.4 New query functions\n\n```typescript\n// queries.ts additions\n\n// List tools with grant and governance counts\nlistToolsWithCounts(surreal, workspaceRecord)\n  → SELECT *, count(←can_use) AS grant_count, count(←governs_tool) AS governance_count\n    FROM mcp_tool WHERE workspace = $ws ORDER BY toolkit, name;\n\n// Tool detail with expanded grants and governance\ngetToolDetail(surreal, toolRecord)\n  → batched query:\n    1.
