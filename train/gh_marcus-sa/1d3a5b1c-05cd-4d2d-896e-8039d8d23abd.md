What is the difference between a mutex and a semaphore?

> AGENT

**Mutex** — exclusive lock. One thread owns it at a time. Only the owner can unlock it. Used to protect a single shared resource.

**Semaphore** — a counter. Initialized to N, it allows up to N threads to enter concurrently. Any thread can signal (increment) it, not just the one that waited.

Key differences:

| | Mutex | Semaphore |
|---|---|---|
| Concurrency | 1 (binary) | N (counting) |
| Ownership | Yes — only owner unlocks | No — any thread can signal |
| Use case | Mutual exclusion | Limiting concurrency (e.g. connection pool of 10) |

A binary semaphore (N=1) looks similar to a mutex but lacks ownership semantics — any thread can release it, which makes it unsuitable for protecting critical sections where you need strict lock/unlock pairing.
