## The Problem You're Identifying

The current `CreateProviderDialog` collects OAuth2 fields (authorization_url, token_url, client_id, client_secret) as if Brain is **manually configuring an OAuth2 provider from scratch**. But the MCP spec defines its own OAuth 2.1 flow where:

1. The **MCP server itself is the protected resource** (OAuth resource server)
2. The MCP server advertises its authorization server via `/.well-known/oauth-protected-resource`
3. Brain (as MCP client) discovers the auth server, registers dynamically, and runs PKCE authorization code flow
4. The user authorizes in the browser and gets redirected back

So there are actually **two distinct auth models** for MCP servers:

### Model 1: Static Headers (simple)
The MCP server expects a fixed header on every request. Examples:
- `Authorization: Bearer ghp_xxx` (GitHub PAT)
- `X-API-Key: sk-xxx`
- Custom headers

No OAuth dance needed. Admin pastes the token/key, Brain encrypts and stores it, injects it on every MCP connection.

### Model 2: MCP-Native OAuth 2.1 (spec-compliant)
The MCP server implements the MCP authorization spec:
