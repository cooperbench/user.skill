## Issue 1: `scan_codebase()` scope overlap — Phase 2 bug

**Root cause**: `scan_codebase()` (line 525) iterates all scopes and for each one does `rglob(pattern)` on the scope directory. Several TypeScript scopes have overlapping directory trees:

| Scope | Directory |
|-------|-----------|
| `typescript-tests` | `extension/tests/` |
| `typescript-extension` | `extension/ui/` |
| `typescript-tasks` | `extension/tasks/` |
| `typescript-extension-scripts` | `extension/scripts/` |
| `typescript-extension-config` | `extension/` (parent of all above) |

When `typescript-extension-config` iterates with `rglob("*.ts")` on `extension/`, it recursively finds files in `extension/tests/`, `extension/ui/`, etc. — every subdirectory.

The overwrite happens at line 538: `results[normalized] = suppressions`. A file in `extension/tests/` gets:

1. First scanned under `typescript-tests` — `scan_file()` uses test-aware patterns including `test-only` and `test-skip` (lines 422-435)
2. Later rescanned under `typescript-extension-config` — `scan_file()` uses generic TS patterns WITHOUT `test-only`/`test-skip` (lines 436-447)
3. Step 2 overwrites step 1's results, dropping any test-only suppressions

**Why `_resolve_scope()` doesn't save us**: `_resolve_scope()` (line 478) correctly uses longest-prefix matching and IS used by `build_baseline()`. But `scan_codebase()` never calls it — it blindly iterates all scopes and overwrites. The scope routing in `build_baseline()` is correct but it receives already-corrupted scan data.

**How we missed it in Phase 2**: T003 refactored `SCOPES` from 3 entries to 6+. The original 3 scopes had no directory overlap (src/, extension/ui/, extension/tests/). When the additional TypeScript scopes were added (including the `extension/` catch-all), the overlapping rglob traversal became a problem. T004 (scan_file pattern dispatch) and T005 (build_baseline scope routing) were correctly fixed to derive from the canonical map, but `scan_codebase()` — the loop that actually feeds data into both — was never updated to respect canonical scope boundaries.

**The fix**: In `scan_codebase()`, resolve each file's canonical scope via `_resolve_scope()` and skip files whose canonical scope doesn't match the current iteration. Each file gets scanned exactly once, under its most-specific scope:

```python
for file_path in scope_path.rglob(pattern):
    if is_excluded(file_path):
        continue
    normalized = normalize_path(file_path, repo_root)
    canonical_scope = _resolve_scope(normalized)
    if canonical_scope != scope_name:
        continue  # belongs to a more-specific scope
    suppressions = scan_file(file_path, scope_name, repo_root)
    if suppressions:
        results[normalized] = suppressions
```
