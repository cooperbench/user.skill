# Code Review: Branch `047-close-suppression-blindspot`

**12 commits, 86 files, +5314/−423 — Closes #232**

## Overview

This branch eliminates the "suppression blindspot" — the gap where lint rule suppressions (`noqa`, `type: ignore`, `eslint-disable`, etc.) existed without coverage across the full codebase. The work has three pillars:

1. **Expanded audit scope** — from 3 to 11 scopes covering every `.py`/`.ts` file in the repo
2. **Compensating guardrails** — new `check_rule_disable_invariants.py` replaces 57 inline `noqa` comments with global rule disables (S603, S607, S311, N999) backed by machine-verified proof artifacts and runtime guardrails
3. **Mypy expansion** — extends type checking from `src/` to `tests/` and `scripts/`

## Strengths

- **Scope overlap fix is well-designed.** `_resolve_scope()` uses longest-prefix + extension matching, and `scan_codebase()` skips files that don't belong to the current iteration's scope. The comment at `:539-542` explains exactly why. This correctly prevents `typescript-extension-config` from overwriting `typescript-tests` results.

- **Tokenize-based scanning eliminates false positives.** Using `tokenize.generate_tokens` for Python files means patterns in docstrings/string literals are structurally excluded. The `_get_code_lines()` helper in the guardrail script uses the same approach. Good consistency.

- **Allowlist design is strict.** `(file, line, code)` triples for subprocess exceptions — not just file-level bypasses. Line drift from formatting is caught by `--verify-artifacts`, and `--regenerate-allowlist` handles updates. This is well-thought-out.

- **All entry points updated consistently.** Pre-commit (`run_repo_hook.py`), preflight (`run_pr_preflight.py`), and CI (`ci.yml`) all get the new gates. The pre-commit path uses `staged_file_content()` for correctness.

- **Test coverage is substantial.** `test_rule_disable_invariants.py` (476 new lines) and `test_audit_suppressions.py` (+700 lines) cover scope resolution, tokenize error handling, the allowlist mechanism, and edge cases.

- **Suppression removal is clean.** The `S105` renames (e.g., `malicious_token` → `malicious_continuation`) and `F401` fixes (e.g., `import_module()` instead of bare `import`) are correct semantic fixes, not just suppression shuffling.

## Issues

### Medium

1. **`run_repo_hook.py` imports at module level via `exec_module`** (`:24-47`). Both `audit-suppressions.py` and `check_rule_disable_invariants.py` are loaded unconditionally when the hook module imports. This runs their module-level code (regex compilation, JSON loading) on every git operation — including `pre-push`, which doesn't use these functions. Consider lazy-loading inside `run_scope_coverage_guard()` and `run_rule_disable_invariants_guard()` only, or at minimum document this as intentional.

2. **`typescript-extension-config` scope `dir: "extension/"` is a superset of 3 other scopes** (`extension/ui/`, `extension/tests/`, `extension/scripts/`). The `_resolve_scope()` longest-prefix logic correctly resolves files in subdirectories to their child scopes. But a `.ts` file placed directly in `extension/` (not a subdirectory) would match `typescript-extension-config`. This is presumably intentional for config files like `extension/*.ts`, but if someone adds `extension/foo/bar.ts`, it silently lands in `typescript-extension-config` without test-runner pattern checking. A scope coverage test that verifies all existing `.ts` files resolve to the expected scope would make this more robust.

3. **`verify-badge-url.py` switches from `urllib` to `requests`** without adding `requests` to any dependency specification. This script runs in CI (`.github/scripts/`), so it relies on `requests` being pre-installed in the CI image. If the CI runner changes, this breaks silently. Either pin `requests` in a CI requirements file or keep `urllib` (which is stdlib).

### Low

4. **`_MockStdin` in `test_cli_dashboard.py`** returns `0` from `fileno()` — this is stdin's fd. If any test inadvertently calls `os.read(0, ...)` through this mock, it would block on real stdin. The class is fine for `os.isatty()` testing, but a comment noting the limitation would help.

5. **Mypy overrides for `tests.*` and `scripts.*`** disable nearly all strict checks (`disallow_untyped_defs`, `disallow_untyped_calls`, `check_untyped_defs`, `disallow_incomplete_defs`, `disallow_any_generics`, `warn_return_any`). This is pragmatic but means type errors can creep into test/script code undetected. The typed fixes in this branch (FakeProphetModule, signal handler types, etc.) are good, but future additions to `tests/` get almost no mypy coverage. Consider keeping at least `check_untyped_defs = true` for tests.

6. **`scan_file()` has hardcoded scope-name check for `typescript-tests`** (`:422`) instead of deriving the pattern list from a scope attribute. If a new test scope is added (e.g., `typescript-e2e-tests`), it won't get test-runner pattern checking unless someone remembers to add it to this `if` branch. Consider adding a `check_test_patterns: bool` field to `ScopeConfig`.

7. **The `_selective_thread` signature in `test_cli_dashboard.py`** (`:586-596`) is very detailed to satisfy mypy — 6 typed parameters for a test mock factory. This is correct but quite verbose for test code. If mypy for tests gets relaxed further per point 5, this precision becomes unnecessary overhead.

## Nits

- `.subprocess-allowlist.json` has duplicate `"reason"` strings like `"Test helper: args built from constants"` and `"Test helper: args built from constants (second call)"`. The second variant is fine for disambiguation but reads oddly — consider `"Test helper: second subprocess.run call site"` or similar.

- `check_rule_disable_invariants.py:287` — the `os.system/popen` check uses `if` (not `elif`), so a line with both `subprocess.run(... shell=True)` and `os.system()` would generate two violations. This is technically correct (two separate issues) but worth a test case to confirm the behavior is intentional.

## Security

- **subprocess allowlist approach is sound.** The `(file, line, code)` triple prevents blanket bypasses and line-number drift is automatically caught.
- **Tokenize-based scanning** eliminates the class of false negatives where suppression patterns appear inside string literals.
- **`verify-badge-url.py` URL validation** — the existing `_validate_badge_url()` with domain allowlist is preserved. The `requests` migration doesn't weaken the validation.
- **No new `shell=True` usage.** All subprocess calls remain `shell=False`.

The main risks are the eager module-level imports in the hook runner (performance), the `requests` dependency gap in CI, and the mypy relaxation for tests. None are blockers.
