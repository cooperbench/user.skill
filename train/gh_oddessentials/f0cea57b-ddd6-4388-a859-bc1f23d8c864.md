**1. `--version` flag doesn't exist**
- `ado-insights --version` fails with `error: the following arguments are required: command`
- The parser at line 47-69 has no `parser.add_argument("--version", ...)` call
- Standard CLI convention — users expect this to work

**2. No `__main__.py` — `python -m ado_git_repo_insights` fails**
- Error: `No module named ado_git_repo_insights.__main__`
- Missing `src/ado_git_repo_insights/__main__.py` file
- Standard Python convention for package invocation

**3. Version always reports `0.0.0` in dev installs**
- `__init__.py` line 3: `__version__ = "0.0.0"  # Managed by setuptools_scm`
- setuptools_scm is configured in `pyproject.toml` but has no `write_to` directive
- During `pip install -e .`, setuptools_scm computes the version (e.g., `5.27.2.dev89+g3bf5b3ba7`) but never writes it back to `__init__.py`
- The `doctor` command reports version via `get_tool_version()` which likely reads from package metadata (works), but `__version__` stays `0.0.0`
- Published releases (5.28.1 via uv) work because the build step sets the version in package metadata

**4. `doctor` says "Scripts Directory: On PATH: No" for uv installs**
- uv manages its own PATH via shims, but the doctor check doesn't understand this
- Reports a false concern for uv users

**5. Eager imports at module load time**
- Lines 14-37: cli.py imports 10+ internal modules at import time (config, extractor, database, aggregators, csv_generator, etc.)
- If any dependency is broken or missing, even `--help` would crash
- The `doctor` and `setup-path` commands don't need most of these imports
- CI's `test-base-no-ml` job verifies this doesn't crash without ML deps, but it's fragile

**6. `extract` doesn't require `--organization` or `--projects`**
- Lines 76-85: both are `type=str` with no `required=True`
- Only `--pat` is required
- User can run `ado-insights extract --pat xxx` and get a confusing error later when config validation fails, instead of an argparse error upfront

### What Works Well

- `ado-insights --help` works and is clear
- All subcommand help works (`extract --help`, `stage-artifacts --help`, etc.)
- `ado-insights doctor` works and gives useful diagnostics
- `ado-insights dashboard` works with existing `run_artifacts/`
- The `stage-artifacts` → `dashboard` pipeline is well-designed
- Error handling is comprehensive (typed exceptions, minimal summaries on failure)
- Security: PAT never logged, path traversal checks, safe ZIP extraction
