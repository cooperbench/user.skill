> AGENT

仕方ないわけではないです。今の ```yml on: push: pull_request: ``` だと、同じブランチで PR を開いている間は、`push` と `pull_request` の両方で走りやすいです。 よくある選択肢は 3 つです。 1. `pull_request` だけにする PR ベースでレビューする運用なら一番すっきりします。PR を作る前のブランチ push では走らなくなります。 2. `push` をデフォルトブランチだけに絞る たとえば `main` への push と、全 PR で走らせる形です。重複をかなり減らせます。 ```yml on: push: branches: - main pull_request: ``` 3. 両方残して concurrency で古い実行を打ち切る 完全な重複防止ではないですが、無駄は減らせます。 今回の用途なら、たぶん `push` は `main` だけにして `pull_request` は残す、が一番自然です。必要ならその形に直します。
