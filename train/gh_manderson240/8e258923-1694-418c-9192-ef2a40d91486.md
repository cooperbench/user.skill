`★ Insight ─────────────────────────────────────`
**Hook layering in Claude Code:** Settings merge from 3 layers: global (`~/.claude/settings.json`) + project (`.claude/settings.json`) + local (`.claude/settings.local.json`). Hooks are **additive** across layers — there's no "override" mechanism. This means having the same hook in multiple layers causes it to fire multiple times. The fix pattern: put common hooks at the global level, project-specific hooks at the project level, and never duplicate between them.

**`set -e` in hooks vs scripts:** `set -euo pipefail` is excellent for deployment scripts where you WANT to fail fast on any error. But hooks have a different contract: they must be resilient observers that never block the main flow. A hook that crashes produces no output, which can corrupt structured output (like our JSON case) or silently disable monitoring.
