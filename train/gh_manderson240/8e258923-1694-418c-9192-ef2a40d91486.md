`★ Insight ─────────────────────────────────────` **`set -euo pipefail` vs "non-blocking" hooks:** This is a classic shell scripting contradiction. `set -e` ("exit on error") kills a script the moment any command returns non-zero. `pipefail` extends this to any stage of a pipeline. So `ls nonexistent 2>/dev/null | wc -l` silently swallows the error message but still has a non-zero exit code from `ls`, which `pipefail` propagates and `set -e` catches — crashing the script. Hooks labeled "non-blocking: always exits 0" should never use `set -e` because their contract is "never crash, never block." **Why triple ruff:** Claude Code merges hooks from all settings layers (global `~/.claude/settings.json` + project `.claude/settings.json` + local `.claude/settings.local.json`).
