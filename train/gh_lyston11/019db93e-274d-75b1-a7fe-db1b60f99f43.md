# 结论

Hermes Agent 更像一个长期运行的 agent 中枢，而不是单一聊天机器人。它原生支持图片生成、TTS、浏览器自动化、脚本编排，并且可以挂载外部 MCP server。  
但就“视频生成”来说，Hermes 本体没有专门的视频生成工具，最佳做法是接第三方视频 MCP server。

# 原生能力

- 官方文档列出一整套内置工具，覆盖 browser、file、terminal、web、vision、image_gen、tts、skills、code_execution 等。
- `image_generate` 走 FAL.ai。
- `text_to_speech` 负责语音生成。
- `execute_code` 可以运行 Python 脚本，并在脚本里调用 Hermes 工具。
- `skill_manage`、`skill_view`、`skills_list` 属于 Skills 工具集，负责技能管理和浏览。

# Skills 机制

- Skills 是“按需加载的知识文档”。
- Skills 默认存放在 `~/.hermes/skills/`，Hub 安装和 agent 自建的 skill 也会落这里。
- Skills 支持 `scripts/`、`templates/`、`references/`、`assets/`。
- 官方明确建议：复杂逻辑、XML/JSON 解析等，优先放到 helper scripts 里，不要每次都让模型现场手写。
- Hermes 也支持外部 skill 目录扫描，比如共享的 `~/.agents/skills/`。

## 和图片/视频相关的技能

### 默认 bundled skills

- `ascii-video`：把视频/音频/图片/生成内容转成彩色 ASCII 视频，可输出 MP4、GIF、序列帧。
- `manim-video`：数学、算法、技术解释类动画视频，偏讲解和可视化演示。
- `p5js`：生成浏览器创意视觉内容，可导出 GIF、MP4、SVG。
- `inference-sh-cli`：通过 `infsh` 调用 150+ AI apps，覆盖 image generation、video creation、3D 等。

### optional / 扩展技能

- `blender-mcp`：控制 Blender，适合 3D 对象、材质、镜头和动画。
- `touchdesigner-mcp`：控制 TouchDesigner，适合实时音画、VJ、GLSL 可视化。
- `stable-diffusion-image-generation`：偏图片生成，但很适合拿来做图生视频的首帧、角色设定图、场景素材图。

这些 skill 里既有纯图片生成，也有可直接产出 MP4、GIF、动画或中间素材的路径，适合包装成 Hermes 的视频工作流。

# MCP 能力

- Hermes 可以连接任意 MCP server。
- 支持两类接入：
  - `stdio` 本地子进程
  - `HTTP` 远程 MCP endpoint
- MCP 工具会自动注册成 `mcp_<server>_<tool>`。
- 可以按 server 做 `include` / `exclude`。
- 也可以关闭 `resources` / `prompts` 包装器。
- MCP 配置放在 `~/.hermes/config.yaml` 的 `mcp_servers` 下。
- 官方还提供：
  - `native-mcp`：Hermes 内置 MCP client
  - `mcporter`：命令行桥接 MCP server
  - `fastmcp`：用 Python 快速创建 MCP server

# 多 Agent 使用

Hermes 的“多 agent”不是单一机制，官方实际上提供两条路：

- 会话内委派：父 agent 通过 `delegate_task` 拉起子 agent，适合并行研究、并行调试、上下文隔离。
- 独立 profile：在一台机器上运行多个互相独立的 Hermes 实例，适合把“代码助手”“研究助手”“视频助手”彻底分开。

## 1. 子 Agent 委派

- 核心工具是 `delegate_task`。
- 每个子 agent 都有独立会话、独立 terminal、独立工具集。
- 子 agent 默认不知道父 agent 上下文，只有你传入的 `goal` 和 `context`。
- 父 agent 最终只收到子 agent 的总结，不会把中间过程全部塞回上下文窗口。
- 最多并行 `3` 个子 agent。
- 默认有迭代上限，文档示例是 `50`。
- 子 agent 不能继续递归委派，也不能调用 `clarify`、`memory`、`send_message`、`execute_code`。

### 典型用法

```python
delegate_task(
    goal="Research three video generation MCP servers",
    context="""Compare PixVerse-MCP, Creatify MCP, and ComfyUI MCP.
    Focus on text-to-video, image-to-video, lip sync, API stability,
    and whether they are suitable for Hermes integration.""",
    toolsets=["web"]
)
```

### 并行批量委派

```python
delegate_task(tasks=[
    {
        "goal": "Research PixVerse-MCP",
        "context": "Focus on text-to-video, image-to-video, transitions, lip sync",
        "toolsets": ["web"]
    },
    {
        "goal": "Research Creatify MCP",
        "context": "Focus on avatar video, shorts, URL-to-video, script generation",
        "toolsets": ["web"]
    },
    {
        "goal": "Review local ComfyUI workflows",
        "context": "Focus on whether video pipelines can be exposed cleanly through MCP",
        "toolsets": ["web", "file"]
    }
])
```

## 2. 多 Profile 并行运行

- Hermes 支持 profile。
- 每个 profile 都有独立的 `config.yaml`、`.env`、memory、sessions、skills、cron、gateway 状态。
- 创建 profile 后会自动生成同名命令。
- 这适合把不同职责拆成多个长期运行 agent。

### 官方示例

```bash
hermes profile create coder
coder setup
coder chat
```

如果你再建一个 `video` profile，那么它会有自己独立的技能、MCP 配置和会话历史，可以专门服务视频生成。

## 3. 对视频生成的实际意义

- 父 agent 负责任务拆解和结果汇总。
- 子 agent 1 研究提示词和分镜。
- 子 agent 2 调 MCP 跑图片或视频生成。
- 子 agent 3 做素材检查、失败重试或参数对比。
- 如果你有长期的视频生产工作流，建议单独建一个 `video` profile，避免和 coding/profile 的记忆、skills、工具权限混在一起。

## 4. 配置建议

可以在 `~/.hermes/config.yaml` 里单独给 delegation 配更便宜或更快的模型：

```yaml
delegation:
  max_iterations: 50
  default_toolsets: ["terminal", "file", "web"]
  model: "google/gemini-3-flash-preview"
  provider: "openrouter"
```

如果视频生成主要依赖 MCP，建议让父 agent 保留 `delegation` 和少量调度工具，把具体生成工具放进视频专用 profile 或视频专用 MCP 白名单里。

# 视频生成调研结果

Hermes 本体没有原生 video generation tool，所以视频能力主要靠 MCP 接入。当前更值得看的方向是：

- `PixVerse-MCP`：最直接，支持 text-to-video、image-to-video、转场、lip sync、sound effects、fusion video。
- `Creatify MCP`：12 个工具，覆盖 avatar 视频、URL-to-video、AI shorts、脚本生成、advanced lip-sync。
- `ComfyUI MCP Server`：本地 ComfyUI 的 MCP 封装，可生成和迭代 refinement 图像/音频/视频。
- `Placid MCP Server`：模板化图片和视频 creatives。

## 推荐优先级

1. 先看 `PixVerse-MCP`，最贴近“直接做视频生成”。
2. 如果你要本地可控管线，再接 `ComfyUI MCP`。
3. 如果你的目标是短视频、口播、营销素材，补 `Creatify MCP`。

## 按场景选型对比

| 目标场景 | 最优先方案 | 备选方案 | 更适合的原因 | 主要限制 |
|---|---|---|---|---|
| 文生视频 | `PixVerse-MCP` | `Creatify MCP`、`inference-sh-cli` | PixVerse README 直接强调 text-to-video、video extension、transition、sound effects，最贴近“直接生成成片” | 更偏云端 API，成本和额度受平台限制 |
| 图生视频 | `PixVerse-MCP` | `ComfyUI MCP Server` | PixVerse 原生支持 image-to-video；如果你已经有角色图/场景图，上手最快 | 可控性不如本地工作流细，调参空间取决于平台 |
| 数字人口播 / Avatar 视频 | `Creatify MCP` | `PixVerse-MCP` | Creatify README 明确覆盖 avatar videos、advanced lip-sync、emotion control、script generation、URL-to-video | 偏营销和商业视频范式，不是最强的通用创意视频工具 |
| 本地可控工作流 | `ComfyUI MCP Server` | `blender-mcp`、`touchdesigner-mcp` | ComfyUI MCP 强在本地模型、可插工作流 JSON、可复现实验、可接私有模型 | 部署和调 workflow 成本高，默认不是“开箱即用成片” |
| 模板化营销视频 | `Placid MCP Server` | `Creatify MCP` | Placid 以模板为核心，适合批量生成 banner/video creatives | 创意自由度低，更像模板引擎，不像生成式视频导演 |
| 技术动画 / 教学视频 | `manim-video` | `p5js`、`blender-mcp` | Hermes 自带 manim skill，最适合公式、算法、图解、解释型视频 | 不适合写实人物视频或商业广告视频 |
| 创意视觉 / 音画装置 | `p5js` | `touchdesigner-mcp`、`ascii-video` | p5js 出图快、迭代轻；TouchDesigner 更适合现场视觉和实时系统 | 更偏视觉设计，不是主流 AI 文生视频路线 |

## 实际组合建议

- 想最快落地文生视频和图生视频：`Hermes + PixVerse-MCP`
- 想做 AI 数字人、短视频口播、广告素材：`Hermes + Creatify MCP`
- 想保留本地模型和强可控性：`Hermes + ComfyUI MCP Server`
- 想做解释型内容、课程动画、算法演示：`Hermes + manim-video`
- 想做风格化视觉、MV、终端感/ASCII 风格视频：`Hermes + p5js` 或 `Hermes + ascii-video`

    64	# 多 Agent 使用
    65	
    66	Hermes 的“多 agent”不是单一机制，官方实际上提供两条路：
    67	
    68	- 会话内委派：父 agent 通过 `delegate_task` 拉起子 agent，适合并行研究、并行调试、上下文隔离。
    69	- 独立 profile：在一台机器上运行多个互相独立的 Hermes 实例，适合把“代码助手”“研究助手”“视频助手”彻底分开。
    70	
    71	## 1. 子 Agent 委派
    72	
    73	- 核心工具是 `delegate_task`。
    74	- 每个子 agent 都有独立会话、独立 terminal、独立工具集。
    75	- 子 agent 默认不知道父 agent 上下文，只有你传入的 `goal` 和 `context`。
    76	- 父 agent 最终只收到子 agent 的总结，不会把中间过程全部塞回上下文窗口。
    77	- 最多并行 `3` 个子 agent。
    78	- 默认有迭代上限，文档示例是 `50`。
    79	- 子 agent 不能继续递归委派，也不能调用 `clarify`、`memory`、`send_message`、`execute_code`。
    80	
    81	### 典型用法
    82	
    83	```python
    84	delegate_task(
    85	    goal="Research three video generation MCP servers",
    86	    context="""Compare PixVerse-MCP, Creatify MCP, and ComfyUI MCP.
    87	    Focus on text-to-video, image-to-video, lip sync, API stability,
    88	    and whether they are suitable for Hermes integration.""",
    89	    toolsets=["web"]
    90	)
    91	```
    92	
    93	### 并行批量委派
    94	
    95	```python
    96	delegate_task(tasks=[
    97	    {
    98	        "goal": "Research PixVerse-MCP",
    99	        "context": "Focus on text-to-video, image-to-video, transitions, lip sync",
   100	        "toolsets": ["web"]
   101	    },
   102	    {
   103	        "goal": "Research Creatify MCP",
   104	        "context": "Focus on avatar video, shorts, URL-to-video, script generation",
   105	        "toolsets": ["web"]
   106	    },
   107	    {
   108	        "goal": "Review local ComfyUI workflows",
   109	        "context": "Focus on whether video pipelines can be exposed cleanly through MCP",
   110	        "toolsets": ["web", "file"]
   111	    }
   112	])
   113	```

   154	# 视频生成调研结果
   155	
   156	Hermes 本体没有原生 video generation tool，所以视频能力主要靠 MCP 接入。当前更值得看的方向是：
   157	
   158	- `PixVerse-MCP`：最直接，支持 text-to-video、image-to-video、转场、lip sync、sound effects、fusion video。
   159	- `Creatify MCP`：12 个工具，覆盖 avatar 视频、URL-to-video、AI shorts、脚本生成、advanced lip-sync。
   160	- `ComfyUI MCP Server`：本地 ComfyUI 的 MCP 封装，可生成和迭代 refinement 图像/音频/视频。
   161	- `Placid MCP Server`：模板化图片和视频 creatives。
   162	
   163	## 推荐优先级
   164	
   165	1. 先看 `PixVerse-MCP`，最贴近“直接做视频生成”。
   166	2. 如果你要本地可控管线，再接 `ComfyUI MCP`。
   167	3. 如果你的目标是短视频、口播、营销素材，补 `Creatify MCP`。

# MCP 能力

- Hermes 可以连接任意 MCP server。
- 支持两类接入：
  - `stdio` 本地子进程
  - `HTTP` 远程 MCP endpoint
- MCP 工具会自动注册成 `mcp_<server>_<tool>`。
- 可以按 server 做 `include` / `exclude`。
- 也可以关闭 `resources` / `prompts` 包装器。
- MCP 配置放在 `~/.hermes/config.yaml` 的 `mcp_servers` 下。
- 官方还提供：
  - `native-mcp`：Hermes 内置 MCP client
  - `mcporter`：命令行桥接 MCP server
  - `fastmcp`：用 Python 快速创建 MCP server

# 多 Agent 使用

Hermes 的“多 agent”不是单一机制，官方实际上提供两条路：

- 会话内委派：父 agent 通过 `delegate_task` 拉起子 agent，适合并行研究、并行调试、上下文隔离。
- 独立 profile：在一台机器上运行多个互相独立的 Hermes 实例，适合把“代码助手”“研究助手”“视频助手”彻底分开。

## 1. 子 Agent 委派

- 核心工具是 `delegate_task`。
- 每个子 agent 都有独立会话、独立 terminal、独立工具集。
- 子 agent 默认不知道父 agent 上下文，只有你传入的 `goal` 和 `context`。
- 父 agent 最终只收到子 agent 的总结，不会把中间过程全部塞回上下文窗口。
- 最多并行 `3` 个子 agent。
- 默认有迭代上限，文档示例是 `50`。
- 子 agent 不能继续递归委派，也不能调用 `clarify`、`memory`、`send_message`、`execute_code`。

### 典型用法

```python
delegate_task(
    goal="Research three video generation MCP servers",
    context="""Compare PixVerse-MCP, Creatify MCP, and ComfyUI MCP.
    Focus on text-to-video, image-to-video, lip sync, API stability,
    and whether they are suitable for Hermes integration.""",
    toolsets=["web"]
)
```

### 并行批量委派

```python
delegate_task(tasks=[
    {
        "goal": "Research PixVerse-MCP",
        "context": "Focus on text-to-video, image-to-video, transitions, lip sync",
        "toolsets": ["web"]
    },
    {
        "goal": "Research Creatify MCP",
        "context": "Focus on avatar video, shorts, URL-to-video, script generation",
        "toolsets": ["web"]
    },
    {
        "goal": "Review local ComfyUI workflows",
        "context": "Focus on whether video pipelines can be exposed cleanly through MCP",
        "toolsets": ["web", "file"]
    }
])
```

## 2. 多 Profile 并行运行

- Hermes 支持 profile。
- 每个 profile 都有独立的 `config.yaml`、`.env`、memory、sessions、skills、cron、gateway 状态。
- 创建 profile 后会自动生成同名命令。
- 这适合把不同职责拆成多个长期运行 agent。

### 官方示例

```bash
hermes profile create coder
coder setup
coder chat
```

如果你再建一个 `video` profile，那么它会有自己独立的技能、MCP 配置和会话历史，可以专门服务视频生成。

## 3. 对视频生成的实际意义

- 父 agent 负责任务拆解和结果汇总。
- 子 agent 1 研究提示词和分镜。
- 子 agent 2 调 MCP 跑图片或视频生成。
- 子 agent 3 做素材检查、失败重试或参数对比。
- 如果你有长期的视频生产工作流，建议单独建一个 `video` profile，避免和 coding/profile 的记忆、skills、工具权限混在一起。

## 4. 配置建议

可以在 `~/.hermes/config.yaml` 里单独给 delegation 配更便宜或更快的模型：

```yaml
delegation:
  max_iterations: 50
  default_toolsets: ["terminal", "file", "web"]
  model: "google/gemini-3-flash-preview"
  provider: "openrouter"
```

如果视频生成主要依赖 MCP，建议让父 agent 保留 `delegation` 和少量调度工具，把具体生成工具放进视频专用 profile 或视频专用 MCP 白名单里。

# 视频生成调研结果

Hermes 本体没有原生 video generation tool，所以视频能力主要靠 MCP 接入。当前更值得看的方向是：

- `PixVerse-MCP`：最直接，支持 text-to-video、image-to-video、转场、lip sync、sound effects、fusion video。
- `Creatify MCP`：12 个工具，覆盖 avatar 视频、URL-to-video、AI shorts、脚本生成、advanced lip-sync。
- `ComfyUI MCP Server`：本地 ComfyUI 的 MCP 封装，可生成和迭代 refinement 图像/音频/视频。
- `Placid MCP Server`：模板化图片和视频 creatives。

## 推荐优先级

1. 先看 `PixVerse-MCP`，最贴近“直接做视频生成”。
2. 如果你要本地可控管线，再接 `ComfyUI MCP`。
3. 如果你的目标是短视频、口播、营销素材，补 `Creatify MCP`。

## 按场景选型对比

| 目标场景 | 最优先方案 | 备选方案 | 更适合的原因 | 主要限制 |
|---|---|---|---|---|
| 文生视频 | `PixVerse-MCP` | `Creatify MCP`、`inference-sh-cli` | PixVerse README 直接强调 text-to-video、video extension、transition、sound effects，最贴近“直接生成成片” | 更偏云端 API，成本和额度受平台限制 |
| 图生视频 | `PixVerse-MCP` | `ComfyUI MCP Server` | PixVerse 原生支持 image-to-video；如果你已经有角色图/场景图，上手最快 | 可控性不如本地工作流细，调参空间取决于平台 |
| 数字人口播 / Avatar 视频 | `Creatify MCP` | `PixVerse-MCP` | Creatify README 明确覆盖 avatar videos、advanced lip-sync、emotion control、script generation、URL-to-video | 偏营销和商业视频范式，不是最强的通用创意视频工具 |
| 本地可控工作流 | `ComfyUI MCP Server` | `blender-mcp`、`touchdesigner-mcp` | ComfyUI MCP 强在本地模型、可插工作流 JSON、可复现实验、可接私有模型 | 部署和调 workflow 成本高，默认不是“开箱即用成片” |
| 模板化营销视频 | `Placid MCP Server` | `Creatify MCP` | Placid 以模板为核心，适合批量生成 banner/video creatives | 创意自由度低，更像模板引擎，不像生成式视频导演 |
| 技术动画 / 教学视频 | `manim-video` | `p5js`、`blender-mcp` | Hermes 自带 manim skill，最适合公式、算法、图解、解释型视频 | 不适合写实人物视频或商业广告视频 |
| 创意视觉 / 音画装置 | `p5js` | `touchdesigner-mcp`、`ascii-video` | p5js 出图快、迭代轻；TouchDesigner 更适合现场视觉和实时系统 | 更偏视觉设计，不是主流 AI 文生视频路线 |

## 实际组合建议

- 想最快落地文生视频和图生视频：`Hermes + PixVerse-MCP`
- 想做 AI 数字人、短视频口播、广告素材：`Hermes + Creatify MCP`
- 想保留本地模型和强可控性：`Hermes + ComfyUI MCP Server`
- 想做解释型内容、课程动画、算法演示：`Hermes + manim-video`
- 想做风格化视觉、MV、终端感/ASCII 风格视频：`Hermes + p5js` 或 `Hermes + ascii-video`

# MCP 能力

- Hermes 可以连接任意 MCP server。
- 支持两类接入：
  - `stdio` 本地子进程
  - `HTTP` 远程 MCP endpoint
- MCP 工具会自动注册成 `mcp_<server>_<tool>`。
- 可以按 server 做 `include` / `exclude`。
- 也可以关闭 `resources` / `prompts` 包装器。
- MCP 配置放在 `~/.hermes/config.yaml` 的 `mcp_servers` 下。
- 官方还提供：
  - `native-mcp`：Hermes 内置 MCP client
  - `mcporter`：命令行桥接 MCP server
  - `fastmcp`：用 Python 快速创建 MCP server

# 多 Agent 使用

Hermes 的“多 agent”不是单一机制，官方实际上提供两条路：

- 会话内委派：父 agent 通过 `delegate_task` 拉起子 agent，适合并行研究、并行调试、上下文隔离。
- 独立 profile：在一台机器上运行多个互相独立的 Hermes 实例，适合把“代码助手”“研究助手”“视频助手”彻底分开。

## 1. 子 Agent 委派

- 核心工具是 `delegate_task`。
- 每个子 agent 都有独立会话、独立 terminal、独立工具集。
- 子 agent 默认不知道父 agent 上下文，只有你传入的 `goal` 和 `context`。
- 父 agent 最终只收到子 agent 的总结，不会把中间过程全部塞回上下文窗口。
- 最多并行 `3` 个子 agent。
- 默认有迭代上限，文档示例是 `50`。
- 子 agent 不能继续递归委派，也不能调用 `clarify`、`memory`、`send_message`、`execute_code`。

### 典型用法

```python
delegate_task(
    goal="Research three video generation MCP servers",
    context="""Compare PixVerse-MCP, Creatify MCP, and ComfyUI MCP.
    Focus on text-to-video, image-to-video, lip sync, API stability,
    and whether they are suitable for Hermes integration.""",
    toolsets=["web"]
)
```

### 并行批量委派

```python
delegate_task(tasks=[
    {
        "goal": "Research PixVerse-MCP",
        "context": "Focus on text-to-video, image-to-video, transitions, lip sync",
        "toolsets": ["web"]
    },
    {
        "goal": "Research Creatify MCP",
        "context": "Focus on avatar video, shorts, URL-to-video, script generation",
        "toolsets": ["web"]
    },
    {
        "goal": "Review local ComfyUI workflows",
        "context": "Focus on whether video pipelines can be exposed cleanly through MCP",
        "toolsets": ["web", "file"]
    }
])
```

## 2. 多 Profile 并行运行

- Hermes 支持 profile。
- 每个 profile 都有独立的 `config.yaml`、`.env`、memory、sessions、skills、cron、gateway 状态。
- 创建 profile 后会自动生成同名命令。
- 这适合把不同职责拆成多个长期运行 agent。

### 官方示例

```bash
hermes profile create coder
coder setup
coder chat
```

如果你再建一个 `video` profile，那么它会有自己独立的技能、MCP 配置和会话历史，可以专门服务视频生成。

## 3. 对视频生成的实际意义

- 父 agent 负责任务拆解和结果汇总。
- 子 agent 1 研究提示词和分镜。
- 子 agent 2 调 MCP 跑图片或视频生成。
- 子 agent 3 做素材检查、失败重试或参数对比。
- 如果你有长期的视频生产工作流，建议单独建一个 `video` profile，避免和 coding/profile 的记忆、skills、工具权限混在一起。

## 4. 配置建议

可以在 `~/.hermes/config.yaml` 里单独给 delegation 配更便宜或更快的模型：

```yaml
delegation:
  max_iterations: 50
  default_toolsets: ["terminal", "file", "web"]
  model: "google/gemini-3-flash-preview"
  provider: "openrouter"
```

如果视频生成主要依赖 MCP，建议让父 agent 保留 `delegation` 和少量调度工具，把具体生成工具放进视频专用 profile 或视频专用 MCP 白名单里。

# 视频生成调研结果

Hermes 本体没有原生 video generation tool，所以视频能力主要靠 MCP 接入。当前更值得看的方向是：

- `PixVerse-MCP`：最直接，支持 text-to-video、image-to-video、转场、lip sync、sound effects、fusion video。
- `Creatify MCP`：12 个工具，覆盖 avatar 视频、URL-to-video、AI shorts、脚本生成、advanced lip-sync。
- `ComfyUI MCP Server`：本地 ComfyUI 的 MCP 封装，可生成和迭代 refinement 图像/音频/视频。
- `Placid MCP Server`：模板化图片和视频 creatives。

## 推荐优先级

1. 先看 `PixVerse-MCP`，最贴近“直接做视频生成”。
2. 如果你要本地可控管线，再接 `ComfyUI MCP`。
3. 如果你的目标是短视频、口播、营销素材，补 `Creatify MCP`。

## 按场景选型对比

| 目标场景 | 最优先方案 | 备选方案 | 更适合的原因 | 主要限制 |
|---|---|---|---|---|
| 文生视频 | `PixVerse-MCP` | `Creatify MCP`、`inference-sh-cli` | PixVerse README 直接强调 text-to-video、video extension、transition、sound effects，最贴近“直接生成成片” | 更偏云端 API，成本和额度受平台限制 |
| 图生视频 | `PixVerse-MCP` | `ComfyUI MCP Server` | PixVerse 原生支持 image-to-video；如果你已经有角色图/场景图，上手最快 | 可控性不如本地工作流细，调参空间取决于平台 |
| 数字人口播 / Avatar 视频 | `Creatify MCP` | `PixVerse-MCP` | Creatify README 明确覆盖 avatar videos、advanced lip-sync、emotion control、script generation、URL-to-video | 偏营销和商业视频范式，不是最强的通用创意视频工具 |
| 本地可控工作流 | `ComfyUI MCP Server` | `blender-mcp`、`touchdesigner-mcp` | ComfyUI MCP 强在本地模型、可插工作流 JSON、可复现实验、可接私有模型 | 部署和调 workflow 成本高，默认不是“开箱即用成片” |
| 模板化营销视频 | `Placid MCP Server` | `Creatify MCP` | Placid 以模板为核心，适合批量生成 banner/video creatives | 创意自由度低，更像模板引擎，不像生成式视频导演 |
| 技术动画 / 教学视频 | `manim-video` | `p5js`、`blender-mcp` | Hermes 自带 manim skill，最适合公式、算法、图解、解释型视频 | 不适合写实人物视频或商业广告视频 |
| 创意视觉 / 音画装置 | `p5js` | `touchdesigner-mcp`、`ascii-video` | p5js 出图快、迭代轻；TouchDesigner 更适合现场视觉和实时系统 | 更偏视觉设计，不是主流 AI 文生视频路线 |

## 实际组合建议

- 想最快落地文生视频和图生视频：`Hermes + PixVerse-MCP`
- 想做 AI 数字人、短视频口播、广告素材：`Hermes + Creatify MCP`
- 想保留本地模型和强可控性：`Hermes + ComfyUI MCP Server`
- 想做解释型内容、课程动画、算法演示：`Hermes + manim-video`
- 想做风格化视觉、MV、终端感/ASCII 风格视频：`Hermes + p5js` 或 `Hermes + ascii-video`

# 一句话结论

Hermes Agent 更像一个长期运行的 agent 中枢，而不是单一聊天机器人。  
它擅长做三件事：

1. 统一调度工具、技能、MCP 和子 agent
2. 记住你的工作流、模板和偏好

# 1. Hermes 的原生边界

## 1.1 Hermes 原生能做什么

- 官方文档列出一整套内置工具，覆盖 `browser`、`file`、`terminal`、`web`、`vision`、`image_gen`、`tts`、`skills`、`code_execution` 等。
- `image_generate` 走 `FAL.ai`，说明 Hermes 在图片生成上已经有原生入口。
- `text_to_speech` 负责语音生成。
- `execute_code` 可以运行 Python 脚本，并在脚本里继续调用 Hermes 工具。
- `skill_manage`、`skill_view`、`skills_list` 属于 Skills 工具集，负责技能管理和浏览。

## 1.2 Hermes 原生不擅长什么

- 截至 `2026-04-24`，Hermes 本体没有一个与 `image_generate` 对称的原生 `video_generate` 工具。
- 因此视频能力不应理解成“Hermes 自己会生成视频”，而应理解成“Hermes 很适合编排外部视频工具”。
- 换句话说，Hermes 的核心价值在 orchestration，而不是自己内置所有媒体生成模型。

# 2. Skills 体系

## 2.1 Skills 是什么

- Skills 是按需加载的知识文档和工作流封装。
- 默认存放在 `~/.hermes/skills/`。
- Skills 支持 `scripts/`、`templates/`、`references/`、`assets/`。
- 官方明确建议：复杂逻辑、结构化解析、重复脚本最好放进 helper scripts，而不是每次让模型现场手写。
- Hermes 也支持外部 skill 目录扫描，比如共享的 `~/.agents/skills/`。

## 2.2 Skills Hub 的实际意义

按照这次搜索看到的官方文档，Hermes 现在已经支持从多个来源搜索、安装和更新 skills，包括：

- `official`
- `skills-sh`
- `github`
- `well-known`

这意味着 Hermes 不只是“有 skill 机制”，而是已经具备一个可扩展的 skill 分发体系。  
对你最重要的变化是：图片、剧本、视频相关能力，不必等官方内置，完全可以通过 GitHub 和 `skills.sh` 接进来。

## 2.3 安装和审计建议

对长期运行的 Hermes profile，推荐统一使用下面的判断顺序：

1. `search`：先确认有没有现成 skill
2. `inspect`：看 skill 做什么、依赖什么
3. `audit`：确认它需要哪些 shell 权限、CLI、API key
4. `install`：最后再装进长期 profile

示例：

```bash

hermes skills search storyboard --source skills-sh

# 3. MCP 体系

## 3.1 Hermes 如何接 MCP

- Hermes 可以连接任意 MCP server
- 支持两类接入：
  - `stdio` 本地子进程
  - `HTTP` 远程 MCP endpoint
- MCP 工具会自动注册成 `mcp_<server>_<tool>`
- 可以按 server 做 `include` / `exclude`
- 也可以关闭 `resources` / `prompts` 包装器
- MCP 配置放在 `~/.hermes/config.yaml` 的 `mcp_servers` 下

Hermes 官方自己也提供了一套 MCP 相关能力：

- `mcp/native-mcp`
- `mcp/mcporter`
- `mcp/fastmcp`

# 6. 多 Agent 和多 Profile 的实际意义

Hermes 的“多 agent”不是一个单独开关，而是两条路线：

- 会话内委派：通过 `delegate_task` 拉起子 agent
- 独立 profile：把不同职责拆成长期运行的独立 Hermes 实例

## 6.1 子 agent 更适合什么

- 并行研究不同 MCP
- 并行写 prompt 和分镜
- 并行对比不同视频模型输出
- 把大任务拆成“调度”和“执行”两层

示例：

```python
delegate_task(tasks=[
    {
        "goal": "Research PixVerse-MCP",
        "context": "Focus on text-to-video, image-to-video, transitions and lip sync",
        "toolsets": ["web"]
    },
    {
        "goal": "Draft a storyboard for a 30-second product video",
        "context": "Create shot list, pacing, transitions and model-friendly prompts",
        "toolsets": ["file", "web"]
    }
])
```

## 6.2 独立 profile 更适合什么

- 把 coding 和记忆与视频工作流隔离
- 给视频 profile 单独配 skill、MCP 白名单、API key
- 把“研究助手”和“视频助手”彻底分开

官方示例：

```bash
hermes profile create coder
coder setup
coder chat
```

如果再建一个 `video` profile，它就可以拥有独立的：

- `config.yaml`
- `.env`
- skills
- memory
- sessions
- cron
- gateway 状态
