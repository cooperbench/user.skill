The Copilot CLI has a bug (tracked as [github/copilot-cli#1750](https://github.com/github/copilot-cli/issues/1750)) where it appends a **dot-prefixed** directory name under XDG paths instead of a bare name. **What should happen (XDG convention):** - `$XDG_CONFIG_HOME/copilot/` - `$XDG_STATE_HOME/copilot/` **What actually happens:** - `$XDG_CONFIG_HOME/.copilot/` - `$XDG_STATE_HOME/.copilot/` The extra `.` prefix is wrong — XDG directories are already "hidden" by being under a non-default base path, so dot-prefixing is redundant and breaks convention. But since real users have configs at these buggy paths, our seatbelt module needs to handle **both** the current (buggy) and eventual (fixed) paths to be forward-compatible. This is why Approach B matters — if we only handle `~/.copilot`, users who set `XDG_CONFIG_HOME` would have their config dir outside the sandbox's allow rules. So — are you good with Approach B?
