## Issue #588: `is_container_available()` ignores Podman

**Root cause**: `is_container_available()` only checks Docker and Apple Container, but `detect_backend()` correctly includes Podman. This means Podman users hit the early guard in `pool.rs:363` before `detect_backend()` ever runs.

**Fix** — 3 changes, all straightforward:

### 1. `crates/browser/src/container.rs:757` — Add Podman check
```rust
pub fn is_container_available() -> bool {
    #[cfg(target_os = "macos")]
    if is_apple_container_available() {
        return true;
    }
    ContainerBackend::Podman.is_available() || is_docker_available()
}
```

### 2. `crates/browser/src/pool.rs:362-368` — Update error message to mention Podman
The error message says "Docker or Apple Container" — it should say "Docker, Podman, or Apple Container" (or just delegate to `detect_backend()` which already has a good message).

### 3. `crates/httpd/src/tools_routes.rs:351-353` — Update warning message
Same issue — the warning string says "Docker or Apple Container" but should include Podman.

**No structural changes needed** — it's a one-line logic fix plus two string updates. The `detect_backend()` function and all downstream container launch/image code already handle Podman correctly. The bug is purely in the availability gate.
