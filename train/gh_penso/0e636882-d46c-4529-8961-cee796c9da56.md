### Configuration Source

The bind address comes from:
- **Config schema**: `/Users/penso/.superset/worktrees/moltis/abalone-carrot/crates/config/src/schema.rs` (lines 784-788)
  - `pub struct ServerConfig` has `pub bind: String`

- **CLI entry point**: `/Users/penso/.superset/worktrees/moltis/abalone-carrot/crates/cli/src/main.rs` (line 399)

  - Also in service commands: `/Users/penso/.superset/worktrees/moltis/abalone-carrot/crates/cli/src/service_commands.rs`

### The Root Cause

When the user sets `bind = "::"` (IPv6 any address), the code does:
```rust
format!("{bind}:{port}")  // Results in: ":::<port>" INVALID!
```

The SocketAddr parser expects:
- IPv4: `"127.0.0.1:8080"` 
- IPv6: `"[::1]:8080"` (brackets required for bare addresses)

So `::<port>` is invalid syntax.

### Test Examples Found

In `/Users/penso/.superset/worktrees/moltis/abalone-carrot/crates/auth/src/locality.rs` (line 158), tests show the correct IPv6 format:
```rust
let addr: SocketAddr = "[::1]:12345".parse().unwrap();  // Correct - with brackets
```

### Required Fix

Both lines need to properly wrap IPv6 addresses with brackets:
1. **Line 5112 in gateway/src/server.rs**
2. **Line 309 in tls/src/lib.rs**

The fix should use a helper function to format the address correctly, checking if `bind` contains `:` (indicating IPv6) and wrapping with brackets if needed.

Here's a summary of the fix for **GitHub issue #447** (IPv6 bind address crash):

**Root cause:** `format!("{bind}:{port}")` produces unparseable strings for IPv6 addresses. For `bind = "::"` and `port = 8080`, this creates `":::8080"` which fails to parse as a `SocketAddr`.

**Fix:** Parse `bind` as `std::net::IpAddr` first, then construct `SocketAddr::new(ip, port)` directly. This handles both IPv4 and IPv6 correctly without string formatting.
