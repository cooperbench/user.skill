The main fix for worktrees is sharing a single `target/` directory across all of them. By default each worktree gets its own `target/`, duplicating all artifacts. **Option 1: Global cargo config** (`~/.cargo/config.toml`) ```toml [build] target-dir = "/Users/penso/.cargo-target" ``` This makes *all* Rust projects share one target dir. Artifacts are keyed by manifest path so they won't collide, but it does mean `cargo clean` in one project nukes everything. **Option 2: Per-project shared target** (better for your case) In the repo root, create/edit `.cargo/config.toml`: ```toml [build] target-dir = "/Users/penso/tmp/molt/moltis-target" ``` All worktrees of this repo will share that single target dir. Cargo handles concurrent builds with file locks, so it's safe. **Option 3: Environment variable** ```bash export CARGO_TARGET_DIR="$HOME/.cargo-target" ``` Same as option 1 but via env. --- **Other space-saving tips:** - **`cargo clean`** periodically on inactive worktrees - **`cargo sweep`** (install with `cargo install cargo-sweep`) — removes artifacts older than N days: ```bash cargo sweep --time 7 # remove artifacts unused for 7+ days ``` - **sccache** — shared compilation cache so rebuilds across worktrees reuse compiled artifacts: ```bash brew install sccache echo '[build]\nrustc-wrapper = "sccache"' >> ~/.cargo/config.toml ``` For your use case with tons of worktrees, **Option 2** (per-project shared target outside the repo) is the sweet spot — massive space savings without affecting other projects.

Add to `~/.zshrc`: ```bash cargo() { if [ -z "$CARGO_TARGET_DIR" ]; then local toplevel toplevel=$(git rev-parse --show-toplevel 2>/dev/null) if [ -n "$toplevel" ]; then # Derive a stable target dir from the repo, shared across worktrees local repo_name=$(basename "$toplevel") export CARGO_TARGET_DIR="$HOME/.cargo-targets/$repo_name" fi fi command cargo "$@" } ``` This automatically shares `target/` across all worktrees of the same repo without any per-worktree config. 4. **Simplest: global config** (`~/.cargo/config.toml`): ```toml [build] target-dir = ".cargo-target" ``` A relative path like `.cargo-target` puts the target dir *inside* each project root but with a different name you can globally gitignore. This doesn't share across worktrees though — it just keeps `target/` out of the way. **My recommendation:** Option 3 (shell wrapper) gives you automatic per-repo sharing across worktrees with zero per-project setup. If you want something simpler, the global `CARGO_TARGET_DIR` env var works if this is your primary Rust project.

> DEVELOPER

but why is target/debug so massive? 100GB quickly

> AGENT

Rust's `target/debug` is notoriously large because of what debug builds produce: - **Every dependency compiled independently** — a project with 300 crates produces 300 `.rlib` files, each with full debug info - **Debug symbols are huge** — DWARF debug info can be 10-50x the size of the actual code. A single `.rlib` that's 1MB of code becomes 50MB with symbols - **Incremental compilation** — Rust stores fine-grained intermediate artifacts (`.o` files, fingerprints, dep-graphs) so it can recompile only what changed. This roughly doubles the space - **Multiple artifact types per crate** — `.rlib`, `.rmeta`, `.d` (dependency tracking), plus incremental `.o` chunks - **Proc macros** — compiled as separate binaries for the host architecture - **Build scripts** — each `build.rs` gets compiled and its output cached - **Tests and benchmarks** — each `#[test]` function produces a separate binary linking the entire dependency tree. In a workspace with many test targets, this multiplies fast For a workspace like moltis with ~15 crates and hundreds of dependencies, you easily get: ``` ~300 deps × ~50MB each (with debug info) = ~15GB per profile × incremental artifacts = ~30GB × test binaries (one per crate) = ~40-50GB × 2-3 worktrees = 100GB+ ``` **To reduce it:** 1. **Share target across worktrees** (discussed above) — biggest win 2. **Split debug info** — in `Cargo.toml` or a profile: ```toml [profile.dev] debug = "line-tables-only" # instead of full debug — cuts symbols ~5-10x ``` 3. **Disable incremental for CI/one-off builds:** ```bash CARGO_INCREMENTAL=0 cargo build ``` 4. **`cargo clean --profile dev`** periodically 5. **`cargo sweep --time 7`** to prune stale artifacts The `debug = "line-tables-only"` change alone can cut `target/debug` by 50-70% while still giving you useful backtraces. You lose variable inspection in a debugger but stack traces still work.
