# Plan: Fix Podman sandbox startup failure (#757)

## Context

PR #706 added sysfs tmpfs overlays to `hardening_args()` in `docker.rs` to mask host hardware identifiers (serial numbers, BIOS data, disk models, LUKS UUIDs). These work on Docker but break Podman on Ubuntu 24.04/26.04 with both runc and crun.

**Root cause:** When Podman mounts a tmpfs over sysfs paths like `/sys/devices/virtual/dmi`, the OCI runtime performs "tmpcopyup" — copying existing directory contents into the new tmpfs. Some sysfs files (e.g., `board_serial`) are permission-denied even for root inside the container (because `--cap-drop ALL` is active), causing the mount to fail entirely.

Docker does not exhibit this behavior because it handles tmpfs overlay differently on sysfs paths.

## Approach

Skip the sysfs tmpfs overlays when the backend is Podman. Podman's OCI runtime already masks `/sys/firmware` by default via its built-in `MaskedPaths`. For the other paths (`/sys/class/dmi`, `/sys/devices/virtual/dmi`, `/sys/class/block`), losing the masking is acceptable — a slightly less hardened but functional sandbox is better than a broken one.

No config option needed for the initial fix — the backend is already known at runtime (`self.cli`). If users report similar issues with specific Docker configurations later, a config escape hatch can be added as follow-up.

   582→/// in `--add-host` (added in Podman 5.0).
   583→pub(crate) fn podman_supports_host_gateway() -> bool {
   584→    let Ok(output) = std::process::Command::new("podman")
   585→        .args(["version", "--format", "{{.Client.Version}}"])
   586→        .output()
   587→    else {
   588→        return false;
   589→    };
   590→    let version_str = String::from_utf8_lossy(&output.stdout);
   591→    let major: u32 = version_str
   592→        .trim()
   593→        .split('.')
   594→        .next()

   600→/// Resolve the host IP that a Podman container (< 5.0) can use to reach the
   601→/// host.  Rootless Podman defaults to slirp4netns where the host is always
   602→/// `10.0.2.2`.  Rootful Podman uses a bridge network whose gateway we query
   603→/// with `podman network inspect`.
   604→pub(crate) fn podman_resolve_host_ip() -> Option<String> {
   605→    let rootless = std::process::Command::new("podman")
   606→        .args(["info", "--format", "{{.Host.Security.Rootless}}"])
   607→        .output()
   608→        .ok()
   609→        .map(|o| String::from_utf8_lossy(&o.stdout).trim().to_string());
   610→
   611→    if rootless.as_deref() == Some("true") {
   612→        // slirp4netns (default rootless network before Podman 5.0) maps the
   613→        // host to 10.0.2.2.
   614→        return Some("10.0.2.2".to_string());
   615→    }
   616→
   617→    // Rootful — ask for the gateway of the default "podman" network.
   618→    let output = std::process::Command::new("podman")
   619→        .args([
   620→            "network",
   621→            "inspect",
   622→            "podman",
   623→            "--format",
   624→            "{{(index .Subnets 0).Gateway}}",
   625→        ])
   626→        .output()
   627→        .ok()?;
   628→    let gateway = String::from_utf8_lossy(&output.stdout).trim().to_string();
   629→    if gateway.is_empty() {
   630→        None
   631→    } else {
   632→        Some(gateway)
   633→    }
   634→}
