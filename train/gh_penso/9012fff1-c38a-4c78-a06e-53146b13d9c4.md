Here's the analysis and plan for fixing **GitHub issue #501: Manual context compaction breaks chat**. ## Root Cause Both compaction sites (`compact()` at line 4391 and `compact_session()` at line 6907 in `crates/chat/src/lib.rs`) store the summary as `PersistedMessage::Assistant`. After compaction, the session history becomes: ``` system (prompt) → assistant (summary) → system (datetime) → user (new message) ``` Strict LLM servers like llama.cpp require every `assistant` message to be preceded by a `user` message. The orphan `assistant` summary violates this, causing: *"No user query found in messages."* ## Proposed Fix **Change the compacted summary from `PersistedMessage::Assistant` to `PersistedMessage::System`.** A system message is semantically correct — the summary is context, not an LLM response. After the fix, the message sequence becomes: ``` system (prompt) → system (summary) → system (datetime) → user (new message) ``` This is valid for all providers. Two locations need the same change: 1. **`crates/chat/src/lib.rs:4391`** — `compact()` method (manual `/compact` command) 2. **`crates/chat/src/lib.rs:6907`** — `compact_session()` function (auto-compact on context overflow) Change `PersistedMessage::Assistant { ... }` → `PersistedMessage::System { content, created_at }` at both sites. ## Regression Test Add a test that: 1.
