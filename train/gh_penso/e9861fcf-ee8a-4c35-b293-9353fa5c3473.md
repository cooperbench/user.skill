   466→/// Simple percent-decoding for URL-encoded strings.
   467→fn url_decode(input: &str) -> Option<String> {
   468→    let mut result = Vec::with_capacity(input.len());
   469→    let mut chars = input.bytes();
   470→
   471→    while let Some(b) = chars.next() {
   472→        match b {
   473→            b'%' => {
   474→                let hi = chars.next()?;
   475→                let lo = chars.next()?;
   476→                let byte = u8::from_str_radix(&format!("{}{}", hi as char, lo as char), 16).ok()?;
   477→                result.push(byte);
   478→            },
   479→            b'+' => result.push(b' '),
   480→            _ => result.push(b),
   481→        }
   482→    }
   483→
   484→    String::from_utf8(result).ok()

## Plan for fixing #766: Missing Slack `/commands` HTTP endpoint

### Root cause

The gateway router (`crates/httpd/src/server/gateway.rs`) registers two Slack HTTP routes under `#[cfg(feature = "slack")]`:
- `POST /api/channels/slack/{account_id}/events`
- `POST /api/channels/slack/{account_id}/interactions`

But the **third route** — `POST /api/channels/slack/{account_id}/commands` — was never added. The manifest snippet in `crates/slack/src/commands.rs:60` tells users to configure this URL in Slack, but it doesn't exist. Socket Mode works because `command_events_callback` in `socket.rs` handles it via the websocket path.

### Changes needed (3 files)

**1. `crates/slack/src/webhook.rs` — add `handle_verified_command_webhook`**

New function, modeled after `handle_verified_interaction_webhook`. Key difference: Slack sends slash commands as `application/x-www-form-urlencoded` (not JSON), with fields like `command`, `text`, `user_id`, `channel_id`. The function should:
- Parse URL-encoded body (reuse existing `extract_form_field` or add a helper)
- Extract `command`, `text`, `user_id`, `channel_id` from form fields
- Combine as `full_command = "{command} {text}".trim()` (mirroring socket.rs:262)
- Look up event_sink from account state
- Call `sink.dispatch_command(&full_command, reply_to, Some(&sender_id)).await`
- Return the response text as `Ok(String)` — Slack expects a plain-text or JSON response body

**2. `crates/slack/src/plugin.rs` — add `ingest_verified_command_webhook`**

New method on `SlackPlugin`, following the pattern of `ingest_verified_interaction_webhook`:
```rust
pub async fn ingest_verified_command_webhook(
    &self,
    account_id: &str,
    body: &[u8],
) -> ChannelResult<String> {
    crate::webhook::handle_verified_command_webhook(account_id, body, &self.accounts).await
}
```

**3. `crates/httpd/src/server/gateway.rs` — register the `/commands` route**

Add a third route block after the interactions route (line ~432), following the same pattern:
- Clone `slack_webhook_plugin` and `state`
- Register `POST /api/channels/slack/{account_id}/commands`
- Verify signature via `channel_webhook_gate` (same middleware pipeline)
- On success, call `p.ingest_verified_command_webhook(&account_id, &verified.body).await`
- Return the response text with `200 OK` (Slack expects plain text or JSON)
- On error, return `{"ok": false, "error": msg}`

### Important detail: response format

Slack slash commands expect an **immediate** response body (within 3 seconds). The response can be plain text or JSON with `{"response_type": "ephemeral", "text": "..."}`. The Socket Mode handler returns `SlackCommandEventResponse` with text — the HTTP handler should match this by returning the dispatch result as the response body.

### Dedup consideration

Slash commands don't have an `event_id` like Events API payloads. The verifier's `idempotency_key` extraction (which looks for `event_id` in JSON) will return `None` for form-encoded command bodies. This is fine — the dedup middleware will skip dedup when `idempotency_key` is `None`, and slash commands are not retried by Slack the same way events are.

2. **Unit test in `plugin.rs`**: Test `ingest_verified_command_webhook` delegates correctly
3. **Existing tests pass**: The signature verification and middleware are already tested; no changes needed there

### No docs changes needed

The manifest snippet in `commands.rs` already correctly references `/api/channels/slack/{account_id}/commands` — it just needs the endpoint to actually exist.
