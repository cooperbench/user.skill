> AGENT

Good question. MiniMax models are hardcoded in the static catalog, which currently only lists M2.5 and older. But you can add any model ID via config. In your `~/.moltis/moltis.toml`, add: ```toml [providers.minimax] models = ["MiniMax-M2.7"] ``` This uses the `models` field on `ProviderEntry` — custom models appear first in the picker, and the static catalog (M2.5, M2.1, etc.) fills in after. As for **why new models don't appear automatically**: MiniMax's API doesn't expose a `/models` endpoint (returns 404), so `supports_model_discovery` is `false` and `fetch_models` has no effect. The only source is the hardcoded `MINIMAX_MODELS` constant. To fix this properly for the project, we should update the static catalog. Let me check the exact model ID MiniMax uses for 2.7 and add it.
