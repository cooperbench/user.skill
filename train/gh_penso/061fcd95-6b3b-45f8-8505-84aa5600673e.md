The strict patch: 1. Forces ALL properties into the `required` array 2. Makes originally-optional properties nullable via `"type": ["boolean", "null"]` 3. Adds `additionalProperties: false` to every object Google's native API (reached via OpenRouter) does not support array-form types like `["boolean", "null"]`. It considers properties with those types as "not defined", then rejects the `required` array for referencing them. The cron tool schema triggers this because it has many optional boolean/enum properties inside its nested `job` object. **Why strict mode can be safely skipped for OpenRouter**: Strict mode is an OpenAI-specific feature that prevents the model from hallucinating extra JSON keys. OpenRouter proxies to many backends (Google, Anthropic, Meta, etc.) and handles format translation itself.
