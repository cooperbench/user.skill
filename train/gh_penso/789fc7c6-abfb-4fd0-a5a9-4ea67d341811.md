> AGENT

`/approve` and `/deny` are channel commands (Telegram, WhatsApp, etc.) for managing **exec tool approval requests** — when the LLM agent wants to run a shell command that requires human approval. ### The flow 1. A user chats with the bot in Telegram/WhatsApp, and the agent decides it needs to run a shell command (e.g., `git status`, `curl ...`, `rm -rf /tmp/build`) 2. The command is checked against the approval policy (`crates/tools/src/approval.rs`). If it's not on the allowlist, it enters a **pending approval** state 3. A notification is sent to the originating channel: "Approval needed for `git status`" 4. The user can then: - `/approvals` — list pending approval requests for the current session - `/approve 2` — approve request #2 from the list - `/deny 1` — deny request #1 5. The agent's tool execution either proceeds (approved) or fails (denied) Previously this was only manageable from the **web UI**. This branch added the channel commands so operators don't have to switch to the browser when a command is waiting for approval — they can resolve it directly from the same Telegram/WhatsApp chat where the conversation is happening. The security concern I flagged (and fixed) was that in a **group chat**, any group member could `/approve` a dangerous command, not just the person who initiated the conversation.
