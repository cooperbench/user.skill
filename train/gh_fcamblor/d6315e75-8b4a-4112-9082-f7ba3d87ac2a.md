Here's the plan for **Consumption color indicators**: --- ## Overall approach A `ConsumptionTier` enum (6 severity levels, `Comparable`) lives in the library target with a pure `consumptionTier(ratio:)` function. This keeps the color logic testable without SwiftUI. Two rendering paths consume it: - **Popover progress bars**: `TimeWindowMetricRow` computes the ratio and passes the tier to `GaugeBar`, replacing its current hard-coded 0.75/0.9 thresholds. - **Menubar badge**: `UsageStore` exposes a `menuBarTier` property — the worst tier among displayed metrics. The app entry point applies it as `.foregroundStyle`. A single App-target extension (`ConsumptionTier.color`) maps tiers to SwiftUI `Color`, shared by both paths for consistency. ## Key design decisions - **`exhausted` tier uses `NSColor.labelColor`** instead of literal `.black` — stays legible in dark mode while signaling maximum severity. - **`consumptionRatio` returns `nil` when theoretical fraction is zero** (window just started) — avoids division by zero; both GaugeBar and menubar fall back to neutral color. - **`Comparable` ordering on the enum** enables `max()` to pick the worst tier for the menubar badge. ## 8 commits across 5 phases | Phase | Commits | Goal | |-------|---------|------| | 1 — Domain model | 1-2 | `ConsumptionTier` enum, ratio function, boundary tests | | 2 — Popover bars | 3 | Replace GaugeBar hard-coded colors with tier-based fill | | 3 — Menubar badge | 4-5 | `menuBarTier` in UsageStore, apply to menubar label | | 4 — Shared extension | 6 | Extract `ConsumptionTier.color` to deduplicate mapping | | 5 — Tests & close | 7-8 | Store tests for all tier scenarios, flip epic to done | Plan validé.
