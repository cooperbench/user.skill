## Règle de détection d'une nouvelle version La détection se fait dans `UpdateChecker.checkForUpdate(currentVersion:)` (`UpdateChecker.swift:52`). **Ce qui est comparé** : - **Version courante** : lue depuis `CFBundleShortVersionString` du bundle de l'app (par `AppDelegate.currentAppVersion()`). - **Version distante** : extraite du champ `tag_name` de la dernière release GitHub renvoyée par `https://api.github.com/repos/fcamblor/mac-ai-trackers/releases/latest`. **Le test** (`UpdateChecker.swift:89`) : ```swift guard version > currentVersion else { return nil } ``` → Une mise à jour est signalée **uniquement si la version distante est strictement supérieure** à la version courante. **Comment la comparaison fonctionne** (`AppVersion.swift`) : 1. Le tag est normalisé : préfixe `v` retiré (`v1.2.3` → `1.2.3`), puis tout suffixe pre-release/metadata ignoré (`1.2.3-beta+build42` → `1.2.3`). 2. Le cœur est splitté en `major.minor.patch` (les composants manquants valent `0`). 3. Comparaison lexicographique sur le triplet `(major, minor, patch)` — d'abord major, puis minor, puis patch. **Conséquences pratiques** : - `v1.2.3` vs `1.2.3` → égaux (le préfixe `v` est ignoré). - `1.2.3-beta` vs `1.2.3` → égaux pour la comparaison (suffixes ignorés). Donc une release `-beta` ne déclenchera **pas** de notification si l'utilisateur est déjà sur la stable correspondante. - `1.2.10` > `1.2.9` → vrai (comparaison numérique, pas lexicale sur les chaînes). - Tag malformé (non parsable) → `UpdateCheckerError.malformedTag` levé, aucun update annoncé. À noter aussi : même si la version est supérieure, l'utilisateur peut avoir « skippé » cette version — `UpdateState.pendingUpdate` filtre alors via `dismissedVersions` (`UpdateState.swift:63`).
