que fait le -p dans npx ?

> AGENT

`-p` (ou `--package`) dit à npx **quel package installer**, indépendamment du **nom du bin à exécuter** qui suit. Par défaut, `npx <truc>` fait deux choses d'un coup : 1. installe le package `<truc>` 2. exécute un bin dont le nom est **déduit** de `<truc>` Avec un package scopé comme `@fcamblor/gitdiff-watcher`, npm 10.9 galère à déduire le nom du bin (`gitdiff-watcher`) à partir du nom scopé, surtout avec un suffixe de version. Avec `-p` on sépare explicitement : ``` npx -y -p @fcamblor/gitdiff-watcher@0.2.0 gitdiff-watcher --on ... --exec ... └── package à installer ─────────┘ └── bin à lancer ┘ └── args du bin ┘ ``` Bonus : `-p` peut être répété pour installer plusieurs packages dans le même env temporaire avant de lancer le bin (ex. `npx -p foo -p bar foo-cli`).
