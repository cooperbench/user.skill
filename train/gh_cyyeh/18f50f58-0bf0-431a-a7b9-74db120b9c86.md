def rewrite_model_in_body(body: bytes, rewrites: dict[str, str]) -> bytes:

    model = data.get("model")

## Root Causes

### 1. `ask_user_question` is NOT in the orchestrator's `allowedTools`

In `sidecar/src/server.ts:202`:
```typescript
allowedTools: ["Task", "mcp__duckdb__execute_sql"],
```

The tool `mcp__duckdb__ask_user_question` is **not listed**, but the system prompt (`agent.py:37-40`) tells the model to use it:

> *"When the user's request is ambiguous... use the ask_user_question tool to ask for clarification"*

**Claude models** seem to handle this gracefully (the SDK may still allow MCP tools not explicitly listed, or Claude tries anyway and it works). **OpenAI models**, when they can't find the tool in their available tools, fall back to **outputting the tool call as plain text** - exactly what your screenshot shows. The model is outputting an `AskUserQuestion`-shaped JSON blob as text content instead of making an actual tool call.

### 2. Bifrost API format translation edge cases

Tool calls have different formats between providers:
- **Anthropic**: `{type: "tool_use", id, name, input: {...}}`  
- **OpenAI**: `{tool_calls: [{id, type: "function", function: {name, arguments: "..."}}]}`

Bifrost translates between these, but edge cases (streaming partial tool call JSON, large inputs for `render_chart`) can cause malformed tool calls that fail silently, with the model falling back to text output.

### 3. Extended thinking not supported by OpenAI

The backend handles `thinking_delta` events (`agent.py:322-325`), but OpenAI models don't produce Anthropic-style thinking blocks. This shouldn't cause a crash but means the thinking UI won't work.
