   170→## Security
   171→
   172→### Credential Proxy
   173→
   174→When the agent runs, the backend spawns a Claude Code subprocess via the Anthropic Agent SDK. A naive approach would pass `ANTHROPIC_API_KEY` directly into that subprocess's environment — but any tool or shell command the agent executes could then read and exfiltrate the key.
   175→
   176→Instead, the backend runs a built-in reverse proxy at `/anthropic` that sits between Claude Code and `api.anthropic.com`:
   177→
   178→```
   179→Claude Code subprocess
   180→  → ANTHROPIC_BASE_URL=http://127.0.0.1:{PORT}/anthropic
   181→  → ANTHROPIC_API_KEY=<short-lived UUID token>
   182→        ↓
   183→FastAPI proxy (/anthropic/{path})
   184→  → validates UUID token
   185→  → swaps it for the real ANTHROPIC_API_KEY
   186→  → forwards request to api.anthropic.com
   187→```
   188→
   189→**How it works:**
   190→
   191→1. Before each agent session, the backend mints a random UUID token with a 10-minute TTL.
   192→2. The token is injected into the subprocess environment as `ANTHROPIC_API_KEY`; the real key is never exposed.
   193→3. The proxy validates every inbound request against the token store and substitutes the real key before forwarding upstream.
   194→4. When the session ends, the token is explicitly revoked in a `finally` block, regardless of success or error.
   195→5. A background task runs every 60 seconds to sweep any tokens that outlived their TTL.
   196→
   197→The subprocess only ever holds a single-session UUID. Even if a tool call reads the environment, all it gets is a temporary token scoped to that conversation.
   198→
   199→### Container Isolation (Optional)
   200→
   201→For additional defense in depth, the backend can run each Claude Code session inside a **gVisor-sandboxed Docker container** ("sidecar") instead of a bare subprocess. This provides code execution sandboxing, multi-tenant isolation, and a hardened boundary between the agent and the host system.
   202→
   203→**Architecture:**
   204→
   205→```
   206→Browser
   207→  │
   208→  ▼
   209→FastAPI Backend (host)
   210→  ├── Chat route ──► ContainerManager ──► Docker SDK
   211→  │                       │
   212→  │                       ▼
   213→  │               ┌──────────────────────┐
   214→  │               │  gVisor Sandbox      │
   215→  │               │                      │
   216→  │               │  Sidecar Container   │
   217→  │               │  (Node.js + Claude)  │
   218→  │               │                      │
   219→  │               │  POST /query → SSE   │
   220→  │               └──────┬───────────────┘
   221→  │                      │

   227→
   228→When `CONTAINER_ENABLED=true`, the data flow for a chat message is:
   229→
   230→1. Frontend sends a chat message to the FastAPI backend.
   231→2. Backend mints a short-lived UUID token via the credential proxy and spins up a gVisor container (or reuses an existing one for the session) via `ContainerManager`.
   232→3. Backend sends the query to the sidecar's `POST /query` endpoint. The sidecar calls the Claude Agent SDK's `query()` function with `includePartialMessages: true` for token-level streaming, configured with the host's MCP SSE endpoint.
   233→4. Claude CLI talks to the host credential proxy (`/anthropic`) for Anthropic API access (using the UUID token, never the real key).
   234→5. Claude CLI's `execute_sql` tool calls reach the host DuckDB via the **MCP SSE bridge** (`/mcp/sse?session_id=...`), which routes each connection to the correct per-user DuckDB instance through the existing `SessionManager`.
   235→6. The sidecar streams SSE events back to the backend, which forwards them to the frontend in the same format as the subprocess path.
   236→7. On session end, the container is stopped and removed; the UUID token is revoked.
   237→
   238→When `CONTAINER_ENABLED=false` (default), the existing in-process subprocess model is used with no container overhead.
   239→
   240→**Sidecar container:** The `sidecar/` directory contains a TypeScript HTTP server (`src/server.ts`) that uses the Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`) with `includePartialMessages: true` for true token-level streaming. The Docker image (`sidecar/Dockerfile`) bundles Node.js 20, Python 3.12, the Agent SDK, and the `@anthropic-ai/claude-code` CLI (required by the SDK internally). Containers run with a read-only root filesystem, all Linux capabilities dropped, no volume mounts, no Docker socket access, and a non-root user.
   241→
   242→**MCP SSE bridge:** The backend exposes the DuckDB `execute_sql` and `generate_chart` tools at `/mcp/sse` using the MCP protocol's SSE transport (`backend/app/mcp_sse.py`). Each SSE connection requires a `session_id` query parameter to route tool calls to the correct per-user DuckDB instance. This is how the containerized Claude CLI reaches DuckDB on the host without any direct database access inside the container.
