The fix is in place. Here's the root cause and what changed:

**Root cause:** The previous macOS fix published port 3000 to a random host port and always used `http://127.0.0.1:{host_port}` for the URL. When the backend runs inside a container (docker-compose), `127.0.0.1` resolves to the backend container itself — not the host — so health checks could never reach the sidecar.

**Fix:** The `url` property now only uses the published host port when running **natively on macOS** (detected via `sys.platform == "darwin"` and absence of `/.dockerenv`). In all other cases — docker-compose on any OS, or bare Linux — it uses the direct container IP, which is reachable via the shared `agent-sandbox` network regardless of runtime (`runsc` or `runc`).

| Scenario | URL used |
|---|---|
| macOS native backend | `http://127.0.0.1:{host_port}` ✓ |
| docker-compose (macOS or Linux) | `http://{container_ip}:3000` ✓ |
| Linux native backend (`runc` or `runsc`) | `http://{container_ip}:3000` ✓ |
