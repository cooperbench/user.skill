## Section 3: Test Runner Architecture **`scenario-runner.spec.ts`** — the core engine: ```typescript // Dynamically generates Playwright tests from YAML files // At import time: glob all YAML files in scenarios/ // For each scenario: test.describe(scenario.name, () => { ... }) // For each step: execute the action, then run verifiers ``` **Execution flow:** 1. Playwright loads `scenario-runner.spec.ts` 2. It reads all `*.yaml` files from `e2e/scenarios/` 3. Each scenario becomes a `test.describe` block 4. Each step becomes a sequential action inside the test 5. Structural `verify` steps run assertions immediately 6. `verify_llm` steps call the Anthropic API with the page content + criteria, parse a pass/fail score **LLM-as-judge flow:** 1. Extract the visible text content from the response area 2. Send to Claude with a prompt: "Given this page content, does it satisfy: {criteria}? Score 0.0-1.0" 3. Parse the score, compare to `pass_threshold` 4. Fail the test with the LLM's reasoning if below threshold **Configuration (`playwright.config.ts`):** - `baseURL`: from `BASE_URL` env var, default `http://localhost:5173` - Retries: 0 (agent responses are non-deterministic, retries won't help) - Timeout: 60s per test (agent responses can be slow) - Reporter: `html` (generates `results/` report) + `list` (terminal output) - Screenshots: on failure - Video: off by default (configurable) **Makefile integration:** ```makefile e2e-test: cd e2e && npx playwright test e2e-report: cd e2e && npx playwright show-report results ``` Does this architecture look right?
