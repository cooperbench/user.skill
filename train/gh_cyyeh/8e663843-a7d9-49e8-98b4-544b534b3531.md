## Design Section 3: Request/Response Translation This is the core of the gateway. A new module `backend/app/gateway.py` handles the bidirectional translation using LiteLLM. **Non-streaming flow:** 1. Receive Anthropic Messages API request body (`model`, `messages`, `system`, `tools`, `max_tokens`, etc.) 2. Convert to OpenAI-compatible format (LiteLLM's internal standard) — messages, tools, system prompt 3. Call `litellm.acompletion(model="gpt-4o", messages=[...], tools=[...])` 4. Convert the OpenAI-format response back to an Anthropic Messages API response (`content` blocks with `type: "text"` / `type: "tool_use"`, `stop_reason`, `usage`, etc.) 5. Return as JSON HTTP response **Streaming flow:** 1. Same request translation 2. Call `litellm.acompletion(model="gpt-4o", ..., stream=True)` 3. Convert each OpenAI streaming chunk to Anthropic SSE events: - Emit `message_start` with message metadata - Convert `choices[].delta.content` → `content_block_delta` with `text_delta` - Convert `choices[].delta.tool_calls` → `content_block_start` + `content_block_delta` with `input_json_delta` - Emit `message_delta` with `stop_reason` and final `usage` - Emit `message_stop` 4. Yield as `text/event-stream` response **Tool use round-trip (critical path):** - **Request direction:** Anthropic `tools` array (name, description, input_schema) → OpenAI `tools` array (function name, description, parameters).
