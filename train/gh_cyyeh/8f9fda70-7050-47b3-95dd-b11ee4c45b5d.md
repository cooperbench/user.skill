Confirmed. Here's the exact bug:

1. **First request:** `session_id=null` → `container_session = "default"` → container created with key `"default"` → Claude CLI creates session, returns `"8b604e30-..."` → frontend stores it
2. **Second request:** `session_id="8b604e30-..."` → `container_session = "8b604e30-..."` → `container_manager.create()` doesn't find key `"8b604e30-..."` → **creates a brand new container** → sidecar tries `resume: "8b604e30-..."` → **new container has no conversation history** → error

The fix: container lifecycle should be keyed by the `backend_session_id` (stable per browser tab), not the Claude agent `session_id` (changes after first response).
