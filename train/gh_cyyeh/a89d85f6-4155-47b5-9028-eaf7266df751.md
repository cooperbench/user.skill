## Research Summary

### What are plugins in the Claude Agent SDK?

Plugins are **self-contained extension packages** that bundle multiple Claude Code extension types (skills, commands, agents, hooks, MCP servers, LSP servers) into a single directory with a manifest file (`.claude-plugin/plugin.json`). They solve the problem of **reusable, shareable, versioned agent extensions** that can be distributed via marketplaces and shared across projects and teams.

### Key Findings

**1. SDK Integration**: Both Python and TypeScript SDKs expose an identical `SdkPluginConfig` type with `type: "local"` and `path: string`. The SDK translates plugin paths into `--plugin-dir` CLI arguments for the Claude Code subprocess. Only local filesystem plugins are currently supported -- there is no remote/URL-based loading.

**2. Plugin Structure**: A plugin is a directory containing:
- `.claude-plugin/plugin.json` (manifest, optional but recommended)
- `commands/` (slash commands as Markdown)
- `agents/` (subagent definitions)
- `skills/` (model-invoked capabilities with `SKILL.md`)
- `hooks/hooks.json` (event handlers)
- `.mcp.json` (MCP server configs)
- `.lsp.json` (Language Server Protocol configs)
- `settings.json` (default settings, only `agent` key supported)

**3. Namespacing**: All plugin components are automatically namespaced with the plugin name (e.g., `/my-plugin:hello`) to prevent conflicts.

**4. 15 Hook Events**: `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `UserPromptSubmit`, `Notification`, `Stop`, `SubagentStart`, `SubagentStop`, `SessionStart`, `SessionEnd`, `TeammateIdle`, `TaskCompleted`, `PreCompact` -- and three hook types: `command`, `prompt`, `agent`.

**5. 29 Official Plugins**: Anthropic maintains an official marketplace at `github.com/anthropics/claude-plugins-official` with plugins for LSP (11 languages), code review, security guidance, SDK development tools, and more.

**6. Python vs TypeScript**: The plugin configuration API is identical. The only differences are in how init messages are accessed (`message.data.get("plugins")` in Python vs `message.plugins` in TypeScript) and language-specific type system conventions.

**7. Limitations**: No remote plugins, no hot-reload, mandatory namespacing, no plugin dependencies system, no programmatic plugin API, cached marketplace plugins require version bumps.

     4→
     5→The Claude Agent SDK (Python `claude-agent-sdk`, TypeScript `@anthropic-ai/claude-agent-sdk`) supports a **plugin system** that allows loading self-contained extension packages into agent sessions.    418→

   435→  // ...

   437→  skills: string[];
   438→  plugins: { name: string; path: string }[];
   439→};
   440→```

   443→
   444→Plugin commands are namespaced with `plugin-name:command-name`:
   445→
   446→```typescript
   447→// TypeScript
   448→for await (const message of query({
   449→  prompt: "/my-plugin:greet",
   450→  options: {

   462→async for message in query(

   474→## Part 5: Plugin Lifecycle
   475→
   476→### Loading Phase
   477→
   478→1. **Path resolution**: SDK resolves relative paths against the current working directory
   479→2. **CLI argument construction**: Each plugin path becomes a `--plugin-dir` argument
   480→3. **Manifest discovery**: CLI scans each plugin directory for `.claude-plugin/plugin.json`
   481→4. **Component discovery**: CLI discovers `commands/`, `agents/`, `skills/`, `hooks/`, `.mcp.json`, `.lsp.json`
   482→5. **Namespacing**: All components are prefixed with the plugin name
   483→6. **Init message**: Loaded plugins are reported in the `system` init message
   484→
   485→### Runtime Phase
   486→
   487→- **Skills**: Available for model-invoked or user-invoked use throughout the session
   488→- **Commands**: Available via `/plugin-name:command-name` slash commands
   489→- **Agents**: Appear in `/agents` and can be invoked by Claude or the user
   490→- **Hooks**: Fire automatically on matching events (e.g., `PostToolUse` on `Write|Edit`)
   491→- **MCP servers**: Start automatically and provide tools throughout the session
   492→- **LSP servers**: Provide code intelligence for supported file types
   493→
   494→### Caching (Marketplace Plugins Only)
   495→
   496→For security, marketplace-installed plugins are copied to `~/.claude/plugins/cache/` rather than used in-place. Plugins loaded via `--plugin-dir` or the SDK `plugins` option are used directly from their specified path.
   497→
   498→### Installation Scopes
   499→
   500→| Scope | Settings File | Use Case |
   501→|-------|--------------|----------|
   502→| `user` | `~/.claude/settings.json` | Personal plugins, all projects (default) |
   503→| `project` | `.claude/settings.json` | Team plugins, shared via version control |
   504→| `local` | `.claude/settings.local.json` | Project-specific, gitignored |
   505→| `managed` | Managed settings | Read-only, update only |

   751→## Part 8: Python SDK vs TypeScript SDK Comparison
   752→
   753→### Plugin Configuration
   754→
   755→| Aspect | Python SDK | TypeScript SDK |
   756→|--------|-----------|----------------|
   757→| **Config type** | `SdkPluginConfig` (TypedDict) | `SdkPluginConfig` (type alias) |
   758→| **Options field** | `ClaudeAgentOptions.plugins: list[SdkPluginConfig]` | `Options.plugins: SdkPluginConfig[]` |
   759→| **Default** | `[]` (empty list) | `[]` (empty array) |
   760→| **Plugin type** | `Literal["local"]` | `"local"` (string literal) |
   761→
   762→### SDK Type Definitions
   763→
   764→**Python:**
   765→
   766→```python
   767→class SdkPluginConfig(TypedDict):
   768→    type: Literal["local"]
   769→    path: str
   770→
   771→@dataclass
   772→class ClaudeAgentOptions:
   773→    # ... other fields ...
   774→    plugins: list[SdkPluginConfig] = field(default_factory=list)
   775→```
   776→
   777→**TypeScript:**
   778→
   779→```typescript
   780→type SdkPluginConfig = {
   781→  type: "local";
   782→  path: string;
   783→};
   784→
   785→interface Options {
   786→  // ... other fields ...
   787→  plugins?: SdkPluginConfig[];
   788→}
   789→```

   813→
   814→**Python:**
   815→
   816→```python
   817→#!/usr/bin/env python3
   818→from pathlib import Path
   819→import anyio
   820→from claude_agent_sdk import (
   821→    AssistantMessage,

   828→async def run_with_plugin():

   832→        plugins=[{"type": "local", "path": str(plugin_path)}],
   833→        max_turns=3,
   834→    )

   836→    async for message in query(
   837→        prompt="What custom commands do you have available?",
   838→        options=options,
   839→    ):

   841→            print(f"Loaded plugins: {message.data.get('plugins')}")
   842→            print(f"Available commands: {message.data.get('slash_commands')}")
   843→
   844→        if isinstance(message, AssistantMessage):
   845→            for block in message.content:
   846→                if isinstance(block, TextBlock):
   847→                    print(f"Assistant: {block.text}")

   948→## Part 10: Best Practices and Limitations
   949→
   950→### Best Practices
   951→
   952→1. **Start standalone, convert to plugin**: Begin with `.claude/` configuration for quick iteration, then package as a plugin when ready to share.
   953→
   954→2. **Use semantic versioning**: Claude Code uses the version to determine whether to update. If you change code without bumping the version, existing users will not see changes.
   955→
   956→3. **Use `${CLAUDE_PLUGIN_ROOT}`**: Always reference plugin-relative paths through this variable for portability across installations.
   957→
   958→4. **Namespace awareness**: All plugin components are namespaced with `plugin-name:`. Choose short, descriptive plugin names.
   959→
   960→5. **Test locally first**: Use `--plugin-dir` (CLI) or the `plugins` option (SDK) during development before publishing.
   961→
   962→6. **Keep plugins self-contained**: Avoid referencing files outside the plugin directory. Path traversal outside the plugin root will not work after marketplace installation due to caching.
   963→
   964→7. **Use symlinks for shared dependencies**: If external files are needed, symlink them into the plugin directory (symlinks are followed during cache copy).
   965→
   966→8. **Make hook scripts executable**: `chmod +x scripts/your-script.sh` and include proper shebang lines.
   967→
   968→### Limitations
   969→
   970→1. **Only `"local"` plugin type supported**: There is no remote/URL-based plugin loading. All plugins must exist on the local filesystem.
   971→
   972→2. **No programmatic plugin definition**: Unlike agents, hooks, and MCP servers which can be defined inline in SDK options, plugins must exist as filesystem directories with manifest files.
   973→
   974→3. **No hot-reload**: Plugin changes require restarting the Claude Code session. Changes are not picked up at runtime.
   975→
   976→4. **Namespace is mandatory**: Plugin skills/commands always get namespaced. You cannot use short names like `/hello` -- it will always be `/plugin-name:hello`.
   977→
   978→5. **Marketplace plugins are cached**: Cached copies may be stale if the version number is not bumped.
   979→
   980→6. **Path traversal restrictions**: Installed plugins cannot reference files outside their directory.
   981→
   982→7. **LSP binary requirement**: LSP plugins do not bundle the language server binary. Users must install it separately.
   983→
   984→8. **Settings scope limited**: Plugin `settings.json` only supports the `agent` key currently. Other settings keys are silently ignored.
   985→
   986→9. **No plugin dependencies**: There is no mechanism for one plugin to depend on or require another plugin.
   987→
   988→10. **No plugin API**: Plugins cannot expose programmatic APIs to other plugins or to the SDK consumer. They are purely configuration-based extensions.
   989→
   990→### Troubleshooting
   991→
   992→| Issue | Cause | Solution |
   993→|-------|-------|----------|
   994→| Plugin not loading | Invalid `plugin.json` | Validate JSON syntax |
   995→| Commands not appearing | Wrong directory structure | Ensure components at root, not in `.claude-plugin/` |
   996→| Hooks not firing | Script not executable | `chmod +x script.sh` |
   997→| MCP server fails | Missing `${CLAUDE_PLUGIN_ROOT}` | Use variable for all plugin paths |
   998→| Path errors | Absolute paths in manifest | All paths must be relative, start with `./` |
   999→| LSP not working | Binary not installed | Install the language server separately |
