# Fix: Empty assistant bubble when switching conversations mid-stream

## Context

When the user sends a message and switches to another conversation before any text tokens arrive from the SSE stream (e.g., during the model's initial thinking delay), then switches back, the original conversation shows an empty assistant bubble (just the "ASSISTANT" header with no content).

**Root cause**: Two issues in `AgentContext.tsx`:
1. The message cache saves empty assistant messages (created with `content: ''` at stream start, no text received yet)
2. The cache is always preferred over backend data, even when the backend has a more complete response (the `finally` block in `agent.py` persists whatever text was generated before disconnect)

## Fix (2 changes in `AgentContext.tsx`)

### Change 1: Filter empty assistant messages from cache

In both `loadMessages` (line ~660-672) and `clearMessages` (line ~708-720), after building the `cleaned` array, filter out assistant messages that have no content AND no meaningful segments before caching.

```typescript
// After: const cleaned = prev.map(m => { ... });
// Add filter to remove empty assistant messages
const toCache = cleaned.filter(m => {
  if (m.role === 'assistant' && !m.content?.trim() && (!m.segments || m.segments.length === 0)) {
    return false;
  }
  return true;
});
messagesCacheRef.current.set(outgoingConversationId, toCache);
```

### Change 2: Prefer backend when cache has fewer messages

Change the cache comparison logic (line ~634-641) to only prefer cache when it has at least as many messages as the backend response.

```typescript
// Before:
if (cached && cached.length > 0) {
  finalMsgs = cached;
}

// After:
if (cached && cached.length > 0 && cached.length >= msgs.length) {
  finalMsgs = cached;
}
```

## Files to modify

- `frontend/src/contexts/AgentContext.tsx` — 3 locations:
  1. `loadMessages` cache save (~line 672)
  2. `loadMessages` cache lookup (~line 636)
  3. `clearMessages` cache save (~line 720)

## Scenario verification

| Scenario | Cache (after filter) | Backend | Winner | Result |
|----------|---------------------|---------|--------|--------|
| No text received, backend empty | `[user]` | `[user]` | cache (equal) | Just user msg, no empty bubble |
| No text received, backend has response | `[user]` | `[user, assistant]` | backend (more) | User + backend's response |
| Partial text received | `[user, partial_assistant]` | `[user, assistant]` | cache (equal, richer segments) | User + cached partial |
| Normal (no streaming) | full messages | full messages | cache (equal, richer segments) | Preserved as-is |

3. Switch back to the original conversation
4. Verify: no empty assistant bubble appears. Either the user message alone is shown, or the backend's persisted response is shown.

    17→async function streamSSE(
    18→  response: Response,
    19→  callbacks: AgentCallbacks,
    20→  signal?: AbortSignal,
    21→): Promise<void> {
    22→  const reader = response.body?.getReader();
    23→  if (!reader) {
    24→    callbacks.onError('No response stream');
    25→    return;
    26→  }
    27→
    28→  let doneReceived = false;
    29→  const wrappedCallbacks: AgentCallbacks = {
    30→    ...callbacks,
    31→    onDone: (sessionId) => {
    32→      doneReceived = true;
    33→      callbacks.onDone(sessionId);
    34→    },
    35→    onError: (error) => {
    36→      doneReceived = true;
    37→      callbacks.onError(error);
    38→    },
    39→  };
    40→
    41→  try {
    42→    const decoder = new TextDecoder();
    43→    let buffer = '';
    44→    let eventType = '';
    45→
    46→    while (true) {
    47→      const { done, value } = await reader.read();
    48→      if (done) break;
    49→
    50→      buffer += decoder.decode(value, { stream: true });
    51→      const lines = buffer.split('\n');
    52→      buffer = lines.pop() ?? '';
    53→      for (const line of lines) {
    54→        if (line.startsWith('event: ')) {
    55→          eventType = line.slice(7).trim();
    56→        } else if (line.startsWith('data: ')) {
    57→          const data = line.slice(6);
    58→          try {
    59→            const parsed = JSON.parse(data);
    60→            handleSSEEvent(eventType, parsed, wrappedCallbacks);
    61→          } catch {
    62→            // Skip malformed JSON
    63→          }
    64→          eventType = '';
    65→        }
    66→      }
    67→    }
    68→
    69→    // Process any remaining data left in buffer after stream ends
    70→    if (buffer.trim()) {
    71→      const remainingLines = buffer.split('\n');
    72→      for (const line of remainingLines) {
    73→        if (line.startsWith('event: ')) {
    74→          eventType = line.slice(7).trim();
    75→        } else if (line.startsWith('data: ')) {
    76→          const data = line.slice(6);
    77→          try {
    78→            const parsed = JSON.parse(data);
    79→            handleSSEEvent(eventType, parsed, wrappedCallbacks);
    80→          } catch {
    81→            // Skip malformed JSON
    82→          }
    83→          eventType = '';
    84→        }
    85→      }
    86→    }
    87→
    88→    // Safety net: if stream ended without done/error, force done
    89→    if (!doneReceived) {
    90→      callbacks.onDone(null);
    91→    }
    92→  } catch (e: unknown) {
    93→    if (signal?.aborted) return;
    94→    const msg = e instanceof Error ? e.message : 'Connection failed';
    95→    callbacks.onError(msg);
    96→  }
    97→}

Clean build. Here's what was causing the intermittent failure and the fix:

**Root cause**: `handleConversationSelect` reads `conversation.activeConversationId` from React state. If the user switches conversations immediately after sending a message (before React re-renders), the state is still `null` (from before `createConversation`). So `outgoingConversationId` is `null`, and the entire cache-save block is skipped. The messages are lost.

**Fix**: Added `streamConversationIdRef` — a ref that's set synchronously in `sendMessage` when the stream starts. Both `loadMessages` and `clearMessages` now use `outgoing = outgoingConversationId || streamConversationIdRef.current` as a fallback. Since refs update synchronously (no React batching delay), this always has the correct conversation ID.
