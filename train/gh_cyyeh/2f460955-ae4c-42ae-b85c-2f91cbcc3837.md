## Design Section 3: Data Flow & Edge Cases

**Data flow:**
```
User clicks toggle → setLanguage('zh-TW') → localStorage updated
→ LanguageContext re-renders → all t() calls return new language strings
→ UI updates instantly (no page reload)
```

**Edge cases handled:**
- **Invalid localStorage value:** Falls back to OS detection, then `en`
- **OS language not zh or en:** Defaults to `en`
- **Missing translation key:** Returns the key itself as fallback (developer-visible, non-breaking)
- **HTML `lang` attribute:** Updated on `<html>` element when language changes (for accessibility)

**What we're NOT doing (YAGNI):**
- No RTL support (neither language needs it)
- No number/date formatting (the app uses raw SQL output)
- No plural rules (we use simple `{count} row(s)` pattern in both languages)
- No namespacing (only ~40 keys total)
- No lazy loading of translations (both files are tiny)
- No backend translation (AI agent scope excluded per earlier decision)
