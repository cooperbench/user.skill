### Langfuse Trace Flushing

**Critical: Trace finalization happens in the `finally` block** (agent.py, lines 308-327):

```python
finally:
    # End any open generation span
    if trace:
        _end_generation()
    
    # Update trace output and flush
    if trace:
        try:
            trace.update_trace(
                output={"session_id": actual_session_id}
            )
            trace.end()
        except Exception as e:
            logger.debug("Failed to update Langfuse trace: %s", e)
    
    # FLUSH DATA TO LANGFUSE
    if langfuse:
        try:
            langfuse.flush()
        except Exception as e:
            logger.debug("Failed to flush Langfuse: %s", e)
```

**Important Details:**
- `langfuse.flush()` is called **synchronously** after stream completion
- This ensures all trace data is sent before the response terminates
- Flushing is non-blocking to SSE streaming (happens after client receives "done" event)
- If flush fails, it logs but doesn't interrupt the response

# @observe() Decorator: Comprehensive Guide

Based on the documentation, here's what you need to know about the `@observe()` decorator:

## Basic Functionality

The `@observe()` decorator "automatically capture[s] inputs, outputs, timings, and errors of a wrapped function without modifying the function's internal logic."

**Python example:**
```python
from langfuse import observe

@observe()
def my_data_processing_function(data, parameter):
    return {"processed_data": data, "status": "ok"}

@observe(name="llm-call", as_type="generation")
async def my_async_llm_call(prompt_text):
    return "LLM response"
```

**JavaScript/TypeScript example:**
```ts
import { observe } from "@langfuse/tracing";

async function fetchData(source: string) {
  return { data: `some data from ${source}` };
}

const tracedFetchData = observe(fetchData, {
  name: "fetch-data",
  asType: "span",
});

const result = await tracedFetchData("API");
```

## Async & Streaming Support

The decorator supports both synchronous and asynchronous functions. Async functions are fully compatible with automatic timing and error capture.

## Traces vs Spans

The decorator creates observations based on the `as_type` parameter (Python) or `asType` parameter (TypeScript). The "function call hierarchy is automatically captured and reflected in the trace." When you nest decorated functions, they automatically become child observations:

```python
@observe
def my_data_processing_function(data, parameter):
    return {"processed_data": data, "status": "ok"}

@observe
def main_function(data, parameter):
    return my_data_processing_function(data, parameter)
```

## Updating Current Observations

Within an `@observe()` decorated function, use these methods:

**Python:**
```python
from langfuse import observe, propagate_attributes

@observe()
def my_llm_pipeline(user_id: str, session_id: str):
    with propagate_attributes(
        user_id=user_id,
        session_id=session_id,
        metadata={"pipeline": "main"}
    ):
        result = call_llm()
        return result
```

For updating the current trace explicitly:
```python
@observe()
def process_user_query(user_question: str):
    answer = call_llm(user_question)
    
    langfuse.update_current_trace(
        input={"question": user_question},
        output={"answer": answer}
    )
    
    return answer
```

**JavaScript/TypeScript:**
```ts
import { observe, updateActiveObservation } from "@langfuse/tracing";

async function fetchData(source: string) {
  updateActiveObservation({ metadata: { source: "API" } });
  return { data: `some data from ${source}` };
}

const tracedFetchData = observe(fetchData, {
  name: "fetch-data",
  asType: "span",
});
```

### Key Research Findings

**1. Async Generator Compatibility with `@observe()`**

After examining the installed Langfuse SDK v3.14.4 source (`/Users/cyyeh/Desktop/duckdb-data-agent/backend/.venv/lib/python3.12/site-packages/langfuse/_client/observe.py`), I found that:

### Architecture Decision: Route Handler Wrapper vs `@observe()` on `stream_chat()`

**Chosen approach**: Apply tracing at the **route handler level** using `start_as_current_observation()` context manager, NOT `@observe()` on `stream_chat()`.

Rationale:
- The route handler (`chat()` in `chat.py`) is a regular `async def` function, avoiding the async generator complications.
- `start_as_current_observation()` sets the OTel context, which `configure_claude_agent_sdk()`'s auto-instrumentation will use to nest its spans.
- `propagate_attributes()` can be used within the context manager to set `session_id` and metadata.
- The auto-instrumented spans from the Claude Agent SDK will appear as children of our root span.
- This completely eliminates all manual tracing code from `agent.py`.

However, there is an important subtlety: The `StreamingResponse` wraps the async generator, and the OTel context from `start_as_current_observation()` may not propagate into the async generator's iteration within Starlette's response streaming. The auto-instrumentation from `configure_claude_agent_sdk()` hooks into the Claude Agent SDK itself, not into our generator, so this should work because the SDK client operations (`client.connect()`, `client.query()`, `client._query.receive_messages()`) happen within the same async task.

**Alternative approach considered but rejected**: Wrapping tracing inside `stream_chat()` using manual `with langfuse.start_as_current_observation(...)` -- this would require the same complex context management we're trying to eliminate.

**Recommended approach**: Move the `start_as_current_observation()` and `propagate_attributes()` into `stream_chat()` itself as a context manager wrapping the core logic. Although `stream_chat()` is an async generator, the context manager will stay active across `yield` points within the same async task. The auto-instrumented spans from `configure_claude_agent_sdk()` will be captured within this context. The key difference from the current approach: we set up OTel context once and let auto-instrumentation do the rest, rather than manually tracking every span/generation.
