**Yes, the fix works with gVisor (`runsc`).** Here's why: Docker port publishing (`-p` / `ports`) works at the **host level**, not inside the container's network stack: 1. Docker creates a `docker-proxy` process on the host that listens on `0.0.0.0:{host_port}` 2. Traffic is forwarded to the container's veth interface via iptables/NAT 3. The container's network stack (whether `runc`'s standard netns or gVisor's netstack) receives traffic on port 3000 normally The gVisor [Quick Start docs](https://gvisor.dev/docs/user_guide/quick_start/docker/) explicitly demonstrate `-p` working with `--runtime=runsc`. The known gVisor networking issues are about **DNS resolution** (already handled via `dns=["8.8.8.8"]` and `extra_hosts`) and **iptables inside the container** (not relevant here since port publishing is host-side). The only scenario where it could break is Docker-in-gVisor (nested containers), which doesn't apply here. Sources: - [Docker Quick Start - gVisor](https://gvisor.dev/docs/user_guide/quick_start/docker/) - [FAQ - gVisor](https://gvisor.dev/docs/user_guide/faq/)
