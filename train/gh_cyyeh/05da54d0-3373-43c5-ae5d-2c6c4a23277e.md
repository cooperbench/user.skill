### 8. VULNERABILITIES & EMPTY DATA HANDLING

**Where empty data can slip through:**

1. **No data validation on render_chart:**
   - `mcp_sse.py` line 134-136 only checks for `data` existence and `layout.title`
   - Does NOT validate:
     - Empty arrays: `data: []` passes
     - Empty traces: `{type: "bar", x: [], y: []}` passes
     - Missing trace fields: `{type: "pie"}` without `labels`/`values` passes

2. **Frontend renders without validation:**
   - `ChartWidget.tsx` passes data directly to Plotly's Plot component
   - No checks for:
     - Empty or null data arrays
     - Missing required trace fields by type
     - NaN/Infinity values
   - Plotly handles rendering but may show blank/broken charts

3. **Tool-level validation gaps:**
   - Chart-builder prompt (agent.py line 87-112) instructs subagent about best practices
   - But no schema enforcement on the tool itself
   - Subagent could call `render_chart` with incomplete specs

4. **SSE transmission:**
   - Specs captured as-is from `tool_use.input`
   - No transformation or cleanup
   - Malformed specs flow through directly

5. **No user feedback:**
   - If a chart has empty `x`/`y` arrays, Plotly renders a blank chart
   - User sees empty space, no error message
   - No way to detect data generation failure
