### 9. KEY ARCHITECTURAL INSIGHTS

**No Chart Subagent:**
- Only the `sql-analyst` subagent exists (for SQL queries)
- The orchestrator handles ALL charting directly via `render_chart` tool
- This prevents the overhead and complexity of multi-hop chart generation

**SSE Event Architecture:**
- Backend streams events: thinking, answer, tool_call, tool_result, subagent_start, subagent_end, done, error
- Chart specs travel in `tool_result` events with `chart_spec` field
- Frontend reassembles into content segments with inline chart rendering

**Cross-Model Compatibility Strategy:**
1. **Numbered steps** (step 1, 2, 3, 4) for Claude clarity
2. **WRONG/CORRECT examples** to show model the difference
3. **Hard constraint** language: "FORBIDDEN", "MUST"
4. **Post-render directive** in tool result `next_step` field for models that don't read system prompt well
5. **Multi-select parameter** guidance so model knows when to ask for clarification

**Chart Spec Capture Pattern:**
The backend captures the original `render_chart` input (`tool_chart_specs`) separately from the tool result, because:
- The MCP tool result may not echo the full spec
- The frontend needs the exact data arrays to render correctly
- This ensures charts render even if the model's response is incomplete

## Phase 1: Root Cause Analysis

I've identified the root cause. Let me trace through the exact problem:

**The Claude Agent SDK conversation loop** works like this:
1. Model responds with tool_use blocks → SDK executes tools, sends results, loop continues
2. Model responds with **only text** (no tool_use) → SDK considers this the **final response** and ends the conversation

**What happens with OpenAI models after the first chart:**
1. execute_sql → data returned
2. render_chart → chart rendered, `next_step` says "write narrative BEFORE making more tool calls"
3. Model writes narrative text **only** (no tool_use blocks) → **SDK ends the loop**
4. Second chart never gets created

**What happens with Claude models:**
1. Same steps 1-2
2. Claude writes narrative text **AND** includes the next execute_sql tool_use in the **same response**
3. SDK sees tool_use → continues the loop → second chart gets created

**Root cause:** The system prompt says `"STOP making tool calls. Write 2-3 sentences of narrative"` (line 46 in agent.py). OpenAI models interpret this literally as "produce a text-only response", which terminates the SDK loop. Claude models naturally mix text + tool_use blocks in one response, so they continue despite the instruction.

The `next_step` in the render_chart result (mcp_sse.py:179-182) reinforces this: "write narrative text BEFORE making any more tool calls" — OpenAI reads this as "write text, end turn."

Changes look good. Now to answer your question about **why Anthropic models don't have this issue**:

## Why Claude models work but OpenAI models don't

The Claude Agent SDK's conversation loop ends when the model produces a **text-only response** (no tool_use blocks). This is by design — text-only means "I'm done."

**Claude models** naturally support mixing text blocks and tool_use blocks in a single response. When the old prompt said "write narrative text, then start the next chart", Claude interpreted this as:

```
Response: [text: "Chart 1 shows..."] + [tool_use: execute_sql(...)]
```

Both text AND tool call in one turn → SDK sees tool calls → continues the loop → second chart gets created.

**OpenAI models** (via Bifrost translation) tend to treat text and tool calls as separate turns. When told "STOP making tool calls, write narrative text", OpenAI produces:

```
Response: [text: "Chart 1 shows..."]   (no tool calls)
```

Text-only response → SDK treats it as final answer → loop ends → second chart never starts.

## The fix (3 files, 3 locations)

1. **System prompt** (`agent.py`): Removed "STOP making tool calls" and the old HARD CONSTRAINT. Added explicit instructions that the model MUST include the next `execute_sql` call in the SAME response as narrative text when more charts remain. Added a "KEEP THE CONVERSATION ALIVE" warning that text-only responses end the conversation permanently.

2. **render_chart tool description** (`mcp_sse.py`): Replaced "Never call execute_sql... until you have written explanatory text" with "write explanation, then include next execute_sql in same response."

3. **render_chart `next_step` result** (`mcp_sse.py`): Replaced "Do NOT call execute_sql until you have written analysis" with "MUST include the next execute_sql in the SAME response — do NOT end with only text or the conversation will end."
