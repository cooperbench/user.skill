**Root cause**: `PROXY_BASE_URL=http://host.docker.internal:8000` — the sidecar (running with `runsc`/gVisor) tries to fetch the MCP endpoint at `host.docker.internal:8000` and fails.

There are two compounding issues:

**The fix**: Get the actual gateway IP of the `agent-sandbox` network from Docker's IPAM config and use that as the static `/etc/hosts` entry for `host.docker.internal`.

The fix is in place. Here's a summary of what was wrong and what was changed:

## Problem

When running `make dev` with `runsc` (gVisor), the sidecar container couldn't reach `host.docker.internal:8000`. Two issues combined:

1. **gVisor doesn't use Docker's embedded DNS** (127.0.0.11) — hostname resolution inside the container relies entirely on `/etc/hosts` entries from `extra_hosts`.

2. **`"host-gateway"` pointed to the wrong IP** — on Linux, Docker resolves `host-gateway` to the `docker0` default bridge IP (e.g., `172.17.0.1`). But the sidecar is on the `agent-sandbox` custom bridge network, which has a *different* gateway (e.g., `172.20.0.1`). There's no route from `agent-sandbox` to `docker0`, so `host.docker.internal` resolved to an unreachable IP.

## Fix (`backend/app/container_manager.py`)

Added `_resolve_host_gateway_ip()` which reads the gateway IP directly from the `agent-sandbox` network's IPAM config via the Docker Python SDK. This is the host-side bridge address of the actual network the sidecar is on — the IP the host backend is reachable at from inside the container.

The `create()` method now uses this resolved IP for `host.docker.internal` instead of the `"host-gateway"` magic string. The magic string is kept as a fallback for environments (Docker Desktop, macOS) where IPAM gateway resolution might fail.

You can verify it's working by checking the backend logs after `make dev` — you should see a line like:
```
Resolved host.docker.internal gateway to 172.20.0.1
Sidecar extra_hosts: {'host.docker.internal': '172.20.0.1'}
```

   137→def _extract_chart_spec(text: str) -> dict | None:
   138→    """Extract chart_spec from subagent output text.
   139→
   140→    The chart-builder subagent returns markdown containing a JSON code block.
   141→    Try pure JSON first, then extract from ```json ... ``` fenced blocks.
   142→    """
   143→
   144→    # Try pure JSON first
   145→    try:
   146→        parsed = json.loads(text)
   147→        if "chart_spec" in parsed:
   148→            return parsed["chart_spec"]
   149→    except (json.JSONDecodeError, TypeError):
   150→        pass
   151→
   152→    # Extract from markdown fenced code blocks (```json ... ``` or ``` ... ```)
   153→    pattern = r"```(?:json)?\s*\n?(.*?)\n?\s*```"
   154→    for match in re.finditer(pattern, text, re.DOTALL):
   155→        block = match.group(1).strip()
   156→        try:
   157→            parsed = json.loads(block)
   158→            if "chart_spec" in parsed:
   159→                return parsed["chart_spec"]
   160→            # The block itself might BE the chart_spec
   161→            if "data" in parsed and isinstance(parsed["data"], list):
   162→                return parsed
   163→        except (json.JSONDecodeError, TypeError):
   164→            continue
   165→
   166→    return None
