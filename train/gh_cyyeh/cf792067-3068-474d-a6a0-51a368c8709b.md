3. So thinking text renders as plain message content (looks like an answer)
4. When `onThinkingDone` fires, segments get created → `hasSegments` becomes true → rendering switches to segment-based mode → text "moves" to the thinking block

The fix: streaming assistant messages should always use the segment-based rendering path, even before segments are populated.
