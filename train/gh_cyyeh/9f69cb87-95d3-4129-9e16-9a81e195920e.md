Found the issue. The sidecar service in `docker-compose.yml` uses `profiles: [build]`, which means it's excluded from default commands. `docker compose build` only builds services in the default profile, so the sidecar gets skipped. The fix is to pass the `--profile build` flag in the `compose-build` target:

> AGENT

The `--profile build` flag tells Docker Compose to include services tagged with the `build` profile, so both `app` and `sidecar` images will be built.
