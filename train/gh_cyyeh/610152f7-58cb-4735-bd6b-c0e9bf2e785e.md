### 2. BACKEND LANGFUSE CODE

**`backend/app/tracing.py`** - Langfuse client wrapper module:

**`backend/app/agent.py`** - Core tracing instrumentation in `stream_chat()` function:

**Trace Hierarchy:**
```
Trace: "agent-chat"
  ├── Generation: "llm-turn-1", "llm-turn-2", ... (one per LLM turn)
  │   input: user message (truncated to 500 chars)
  │   output: thinking + text content (truncated to 1000 chars)
  │   model: ANTHROPIC_MODEL
  │
  ├── Span: "tool-execute_sql" (for each SQL tool execution)
  │   input: { sql }
  │   output: { rowCount, columns } on success OR { error } on failure
  │
  └── Metadata: { session_id, model }
```

**Tracing Features:**
- Uses Langfuse SDK v3 API (`start_span`, `start_generation`, `update`, `end`, `flush`)
- `_start_generation()` - Creates a generation span for each LLM turn
- `_end_generation()` - Ends generation, recording accumulated thinking & answer text
- Tool SQL execution creates spans with `trace.start_span(name=f"tool-{tool_name}")`
- Truncates data to prevent sending large datasets to Langfuse (500 char for messages, 1000 for outputs, 100 rows max)
- Graceful error handling - tracing failures are logged but don't break the agent
- `langfuse.flush()` called in finally block to ensure all data is sent

**Session Grouping:** Each trace uses `session_id` to group multi-turn conversations in Langfuse.
