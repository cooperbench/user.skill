### 6. KEY CRITICAL INSIGHTS

1. **The `subagent_sql_data` dict is a temporary accumulator** that exists only during stream_chat execution. It's rebuilt for every chat message.

2. **Tool IDs are unique per message stream** and are tracked in the `tool_names` dict to detect parent relationships.

3. **The `continue` statements on lines 551 and 678 prevent double-emission** — internal tools don't generate frontend-visible events, only end-result data.

4. **The 100-row limit** is enforced at line 671 during capture: `entry["rows"] = sa_parsed.get("rows", [])[:100]`

5. **Chart specs are handled separately** — they arrive in the `subagent_end` event, and the frontend unpacks them into individual segments (lines 260-268 in agentService.ts).

6. **Thinking blocks are already streamed real-time** through `subagent_thinking` events (lines 454-455, 526 in agent.py).

7. **The frontend already has all components ready** to render SQL results incrementally:
   - `InlineQueryResult` component (renders a single SQL result)
   - `ContentSegment` type with `sqlResults` field
   - Callbacks for `onSubagentSqlQuery` and `onSubagentSqlResult` can be added following the same pattern as `onSubagentThinking`

This architecture makes it straightforward to add real-time SQL event streaming without breaking existing code!
