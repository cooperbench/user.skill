## Summary of Findings

I've thoroughly explored the frontend codebase and identified the root cause of the bug where switching away from a conversation while the agent is streaming, then switching back, shows an empty assistant message.

### The Problem

The issue is in the **streaming state management** in `/Users/cyyeh/Desktop/duckdb-data-agent/frontend/src/contexts/AgentContext.tsx`:

   - This message is immediately added to the messages array

   - `textBufferRef.current` - buffered text chunks (line 72)
   - `currentTextRef.current` - current text being accumulated (line 74)
   - `segmentsRef.current` - structured segments (line 73)

3. **Problem**: These refs are **not persisted in React state** when the component unmounts/remounts (e.g., when switching away and back to a conversation).

### How the Bug Manifests

**Scenario:**
1. User sends a message while a conversation is active
2. Agent starts streaming a response → text accumulates in `textBufferRef` and `currentTextRef`
3. User switches away to a different conversation (or tab/window gets hidden)
4. Component may unmount or lose focus
5. User switches back to the original conversation
6. The refs are reset or lost, but the `assistantMsg` in the messages array still has the old empty `content: ''`

### Why It Happens

The key issues are:

1. **Refs don't survive component unmounting**: If the `AgentProvider` unmounts when switching conversations, the refs (`textBufferRef`, `currentTextRef`, `segmentsRef`, `assistantIdRef`) are recreated fresh, losing accumulated state.

2. **Buffered text is not in React state**: The `flushText` callback (line 37-48) updates the message's `content` via `setMessages`, but:
   - Text chunks are first buffered in `textBufferRef`
   - There's a debounce timer (50ms) before flushing to avoid excessive re-renders
   - If the component unmounts before the flush timer fires, buffered text is lost

3. **Segments not saved during streaming**: The `segmentsRef` array accumulates structured content, but when the component unmounts/remounts, this array is recreated empty.

4. **No visibility/focus handling**: There's no code that detects when the page becomes hidden or loses focus to flush pending buffers before unmounting.
