### Architecture Overview

The credential proxy system prevents the Claude Code subprocess from accessing the real Anthropic API key through prompt injection attacks. Instead, it issues short-lived UUID tokens that are scoped to individual chat sessions.

```
User Browser
    ↓
  FastAPI Backend (/api/chat endpoint)
    ↓
Creates short-lived UUID token (10 min TTL)
    ↓
Spawns Claude Code subprocess with:
  - ANTHROPIC_API_KEY=<UUID token>

    ↓
Claude Code subprocess makes requests to /anthropic/{path}
    ↓
Proxy validates UUID token
    ↓
Swaps UUID for real ANTHROPIC_API_KEY
    ↓
Forwards request to https://api.anthropic.com
    ↓
Streams response back to subprocess
```

### Credential Proxy Security

1. **Subprocess Isolation:** Claude Code subprocess never has access to real ANTHROPIC_API_KEY
2. **Token Scoping:** UUID tokens are:
   - Single-use per session (same UUID used for all calls in one chat)

## Changes made

**Two layers of defense** to prevent the Claude agent subprocess from accessing Langfuse credentials:

### 1. `backend/app/agent.py` (lines 137-140)
Added `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` as empty strings in the subprocess `env` dict. Since the SDK merges `options.env` into `os.environ` (with `options.env` winning), this overrides any inherited values to empty strings.

### 2. `backend/app/tracing.py` (lines 32-36)
After the Langfuse client is initialized (credentials stored internally in the client object), the keys are scrubbed from `os.environ`. This prevents any subprocess spawned later from inheriting them, even if the `env` override in agent.py were somehow missed.

**Defense in depth**: Either change alone would be sufficient, but both together ensure the keys can't leak regardless of how subprocesses are spawned.
