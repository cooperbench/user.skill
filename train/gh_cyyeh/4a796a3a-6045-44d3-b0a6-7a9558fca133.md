These are pre-existing errors from missing `node_modules` — not related to my change. The change itself is straightforward: just reordering the variable declaration and conditionally prepending the skill restriction to the prompt on resume.

Here's what the fix does:

**Root cause**: When the agent session is resumed (via `session_id`), the Claude Agent SDK reuses the original session's system prompt — which still lists the now-deleted skill. The `discoverSkills()` call builds a fresh `skillRestriction` string on every request, but it only goes into `systemPrompt` in `baseOptions`, which gets ignored during resume.

**Fix**: When resuming (`useResume` is true), prepend the current `skillRestriction` to the user message (prompt). This way the model sees the updated list of available skills even though the original system prompt is stale. On non-resume requests, the system prompt already contains the restriction, so no prepending is needed.
