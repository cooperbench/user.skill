### 4. **How host.docker.internal is Resolved (Critical for gVisor)**

- On macOS, Docker containers can't directly route to bridge IPs due to VM isolation

### 5. **Runc vs. Runsc (gVisor) Runtime Modes**

**Configuration via environment variable** (in `.env.example` line 15):
```
CONTAINER_RUNTIME=runc  # use `runsc` for gVisor
```

**Runc (default):**
- Docker's standard runtime
- Fast, light container isolation
- Available on all platforms (macOS, Linux, Windows)
- Container filesystem, processes, networks isolated
- All capabilities dropped with `--cap-drop=ALL`
- Security: containers isolated but share host kernel

**Runsc (gVisor):**
- Application kernel (user-space syscall interception)
- Stronger isolation: intercepts all syscalls, even from bash/python
- Linux-only (kernel 4.14.77+, x86_64 or ARM64)
- Slower startup (10-30 seconds vs. ~1 second for runc)
- Best for multi-tenant deployments

**Special handling required for runsc:**
1. **DNS resolution**: gVisor doesn't use Docker's embedded DNS (127.0.0.11)
   - Solution: Use public DNS (8.8.8.8, 8.8.4.4) - line 142 of container_manager.py
   - Also resolve container hostnames via extra_hosts for inter-container communication

2. **host.docker.internal resolution**: 
   - Magic value "host-gateway" doesn't work
   - Solution: Read actual gateway IP from network IPAM config (as described above)

3. **Port publishing for macOS**:
   - macOS Docker Desktop can't route to bridge IPs
   - Solution: Publish port 3000 to random host port and use 127.0.0.1:{host_port}
   - Linux/docker-compose: Use direct container IP

The fix looks correct. Here's the summary:

**Root cause:** `_resolve_host_gateway_ip()` returns the IPAM gateway IP of the `agent-sandbox` bridge network (e.g., `172.20.0.1`). On macOS Docker Desktop, this IP is the bridge gateway **inside the Linux VM**, not the Mac host where your backend is running. So the sidecar was trying to reach `172.20.0.1:8000` instead of the actual Mac host.

**Fix:** Only use the IPAM gateway IP for gVisor (`runsc`) on Linux, where Docker's `host-gateway` magic value isn't honored. For all other cases (runc on any platform, macOS Docker Desktop), use `host-gateway` which Docker resolves correctly:

| Platform | Runtime | `host.docker.internal` resolves via |
|----------|---------|-------------------------------------|
| macOS | runc | `host-gateway` → Mac host IP |
| Linux | runc | `host-gateway` → docker0 bridge IP (host) |
| Linux | runsc | IPAM gateway IP (explicit, gVisor-safe) |

This makes both `runc` and `runsc` work correctly. You can test it with `make dev` now.
