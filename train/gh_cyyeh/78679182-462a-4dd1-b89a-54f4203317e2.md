### 8. CONTAINER LIFECYCLE EXAMPLE

**Sequence:**
1. User sends query → backend route handler

   - Removes containers idle > 300s OR older than 3600s

### 9. NETWORKING (gVisor DNS & Host Gateway)

The code handles special networking requirements for gVisor (runsc) containers:

- **DNS Resolution:** gVisor's netstack doesn't use Docker's embedded DNS (127.0.0.11), so the backend builds `extra_hosts` from container IPs on the shared network
- **Host Gateway:** Resolves `host.docker.internal` from network IPAM gateway on Linux+gVisor (different from `host-gateway` magic value)
- **Public DNS:** Uses Google DNS (8.8.8.8, 8.8.4.4) for external host resolution inside containers

**Summary:**

**Root cause:** The skills volume bind mount at `/home/appuser/.claude/skills` caused Docker to create the intermediate `/home/appuser/.claude` directory as **root-owned** inside the `appuser` tmpfs. When `server.ts` tried to create `~/.claude/debug` at startup, `appuser` couldn't write to the root-owned `.claude` directory, crashing the process with `EACCES`.

**Fix:** Added a separate tmpfs mount at `/home/appuser/.claude` with `uid=1000,gid=1000` in `container_manager.py`. This ensures the `.claude` directory is always owned by `appuser`, regardless of how Docker handles bind mount point creation.
