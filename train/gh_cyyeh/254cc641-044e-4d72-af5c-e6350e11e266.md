### 5. **Message-to-Langfuse Session Mapping Pattern**

**How Conversation Messages Are Grouped Under a Single Langfuse Session:**

1. **User Session ID (X-Session-ID):**
   - Browser generates UUID once and stores in `SessionContext`
   - Attached to every API call as header
   - Not directly used in Langfuse but identifies unique browser session

2. **Agent Session ID (claude-agent-sdk):**
   - Used for Langfuse session grouping
   - Passed via `session_id` parameter to `stream_chat()`
   - First message: `sessionIdRef.current = null` → SDK generates new ID
   - Subsequent messages: `sessionIdRef.current` → Reuse same agent session → `--resume` flag resumes conversation
   - Returned in SSE "done" event for client: `callbacks.onDone(newSessionId)`

3. **Langfuse Session Mapping:**
   - When agent session starts, `stream_chat()` receives `session_id` parameter
   - Creates Langfuse observation context: 
   ```python
   observation_ctx = langfuse.start_as_current_observation(
       name="agent-chat",
       input={"message": message[:500]},
       metadata={"model": ANTHROPIC_MODEL},
   )
   ```
   - Propagates session_id for grouping: 
   ```python
   propagate_ctx = propagate_attributes(session_id=session_id)
   ```
   - Updates trace with actual session_id at end:
   ```python
   langfuse.update_current_trace(session_id=actual_session_id, ...)
   ```

4. **Conversation Continuity:**
   - Client maintains `sessionIdRef.current` in `AgentContext`
   - First message: null → get new session_id from response
   - Follow-up messages: reuse session_id → SDK resumes with `--resume`
   - All messages in conversation grouped under same Langfuse session_id
   - Edited messages: session_id reset to null (fresh session) but conversation_history passed to system prompt for context

**Root Cause Identified.**

The issue is clear: the Langfuse `session_id` is set to the **Claude SDK's session ID** (`actual_session_id`). When editing or asking a new question after a delete:

- **Edit flow**: `/api/chat/edit` always passes `session_id=None` → new Claude SDK session created → new `actual_session_id` → **new Langfuse session**
- **After delete**: `deleteMessage` resets `sessionIdRef.current = null` → next `sendMessage` also starts a new agent session → **new Langfuse session**

So Q1 ends up under `session_A` and the edited/replaced Q2 under a completely different `session_B` in Langfuse.

**Fix:** Decouple the Langfuse session_id from the Claude SDK session_id by introducing a stable `conversationId` on the frontend that persists across edits/deletes (only resets on `clearMessages()`), and use it as the Langfuse session_id.
