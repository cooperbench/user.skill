## Root Cause Found

The bug is in `loadMessages()` (AgentContext.tsx:612-616). When switching conversations, it only replaces messages but does **not**:
1. Abort the ongoing streaming request
2. Reset `isStreaming` to `false`
3. Clear streaming-related refs (`textBufferRef`, `segmentsRef`, `assistantIdRef`, etc.)
4. Clear any pending flush timer

This means:
- The old stream keeps running with stale `assistantIdRef`
- `isStreaming` stays `true`, which blocks the UI (input disabled, guards like `if (isStreaming) return`)
- Callbacks silently fail since no message matches the old assistant ID
- When switching back, the state is corrupted

The fix is straightforward - `loadMessages()` needs to do the same cleanup as `clearMessages()`:
