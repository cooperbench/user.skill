Now I have the full picture. Here are the **approaches**:

## Approach 1: Interleaved rendering using original segment order (Recommended)

Instead of separating `chartSegments` and `answerSegments` into two groups, collect all answer-relevant segments (both text and chart) and render them in their **original order** from `message.segments`. This preserves the natural flow: text describing a chart appears right before/after that chart.

**Trade-offs:**
- Simplest change — just reorder rendering, no new data structures
- Preserves the natural ordering the backend already provides
- Works with streaming since segments arrive in order

## Approach 2: Explicit pairing with heuristic matching

Parse answer text to detect chart references, then pair each chart with its closest text block. Render as paired groups.

**Trade-offs:**
- More complex — requires heuristic text analysis
- Fragile if the LLM's text doesn't reference charts predictably
- Overkill for the "interleaved full-width" layout you chose

## Approach 3: Backend-driven pairing

Add a `chart_ref` field to segments on the backend so each text segment knows which chart it relates to.

**Trade-offs:**
- Requires backend changes
- Most robust long-term but over-engineered for now

**My recommendation: Approach 1.** It's the simplest change that achieves the goal — render answer-block segments in their natural order instead of grouping by type.

Good question. Let me explain how the ordering works:

The backend sends segments in **chronological order** as the agent produces them. When the agent writes text explaining something, that becomes an `answer` segment. When it then produces a chart, that becomes a `tool` or `subagent_end` segment with `chart_spec`. These arrive in the order the agent generated them.

Currently the frontend **splits** them into two separate arrays (`chartSegments` and `answerSegments`) and renders charts first, text second — destroying the natural order.

The fix is to **stop splitting** and instead filter for answer-relevant segments while **preserving their original index** in `message.segments`. Since the agent naturally writes "here's chart 1..." then produces chart 1, then "here's chart 2..." then produces chart 2, the original order inherently pairs text with its corresponding chart.

The key code change: instead of two separate `.filter()` calls (one for charts, one for text), we do **one** `.filter()` that keeps both chart and text segments, maintaining their position in the array.
