   - Does this conversation belong to the current session?
   - Is the user authorized to view it?

3. **How the bug manifests**:
   - If two users are using the app simultaneously (or same user in two browser tabs with different session IDs)
   - User A switches to conversation A
   - User B can fetch User A's conversation messages by knowing the conversation ID
   - Or if session-scoping is involved, a stale conversation from a different session could be loaded

No type errors. Here's a summary of the fix:

**Root cause**: `sendMessage` is a `useCallback` that captures `messages` in its closure, but `messages` is not in its dependency array. When you switch conversations, `loadMessages` updates the `messages` state, but the `sendMessage` closure still holds the **old** messages from the previous conversation. So the agent receives the wrong conversation's history.

**Fix**: Added a `messagesRef` that stays in sync with `messages` via `useEffect`, and read from `messagesRef.current` instead of the stale closure variable. This way `sendMessage` always sees the current conversation's messages regardless of when the callback was last recreated.
