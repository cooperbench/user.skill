### Session ID Generation
- **Frontend**: Generated client-side using `crypto.randomUUID()` in `SessionContext.tsx` (line 6)
- Each user gets a unique session ID that persists for the browser session via a ref

### How Session ID is Passed
- **Frontend to Backend**: Sent as `X-Session-ID` HTTP header in all requests via `agentService.ts` (lines 72, 104)
- Also used in heartbeat requests every 30 seconds (SessionContext.tsx line 12-16)
- Cleanup signal sent via `navigator.sendBeacon()` on page unload (line 20)

### Session Tracking & Storage
- **Backend**: `SessionManager` class maintains an in-memory dictionary mapping session IDs to `SessionEntry` objects
- Each `SessionEntry` contains:
  - A per-user `Database` instance (in-memory DuckDB connection)
  - A `last_seen_at` timestamp (UTC)
- Created on-demand via `get_or_create()` when first request with a session ID arrives

### Isolation
- Each user gets an isolated DuckDB connection via `database.py` → `Database()` creates `:memory:` connections
- Routes use dependency injection `get_session_db()` which extracts `X-Session-ID` header and returns the user's Database instance
- All routes (tables, query, chat) use this same dependency, ensuring data isolation per user

### TTL & Cleanup
- **TTL**: 300 seconds (5 minutes) - sessions without activity are marked stale
- **Cleanup Loop**: Runs every 60 seconds in `main.py` (background task via `_cleanup_loop()`)
- **Activity Updates**: 
  - Heartbeat endpoint (`/api/heartbeat`) touches `last_seen_at` timestamp
  - Each API call automatically updates `last_seen_at` via `get_or_create()`
- Stale sessions are destroyed via `cleanup_stale()` which closes the DuckDB connection and removes from dictionary

### Request Flow
1. Frontend generates/sends session ID in `X-Session-ID` header
2. Backend `get_session_db()` dependency extracts header
3. `SessionManager.get_or_create()` retrieves or creates user's isolated Database instance
4. User's queries operate on their isolated in-memory DuckDB
5. Background cleanup removes idle sessions after 5 minutes
