The architecture cleanly separates **mode concerns** into:

1. **Agent execution**: Delegated to either subprocess (`ClaudeSDKClient`) or sidecar container (`express + Claude Agent SDK`)
2. **Data access**: Both modes use MCP SSE bridge (`/mcp/sse`) for identical tool access
3. **Credential security**: Both modes use the credential proxy (UUID tokens)

5. **Configuration**: Single `CONTAINER_ENABLED` flag determines dispatch; all settings in `config.py`

   168→## Security
   169→
   170→### Credential Proxy
   171→
   172→When the agent runs, the backend spawns a Claude Code subprocess via the Anthropic Agent SDK. A naive approach would pass `ANTHROPIC_API_KEY` directly into that subprocess's environment — but any tool or shell command the agent executes could then read and exfiltrate the key.
   173→
   174→Instead, the backend runs a built-in reverse proxy at `/anthropic` that sits between Claude Code and `api.anthropic.com`:
   175→
   176→```
   177→Claude Code subprocess
   178→  → ANTHROPIC_BASE_URL=http://127.0.0.1:{PORT}/anthropic
   179→  → ANTHROPIC_API_KEY=<short-lived UUID token>
   180→        ↓
   181→FastAPI proxy (/anthropic/{path})
   182→  → validates UUID token
   183→  → swaps it for the real ANTHROPIC_API_KEY
   184→  → forwards request to api.anthropic.com
   185→```
   186→
   187→**How it works:**
   188→
   189→1. Before each agent session, the backend mints a random UUID token with a 10-minute TTL.
   190→2. The token is injected into the subprocess environment as `ANTHROPIC_API_KEY`; the real key is never exposed.
   191→3. The proxy validates every inbound request against the token store and substitutes the real key before forwarding upstream.
   192→4. When the session ends, the token is explicitly revoked in a `finally` block, regardless of success or error.
   193→5. A background task runs every 60 seconds to sweep any tokens that outlived their TTL.
   194→
   195→The subprocess only ever holds a single-session UUID. Even if a tool call reads the environment, all it gets is a temporary token scoped to that conversation.
   196→
   197→### Container Isolation (Optional)
   198→
   199→For additional defense in depth, the backend can run each Claude Code session inside a **gVisor-sandboxed Docker container** ("sidecar") instead of a bare subprocess. This provides code execution sandboxing, multi-tenant isolation, and a hardened boundary between the agent and the host system.
   200→
   201→**Architecture:**
   202→
   203→```
   204→Browser
   205→  │
   206→  ▼
   207→FastAPI Backend (host)
   208→  ├── Chat route ──► ContainerManager ──► Docker SDK
   209→  │                       │
   210→  │                       ▼
   211→  │               ┌──────────────────────┐
   212→  │               │  gVisor Sandbox      │
   213→  │               │                      │
   214→  │               │  Sidecar Container   │
   215→  │               │  (Node.js + Claude)  │
   216→  │               │                      │
   217→  │               │  POST /query → SSE   │
   218→  │               └──────┬───────────────┘
   219→  │                      │
   220→  ├── /anthropic ◄───────┘  (credential proxy)
   221→  ├── /mcp/sse   ◄───────┘  (DuckDB MCP bridge)
   222→  │
   223→  └── DuckDB (per-user, in-memory)
   224→```
   225→
   226→When `CONTAINER_ENABLED=true`, the data flow for a chat message is:
   227→
   228→1. Frontend sends a chat message to the FastAPI backend.
   229→2. Backend mints a short-lived UUID token via the credential proxy and spins up a gVisor container (or reuses an existing one for the session) via `ContainerManager`.
   230→3. Backend sends the query to the sidecar's `POST /query` endpoint. The sidecar calls the Claude Agent SDK's `query()` function with `includePartialMessages: true` for token-level streaming, configured with the host's MCP SSE endpoint.
   231→4. Claude CLI talks to the host credential proxy (`/anthropic`) for Anthropic API access (using the UUID token, never the real key).
   232→5. Claude CLI's `execute_sql` tool calls reach the host DuckDB via the **MCP SSE bridge** (`/mcp/sse?session_id=...`), which routes each connection to the correct per-user DuckDB instance through the existing `SessionManager`.
   233→6. The sidecar streams SSE events back to the backend, which forwards them to the frontend in the same format as the subprocess path.
   234→7. On session end, the container is stopped and removed; the UUID token is revoked.
   235→
   236→When `CONTAINER_ENABLED=false` (default), the existing in-process subprocess model is used with no container overhead.
   237→
   238→**Sidecar container:** The `sidecar/` directory contains a TypeScript HTTP server (`src/server.ts`) that uses the Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`) with `includePartialMessages: true` for true token-level streaming. The Docker image (`sidecar/Dockerfile`) bundles Node.js 20, Python 3.12, the Agent SDK, and the `@anthropic-ai/claude-code` CLI (required by the SDK internally). Containers run with a read-only root filesystem, all Linux capabilities dropped, no volume mounts, no Docker socket access, and a non-root user.
   239→
   240→**MCP SSE bridge:** The backend exposes the DuckDB `execute_sql` tool at `/mcp/sse` using the MCP protocol's SSE transport (`backend/app/mcp_sse.py`). Each SSE connection requires a `session_id` query parameter to route tool calls to the correct per-user DuckDB instance. This is how the containerized Claude CLI reaches DuckDB on the host without any direct database access inside the container.

   200→        env["LANGFUSE_SECRET_KEY"] = LANGFUSE_SECRET_KEY
   201→        env["LANGFUSE_BASE_URL"] = LANGFUSE_BASE_URL
   202→
   203→    if "127.0.0.1" in PROXY_BASE_URL or "localhost" in PROXY_BASE_URL:
   204→        logger.warning(
   205→            "PROXY_BASE_URL=%s uses localhost which is unreachable from containers. "
   206→            "Set PROXY_BASE_URL to the host's Docker-accessible address "
   207→            "(e.g., http://host.docker.internal:10000).",
   208→            PROXY_BASE_URL,
   209→        )
   210→
   211→    # Use the backend session ID (X-Session-ID header) for both:
   212→    # 1. MCP SSE URL — so the container queries the correct DuckDB instance
   213→    # 2. Container lifecycle key — so the same container is reused across
   214→    #    requests from the same browser tab (the Claude agent session_id
   215→    #    changes after the first response, which would orphan the container)
   216→    stable_session = backend_session_id or session_id or "default"
   217→
   218→    try:
   219→        # Send SSE keepalive immediately so the HTTP response starts and
   220→        # intermediate proxies (Vite, nginx) don't drop the idle connection
   221→        # before we've finished the blocking Docker container creation.
   222→        yield ": keepalive\n\n"
   223→
   224→        # container_manager.create() is synchronous (blocking Docker API call).
   225→        # Run it in a thread executor so the event loop stays responsive and
   226→        # can continue flushing keepalives to the client during startup.
   227→        # gVisor (runsc) containers can take 10-30 seconds to spin up.
   228→        loop = asyncio.get_event_loop()
   229→        create_future = loop.run_in_executor(None, container_manager.create, stable_session, env)
   230→
   231→        max_create_wait = 60.0
   232→        elapsed = 0.0
   233→        while not create_future.done():
   234→            await asyncio.sleep(2.0)
   235→            elapsed += 2.0
   236→            if elapsed >= max_create_wait:
   237→                create_future.cancel()
   238→                raise RuntimeError(f"Container creation timed out after {max_create_wait:.0f}s")
   239→            yield ": keepalive\n\n"
   240→        info = await create_future
   241→
   242→        # Wait for container to be ready
   243→        for attempt in range(10):
   244→            try:
   245→                async with httpx.AsyncClient(timeout=httpx.Timeout(5.0)) as check_client:
   246→                    resp = await check_client.get(f"{info.url}/health")
   247→                    if resp.status_code == 200:
   248→                        break
