   164→## Security
   165→
   166→### Credential Proxy
   167→
   168→When the agent runs, the backend spawns a Claude Code subprocess via the Anthropic Agent SDK. A naive approach would pass `ANTHROPIC_API_KEY` directly into that subprocess's environment — but any tool or shell command the agent executes could then read and exfiltrate the key.
   169→
   170→Instead, the backend runs a built-in reverse proxy at `/anthropic` that sits between Claude Code and `api.anthropic.com`:
   171→
   172→```
   173→Claude Code subprocess
   174→  → ANTHROPIC_BASE_URL=http://127.0.0.1:{PORT}/anthropic
   175→  → ANTHROPIC_API_KEY=<short-lived UUID token>
   176→        ↓
   177→FastAPI proxy (/anthropic/{path})
   178→  → validates UUID token
   179→  → swaps it for the real ANTHROPIC_API_KEY
   180→  → forwards request to api.anthropic.com
   181→```
   182→
   183→**How it works:**
   184→
   185→1. Before each agent session, the backend mints a random UUID token with a 10-minute TTL.
   186→2. The token is injected into the subprocess environment as `ANTHROPIC_API_KEY`; the real key is never exposed.
   187→3. The proxy validates every inbound request against the token store and substitutes the real key before forwarding upstream.
   188→4. When the session ends, the token is explicitly revoked in a `finally` block, regardless of success or error.
   189→5. A background task runs every 60 seconds to sweep any tokens that outlived their TTL.
   190→
   191→The subprocess only ever holds a single-session UUID. Even if a tool call reads the environment, all it gets is a temporary token scoped to that conversation.
   192→
   193→### Container Isolation (Optional)
   194→
   195→For additional defense in depth, the backend can run each Claude Code session inside a **gVisor-sandboxed Docker container** ("sidecar") instead of a bare subprocess. This provides code execution sandboxing, multi-tenant isolation, and a hardened boundary between the agent and the host system.

   200→Browser

   222→When `CONTAINER_ENABLED=true`, the data flow for a chat message is:
   223→
   224→1. Frontend sends a chat message to the FastAPI backend.
   225→2. Backend mints a short-lived UUID token via the credential proxy and spins up a gVisor container (or reuses an existing one for the session) via `ContainerManager`.
   226→3. Backend sends the query to the sidecar's `POST /query` endpoint. The sidecar calls the Claude Agent SDK's `query()` function with `includePartialMessages: true` for token-level streaming, configured with the host's MCP SSE endpoint.
   227→4. Claude CLI talks to the host credential proxy (`/anthropic`) for Anthropic API access (using the UUID token, never the real key).

   229→6. The sidecar streams SSE events back to the backend, which forwards them to the frontend in the same format as the subprocess path.
   230→7. On session end, the container is stopped and removed; the UUID token is revoked.
   231→
