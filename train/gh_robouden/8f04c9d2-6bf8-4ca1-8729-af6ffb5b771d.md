**No, CloudFront cannot route SSH traffic.** Here's why and what your alternatives are: ## Why CloudFront Can't Handle SSH CloudFront is a **Layer 7 (Application Layer) CDN** designed exclusively for HTTP/HTTPS: - **Protocols supported:** HTTP and HTTPS only - **Ports:** Only 80 (HTTP) and 443 (HTTPS) - **SSH operates on:** Port 22 (Layer 4 TCP protocol) - **CloudFront's purpose:** Cache and deliver web content, not arbitrary TCP traffic When you try to SSH to a CloudFront domain: ```bash ssh root@simplemap.safecast.org # Port 22 # DNS → CloudFront IPs (listening only on ports 80/443) # CloudFront: "I don't accept connections on port 22" → Connection refused ``` ## Alternative Solutions ### Option 1: SSH Subdomain (Recommended) Create a separate DNS A record that bypasses CloudFront: ```bash # In Route53, add a new record: ssh.simplemap.safecast.org → 65.108.24.131 (A record, NOT CloudFront alias) # Then you can SSH with: ssh root@ssh.simplemap.safecast.org ``` **Pros:** - ✅ Clean, memorable hostname - ✅ No extra cost - ✅ Simple to set up **Cons:** - ❌ Different hostname for SSH vs web - ❌ No geographic routing ### Option 2: AWS Network Load Balancer (NLB) Use an NLB to route TCP traffic (including SSH): ``` User → NLB (Port 22) → EC2 Instance (65.108.24.131:22) ``` **Pros:** - ✅ Can use domain name for SSH - ✅ Health checks and failover - ✅ Can handle multiple backends **Cons:** - ❌ **Cost:** ~$16-20/month for the NLB alone - ❌ Added complexity - ❌ Overkill for a single server ### Option 3: AWS Global Accelerator Route TCP traffic globally with anycast IPs: **Pros:** - ✅ Global routing optimization - ✅ Handles SSH and other TCP protocols **Cons:** - ❌ **Very expensive:** $0.025/hour + data transfer (~$18/month minimum) - ❌ Massive overkill for SSH to one server ### Option 4: SSH …
