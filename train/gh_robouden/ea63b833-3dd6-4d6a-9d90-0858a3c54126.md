    65→## Component Details
    66→
    67→### 1. File Watcher (fsnotify)
    68→
    69→**Purpose**: Monitor filesystem for changes in real-time.
    70→
    71→**Implementation**:
    72→```go
    73→watcher, _ := fsnotify.NewWatcher()
    74→watcher.Add("/root/anytype-workspace")
    75→
    76→for {
    77→    select {
    78→    case event := <-watcher.Events:
    79→        if event.Op&fsnotify.Remove == fsnotify.Remove {
    80→            DeleteFile(event.Name)
    81→        } else if event.Op&fsnotify.Write == fsnotify.Write {
    82→            SyncFile(event.Name)
    83→        }
    84→    }
    85→}
    86→```
    87→
    88→**Features**:
    89→- Recursive directory watching
    90→- Debouncing (2 second delay to avoid duplicate events)
    91→- File timestamp tracking
    92→- `.md` file filtering
    93→
    94→**Events Handled**:
    95→- `Create` - New file created → Sync to AnyType
    96→- `Write` - File modified → Update in AnyType
    97→- `Remove` - File deleted → Delete from AnyType
    98→
    99→### 2. Object Map (Persistent Storage)
   100→
   101→**Purpose**: Maintain bidirectional mapping between filenames and AnyType object IDs.
   102→
   103→**File Location**: `/root/.anytype-workspace-objectmap.json`
   104→
   105→**Structure**:
   106→```json
   107→{
   108→  "filename-without-extension": "bafyreif6xrpi4yx4fmhy7...",
   109→  "another-file": "bafyreickujocrhaglvvru..."
   110→}
   111→```
   112→
   113→**Implementation**:
   114→```go
   115→type ObjectMap struct {
   116→    mu      sync.RWMutex
   117→    mapping map[string]string
   118→}
   119→
   120→func (om *ObjectMap) Set(filename, objectID string) error {
   121→    om.mu.Lock()
   122→    defer om.mu.Unlock()
   123→    om.mapping[filename] = objectID
   124→    return om.save()
   125→}
   126→```
   127→
   128→**Thread Safety**: Uses `sync.RWMutex` for concurrent access.
   129→
   130→**Persistence**: Saves to disk after every modification.
   131→
   132→**Use Cases**:
   133→1. **Create/Update**: Store object ID after successful creation
   134→2. **Delete**: Look up object ID, delete from AnyType, remove from map
   135→3. **Restart Recovery**: Load mappings from disk on service start
   136→
   137→### 3. gRPC Client
   138→
   139→**Purpose**: Communicate with AnyType's gRPC API for object operations.
   140→
   141→**Connection**:
   142→```go
   143→conn, _ := grpc.Dial("127.0.0.1:31010",
   144→    grpc.WithTransportCredentials(insecure.NewCredentials()))
   145→client := service.NewClientCommandsClient(conn)
   146→```
   147→
   148→**Authentication**:
   149→```go
   150→// Read session token from config
   151→token := readSessionToken() // from ~/.anytype/config.json
   152→
   153→// Add to every request
   154→ctx = metadata.AppendToOutgoingContext(ctx, "token", token)
   155→```
   156→
   157→**RPCs Used**:
   158→
   159→1. **WorkspaceOpen** - Opens a space for operations
   160→   ```go
   161→   resp, _ := client.WorkspaceOpen(ctx, &pb.RpcWorkspaceOpenRequest{
   162→       SpaceId: spaceID,
   163→   })
   164→   ```
   165→
   166→2. **ObjectCreate** - Creates a new note
   167→   ```go
   168→   resp, _ := client.ObjectCreate(ctx, &pb.RpcObjectCreateRequest{
   169→       SpaceId:             spaceID,
   170→       Details:             details,
   171→       ObjectTypeUniqueKey: "ot-note",
   172→   })
   173→   ```
   174→
   175→3. **ObjectListDelete** - Deletes objects
   176→   ```go
   177→   resp, _ := client.ObjectListDelete(ctx, &pb.RpcObjectListDeleteRequest{
   178→       ObjectIds: []string{objectID},
   179→   })
   180→   ```
   181→
   182→### 4. AnyType Desktop (Server Mode)
   183→
   184→**Start Command**:
   185→```bash
   186→anytype serve -q
   187→```
   188→
   189→**Features**:
   190→- Runs headless (no GUI)
   191→- gRPC server on `127.0.0.1:31010`
   192→- gRPC-Web proxy on `127.0.0.1:31011`
   193→- Auto-login from stored credentials
   194→
   195→**Authentication Flow**:
   196→1. Reads account key from `/root/.anytype/config.json`
   197→2. Generates session token
   198→3. Stores token back in config
   199→4. Validates token on every gRPC request
   200→
   201→**Session Token Format**:
   202→```
   203→eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.REDACTED.xWn_B2psFw1...
   204→```
   205→- JWT (JSON Web Token)
   206→- HS256 algorithm
   207→- Contains account seed

   292→## Security Model
   293→
   294→### Authentication Chain
   295→
   296→```
   297→1. Account Creation
   298→   anytype auth create bot-name --network-config ...
   299→   ↓
   300→   Generates: Account Key (private key)
   301→
   302→2. Login
   303→   anytype auth login --account-key KEY
   304→   ↓
   305→   Stores: Account Key in ~/.anytype/config.json
   306→
   307→3. Server Start
   308→   anytype serve -q
   309→   ↓
   310→   Auto-login: Reads account key
   311→   Generates: Session Token (JWT)
   312→   Stores: Session Token in config.json
   313→
   314→4. Workspace Sync
   315→   Reads: Session Token from config.json
   316→   Sends: Token with every gRPC request
   317→   ↓
   318→   Server validates: Token signature and expiry
   319→```
   320→
   321→### Security Boundaries
   322→
   323→1. **Local Only**: gRPC server binds to `127.0.0.1` (not accessible remotely)
   324→2. **Session Tokens**: Short-lived, rotated on server restart
   325→3. **Account Keys**: Long-lived, stored encrypted on disk
   326→4. **File Permissions**: Config files readable only by root
   327→
   328→### Threat Model
   329→
   330→**Protected Against**:
   331→- ✅ Remote access (localhost binding)
   332→- ✅ Unauthorized local processes (session token required)
   333→- ✅ Token theft (short-lived)
   334→
   335→**Not Protected Against**:
   336→- ❌ Root-level compromise
   337→- ❌ Session token expiry (requires restart)
   338→- ❌ Account key theft

   371→## Error Handling
   372→
   373→### Retry Strategy
   374→
   375→**No Retries**: Currently, failed operations are logged but not retried.
   376→
   377→**Rationale**:
   378→- File changes can be re-triggered by modifying the file again
   379→- Automatic retry could mask authentication issues
   380→- Systemd handles service-level restarts
   381→
   382→### Error Categories
   383→
   384→1. **Authentication Errors** (`Unauthenticated`)
   385→   - Action: Log error
   386→   - Recovery: Restart services
   387→   - Prevention: Implement token refresh
   388→
   389→2. **Network Errors** (`Unavailable`)
   390→   - Action: Log error
   391→   - Recovery: Service auto-restart
   392→   - Prevention: Health checks
   393→
   394→3. **Application Errors** (`InvalidArgument`, `Internal`)
   395→   - Action: Log error with details
   396→   - Recovery: Manual investigation
   397→   - Prevention: Input validation
   398→
   399→### Logging
   400→
   401→**Format**: RFC3339 timestamp + message
   402→```
   403→[2026-03-01T12:00:00Z] ✓ file synced to AnyType
   404→```
   405→
   406→**Levels**:
   407→- `✓` Success
   408→- `⚠` Warning (non-fatal)
   409→- `✗` Error (operation failed)
   410→- `→` Debug/Info
   411→
   412→**Destinations**:
   413→- Stdout → systemd journal
   414→- Journal → `journalctl -u anytype-workspace-sync`

   416→## Design Decisions
   417→
   418→### Why Filesystem-Based?
   419→
   420→**Pros**:
   421→- ✅ Simple interface (any tool can write files)
   422→- ✅ Version control friendly (git works)
   423→- ✅ No API learning curve
   424→- ✅ Observable (can see files)
   425→
   426→**Cons**:
   427→- ❌ Not real-time (2s debounce)
   428→- ❌ No conflict resolution
   429→- ❌ Filesystem limits apply
   430→
   431→**Alternative Considered**: Direct gRPC API
   432→- Rejected: Requires every client to understand AnyType protocol
   433→
   434→### Why Session Tokens?
   435→
   436→**Pros**:
   437→- ✅ No password in memory
   438→- ✅ Can be revoked
   439→- ✅ Time-limited
   440→
   441→**Cons**:
   442→- ❌ Expire quickly
   443→- ❌ Require server restart to refresh
   444→
   445→**Alternative Considered**: Account Key directly
   446→- Rejected: Security risk (long-lived credential)
   447→
   448→### Why Object Map?
   449→
   450→**Pros**:
   451→- ✅ Enables delete operations
   452→- ✅ Survives restarts
   453→- ✅ Simple JSON format
   454→
   455→**Cons**:
   456→- ❌ Can get out of sync
   457→- ❌ No garbage collection
   458→
   459→**Alternative Considered**: Query AnyType for object by name
   460→- Rejected: API doesn't support efficient name-based lookup
   461→
   462→### Why Go?
   463→
   464→**Pros**:
   465→- ✅ Static binary (easy deployment)
   466→- ✅ Good gRPC support
   467→- ✅ Cross-compilation
   468→- ✅ AnyType SDK in Go
   469→
   470→**Cons**:
   471→- ❌ Larger binary size (~10 MB)
   472→- ❌ GC overhead (minimal)
   473→
   474→**Alternative Considered**: Python
   475→- Rejected: Requires runtime, slower gRPC

   477→## Future Enhancements
   478→
   479→### 1. Token Refresh
   480→**Problem**: Session tokens expire
   481→**Solution**: Implement automatic refresh
   482→```go
   483→if resp.Error == "Unauthenticated" {
   484→    token := refreshToken(accountKey)
   485→    retry(request, token)
   486→}
   487→```
   488→
   489→### 2. Bidirectional Sync
   490→**Problem**: Changes in AnyType don't reflect in files
   491→**Solution**: Subscribe to space changes
   492→```go
   493→stream := client.ObjectSubscribe(spaceID)
   494→for change := range stream {
   495→    writeFile(change.ObjectId, change.Content)
   496→}
   497→```
   498→
   499→### 3. Conflict Resolution
   500→**Problem**: Simultaneous changes cause data loss
   501→**Solution**: Implement last-write-wins or merge
   502→```go
   503→if localModTime > remoteModTime {
   504→    pushToRemote()
   505→} else {
   506→    pullFromRemote()
   507→}
   508→```
   509→
   510→### 4. Health Endpoint
   511→**Problem**: Hard to monitor service health
   512→**Solution**: HTTP health check
   513→```go
   514→http.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
   515→    if isHealthy() {
   516→        w.WriteHeader(200)
   517→    } else {
   518→        w.WriteHeader(500)
   519→    }
   520→})
   521→```

   276→## Data Flow Summary
   277→
   278→### 1. OpenClaw → MongoDB (Primary Data Store)
   279→- OpenClaw stores all bot state, notes, tasks in MongoDB
   280→- Uses MongoDB change streams for real-time updates
   281→- MongoDB is source of truth for bot logic
   282→
   283→### 2. OpenClaw → File System (Export)
   284→- OpenClaw writes markdown files to `/root/anytype-workspace/`
   285→- Each note in MongoDB can generate a corresponding .md file
   286→- File names are slug-ified note titles
   287→
   288→### 3. File System → Workspace Sync (Watch)
   289→- `fsnotify` watches directory for changes (CREATE, WRITE, REMOVE)
   290→- 2-second debounce prevents duplicate syncs
   291→- Tracks file modification timestamps
   292→
   293→### 4. Workspace Sync → Object Map (Tracking)
   294→- Maps filenames to AnyType object IDs
   295→- Stored in `/root/.anytype-workspace-objectmap.json`
   296→- Required for delete operations
   297→- Thread-safe with mutex locks
   298→
   299→### 5. Workspace Sync → AnyType Server (gRPC)
   300→- Connects to `127.0.0.1:31010`
   301→- Uses session token from `~/.anytype/config.json`
   302→- RPC methods: `ObjectCreate`, `ObjectListDelete`, `WorkspaceOpen`
   303→
   304→### 6. AnyType Server → Space (Sync)
   305→- `anytype serve` maintains connection to self-hosted network
   306→- Syncs objects to coordinator, consensus, and file nodes
   307→- Handles network-level replication
