     2→
     3→An MCP (Model Context Protocol) server that exposes [Safecast](https://safecast.org) radiation monitoring data to AI assistants like Claude. The server provides 15 tools for querying both real-time sensor readings and historical radiation measurements, browsing sensor tracks, spectroscopy data, analytics, and educational reference data.

    35→## Real-time Data Access
    36→
    37→The Safecast MCP server provides access to real-time radiation data from fixed sensors (Pointcast, Solarcast, bGeigieZen, etc.) through dedicated tools. These tools query the `realtime_measurements` table in the PostgreSQL database to retrieve the most current readings from active sensors.
    38→
    39→### Real-time Tools
    40→- `list_sensors`: Discover active fixed sensors by location or type
    41→- `sensor_current`: Get the latest reading(s) from specific sensors or geographic areas
    42→- `sensor_history`: Pull time-series data from fixed sensors over date ranges
    43→- `device_history`: Access both historical bGeigie data and real-time sensor data for a specific device
    44→
    45→> **Note**: Real-time data tools require a database connection to access the `realtime_measurements` table. These tools will fall back to the Safecast REST API if no database is configured.

     5→## Problem
     6→
     7→- Opening the SSE stream at `/sse` worked and returned a session ID
     8→- POSTing MCP messages (`initialize`, `tools/list`, `tools/call`) returned **404 page not found**
     9→
    10→## Root Cause
    11→
    12→In `cmd/mcp-server/main.go`, the SSE server was mounted incorrectly:
    13→
    14→```go
    15→http.Handle("/sse/", http.StripPrefix("/sse", sseServer))
    16→```
    17→
    18→The `mcp-go` library's `SSEServer.ServeHTTP` routes internally using exact path matching:
    19→- `GET /sse` -> SSE stream handler
    20→- `POST /message` -> message handler
    21→
    22→With `StripPrefix("/sse", ...)`, when a client hit `GET /sse/sse`, the prefix was stripped and the handler saw `/sse` — so the SSE stream worked.     23→

    25→
    26→Replaced the manual mux registration with `sseServer.Start()`, which sets the SSEServer as the root HTTP handler for both endpoints:
    27→
    28→```go
    29→// Before (broken)
    30→sseServer := server.NewSSEServer(mcpServer)
    31→http.Handle("/sse/", http.StripPrefix("/sse", sseServer))
    32→http.ListenAndServe(":3333", nil)
    33→
    34→// After (fixed)
    35→sseServer := server.NewSSEServer(mcpServer,
    36→    server.WithBaseURL("http://localhost:3333"),
    37→)
    38→sseServer.Start(":3333")
    39→```

   101→  - Attach Postgres with the postgres extension.

   105→### 4.2 What to watch for
   106→
   107→- **PostGIS types:** DuckDB’s postgres extension can read geometry as raw bytes or as a supported type depending on version. For complex spatial analytics you might:
   108→  - Do spatial filters in Postgres (e.g. create a materialized view or a table with pre-filtered rows) and then aggregate in DuckDB, or
   109→  - Export filtered subsets to Parquet and run spatial work in DuckDB’s spatial extension, or
   110→  - Keep heavy spatial queries in Postgres and use DuckDB for non-spatial aggregations (counts, time series, device stats).
   111→- **Volume:** For very large scans, consider periodic exports (e.g. nightly) of aggregated or filtered data to Parquet and point DuckDB at Parquet for the heaviest reports, to avoid long-running connections to Postgres.
