The `active()` method is defined in `Activatable.hpp` and is inherited by `GpsConnector` through `Worker → Activatable`. It's used dozens of places in the codebase with `GpsConnector` — the IDE diagnostic is a false positive (the language server is confused, not the compiler).

The change is correct. The fix mirrors the existing geiger counter grace period pattern exactly:

```cpp
// Before (no grace period):
if (required_gps && !workers.worker<GpsConnector>(k_worker_gps_connector)->active())

// After (15s grace period, matching M7 NMEA scan time):
if (required_gps && millis() > 15000 && !workers.worker<GpsConnector>(k_worker_gps_connector)->active())
```

The M7 baud-rate scan takes ~11-12s before detecting NMEA-only mode, so the 15-second grace period suppresses the false boot-time error while still catching genuine GPS hardware failures shortly after.
