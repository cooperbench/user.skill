     2→
     3→**Date:** 2026-02-08
     4→**Status:** 🗄️ ARCHIVED - Historical reference only
     5→
     6→> **Note**: This document describes the SSE server debugging process from February 2026. The implementation details may have evolved since then. For current architecture, see [README.md](README.md).
     7→
     8→## Problem
     9→
    10→- Opening the SSE stream at `/sse` worked and returned a session ID
    11→- POSTing MCP messages (`initialize`, `tools/list`, `tools/call`) returned **404 page not found**
    12→
    13→## Root Cause
    14→
    15→In `cmd/mcp-server/main.go`, the SSE server was mounted incorrectly:
    16→
    17→```go
    18→http.Handle("/sse/", http.StripPrefix("/sse", sseServer))
    19→```
    20→
    21→The `mcp-go` library's `SSEServer.ServeHTTP` routes internally using exact path matching:
    22→- `GET /sse` -> SSE stream handler
    23→- `POST /message` -> message handler
    24→
    25→With `StripPrefix("/sse", ...)`, when a client hit `GET /sse/sse`, the prefix was stripped and the handler saw `/sse` — so the SSE stream worked. But the message endpoint URL sent back to the client was `/message?sessionId=...` (no `/sse` prefix), which didn't match any route on the default mux, resulting in a 404.

   500→## Phase 7: Migration of Existing Data
   501→
   502→### 7.1 Migration Steps
   503→
   504→1. **Set up the Patroni cluster** with an empty database (Phases 1–4).
   505→2. **Stop writes** to the source database (schedule maintenance window).
   506→3. **Dump the source database:**
   507→   ```bash
   508→   pg_dump -h old-server -U postgres -Fc -j 4 mydb > mydb.dump
   509→   ```
   510→4. **Restore to the Patroni primary:**
   511→   ```bash
   512→   pg_restore -h haproxy-host -p 5000 -U admin -d mydb -j 4 mydb.dump
   513→   ```
   514→5. **Verify** data integrity and replication lag on all nodes.
   515→6. **Switch application** connection strings to HAProxy endpoints.
   516→
   517→> For 100GB, expect the dump/restore to take approximately 30–60 minutes depending on hardware and data complexity.
   518→
   519→### 7.2 Minimal Downtime Alternative
   520→
   521→Use **logical replication** to migrate with near-zero downtime:
   522→
   523→1. Set up the Patroni cluster.
   524→2. Configure logical replication from old server → Patroni primary.
   525→3. Let it sync fully.
   526→4. Switch application connections.
   527→5. Drop logical replication.

     1→# MCP Server Plan for Safecast Map
     2→
     3→## Overview
     4→
     5→An MCP (Model Context Protocol) server that allows AI assistants (Claude, etc.) to query the Safecast radiation map data through structured tools. Users chatting with an AI can ask questions like "What's the radiation level near Fukushima?" and the AI will call MCP tools to get real answers from the database.
     6→
     7→**No authentication required** - all tools are read-only queries against public data.
     8→
     9→---
    10→
    11→## Architecture
    12→
    13→### Recommended: Standalone MCP Server
    14→
    15→A separate Go binary that connects to the same PostgreSQL database and exposes MCP tools over `stdio` or `SSE` transport. Keeps concerns separated and can be deployed independently.
    16→
    17→```
    18→┌──────────────┐     ┌──────────────┐     ┌────────────┐
    19→│  AI Client   │────▶│  MCP Server  │────▶│ PostgreSQL │
    20→│  (Claude)    │◀────│  (Go binary) │◀────│  Database  │
    21→└──────────────┘     └──────────────┘     └────────────┘
    22→                      Uses pkg/database/
    23→```
    24→
    25→### Alternative: Embedded in Existing Server
    26→
    27→Add MCP endpoints alongside the existing HTTP API. Simpler deployment but couples the MCP protocol to the map server.
    28→
    29→---
    30→
    31→## Tools to Expose
    32→
    33→### 1. `query_radiation` - Query radiation levels near a location
    34→
    35→- **Description:** Find radiation measurements near a geographic location
    36→- **Inputs:**
    37→  - `lat` (float, required) - Latitude
    38→  - `lon` (float, required) - Longitude
    39→  - `radius_m` (int, optional, default 1500, range 25-50000) - Search radius in meters
    40→  - `limit` (int, optional, default 25, max 200) - Maximum results
    41→- **Returns:** Nearest measurements with dose rates (µSv/h), count rates (CPS), dates, detector info, coordinates
    42→- **Maps to:** Existing `StreamLatestMarkersNear()` database method
    43→
    44→### 2. `get_track` - Get measurements from a specific track
    45→
    46→- **Description:** Retrieve all radiation measurements recorded during a specific track/journey
    47→- **Inputs:**
    48→  - `track_id` (string, required) - Track identifier
    49→  - `from` (int, optional) - Start marker ID for pagination
    50→  - `to` (int, optional) - End marker ID for pagination
    51→- **Returns:** All markers in the track with dose rates, coordinates, timestamps, detector info, speed, altitude
    52→- **Maps to:** Existing track query + `StreamMarkersInRange()`
    53→
    54→### 3. `list_tracks` - Browse available tracks
    55→
    56→- **Description:** List available radiation measurement tracks, optionally filtered by date
    57→- **Inputs:**
    58→  - `year` (int, optional) - Filter by year
    59→  - `month` (int, optional) - Filter by month (requires year)
    60→  - `limit` (int, optional, default 50) - Maximum results
    61→- **Returns:** Track summaries with track ID, marker count, date ranges, API URLs
    62→- **Maps to:** `StreamTrackSummaries()` and date-range variants
    63→
    64→### 4. `get_spectrum` - Get gamma spectroscopy data
    65→
    66→- **Description:** Retrieve gamma spectrum data for a specific measurement point
    67→- **Inputs:**
    68→  - `marker_id` (int, required) - Marker identifier
    69→- **Returns:** Channel data array, energy range (keV), calibration coefficients, live/real time, device model, source format
    70→- **Maps to:** `GetSpectrum()`
    71→
    72→### 5. `search_area` - Search for measurements in a bounding box
    73→
    74→- **Description:** Find radiation measurements within a geographic bounding box
    75→- **Inputs:**
    76→  - `min_lat` (float, required) - Southern boundary
    77→  - `max_lat` (float, required) - Northern boundary
    78→  - `min_lon` (float, required) - Western boundary
    79→  - `max_lon` (float, required) - Eastern boundary
    80→  - `limit` (int, optional, default 100, max 200) - Maximum results
    81→- **Returns:** Markers within the bounding box with full metadata
    82→- **Maps to:** Existing `get_markers` tile query logic
    83→
    84→### 6. `radiation_info` - General radiation reference information
    85→
    86→- **Description:** Get reference information about radiation units, safety levels, and terminology
    87→- **Inputs:**
    88→  - `topic` (string, required) - One of: `units`, `dose_rates`, `safety_levels`, `detectors`, `background_levels`, `isotopes`
    89→- **Returns:** Static reference content about radiation science
    90→- **Implementation:** Hardcoded reference content (no database query needed)
    91→

    93→
    94→- **Description:** Get historical measurements from a specific monitoring device
    95→- **Inputs:**
    96→  - `device_id` (string, required) - Device identifier
    97→  - `days` (int, optional, default 30) - Number of days of history
    98→- **Returns:** Historical measurements with values, units, coordinates, timestamps
    99→- **Maps to:** `realtime_measurements` table queries

   125→## Implementation Details

   127→### MCP SDK
   128→
