What is this `COMPONENT_NAMED_ADAPTER_TEST_FILES` in the @xtask/src/lint.rs ?

> AGENT

It's a small allowlist used by the adapter-parity lint to recognize integration test files that don't follow the canonical `test_{component}_*.rs` naming. **How it's used** (`xtask/src/lint.rs:412-421`): ```rust let files = collect_files(dir, |path| { path.file_name() .and_then(|name| name.to_str()) .is_some_and(|name| { (name.starts_with("test_") && name.ends_with(".rs")) || COMPONENT_NAMED_ADAPTER_TEST_FILES .iter() .any(|component| name == format!("{component}.rs")) }) })?; ``` `check_adapter_parity` counts `#[test]` / `#[wasm_bindgen_test]` functions per component in both `crates/ars-leptos/tests/` and `crates/ars-dioxus/tests/`, then asserts the two sides stay within a tolerance. It needs to know *which* `.rs` files to include. The canonical naming is `test_{component}_{whatever}.rs`, but older suites in this workspace landed as plain `{component}.rs` (e.g. `tests/separator.rs`, `tests/visually_hidden.rs`, `tests/heading.rs`, `tests/highlight.rs`, `tests/landmark.rs`). Rather than silently treating those zero-test files (which would trigger a parity failure on otherwise-tested components), they're explicitly admitted by name. The comment on `lint.rs:14-15` calls this out: > `// Component-named adapter integration tests admitted while older adapter suites migrate toward the canonical test_{component}_*.rs parity naming pattern.` So it's a transitional allowlist — entries should be removed as suites are renamed to the canonical `test_*.rs` pattern. I added `heading`, `highlight`, and `landmark` here during the recent adapter work (the previous summary noted that), because those tests landed as `tests/heading.rs` etc. Once those are renamed to `test_heading_*.rs`, the entries can be dropped. There's a regression test at `lint.rs:1128-1159` (`adapter_parity_counts_component_named_integration_tests`) that pins the behavior.
