The trait object slot is actually `dyn for<'a> Fn(&'a CalendarDate) -> bool + Send + Sync` (HRTB elision), and there's no constructor in `Callback`'s public surface that accepts a higher-ranked closure over a reference argument — the `Arc` field is `pub(crate)`, so we can't fall through to raw `Arc::new` from outside `ars-core` either. There's no current user of `Callback<dyn Fn(&T) ...>` in the workspace, so it's an unproven path. Two ways to enable it: 1. **Extend `Callback` in ars-core** with a sibling constructor: ```rust impl<T: ?Sized + 'static, Out: 'static> Callback<dyn for<'a> Fn(&'a T) -> Out + Send + Sync> { pub fn new_ref(f: impl for<'a> Fn(&'a T) -> Out + Send + Sync + 'static) -> Self { Self(Arc::new(f)) } } ``` Small, additive change. After that, `Calendar` (and any future component with predicate Props) can drop the manual `PartialEq` + accept closures with captured state. 2. **Keep `fn` pointer** — the trade-off I already wrote up in the spec/code.
