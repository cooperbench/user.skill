223	### Read-Backup-Modify-Write Pattern
224	
225	Every campaign step MUST follow this sequence when modifying state:
226	
227	1. **Read** `_campaign-state.yaml`
228	2. **Validate** against `assets/campaign-state-schema.json` (halt on invalid)
229	3. **Backup** — copy current `_campaign-state.yaml` → `_campaign-state.yaml.bak`
230	4. **Modify** in memory
231	5. **Update** `campaign.last_updated` to current ISO-8601 timestamp
232	6. **Write** modified state back to `_campaign-state.yaml`
233	
234	The `.bak` file is one-deep (overwritten on every write). If the primary file is corrupted (crash during write), the `.bak` file contains the last valid state.
235	
236	For testability: the test suite implements this pattern with `shutil.copy2` + YAML write, validating `.bak` content matches the pre-modification state.
