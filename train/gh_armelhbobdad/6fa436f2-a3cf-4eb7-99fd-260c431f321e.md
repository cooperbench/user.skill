### 2. **Best-Practices-for-Creating-Agent-Skills.md - Main Principles**

**Discoverability Optimization:**
- Name and description are the ONLY metadata agents see before triggering a skill
- Write "trigger-optimized descriptions" with negative triggers (what NOT to use it for)
- Avoid vague descriptions; be domain-specific

- SKILL.md as the "brain" for high-level logic and navigation
- Use flat subdirectories exactly one level deep (e.g., `references/schema.md` not `references/db/v1/schema.md`)

**Procedural Instructions for LLMs:**
- Step-by-step numbering with decision trees mapped out
- Provide concrete templates in `assets/` instead of prose descriptions
- Write in third-person imperative (e.g., "Extract the text..." not "I will extract...")
- Use consistent, specific terminology throughout

**Anti-Patterns (What NOT to create):**
- Documentation files (README.md, CHANGELOG.md, INSTALLATION_GUIDE.md)
- Redundant logic the agent already handles
- Library code (skills reference existing tools, not bundle large libraries)

**Validation Strategy:**
- Discovery Validation: Test if description triggers the skill correctly
- Logic Validation: Ensure step-by-step instructions are deterministic
- Edge Case Testing: Force LLM to identify vulnerabilities and failure states
- Architecture Refinement: Enforce progressive disclosure, shrink token footprint

**Three-Phase Model:**

1. **Discovery Phase**: Load only `name` and `description` at startup for all skills (~100 tokens)

**Self-Documenting Design:**
- Skills are readable and auditable by humans and agents
- Format ranges from text-only to executable code + assets + templates
- Portable: just files, easy to version and share
