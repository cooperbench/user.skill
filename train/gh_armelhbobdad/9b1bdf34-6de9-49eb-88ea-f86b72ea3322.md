53	| QS | TS | skill name (from `repo_name`) | Forger passes the quick-skill's output name to TS |
54	| QS | EX | skill name | Same |
55	| AS | US | skill name + drift severity | Forger checks `summary.severity` in `audit-skill-result-latest.json`; if CLEAN, skips US |
56	| VS | RA | architecture doc path | Already known from VS invocation |
57	
58	## Circuit Breakers
59	
60	Circuit breakers halt the pipeline when a workflow's output doesn't meet a quality threshold:
61	
62	| Workflow | Check | Default Threshold | Halt Condition |
63	|----------|-------|-------------------|----------------|
64	| AN | recommended units count | min: 1 | Zero skillable units found |
65	| CS | compilation success | must complete | Hard error during compilation |
66	| TS | completeness score | min: 60 (per-pipeline defaults apply — see init.md §1b) | Score below threshold |
67	| AS | drift score | not CRITICAL | Critical drift found |
68	| VS | feasibility verdict | not BLOCKED | All integrations blocked |
69	
70	Override syntax: `TS[min:80]` sets the test-skill threshold to 80 for this pipeline run.
71	
72	### Bracket Syntax
73	
74	Brackets after a workflow code (`CODE[value]`) are parsed as follows:
75	
76	- **Circuit breaker override**: `min:N` where N is a number — e.g., `TS[min:80]` sets the threshold for that workflow
77	- **Mode flag**: `auto` — e.g., `AN[auto]` activates auto mode for that workflow. The workflow's first step reads the flag from pipeline data context and routes to the appropriate auto-mode step file.
78	- **Target argument**: any other value — e.g., `CS[cocoindex]` passes "cocoindex" as the target to CS
79	
80	Only workflows with a circuit breaker entry (AN, CS, TS, AS, VS) accept `min:N` overrides. All other workflows ignore `min:N` brackets. Target arguments are valid for any workflow that accepts a named input (CS, QS, BS, US, etc.).
81	
82	## Pipeline State
83	
84	The forger tracks pipeline state in memory during execution:
85	
86	```yaml
87	pipeline:
88	  alias: "forge"          # pipeline alias name, or null for ad-hoc sequences
89	  workflows: [AN, CS, TS, EX]
90	  current_index: 1
91	  completed:
92	    - {code: AN, status: ok, output: {units: 3, briefs: [...]}}
93	  pending: [CS, TS, EX]
94	  data:
95	    pipeline_alias: "forge" # forwarded to each workflow's data context (consumed by TS init.md §1b for per-pipeline threshold lookup)
96	    skill_name: "cocoindex"
97	    brief_path: "/path/to/skill-brief.yaml"
98	    target: "cocoindex"
99	```

101	## Anti-Patterns
102	
103	The forger validates the pipeline sequence and warns about:
104	
105	| Pattern | Issue | Suggestion |
106	|---------|-------|------------|
107	| EX before TS | Exporting untested skill | Add TS before EX |
108	| US without AS | Updating without audit | Run AS first to detect what changed |
109	| CS without BS or AN | Compiling without brief | Need a brief — use QS for quick path, or AN for brownfield |
110	| TS after EX | Testing after export | Move TS before EX |
111	| Duplicate codes | Same workflow twice | Remove duplicate |
