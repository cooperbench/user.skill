137	The export manifest gains version awareness:

139	```json

162	**Fields:**
163	- `schema_version`: `"2"` — enables v1-to-v2 migration detection
164	- `active_version`: The version whose `{skill_package}` supplies the context snippet for the managed section. Must match exactly one version with `status: "active"`
165	- `versions.{v}.status`: `"active"` (currently exported), `"archived"` (previously exported, retained on disk), `"deprecated"` (dropped via drop-skill workflow, excluded from all exports), `"draft"` (created but never exported)
166	- `versions.{v}.ides`: Array of IDE identifiers from `config.yaml.ides` whose context file this version was last exported to (e.g. `["claude-code", "cursor"]`). 167	- `versions.{v}.last_exported`: ISO date of the last export
168	
169	**Only one version per skill can have `status: "active"` at any time.**

171	## Skill Management Operations
172	
173	Two workflows operate on the version-aware structure for skill lifecycle management:
174	
175	### Rename (RS - Rename Skill)
176	
177	Renames a skill across all versions. Because the agentskills.io spec requires `name` to match parent directory name, a rename is a coordinated move across:
178	1. Outer `{skill_group}` directory: `{skills_output_folder}/{old-name}/` → `{skills_output_folder}/{new-name}/`
179	2. Inner `{skill-name}/` directories inside each version: `{version}/{old-name}/` → `{version}/{new-name}/`
180	3. `SKILL.md` frontmatter `name:` field (in every version)
181	4. `metadata.json` `name` field (in every version)
182	5. `context-snippet.md` root paths and display name (in every version)
183	6. `provenance-map.json` `skill_name` field (in every version under `{forge_group}`)
184	7. `{forge_group}` directory: `{forge_data_folder}/{old-name}/` → `{forge_data_folder}/{new-name}/`
185	8. Export manifest: remove old key, add new key with same version data
186	9. Platform context files (CLAUDE.md, AGENTS.md, .cursorrules): rebuild managed sections
187	
188	Rename is transactional — copy-verify-delete pattern. If any step fails, old skill remains intact. See `skf-rename-skill/`.
189	
190	### Drop (DS - Drop Skill)
191	
192	Drops a specific version or the entire skill with two modes:
193	
194	**Soft drop (default):** Sets version status to `"deprecated"` in the export manifest. Files remain on disk. Export-skill excludes deprecated versions from all platform context files. Reversible by manually editing manifest back to `"active"`/`"archived"`.
195	
196	**Hard drop (`--purge`):** Same as soft drop, plus deletes the version directory (`{skill_package}`) and forge data directory (`{forge_version}`). Irreversible.
197	
198	**Active version guard:** Cannot drop the active version when other versions exist. The user must either switch active to another version first, or drop all versions at once.
199	
200	**Skill-level drop:** Removes the entire `{skill_group}` from the manifest. If purge, also deletes `{skill_group}` and `{forge_group}` directories.
201	
202	See `skf-drop-skill/`.

205	
206	Directory names use the semver version with `+{build}` metadata stripped:

208	| Source Version | Directory Name | Rule |

213	| `2.0.0+20260404` | `2.0.0` | Build metadata stripped |
214	
215	Build metadata does not affect version precedence per the semver specification and is stripped to avoid filesystem issues with the `+` character.
