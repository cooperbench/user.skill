### 🔬 Dr. Quinn (Problem Solver):

"AHA! Let me apply the magnifying glass to the **root causes**, not just symptoms.

**Issue-02 + Issue-06 are the SAME root cause.** Both are ast-grep v0.41.x behavioral issues with TSX. Issue-02 documents that `export function` pattern fails in TSX. Issue-06 documents that `--json=stream` fails. But look at Issue-06's reproduction steps — they test with `export function` patterns! The streaming failure may be a **consequence** of the pattern failure, not a separate bug. We need to separate: does `--json=stream` fail for ALL patterns in TSX, or only for `export function`?

**Critical missing regression from fixing Issue-01:** If we change `--top` to `--limit` in the CLI templates, we need to verify the **actual CCC help output** shown in Issue-01 is correct. The issue says `--path TEXT Filter by file path glob` — wait, if `--path` IS a valid flag but just means something different (file path glob filter, not project directory), then **ccc-bridge.md's `search()` signature is semantically wrong**. The operation signature says `search(query, path?, top_k?)` where `path` implies a project directory. But the real `--path` flag is a file filter within the already-indexed directory. This is an **API design mismatch** in the bridge abstraction itself.

**Issue-05 (QMD version):** The TODO only covers step-05-compile, but `tool_versions` also appears in the **evidence-report** (step-05 section 7). If we add a QMD resolution chain, both sections need it. Also — the `skf_version` resolution chain is well-documented but the `ast_grep_version` resolution is not documented at all. How is `tool_versions.ast_grep` currently resolved? I'd wager it's **also guessed**.

**Hidden bug not in any TODO:** In extraction-patterns.md, the CLI streaming fallback template (line 184) uses `ast-grep -p '{pattern}'` — but earlier in the Decision Tree (line 133), it says `CLI streaming fallback: ast-grep --json=stream`. The actual command should be `ast-grep run -p '{pattern}' --json=stream` — the `run` subcommand is missing in the template. The `-p` flag implies `run`, but `--json=stream` may require explicit `run` subcommand."

### 🏗️ Morgan (Module Builder):

"Let me evaluate the **cross-module and architectural impacts**.

**Proposal-01 (Component Library):** This is the biggest item and the TODO correctly scopes it as non-breaking, but I see a **schema versioning risk**. Adding `scope.type: "component-library"` to the brief schema means existing briefs created before this change work fine — but if someone creates a component-library brief and then downgrades SKF, the brief becomes invalid. We need a `min_skf_version` field in the brief schema or a graceful unknown-scope-type handler.

**Cross-workflow contamination from Issue-01 fix:** The `ccc_bridge` resolution in tool-resolution.md is consumed by:
1. `create-skill` (steps 02b, 03)
2. `update-skill` (re-extraction)  
3. `create-stack-skill` (integration detection)
4. `setup-forge` (step-01b indexing)

Fixing the CLI column in tool-resolution.md fixes ALL consumers. But we need to verify that **setup-forge step-01b** also uses the correct `ccc init` syntax — that step does the initial indexing.

**Missing regression from Issue-03 fix:** If we add `cd {project-root}` before cleanup, and the project root was a relative path in context, the `cd` could fail. The cleanup protocol should use an absolute path captured at clone time.

**Systemic issue not in any TODO:** The extraction-patterns.md YAML Rule Recipes section has JS/TS patterns using `language: typescript` — but Issue-02 revealed that TSX files need `language: tsx`. The recipes don't document when to use `typescript` vs `tsx` vs `javascript`. An agent following these recipes on a React codebase would use `typescript` and potentially miss all JSX-containing files. This is a **documentation gap** separate from the ast-grep bug."
