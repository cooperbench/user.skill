# UnifiedPush Android Specification Technical Summary

## Core Architecture

UnifiedPush Android (AND_3.1.0) establishes a three-party push notification system: end user applications (connectors), push distributors, and push servers. The specification defines how these components interact through broadcast intents and services.

## Registration Process

Applications initiate registration by requesting a deep link `unifiedpush://link` to select a distributor. During registration, the app generates a unique connection token and optionally provides a VAPID public key. The spec states: *"This token must contain sufficient entropy so it cannot be guessed. To generate this token, UUIDv4 is suggested."*

The distributor responds with `org.unifiedpush.android.connector.NEW_ENDPOINT`, delivering the push endpoint URL. Applications must acknowledge receipt via `org.unifiedpush.android.distributor.MESSAGE_ACK`.

## Key Technical Components

**Connection Token**: Maximum 100 bytes, generated by the connector using UUIDv4, uniquely identifies registrations per distributor.

**VAPID Public Key**: Precisely *"a public key on the P-256 curve encoded in the uncompressed form SEC 1 (section 2.3.3), and base64url encoded. This is a 87 bytes long string."*

**Push Messages**: Encrypted payloads between 1-4096 bytes following RFC8291, with cleartext content limited to 3993 bytes maximum.

**Endpoints**: URLs up to 1000 bytes with *"enough random entropy to ensure it is difficult to successfully guess a valid URL. We recommend using a 160 bits (20 bytes) random value URL-safe base64 encoded string."*

## Message Flow

Distributors forward encrypted push messages via `org.unifiedpush.android.connector.MESSAGE`, sending the raw POST data received from push servers. The specification requires distributors to *"raise the application to the foreground importance for 5 seconds when sending this intent,"* achievable through system privileges or binding to the app's foreground service.

## FCM Compatibility

The specification makes no explicit reference to Firebase Cloud Messaging (FCM). UnifiedPush operates as a decentralized alternative, supporting any push server implementing RFC8030.

## Error Handling

Registration failures return `org.unifiedpush.android.connector.REGISTRATION_FAILED` with reasons: INTERNAL_ERROR, NETWORK, ACTION_REQUIRED, or VAPID_REQUIRED—enabling apps to implement appropriate retry logic.
