> AGENT

Here's how it works: 1. **The Android app sends a `verifyUrl` template** (RFC 6570 URI Template) in the GraphQL mutation — currently `hackerspub://verify?token={token}&code={code}` 2. **The server expands it** with `parseTemplate(verifyUrlTemplate).expand({ token, code })` — replacing `{token}` and `{code}` with real values 3. **The server validates** the scheme is one of `https:`, `http:`, or `hackerspub:` 4. **The expanded URL goes into the email** as both plain text and a clickable `<a href>` link So the flow is entirely controlled by what template the app sends. The `hackerspub://` scheme works for direct app opening.
