### 4. **Recommended Actors Algorithm**

**Implementation File:** `/Users/kodingwarrior/fediverse/hackerspub/models/actor.ts` (lines 498-609)

**Function Signature:**
```typescript
export async function recommendActors(
  db: Database,
  { mainLocale, locales, account, limit }: RecommendActorsOptions = {},
): Promise<(Actor & { account?: Account | null })[]>
```

**Algorithm Details:**

The recommendation system uses a multi-factor scoring model:

1. **Filters Applied:**
   - Only recommends actors with type = "Person"
   - Filters by language(s) - matches posts in user's locale(s)
   - Excludes the current user's account
   - Excludes actors already followed by the current user
   - Excludes local actors (those with accountId != null) if viewing unauthenticated

2. **Scoring Metrics (normalized with sigmoid-like dampening):**
   - **Reactions Count:** `reactionsCount / (reactionsCount + 15.0)` - weights popularity
   - **Replies Count:** `repliesCount / (repliesCount + 5.0)` - engages conversations
   - **Shares Count:** `sharesCount / (sharesCount + 10.0)` - measures influence
   - **Followers Count:** `followersCount / (followersCount + 50.0)` - considers established reputation
   - **Network Effects (Friends-of-Friends):** `followersCount / (followersCount + 5.0) * 5` (multiplied 5x) - recommends connections of followed accounts
   - **Language Match:** `postsCount / (postsCount + 15.0) * 5` (multiplied 5x) - prioritizes posts in user's language
   - **Local Status:** `local * 5` (multiplied 5x) - heavily boosts local (server-native) actors

3. **Database Implementation:**
   - Uses CTEs (Common Table Expressions) for query optimization
   - Two CTEs: "stats" for actor engagement metrics and "follows" for friend-of-friend connections
   - Orders by combined scoring formula descending
   - Returns sorted by original query order

5. **Follow action automatically removes the actor from recommendations.** When a user follows an actor, that actor is removed from the buffer and display, same as dismissing. The `seenActorIds` set ensures they won't reappear in subsequent fetches during this session.
