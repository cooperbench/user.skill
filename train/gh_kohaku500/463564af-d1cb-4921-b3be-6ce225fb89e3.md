107	JIS B 2704は、金属材料の円形断面線材を用いたコイルばねの基本計算方法を規定したJIS規格です。
108	2018年に改訂され、現在は以下の3部構成です:

111	- **JIS B 2704-2:2018** 仕様書の書き方

118	## 圧縮コイルばねの基本計算式
119	
120	### ばね定数 k
121	
122	```
123	k = G × d⁴ / (8 × D³ × Na)
124	```
125	
126	- `G`: 横弾性係数 [MPa]
127	- `d`: 線径 [mm]
128	- `D`: コイル平均径 [mm]
129	- `Na`: 有効巻数
130	
131	### ねじり応力 τ
132	
133	```
134	τ = Kw × (8 × P × D) / (π × d³)
135	```
136	
137	Kwはワール応力修正係数:
138	```
139	Kw = (4C - 1) / (4C - 4) + 0.615 / C
140	C = D / d  (ばね指数)
141	```
142	
143	### たわみ δ
144	
145	```
146	δ = P / k
147	```
148

509	### JIS B 2704 計算ロジック（JavaScript実装）
510	
511	```javascript
512	// JIS B 2704 計算定数
513	const MATERIALS = {
514	  'SWP-A':      { G: 78500, name: 'ピアノ線 SWP-A' },
515	  'SW-B':       { G: 78500, name: 'ばね用炭素鋼線 SW-B' },
516	  'SW-C':       { G: 78500, name: 'ばね用炭素鋼線 SW-C' },
517	  'SWO-A':      { G: 78500, name: 'オイルテンパー線 SWO-A' },
518	  'SWOSC-B':    { G: 78500, name: 'シリコンクロム鋼線 SWOSC-B' },
519	  'SUS304-WPB': { G: 68500, name: 'ステンレスばね鋼線 SUS304-WPB' }
520	};
521	
522	/**
523	 * JIS B 2704 コイルばね計算
524	 * @param {number} d   - 線径 [mm]
525	 * @param {number} D   - コイル平均径 [mm]
526	 * @param {number} Na  - 有効巻数
527	 * @param {number} P   - 荷重 [N]
528	 * @param {string} mat - 材料キー
529	 * @returns {Object}   - 計算結果
530	 */
531	function calcSpring(d, D, Na, P, mat) {
532	  const G = MATERIALS[mat].G;
533	
534	  const C  = D / d;                                       // ばね指数
535	  const Kw = (4*C - 1) / (4*C - 4) + 0.615 / C;         // Wahl応力修正係数
536	  const k  = G * d**4 / (8 * D**3 * Na);                 // ばね定数 [N/mm]
537	  const delta = P / k;                                    // たわみ [mm]
538	  const tau   = 8 * P * D * Kw / (Math.PI * d**3);       // ねじり応力 [MPa]
539	  const Lc    = (Na + 2) * d;                             // 密着高さ [mm]
540	
541	  return { C, Kw, k, delta, tau, Lc };
542	}
543	
544	// 安全判定（JIS B 2704 推奨範囲）
545	function safetyCheck(C, tau, sigmab) {
546	  const ratio = tau / sigmab;
547	  if (ratio > 0.45)   return { status: 'NG',   label: '応力超過' };
548	  if (C < 4 || C > 14) return { status: 'WARN', label: '指数注意' };
549	  return { status: 'OK', label: '安全' };
550	}
551	```
552

1272	# 17年間Excelでばね計算してきた設計エンジニアが、スマホアプリを自作した理由
1273	
1274	## 壊れたExcelと、引き継いだ「呪い」
1275	
1276	入社2年目のとき、先輩から引き継いだExcelファイルがあった。
1277	
1278	圧縮コイルばねの設計計算シート。セルが色分けされていて、一見きれいにできていた。でも、数式の入ったセルをうっかり触ると参照エラーが飛び出してくる。どの式がどこと繋がっているのか、もはや作った本人にしかわからない状態だった。
1279	
1280	「直し方を教えてください」と聞いたら、先輩は苦笑いしながら言った。「正直、俺も全部はわかってない。動いてるときに触らないのが正解」
1281	
1282	それが、私の設計者人生の出発点だった。
1283	
1284	---
1285	
1286	## 17年かけて気づいたこと
1287	
1288	機械設計の現場では、ばねの計算は「日常業務」だ。圧縮ばね、引張ばね、ねじりばね——形は違っても、基本の計算式は変わらない。JIS B 2704という規格に全部書いてある。
1289	
1290	でも現場の道具は、なぜかいつも不完全だった。
1291	
1292	- Excelシートは属人化していて、バージョンが上がるたびに壊れる
1293	- Webアプリは便利だが、工場の中はWi-Fiが届かないことがある
1294	- スマホアプリを探しても、JIS準拠を謳っているものがほとんどない
1295	
1296	17年間、ずっと「なんかいい方法ないかな」と思いながら仕事してきた。
1297	
1298	答えは出なかった。だから自分で作ることにした。
1299	
1300	---

1302	## 個人開発を始めた日
1303	
1304	きっかけは、工場の現場で計算し直しが必要になった瞬間だった。
1305	
1306	試作品のばねを組み付けてみたら、たわみ量が設計値とずれた。「線径を変えた場合の計算をすぐ確認したい」。でもその場所、Wi-Fiが届かなかった。
1307	
1308	事務所まで戻って、Excelを開いて、入力して、また現場に戻る。往復15分。
1309	
1310	「このロスが年間で何十時間になってるんだろう」と思ったとき、Androidアプリを作ろうと決めた。
1311	
1312	当時、Androidアプリの開発経験はゼロだった。
1313	
1314	---
1315	
1316	## 「計算式」だけでは足りなかった
1317	
1318	最初は「JISの計算式をそのままコードにすれば終わり」と思っていた。
1319	
1320	でも、実際に設計ツールとして使えるものを作ろうとすると、そうはいかない。
1321	
1322	教科書の計算順序は「線径 → コイル径 → 巻数 → 荷重 → 応力チェック」だ。でも現場での設計フローは違う。「取付スペースが決まっている。荷重はこのくらい必要。材料はこれが手配できる。では線径はいくつになるか?」という逆算から始まることが多い。
1323	
1324	UXを設計者の思考フローに合わせる、という作業に一番時間がかかった。
1325	
1326	---
1327	
1328	## JIS規格書を毎回開かなくていい設計にした
1329	
1330	ばねの安全確認には、材料ごとの「引張強さσB」が必要になる。JIS B 2704の附属書に数表がある。
1331	
1332	以前は毎回PDF を開いて、線径の行を探して、材料の列を見て……という作業をしていた。年間で何百回やっただろう。
1333	
1334	SpringSense（これが完成後のアプリ名）では、材料と線径を選ぶだけで自動的にσBが参照され、安全判定まで一発で出るようにした。JIS規格書を開く必要がない。
1335	
1336	これを実装したとき、「これが欲しかったやつだ」と一人で思った。
1337	
1338	---
1339	
1340	## 計算根拠を表示することにこだわった理由
1341	
1342	結果の数字だけを出すアプリは、作るのは簡単だ。
1343	
1344	でも現場では、計算根拠を上司に説明しなければならない場面がある。「この線径で安全な根拠は？」「ばね定数の計算式は？」——Excelのセル参照を口頭で説明するより、式と中間値が全部出ている画面を見せるほうが10倍早い。
1345	
1346	だから、ばね指数C、Wahl係数Kw、ねじり応力τ、τ/σB比……全部の中間値を画面に表示する設計にした。
1347	
1348	若手エンジニアが計算式を覚える教材にもなる、という想いもあった。
1349
