   409→	if err != nil {

   412→
   413→	var gitDir string

   425→			return ""
   426→		}

   428→		if !filepath.IsAbs(gitDir) {
   429→			gitDir = filepath.Join(repoRoot, gitDir)

     1→# Wingman: Automated Code Review
     2→
     3→Wingman is an automated code review system that reviews agent-produced code changes after each commit and delivers actionable suggestions back to the agent.
     4→
     5→## Overview
     6→
     7→When enabled, wingman runs a background review after each commit (or checkpoint), writes suggestions to `.entire/REVIEW.md`, and ensures the agent addresses them. The system prioritizes **visible delivery** — the user should see the agent reading and applying the review in their terminal.
     8→
     9→## Architecture
    10→
    11→### Components
    12→
    13→| Component | File | Purpose |
    14→|-----------|------|---------|

    17→| Review prompt | `wingman_prompt.go` | Builds the review prompt from diff, prompts, context |
    18→| Instruction | `wingman_instruction.md` | Embedded instruction injected into agent context |
    19→| Process spawning | `wingman_spawn_unix.go` | Detached subprocess spawning (Unix) |
    20→| Process spawning | `wingman_spawn_other.go` | No-op stubs (non-Unix) |
    21→| Hook integration | `hooks_claudecode_handlers.go` | Prompt-submit injection, stop hook notifications, session-end trigger |

    25→| File | Purpose |
    26→|------|---------|

    28→| `.entire/wingman-state.json` | Dedup state, session ID, apply tracking |

    30→| `.entire/wingman-payload.json` | Payload passed to detached review process |
    31→| `.entire/logs/wingman.log` | Review process logs (stderr redirect) |

    34→
    35→### Phase 1: Trigger
    36→
    37→A wingman review is triggered after code changes are committed:
    38→

    45→3. Lock file acquired atomically (`acquireWingmanLock()`)
    46→4. File hash dedup — skip if same files were already reviewed this session

    49→

    51→
    52→```
    53→┌─ Detached Process ─────────────────────────────────────┐
    54→│ 1. Read payload from file                              │
    55→│ 2. Wait 10s for agent turn to settle                   │

    60→│ 7. Write REVIEW.md                                     │
    61→│ 8. Save dedup state                                    │

    70→
    71→There are two delivery mechanisms. The system chooses based on whether any session is still alive.

   178→### Diff Strategy
   179→
   180→The diff is computed against the **merge-base** with `main`/`master`, not just the latest commit. This gives the reviewer a holistic view of all branch changes rather than a narrow single-commit diff. Fallback chain:

   185→4. `git diff HEAD~1 HEAD` → latest commit if no uncommitted changes

- **`--setting-sources ""`**: Disables hooks in Claude CLI calls to prevent recursive triggering

- Applied to Claude CLI calls (review and auto-apply), NOT at process spawn time
- Prevents index corruption from Claude Code's internal git operations
- Also strips `CLAUDECODE=` to allow nested Claude CLI invocation
