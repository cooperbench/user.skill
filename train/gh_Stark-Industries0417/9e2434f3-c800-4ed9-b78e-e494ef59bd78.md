To answer your question about **whether we need both `PendingCheckpointID` and `LastCheckpointID`**: **Short answer**: Yes, for now — they serve different lifecycle purposes. - **`PendingCheckpointID`** = "the ID from a commit trailer that hasn't been condensed yet" — set in PostCommit (ACTIVE → ACTIVE_COMMITTED), consumed by `handleTurnEndCondense` at TurnEnd. The critical distinction: if condensation **fails**, `PendingCheckpointID` held the trailer ID (now orphaned), but `LastCheckpointID` correctly remains empty (no data was committed). Merging them would mean setting `LastCheckpointID` eagerly before condensation, which would falsely claim data exists when it doesn't. That said, condensation failure is extremely rare in practice. Unifying into just `LastCheckpointID` (set eagerly, cleared on failure) is a reasonable simplification for a follow-up — just not worth doing in this bug-fix PR.
