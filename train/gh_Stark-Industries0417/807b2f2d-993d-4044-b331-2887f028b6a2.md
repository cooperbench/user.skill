Found it. The bug is in `isOutdated()` at line 225. The issue is that `semver.Compare()` from `golang.org/x/mod/semver` interprets `v0.4.4-76-g230b49bf-dirty` as a **prerelease** of `v0.4.4`. In semver, prereleases sort **before** the release, so: ``` v0.4.4-76-g230b49bf-dirty < v0.4.4 (semver rules) ``` But in `git describe` format, `v0.4.4-76-g230b49bf-dirty` means "76 commits **ahead** of tag v0.4.4" — it's clearly **newer**, not older. The fix is to strip the `git describe` suffix before comparing. The base semver version (`v0.4.4`) is what should be compared against the latest release (`v0.4.4`), and if they're equal, a dev build should never be considered outdated.
