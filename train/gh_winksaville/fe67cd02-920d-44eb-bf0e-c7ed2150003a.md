Right. The shell problems:

- `<>` — redirection operators, always need quoting
- `[]` — glob patterns. `[za]` means "match a file named `z` or `a`". If no file matches, bash passes it through literally (by default), but it's still fragile and surprising
- `""` inside an argument — shell strips them. `linker.args-=["za"]` becomes `linker.args-=[za]`

`{}` dodges all of these. `{name}` is inert — brace expansion only fires with commas (`{a,b}`) or ranges (`{1..3}`).

Thoughts on using parens () instead of square brackets [] on the command line?

> AGENT

Parentheses are worse — they're bash syntax-level constructs (subshells, function definitions, command grouping). `tspec ts set linker.args=(-static)` would be a shell parse error, not just an expansion that might silently change. You can't even get past bash to reach tspec.

- `linker.args+=[-static,-nostdlib]` — brackets pass through as glob (no file matches), tspec bare-fallback handles it
- `linker.args+='["-Wl,--gc-sections","-static"]'` — single-quote when you need embedded commas
