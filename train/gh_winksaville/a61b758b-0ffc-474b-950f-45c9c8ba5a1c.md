     1→# tspec - Translation Spec Build System
     2→
     3→A spec-driven build system for Rust that wraps cargo with configurable target triples, compiler flags, and linker options.
     4→
     5→**Status:** Active development. Works with both workspaces and single-package projects (POPs).
     6→
     7→## Installation
     8→
     9→```bash
    10→cargo install --path .
    11→```
    12→
    13→Or run directly:
    14→```bash
    15→cargo run -- build
    16→```
    17→
    18→## Usage
    19→
    20→```bash
    21→tspec build                                # Build current package (or all in workspace) with tspec.ts.toml if present
    22→tspec build -p myapp                       # Build specific package with tspec.ts.toml if present
    23→tspec build -p myapp -t tspec-opt          # Build with alternative spec tspec-opt.ts.toml
    24→tspec build -p myapp -t tspec-opt.ts.toml  # Build with alternative spec tspec-opt.ts.toml
    25→tspec build -p myapp -r -s                 # Build release, strip symbol with tspec.ts.toml if present
    26→tspec run -p myapp                         # Build and run with tspec.ts.toml if present
    27→tspec test -p myapp                        # Build and test with tspec.ts.toml if present
    28→tspec build -a                             # Build all packages (even from inside a package dir)
    29→tspec compare -p myapp -r                  # Compare all tspec*.ts.toml by binary size
    30→```
    31→
    32→The `-p` flag specifies a package (defaults to current directory if in a package, otherwise all packages).
    33→Use `-a, --all` to force all-packages mode even when inside a package directory.
    34→The `-t` flag selects a tspec file; if omitted and `tspec.ts.toml` exists, it's used automatically.
    35→
    36→## tspec Files
    37→
    38→Translation specs are TOML files (conventionally `*.ts.toml`) that configure builds:
    39→
    40→```toml
    41→# tspec.ts.toml - Example spec
    42→[cargo]
    43→profile = "release"
    44→target_triple = "x86_64-unknown-linux-musl"
    45→
    46→[rustc]
    47→opt_level = "z"
    48→panic = "abort"
    49→lto = true
    50→codegen_units = 1
    51→
    52→[linker]
    53→args = ["-static", "-nostartfiles"]
    54→```
    55→
    56→### Key Concepts
    57→
    58→- **tspec.ts.toml is optional** - Packages without one get plain `cargo build/test`

    62→### How Linker Flags Work
    63→
    64→tspec generates a temporary `build.rs` to apply linker flags with binary-scoped directives:
    65→
    66→```rust
    67→// Generated by tspec - deleted after build
    68→fn main() {
    69→    println!("cargo:rustc-link-arg-bin=myapp=-static");
    70→    println!("cargo:rustc-link-arg-bin=myapp=-nostdlib");
    71→}
    72→```
    73→
    74→This is necessary because RUSTFLAGS affects ALL compilations (including dependency
    75→build scripts), causing crashes with flags like `-nostartfiles`. The generated
    76→build.rs scopes flags to just the binary.

Makes sense — specs should be self-contained so you don't have to remember `-r -s` every time you build with a particular spec.

A few thoughts:

**`release` is already half-there.** The spec has `cargo.profile = "release"`. The `-r` flag is effectively a shorthand for that. You could make `-r` just set `profile = "release"` when the spec doesn't specify a profile, and the spec's `profile` field already handles the "baked into the spec" case. Adding a separate `release = true` boolean would be redundant with the existing `profile` field.

**`strip` has two meanings in the codebase.** There's `rustc.strip = "symbols"` (compiler flag, `-C strip=symbols`) which is already a spec field, and the `-s` CLI flag which runs the external `strip` command post-build. They overlap in effect but aren't identical — the rustc one is lighter-weight and doesn't need a separate tool. Worth deciding whether `-s` should map to the existing `rustc.strip` spec field or be a distinct `cargo.strip = true` for the post-build step.

**Precedence model** (CLI > spec > default) is the right call. It's what cargo does with `--release` overriding profile settings.

So the main question is: do you actually need new spec fields, or just wire `-r` to respect the existing `cargo.profile` and `-s` to respect `rustc.strip`? That might get you what you want without adding anything to the spec format.
