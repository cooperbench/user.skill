# Plan: Add `toolchain` field to translation specs

## Context

When testing packages in rlibc-x that use `-Z build-std` (nightly-only), tspec currently auto-detects the need for nightly and hardcodes `+nightly`. A `toolchain` field lets specs explicitly declare which toolchain to use (e.g., `nightly`, `stable`, `nightly-2025-01-15`, `1.75`), giving users control and making specs self-documenting. When set, it overrides auto-detection; when absent, current behavior is preserved.

```
   318→/// Apply spec parameters to a cargo command.
   319→/// `cli_profile` is the CLI-specified profile (None = debug default).
   320→pub fn apply_spec_to_command(
   321→    cmd: &mut Command,
   322→    spec: &Spec,
   323→    workspace: &Path,
   324→    cli_profile: Option<&str>,
   325→    expanded_target_dir: Option<&str>,
   326→) -> Result<()> {
   327→    // Set custom target directory if specified
   328→    if let Some(td) = expanded_target_dir {
   329→        cmd.arg("--target-dir")
   330→            .arg(workspace.join("target").join(td));
   331→    }
   332→
   333→    // Handle high-level panic mode (cargo -Z flag)
   334→    if let Some(panic_mode) = spec.panic
   335→        && let Some(z_flag) = panic_mode.cargo_z_flag()
   336→    {
   337→        cmd.arg("-Z").arg(z_flag);
   338→    }
   339→
   340→    // Handle cargo config
   341→    let has_profile = spec.cargo.profile.is_some();
   342→    if let Some(ref profile) = spec.cargo.profile {
   343→        match profile.as_str() {
   344→            "debug" | "dev" => {
   345→                // Debug/dev is default, no flag needed
   346→            }
   347→            _ => {
   348→                cmd.arg("--profile").arg(profile);
   349→            }
   350→        }
   351→    }
   352→
   353→    if let Some(ref triple) = spec.cargo.target_triple {
   354→        cmd.arg("--target").arg(triple);
   355→    }
   356→
   357→    if let Some(ref path) = spec.cargo.target_json {
   358→        cmd.arg("-Z").arg("json-target-spec");
   359→        cmd.arg("--target").arg(path);
   360→    }
   361→
   362→    for flag in &spec.cargo.unstable {
   363→        cmd.arg("-Z").arg(flag);
   364→    }
   365→
   366→    // Inject --config key=value pairs (flattened from potentially nested config)
   367→    for (key, value) in flatten_config(&spec.cargo.config) {
   368→        cmd.arg("--config").arg(format!("{}={}", key, value));
   369→    }
   370→
   371→    // If no profile in spec, fall back to CLI profile
   372→    if !has_profile && let Some(p) = cli_profile {
   373→        match p {
   374→            "debug" | "dev" => {} // default, no flag needed
   375→            _ => {
   376→                cmd.arg("--profile").arg(p);
   377→            }
   378→        }
   379→    }
   380→
   381→    // Collect rustc flags
   382→    let mut rustc_flags: Vec<String> = Vec::new();
   383→
   384→    // Handle high-level panic mode (rustc -C flag)
   385→    if let Some(panic_mode) = spec.panic
   386→        && let Some(panic_value) = panic_mode.rustc_panic_value()
   387→    {
   388→        rustc_flags.push(format!("-C panic={}", panic_value));
   389→    }
   390→
   391→    // Handle high-level strip mode
   392→    if let Some(strip_mode) = spec.strip
   393→        && let Some(strip_value) = strip_mode.rustc_strip_value()
   394→    {
   395→        rustc_flags.push(format!("-C strip={}", strip_value));
   396→    }
   397→
   398→    if !spec.cargo.build_std.is_empty() {
   399→        // -Z build-std is a cargo flag, not rustc
   400→        let crates_str = spec.cargo.build_std.join(",");
   401→        cmd.arg("-Z").arg(format!("build-std={}", crates_str));
   402→    }
   403→
   404→    for flag in &spec.rustflags {
   405→        rustc_flags.push(flag.clone());
   406→    }
   407→
   408→    // Handle version script (generates file and adds linker arg)
   409→    if let Some(vs) = &spec.linker.version_script {
   410→        let vs_dir = match expanded_target_dir {
   411→            Some(td) => workspace.join("target").join(td),
   412→            None => workspace.join("target"),
   413→        };
   414→        let _ = fs::create_dir_all(&vs_dir);
   415→        let version_script_path = vs_dir.join("tspec-version.script");
   416→
   417→        // Generate version script: { global: sym1; sym2; local: *; };
   418→        let globals = vs.global.join("; ");
   419→        let content = format!("{{ global: {}; local: {}; }};", globals, vs.local);
   420→
   421→        let mut f =
   422→            fs::File::create(&version_script_path).context("failed to create version script")?;
   423→        writeln!(f, "{}", content)?;
   424→
   425→        rustc_flags.push(format!(
   426→            "-C link-arg=-Wl,--version-script={}",
   427→            version_script_path.display()
   428→        ));
   429→    }
   430→
   431→    // Apply rustc flags (linker args from Args handled by generated build.rs)
   432→    if !rustc_flags.is_empty() {
   433→        cmd.env("RUSTFLAGS", rustc_flags.join(" "));
   434→    }
   435→
   436→    Ok(())
   437→}
```

    66→## tspec Files
    67→
    68→Translation specs are TOML files (conventionally `*.ts.toml`) that configure builds:
    69→
    70→```toml
    71→# tspec.ts.toml - all supported fields shown
    72→
    73→# Top-level high-level options (expand to lower-level cargo/rustc flags)
    74→panic = "abort"                            # "unwind" (default), "abort", "immediate-abort" (nightly)
    75→strip = "symbols"                          # "none" (default), "debuginfo", "symbols"
    76→rustflags = ["-C", "relocation-model=static"]  # raw flags passed through to RUSTFLAGS
    77→
    78→[cargo]
    79→profile = "release"                        # "debug" (default), "release", or custom profile
    80→target_triple = "x86_64-unknown-linux-musl"
    81→target_json = "path/to/custom-target.json" # custom target spec (auto-adds -Z json-target-spec)
    82→unstable = ["panic-immediate-abort"]       # -Z flags (nightly only)
    83→target_dir = "{name}"                      # per-spec target dir; supports {name} and {hash} placeholders
    84→build_std = ["core", "alloc"]              # crates to rebuild with -Z build-std (nightly)
    85→
    86→[cargo.config.profile.release]             # nested tables under [cargo.config] become individual
    87→opt-level = "z"                            # --config KEY=VALUE args to cargo; any valid cargo
    88→lto = true                                 # config key works (profile, build, target, etc.)
    89→codegen-units = 1
    90→
    91→[linker]
    92→args = ["-static", "-nostartfiles"]
    93→
    94→[linker.version_script]                    # symbol visibility control (enables --gc-sections)
    95→global = ["_start"]                        # symbols to keep
    96→local = "*"                                # default: "*" (hide everything else)
    97→```
    98→
    99→The top-level `panic` sets both cargo `-Z` and rustc `-C` flags automatically.
   100→
   101→### Key Concepts
   102→
   103→- **One tspec per package** - A tspec applies to all crates (targets) within a Cargo package. For per-crate control, use separate packages in a workspace.
   104→- **tspec.ts.toml is optional** - Packages without one get plain `cargo build/test`
   105→- **Generated build.rs** - tspec generates temporary build.rs for scoped linker flags
   106→- **Spec comparison** - Compare binary sizes across different specs; always shows both `cargo --release` and `cargo --release-strip` baselines. Supports `-w` for all-packages mode — per-package tables are collected and printed together at the end. With a single package, only its comparison table is shown
   107→
   108→### How Linker Flags Work
   109→
   110→tspec generates a temporary `build.rs` to apply linker flags with binary-scoped directives:
   111→
   112→```rust
   113→// Generated by tspec - deleted after build
   114→fn main() {
   115→    println!("cargo:rustc-link-arg-bin=myapp=-static");
   116→    println!("cargo:rustc-link-arg-bin=myapp=-nostdlib");
   117→}
   118→```
   119→
   120→The only other alternative is to add these linker flags to RUSTFLAGS, but that
   121→affects ALL compilations (including dependency build scripts), causing crashes
   122→with flags like `-nostartfiles`. The generated build.rs scopes flags to just
   123→the binary.
   124→
   125→### Cargo Config Passthrough (`cargo.config`)
   126→
   127→The `[cargo.config]` section is a general-purpose passthrough to cargo's `--config KEY=VALUE` mechanism. Any nested tables under `[cargo.config]` are flattened into dotted keys and passed as `--config` args. This lets you override any [cargo configuration](https://doc.rust-lang.org/cargo/reference/config.html) value at the command line.
   128→
   129→**Profile settings** are the most common use case:
   130→
   131→```toml
   132→[cargo.config.profile.release]
   133→opt-level = "z"
   134→codegen-units = 1
   135→lto = true
   136→```
   137→
   138→This produces: `cargo --config profile.release.opt-level="z" --config profile.release.codegen-units=1 --config profile.release.lto=true`
   139→
   140→**Other cargo config keys** work too:
   141→
   142→```toml
   143→[cargo.config.target.x86_64-unknown-linux-gnu]
   144→linker = "clang"
   145→runner = "qemu-x86_64"
   146→```
   147→
   148→**Note:** Do not use `build.rustflags` in `[cargo.config]`. tspec sets the `RUSTFLAGS` env var (from top-level `rustflags`, `panic`, and `strip`), which takes precedence over `--config build.rustflags` per cargo's precedence rules. Use the top-level `rustflags` array instead.
   149→
   150→**Custom profiles:** Any profile defined in your workspace `Cargo.toml` (with `inherits`) can be used. tspec validates that custom profiles exist before invoking cargo. Use `cargo.profile` in the spec or `--profile` on the CLI.
   151→
   152→**Flat dotted keys** also work — TOML treats them equivalently:
   153→
   154→```toml
   155→[cargo.config]
   156→"profile.release.opt-level" = "z"
   157→```
   158→
   159→## tspec Management (ts subcommand)
   160→
   161→Manage spec files without manual TOML editing. All commands that modify files preserve comments and formatting.
   162→
   163→| Command | Description |
   164→|---------|-------------|
   165→| `ts list` | List tspec files found in the workspace or a specific package |
   166→| `ts show` | Display the TOML contents of a tspec file |
   167→| `ts hash` | Print the content hash (used in backup filenames) of a tspec |
   168→| `ts new` | Create a new tspec with defaults, or copy an existing one with `-f` (byte-for-byte) |
   169→| `ts set` | Set a scalar value or replace an entire array |
   170→| `ts unset` | Remove a field (scalar or array) from a tspec entirely |
   171→| `ts add` | Add items to an array field (append or insert at position) |
   172→| `ts remove` | Remove items from an array field (by value or by index) |
   173→| `ts backup` | Create a versioned backup copy (`name-NNN-hash.ts.toml`) |
   174→| `ts restore` | Restore a tspec by copying a versioned backup back to its original name |
   175→
   176→```bash
   177→# List / show / hash
   178→tspec ts list                            # List all tspec files
   179→tspec ts list -p myapp                   # List tspec files for a package
   180→tspec ts show -p myapp                   # Show all tspec contents
   181→tspec ts show -p myapp -t tspec-opt      # Show specific tspec-opt.ts.toml
   182→tspec ts hash -p myapp                   # Show content hash of tspec.ts.toml
   183→
   184→# Create new tspec files
   185→tspec ts new -p myapp                    # Create tspec.ts.toml with defaults
   186→tspec ts new experiment -p myapp         # Create experiment.ts.toml
   187→tspec ts new opt2 -p myapp -f tspec-opt  # Copy from existing spec (byte-for-byte)
   188→
   189→# Set scalar values
   190→tspec ts set strip symbols -p myapp              # Set a scalar field
   191→tspec ts set cargo.profile release               # No quoting needed
   192→
   193→# Set (replace) entire arrays — each element is a separate arg
   194→tspec ts set linker.args -static -nostdlib        # Replace array
   195→tspec ts set cargo.build_std core alloc           # Replace array
   196→tspec ts set rustflags -C relocation-model=static # Replace array
   197→
   198→# Add items to arrays (append by default)
   199→tspec ts add linker.args -Wl,--gc-sections        # Append one item
   200→tspec ts add linker.args -nostdlib -pie            # Append multiple items
   201→tspec ts add -i 0 linker.args -nostartfiles        # Insert at position 0
   202→
   203→# Remove items from arrays
   204→tspec ts remove linker.args -nostdlib              # Remove by value
   205→tspec ts remove linker.args -static -pie           # Remove multiple by value
   206→tspec ts remove -i 2 linker.args                   # Remove by index
   207→
   208→# Remove a field entirely
   209→tspec ts unset strip -p myapp                      # Remove scalar field
   210→tspec ts unset linker.args -t tspec-opt            # Remove array field
   211→
   212→# Backup and restore (byte-for-byte copies)
   213→tspec ts backup -p myapp                 # Backup tspec.ts.toml → tspec-001-abcd1234.ts.toml
   214→tspec ts backup -p myapp -t tspec-opt    # Backup tspec-opt.ts.toml
   215→tspec ts restore -t t1-001-abcd1234      # Restore t1.ts.toml from backup
   216→```
   217→
   218→Backups are valid spec files and can be used directly with `-t`.
   219→
   220→`ts set`, `ts unset`, `ts add`, and `ts remove` use `toml_edit` for surgical editing — comments and formatting are preserved.
   221→`ts backup`, `ts restore`, and `ts new -f` use byte-for-byte file copy — comments are preserved exactly.
   222→
   223→### Supported keys
   224→
   225→Keys use two forms: `FIELD` for top-level fields (`panic`, `strip`, `rustflags`) or `TABLE.FIELD` for nested fields (`cargo.profile`, `linker.args`).
   226→
   227→| Key | Type | Values |
   228→|-----|------|--------|
   229→| `panic` | scalar | `unwind`, `abort`, `immediate-abort` |
   230→| `strip` | scalar | `none`, `debuginfo`, `symbols` |
   231→| `rustflags` | array | e.g. `-C relocation-model=static` |
   232→| `cargo.profile` | scalar | `debug`, `release`, or any custom profile defined in `Cargo.toml` |
   233→| `cargo.target_triple` | scalar | any string |
   234→| `cargo.target_json` | scalar | any path |
   235→| `cargo.target_dir` | scalar | any string (supports `{name}`, `{hash}`) |
   236→| `cargo.unstable` | array | e.g. `panic-immediate-abort` |
   237→| `cargo.config` | table | arbitrary `--config KEY=VALUE` passthrough; supports nested tables (e.g. `[cargo.config.profile.release]`) |
   238→| `cargo.build_std` | array | e.g. `core alloc` |
   239→| `linker.args` | array | e.g. `-static -nostdlib` |
   240→
   241→### Array operations
   242→
   243→Four orthogonal commands operate on arrays at two levels:
   244→
   245→| Level | Command | Purpose |
   246→|-------|---------|---------|
   247→| Field-level | `ts set` | Replace entire array with new values |
   248→| Field-level | `ts unset` | Remove the array field entirely |
   249→| Item-level | `ts add` | Append items (or insert at position with `-i`) |
   250→| Item-level | `ts remove` | Remove items by value (or by index with `-i`) |
   251→
   252→```bash
   253→tspec ts set linker.args -static -nostdlib   # replace all with these
   254→tspec ts unset linker.args                   # clear the field
   255→tspec ts add linker.args -Wl,--gc-sections   # append (skips duplicates)
   256→tspec ts add -i 0 linker.args -nostartfiles  # insert at position
   257→tspec ts remove linker.args -static          # remove by value
   258→tspec ts remove -i 2 linker.args             # remove by index
   259→```
   260→
   261→Values starting with `-` work without quoting thanks to `allow_hyphen_values`.
   262→Use `--` as an escape hatch if a value collides with a flag like `-p`, `-t`, or `-i`.
   263→

```rust
/// because `-Zpanic_abort_tests` is nightly-only.
fn requires_nightly(spec: &Spec, strict_panic: bool) -> bool {
    let panic_needs_nightly = if strict_panic {
        spec.panic.map(|p| p.rustc_panic_value().is_some()).unwrap_or(false)
    } else {
        spec.panic.map(|p| p.requires_nightly()).unwrap_or(false)

    let has_build_std = !spec.cargo.build_std.is_empty();
    let has_unstable = !spec.cargo.unstable.is_empty();
    panic_needs_nightly || has_build_std || has_unstable
}
```

**Option B: Pass through function parameters.** Add `verbosity: Verbosity` to `run_cargo()`, `build_package()`, `test_package()`, `build_all()`, `test_all()`, `run_all()`, `compare_specs()`, `execute_cargo_subcommand()`, etc.

**Option C: Thread-local / global.** Set once, read anywhere. Simplest but least Rustic.

**Decision: Option B (parameters)** is the cleanest. The Execute trait signature change is acceptable since all impls are in this crate. However, this creates a large signature change cascade.

**Revised decision: Hybrid approach.** Change the Execute trait to pass verbosity, and add it to `run_cargo()` and `execute_cargo_subcommand()`. The all.rs batch functions get it threaded from the cmd layer.

#### Verbose Helper Function

```rust
fn print_verbose_command(cmd: &Command, verbosity: Verbosity) {
    if verbosity < Verbosity::Verbose {
        return;
    }
    // Print the command line
    let program = cmd.get_program().to_string_lossy();
    let args: Vec<String> = cmd.get_args().map(|a| a.to_string_lossy().into_owned()).collect();
    println!("[verbose] {} {}", program, args.join(" "));

    // Print relevant env vars
    for (key, val) in cmd.get_envs() {
        let key_str = key.to_string_lossy();
        if matches!(key_str.as_ref(), "RUSTFLAGS" | "TSPEC_SPEC_FILE") {
            if let Some(v) = val {
                println!("[verbose] {}={}", key_str, v.to_string_lossy());
            }
        }
    }
}
```
