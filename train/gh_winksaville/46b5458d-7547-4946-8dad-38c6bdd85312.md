# Plan: Remove classify_package and PackageKind

## Context

`classify_package()` hardcodes directory conventions (`apps/`, `libs/`, `tools/`, `*/tests`)
that are specific to one workspace layout. tspec shouldn't impose layout opinions — cargo
metadata already provides `has_binary`, and the only real behavioral need is excluding build
tools (tspec/xt/xtask) from batch operations.

## Changes

### `src/workspace.rs`

- **Remove** `PackageKind` enum (5 variants)
- **Remove** `classify_package()` function
- **Remove** `test_members()` method
- **Replace** `kind: PackageKind` with `is_build_tool: bool` on `PackageMember`
- **Add** `fn is_build_tool_name(name: &str) -> bool` — checks tspec/xt/xtask
- **Update** `discover()` — set `is_build_tool` instead of calling `classify_package`
- **Update** `buildable_members()` — filter `!m.is_build_tool`
- **Update** `runnable_members()` — filter `m.has_binary && !m.is_build_tool`
- **Replace unit tests** — drop all `classify_*` tests, add `is_build_tool_name` tests,
  update `discover_works` to check `is_build_tool` instead of `PackageKind`
