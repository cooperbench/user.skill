     1→# tspec - Translation Spec Build System
     2→
     3→A spec-driven build system for Rust that wraps cargo with configurable target triples, compiler flags, and linker options. Each tspec applies to a Cargo **package** — the unit with a `Cargo.toml`. If different crates need different compilation settings, they should be in separate packages.
     4→
     5→**Status:** Active development. Works with both workspaces and single-package projects (POPs).
     6→
     7→## Installation
     8→
     9→```bash
    10→cargo install --path .
    11→```
    12→
    13→Or run directly:
    14→```bash
    15→cargo run -- build
    16→```
    17→
    18→## Usage
    19→
    20→```bash
    21→tspec build                                # Build current package (or all in workspace) with tspec.ts.toml if present
    22→tspec build -p myapp                       # Build specific package with tspec.ts.toml if present
    23→tspec build myapp                          # Same, using positional argument
    24→tspec build .                              # Build the package in current directory
    25→tspec build -p myapp -t tspec-opt          # Build with alternative spec tspec-opt.ts.toml
    26→tspec build -p myapp -t tspec-opt.ts.toml  # Build with alternative spec tspec-opt.ts.toml
    27→tspec build -p myapp -r -s                 # Build release, strip symbols with tspec.ts.toml if present
    28→tspec run -p myapp                         # Build and run with tspec.ts.toml if present
    29→tspec test -p myapp                        # Build and test with tspec.ts.toml if present
    30→tspec build -w                             # Build all packages (even from inside a package dir)
    31→tspec compare                              # Compare all tspec*.ts.toml by binary size
    32→tspec compare -t *.ts.toml                 # Compare using shell-expanded glob
    33→tspec compare -p myapp                     # Compare for a specific package
    34→```
    35→
    36→The `-p` flag or positional argument specifies a package by name or path (defaults to current directory if in a package, otherwise all packages). Paths like `.` are resolved to the actual cargo package name. At a pure workspace root (no `[package]`), `.` means "all packages."
    37→Use `-w, --workspace` to force all-packages mode even when inside a package directory.
    38→The `-t` flag selects a tspec file; if omitted and `tspec.ts.toml` exists, it's used automatically.
    39→
    40→**Note on `cmd` vs `cmd .`:** For passthrough commands (clean, clippy, fmt), `tspec cmd` passes no `-p` to cargo (operates on everything), while `tspec cmd .` resolves to `cargo cmd -p <name>` (package-specific). The difference is most visible with `clean`: `cargo clean` removes all of target/ while `cargo clean -p <name>` leaves shared metadata files. This matches cargo's own behavior. Use `tspec clean` or `tspec clean -w` for a full clean.
    41→
    42→## tspec Files
    43→
    44→Translation specs are TOML files (conventionally `*.ts.toml`) that configure builds:
    45→
    46→```toml
    47→# tspec.ts.toml - all supported fields shown
    48→
    49→# Top-level high-level options (expand to lower-level cargo/rustc flags)
    50→panic = "abort"                            # "unwind" (default), "abort", "immediate-abort" (nightly)
    51→strip = "symbols"                          # "none" (default), "debuginfo", "symbols"
    52→
    53→[cargo]
    54→profile = "release"                        # "debug" (default), "release"
    55→target_triple = "x86_64-unknown-linux-musl"
    56→target_json = "path/to/custom-target.json" # custom target spec (auto-adds -Z json-target-spec)
    57→unstable = ["panic-immediate-abort"]       # -Z flags (nightly only)
    58→target_dir = "{name}"                      # per-spec target dir; supports {name} and {hash} placeholders
    59→
    60→[rustc]
    61→opt_level = "z"                            # "0", "1", "2", "3", "s", "z"
    62→panic = "abort"                            # "abort", "unwind", "immediate-abort" (prefer top-level panic)
    63→lto = true
    64→codegen_units = 1
    65→build_std = ["core", "alloc"]              # crates to rebuild with -Z build-std (nightly)
    66→flags = ["-C", "relocation-model=static"]  # raw rustc flags passed through
    67→
    68→[linker]
    69→args = ["-static", "-nostartfiles"]
    70→
    71→[linker.version_script]                    # symbol visibility control (enables --gc-sections)
    72→global = ["_start"]                        # symbols to keep
    73→local = "*"                                # default: "*" (hide everything else)
    74→```
    75→
    76→The top-level `panic` sets both cargo `-Z` and rustc `-C` flags automatically. If both
    77→top-level `panic` and `rustc.panic` are set, both are applied (prefer one or the other).
    78→
    79→### Key Concepts
    80→
    81→- **One tspec per package** - A tspec applies to all crates (targets) within a Cargo package. For per-crate control, use separate packages in a workspace.
    82→- **tspec.ts.toml is optional** - Packages without one get plain `cargo build/test`
    83→- **Generated build.rs** - tspec generates temporary build.rs for scoped linker flags
    84→- **Spec comparison** - Compare binary sizes across different specs; always shows both `cargo --release` and `cargo --release-strip` baselines
    85→
    86→### How Linker Flags Work
    87→
    88→tspec generates a temporary `build.rs` to apply linker flags with binary-scoped directives:
    89→
    90→```rust
    91→// Generated by tspec - deleted after build
    92→fn main() {
    93→    println!("cargo:rustc-link-arg-bin=myapp=-static");
    94→    println!("cargo:rustc-link-arg-bin=myapp=-nostdlib");
    95→}
    96→```
    97→
    98→This is necessary because RUSTFLAGS affects ALL compilations (including dependency
    99→build scripts), causing crashes with flags like `-nostartfiles`. The generated
   100→build.rs scopes flags to just the binary.
   101→
   102→## tspec Management (ts subcommand)
   103→
   104→Manage spec files without manual TOML editing. All commands that modify files preserve comments and formatting.
   105→
   106→| Command | Description |
   107→|---------|-------------|
   108→| `ts list` | List tspec files found in the workspace or a specific package |
   109→| `ts show` | Display the TOML contents of a tspec file |
   110→| `ts hash` | Print the content hash (used in backup filenames) of a tspec |
   111→| `ts new` | Create a new tspec with defaults, or copy an existing one with `-f` (byte-for-byte) |
   112→| `ts set` | Set a scalar value or replace an entire array |
   113→| `ts unset` | Remove a field (scalar or array) from a tspec entirely |
   114→| `ts add` | Add items to an array field (append or insert at position) |
   115→| `ts remove` | Remove items from an array field (by value or by index) |
   116→| `ts backup` | Create a versioned backup copy (`name-NNN-hash.ts.toml`) |
   117→| `ts restore` | Restore a tspec by copying a versioned backup back to its original name |
   118→
   119→```bash
   120→# List / show / hash
   121→tspec ts list                            # List all tspec files
   122→tspec ts list -p myapp                   # List tspec files for a package
   123→tspec ts show -p myapp                   # Show all tspec contents
   124→tspec ts show -p myapp -t tspec-opt      # Show specific tspec-opt.ts.toml
   125→tspec ts hash -p myapp                   # Show content hash of tspec.ts.toml
   126→
   127→# Create new tspec files
   128→tspec ts new -p myapp                    # Create tspec.ts.toml with defaults
   129→tspec ts new experiment -p myapp         # Create experiment.ts.toml
   130→tspec ts new opt2 -p myapp -f tspec-opt  # Copy from existing spec (byte-for-byte)
   131→
   132→# Set scalar values
   133→tspec ts set strip symbols -p myapp              # Set a scalar field
   134→tspec ts set rustc.lto true -t tspec-opt         # Set in a specific tspec
   135→tspec ts set cargo.profile release               # No quoting needed
   136→
   137→# Set (replace) entire arrays — each element is a separate arg
   138→tspec ts set linker.args -static -nostdlib        # Replace array
   139→tspec ts set rustc.build_std core alloc           # Replace array
   140→
   141→# Add items to arrays (append by default)
   142→tspec ts add linker.args -Wl,--gc-sections        # Append one item
   143→tspec ts add linker.args -nostdlib -pie            # Append multiple items
   144→tspec ts add -i 0 linker.args -nostartfiles        # Insert at position 0
   145→
   146→# Remove items from arrays
   147→tspec ts remove linker.args -nostdlib              # Remove by value
   148→tspec ts remove linker.args -static -pie           # Remove multiple by value
   149→tspec ts remove -i 2 linker.args                   # Remove by index
   150→
   151→# Remove a field entirely
   152→tspec ts unset rustc.lto -p myapp                  # Remove scalar field
   153→tspec ts unset linker.args -t tspec-opt            # Remove array field
   154→
   155→# Backup and restore (byte-for-byte copies)
   156→tspec ts backup -p myapp                 # Backup tspec.ts.toml → tspec-001-abcd1234.ts.toml
   157→tspec ts backup -p myapp -t tspec-opt    # Backup tspec-opt.ts.toml
   158→tspec ts restore -t t1-001-abcd1234      # Restore t1.ts.toml from backup
   159→```
   160→
   161→Backups are valid spec files and can be used directly with `-t`.
   162→
   163→`ts set`, `ts unset`, `ts add`, and `ts remove` use `toml_edit` for surgical editing — comments and formatting are preserved.
   164→`ts backup`, `ts restore`, and `ts new -f` use byte-for-byte file copy — comments are preserved exactly.
   165→
   166→### Supported keys
   167→
   168→Keys use two forms: `FIELD` for top-level fields (`panic`, `strip`) or `TABLE.FIELD` for nested fields (`rustc.lto`, `linker.args`).
   169→
   170→| Key | Type | Values |
   171→|-----|------|--------|
   172→| `panic` | scalar | `unwind`, `abort`, `immediate-abort` |
   173→| `strip` | scalar | `none`, `debuginfo`, `symbols` |
   174→| `cargo.profile` | scalar | `debug`, `release` |
   175→| `cargo.target_triple` | scalar | any string |
   176→| `cargo.target_json` | scalar | any path |
   177→| `cargo.target_dir` | scalar | any string (supports `{name}`, `{hash}`) |
   178→| `cargo.unstable` | array | e.g. `panic-immediate-abort` |
   179→| `rustc.opt_level` | scalar | `0`, `1`, `2`, `3`, `s`, `z` |
   180→| `rustc.panic` | scalar | `abort`, `unwind`, `immediate-abort` |
   181→| `rustc.lto` | scalar | `true`, `false` |
   182→| `rustc.codegen_units` | scalar | integer |
   183→| `rustc.build_std` | array | e.g. `core alloc` |
   184→| `rustc.flags` | array | e.g. `-Cforce-frame-pointers=yes` |
   185→| `linker.args` | array | e.g. `-static -nostdlib` |
   186→
   187→### Array operations
   188→
   189→Four orthogonal commands operate on arrays at two levels:
   190→
   191→| Level | Command | Purpose |
   192→|-------|---------|---------|
   193→| Field-level | `ts set` | Replace entire array with new values |
   194→| Field-level | `ts unset` | Remove the array field entirely |
   195→| Item-level | `ts add` | Append items (or insert at position with `-i`) |
   196→| Item-level | `ts remove` | Remove items by value (or by index with `-i`) |
   197→
   198→```bash
   199→tspec ts set linker.args -static -nostdlib   # replace all with these
   200→tspec ts unset linker.args                   # clear the field
   201→tspec ts add linker.args -Wl,--gc-sections   # append (skips duplicates)
   202→tspec ts add -i 0 linker.args -nostartfiles  # insert at position
   203→tspec ts remove linker.args -static          # remove by value
   204→tspec ts remove -i 2 linker.args             # remove by index
   205→```
   206→
   207→Values starting with `-` work without quoting thanks to `allow_hyphen_values`.
   208→Use `--` as an escape hatch if a value collides with a flag like `-p`, `-t`, or `-i`.
