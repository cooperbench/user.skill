Yeah, that's jj's git-side conflict format. When jj has a conflict in a commit, it serializes the conflict state into a tree containing `JJ-CONFLICT-README` plus `.jjconflict-base-*` and `.jjconflict-side-*` directories holding each input. Plain git tools see it as a real tree and display it as such, which is why gitk shows `JJ-CONFLICT-README` — it's a real file in git's view, even though jj treats the commit as "in conflict."

Two practical implications for the eventual rebase:
