- **(a) In-memory, within one invocation.** `save-state` reads the relevant regs (5 baud / 6 ascii-type / 7 rate / 75 binary) into the running process; `restore-state` writes them back before exit. No filesystem. This is *exactly* bench's old auto-restore — but now explicit, general, and composable with any set-combo. Pairs perfectly with the keystone.
- **(b) File-backed, across invocations.** `save-state` persists a snapshot to disk; `restore-state` reads it back tomorrow. More powerful, but adds config-file concerns (where it lives, format, staleness if the device changed underneath it).

I'd do **(a) first**. It's the clean replacement for what we're removing and needs no new persistence story. The convenience save-state buys over typing it yourself: you don't have to *know* the current values — it reads "whatever it is now" and puts it back. Same value bench's restore had.

- **Binary**: the rate is the **rateDivisor inside reg 75**, *the same register as the fields* (`VNWRG,75,1,<divisor>,01,<mask>`). There is no separate "binary rate register." That's resolvable and can still look clean to you, but it changes the execution model: it's not pure "each command = one register poke, left to right."
