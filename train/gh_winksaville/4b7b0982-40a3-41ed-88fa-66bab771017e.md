I'm thinking it's global, like rust-toolchain.toml, although being able to target it on a per package is actually quite interesting, thoughts?

> AGENT

Good question. Here's my thinking:

**Per-package control is already built-in** — since each package gets its own `.ts.toml` spec, putting `toolchain` in the spec *already* gives per-package control regardless of where it sits in the TOML structure. Package A can have `toolchain = "nightly"` while package B has `toolchain = "stable"` or omits it entirely.

**Top-level makes more sense** for a few reasons:
1. It's analogous to `rust-toolchain.toml` being a top-level project concept
2. It sits alongside `panic` and `strip` which are also high-level build strategy choices
3. The toolchain affects everything (which rustc, which stdlib) — it's bigger than just a cargo flag
4. Simpler to write: `toolchain = "nightly"` vs needing `[cargo]` section

**The `[cargo]` section** holds things that map to specific cargo CLI flags (`--profile`, `--target`, `-Z`). While `+nightly` is technically a cargo argument, the toolchain choice is conceptually higher-level.

My recommendation: **top-level `toolchain`**. You get per-package control for free because specs are per-package, and it keeps the mental model clean — "toolchain is a fundamental build choice, like panic strategy."
