> AGENT

The `resolve_spec_path_inner` function takes the env var values as parameters instead of reading them itself. This means:

- **`resolve_spec_path`** (the real entry point) reads `CARGO_MANIFEST_DIR` and `TSPEC_SPEC_FILE` from the process environment, then passes them to `_inner`.
- **`resolve_spec_path_inner`** does the actual logic using only its parameters — it never touches `std::env`.

Tests call `_inner` directly with whatever values they want:
```rust
resolve_spec_path_inner(None, Some("/fake/manifest"), Some("/tmp/test.ts.toml"))
resolve_spec_path_inner(None, Some("/fake/manifest"), None)
```

Each test owns its own data on the stack. No `set_var`, no `remove_var`, no shared mutable state. Two tests running on different threads can't interfere because they're just passing different arguments to a pure function.

The general principle: push side effects (env var reads, file I/O, network) to the edges, keep the core logic pure and parameterized. Then tests exercise the logic without touching the real world.
