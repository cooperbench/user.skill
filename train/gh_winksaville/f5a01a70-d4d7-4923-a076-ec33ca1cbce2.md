# Plan: Parse cargo test output for counts and filtering

## Context

`tspec test` currently streams cargo output live via `cmd.status()` and
only knows pass/fail per package. The summary shows `[PASS]`/`[FAIL]`
with no test counts. Worse, 0 tests running is reported as success.

Goals:
1. Parse `test result:` lines to extract passed/failed/ignored counts
2. Show per-package test counts in the summary table
3. Warn when 0 tests ran (likely a filter typo)
4. Filter "running 0 tests" noise from single-target execution

## Approach: Tee stdout with line parsing

Change `run_cargo` (Test mode only) to pipe stdout, read lines in a
loop, print each line live, and accumulate `test result:` lines. Return
parsed counts alongside the exit status.

### New struct: `TestResult`

```rust
/// Parsed test statistics from cargo test output
pub struct TestResult {
    pub passed: u32,
    pub failed: u32,
    pub ignored: u32,
    pub filtered: u32,
}
```

### Changes

#### `src/tee.rs` (new module — reusable tee-and-filter utility)

Generic "run command, tee stdout line-by-line, collect lines matching
a predicate" utility. Not test-specific.

```rust
pub struct TeeResult {
    pub status: ExitStatus,
    pub matched_lines: Vec<String>,
}

/// Spawn a command with piped stdout (stderr inherited),
/// print each stdout line live, and collect lines where
/// `filter(line)` returns true.
pub fn tee_stdout<F>(cmd: &mut Command, filter: F) -> Result<TeeResult>
where
    F: Fn(&str) -> bool;
```

This is reusable for any future command that needs live output +
selective parsing (e.g., build warnings, benchmark results).

#### `src/cargo_build.rs`

- Add `TestResult` struct
- Add `fn parse_test_result_line(line: &str) -> Option<TestResult>` —
  parses `test result: ok. 263 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out`
- Change `test_package()` return type: `Result<()>` → `Result<TestResult>`
- In `run_cargo()` for `CargoMode::Test`: use `tee_stdout()` with a
  filter for `test result:` lines, then parse and aggregate counts.
  stderr stays inherited (compiler errors/warnings stream live).
- Add unit tests for `parse_test_result_line`

#### `src/all.rs`

- Update `test_all()` to use new `TestResult` from `test_package()`
- Store counts in `OpResult.message` or add fields to `OpResult`
- Better: add `test_counts: Option<TestResult>` to `OpResult`

#### `src/all.rs` — `print_test_summary()`

- Show per-package counts: `[PASS]  263 passed` or `[FAIL]  2 failed`
- Show totals in footer: `Test: 2 packages, 279 passed, 0 failed`
- Fail (exit 1) when total tests across all packages is 0:
  `Error: 0 tests ran (filter may not match anything)`

#### `src/cmd/test.rs`

- Update single-package path to use `TestResult` return value
- Fail (exit 1) on 0 tests for single-package execution too

### Filtering "running 0 tests" noise

While reading stdout line-by-line, suppress lines matching:
- `running 0 tests` (when immediately followed by empty test result)
- `test result: ok. 0 passed; 0 failed; ...` when all zeros

Only suppress when the block is entirely empty (0 passed, 0 failed).
This cleans up output when `--test` targets specific files.

### What NOT to change

- Build and run modes stay on `cmd.status()` (no parsing needed)
- stderr stays inherited in all modes (compiler output streams live)
- The `--list` and `--target-names` code paths are unaffected
