## 1. Custom Slash Commands (via Skills)

**Where to define them:**
- Personal scope: `~/.claude/skills/<skill-name>/SKILL.md`
- Project scope: `.claude/skills/<skill-name>/SKILL.md`

**File format:**
Skills use YAML frontmatter + markdown instructions:

```yaml
---
name: exit-commit
description: Commit changes and exit Claude Code
disable-model-invocation: true
---

Commit the following changes:
- App repo: jj commit -m "title" -m "body" -R .
- Bot session repo: jj commit -m "title" -m "body" -R .claude
```

**Frontmatter fields relevant to your use case:**
- `name`: becomes the `/slash-command` (required for invocation)
- `disable-model-invocation: true`: prevents Claude from auto-triggering, you invoke manually with `/exit-commit`
- `description`: tells Claude what it does
- `allowed-tools`: restrict which tools Claude can use

**What custom slash commands can do:**
1. Inject custom prompts/instructions
2. Run shell commands (via `!` backtick syntax for preprocessing)
3. Access arguments via `$ARGUMENTS` or `$0`, `$1`, etc.
4. Load supporting files (templates, examples, scripts)
5. Run in a subagent with `context: fork`

**Critical limitation: Skills cannot directly cause Claude Code to exit.** Skills are instructions that guide Claude's behavior, not system commands that control the application lifecycle.

## 2. Hooks: The Real Exit Point

**SessionEnd Hook** is your solution for post-session automation:

From the hooks reference, `SessionEnd` fires **when a session terminates**, with a matcher on why it ended: `clear`, `logout`, `prompt_input_exit`, `bypass_permissions_disabled`, `other`.

**Configuration in `.claude/settings.json`:**

```json
{
  "hooks": {
    "SessionEnd": [
      {
        "matcher": "prompt_input_exit",
        "hooks": [
          {
            "type": "command",
            "command": "cd /home/wink/data/prgs/rust/hw-jjg-bot && jj commit -m 'session work' -R . && jj commit -m 'session end' -R .claude && jj git push -R . && jj git push -R .claude"
          }
        ]
      }
    ]
  }
}
```

**How it works:**
1. Hook runs shell commands at specific lifecycle points
2. Exit code 0 = action proceeds normally
3. Exit code 2 = block the action (with stderr feedback to Claude)
4. Stdout is captured and can be injected into context

**Available hook events relevant to exit workflows:**

| Event | Trigger | Use Case |
|-------|---------|----------|
| `SessionEnd` | Session terminates | **Your `/exit-commit` workflow** |
| `Stop` | Claude finishes responding | Run checks before Claude stops |
| `UserPromptSubmit` | Before processing your prompt | Inject pre-commit context |
| `PostToolUse` | After tool executes | Auto-format, auto-commit incrementally |
