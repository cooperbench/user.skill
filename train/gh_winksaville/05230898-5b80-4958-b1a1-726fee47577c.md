Explain why in show.rs why there is `show`, `show_one_commit` and `show_both`

> AGENT

The three functions form a dispatch hierarchy:

- **`show`** (line 68) — the **entry point** called from main. It parses args, resolves the revset, and decides which path to take. If the user used `..` notation (e.g. `vc-x1 show rev..`), it delegates to `show_both`. Otherwise it loops over the resolved commit IDs itself, calling `show_one_commit` for each.

- **`show_one_commit`** (line 209) — the **leaf renderer**. It prints all the detail for a single commit: IDs, author, committer, parents, children, branches, follows/precedes tags, description, and changed files. Both `show` and `show_both` call this.

- **`show_both`** (line 133) — handles the **`..` (both-directions) case**. When the user writes e.g. `vc-x1 show @.. 3`, they want to see commits both above and below the anchor. `show_both` resolves descendants (`rev::`) and ancestors (`::rev`) separately, takes `both_count` from each direction, then renders them in order: descendants first, then the anchor (marked primary), then ancestors — each via `show_one_commit`.

In short: `show` is the dispatcher, `show_one_commit` is the single-commit renderer, and `show_both` is the special-case orchestrator for bidirectional `..` queries. The split keeps the bidirectional logic (which needs separate ancestor/descendant revset resolution) out of the normal single-direction loop.
