2	
3	This protocol uses [Prose form](../AGENTS.md#prose-form).
4	
5	## Cycles
6	
7	A cycle has three phases:
8	
9	- **[Preparation](#preparation)** (`X.Y.Z-0`) — the cycle's
10	  first commit. Sets up the cycle:
11	  - Backfill the previous cycle's chores `Commits:` ref.
12	  - Bump `Cargo.toml` to `X.Y.Z-0`.
13	  - Pick up a `## Todo` item (typically the top-ranked,
14	    #1) into `## In Progress` (bold title + succinct problem
15	    statement + plan ladder).
16	  - Open the [chores section](#chores-sections).
17	- **[Work-N](#work-n)** (`X.Y.Z-1`, `X.Y.Z-2`, …) — the
18	  commits that implement the change. As many as the change
19	  needs; each runs through the
20	  [per-commit flow](#per-commit-flow).
21	- **[Close-out](#close-out)** (bare `X.Y.Z`) — the cycle's
22	  last commit. Bookkeeping only:
23	  - Move the picked-up item to a one-line entry in
24	    `## Done`.
25	  - Move the `## In Progress` block into the
26	    [chores section](#chores-sections).
27	  - Optionally update `notes/README.md` if functionality
28	    changed.
29	
30	A cycle's commits are published to the project remote
31	either incrementally or as one batch at close-out; the
32	result must always be published at close-out. See
33	[Pushing](#pushing).
34	
35	**Sub-cycles.** When a Work commit's scope grows enough to
36	warrant its own ladder, it subdivides — `X.Y.Z-3.0`

311	   <closeout> --onto <prev> --onto <work-tip>`.
312	   - `-r <closeout>` keeps the `<closeout>` commit in place.
313	   - `--onto <prev>` becomes its first parent (trunk).
314	   - `--onto <work-tip>` becomes the second parent.
315	
316	   Together these make `<closeout>` a merge of
317	   `<prev>` + `<work-tip>`, forming a trapezoidal commit.
318	2. **Use `jj new <merge>`** to add an empty `@` above the
319	   merge. The rebase left `@` *on* the now-content-bearing
320	   merge, which git/IDE diff views show as uncommitted;
321	   `jj new` restores the clean empty `@` on top.
322	3. **Push** — `jj git push --bookmark main -R .`.
323	
324	**Post-hoc caveat.** If the cycle was already pushed
325	[Keep separate](#shape-at-close-out-push) its commits are
326	immutable: the rebase needs `--ignore-immutable` and the
327	push force-updates `main`.
328	The standard sequence assumes the merge is set up *before*
329	the close-out push.
330	
331	### vc-x1 push wrapper
332	
333	`vc-x1 push <bookmark>` wraps per-push mechanics. See
334	`vc-x1 push --help` for current flags.
335	
336	**Current limitation**: only fully supports the
337	[Keep separate](#shape-at-close-out-push) shape; other
338	shapes need manual jj steps. Improvements tracked /
339	planned:
340	
341	- N:1 code↔bot for Merge non-ff (`## Todo` entry P1).
342	- Symmetric squash (planned, to be captured in `-2`).
343	- Per-repo bookmark names (planned).
344	
345	### .claude cadence
346	
347	**Cadence**: one push = one `.claude` commit, paired
348	with every code commit in that push.
349	
350	The `.claude` working copy accumulates session data
351	across the cycle; its change ID stays stable across
352	snapshots, `jj describe`, and the finalize commit, so
353	code-side `ochid:` trailers resolve.
354	
355	`.claude` is a linear journal — all session work lives
356	on `main`, regardless of the app-side bookmark. **Do not
357	create or maintain `.claude` bookmarks that mirror
358	app-side branches** — risks the bot steering session
359	pushes to the wrong remote ref.
360	
361	Ending a session: if the user runs `/exit` there will be
362	session information created, which we don't worry about.
363	The user can close the terminal instead and `@` will
364	remain empty — this behavior was verified in 0.64.0.
365	
366	### Bot communication at the reviews
367	
368	Use plain prose — no insider jargon ("Gate N signal",
369	"Checkpoint N", etc.):
370	
371	- **At Work review** — summarize what changed and stop.
372	  "Work complete. Please review."
373	- **At Commit Description review** — present `$TITLE`
374	  and `$BODY` explicitly; ask permission to commit/push.
375	  Don't spell out the full `vc-x1 push ... --title ...
376	  --body ...` invocation by default.
377	- **At Post close-out review** — surface the shape
378	  options (squash / merge / keep) and the push target;
379	  wait for the user's choice before any `jj squash` /
380	  `jj rebase` / `jj git push` invocation.
381	
382	### After push or finalize: stop and wait
383	
384	After you **push** (cross the remote boundary) or launch
385	**finalize** on the `.claude` repo (`vc-x1 finalize --repo
386	.claude --squash --push <bookmark> --delay 10 --detach`) — by
387	hand or via the `vc-x1 push` wrapper — you **MUST NEVER**
388	proceed (next step, edit, tool call, text output) until the
389	user explicitly directs you to continue. **Even when the next
390	step seems obvious — wait.** Treat push-or-finalize as a hard
391	stop for the whole turn.
392	
393	`vc-x1 push` performs both as its tail stages — `push-app`
394	then the detached `vc-x1 finalize` on `.claude` — so there is
395	no gap left to speak in once the push is invoked. Put **all**
396	closing words *before* invoking it; do not purposely emit anything
397	after the tool returns.
398	
399	Why (`.claude` is the live journal finalize snapshots →
400	squashes → pushes):
401	
402	- **`--detach`**: lets the tool return immediately so the
403	  harness can keep flushing the *trailing* session-data — the
404	  tool call's own transcript and any words emitted *before*
405	  the invoke — into the snapshot.
406	- **`--delay 10`**: gives the harness time to complete that
407	  flush before the snapshot is taken. It is **not** time for
408	  the bot to do more work.
409	- **silence**: the bot must not summarize or perform any work
410	  after the tool returns.
411	
412	**Known slip**: the bot has emitted a summary after launching
413	finalize. There is no "harmless" closing line — if it's worth
414	saying, say it *before* the invoke.
415	
416	### Recovery
417	
418	- **If push exits before `finalize-claude`** (e.g.
419	  failure between `push-app` and `finalize-claude`), run
420	  finalize by hand:
421	
422	  ```
423	  vc-x1 finalize --repo .claude --squash --push <bookmark> --delay 10 --detach --log /tmp/vc-x1-finalize.log
424	  ```
425	
426	- **Run finalize again if `@` is non-empty** after the
427	  finalize's squash-and-commit (also desirable after
428	  extra activity by the bot's agents).
429	  - Why: finalize snapshots `.claude` at `--delay`, but the
430	    bot keeps writing session data while it runs — the tool's
431	    own invocation plus the bot's closing response land
432	    *after* the snapshot.
433	  - Safe to repeat: bot session data is append-only, so a
434	    re-run never conflicts or overwrites. (This could
435	    change; it is not under the user's control.)
436	  - Fix: run `vc-x1 finalize --repo .claude --squash --push
437	    <bookmark> --delay 10 --detach` another time to capture
438	    that tail; one extra pass is generally enough.
439	    - Verified 0.64.0: two finalizes were executed and
440	      we purposely used the bot again and the second finalize
441	      captured everything.
442	  - No guarantees: events outside the bot's control can leave
443	    `@` non-empty — e.g. the bot's back end may decide to
444	    squash/consolidate session data, which can take minutes
445	    and land after the snapshot. The remedy is the same: just
446	    run finalize again. This is why a single pass is never
447	    guaranteed to leave `@` empty.
448	- **Clear push's saved state** after any out-of-band
449	  recovery — `rm .vc-x1/push-state.toml` or `vc-x1 push
450	  <bookmark> --restart` — otherwise push resumes from a
451	  stale stage.
452	- **Late code-repo tweak after `push-app` succeeded**
453	  (e.g. updating AGENTS.md or memory) requires `jj
454	  squash --ignore-immutable` and a re-push; that is a
455	  remote rewrite and needs explicit approval like any
456	  push.
457	
458	## ochid trailers
459	
460	A **chid** is jj's change ID — a permanent identifier
461	that survives rebases and describes (see
462	[`jj-revsets.md`](jj-revsets.md)). An **ochid** trailer
463	on a commit body links it to its counterpart in the
464	other repo via that counterpart's chid, written as a
465	workspace-root-relative path. See
466	[`forks-multi-user.md`](forks-multi-user.md) for the
467	multi-line trailer design (multi-user / forking).
468	
469	- **Code-side commits** each carry one
470	  `ochid: /.claude/<.claude-chid>` — the `.claude`
471	  change ID.
472	- **The `.claude` commit** has one `ochid: /<code-chid>`
473	  per code commit in that push. More than one occurs on
474	  Merge non-ff close-out (one ochid per Work commit in
475	  the cycle).
476	
477	Use `vc-x1 chid -s code,bot -L` to capture the change
478	IDs (first line app, second `.claude`).
479	
480	## Iterative work
481	
482	When work for a single commit (the **target**) benefits
483	from incremental review, loop:
484	
485	1. `jj new -R .` — fresh empty `@` on top of the target.
486	2. Make the next round of changes.
487	3. User reviews the round (see
488	   [Reviewing changes](#reviewing-changes)).
489	4. `jj squash -R .` folds into the target and creates a
490	   new empty `@`.
491	5. If not done, go to step 2.
492	
493	Same jj mechanics as a
494	[sub-cycle ladder](#sub-cycle-ladders), but at
495	single-commit scope — the cycle's version suffix
496	doesn't change.
497	
498	## Sub-cycle ladders
499	
500	When a Work commit subdivides into a sub-cycle (see
501	[Numbering](#numbering) for suffix nesting), its Work
502	commits typically live as a local jj `@` chain and
503	**collapse into the sub-cycle's Close-out** before the
504	parent cycle continues. Ladder commits are scratch —
505	for review and bisection only.
506	
507	### Per-Work-commit contract within a ladder
508	
509	For each Work commit in the ladder:
510	
511	1. `jj new -R .` — create a fresh empty `@`.
512	2. Do the commit's work.
513	3. Run `cargo test --bins`. **Non-negotiable** — build
514	   and clippy alone miss regressions until a later
515	   commit runs the full suite, raising bisection cost.
516	4. `jj describe -m "..." -m "..." -R .` — working title
517	   only (no version suffix); the sub-cycle Close-out
518	   collects everything into one final commit with the
519	   `(X.Y.Z-N)` marker.
520	
521	### Navigating the ladder
522	
523	Common moves:
524	
525	- `jj log -r '<base>::' -R .` — see the whole ladder
526	  from its base.
527	- `jj edit -r <prefix> -R .` — jump `@` to any ladder
528	  commit by chid prefix; useful for bisection.
529	- `jj edit @-- -R .` — quick-jump back two commits.
530	- `jj diff -r <chid> -R .` — review one commit in
531	  isolation.
532	
533	Modifications to any ladder commit rewrite it in place;
534	descendants auto-rebase.
535	
536	### Close-out: squash the ladder
537	
538	When all ladder Work commits are done and tests pass:
539	
540	```
541	jj squash --from "<base>..@-" --into @ -u -R .
542	```
543	
544	`<base>` is the parent of the first ladder commit; `-u`
545	keeps `@`'s description and discards the sources'.
546	After squash, history is linear: `<base> → @`;
547	intermediate commits are auto-abandoned.
548	
549	Then `vc-x1 push <bookmark>` as for any other commit.
550	
551	For N = 1 the squash is a no-op (`<base>..@-` is empty
552	when `@-` is `<base>`); push the single commit directly.
553	
554	### Recovery
555	
556	If a ladder commit goes wrong, back out without losing
557	prior commits:
558	
559	- **Discard the current commit.** `jj abandon @ -R .`
560	  drops it; you get a fresh empty `@` on the same
561	  parent.
562	- **Edit an earlier commit.** `jj edit -r <chid> -R .`,
563	  make corrections, then `jj edit -r <last-ladder-chid>`
564	  to return. Descendants auto-rebase.
565	- **Discard the entire ladder.** `jj op log -R .` shows
566	  the op history; `jj op restore <op-id> -R .` reverts
567	  to that point. Full undo — removes *all* ladder work
568	  after the chosen op. Use only to start over.

vc-x1 0.65.1-0

Dual-repo commit+push+finalize in one resumable command.

Collapses today's manual Commit-Push-Finalize Flow into a
single subcommand with two interactive approval gates and a
state machine with persistent progress so interruptions can
resume without re-doing completed stages.

Stages: preflight (fmt/clippy/test) → review (approve diff)
→ message ($EDITOR / --title+--body, approve text) →
commit-app → commit-claude (skipped if clean) → bookmark-both
→ push-app → finalize-claude. Failures in commit-app /
commit-claude / bookmark-both roll both repos back via
`jj op restore` to the snapshot recorded before commit-app.
After push-app succeeds the remote boundary is crossed and
recovery is forward-only.

Non-interactive use: pass both --title and --body plus --yes
to skip the review gate. Saved state carries title/body
across resumes so only the first invocation needs them.

Usage: vc-x1 push [OPTIONS] [BOOKMARK]

Arguments:
  [BOOKMARK]

          Accepting a positional lets the common case read as `vc-x1 push main`

          Bookmark to advance in both repos (flag form; see positional)
