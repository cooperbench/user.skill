I'm trying out the Official "Claude Code for VS Code" and it seems similar to cli version I've been using, tell me the difference?

> AGENT

They're essentially the **same engine** — same model, same tools, same CLAUDE.md/settings, same memory. The differences are mostly about the UI wrapper:

## What the VS Code Extension Adds

- **Inline diffs** — side-by-side visual comparison of proposed changes in the editor
- **Visual permission prompts** — clickable approve/deny instead of terminal y/n
- **@-mentions** — reference files with `@file.ts` or line ranges with `@file.ts#5-10`
- **Multiple conversation tabs** — parallel sessions in separate panels
- **Auto-accept mode** — bypass permission prompts for faster iteration

## What's CLI-Only

- **Piping & scripting** — `git diff | claude -p "review this"`, CI/CD automation
- **MCP server setup** — `claude mcp add ...` configuration commands
- **Worktrees** — `--worktree` for isolated parallel branches
- **`!` shortcut** — quick shell command execution
- **Tab completion** in the terminal

## Shared (identical in both)

- Same Claude model and capabilities
- CLAUDE.md project instructions
- Auto memory across sessions
- Hooks, skills, MCP servers (once configured)
- Git integration, file editing, all the core agent behavior
- Settings from `~/.claude/settings.json`

## Practical Take

They're interchangeable for most work. The VS Code extension is nicer when you want to **visually review diffs** and stay in the editor. The CLI is better for **automation, scripting, and terminal-native workflows**. You can even use both — run `claude` in VS Code's integrated terminal alongside the extension panel.

Since you're already comfortable with the CLI, the extension should feel very familiar — just with a graphical layer on top.

Correct on both counts. The CLI has this too, you may just not have used it:

The VS Code extension just makes this more discoverable with a visible session list in the UI, whereas in the CLI you have to know the flags exist.
