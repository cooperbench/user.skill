# Plan: Add Custom Profile Support

## Context

Currently `cargo.profile` only accepts `"debug"` or `"release"` (a Rust enum). Cargo supports custom profiles defined in `Cargo.toml` (e.g., `[profile.release-small]` with `inherits = "release"`), selected via `cargo build --profile <name>`. tspec should support selecting and overriding these custom profiles.

Key insight: Custom profile **definitions** must live in `Cargo.toml` (cargo requirement — they need `inherits`). tspec's role is **selecting** a profile and **overriding** its settings via `cargo.config`.

Cargo's profile-to-directory mapping: `dev` → `target/debug/`, `release` → `target/release/`, custom → `target/<name>/`.

## Profile semantics

| `cargo.profile` value | Cargo flag | Target dir |
|---|---|---|
| `"debug"` or `"dev"` | *(none — default)* | `target/debug/` |
| `"release"` | `--profile release` | `target/release/` |
| `"release-small"` | `--profile release-small` | `target/release-small/` |
| *(absent)* + CLI `--release` | `--release` | `target/release/` |
| *(absent)* + CLI `--profile X` | `--profile X` | `target/X/` or `target/debug/` |

## CLI priority

Spec `cargo.profile` takes precedence over CLI flags. CLI `--profile` is a fallback when spec doesn't set a profile. `--release` is sugar for `--profile release`. `--profile` and `--release` conflict (cannot use both).
