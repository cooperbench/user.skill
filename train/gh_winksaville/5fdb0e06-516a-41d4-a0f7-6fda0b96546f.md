QQ: I used `-j=1` but `-j1` and `-j 1` seem to all work, I assume clap is giving us that?

> AGENT

Yes, clap handles all three forms automatically for short args with values. `-j 1`, `-j1`, and `-j=1` are all standard short option syntax that clap supports out of the box. The long form `--jobs=1` and `--jobs 1` also both work.

> DEVELOPER

but --jobs1 doesn't?

> AGENT

Correct — `--jobs1` doesn't work. For long options, the value must be separated by `=` or a space (`--jobs=1`, `--jobs 1`). For short options, all three work (`-j1`, `-j 1`, `-j=1`) because the single-character flag makes it unambiguous where the flag ends and the value begins. With `--jobs1`, clap sees the whole thing as the flag name `jobs1`, which doesn't exist.

This is standard POSIX/GNU option convention, not clap-specific.

> DEVELOPER

is `--verbose --verbose` == `-vv`?

> AGENT

Yes — with `ArgAction::Count`, each occurrence increments the counter. So these are all equivalent (count=2):

- `-vv`
- `-v -v`
- `--verbose --verbose`
- `--verbose -v`

> DEVELOPER

what about `--jobs --jobs`, does that increment too?

> AGENT

No — `jobs` uses a different action. It's declared as `Option<u16>`, so clap expects a *value* after it. `--jobs --jobs` would try to parse the second `--jobs` as the numeric value for the first one, and fail.

`ArgAction::Count` is specifically what makes `-v` stackable. `jobs` uses the default `ArgAction::Set` — it takes a value, and if repeated (`--jobs 2 --jobs 4`), the last one wins.

Who build the dependency tree cargo or rustc? (We see many crates being built are these recursive invocations from rustc or "linear (-j 1)" invocations from cargo?

> AGENT

Cargo. It resolves the full dependency graph from `Cargo.toml`/`Cargo.lock` upfront, topologically sorts it, then invokes `rustc` once per crate in the right order. > DEVELOPER

> AGENT

Cargo has a few ways to get dependency info:

**`cargo tree`** — human-readable dependency tree:
```bash
cargo tree -p tspec
cargo tree -p tspec --edges all    # includes build deps and dev deps
```

Here's the picture:

**Test selection in cargo works at two levels:**

1. **Target selection** (`--test <NAME>`, `--lib`, `--bin <NAME>`, `--tests`, etc.) — selects which test *binary/target* to run. `--test` takes a single name, no globs. You can repeat it: `--test foo --test bar`.

2. **Test name filter** (`TESTNAME` positional arg) — filters *within* a test binary by test function name substring. So `cargo test my_func` runs only tests containing "my_func". This supports no globs either, just substring match.

3. **After `--`** — args to the test harness itself: `--ignored`, `--nocapture`, `--exact`, `--include-ignored` (runs both normal AND ignored), `--skip <PATTERN>` (excludes tests matching pattern).
