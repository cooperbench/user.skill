147	### Why not decompose into leaves
148	
149	The first take decomposed `CommonArgs` into per-flag
150	`options_flags/` leaves (`revision` / `commit_limit` /
151	`repo_label`) flattened into a `common_bundle` — mirroring
152	`init` + `provision_bundle`. Backed out:
153

155	  `clone`, etc.) — a per-flag leaf is the unit of sharing. The
156	  four here share the *whole set*; none of `revision` / `limit`
157	  / `label` / etc. is reused elsewhere, so per-flag leaves buy
158	  nothing the shared struct doesn't already give.
159	- **`value`/`id` friction.** Two single-field-`value` leaves
160	  ([README](../src/options_flags/README.md)) collide on the clap
161	  arg *id* (derived from the field name) when co-flattened —
162	  `clap_builder` panics. The fix (`#[arg(id = …)]` on each) is

164	  self-inflicted by decomposing leaves that didn't need to be.

167

169	  that granularity (`--dry-run`, `--squash`).

171	  commands but its parts aren't reused.

173	  `CommonArgs` then `#[command(flatten)]`s the extracted type

322	### Design: `-R` and `-s` compose rather than conflict
323	
324	The chores plan had `-R` dropped, with `--scope=<path>` covering
325	single-repo via `Scope::Single`. On review the design walked
326	through three iterations:
327	
328	- **Drop `-R`.** `--scope=./foo` covers single-path via
329	  `Scope::Single`; one flag, the `./` prefix disambiguates from
330	  the role keywords.
331	- **Mutually-exclusive `-R` + `-s`.** Keep `-R` for paths, add
332	  `-s` for roles, `conflicts_with` between them. Familiar `-R`
333	  preserved; redundant on the path side.
334	- **Composing `-R` + `-s`** (chosen). `-R` overrides the
335	  workspace root (replaces `find_workspace_root()`), `-s`
336	  selects sides (replaces `default_scope(...)`). Together:
337	  `-R <ws> -s <roles>` resolves the roles within `<ws>`. Each
338	  flag alone reads as today's behavior: `-R foo` → `[foo]`, no
339	  flag → `[.]`. The net-new expressivity is the combined form
340	  (e.g. `vc-x1 chid -R ../foo -s bot` → `[../foo/.claude]`).
341	  `-s` is keyword-only today (`parse_scope_roles` rejects paths
342	  with a hint at `-R`); `-s <path>` and the `-s <path>,roles`
343	  workspace-root override are queued as `## Todo` (a future
344	  `Scope::RolesAt { root, sides }` variant, probably). "Drop
345	  `-R` once `-s` is established" is a separate `## Todo` for
346	  after the migration period — kept for backwards-compat now.

352	(`&Path`, not `&PathBuf`). At each call site that produces an

354	times across the subcommand bodies, with another four to come in
355	`0.49.0-3..-6`'s `TryFrom<&XxxArgs>` impls. A method on
356	`CommonArgs` localizes the conversion ceremony to one place so

842	### Naming: `SubcommandRunner`
843	
844	`clap::Subcommand` is the name of both a clap trait and a
845	derive macro (used on `enum Commands`). Naming our trait
846	`Subcommand` collides. Three real options:
847	
848	- **Rename our trait** ← landed: `SubcommandRunner`. The
849	  `*Runner` suffix is idiomatic Rust (`TestRunner`,
850	  `BenchmarkRunner`, …); reads cleanly at `impl
851	  SubcommandRunner for ChidArgs`; no namespace gymnastics
852	  anywhere.
853	- **`SubcommandTrait`** — rejected. Rust style guides
854	  specifically discourage `*Trait` suffixes (parallel to
855	  `*Interface` in older Java style).
856	- **`SubcommandExec`** — fine, just less idiomatic than
857	  `*Runner`.
858	- **Keep `Subcommand`, qualify clap at use site** — was the
859	  first thing tried (`#[derive(clap::Subcommand, ...)]`,
860	  drop `Subcommand` from `use clap::{...}`). Worked, but
861	  the one ugly use site read worse than a clean rename.
862	
863	### Trait scope: peek methods read from Params
864	
865	The trait carries:
866	
867	- `type Params` (associated type for the clap-free domain
868	  struct each subcommand operates on).
869	- `to_params(&self) -> Result<Params, String>` (required).
870	- `run(ctx, params) -> Result<(), Box<dyn Error>>` (required).
871	- `suppress_banner(params: &Self::Params) -> bool { false }`
872	  (peek, default false).
873	- `is_detached_exec(params: &Self::Params) -> bool { false }`
874	  (peek, default false).
875	- `dispatch(&self, log) -> ExitCode` (default impl below).

877	Earlier iterations considered dropping the peek methods —
878	the reasoning was that they hid a field read without
879	collapsing the per-arm match in `main.rs`. That argument
880	no longer applies once the chrome lives in the trait's
881	default `dispatch`: the peeks are read by `dispatch` (via
882	`Self::suppress_banner(&params)` /
883	`Self::is_detached_exec(&params)`) and passed into
884	`crate::sb_ide(…)`. They're load-bearing, not indirection.
885	
886	The peeks take `params: &Self::Params` (not `&self`) so
887	the chrome data lives on each command's `Params` struct
888	(e.g. `ChidParams::suppress_banner`). Commands that don't
889	need either flag (the 10 non-chid, non-finalize ones)
890	just don't override; the default `false` applies.
891	
892	This makes ported arms in `main` true one-liners
893	(`Commands::Chid(args) => args.dispatch(cli.log),`) —
894	all the chrome behavior is driven by the command's own
895	`Params` content, queried through trait methods, with no
896	visible coupling to `main`.

898	### Session chrome: order shift
899	
900	Today `main` has an inline `if !is_detached_exec { …
901	log::info!("{BANNER}"); finalize::surface_previous_failures();
902	}` block *before* the outer match. Each subcommand runs
903	under that shared chrome.

905	The extraction lifts this block into a global
906	`pub fn sb_ide(suppress_banner: bool, is_detached_exec: bool)`
907	in `main.rs` (placed near `BANNER` and `bm_track`). Two
908	call sites:
909	
910	- The trait's default `dispatch` calls `crate::sb_ide(...)`
911	  for ported commands (after `Context::load` and
912	  `to_params` succeed).
913	- Each unported arm in `main` calls
914	  `sb_ide(suppress_banner, is_detached_exec)` directly,
915	  reading the bools from a shrunken pre-match peek match
916	  (which only enumerates the unported `-L`-supporting
917	  variants — chid is gone, future ports remove their
918	  variants too).

940
