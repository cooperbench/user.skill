The core problem is that `ts set` takes the entire assignment as **one positional argument** (`key=value`), which forces the user to fight the shell:

```bash
# Simple scalar — fine
tspec ts set rustc.lto=true

# Array — now you're fighting quotes and brackets
tspec ts set 'linker.args=["-static","-nostdlib"]'
#             ^--- shell quote to protect brackets (glob chars)
#                          ^--- inner TOML quotes for strings

# Append — still awkward
tspec ts set 'linker.args+=-Wl,--gc-sections'
```

The fix: **split `key` and `value` into separate clap arguments**, and make `value` variadic for arrays.

### Proposed syntax

```bash
# Scalars — just two words, no quoting ever
tspec ts set rustc.lto true
tspec ts set cargo.profile release
tspec ts set panic abort

# Arrays — each element is its own shell arg (no brackets, no inner quotes)
tspec ts set linker.args -static -nostdlib
tspec ts set linker.args -- -static -nostdlib   # -- if values look like flags

# Append/remove — explicit flags replace the +=/-= encoding
tspec ts set -a linker.args -Wl,--gc-sections
tspec ts set -r linker.args -static
tspec ts set --append linker.args -static -nostdlib
tspec ts set --remove linker.args -static
```

### Why this works

1. **No quoting for scalars** — `key` and `value` are separate shell tokens
2. **No brackets or inner quotes for arrays** — each element is a separate arg; the field registry already knows whether a field is scalar or array, so tspec auto-handles it
3. **No `+=`/`-=` encoded in strings** — `--append`/`--remove` flags are explicit and shell-friendly
4. **`--` escape hatch** — standard POSIX convention for values that look like flags

### The clap change

```rust
Set {
    /// Field key (e.g., "rustc.lto", "linker.args")
    key: String,
    /// Value(s). Multiple values set an array.
    #[arg(required = true)]
    value: Vec<String>,
    /// Append to array instead of replacing
    #[arg(short = 'a', long = "append")]
    append: bool,
    /// Remove from array
    #[arg(short = 'r', long = "remove")]
    remove: bool,
    #[arg(short = 'p', long = "package")]
    package: Option<String>,
    #[arg(short = 't', long = "tspec")]
    tspec: Option<String>,
}
```

Then in the handler: if the field is scalar, `value[0]` is the value. If it's an array, the full `Vec<String>` becomes the array elements. No `parse_assignment()`, no `parse_array_value()` bracket/quote gymnastics.

### Backward compatibility

You could keep the old `key=value` form working by detecting an `=` in the first positional and falling back, but honestly it might be better to just break it cleanly — the old syntax is the problem.

The issue with `set` + flags is that "append to an array" and "set a scalar" aren't the same operation with a mode switch — they're fundamentally different verbs. Making them orthogonal means each operation gets its own command:

### Proposed design

| Command | Purpose | Scope |
|---|---|---|
| `ts set` | Set scalar or replace entire array | whole field |
| `ts unset` | Remove entire field | whole field |
| `ts add` | Add items to array | array items |
| `ts remove` | Remove items from array by value | array items |

`set`/`unset` operate on **fields**. `add`/`remove` operate on **items within arrays**. Two separate axes.

Insert is a modifier on `add` — you're still adding, just at a position:

```bash
# === Field-level (set/unset) ===

# Scalars
tspec ts set rustc.lto true
tspec ts set cargo.profile release

# Replace entire array
tspec ts set linker.args -- -static -nostdlib

# Remove entire field
tspec ts unset linker.args

# === Item-level (add/remove) ===

# Append (default add)
tspec ts add linker.args -- -Wl,--gc-sections
tspec ts add rustc.flags -- -Cforce-frame-pointers=yes -Clink-dead-code=no

# Insert at position
tspec ts add -i 0 linker.args -- -nostdlib

# Remove specific items
tspec ts remove linker.args -- -static
tspec ts remove linker.args -- -static -nostdlib
```

### The five array operations, all distinct

```bash
ts set    linker.args -- -static -nostdlib    # replace all with these
ts unset  linker.args                         # clear the field
ts add    linker.args -- -Wl,--gc-sections    # append
ts add -i 0 linker.args -- -nostdlib          # insert at position
ts remove linker.args -- -static              # remove by value
```

### Clap definitions

```rust
/// Set a field (scalar value or replace entire array)
Set {
    key: String,
    #[arg(required = true)]
    value: Vec<String>,
    ...
}

/// Add items to an array field (append, or insert at position)
Add {
    key: String,
    #[arg(required = true)]
    value: Vec<String>,
    /// Insert at this index instead of appending
    #[arg(short = 'i', long = "index")]
    index: Option<usize>,
    ...
}

/// Remove items from an array field by value
Remove {
    key: String,
    #[arg(required = true)]
    value: Vec<String>,
    ...
}

/// Remove a field entirely (already exists)
Unset { key: String, ... }
```

### Why this is orthogonal

- **No flags that change the fundamental operation** — each verb does one thing
- **`add` and `remove` are a natural pair** — symmetric item-level operations
- **`set` and `unset` are a natural pair** — symmetric field-level operations
- **`--index` on `add` is the only modifier**, and it doesn't change *what* it does (add items), only *where*
- **`add` deduplicates** — if the item's already there, no-op. Want duplicates? Use `set` to replace the whole array

Good instinct, but the issue isn't the shell — it's **clap's argument parser**. When clap sees:

```bash
tspec ts set linker.args -static -nostdlib
```

It tries to parse `-static` as flags: `-s`, `-t` (matches `--tspec`!), `-a`, `-t`, `-i`, `-c`. This happens regardless of whether the command is builtin or spawned.

**However**, clap has `allow_hyphen_values = true` which solves this:

```rust
/// Value(s). For scalars, one value. For arrays, each arg is an element.
#[arg(required = true, allow_hyphen_values = true)]
value: Vec<String>,
```

With this, clap treats unknown hyphen-prefixed tokens as positional values instead of trying to parse them as flags. So `-static`, `-nostdlib`, `-Wl,--gc-sections` all just work.
