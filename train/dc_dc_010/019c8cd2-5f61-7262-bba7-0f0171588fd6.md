I checked the latest open issue (`#133`, created February 23, 2026): [Issue 133](https://github.com/peteromallet/desloppify/issues/133).

**Root Cause**
- Counts are coming from different scopes without labels.
- Scoped stats are computed from `scan_path` via [`path_scoped_findings`](#/user_c042661f/Documents/desloppify/desloppify/engine/_state/filtering.py:26) and used in [`_recompute_stats`](#/user_c042661f/Documents/desloppify/desloppify/engine/_state/scoring.py:359).
- Out-of-scope findings are intentionally not auto-resolved during subset scans ([`auto_resolve_disappeared`](#/user_c042661f/Documents/desloppify/desloppify/engine/_state/merge_findings.py:78)).
- Scan/status surfaces scoped `stats.open` (for example [`show_score_delta`](#/user_c042661f/Documents/desloppify/desloppify/app/commands/scan/scan_reporting_summary.py:105)), while raw state is global.
- `issues` has additional semantic mismatch: it lists only open `review` detector findings globally ([`list_open_review_findings`](#/user_c042661f/Documents/desloppify/desloppify/engine/_work_queue/issues.py:40)), not `subjective_review`.
- `issues --state` is ambiguous and currently interpreted as file path ([parser](#/user_c042661f/Documents/desloppify/desloppify/app/cli_support/parser_groups_admin.py:253), [state resolver](#/user_c042661f/Documents/desloppify/desloppify/app/commands/helpers/state.py:12)); if path doesn’t exist, load silently returns empty state ([`load_state`](#/user_c042661f/Documents/desloppify/desloppify/engine/_state/persistence.py:48)).

**Best Approach**
- Keep current merge semantics (do not auto-resolve out-of-scope). They are correct for partial scans.
- Add one shared “scope breakdown” helper (in-scope open, out-of-scope carried open, global open; same for `subjective_review`) and use it everywhere counts are printed.
- Update `status` and scan summary to print explicit reconciliation:
  - `open (in-scope)`
  - `open (out-of-scope carried)`
  - `open (global total)`
- Update subjective coverage output to show scoped + out-of-scope + global (currently scoped-only in [`scan_reporting_subjective.py`](#/user_c042661f/Documents/desloppify/desloppify/app/commands/scan/scan_reporting_subjective.py:348)).
- Rename `issues --state` to `--state-file`, keep `--state` deprecated alias with warning, and hard-fail on status-like values (`resolved`, `open`, etc.) when passed as state path with a guidance error.
- Optional follow-up: add `issues list --status` after the above (not required to fix the core confusion immediately).

This is a UX/terminology bug, not a data integrity bug. The fastest safe fix is explicit dual-count labeling plus `--state-file` cleanup. If you want, I can implement this as a focused PR with tests next.
