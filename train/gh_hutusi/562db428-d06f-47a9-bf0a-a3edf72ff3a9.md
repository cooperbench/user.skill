### 2. **Theme Switching Mechanism**

**Files involved**:
- `/Users/hutusi/workspace/ai/naive/agentcenter-nuxt/app/composables/useTheme.ts` (26 lines)
- `/Users/hutusi/workspace/ai/naive/agentcenter-nuxt/app/components/layout/ThemeSwitch.vue` (23 lines)
- `/Users/hutusi/workspace/ai/naive/agentcenter-nuxt/shared/theme.ts` (10 lines)

**How it works** (from `useTheme.ts`):
1. **Cookie-backed state**: `useCookie<Theme>("theme", { default: () => "ivory", sameSite: "lax", maxAge: 60*60*24*365 })`
2. **Validation**: Invalid cookie values reset to "ivory" via `isValidTheme()` check
3. **Class application**: `useHead({ htmlAttrs: { class: computed(() => cookie.value === "dark" ? "dark" : "") } })`
   - This sets the `class` attribute on the `<html>` root element
   - Called synchronously in `app.vue`'s `<script setup>` so Nuxt's `useHead` serializes it into the SSR HTML before response streams
4. **Toggle function**: `toggle()` flips between "ivory" and "dark"
5. **Set function**: `set(theme)` directly sets a theme value

**ThemeSwitch component** displays a Moon icon (when on ivory) or Sun icon (when on dark), with i18n labels:
```vue
<button @click="toggle">
  <Moon v-if="theme === 'ivory'" /> 
  <Sun v-else />
</button>
```

**No-flash-on-hydrate trick**: 
- The cookie is read on the server during SSR
- The class is serialized into the initial HTML response
- On client hydration, Vue reads the same cookie and applies the same class (no mismatch, no flash)
- Only happens if `useTheme()` is called in a top-level setup context (`app.vue`)
