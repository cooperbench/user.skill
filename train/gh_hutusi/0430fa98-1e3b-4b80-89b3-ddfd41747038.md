> AGENT

AVIF itself is excellent — better compression than WebP, and widely supported in modern browsers. The problem was specific to `next-image-export-optimizer`'s handling of AVIF **source** files. It has a bug: when the source is `.avif`, it writes optimized `.WEBP` output but generates srcset paths with `.AVIF` extension — a mismatch. If this project used Next.js's **built-in** image optimization (server mode), AVIF would work perfectly fine — Next.js can serve AVIF output natively. The limitation is the toolchain choice here: `output: "export"` (static site) → `next-image-export-optimizer` → which has this AVIF source bug. **Practical rule for this project:** Use `.jpg`, `.png`, or `.webp` as source images for cover images. The optimizer will convert them to WebP at build time, which is fine for the target browsers. AVIF as a **source** format is the problematic case, not as an output format. You could also file a bug upstream with `next-image-export-optimizer` — the fix in their code would be a one-liner on line 29 of `ExportedImage.js`, changing: ```js // current — excludes AVIF from WebP substitution ["JPG", "JPEG", "PNG", "GIF"].includes(extension.toUpperCase()) ``` to: ```js // fixed — also converts AVIF sources to WebP output paths ["JPG", "JPEG", "PNG", "GIF", "AVIF"].includes(extension.toUpperCase()) ```
