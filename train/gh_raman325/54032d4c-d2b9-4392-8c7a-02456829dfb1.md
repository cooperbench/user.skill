1	# Lock Code Manager
2	
3	Lock Code Manager is a Home Assistant integration that keeps PIN codes in sync
4	across one or more locks, even across different lock providers (e.g. Z-Wave and
5	Matter locks sharing the same codes). Define your codes once and Lock Code
6	Manager handles setting, clearing, and monitoring them on every lock.
7	
8	Features:
9	
10	- Synchronize PIN codes across multiple locks and providers
11	- Automatic sync — codes are set and cleared as needed, with retry and
12	  drift detection
13	- Condition entities control when a code is active:
14	  - `calendar` — active during events
15	  - `binary_sensor` / `switch` / `input_boolean` — active when on
16	  - `schedule` — active during scheduled times
17	- [Blueprints](https://github.com/raman325/lock_code_manager/wiki/Blueprints)
18	  for usage limiting, calendar-driven PINs, and more
19	- Dashboard cards for managing codes and viewing lock status
20	
21	Supported lock integrations:
22	
23	| Integration | Read PINs | Push Updates | Code Events | Notes |
24	| --- | --- | --- | --- | --- |
25	| [Z-Wave][wiki-zwave] | Varies | ✅ | ✅ | Some locks mask PINs |
26	| [Zigbee2MQTT][wiki-zigbee2mqtt] (MQTT)² | Varies | ✅ | ✅ | Same broker as Z2M; PIN support depends on lock |
27	| [Matter][wiki-matter] | ❌ | ✅ | ✅ | PINs write-only per spec |
28	| [Schlage WiFi][wiki-schlage] | ❌ | ❌ | ❌ | Cloud-based, PINs masked |
29	| [Akuvox][wiki-akuvox]¹ | ✅ | ❌ | ❌ | Local API, polling-based |
30	| [Virtual][wiki-virtual]¹ | ✅ | ❌ | ❌ | For testing only |
31	
32	¹ Custom integration required ([Local Akuvox][local-akuvox],
33	[hass-virtual][hass-virtual])
34	
35	² **Zigbee2MQTT (MQTT)** — Pair the lock in [Zigbee2MQTT][zigbee2mqtt] with PIN/user-code support for your firmware.
36	The **Code Events** column refers to PIN-used automations from Lock Code Manager’s event entity
37	(which slots were used to lock/unlock).
38	Zigbee2MQTT lock/unlock actions with user identification are mapped to code slot events for PIN-used automations.
39	Configure Home Assistant’s **MQTT** integration on the **same broker** Zigbee2MQTT uses.
40	The default Zigbee2MQTT base topic `zigbee2mqtt` matches what Lock Code Manager expects unless you customize topics
41	(`{base_topic}/{friendly_name}/set|get`).
42	During LCM setup, choose your `lock.*` entity from **MQTT**.
43	If you rename the device in HA, keep it aligned with the **friendly name** in Zigbee2MQTT.

71	## Installation
72	
73	The best way to install this integration is via HACS.
74	
75	1. Set up your locks in Home Assistant through a supported integration
76	   (Z-Wave, Matter, Schlage, Zigbee2MQTT/MQTT, etc.)
77	2. Add this repository as a custom integration repository in HACS
78	3. Go to Settings > Devices & Services > Add Integration
79	4. Select Lock Code Manager
80	5. Follow the prompts - additional information about the configuration options are
81	   available in the Wiki

83	## Blueprints
84	
85	Pre-built automations and templates for common lock management
86	patterns. See [BLUEPRINTS.md](BLUEPRINTS.md) for full details,
87	input tables, and import buttons.
88	
89	### Template blueprints
90	
91	- **Calendar Condition** — Binary sensor for calendar-based slot access
92	- **Date Range Condition** — Binary sensor for start/end date access
93	
94	### Automation blueprints
95	
96	- **Slot Usage Limiter** — Disable a slot after a set number of uses
97	- **Calendar PIN Setter** — Extract and set PINs from calendar events
98	- **Auto Re-lock** — Re-lock after a delay with day/night support
99	- **Lock on Door Close** — Lock when a door sensor detects closure
100	- **Slot Usage Notifier** — Notify when a code slot PIN is used
101	- **Condition Linker** — Assign a condition entity to a slot via UI
102

109	
110	Lock Code Manager provides Lovelace strategies and custom cards for managing PINs.

114	## Inspiration
115	
116	I am a [keymaster](https://github.com/FutureTense/keymaster) maintainer,
117	and what I learned working on it, and the regular complaints users had about it generating
118	too many automations, entities, etc. led me to take a different approach. This isn't a
119	knock on `keymaster`, unfortunately a lot of what is built in this integration wasn't
120	possible for most of `keymaster`'s life. I briefly considered implementing this into
121	`keymaster` but:
122	
123	1. `keymaster` is still a great solution that works as is.
124	2. `keymaster` is surprisingly simple under the hood because it makes Home Assistant do a
125	   lot of the heavy lifting for figuring out when to enable and disable a usercode. This
126	   integration, on the other hand, attempts to do all of the heavy lifting internally in
127	   code, which means it will generate less entities and automations but it is likely more
128	   fragile to changes in HA Core or even changes in the codebase.
129	3. It would be impossible to seamlessly migrate users from the current implementation of
130	   `keymaster` to this integration's implementation. Rewriting `keymaster` to do this
131	   would have been the equivalent of creating a new integration anyway.
132

1	# ZHA (Zigbee Home Automation) Integration
2	
3	Lock Code Manager supports Zigbee locks connected through the [ZHA](https://www.home-assistant.io/integrations/zha/) integration.
4	
5	## How It Works
6	
7	Lock Code Manager communicates directly with the lock's zigpy DoorLock cluster through ZHA. PIN codes are read, set, and cleared using the standard ZCL DoorLock cluster commands (`get_pin_code`, `set_pin_code`, `clear_pin_code`).
8	
9	PIN codes are **readable** on most Zigbee locks — the lock returns the actual PIN value, not a masked placeholder. This enables full sync verification without relying on optimistic updates.
10	
11	## Requirements
12	
13	- [ZHA](https://www.home-assistant.io/integrations/zha/) integration set up and running in Home Assistant
14	- A Zigbee lock that supports PIN codes (e.g., Kwikset 914, Yale YRD256, or similar models with the DoorLock cluster)
15	- The lock entity must appear as `lock.*` from the `zha` integration in Home Assistant
16	
17	## Supported Operations
18	
19	| Operation | Supported | Notes |
20	|-----------|-----------|-------|
21	| Set PIN | Yes | Via zigpy `set_pin_code` cluster command |
22	| Clear PIN | Yes | Via zigpy `clear_pin_code` cluster command |
23	| Read PIN | Yes | Via zigpy `get_pin_code` — actual PINs returned |
24	| Push updates | Yes | Via zigpy cluster listeners for operation and programming events |
25	| Code slot events | Yes | Lock/unlock with user identification via operation event notifications |
26	
27	## Push Updates
28	
29	Lock Code Manager subscribes to the DoorLock cluster as a zigpy listener and receives two types of events:
30	
31	- **Operation event notifications** (`0x20`): Fired when the lock is locked or unlocked, including the source (keypad, RF, manual) and user ID. These are mapped to Lock Code Manager code slot events for automations.
32	- **Programming event notifications** (`0x21`): Fired when a PIN code is added, modified, or deleted on the lock. These trigger a coordinator refresh to pick up the change.
33	
34	### Programming Event Detection
35	
36	Not all locks support programming event notifications. Lock Code Manager automatically detects support by reading the lock's event mask attributes (`keypad_programming_event_mask`, `rf_programming_event_mask`, `rfid_programming_event_mask`). If no mask attributes have non-zero values, Lock Code Manager falls back to hourly drift detection polling to catch out-of-band changes.
37	
38	## Limitations
39	
40	- **No user names**: The ZCL DoorLock cluster does not have a concept of user names attached to PIN slots. The `name` parameter in `async_set_usercode` is accepted but ignored by the lock hardware.
41	- **Sequential slot queries**: PIN codes are fetched one slot at a time. This is slower than a bulk read but necessary because the DoorLock cluster only supports per-slot queries.
42	- **Programming event support varies**: Some lock models do not fire programming event notifications. Lock Code Manager detects this and enables drift detection as a fallback.
43	
44	## Verified Locks
45	
46	The following locks have been tested with Lock Code Manager via ZHA:
47	
48	- Kwikset 914 (ZNP coordinator over network)
49	
50	If you have tested Lock Code Manager with a specific Zigbee lock via ZHA, please open an issue or PR to add it to this list.
51	
52	## ZHA vs Zigbee2MQTT
53	
54	Both ZHA and Zigbee2MQTT support Zigbee locks, but they use different communication paths:
55	
56	| | ZHA | Zigbee2MQTT |
57	|--|-----|-------------|
58	| Communication | Direct zigpy cluster commands | MQTT publish/subscribe |
59	| PIN readback | Direct from lock | Depends on `expose_pin` setting |
60	| Push updates | Cluster listener callbacks | MQTT subscription |
