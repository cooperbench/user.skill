# Custom Dashboard Strategy Registration in Home Assistant 2026.5

## What Changed

Previously, developers had to manually guide users through a cumbersome process: create a blank dashboard, switch to YAML editing mode, and paste custom strategy code. Home Assistant 2026.5 introduced a registration system that mirrors custom card functionality, enabling automatic discovery and simplified addition through the dashboard UI.

## The New API

The mechanism centers on `window.customStrategies.push()`, which accepts configuration objects with these properties:

- **`type`**: Strategy identifier (without `custom:` prefix)
- **`strategyType`**: Must be set to `"dashboard"`
- **`name`**: Human-readable title
- **`description`** (optional): Brief overview
- **`documentationURL`** (optional): Reference documentation link

## Code Example

```javascript
window.customStrategies = window.customStrategies || [];

window.customStrategies.push({
  type: "my-demo",
  strategyType: "dashboard",
  name: "My demo dashboard",
  description: "A starter dashboard generated from JavaScript.",
  documentationURL: "https://example.com/my-demo-dashboard",
});
```

## Implementation Notes

The metadata registration remains separate from the custom element itself. Developers still must register the strategy with a tag like `ll-strategy-dashboard-my-demo`, and users need the resource loaded beforehand. HACS can distribute these resources alongside other frontend components.

1	# UI Strategies
2	
3	Strategies are Lovelace generators: you write a small block of YAML, and Home Assistant calls into Lock Code Manager at render time to produce the views, sections, and cards. The strategy reads your LCM config entries directly, so it stays in sync as slots and locks are added or removed without you having to edit the dashboard.
4	
5	LCM ships **four** strategies, all under the `custom:lock-code-manager*` family. They differ in **what scope of your LCM data** they render:
6	
7	| Strategy | Scope | Output |
8	|---|---|---|
