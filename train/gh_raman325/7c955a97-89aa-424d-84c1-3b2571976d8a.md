can you explain what's happening with the started variable?

> AGENT

The `started` flag tracks whether the `EVENT_HOMEASSISTANT_STARTED` event has already fired and our `_on_started` callback ran. **The problem:** `async_listen_once` auto-removes the listener after it fires. If HA has already started and unload runs later, calling `unsub()` tries to remove a listener that's already gone. HA core logs an ERROR inside `_async_remove_listener` *before* raising `ValueError` — so even though the old code caught the `ValueError`, the error message was already emitted to the log. **The fix:** When `_on_started` fires, it sets `started = True`. Then `_safe_unsub` checks: if `started` is `True`, the listener already auto-removed itself, so we skip calling `unsub()` entirely. This avoids ever hitting `_async_remove_listener` with a missing listener, so no error is logged. Both `_on_started` and `_safe_unsub` run on the event loop (both are `@callback`), so there's no race between them — `started` is always read/written from the same thread.
