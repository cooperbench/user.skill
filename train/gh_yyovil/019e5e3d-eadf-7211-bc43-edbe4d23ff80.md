`.unit.spec.ts` is just a naming convention layered on top of Vitest’s normal test-file discovery. Breakdown: - `.ts`: TypeScript file. - `.spec`: “specification” file, meaning a test file that describes expected behavior. - `.unit`: this repo’s extra label saying “run this as a unit test”. So: ```txt terminal-connection.unit.spec.ts ``` means: ```txt terminal-connection unit test specification TypeScript ``` `.spec.ts` and `.test.ts` are usually equivalent semantically. Many teams use either: ```txt foo.test.ts foo.spec.ts ``` The word “spec” comes from behavior/specification-style testing: “this code should behave like this.” It is common in Jest, Vitest, Jasmine, RSpec-inspired ecosystems, etc. The important part in this repo is the middle segment: ```txt .unit.spec.ts .browser.spec.tsx ``` That segment controls which Vitest project runs the file. In `web/vitest.config.ts`, unit tests are matched by: ```ts src/**/*.unit.{test,spec}.?(c|m)[jt]s?(x) ``` Browser tests are matched by: ```ts src/**/*.browser.{test,spec}.?(c|m)[jt]s?(x) ``` So these would all be valid unit test names here: ```txt terminal-connection.unit.spec.ts terminal-connection.unit.test.ts ``` And these would be browser tests: ```txt field-text.browser.spec.tsx field-text.browser.test.tsx ``` Practically, `.unit.spec.ts` says: “this is a Vitest test file, specifically for pure unit logic, and it should run in Node rather than in a browser.” The repo could have chosen `.unit.test.ts` instead; `.spec` is not special beyond being included in the configured glob.
