# Improve Codebase Architecture

Surface architectural friction and propose **deepening opportunities** — refactors that turn shallow modules into deep ones. The aim is testability and AI-navigability.

## Glossary

Use these terms exactly in every suggestion. Consistent language is the point — don't drift into "component," "service," "API," or "boundary." Full definitions in [LANGUAGE.md](LANGUAGE.md).

- **Module** — anything with an interface and an implementation (function, class, package, slice).
- **Interface** — everything a caller must know to use the module: types, invariants, error modes, ordering, config. Not just the type signature.
- **Implementation** — the code inside.
- **Depth** — leverage at the interface: a lot of behaviour behind a small interface. **Deep** = high leverage. **Shallow** = interface nearly as complex as the implementation.
- **Seam** — where an interface lives; a place behaviour can be altered without editing in place. (Use this, not "boundary.")
- **Adapter** — a concrete thing satisfying an interface at a seam.
- **Leverage** — what callers get from depth.
- **Locality** — what maintainers get from depth: change, bugs, knowledge concentrated in one place.

- **Deletion test**: imagine deleting the module. If complexity vanishes, it was a pass-through. If complexity reappears across N callers, it was earning its keep.

- **One adapter = hypothetical seam. Two adapters = real seam.**

async function openTerminalAttachment(browser, webOrigin, selectedSession) {
  const page = await browser.newPage({
    viewport: { width: 1440, height: 900 },

  const pageErrors = [];

    pageErrors.push(error.message);

    if (!socket.url().includes('/api/sessions/')) {
      return;
    }

    const terminalSocket = {
      closed: false,
      received: 0,
      sent: 0,
      sentPayloads: [],
      url: socket.url(),
    };

      terminalSocket.sent += 1;
      terminalSocket.sentPayloads.push(decodeFramePayload(frame.payload));

      terminalSocket.received += 1;
    });
    socket.on('close', () => {
      terminalSocket.closed = true;
    });

    const timeout = setTimeout(() => {

        new Error(
          `Timed out waiting for better-ao stack origins.\n\n${output.trim()}`

      );
    }, stackTimeoutMs);

    const fail = (error) => {
      if (settled) {
        return;
      }

      settled = true;
      clearTimeout(timeout);
      rejectOrigins(error);
    };

    const maybeResolve = () => {
      if (settled || !backendOrigin || !webOrigin) {
        return;
      }

      settled = true;
      clearTimeout(timeout);
      resolveOrigins({ backendOrigin, webOrigin });
    };

    const capture = (chunk, stream) => {
      const text = chunk.toString();
      output += text;
      stream.write(text);

      const backendMatch = text.match(/better-ao backend:\s*(\S+)/);
      if (backendMatch) {
        backendOrigin = backendMatch[1];
      }

      const webMatch = text.match(/better-ao web:\s*(\S+)/);
      if (webMatch) {
        webOrigin = webMatch[1];
      }

      maybeResolve();
    };

    child.stdout.on('data', (chunk) => capture(chunk, process.stdout));
    child.stderr.on('data', (chunk) => capture(chunk, process.stderr));
    child.on('error', fail);
    child.on('exit', (code, signal) => {
      if (settled) {
        return;
      }

      fail(
        new Error(
          `better-ao stack exited before it was ready: code=${code} signal=${signal}\n\n${output.trim()}`
        )
      );
    });
  });
}

# Go-First Cleanup And Rebuild Plan

## Summary

Clean up the repo so JavaScript only builds/tests the React frontend, while all runtime, CLI, dev-stack orchestration, packaging, and embedded-dashboard serving are owned by Go.

## Cleanup

- Delete the root `scripts/` directory entirely.
- Remove the root `package.json` `bin` entry and all script entries that make Node look like the product CLI: `better-ao`, `dev`, `backend:*`, `cli:test`, `api:generate`, and root combined `build/lint/test` orchestration.
- Keep root pnpm only as a workspace/frontend convenience layer: `web:dev`, `web:build`, `web:lint`, `web:test`, `web:e2e`, plus `prepare` for lefthook if still needed.
- Move repo-level orchestration to `justfile`: `dev`, `build`, `test`, `lint`, and `api-generate` should call Go directly and call pnpm only for `web`.
- Update README, `web/AGENTS.md`, CI, Playwright config, and the live terminal smoke test so nothing points at `scripts/*.mjs`.

## Build Back In Go

- Add a Go-owned `dev` command under `cmd/better-ao`.
  - It starts the Go API/terminal server and spawns `pnpm --dir web dev`.
  - It resolves backend/web ports in Go, preserving `BETTER_AO_BACKEND_HOST`, `BETTER_AO_BACKEND_PORT`, and `VITE_PORT`.
  - It prints `better-ao backend: <url>` and `better-ao web: <url>` so existing smoke tooling can keep parsing origins.
  - It owns signal handling and terminates the Vite child process cleanly.
- Keep `start`/`dashboard` as packaged runtime commands.
  - They serve the built frontend from Go, never by spawning Node.
  - They open the Go-served dashboard URL when `-open=true`.
- Replace `server.Config.WebDir string` with a dashboard filesystem interface, using `fs.FS`.
  - Production builds use embedded `web/dist`.
  - Dev/non-embedded builds can still serve `web/dist` from disk if it exists, otherwise show the existing “build the dashboard first” fallback.
- Add a small Go frontend-asset adapter with an `embed_web` build tag.
  - Normal `go test ./...` works without `web/dist`.
  - Release builds run `pnpm --filter @better-ao/web build` and then `go build -tags embed_web -o ./bin/better-ao ./cmd/better-ao`.

## Test Plan

- `go test ./...`
- `pnpm --filter @better-ao/web lint`
- `pnpm --filter @better-ao/web test:ci`
- `pnpm --filter @better-ao/web build`
- `go build -tags embed_web -o ./bin/better-ao ./cmd/better-ao`
- `node --check web/e2e/live-terminal-smoke.mjs`
- Run the live terminal smoke against the new Go dev command: `pnpm e2e:live-terminal` or the equivalent `just` target.

## Assumptions

- Root pnpm stays only because this is a pnpm workspace with a frontend package.
- End users receive and run the Go binary only.
- Node/pnpm are development/build dependencies, not runtime dependencies.
- `just dev` becomes the preferred local full-stack command; `pnpm --filter @better-ao/web dev` remains frontend-only.
