In `better-ao`, layout is mostly built as a **composable shell pattern**: a root route renders global providers + `Outlet`, then the home route renders a workspace template with pluggable regions (`sidebar`, `topbar`, `main`).

The practical techniques are:

- **Shell-first composition**  
  Root layout keeps app-wide concerns (theme, query client, toasts, global CSS) in providers, then hands control to route content.  
  - [web/src/routes/__root.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/routes/__root.tsx)  
  - [web/src/providers.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/providers.tsx)

- **Single high-level template** for home/workspace  
  The active page composes:
  - sidebar region  
  - top bar  
  - main content region  
  into one root template.  
  - [web/src/features/home/pages/orchestrator-home-page.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/pages/orchestrator-home-page.tsx)  
  - [web/src/features/home/templates/orchestrator-workspace-template.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/templates/orchestrator-workspace-template.tsx)

- **Reusable layout primitive (`ui/sidebar`)**  
  The sidebar system is stateful and reusable rather than page-local:
  - desktop + mobile modes (drawer on small screens),
  - open/collapsed state + width state,
  - `Ctrl/Cmd + B` keyboard toggle,
  - persisted state in cookie,
  - resize logic with min/max constraints.  
  - [web/src/components/ui/sidebar.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/components/ui/sidebar.tsx)

- **Primary sidebar content pattern**  
  Active implementation uses semantic sections (`Header`, `Content`, `Group`, `Menu`) with collapsible nested items for project/workspace/session hierarchies.  
  - [web/src/features/home/components/organisms/project-orchestrator-sidebar.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/organisms/project-orchestrator-sidebar.tsx)

- **Topbar + tabbed content switching as layout control surface**  
  Topbar is grid-based and contains toggle + session tabs + actions; tabs implement custom keyboard behavior and constrained widths for compactness.  
  - [web/src/features/home/components/organisms/main-topbar.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/organisms/main-topbar.tsx)  
  - [web/src/features/home/components/molecules/session-view-tabs.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/molecules/session-view-tabs.tsx)

- **Panel-based main workspace**  
  Main content uses split/overlay behavior with conditional visibility for kanban/terminal sections and preserves terminal mount state once opened.  
  - [web/src/features/home/components/organisms/session-workspace-panel.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/organisms/session-workspace-panel.tsx)

- **Kanban layout behavior**  
  Uses horizontal scroll with responsive minimum-width constraints (and breakpoint-based relaxing) plus column-level internal scroll/fixed-height balancing.  
  - [web/src/features/home/components/organisms/kanban-board.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/organisms/kanban-board.tsx)  
  - [web/src/features/home/components/organisms/kanban-column.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/organisms/kanban-column.tsx)

- **Terminal panel behavior**  
  Overlay controls, fullscreen sizing (`h-dvh`, `w-dvw`), and absolute-positioned header controls integrated into the same shell.  
  - [web/src/features/home/components/organisms/terminal-panel.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/organisms/terminal-panel.tsx)

- **Modal/drawer conventions**  
  Dialogs and sheets are reusable; for example settings uses two-column responsive dialog with scrollable detail pane, preserving the same spacing/radius/transition system.  
  - [web/src/features/home/components/organisms/settings-dialog.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/organisms/settings-dialog.tsx)

- **Design-tokenized global styling**  
  `app.css` defines viewport-safe vars, custom radii/breakpoints/colors, sidebar terminal tokens, and `dvh` behavior, so layout behavior is driven by tokens + utility classes rather than hardcoded numbers.  
  - [web/src/styles/app.css](/Users/tanishqpalandurkar/Projects/better-ao/web/src/styles/app.css)

There is also a legacy/alternate sidebar variant (`worker-sessions-sidebar.tsx`) still in-tree, but the currently active composition is the **single-shell sidebar + topbar + main content** structure above.
