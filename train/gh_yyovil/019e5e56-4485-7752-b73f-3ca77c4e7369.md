# better-ao

Local-first agent orchestration for parallel AI coding work

## Requirements

- Go 1.25+
- Node.js 22+
- pnpm
- Nix with flakes enabled, optional but recommended

## Development

```bash
nix develop
pnpm install
better-ao
```

The `better-ao` dev command starts both the Vite dashboard and the Go API/terminal server from the current checkout. The dashboard runs on `http://localhost:3000` by default. Set `VITE_PORT` in `web/.env` to use another port. If the default backend port is already in use, the launcher picks the next available local backend port and points Vite at it.

If you are not using the Nix shell, use the package script instead:

```bash
pnpm dev
```

## Real AO Terminal Runtime

The Terminal tab reads the local Agent Orchestrator runtime from `~/.agent-orchestrator`. It lists active orchestrator and worker sessions from `running.json` plus each project's `sessions/*.json` metadata, then attaches the browser terminal to the selected session's real runtime:

- Zellij-backed AO sessions attach with `zellij attach <session>`.
- Legacy tmux-backed AO sessions seed browser scrollback with `tmux capture-pane`, then attach with `tmux attach-session -t =<session>`.
- Windows process-backed AO sessions attach through the AO named-pipe terminal protocol when metadata exposes a `pipePath`.
- Terminal websocket URLs include both the session id and project id, so duplicate session ids across projects still attach to the right runtime.

The browser terminal attachment is separate from the underlying AO runtime. Browser reconnects may recreate the attach process, but they should not kill the AO worker or orchestrator session. If there are no active AO workers, the dashboard shows an empty state instead of demo sessions while still exposing the project orchestrator when AO metadata reports one.

Zellij is the preferred durable-session runtime. tmux support exists as compatibility for existing AO metadata that still reports `runtimeName: "tmux"`.

`pnpm e2e:live-terminal` is the real-runtime smoke. It starts the local stack on OS-assigned temporary ports, reads active AO worker metadata, opens the Terminal tab with Playwright, confirms the terminal websocket is project-scoped, waits for real terminal frames, verifies browser resize sends a valid terminal resize control frame, then verifies a tmux-backed worker session survived the browser attachment. It requires at least one active AO worker with terminal support and does not send keyboard input to the worker. Pass `--backend-port=<port>` and `--web-port=<port>` to the underlying script only when you need fixed ports.

`pnpm e2e:live-terminal:reuse` runs the same real-runtime smoke against an already-running manual dev stack. By default it checks `http://127.0.0.1:7331` and `http://localhost:3000`; pass `--backend-origin=<origin>` and `--web-origin=<origin>` to the underlying script for a different stack. Use the `reuse:*:watch` variants when you want to watch the already-running manual stack instead of a throwaway stack.

`pnpm e2e:live-terminal:reconnect` repeats that attachment through browser page reopens and fails if any reattached terminal websocket loses project scoping, stops receiving frames, stops sending resize control frames, or kills the tmux-backed worker session. Use `--reconnects=<count>` when running the underlying script directly.

`pnpm e2e:live-terminal:soak` keeps that real terminal attachment open and fails if the terminal websocket closes, the terminal UI disappears, browser page errors occur, or a tmux-backed worker session stops existing. It is still non-mutating: it observes terminal frames but does not type into the worker. Use `--soak-ms=<milliseconds>` when running the underlying script directly.

`pnpm e2e:live-terminal:switch` opens the selected worker terminal, switches the UI to another terminal-supported AO worker, confirms the new websocket is project-scoped, receiving real frames, and sending resize control frames, then verifies both tmux-backed worker sessions are still alive. Pass `--switch-target=<worker>` to force the target worker when running the underlying script directly; otherwise the script picks the next available terminal-supported worker.

Use the `:watch` variants when you want to see the same real-runtime smoke in a headed browser. They slow Playwright down and keep the terminal visible briefly after assertions pass. Use `pnpm e2e:live-terminal:soak:watch` for manual observation. Change the soak, reconnect, target, or hold values with `--soak-ms=<milliseconds>`, `--reconnects=<count>`, `--switch-target=<worker>`, and `--hold-ms=<milliseconds>` when running the underlying `web/e2e/live-terminal-smoke.mjs` script directly.

Use `pnpm e2e:live-terminal:manual` to open the current running stack in a headed browser and hold it for four hours after the initial real-runtime attach assertion. Use `pnpm e2e:live-terminal:manual-soak` when you want the same four-hour hold after a five-minute real-runtime soak. Script-level options are read from the last matching CLI value, so you can shorten a manual pass with `pnpm --dir web e2e:live-terminal:manual -- --hold-ms=60000`.

Manual terminal acceptance is:

1. Start or reuse a real AO worker so at least one terminal-supported session appears.
2. Start the local stack with `better-ao` or `pnpm dev`.
3. Run `pnpm e2e:live-terminal:manual-soak` from the repository root.
4. Watch the headed browser: terminal output should remain visible, reconnect/switch controls should not show failure toasts, and the selected worker should stay attached across workspace refreshes.
5. Let the terminal sit open or use the normal app for the intended manual window.
6. Treat the pass as failed if the final JSON reports a nonzero `terminalSocketCountDelta`, missing terminal frames, missing `resize.resizeFrame`, a non-`tmux` runtime for current AO metadata, or if the underlying tmux session disappears.

Current shape:

- [pnpm-workspace.yaml](/Users/tanishqpalandurkar/Projects/better-ao/pnpm-workspace.yaml:1) makes `web/` the workspace package.
- [web/package.json](/Users/tanishqpalandurkar/Projects/better-ao/web/package.json:2) is the actual frontend package, `@better-ao/web`.
- [package.json](/Users/tanishqpalandurkar/Projects/better-ao/package.json:21) pins pnpm, exposes the `better-ao` bin, and defines root commands.
- [flake.nix](/Users/tanishqpalandurkar/Projects/better-ao/flake.nix:37) makes the Nix `better-ao` command just run `pnpm dev` from the workspace root.
- [scripts/better-ao.mjs](/Users/tanishqpalandurkar/Projects/better-ao/scripts/better-ao.mjs:43) starts both sides: Go backend plus `pnpm --dir web dev`, wiring ports/env between them.

So the root npm package exists to give you one command surface: `pnpm install`, `pnpm dev`, `pnpm build`, `pnpm test`, `pnpm backend:test`, `pnpm web:lint`, etc. It also lets pnpm filters work cleanly against `@better-ao/web`.

It is not a runtime boundary for the Go backend. It is dev/build orchestration glue around a Go backend plus a web npm package.

Important caveat: this root package layout is in the current local scaffold diff. The root `package.json` used to be the frontend app package; now most frontend ownership has moved under `web/`, while root stayed as the workspace/task runner.
