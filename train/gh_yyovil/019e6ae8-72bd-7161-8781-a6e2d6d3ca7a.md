It’s custom-built on top of the shared shadcn-style sidebar, not a browser/CSS resize property. The actual resize handle is `SidebarRail` in [sidebar.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/components/ui/sidebar.tsx:364). On pointer down it captures the pointer, records `startX` and current sidebar width, listens to `pointermove`, computes the horizontal delta, then calls `setSidebarWidth(startWidth + delta)`. The width is stored in `SidebarProvider` as a controlled/uncontrolled number, clamped between `208px` and `420px`, then written into the CSS variable `--sidebar-width` on the wrapper: [sidebar.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/components/ui/sidebar.tsx:113). The desktop sidebar gap and fixed sidebar container both use `w-(--sidebar-width)`, so changing the variable resizes the whole layout: [sidebar.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/components/ui/sidebar.tsx:293). In the home workspace, that controlled width is wired through [orchestrator-workspace-template.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/templates/orchestrator-workspace-template.tsx:16), where `SidebarProvider` receives `width={props.sidebarWidth}` and `onWidthChange={props.onSidebarWidthChange}`. `workspace-layout.tsx` owns that state and persists it into localStorage preferences: [workspace-layout.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/pages/workspace-layout.tsx:47), [workspace-preferences.ts](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/data/workspace-preferences.ts:19).
