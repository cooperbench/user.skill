`handleWorkspace` is the backend endpoint behind `GET /api/workspace`. The method itself is intentionally thin: it asks the server for the current `session.Workspace`, returns `500` if that lookup fails, otherwise writes the workspace as JSON.

The important part is the delegation:

- Route registration: [internal/server/server.go](/Users/tanishqpalandurkar/Projects/better-ao/internal/server/server.go:77)
- Handler: [internal/server/server.go](/Users/tanishqpalandurkar/Projects/better-ao/internal/server/server.go:98)
- Workspace lookup: [internal/server/server.go](/Users/tanishqpalandurkar/Projects/better-ao/internal/server/server.go:181)

`workspaceForRequest` chooses between two sources. If `WorkspaceSource` is configured, it calls that dynamic provider. In the real app, this is wired to `ao.NewWorkspaceProvider()` in [internal/app/app.go](/Users/tanishqpalandurkar/Projects/better-ao/internal/app/app.go:36). That provider reads AO runtime/session metadata and maps it into the `session.Workspace` JSON shape. If no source is configured, it just returns the static `s.workspace`, which is mainly useful for tests or injected fixtures.

The frontend consumes it in [web/src/features/home/data/workspace.ts](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/data/workspace.ts:21): React Query fetches `/api/workspace`, validates the response with the generated Zod schema, and refreshes every 5 seconds. So conceptually, `handleWorkspace` is the dashboard’s read-only “current AO workspace snapshot” endpoint.
