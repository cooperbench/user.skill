- `/` or `/projects` renders the Kanban/workspace overview.
- Clicking a worker/orchestrator session in the sidebar navigates to the terminal route.
- Clicking the project/sidebar header, a small board icon, or “Workspace” nav target returns to Kanban.
- Terminal is no longer a “view mode”; it is a resource route.

That means Kanban should stay, but its job changes: it becomes the command center for session state, not a tab beside terminal. It answers “what is happening across workers?” Terminal answers “what is this session doing right now?”

In this checkout, the pieces to simplify are still the old tab model:

- [orchestrator-home-page.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/pages/orchestrator-home-page.tsx:41) owns `view`.
- [session-view-tabs.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/molecules/session-view-tabs.tsx:10) defines `kanban | terminal`.
- [session-workspace-panel.tsx](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/components/organisms/session-workspace-panel.tsx:23) renders hidden Kanban/Terminal branches.

One caution: I would avoid bare `/terminal/[sessionId]` unless session IDs are globally unique. The current app logic is already project-qualified. Better route shape would be something like `/projects/[projectId]/terminal/[sessionId]` or `/terminal/[projectId]/[sessionId]`. If you keep `/terminal/[sessionId]`, the route needs a deterministic ambiguity rule.

My recommendation: delete the top-level tabs entirely, make Kanban the default/root route, and make Terminal a route selected by sidebar session clicks. Keep Kanban as the overview surface.
