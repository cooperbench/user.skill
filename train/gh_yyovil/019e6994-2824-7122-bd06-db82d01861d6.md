`approval_policy` is only the prompt/confirmation rule. It answers: “when should Codex ask a human before running/escalating something?”

`permissions` in this repo is broader. [permissions.go](/Users/tanishqpalandurkar/Projects/better-ao/internal/plugin/agent/permissions.go:3) defines it as the agent’s filesystem, network, and approval boundary. The Codex plugin then maps that one Better-AO mode into multiple Codex CLI knobs in [codex.go](/Users/tanishqpalandurkar/Projects/better-ao/internal/plugin/agent/codex/codex.go:228):

- `default` -> `--sandbox workspace-write --ask-for-approval on-request`
- `auto-review` -> same sandbox/approval, plus `approvals_reviewer="auto_review"`
- `full-access` -> `--sandbox danger-full-access --ask-for-approval never`

So in Codex CLI terms:

- `--ask-for-approval` / `approval_policy`: human approval behavior.
- `--sandbox` / `sandbox_mode`: actual execution boundary for shell commands.
- Better-AO `Permissions`: our cross-agent mode that sets both together.

The important bit: `approval_policy = "never"` does not by itself mean full filesystem access. It only means “do not ask.” Full access comes from `sandbox_mode = "danger-full-access"` or `--sandbox danger-full-access`.
