The backend resolves that exact `project + sessionID` into a worker session, then uses that session’s `CWD`, so the diff is scoped to the current agent session worktree: [internal/server/diff.go](/Users/tanishqpalandurkar/Projects/yyork/internal/server/diff.go:58). 3. For tracked changes, it runs: `git -C <session cwd> diff --no-ext-diff --binary HEAD --` That unified diff output is where the normal hunk headers and hunk lines come from: [internal/server/diff.go](/Users/tanishqpalandurkar/Projects/yyork/internal/server/diff.go:101). 4. Separately, it runs: `git -C <session cwd> diff --numstat HEAD --` That is only for file summary counts, not for rendering hunks. 5. For untracked text files, Git does not include them in `git diff HEAD`, so we synthesize a valid “new file” patch by reading untracked regular text files and creating a `diff --git ...`, `new file mode`, `--- /dev/null`, `+++ b/path`, `@@ -0,0 +1,N @@` patch section: [internal/server/diff.go](/Users/tanishqpalandurkar/Projects/yyork/internal/server/diff.go:204). 6. The tracked patch and synthetic untracked patches get joined into `payload.patch`; if it exceeds `2 MiB`, we return no patch and set `patchTruncated`. 7. The frontend passes `diffQuery.data.patch` directly into `<PatchDiff patch={...} />`; `@pierre/diffs` parses the unified diff into files/hunks internally: [canvas-diff-view.tsx](/Users/tanishqpalandurkar/Projects/yyork/web/src/features/home/components/organisms/canvas-diff-view.tsx:153).
