The clean model is: keep `/` as the Kanban route, but make the selected project part of the route search state: `/?project=<projectId>`.

That gives us project-specific Kanban without adding a new path. It also preserves refresh, back/forward, copyable links, and avoids abusing `openProjectIds`, which is only sidebar disclosure state.

Current code shape supports this well:

- [`web/src/routes/_app.index.tsx`](/Users/tanishqpalandurkar/Projects/better-ao/web/src/routes/_app.index.tsx:5) owns `/`.
- [`web/src/routes/_app.terminal.$sessionId.tsx`](/Users/tanishqpalandurkar/Projects/better-ao/web/src/routes/_app.terminal.$sessionId.tsx:5) owns terminal detail.
- [`WorkspaceLayout`](/Users/tanishqpalandurkar/Projects/better-ao/web/src/features/home/pages/workspace-layout.tsx:37) already owns project/session selection state.
- The sidebar project row currently expands/collapses only; it does not navigate to a project board.

I’d implement it like this:

1. Add optional root search: `project?: string`.
2. In `WorkspaceLayout`, derive `selectedProjectId` from `?project=`, falling back to `workspace.activeProjectId` or the first visible project.
3. Keep `workspaceSessions` as all visible sessions for sidebar and terminal lookup, but compute `kanbanSessions` filtered to `selectedProjectId`.
4. Pass project-filtered columns to `KanbanPage`.
5. Add `onProjectSelect(projectId)` to the sidebar and navigate with `navigate({ to: '/', search: { project: projectId } })`.
6. UX-wise, make the project row’s primary action select/open that project Kanban; use a smaller chevron/folder disclosure action for expanding worker sessions.

That keeps the route truth simple: `/` means “Kanban surface”, `?project=` means “which project’s Kanban”. Terminal remains `/terminal/$sessionId`, and the existing encoded selection key already handles project collisions.

Why the fuck do we have "_app" in the filename for for route: "/"?

> AGENT

Because `_app` is a **pathless layout route**, not a URL segment.

In this repo:

- [`web/src/routes/_app.tsx`](/Users/tanishqpalandurkar/Projects/better-ao/web/src/routes/_app.tsx:5) mounts `WorkspaceLayout`.
- [`web/src/routes/_app.index.tsx`](/Users/tanishqpalandurkar/Projects/better-ao/web/src/routes/_app.index.tsx:5) is that layout’s index child, so it renders at `/`.
- [`web/src/routes/_app.terminal.$sessionId.tsx`](/Users/tanishqpalandurkar/Projects/better-ao/web/src/routes/_app.terminal.$sessionId.tsx:5) is another child, rendered at `/terminal/$sessionId`.

The underscore tells TanStack Router: “use this as a grouping/layout segment, but don’t put `app` in the URL.” So `_app.index.tsx` maps to `/`, not `/_app` or `/app`.

The reason it exists is to let `/` Kanban and `/terminal/$sessionId` share the same app shell: sidebar, topbar, workspace query/context, preferences, and selection logic. The name `_app` is just a convention for “app shell”.
