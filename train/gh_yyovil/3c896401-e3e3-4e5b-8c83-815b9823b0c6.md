[scripts/ao-doctor.sh](scripts/ao-doctor.sh) is the health-check / diagnostic script for Agent Orchestrator installs. Intended usage: **When to run it** - **After install or upgrade** — confirm the environment is ready before running `ao` for real. - **When something feels off** — launcher missing from PATH, stale locks, config dirs gone, a build that won't run. - **During support triage** — users paste the output so maintainers can see what's broken. **What it checks** - Toolchain prerequisites: Node 20+, git 2.25+, pnpm, tmux, gh (authed). - Install layout: `node_modules`, built `core` and `cli` dists, launcher entrypoint at [packages/agent-orchestrator/bin/ao.js](packages/agent-orchestrator/bin/ao.js). - The `ao` launcher resolves on PATH and `ao --version` actually runs. - Config discovery (`agent-orchestrator.yaml` walk up from CWD, then `$REPO_ROOT`, then `~/.agent-orchestrator.yaml`) and that `dataDir` / `worktreeDir` exist. - Stale `ao-*.tmp|pid|lock` files older than 60 min under `$TMPDIR/agent-orchestrator`. **Two modes** - **Default** — read-only; reports PASS/WARN/FAIL with a `Fix:` hint on each problem. Exits 1 if any FAIL. - **`--fix`** — applies only the safe repairs: `mkdir -p` missing data/worktree dirs, `npm link` (then `sudo npm link` if TTY) to restore the `ao` launcher, and delete stale temp files. It does **not** install Node/git/pnpm, build packages, or run `pnpm install` — those stay as instructions. It's invoked by the CLI's `ao doctor` command (wired through [packages/cli/src/commands/doctor.ts](packages/cli/src/commands/doctor.ts), which is what your current branch is touching).
