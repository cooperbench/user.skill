## Code Review: paper-scan-processor

### Folder layout / organization

**`pageCache.ts` is misclassified as a hook.** It's a module-level singleton (four mutable `Map`/`Set` globals with pub/sub), not a hook. `usePageCacheRender` is a hook but it's a 3-liner that lives on top of the cache. Move the file to `src/lib/pageCache.ts` or `src/cache/pageCache.ts`; the `hooks/` name implies per-render stateful logic.

**`rotate`/`toggleSkip` are duplicated.** `usePDFFile.ts:33–47` implements both, and `SplitMode/index.tsx:39–54` implements them again identically. SplitMode doesn't use `usePDFFile` at all. Either use the hook in SplitMode too, or inline everything in SplitMode and delete the partial hook (MergeMode is the only consumer of `usePDFFile`).

---

### Component hierarchy

**`ThumbColumn` returns a raw array.** `MergeMode/ThumbnailPanel.tsx:189` returns `virtualizer.getVirtualItems().map(...)` directly — no wrapper, no Fragment. React allows it but it's unconventional for a function component. Wrapping in `<>...</>` makes the intent clearer and lets callers set a key.

**`FilePickerColumn` as a local function** inside `MergeMode/index.tsx` is fine — it's only used once in that file.

---

### Bug: duplicate global keydown handlers

Both `SplitMode/ThumbnailPanel.tsx:110–126` and `DetailPanel.tsx:33–51` register `window.addEventListener('keydown')` for the same keys (ArrowLeft, ArrowRight, Delete/Backspace). **In SplitMode with reordered pages, these conflict.** The thumbnail panel navigates by `pageOrder[selectedPos ± 1]` (visual order), while DetailPanel navigates by `pageNum ± 1` (numeric order). Both setState calls run; since DetailPanel registers later, its handler is called last and wins — so arrow keys after a page reorder jump to the numerically adjacent page, not the visually adjacent one.

Fix: remove the ArrowLeft/ArrowRight/Delete listeners from `DetailPanel` and leave navigation solely to the mode-level panel (which knows about `pageOrder`). The `r` key for rotation can stay in DetailPanel or be lifted to the mode level.

---

### Superfluous library

**`@mantine/dropzone` is installed but unused.** It's in `package.json` and its styles are imported in `main.tsx:6`, but the component is never rendered. Remove the package and the import.

---

### Code smells

**`toggle` missing `useCallback` in `useOutputFiles.ts:25`.** `setName`, `pickFolderOverride`, and `reset` are all memoized, but `toggle` is not. `SplitMode/index.tsx:143` has `useCallback(..., [template, outputFiles.toggle])` — since `toggle` is a new function every render, `handleToggleSplitPoint` is effectively recreated every render, defeating its own memoization.

**Magic pixel offsets in `MergeMode/index.tsx`.** Line 34 subtracts 22 px (`totalWidth - 22`) and line 90 adds 26 px (`colWidth + 26`). Two different magic numbers for what the comments call "scrollbar + gap". One of these is wrong, or they represent different things — either way, they should be named constants.

**`exec.Command("open", path)` in `app.go:104` is macOS-only.** The repo's `build/` directory has both `darwin/` and `windows/` subdirs, implying Windows is a target. `open` doesn't exist on Windows. Wails provides `runtime.BrowserOpenURL` but for a local folder `runtime.OpenDirectoryDialog` isn't right either. The right fix is a build-tag split or using `os/exec` with platform-specific commands.

**`copyFile` in `pdf.go:201` doesn't `Sync()`.** After `io.Copy`, calling `out.Sync()` before `out.Close()` ensures the data is flushed to disk. Without it, a crash in the window between write completion and OS flush could silently corrupt the output PDF. Low probability but the consequence (data loss) is high.

**`getSplitPoints` in `useOutputFiles.ts:79` isn't memoized.** All other expensive computations in that hook use `useMemo` or `useCallback`. `getSplitPoints` creates a new `Set` on every call. It could be a `useMemo(() => ..., [files])` like `duplicateFirstPages`, rather than requiring callers to wrap it.
