Is it best practice to name functions exported by Wails PacscalCase? It looks weird in the TS code.

> AGENT

It's not a TypeScript best practice — PascalCase functions look like constructors or React components. It's just a consequence of Go requiring exported symbols to be PascalCase, and Wails generating bindings verbatim. The common workaround is a thin wrapper module that re-exports everything with camelCase names: ```ts // src/api.ts export { MergePDFs as mergePDFs, OpenFile as openFile, OpenPDF as openPDF, PageCount as pageCount, RenderPage as renderPage, SavePDF as savePDF } from '../wailsjs/go/main/App' ``` Then all imports go through `src/api.ts` instead of directly to the generated bindings. The downside is one extra indirection layer and manual upkeep when new functions are added. Whether that trade-off is worth it is a matter of taste — many Wails projects just accept PascalCase and move on.
