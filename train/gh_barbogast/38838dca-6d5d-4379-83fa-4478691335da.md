Would it be possible to reuse the useThumbnailLoader hook for DetailPanel?

> AGENT

Not cleanly without refactoring the hook's interface. The mismatch is in how loads are triggered: - `useThumbnailLoader` is driven by `virtualItems: VirtualItem[]` — it loads *all* currently visible items from the virtualizer on every render. That's the right model for a scrolling list. - `DetailPanel` just needs to load *one specific page* when `pageNum` changes — a simpler pull model. To share the hook directly you'd have to pass a synthetic `VirtualItem` object (with `index`, `start`, `size`, `key`, etc.) just to satisfy the interface, which is awkward. The shared logic (Map cache, Set for in-flight requests, `setTick` re-render nudge, RPC call) could be pulled into a lower-level `usePageCache(pdfPath)` primitive returning `{ getSrc, isLoading, isFailed, invalidate, load }`, and both hooks would call `load(page)` themselves. But that's one more abstraction layer for two consumers — probably not worth it at this stage. My recommendation: leave the duplication as-is for now. If a third consumer appears (e.g. Merge mode's detail view), that's the right moment to extract the shared primitive.

> DEVELOPER

How about both components actually share the cache? Not only the code but the actual cache ref on the page?

> AGENT

Not straightforwardly — the two caches store images at different resolutions. `ThumbnailPanel` renders at `thumbWidth` (e.g. 220px) and `DetailPanel` at 1400px, so a shared `Map<number, string>` would need to key by `(page, width)` to avoid serving a thumbnail-sized image to the detail panel or vice versa. You could lift a `Map<string, string>` (keyed by `"${page}-${width}"`) into a Zustand store or a React context, and both hooks would read/write the same instance. But since the two panels almost never render the same page at the same width, the hit rate on shared entries would be near zero — you'd add complexity without getting actual cache reuse. The case where sharing *would* pay off is if both panels used the same resolution (e.g. detail panel pre-warms from the thumbnail cache on navigation). That would require a design change: render thumbnails at a higher base resolution and scale them down with CSS, then reuse those images in the detail panel until the full-res version loads. Worth considering, but it's a different trade-off from what we have now. My recommendation: leave the caches separate. The current setup is the right shape for the current design.
