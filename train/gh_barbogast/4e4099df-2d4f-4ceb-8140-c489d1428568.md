> DEVELOPER

Does it make sense to have the index start with 1? It's unusual

> AGENT

For this domain, 1-based actually makes sense and is the right call. Three reasons: 1. **The underlying library uses it.** `pdfcpu`'s `SplitByPageNrFile` is 1-indexed. Starting at 0 internally would just push the `+1` conversion deeper and add a translation layer with no benefit. 2. **Pages are a user-facing concept.** Unlike array indices, page numbers are something users see and reason about directly — the thumbnail panel shows `1`, `2`, `3`, etc. 0-based would require a `+1` on every label render. 3. **The constraint "first entry must be 1" is natural.** `OutputFileSpec.FirstPage = 1` reads correctly. With 0-based it would be `FirstPage = 0`, which is a less obvious invariant. The `afterPage` name (rather than `beforePage`) carries the semantics clearly without needing 0-indexing — "after page 3" is unambiguous whether you use 0 or 1 based counting. The only place 0-based would feel more natural is if these values were used as array indices directly, but they're not — they're always compared against page numbers or converted via `firstPage - 1` / `firstPage + 1` at well-defined boundaries. The current design is good.
