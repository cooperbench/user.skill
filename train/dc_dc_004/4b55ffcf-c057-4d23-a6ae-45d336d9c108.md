
### 1.2 Silent finding drop during import (review.py)

**Bug**: Both `import_review_findings` (line 1017) and `import_holistic_findings` (line 1456) silently `continue` past findings missing required fields. Agent gets no feedback.

**Fix**: Track skipped findings and return count in diff:
- Add `skipped` list tracking index + missing fields
- Add `diff["skipped"] = len(skipped)` and `diff["skipped_details"]` to diff dict
- In `review_cmd.py` `_do_import`, print warning: `"⚠ N findings skipped (missing required fields)"`
- For each skipped, print the missing fields so agent can fix their output

### 1.3 Holistic findings never auto-resolve on re-import (review.py + state.py)

**Bug**: `_IMPORT_ONLY_DETECTORS = {"review"}` in state.py:294 blocks `_auto_resolve_disappeared` from resolving old review findings. Old holistic findings persist forever.

**Fix**: After `merge_scan()` in `import_holistic_findings()`, explicitly resolve old holistic findings not in the new import:
```python
new_ids = {f["id"] for f in review_findings}
for fid, f in state.get("findings", {}).items():
    if (f["status"] == "open" and f.get("detector") == "review"
        and f.get("detail", {}).get("holistic")
        and fid not in new_ids):
        f["status"] = "auto_resolved"
        f["resolved_at"] = _now()
        f["note"] = "not reported in latest holistic re-import"
        diff["auto_resolved"] = diff.get("auto_resolved", 0) + 1
```

Same for `import_review_findings()` — resolve per-file findings for re-reviewed files that no longer have findings.

### 1.4 Duplicate Evidence headers (issues.py:146-159)

**Bug**: Both `evidence` and `evidence_lines` render as `## Evidence`.

**Fix**: Change `evidence_lines` header on line 156 to `## Code References`.

### 1.5 Plan command missing assessment dimensions (plan.py:140)
