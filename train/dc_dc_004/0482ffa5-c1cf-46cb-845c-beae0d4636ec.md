No LLM involvement at all. The zones are purely deterministic — based on file path patterns. ## How classification works Each language config defines a list of pattern rules, checked in order. First match wins: - **generated**: paths containing `/migrations/`, `_pb2.py`, `.d.ts`, etc. - **test**: paths containing `test_`, `.test.`, `/__tests__/`, `/fixtures/`, etc. - **config**: paths containing `setup.py`, `vite.config`, `tsconfig`, etc. - **script**: paths containing `/scripts/`, `/bin/`, `__main__.py` - **vendor**: (no rules yet — available for future use) - **production**: everything else (the default) So `src/components/Button.tsx` → production. `src/__tests__/Button.test.tsx` → test. `vite.config.ts` → config. ## How they flow through the system 1. **At scan start** (`plan.py`): all discovered files are classified once into a `FileZoneMap` — a cached dict of `{filepath: zone}` 2. **During detection**: `phase_dupes` filters out non-production functions *before* the expensive O(n²) duplicate comparison, so test files never generate dupe findings 3. **After detection**: every finding gets a `zone` field stamped on it, and confidence gets downgraded per zone policy (e.g. smells in test files → "low" confidence) 4. **Scoring** (`scoring.py`): findings with zone in `{test, config, generated, vendor}` are skipped entirely — they don't affect the health score 5. **Display** (`show.py`): non-production findings show a `[test]` or `[config]` tag 6. **Query output**: `zone_distribution` counts go into `query.json` so the LLM *consumer* can see the breakdown and reason about it ## What it solves The two main false positive sources: - **Test file duplicates**: test files naturally share patterns (setup, assertions, fixtures). Before zones, these flooded the Duplication dimension. Now they're excluded from both detection and scoring. - **TS regex smells in strings/comments**: separate from zones but implemented alongside — the new TS line classifier (`_build_ts_line_state` + `_ts_match_is_in_string`) skips regex checks inside block comments, template literals, and string literals.
