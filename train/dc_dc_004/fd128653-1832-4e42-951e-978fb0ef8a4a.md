# Plan: Eliminate Duplicate Defaults Across Tool Settings

## Problem Summary

Defaults are defined in up to **4 layers** per tool, and they've silently drifted apart:

```
Layer 1: settings.ts           (feeds DB cascade via toolsManifest)
Layer 2: Hook DEFAULT_*        (feeds useAutoSaveSettings local state + reset)
Layer 3: Component destructuring (inline fallbacks like `foo = 8` or `foo ?? false`)
Layer 4: Task creation          (backend fallbacks like `enhance_prompt ?? true`)
```

**True conflicts found** (not just duplication):

| Field | Conflict | Impact |
|-------|----------|--------|
| `contextFrameCount` | 8 vs 15 vs 16 across locations | Wrong frame count on reset or fresh state |
| `gapFrameCount` | 12 vs 23 vs **53** (task creation) | Backend uses wildly different gap than UI shows |
| `enhancePrompt` | true (settings.ts) vs false (hooks) | Toggle flashes wrong state during load |
| `resolution` (char-animate) | 480p (settings.ts) vs 720p (task creation) | Backend ignores UI default |

Additionally, the model string `'wan_2_2_vace_lightning_baseline_2_2_2'` is hardcoded in **12+ files**. Changing the default model would require touching all of them.

## Architecture: What Changes

### Before (current)
```
settings.ts → toolsManifest → useToolSettings (DB cascade)
Hook DEFAULT_* → useAutoSaveSettings (local state)    ← DUPLICATED, DRIFTED
Component → inline fallbacks                           ← TRIPLICATED
Task creation → own DEFAULT_VALUES                     ← QUADRUPLICATED
```

### After (proposed)
```
VACE_GENERATION_DEFAULTS (shared)
    ↓ spread
settings.ts (adds tool-specific fields)     ← SINGLE SOURCE OF TRUTH
    ↓ import
Hook → useAutoSaveSettings(defaults: settings.defaults)
    ↓ trust the value
Component → no fallbacks
    ↓ import
Task creation → import from settings.ts
```

A future improvement would be a generic `toSnakeCase(joinClipsSettings.defaults)` utility or a shared type that enforces both sides stay in sync.
