## Context

1. Creates a dedicated `.desloppify/config.json` (project-wide, committable)
2. Migrates all existing config keys from state files
3. Adds `review_max_age_days` and `generate_scorecard` / `badge_path`
4. Adds a `config` CLI command
5. Surfaces config in query.json for agent visibility

```json
{
  "review_max_age_days": 30,
  "holistic_max_age_days": 30,
  "generate_scorecard": true,
  "badge_path": "scorecard.png",
  "exclude": [],
  "ignore": [],

}
```

## Subjective measures in both scans

**Yes**, both scans include subjective review. It shows up in two places:

- **Tier 4**, detector `subjective_review`

- TypeScript: **70.0%** (828 open findings out of 827 reviewable files)

### 2. Review assessment dimensions (after import)
- When you run `desloppify review --import findings.json`, the agent provides per-dimension **assessment scores** (0–100)
- Each assessed dimension (e.g. "Naming Quality", "Abstraction Fitness") becomes a **first-class scoring dimension at tier 4** with `ASSESSMENT_CHECKS = 10` synthetic checks
- The Python scan already has these from a prior import — that's why you see dimensions like "Cross Module Architecture 65%", "Error Consistency 60%", "Logic Clarity 80%" etc.

## Weighting

The overall score uses **tier-weighted averaging with sample dampening**:

| Tier | Weight | Examples |
|------|--------|---------|
| T1 | 1 | Import hygiene, Debug cleanliness |
| T2 | 2 | API surface, Deprecated |
| T3 | 3 | File health, Code quality, Coupling |
| T4 | 4 | Security, Test health, **Review coverage**, **Assessments** |

**Sample dampening**: dimensions with fewer than `MIN_SAMPLE = 200` checks get their weight reduced proportionally (`effective_weight = tier_weight * min(1.0, checks / 200)`). This is key for subjective measures:

- **Review coverage** (potential = file count): Python has 96 checks → `sample_factor = 96/200 = 0.48`, so effective weight = `4 * 0.48 = 1.92`. TypeScript has 827 → full weight of 4.
- **Each assessment dimension**: only `ASSESSMENT_CHECKS = 10` synthetic checks → `sample_factor = 10/200 = 0.05`, so effective weight = `4 * 0.05 = 0.2`. Very lightweight individually, but multiple assessed dimensions add up.

So subjective measures **are** included but their weight is dampened to avoid swinging the score from a small sample. A repo with many assessed dimensions gets more total subjective weight than one with few.

### Secondary measures?

No — assessment dimensions don't get their own secondary/strict score distinction. They use the assessment score directly (the agent's 0–100 rating becomes the dimension score). The only way to change them is re-review. The "strict" vs "lenient" split (which treats `wontfix` findings differently) doesn't apply because assessment scores aren't finding-based.
