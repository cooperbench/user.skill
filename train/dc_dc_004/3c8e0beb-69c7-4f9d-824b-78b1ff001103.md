## Context

The generic plugin framework (`generic.py`) now provides a rich set of tree-sitter-powered detectors (AST smells, complexity signals, god class detection, cohesion, unused imports, signature variance) that are automatically enabled for all 18+ generic language plugins. However, the three "full" plugins that predate this framework — **C#**, **Dart**, and **GDScript** — don't benefit from these capabilities despite having tree-sitter specs already defined.

Additionally, C#'s structural and coupling phases contain ~120 lines that are nearly identical to the shared runners in `phases_common.py`, differing only in:
- God class detection (4 rules + class extractor)
- 3 custom complexity compute functions (brace nesting, method count, long methods)
- Actionability gates for single_use/orphaned findings

This plan consolidates the duplication and enables tree-sitter phases for all full plugins.

**Not in scope**: Python and TypeScript plugins — these have deeply language-specific detection (Python AST module, TS React/props/concerns) that the generic framework can't replace.

## Subjective Review Dimensions

**Current state is very uneven:**
- Python: 11 custom dimensions
- TypeScript + C#: 12 shared dimensions
- Dart + GDScript: 4 scaffold defaults
- **22 other languages: ZERO review dimensions**

The shared dimensions from `_shared/review_dimensions.py` (cross_module_architecture, convention_outlier, error_consistency, abstraction_fitness, etc.) are universal enough to apply to most languages. The 22 generic plugins could get these as a baseline.

Beyond that, language-specific dimensions would add real value for major languages — things like Go's error handling patterns, Rust's unsafe discipline, Java's null safety, Ruby's metaprogramming clarity.
