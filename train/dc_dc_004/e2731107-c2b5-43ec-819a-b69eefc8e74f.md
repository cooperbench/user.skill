## Date Navigator Design

A smooth, draggable horizontal timeline — feels like scrubbing through time, not clicking buttons.

```
  ···  Jan 4   Jan 5   Jan 6   [Jan 7]   Jan 8  ···
                                ^^^^^^^^ selected, larger/brighter
```

**Interaction model:**
- Horizontal scroll/drag container with CSS `overflow-x: auto`, `scroll-snap-type: x proximity`
- Touch: swipe to browse dates, snap to nearest
- Mouse: click-drag to scrub, or click a date to select it
- Momentum scrolling on both touch and mouse (native browser behavior via overflow-x)
- Selected date snaps to center with `scroll-snap-align: center` on each pill
- Auto-scrolls to center the selected date on mount and on date change
- Gradient fades at left/right edges (like the homepage mobile card scroll) to hint at more dates

**Visual feel:**
- Date pills spaced evenly, today/yesterday labeled as such
- Selected date: `bg-white/15 text-white text-sm font-medium` — slightly larger
- Unselected dates: `text-white/40 text-xs` — subtle, recede
- No arrow buttons — just smooth drag/scroll (arrows add clutter and feel cumbersome)
- Hide scrollbar with `scrollbar-hide` + `scrollbarWidth: 'none'`
- Defaults to most recent date with content, centered in view

**Empty state**: "No community updates for this day" below the date strip if selected date has no topics

## Data Fetching: `useCommunityNews` hook

**Step 1 — On mount**: Fetch distinct dates with content (last 90 days):
```ts
client.from('daily_summaries')
  .select('date')
  .eq('included_in_main_summary', true)
  .eq('dev_mode', false)
  .gte('date', ninetyDaysAgo)
  .order('date', { ascending: false })
// Deduplicate client-side
```
Set `selectedDate` to the most recent.

**Step 2 — On date select**: Fetch summaries for that date using the same `fetchSummariesForDate` + `parseSummariesToTopics` + `filterAndSortTopics` helpers already in `useCommunityTopics.ts`.

**Optimization**: On mount, fire both queries in parallel (dates + topics for most recent date).

**Caching**: `Map<string, TopicData[]>` — navigating back to a seen date is instant.

**Return type**:
```ts
{
  availableDates: string[];
  selectedDate: string | null;
  setSelectedDate: (date: string) => void;
  topics: TopicData[];
  loading: boolean;
  loadingDates: boolean;
  error: string | null;
}
```
