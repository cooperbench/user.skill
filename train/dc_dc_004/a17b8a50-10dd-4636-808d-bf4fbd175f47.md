# Plan: Fix `--exclude` architecture — grep detectors, double state load, global cleanup

## Context

`--exclude` only works for detectors that use `find_source_files()`. The 13 grep-based subprocess calls in detectors scan the full directory tree regardless. Additionally, `ruff`/`pyflakes` and `visualize.py` bypass it too. The module-level `_extra_exclusions` global works but is messy, and state gets loaded twice during every scan.

## Step 1: Add `run_grep()` helper to utils.py

**Problem**: 13 grep subprocess calls across 5 detector files ignore `--exclude` entirely.

**Fix**: Add a `run_grep()` function that wraps `subprocess.run` and post-filters output lines by `_extra_exclusions`. Post-filtering (not `--exclude-dir`) because our exclusions are substring matches on full paths, which is consistent with how `find_source_files` works.

```python
def run_grep(cmd: list[str]) -> str:
    """Run a grep command, filtering results by active exclusions."""
    result = subprocess.run(cmd, capture_output=True, text=True, cwd=PROJECT_ROOT)
    if not _extra_exclusions or not result.stdout:
        return result.stdout
    lines = result.stdout.splitlines()
    filtered = [l for l in lines if not any(ex in l for ex in _extra_exclusions)]
    return "\n".join(filtered) + ("\n" if filtered else "")
```

**File**: `desloppify/utils.py`

## Step 5: Eliminate double state load

**Problem**: During a scan, state is loaded twice from the same file:
1. In `_apply_persisted_exclusions()` (cli.py:194) — to read `config.exclude`
2. In `cmd_scan()` (scan.py:15) — to merge findings

**Fix**: Load state once in `main()`, pass to both:

```python
def main():
    ...
    sp = _state_path(args)
    from .state import load_state
    state = load_state(sp)
    _apply_persisted_exclusions(args, state)  # pass state instead of loading again
    args._preloaded_state = state
    args._state_path = sp
    ...
```

Update `_apply_persisted_exclusions(args, state)` to accept state as parameter.

Update `cmd_scan` to use `args._preloaded_state` instead of `load_state()`:
```python
def cmd_scan(args):
    state = getattr(args, '_preloaded_state', None) or load_state(_state_path(args))
    sp = getattr(args, '_state_path', None) or _state_path(args)
```

Other commands that load state (status, show, next, resolve) are unaffected — they don't need exclusions and can keep loading independently.

**Files**: `desloppify/cli.py`, `desloppify/commands/scan.py`

Yes, this is a real need — especially when acting on flat-directory findings (splitting `shared/hooks/` into subdirectories means updating every import). For **TypeScript**, the best approach is using the TS Language Server's rename/move refactoring (which VS Code uses under the hood). For **Python**, the landscape:

- **`rope`** — the classic Python refactoring library. Has `rope.refactor.move` for moving modules/functions with automatic import updates. Mature but can be slow on large codebases.
- **`libcst`** (from Instagram/Meta) — CST-based transforms. You'd write a codemod to rewrite import paths. More manual but precise and fast.
- **`bowler`** — built on `libcst`, provides a higher-level API for codemods including moves. Less maintained now.
- **`ruff`** — doesn't do moves, but could clean up after one (fix unused imports, sort remaining ones).

For a decruftify `fix move` command, I'd lean toward building a simple move helper that:
1. Uses the dep graph we already have to find all importers
2. Moves the file
3. Rewrites import paths in all importing files (simple string replacement on the import path — we already know exact resolution)
