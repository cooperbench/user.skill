# Security Detector Implementation Plan

## Context

Desloppify currently detects code quality issues (smells, unused imports, duplication, etc.) but has no dedicated security detection. We want to add a comprehensive security scanning dimension that catches common vulnerabilities in both Python and TypeScript codebases — hardcoded secrets, injection risks, unsafe deserialization, insecure crypto, etc.

Four research agents explored both the Reigh (TypeScript) and desloppify (Python) codebases from different perspectives. Their findings converge on ~25 high-value detectors organized into a dedicated "Security" scoring dimension.

## Architecture Decisions

1. **Dedicated "Security" dimension** (tier 4, max weight) — not folded into "Code quality"
2. **Zone override**: Security findings in test/config zones are NOT excluded from scoring (secrets in test fixtures are real risks). Only GENERATED and VENDOR zones skip security.
3. **Never auto-fixable**: Security findings use `action_type="manual_fix"` (tier 2-3, never tier 1). Security fixes need human review.
4. **Cross-language core** in `detectors/security.py` with lang-specific extensions in `lang/{python,typescript}/detectors/security.py`
5. **Shared phase runner** `phase_security()` in `lang/base.py` (same pattern as `phase_test_coverage`)
6. **File-based detector**: Added to `_FILE_BASED_DETECTORS` since multiple security findings per file are common

### Phase 2: Cross-Language Secret Detection (~2 files)

**`desloppify/detectors/security.py`** (NEW) — Core cross-language detector.

Function signature following `test_coverage.py` pattern:
```python
def detect_security_issues(
    files: list[str],
    zone_map,           # FileZoneMap or None
    lang_name: str,     # "python" | "typescript"
) -> tuple[list[dict], int]:
```

Returns `(entries, potential)` where potential = number of files scanned.

Each entry dict:
```python
{
    "file": str,
    "line": int,
    "name": "security::{check_id}::{file}::{line}",
    "tier": 2,          # quick fix (move secret to env var, etc.)
    "confidence": "high" | "medium" | "low",
    "summary": str,      # Human-readable description
    "detail": {
        "kind": str,     # "hardcoded_secret" | "shell_injection" | etc.
        "severity": str, # "critical" | "high" | "medium" | "low"
        "content": str,  # Matched line (truncated)
        "remediation": str, # How to fix
    },
}
```

**Checks implemented in this file (cross-language):**

1. `hardcoded_secret_value` — Regex on known secret formats:
   - AWS keys (`AKIA[0-9A-Z]{16}`)
   - GitHub tokens (`gh[ps]_[A-Za-z0-9_]{36,}`)
   - Private keys (`-----BEGIN.*PRIVATE KEY-----`)
   - Stripe keys (`[sr]k_(live|test)_[0-9a-zA-Z]{20,}`)
   - Slack tokens (`xox[bpas]-`)
   - JWTs (`eyJ...\.eyJ...\.`)
   - DB connection strings with embedded passwords (`postgres://user:pass@`)
   - Generic high-entropy hex/base64 assigned to secret-named vars

2. `hardcoded_secret_name` — Variable assignments where name matches `password|secret|api_key|token|credentials|auth_token|private_key|access_key` and value is a non-empty, non-placeholder string literal (not env lookup).

   Suppression rules:
   - Skip placeholders: `""`, `"changeme"`, `"xxx"`, `"your-*"`, `"<*>"`, `"PLACEHOLDER"`, values < 8 chars
   - Skip env lookups: `os.environ`, `os.getenv`, `process.env.`, `import.meta.env`
   - In test zones: flag at `confidence="medium"` instead of `"high"`

3. `insecure_random` — `Math.random()` / `random.random()` used near security-named variables (token, key, nonce, session, salt)

4. `weak_crypto_tls` — `verify=False` in requests, `ssl._create_unverified_context()`, `rejectUnauthorized: false`

5. `log_sensitive` — Logging calls that include secret-named variables (`password`, `token`, `secret`, `api_key`, `credentials`)

**`desloppify/lang/base.py`** — Add `phase_security()` shared runner:
```python
def phase_security(path: Path, lang: LangConfig) -> tuple[list[Finding], dict[str, int]]:
    from ..detectors.security import detect_security_issues
    zm = lang._zone_map
    files = lang.file_finder(path) if lang.file_finder else []
    entries, potential = detect_security_issues(files, zm, lang.name)
    # Also call lang-specific security detectors
    if hasattr(lang, 'detect_lang_security'):
        lang_entries, _ = lang.detect_lang_security(files, zm)
        entries.extend(lang_entries)
    findings = []
    for e in entries:
        findings.append(make_finding(
            detector="security", file=e["file"], name=e["name"],
            tier=e["tier"], confidence=e["confidence"],
            summary=e["summary"], detail=e["detail"],
            zone=...,  # from zone_map
        ))
    return findings, {"security": potential}
```

Register in both lang plugins:
```python

```

### Phase 3: Python-Specific Security Detectors (~1 file)

**`desloppify/lang/python/detectors/security.py`** (NEW)

Function: `detect_python_security(files, zone_map) -> tuple[list[dict], int]`

Uses AST analysis (like existing `smells.py` for `unreachable_code`, `constant_return`, etc.) plus regex.

**Checks (priority order):**

1. `shell_injection` — AST: `subprocess.*(shell=True)` where command arg is f-string/format/concat (not literal). Also `os.system()` / `os.popen()` with non-literal arg. **Severity: critical.**

2. `unsafe_deserialization` — AST: `pickle.loads/load`, `yaml.load()` without `Loader=SafeLoader`, `marshal.loads`, `shelve.open`. **Severity: critical.**

3. `sql_injection` — AST: `.execute(f"...")` or `.execute("..." + var)` or `.execute("...".format(...))`. **Severity: critical.**

4. `unsafe_yaml` — AST: `yaml.load()` missing `Loader` keyword or using non-safe loader. **Severity: high.**

5. `debug_mode` — Regex: unconditional `DEBUG = True`, `app.run(debug=True)`. **Severity: medium.**

6. `unsafe_tempfile` — Regex: `tempfile.mktemp()`. **Severity: high.**

7. `xxe_vuln` — Regex: `xml.etree.ElementTree.parse`, `xml.sax.parse` without `defusedxml`. **Severity: high.**

8. `assert_security` — AST: `assert` with security-named test (`is_authenticated`, `has_permission`, `authorized`, `user.is_staff`). **Severity: medium.**

9. `weak_password_hash` — AST: `hashlib.md5/sha1` where nearby variable name suggests password context. **Severity: medium.**

10. `insecure_cookie` — Regex: `set_cookie()` without `secure=True`. **Severity: low.**

Called from `phase_security()` via a `detect_lang_security` method on `PythonConfig`.

### Phase 4: TypeScript-Specific Security Detectors (~1 file)

**`desloppify/lang/typescript/detectors/security.py`** (NEW)

Function: `detect_ts_security(files, zone_map) -> tuple[list[dict], int]`

**Checks (priority order):**

1. `service_role_on_client` — Regex: `createClient(` with `SERVICE_ROLE` or `service_role` in `src/` directory files. **Severity: critical.**

2. `unverified_jwt_decode` — Regex: `atob(` near `payload.sub` or JWT segment extraction without `auth.getUser`. **Severity: critical.**

3. `eval_injection` — Regex: `eval(`, `new Function(`, `setTimeout(` with string arg (not in comment/string context, using existing `_build_ts_line_state`). **Severity: critical.**

4. `dangerouslySetInnerHTML` — Regex. **Severity: high.**

5. `rls_bypass_views` — Regex: `CREATE VIEW` without `security_invoker = true` in `.sql` files. **Severity: high.** (Only if SQL migration files are in scan path.)

6. `innerHTML_assignment` — Regex: `.innerHTML =` without preceding `esc()` or sanitization. **Severity: high.**

7. `edge_function_missing_auth` — File-level: files in `functions/*/index.ts` containing `serve(async` but not `authenticateRequest` or `Authorization`. **Severity: high.**

8. `dev_credentials_env` — Regex: `VITE_.*PASSWORD`, `VITE_.*SECRET` in env access. **Severity: medium.**

9. `open_redirect` — Regex: `window.location.href = data.` or `window.location = response.`. **Severity: medium.**

10. `json_parse_unguarded` — Regex: `JSON.parse(` not inside try block (multi-line check). **Severity: low.**

Called from `phase_security()` via a `detect_lang_security` method on `TypeScriptConfig`.
