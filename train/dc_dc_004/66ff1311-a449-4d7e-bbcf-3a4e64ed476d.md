# Dict Key Flow Tracer — Implementation Plan

## Context

Desloppify catches structural/syntactic code issues but misses semantic data-flow bugs. In the LoRA handler review, we found: dead dict writes (`payload["lora_names"]` set but never read), redundant processing (dict processed → serialized → re-processed), and copy-paste variants that dodged syntax-based dupe detection (7 blocks with slightly different key names).

The Dict Key Flow Tracer detects broken "conversations" between dict producers and consumers — **without** attempting full inter-procedural data flow analysis. Instead, it focuses on the 80/20: single-scope key analysis and cross-file schema consensus, which catches the majority of real bugs with minimal false positives.

## What We're Building

A new Python detector with two analysis passes:

### Pass 1: Single-Scope Dict Key Analysis
Within each function, track dicts that are created locally (`d = {}`, `d = dict(...)`, `d = {"k": v}`). For each tracked dict, collect literal-key writes and reads. Report:

- **Dead writes** — key written but never read in the function (and dict is NOT returned/passed out)
- **Phantom reads** — key read from a locally-created dict but never written (certain bug)
- **Near-miss keys** — edit distance ≤ 2 between a dead write and a phantom read (likely typo)
- **Overwritten keys** — same key assigned twice with no read in between

Also track `self.x` dicts across all methods of a class (same analysis, class-scoped).

### Pass 2: Dict Literal Schema Clustering
Across all files, collect every dict literal where all keys are string constants and there are ≥ 3 keys. Cluster by Jaccard similarity ≥ 0.8. Within each cluster (≥ 3 members), find outlier keys. Report:

- **Schema drift** — key appears in <30% of cluster members (likely typo or missed rename)

### New: `desloppify/lang/python/detectors/dict_keys.py` (~250 lines)

Core detector module with:

```
@dataclass TrackedDict:
    name, created_line, locally_created, returned_or_passed
    writes: dict[str, list[int]]   # key → line numbers
    reads: dict[str, list[int]]

class DictKeyVisitor(ast.NodeVisitor):
    - visit_FunctionDef: push scope, walk body, pop scope + analyze
    - visit_ClassDef: push class context for self.x tracking
    - visit_Assign: detect d = {}, d = dict(), d["k"] = v
    - visit_AugAssign: d["k"] += v
    - visit_Subscript: d["k"] read (Load ctx) vs write (Store ctx)
    - visit_Call: d.get("k"), d.update({"k": v}), d.setdefault("k", v), d.pop("k")
    - visit_Return/visit_Yield: mark dict as returned (suppress dead-write findings)
    - Calls with dict as arg: mark dict as passed (suppress dead-write findings)

def detect_dict_key_flow(path: Path) -> tuple[list[dict], int]:
    Walk all .py files, run DictKeyVisitor, collect entries.

def detect_schema_drift(path: Path) -> tuple[list[dict], int]:
    Collect all dict literals with ≥3 string-constant keys.
    Cluster by Jaccard similarity. Report outliers.
```

**AST patterns to handle:**
- `d["key"] = val` → Assign/AugAssign with Subscript(Store) target, Constant(str) slice → **write**
- `d["key"]` → Subscript(Load), Constant(str) slice → **read**
- `d.get("key")` / `d.get("key", default)` → Call with Attribute(attr="get"), first arg Constant(str) → **read**
- `d.pop("key")` → Call with Attribute(attr="pop") → **read + delete**
- `d.setdefault("key", val)` → Call with Attribute(attr="setdefault") → **read + write**
- `d.update({"key": val})` → Call with Attribute(attr="update"), arg is Dict → **write** the literal keys
- `d.update(key=val)` → keywords → **write**
- `"key" in d` → Compare with In, left is Constant(str) → **read (check)**
- `{**d}` / `func(**d)` → starred → **bulk read (suppress all dead-write warnings)**
- `d.keys()` / `d.values()` / `d.items()` → **bulk read**
- `del d["key"]` → Delete with Subscript(Del) → **read + delete**
- Dict literal `{"k1": v1, "k2": v2}` → creation with initial **writes**
- `dict(k1=v1, k2=v2)` → creation with initial **writes**

**Confidence suppression — do NOT report dead writes when:**
- Dict is returned or yielded (external consumer)
- Dict is passed as argument to any function call
- Dict has any dynamic key access (`d[variable]`, `d[f"..."]`)
- Dict variable name matches config patterns: `config`, `settings`, `defaults`, `options`, `kwargs`, `context`, `env`
- Dict has `**d` unpacking anywhere (all keys potentially consumed)
- Function is `__init__` or `setUp` (dicts stored as `self.x` read elsewhere)
- Dict has < 3 total literal keys (too small to be interesting)

**DO report phantom reads (key read but never written on locally-created dict) even when dict is returned** — these are almost always bugs.

**Near-miss detection**: For each dead-write key × each phantom-read key on the same dict, compute Levenshtein distance. Also check singular/plural (`"name"` vs `"names"`). Flag pairs with distance ≤ 2.

## Finding Tiers and Confidence

| Finding Type | Tier | Confidence | Rationale |
|---|---|---|---|
| Phantom read (locally-created dict) | 2 | high | Almost certainly a bug — you made the dict and read a key you never set |
| Near-miss key pair | 2 | high | Strong typo signal when dead write + phantom read have edit distance ≤ 2 |
| Schema drift (outlier in cluster ≥ 5) | 2 | high | Consensus of 5+ dict literals is strong evidence |
| Overwritten key (no read between) | 3 | medium | Likely dead code, could be intentional overwrite |
| Dead write (closed scope, no escape) | 3 | medium | Probably dead code, but might be intentional future-proofing |
| Schema drift (cluster 3-4 members) | 3 | medium | Smaller consensus, less certain |

## What We're NOT Building

- **Cross-function dict tracing** — following a dict through function calls/returns requires points-to analysis. 5% of value for 50% of effort. Skip entirely.
- **Dynamic key analysis** — `d[variable]` is opaque. We detect its presence and lower confidence, but don't try to resolve it.
- **Control-flow sensitivity** — "key only written in if-branch but read unconditionally" requires CFG. Leave to mypy/pyright with TypedDict.
- **Serialization boundary tracing** — dict → json.dumps → DB → json.loads. No static link exists.
- **Dict subclass analysis** — defaultdict, OrderedDict, UserDict. Stick to plain `dict` and `{}`.
