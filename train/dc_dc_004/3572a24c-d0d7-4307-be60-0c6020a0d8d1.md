# Plan: `scripts/decruftify.py` — Automated Cruft Detection

## Context

During the Timeline.tsx cleanup (1203→810 lines), we identified recurring cruft categories: debug logging left behind, unused imports/variables, dead exports, stale deprecation shims, dead interface props. A codebase survey confirmed the scale:

- **2,039 tagged `console.log`s** across 260 files (e.g. `[ZoomDebug]`, `[DataTrace]`)
- **715 unused declarations** across 250 files (via `tsc --noUnusedLocals/Parameters`)
- **55 `@deprecated` annotations** — many still actively imported
- **Dead type exports** — exported types/interfaces with zero external importers

These categories are mechanical to detect. A single CLI tool can surface them on demand, making cleanup systematic rather than accidental.

## Design

Single file: **`scripts/decruftify.py`** (~350 lines). No external deps beyond Python 3.10+ stdlib. Follows the `scripts/debug.py` pattern (argparse + subcommands) but all in one file since the logic is simpler.

### Subcommands

#### `logs` — Tagged console.log detection
```
decruftify.py logs [--top N] [--path PATH] [--fix]
```
- Regex: `console\.(log|warn|info|debug)\s*\(\s*['"\`]\[` (matches tagged logs like `console.log('[Tag]`)
- Groups by tag prefix, counts per file
- `--top N`: show top N files by count (default: 20)
- `--fix`: removes lines matching the pattern (with confirmation prompt)

**Technique**: `grep -rn` via subprocess, parse output. Fast and reliable.

#### `unused` — Unused declarations (tsc-based)
```
decruftify.py unused [--top N] [--path PATH] [--category imports|vars|params|all]
```
- Runs `npx tsc --noEmit --noUnusedLocals --noUnusedParameters 2>&1`
- Parses TS6133 errors: `file(line,col): error TS6133: 'name' is declared but its value is never read.`
- Groups by file, categorizes (import vs local var vs parameter via heuristic: reads the source line)
- `--category`: filter to just imports, vars, or params
- `--top N`: top N files by unused count

**Technique**: TypeScript compiler itself — authoritative for single-file unused detection.

#### `exports` — Dead exports (cross-file)
```
decruftify.py exports [--top N] [--path PATH]
```
- Phase 1: Find all `export (const|function|class|type|interface|enum) NAME` declarations via regex
- Phase 2: For each exported name, `grep -r` for import usage across `src/` (excluding the declaring file)
- Reports exports with zero external importers
- Excludes: `index.ts` re-exports, `types.ts` files that are public API by convention

**Technique**: Regex + grep. Not 100% precise (dynamic imports, barrel re-exports can cause false positives) but catches the vast majority. We accept ~5% false positive rate since the output is advisory.

#### `deprecated` — Stale deprecation shims
```
decruftify.py deprecated [--top N]
```
- Finds all `@deprecated` JSDoc annotations and `// @deprecated` comments
- For each deprecated symbol, checks if it's still imported anywhere
- Reports: symbol name, declaring file, number of active importers
- Sorts by importer count ascending (0 importers = safe to delete)

**Technique**: Regex for annotations + grep for import usage. Same cross-file approach as `exports`.

#### `all` — Summary dashboard
```
decruftify.py all [--path PATH] [--json]
```
- Runs all four detectors, prints a summary table:
  ```
  Category        Count   Top File
  ─────────────────────────────────────────────
  Tagged logs     2,039   Timeline.tsx (47)
  Unused decls      715   types.ts (23)
  Dead exports      142   utils/index.ts (8)
  Stale deprecated   12   useOldHook.ts
  ```
- `--json`: output as JSON for CI integration

### Common flags

| Flag | Description |
|------|-------------|
| `--path PATH` | Scope to directory (default: `src/`) |
| `--top N` | Limit output to top N results (default: 20) |
| `--json` | JSON output |
| `--fix` | Auto-fix where safe (only `logs` initially) |

## The Meta-Problem: Agent Actionability

If I were an agent tasked with "clean up this codebase using decruftify output," here's where I'd struggle:

1. **No priority ordering across detectors.** The `all` dashboard shows counts but doesn't say "start here." Is it more valuable to delete 343 dead exports or fix 59 god components? The answer depends on effort/impact ratio, which the tool doesn't provide.

2. **Results overlap heavily.** The same 20 worst files appear in 5+ detectors. An agent shouldn't clean logs from a file that needs a full rewrite — it should rewrite the file and the logs disappear naturally.

4. **False positive rate unknown.** An agent blindly actioning everything will break things. Each detector should report its expected false positive rate so the agent knows when to verify vs. trust.

5. **Missing the dependency question.** Before touching any file, an agent needs to know: "what depends on this file, and will my changes cascade?" The `deps` data exists but isn't integrated into each detector's output.

## Design: Decruftify State System

### The State File (`.decruftify/state.json`)

A single JSON file that lives in the repo. It's the source of truth.

```
{
  "version": 1,
  "last_scan": "2026-02-10T02:00:00Z",
  "scan_count": 3,
  "score": 42,                          // % of findings addressed
  "config": {
    "ignore": [...]                     // patterns to skip
  },
  "stats": { open: N, fixed: N, ... },
  "findings": { "<id>": {...}, ... }
}
```

Each finding:
```
{
  "id": "exports::src/foo.tsx::MyComponent",
  "detector": "exports",
  "file": "src/foo.tsx",
  "tier": 2,
  "confidence": "high",
  "summary": "Dead export: MyComponent (0 importers)",
  "status": "open",             // open | fixed | wontfix | false_positive | auto_resolved
  "note": null,                 // human/agent explanation when resolving
  "first_seen": "2026-02-10",
  "last_seen": "2026-02-10"
}
```

### The Hard Problems

**1. Stable IDs (biggest challenge)**

Line numbers drift when files change. IDs need to survive edits.

| Detector | ID scheme | Why |
|----------|-----------|-----|
| logs | `logs::{file}::{tag}` | Tags are stable. Group all logs of same tag in same file. |
| unused | `unused::{file}::{symbol_name}` | Symbol names are stable unless renamed. |
| exports | `exports::{file}::{name}` | Export names are stable. |
| deprecated | `deprecated::{file}::{symbol}` | Symbol names stable. |
| gods | `gods::{file}` | One finding per file. |
| concerns | `concerns::{file}` | One per file. |
| large | `large::{file}` | One per file. |
| complexity | `complexity::{file}` | One per file. |
| smells | `smells::{file}::{smell_id}::{content_hash[:8]}` | Content hash survives line moves but not content edits. |
| dupes | `dupes::{file_a}::{name_a}::{file_b}::{name_b}` | Pair identity. Sort alphabetically for consistency. |
| props | `props::{file}::{interface_name}` | Interface name stable. |
| single-use | `single_use::{file}` | One per file. |

**2. Deduplication across detectors**

Raw findings stay separate (they're different issues). But the **plan view** groups by file:

```
src/pages/Home/HomePage.tsx  (5 findings, tier 4)
  - [open] gods: 27 hooks, 10 useEffects  
  - [open] complexity: score 35, 23 imports
  - [open] concerns: jsx + data_fetching + handlers(7)
  - [wontfix] large: 638 LOC — "main page orchestrator, inherent complexity"
  - [fixed] logs: removed 8 tagged logs
```

The file's tier = max tier of its open findings. So even if you fix the logs, the file stays tier 4 until the god component is addressed.

**3. Ignore list**

In `config.ignore`, patterns like:
- `src/integrations/supabase/types.ts` — ignore this whole file (auto-generated)
- `smells:async_no_await` — ignore this smell globally (too many false positives)
- `smells:hardcoded_rgb:src/shared/components/canvas/**` — ignore in canvas files
- `logs:ApplySettings` — ignore this specific tag everywhere

Ignored findings never enter state. They don't count against the score.

**4. Re-scan logic**

```
Current scan findings  ←→  Previous state
─────────────────────────────────────────
New finding            →   Add as "open"
Still exists + open    →   Update last_seen
Still exists + fixed   →   Reopen! (regression)
Disappeared + open     →   Mark "auto_resolved"
Disappeared + wontfix  →   Keep as-is (decision stands)
Disappeared + false_pos →  Keep as-is
```

The key insight: if you marked something `wontfix` with a reason, and the code changes so the finding disappears, the decision is preserved. If the code changes back and the finding reappears, the `wontfix` status + note are still there — no re-triage needed.

**5. The Score**

```
score = (addressed / total) * 100

addressed = fixed + wontfix + false_positive + auto_resolved
total = all findings (excluding ignored)
```

Score 0 = first scan, nothing addressed. Score 100 = every finding has been dealt with or explained. A score of 100 does NOT mean the codebase is perfect — it means every known issue has been consciously handled.

**6. Tier assignment**

| Tier | Criteria | Example |
|------|----------|---------|
| 1 | High confidence + trivial effort | Unused imports (tsc-verified), deprecated with 0 importers |
| 2 | High confidence + low effort | Dead exports, tagged logs, exact dupes ≥8 LOC |
| 3 | Medium confidence or judgment needed | Code smells, near-dupes, bloated props |
| 4 | Major refactor needed | God components, mixed concerns, files needing rewrite |

Auto-suppressed (never enters state):
- Duplicate functions <8 LOC
- Deprecated properties (migration task, not cleanup)  
- Single-use abstractions 50-200 LOC
- Items matching ignore list

### Commands

| Command | What it does |
|---------|-------------|
| `scan` | Run all detectors, diff against state, update. Shows new/resolved/reopened counts. |
| `status` | Score dashboard: total/open/fixed/wontfix by tier. Progress bars. |
| `next [--tier N]` | Print the single highest-priority open finding for an agent to action. |
| `resolve <id> <fixed\|wontfix\|fp> --note "reason"` | Mark a finding. Note is required for wontfix. |
| `ignore <pattern>` | Add to ignore list, remove matching findings from state. |
| `plan [--output FILE]` | Generate prioritized markdown grouped by file, tier by tier. |
| `diff` | Show what changed since last scan without updating state (dry run). |

### Agent Workflow

```
# Initialize
decruftify scan

# Agent loop
while score < 100:
    item = decruftify next          # get highest priority open item
    if item.tier <= 2:
        fix(item)                   # agent fixes it
        decruftify resolve <id> fixed --note "removed unused import"
    else:
        assess(item)                # agent reads context
        if intentional:
            decruftify resolve <id> wontfix --note "fire-and-forget pattern"
        else:
            refactor(item)
            decruftify resolve <id> fixed --note "extracted to shared hook"
    
    decruftify scan                 # re-scan to catch cascading fixes
```

  cli.py         # Updated with: scan, status, next, resolve, ignore, plan, diff
