# Plan: Add Architectural Detectors to Decruftify

## Context

The decruftify toolset detects per-file issues but misses codebase-level architectural problems. Three analysis agents identified: backwards coupling (shared→tools imports), competing patterns (5 settings hooks, only some areas using handleError), and naming inconsistencies. These should be caught automatically during `scan`, not discovered manually.

**Approach**: Three new detectors that run during `scan` and produce standard T3 findings. Everything flows through the existing pipeline — `status`, `show`, `plan`, `resolve`. No new commands, no new data types, no separate `audit` mode. Also available via `decruftify detect <name>` for raw access (full census/details).

**Tier & Score Integration**: All findings are **T3** (structural, needs judgment) — the same tier as props bloat, large files, and complexity findings. T3 carries weight 3 in the scoring formula (`TIER_WEIGHTS = {1:1, 2:2, 3:3, 4:4}`), meaning each finding contributes 3 points to the total weight pool. The score engine in `state.py::_recompute_stats()` iterates ALL findings regardless of detector, so new findings are automatically:
- Counted in the tier stats table shown by `status`
- Included in both `score` (addressed/total) and `strict_score` (fixed/total)
- Filterable, resolvable, and reportable through the existing pipeline
- Auto-resolved on rescan if the underlying issue disappears

**`detect_pattern_anomalies(path)`**:
1. Scan all .ts/.tsx files, classify into areas via `get_area()`
2. For each file, count which patterns from each family are present (file-level, not instance count)
3. Build matrix: area × pattern family → set of patterns used
4. Flag anomalies:
   - Area uses **3+ different patterns** from same family (fragmentation)
   - Area uses a pattern that **<10% of other areas** use (outlier adoption)
   - Area has **0 usage** of a pattern that **>70% of areas** use (missing adoption)
5. Each anomaly → T3 finding, confidence "low" (needs judgment)
6. Detail field includes full census for that area + review prompt

**Examples of what it would produce**:
- `patterns::src/shared/components/ImageGenerationForm::settings` → "3 settings patterns used (useToolSettings, usePersistentToolState, useUserUIState). Review: is consolidation possible?"
- Would NOT flag error handling (handleError used consistently, no anomaly)
- Would NOT flag areas with 1-2 patterns from a family (normal)

**`cmd_patterns(args)`** — Raw access via `decruftify detect patterns`. Shows FULL census matrix (all areas × all families), not just anomalies. Useful for landscape overview.

## Step 4: New detector — `detectors/naming.py`

**`detect_naming_inconsistencies(path)`**:
1. For each directory, classify .ts/.tsx filenames by convention: PascalCase, camelCase, kebab-case
2. Skip standard names: `index.ts`, `types.ts`, `constants.ts`, `utils.ts`, etc.
3. Identify majority convention per directory
4. Flag directories where minority convention has **3+ files** (not just 1 outlier)
5. Each inconsistency → T3 finding, confidence "low"
6. Detail includes outlier filenames + majority convention

**`cmd_naming(args)`** — Raw access via `decruftify detect naming`
