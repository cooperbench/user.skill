# Plan: Computed Narrative Context + Dynamic Tool Coaching

## Context

The user wants score-aware coaching that pushes users toward 90+ strict, with per-dimension structural recommendations, wontfix debt callouts, and anti-laziness nudges at every touchpoint.

Two independent critical reviews converged on the same insight: **the primary consumer is an LLM reading `query.json`, not a human reading the terminal**. Every command already calls `_write_query()`. The SKILL.md instructs the LLM to read that JSON. This means the richest coaching should flow through query.json as structured data, letting the LLM craft natural responses — while the terminal gets tight, computed observations instead of canned platitudes.

**Critical addition**: The narrative must dynamically surface the right desloppify tool for each problem. When coupling/organization issues dominate → tell them about `move`. When T1 items exist → tell them about specific `fix` commands. The LLM needs enough structured context to act as a coach at every stage, not just report numbers.

### 1. New file: `desloppify/narrative.py` (~220 lines)

One module, pure functions, computes structured observations from state data. No print statements. Returns dicts that flow into `_write_query()`.

**Main function:**
```python
def compute_narrative(state: dict, *, diff: dict | None = None, lang: str | None = None) -> dict
```

Returns a structured narrative context dict with these computed sections:

**a) Phase detection** (from scan_history trajectory):
- `"first_scan"` — no history, frame as discovery
- `"early_momentum"` — scans 2-5, score rising
- `"middle_grind"` — T1/T2 clear, T3/T4 dominate, progress slowing
- `"refinement"` — strict >80, dimension-level tuning
- `"maintenance"` — strict >93, watch for regressions
- `"stagnation"` — strict unchanged ±0.5 for 3+ scans
- `"regression"` — strict dropped from previous scan

**b) Headline** — one computed sentence for terminal display:
- Leverage point: "Coupling is your biggest lever: 8 items → +4.2 pts" (uses `compute_score_impact`)
- Stagnation: "Score stuck at 65.0 for 3 scans. 12 wontfix items in Organization — revisit?"
- Gap: "Strict 61.2 vs lenient 72.3 — 11.1 pts of wontfix debt, mostly in Coupling"
- Milestone: "You cleared all T1 items!" / "Crossed 80% strict!"
- Regression: "Score dropped 3.2 — 5 findings reopened, likely cascade from recent fixes"
- First scan: "First scan complete. {N} findings across {M} dimensions."

## Key design principles

- **Computed, not canned.** Every observation is derived from actual data. No lookup tables of advice.
- **Tool-aware.** Every recommendation maps to a specific desloppify command the user can run.
- **Trajectory-aware.** Phase detection uses scan_history, not static score ranges.
- **One headline, not a wall.** Terminal gets 1 line max. LLM gets the full structured context.
- **LLM is the coach.** The narrative module provides the structured playbook; the LLM crafts the conversation. SKILL.md tells it how.
- **Net output reduction.** We remove 3-4 static lines and add 0-1 computed lines.

## How the LLM gets enough context

At each stage, the LLM sees:

| Stage | Terminal | query.json | LLM knows to... |
|-------|----------|------------|------------------|
| After scan | 1 headline | narrative.phase, narrative.actions, narrative.tools | Suggest specific fixers or move commands based on what's new |
| After status | Focus dimension + headline | narrative.dimensions, narrative.debt | Recommend the right tool for the weakest dimension |
| After next | Finding detail | narrative.actions (with tool_type per action) | Tell user which tool fixes this specific finding type |
| After show | Findings list | narrative.tools (relevant to shown detector) | Suggest auto-fix if available, move if structural |
| After resolve | Milestone (if any) | narrative.phase, narrative.debt (updated) | Celebrate milestones, surface remaining debt |
| After fix | Items fixed + skips | narrative.actions (next priority) | Suggest rescan, then next tool to use |
