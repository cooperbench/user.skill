Here's a summary of what the plan proposes:

**The systematic issue:** Three tools (`join-clips`, `edit-video`, `travel-between-images`) each define defaults in TWO places — `settings.ts` (used by the DB cascade) and a hook-level `DEFAULT_*` constant (used by `useAutoSaveSettings` for local state). These have silently drifted apart, causing bugs. Components then add a third layer of fallback defaults, and task creation adds a fourth.

**The fix:** Follow the `character-animate` pattern — `settings.ts` is the single source of truth, hooks import from it instead of defining their own constants. Wrapper hooks that need extra fields (like `useJoinSegmentsSettings`) spread the base defaults and only add their extension fields.

Key changes:
- **3 hook files** lose their duplicate `DEFAULT_*` constants, import from `settings.ts` instead
- **`travel-between-images/settings.ts`** fixes stale `enhancePrompt: true` → `false`
- **`joinClips.ts:295`** fixes contradictory `enhance_prompt ?? true` → `false`
- **~10 component files** lose unnecessary inline destructuring fallbacks
- **No structural changes** to `useAutoSaveSettings` or `useToolSettings` — the architecture is sound, it's just the usage pattern that needs fixing
