# Plan: Trailing Segment as First-Class Position Entity

## Problem

The trailing segment endpoint is bolted onto the position system via completely separate state management. Normal segments use `useTimelinePositions` (optimistic updates, single source of truth). The trailing endpoint bypasses all of this with its own `derivedEndFrame`/`localEndFrame` state, a separate prop chain through 3+ memo'd components, and custom DB writes. This caused the "form doesn't update timeline" bug and makes the code hard to reason about.

## Approach

Add the trailing endpoint to the `useTimelinePositions` positions map as a keyed entry (`TRAILING_ENDPOINT_ID`). All reads and writes go through the position system, giving consistent optimistic update behavior. The visual rendering stays as `TrailingEndpoint` (it's intentionally different from `PairRegion`).

## Key Design Decisions

- **Key**: Reuse existing `TRAILING_ENDPOINT_ID = '__trailing_endpoint'` from `TrailingEndpoint.tsx`
- **`getPairInfo`**: Filter out trailing key (trailing is still rendered separately, not as a normal pair)
- **`quantizePositions`**: Extract trailing key before quantizing (its gap has different constraints), re-add after
- **`updatePositions` DB write**: Partition changes — normal entries go through `batch_update_timeline_frames` RPC, trailing entry does a separate `metadata.end_frame` write on the last image
- **Drag handler**: Stays in `useTimelineOrchestrator` (different constraints than image drag) but writes through position system instead of direct Supabase
