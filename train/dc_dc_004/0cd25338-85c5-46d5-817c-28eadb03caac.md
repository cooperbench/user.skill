## Analysis: Timeline Prop-Drilling Chain

### The Chain

```
ShotSettingsContext (has everything)
  → TimelineSection (destructures context into individual props)
    → ShotImagesEditor (72 props interface, ~60 passed to Timeline)
      → Timeline (115 props interface, ~45 passed to TimelineContainer)
        → TimelineContainer (86 props interface, consumes all)
```

### The Real Structural Issue

The finding about "15 structure video/audio props repeated at all 3 levels" is accurate, but the deeper issue is more interesting: **there's already a context that has all this data (`ShotSettingsContext`), but it gets destructured into individual props at `TimelineSection`, then those individual props flow through 3 more layers as a flat list.**

Looking at `TimelineSection.tsx:91-93`:

It pulls structured objects out of context, then immediately explodes them into ~20 individual props on `ShotImagesEditor`. ShotImagesEditor reassembles them and passes them through to `Timeline`, which passes them through untouched to `TimelineContainer`.

### What's Actually Wrong (Structural Issues)

**Issue 1: Context is available but not used below TimelineSection**

The `ShotSettingsContext` already exposes `useShotStructureVideo()`, `useShotAudio()`, etc. But ShotImagesEditor doesn't use context - it takes everything as props. This made sense historically (ShotImagesEditor also renders in `SharedGenerationView` which has no `ShotSettingsContext`), but it means 18+ props flow through 3 layers unnecessarily in the primary (non-shared) code path.

**Issue 2: Legacy single-video props alongside multi-video array**

The structure video section has **both** a legacy single-video interface (8 props) and a new multi-video array interface (4 props). The `useStructureVideo` hook even marks the legacy accessors as `@deprecated`. These dual interfaces bloat every level in the chain.

**Issue 3: Dead props**

`uni3cEndPercent` and `onUni3cEndPercentChange` flow through 3 components but are never consumed by TimelineContainer (it doesn't destructure them). They also aren't consumed by Timeline. They're only used in `ShotImagesEditor` → `BatchModeContent` path, not the Timeline path.

**Issue 4: Timeline is an orchestrator that barely orchestrates the drilled props**

Timeline's primary job is managing the lightbox, external generations, and position hooks. For the structure video/audio/shot management props, it's purely a relay. Its 115-prop interface is inflated by props it never reads.

**Phase 1: Remove dead props and legacy duplication** (quick, low-risk)

1. Remove `uni3cEndPercent` and `onUni3cEndPercentChange` from `TimelineProps` and `TimelineContainerProps` - they're only used in batch mode path
2. Audit whether the legacy single-video structure props can be removed from the Timeline→TimelineContainer chain (they're only consumed via the `structureVideos ? multi : legacy` branching in TimelineContainer)

**Phase 2: Group pass-through props into sub-interfaces** (medium effort)

Create typed sub-interfaces for the prop groups that are drilled verbatim:

```ts
// In a shared types file
interface StructureVideoProps {
  structureVideoPath?: string | null;
  structureVideoMetadata?: VideoMetadata | null;
  structureVideoTreatment?: 'adjust' | 'clip';
  structureVideoMotionStrength?: number;
  structureVideoType?: 'uni3c' | 'flow' | 'canny' | 'depth';
  onStructureVideoChange?: (...) => void;
  structureVideos?: StructureVideoConfigWithMetadata[];
  onAddStructureVideo?: (...) => void;
  onUpdateStructureVideo?: (...) => void;
  onRemoveStructureVideo?: (...) => void;
}

interface AudioStripProps {
  audioUrl?: string | null;
  audioMetadata?: { duration: number; name?: string } | null;
  onAudioChange?: (...) => void;
}
```

Then `TimelineProps` and `TimelineContainerProps` use `& StructureVideoProps & AudioStripProps`, and the drilling becomes `{...structureVideoProps}` instead of 15 individual props. This makes the pass-through explicit without changing architecture.

**Phase 3: Consider context for the primary code path** (larger change, optional)

The most impactful change would be making `Timeline` and `TimelineContainer` context-aware when running inside `ShotSettingsContext`. This would:
- Eliminate ~18 pass-through props from Timeline entirely
- Let TimelineContainer call `useShotStructureVideo()` and `useShotAudio()` directly
- Keep the props interface for `SharedGenerationView` (which has no context)
