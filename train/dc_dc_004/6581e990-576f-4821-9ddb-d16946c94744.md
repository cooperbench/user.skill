## TIER 1: Potential Data Corruption / Money Bugs

These could silently lose user data or charge incorrectly.

### 1. Cost calculation silently charges 100x on missing task_type row
**`supabase/functions/calculate-task-cost/index.ts:305-310`**
If a `task_types` row is missing (e.g. new task type added to client but not to DB), the fallback is `0.01/sec` — roughly 100x the intended FILM rate of `0.0013/sec`. No alert, no log escalation. The user gets silently overcharged.

### 2. Cascading task failure can overwrite completed tasks as "Failed"
**`supabase/functions/update-task-status/index.ts:229-278`**
When an orchestrator fails, the code reads child tasks then updates each individually. Between read and write, a child could legitimately complete. The cascade overwrites `Complete` → `Failed`. Not atomic — no transaction wraps this.

### 3. Stripe webhook idempotency check is not atomic
**`supabase/functions/stripe-webhook/index.ts:155-174`**
The "already processed" check (SELECT) and the insert are separate operations. Two near-simultaneous webhook deliveries can both pass the check and both insert, potentially double-crediting. The unique constraint catch at line 176 handles this partially, but the flow between ledger insert and `process-auto-topup` call could still race.

### 4. `extractFromParams` converts booleans to strings, breaking `addInPosition` logic
**`supabase/functions/complete_task/params.ts:62, 163-164`**
`String(false)` becomes `'false'` (a truthy string). The comparison `=== 'true'` catches `true` correctly, but a boolean `false` stored in params becomes `'false'` which is truthy when tested as a string. This can cause images to be incorrectly positioned in shots.

### 5. Regeneration handler ignores `create_as_generation` flag
**`supabase/functions/complete_task/generation.ts:88-100`**
When a task already has an existing generation, the code always creates a variant. It doesn't check `create_as_generation`, so there's no way to force a new standalone generation for a re-run.

## TIER 2: Race Conditions & Concurrency

### 6. Settings read-modify-write race across tabs
**`src/shared/hooks/useToolSettings.ts:58-78`**
Settings are read from DB, merged client-side with `deepMerge`, then written back via RPC. Two tabs doing this simultaneously will cause last-write-wins, silently discarding one tab's changes. The write queue serializes writes within one tab but can't help across tabs.

### 7. `beforeunload` doesn't await pending settings writes
**`src/shared/lib/settingsWriteQueue.ts:194-197`**
`flushAll()` fires async writes but `beforeunload` doesn't wait for promises. Quick navigation after settings changes can lose writes.

### 8. Auto-topup trigger timing race
**`supabase/functions/process-auto-topup` and `trigger-auto-topup`**
Both check `auto_topup_last_triggered` but don't update it atomically. Multiple near-simultaneous triggers can all pass the time check and proceed.

### 9. Welcome bonus concurrent creation race
**`supabase/functions/grant-credits/index.ts:109-164`**
Two simultaneous requests can both see "user doesn't exist", both try to create the user row. One gets a 23505 conflict but continues assuming the user exists, potentially granting the bonus twice.

### 10. Variant loading race — old variant images overwrite new selection
**`src/shared/hooks/useLoadVariantImages.ts:50-100`**
Selecting Variant A starts async image loading. Quickly selecting Variant B starts another load. If A completes after B, the timeline shows A's images while the UI says B is selected. No abort controller or session tracking.

## TIER 3: Logic Bugs

### 11. Lexicographic `.sort()` on generation IDs causes cache misses
**`src/shared/hooks/useVariantBadges.ts:51-54`**
`[...generationIds].sort()` without a comparator does string sorting: `['10','2','3']` sorts to `['10','2','3']` instead of `['2','3','10']`. Different insertion orders of the same ID set produce different query keys, causing duplicate React Query cache entries and wasted fetches.

### 12. `clearNavigation` useCallback has wrong dependency array
**`src/shared/components/MediaGallery/hooks/useMediaGalleryPagination.ts:182-191`**
Dependencies are `[navigationState.status, navigationState.direction]` but the callback body doesn't use these values — it resets to `INITIAL_NAVIGATION_STATE`. This causes unnecessary callback recreation and a stale closure chain through `handlePageChange`.

### 13. Two files sort shots by lossy `position` instead of `timeline_frame`
**`src/tools/travel-between-images/hooks/useNavigationState.ts:57` and `ShotListDisplay.tsx:103`**
`position = Math.floor(timeline_frame / 50)` is lossy — multiple timeline_frames map to position 0. Sorting by `position` loses deterministic ordering. The other 26 files correctly sort by `timeline_frame`.

### 14. Pagination range shows "0 to -1" on empty results
**`src/shared/components/MediaGallery/hooks/useMediaGalleryPagination.ts:154-159`**
When `totalFilteredItems === 0`, `rangeStart = 0` and `rangeEnd = 0 + 0 - 1 = -1`. UI displays "Showing 0 to -1 of 0".

### 15. `pair_shot_generation_id` validated for existence but not for correct shot
**`supabase/functions/complete_task/generation-child.ts:289-303`**
The code checks the FK reference exists but not that it belongs to the target shot. A regeneration with a `pair_shot_generation_id` from a different shot would create a variant on the wrong parent.

**`src/shared/lib/settingsResolution.ts:18-20`**
