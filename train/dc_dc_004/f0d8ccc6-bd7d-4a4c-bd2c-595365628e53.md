**Root cause: double `getSession()` with `navigator.locks` stall**

The sequence was:
1. `AuthContext.getSession()` runs → acquires Supabase's exclusive `navigator.locks` lock → resolves → `isLoading = false`
2. `AuthGate` lets through → providers initialize → projects load → `[ImageLoadTracker]` log fires
3. `Layout` mounts → `useAuthGuard()` starts with `session = undefined` → shows `<ReighLoading />`
4. `useAuthGuard.getSession()` tries to acquire `navigator.locks` — but if Supabase's `autoRefreshToken` kicked in between steps 1 and 3, that refresh holds the exclusive lock and `getSession()` queues behind it
5. App stays stuck on `<ReighLoading />` indefinitely — no timeout, no fallback

**Fix:** `Layout` now uses `useAuth()` instead of `useAuthGuard()`. By the time `Layout` renders, `AuthGate` has already guaranteed `isLoading = false`, so the auth state is immediately available from context with no second lock acquisition needed. `AuthContext` also maintains ongoing auth subscriptions via `AuthStateManager`, so sign-out events still work correctly.

`useAuthGuard.ts` and its test still exist but `Layout` no longer calls it.

## Root cause of the visual stall
