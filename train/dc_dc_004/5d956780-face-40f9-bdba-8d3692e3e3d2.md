# Make Subjective Review a First-Class Detector+Fixer

## Context

Desloppify has two workflows: **scan** (find problems) and **fix** (resolve them). A `review_coverage` detector already runs during scan and flags production files that haven't been through the subjective design review process. This plan renames the detector to `subjective_review` for clarity and adds the `fix review` fixer to complete the workflow.

**What is subjective review?** An AI/human evaluates production code against 11 quality dimensions (naming, error handling, abstraction fitness, etc.) that automated linting can't catch. The detector tracks which files need this process; the fixer guides the reviewer through it using dimension prompt templates.

## Naming

| Name | What it is |
|------|------------|
| `subjective_review` | **Scan detector** — flags files needing subjective review (unreviewed, changed, stale) |
| `review` | **Import-only detector** — actual findings from AI review (naming issues, error inconsistencies, etc.) |
| `fix review` | **Fixer command** — prepares review data + dimension templates for AI to evaluate files |
