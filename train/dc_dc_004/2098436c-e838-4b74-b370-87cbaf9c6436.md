# Plan: `useTaskPlaceholder` — Collapse Placeholder Boilerplate to One Call

## Context

After the task-ID matching refactor, 17 callers each contain the same 5-line lifecycle:
```typescript
const { addIncomingTask, removeIncomingTask, resolveTaskIds } = useIncomingTasks();
// ...
const id = addIncomingTask({ taskType, label });
try {
  const result = await createXxxTask(params);
  resolveTaskIds(id, [result.task_id]);
} finally {
  await queryClient.refetchQueries(...paginatedAll);
  await queryClient.refetchQueries(...statusCountsAll);
  removeIncomingTask(id);
}
```
Two additional issues: (a) `useRepositionTaskCreation` has no `finally` — splits cleanup between `try` and `catch`, and omits refetch on error. (b) The four `useMutation` callers need a `useRef` to pass the placeholder ID across `onMutate`/`onSuccess`/`onSettled` callbacks.

**Goal**: One hook, one call. Callers say "show a placeholder while this runs." The lifecycle is invisible.

---

## The Abstraction

### New file: `src/shared/hooks/useTaskPlaceholder.ts`

```typescript
export interface TaskPlaceholderOptions {
  taskType: string;
  label: string;
  expectedCount?: number;
  context: string;          // for handleError
  toastTitle: string;       // for error toast
  create: () => Promise<unknown>;   // auto-extracts task IDs from result
  onSuccess?: (taskIds: string[]) => void | Promise<void>;  // extra invalidations, success state
}

export function useTaskPlaceholder(): (options: TaskPlaceholderOptions) => Promise<void>
```

**Internal logic:**
1. `addIncomingTask({ taskType, label, expectedCount })`
2. `try { result = await create(); taskIds = extractTaskIds(result); resolveTaskIds(id, taskIds); await onSuccess?.(taskIds); }`
3. `catch { handleError(...) }`
4. `finally { refetch(paginatedAll, statusCountsAll); removeIncomingTask(id); }`

**`extractTaskIds(result: unknown): string[]`** — auto-detects shape:
- `{ task_id: string }` → `[result.task_id]` (single `TaskCreationResult`)
- `Array<{ task_id: string }>` → `result.map(r => r.task_id)` (batch results)
- `string` → `[result]` (raw task_id, used by `submitSegmentTask`)
- `void/null` → `[]` (graceful degradation)

**Caller example (before/after):**
```typescript
// Before — 9 lines of boilerplate
const { addIncomingTask, removeIncomingTask, resolveTaskIds } = useIncomingTasks();
const queryClient = useQueryClient();
const id = addIncomingTask({ taskType: 'image-upscale', label: 'Upscale 2x' });
try {
  const result = await createImageUpscaleTask(params);
  resolveTaskIds(id, [result.task_id]);
} finally {
  await queryClient.refetchQueries({ queryKey: taskQueryKeys.paginatedAll });
  await queryClient.refetchQueries({ queryKey: taskQueryKeys.statusCountsAll });
  removeIncomingTask(id);
}

// After — 5 lines, no boilerplate
const run = useTaskPlaceholder();
try {
  await run({ taskType: 'image-upscale', label: 'Upscale 2x',
               context: 'useUpscale', toastTitle: 'Upscale failed',
               create: () => createImageUpscaleTask(params) });
} finally {
  setIsUpscaling(false);  // caller-specific state only
}
```

## Key Invariants

- `run()` always calls `removeIncomingTask` in `finally` — no more split try/catch cleanup
- `run()` always refetches `paginatedAll` + `statusCountsAll` in `finally` — fixes `useRepositionTaskCreation`'s error path

- Error handling (`handleError`) is inside `run()` — callers don't need `toastTitle` in scope
- No more `useRef` for placeholder IDs in mutation callers
