## Issue found during review: Config data DRY violation

Complexity signals, god rules, and naming skip patterns are currently defined **inline** in both the phase runner and the cmd wrapper — the same list of signals appears in `_phase_structural` AND `_cmd_ts_complexity`. Same for god rules. This means:
- Change a threshold? You have to change it in two places.
- Add a new language? You copy-paste config data into two functions.

**Fix:** Hoist config data to module-level constants in `__init__.py`. Both phase runners (same file) and cmd wrappers (in `commands.py`, import from parent) reference the single source of truth. This follows the plan's "config is data, not code" principle.

```python
# lang/typescript/__init__.py — config data section
TS_COMPLEXITY_SIGNALS = [
    ComplexitySignal("imports", r"^import\s", weight=1, threshold=15),
    ComplexitySignal("destructured props", None, weight=1, threshold=8,
                     compute=_compute_ts_destructure_props),
    ...
]
TS_GOD_RULES = [
    GodRule("context_hooks", "context hooks", lambda c: c.metrics.get("context_hooks", 0), 3),
    ...
]
TS_SKIP_NAMES = {"index.ts", "index.tsx", "types.ts", ...}
TS_SKIP_DIRS = {"src/shared/components/ui"}
```

Then `_phase_structural` references `TS_COMPLEXITY_SIGNALS` and `TS_GOD_RULES`, and `commands.py` does:
```python

```

Same for Python: `PY_COMPLEXITY_SIGNALS`, `PY_GOD_RULES`, `PY_SKIP_NAMES`.

## Convention: Lang Package File Layout

Establish this as the enforced convention for all language packages:

```
lang/<name>/
├── __init__.py      # LangConfig subclass + phase runners + config data (signals, rules, thresholds)
├── commands.py      # detect-subcommand wrappers + command registry
├── extractors.py    # extract_* functions → FunctionInfo/ClassInfo
├── deps.py          # Import graph builder + cmd_deps, cmd_cycles
├── unused.py        # Language tool wrapper + cmd_unused
├── smells.py        # Language-specific smell rules + multi-line helpers
└── <ts-only>.py     # logs, exports, deprecated, concerns, patterns, props, react
```

**Rules:**
- `__init__.py` ≤ 400 LOC — scan pipeline + config only. No CLI display code.
- `commands.py` ≤ 350 LOC — all `detect` subcommand wrappers for shared detectors.
- Detectors that live in the lang package (e.g., `logs.py`) keep their cmd wrapper in the same file.
- All cmd wrappers named `cmd_<name>(args)` — no underscore prefix, no language prefix (module path provides context).

## Step 1: Display helper in `utils.py`

Add `display_entries()` to `scripts/decruftify/utils.py` — shared by all cmd wrappers:

```python
def display_entries(args, entries, *, label, empty_msg, columns, widths, row_fn,
                    json_payload=None, overflow=True):
    """Standard JSON/empty/table display for detect commands.

    Returns True if entries were displayed, False if empty.
    """
    import json as _json
    if getattr(args, "json", False):
        payload = json_payload or {"count": len(entries), "entries": entries}
        print(_json.dumps(payload, indent=2))
        return True
    if not entries:
        print(c(empty_msg, "green"))
        return False
    print(c(f"\n{label}: {len(entries)}\n", "bold"))
    top = getattr(args, "top", 20)
    rows = [row_fn(e) for e in entries[:top]]
    print_table(columns, rows, widths)
    if overflow and len(entries) > top:
        print(f"\n  ... and {len(entries) - top} more")
    return True
```

**Saves ~10 LOC per wrapper** for the 13 simple-pattern wrappers (~130 LOC total).
