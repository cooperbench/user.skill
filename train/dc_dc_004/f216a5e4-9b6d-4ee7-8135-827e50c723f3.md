## Phase 1: Fix `json_parse_unguarded` False Positives

### File: `desloppify/lang/typescript/detectors/security.py` (lines 175-203)

**Problem**: The `in_try` counter is fragile — `try {` must be on same line, no string awareness, closing `}` detection depends on line position.

**Fix**: Replace stateful `in_try` counter with per-match backward scan. For each `JSON.parse` match, scan backward through preceding lines tracking brace depth. If we hit `try` when depth is ≤ 0, the parse is guarded.

```python
def _is_in_try_scope(lines: list[str], target_line: int) -> bool:
    """Check if target_line is inside a try block by scanning backwards."""
    depth = 0
    for i in range(target_line - 2, -1, -1):  # 0-indexed, go backwards
        stripped = lines[i].strip()
        depth += stripped.count('}') - stripped.count('{')
        if depth <= 0 and re.search(r'\btry\b', stripped):
            return True
    return False
```

Then in `_check_json_parse_unguarded`, replace the `in_try` tracking loop with:
```python
if _JSON_PARSE_RE.search(line) and not _is_in_try_scope(lines, line_num):
    if not _JSON_DEEP_CLONE_RE.search(line):
        entries.append(...)
```

### Tests: `tests/test_security.py`
- `test_json_parse_in_try_catch_not_flagged` — inside `try { ... } catch` → not flagged
- `test_json_parse_in_try_multiline` — `try` on one line, `{` on next → not flagged
- `test_json_parse_outside_try_still_flagged` — no enclosing try → still flagged
- `test_json_parse_nested_function_in_try` — inside inner function → still flagged (conservative: depth resets)
