# Generic Language Plugin System

## Context

desloppify ships 5 full language plugins (python, typescript, csharp, dart, gdscript), each requiring ~6 files + 3 directories. Adding more languages at that cost is impractical. The goal is one simple generic system — used both internally to ship many more languages and externally for users to add their own detectors.

The system is built around one idea: **run a shell tool, parse the output format, emit findings**. Each "language plugin" is just a list of tool configs. Depth is honest metadata, not a goal.

---

## Core: `desloppify/languages/framework/generic.py` (new file)

Single file. No package. Four pieces:

### 1. Output parsers

**`parse_gnu(output, scan_path) → list[dict]`**
Handles `file:line: message` and `file:line:col: message`. Used by: go vet, mypy, cppcheck, clang-tidy, cargo (fallback).

**`parse_golangci(output, scan_path) → list[dict]`**
Handles `{"Issues": [{"Pos": {"Filename": ..., "Line": ...}, "Text": ...}]}`. Used by golangci-lint.

**`parse_json(output, scan_path) → list[dict]`**
Flat JSON array with field aliases: `file`/`filename`/`path`, `line`/`line_no`/`row`, `message`/`text`/`reason`. Used by swiftlint, phpstan, credo, ktlint.

**`parse_rubocop(output, scan_path) → list[dict]`**
Handles nested `{"files": [{"path": ..., "offenses": [{"location": {"line": ...}, "message": ...}]}]}`.

**`parse_cargo(output, scan_path) → list[dict]`**
Handles cargo clippy JSON Lines: `{"reason": "compiler-message", "message": {"spans": [{"file_name", "line_start"}], "rendered": ...}}`.

### 2. `make_tool_phase(label, cmd, fmt, smell_id, tier) → DetectorPhase`

Runs the command at scan time. Graceful degradation: `FileNotFoundError` or `TimeoutExpired` → `[], {}`. Non-zero exit without output → `[], {}`. Parses with the appropriate parser. Returns `(findings, {smell_id: count})`.

```python
def make_tool_phase(label: str, cmd: str, fmt: str, smell_id: str, tier: int) -> DetectorPhase:
    def run(path: Path, lang) -> tuple[list, dict]:
        try:
            result = subprocess.run(cmd, shell=True, cwd=path,
                                    capture_output=True, text=True, timeout=120)
        except (FileNotFoundError, TimeoutExpired):
            return [], {}
        output = result.stdout + result.stderr
        entries = _PARSERS[fmt](output, path)
        findings = [make_finding(smell_id, e["file"], f"{smell_id}::{e['line']}",
                                 tier=tier, summary=e["message"]) for e in entries]
        return findings, {smell_id: len(entries)} if entries else {}
    return DetectorPhase(label, run)
```

### 3. Stubs

**`make_file_finder(extensions, exclusions)`** — globs for given extensions, respects `_extra_exclusions`.
**`empty_dep_graph(path)`** — returns `{}`.
**`generic_zone_rules(extensions)`** — minimal rules: test dirs → test, vendor/node_modules → vendor.

### 4. `generic_lang(name, extensions, tools, *, exclude=None, depth="shallow") → LangConfig`

Builds and registers a LangConfig. Each entry in `tools` is:
```python
{"label": str, "cmd": str, "fmt": str, "id": str, "tier": int}
```

Calls `register_generic_lang(name, cfg)` — which skips `validate_lang_structure`, calls `validate_lang_contract`, stores instance in `registry_state._registry`.

## Depth field on LangConfig

Add one field to `desloppify/languages/framework/base/types.py`:
```python
integration_depth: str = "full"  # "full" | "standard" | "shallow" | "minimal"
```

- `full` — custom Python detectors, full phase coverage (python, typescript, csharp, dart, gdscript)
- `standard` — multiple external tools covering lint + type checking or security
- `shallow` — 1-2 tools covering linting only
- `minimal` — single tool, basic coverage

## Language plugins to ship

All go in `desloppify/languages/` as `plugin_<lang>.py`. Pattern is identical for all:

```python
# desloppify/languages/plugin_go.py
from desloppify.languages.framework.generic import generic_lang

generic_lang(
    name="go",
    extensions=[".go"],
    tools=[
        {"label": "golangci-lint", "cmd": "golangci-lint run --out-format=json",
         "fmt": "golangci", "id": "golangci_lint", "tier": 2},

         "fmt": "gnu", "id": "vet_error", "tier": 3},
```

## User-extensible plugins

Add to `desloppify/languages/framework/discovery.py` after `load_all()` finishes: scan `PROJECT_ROOT/.desloppify/plugins/*.py` and import each. Users drop a file there calling `generic_lang()` with their own tools — no framework knowledge needed.

```python
# .desloppify/plugins/plugin_mycheck.py
from desloppify.languages.framework.generic import generic_lang

generic_lang(
    name="python",          # augments existing python detection
    extensions=[".py"],
    tools=[{"label": "mypy strict", "cmd": "mypy --strict .",
            "fmt": "gnu", "id": "mypy_strict", "tier": 2}],
    depth="shallow",
)
```

Wait — augmenting an existing language (python) by calling `generic_lang("python", ...)` would overwrite the existing python plugin in `_registry`. **Augmentation needs a separate function**: `add_detector(lang_name, tool_spec)` that appends a phase to an already-registered config rather than replacing it.

This is low-risk to add at implementation time once we see how resolution.py works.
