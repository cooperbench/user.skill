## Phase 2: Create fixers/ Directory + Extract Common Utilities

**Why:** fix.py is 1,289 lines with 7 fixers repeating the same ~20-line template, and 4 near-identical bracket-tracking implementations.

### Step 2a: Create `fixers/` with `common.py`

Create `fixers/__init__.py` and `fixers/common.py` containing:

1. **`find_balanced_end(lines, start, *, track="parens", max_lines=80)`** — unified bracket tracker replacing `_find_statement_end` (parens only), `_find_block_end` (all brackets), and reusable by `_find_if_chain_end` and `_extract_useeffect_body`. The `track` param selects which brackets to track: `"parens"`, `"braces"`, `"all"`. All implementations share the same `in_str`/`prev_ch` string-escape state machine.

2. **`extract_body_between_braces(text, search_after="")`** — replaces `_extract_useeffect_body`. Finds first `{` (optionally after a search string like `=>`), tracks to matching `}`, returns inner content.

3. **`apply_fixer(entries, transform_fn, *, dry_run=False, file_key="file")`** — shared file-loop template. Groups entries by file, resolves path, reads content, calls `transform_fn(lines, file_entries) -> (new_lines, removed_names)`, diffs, writes if changed, catches exceptions. Returns `list[{file, removed, lines_removed}]`.

### Step 2b: Split fix.py into per-fixer files

Each fixer moves to its own file in `fixers/`, using `common.py` utilities:

| File | Source | Content |

`fixers/__init__.py` re-exports all fix functions so existing `from .fix import fix_*` imports in cli.py can change to `from .fixers import fix_*`.

- **Overview**: What decruftify is, what it does (2-3 sentences)
- **Directory Layout**: Annotated tree of the package after refactoring
- **Data Flow Diagram**: scan → detectors → plan.generate_findings → state.merge_scan → state.json; fix → detector → fixer → state.resolve; show/resolve → state.match_findings
- **Key Abstractions**:
  - Finding: `{id, detector, file, tier, confidence, summary, detail, status}`. ID format: `detector::rel_path::name`
  - State: `{findings, score, strict_score, stats, config, scan_count, last_scan}`
  - Tier system: T1 auto-fixable, T2 quick fix, T3 needs judgment, T4 major refactor
  - Scoring: tier-weighted (T4=4x weight), strict score excludes wontfix
- **Detector Contract**: `detect_*(path: Path) -> list[dict]` + `cmd_*(args)`. Each returns tool-specific dicts; plan.py normalizes to findings
- **Fixer Contract**: `fix_*(entries, *, dry_run) -> list[{file, removed, lines_removed}]`. Shared template in `fixers/common.py`
- **State Machine**: Finding statuses: open → fixed/wontfix/false_positive/auto_resolved. Merge logic: new findings added, disappeared auto-resolved (with suspect-detector guard), wontfix that disappear upgrade to auto_resolved
- **CLI Architecture**: argparse in cli.py, commands in commands/, each command imports what it needs

### `scripts/decruftify/README.md` — User-facing guide

Content outline:
- **Quick Start**: scan → status → fix → re-scan loop (4 commands)
- **Workflow**: Step-by-step guide for a typical cleanup session
- **Commands Reference**: One section per command with examples
  - scan, status, show, next, resolve, ignore, fix, plan, detect, tree, viz
- **Fix Order**: The cascade chain (debug-logs → unused-imports → dead-exports → unused-vars → unused-imports again)
- **Tier System**: What T1-T4 mean, what goes in each tier
- **Score Interpretation**: Weighted scoring, strict vs permissive, why score can temporarily drop
- **Tips**: Always `--dry-run` first, always `npx tsc --noEmit` after fixing, always commit between fixers
