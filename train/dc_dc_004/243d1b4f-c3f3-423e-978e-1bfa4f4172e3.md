## Phase 5: Fix prev_ch String Tracking Bug

15 sites use `prev_ch != "\\"` to track whether we're inside a string. This fails on `\\\"` (escaped backslash before quote). The correct pattern (already used in `_strip_ts_comments`) uses `i += 2` to skip escaped characters.

**Strategy:** Extract a shared string-aware character iterator:

```python
# desloppify/lang/typescript/detectors/_smell_helpers.py (or a new shared module)

def iter_code_chars(content: str) -> Iterator[tuple[int, str, bool]]:
    """Yield (index, char, in_string) for each character, handling escapes correctly.

    Skips escaped characters (\\x) by advancing +2 instead of +1.
    Tracks single-quoted, double-quoted, and template literal strings.
    """
    i = 0
    in_string = False
    string_char = ""
    while i < len(content):
        ch = content[i]
        if in_string:
            if ch == "\\" :
                yield (i, ch, True)
                i += 2  # Skip escaped char entirely
                continue
            if ch == string_char:
                in_string = False
                string_char = ""
            yield (i, ch, True)
        else:
            if ch in ("'", '"', '`'):
                in_string = True
                string_char = ch
            yield (i, ch, in_string)
        i += 1
```

**15 sites to fix** (all in `desloppify/lang/typescript/detectors/_smell_helpers.py` and `desloppify/lang/typescript/extractors.py`):

For each site, replace the manual `prev_ch` tracking loop with the shared iterator, or apply the `i += 2` skip pattern inline. The specific fix depends on what each site is doing (brace counting, string detection, etc.), so each needs individual attention.

**Testing:** Add a test case with `\\\"` (escaped backslash before quote) for each affected detector to confirm the fix.

## Phase 8: File Content Cache

During a scan, each file is read 14-20 times by different detectors (`grep_files`, `grep_files_containing`, `_read_file_text`). For a 1000-file codebase, that's ~15,000 redundant reads.

**Solution:** Add an opt-in scan-scoped cache to `utils.py`:

```python
# utils.py

_file_cache: dict[str, str | None] = {}
_cache_enabled = False

def enable_file_cache():
    global _cache_enabled
    _cache_enabled = True
    _file_cache.clear()

def disable_file_cache():
    global _cache_enabled
    _cache_enabled = False
    _file_cache.clear()

def _read_file_text(filepath: str) -> str | None:
    """Read a file as text, with optional caching."""
    if _cache_enabled:
        if filepath in _file_cache:
            return _file_cache[filepath]
    try:
        content = Path(filepath).read_text(errors="replace")
    except OSError:
        content = None
    if _cache_enabled:
        _file_cache[filepath] = content
    return content
```

**Integration:** `scan` command enables cache before running phases, disables after:
```python
# commands/scan.py
from ..utils import enable_file_cache, disable_file_cache

enable_file_cache()
try:
    findings, potentials = generate_findings(path, lang=lang, ...)
finally:
    disable_file_cache()
```

**Memory:** For a 1000-file codebase averaging 200 lines/file, cache uses ~40-80MB — acceptable for a CLI tool that runs and exits.

**Testing:** Add a test that enables cache, reads a file twice, verifies only one disk read (mock `Path.read_text`).
