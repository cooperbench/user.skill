> DEVELOPER

is this overszealous or fair?

> AGENT

Fair, with one slightly awkward detail.

**Why it's fair:**
- A 0-file review packet is not a partial result — it's a completely useless one. Proceeding silently produces a `query.json` that looks valid and an agent will act on it. That's worse than failing.
- The error is specific, the hint reads directly from state and tells you the exact command to run. It's not just a vague "something went wrong."
- `sys.exit(1)` is the right severity — this isn't a warning condition.

**The one awkward thing:** `write_query_fn(data)` is called before the guard check. The commit message tries to justify this ("so agents can inspect the empty packet for debugging") but that's not a real use case — nobody is going to deliberately introspect an empty query.json. The honest reason is just that the check comes after `write_query_fn` in the code flow. It's not actively harmful, but it means a failed run leaves a stale `query.json` that contains 0 files — which a subsequent command might read and misinterpret.

The cleaner version would be to check `total_files` before writing, and only write on success:

```python
total = data.get("total_files", 0)
if total == 0:
    # ... error + sys.exit(1) — never writes query.json
    
write_query_fn(data)  # only reached when there are files
```

Worth fixing, but it's genuinely minor — the exit code already signals failure to any process that cares, and the next successful run overwrites `query.json` anyway.

The detectors most worth converting first, because the current implementations are most likely to produce false positives: **`unused`** (type-only imports trip it), **`exports`/`orphaned`** (needs framework awareness), and **Python smells** (ruff covers the same ground more reliably).

### Phase 1 — Knip (TypeScript unused/dead code)

**Replaces**: `unused` (imports/vars/params), `exports`, `orphaned`, partially `facade`

Knip is already better than the current `tsc` hack — it understands entry points, re-exports, and dynamic references. Output is JSON.

**Integration pattern** (same as existing `tsc` subprocess in `unused.py`):
```python
result = subprocess.run(
    ["npx", "knip", "--reporter", "json", "--no-gitignore"],
    capture_output=True, text=True, cwd=path, timeout=120
)
data = json.loads(result.stdout)
# data["files"]  → orphaned files (replaces orphaned detector)
# data["exports"] → unused named exports (replaces exports detector)

```

**Fixer implication**: Knip has `knip --fix` which can auto-remove dead exports and imports — could eventually replace `fix_dead_exports` and `fix_unused_imports`. For now keep custom fixers; they work without requiring Knip to be installed.

**What to keep**: `unused-params` fixer (prefixing with `_` is subtle, Knip doesn't do this).

**Effort**: Medium — parse Knip's JSON schema into the existing `Finding` TypedDict. Two adapters needed (one each for unused/exports, one for orphaned). The existing `tsc` fallback can be kept for Deno environments where Knip also struggles.

**Replaces**: `unused` (Python), most `smells` (Python)

|---|---|

### Integration Architecture

All phases follow the same pattern already used for `tsc`:

```
phase_X()
  └── run_external_tool(path, timeout)  # subprocess JSON
        └── parse_tool_output(stdout)   # tool-specific adapter
              └── make_findings(entries) # → list[Finding]
                    └── (existing pipeline: upsert → score → narrative)
```

Each external tool becomes an **adapter module** alongside the existing detector:
- `languages/typescript/detectors/knip_adapter.py`
- `languages/python/detectors/ruff_adapter.py`
- etc.

The adapter has one responsibility: convert tool JSON → `list[Finding]` with proper `detector`, `tier`, `confidence`, `detail` fields. The `detail` dict carries the tool's native rule ID for traceability (e.g., `{"source_rule": "F401", "ruff_version": "0.x"}`).

**Graceful degradation**: Each adapter catches `FileNotFoundError` and `subprocess.TimeoutExpired`, logs a warning, and returns `[]`. The tool remaining uninstalled degrades silently — same pattern as the existing tsc Deno fallback.

## **3. Finding Factories: Normalization**

The factory functions convert raw detector output into standardized `Finding` dicts with `tier`, `confidence`, `summary`, `detail`.

### **make_dupe_findings** (finding_factories.py)
- **Input**: Duplicate entries from `detect_duplicates()`
- **Filters**: Removes dupes <10 LOC in both functions
- **Output**: `List[Finding]` with:
  - `name`: `"func_a::file_b::func_b"` (stable, sortable)
  - `tier`: 2 (exact) or 3 (near)
  - `confidence`: "high" (exact) or "low" (near)
  - `detail`: fn_a, fn_b, similarity, kind, cluster_size, full cluster

```python
def make_dupe_findings(entries: list[dict], stderr_fn) -> list[Finding]:
    results = []
    for e in entries:
        # Filter small dupes
        if e["fn_a"]["loc"] < 10 and e["fn_b"]["loc"] < 10:
            continue
        # Create stable name
        pair = sorted([(a["file"], a["name"]), (b["file"], b["name"])])
        name = f"{pair[0][1]}::{rel(pair[1][0])}::{pair[1][1]}"
        tier = 2 if e["kind"] == "exact" else 3
        # Create Finding
        results.append(make_finding("dupes", ...))
    return results
```

## **7. Key Architectural Patterns**

1. **Adapter Graceful Degradation**: All adapters return `None` (not crashes) when tools missing
2. **Clustering Instead of Pairs**: `detect_duplicates()` uses union-find to collapse O(n²) pairs into clusters
3. **Normalized Line Matching**: `boilerplate_duplication` normalizes strings/numbers/identifiers for pattern detection
4. **Zone Filtering**: Duplicate detection filters zone-excluded files before O(n²) comparison
5. **Stable Finding Names**: Used for wontfix tracking (e.g., bandit's `test_id`, dupes' `fn_a::rel_path::fn_b`)
6. **Two-Stage Processing**: Detector → raw entries → factory → normalized Finding objects
