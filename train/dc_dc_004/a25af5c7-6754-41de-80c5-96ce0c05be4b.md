Here's the full picture of the subjective/non-explicit detectors: ## Registry entries (registry.py:111-118) Two detector names in the `# ── Subjective review` section: | Detector | Display | Dimension | Action Type | Purpose | |---|---|---|---|---| | `review` | "design review" | Review coverage | refactor | Per-file AI findings imported back into state | | `subjective_review` | "subjective review" | Review coverage | manual_fix | Tracks which files still need review | ## How it works The system is split into **two layers**: ### 1. Per-file review (`review.py`) - **11 dimensions**: naming_quality, comment_quality, error_consistency, convention_outlier, abstraction_fitness, logic_clarity, contract_coherence, initialization_coupling, logging_quality, type_safety, cross_module_architecture - `prepare_review()` gathers codebase context (naming vocabulary, error conventions, module patterns, import graph, sibling conventions) and selects priority files based on blast radius + existing findings - Outputs a structured prompt + file batches for an AI agent — **no LLM calls happen in this module** - Agent returns findings + per-dimension **assessments** (0-100 scores) that feed into scoring - `import_review_findings()` merges agent output back into state as `detector="review"` findings ### 2. Holistic (codebase-wide) review (`review.py:1088+`) - **8 dimensions**: cross_module_architecture, initialization_coupling, convention_outlier, error_consistency, abstraction_fitness, dependency_health, test_strategy, api_surface_coherence - Looks at patterns **across** files — god modules, sibling behavior outliers, mixed error strategies, util dumping grounds, etc. - Builds 4 parallelizable investigation batches - Holistic findings have no single `file` — stored as `file="."` with `detail.related_files` ### 3. Review coverage detector (`detectors/review_coverage.py`) - Runs every scan — flags production files that are **unreviewed**, **stale** (>30 days), or **changed** since last review - Also checks if a holistic review is needed (never run, stale, or >20% file count drift) ### 4. Issues work queue (`issues.py`) - Lists open review findings sorted by weight - Supports investigation notes on findings - Auto-expires stale holistic findings after 30 days The key insight: the programmatic detectors (unused, smells, security, etc.) use regex/AST analysis. The subjective detectors **prepare structured context and prompts** for an external AI agent, then import its structured JSON findings back into the same state/scoring pipeline. The review coverage detector then tracks freshness so the system knows when to re-review.
