# Per-Issue Documents: Replace Monolithic Plan with Individual Work Orders

## Context

The holistic review currently produces one big `holistic-plan.md` containing all findings. Per-file review produces no plan at all. Both should instead create **individual issue docs** in `.desloppify/issues/` — one self-contained markdown file per finding that needs work.

This makes issues:
- **Parallelizable** — multiple agents work on different docs simultaneously
- **Granular** — resolve one without touching others
- **Discoverable** — `ls .desloppify/issues/` is the work queue
- **Self-contained** — each doc has everything needed to fix that one thing

The narrative system needs to guide agents step by step: scan → triage (review + create issue docs) → fix (work through issue docs) → re-scan.

## Changes

### 1. New file: `desloppify/issues.py` (~150 lines)

Core module for issue doc lifecycle.

```
ISSUES_DIR = PROJECT_ROOT / ".desloppify" / "issues"
```

**Functions:**

| Function | Purpose |
|----------|---------|
| `_issue_slug(finding)` | Human-readable filename: `{dim_short}-{identifier}-{hash8}.md` |
| `_render_issue_doc(finding, lang_name)` | Render one finding as markdown work order |
| `write_issue_docs(findings, state, lang_name) -> list[Path]` | Write all docs, return paths created |
| `remove_issue_doc(finding_id) -> bool` | Delete the doc for a finding ID |
| `cleanup_stale_docs(state)` | Remove docs whose finding is no longer open |
| `count_issue_docs() -> int` | Count docs without reading them |
| `find_doc_for_finding(finding_id) -> Path | None` | Look up doc path by finding ID |

**Slug format:** `{dim_short}-{identifier}-{hash8}.md`
- e.g. `arch-cli_helper_focal_point-e6637111.md`
- `dim_short` = first word of dimension (or detector name for per-file)
- `identifier` from finding detail, or filename stem for per-file findings
- `hash8` = last 8 chars of finding ID (already a hash in our ID scheme)

**Issue doc template:**
```markdown
# {dimension}: {identifier}

**Finding**: `{finding_id}`
**Dimension**: {dimension} | **Confidence**: {confidence}
**Score impact**: {impact_label} (~{pts} pts)

## Problem

{summary}

## Evidence

- {evidence_1}
- {evidence_2}

## Suggested Fix

{suggestion}

## Files

- `{file_1}`
- `{file_2}`

## Why This Matters

{reasoning}

## When Done

\`\`\`bash
desloppify --lang {lang} resolve fixed "{finding_id}"
\`\`\`
```

For per-file findings (no `detail.holistic`): uses `finding.file` as the file, `detail.evidence_lines` for evidence, no "Why This Matters" section.

**Score impact computation:** Extract the weight logic from `generate_remediation_plan()` into a shared helper `_finding_weight(finding)` that returns `(weight, impact_pts)`. Both `_render_issue_doc` and any future plan generator can use it.

**Cleanup logic:** `cleanup_stale_docs(state)` reads each `.md` file's first few lines to extract the finding ID, checks if it's still open in state, deletes if not. Called after import (to catch auto-resolved findings).
