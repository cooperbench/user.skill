## Phase 2: `traceback.print_exc()` → Structured Logging (Low risk, 56 instances)

Replace all 56 `traceback.print_exc()` calls with `logger.error("...", exc_info=True)` or `logger.exception("...")` (which is equivalent). This routes stack traces through the structured logging pipeline instead of raw stderr.

**Pattern:**
```python
# Before:
except (SomeError) as e:
    logger.error(f"Failed: {e}")
    traceback.print_exc()

# After:
except (SomeError) as e:
    logger.error(f"Failed: {e}", exc_info=True)
```

**Files (56 instances across ~30 files):**
- `source/media/` — 16 instances (structure/, vlm/, video/)
- `source/task_handlers/` — 30 instances (travel/, join/, tasks/, edit_video, inpaint, create_visualization)
- `source/core/db/` — 4 instances (task_polling, task_dependencies, task_status)
- `source/utils/` — 4 instances (frame_utils, output_path_utils, pose_utils, download_utils)
- `source/models/comfy/` — 1 instance

Also remove `import traceback` from files that no longer need it.

> **GATE 2**: Run tests. Grep for any remaining `traceback.print_exc`. Verify structured logs still capture stack traces.

## Phase 3: Exception Chain Integrity (Low risk, additive)

Add `from e` to `raise` statements inside except blocks that create new exceptions. This preserves the original cause in the exception chain per PEP 3134.

**Pattern:**
```python
# Before:
except (RuntimeError, ValueError) as e:
    raise FatalWorkerError(f"Fatal: {e}")

# After:
except (RuntimeError, ValueError) as e:
    raise FatalWorkerError(f"Fatal: {e}") from e
```

**Key locations:**
- `source/task_handlers/queue/task_processor.py` — FatalWorkerError re-raise
- `source/media/structure/preprocessors.py` — RuntimeError re-raises for model download failures
- Any other `raise SomeException(...)` inside `except` blocks (need to audit full list)

Skip bare `raise` (already preserves chain) and `raise X from None` (intentional suppression).

> **GATE 3**: Run tests. Verify exception chains work correctly (trigger a test error and check traceback shows both cause and effect).

## Phase 5: TaskResult Dataclass (Medium risk)

Replace the `(bool, str)` return convention with a proper result type. This eliminates the magic string prefix parsing (`"[ORCHESTRATOR_COMPLETE]<json>"`).

**5a. Create `source/core/params/task_result.py`**

```python
from dataclasses import dataclass
from enum import Enum

class TaskOutcome(Enum):
    SUCCESS = "success"           # output_path is a file path
    FAILED = "failed"             # message is an error description
    ORCHESTRATING = "orchestrating"  # orchestrator is managing children
    ORCHESTRATOR_COMPLETE = "orchestrator_complete"  # orchestrator finished, output_path is final

@dataclass
class TaskResult:
    outcome: TaskOutcome
    output_path: str | None = None
    error_message: str | None = None
    thumbnail_url: str | None = None

    @property
    def success(self) -> bool:
        return self.outcome in (TaskOutcome.SUCCESS, TaskOutcome.ORCHESTRATOR_COMPLETE)
```
