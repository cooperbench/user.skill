This is also why the codebase separates them architecturally: - `engine/detectors/` — genuinely cross-language (security, test coverage, jscpd) - `languages/python/detectors/` — Python linters (ruff, bandit, import-linter) - `languages/typescript/detectors/` — TS-specific tools (Knip, tsc) ## The cross-language candidates The few tools that do work across languages tend to cover **structural** rather than **semantic** properties: - **jscpd** — structure of token sequences (language-agnostic) - **semgrep** — pattern matching (but rules are still written per-language) - **gitleaks / trufflehog** — secret detection (regex on text, no AST needed) - **lizard** — cyclomatic complexity (counts decision points, works on any C-like syntax) Notably, desloppify already uses a cross-language approach for security (the `detectors/security.py` core runs regex on file text regardless of language) and test coverage (import graph analysis with per-language adapters for the graph-building step). ## Practical implication If you added a third language (e.g., Go), jscpd would work out of the box.
