# Plan: Open Image in Shot Context from TasksPane

## Context

When a user clicks "Open Image" on a task in the TasksPane, it currently always opens a lightbox overlay within the TasksPane. But if that image belongs to a shot (via `shot_id` in task params), the user should instead be navigated to the shot and see the image opened in the shot editor's lightbox — viewing it in context alongside the other shot images.

Most image edit tasks (inpaint, magic edit, annotated edit, image gen) already pass `shot_id` in their task params. Two exceptions (upscale, img2img) don't, and need to be fixed.

The travel segment video tasks already have this exact pattern — `handleViewVideo` checks for a shot, navigates there, and passes `openSegmentSlot` in `location.state` to auto-open the segment. There's also a `pendingImageToOpen` mechanism in Timeline.tsx that auto-opens an image lightbox by ID. We'll wire these together.

## Changes

**File:** `src/shared/components/TasksPane/TaskItem.tsx` (~line 160-171)

Remove the `isVideoTask || isTravelTask` guard. Just call `extractShotId(task)` unconditionally so image tasks with `shot_id` get a non-null `shotId`.

### 2. Modify `handleViewImage` to navigate to shot when applicable
**File:** `src/shared/components/TasksPane/TaskItem.tsx` (~line 372-382)

- Else: fall through to existing lightbox behavior
