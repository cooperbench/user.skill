# Rework: `desloppify issues` as the Work Queue Command

## Context

The first implementation created issue docs as a side effect of `review --import`. Testing it end-to-end revealed several UX problems:

1. **No entry point** — scan never tells agents about `desloppify issues`; agents are told to `cat .desloppify/issues/*.md`
2. **`cat *.md` dumps everything** — 4 docs = 120 lines of unsorted markdown
3. **No "what's next" after resolve** — agent has to remember to go back
4. **Competes with `desloppify next`** — two systems giving different advice
5. **Stale docs** — files linger on disk after findings are resolved elsewhere

The fix: make `desloppify issues` a proper command that regenerates docs from state on demand and provides a numbered, prioritized interface.

## Design

### Agent workflow

```
$ desloppify scan
  Health 93.3/100 — maintenance mode.
  Suggested next: `desloppify issues` — 3 review findings need attention

$ desloppify issues
  3 open review findings (highest impact first)

  #  Impact  Dimension                   Summary
  1  +++     initialization coupling     _extra_exclusions requires module-attribute access
  2  ++      cross module architecture   cli.py exports shared helpers used by 13 modules
  3  ++      test strategy               constants module untested

  Docs written to .desloppify/issues/
  Show one: desloppify issues show 1

$ desloppify issues show 1
  (full issue doc markdown rendered to terminal)

$ desloppify resolve fixed "review::.::holistic::..."
  Resolved 1 finding(s) as fixed
  Score: 95.1/100 (+1.7)
  2 review findings remaining — run `desloppify issues`
```

### Key decisions

- **`issues` regenerates all docs from state** — clears `.desloppify/issues/`, writes fresh. No stale files.
- **Import stays clean** — data operation only, just points to `desloppify issues`
- **Resolve shows remaining count** — always tells agent what's next
- **`issues show N`** — numbered by priority, renders to terminal + writes file
- **Headline stays simple** — "(N review findings pending)", no file counting
