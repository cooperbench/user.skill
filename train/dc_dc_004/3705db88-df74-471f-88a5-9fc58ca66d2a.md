## Analysis: MediaGallery Filter Props

### The Surface Problem

MediaGallery has **14 filter-related props** (7 `initialX` + 7 `onXChange` callbacks). Every consumer must pass these as individual props, and MediaGallery's `index.tsx` manually wraps each callback with pagination-reset boilerplate (lines 634-691 — the same `goToFirstPage()` + `setIsGalleryLoading(true)` pattern copy-pasted 5 times).

### The Deeper Structural Issue: **Three Competing State Ownership Patterns**

This isn't just a props count problem. There are **three fundamentally different approaches** to gallery filter state, and they don't compose:

| Pattern | Used by | Filter state owner | Pagination reset |
|---|---|---|---|
| **A. `useGalleryPageState` → `useGalleryFilterState`** | GenerationsPane | Shared hook with per-shot persistence, smart defaults, query fallback | Hook handles `setPage(1)` internally |
| **B. Raw `useState` + manual `initialX` props** | ImageGenerationToolPage, VideoTravelVideosGallery, MediaSelectionPanel | Page component with 6-7 individual `useState` calls | Either a `useEffect` watching all filters, or inline `setVideoPage(1)` in every callback |
| **C. Static config (no callbacks)** | EditVideoPage, CharacterAnimatePage, JoinClipsPage | No external state — fire-and-forget initial values | N/A |

**The core issue:** Pattern A (`useGalleryPageState`) is sophisticated and handles hard edge cases (per-shot persistence, query fallback to "all" when 0 results, smart defaults from shot image counts). But **ImageGenerationToolPage — the most complex consumer — doesn't use it at all**. It reimplements a simpler version with raw `useState`, missing:
- Per-shot filter persistence
- Smart shot-aware defaults
- Query-based fallback

Meanwhile, the `initialX + onXChange` prop API exists specifically to support Pattern B consumers, but it creates the **dual-state sync problem**: every filter value lives in both the parent's `useState` AND MediaGallery's internal `useReducer`, kept in sync by a fragile `useEffect` (lines 214-265 of `useMediaGalleryFiltersOptimized.ts`) that compares current state against props on every render.

### Why the Dual State Exists

The root cause: MediaGallery needs to own filter state for its internal UI (header dropdowns, search input, starred toggle) AND needs to notify parents so they can:
1. Rebuild server-side query params (for server-paginated mode)
2. Reset pagination to page 1
3. Persist filter preferences

The `initialX` props are the mechanism for parents to push state back in (e.g., when shot navigation changes the filter externally). But this creates a circular data flow: parent → `initialX` → internal reducer → `onXChange` callback → parent → `initialX` again. The sync effect exists to break the loop, but it's messy and has edge cases (it includes `filtersState.*` in its own dependency array, which means every internal change re-runs the comparison).

### The Pagination Reset Duplication

In `index.tsx`, lines 634-691, MediaGallery wraps every filter callback with identical boilerplate:

```tsx
onStarredFilterChange={(val) => {
  filtersHook.setShowStarredOnly(next);
  paginationHook.goToFirstPage();          // ← duplicated 5 times
  if (paginationHook.isServerPagination) { // ← duplicated 5 times  
    paginationHook.setIsGalleryLoading(true);
  }
  onStarredFilterChange?.(next);           // ← bubble to parent
}}
```

This should be a single wrapper function, but the real issue is that MediaGallery shouldn't need to know about pagination reset at all — it should happen automatically when filter state changes.

### What Would Actually Fix This

The fix isn't just "consolidate into a `filterState` object" — that would reduce prop count but not solve the dual-state or duplication problems. The real fix has three layers:

**1. Controlled/Uncontrolled Pattern** (like how `<input>` works)

Replace the `initialX + onXChange` pairs with a proper controlled component pattern:

```tsx
// Uncontrolled: MediaGallery owns filter state (Pattern C consumers)
<MediaGallery defaultFilters={{ mediaType: 'video', toolType: true }} />

// Controlled: Parent owns filter state (Pattern A & B consumers)
<MediaGallery filters={filterState} onFiltersChange={setFilterState} />
```

This eliminates the dual-state sync entirely. In controlled mode, MediaGallery doesn't maintain internal filter state — it uses the `filters` prop directly and calls `onFiltersChange` for UI interactions. In uncontrolled mode, it initializes from `defaultFilters` and manages state internally.

**2. Colocate pagination reset with filter changes**

Instead of wrapping each callback in `index.tsx`, MediaGallery should have a single `useEffect` that resets pagination whenever `filters` (the controlled prop) changes reference-equality. This is already partially happening in `useGalleryPageState` (lines 94-101).

**3. Migrate ImageGenerationToolPage to `useGalleryPageState`**

The biggest consumer of Pattern B should switch to Pattern A. ImageGenerationToolPage currently duplicates filter state, query construction, and pagination reset that `useGalleryPageState` already handles. The main gap is that `useGalleryPageState` hardcodes the tool type from its options while ImageGenerationToolPage has a toggleable tool type filter — but this is a small extension to the hook.

### Impact Assessment

| Consumer | Change needed | Effort |
|---|---|---|
| ImageGenerationToolPage | Migrate to `useGalleryPageState` + controlled pattern | Medium (removes ~40 lines of state, adds toolType toggle to hook) |
| GenerationsPane | Already uses `useGalleryPageState`, just pass `filters` object | Small |
| VideoTravelVideosGallery | Extract filter state into small hook, pass as controlled | Small |
| MediaSelectionPanel | Extract filter state, pass as controlled | Small |
| Static consumers (EditVideo, CharacterAnimate, JoinClips) | Switch to `defaultFilters` object | Trivial |
| MediaGallery internals | Remove sync effect, support controlled/uncontrolled | Medium |
| `useMediaGalleryFiltersOptimized` | Simplify: accept `filters` directly instead of individual `initialX` props | Medium |

### Recommendation

This is worth doing, but it's a **medium-effort refactor** touching 8+ files. The benefit is clear: eliminate ~60 lines of duplicated state management across consumers, remove the fragile sync effect, and make it impossible for parent/child filter state to diverge. The risk is moderate — filter state affects every gallery view, and the sync edge cases exist for a reason (external shot navigation pushes filters).

I'd recommend doing it in phases:
1. **Phase 1**: Define the `GalleryFilterState` type and `defaultFilterState` factory. Add `filters`/`onFiltersChange`/`defaultFilters` props to `MediaGalleryProps` (alongside the existing props for backward compat).
2. **Phase 2**: Migrate static consumers (trivial) and GenerationsPane (already has the right state shape). 
3. **Phase 3**: Migrate ImageGenerationToolPage (biggest win — requires extending `useGalleryPageState` with tool type toggle).
4. **Phase 4**: Clean up — remove old `initialX` props, delete the sync effect.
