# Consolidate duplicate `useSegmentOutputsForShot` hook instances

## Context

`SegmentOutputStrip` and `ShotImagesEditor` each call `useSegmentOutputsForShot` independently. This causes duplicate DB queries, and the two instances can disagree on slot assignments (e.g., the trailing video bug we just fixed — the parent's hook didn't know about `trailingShotGenId`). Consolidating to one call eliminates the sync problem entirely.

## Key Insight: Strip's hook is mostly dead code

The strip destructures 8 values from the hook but only uses 3:
- `segmentSlots` — rendering (displaySlots, source change detection, trailing video info)
- `selectedParentId` — already comes in as controlled prop `controlledSelectedParentId`
- `isLoading` — loading indicator

Dead code in strip: `parentGenerations`, `setSelectedParentId`, `selectedParent`, `hasFinalOutput`, `segmentProgress`, `parentVideoRow`, `isParentLightboxOpen`, parent lightbox JSX.

## Plan

### 1. ShotImagesEditor.tsx — Single hook call with positions

Compute `localShotGenPositions` from `shotGenerations` (DB-derived, same as orchestrator's but from cache instead of optimistic drag state — fine since users don't click segments during drag):

```typescript
const localShotGenPositions = useMemo(() => {
  const positioned = shotGenerations
    .filter(g => g.timeline_frame != null && g.timeline_frame >= 0)
    .sort((a, b) => (a.timeline_frame ?? 0) - (b.timeline_frame ?? 0));
  const posMap = new Map<string, number>();
  positioned.forEach((g, index) => posMap.set(g.id, index));
  return posMap.size > 0 ? posMap : undefined;
}, [shotGenerations]);
```

Update hook call to pass positions:
```typescript
const { segmentSlots, selectedParentId, isLoading: isSegmentsLoading } = useSegmentOutputsForShot(
```
