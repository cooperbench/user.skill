# Merge ImageEditContext + EditFormContext into a Single Context

## Context

The split between `ImageEditContext` (mode/brush/annotation/reposition state) and `EditFormContext` (prompts/settings/generation status) was by abstract concept rather than by feature. This caused a bug where reposition status values were in `EditFormContext` but `EditModePanel` read them from `ImageEditContext` — getting `undefined`. The bug was patched by duplicating 4 values into both contexts, but the real fix is to eliminate the split entirely.

**Goal**: One context, one interface, one `useMemo`, one `prop ?? context` override. Impossible to put a value in the "wrong context."

  setIsEraseMode: (value: boolean) => void;
