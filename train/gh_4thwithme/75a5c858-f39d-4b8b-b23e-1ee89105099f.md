Based on the official Claude Code documentation, here's everything you need to know about `CLAUDE_CODE_NEW_INIT` and environment variables:

## CLAUDE_CODE_NEW_INIT

**What it does:**
`CLAUDE_CODE_NEW_INIT=true` makes the `/init` command run an interactive setup flow instead of automatically generating configuration. The interactive flow asks you which files to generate (CLAUDE.md, skills, hooks) before exploring the codebase and writing them. Without this variable, `/init` generates a CLAUDE.md automatically without prompting.

**Where to set it:**
Set it in your shell before launching Claude Code:

```bash
CLAUDE_CODE_NEW_INIT=true claude
```

## All Options for Setting Environment Variables in Claude Code

There are **three main approaches** for setting environment variables:

### 1. Shell Environment (Per-session)
Set the variable in your shell before running Claude Code:

```bash
VARIABLE_NAME=value claude
```

This applies only to that specific session.

### 2. settings.json (All sessions, sharable with team)
Configure environment variables under the `env` key in `settings.json` to apply them to every Claude Code session:

**Locations by scope:**
- **User scope** (`~/.claude/settings.json`): Applies to all your projects
- **Project scope** (`.claude/settings.json`): Applies to all collaborators on this repository (committed to git)
- **Local scope** (`.claude/settings.local.json`): Applies only to you in this repository (gitignored)

Example in `settings.json`:
```json
{
  "env": {
    "CLAUDE_CODE_NEW_INIT": "true",
    "DISABLE_TELEMETRY": "1"
  }
}
```

### 3. System-level (Enterprise/Managed)
Managed settings configured by IT administrators at the system level (plist on macOS, registry on Windows, or `managed-settings.json`).

## Key Points

- **Settings in `settings.json` take precedence** over shell environment variables
- You can use different scopes for different scenarios:
  - **User scope**: Personal preferences that apply everywhere
  - **Project scope**: Team conventions and shared configurations
  - **Local scope**: Your personal overrides for a specific project
  - **Managed scope**: Organization-wide policies enforced by IT

- The full list of available environment variables is documented in the [official environment variables reference](https://code.claude.com/docs/en/env-vars), which includes variables for API keys, model configuration, feature flags, timeouts, and more.

For your workflow, using `settings.json` is recommended if you want `CLAUDE_CODE_NEW_INIT=true` to persist across sessions without having to set it manually each time.
