   - **Intro paragraph (~40 words):** define a hash chain — a sequence of entries where each entry includes the SHA-256 hash of the previous entry, so entries are cryptographically linked. Mention that the first entry's `prev_hash` is typically all zeros (the genesis entry).
   - **Code example (fenced ```` ```json ````, 2 entries):** show entry 0 with `prev_hash: "0000...00"` and entry 1 with `prev_hash` equal to `hash(entry_0)`. Include `id`, `data`, `prev_hash` fields. Use truncated hashes like `"a3f1...9c"` to keep it readable. Example:
     ```json
     { "id": 0, "data": "user_login", "prev_hash": "0000...00" }
     { "id": 1, "data": "file_read",  "prev_hash": "a3f1...9c" }  // = sha256(entry 0)
     ```
   - **What it detects (~60 words):** tampering with any past entry. Editing entry N changes its hash, which breaks entry N+1's `prev_hash`, and the mismatch cascades through every subsequent entry. A verifier just walks the chain and recomputes hashes — one pass, O(n).
   - **What it does NOT detect (~80 words):** be explicit about three failure modes:
     1. **Truncation of the tail** — chopping off the last K entries leaves a still-valid shorter chain. The chain doesn't know how long it should be.
     2. **Replacement of the whole chain** — an attacker who controls the storage can rebuild the chain from scratch with different contents; every `prev_hash` will be internally consistent.
     3. **Out-of-band modification with full rewrite** — same idea: if the attacker can recompute all downstream hashes after editing, the chain re-validates.
     The mitigation (mention briefly, don't expand): pin the latest hash somewhere the attacker can't rewrite — a signed checkpoint, a witness, an append-only WORM store, or a public ledger.
   - **Use case (~50 words):** audit/event logs. Servers append security events (logins, privilege changes, file accesses); each entry chains to the previous one. A periodic checkpoint of the head hash is signed and shipped off-host. After an incident, you can verify no historical entry was edited without rewriting every event since.
   - Keep total prose at ~250 words (±25). Verify by rough word count before finishing.
