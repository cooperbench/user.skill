## Overview

Currently the Hermes agent executes code locally (macOS, Python 3.11) but SWE-bench scores in Docker (Linux, Python 3.9). This mismatch causes false passes. The fix: route the execute phase through the same Docker image SWE-bench uses for scoring, using the existing `TERMINAL_ENV=docker` backend that Terminal Bench already uses.

**Key architecture points:**
- `megaplan_env_overrides()` in `swe_bench.py:588` currently returns `{}`. Terminal Bench (`terminal_bench.py:249-255`) shows the exact pattern to follow.
- The Docker backend (`tools/environments/docker.py`) supports `TERMINAL_DOCKER_VOLUMES` for custom mount points and `TERMINAL_CWD` for setting the working directory — we need `/testbed`, not `/workspace`.
- SWE-bench images are named `sweb.env.py.x86_64.<hash>:latest` and built by `swebench.harness.run_evaluation`. We need to compute this name and pre-build the image before execute.
- Patch extraction currently runs `git diff` on the host workspace (`swe_bench.py:351-362`). With Docker execution, edits happen inside the container on a bind-mounted volume, so `git diff` on the host still works — this is the key simplification.

**Chosen approach: Bind-mount workspace at /testbed**

Mount the host workspace into the SWE-bench container at `/testbed` via `TERMINAL_DOCKER_VOLUMES`. Set `TERMINAL_CWD=/testbed`. The agent edits files on the bind mount; `git diff` on the host sees the changes. No change to patch extraction. This is simpler than the alternatives (full agent in container, SSH, etc.) and matches the Terminal Bench pattern exactly.

def megaplan_env_overrides(self, prepared) -> dict[str, str]:
    image = prepared.metadata.get("docker_image", "")
    if not image:

## Overview

Currently the Hermes agent executes code locally (macOS, Python 3.11) but SWE-bench scores in Docker (Linux, Python 3.9). This mismatch causes false passes. The fix: route the execute phase through the same Docker image SWE-bench uses for scoring, using the existing `TERMINAL_ENV=docker` backend.

**Revised approach: Use the container's own `/testbed` — no bind-mount**

The v1 plan proposed bind-mounting the host workspace at `/testbed`. This has two fatal problems:
1. **Worktree `.git` pointer**: `prepare_workspace()` creates git worktrees (`swe_bench.py:257`). The `.git` file contains an absolute host path like `gitdir: /Users/.../worktrees/...` which breaks inside the container.
2. **`/root` clobber**: The Docker backend mounts tmpfs or bind-mount over `/root` (`docker.py:288-309`), destroying the conda/Python environment that SWE-bench installs there.

**New approach**: Don't mount anything. The SWE-bench Docker image already has the repo at `/testbed` at the correct commit with all dependencies installed. The agent works entirely inside the container. After execution, extract the git diff from inside the container via the Hermes terminal tool (which is already running `docker exec`), then write the patch to the host for scoring. This requires:
- A Docker backend change to add a `skip_home_overlay` flag that preserves the image's `/root` and `/home` contents
- Relaxing sandbox limits (`--pids-limit`, tmpfs sizes, memory) for SWE-bench parity
- A new `_extract_patch_from_container()` step before scoring
- Computing the SWE-bench image name via subprocess (matching existing codebase patterns)
