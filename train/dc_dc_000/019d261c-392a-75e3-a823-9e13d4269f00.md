        # Implementation Plan: Fix video editor not compressing when bottom pane is locked

## Overview

When the full video editor is active (`/tools/video-editor?timeline=xxx`), locking the generations pane at the bottom causes the pane to overlap the editor rather than compressing the editor to make room. The root cause is in `LayoutMainContent.tsx` which explicitly zeroes all padding/margin when `isVideoEditorShellActive`, and the video editor container chain uses `h-screen` throughout without accounting for the generations pane height.

**The chain of `h-screen` containers:**
1. `Layout.tsx:112` — outer `div` gets `h-screen overflow-hidden` when shell is active
2. `LayoutMainContent.tsx:65-66` — content container gets `h-screen w-screen overflow-hidden`
3. `VideoEditorPage.tsx:292` — renders `h-screen w-screen overflow-hidden`

All three layers use full viewport height, and `LayoutMainContent` sets `paddingBottom: '0px'` when `isVideoEditorShellActive`. Meanwhile `GenerationsPane` renders `fixed bottom-0` and overlays on top.

**Reference behavior ("compressed button below the video"):** The compact editor pane (`EditorPaneTab.tsx:42-43`) already handles this correctly — it subtracts `effectiveGenerationsPaneHeight` when the generations pane is locked, shrinking to `MIN_EDITOR_HEIGHT` (200px). The full editor page needs analogous logic.

## Main Phase

### Step 2: Fix `LayoutMainContent.tsx` to pass bottom offset to the video editor container (`src/app/components/LayoutMainContent.tsx`)
**Scope:** Small
1. **Change** the `isVideoEditorShellActive` branch to still apply bottom offset for the generations pane. Currently (line 41):
   ```ts
   paddingBottom: isVideoEditorShellActive ? '0px' : ...
   ```
   The video editor uses `overflow-hidden` so padding won't work — we need to reduce the container height instead.

2. **Replace** the hardcoded `h-screen` class (line 66) with a dynamic height that accounts for the generations pane:
   ```tsx
   // When video editor is active but generations pane is locked, reduce available height
   const videoEditorBottomOffset = (isGenerationsPaneLocked || isGenerationsPaneOpen) 
     ? effectiveGenerationsPaneHeight : 0;

   // In the className:
   isVideoEditorShellActive
     ? `w-screen overflow-hidden ${videoEditorBottomOffset > 0 ? '' : 'h-screen'}`
     : 'transition-[margin,padding] duration-300 ease-smooth'

   // Add style.height when shell is active:
   height: isVideoEditorShellActive 
     ? (videoEditorBottomOffset > 0 ? `calc(100vh - ${videoEditorBottomOffset}px)` : '100vh')
     : undefined
   ```

3. **Keep** `paddingBottom: '0px'` for the video editor case — the height reduction replaces padding.

### Step 3: Fix `Layout.tsx` outer container height (`src/app/Layout.tsx:112`)
**Scope:** Small
1. **Update** line 112 which also sets `h-screen overflow-hidden` when video editor is active. This outer container must also shrink to avoid clipping:
   ```tsx
   // Use dynamic height instead of h-screen when gens pane is visible
   const outerStyle = isVideoEditorShellActive && (isGenerationsPaneLocked || isGenerationsPaneOpen)
     ? { height: `calc(100vh - ${effectiveGenerationsPaneHeight}px)`, overflow: 'hidden' as const }
     : undefined;
   ```
   And remove `h-screen` from the className when the offset applies, using the style instead.

2. **Note:** `Layout.tsx` already imports `usePanes()` and destructures `isGenerationsPaneLocked` (line 53), but does NOT currently have `effectiveGenerationsPaneHeight`. Add it to the destructure, or use `generationsPaneHeight` (which it already has) as a simpler approximation. Prefer `effectiveGenerationsPaneHeight` for consistency with the rest of the system.

### Step 4: Verify `VideoEditorPage.tsx` container cooperates (`src/tools/video-editor/pages/VideoEditorPage.tsx:292`)
**Scope:** Small
1. **Check** that `VideoEditorPage`'s own `h-screen w-screen overflow-hidden` div (line 292) inherits the reduced height from its parent. Since `LayoutMainContent` wraps it and constrains the height, the inner div's `h-screen` becomes `h-full` effectively because its parent is smaller. However, `h-screen` = `100vh` which is absolute, not relative to parent.

2. **Change** `VideoEditorPage.tsx:292` from `h-screen` to `h-full` so it respects the parent's constrained height:
   ```tsx
   <div className={cn('h-full w-full overflow-hidden bg-background')}>
   ```

3. **Similarly check** `FullEditorLayout` (`VideoEditorShell.tsx:107`) — it uses `h-full` already, so no change needed.

### Step 5: Add transition for smooth resize (`src/app/components/LayoutMainContent.tsx`)
**Scope:** Small
1. **Add** `transition-[height]` to the video editor container so the compression animates smoothly when the generations pane locks/unlocks, matching the 300ms ease-smooth used elsewhere:
   ```tsx
   'w-screen overflow-hidden transition-[height] duration-300 ease-smooth'
   ```
