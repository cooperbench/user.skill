        # Implementation Plan: Phase 8 Inbox Surface

## Overview
Phase 8 adds an opt-in file inbox at `runs/<run-id>/inbox/` so humans, scripts, or external tools can signal lifecycle decisions for the current attested step through files. The current runtime already has the right foundations: active runs and project layout in `artagents/core/task/lifecycle.py`, explicit decision handling in `artagents/core/task/lifecycle_ack.py`, hash-chained events in `artagents/core/task/events.py`, and cursor/identity validation in `artagents/core/task/gate.py`.

The latest critique does not suggest the plan is targeting the wrong root cause or wrong code. It identifies that the prior stale-check mechanism was pointed at the right subsystem but depended on virtual repeat traversal events from `peek_current_step`; those events are not persisted before inbox consumption. The revised approach stays in Phase 8 scope and keeps the requested five-field JSON format by deriving a repeated-step stale lower bound from already persisted cursor-advancing events, not from virtual `item_started` or `iteration_started` events. For abort, the already-settled explicit `cmd_next` post-consume branch remains part of the plan.

## Main Phase

### Step 1: Add Inbox Parser and Types (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. **Create** `InboxEntry` with `path`, `step_id`, `decision`, `evidence`, `submitted_at`, and `submitted_by`. Keep `evidence` as a JSON object in memory and parse `submitted_at` as timezone-aware ISO 8601.
2. **Define** an internal skip result or `InboxSkip` exception for stale/non-applicable entries so malformed, stale, or non-current files can be logged and ignored without crashing lifecycle commands.
3. **Implement** `inbox_dir(run_dir) -> Path` as `Path(run_dir) / "inbox"`.
4. **Implement** `scan_inbox(run_dir) -> list[InboxEntry]`: if `inbox/` is absent, return `[]`; scan only top-level regular `*.json` files; ignore `.consumed/`, `.evidence/`, and subdirectories; validate required fields; require `decision in {"approve", "retry", "abort"}`; require `evidence` to be an object; log malformed JSON or invalid shapes with `logging.getLogger(__name__)` and skip.
5. **Sort** parsed entries by `(submitted_at, filename)` for deterministic consumption when several entries are pending.

### Step 2: Resolve Run Context and Current Cursor (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. **Infer** layout from `run_dir`: `runs_root = run_dir.parent`, `project_root = runs_root.parent`, `slug = project_root.name`, and `run_id = run_dir.name`.
2. **Validate** that `run_dir.name` matches `read_active_run(slug, root=project_root.parent)["run_id"]` before any event write. If it does not match, log and skip the entry.
3. **Load** `project_root / "plan.json"` and `run_dir / "events.jsonl"`, then call `peek_current_step(plan, events, slug, project_root=project_root, run_id=run_id)` to get the current cursor.
4. **Validate** that the current cursor is an `AttestedStep` and that `entry.step_id` equals `STEP_PATH_SEP.join(peek.path_tuple)`. If not, log and skip without moving the file.
5. **Do not** rely on `peek_current_step` captured traversal events for stale detection, because repeat traversal events are virtual during peek and are not present in `events.jsonl` before consumption.

### Step 3: Derive Repeated-Step Stale Lower Bounds (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. **Implement** a helper such as `_current_cursor_lower_bound(events, peek) -> datetime | None` that uses only persisted events already in `events.jsonl`.
2. **For non-repeated attested cursors**, use the latest relevant persisted event timestamp for the current path when present, falling back to the `run_started` timestamp. This rejects entries submitted before the run existed and keeps ordinary top-level attested steps simple.
3. **For `repeat_for_each` cursors**, use the latest persisted `item_attested` or `item_completed` event for the same host path as the lower bound. This represents the point after which a file can safely apply to the next current item. If no prior item is complete, fall back to `run_started` or the latest persisted host-path setup event if present.
4. **For `repeat_until` cursors**, use the latest persisted `iteration_failed` event for the same host path as the lower bound. This represents the point after which a file can safely apply to the next current iteration. If no prior iteration failed, fall back to `run_started` or the latest persisted host-path setup event if present.
5. **Reject as stale** any inbox entry whose `submitted_at` is earlier than or equal to the lower bound. This prevents old same-`step_id` files from being applied after the cursor has advanced to a later item or iteration, without depending on virtual current-start events.
6. **If** the lower bound cannot be determined at all because persisted event timestamps are malformed or absent, skip consumption and log the reason rather than guessing.
7. **Document** the current-cursor semantics: the five-field inbox format does not target arbitrary future items or iterations; it targets the attested unit currently exposed by `next`, with `submitted_at` used only to reject files older than the current cursor’s persisted lower bound.

### Step 4: Normalize Evidence and Identity (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. **Persist** structured `entry.evidence` as canonical JSON under `run_dir / "inbox" / ".evidence" / "<sha256>.json"`, where the hash is computed from the original inbox file bytes. This gives the existing event model a stable string evidence token without changing `make_step_attested_event`.
2. **Pass** the evidence artifact path as a single `--evidence <path>` token in synthesized ack/gate commands. Tests should assert the attestation event stores a list containing that string path.
3. **Map** `submitted_by` according to the current step’s ack rule: for `ack.kind == "agent"`, synthesize `--agent <submitted_by>`; for `ack.kind == "actor"`, synthesize `--actor <submitted_by>`.
4. **For actor inbox consumption**, set `ARTAGENTS_ACTOR=submitted_by` only for the scoped gate/ack call so the existing actor validation remains in force. Do not bypass `validate_attested_identity`; self-ack rejection from `run_started` still applies.
5. **For repeated cursors**, after passing the persisted lower-bound stale check, use the current `peek_current_step` context: if `peek.item_id` is set, include `--item <peek.item_id>` in synthesized approve/retry commands; if `peek.iteration` is set, no extra token is needed because the current cursor identifies the active attempt.

### Step 5: Implement Decision Consumption (`artagents/core/task/inbox.py`, `artagents/core/task/lifecycle_ack.py`)
**Scope:** Medium
1. **Implement** `consume_inbox_entry(run_dir, entry) -> dict | None` so successful decisions return the primary stored event record and skipped entries return `None` after logging.
2. **Approve:** synthesize the current attested step command plus identity, evidence, and optional current `--item`, then call `gate_command(slug, incoming, [], root=project_root.parent)` followed by `record_dispatch_complete(decision, 0)`. Read back and return the matching `step_attested` or `item_attested` event.
3. **Retry:** reuse existing retry semantics instead of inventing an inbox-only event. If needed, extract the retry body from `cmd_ack` into a shared helper that accepts parsed identity/evidence/item arguments, validates the current cursor and latest `produces_check_failed`, and appends the existing `cursor_rewind` event. Return the stored `cursor_rewind` event. If retry preconditions are not met, log and skip without consuming.
4. **Abort:** delegate to existing abort behavior for the active project, appending `run_aborted` and clearing `active_run.json`. Return the stored `run_aborted` event.
5. **Move** the original inbox file only after a decision successfully writes its expected event. Move to `run_dir / "inbox" / ".consumed" / "<sha256>"`; if a collision exists, append a numeric suffix while preserving the hash prefix.
6. **Do not consume** stale entries, entries for non-attested cursors, retry entries whose preconditions are false, entries whose identity fails existing validation, or repeated-cursor entries whose `submitted_at` is not newer than the persisted lower bound for the current repeated unit.

### Step 6: Wire Lifecycle Handlers (`artagents/core/task/lifecycle.py`)
**Scope:** Medium
1. **In `cmd_next`**, after resolving the active run but before rendering the current action, call `scan_inbox(run_dir)` and attempt to consume the first entry applicable to the current cursor.
2. **If consumption returns `run_aborted`**, immediately re-read active run state, print an abort acknowledgement such as `run aborted by inbox entry`, and return without reloading the cached cursor or rendering a next step. This explicit branch is required because `derive_cursor` ignores `run_aborted`.
3. **If consumption returns another event**, reload `events.jsonl`, recompute `peek_current_step`, and render from the updated cursor.
4. **Keep consumption bounded** to at most one successful inbox decision per `next` call. This avoids surprising multi-step advancement from a batch of dropped files.
5. **In `cmd_status`**, call `scan_inbox(run_dir)` in read-only mode and print `inbox:     X pending` after run metadata. Do not call `consume_inbox_entry` from `status`, preserving the existing no-mutation contract requested by current tests and the implementation brief.
6. **Leave `cmd_ack` CLI behavior unchanged**, except for any internal helper extraction needed so inbox retry can share existing logic.

### Step 7: Update Run Operator Instructions (`artagents/core/task/lifecycle.py`)
**Scope:** Small
1. **Extend** `_AGENT_MD_TEMPLATE` to mention the optional `runs/<run-id>/inbox/` surface.
2. **Document** the exact JSON shape, decision values, identity mapping, structured evidence artifact behavior, current-cursor matching rule, repeated-step `submitted_at` lower-bound stale guard, and `.consumed/<hash>` move policy.
3. **Keep** existing recovery commands and stop-hook instructions unchanged.

### Step 8: Add Focused Tests (`tests/test_inbox_scan.py`, `tests/test_inbox_consume.py`, `tests/test_inbox_stale.py`, lifecycle tests)
**Scope:** Medium
1. **Add** `tests/test_inbox_scan.py`: create a run inbox with three valid JSON entries and one malformed file; assert `scan_inbox` returns three entries and does not raise.
2. **Add** `tests/test_inbox_consume.py`: start a simple attested run, drop an `approve` inbox entry, call `cmd_next`, assert a hash-chained `step_attested` event exists, evidence points to the persisted JSON artifact, the cursor advances, and the source file moves to `.consumed/`.
3. **Add** retry coverage in `tests/test_inbox_consume.py` or a sibling test: prepare an attested step with a latest `produces_check_failed`, drop a `retry` entry, call `cmd_next`, and assert the existing retry event (`cursor_rewind`) is recorded and the file is consumed.
4. **Add** abort coverage: drop an `abort` entry, call `cmd_next`, assert `run_aborted` is recorded, active run state is cleared, and `cmd_next` does not render the stale cached current step after abort.
5. **Add** actor identity coverage: for an actor-ack step, assert `submitted_by` is passed as `--actor` under scoped `ARTAGENTS_ACTOR`, and self-ack rejection still leaves the file unconsumed.
6. **Add** repeat positive coverage for `repeat_for_each`: when `peek.item_id` is active and the entry `submitted_at` is after the latest persisted prior item completion lower bound, inbox approval consumes the current item by passing `--item <peek.item_id>`.
7. **Add** repeat positive coverage for `repeat_until`: when the entry `submitted_at` is after the latest persisted prior `iteration_failed` lower bound, inbox approval consumes the current iteration.
8. **Add** repeat stale coverage: create an inbox entry for the same repeated `step_id` with `submitted_at` before or equal to the persisted lower bound; assert it is ignored, not consumed, and no attestation event is appended for the current repeated unit.
9. **Add** `tests/test_inbox_stale.py`: mismatched `step_id` is ignored, not consumed, and does not append an attestation event.
10. **Extend** `tests/test_lifecycle_status.py`: status reports pending inbox count and leaves `events.jsonl` byte-for-byte unchanged.
