        # Implementation Plan: Agentic Test Harness for Timeline Agent

## Overview

Build an integration test harness that exercises the `ai-timeline-agent` edge function against a real Supabase instance with real data. The harness has two layers:

1. **Core harness** — a TypeScript library that can: create/load a real timeline session, send messages to the real agent endpoint, poll for async side-effects (task completion, generations, asset registry), snapshot all affected DB tables, and diff snapshots to detect changes.

2. **Agentic outer loop** — a Claude-driven runner that inspects actual timeline state, generates contextual test messages, invokes the harness, scores results, identifies failure patterns, and optionally proposes fixes.

**Key constraints:**
- No mocks — all calls hit real Supabase (the deployed edge functions, not local `supabase functions serve`)
- Must handle the async cascade: agent creates tasks → tasks get picked up by workers → complete_task fires → generations/shots/asset_registry update
- Must be safe: use a dedicated test project/timeline, clean up after runs, never touch production data
- Existing test infra uses Vitest; smoke tests already call real edge functions via HTTP

**Location:** `reigh-app/supabase/functions/_tests/harness/` — colocated with existing edge function test infrastructure. The agentic runner script lives alongside as a standalone Node/ts-node script.

## Phase 1: Foundation — Harness Core Library

### Step 1: Create authenticated Supabase + HTTP client utilities (`reigh-app/supabase/functions/_tests/harness/client.ts`)
**Scope:** Small
1. **Implement** a client module that:
   - Creates a `@supabase/supabase-js` admin client using `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` from env
   - Provides `callAgent(sessionId, userMessage, selectedClips?)` that POSTs to the deployed `ai-timeline-agent` endpoint with a real user JWT (obtained via `supabase.auth.signInWithPassword` for a test user)
   - Provides `callCreateTask(body)` for direct task creation if needed
2. **Config:** Read env vars from `reigh-app/.env.local` (already has credentials) or a dedicated `.env.test`

### Step 2: Create DB snapshot and diff utilities (`reigh-app/supabase/functions/_tests/harness/snapshot.ts`)
**Scope:** Medium
1. **Implement** `snapshotState(timelineId, projectId)` that queries all relevant tables and returns a typed object:
   - `timelines` — config, config_version, asset_registry
   - `tasks` — all tasks for the project (id, family, status, input, output_location, created_at)
   - `generations` — all generations for the project
   - `generation_variants` — variants for those generations
   - `shot_generations` — junction records
   - `shots` — all shots for the project
   - `timeline_agent_sessions` — the session under test (turns, status)
2. **Implement** `diffSnapshots(before, after)` that returns a structured diff:
   - Added/removed/modified rows per table
   - Changed fields with old/new values
   - Special handling for timeline config (deep diff of clips array)
3. **Implement** `summarizeDiff(diff)` for human/LLM-readable output

### Step 3: Create async completion waiter (`reigh-app/supabase/functions/_tests/harness/waiter.ts`)
**Scope:** Medium
1. **Implement** `waitForTaskCompletion(taskIds, timeoutMs=120_000)` that polls `tasks` table until all specified task IDs reach `Complete` or `Failed` status
2. **Implement** `waitForAgentSession(sessionId, timeoutMs=60_000)` that polls until session status is not `processing`
3. **Implement** `waitForGenerations(taskIds, timeoutMs=120_000)` that waits for generations to appear in the `generations` table for the given task IDs
4. **Polling:** 2-second intervals, exponential backoff option, clear timeout errors showing which items are still pending

### Step 4: Create test fixture setup/teardown (`reigh-app/supabase/functions/_tests/harness/fixtures.ts`)
**Scope:** Medium
1. **Implement** `createTestTimeline(userId, config?)` — creates a project + timeline with known initial state (e.g., 2-3 clips on a single track, some with generation IDs pointing to real assets)
2. **Implement** `createTestSession(timelineId, userId)` — creates a `timeline_agent_sessions` row in `waiting_user` status
3. **Implement** `cleanupTestData(projectId)` — deletes test project and cascading data (tasks, generations, shots, sessions)
4. **Implement** `getOrCreateTestUser()` — signs in as a test user (env var credentials) or creates one, returns user ID + JWT

### Step 5: Wire up the harness entry point (`reigh-app/supabase/functions/_tests/harness/index.ts`)
**Scope:** Small
1. **Export** a unified `TestHarness` class that composes all the above:
   ```typescript
   class TestHarness {
     async setup(): Promise<{ timelineId, sessionId, projectId, userId }>
     async sendMessage(message: string, selectedClips?: SelectedClip[]): Promise<AgentResponse>
     async waitForCompletion(): Promise<void>
     async snapshot(): Promise<Snapshot>
     async diff(before: Snapshot, after: Snapshot): Promise<Diff>
     async teardown(): Promise<void>
   }
   ```

## Phase 2: Evaluation Framework

### Step 6: Create evaluation primitives (`reigh-app/supabase/functions/_tests/harness/evaluate.ts`)
**Scope:** Medium
1. **Implement** assertion helpers that return `{ pass: boolean, reason: string }`:
   - `expectClipMoved(diff, clipId, expectedPosition)` — clip exists at new position
   - `expectClipDeleted(diff, clipId)` — clip removed from config
   - `expectTaskCreated(diff, family, promptSubstring?)` — new task row with matching family
   - `expectGenerationCreated(diff, taskId?)` — generation appeared
   - `expectNoCollateralDamage(diff, allowedChanges)` — only expected tables/rows changed
   - `expectSessionCompleted(snapshot)` — session status is `done` or `waiting_user`
2. **Implement** `scoreResult(assertions[])` → `{ passed, failed, score, details[] }`

### Step 7: Create test case definitions (`reigh-app/supabase/functions/_tests/harness/cases.ts`)
**Scope:** Medium
1. **Define** a `TestCase` type:
   ```typescript
   type TestCase = {
     name: string
     category: 'timeline-edit' | 'generation' | 'compound' | 'error-handling'
     setup?: (harness: TestHarness) => Promise<void>  // optional extra setup
     message: string | ((snapshot: Snapshot) => string)  // static or dynamic
     selectedClips?: SelectedClip[]
     evaluate: (before: Snapshot, after: Snapshot, diff: Diff) => EvalResult
     timeoutMs?: number
   }
   ```
2. **Implement** seed test cases for each category:
   - **Timeline edits:** "move clip X to 5 seconds", "delete clip X", "trim clip X to 3 seconds", "add text 'Hello' at 0s for 2 seconds", "set volume of clip X to 0.5"
   - **Generation:** "generate an image of a sunset" (text-to-image), "apply the style of clip X to a new image" (style-transfer with selected_clips)
   - **Compound:** "generate an image of a mountain and add it to track 1 at 10 seconds"
   - **Error handling:** "move clip NONEXISTENT to 5s", "delete everything" (ambiguous)

## Phase 3: Runners

### Step 8: Create deterministic test runner (`reigh-app/supabase/functions/_tests/harness/runner.ts`)
**Scope:** Medium
1. **Implement** `runTestSuite(cases: TestCase[])` that:
   - Sets up a fresh timeline per test (or reuses with reset)
   - Takes a before-snapshot
   - Sends the message to the agent
   - Waits for agent session to settle (not `processing`)
   - If agent created tasks, waits for task completion + generations
   - Takes an after-snapshot
   - Runs the evaluate function
   - Reports results (pass/fail, diff summary, timing)
2. **Output:** JSON report + console summary
3. **Can be run via:** `npx tsx reigh-app/supabase/functions/_tests/harness/runner.ts`

### Step 9: Create agentic test runner (`reigh-app/supabase/functions/_tests/harness/agentic-runner.ts`)
**Scope:** Large
1. **Implement** a script that:
   - Takes a timeline ID (existing real timeline with real assets) or creates a test one
   - Snapshots the current state
   - Sends the state summary to Claude (via Anthropic API) with a prompt: "Given this timeline state, generate 5 diverse test messages that exercise different capabilities"
   - Claude returns structured test cases with expected behaviors
   - Runs each test case through the harness
   - Collects results
   - Sends results back to Claude: "Here are the results. Identify failure patterns and suggest which tests to run next."
   - Iterates for N rounds (configurable, default 3)
2. **Output:** Full report with test results, failure patterns, suggested code fixes
3. **Safety:** Dry-run mode that generates test cases but doesn't execute; max task creation limit per run

### Step 10: Add Vitest integration for CI (`reigh-app/supabase/functions/_tests/harness/harness.test.ts`)
**Scope:** Small
1. **Create** a Vitest test file that runs the deterministic test cases
2. **Gate** on `HARNESS_ENABLED=1` env var (skip in CI unless explicitly enabled, since it costs real API calls and creates real tasks)
3. **Add** to `vitest.edge.smoke.config.ts` include patterns

## Execution Order
1. Phase 1 first (Steps 1-5) — the harness is useless without the foundation
2. Step 6 before Steps 7-8 — evaluation primitives needed by test cases and runner
3. Steps 7-8 can be developed together
4. Step 9 (agentic runner) depends on Steps 1-8 being solid
5. Step 10 is a thin integration, do last

## Validation Order
1. Manually test client.ts by calling the agent endpoint with a simple "view timeline" message
2. Verify snapshot/diff by taking two snapshots around a known change
3. Run a single deterministic test case end-to-end before building the full suite
4. Run the agentic runner on a small timeline (2-3 clips) with 1 round before scaling up
