        # Implementation Plan: Migrate from YAML/ffmpeg to Remotion

## Overview

The project currently uses a `timeline.yaml` file as the source of truth for video composition, `tools/render.py` (400 LOC) to translate that into ffmpeg filter_complex commands, and a custom React viewer app (`viewer/`, ~1960 LOC across 5 components) for visual preview/editing. The goal is to replace the YAML+ffmpeg render pipeline and the custom viewer with Remotion — a React-based programmatic video framework that provides both a Studio UI (preview/editing) and a headless renderer.

**What stays:** `tools/ingest.py`, `tools/search.py`, `tools/tts.py`, `tools/imagegen.py`, `tools/common.py`, `asset_profiles/`, `inputs/`, and `scripts/`. These produce and manage assets that the new Remotion compositions will consume.

**What goes:** `timeline.yaml` as the composition format, `tools/render.py`, `tools/view.py`, and the entire `viewer/` app (App.tsx, LivePreview.tsx, OverlayEditor.tsx, AssetPanel.tsx, timeline-data.ts, vite.config.ts).

**What replaces them:** A Remotion project with React compositions that encode the timeline directly in code, Remotion's `<Player>` and Studio for preview, and Remotion's CLI renderer replacing ffmpeg.

**Key constraints:**
- The current timeline has 4 video clips, 1 audio clip, and 63 assets in the map — modest scope, good for a manual port.
- Features to preserve: trim (from/to), speed, volume, fade in/out, hold (image duration), overlay positioning/opacity, background compositing with scaling, gap-filling (black video, silent audio), and multi-layer audio mixing.
- Remotion handles frame-based timing (not seconds), so all time math needs conversion via `fps`.

3. **Configure** `remotion/src/Root.tsx` with the output settings from the current timeline: 1280×720 resolution, 30 fps. Set a composition duration matching the current timeline length (~120s = 3600 frames).
4. **Add** static file serving for `../inputs/` and `../asset_profiles/` by configuring Remotion's `public/` folder or using `staticFile()` with a symlink/copy strategy.

**Validation:** Remotion Studio opens and shows a blank composition at 1280×720 @ 30fps.

## Step 2: Build core timeline abstractions
**Scope:** Medium

1. **Create** `remotion/src/types.ts` defining the clip data model — mirrors the current `ClipMeta` from `timeline-data.ts:10-22`:
   ```typescript
   interface Clip {
     at: number        // timeline seconds
     track: 'video' | 'audio' | 'overlay'
     asset: string     // key into asset map
     from: number      // source start seconds
     to: number        // source end seconds
     speed?: number    // default 1
     volume?: number   // default 1
     hold?: number     // image display duration
     x?: number; y?: number
     width?: number; height?: number
     opacity?: number
     effects?: { fade_in?: number; fade_out?: number }
   }
   ```

2. **Create** `remotion/src/timeline-config.ts` — a TypeScript file that replaces `timeline.yaml`. This is the new source of truth. Export the asset map, output settings, and clips array. Port the current 91-line YAML into this typed structure.

3. **Create** `remotion/src/utils.ts` with time conversion helpers:
   - `secondsToFrames(seconds, fps)` / `framesToSeconds(frame, fps)`
   - `clipTimelineDuration(clip)` → `(to - from) / speed` or `hold`
   - `sourceTimeAtFrame(clip, frame, fps)` → source seconds for a given output frame

**Validation:** TypeScript compiles with no errors. Unit-test the time conversion functions with known values from the current timeline (e.g., the venn-diagram clip at 6.91s with speed 1.06).

## Step 3: Implement the video track component
**Scope:** Large — this is the core rendering logic, replacing `render.py:100-220`

1. **Create** `remotion/src/VideoTrack.tsx` — a Remotion `<Sequence>`-based component that:
   - Iterates over video clips sorted by `at`
   - Wraps each in a `<Sequence from={secondsToFrames(clip.at)} durationInFrames={...}>`
   - For video assets: uses `<Video src={...} startFrom={secondsToFrames(clip.from)} playbackRate={clip.speed} />`
   - For image assets (hold): uses `<Img src={...} />` inside a Sequence with `durationInFrames={secondsToFrames(clip.hold)}`
   - Applies fade effects via `<Sequence>` + `interpolate()` on opacity

2. **Handle gap-filling:** Gaps between clips are naturally transparent in Remotion (no video = nothing rendered). If a background is configured, the background layer handles fill. If not, wrap the composition in a `<div style={{backgroundColor: 'black'}}>`.

3. **Handle aspect ratio preservation:** Use CSS `object-fit: contain` on `<Video>` and `<Img>` elements within a 1280×720 container — equivalent to ffmpeg's `force_original_aspect_ratio=decrease` + padding.

**Validation:** Remotion Studio shows the 4 video clips appearing at correct times with correct trims and the venn-diagram clip playing at 1.06× speed.

## Step 4: Implement the audio track component
**Scope:** Medium — replacing `render.py:222-310`

1. **Create** `remotion/src/AudioTrack.tsx`:
   - For each audio clip: `<Sequence from={secondsToFrames(clip.at)}>` containing `<Audio src={...} startFrom={secondsToFrames(clip.from)} volume={clip.volume} />`
   - Multiple audio clips naturally mix in Remotion (no special amix filter needed)
   - Silence in gaps is automatic (no audio element = silence)

2. **Handle speed on audio:** If any audio clips have speed != 1, use Remotion's `playbackRate` prop on `<Audio>`.

**Validation:** Audio plays in sync with video in Studio preview. Volume levels match the current render.

## Step 5: Implement the overlay track component

   - Stack overlays in DOM order (later overlays render on top, matching current ffmpeg behavior)

## Overview

**Current state:** A video editing project with four layers:
1. **Config:** `timeline.yaml` — clips, asset_map, output settings (read/written by all layers)
2. **Render:** `tools/render.py` (400 LOC) — translates YAML → ffmpeg filter_complex
3. **Visual editor:** `viewer/` (~1960 LOC) — React + `@xzdarcy/react-timeline-editor` with drag-and-drop timeline, canvas-based live preview (`LivePreview.tsx`), overlay drag/resize (`OverlayEditor.tsx`), and asset library with upload (`AssetPanel.tsx`). Writes edits back to YAML via `/api/save-timeline`.
4. **Agent tools:** `tools/view.py` (430 LOC) produces an agent-readable timeline summary with transcript context and issue detection. `tools/place.py` (349 LOC) moves clips by timestamp or transcript phrase (`--at-word`) with overlap/gap resolution. `tools/cli.py` is the unified CLI entry point. All read/write `timeline.yaml`.
5. **Asset tools:** `ingest.py`, `search.py`, `tts.py`, `imagegen.py` — produce assets, register via `common.py:register_asset()` which writes to `timeline.yaml`'s `asset_map`.

**Target architecture — three decoupled layers sharing a JSON config:**

```
┌─────────────────────────┐    ┌───────────────────────────┐
│   Visual Editor UI      │    │  Agent Tools              │
│   (drag-drop timeline,  │    │  (view.py, place.py,      │
│    overlay editor,      │    │   Claude natural language) │
│    asset panel)         │    │                           │
└──────────┬──────────────┘    └─────────┬─────────────────┘
           │ reads/writes                 │ reads/writes
           ▼                              ▼
      ┌────────────────────────────────────────┐
      │     timeline.json + asset-registry.json │  ← shared config
      └──────────────────┬─────────────────────┘
                         │ reads (never writes)
                         ▼
      ┌────────────────────────────────────────┐
      │         Remotion (render engine)        │
      │   Studio preview + CLI/API render       │
      └────────────────────────────────────────┘
```

**Key constraints from user:**
1. Two edit paths — AI agent AND visual drag-and-drop — writing to the same config
2. Config must be fast/intuitive for both AI and visual editor → JSON
3. Remotion is purely the render engine — reads config, produces video, never writes config
4. Python tools write to a shared asset registry consumed by Remotion
5. Drag-and-drop timeline editor IS required — Remotion Studio alone is NOT sufficient

**Migration strategy:** Change the config format (YAML → JSON, split asset registry), swap the render engine (ffmpeg → Remotion), swap the preview (canvas → Remotion Player), but keep the visual editor shell and all agent tools. The viewer is adapted, not removed.
