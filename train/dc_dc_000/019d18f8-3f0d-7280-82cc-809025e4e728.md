| Risk | Mitigation |
|------|-----------|
| Visual regression | Import existing CSS wholesale first; convert to Tailwind incrementally |
| Canvas animation breaks | Keep `plant-animation.js` logic intact, only wrap in React lifecycle |
| Blog post rendering differences | Diff HTML output of `marked` between old and new pipelines |
| SEO regression (if blog posts indexed) | Use pre-rendering or SSR for `/posts/*` routes |
| Supabase key exposure | Move to env vars immediately; current key is already in client-side JS |
| Large `script.js` has subtle DOM-dependent logic | Port feature-by-feature with manual testing after each |

# Migration Plan: Personal Website → React 19 + Vite + TypeScript + Tailwind CSS + Supabase

## Current State Summary

- **Server**: Custom Node.js HTTP server (`server.js`, 1254 lines) — serves SSR HTML, handles redirects, parses markdown posts
- **Frontend**: Vanilla JS (`script.js`, ~2000 lines) + vanilla CSS (`styles.css`, ~4100 lines)

## Architecture Decision: Vite SSR + Express

Since SSR is required for blog SEO and the site already runs on Railway as a Node server, the new stack will be:

- **Vite SSR** with a custom Express server (`server.ts`) that renders React on the server
- **React Router v6** for both server and client routing
- **Express** handles HTTP redirects (301s), serves static assets, and returns proper 404 status codes
- **Supabase** stores blog posts (fetched server-side for SSR) and weight measurements (fetched client-side)
- **Railway** continues to run `node dist/server/entry-server.js` (compiled from TypeScript)

This replaces the current `server.js` while preserving its server-side rendering, redirect, and 404 behavior.

```sql
CREATE TABLE posts (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  slug TEXT UNIQUE NOT NULL,
  title TEXT NOT NULL,

  draft BOOLEAN DEFAULT false,
  markdown TEXT NOT NULL,
  excerpt TEXT,

  updated_at TIMESTAMPTZ DEFAULT now()
);

-- RLS: public read for published posts, no client writes
ALTER TABLE posts ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Public read published posts"
```

Since SSR is required for blog SEO and the site already runs on Railway as a Node server, the new stack will be:

```sql
CREATE TABLE posts (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  slug TEXT UNIQUE NOT NULL,
```
