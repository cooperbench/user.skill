# Implementation Plan: Local-worker HTTP endpoints + `file://` input handling

## Overview

Goal: enable the dormant local-worker fast-path. Build a stdlib HTTP server with `/health`, `/ingest`, `/cleanup` (PAT-mode only, bound to `127.0.0.1:8765`, CORS-enabled, Bearer-auth on the two state-changing endpoints); teach `download_utils.py` to honor `file://` paths inside the materialization dir; and **make cleanup actually fire via a periodic age-based janitor**, not via per-task hooks that break sibling-task sharing.

**Architecture decision driven by iter-3 critique** (resolves FLAG-002 / issue_hints-1 / scope / callers / FLAG-006 / correctness / all_locations):
The shipped app's `create-task/index.ts:502-504` copies the same `materialized_inputs` array onto every task returned by a resolver, and `maskedEditResolver:83-85` creates one queued task per `num_generations`. Multiple non-orchestrator sibling tasks share the same `file://` input. The v3 plan's per-task self-cleanup would delete that shared input after the first sibling completes, breaking the rest. Switching to a **periodic age-based janitor** fixes this in one move:
- Background daemon thread sweeps the materialization dir every N minutes (default 30 min) and deletes files whose mtime is older than the configured TTL (default 6 hours).
- All sibling tasks of a single `create-task` call finish well within 6h, so shared inputs survive long enough to be consumed.
- All failure branches (raw-result failure, unhandled exception, requeue exhaustion) are covered uniformly without per-branch hooking — addresses FLAG-006 / correctness / all_locations.
- Orchestrator chains (travel/join/edit_video) typically finish within the TTL; if a chain runs longer, the worker can extend the TTL via env var.
- Sweep also runs ONCE at startup so files left from a previous crash get cleaned.

The HTTP `/cleanup` endpoint stays as a contract entry-point (built, tested, idempotent, auth-gated) for any future browser-driven flow that wants to explicitly free a file early. Cleanup correctness no longer depends on it.

**Other course corrections from iter-3 critique:**
- **FLAG-007 / issue_hints-2** (auth tradeoff visibility): keep `REIGH_LOCAL_WORKER_AUTH_OPTIONAL=1` (default off) for single-machine smoke testing, but make the tradeoff loud: emit an `headless_logger.warning(...)` line at startup whenever the knob is enabled, prefixed `[SECURITY]`, naming the brief's threat model and instructing production setups to leave it unset. Add the same warning to the deliverable summary.

Repo shape:
- Polling worker entrypoint: `source/runtime/worker/server.py:main()` (`server.py:248-836`); auth-mode resolver at `server.py:47-64`.
- URL fetcher: `source/utils/download_utils.py:_download_file_if_url` (`download_utils.py:202-240`).

Constraints baked in: bind `127.0.0.1` only; refuse path-traversal AND literal `..` components; gate startup on PAT-mode; persist `~/.reigh-local-worker/auth-token` (0600) and `~/.reigh-local-worker/port`; do NOT pull in heavyweight HTTP frameworks.

### Step 1: Add the local HTTP server module (`source/runtime/worker/local_http.py`)
**Scope:** Medium

1. **Create** `source/runtime/worker/local_http.py` exposing `start_local_http_server(*, materialization_dir: Path, port: int, worker_id: str, version: str, auth_optional: bool = False, file_ttl_seconds: int = 21600, janitor_interval_seconds: int = 1800) -> LocalHttpServer` and `LocalHttpServer.shutdown()`.
2. **Implement** with `http.server.ThreadingHTTPServer` bound to `("127.0.0.1", port)` plus a `BaseHTTPRequestHandler` subclass.
3. **Endpoints**:
   - `GET /health` → `200 application/json` `{"ok": true, "worker_id": ..., "version": ...}`. No auth check.
   - `POST /ingest` → require `Authorization: Bearer <token>` (constant-time `hmac.compare_digest`) UNLESS `auth_optional=True`. Parse `multipart/form-data` with `cgi.FieldStorage` reading exactly one file part named `file`. Sanitize the upload's filename suffix via `re.search(r"\\.[A-Za-z0-9]+$", filename)`; default `.bin`. Write to `materialization_dir / f"{uuid4().hex}{suffix}"` via `os.open(..., O_WRONLY|O_CREAT|O_EXCL, 0o600)`. Respond `200` with `{"path": "<abs>", "size": <bytes>}`.
   - `POST /cleanup` → same auth gate. Read JSON `{"path": "..."}`. **Validate path components**: if any part of `Path(payload_path).parts` equals `".."`, return `400` (literal `..` ban — addresses prior FLAG-005). Then resolve via `Path(path).resolve(strict=False)` and require `is_relative_to(materialization_dir.resolve())`. Outside → `400`. Doesn't exist → `204` (idempotent). Else `unlink()` + `204`.
   - `OPTIONS <any>` → `204` with CORS headers.
   - Any other path/method → `404`.
   - Override `log_message` to route through `headless_logger.debug`.
4. **CORS**: on every response, set `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, `Access-Control-Allow-Headers: Authorization, Content-Type`, `Access-Control-Max-Age: 600`.
5. **Token + persisted state**: `secrets.token_urlsafe(32)`. Ensure `~/.reigh-local-worker/` exists with mode 0700; write `auth-token` via `os.open(..., O_WRONLY|O_CREAT|O_TRUNC, 0o600)`; write `port` (the actual `server.server_address[1]`) as plain text. On shutdown, best-effort delete both files.
6. **Materialization dir**: `Path.mkdir(mode=0o700, exist_ok=True, parents=True)`; on POSIX, `os.chmod(0o700)` if pre-existed (best-effort).
7. **Threading**: `serve_forever()` on a daemon HTTP thread; `shutdown()` calls `server.shutdown()`, `server.server_close()`, joins with 5-second timeout AND signals the janitor thread to exit (see Step 2).

### Step 2: Add the periodic age-based janitor (`source/runtime/worker/local_http.py`)
**Scope:** Small — addresses FLAG-002 / issue_hints-1 / scope / callers / FLAG-006 / correctness / all_locations

1. **Add** a `_FileJanitor` class in the same module:
   - Constructor takes `materialization_dir: Path`, `file_ttl_seconds: int`, `interval_seconds: int`, plus a `threading.Event` `stop_event`.
   - `run()` method: at startup do one `_sweep()` immediately (clean up files left over from prior crashes); then loop `while not stop_event.wait(interval_seconds): self._sweep()`.
   - `_sweep()` method: iterate `materialization_dir.iterdir()`, skip non-files, compute `age = time.time() - file.stat().st_mtime`. If `age > file_ttl_seconds`, `unlink(missing_ok=True)`. Wrap each unlink in `try/except OSError` and log via `headless_logger.debug`. NEVER follow symlinks; use `Path.is_file()` (which returns False for symlinks pointing outside, since `iterdir` only returns immediate children of the resolved dir). Skip any file whose name doesn't look like our `<uuid>.<ext>` pattern (regex `^[a-f0-9]{32}\\.[A-Za-z0-9]+$`) — keeps the janitor safe if a user manually drops files into the dir.
2. **Run** the janitor on its own daemon thread, started inside `start_local_http_server`. Pass the same `stop_event` shared with the HTTP server's `shutdown()`. On `LocalHttpServer.shutdown()`, set the event, join the janitor thread with a 5-second timeout.
3. **Why this design satisfies all open cleanup flags**:
   - Sibling tasks sharing a `file://` input all finish within `file_ttl_seconds=6h` → janitor doesn't race them.
   - All failure branches (raw-result failure path `server.py:740-757`, unhandled-exception path `server.py:760-789`, exhausted-retry, orchestrator chains) are covered uniformly with zero per-branch hooks.
   - Crash recovery: stale files from a prior crash get swept on next startup.
   - Worker doesn't need DB queries to check sibling-task references.

# Implementation Plan: Local-worker HTTP endpoints + `file://` input handling

## Overview

Goal: enable the dormant local-worker fast-path. Build a stdlib HTTP server with `/health`, `/ingest`, `/cleanup` (PAT-mode only, bound to `127.0.0.1:8765`, CORS-enabled, Bearer-auth on the two state-changing endpoints); teach `download_utils.py` to honor `file://` paths inside the materialization dir; and **make cleanup actually fire via a periodic age-based janitor**, not via per-task hooks that break sibling-task sharing.

**Architecture decision driven by iter-3 critique** (resolves FLAG-002 / issue_hints-1 / scope / callers / FLAG-006 / correctness / all_locations):
The shipped app's `create-task/index.ts:502-504` copies the same `materialized_inputs` array onto every task returned by a resolver, and `maskedEditResolver:83-85` creates one queued task per `num_generations`. Multiple non-orchestrator sibling tasks share the same `file://` input. The v3 plan's per-task self-cleanup would delete that shared input after the first sibling completes, breaking the rest. Switching to a **periodic age-based janitor** fixes this in one move:
- Background daemon thread sweeps the materialization dir every N minutes (default 30 min) and deletes files whose mtime is older than the configured TTL (default 6 hours).
- All sibling tasks of a single `create-task` call finish well within 6h, so shared inputs survive long enough to be consumed.
- All failure branches (raw-result failure, unhandled exception, requeue exhaustion) are covered uniformly without per-branch hooking — addresses FLAG-006 / correctness / all_locations.
- Orchestrator chains (travel/join/edit_video) typically finish within the TTL; if a chain runs longer, the worker can extend the TTL via env var.
- Sweep also runs ONCE at startup so files left from a previous crash get cleaned.

The HTTP `/cleanup` endpoint stays as a contract entry-point (built, tested, idempotent, auth-gated) for any future browser-driven flow that wants to explicitly free a file early. Cleanup correctness no longer depends on it.
