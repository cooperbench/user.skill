        # Implementation Plan: Asset Slots for AI-Generated Sequence Components

## Overview
The root approach is still correct: the issue is not in timeline media assets generally, but in the generated Sequence Creator component contract. The critique shows the first plan was missing several boundary changes required by that contract: generated-code param coverage, both controls-manifest validators, runtime access to saved slot metadata, slot-aware smoke rendering, and a richer edge allowed-asset payload. This revision keeps the scope focused on AI-generated DB-stored sequence components and does not migrate trusted built-in sequence `asset-list` params.

Current generated components use loose `params.imageAssetKeys` / `params.videoAssetKeys`, with frontend convention materialization to `params.images` / `params.videos`. The new contract is: persist `params.assetSlotBindings` as registry-key arrays, persist component-level `assetSlots` metadata on sequence-component resources, and inject runtime `params.assetSlots` as `Record<slotId, string[]>` URL arrays. `assetSlots` is host-injected and must be exempt from user-param coverage and controls-manifest coverage; `assetSlotBindings` is persisted defaults data and slot-picker owned, not a normal control.

## Phase 1: Contract Foundation

### Step 1: Add shared asset-slot helpers (`src/tools/video-editor/sequences/assetSlots.ts`, `src/features/resources/hooks/useResources.ts`)
**Scope:** Medium
1. **Create** `assetSlots.ts` with:
   - `SequenceAssetSlot`: `{ id, label, mediaType: 'image' | 'video', minItems?, maxItems?, required?, defaultAssetKeys? }`.
   - `SequenceAssetSlotBindings`: `Record<string, string[]>`.
   - `ResolvedSequenceAssetSlots`: `Record<string, string[]>` URL arrays.
   - `normalizeAssetSlots`, `normalizeAssetSlotBindings`, `validateAssetSlotBindings`, `materializeAssetSlotBindings`, and `inferRegistryAssetMediaType`.
2. **Infer** registry media type from `ResolvedAssetRegistryEntry.type` MIME-ish strings first, then URL/file extension only as a fallback. In Sequence Creator preview/UI, prefer `AllowedSequenceAsset.mediaType`, because that is already normalized.
3. **Add** `assetSlots?: unknown[]` to `SequenceComponentMetadata` in `src/features/resources/hooks/useResources.ts`.
4. **Keep** trusted built-in sequence descriptors unchanged; this module supports generated DB components first.

### Step 2: Make the slot param contract explicit (`src/tools/video-editor/sequences/assetSlots.ts`)
**Scope:** Small
1. **Persist** key choices in `params.assetSlotBindings`.
2. **Inject** runtime URLs in `params.assetSlots` as `Record<slotId, string[]>`.
3. **Reserve** both names from user controls: `assetSlots` is host-injected runtime data; `assetSlotBindings` is edited only by slot pickers.
4. **Reject** generated-component use of loose `imageAssetKeys`, `videoAssetKeys`, `images`, and `videos`.

## Phase 2: Edge Prompt, Parsing, and Validators

### Step 3: Pass rich allowed assets to edge prompt/validation (`supabase/functions/ai-generate-sequence-component/index.ts`, `supabase/functions/ai-generate-sequence-component/templates.ts`)
**Scope:** Medium
1. **Normalize** `allowed_assets` on the edge into objects containing `key`, `mediaType`, `label`, and optional source context; keep `allowedAssetKeys` only as a derived convenience.
2. **Number** allowed assets in prompts using the normalized objects, for example `1. [image] asset-a - Shot name`.
3. **Pass** normalized allowed assets into template construction and slot validation so media-type checks do not depend on a flat key list.

### Step 4: Require `ASSET_SLOTS` metadata in generated code (`supabase/functions/ai-generate-sequence-component/templates.ts`)
**Scope:** Medium
1. **Update** output requirements to include `// ASSET_SLOTS: [...]` between `DEFAULTS` and `CONTROLS`.
2. **Instruct** the model to declare slots in `ASSET_SLOTS`, put default registry keys in `DEFAULTS.assetSlotBindings`, and render from `params.assetSlots.<slotId>`.
3. **Remove** prompt guidance for generated components that asks for `imageAssetKeys`, `videoAssetKeys`, `images`, or `videos`.
4. **Allow** `ASSET_SLOTS: []` for components that genuinely do not use media or when no allowed media is available.

### Step 5: Parse and return slot metadata (`supabase/functions/ai-generate-sequence-component/templates.ts`, `supabase/functions/ai-generate-sequence-component/index.ts`, `src/tools/video-editor/components/SequenceCreator/sequenceGenerationService.ts`)
**Scope:** Medium
1. **Extend** extraction metadata and edge response types with `assetSlots`.
2. **Require** `ASSET_SLOTS` to parse as a JSON array for new generated components.
3. **Return** `assetSlots` to the frontend and normalize it before accepting a successful code-path generation.

### Step 6: Update generated-code and controls-manifest validators (`supabase/functions/ai-generate-sequence-component/sequence-component-validation.ts`, `supabase/functions/ai-generate-sequence-component/controls-manifest-validation.ts`, `src/tools/video-editor/sequences/controlsManifest.ts`)
**Scope:** Medium
1. **Exempt** `params.assetSlots` from SCHEMA/DEFAULTS coverage in `validateSequenceComponentCode()` because it is host-injected runtime data.
2. **Permit** `params.assetSlotBindings` in SCHEMA/DEFAULTS only as persisted binding data, while excluding it from `CONTROLS` cross-coverage.
3. **Add** `assetSlots` and `assetSlotBindings` to reserved/managed params in both edge and frontend controls-manifest validators.
4. **Reject** loose generated-component media params: `imageAssetKeys`, `videoAssetKeys`, `images`, and `videos` in schema/defaults/code for the code-path endpoint.
5. **Add** slot validation on the edge: duplicate slot ids, invalid ids, invalid media type, invalid cardinality, unknown binding slot, unknown asset key, wrong media type, missing required slots, and min/max violations.

## Phase 3: Frontend State, Save, Load, and Runtime Metadata

### Step 7: Carry asset slots through generated-component state (`src/tools/video-editor/components/SequenceCreator/sequenceGenerationService.ts`, `src/tools/video-editor/state/sequenceCreatorStore.ts`)
**Scope:** Medium
1. **Extend** `RunSequenceComponentGenerationResult` and `GeneratedComponent` with normalized `assetSlots`.
2. **Keep** edited bindings in `generatedComponent.defaultsJson.assetSlotBindings` as the single source of truth for preview, smoke render, save, Insert, and Replace.
3. **Clear** stale generated component slot state when JSON-path drafts replace code-path state.

### Step 8: Save and reload slot metadata with resources (`src/tools/video-editor/components/SequenceCreator/SequenceCreatorPanel.tsx`, `src/tools/video-editor/hooks/useSequenceResources.ts`)
**Scope:** Medium
1. **Include** `assetSlots` in the `SequenceComponentMetadata` saved by `persistGeneratedComponent`.
2. **When loading or previewing** a library resource, populate `generatedComponent.assetSlots` from resource metadata.
3. **When reusing** a library component for Insert/Replace, synthesize the draft from current `generatedComponent.defaultsJson`, not raw resource defaults, so current slot picker assignments are applied.
4. **Do not** add MP4 preview cache fields, jobs, thumbnails, or resource metadata.

### Step 9: Make dynamic runtime materialization slot-aware (`src/tools/video-editor/sequences/materialize.ts`, `src/tools/video-editor/sequences/SequenceComponentRegistryContext.tsx`, `src/tools/video-editor/compositions/TimelineRenderer.tsx`)
**Scope:** Medium
1. **Extend** dynamic sequence registry entries to include `assetSlots` from each `SequenceComponentResource`.
2. **Plumb** dynamic entries or a `clipType -> assetSlots` lookup into materialization call sites that render DB-stored sequence components.
3. **Update** `materializeSequenceParams` / `materializeSequenceConfig` to accept optional slot metadata lookup while preserving current trusted descriptor-driven materialization for built-ins.
4. **Materialize** `params.assetSlotBindings` to `params.assetSlots` only when slot metadata is available for the clip type.
5. **Validate** slot id/cardinality/media type during materialization with registry media-type inference; warn and omit invalid URL injections rather than mutating persisted params.
6. **Remove** generic generated-component convention materialization from `imageAssetKeys` / `videoAssetKeys` to `images` / `videos`.

## Phase 4: Preview, Smoke Render, and Slot Picker UI

### Step 12: Build and wire slot pickers (`src/tools/video-editor/components/SequenceCreator/AssetSlotPicker.tsx`, `src/tools/video-editor/components/SequenceCreator/SequenceCreatorPanel.tsx`)

### Step 13: Keep trusted JSON sequence editing stable (`src/tools/video-editor/components/PropertiesPanel/SequenceParamEditor.tsx`)
