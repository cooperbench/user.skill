        # Implementation Plan: Video Editor Tool — 8-Issue Fix Bundle

## Overview

The video editor (`src/tools/video-editor/`) has 8 issues across drag-drop UX, pane layout, rendering, property panel filtering, and lightbox interaction. The editor uses two distinct drag systems (pointer events for internal clip movement, HTML5 drag-drop for external assets), a Remotion-based preview, and integrates as both a standalone page and a compact sliding pane.

**Key constraints:**
- Shared drag-drop utilities in `src/shared/lib/dnd/dragDrop.ts` must not break gallery/shot targets.
- Remotion render is currently a stub — the "broken render" issue may mean either fixing the stub or wiring a real render pipeline.
- The `@xzdarcy/react-timeline-editor` library controls much of the internal clip movement UX; some drag-drop unification may be limited by its API.

---

## Phase 1: Low-Risk UI/UX Fixes (no data flow changes)

### Step 1: Add type mismatch indicator to cross-track drag (`useCrossTrackDrag.ts`, `timeline-overrides.css`)
**Scope:** Small
1. **Inspect** `useCrossTrackDrag.ts:180-183` — currently when `targetTrack.kind !== session.sourceKind`, the drop target is silently cleared with no indicator.
2. **Implement** a "reject" visual indicator: when the drop target track has a mismatched kind, show the highlight row with a red/warning tint instead of hiding it. Add a CSS class `cross-track-drop-reject` to `timeline-overrides.css`.
3. **Update** `updateDropTarget()` to set `session.createTrackOnDrop = false` and render a red-tinted highlight (e.g., `rgb(250 137 137 / 0.12)`) when the target kind doesn't match, and set cursor to `not-allowed` on the ghost.
4. **Leverage** the existing `resolveDropTarget()` helper in `coordinate-utils.ts:118-132` which already returns `{ kind: 'reject' }` for mismatched kinds.

### Step 2: Filter ClipPanel tabs based on clip type (`ClipPanel.tsx`)
**Scope:** Small
1. **Inspect** `ClipPanel.tsx:94-101` — all 5 tabs always shown regardless of `clip.clipType`.
2. **Implement** conditional tab rendering:
   - For `clipType === 'text'`: hide "Audio" tab (text clips have no audio), hide "Timing > Source In/Out" fields (no source media).
   - For `clipType !== 'text'`: hide "Text" tab entirely.
   - For audio tracks (`track?.kind === 'audio'`): hide "Position" and "Text" tabs.
3. **Update** `TabsList grid-cols-5` to dynamically adjust column count based on visible tabs.

### Step 3: Add double-click lightbox for media clips in preview (`OverlayEditor.tsx`, `AssetPanel.tsx`)
**Scope:** Small–Medium
1. **Inspect** `OverlayEditor.tsx:390` — `onDoubleClick` currently only triggers `beginTextEdit` for text clips. Non-text clips have no double-click handler.
2. **Implement** double-click on non-text overlay clips opens the source generation lightbox:
   - When `clipMeta.clipType !== 'text'` and `clipMeta.asset` is set, double-click should open MediaLightbox for the asset's generation.
   - Add `onDoubleClickAsset?: (assetKey: string) => void` callback to `OverlayEditorProps`.
   - In `OverlayEditor`, dispatch: `onDoubleClick={() => clipMeta.clipType === 'text' ? beginTextEdit(overlay.actionId) : onDoubleClickAsset?.(clipMeta.asset)}`.
3. **Wire** the lightbox state from the existing `AssetPanel` lightbox infrastructure or lift it to `PropertiesPanel`/`VideoEditorShell` level.

## Phase 2: Drag-Drop Unification

### Step 4: Unify drop zone visual indicators (`useTimelineEditing.ts`, `useCrossTrackDrag.ts`)
**Scope:** Medium
1. **Audit** the two indicator systems:
   - Internal (pointer): creates DOM elements in `useCrossTrackDrag.ts:186-198` (`.cross-track-drop-highlight`, `.cross-track-ghost`).
   - External (HTML5 drag): creates DOM elements in `useTimelineEditing.ts:153-217` (row highlight, line, ghost, label).
2. **Extract** a shared `DropIndicator` module (or utility functions) that both systems use for consistent visual feedback. Key elements: row highlight, time position line, ghost preview, label.
3. **Implement** consistent styling: same blue highlight color (`rgb(137 180 250 / 0.12)`), same ghost opacity, same label format (`TrackName · Xs`).
4. **Update** both drag handlers to use the shared indicator.

### Step 5: Add drop rejection feedback for external drops (`useTimelineEditing.ts`)
**Scope:** Small
1. **Inspect** `onTimelineDragOver` (`useTimelineEditing.ts:556-619`) — currently highlights the drop row but doesn't indicate if the asset kind is incompatible with the target track.
2. **Implement** kind checking during `onTimelineDragOver`:
   - For `asset-key` drags: read `asset-kind` from dataTransfer types to determine if the hovered track is compatible.
   - For generation drags: infer kind from metadata (generation drags are always visual).
   - For file drags: infer from file extension via MIME types in `dataTransfer.items`.
3. **Show** the reject indicator (red-tinted row from Step 1) when kinds don't match.

### Step 6: Add explicit drop zone boundaries and empty-track affordance (`TimelineEditor.tsx`)
**Scope:** Small
1. **Inspect** `TimelineEditor.tsx:209-214` — the wrapper div is the only drop zone.
2. **Implement** visual drop zone borders during drag: add a `data-drag-over` CSS rule in `timeline-overrides.css` that shows a dashed border around the timeline area when a valid drag is in progress.
3. **Consider** adding a "drop below to create new track" indicator at the bottom of the track list during external drags (similar to the cross-track drag's `drop-target-new-track` class).

## Phase 3: Pane Layout and Render Fixes

### Step 7: Fix pane locking view shift for editor pane (`EditorPaneTab.tsx`, `PanesContext`)
**Scope:** Medium
1. **Inspect** `EditorPaneTab.tsx:71-73` — `horizontalOffset` is computed from shots/tasks pane widths, and `left`/`right` are applied inline (`lines 126-127`). When these panes lock/unlock, the editor pane jumps.
2. **Implement** smooth transition on `left` and `right` style changes by adding `transition-[left,right]` and `duration-300` to the pane's className (line 130-133).
3. **Verify** the compact `VideoEditorShell` resizes its content correctly when the container dimensions change (Remotion Player uses `width: '100%'`).
4. **Test** edge case: locking editor pane, then locking shots pane — editor should smoothly shift right without content jump.

### Step 8: Fix broken Remotion render (`useTimelineData.ts`, new: render task creation)
**Scope:** Large (may require server-side work)
1. **Inspect** `useTimelineData.ts:603-606` — `startRender` is a stub showing a toast.
2. **Decision point:** This is either:
   - **(A)** Wire to existing task creation infrastructure (`unified_task_creation.md`) to create a render task that a worker picks up, OR
   - **(B)** Implement client-side Remotion rendering using `@remotion/renderer`, OR
   - **(C)** Keep stub but fix any UI that implies rendering works (remove Render button or mark as "Coming Soon").
3. **If (A):** Create a `render-video` task type, add a migration for video render tasks table, wire `startRender` to `createTask()` with the timeline config as params.
4. **If (C):** Update the Render button in `VideoEditorShell.tsx:135-139` to show "Coming Soon" badge and disable the button.
