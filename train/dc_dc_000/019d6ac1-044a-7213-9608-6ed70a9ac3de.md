# Implementation Plan: User-Configurable Default Tool + Promote Video Editor to Main Tools

## Overview
Two tightly-related changes to the tools sidebar:
1. **User-configurable default landing tool.** Today, `authRedirectLoader` and two `/tools` loaders all hardcode `/tools/travel-between-images` (`src/app/routes.tsx:57,125,129`). Add a per-user preference `defaultTool.toolId` stored in `users.settings.ui` via the existing `useUserUIState` hook, and route the app landing through a tiny redirect component that honors the preference. Each `ToolCard` gets a home-icon button that sets the default; the card whose id matches the stored default renders the home icon filled/highlighted.
2. **Promote Video Editor to "Main Tools."** In `src/shared/lib/tooling/toolManifest.ts:102`, change `paneSection: 'assistant'` → `'main'` for the `videoEditorSettings` entry. No other wiring needed — `ToolsPane.tsx:19-20` already partitions by `paneSection`.

Reuse the existing settings pattern (mirrors `paneLocks`, `theme`, etc.): add a new `defaultTool` key to `UISettings`, a `decodeDefaultTool` helper, and a branch in `normalizeUserUISetting`.

Constraint: the React-Router loaders are synchronous and can't await async Supabase reads, so the redirect must happen inside a React component mounted under `<Layout>` (where `AuthContext` and hooks are available).

## Main Phase

### Step 1: Add `defaultTool` to the user-UI-state schema (`src/shared/hooks/useUserUIState.ts`)
**Scope:** Small
1. **Add** `defaultTool: { toolId: string }` to the `UISettings` interface (`src/shared/hooks/useUserUIState.ts:42`).
2. **Add** a `decodeDefaultTool(value, fallback)` helper alongside the other `decode*` functions (~`useUserUIState.ts:179`). It should return `{ toolId: readString(record?.toolId, fallback.toolId) }`.
3. **Add** a `case 'defaultTool':` branch to `normalizeUserUISetting` (`useUserUIState.ts:205`).
4. No migration needed — `users.settings` is a JSONB column and the existing auto-backfill path handles new keys.

### Step 2: Promote Video Editor to Main Tools (`src/shared/lib/tooling/toolManifest.ts`)
**Scope:** Tiny
1. **Change** the `videoEditorSettings` entry's `paneSection` from `'assistant'` to `'main'` (`src/shared/lib/tooling/toolManifest.ts:102`). `ToolsPane.tsx` automatically picks it up.

### Step 3: Create a default-tool redirect component (`src/app/DefaultToolRedirect.tsx`, new file)
**Scope:** Small
1. **Create** a small component that calls `useUserUIState('defaultTool', { toolId: 'travel-between-images' })`, waits for `isLoading === false`, then renders `<Navigate to={`/tools/${value.toolId}`} replace />`. While loading, render `<ReighLoading />` (same fallback used elsewhere in routes).
2. **Guard** against a stale/unknown `toolId` by checking against `toolRuntimeManifest`. If the stored id is not found (tool was removed), fall back to `travel-between-images` and overwrite the bad value via `update({ toolId: 'travel-between-images' })`.

### Step 4: Route the landing path through the redirect component (`src/app/routes.tsx`)
**Scope:** Small
1. **Change** the `/tools` route (`src/app/routes.tsx:127-130`) from `loader: () => redirect('/tools/travel-between-images')` to `element: <DefaultToolRedirect />` (keeps it inside `<Layout>` so auth + hooks are available).
2. **Change** the PWA `/` redirect (`src/app/routes.tsx:123-126`) similarly to render `<DefaultToolRedirect />`.
3. **Change** `authRedirectLoader` (`src/app/routes.tsx:57`) to `redirect('/tools')` instead of `redirect('/tools/travel-between-images')`. This funnels the authed-user landing through the same preference-aware component.

### Step 5: Add home-button UI to ToolCard (`src/shared/components/ToolsPane/ToolsPane.tsx`)
**Scope:** Medium
1. **Import** `Home` from `lucide-react` (`ToolsPane.tsx:13`).
2. **Lift** the default-tool hook into `ToolsPaneComponent` so the value and `update` are available to all cards: `const { value: defaultTool, update: updateDefaultTool } = useUserUIState('defaultTool', { toolId: 'travel-between-images' });` (next to the existing `generationMethods` hook at `ToolsPane.tsx:228`).
3. **Thread** `isDefault` (bool) and `onSetDefault` (callback) props into `ToolCard` (`ToolsPane.tsx:24-29`). Pass them from both the "Main Tools" and "Assistant Tools" map loops.
4. **Render** a `<button>` inside the card, absolutely positioned or in the existing flex row next to the "current indicator" dot (`ToolsPane.tsx:109-112`). Icon: `<Home>` with `fill-current` + accent color when `isDefault`, unfilled/muted otherwise.
5. **Handle** click: the button must call `e.stopPropagation()` (and return without calling `onPointerUp`) so it doesn't trigger the card's navigate handler. On click: `updateDefaultTool({ toolId: item.id })`. Add `aria-label="Set as default landing tool"` and a tooltip via `title`.
6. **Accessibility**: ensure the button is `type="button"` and focus-visible.

### Step 6: Manual + automated verification
**Scope:** Small
1. **Run** `npm run lint` and `npm run typecheck` (or `tsc --noEmit`) — cheapest checks, catches the new `UISettings` key wiring.
2. **Run** `npm test` for any existing tests touching `useUserUIState` or `ToolsPane` (search: `useUserUIState.test`, `ToolsPane.test`). Update snapshots/tests if the ToolCard shape changed.
3. **Dev smoke test** (documented as info-priority criteria below): load the app, confirm video-editor appears under "Main Tools," click the home icon on a non-default tool, reload the app, and verify you land on that tool.
