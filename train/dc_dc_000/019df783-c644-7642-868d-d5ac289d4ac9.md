        # Implementation Plan: Phase 8 Inbox Surface

## Overview
Phase 8 adds an opt-in `runs/<run-id>/inbox/` JSON completion channel for active task runs. The current V1 lifecycle already has hash-chained events in `artagents/core/task/events.py:25`, read-only cursor peeking in `artagents/core/task/gate.py:454`, attested completion in `artagents/core/task/gate.py:904`, `status` output in `artagents/core/task/lifecycle.py:245`, `next` output in `artagents/core/task/lifecycle.py:367`, and the generated run `AGENT.md` template in `artagents/core/task/lifecycle.py:53`.

The smallest durable implementation is additive: introduce inbox parsing/consumption beside the task kernel, factor the existing attested-event write path enough for inbox reuse, then wire `status` and `next` without changing `ack` semantics.

## Main Phase

### Step 1: Add the inbox module (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Define `InboxEntry` and `EventRecord` types around the requested JSON shape: `step_id`, `decision`, `evidence`, `submitted_at`, `submitted_by`, plus `source_path` and source-content hash for consumption bookkeeping.
2. Implement `inbox_dir(run_dir) -> Path` as `<run_dir>/inbox`.
3. Implement `scan_inbox(run_dir) -> list[InboxEntry]` so absence of `inbox/` returns `[]`; only regular non-dot JSON files are read; malformed JSON/schema/type/timestamp/decision files are logged with stdlib `logging` and skipped.
4. Use deterministic ordering by path name so tests and operators see stable behavior.
5. Document the consumed-file policy in the module docstring: processed files move to `inbox/.consumed/<sha256>.json` rather than being deleted.

### Step 2: Reuse attested event recording safely (`artagents/core/task/gate.py`)
**Scope:** Medium
1. Extract the shared core of `_dispatch_attested` at `artagents/core/task/gate.py:904` into a helper that records a prevalidated attestation for the current `AttestedStep`, preserving `step_attested`/`item_attested`, inline produces checks, iteration feedback behavior, and hash-chained writes.
2. Keep `gate_command` identity validation unchanged for explicit `ack`/gate paths.
3. Let inbox consumption call the new helper with `attestor_kind=peek.step.ack.kind` and `attestor_id=entry.submitted_by` after it has verified `entry.step_id` matches the current cursor and the current step is attested.

### Step 3: Consume actionable inbox files (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Implement `consume_inbox_entry(run_dir, entry) -> EventRecord` by deriving `project_root`, `projects_root`, and `run_id` from `<project>/runs/<run-id>`; then load `plan.json`, `events.jsonl`, and `peek_current_step`.
2. Validate current expectations before mutation: active run exists, cursor is an `AttestedStep`, `entry.step_id == STEP_PATH_SEP.join(peek.path_tuple)`, and the entry decision is valid for the cursor.
3. For `approve`, append the attested event through the shared gate helper, then move the source file to `.consumed`.
4. For `retry`, mirror existing `ack retry` semantics: only consume if the latest event for the current path is `produces_check_failed`; append `cursor_rewind`; otherwise log and leave the file in place.
5. For `abort`, consume only when the `step_id` matches the current attested cursor; append `run_aborted`, clear `active_run.json`, and move the file.
6. Stale entries whose `step_id` does not match the current cursor are logged and left untouched, not consumed.

### Step 4: Wire lifecycle surfaces (`artagents/core/task/lifecycle.py`, `artagents/core/task/__init__.py`)
**Scope:** Medium
1. In `cmd_next`, after resolving the active run and before printing the final current-step instructions, scan the active run inbox, consume at most one actionable entry for the current attested cursor, reread events/active-run state, and recompute the cursor so output reflects advancement.
2. If an inbox `abort` clears the active run, print a concise aborted/consumed message after the mandatory preamble and return without falling through to normal next-step output.
3. In `cmd_status`, scan read-only and print `inbox:    N pending` where `N` is the number of structurally valid, currently actionable entries; do not mutate `events.jsonl` or move files.
4. Export inbox helpers from `artagents/core/task/__init__.py` only if tests or local style benefit from package-level imports.
5. Do not change `cmd_ack` in `artagents/core/task/lifecycle_ack.py`.

### Step 5: Update generated operator docs (`artagents/core/task/lifecycle.py`)
**Scope:** Small
1. Extend `_AGENT_MD_TEMPLATE` at `artagents/core/task/lifecycle.py:53` with an `INBOX` section showing the JSON file shape and explaining that files dropped into `runs/<run-id>/inbox/` are scanned by `next` and surfaced by `status`.
2. State the consumed-file behavior: valid consumed submissions move to `inbox/.consumed/<sha256>.json`; malformed and stale files remain for inspection.

### Step 6: Add focused tests (`tests/test_inbox_scan.py`, `tests/test_inbox_consume.py`, `tests/test_inbox_stale.py`)
**Scope:** Medium
1. `tests/test_inbox_scan.py`: create `run_dir/inbox`, write 3 valid JSON files and 1 malformed file, assert `scan_inbox` returns 3 entries and logs/skips the malformed file without raising.
2. `tests/test_inbox_consume.py`: use `tests/_lifecycle_fixtures.py:45` to create an attested step followed by a code step, drop a valid `approve` inbox entry, call `cmd_next`, assert a hash-chained `step_attested` event exists, the inbox file moved to `.consumed`, and the output/cursor advances to the following step.
3. Add a status assertion in the consume flow or a separate small test: before `next`, `cmd_status` prints `inbox:    1 pending` and does not mutate `events.jsonl`.
4. `tests/test_inbox_stale.py`: drop a valid entry for a non-current `step_id`, call `cmd_next`, assert no attested event is recorded, the file remains in inbox, and no exception occurs.

## Execution Order
1. Add parser-only `inbox.py` and `test_inbox_scan.py` first; this is the cheapest validation and avoids lifecycle complexity.
2. Factor the gate attestation helper before wiring `next`, so inbox approval reuses the same event/check behavior as explicit attestation.
3. Wire `status` read-only behavior before mutating `next` behavior, preserving the existing `test_status_does_not_mutate_events_jsonl` invariant.
4. Wire `next` consumption and then add consume/stale integration tests.
5. Update the `AGENT.md` template after behavior is stable.

3. Run focused lifecycle regressions: `pytest tests/test_lifecycle_next.py tests/test_lifecycle_status.py tests/test_lifecycle_ack.py`.
4. Run the full suite: `pytest tests/`.

        # Implementation Plan: Phase 8 Inbox Surface

## Overview
Phase 8 adds an opt-in `runs/<run-id>/inbox/` JSON completion channel for active task runs. The current V1 lifecycle already has hash-chained events in `artagents/core/task/events.py:25`, cursor peeking in `artagents/core/task/gate.py:454`, gate dispatch in `artagents/core/task/gate.py:510`, `status` in `artagents/core/task/lifecycle.py:245`, `next` in `artagents/core/task/lifecycle.py:367`, and the generated run `AGENT.md` template in `artagents/core/task/lifecycle.py:53`.

The critique does not show the plan targeting the wrong files, but it does show the original consume approach targeted the wrong layer: appending an attested event after `peek_current_step` would skip persisted traversal events for nested/repeat cursors. The revised approach keeps parsing in a new inbox module, but routes approval consumption through a gate-level external-attestation path that performs the same active-run checks and auto-traversal event persistence as `gate_command` before writing `step_attested`/`item_attested`.

Phase 8 remains approval-focused. The JSON format accepts `decision: approve | retry | abort`, but only `approve` is actionable in this phase because the design describes an external completion-signal protocol. `retry` and `abort` entries are structurally valid files, logged as non-actionable, not counted as pending, and not consumed.

## Main Phase

### Step 1: Add inbox parsing and read-only actionability (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Define `InboxEntry`, `EventRecord`, and an actionability result type around the requested JSON fields: `step_id`, `decision`, object-shaped `evidence`, `submitted_at`, `submitted_by`, plus `source_path` and source-content hash.
2. Implement `inbox_dir(run_dir) -> Path` as `<run_dir>/inbox`.
3. Implement `scan_inbox(run_dir) -> list[InboxEntry]`: absence of `inbox/` returns `[]`; regular non-dot JSON files are read in deterministic path-name order; malformed JSON/schema/type/timestamp files are logged with stdlib `logging` and skipped.
4. Implement a non-mutating helper such as `actionable_inbox_entries(run_dir, entries=None) -> list[InboxEntry]` that loads the active run, plan, events, and `peek_current_step`, then returns only structurally valid `approve` entries whose `step_id` matches the current attested cursor. This helper is used by `status` and by `next` before consumption, so stale files are not overcounted and validation logic is not duplicated.
5. Document that consumed files move to `inbox/.consumed/<sha256>.json`; malformed, stale, and non-approve files remain in place for operator inspection.

### Step 2: Add a gate-level external attestation path (`artagents/core/task/gate.py`)
**Scope:** Medium
1. Add a public helper such as `gate_external_attestation(slug, *, step_id, submitted_by, evidence, submitted_at, inbox_source_hash, root=None) -> GateDecision` rather than consuming by direct append after `peek_current_step`.
2. Reuse the same active-run read, plan-hash check, event-chain verification, plan load, cursor derivation, and `_auto_traverse_to_leaf(..., append_fn=_gate_append, raise_on_exhausted=True)` flow used by `gate_command` at `artagents/core/task/gate.py:510`. This persists `nested_entered`, `iteration_started`, `for_each_expanded`, and `item_started` before the inbox attestation event.
3. Validate that the current leaf is an `AttestedStep`, `step_id` matches `STEP_PATH_SEP.join(current_path)`, and the inbox decision is `approve` before writing any event.
4. Record the attestation as external inbox identity, not as an actor shell identity: `attestor_kind="inbox"`, `attestor_id=submitted_by`, and metadata fields for `submitted_at`, `submitted_by`, and `inbox_source_hash`. This explicitly bypasses `ARTAGENTS_ACTOR`/self-ack validation because inbox files are the trusted external signal channel; explicit `ack` keeps the existing identity rules unchanged.
5. Preserve event compatibility for existing tests by keeping the existing `evidence` field as an ack-style list and storing the required object-shaped inbox payload under `inbox_evidence`. Add a small event-maker helper if that keeps this shape centralized.
6. Preserve inline produces checks and iteration/item handling by sharing the post-attestation `GateDecision` construction and check runner used by `_dispatch_attested`.

### Step 3: Consume inbox entries safely (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Implement `consume_inbox_entry(run_dir, entry) -> EventRecord` for entries already identified as actionable. It derives `project_root`, `projects_root`, and `run_id` from `<project>/runs/<run-id>`, calls `gate_external_attestation`, then moves the source file to `.consumed` only after the hash-chained event write succeeds.
2. Use a collision-safe consumed filename: default `<sha256>.json`, with a deterministic suffix if a file already exists for the same hash.
3. If the entry is stale, non-approve, or no longer current by the time consumption runs, log and leave it in place; lifecycle callers treat that as ignored rather than a crash.
4. Keep `retry` and `abort` out of Phase 8 consumption. They remain parse-valid decisions so producers can use the declared schema, but they are not completion signals and require future explicit semantics/tests before they mutate verifier or active-run state.

### Step 4: Wire lifecycle surfaces and hook-visible behavior (`artagents/core/task/lifecycle.py`, `artagents/core/task/__init__.py`, `artagents/core/task/hook.py` tests)
**Scope:** Medium
1. In `cmd_next`, after resolving the active run but before final cursor output, call `actionable_inbox_entries`; consume at most one actionable entry; reread events; recompute the cursor; then print the current next step. This means direct `artagents next` and callers that delegate to `cmd_next` see the same behavior.
2. Acknowledge the Stop-hook caller explicitly: `artagents/core/task/hook.py` invokes `cmd_next`, so a pending actionable inbox entry will be consumed during Stop-hook reinjection. Treat this as intended because Phase 8 says `next` validates inbox files, and add a focused regression test for it.
3. In `cmd_status`, call the read-only actionability helper and print `inbox:    X pending` without mutating `events.jsonl` or moving files.
4. Do not change `cmd_ack` in `artagents/core/task/lifecycle_ack.py`; the explicit verb remains separate from the implicit inbox channel.
5. Export inbox helpers from `artagents/core/task/__init__.py` only if tests or established package-level imports call for it.

### Step 5: Update generated operator docs (`artagents/core/task/lifecycle.py`)

### Step 6: Add focused tests and a golden-style external attestation regression (`tests/`)
**Scope:** Medium
1. `tests/test_inbox_scan.py`: create `run_dir/inbox`, write 3 valid JSON files and 1 malformed file, assert `scan_inbox` returns 3 entries and logs/skips the malformed file without raising.

The right root cause remains in the task gate/lifecycle layer: valid inbox approval must persist the same traversal events as `gate_command`, but stale/non-current inbox files must be rejected before any mutating `_auto_traverse_to_leaf` call can append traversal events. The revised plan therefore uses a two-stage flow: read-only current-leaf validation first, then mutating gate traversal and attestation only for entries already proven actionable.

Phase 8 remains approval-focused. The JSON format accepts `decision: approve | retry | abort`, but only `approve` is actionable in this phase because the design describes an external completion-signal protocol. `retry` and `abort` entries are structurally valid files, logged as non-actionable, not counted as pending, and not consumed.

### Step 1: Add inbox parsing and read-only actionability (`artagents/core/task/inbox.py`)
