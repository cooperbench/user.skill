        Approved plan:
        # Implementation Plan: Add `travel_guidance.kind = "ltx_anchor"` for native LTX keyframe anchoring

## Overview
Add a new travel guidance kind `ltx_anchor` that routes anchor images directly to LTX's keyframe-index conditioning (`VideoConditionByKeyframeIndex`) via the existing `image_refs_paths` / `frames_positions` / `image_refs_strengths` plumbing, **without** baking a pixel cross-fade guide video. This sits alongside — not replaces — `ltx_control` and `ltx_hybrid`. The default `kind` is NOT flipped.

Key behaviors:
- Anchors-only contract (no `videos`, no control mode).
- VPT is forced to `"KFI"`.
- Per-anchor strength exposed on the contract; the **contract parser** (not the orchestrator's per-segment remap) applies the global count-based default when the caller omits all per-anchor strengths:
  - **2 anchors** (FF+LF) → `strength=1.0` on both (Inplace semantics at LTX layer).
  - **3+ anchors** → `strength=1.0` on FF+LF, `strength=0.0` on middles (AddGuide semantics; documented community fix for middle-frame stutter).
- Guide builder does **not** run the pixel cross-fade for this kind.
- Orchestrator's `travel_guidance` PATH A must not attempt a composite guidance video build for `ltx_anchor` (it has no videos).
- `ltx_control` pixel-guide path is untouched.

Constraints that matter (revised after critique):
- **FLAG-001 gap in the data model:** `AnchorEntry.from_dict` at `source/core/params/travel_guidance.py:74-79` uses `d.get("strength", 1.0)`, so post-parse we cannot tell "omitted" from "explicitly 1.0." The fix moves the default-detection to `TravelGuidanceConfig.from_payload` (or a helper) that inspects the **raw payload dicts** — before `AnchorEntry.from_dict` discards the presence/absence signal.
- **FLAG-002 orchestrator PATH A trap:** `source/task_handlers/travel/orchestrator.py:1254-1333` unconditionally calls `create_composite_guidance_video` for any non-`none` `travel_guidance`; that function raises `ValueError("No valid structure video configs provided")` when passed an empty list (`source/media/structure/compositing.py:181-185`). The error is currently caught and logged as a warning, but for `ltx_anchor` we should skip the branch entirely.
- **FLAG-003 per-segment slicing reorders anchors:** `_build_segment_hybrid_guidance_config` remaps/filters anchors per stitched range, and a single global anchor can land in multiple segments (`tests/test_ltx_hybrid_travel.py:159-185`). Applying count-based defaults inside the remap helper would see a local 2-anchor slice of a global 4-anchor config and wrongly promote a middle anchor to `1.0`. The fix computes strengths **globally** in `from_payload`, sorted by `frame_position`, and the per-segment remap copies each anchor's pre-assigned strength verbatim.
- The payload contract (`image_refs_paths`, `frames_positions`, `image_refs_strengths`) is already serialized for `ltx_hybrid` in `segment_processor._build_hybrid_anchor_payload` and passed through by `wgp_params.py` — wiring exists; we reuse it.
- `clear_conditioning` in `Wan2GP/models/ltx2/ltx_core/tools.py` strips the keyframe tokens before VAE decode — no cleanup on our side.

Out of scope (per the brief — list as PR follow-ups, not tasks):
- Flipping the default kind to `ltx_anchor`.
- Upscaler-stage re-injection of anchors.
- Identity drift fixes (ID-LoRA / IP-adapter).
- Real-GPU empirical validation.
