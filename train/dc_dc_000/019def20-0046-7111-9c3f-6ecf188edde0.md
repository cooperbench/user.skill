        # Implementation Plan: Implement ArtAgents Thread / Variant / Iteration-Video Layer

## Overview
Ship the 10-day sprint in `docs/sprint-thread-layer.md` as a staged implementation: Week 1 creates the durable thread/run/variant metadata layer at the executor and orchestrator chokepoints, and Week 2 consumes that metadata to produce `builtin.iteration_video` outputs. The repo already has the two key chokepoints: `artagents/executors/runner.py` with `ExecutorRunRequest` and `run_executor()`, and `artagents/orchestrators/runner.py` with `OrchestratorRunRequest` and `run_orchestrator()`.

The simplest organizing principle is: first make persisted records trustworthy and cheap to test, then wrap the two runners, then add CLI and variant semantics, and only then build iteration-video on top.

## Phase 1: Foundation

### Step 1: Establish current CLI and registry surfaces
**Scope:** Small
1. Inspect `artagents/__main__.py`, executor/orchestrator CLI files, and registry conventions.
2. Run cheap baseline checks: `python3 -m artagents --help`, `doctor`, `executors list`, `orchestrators list`, and `elements list`.

### Step 2: Add thread state package
**Scope:** Large
1. Create `artagents/threads/{ids,schema,index}.py`.
2. Implement Crockford ULIDs, v1 schema constants/validators, repo-relative path enforcement, and `.artagents/threads.json` with `fcntl.flock`, timeout, atomic replace, fsync, and `.bak` rotation.
3. Add `xxhash>=3.4` if needed.

### Step 3: Prove state layer early
**Scope:** Medium
1. Add tests for schema round-trip, ULID format, lock timeout, atomic replacement, `.bak` recovery, path validation, and eight-writer concurrency.

## Phase 2: Runner Chokepoints

### Step 4: Build run record helpers
**Scope:** Large
1. Create `artagents/threads/{record,wrapper}.py`.
2. Implement `begin`/`finalize` around a normalized request.
3. Capture trimmed SD-008 fields, typed `parent_run_ids`, xxhash inputs digest, sha256 output hashes, brief sha, redacted CLI args, private-path sha-only metadata, and trimmed external model provenance.

### Step 5: Wrap executor and orchestrator runners
**Scope:** Large
1. Extend `ExecutorRunRequest` and `OrchestratorRunRequest` with thread/variant fields.
2. Wrap `run_executor()` and `run_orchestrator()`.
3. Preserve no-op gates: dry run, temp/unwritable output, `@none`, `ARTAGENTS_THREADS_OFF=1`, inherited child context, and `upload.youtube` zero-artifact behavior.

### Step 6: Wire run flags through CLI
**Scope:** Medium
1. Add `--thread`, `--variants`, and `--from` to executor and orchestrator run commands.
2. Keep parsing thin; centralize attribution/validation in `artagents/threads`.

## Phase 3: Attribution, Prefix, Lifecycle, CLI

### Step 7: Implement attribution and prefix contracts
**Scope:** Large
1. Add `attribute.py` and `prefix.py`.
2. Implement explicit thread, lineage inference, active open thread, reopen window, then new thread.
3. Implement stdout prefix order: `[thread]`, `[variants]`, `Notice:`, blank line, command output.
4. Honor trims: no `Warn:`, no `[thread-health]`, no `[hint]`.

### Step 8: Add thread commands and reaper
**Scope:** Large
1. Add `thread new/list/show/archive/reopen/backfill`.
2. Support `thread show @active --no-content`.
3. Implement lazy lifecycle enforcement and once-per-process in-flight reaper.
4. Backfill existing `runs/*` without moving files, clustered by hash graph.

## Phase 4: Variants and Provenance

### Step 9: Implement variant state
**Scope:** Large
1. Add `selections.py` and `groups.py`.
2. Implement append-only selections, last-write-wins reads, `groups.json`, `thread keep`, `thread group`, and unresolved `[variants]` nag.
3. Use `role: variant | other`, default `other`.

### Step 10: Patch only allowed producers
**Scope:** Medium
1. Patch `artagents/executors/generate_image/run.py` and `artagents/orchestrators/logo_ideas/run.py` for variant metadata.
2. Confirm no other executor `run.py` opts into variants.

### Step 11: Add brief snapshots and hype provenance
**Scope:** Large
1. Write `brief.copy.txt` and stamp `brief_content_sha256`.
2. Add `pipeline.provenance` to `hype.metadata.json` with v1 fields and denormalized thread label/agent version.

## Phase 5: Iteration Video

### Step 12: Add modality registry
**Scope:** Medium
1. Create `artagents/modalities/{image_grid,audio_waveform,generic_card}.py` and registry CLI.
2. Register exactly three renderers; dispatch by artifact `kind`; keep `generic_card` as loud fallback.

### Step 13: Create `iteration.prepare`
**Scope:** Large
1. Add a normal executor with new `STAGE.md`.
2. Walk typed provenance graph, compute data quality, emit `iteration.quality.json`, enforce max-iterations before uncached `builtin.understand`, cache summaries, estimate cost, and emit draft manifest.

### Step 14: Create `iteration.assemble`
**Scope:** Large
1. Consume prepare outputs only.
2. Resolve renderers, enforce quality floor before render, support `--force`, chaptered mode, label-only direction, automatic audio bed, fallback diagnostics, timeline, and final manifest.

### Step 15: Add `builtin.iteration_video`
**Scope:** Large
1. Wire `iteration.prepare -> iteration.assemble -> builtin.cut -> builtin.render`.
2. Add `iteration_video inspect <thread>` with no render/summarize dispatch.
