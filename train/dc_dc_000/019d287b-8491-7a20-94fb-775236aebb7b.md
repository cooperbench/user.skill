        # Implementation Plan: Multi-Select Feature Parity

## Overview

The video editor's `BulkClipPanel` (PropertiesPanel.tsx:21-148) currently exposes only **3 fields** (opacity, speed, mute) when multiple clips are selected. The single-clip `ClipPanel` (ClipPanel.tsx:56-309) exposes **5 tabs** with ~20 fields: Effects (entrance/exit/continuous + custom), Timing (start/speed/from/to), Position (x/y/w/h/opacity/reset), Audio (volume slider + mute toggle), and Text (content/fontSize/color).

Additionally, arrow-key track movement is disabled for multi-select (VideoEditorShell.tsx:50 guards `size === 1`), and the context menu (ClipAction.tsx:137-198) only offers mute/delete for batch selections (no split, no copy).

**Core constraint:** The existing `handleUpdateClips(clipIds, patch)` in useClipEditing.ts:89-105 already applies the same `Partial<ClipMeta>` to all clips — so the mutation path works. The main work is (1) building a tabbed bulk panel with mixed-value handling, (2) deciding which fields are semantically meaningful in bulk, and (3) extending keyboard/context menu operations.

## Phase 1: Foundation — Bulk Panel with Tabs

### Step 1: Extract `getSharedValue` and add `getSharedObjectValue` helper
**Scope:** Small
1. **Move** `getSharedValue` (PropertiesPanel.tsx:12-19) into a shared utility, e.g. `src/tools/video-editor/lib/bulk-utils.ts`.
2. **Add** `getSharedObjectValue<T>(values: T[], key)` that handles nested objects (entrance, exit, continuous, text) — returns `null` if the sub-object type fields differ across clips, or the shared value if all match.
3. **Export** both. Import back into PropertiesPanel.tsx.

### Step 2: Replace `BulkClipPanel` with a tabbed `BulkClipPanel` matching ClipPanel's tab structure
**Scope:** Large — this is the core of the feature
1. **Rewrite** `BulkClipPanel` (PropertiesPanel.tsx:21-148) to accept the full set of shared values computed in PropertiesPanel, and render the same tab structure as ClipPanel.
2. **Compute shared values** in PropertiesPanel for all ClipMeta fields: entrance type, exit type, continuous type, speed, from, to, x, y, width, height, opacity, volume, text content/fontSize/color. Use `getSharedValue` for scalars and `getSharedObjectValue` for nested objects.
3. **Determine visible tabs** based on the union of clip types in the selection:
   - If ALL clips are text → show text tab
   - If ANY clips are on audio tracks → show audio tab  
   - If ANY clips are on visual tracks → show position tab
   - Effects and Timing always shown
4. **Mixed-value UX**: Each input shows placeholder "Mixed" when `getSharedValue` returns null. Editing a field applies that value to ALL selected clips (existing `handleUpdateClips` behavior). Leave empty fields alone (only dispatch the changed field).
5. **Effects tab**: Entrance/Exit/Continuous selects. When mixed, show "Mixed" as a disabled sentinel. Selecting a value applies to all. Custom effect editor: show when all clips share the same custom effect.
6. **Timing tab**: Speed, Source In, Source Out. Start time is intentionally EXCLUDED from bulk (each clip has its own start; bulk-setting start would stack all clips). 
7. **Position tab**: X, Y, Width, Height, Opacity slider, Reset Position button (applies to all selected clips).
8. **Audio tab**: Volume slider, Toggle Mute button.
9. **Text tab**: Only visible when ALL selected clips are text. Font size, color (not content — mixed text content editing is confusing).
10. **Wire** the `onChange` callback to call `handleUpdateClips(selectedClipIdsList, patch)` — same as today, just with a wider patch surface.
11. **Add** `handleResetClipsPosition(clipIds)` to useClipEditing.ts, analogous to `handleResetClipPosition` but looping over clipIds.

### Step 3: Update PropertiesPanel to compute and pass all shared values
**Scope:** Medium
1. **Expand** the shared-value computation block (PropertiesPanel.tsx:188-191) to cover all ClipMeta fields needed by the new BulkClipPanel.
2. **Pass** `compositionWidth`, `compositionHeight`, and `handleResetClipsPosition` to BulkClipPanel.
3. **Pass** `activeTab` and `setActiveTab` to BulkClipPanel so tab state persists.
4. **Determine** `bulkVisibleTabs` based on the union logic from Step 2.3 and pass it down.

## Phase 2: Keyboard & Context Menu Multi-Select Operations

### Step 4: Enable arrow-key track movement for multi-select
**Scope:** Medium
1. **Add** `moveSelectedClipsToTrack(direction)` to useTimelineTrackManagement.ts that moves ALL selected clips in the same direction. Logic: group selected clips by current track, find each group's target track (same kind, one step in direction), move all clips in the group. Skip if any group can't move (same behavior as single: no-op if blocked).
2. **Update** VideoEditorShell.tsx:50 — change `canMoveSelectedClipToTrack` from `size === 1` to `size >= 1`.
3. **Wire** the new `moveSelectedClipsToTrack` through `useTimelineState` to `useKeyboardShortcuts`.

### Step 5: Expand context menu operations for multi-select
**Scope:** Medium
1. **Add "Split at Playhead" for batch**: In ClipAction.tsx context menu, when `hasBatchSelection`, add a "Split N clips at playhead" option that calls a new `onSplitClipsAtPlayhead(selectedClipIds)` handler.
2. **Add** `handleSplitSelectedClips()` to useClipEditing.ts — iterates over all selected clip IDs and splits each at the current playhead time (using existing `splitClipAtPlayhead` utility). Clips not intersecting the playhead are skipped.
3. **Add "Copy N clips"** context menu item (if copy/paste exists or is planned — see assumptions).
4. **Keep single-clip "Split Here"** (cursor-position split) as single-only — it doesn't make sense for batch since each clip has a different cursor-relative position.

### Step 6: Multi-drag visual feedback improvements
**Scope:** Small
1. **Audit** current multi-drag behavior in useClipDrag.ts. Based on research: multi-drag already preserves relative timing, shows count badge, and highlights all selected clips.
2. **If missing**: Add ghost outlines for all dragged clips (not just the anchor) during cross-track drag. Currently only the anchor gets a floating ghost (useClipDrag.ts:303).
3. **If already sufficient**: Skip — don't gold-plate working behavior.

## Phase 3: Validation

### Step 7: Manual testing checklist
**Scope:** Small
1. **Select 2+ clips of same type** → verify all tabs appear, all fields show shared or "Mixed" values, editing applies to all.
2. **Select mixed types** (video + audio, video + text) → verify only applicable tabs appear.
3. **Arrow up/down with multi-select** → verify all clips move together, blocked if any can't move.
4. **Right-click multi-select** → verify split-at-playhead, mute, delete all appear.
5. **Multi-drag** → verify count badge, relative timing preserved.
6. **Undo** after bulk edit → verify all clips revert.

### Step 8: TypeScript compilation check
**Scope:** Small  
1. **Run** `npx tsc --noEmit` to catch type errors from the expanded patch surface.
2. **Fix** any type mismatches between BulkClipPanel's `onChange` signature and `handleUpdateClips`.

        # Implementation Plan: Multi-Select Feature Parity

## Overview

The video editor's `BulkClipPanel` (PropertiesPanel.tsx:21-148) currently exposes only **3 fields** (opacity, speed, mute) when multiple clips are selected. The single-clip `ClipPanel` (ClipPanel.tsx:56-309) exposes **5 tabs** with ~20 fields: Effects (entrance/exit/continuous + custom), Timing (start/speed/from/to), Position (x/y/w/h/opacity/reset), Audio (volume slider + mute toggle), and Text (content/fontSize/color).

Additionally, arrow-key track movement is disabled for multi-select (VideoEditorShell.tsx:50 guards `size === 1`), and the context menu (ClipAction.tsx:137-198) only offers mute/delete for batch selections (no split).

**Scope boundary:** "Parity" means matching `ClipPanel`'s current feature set. Crop editing lives in `OverlayEditor.tsx`, not ClipPanel. Transition controls don't exist anywhere in the UI. Copy/paste has no existing infrastructure. All three are out of scope — they'd be new features, not parity gaps.

**Critical constraint — shallow merge:** `applyTimelineEdit` (useTimelineSave.ts:236-237) does `{ ...existingMeta, ...patch }` — a top-level spread. Nested objects (`entrance`, `exit`, `continuous`, `text`) would be **overwritten**, not merged. The single-clip `ClipPanel` works around this by always constructing complete nested objects per-clip (e.g., `{ entrance: { type: value, duration: clip.entrance?.duration ?? 0.4 } }`). The bulk panel must do the same: build **per-clip patches** that preserve each clip's existing nested fields. A single shared patch object is only safe for scalar fields (opacity, speed, volume, x, y, width, height).

   ```typescript
   const handleUpdateClipsDeep = useCallback((
     clipIds: string[],
     patchFn: (existing: ClipMeta) => Partial<ClipMeta>,
   ) => {
     const current = dataRef.current;
     if (!current) return;
     const validIds = getValidClipIds(clipIds);
     if (validIds.length === 0) return;
     const metaUpdates = Object.fromEntries(
       validIds.map((id) => [id, patchFn(current.meta[id] ?? { track: '' })])
     );
     applyTimelineEdit(current.rows, metaUpdates);
   }, [applyTimelineEdit, dataRef, getValidClipIds]);
   ```
