> AGENT

**Intent**
Build a local canonical domain layer under `src/tools/video-editor/domain` that makes persisted `TimelineConfig + AssetRegistry` the single source of truth. Existing `TimelineData`, rows/meta/clipOrder, and resolved configs stay projections built from the canonical persisted shape.

**Plan**
1. Add a small domain module with tests first:
   - `src/tools/video-editor/domain/types.ts`
   - `src/tools/video-editor/domain/duration.ts`
   - `src/tools/video-editor/domain/canonicalize.ts`
   - `src/tools/video-editor/domain/validate.ts`
   - `src/tools/video-editor/domain/serialize.ts`
   - `src/tools/video-editor/domain/index.ts`
   - `src/tools/video-editor/domain/README.md`

2. Define stable diagnostic primitives:
   - `code`, `severity: 'error' | 'warning'`, `path`, `message`, optional `suggestedRepair`.
   - Hard errors for impossible/unsafe states: invalid output/fps, missing required clip ids/tracks, non-finite times, non-positive resolved duration, invalid speed.
   - Warnings for repairable/compatible states: duplicate legacy ids, missing assets, unknown clip types, inferred tracks, missing optional `to` with asset-duration fallback, stale pinned group metadata.

3. Centralize duration semantics:
   - Add `getCanonicalClipSourceDuration(clip, registry, options?)`.
   - Add `getCanonicalClipTimelineDuration(clip, registry, options?)`.
   - Rule: `hold` wins; otherwise valid `from/to` wins; otherwise media clips may use `AssetRegistry.assets[asset].duration` as controlled fallback with a warning; otherwise duration is invalid or zero depending caller mode.
   - Keep `config-utils.ts` wrappers initially to preserve imports, but delegate where safe.

4. Wrap existing repair/migration without rewriting it:
   - Domain canonicalization should call existing `repairConfig`, `repairShotGroupContiguity`, and `migrateToFlatTracks`.
   - Return `{ config, registry, diagnostics, repaired }`.
   - Do not persist read-time repairs automatically.
   - Preserve unknown clip types and theme fields.

5. Move serialization validation behind the domain boundary:
   - Keep current `serializeForDisk` behavior, but expose canonical `serializeCanonicalTimeline(...)`.
   - Keep `validateSerializedConfig` compatibility, then route it to the domain validator or have it use the same allowlists.
   - Avoid changing persisted output unless explicit save/import/agent write occurs.

6. Route low-risk UI paths through the domain:
   - `buildTimelineData` becomes the main UI read canonicalization point.
   - `buildDataFromCurrentRegistry` and `buildDataFromSnapshot` use the same canonical migration/repair helper instead of open-coding `repairConfig + migrateToFlatTracks`.
   - `configToRows`, `rowsToConfig`, and `useDerivedTimeline` duration calculations should use canonical duration helpers or wrappers.

7. Route renderer duration hotspots:
   - Replace manual sequence duration calculations in `TimelineRenderer.tsx` generated/theme placeholder paths with the shared duration helper.
   - Keep Remotion behavior stable by clamping frame durations exactly as current code does.

8. Route ai-timeline-agent safely:
   - Replace local duration helpers in `supabase/functions/ai-timeline-agent/tools/timeline.ts` with canonical duration helpers.
   - Update `selectedClips.ts` placement duration to use canonical duration with registry fallback.
   - In `loadTimelineState`, canonicalize loaded config in memory and attach/log warnings, but only save canonical output when an agent tool actually writes.
   - Do not change LLM-visible result strings except where a current inconsistency is intentionally fixed and tested.

9. Route timeline import minimally:
   - Keep existing Zod schema validation.
   - Add canonical validation/canonicalization after payload envelope validation.
   - Reject only hard errors; allow warnings.
   - Persist canonicalized config on import because import is an explicit write.

10. Document non-canonical leftovers:
   - Add a short notes file or README section listing remaining direct duration/shape call sites and why they were left.
   - Explicitly classify poll sync `configVersionRef` and pinned shot group backend CRUD as Sprint 2 unless the change is tiny and covered by existing tests.

**Cheap Validation First**
Before broad rewiring, add focused tests that currently expose the intended semantics:

- Domain duration tests:
  - `hold` duration.
  - `from/to` media duration.
  - missing `to` with asset duration fallback.
  - missing asset warning.
  - speed handling.
  - unknown clip type warning but accepted.

- Canonicalization tests:
  - duplicate track/clip repair returns warnings and canonical config.
  - legacy missing tracks migrates to flat tracks.
  - pinned shot group legacy fields repair without projecting geometry.

- Import-adjacent tests:
  - malformed payload still fails.
  - unknown clip type accepted with warning.
  - hard duration error rejected.
  - canonicalized explicit import is what would be written.

- Agent-adjacent tests:
  - `viewTimeline`, `queryTimeline`, split/trim boundary checks use the same duration as domain.
  - selected clip placement insertion time matches canonical duration.

**Observable Success Criteria**
- `src/tools/video-editor/domain` exists with documented public API and stable diagnostics.
- There is one shared duration implementation used by UI projection, renderer sequence duration hotspots, import validation, and agent timeline helpers, or remaining exceptions are documented.
- `buildTimelineData` and save/snapshot reconstruction use the same canonicalization boundary.
- Import rejects hard canonical errors and accepts warning-only compatible timelines.
- ai-timeline-agent no longer interprets missing `from/to` differently from the domain helper.
- Unknown clip types remain accepted and render through existing placeholder behavior.
- Current editor page and shell behavior are unchanged in normal timelines.
- Targeted tests plus relevant existing suites pass.
