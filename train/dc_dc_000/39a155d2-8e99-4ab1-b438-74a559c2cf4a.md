# Implementation Plan: Phase 1 Kernel — Frozen Plan Gate Above Dispatch + Task-Run Env Contract

## Overview

Phase 1 of the Orchestrator V1 plan adds a **kernel** under `artagents/core/task/` that gates every command dispatch against an immutable `plan.json` and a hash-chained `events.jsonl`, **and** plumbs the `ARTAGENTS_TASK_RUN_ID` env contract through the three `prepare_project_run` callers so that child orchestrator/executor/hype dispatches attach to the parent task run instead of creating sibling project runs. The kernel is **additive** — it activates only when an `active_run.json` pointer exists for the active project (or, for child processes, when `ARTAGENTS_TASK_RUN_ID` is inherited); otherwise the existing pipeline, orchestrator, executor, and hype paths run unchanged.

Repo dispatch surfaces (already present): `artagents/pipeline.py:15` (top-level CLI gateway), `artagents/core/orchestrator/runner.py:132` (`run_orchestrator`) with `_prepare_project_request` at line 397 calling `prepare_project_run` at 410, `artagents/core/executor/runner.py:88` (`run_executor`) with its own `_prepare_project_request` calling `prepare_project_run` at 333, `artagents/packs/builtin/hype/run.py:1447` (`main`) calling `prepare_project_run` at 1521, and `artagents/core/project/run.py:59` (`prepare_project_run`). Storage root resolves through `artagents/core/project/paths.py:20` → `~/Documents/reigh-workspace/artagents-projects/<slug>/`. There is no `artagents/core/task/` package yet.

Phase 1 explicitly **does not** add: new step kinds, the DSL, produces inline checks, repeat semantics, lifecycle verbs (`next`/`ack`/`start`), Stop-hook, or CAS. Those are Phases 2–7.

**Key design decisions:**
- Hash chain: `sha256(prev_hash + canonical_event_json)`, no HMAC (SD-004).
- Plan hash: `sha256` of the canonical-JSON re-serialized `plan.json`; `active_run.json` stores `{"run_id", "plan_hash"}` (SD-003).
- Gate fires **before** `_prepare_project_request()` and `thread_wrapper.begin_orchestrator_run()` so a rejected command writes zero project-run side effects (SD-012, A7).
- Single-host, honor-based, accidental-edit tripwire only (SD-025).
- The "incoming command" matched against the plan cursor in Phase 1 is the canonical argv of the dispatch (no new verbs); cursor advances when `step_completed` is appended (SD-013).
- **`ARTAGENTS_TASK_RUN_ID` env contract is fully wired in Phase 1** (SD-017, A9; doc Section 12 Phase 1 exit criterion: "all three `prepare_project_run()` callers honor `ARTAGENTS_TASK_RUN_ID`"). When the env var is set, `prepare_project_run` does **not** create a child `runs/<id>/run.json`; instead it returns a `ProjectRunContext` whose `run_root` points at `<projects_root>/<slug>/runs/<task-run-id>/steps/<plan-step-id>/` (SD-018). Standalone callers (env unset) keep generating fresh run dirs and `run.json`, preserving `tests/test_project_runs.py`.
- Hype artifact mirroring under `runs/<task-run-id>/steps/<step-id>/produces/` is included in Phase 1 because it is the SD-018 / A10 child-output preservation behavior tied to the env contract.

### Step 7: The gate (`artagents/core/task/gate.py`)

**Scope:** Medium
