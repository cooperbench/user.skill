        # Implementation Plan: First-Class Conductors

## Overview
ArtAgents already has a first-class `artagents/nodes/` package with schema, folder discovery, registry, CLI, runner, installation helpers, and tests. The hype pipeline orchestration still lives in `artagents/pipeline.py`, with `pipeline.py` as a root compatibility launcher. Event-talk orchestration similarly lives in `artagents/event_talks.py`, with `event_talks.py` as a root launcher.

The simplest durable fix is to add a parallel `artagents/conductors/` package that reuses the proven node patterns where they fit, but keeps conductors semantically separate: conductors coordinate nodes and declared child conductors; nodes remain executable units and must not call conductors. The hype and event-talk flows should become curated conductor folders, while existing `pipeline.py ...` and `event_talks.py ...` commands continue to work as wrappers.

## Phase 1: Define The Conductor Substrate

### Step 1: Add conductor schema and API helpers (`artagents/conductors/schema.py`, `artagents/conductors/api.py`, `artagents/conductors/__init__.py`)
**Scope:** Medium
1. Create `ConductorDefinition` and `ConductorSpec` analogous to `NodeDefinition` and `NodeSpec`, reusing `NodePort`, `NodeOutput`, `CachePolicy`, `CommandSpec`, and `IsolationMetadata` where practical instead of inventing duplicate port schemas.
2. Add conductor-specific graph metadata such as `child_nodes`, `child_conductors`, `provides`, and `consumes`.
3. Validate conductor IDs, kind values, command shape, outputs, and graph metadata.
4. Enforce the architectural distinction in data shape: conductors may declare node and conductor children; node schema remains conductor-blind.

### Step 2: Add folder discovery for conductors (`artagents/conductors/folder.py`)
**Scope:** Medium
1. Mirror node folder discovery but search for `conductor.py` instead of `node.py`.
2. Support `CONDUCTOR`, `CONDUCTORS`, lowercase `conductor`, and decorated callables, matching the node authoring ergonomics.
3. Attach folder metadata: `source`, `conductor_root`, `conductor_file`, `folder_id`, plus optional `requirements_file`, `pyproject_file`, and `SKILL.md` if present.
4. Keep extraction out-of-process like nodes so folder metadata imports cannot mutate the parent process.

### Step 3: Add registry validation (`artagents/conductors/registry.py`)
**Scope:** Medium
1. Implement `ConductorRegistry` with `register`, `get`, `list`, `validate_all`, `to_dict`, and `to_json` methods analogous to `NodeRegistry`.
2. Load curated conductor folders from `artagents/conductors/curated/`.
3. Validate `child_nodes` against `load_default_registry()` from `artagents.nodes.registry`.
4. Validate `child_conductors` against the conductor registry and reject self-references.
5. Add tests proving duplicate conductor IDs, missing node children, missing conductor children, and self-dependencies fail clearly.

## Phase 2: Runtime And CLI

### Step 4: Add conductor runner (`artagents/conductors/runner.py`)
**Scope:** Medium
1. Add `ConductorRunRequest` and `ConductorRunResult` with fields analogous to `NodeRunRequest`: `conductor_id`, `out`, `inputs`, `brief`, `dry_run`, `python_exec`, and `verbose`.
2. For command-backed conductors, expand placeholders using the same runtime contract as node runner where possible.
3. For Python-backed curated conductors, call the declared module/function directly only when the folder definition marks it as built-in or in-process; otherwise use subprocess commands.
4. Return dry-run commands without executing subprocesses.
5. Keep node execution delegated through `artagents.nodes.runner.run_node` only from conductor code, never the other direction.

### Step 5: Add conductor CLI (`artagents/conductors/cli.py`, `artagents/pipeline.py`)
**Scope:** Medium
1. Implement `pipeline.py conductors list`, `inspect`, `validate`, and `run` with output shape matching `pipeline.py nodes ...` where practical.
2. Dispatch `pipeline.main(["conductors", ...])` before legacy argument validation, exactly like the existing `nodes` dispatch.
3. Include `--json`, `--kind`, `--check-binaries` if command-backed conductors declare binaries, `--input NAME=VALUE`, `--brief`, `--out`, `--dry-run`, and `--verbose`.
4. Add CLI tests paralleling `tests/test_nodes_cli.py`.

## Phase 3: Migrate Existing Orchestrators Into Conductor Folders

### Step 6: Create the hype conductor folder (`artagents/conductors/curated/hype/conductor.py`)
**Scope:** Large
1. Define a curated conductor, likely `built_in.hype`, whose declared `child_nodes` are the current built-in pipeline nodes from `STEP_ORDER`.
2. Move orchestration ownership from `artagents/pipeline.py` into a conductor-facing module without breaking imports. The low-risk split is:
   - keep reusable step primitives in `artagents/pipeline.py` initially,
   - add conductor folder metadata and a `run(argv)`/`main(argv)` bridge that calls the existing `resolve_args` and `pool_main`,
   - then, if the diff stays controlled, move orchestration functions into `artagents/conductors/curated/hype/runtime.py` and leave `artagents/pipeline.py` as a compatibility facade.
3. Preserve the legacy root wrapper `pipeline.py` and the existing `python3 pipeline.py --video ...` behavior.
4. Preserve `pipeline.py nodes ...`; add `pipeline.py conductors ...` without changing node behavior.
5. Update `tests/test_pipeline_caching.py` so legacy invocation still uses the ordered hype flow and does not accidentally route through the nodes CLI.

### Step 7: Create the event-talks conductor folder (`artagents/conductors/curated/event_talks/conductor.py`)
**Scope:** Large
1. Define a curated conductor, likely `built_in.event_talks`, with child conductors or internal actions for `ados-sunday-template`, `search-transcript`, `find-holding-screens`, and `render`.
2. Keep `event_talks.py` root launcher compatible.
3. Move practical orchestration metadata and any reusable runtime bridge into the folder while avoiding a risky full rewrite of the rendering internals.
4. Declare relevant child node usage where obvious, such as render/timeline generation dependencies, but do not force every helper function into a node if that would only add indirection.
5. Add focused tests for template writing, transcript search dispatch, render dry-run dispatch, and conductor registry visibility.

## Phase 4: Architectural Guardrails And Documentation

### Step 8: Add invariants/tests for node-conductor separation (`tests/test_conductors_schema.py`, `tests/test_conductors_registry.py`, `tests/test_conductors_runner.py`)
**Scope:** Medium
1. Test that conductors can declare child nodes and child conductors.
2. Test that nodes do not accept or expose conductor references.
3. Add a cheap static test that files under `artagents/nodes/` do not import `artagents.conductors`.
4. Test `pipeline.py conductors validate` catches missing child node/conductor references.
5. Test `pipeline.py conductors run built_in.hype --dry-run ...` returns the expected legacy command or planned execution without running expensive media steps.

### Step 9: Update user-facing docs (`README.md`)
**Scope:** Small
1. Add a `Conductors` section next to `Nodes` explaining the distinction: nodes execute one unit; conductors orchestrate nodes and may call declared child conductors.
2. Document example commands:

   ```bash
   python3 pipeline.py conductors inspect built_in.hype --json
   python3 pipeline.py conductors validate
   python3 pipeline.py conductors run built_in.hype --out runs/example --brief brief.txt --dry-run
   ```
3. Keep existing `pipeline.py nodes ...`, `pipeline.py ...`, and `event_talks.py ...` examples intact.

2. Add registry validation before runtime execution, so bad graph contracts fail cheaply.

4. Register hype as the first curated conductor, preserving legacy `pipeline.py` behavior at every step.
5. Register event-talks second, because it has multiple subcommands and heavier renderer side effects.
6. Add architectural guardrail tests and docs once behavior is wired.
