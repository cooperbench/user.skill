how does from-doc mode work?

> AGENT

`--from-doc` is a flag on `megaplan init` that imports settled design decisions from a previously-executed doc-mode plan into a new plan, so the new plan inherits load-bearing constraints as success criteria. **Flow:** 1. **CLI** (`megaplan/cli.py:914`) — `--from-doc <relative-path>` accepts a path to any prior doc artifact (works with `--mode code`, `doc`, `joke`, or `creative`). 2. **Init handler** (`megaplan/handlers/init.py:85-96`) validates the path, reads the file, and calls `extract_settled_decisions(...)`. 3. **Extraction** (`megaplan/doc_assembly.py:43`) scans for a top-level `## Settled Decisions` section and parses entries in either: - **Bold-dash inline** (preferred): `- **SD-001** — summary. _load_bearing: true_` - **YAML-ish**: `- id: SD-001` / `decision:` / `rationale:` / `load_bearing:` Malformed entries become warnings (saved as meta notes) but never raise. 4. **State** (`init.py:160-162`) stores `config.from_doc` (the relative path) and `meta.imported_decisions` (parsed list). 5. **Strict-notes auto-on**: doc mode flips `strict_notes=True` automatically (`init.py:112`). 6. **Plan prompt** (`prompts/planning.py:131-159`) injects a "Prior doc context" block listing each imported decision with its id, rationale, and load_bearing flag, and instructs the planner: load_bearing=true → success criterion with `priority: must`; load_bearing=false → `priority: info`. Each criterion must reference the SD-NNN id. 7. **Criterion merge** (`handlers/shared.py:55` `_merge_imported_decision_criteria`) is called from the plan and critique handlers — if the planner forgets to reference an imported SD-NNN id, this synthesizes a fallback success criterion (`"Plan adheres to imported decision SD-NNN: ..."`) so load-bearing decisions can't be silently dropped. If no `## Settled Decisions` section exists in the source doc, the path is stored for reference but no criteria are imported.

> DEVELOPER

Does it just run the normal process then?

> AGENT

Yes — `--from-doc` is just a seed flag, not a separate mode. After init, the plan runs the normal init → plan → critique → execute → review → finalize loop for whatever `--mode` you picked. The only differences are: - **Plan/critique phases** see the imported decisions in their prompt and are told to attach `must`/`info` success criteria referencing each SD-NNN id (`prompts/planning.py:131`, `handlers/critique.py:254`). - **Safety net**: if the planner doesn't reference an imported id, `_merge_imported_decision_criteria` synthesizes the criterion so load-bearing decisions can't be dropped (`handlers/shared.py:55`). - **Strict-notes** defaults on for `--mode doc` (unrelated to `--from-doc` itself). Execute, review, finalize behave identically to a plan that was authored with those criteria from scratch.
