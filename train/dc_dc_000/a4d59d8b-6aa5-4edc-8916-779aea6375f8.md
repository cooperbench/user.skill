Mostly, but two gaps:

**Definite gap — the `[db]` install extra.** `psycopg` is behind the `db` optional dependency (`pyproject.toml:27-30`). The base `pip install megaplan-harness` doesn't include it, so step 1 of the agent prompt will trip on `ImportError` the moment it constructs `DBStore()`. The instructions need a step 0: `pip install 'megaplan-harness[db]'` (or `'megaplan-harness[db,agent]'` if they're also using open models).

**Probable gotcha — Supabase connection string flavor.** Supabase's dashboard shows three URIs: **direct** (port 5432), **transaction-mode pooler** (port 6543), and **session-mode pooler**. `DBStore` opens one long-lived connection and relies on `set_actor` setting a session config var (`supabase/migrations/202605040000_megaplan_dbstore_foundation.sql:13`). Transaction-mode pooling shuffles statements across backends and can drop that state, so the safe pick is the **direct** URI (or session-mode pooler) — worth saying explicitly so they don't grab the default "Connection pooling" string Supabase often surfaces first.

Minor polish I'd also fold in:
- "Create the bucket first in the Storage tab (private is fine)" — current wording is a bit hand-wavy.
- Mention that `MEGAPLAN_ACTOR_ID` being set is enough to switch backends; no `--backend db` flag needed on every command.
