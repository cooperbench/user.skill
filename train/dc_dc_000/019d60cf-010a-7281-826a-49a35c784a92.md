        # Implementation Plan: Five New Primitives for ai-timeline-agent

## Overview

Add 5 new capabilities to the ai-timeline-agent edge function:

1. **split_clip** — Split a clip at a given time (as a `run` command: `split <clipId> <time>`)
2. **swap_clip_asset** — Replace a clip's asset with a new generation (as a `run` command: `swap <clipId> <generation_id> <url> [--type video]`)
3. **create_shot** — Group generations into a shot (as a top-level tool, needs supabase)
4. **undo** — Revert the last config change (as a top-level tool, needs DB + state)
5. **query** — Return detailed timeline statistics (as a `run` command: `query [filter]`)

**Architecture decisions:**
- `split_clip`, `swap_clip_asset`, and `query` are timeline operations → `run` subcommands (parsed by command-parser.ts, handled in tools/timeline.ts, routed via tools/registry.ts)
- `create_shot` needs supabase admin for the `insert_shot_at_position` RPC → top-level tool (schema in tool-schemas.ts, handler in loop.ts)
- `undo` needs to restore a previous config snapshot → top-level tool with snapshot tracking in loop.ts

**Key constraint:** `splitClipAtPlayhead` in editor-utils.ts uses `ResolvedTimelineConfig` (clips have `assetEntry` attached, tracks required). The agent works with plain `TimelineConfig`. We must port the split logic to work with `TimelineConfig` + `AssetRegistry` separately, matching the pattern of all other tools in tools/timeline.ts. The actual logic (hold vs source-trimmed splitting) is straightforward to adapt since `assetEntry` isn't used in the split math.

**Undo strategy:** There is no config history table — only a version counter on the `timelines` row. We'll implement undo by snapshotting the config in-memory before each mutation within the agent loop. This gives single-level undo within an agent session. The snapshot lives on `TimelineState` as `previousConfig?: TimelineConfig`. On undo, we save `previousConfig` as the new config via the versioned save RPC.
