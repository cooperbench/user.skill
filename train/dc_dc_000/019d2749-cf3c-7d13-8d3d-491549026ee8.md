## Overview

**Goal:** Add Hermes Agent as a third execution backend for the megaplan planning loop (alongside `claude` and `codex` CLI agents), with per-phase model configuration and a `--hermes` convenience flag.

**Repository shape:** The hermes-agent repo contains the full AIAgent framework (`run_agent.py`), CLI (`cli.py`), delegation infrastructure (`tools/delegate_tool.py`), provider resolution (`hermes_cli/runtime_provider.py`), and config system (`hermes_cli/config.py`). The `.megaplan/` directory holds phase JSON schemas and plan state, but the megaplan orchestration skill itself lives in Claude Code's custom commands (not in this repo). This means: changes to the orchestrator are skill-side (Claude Code config), while changes to the execution backend are repo-side.

**Critical constraint:** Hermes currently has **no structured output support** — the `_build_api_kwargs()` method (`run_agent.py:4034`) never sets `response_format`. This must be added before Hermes can reliably return phase-schema-compliant JSON.

**Phases in megaplan:** plan → critique → revise → gate → execute → review → finalize. Each has a JSON schema in `.megaplan/schemas/`. Planning phases (plan, critique, revise, gate, review, finalize) need only text reasoning. Execute phase needs terminal/file tools.

### Step 1: Add `response_format` parameter to AIAgent (`run_agent.py`)
**Scope:** Medium

3. **Add** a `set_response_format(schema: dict, name: str = "output")` convenience method that wraps the raw dict into the correct envelope.

**Scope:** Small
