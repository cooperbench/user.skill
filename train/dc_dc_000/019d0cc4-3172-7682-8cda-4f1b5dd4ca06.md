## Implementation Plan: Decouple force-rescan from cycle-completion detection

### Problem

`cycle_just_completed` (pipeline.py:159) is computed as `not plan.get("plan_start_scores")`. Force-rescan preserves `plan_start_scores` to keep `is_mid_cycle()` true (cluster protection), so `cycle_just_completed` is always `False` after force-rescan. This makes `should_defer = objective_backlog and not cycle_just_completed` perpetually `True`, evicting stale/under-target subjective reviews behind objective work indefinitely.

### Approach

Thread `force_rescan` as a parameter from `reconcile_plan_post_scan` → `reconcile_plan`, where it overrides `cycle_just_completed` to `True`. Then refresh the score values in `plan_start_scores` without touching workflow sentinels.

**Why this works**: `force_rescan=True` makes `cycle_just_completed=True` regardless of `plan_start_scores`, so `should_defer` (dimensions.py:290) becomes `False`, allowing stale/under-target injection.

**Why not pass force_rescan deeper**: The existing `cycle_just_completed` parameter on `sync_subjective_dimensions` already captures the right semantic ("treat this as a cycle boundary for stale injection"). ### Step 3: Refresh score values after force-rescan (without clearing sentinels)

**File**: `desloppify/app/commands/scan/plan_reconcile.py`

**Problem with reusing `_seed_plan_start_scores`**: It calls `clear_score_communicated_sentinel(plan)` and `clear_create_plan_sentinel(plan)` (lines 117-118). During force-rescan, `reconcile_plan()` runs first (line 321) and may inject `workflow::communicate-score`, which sets `previous_plan_start_scores` and rebaselines `plan_start_scores` via `_rebaseline_plan_start_scores` (workflow.py:500-511). A subsequent `_seed_plan_start_scores` call would clear the sentinels that `sync_communicate_score_needed` just set, breaking the score-delta display and potentially causing re-injection on the next scan.

**Solution**: Add a new targeted function `_refresh_plan_start_score_values` that ONLY updates the numeric score values in `plan_start_scores` without touching any sentinels or `scan_count_at_plan_start`:

```python
def _refresh_plan_start_score_values(
    plan: dict[str, object], state: state_mod.StateModel
) -> bool:
    """Update plan_start_scores values to current scan scores.

    Unlike ``_seed_plan_start_scores``, this does NOT clear workflow
    sentinels or update ``scan_count_at_plan_start`` — it only refreshes
    the baseline score numbers so the frozen display reflects post-rescan
    reality.
    """
    existing = plan.get("plan_start_scores")
    if not isinstance(existing, dict) or not existing:
        return False
    scores = state_mod.score_snapshot(state)
    if scores.strict is None:
        return False
    plan["plan_start_scores"] = {
        "strict": scores.strict,
        "overall": scores.overall,
        "objective": scores.objective,
        "verified": scores.verified,
    }
    return True
```

- Change line 335 from:
  ```python
  if not force_rescan and _sync_plan_start_scores_and_log(plan, runtime.state):
  ```
  to:
  ```python
  if force_rescan:
      if _refresh_plan_start_score_values(plan, runtime.state):
          append_log_entry(plan, "seed_start_scores", actor="system", detail={})
          dirty = True
  elif _sync_plan_start_scores_and_log(plan, runtime.state):
      dirty = True
  ```

This keeps `_seed_plan_start_scores` and `_sync_plan_start_scores_and_log` completely untouched. The force-rescan path uses a dedicated function that only updates score values — safe even if `sync_communicate_score_needed` already ran in `reconcile_plan` (the rebaseline wrote current scores to `plan_start_scores` too, so this is either a no-op or a harmless refresh; either way, `previous_plan_start_scores` and workflow sentinels are untouched).
