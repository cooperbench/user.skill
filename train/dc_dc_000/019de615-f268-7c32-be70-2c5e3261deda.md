> AGENT

Short version: **data parity is mostly there for ArtAgents -> Reigh import, but not perfectly symmetric. Feature/render parity is not complete.**

**Data Parity**
ArtAgents is deliberately aligned with the shared `@banodoco/timeline-schema` boundary. It imports the shared Python schema, validates timelines through it, and allows the same main clip fields Reigh persists: `clipType`, `params`, `pool_id`, `clip_order`, `source_uuid`, `generation`, tracks, `theme`, `theme_overrides`, `pinnedShotGroups`, and asset metadata like `generationId`, `variantId`, `thumbnailUrl`.

Key parity issue: Reigh’s local editor type/serializer allows `generation_defaults`, but the shared schema does not list it, and ArtAgents explicitly rejects unknown top-level timeline keys. So a Reigh-authored timeline containing `generation_defaults` would not round-trip through ArtAgents today.

There is also a mild contract mismatch around `theme`: Reigh’s default timelines intentionally omit `theme`, but the shared schema and ArtAgents validator require a non-empty theme slug. ArtAgents-authored timelines are fine because they emit `theme`, but Reigh defaults are not fully ArtAgents-compatible until a theme is set.

**Feature Parity**
Not full parity. Reigh’s live renderer has newer behavior ArtAgents’ local Remotion renderer does not fully match:

- Reigh supports open-ended `clipType` values and dispatches registered sequence/theme components.
- Reigh shows loud placeholders for unknown clip types.
- Reigh has generated Remotion module placeholders.
- Reigh materializes sequence configs before rendering.

ArtAgents’ local `remotion/src/Root.tsx` is much narrower: it handles basic `media`, `text`, and a few `effect-layer` `params.kind` cases. So ArtAgents can **author/import** richer timeline data than its local renderer can faithfully preview/render.

**Practical conclusion**
- **ArtAgents -> Reigh:** mostly safe if timelines use registered effect IDs and include `theme`.
- **Reigh -> ArtAgents:** not fully safe because Reigh may emit/hold fields ArtAgents rejects, especially `generation_defaults`, and may contain theme-less defaults.
- **Visual/render equivalence:** not guaranteed. Reigh is the more complete renderer for sequence/theme clip types.

Highest-value fix would be to make the shared schema the single truth again: either add `generation_defaults` to `@banodoco/timeline-schema` and ArtAgents’ allowlist, or remove it from Reigh’s persisted serializer. Then decide whether ArtAgents’ renderer should depend on the same timeline-composition registry Reigh uses, instead of maintaining its narrower local renderer.

> DEVELOPER

Think through what we'd need to do to make it extremely save at a high-level?

> AGENT

To make the Reigh-app <-> ArtAgents timeline boundary **extremely safe**, I’d treat it as a productized compatibility contract, not just “both sides happen to accept similar JSON.”

The high-level work is:

1. **Pick One Canonical Contract**
   Make `@banodoco/timeline-schema` the only source of truth for persisted timeline shape. Reigh, ArtAgents, import edge functions, renderers, and tests should all validate against the same package/version.

   Current drift to resolve:
   - Reigh has `generation_defaults`.
   - ArtAgents/shared schema do not.
   - Reigh can omit `theme`.
   - ArtAgents currently requires `theme`.

2. **Define Compatibility Levels**
   Separate three concepts explicitly:

   - **Shape parity:** JSON validates.
   - **Data round-trip parity:** JSON can move Reigh -> ArtAgents -> Reigh without losing fields.
   - **Render parity:** both systems produce equivalent visuals/audio.

   We probably want shape + round-trip parity as hard requirements. Render parity can be tiered, because ArtAgents may not need to preview every Reigh-native/generated module exactly.

3. **Add Versioned Migration**
   Add a `schema_version` or equivalent persisted version. Then every loader path should do:

   ```text
   unknown input -> migrate -> validate canonical schema -> operate
   ```

   This is what prevents old timelines, theme-less Reigh defaults, and future fields from breaking tools unpredictably.

4. **Make Unknown Fields a Deliberate Policy**
   Today ArtAgents is strict. That’s good for authoring, risky for interoperability.

   I’d split modes:
   - **Import/round-trip mode:** preserve unknown extension fields in namespaced bags.
   - **Authoring/publish mode:** reject unknown fields unless explicitly allowed.
   - **Render mode:** tolerate unsupported features with visible placeholders or clear diagnostics.

   A good pattern would be:

   ```json
   {
     "extensions": {
       "reigh": {},
       "artagents": {}
     }
   }
   ```

   instead of scattering future fields at top level.

5. **Unify Serializer Allow Lists**
   Reigh’s `serializeForDisk`, ArtAgents’ `_TIMELINE_TOP_ALLOWED`, `_CLIP_ALLOWED`, `_ASSET_ENTRY_ALLOWED`, and the Zod schema should be generated from the same field list. No hand-maintained parallel allowlists.

6. **Add Golden Round-Trip Fixtures**
   Create fixtures for:

   - minimal Reigh timeline
   - theme-less Reigh default timeline
   - ArtAgents source-cut timeline
   - ArtAgents generative/effect timeline
   - sequence/theme clip timeline
   - pinned shot groups
   - asset registry with local file, storage key, remote URL, generation metadata
   - unknown future extension field

   Then test:

   ```text
   Reigh serialize -> shared validate -> ArtAgents load/save -> shared validate -> Reigh load
   ArtAgents save -> shared validate -> Reigh import validate -> Reigh serialize -> ArtAgents load
   ```

7. **Separate Render Capability From Data Compatibility**
   ArtAgents should be allowed to carry Reigh-native timeline data even when its local renderer can’t render it exactly.

   For unsupported render features, use:
   - capability manifest
   - explicit warnings
   - placeholder render
   - no silent dropping

   Example capability output:

   ```json
   {
     "can_validate": true,
     "can_roundtrip": true,
     "can_render_exactly": false,
     "unsupported_clip_types": ["generated-remotion-module"]
   }
   ```

8. **Add Import Preflight**
   Before publishing to Reigh, ArtAgents should run a `reigh-compat check` that reports:

   - schema validity
   - asset registry validity
   - missing files/URLs
   - unsupported clip types
   - unknown theme
   - whether publish will be lossless
   - whether Reigh render should work

9. **Use Contract Tests Across Repos**
   Ideally both repos consume the same test fixture package. At minimum, ArtAgents should run a small test command against the sibling `reigh-app` schema/import validator, and Reigh should run against ArtAgents-produced fixtures.

10. **Make Publishing Idempotent and Auditable**
   The publish path is already pretty careful with asset uploads and versioned timeline import. To make it safer:

   - include schema version and producer metadata
   - include content hashes for timeline and asset registry
   - write import summary
   - never mutate fields during publish except asset URL/key rewriting
   - diff local vs server before overwrite

The core principle: **ArtAgents should be strict when authoring, tolerant when reading, and lossless when round-tripping. Reigh should validate shape, tolerate future compatible fields, and clearly mark unsupported render features.**

The first concrete fix I’d make is small but important: resolve `generation_defaults` and optional `theme` across Reigh, shared schema, and ArtAgents. That’s the current obvious contract drift.

> DEVELOPER

Which of that is just overzealous?

> AGENT

The overzealous parts are mostly the “platform hardening” bits. Good ideas eventually, but not required to make this boundary safe now.

**Probably Overzealous**
- `schema_version` / full migration framework: useful once the format is changing frequently, but right now the drift is small. A lighter `compat_version` or package version check is enough.
- Namespaced `extensions`: clean long term, but disruptive. Reigh already has real fields like `generation_defaults`; moving everything into extension bags would create churn.
- Shared fixture package across repos: nice, but you can get 80% of the value with a few copied golden fixtures and CI tests in each repo.
- Full render parity: not necessary. ArtAgents does not need to render every Reigh editor feature exactly if Reigh is the authoritative preview/render surface.
- Capability manifest JSON: probably too much ceremony for now. A simple preflight report is enough.
- Content hashes and full audit summaries on every publish: useful later. Publish already has versioned import and asset hashing; that is likely enough.

**Worth Keeping**
- One canonical schema. This is the important one.
- Fix the known drift: `generation_defaults` and optional/required `theme`.
- Golden round-trip tests. Small, high value.
- Serializer/allowlist alignment. Avoid hand-maintained drift.
- Read tolerant, write strict. ArtAgents should not reject harmless Reigh-authored fields when reading, but should still be strict before publishing.
- Publish/import preflight. Even a simple `validate + assets + unsupported clip types` check would help a lot.

**Pragmatic Minimum**
I’d reduce the plan to four things:

1. Update `@banodoco/timeline-schema` so it exactly matches what Reigh persists.
2. Regenerate/update ArtAgents types and allowlists from that schema.
3. Add 4-6 round-trip fixtures covering Reigh default, ArtAgents source cut, generative/effect clips, assets, and pinned groups.
4. Add a preflight command that says: valid, publishable, renderable-in-ArtAgents, renderable-in-Reigh.

That’s enough to make it meaningfully safe without turning this into a schema governance project.
