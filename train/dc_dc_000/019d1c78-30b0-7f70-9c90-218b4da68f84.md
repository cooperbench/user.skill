        # Implementation Plan: Harden Review & Execution Checklist Enforcement

## Overview
Megaplan already tracks coverage deviations (incomplete task updates, incomplete review verdicts) and logs them as issues/warnings — but never **blocks** on them, never **rejects empty-string verdicts**, and never **renders gaps visibly** in `final.md`. The idea is to close these holes without adding friction to the happy path.

Current state:
- `_validate_merge_inputs` (`handlers.py:183`) validates structure/types/enums but allows empty strings in free-text fields like `reviewer_verdict`, `executor_notes`, and sense-check `verdict`.
- Execute (`handlers.py:1091-1093`) and review (`handlers.py:1178-1193`) count coverage gaps and add deviations/issues but always transition state regardless.
- `render_final_md` (`_core.py:92-134`) silently omits empty verdicts/notes (they're falsy strings, so the `if verdict:` / `if executor_notes:` checks skip them).
- The execute prompt (`prompts.py:352-397`) includes `finalize.json` but doesn't call out sense checks or watch items as things the executor should actively verify.

## Step 1: Reject empty-string verdicts in `_validate_merge_inputs` (`megaplan/handlers.py:183`)
**Scope:** Small
1. **Add** an optional `nonempty_fields` parameter to `_validate_merge_inputs` — a set of field names that must be non-empty after `.strip()`.
2. **Apply** at the three call sites:
   - Execute merge (`handlers.py:1073`): `nonempty_fields={"executor_notes"}` — reject updates where the executor left notes blank.
   - Review task verdicts (`handlers.py:1156`): `nonempty_fields={"reviewer_verdict"}`.
   - Review sense-check verdicts (`handlers.py:1162`): `nonempty_fields={"verdict"}`.
3. **Behavior:** entries with empty values get filtered out (same as malformed entries) and a deviation is appended: `"Skipped {label}[{index}]: '{field}' must not be empty."` This means they won't count toward coverage — so the existing coverage checks downstream will naturally flag incomplete tracking.

## Step 2: Block state transition on incomplete coverage (`megaplan/handlers.py`)
**Scope:** Medium
1. **Execute handler** (`handlers.py:1099`): Before setting `state["current_state"] = STATE_EXECUTED`, check `untracked_tasks > 0`. If so, **do not transition** — keep state as `STATE_FINALIZED`, set `response["success"] = False`, and surface a clear error: `"Blocked: {untracked_tasks}/{total_tasks} tasks have no executor update. Re-run execute to complete tracking."` Still write `execution.json` and updated `finalize.json` so partial progress is saved.
2. **Review handler** (`handlers.py:1199`): Before setting `state["current_state"] = STATE_DONE`, check both `verdict_count < total_tasks` and `check_count < total_checks`. If either is incomplete, keep state as `STATE_EXECUTED`, set `response["success"] = False`, and surface: `"Blocked: incomplete review coverage ({verdict_count}/{total_tasks} task verdicts, {check_count}/{total_checks} sense checks). Re-run review to complete."` Still write `review.json` and updated `finalize.json`.
3. **Re-run semantics:** Because state doesn't advance, the same step can be re-invoked. The merge logic already handles idempotent overwrites (keyed by task_id/sense_check_id), so re-running with complete output will succeed and transition.

## Step 3: Render gaps visibly in `final.md` (`megaplan/_core.py:92`)

2. **Sense Checks section** (`_core.py:123-125`): When `verdict` is empty/missing, render `  Verdict: ⚠ PENDING` instead of omitting.

If any > 0, render a `## Coverage Gaps` section with counts. If all covered, omit the section entirely (no noise on the happy path).

### 2a: Fix duplicate-entry counting (`handlers.py:1080-1093`, `handlers.py:1168-1193`)
