# Implementation Plan: User Actions in Finalize Phase

## Overview

Add a top-level `user_actions` array to the finalize artifact for human-only setup/operational steps (env vars, secrets, migrations, manual UI smoke tests, deploys, approvals). The boundary is enforced through five mutually reinforcing layers: (1) schema, (2) prompt inclusion criteria + mode gating, (3) coverage validation rename so user_actions count toward plan-step coverage, (4) synthetic gate tasks injected at head/tail of `tasks` (mirrors `_ensure_verification_task`), and (5) per-task PREREQUISITE block injected into the executor prompt for tasks named in `blocks_task_ids`. Artifacts: `final.md` gets a User Actions section, and a separate `user_actions.md` is always written (data-parity stub when empty).
