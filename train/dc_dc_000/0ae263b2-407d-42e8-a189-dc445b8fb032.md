## Windows subprocess compatibility issue (Issue 383)

**Location:** `/Users/user_c042661f/Documents/desloppify/desloppify/app/commands/runner/codex_batch.py`, line 30

**The Problem:**

```python
codex = shutil.which("codex") or "codex"
return [
    codex,
    "exec",
    ...
]
```

And then the command list is passed to `subprocess.Popen()` (in `/Users/user_c042661f/Documents/desloppify/desloppify/app/commands/review/runner_process_impl/attempts.py`, line 107-113) **without `shell=True`**.

**Windows Issue:**
- On Windows, `shutil.which("codex")` searches for executables with platform-specific extensions (`.exe`, `.bat`, `.cmd`)
- If the "codex" command is not in PATH or not an executable (e.g., it's a wrapper script), `shutil.which()` returns `None`
- The code then falls back to `"codex"` as a string
- When `subprocess.Popen()` is called with a list and no `shell=True`, Windows cannot find or execute a bare command name like `"codex"` - it needs the full path or must use `shell=True` to let the Windows command interpreter resolve it
- This causes **WinError 2 (file not found)** 

**Related calls:**
- Line 30 in `codex_batch.py`: `codex = shutil.which("codex") or "codex"` 
- Line 107-113 in `attempts.py`: `deps.subprocess_popen(cmd, ...)` — passes list without `shell=True`
- Line 260 in `attempts.py`: `deps.subprocess_run(cmd, ...)` — also without `shell=True`
- Line 170-174 in `codex_batch.py`: `deps.subprocess_run(scan_cmd, ...)` — also without `shell=True`

**Solution options:**
1. Add `shell=True` to all subprocess calls
2. Resolve the executable path more robustly (handle Windows batch/cmd wrappers)
3. Use `shutil.which()` with extended search for Windows equivalents
4. Check if command exists before falling back to bare command name

The core issue is that **`shell=True` is needed on Windows** for the subprocess calls to work properly when the executable is in PATH, especially if it's not a direct binary but a wrapper script.

## Root Cause Analysis

The issue is that:

1. **codex binary resolution fails on Windows** - `shutil.which("codex")` may return `None` if `codex.cmd` or `codex.bat` is not properly registered in PATH
2. **Fallback to bare string** - Code falls back to `"codex"` (line 30)
3. **Subprocess without shell=True** - When Popen/run is called with a bare `"codex"` string on Windows, Python's subprocess module fails with WinError 2 because:
   - On Windows, the first element of argv is not automatically searched in PATH like on Unix
   - Without `shell=True`, Windows cmd.exe won't expand `.cmd`/`.bat` wrappers
   - Python subprocess requires either the full path OR `shell=True` on Windows
