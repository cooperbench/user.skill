        # Implementation Plan: Workflow Runtime Contract v1

## Overview
Add a VibeComfy-only runtime contract path that builds a read-only `version: 1` JSON payload from a built `VibeWorkflow` plus existing metadata. The repo already has the right raw material: `VibeWorkflow` carries `source`, `requirements`, `inputs`, `outputs`, and `metadata` in `vibecomfy/workflow.py`; ready-template policy merges `READY_METADATA` and `READY_REQUIREMENTS` in `vibecomfy/registry/ready_template.py`; CLI commands are explicit modules in `vibecomfy/commands/`; existing SageAttention/runtime checks live partly in `vibecomfy/porting/workbench.py` and `tests/test_ready_templates.py`.

The first slice should not mutate environments, install packages, alter Reigh/Astrid behavior, or freeze a cross-repo format. It should expose a local, stable-enough v1 inspection and doctor surface for downstream consumers to read.

## Main Phase

### Step 1: Add the contract model and builder (`vibecomfy/contracts/model.py`)
**Scope:** Medium
1. Create a new `vibecomfy/contracts/` package rather than adding more surface to `vibecomfy/workflow.py`; this keeps the IR focused and makes the contract layer explicitly derived.
2. Define dataclasses or typed builders for a JSON-serializable payload with this minimum shape:
   ```json
   {
     "version": 1,
     "workflow_id": "image/z_image",
     "source": {"id": "...", "path": "...", "source_type": "..."},
     "source_policy": {...},
     "model_assets": [...],
     "custom_nodes": [...],
     "runtime_packages": [...],
     "comfy_configuration": {...},
     "inputs": [...],
     "outputs": [...],
     "runtime_nodes": [...],
     "readiness_level": "..."
   }
   ```
3. Implement `build_contract(workflow: VibeWorkflow) -> WorkflowRuntimeContract` from existing fields only: `workflow.source`, `workflow.metadata`, `workflow.requirements`, `workflow.inputs`, `workflow.outputs`, `workflow.runtime_class_types()`, and `workflow.compile("api")` for the runtime node inventory.
4. Normalize data without inventing parallel declarations: sort custom nodes, sort inputs by name, preserve authored `model_assets` and `runtime_packages` as lists of dicts, and include only JSON-safe values.
5. Keep `readiness_level` simple and derived, for example `ready_template` when `metadata["ready_template"]` exists, `workflow` otherwise, with validation/doctor status left to the doctor command.

### Step 2: Add contract diagnostics (`vibecomfy/contracts/doctor.py`)
**Scope:** Medium
1. Add a small diagnostic model with `code`, `severity`, `message`, `node_id`, `class_type`, `detail`, and `recommendation`, matching the useful shape already used by porting diagnostics.
2. Implement `doctor_contract(workflow: VibeWorkflow, contract: WorkflowRuntimeContract) -> ContractDoctorReport`.
3. Cover the first known runtime-package gap rules:
   - `PathchSageAttentionKJ` with `sage_attention` other than `None` or `disabled` requires a declared `runtime_packages` entry named `sageattention`.
   - `LTX2MemoryEfficientSageAttentionPatch` requires declared `sageattention`.
   - `LTX2SamplingPreviewOverride` is headless-incompatible and should be an error unless a future explicit contract escape hatch is added.
4. Validate declared runtime packages enough for this slice: each dict entry should have `name`; entries that affect runtime should have at least one install/source/probe hint (`source`, `install`, `install_command`, `verify`, or `probe`, exact accepted keys decided in code and tests).
5. Avoid package installation, node-pack installation, environment probing, and any `--apply` behavior.

### Step 3: Wire the CLI (`vibecomfy/commands/contract.py`, `vibecomfy/commands/__init__.py`)
**Scope:** Small
1. Add `vibecomfy/commands/contract.py` with `register(subparsers)` and nested subcommands:
   - `contract inspect <workflow> [--json]`
   - `contract doctor <workflow> [--json]`
2. Load workflows with `load_workflow_any`, build the contract, and emit via `vibecomfy.commands._output.emit` like `inspect.py` and `doctor.py`.
3. Make `contract inspect --json` print the normalized v1 payload.
4. Make `contract doctor --json` print `{ "status": "ok"|"error", "contract": ..., "diagnostics": [...] }` and return nonzero only for error diagnostics.
5. Add `CommandSpec("contract", "vibecomfy.commands.contract")` after `convert` and before `validate` or `doctor`; update the explicit command-order test accordingly.

### Step 4: Add focused tests (`tests/test_contract.py`, `tests/test_cli.py`)
**Scope:** Medium
1. Add unit tests for `build_contract(workflow_from_ready("image/z_image"))` asserting `version == 1`, workflow id, model assets, custom nodes, inputs, outputs, and JSON serialization.
2. Add CLI tests for `contract inspect image/z_image --json` using direct command helper invocation or parser-level invocation consistent with existing CLI tests.
3. Add contract doctor tests with small synthetic workflows:
   - `PathchSageAttentionKJ` in `auto` mode without `runtime_packages` returns an error mentioning `sageattention`.
   - The same workflow with a complete `runtime_packages` declaration returns ok.
   - A declared runtime package missing source/install/probe hints returns a declaration diagnostic.
   - `image/z_image` or another non-LTX template returns ok.
4. Keep tests deterministic: no ComfyUI runtime, no network, no package installation, no model downloads.

### Step 5: Replace duplicated ready-template runtime checks with the contract path (`tests/test_ready_templates.py`)
**Scope:** Small
1. Update `test_ready_templates_do_not_enable_uncontracted_sageattention` to call `doctor_contract` or the contract doctor helper instead of manually scanning compiled API.
2. Consider folding the existing `LTX2MemoryEfficientSageAttentionPatch` and `LTX2SamplingPreviewOverride` ready-template tests into the same contract-doctor loop, preserving clear failure messages with `(template_id, diagnostic.code, node_id)`.
3. Do not broaden all ready templates into strict porting mode; this remains a lightweight contract check.

### Step 6: Optional export polish (`vibecomfy/contracts/__init__.py`)
**Scope:** Small
1. Export `WorkflowRuntimeContract`, `build_contract`, and `doctor_contract` from `vibecomfy/contracts/__init__.py`.
2. Do not add top-level `vibecomfy.__init__` exports unless tests or intended API usage need it; keeping this under `vibecomfy.contracts` is a cleaner first slice.

## Execution Order
1. Build `vibecomfy/contracts/model.py` first and prove JSON shape with one unit test.
2. Add `contracts/doctor.py` against synthetic workflows before wiring the CLI.
3. Wire `contract inspect` and `contract doctor` after the model/report APIs are stable.
4. Update ready-template tests last so failures point at the new contract diagnostics rather than bespoke scans.
