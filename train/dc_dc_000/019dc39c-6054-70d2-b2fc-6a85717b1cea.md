# Implementation Plan: Port useful old VibeComfy capabilities into the new package

## Overview
The new `vibecomfy` package is centered on `VibeWorkflow` as the only editable IR; JSON is input/output only and embedded Comfy is the default runtime. This plan ships two tracks together:

1. **Structural cleanup** so the port has a clean home: split monolithic `vibecomfy/cli.py` into `vibecomfy/commands/`, dedupe the three RunPod scripts behind `scripts/runpod_runner.py`, fix wrong `sources sync` defaults that point at non-existent `vendor/workflow_templates`, kill dead/empty paths (`input/`, `docs/comfyscript_spike/`), split `vibecomfy/templates/` (five modules: loader/normalize/index/library/**ready**) into `vibecomfy/ingest/` (loader + normalize + index) and `vibecomfy/registry/` (library + **ready**), fix the latent template-id resolver bug (`workflow_from_template` ignores the external index whenever the official one exists), and add module homes `vibecomfy/schema/`, `vibecomfy/analysis/`, `vibecomfy/search/`.
2. **Port-early features**: schema-aware validation backed by `/object_info` (reusing the existing `ValidationIssue`/`ValidationReport` types), graph analysis (`analyze`/`trace`/`upstream`/`downstream`/`path`/`subgraph`/`values`/`diff`/`unconnected`) on `VibeWorkflow`, and node search with weighted scoring + task aliases (`i2v`/`t2v`/`t2i`/`controlnet`/`wan`/`ltx`/`audio_reactive`/`flux`/`sdxl`/`qwen`/`hunyuan`/`inpaint`/`outpaint`).

Port-after-redesign work (editing primitives, SVG/visualization, MCP adapter) is **out of scope** — follow-up plan.

**Scope:** Small-Medium

**Scope:** Medium
