# Implementation Plan: MP-4 — Custom-Node Lifecycle and Lockfile Enforcement

## Overview

Land the four lifecycle/integrity gates from `docs/python_composition_dsl_review.md` §6–§7 and `docs/python_composition_dsl_plan.md` SD-006 / "Custom Nodes — Adding On the Fly" / "Custom Nodes — Pinning, Hashes, and Lockfiles":

2. an explicit `reload_for_nodepack_change()` verb on both `EmbeddedSession` and `ServerSession`,

4. a structured `custom_nodes.lock` schema (`git_commit_sha` required; `semantic_label`, `source_sha256` optional) with a backward-compat reader for today's three-token lines,

   - Always refuse on in-flight: `if self._inflight_run and not self._inflight_run.done(): raise RuntimeError(f"reload_for_nodepack_change refused: run in flight (reason={reason!r})")`.
   - Call `await self.stop(wait_for_inflight=False)` (we already proved no run is in flight).
   - Call `await self.start()` to reopen the context (mirrors lines 103–109).
   - Clear `_schema_provider` and `_schema_warning_emitted` so `NODE_CLASS_MAPPINGS` is re-read from the fresh `Comfy()` context on the next `run()`.

### Step 4: Lockfile schema, reader, writer (`vibecomfy/node_locks.py`)
**Scope:** Medium
1. **Create** `vibecomfy/node_locks.py` with:
   ```python
   @dataclass(frozen=True, slots=True)
   class NodepackLock:
       name: str
       repo_url: str
       git_commit_sha: str
       semantic_label: str | None = None
       source_sha256: dict[str, str] = field(default_factory=dict)  # class_name -> hex
   ```
2. **Format pick:** keep `custom_nodes.lock` as a text file but switch to **YAML** for new writes — already a project pattern (`vibecomfy/registry/models.yaml`, see `models_loader.py`). YAML carries optional fields and per-class hashes cleanly. The reader **auto-detects** legacy three-token lines vs YAML by sniffing the first non-blank line: if it parses as `name sha url`, read all lines as legacy; otherwise parse as YAML.
3. **Reader** `load_locks(path: Path = Path("custom_nodes.lock")) -> list[NodepackLock]`:
   - Sniff format. Legacy lines map to `NodepackLock(name=..., repo_url=..., git_commit_sha=..., semantic_label=None, source_sha256={})`.
   - YAML form: top-level mapping `nodepacks: [{name, repo_url, git_commit_sha, semantic_label?, source_sha256?}, ...]`.
   - **Backward-compat field rename:** when reading YAML, accept either `git_commit_sha` or legacy `git_sha` for the same field; prefer `git_commit_sha`. Emit a one-shot deprecation warning when `git_sha` is used. (This satisfies the brief's "preserve `git_sha` → `git_commit_sha` rename with backward-compat read.")
4. **Writer** `write_locks(locks: list[NodepackLock], path: Path = Path("custom_nodes.lock")) -> None`:
   - Always emit YAML in canonical key order (`name`, `repo_url`, `git_commit_sha`, then optional `semantic_label`, then optional `source_sha256` with sorted class names). Stable enough for round-trip equality tests.
5. **Resolver** `resolve_pack(repo_dir: Path) -> NodepackLock`:
   - `git_commit_sha`: `git -C <dir> rev-parse HEAD`.
   - `repo_url`: `git -C <dir> config --get remote.origin.url`.
   - `semantic_label`: best-effort — `git describe --tags --exact-match` else `git rev-parse --abbrev-ref HEAD`. Skip if both fail.
   - `source_sha256`: only when explicitly requested (`--hash-classes class1,class2`). Compute SHA-256 over the bytes of the file declaring each class (look up via `nodepack_dir/__init__.py` or scan `*.py`). Out of scope: auto-discover all classes per pack.
6. **Verifier** `verify_locks(locks, *, custom_nodes_dir=Path("custom_nodes")) -> list[LockMismatch]`:
   - Each lock: check `custom_nodes_dir/<name>/.git` exists, `git rev-parse HEAD == git_commit_sha`. Mismatch carries `(name, expected_sha, actual_sha, kind)` where `kind` is `"missing"`, `"sha_drift"`, or `"source_drift"`.
   - For each `(class_name, expected_sha256)` in `source_sha256`, locate the class file (heuristic: scan pack tree for `class <name>`), recompute SHA-256, compare.

### Step 4: Lockfile schema, reader, writer, verifier, runtime gate (`vibecomfy/node_locks.py`)
**Scope:** Medium
1. **Create** `vibecomfy/node_locks.py`:
   ```python
   @dataclass(frozen=True, slots=True)
   class NodepackLock:
       name: str
       repo_url: str
       git_commit_sha: str
       semantic_label: str | None = None
       source_sha256: dict[str, str] = field(default_factory=dict)

   @dataclass(frozen=True, slots=True)
   class LockMismatch:
       name: str
       kind: str           # "missing" | "sha_drift" | "source_drift"
       expected: str
       actual: str
       detail: str = ""
   ```
2. **Reader** `load_locks(path: Path = Path("custom_nodes.lock")) -> list[NodepackLock]`:
   - Missing or empty file → `[]`.
   - Sniff the first non-blank, non-comment line: if it splits into 3 whitespace-separated tokens with `len(tokens[1]) == 40` (SHA-1 hex), treat the whole file as legacy `name sha url` lines.
   - Otherwise parse as YAML: `{nodepacks: [{name, repo_url, git_commit_sha | git_sha, semantic_label?, source_sha256?}, ...]}`. When a `git_sha` key is encountered, accept it, emit a one-shot `warnings.warn(...)` deprecation about the rename, and treat the value as `git_commit_sha` (satisfies the brief's backward-compat clause).
3. **Writer** `write_locks(locks: list[NodepackLock], path: Path = Path("custom_nodes.lock")) -> None`:
   - Always emit YAML with canonical key order: `name`, `repo_url`, `git_commit_sha`, `semantic_label` (omitted when `None`), `source_sha256` (omitted when empty; sorted by class name when present). Write with `sort_keys=False, default_flow_style=False` for stable round-trips.
4. **Resolver** `resolve_pack(repo_dir: Path, *, hash_classes: Iterable[str] = ()) -> NodepackLock`:
   - `git_commit_sha`: `git -C <dir> rev-parse HEAD`.
   - `repo_url`: `git -C <dir> config --get remote.origin.url`.
   - `semantic_label`: best-effort — `git -C <dir> describe --tags --exact-match` then `git -C <dir> rev-parse --abbrev-ref HEAD`; skip if both fail.
   - `source_sha256`: only for class names in `hash_classes`. Locate by scanning `repo_dir/**/*.py` for `class <Name>(`; if exactly one match, hash that file's bytes with SHA-256; if zero or multiple matches, log a warning and skip that class (do not abort the whole lock).
5. **Verifier** `verify_locks(locks: list[NodepackLock], *, custom_nodes_dir: Path = Path("custom_nodes")) -> list[LockMismatch]`:
   - Per lock: if `custom_nodes_dir/<name>/.git` is missing → `LockMismatch(kind="missing", expected=git_commit_sha, actual="")`.
   - Else `git -C <dir> rev-parse HEAD`; if it differs → `LockMismatch(kind="sha_drift", expected=..., actual=...)`.
   - For each `(class_name, expected_sha256)` in `source_sha256`: locate the class file as in `resolve_pack`; recompute SHA-256; if it differs → `LockMismatch(kind="source_drift", expected=..., actual=..., detail=class_name)`.
6. **Runtime gate** `assert_clean(policy: str = "enforce", *, lockfile: Path = Path("custom_nodes.lock"), custom_nodes_dir: Path = Path("custom_nodes")) -> None`:
   - Honor env var override: `os.environ.get("VIBECOMFY_LOCK_CHECK", policy)`. When effective policy is `"skip"`, return immediately.
   - `locks = load_locks(lockfile)`. When empty, return (no lockfile → nothing to enforce; keeps tests green and matches the brief's "lockfile is decoration without a doctor/runtime check" framing — there has to be a lockfile to enforce).
   - `mismatches = verify_locks(locks, custom_nodes_dir=custom_nodes_dir)`. When empty, return.
   - When effective policy is `"warn"`: `logger.warning(...)` for each mismatch and return.
   - When effective policy is `"enforce"`: raise `LockfileDriftError("nodepack lockfile drift: ..."` with a structured per-mismatch summary in the message). New exception class lives in `node_locks.py`.
7. This satisfies FLAG-001 / issue_hints — runtime startup *does* enforce, gated by `lockfile_check` on the session constructor (default `"enforce"`) and overridable via `VIBECOMFY_LOCK_CHECK`. Tests that don't ship a `custom_nodes.lock` are unaffected because `load_locks` of a missing path returns `[]`.

# Implementation Plan: MP-4 — Custom-Node Lifecycle and Lockfile Enforcement

## Overview

Iteration 3 closes two concrete correctness gaps from iteration 2 — neither indicates the approach is wrong:

- **In-flight tracking window (FLAG-002 / correctness):** the `_inflight` set must span the *entire* `run()` lifetime, not just the `queue_prompt_api` call. Today `run()` does several awaits before reaching the queue (`start()`, `_warm_schema_provider`, `_prepare_prompt_async`, `_maybe_flush_for_policy`, `_start_watchdog`); a concurrent `stop(wait_for_inflight=False)` or reload during that window would see an empty set and tear down `_comfy` mid-prep. Fix: register the task at the top of `run()` (before any await) and discard in an outer `finally`. The `asyncio.Lock` stays narrow around `queue_prompt_api` — it serializes the actual prompt submission, while the set tracks "is anything in flight" for the whole call.
- **External-mode `reconfigure()` (scope / callers):** with `external_url` set, today's plan would let `reconfigure()` silently no-op (stop is a no-op, start re-points at the same URL) and return `True`. Fix: raise `ExternalServerRestartRequired` from `reconfigure()` whenever `self._external` is True and `new_argv != self._argv`, mirroring the `reload_for_nodepack_change` policy. A future `ExternalServerReconfigureRequired` could be introduced if the use cases diverge, but for now the same exception type carries the same intent: "VibeComfy can't restart a server it doesn't own."
