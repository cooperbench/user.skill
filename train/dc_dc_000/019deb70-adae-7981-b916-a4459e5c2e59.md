# Task: add per-milestone PR-and-push workflow to megaplan chain

## Goal

Modify `megaplan/chain.py` (and Dockerfile + a tiny bit of `auto.py`) so that running `megaplan chain start --spec <chain.yaml>` in cloud:

1. **At milestone start**: create a fresh git branch from `main` (using the `milestones[i].branch` field already in chain.yaml — currently informational), push it to `origin`, open a **draft PR** via `gh pr create --draft --base main`.
2. **At each phase boundary** inside `auto.drive` (plan, critique, gate, finalize, execute, review): commit the resulting artifacts + any code changes the phase produced, push to the milestone branch.
3. **At milestone end** (plan reaches `done`):
   - If `merge_policy == "auto"` (default): mark PR ready (`gh pr ready`) and `gh pr merge --auto --squash --delete-branch`.
   - If `merge_policy == "review"`: mark PR ready, halt the chain at a new state `awaiting_pr_merge` recorded in `chain_state.json`. Next invocation should poll `gh pr view <number> --json state` and advance to the next milestone if merged, else halt again.
4. **At milestone failure** (gate stop, escalation): leave the PR as draft for forensics; abort behavior already governed by `on_failure`/`on_escalate` keeps working.

This makes the chain durable across container loss (everything pushed to GitHub), reviewable on GitHub, and resumable.

## Why it matters

Right now the chain pulls main per milestone but **never pushes**. An 8-sprint multi-day chain is one volume failure away from total work loss. The existing `branch:` field in chain.yaml is "currently informational" — this wires it up.

## Constraints / landmines

1. **Backwards compatibility:** `merge_policy` is new. Default `auto`. Existing chain.yaml files without it must continue to work.
2. **No-network test mode:** the chain must still be runnable in tests where there's no GitHub remote. Use a `--no-push` flag (and/or env var `MEGAPLAN_CHAIN_NO_PUSH=1`) that disables branch/PR/push entirely. Tests should set it.
3. **`gh` auth:** GITHUB_TOKEN is set as env var in cloud — `gh` auto-uses it. No extra auth setup needed in entrypoint.
4. **Branch / PR collisions:** if `<branch>` already exists on remote (e.g., resume after chain restart), `git checkout -b` fails. Detect and `git checkout`/`reset` instead. Same for PR — if a draft PR for that branch already exists, reuse it (`gh pr list --head <branch> --json number,state`).
5. **Empty commits:** some phases produce trivial diffs; some produce none. Don't commit empty diffs (`git diff --cached --quiet && skip`).
6. **`.megaplan/plans/<plan>/` artifacts:** these ARE part of the work and SHOULD be committed (precedent: arnold-v2 has them committed). Don't gitignore them.
7. **Chain resume semantics:** existing `ChainState` tracks `current_milestone_index`, `current_plan_name`, `last_state`, `completed`. Extend with `pr_number: int | None` and `pr_state: str | None` (`open` / `awaiting_merge` / `merged`).
8. **Don't touch the running chain.** Your changes go to `main` of `peteromallet/megaplan`. The container won't pick them up until a redeploy.
