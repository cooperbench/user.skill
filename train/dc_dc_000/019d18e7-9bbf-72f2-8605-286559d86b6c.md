# Lifecycle State Machine Enforcement

## Problem Summary

Five deviation vectors let code change lifecycle mode or advance the pipeline outside the canonical `reconcile_plan()` path:

| # | Vector | Location | Mechanism |
|---|--------|----------|-----------|
| 1 | **resolve_workflow side-channel** | `resolve_workflow.py:364-390` | Directly calls `inject_triage_stages()` + `set_lifecycle_phase(plan, "plan")` when WORKFLOW_CREATE_PLAN_ID resolved with open reviews — bypasses reconcile entirely |
| 2 | **clear_postflight_scan_completion** | `refresh_lifecycle.py:210-224`, 5 call sites | Directly writes `refresh_state["lifecycle_phase"] = "execute"` AND clears scan marker — bypasses even `set_lifecycle_phase()` |
| 3 | **Dual phase derivation** | `snapshot.py:263-346` vs `pipeline.py:97-149` | Two independent functions derive display phase from queue contents with different logic and priority ordering |
| 4 | **synthetic.py phase read** | `synthetic.py:240-261` | Reads persisted mode to suppress stale refreshes — read-only, lowest risk |
| 5 | **Unguarded set_lifecycle_phase** | `refresh_lifecycle.py:141-149` | Public function, any caller can set mode to any valid value |

## Design

**Single-writer principle**: Only `reconcile_plan()` (and a new `invalidate_scan()` helper it delegates to) may mutate `refresh_state["lifecycle_phase"]`. All other code paths are refactored to either (a) call reconcile, or (b) request a state invalidation that reconcile will resolve on the next boundary.

**Single derivation function**: Extract one `derive_display_phase()` that both pipeline.py and snapshot.py call.

**No new state machine abstraction**: The two-mode system (plan/execute) with display phases derived from queue contents is already effectively a state machine. Adding a formal `Transition` enum or typed state machine class would be over-engineering — the real fix is eliminating the side-channels and unifying derivation, not adding infrastructure.

### Step 1: Unify display-phase derivation (1 file changed, 2 files updated)

**Problem**: `_resolve_reconcile_display_phase()` in pipeline.py and `_derive_display_phase()` in snapshot.py compute display phase independently with subtly different logic. Pipeline checks `result` fields (injected IDs, triage snapshot); snapshot checks item partitions.

**Fix**:
1. Create a single `derive_display_phase()` in `refresh_lifecycle.py` that takes the queue partition counts/flags as input (not ReconcileResult or item lists — keep it decoupled)
2. Define a small `PhaseInput` dataclass (or kwargs) that both callers can construct from their respective data
3. Update `pipeline.py:_resolve_reconcile_display_phase()` to delegate to the shared function
4. Update `snapshot.py:_phase_for_snapshot()` to delegate to the shared function
5. Verify: both paths produce identical display phases for the same queue state

**Key detail**: The priority ordering must be reconciled. Pipeline checks `PRE_REVIEW_WORKFLOW_IDS` first; snapshot checks `fresh_boundary + initial_review_items` first. Determine which is correct and use one ordering.

### Step 2: Make `set_lifecycle_phase` private (1 file changed)

**In `refresh_lifecycle.py`**:
1. Rename `set_lifecycle_phase` → `_set_lifecycle_phase`
2. Update the single legitimate caller in `pipeline.py` (reconcile_plan) to use the private name via a package-internal import
3. Remove from `__all__`
4. Any other caller that was using it directly will now get an import error — this is the enforcement mechanism

**Note**: Python's `_` prefix is a convention, not hard enforcement. But it's the standard mechanism, and paired with removal from `__all__`, it makes accidental use unlikely. A runtime guard (checking call stack) would be over-engineering.

### Step 3: Eliminate the resolve_workflow side-channel (1 file changed)

**In `resolve_workflow.py:_reconcile_if_queue_drained()`**:

The side-channel at lines 364-390 does three things when WORKFLOW_CREATE_PLAN_ID is resolved with open reviews:
1. `ensure_active_triage_issue_ids(plan, state_data)` — preps triage metadata
2. `inject_triage_stages(plan)` — adds triage items to queue
3. `set_lifecycle_phase(plan, "plan")` — forces plan mode

**Fix**: Remove the special-case branch entirely. Instead:
1. Before calling `reconcile_plan()`, call `ensure_active_triage_issue_ids(plan, state_data)` + `inject_triage_stages(plan)` to prep the queue (these are queue mutations, not lifecycle mutations — they're valid pre-reconcile setup)
2. Let `reconcile_plan()` handle the lifecycle phase derivation naturally — with triage items now in the queue, it will derive `LIFECYCLE_PHASE_TRIAGE_POSTFLIGHT` → mode `"plan"` automatically
3. Delete the direct `set_lifecycle_phase` call
4. The `emit_transition_message("triage")` moves to after the reconcile result check

**Verify**: Write a test that resolves WORKFLOW_CREATE_PLAN_ID with open reviews and confirms the plan ends up in mode "plan" with triage stages injected.

### Step 4: Route `clear_postflight_scan_completion` through reconcile (2 files changed)

**Problem**: `clear_postflight_scan_completion` directly writes `lifecycle_phase = "execute"` AND clears the scan marker. It's called from 5 places (skip, unskip, backlog, reopen, resolve) that all then manually check the return value and set `transition_phase = "execute"`.

**Fix**:
1. **Rename to `invalidate_postflight_scan()`** to clarify intent
2. **Remove the lifecycle_phase write** (line 222: `refresh_state[_LIFECYCLE_PHASE_KEY] = "execute"`) — only clear the scan marker
3. Have each call site call `reconcile_plan()` after invalidation to let reconcile derive the correct phase
4. OR: simpler — have `invalidate_postflight_scan()` return a flag, and have the callers call reconcile. Since these callers already do `if result: transition_phase = "execute"` + `emit_transition_message`, they can instead do `reconcile_plan()` + check `result.lifecycle_phase_changed`.

**Preferred approach**: Option 2 (callers call reconcile after invalidation). This keeps the invalidation function simple and lets reconcile be the single phase-setting path.

**Migration**: All 5 call sites follow the same pattern. Refactor each:
```python
# Before:
if clear_postflight_scan_completion(plan, issue_ids=ids, state=state):
    transition_phase = "execute"
# ... later: emit_transition_message(transition_phase)

# After:
invalidate_postflight_scan(plan, issue_ids=ids, state=state)
result = reconcile_plan(plan, state, target_strict=target_strict)
if result.lifecycle_phase_changed:
    emit_transition_message(result.lifecycle_phase)
```

**Concern**: Some call sites may not have `state` or `target_strict` readily available. Audit each:
- `skip.py` (3 sites): has `state` from earlier load; needs `target_strict` from config
- `living_plan.py` (1 site): has `state`; needs `target_strict`
- `misc.py:cmd_plan_reopen` (1 site): has `state_data`; needs `target_strict`

All are CLI commands that load state anyway, so `target_strict` can be derived from `state.get("config")`.

### Step 5: Verify synthetic.py is read-only (no change needed)

`synthetic.py:240-261` only reads `current_lifecycle_phase(plan)`. This is the correct pattern — consumers READ mode, they never WRITE it. No change needed, but add a brief comment noting the read-only contract.

# Lifecycle State Machine Enforcement (v2)

## Problem Summary

Five deviation vectors let code change lifecycle mode or advance the pipeline outside the canonical `reconcile_plan()` path:

| # | Vector | Location | Mechanism |
|---|--------|----------|-----------|
| 1 | **resolve_workflow side-channel** | `resolve_workflow.py:364-390` | Directly calls `inject_triage_stages()` + `set_lifecycle_phase(plan, "plan")` when WORKFLOW_CREATE_PLAN_ID resolved with open reviews — bypasses reconcile entirely |
| 2 | **clear_postflight_scan_completion** | `refresh_lifecycle.py:210-224`, 5 call sites | Directly writes `refresh_state["lifecycle_phase"] = "execute"` AND clears scan marker — bypasses even `set_lifecycle_phase()` |
| 3 | **Dual phase derivation** | `snapshot.py:263-346` vs `pipeline.py:97-149` | Two independent functions derive display phase from queue contents with different logic and priority ordering |
| 4 | **synthetic.py phase read** | `synthetic.py:240-261` | Reads persisted mode to suppress stale refreshes — read-only, correct pattern |
| 5 | **Unguarded set_lifecycle_phase** | `refresh_lifecycle.py:141-149` | Public function, any caller can set mode to any valid value |

## Design Principles

1. **Single writer**: Only `reconcile_plan()` in pipeline.py may call `_set_lifecycle_phase()`. Enforcement: `_` prefix + removal from `__all__` + elimination of all other callers. Sufficient for an internal tool.
2. **Snapshot is canonical**: `_derive_display_phase()` in snapshot.py is the single source of display-phase logic. Pipeline delegates to it.
3. **Reconcile owns pipeline advancement**: No manual `inject_triage_stages` + `set_lifecycle_phase` outside reconcile. Push the WORKFLOW_CREATE_PLAN_ID triage prep into `sync_triage_needed()`.
4. **One-shot data migration is exempt**: `current_lifecycle_phase()` persists a migrated value on first read of legacy state. This is a one-shot data fixup, not a control flow side-channel.

## Design Principles

1. **Single writer**: Only `reconcile_plan()` in pipeline.py may call `_set_lifecycle_phase()`. Enforcement: `_` prefix + removal from `__all__` + elimination of all other callers. Sufficient for an internal tool.
2. **Reconcile is state-driven**: `reconcile_plan()` derives all behavior from `plan` + `state` dicts. No function parameters carry command-context side-channels. When a caller needs to influence reconcile, it writes a marker to plan state BEFORE calling reconcile.
3. **Two derivation paths, one invariant**: Pipeline derives display phase from `queue_order` prefixes. Snapshot derives from materialized item partitions. They produce equivalent results because sync preconditions ensure the same items exist in both representations. This equivalence is enforced by test, not by forcing them through the same function.
4. **One-shot data migration is exempt**: `current_lifecycle_phase()` persists a migrated value on first read of legacy state. This is a one-shot data fixup, not a control flow side-channel.
