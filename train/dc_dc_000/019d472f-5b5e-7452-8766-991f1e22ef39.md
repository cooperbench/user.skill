## Overview

Currently, each iteration under `results/auto-improve/iteration-NNN/` needs its own `watch_scoring` process started via `--results-root`. The new `evals/watch_scoring_all.py` will auto-discover all active iterations and round-robin score them in a single process, reusing the existing scoring infrastructure from `evals/watch_scoring.py`.

The existing `watch_scoring.py` exposes all the needed building blocks as module-level functions: `_score_single_prediction`, `_load_scores_data`, `_refresh_scores_summary`, `_write_incremental_results`, and the formatting helpers. The new script imports and orchestrates these — no duplication.

## Main Phase

### Step 1: Create `evals/watch_scoring_all.py` (`evals/watch_scoring_all.py`)
**Scope:** Medium (~60-80 lines)

1. **Implement** `discover_active_iterations(base_dir)` — scans `results/auto-improve/` for subdirs containing `_task_manifest.json` AND `_swebench_predictions/`. Returns a list of `Path` objects sorted by name.

2. **Implement** `find_scorable(iteration_root)` — for a single iteration dir, loads the manifest and scores data, computes the set of scorable instance IDs (same logic as `watch_and_score` lines 59-97 in `watch_scoring.py`), and returns a list of `(instance_id, pred_path)` tuples. Returns empty list if nothing to score.

3. **Implement** `watch_all(base_dir, poll_interval, use_modal)` — the main loop:
   - Generate a single `run_id` for the session.
   - Each iteration: call `discover_active_iterations()`, then for each iteration call `find_scorable()`.
   - Score the first scorable prediction found (single-threaded, Modal-first as specified) using `_score_single_prediction` from `watch_scoring`.
   - After scoring, update that iteration's `_watch_scores.json` via `_write_incremental_results` and `_refresh_scores_summary`.
   - Print a progress line prefixed with the iteration name (e.g., `[iter-012] [scored 5 | ...]`).
   - If no predictions were scorable across all iterations, sleep `poll_interval` seconds.
   - Exit when all discovered iterations have `manifest.all_done()` AND no scorable predictions remain.

4. **Implement** `main()` with argparse:
   - `--base-dir` (default: `results/auto-improve`)
   - `--poll-interval` (default: 15)
   - `--timeout` (default: 7 days, same as watch_scoring)

5. **Wire** `if __name__ == "__main__": raise SystemExit(main())` — keep it simple, no auto-restart wrapper (the existing `watch_scoring.py` has one but it adds complexity; this script can be restarted manually or wrapped externally).

## Key Design Decisions

- **Round-robin, not parallel**: Score one prediction at a time, cycling across iterations. This is simpler and avoids resource contention on Modal/Docker.
- **Re-discover iterations each loop**: New iterations appearing mid-run get picked up automatically.
- **Reuse retry logic**: The existing retry/exhaustion logic in `find_scorable` (attempts < 3, exhausted marking) is replicated by using the same scorable-ID computation from `watch_scoring.py`.
- **Progress prefix**: Each log line is prefixed with the iteration dirname so the operator can tell which iteration is being scored.
- **No `--results-root` flag**: The script always scans a base directory, not a single iteration. For single-iteration scoring, use the existing `watch_scoring.py`.
