1. `claim/decision`: AD-2 "`store is the write source of truth; React Query flushes`" is not conceptually sound as written.
`architectural concern`: In this repo, React Query is not just a transport cache. It is already the shared persisted-state snapshot and optimistic coherence layer for settings. Moving authority into Zustand while only invalidating RQ after save creates two client truths and weakens cross-surface consistency.
`repo evidence`: [state_management_refactor_plan.md](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/docs/state_management_refactor_plan.md:62) defines store-first writes with invalidate-on-success only. [useToolSettings.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/shared/hooks/settings/useToolSettings.ts:90) immediately merges successful writes into the query cache via `setQueryData`, and [useAutoSaveSettings.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/shared/settings/hooks/useAutoSaveSettings.ts:232) reads that cache as its load source.
`failure mode`: One surface edits via store, another surface still reading React Query stays stale until refetch; hybrid migration produces oscillation where store state, query cache, and DB snapshot disagree.
`recommended change`: Keep React Query as the canonical persisted snapshot. Use Zustand as a draft/interaction layer on top of it. On successful save, write through to the relevant query cache immediately, then invalidate/refetch only where needed.

2. `claim/decision`: The proposed `pendingFields: Set<keyof T>` plus “merge only non-pending fields on RQ refetch” is too shallow for the actual settings model.
`architectural concern`: Current logic protects the whole pending entity, not just text fields, and several settings are nested objects with mixed persistence semantics. A flat `Set<keyof T>` cannot safely represent partial dirtiness inside `advancedSettings`, `enhanceSettings`, or cross-source overlays.
`repo evidence`: [state_management_refactor_plan.md](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/docs/state_management_refactor_plan.md:64) scopes merge protection to “pending text edits”. [useEditSettingsPersistence.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/domains/media-lightbox/hooks/persistence/useEditSettingsPersistence.ts:267) also merges nested `advancedSettings`, while [useEditSettingsPersistence.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/domains/media-lightbox/hooks/persistence/useEditSettingsPersistence.ts:275) keeps `enhanceSettings` generation-only.
`failure mode`: Refetch merges can clobber nested unsaved edits, or preserve the wrong top-level object and accidentally hide valid remote changes.
`recommended change`: Model `baseline persisted snapshot` plus `local draft patch` plus `dirty paths`, not `pending text fields`. For nested settings, use path-aware dirtiness or domain-specific reconciliation functions.
