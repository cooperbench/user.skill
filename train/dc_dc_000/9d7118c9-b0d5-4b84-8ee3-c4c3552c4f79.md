        # Implementation Plan: Phase 9 — Author Test with Golden Runs

## Overview

Phase 9 is the final V1 phase. It replaces the Phase 5 scaffold `_cmd_test` (which only diffs pre-captured files) with a real runtime replay: compile the orchestrator, start a task run in a scratch directory, auto-approve all attested steps, execute all code steps as subprocesses, capture `events.jsonl`, normalize it, and diff against the committed golden file. 

The codebase is well-structured: `artagents/core/task/` has the gate, events, plan loading, lifecycle; `artagents/orchestrate/cli.py` has the author verbs. The hype pipeline is a legacy folder-based orchestrator (`artagents/packs/builtin/hype/run.py`) — we need a DSL `.py` wrapper to create a task-plan for it, or we create a standalone simple DSL orchestrator for testing.

**Key design decisions:**
- Hash-chain hashes are STRIPPED during normalization (not recomputed). The normalized form of each event line is `json.dumps(payload_without_hash_ts_runid_paths, sort_keys=True)`. This is simpler, deterministic, and the scaffold already does it partially.
- `run_id` is also volatile (generated per-run). We strip it too.
- Absolute paths are replaced with `<RUN_DIR>/...` relative forms.
- The auto-approval mode injects a synthetic `step_attested` event with `source: "author_test"` and skips `validate_attested_identity` entirely.
- We create a simple DSL orchestrator `artagents/packs/builtin/hype.py` that wraps the legacy hype pipeline as a single code step for smoke-testing, plus a fixture and golden.

## Overview

Phase 9 is the final V1 phase. It replaces the Phase 5 scaffold `_cmd_test` (which only diffs pre-captured files) with a real runtime replay: compile the orchestrator, start a task run in a scratch directory, auto-approve all attested steps, execute code steps as subprocesses, capture `events.jsonl`, normalize it, and diff against the committed golden file.

**Key architectural decisions (v3, informed by v2 gate critique and codebase audit):**

- **We do NOT use the folder-based `builtin/hype/`** — `compile_to_path` only supports DSL `.py` modules (`compile.py:86` requires `<pack>/<name>.py`). The folder orchestrator with `orchestrator.yaml` + `run.py` cannot compile to `build/hype.json`. The idea's "canonical hype orchestrator" requirement is infeasible. Instead, we create a **synthetic feature-exercise DSL orchestrator** (`builtin.demo`) that exercises all V1 features: code steps with subprocess execution, attested steps with auto-approval, nested steps, and repeat.for_each with static items.
- **The runtime loop uses `gate_command` for EVERY step** (code + attested alike). `gate_command` (gate.py:510) already handles auto-traversal (nested_entered, for_each_expanded, item_started, etc.) and PERSISTS them to `events.jsonl` via `_gate_append`. The old plan's idea of using `peek_current_step` for code steps is wrong — peek appends to a transient `events_view` that never hits disk (gate.py:481-483).
- **For code steps in author_test mode**: `gate_command` → `_dispatch_code` returns a `GateDecision`. We then run the subprocess ourselves with `cwd=step_dir` and call `record_dispatch_complete(decision, returncode)` which writes `step_completed` + runs inline produces checks against artifacts the subprocess created.
- **No executor_overrides mechanism** — we just write correct produces artifacts from within the code steps' shell commands. The DSL orchestrator defines shell commands that produce their declared outputs.
- **Hash-chain hashes are STRIPPED** during normalization (not recomputed), along with `ts`, `run_id`, `plan_hash` (in run_started only), and absolute paths. `cas_sha256` is also stripped (environment-dependent content hash).
- **Absolute paths are replaced recursively** through all nested dicts/lists/strings in event payloads.
- **Auto-approval bypass** lives in `_dispatch_attested`, guarded by `ARTAGENTS_AUTHOR_TEST=1`, skips identity validation AND inline produces checks, emits `step_attested` with `source: "author_test"` (and `item_attested` when inside for_each).
- CLI keeps the existing positional `<pack>.<name>` qid form. A new `--regenerate` flag is added.
- The old `_strip_volatile` / `_VOLATILE_EVENT_FIELDS` in cli.py are removed; `normalize.py` is the single normalization path.
- `_cmd_new` writes a placeholder `.gitkeep`-style comment in the golden file rather than an empty file, directing authors to use `--regenerate`.
