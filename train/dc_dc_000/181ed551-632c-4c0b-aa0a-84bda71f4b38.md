        # Implementation Plan: Phase 8 — Inbox Surface

## Overview

Add `runs/<run-id>/inbox/` as an opt-in external completion-signal protocol. External processes (humans, scripts, other tools) drop JSON files into the inbox directory to signal that an attested step has completed. On the next `artagents next` or `artagents status` call, the inbox is scanned. Valid entries are consumed (recorded as hash-chained events), advancing the cursor past the corresponding attested step. Malformed or stale entries are logged and ignored.

**Repository shape:** The task-mode kernel lives in `artagents/core/task/` with separate modules for events (`events.py`), the gate (`gate.py`), lifecycle verbs (`lifecycle.py`, `lifecycle_ack.py`), and the plan model (`plan.py`). The top-level pipeline (`artagents/pipeline.py`) short-circuits lifecycle verbs to the handler functions. `artagents/core/task/__init__.py` exports the public API surface. Tests live in `tests/test_task_*.py` and use `tmp_projects_root` from `tests/conftest.py`.

**Key constraints:**
- Additive only — no changes to Phase 7 CAS or earlier phases.
- No new dependencies.
- Inbox is opt-in: presence of `inbox/` directory triggers scanning, absence skips it (no error).
- Honor existing patterns: hash-chained `events.jsonl` via `append_event`, gate-above-dispatch, file-based state.
- Stale/malformed files are logged (stderr) but never crash.

## Phase 1: Inbox Module + Event Type

### Step 1: Create `artagents/core/task/inbox.py`
**Scope:** Medium — new module with three functions and an `InboxEntry` dataclass.

1. Define the `InboxEntry` dataclass in `artagents/core/task/inbox.py`:1:
   ```python
   @dataclass(frozen=True)
   class InboxEntry:
       step_id: str
       decision: str  # "approve" | "retry" | "abort"
       evidence: dict[str, Any]
       submitted_at: str  # ISO 8601
       submitted_by: str
       source_path: Path  # path to the file on disk
   ```

2. Implement `inbox_dir(run_dir: Path) -> Path` — returns `<run_dir>/inbox/`. Does not create the directory; caller must check existence.

3. Implement `scan_inbox(run_dir: Path) -> list[InboxEntry]`:
   - Returns empty list if `inbox/` does not exist.
   - Iterates over `*.json` files in the inbox directory (non-recursive).
   - Skips files starting with `.`.
   - For each file, attempts to parse as JSON and validate against the required shape (dict with string keys `step_id`, `decision`, `evidence`, `submitted_at`, `submitted_by`).
   - `decision` must be one of `"approve"`, `"retry"`, `"abort"`.
   - Malformed files: log a warning to stderr (`print(f"inbox: skipping malformed file {path}: {reason}", file=sys.stderr)`) and continue — never raise.
   - Returns valid entries sorted by `submitted_at` (oldest first).

4. Implement `consume_inbox_entry(slug: str, run_id: str, entry: InboxEntry, *, projects_root: Path | None = None) -> dict[str, Any]`:
   - Load the active run, plan, and events to get the current cursor via `peek_current_step`.
   - Validate that `entry.step_id` matches the current step's `id` (only the leaf id, not the full path — the step_id in an inbox file references the plan-level step id). If it doesn't match, log a warning and return `None` (stale entry).
   - Validate that the current step is an `AttestedStep` (only attested steps accept external completion signals). If not, log a warning and return `None`.
   - Construct an event via `make_step_attested_event(plan_step_path, attestor_kind="external", attestor_id=entry.submitted_by, evidence=tuple(entry.evidence.keys()))`.
   - Append the event to `events.jsonl` via `append_event`.
   - Move the inbox file to `<run_dir>/inbox/.consumed/<sha256_of_content>.json` using sha256 of the file content.
   - Create `.consumed/` directory if it doesn't exist.
   - Return the appended event dict.

def make_external_attested_event(

## Phase 2: Hook Into Lifecycle Handlers

### Step 4: Wire inbox scanning into `cmd_next` (`lifecycle.py`)
**Scope:** Medium — integration point.

In `artagents/core/task/lifecycle.py`, in `cmd_next` (after the preamble is printed and before computing `peek`):

1. Determine the run directory: `run_dir = proj_root / "runs" / run_id`.
2. Call `scan_inbox(run_dir)` to get pending entries.
3. If there are pending entries and the peek reveals an `AttestedStep`, match the first pending entry's `step_id` against the current step id:
   - If it matches, call `consume_inbox_entry(slug, run_id, entry, projects_root=projects_root)`.
   - Re-read events and re-compute `peek` after consumption.
   - Print a notice: `f"consumed inbox entry from {entry.submitted_by}"`.
4. If the entry doesn't match, print a notice: `f"inbox: skipping stale entry for step {entry.step_id} (current step is {peek.path_tuple[-1]})"`.

### Step 5: Wire inbox scanning into `cmd_status` (`lifecycle.py`)
**Scope:** Small — read-only surface.

In `artagents/core/task/lifecycle.py`, in `cmd_status` (after printing the current step info and before printing recent events):

1. Determine the run directory.
2. Call `scan_inbox(run_dir)`.
3. If any entries exist, print `f"inbox: {len(entries)} pending inbox entries"`.
4. For each entry in entries (up to 5), print `f"  {entry.step_id}  {entry.decision}  by {entry.submitted_by}  {entry.submitted_at}"`.

        # Implementation Plan: Phase 8 — Inbox Surface (Revised)

## Overview

Add `runs/<run-id>/inbox/` as an opt-in external completion-signal protocol. External processes (humans, scripts, other tools) drop JSON files into the inbox directory to signal that an attested step has completed. On the next `artagents next` or `artagents status` call, the inbox is scanned. Valid entries targeting the current step are consumed (recorded as `step_attested` hash-chained events with `attestor_kind='external'`), advancing the cursor past the corresponding attested step. Malformed or stale entries are logged and ignored.

**Repository shape:** The task-mode kernel lives in `artagents/core/task/` with `events.py` (event record factories + append), `gate.py` (cursor derivation at line 257 advances on `step_attested`/`step_completed`; `record_step_attested` at line 1183 wraps `make_step_attested_event`), `lifecycle.py` (`cmd_next` at line 367, `cmd_status` at line 245, `_AGENT_MD_TEMPLATE` at line 53), and `plan.py` (`STEP_PATH_SEP = "/"`, plan model types). Tests live in `tests/test_task_*.py` and use `tmp_projects_root` from `tests/conftest.py`.

**Key constraints:**
- Additive only — no changes to Phase 7 CAS or earlier phases.
- No new dependencies.
- Inbox is opt-in: presence of `inbox/` directory triggers scanning, absence skips silently.
- Honor existing patterns: hash-chained `events.jsonl` via `append_event`, `step_attested` events (the kind that `derive_cursor` at gate.py:257 already advances on), file-based state.
- Stale/malformed files are logged to stderr but never crash.
- Inbox is an external signal channel that intentionally bypasses gate dispatch and `validate_attested_identity` — it does not need agent/actor identity validation.

**Design decisions (addressing gate critique):**
- Use `step_attested` event kind with `attestor_kind='external'` (NOT a new `external_attested` kind). This avoids the cursor-advance silent-failure bug flagged at gate.py:257.
- Match inbox entries by the full `STEP_PATH_SEP`-joined path from `peek.path_tuple`, not leaf `step_id`. This resolves the nested-step collision flagged in correctness-3.
- Stale-skip when `peek.item_id is not None` (item-level for_each body). Inbox does not support item-level attestation in Phase 8. This resolves correctness-4.
- Scanner validates `decision` against `(approve, retry, abort)` but only `approve` triggers consumption. `retry`/`abort` are recognized, logged, and treated as Phase 8 no-ops (future extension). This resolves issue_hints-1.
- AGENT.md template update only affects new runs — accepted limitation (issue_hints-2).

## Phase 1: Inbox Module

### Step 1: Create `artagents/core/task/inbox.py`
**Scope:** Medium — new module with `InboxEntry` dataclass, `inbox_dir`, `scan_inbox`, `consume_inbox_entry`.

1. Define `InboxEntry` dataclass:
   ```python
   from dataclasses import dataclass, field
   from pathlib import Path
   from typing import Any

   @dataclass(frozen=True)
   class InboxEntry:
       step_id: str          # the step path string from the inbox file
       decision: str         # "approve" | "retry" | "abort"
       evidence: dict[str, Any]
       submitted_at: str     # ISO 8601
       submitted_by: str
       source_path: Path     # path to the file on disk
   ```

2. Implement `inbox_dir(run_dir: Path) -> Path`:
   - Returns `<run_dir>/inbox/`. Does NOT create the directory.

3. Implement `scan_inbox(run_dir: Path) -> list[InboxEntry]`:
   - Returns empty list if `inbox/` does not exist or is empty.
   - Iterates `*.json` files non-recursively.
   - Skips files starting with `.`.
   - Parses JSON, validates required keys (`step_id`, `decision`, `evidence`, `submitted_at`, `submitted_by` all strings; `evidence` must be a dict).
   - `decision` must be one of `"approve"`, `"retry"`, `"abort"`.
   - Malformed/missing-key files: log warning to stderr (`print(f"inbox: skipping malformed file {path}: {reason}", file=sys.stderr)`) and continue.
   - Returns valid entries sorted by `submitted_at` (oldest first). If `submitted_at` is unparseable, sort by filename as fallback.

4. Implement `consume_inbox_entry(slug: str, run_id: str, entry: InboxEntry, *, projects_root: Path | None = None) -> dict[str, Any] | None`:
   - Load the active run, plan, and events to get `peek_current_step`.
   - **Item-level guard:** If `peek.item_id is not None`, log warning and return `None` (inbox does not support item-level attestation in Phase 8).
   - **Path match:** Build `current_path = STEP_PATH_SEP.join(peek.path_tuple)`. If `entry.step_id != current_path`, log warning and return `None` (stale entry).
   - **Step kind guard:** If `peek.step` is not an `AttestedStep`, log warning and return `None`.
   - **Decision guard:** If `entry.decision != "approve"`, log info message and return `None` (retry/abort reserved for future phases).
   - Construct event via `make_step_attested_event(plan_step_path=current_path, attestor_kind="external", attestor_id=entry.submitted_by, evidence=tuple(entry.evidence.keys()))`.
   - Append to `events.jsonl` via `append_event`.
   - Move inbox file to `<run_dir>/inbox/.consumed/<sha256_of_content>.json`. Create `.consumed/` if needed.
   - Return the appended event dict.
