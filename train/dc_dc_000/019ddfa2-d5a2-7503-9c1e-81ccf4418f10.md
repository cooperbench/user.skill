> AGENT

Practically, the distinction should be about **control responsibility**, not packaging. **Node** A node is an executable unit with a narrow contract: ```text inputs -> work -> outputs ``` It should be mostly unaware of the wider workflow. It may call libraries and subprocesses, but it should not decide the broader production sequence. Examples: `transcribe`, `scenes`, `shots`, `render_card`, `render_talk_body`, `validate_video`. **Orchestrator / Conductor** A conductor decides: ```text which nodes run, in what order, with what shared context, retries, skips, cache policy, and artifact layout ``` Examples: `hype_cut`, `event_talks`, `podcast_clips`, `social_pack`. The clean rule set I’d use: 1. **Conductors can run nodes** Yes. That is their main job. 2. **Nodes should not run conductors** No, not directly. If a node needs a whole workflow, it is probably not a node. Make it a conductor step or call a smaller node instead. 3. **Conductors can run other conductors, but explicitly** Yes, with guardrails. This is useful for composition: `event_talks` might call a `render_cards` conductor or a `transcript_analysis` conductor. But make it visible in metadata as a child conductor dependency, not hidden in arbitrary code. 4. **Nodes can run other nodes only rarely** Usually no. A node should not secretly orchestrate a mini-pipeline. If it must, either: - split it into multiple nodes and move sequencing into a conductor, or - mark it as a composite node, but that is a smell. The practical distinction: ```text Node = leaf work unit Conductor = workflow controller ``` A stricter runtime model: ```text Conductor -> Node allowed Conductor -> Conductor allowed, declared Node -> Node discouraged / only internal implementation detail Node -> Conductor disallowed ``` Why this matters: - Scheduling: conductors create run graphs; nodes execute graph leaves. - Caching: nodes cache outputs; conductors cache workflow state and decisions. - UI: nodes appear as capabilities; conductors appear as workflows/templates. - Debugging: conductor run contains step runs; node run contains logs/artifacts. - Reuse: nodes should be reusable across conductors without dragging workflow assumptions. - Safety: preventing nodes from launching conductors avoids recursive or invisible workflows. So the actual test is: > Does this thing decide a workflow, or does it perform one bounded operation? If it decides sequencing, branching, retries, child runs, or cross-step artifact policy, it is a conductor. If it turns declared inputs into declared outputs, it is a node.
