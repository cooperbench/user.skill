        # Implementation Plan: Eliminate phase-derivation bypasses in `_phase_for_snapshot`

## Overview

`_phase_for_snapshot()` in `snapshot.py:264-311` has two short-circuit paths that bypass the canonical `derive_display_phase()` in `refresh_lifecycle.py:175-201`:

1. **No-plan fast path** (lines 277-293): When `plan` is not a dict, returns `REVIEW_INITIAL` or `EXECUTE` directly before falling through to `_derive_display_phase()`. This partially duplicates the priority chain but is semantically redundant — with `prefer_scan=False`, `derive_display_phase` produces identical results.

2. **Execute-mode override** (lines 297-298): When `raw_phase == "execute"` and execution items exist, returns `EXECUTE` directly. This compensates for snapshot passing `prefer_scan=True` when in execute mode — without the bypass, `derive_display_phase` would return `SCAN` instead of `EXECUTE`.

**Key insight from critique:** The fix must stay local to `_phase_for_snapshot`. The shared `derive_display_phase()` must NOT be modified because the pipeline caller (`_resolve_reconcile_display_phase` in `pipeline.py:110`) computes `prefer_scan` from scan workflow IDs in `queue_order` (line 135), which has different semantics than snapshot's `raw_phase == "execute"`. An existing divergence — pipeline returns `scan` while snapshot returns `execute` for `queue_order=['stale-issue','workflow::run-scan']` — must be preserved.

**Approach:** Instead of modifying the shared function, fix the `prefer_scan` signal that `_phase_for_snapshot` passes. The execute-mode bypass exists because snapshot currently passes `prefer_scan=True` then short-circuits before it takes effect. By passing `prefer_scan=False` when execution items exist, the bypass becomes unnecessary.

**Key files:**
- `desloppify/engine/_work_queue/snapshot.py` — `_phase_for_snapshot()` (only file changed)
- `desloppify/engine/_plan/refresh_lifecycle.py` — `derive_display_phase()` (unchanged, verified)
- `desloppify/engine/_plan/sync/pipeline.py` — `_resolve_reconcile_display_phase()` (unchanged, verified)

## Step 1: Rewrite `_phase_for_snapshot` to remove both bypasses
**Scope:** Small — net deletion of ~15 lines  
**File:** `desloppify/engine/_work_queue/snapshot.py:264-311`

1. **Replace** the entire function body with a single code path:
   ```python
   def _phase_for_snapshot(plan, *, fresh_boundary, initial_review_items,
                           anchored_execution_items, explicit_queue_items,
                           scan_items, postflight_assessment_items,
                           postflight_review_items, postflight_workflow_items,
                           triage_items) -> str:
       has_execution = bool(anchored_execution_items or explicit_queue_items)
       raw_phase = current_lifecycle_phase(plan) if isinstance(plan, dict) else None
       # In execute mode, prefer_scan only activates when no execution work remains
       # (signals "all done, time to re-scan"). When execution items exist, we must
       # not override them with a scan phase.
       prefer_scan = raw_phase == "execute" and not has_execution

       return _derive_display_phase(
           fresh_boundary=fresh_boundary,
           initial_review_items=initial_review_items,
           anchored_execution_items=anchored_execution_items,
           explicit_queue_items=explicit_queue_items,
           scan_items=scan_items,
           prefer_scan=prefer_scan,
           postflight_assessment_items=postflight_assessment_items,
           postflight_review_items=postflight_review_items,
           postflight_workflow_items=postflight_workflow_items,
           triage_items=triage_items,
       )
   ```

2. **Why this works for each removed bypass:**
   - **No-plan bypass (was lines 277-293):** When `plan` is not a dict, `raw_phase=None`, so `prefer_scan=False`. With `prefer_scan=False`, `derive_display_phase` checks `fresh_boundary and has_initial_review` first (→ `REVIEW_INITIAL`), then falls through to `has_execution` (→ `EXECUTE`), exactly matching the removed bypass.
   - **Execute-mode override (was lines 297-298):** When `raw_phase=="execute"` and execution items exist, `prefer_scan=False` (because `not has_execution` is False). So `derive_display_phase` skips the scan check and reaches `has_execution` → `EXECUTE`.

3. **What is NOT changed:** `derive_display_phase()` in `refresh_lifecycle.py` and `_resolve_reconcile_display_phase()` in `pipeline.py` are untouched. The pipeline's `prefer_scan` (computed from `_SCAN_PHASE_WORKFLOW_IDS`) retains its independent semantics.
