**Phase 2: Encode Canonical Rules**

Duration rule:

- `hold` is explicit duration and wins.
- Otherwise, if finite `from` and `to` exist, source duration is `to - from`.
- Otherwise, for media clips with an asset whose registry entry has finite positive `duration`, use `asset.duration - from` when `from` exists, or `asset.duration` when `from` is absent.
- Apply positive finite `speed`, defaulting invalid/missing speed to `1` with a warning.
- Clamp frame duration to at least `1` frame only at frame conversion boundaries, not in seconds-domain helpers.
- Preserve visible behavior where tests show a risk; document any place still using zero-duration fallback as a follow-up.

Validation diagnostics shape:

```ts
type TimelineDiagnostic = {
  code: 'missing_asset' | 'unknown_clip_type' | 'invalid_duration' | 'legacy_shape_repaired' | ...;
  severity: 'error' | 'warning' | 'info';
  path: string;
  message: string;
  suggestedRepair?: string;
};
```

Hard errors: non-object timeline, missing output, invalid clips array, invalid IDs/tracks, impossible negative duration after all fallbacks, unsafe non-finite numeric values.

Warnings: repaired legacy tracks, duplicate IDs repaired, missing optional metadata, unknown future clip types, missing assets where placeholder rendering exists, pinned group references to missing clips, media clips needing registry duration fallback.
