        # Implementation Plan: First-Class Shot Context for the Timeline Agent

## Overview
The repo already has the core shot-group click-to-select behavior: `TimelineCanvas` calls `onSelectClips(group.clipIds)` and `TimelineEditor` already wires that to `selectClips`. The missing work is the shot-context data model. `pinnedShotGroups` only carries IDs, so backend timeline summaries cannot render shot names without an explicit lookup, and shot metadata currently gets dropped in both the chat attachment path and persisted turn recovery. This revision narrows scope away from new canvas selection code and focuses on one shared shot-context pipeline used by timeline summaries, selected-clip prompts, and same-shot tool behavior.

## Phase 1: Re-scope Around the Real Gap

### Step 1: Reuse the existing shot-group selection path (`src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx:1023`, `src/tools/video-editor/components/TimelineEditor/TimelineEditor.tsx:874`, `src/tools/video-editor/components/TimelineEditor/TimelineCanvas.test.tsx:1016`)
**Scope:** Small
1. **Treat** shot-group single-click selection as already implemented: `TimelineCanvas` already calls `onSelectClips(group.clipIds)` and `TimelineEditor` already passes `selectClips`.
2. **Remove** the stale plan work that added a new `onShotGroupSelect` prop or duplicate click handler.
3. **Keep** the existing canvas regression test as the guardrail for the original UX requirement instead of expanding scope.

## Phase 2: Plumb Shot Metadata Through the Selected-Clip Contract

### Step 2: Extend shared selected-clip and attachment types (`src/tools/video-editor/types/agent-session.ts:8`, `supabase/functions/ai-timeline-agent/types.ts:74`)
**Scope:** Small
1. **Add** optional shot metadata to both sides of the contract: `shotId?: string` / `shotName?: string` on persisted frontend attachments and `shot_id?: string` / `shot_name?: string` on backend `SelectedClipPayload`.
2. **Keep** the fields optional so existing sessions, gallery attachments, and older function calls remain valid.
3. **Update** any attachment and turn normalization that currently assumes attachments only carry clip, URL, media type, generation, and prompt fields.

### Step 3: Enrich frontend-selected clips before send (`src/tools/video-editor/hooks/useSelectedMediaClips.ts:29`, `src/tools/video-editor/components/AgentChat/AgentChat.tsx:303`, `src/tools/video-editor/hooks/useAgentSession.ts:275`)
**Scope:** Medium
1. **Update** `useSelectedMediaClips()` to join `resolvedConfig.pinnedShotGroups` with `useShots()` data so each selected timeline clip can expose `shotId` and resolved `shotName`.
2. **Preserve** that metadata in `AgentChat` when timeline and gallery attachments are merged; gallery items may legitimately omit shot fields.
3. **Include** `shot_id` and `shot_name` in the `selected_clips` body sent by `useSendMessage()`.

### Step 4: Preserve shot metadata through normalization and recovery (`supabase/functions/ai-timeline-agent/selectedClips.ts:26`, `supabase/functions/ai-timeline-agent/loop.ts:66`, `supabase/functions/ai-timeline-agent/index.ts:24`)
**Scope:** Medium
1. **Update** `normalizeSelectedClips()` to accept and trim incoming `shot_id` and `shot_name`.
2. **Update** `attachSelectedClips()` so persisted user-turn attachments keep shot metadata.
3. **Update** `recoverSelectedClipsFromTurns()` so continuation turns recover the same shot context instead of dropping it after the first request.
4. **Continue** enriching prompts from generation metadata without overwriting explicit shot metadata supplied by the frontend.

## Phase 3: Load Explicit Shot Names and Centralize Same-Shot Resolution

### Step 5: Supply backend timeline summaries with explicit shot names (`supabase/functions/ai-timeline-agent/db.ts:308`, `supabase/functions/ai-timeline-agent/types.ts:56`, `supabase/functions/ai-timeline-agent/tools/registry.ts:49`, `supabase/functions/ai-timeline-agent/tools/timeline.ts:52`)
**Scope:** Medium
1. **Extend** `loadTimelineState()` to batch-load shot names for the timeline's pinned shot IDs from the `shots` table and return a `shotNamesById` map alongside config and registry.
2. **Thread** `shotNamesById` through `TimelineState`, `ToolContext`, and the `view_timeline` handler path so runtime `run(command="view")` uses the same data as loop-time summaries.
3. **Update** `describeTimeline()` and `formatClipLine()` to use `pinnedShotGroups` plus `shotNamesById`, emitting per-clip shot metadata and a `Shot groups:` section listing resolved shot name, `shotId`, `trackId`, `clipIds`, and `mode`.
4. **Fall back** to `shotId` when a shot name cannot be loaded, rather than silently omitting shot context.

### Step 6: Centralize same-shot semantics for all agent flows (`supabase/functions/ai-timeline-agent/tools/clips.ts:4`, `supabase/functions/ai-timeline-agent/loop.ts:371`, `supabase/functions/ai-timeline-agent/tools/create-task.ts:216`, `supabase/functions/ai-timeline-agent/tools/loras.ts:104`, `supabase/functions/ai-timeline-agent/tools/duplicate-generation.ts:4`, `supabase/functions/ai-timeline-agent/prompts.ts:67`)
**Scope:** Medium
1. **Add** a shared helper in `tools/clips.ts` that resolves shot context from selected clips in this order: explicit `shot_id` on the payload, pinned-shot-group membership for timeline clips, then `findShotForGenerations()` as the legacy fallback.
2. **Use** that helper in `runAgentLoop()` so travel defaults and active-reference lookup key off the selected shot when available instead of always re-deriving from generation IDs.
3. **Use** the same helper in `executeCreateTask()`, `executeSetLora()`, and `executeDuplicateGeneration()` so shot reuse, travel LoRAs, and duplicate semantics all agree on what "same shot" means.
4. **Keep** `executeDuplicateGeneration()` on the fast path when the selected clips already share a `shot_id`, skipping the extra generation lookup in that case.
5. **Update** selected-clip prompt rendering and the system prompt to mention shared-shot context explicitly once structured shot data is available, without adding new tools or changing the existing duplicate/edit/place workflow.

## Phase 4: Prove the Wiring End to End

### Step 7: Add focused backend and frontend tests (`supabase/functions/ai-timeline-agent/tools/timeline.test.ts:1`, `supabase/functions/ai-timeline-agent/selectedClips.test.ts:1`, `supabase/functions/ai-timeline-agent/loop.test.ts:1`, `supabase/functions/ai-timeline-agent/tools/duplicate-generation.test.ts:1`, `src/tools/video-editor/hooks/useSelectedMediaClips.test.tsx:1`, `src/tools/video-editor/hooks/useAgentSession.test.tsx:1`, `src/tools/video-editor/components/AgentChat/AgentChat.test.tsx:183`)
**Scope:** Medium
1. **Backend tests:** cover shot-group timeline summaries, per-clip shot annotations, shot metadata normalization, shot metadata recovery from stored attachments, selected-clip prompt rendering with shot context, and duplicate-generation behavior when `shot_id` is already present.
2. **Frontend tests:** cover `useSelectedMediaClips()` shot resolution, `AgentChat` preserving shot fields when it builds attachments, and `useSendMessage()` including `shot_id` and `shot_name` in `selected_clips`.
3. **Regression coverage:** keep the existing `TimelineCanvas` single-click shot-group selection test green instead of adding a redundant second path.
