        # Implementation Plan: Auto-Switch Shot Aspect Ratio on Image Drop

## Overview
When a user drops an image onto a shot in the shot editor, if the image's aspect ratio doesn't match the shot's current aspect ratio, auto-switch the shot to the closest canonical ratio (from `ASPECT_RATIO_TO_RESOLUTION`) and show a small notice above the `AspectRatioSelector` with a "Revert to project default" button.

**Key repo shape (verified):**
- Drop handlers live in `src/tools/travel-between-images/components/ShotEditor/hooks/actions/useDropActions.ts`. Both `handleTimelineImageDrop` (line 79) and `handleBatchImageDrop` (line 202) currently call `cropImagesToShotAspectRatio(files, currentShot, …)` which crops each dropped file to `selectedShot.aspect_ratio`. We must adjust the shot's `aspect_ratio` **before** that crop call so files get cropped to the new (wider/taller) ratio.
- Canonical ratio list and utilities already exist at `src/shared/lib/media/aspectRatios.ts`: `ASPECT_RATIO_TO_RESOLUTION` (line 3), `parseRatio` (line 38), `findClosestAspectRatio` (line 57). Canonical keys: `21:9, 16:9, 4:3, 3:2, 1:1, 2:3, 3:4, 9:16, 9:21`.
- `AspectRatioSelector` is rendered inside `Header.tsx` (desktop line 227, mobile line 315), wrapped in a fixed-width (`w-[100px]` / `w-[75px]`) column. The current `handleAspectRatioChange` (line 62) optimistically updates the shots query cache, debounces a DB update, and clears `customWidth/customHeight` from tool settings. We need this same update flow when the drop hook mutates the AR.
- Shot editor state is a reducer at `src/tools/travel-between-images/components/ShotEditor/state/useShotEditorState.ts`. Exposed via `ShotSettingsContext` (`state`, `actions`) — already passed to `Header.tsx` through `HeaderSection.tsx:43`.
- Project default AR: `useProject()` / `projects` array (`ProjectContext.tsx:10` — `Project.aspectRatio`). Drop hook already has `projectsRef` at `useDropActions.ts:55`.
- `cropImagesToShotAspectRatio` respects `uploadSettings.cropToProjectSize` (`timelineDropHelpers.ts:61`). When `cropToProjectSize !== false`, files are cropped to the **project** AR, not the shot. In that case auto-switching the shot AR would be pointless — the dropped image is already being conformed to project AR. We will **skip the auto-switch** in that case.

**Constraints:**
- Light touch: no refactors beyond (a) extracting the shot-AR update logic so Header and the drop hook can share it, (b) adding one reducer slice, (c) rendering the notice.
- Canonical list is already authoritative — do not invent ratios.
- Don't regress existing tests in `useDropActions`, `Header`, or `timelineDropHelpers`.

## Main Phase

### Step 1: Extract shared shot-aspect-ratio update helper (`src/shared/hooks/shots/useUpdateShotAspectRatio.ts` — new)
**Scope:** Small

1. **Create** a thin hook `useUpdateShotAspectRatio()` that returns a function `updateShotAspectRatio(shotId, projectId, newAspectRatio, { immediate?: boolean })`. Port the logic currently inline at `Header.tsx:62-127`:
   - Optimistically set `aspect_ratio` on both `queryKeys.shots.list(projectId, 0)` and `(projectId, 2)` caches.
   - Read current `settings`, clear `customWidth`/`customHeight`, set `dimensionSource: 'firstImage'` under `TOOL_IDS.TRAVEL_BETWEEN_IMAGES`.
   - Persist `aspect_ratio` + merged `settings` in one `shots` update.
   - On success, invalidate `queryKeys.settings.tool(TRAVEL_BETWEEN_IMAGES, projectId, shotId)`.
   - On error, surface via `normalizeAndPresentError` and invalidate `queryKeys.shots.list(projectId)`.
2. **Preserve** the 300ms debounce used by the Header (required for the AR selector's rapid click-through), but provide an `immediate: true` path the drop hook can use to flush synchronously — the drop flow needs the DB update to land before cropping so subsequent reads are consistent. Implementation: `immediate` skips the setTimeout and awaits the update directly.
3. **Export** the hook from `src/shared/hooks/shots/index.ts` barrel (check existing barrel).

### Step 2: Wire Header to the new helper (`src/tools/travel-between-images/components/ShotEditor/ui/Header.tsx`)
**Scope:** Small

2. **Delete** the local `updateTimeoutRef` and its cleanup `useEffect` — now owned by the hook.

### Step 3: Add reducer state for "auto-adjusted due to drop" (`src/tools/travel-between-images/components/ShotEditor/state/useShotEditorState.ts`, `state/types.ts`)

### Step 4: Detect mismatch and auto-switch in the drop hook (`src/tools/travel-between-images/components/ShotEditor/hooks/actions/useDropActions.ts`)
**Scope:** Medium

1. **Add** deps: consume `useUpdateShotAspectRatio()`; accept `setAutoAdjustedAspectRatio` from props (wired from `state.actions` at the caller). Add `setAutoAdjustedAspectRatioRef` mirror ref (match the existing ref pattern at lines 55-74).
2. **Create** a small internal helper `maybeAutoAdjustShotAspectRatio(files, currentShot, projectsList, uploadSettings)` that:
   - Returns `null` if `uploadSettings.cropToProjectSize !== false` (project crop takes precedence — leave shot AR alone).
   - Reads `files[0]`'s natural dimensions using the same `FileReader` + `new Image()` pattern as `imageCropper.ts:42-49`. One-file probe only.
   - Computes `imageRatio = width / height`.
   - Calls `findClosestAspectRatio(imageRatio)`.
   - Compares against `currentShot.aspect_ratio ?? projectAspectRatio ?? '16:9'` (mirror the fallback in Header.tsx:228).
   - If equal, returns `null`. Otherwise returns `{ previousAspectRatio, adjustedTo }`.
3. **Call** this helper at the top of both `handleTimelineImageDrop` (line 89, inside the `try` before `fetchNextAvailableFrameForShot`) and `handleBatchImageDrop` (line 218). On a non-null result:
   - `await updateShotAspectRatio(currentShot.id, currentProjectId, result.adjustedTo, { immediate: true })` — must complete before cropping.
   - `setAutoAdjustedAspectRatioRef.current(result)` to surface the notice.
   - Mutate a **local** `currentShot` copy so the subsequent `cropImagesToShotAspectRatio(files, { ...currentShot, aspect_ratio: result.adjustedTo }, …)` crops to the new ratio. (The Shot object is read at line 80; updating the DB won't synchronously change the ref, so pass the updated object explicitly.)
4. **Do not** swallow errors from the AR update. If `immediate: true` fails, let `normalizeAndPresentError` handle it in the outer catch (the drop proceeds with the old AR — acceptable fallback).

### Step 5: Render the notice + revert button (`src/tools/travel-between-images/components/ShotEditor/ui/Header.tsx`)

Keep text minimal: "Adjusted to match dropped image" + inline `Button` "Revert".

   - User clicks Revert (handled above).
   - User manually changes AR via the selector (in the existing `handleAspectRatioChange`, call `actions.setAutoAdjustedAspectRatio(null)`).
   - `selectedShot.id` changes (add a `useEffect` in `HeaderSection.tsx` keyed on `selectedShotId` that clears the flag).
