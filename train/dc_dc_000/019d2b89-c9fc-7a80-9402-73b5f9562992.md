        Plan:
        # Implementation Plan: Inline Track Labels in Timeline Canvas

## Overview
**Goal:** Move track labels from a separate scrolling sidebar column into the timeline canvas's scroll container, so labels and rows are always perfectly aligned — especially during drag-to-reorder.

**Current architecture:**
- **Left column** (`w-36`, `overflow-y-auto`): Contains `TrackLabel` components wrapped in a dnd-kit `DndContext`. Scrolls independently and syncs scroll via bidirectional `scrollTop` assignment between `trackListRef` and `scrollContainerRef` inside `TimelineCanvas`.
- **Right column** (`flex-1`): Contains `TimelineCanvas` which renders the grid, clips, cursor, and ruler in its own scrollable `div.timeline-canvas-edit-area`.
- Scroll sync between the two columns is done imperatively in `TimelineCanvas.tsx:183-185` and `TimelineEditor.tsx:266-268`.

**Problem:** The two-column layout with imperative scroll sync can drift out of alignment, especially during drag-to-reorder operations where dnd-kit transforms only apply to the label column.

**Solution:** Render track labels inside the same scrollable container as the timeline rows. Each row becomes a single unit containing both its label (positioned at the left edge) and its clip content. The dnd-kit drag context wraps the entire row so the label and clips move together.

**Existing working-tree changes:** The branch already has changes that unified the two separate `SortableContext`s (visual/audio) into a single `SortableContext` for all tracks, and removed the redundant kind-check in `handleTrackDragEnd`. These changes align with this plan.

## Phase 1: Merge Labels into Canvas Rows

### Step 1: Add track data to TimelineCanvas props
**Scope:** Small
1. **Add** `tracks: TrackDefinition[]` prop to `TimelineCanvasProps` (`TimelineCanvas.tsx:41`).
2. **Add** track-related callbacks as props: `selectedTrackId`, `onSelectTrack`, `onTrackChange`, `onRemoveTrack` — mirroring what `TrackLabel` currently receives.
3. **Add** the dnd-kit drag-end handler and sensors as props (or move the `DndContext` wrapping into `TimelineCanvas`).

### Step 2: Render TrackLabel inside each canvas row
**Scope:** Medium  
1. **Inside** the row rendering loop (`TimelineCanvas.tsx:381-433`), render a `TrackLabel` at the left edge of each row, absolutely positioned at `left: 0`.
2. **Wrap** each row in a dnd-kit `useSortable` container so drag-to-reorder moves the entire row (label + clips) as one visual unit.
3. **Set** `TIMELINE_START_LEFT` to accommodate the label width (~144px / `w-36`). This replaces the current 20px left padding. Clips start after the label area. The grid background `startLeft` updates to match.
4. **Make** labels sticky horizontally: use `position: sticky; left: 0; z-index: 10` so labels stay visible when scrolling horizontally through clips, but scroll vertically with the row.

### Step 3: Widen the label or keep it compact
**Scope:** Small  
1. **Decide** label width: keep the current `w-36` (144px) or use a narrower inline version. The label can be simplified since it's now inside the canvas — the hover overlay with settings popover still works.
2. **Update** `TIMELINE_START_LEFT` in `coordinate-utils.ts:6` from `20` to the new label width (e.g., `144` or a new constant `LABEL_WIDTH`).
3. **Adjust** `buildGridBackground` positioning to start grid lines after the label area.

## Phase 2: Remove Old Sidebar and Scroll Sync

### Step 4: Remove the left column from TimelineEditor
**Scope:** Medium  
1. **Remove** the entire left column `div` (`TimelineEditor.tsx:263-311`) — the `trackListRef` container, the `DndContext`/`SortableContext` wrapping, and the +Video/+Audio buttons.
2. **Move** the +Video/+Audio buttons into the canvas area (e.g., rendered below the last row inside the canvas, or as a footer row).
3. **Remove** `trackListRef` ref (`TimelineEditor.tsx:73`) and its scroll handler (`TimelineEditor.tsx:266-268`).
4. **Remove** the `trackLabelRef` prop from `TimelineCanvas` and all scroll sync code (`TimelineCanvas.tsx:57`, `183-185`, and the `setScrollTop` imperative method at `~169-173`).
5. **Update** `TimelineEditorContext` if it exposes `trackLabelRef` or related state.

### Step 5: Move DndContext into TimelineCanvas
**Scope:** Medium  
1. **Wrap** the row-rendering section of `TimelineCanvas` with `DndContext` + `SortableContext`.
2. **Each row** gets a sortable wrapper using `useSortable({ id: \`track-${row.id}\` })`.
3. **During drag**, dnd-kit's transform applies to the entire row div (label + clips), keeping them visually unified.
4. **Pass** `handleTrackDragEnd` to the `DndContext` inside `TimelineCanvas`, either directly as a prop or through the existing context.

### Step 6: Update coordinate calculations
**Scope:** Small  
1. **Update** `clientXToTime` (`TimelineEditor.tsx:159-167`) to account for the new `TIMELINE_START_LEFT` value.
2. **Update** `rawRowIndexFromY` in `coordinate-utils.ts:104-112` — this should still work since rows are still positioned at `rowIndex * rowHeight`, just inside a wider container.
3. **Update** `resolveDropTarget` (`coordinate-utils.ts:114-133`) if needed.
4. **Verify** `useClipDrag` calculations still work with the wider start offset.

## Phase 3: Polish and Test

### Step 7: Fix grid background and visual polish
**Scope:** Small

3. **Maintain** the border between label area and clip area visually (subtle vertical line at the label's right edge).

### Step 8: Test drag-to-reorder behavior
**Scope:** Small  
1. **Verify** dragging a track reorders both label and clips together — no split-brain.
2. **Verify** horizontal scrolling: labels stay sticky at the left edge while clips scroll.
3. **Verify** vertical scrolling: labels scroll with their rows (no sync needed since they're in the same container).
4. **Verify** external drag-drop (adding clips from asset panel) still resolves to correct tracks.
5. **Verify** clip drag across tracks still works with `useClipDrag`.

### Step 9: Update tests
**Scope:** Small

2. **Smoke test** the marquee selection since `editAreaRef` dimensions changed.
