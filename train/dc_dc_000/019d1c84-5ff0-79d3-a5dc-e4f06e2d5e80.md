        # Implementation Plan: Harden Review & Execution Checklist Enforcement

## Overview
Megaplan already tracks coverage deviations (incomplete task updates, incomplete review verdicts) and logs them as issues/warnings — but never **blocks** on them, never **rejects empty-string verdicts**, and never **renders gaps visibly** in `final.md`. The idea is to close these holes without adding friction to the happy path.

Current state:
- `_validate_merge_inputs` (`handlers.py:183`) validates structure/types/enums but allows empty strings in free-text fields like `reviewer_verdict`, `executor_notes`, and sense-check `verdict`.
- Execute (`handlers.py:1091-1093`) and review (`handlers.py:1178-1193`) count coverage gaps and add deviations/issues but always transition state regardless. Coverage counting is also vulnerable to duplicate entries inflating the count (see Step 2).
- `render_final_md` (`_core.py:92-134`) silently omits empty verdicts/notes (they're falsy strings, so the `if verdict:` / `if executor_notes:` checks skip them). It receives only `finalize_data` with no phase context.
- The execute prompt (`prompts.py:352-397`) includes `finalize.json` but doesn't call out sense checks or watch items as things the executor should actively verify.

## Step 1: Reject empty-string verdicts in `_validate_merge_inputs` (`megaplan/handlers.py:183`)
**Scope:** Small
1. **Add** an optional `nonempty_fields` parameter to `_validate_merge_inputs` — a set of field names that must be non-empty after `.strip()`.
2. **Apply** at the three call sites:
   - Execute merge (`handlers.py:1073`): `nonempty_fields={"executor_notes"}` — reject updates where the executor left notes blank.
   - Review task verdicts (`handlers.py:1156`): `nonempty_fields={"reviewer_verdict"}`.
   - Review sense-check verdicts (`handlers.py:1162`): `nonempty_fields={"verdict"}`.
3. **Behavior:** entries with empty values get filtered out (same as malformed entries) and a deviation is appended: `"Skipped {label}[{index}]: '{field}' must not be empty."` This means they won't count toward coverage — so the existing coverage checks downstream will naturally flag incomplete tracking.

## Step 2: Deduplicate entries and block state transition on incomplete coverage (`megaplan/handlers.py`)
**Scope:** Medium

### 2a: Fix duplicate-entry counting (`handlers.py:1080-1093`, `handlers.py:1168-1193`)
The current merge loops increment `merged_count` / `verdict_count` for every incoming entry that matches a known ID, not for unique IDs. If a worker sends two updates for T1 and none for T2, coverage shows 2/2 while T2 is untouched. Fix:
1. **Execute handler** (`handlers.py:1082-1090`): Track a `seen_ids: set[str]` alongside `merged_count`. On each successful merge, add `task_update["task_id"]` to `seen_ids`. After the loop, set `merged_count = len(seen_ids)`. Log a deviation for duplicate entries: `"Duplicate task_update for '{task_id}' — last entry wins."`.
2. **Review handler** (`handlers.py:1170-1191`): Same pattern for `task_verdicts` (keyed on `task_id`) and `sense_check_verdicts` (keyed on `sense_check_id`). Track `seen_task_ids` and `seen_check_ids` sets respectively. Use their lengths for `verdict_count` and `check_count`.

### 2b: Block state transition on incomplete coverage
1. **Execute handler** (`handlers.py:1099`): Before setting `state["current_state"] = STATE_EXECUTED`, check `untracked_tasks > 0`. If so:
   - Keep state as `STATE_FINALIZED`.
   - Set `result = "blocked"` in the history entry (matching the gate handler pattern at `handlers.py:955`).
   - Set `response["success"] = False`.
   - Set `response["next_step"] = "execute"` (not `"review"`) so the orchestrator re-runs execute.
   - Surface: `"Blocked: {untracked_tasks}/{total_tasks} tasks have no executor update. Re-run execute to complete tracking."` as the summary.
   - Still write `execution.json` and updated `finalize.json` so partial progress is saved.
2. **Review handler** (`handlers.py:1199`): Before setting `state["current_state"] = STATE_DONE`, check both `verdict_count < total_tasks` and `check_count < total_checks`. If either is incomplete:
   - Keep state as `STATE_EXECUTED`.
   - Set `result = "blocked"` in the history entry.
   - Set `response["success"] = False`.
   - Set `response["next_step"] = "review"` (not `None`) so the orchestrator re-runs review.
   - Surface: `"Blocked: incomplete review coverage ({verdict_count}/{total_tasks} task verdicts, {check_count}/{total_checks} sense checks). Re-run review to complete."`.
   - Still write `review.json` and updated `finalize.json`.
3. **Re-run semantics:** Because state doesn't advance, the same step can be re-invoked. The merge logic overwrites by keyed ID lookup (`tasks_by_id.get()`), so a second run with complete output will overwrite partial results and succeed. With 2a's deduplication fix, coverage counting is now accurate.

## Step 3: Render gaps visibly in `final.md` (`megaplan/_core.py:92`)
**Scope:** Small

To distinguish "empty because not yet reached" from "empty because something was missed," add an optional `phase` parameter to `render_final_md`:
```python
def render_final_md(finalize_data: dict[str, Any], *, phase: str = "finalize") -> str:
```
Phase values: `"finalize"` (initial), `"execute"` (after execute), `"review"` (after review). Callers:
- `handlers.py:1021` (finalize): `render_final_md(payload)` — default `"finalize"`, no gap markers.
- `handlers.py:1095` (execute): `render_final_md(finalize_data, phase="execute")` — show gaps for executor_notes on non-pending tasks.
- `handlers.py:1195` (review): `render_final_md(finalize_data, phase="review")` — show gaps for executor_notes, reviewer_verdict, and sense-check verdicts.

Rendering rules:
1. **Task section** (`_core.py:101-106`): When `phase >= "execute"` and `executor_notes` is empty on a non-pending task, render `  Executor notes: [MISSING]`. When `phase == "review"` and `reviewer_verdict` is empty, render `  Reviewer verdict: [PENDING]`.
2. **Sense Checks section** (`_core.py:123-125`): When `phase == "review"` and `verdict` is empty, render `  Verdict: [PENDING]`.
3. **Gap summary:** After the Meta section, if any gaps exist for the current phase, render a `## Coverage Gaps` section with counts (e.g., "2 tasks missing executor notes, 1 sense check missing verdict"). Omit the section entirely when all gaps are covered (no noise on the happy path).

## Step 4: Nudge executors on sense checks (`megaplan/prompts.py:352`)
**Scope:** Small
1. **Add** to the execute prompt (`prompts.py:388-396`) a short block surfacing sense checks from `finalize_data`:
   ```
   Sense checks to keep in mind during execution (reviewer will verify these):
   - SC1 (T1): Does validate_plan_structure() correctly return empty list for well-formed plan?
   ```
   This is informational only — the executor doesn't fill in verdicts, but awareness helps them avoid obvious gaps.
2. **Add** a line surfacing `watch_items` if present: `"Watch items from planning: ..."`. Currently `finalize.json` is dumped wholesale, but watch items deserve explicit callout in the requirements section.

## Step 5: Update tests (`tests/test_megaplan.py`, `tests/test_prompts.py`)
**Scope:** Medium
1. **Unit test** `_validate_merge_inputs` with `nonempty_fields`: verify empty-string and whitespace-only entries are filtered and deviations recorded.
2. **Unit test** `render_final_md` with `phase` parameter: verify `[MISSING]` / `[PENDING]` markers appear at correct phases and `## Coverage Gaps` section renders/omits correctly.
3. **Unit test** duplicate-entry deduplication: send two updates for the same task_id, assert `merged_count` reflects unique IDs and a deviation is logged for the duplicate.
4. **Workflow test** for blocked transitions: mock worker output with incomplete `task_updates` → assert state remains `STATE_FINALIZED`, `response["success"] == False`, and `response["next_step"] == "execute"`. Same for review with incomplete verdicts → state remains `STATE_EXECUTED`, `next_step == "review"`.
5. **Update mock workers** (`workers.py:336-410`): ensure `_mock_execute` and `_mock_review` produce complete, non-empty, non-duplicate coverage so the existing happy-path e2e test passes the new enforcement.
6. **Prompt tests** (`tests/test_prompts.py`): assert execute prompt contains "Sense checks" and "Watch items" blocks.
