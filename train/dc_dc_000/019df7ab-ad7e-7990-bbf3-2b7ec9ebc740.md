        # Implementation Plan: Phase 8 Inbox Surface

## Overview
Phase 8 adds an opt-in `runs/<run-id>/inbox/` JSON completion channel for active task runs. The current V1 lifecycle already has hash-chained events in `artagents/core/task/events.py:25`, cursor peeking in `artagents/core/task/gate.py:454`, gate dispatch in `artagents/core/task/gate.py:510`, `status` in `artagents/core/task/lifecycle.py:245`, `next` in `artagents/core/task/lifecycle.py:367`, and the generated run `AGENT.md` template in `artagents/core/task/lifecycle.py:53`.

The critique does not show the plan targeting the wrong files, but it does show the mutation boundary must be stricter. The right root cause remains in the task gate/lifecycle layer: valid inbox approval must persist the same traversal events as `gate_command`, but stale/non-current inbox files must be rejected before any mutating `_auto_traverse_to_leaf` call can append traversal events. The revised plan therefore uses a two-stage flow: read-only current-leaf validation first, then mutating gate traversal and attestation only for entries already proven actionable.

Phase 8 remains approval-focused. The JSON format accepts `decision: approve | retry | abort`, but only `approve` is actionable in this phase because the design describes an external completion-signal protocol. `retry` and `abort` entries are structurally valid files, logged as non-actionable, not counted as pending, and not consumed.

## Main Phase

### Step 1: Add inbox parsing and read-only actionability (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Define `InboxEntry`, `EventRecord`, and an actionability result type around the requested JSON fields: `step_id`, `decision`, object-shaped `evidence`, `submitted_at`, `submitted_by`, plus `source_path` and source-content hash.
2. Implement `inbox_dir(run_dir) -> Path` as `<run_dir>/inbox`.
3. Implement `scan_inbox(run_dir) -> list[InboxEntry]`: absence of `inbox/` returns `[]`; regular non-dot JSON files are read in deterministic path-name order; malformed JSON/schema/type/timestamp files are logged with stdlib `logging` and skipped.
4. Implement a non-mutating helper such as `actionable_inbox_entries(run_dir, entries=None) -> list[InboxEntry]` that loads the active run, plan, events, and `peek_current_step`, then returns only structurally valid `approve` entries whose `step_id` matches the current attested cursor. This helper is used by `status`, by `next`, and immediately before `consume_inbox_entry` mutates anything.
5. Document that consumed files move to `inbox/.consumed/<sha256>.json`; malformed, stale, and non-approve files remain in place for operator inspection.

### Step 2: Add a preflight-safe gate external attestation path (`artagents/core/task/gate.py`)
**Scope:** Medium
1. Add a public helper such as `gate_external_attestation(slug, *, step_id, submitted_by, evidence, submitted_at, inbox_source_hash, root=None) -> GateDecision`.
2. Start the helper with a read-only preflight: active-run read, plan-hash check, event-chain verification, plan load, event read, and `peek_current_step`. Validate `decision=approve` before calling this helper, then validate the preflight leaf is an `AttestedStep` and `step_id == STEP_PATH_SEP.join(peek.path_tuple)`. If this preflight fails, return/raise a non-actionable result before any event append.
3. Only after read-only preflight succeeds, run the mutating traversal path equivalent to `gate_command`: derive the cursor from the same event log and call `_auto_traverse_to_leaf(..., append_fn=_gate_append, raise_on_exhausted=True)` so `nested_entered`, `iteration_started`, `for_each_expanded`, and `item_started` are persisted for valid entries.
4. After mutating traversal returns the leaf, defensively recheck that it is still the same attested `step_id`. In normal single-process lifecycle use this should match; if it does not, do not write the attestation event or move the file. This second check is a race guard, not the primary stale-file filter.
5. Record the attestation as external inbox identity: `attestor_kind="inbox"`, `attestor_id=submitted_by`, and metadata fields for `submitted_at`, `submitted_by`, and `inbox_source_hash`. This explicitly bypasses `ARTAGENTS_ACTOR`/self-ack validation because inbox files are the trusted external signal channel; explicit `ack` keeps the existing identity rules unchanged.
6. Preserve event compatibility for existing tests by keeping the existing `evidence` field as an ack-style list and storing the required object-shaped inbox payload under `inbox_evidence`. Add a small event-maker helper if that keeps this shape centralized.
7. Preserve inline produces checks and iteration/item handling by sharing the post-attestation `GateDecision` construction and check runner used by `_dispatch_attested`.

### Step 3: Consume inbox entries safely (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Implement `consume_inbox_entry(run_dir, entry) -> EventRecord` for entries already identified as actionable. It derives `project_root`, `projects_root`, and `run_id` from `<project>/runs/<run-id>`.
2. Re-run `actionable_inbox_entries(run_dir, [entry])` immediately before mutation. If the entry is now stale, non-current, non-approve, or no longer attested, log and leave both `events.jsonl` and the source file untouched.
3. For still-actionable entries, call `gate_external_attestation`, then move the source file to `.consumed` only after the hash-chained attestation event write succeeds.
4. Use a collision-safe consumed filename: default `<sha256>.json`, with a deterministic suffix if a file already exists for the same hash.
5. Keep `retry` and `abort` out of Phase 8 consumption. They remain parse-valid decisions so producers can use the declared schema, but they are not completion signals and require future explicit semantics/tests before they mutate verifier or active-run state.

### Step 4: Wire lifecycle surfaces and hook-visible behavior (`artagents/core/task/lifecycle.py`, `artagents/core/task/__init__.py`, `artagents/core/task/hook.py` tests)
**Scope:** Medium

4. Do not change `cmd_ack` in `artagents/core/task/lifecycle_ack.py`; the explicit verb remains separate from the implicit inbox channel.
5. Export inbox helpers from `artagents/core/task/__init__.py` only if tests or established package-level imports call for it.

### Step 5: Update generated operator docs (`artagents/core/task/lifecycle.py`)

        # Implementation Plan: Phase 8 Inbox Surface

## Overview
Phase 8 adds an opt-in `runs/<run-id>/inbox/` JSON completion channel for active task runs. The current V1 lifecycle already has hash-chained events in `artagents/core/task/events.py:25`, cursor peeking in `artagents/core/task/gate.py:454`, gate dispatch in `artagents/core/task/gate.py:510`, `status` in `artagents/core/task/lifecycle.py:245`, `next` in `artagents/core/task/lifecycle.py:367`, and the generated run `AGENT.md` template in `artagents/core/task/lifecycle.py:53`.

The critique does not show the plan targeting the wrong files, but it does show the mutation boundary must be stricter. The right root cause remains in the task gate/lifecycle layer: valid inbox approval must persist the same traversal events as `gate_command`, but stale/non-current inbox files must be rejected before any mutating `_auto_traverse_to_leaf` call can append traversal events. The revised plan therefore uses a two-stage flow: read-only current-leaf validation first, then mutating gate traversal and attestation only for entries already proven actionable.

Phase 8 remains approval-focused. The JSON format accepts `decision: approve | retry | abort`, but only `approve` is actionable in this phase because the design describes an external completion-signal protocol. `retry` and `abort` entries are structurally valid files, logged as non-actionable, not counted as pending, and not consumed.

## Main Phase

### Step 1: Add inbox parsing and read-only actionability (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Define `InboxEntry`, `EventRecord`, and an actionability result type around the requested JSON fields: `step_id`, `decision`, object-shaped `evidence`, `submitted_at`, `submitted_by`, plus `source_path` and source-content hash.
2. Implement `inbox_dir(run_dir) -> Path` as `<run_dir>/inbox`.
3. Implement `scan_inbox(run_dir) -> list[InboxEntry]`: absence of `inbox/` returns `[]`; regular non-dot JSON files are read in deterministic path-name order; malformed JSON/schema/type/timestamp files are logged with stdlib `logging` and skipped.
4. Implement a non-mutating helper such as `actionable_inbox_entries(run_dir, entries=None) -> list[InboxEntry]` that loads the active run, plan, events, and `peek_current_step`, then returns only structurally valid `approve` entries whose `step_id` matches the current attested cursor. This helper is used by `status`, by `next`, and immediately before `consume_inbox_entry` mutates anything.
5. Document that consumed files move to `inbox/.consumed/<sha256>.json`; malformed, stale, and non-approve files remain in place for operator inspection.

### Step 2: Add a preflight-safe gate external attestation path (`artagents/core/task/gate.py`)
**Scope:** Medium
1. Add a public helper such as `gate_external_attestation(slug, *, step_id, submitted_by, evidence, submitted_at, inbox_source_hash, root=None) -> GateDecision`.
2. Start the helper with a read-only preflight: active-run read, plan-hash check, event-chain verification, plan load, event read, and `peek_current_step`. Validate `decision=approve` before calling this helper, then validate the preflight leaf is an `AttestedStep` and `step_id == STEP_PATH_SEP.join(peek.path_tuple)`. If this preflight fails, return/raise a non-actionable result before any event append.
3. Only after read-only preflight succeeds, run the mutating traversal path equivalent to `gate_command`: derive the cursor from the same event log and call `_auto_traverse_to_leaf(..., append_fn=_gate_append, raise_on_exhausted=True)` so `nested_entered`, `iteration_started`, `for_each_expanded`, and `item_started` are persisted for valid entries.
4. After mutating traversal returns the leaf, defensively recheck that it is still the same attested `step_id`. In normal single-process lifecycle use this should match; if it does not, do not write the attestation event or move the file. This second check is a race guard, not the primary stale-file filter.
5. Record the attestation as external inbox identity: `attestor_kind="inbox"`, `attestor_id=submitted_by`, and metadata fields for `submitted_at`, `submitted_by`, and `inbox_source_hash`. This explicitly bypasses `ARTAGENTS_ACTOR`/self-ack validation because inbox files are the trusted external signal channel; explicit `ack` keeps the existing identity rules unchanged.
6. Preserve event compatibility for existing tests by keeping the existing `evidence` field as an ack-style list and storing the required object-shaped inbox payload under `inbox_evidence`. Add a small event-maker helper if that keeps this shape centralized.
7. Preserve inline produces checks and iteration/item handling by sharing the post-attestation `GateDecision` construction and check runner used by `_dispatch_attested`.

### Step 3: Consume inbox entries safely (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Implement `consume_inbox_entry(run_dir, entry) -> EventRecord` for entries already identified as actionable. It derives `project_root`, `projects_root`, and `run_id` from `<project>/runs/<run-id>`.
2. Re-run `actionable_inbox_entries(run_dir, [entry])` immediately before mutation. If the entry is now stale, non-current, non-approve, or no longer attested, log and leave both `events.jsonl` and the source file untouched.
3. For still-actionable entries, call `gate_external_attestation`, then move the source file to `.consumed` only after the hash-chained attestation event write succeeds.
4. Use a collision-safe consumed filename: default `<sha256>.json`, with a deterministic suffix if a file already exists for the same hash.
5. Keep `retry` and `abort` out of Phase 8 consumption. They remain parse-valid decisions so producers can use the declared schema, but they are not completion signals and require future explicit semantics/tests before they mutate verifier or active-run state.

### Step 4: Wire lifecycle surfaces and hook-visible behavior (`artagents/core/task/lifecycle.py`, `artagents/core/task/__init__.py`, `artagents/core/task/hook.py` tests)
