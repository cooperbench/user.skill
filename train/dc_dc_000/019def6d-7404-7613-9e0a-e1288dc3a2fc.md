        # Implementation Plan: Packs Layout Migration With No Compatibility Shims

## Overview
ArtAgents currently mixes framework code and registered content under `artagents/executors/`, `artagents/orchestrators/`, and `artagents/elements/`. Registries scan those same directories, manifests point at modules inside them, tests import moved content directly, and Remotion resolves bundled/managed/override elements through aliases that point at the old element layout.

The migration target remains a clean split:

- `artagents/core/executor/`, `artagents/core/orchestrator/`, and `artagents/core/element/` hold framework code only.
- `artagents/packs/<pack>/pack.yaml` marks a pack.
- `artagents/packs/<pack>/<thing>/executor.yaml|orchestrator.yaml|element.yaml` holds registered content.
- Qualified ids are mandatory. Bare-name resolution is removed.
- No compatibility shims, fallback path lookups, migration commands, or old element source roots remain.

Root-cause check from critique: the plan is still targeting the right architectural problem, but the first draft blurred two identity rules. Pack identity must preserve existing qualified ids, so a thing with id `external.moirae` belongs under pack `external`, not under `builtin`. Likewise, the element migration must remove the old `.artagents/elements/managed` and `.artagents/elements/overrides` source model instead of quietly preserving it. This revision makes those calls explicit.
