## Overview
This revision keeps the original root cause: the conductor implementation is mostly correct, but a few first-class conductor boundaries are leaky. No critique flags indicated that the plan is targeting the wrong code path or should replace legacy scheduling, so the approach remains a narrow cleanup around schemas, registry semantics, CLI validation, dry-run structure, and tests/docs.

Current touch points:

- `artagents.conductors.schema` imports neutral primitives from `artagents.nodes.schema`, tying conductor contracts to node ownership.
- Built-in conductors have public ids like `builtin.hype` and `builtin.event_talks`, but are currently discovered through `artagents/conductors/curated/` while `load_builtin_conductors()` is empty.
- `artagents.conductors.cli` requires `run --out` at argparse time, even when `builtin.event_talks --dry-run` only needs passthrough output flags.
- `ConductorRunResult` exposes dry-run commands as shell tuples, but does not expose a structured conductor plan for internal/API callers.
- Real execution must continue to delegate to existing legacy `pipeline.py` and `event_talks.py` behavior.

The concrete defaults for implementation are: use `artagents.contracts.schema` as the neutral shared schema module, and do not physically move built-in conductor package files unless implementation reveals that registry-level source semantics cannot be made honest without a move.
