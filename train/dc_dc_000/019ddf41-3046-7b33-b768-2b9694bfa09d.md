        # Implementation Plan: ArtAgents Node Architecture MVP

## Overview
ArtAgents currently has a cache-aware pipeline orchestrator in `artagents/pipeline.py` with a `Step` dataclass, hard-coded `STEP_ORDER`, hard-coded command builders, sentinel-based caching, and subprocess execution (`artagents/pipeline.py:29`, `artagents/pipeline.py:68`, `artagents/pipeline.py:465`, `artagents/pipeline.py:777`, `artagents/pipeline.py:816`). The root `pipeline.py` is only a compatibility launcher, so CLI exposure should be added through `artagents/pipeline.py` while preserving every existing legacy invocation.

The critique does not show that the plan targeted the wrong code or root cause: `artagents/pipeline.py` is still the right integration point because it owns the executable stage list, command builders, cache sentinels, and legacy CLI dispatch. The needed correction is narrower: standalone node execution cannot naively pass a small `NodeRunRequest` into existing `Step.build_cmd(args)` lambdas. Those lambdas expect a fully normalized legacy namespace produced by `resolve_args()` and pre-run preparation such as `prepare_brief_artifacts()`. The revised MVP keeps the node layer beside the existing orchestrator, but adds an explicit legacy context adapter before any built-in node can build or run a command.

The pragmatic MVP remains discovery, validation, CLI exposure, curated external manifest support, and a cheap single-node run/dry-run path. Graph/condition support should be represented in typed metadata plus validation helpers now; full graph orchestration remains outside the MVP to preserve legacy pipeline behavior.

Moirae is a good external boundary fixture because its README describes a terminal-demo video pipeline invoked as `python -m moirae screenplay.yaml -o demo.mp4`, with external prerequisites like `asciinema`, `agg`, and `ffmpeg`. The MVP should include a curated manifest for Moirae, but tests must not require cloning it or installing those binaries.

## Phase 1: Define Node Metadata And Validation

### Step 1: Add the node package skeleton (`artagents/nodes/`)
**Scope:** Medium
1. **Create** `artagents/nodes/__init__.py`, `artagents/nodes/schema.py`, `artagents/nodes/registry.py`, `artagents/nodes/builtin.py`, `artagents/nodes/runner.py`, and `artagents/nodes/cli.py`.
2. **Use** stdlib `dataclasses`, `json`, `string.Formatter`, and explicit validators rather than adding Pydantic, because this repo does not currently depend on Pydantic and the MVP does not need a new runtime dependency.
3. **Model** the core typed schema:
   - `NodeDefinition`: `id`, `label`, `kind` (`built_in` or `external`), `version`, `description`, `inputs`, `outputs`, `command`, `cache_policy`, `conditions`, `graph`, `isolation`, `source`.
   - `NodePort`: `name`, `type`, `required`, `default`, `description`, `path_role`.
   - `NodeOutput`: `name`, `type`, `mode` (`mutate`, `create`, `create_or_replace`), `path`, `description`, optional `placeholder`.
   - `CommandSpec`: `argv` template list, `placeholder_sources` (`inputs`, `outputs`, `runtime`) validated explicitly.
   - `CachePolicy`: `sentinels`, `always_run`, `per_brief`, and optional dependency hints.
   - `Condition`: minimal declarative checks such as `requires_input`, `requires_file`, and `skip_when` for built-in discovery and future graph execution.
   - `Isolation`: `subprocess` as the only MVP execution backend, plus `requires_binaries` and `env_passthrough` metadata.
4. **Implement** `validate_node_definition(raw)` and `load_node_manifest(path)` with clear error messages and no defensive coercions beyond JSON parsing.
5. **Validate** command placeholders against declared input names, declared output placeholders/names, and known runtime placeholders such as `python_exec`, `out`, and `brief_out`. This directly prevents the Moirae `{output}` ambiguity from failing its own manifest when `output` is declared as an output placeholder.

### Step 2: Add curated external manifest support (`artagents/nodes/curated/moirae.json`)
**Scope:** Small
1. **Create** a packaged curated manifest directory under `artagents/nodes/curated/` with an `__init__.py` file so `importlib.resources.files("artagents.nodes.curated")` can discover manifests in a source checkout and in an installed package when package data is included.
2. **Add** `moirae.json` describing Moirae as an external wrapped node:
   - input `screenplay` as a required YAML path.
   - output `video` with `create_or_replace` mode and placeholder `output`.
   - optional runtime `output` override accepted by the runner, defaulting to `<out>/moirae.mp4`.
   - command template equivalent to `{python_exec} -m moirae {screenplay} -o {output}`.
   - isolation metadata listing external requirements (`moirae`, `asciinema`, `agg`, `ffmpeg`) but marking tests as manifest-only unless `--check-binaries` is passed.
3. **Keep** this as a fixture/curated descriptor, not an installer or clone step, to avoid making ArtAgents tests depend on network access or Moirae binaries.
4. **Document** package-data status in code and README: the repo currently has no `pyproject.toml`, `setup.py`, `setup.cfg`, or `MANIFEST.in`, so source-checkout discovery is the verified MVP path. If packaging files are added later, they must include `artagents/nodes/curated/*.json`.

## Phase 3: Runner And CLI Exposure

### Step 5: Add an explicit legacy context adapter for built-in node runs (`artagents/nodes/runner.py`, `artagents/pipeline.py`)
**Scope:** Medium
