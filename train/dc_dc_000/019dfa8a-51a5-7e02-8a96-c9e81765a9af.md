        # Implementation Plan: VibeComfy Memory-Profile MVP

## Overview
VibeComfy already has the right seams for this sprint: `SessionConfig` carries process/runtime config, `_embedded_configuration_for_session()` converts it to embedded Comfy configuration, `_comfy_server_argv()` converts it to managed-server argv, `vibecomfy run` loads a workflow before dispatch, and ready templates preserve per-template `metadata["comfy_configuration"]`. Wan2GP’s externally visible profile labels and process/per-run semantics are visible in `reigh-worker/Wan2GP/wgp.py`, especially `compute_profile()`, `init_pipe()`, and `memory_profile_choices`.

The simplest viable implementation is to add a first-class `MemoryProfile` abstraction in `vibecomfy/`, wire it through `SessionConfig` and CLI flags, and apply per-run overrides to workflow metadata/config before runtime dispatch. Avoid patching worker strings; only apply workflow node-level profile changes if VibeComfy/Comfy custom-node schema exposes a real typed profile input such as WanVideoWrapper’s `WanVideoVRAMManagement`.

## Phase 1: Define The Contract

### Step 1: Add `MemoryProfile` (`vibecomfy/memory_profile.py`)
**Scope:** Medium
1. Implement a small immutable abstraction accepting only profiles `1..5`, with labels mirroring Wan2GP’s public names from `reigh-worker/Wan2GP/wgp.py`.
2. Include helpers for parsing CLI/config values, serializing to metadata, and producing documented runtime effects:
   - process-level config fields such as `vram_policy`, `reserve_vram_gb`, `cache_policy`, `disable_smart_memory` only where operationally proven;
   - optional workflow-level adjustments only through typed VibeComfy graph inputs.
3. Expose restart metadata, e.g. `requires_session_restart=True` for managed-server argv/config changes and `False` for per-run graph-only changes.

### Step 2: Wire Session Config (`vibecomfy/runtime/session.py`)
**Scope:** Medium
1. Add `memory_profile: int | None` to `SessionConfig` while preserving current defaults when it is unset.
2. Update `SessionConfig.from_dict()` and `from_workflow_metadata()` so `memory_profile` round-trips from typed config and `workflow.metadata["comfy_configuration"]`.
3. Update `_embedded_configuration_for_session()` and `_comfy_server_argv()` to emit only proven native Comfy/VibeComfy settings for a profile, and include the profile value in an inspectable config path even if the effective mapping is intentionally conservative.

## Phase 2: Runtime And CLI Semantics

### Step 3: Add Process Defaults (`vibecomfy/commands/session.py`, `vibecomfy/runtime/server.py`)
**Scope:** Medium
1. Add `--memory-profile {1,2,3,4,5}` to `vibecomfy session start` and include it in daemon `config.json`.
2. Allow managed one-shot server startup to receive a `SessionConfig` instead of always constructing `SessionConfig(port=8188)`, so one-shot server round-trip tests can cover profile argv/config.
3. Document in code/tests that changing a managed process profile requires restart when argv-affecting settings change.

### Step 4: Add Per-Run Overrides (`vibecomfy/commands/run.py`, `vibecomfy/runtime/run.py`)
**Scope:** Medium
1. Add `--memory-profile {1,2,3,4,5}` to `vibecomfy run`.
2. Apply the override after workflow load and before dispatch by updating workflow metadata/config through the new `MemoryProfile` helper.
3. Preserve precedence: per-run CLI override wins over workflow metadata; workflow metadata wins over process default for new embedded sessions; an already-running external/managed server keeps its process default unless the override can be applied as graph/session reconfiguration without restart.
4. Record the selected/effective profile and restart requirement in run metadata from `_run_metadata()`.

## Phase 3: Template Smokes

### Step 5: Profile-Aware Template Application (`vibecomfy/registry/ready_template.py`, ready templates as needed)
**Scope:** Medium
1. Add a shared hook that can apply profile metadata to ready-template workflows without editing generated templates directly unless the generator/policy path requires it.
2. For representative WanVideoWrapper templates such as `ready_templates/video/wanvideo_wrapper_21_14b_i2v.py`, verify whether `WanVideoVRAMManagement` or related nodes provide a typed profile-like input; if yes, update through graph APIs and test the compiled API. If no, leave graph unchanged and rely on documented process/session config.
3. Include a non-Wan required template such as `ready_templates/video/wan_t2v.py` as a smoke to ensure profiles do not corrupt ordinary Comfy graphs.

## Phase 4: Tests And Documentation

### Step 6: Round-Trip Unit Tests (`tests/test_memory_profile.py`, `tests/test_runtime_session.py`)
**Scope:** Medium
1. Test parsing/validation for profiles `1..5` and rejection of invalid values.
2. Test `SessionConfig.from_dict()` and `from_workflow_metadata()` preserve profile values.
3. Test `_embedded_configuration_for_session()` receives profile-derived config without losing existing raw HiddenSwitch keys such as `reserve_vram`, `cache_none`, and `fp8_e4m3fn_text_enc`.
4. Test `_comfy_server_argv()` output for every profile where argv changes are proven, and assert no argv/default churn when profile is unset.

### Step 7: CLI And Override Tests (`tests/test_session_cli.py`, `tests/test_run_command.py`)
**Scope:** Medium
1. Extend session CLI tests so `vibecomfy session start --memory-profile N` is persisted into daemon config.
2. Extend run command tests so `--memory-profile N` mutates the workflow/config passed to `run_embedded_sync()` or `run_sync()`.
3. Add precedence tests for process default plus per-run override.

### Step 8: Representative Template Smokes (`tests/test_ready_templates.py` or `tests/test_memory_profile.py`)
**Scope:** Small
1. Compile representative templates under profiles `1..5` and assert validation still passes.
2. For WanVideoWrapper, assert any typed profile node changes are visible in compiled API; otherwise assert the workflow metadata carries the profile and graph stays stable.
3. Add focused snapshots/counters only if graph changes are intentional.

### Step 9: Restart Documentation (`docs/runtime_lifecycle.md` or runtime docstring)
**Scope:** Small
1. Document which profile changes require managed-server restart versus embedded reconfigure versus per-run graph mutation.
2. Keep this narrowly scoped to runtime lifecycle/profile behavior.
