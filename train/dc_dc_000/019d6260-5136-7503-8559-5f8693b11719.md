        # Implementation Plan: Persistent RemotionPreview via DOM Reparenting

## Overview

VideoEditorShell renders two separate `<RemotionPreview>` instances — one in the condensed branch (line 441) and one inside `<PreviewPanel>` in the full branch (line 485/PreviewPanel:54). Switching layouts unmounts one and mounts the other, causing a playback gap. An autoPlay polling hack (lines 75-76, 178-197) partially mitigates this but still produces a visible interruption.

**Goal:** Render a single `<RemotionPreview>` that never unmounts. Use `useLayoutEffect` + DOM `appendChild` to physically move the preview node between layout slots. Remove the autoPlay hack entirely.

**Key constraint:** In condensed mode, a tab switcher toggles between "preview" and "properties" (line 436). The preview slot must remain mounted (not conditionally rendered) even when the properties tab is active — otherwise the reparented DOM node gets destroyed. We'll keep both tab contents always rendered and hide the inactive one with CSS.
