## Phase 1: Pause/Resume Foundation

### Step 1: Add DB-backed system state (`app/services/system_state.py`, `app/services/hooks.py`, `app/services/scheduled_jobs.py`)
**Scope:** Medium

   - `is_paused(pool) -> bool`
   - `paused_for_user(pool, user_id) -> bool` as a global pause check for compatibility with user-scoped callers.
   - `pause(pool, user_id, reason=None, now=None)` that sets `paused_at`, `paused_by_user_id`, `pause_reason`, and `updated_at`.
   - `resume(pool, now=None)` that clears pause fields and updates `updated_at`.
   - `supersede_user_facing_jobs(pool, now=None)` that marks pending `weekly_summary`, `checkin`, `watch_item_due`, `oob_review`, and `deferred_turn` jobs `superseded` while leaving `heartbeat` alone.
2. **Update** `hooks.paused_for_user` so existing callers still work. Prefer a minimal compatibility layer that accepts either `(user_id)` for monkeypatched tests or `(pool, user_id)` for DB-backed call sites; avoid a hidden module-level pool unless existing app startup forces it.
3. **Replace** `scheduled_jobs.is_globally_paused()` direct SQL with the new `system_state.is_paused(pool)` helper so pause logic has one source.

### Step 2: Add pause-aware outbound bypass (`app/services/messaging.py`)
**Scope:** Small
1. **Add** `ignore_pause: bool = False` to `send_outbound(...)`.
2. **Keep** ordinary outbound withheld while paused.
3. **Allow** pause/resume/system-control confirmations through when `ignore_pause=True`; still run the existing OOB/template/window behavior unless the code path already bypasses it.
4. **Update** tests and monkeypatch fakes that spy on `send_outbound` to accept the new keyword.

### Step 3: Handle `/pause` and `/resume` after inbound persistence (`app/services/inbound.py`, `app/services/scheduled_job_handlers.py`)
**Scope:** Medium
1. **Detect** literal text commands only after `_insert_message(...)` succeeds, so the command message itself is persisted and duplicates remain idempotent.
2. **On `/pause`:** call `system_state.pause`, supersede all pending user-facing jobs for both partners, fetch both users, and send the spec confirmation to both partners with `ignore_pause=True` and `TemplateCall("pause_confirmation", [...])` if the template exists or after adding it to `app/services/templates.py`.
3. **On `/resume`:** clear pause, restore weekly summaries via existing durable per-user schedule fields (`seed_weekly_summaries` / `schedule_next_weekly_summary`), send a resume confirmation only if current product copy already supports it, and do not enqueue the stored backlog.
4. **Gate enqueue paths** for text and document directly in `inbound.py` using DB-backed pause checks.
5. **Gate media paths** so voice/image messages still fetch/store/transcribe/analyze as applicable but do not call `coalescer.add(...)` while paused. This likely means adding a pause check in `handle_voice` and `handle_image`, because those functions enqueue after async media processing.
6. **Ensure** `recover_on_startup` also respects pause before replaying old raw messages or crashed turns, so restart does not bypass the pause kill switch.

## Phase 2: Write-Tool Tightening

### Step 4: Make all check-in scheduling transactional and UTC-aware (`app/services/tools/write_tools.py`, `app/services/scheduled_job_handlers.py`, optional shared helper, `tool_schemas.py`, `tests/conftest.py`)
**Scope:** Medium
1. **Identify both check-in writers** before editing: agent-facing `schedule_checkin` in `app/services/tools/write_tools.py` and scheduler/internal `schedule_checkin_job` in `app/services/scheduled_job_handlers.py`, which is called by `handle_watch_item_due`.
2. **Introduce one shared implementation** for supersede-plus-insert if it keeps the code simpler, for example a private helper in `scheduled_job_handlers.py` or a small scheduler-write helper module. Both public call sites must use the same transaction-safe path.
3. **Reject** naive datetimes at schema or tool boundary. Prefer Pydantic validation in `ScheduleCheckinInput`; otherwise reject at the top of `schedule_checkin` with `ToolCallRejected`. Apply the same aware-datetime requirement to internal `schedule_checkin_job` arguments.
4. **Normalize** aware datetimes to UTC before storing, preserving absolute instants.
5. **Wrap** supersede-plus-insert in one DB transaction using `async with pool.acquire() as conn, conn.transaction(): ...` so both writers cooperate with `idx_scheduled_jobs_one_pending_checkin_per_user`.
6. **Use** a partial-unique-compatible SQL pattern: supersede existing pending check-ins for the user, then insert exactly one pending check-in. If an asyncpg unique-violation race can still happen, retry the supersede/insert once inside the shared helper rather than adding broad fallback behavior.
7. **Keep** return shapes compatible: `schedule_checkin` still returns `ScheduleCheckinOutput`, and `schedule_checkin_job` still returns the row needed by scheduled handlers.
8. **Update** `FakePool`/`FakeConnection` narrowly to support `fetchrow`, `execute`, and `transaction()` on acquired connections.

### Step 5: Gate escalation from trusted turn metadata (`app/services/turn_context.py`, `app/services/agentic.py`, `app/services/tools/write_tools.py`)
**Scope:** Medium
