        # Implementation Plan: Make VideoGenerationModal Sections Fully Interactive

## Overview
The VideoGenerationModal currently renders three collapsible ModalAccordionSections (Shot Images, Final Video, Generation Settings) in a read-only state with no-op callbacks. The goal is to make Shot Images and Final Video fully interactive — supporting image reorder, drag/drop, delete, upload, mode switching, video playback, sharing, etc. — and to reorder/conditionally render sections.

**Current state:**
- `ModalShotImagesEditor` uses `readOnly: true` and stubs all callbacks with `noop`/`noopAsync` (`VideoGenerationModalSections.tsx:289-329`)
- `FinalVideoSection` rendered with `readOnly` prop (`VideoGenerationModalSections.tsx:444`)
- Section order: Shot Images → Final Video → Generation Settings
- `useVideoGenerationModalController` returns `shotGenerations` (from `useShotImages`) but no mutation handlers

**Key design decision:** Rather than wrapping the modal in `ShotSettingsProvider` (which requires full `ShotEditorState`, structure video hooks, audio hooks, join state, etc.), build a lightweight `useModalImageHandlers` hook that directly composes the existing mutation hooks (`useRemoveImageFromShot`, `useAddImageToShot`, `useHandleExternalImageDrop`, `useDuplicateAsNewGeneration`). These mutation hooks are standalone React Query mutations with no coupling to the ShotEditor state machine.

## Phase 1: Reorder + Conditional Rendering (No New Logic)

**Scope:** Small
1. **Move** the Final Video `ModalAccordionSection` block (lines 435-446) to render ABOVE the Shot Images section (lines 422-433), so the order becomes: Final Video → Shot Images → Generation Settings.

3. **Thread `shotId`** into `VideoGenerationModalAccordionContent` — it already receives `positionedImages` and `shotGenerations` but needs the raw `shotId` for the `useVideoOutputs` query. Add it to `VideoGenerationModalAccordionContentProps`.

### Step 4: Build `useModalImageHandlers` hook (new file: `hooks/useModalImageHandlers.ts`)
**Scope:** Medium
1. **Create** `src/tools/travel-between-images/components/hooks/useModalImageHandlers.ts`.
2. **Compose** existing mutation hooks directly:
   - `useRemoveImageFromShot()` — for `onDelete` and `onBatchDelete`
   - `useAddImageToShot()` — for `onGenerationDrop`, `onBatchGenerationDrop`
   - `useHandleExternalImageDrop()` — for `onFileDrop`, `onBatchFileDrop`
   - Image reorder: call `updateShotImagePositions` RPC (same pattern as `handleImageReorder` in `useShotSettingsValue.ts`)
   - Upload: use the same pattern as `handleImageUpload` in `useShotSettingsValue.ts`
3. **Interface:** `useModalImageHandlers(shotId: string, projectId: string, orderedImages: GenerationRow[])` → returns `ShotImageHandlers` shape.

   - No `pendingFramePositions` state (modal doesn't need optimistic timeline updates)
   - No `duplicatingImageId` animation state
   - No structure video handlers (omit optional callbacks)
   - No audio handlers (omit optional callbacks)
   - After mutations: invalidate the `shotGenerations` query key so the modal data refreshes

### Step 5: Wire real handlers into ModalShotImagesEditor (`VideoGenerationModalSections.tsx`)
**Scope:** Medium

   - `onGenerationDrop` → `handlers.onGenerationDrop`
   - `onBatchFileDrop` → `handlers.onBatchFileDrop`
   - `onBatchGenerationDrop` → `handlers.onBatchGenerationDrop`
   - `onImageDelete` → `handlers.onDelete`
   - `onBatchImageDelete` → `handlers.onBatchDelete`
   - `onImageDuplicate` → `handlers.onDuplicate` (or leave undefined if skipping for now)
   - `onImageUpload` → `handlers.onUpload`
   - `onOpenUnpositionedPane` → noop (not applicable in modal context)
   - Structure video / audio callbacks → omit (optional in interface)
4. **Remove** `readOnly: true` from the displayOptions.
