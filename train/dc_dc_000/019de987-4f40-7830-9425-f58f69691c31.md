**Findings**

- There is no public barrel/API at `src/tools/video-editor`; consumers import deep internals directly. The only obvious top-level entrypoints are `VideoEditorPage`, `VideoEditorProvider`, `VideoEditorShell`, `DataProvider`, and many deep component/hook exports.
- The cleanest external seam is the persistence adapter: [DataProvider.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/data/DataProvider.ts:53) defines `loadTimeline`, `saveTimeline`, registry, upload, waveform, and profile methods. This is a useful contract for swapping storage.
- `VideoEditorProvider` is not just editor state injection. It pulls in router search params, app agent chat, shots, selection store, media lightbox, custom effects, and pending generation-add behavior: [VideoEditorProvider.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/contexts/VideoEditorProvider.tsx:69), [VideoEditorProvider.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/contexts/VideoEditorProvider.tsx:106), [VideoEditorProvider.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/contexts/VideoEditorProvider.tsx:340). It is reusable inside the Reigh app, but not a lightweight editor-provider boundary.
- Runtime injection is small and clear: [DataProviderContext.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/contexts/DataProviderContext.tsx:4) exposes `{ provider, timelineId, userId, timelineName }`, and `useVideoEditorRuntime` hard-requires the wrapper at [DataProviderContext.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/contexts/DataProviderContext.tsx:27).
- The main context/store API is split into data, ops, chrome, and playback slices, which is good for component authors: [timelineStore.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/timelineStore.ts:460). The slice contracts are large and strongly coupled to internal hooks via `ReturnType<typeof useX>`: [useTimelineState.types.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useTimelineState.types.ts:56), [useTimelineState.types.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useTimelineState.types.ts:92).
- `useTimelineState` is the real composition root. It wires app mobile hooks, project context, React Query, data provider, save/history/render/playback/assets/drag/drop/editing/track management: [useTimelineState.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useTimelineState.ts:417), [useTimelineState.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useTimelineState.ts:444), [useTimelineState.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useTimelineState.ts:578).
- `VideoEditorShell` exposes only `mode`, `timelineId`, and `onCreateTimeline`: [VideoEditorShell.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/VideoEditorShell.tsx:70). It owns layout, toolbar, preview portal, render/download controls, timeline, properties, dialogs, and responsive behavior internally: [VideoEditorShell.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/VideoEditorShell.tsx:622), [VideoEditorShell.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/VideoEditorShell.tsx:637). Good app shell, poor compositional API.
- `PreviewPanel`, `PropertiesPanel`, `TimelineEditor`, and `CompactPreview` are context-bound rather than prop-driven. Examples: [PreviewPanel.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/PreviewPanel/PreviewPanel.tsx:21), [PropertiesPanel.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/PropertiesPanel/PropertiesPanel.tsx:18), [TimelineEditor.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineEditor.tsx:194), [CompactPreview.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/CompactPreview.tsx:23). Developers can place them only under the full provider/store environment.
- Some leaf components are genuinely reusable. `RemotionPreview` has a narrow prop/ref contract around `ResolvedTimelineConfig`: [RemotionPreview.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/PreviewPanel/RemotionPreview.tsx:11), [RemotionPreview.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/PreviewPanel/RemotionPreview.tsx:19). `ParameterControls` is cleanly prop-driven: [ParameterControls.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/ParameterControls.tsx:9). `ClipPanel` is also prop-driven, but its props are very broad and it still reaches into runtime/effect resources: [ClipPanel.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/PropertiesPanel/ClipPanel.tsx:25), [ClipPanel.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/PropertiesPanel/ClipPanel.tsx:17).
- `TimelineCanvas` is the most reusable timeline primitive, with explicit rows/tracks/handlers props: [TimelineCanvas.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx:72). But the higher-level `TimelineEditor` wraps it with Reigh-specific shots, project, generation modal, final-video, stale variant, and selection logic: [TimelineEditor.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineEditor.tsx:14), [TimelineEditor.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineEditor.tsx:200).
- Types are centralized and useful for consumers: [types/index.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/types/index.ts:226), [types/index.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/types/index.ts:263). But component prop interfaces are often unexported, so reusable component contracts are discoverable by source, not importable.

**Bottom Line**

The editor exposes good internal primitives, but the practical public API is still “mount the Reigh video editor shell under the full provider.” For developers building custom UI on top, the useful pieces are `DataProvider`, store selectors, `ResolvedTimelineConfig` types, `RemotionPreview`, `ParameterControls`, and maybe `TimelineCanvas`. Most higher-level UI hides too much behavior behind `VideoEditorProvider`/`VideoEditorShell` and app-level contexts to be comfortably recomposed.
