## Overview
The critique step currently has its 5 required checks defined inline in three places: the prompt text (`prompts.py:642-659`), the category mapping in the handler (`handlers.py:261-267`), and implicitly in the mock payload (`workers.py:346-369`). The schema (`schemas.py:123-170`) defines the `checks` array shape but not the specific check IDs.

**Goal:** Create a single source of truth (`checks.py`) defining all critique checks as structured data, expand from 5 to 7 checks, generate pre-filled templates, validate check completeness with retry, surface check results at the gate, and handle iteration 2+ by injecting prior findings. All changes must be backward-compatible with existing critique artifacts that only have 5 checks.

## Phase 1: Foundation — Single Source of Truth

### Step 1: Create `megaplan/checks.py` as the canonical check registry
**Scope:** Small
1. **Create** `megaplan/checks.py` with a `CRITIQUE_CHECKS` list of dataclass/dict entries, each containing:
   - `id: str` — e.g. `"callers"`
   - `question: str` — the question the reviewer must answer
   - `instruction: str` — the guidance for how to investigate
   - `category: str` — the flag category when flagged (e.g. `"correctness"`)
   - `default_severity: str` — default severity_hint when flagged (e.g. `"likely-significant"`)
2. **Include** the existing 5 checks (`callers`, `all_locations`, `conventions`, `issue_hints`, `scope`) plus 2 new ones (see Assumptions).

   - `build_empty_template() -> list[dict]` — returns pre-filled check dicts with `finding: ""`, `flagged: False`

### Step 2: Wire `checks.py` into `prompts.py` (`megaplan/prompts.py:642-669`)
**Scope:** Medium
