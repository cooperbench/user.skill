## Background

The `seinfeld.lora_train` orchestrator (`astrid/packs/seinfeld/lora_train/run.py`) chains: provision → repo_setup → **aitoolkit_stage** → aitoolkit_train → lora_eval_grid → human gate → resume. The training step (`aitoolkit_train/run.py`) runs `python3 run.py /workspace/config.yaml`. ## Behavior

### Dataset source resolution

Read the manifest at `args.manifest` (path supplied by orchestrator). For each clip in `manifest["clips"]`:
- `clip_file` is repo-root-relative — resolve against `REPO_ROOT` (parents[4] of run.py).
- `caption_file` similarly.

In `--smoke` mode, take only the first 5 clips. In normal mode, take all of them.

Strategy options (pick one, document why):
1. **Symlink farm**: create `_dataset_staging/` and symlink each clip + caption into it, then upload. Pros: doesn't duplicate 133MB; cons: sftp_walk might follow or skip symlinks unpredictably.
2. **Copy farm**: create `_dataset_staging/<bucket>/<clip_id>.mp4` + `.caption.json` copies. Disk-heavy but reliable.
3. **Direct upload from accepted/**: just point `--local-root` at `runs/seinfeld-dataset/accepted/`. Simple, but uploads ALL clips even in smoke mode.

Recommendation: copy farm (option 2) — simplest, predictable, doesn't blow disk for 133MB. In smoke mode, only copies 5 clips so even smaller.

### Default remote path
`/workspace/dataset` — match what the ai-toolkit config's `datasets.folder_path` points at (we already set this in the generated config). Make it configurable via `--dataset-remote-path` for flexibility.

### Dry-run behavior
In `args.dry_run`, skip the actual upload exec call — just print what would be uploaded.
