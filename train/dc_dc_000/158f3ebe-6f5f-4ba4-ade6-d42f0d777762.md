        # Implementation Plan: Orchestrator V1 Phase 2 — `code`, `attested`, `nested` step kinds

## Overview
Phase 1 already shipped the kernel under `artagents/core/task/` (events, active_run, plan, env, gate). Today's `plan.json` only knows shape `{id, command}`, the gate matches commands by exact-string equality (`gate.py:74`), and the cursor is a flat count of `step_completed` events (`gate.py:69`). Phase 2 introduces three explicit step kinds — and the data structures the gate needs to reason about a tree of steps — without breaking existing pack manifests.

Critical design points raised by review:

- **Cursor is a path, not an index.** A flat counter cannot model nested traversal. The gate replays events to rebuild a *path stack* of `(plan_step_id, child_index)` frames: `nested_entered` pushes a frame, `nested_exited` pops, `step_completed` / `step_attested` advances the current frame's child index. The "next step" is then the step at the path tip.
- **Per-kind command matching.** `code` keeps strict-equality (`command == step.command`). `attested` uses a *prefix-match* helper that strips identity (`--agent`, `--actor`) and evidence (`--evidence`) tokens before comparing, so `step.command` is the stable canonical lifecycle prefix and runtime tokens never break gating. `nested` is implicit — there is no caller-supplied command to match for nested entry; the gate emits `nested_entered` automatically when the cursor lands on a `nested` step.
- **Path-qualified `plan_step_id` on events.** `step_completed` / `step_attested` / `step_dispatched` / `nested_entered` / `nested_exited` carry `plan_step_id` as a slash-separated path (e.g., `"s2/c1"`), so identical leaf ids in different subtrees are unambiguous on replay.
- **Phase 2 is kernel-only for attested and nested.** No new CLI verbs (Phase 5 reserves them). Attested and nested are exercised via direct `gate_command(...)` calls in unit tests with synthetic argv. The Phase 2 exit criterion "attested and nested dry runs emit expected events" is reached by the kernel surface, not by `artagents` subcommands.

The phase remains additive. Existing pack-side `OrchestratorDefinition` JSON manifests with `RUNTIME_KINDS={python,command}` keep loading unchanged. No DSL (Phase 4), no lifecycle CLI verbs (Phase 5), no produces-inline-checks/repeat (Phase 3), no CAS (Phase 7).

Sibling-id collisions inside one frame are rejected; identical leaf ids in different subtrees are allowed because their paths differ.

### Step 4: Replace the cursor with a path-stack walker and dispatch by kind (`artagents/core/task/gate.py`)
**Scope:** Medium
1. **Replace** the flat counter (`gate.py:67-69`) with `derive_cursor(plan, events) -> CursorPath`:
   - Replay `events.jsonl` left-to-right with a frame stack initialized to `[Frame(plan=plan, child_index=0)]`.
   - On `nested_entered`: push `Frame(plan=current_step.plan, child_index=0)` (look up the step at the current path before pushing).
   - On `nested_exited`: pop and increment the parent frame's `child_index`.
   - On `step_completed` or `step_attested`: increment the top frame's `child_index`.
   - On `step_dispatched`: do not advance (it is paired with a future `step_completed`).
   - The result is a path tuple `(parent_id, child_id, ...)` pointing at the next step to dispatch, or a `done` sentinel when the root frame's `child_index` reaches `len(steps)`.
2. **Add** an entry-loop after cursor derivation: while the step at the cursor is a `NestedStep`, emit `nested_entered` (with `child_plan_hash = compute_plan_hash` over the inlined child plan's serialized form), push the frame, and recompute the cursor. When a frame's `child_index` equals `len(steps)`, emit `nested_exited` (returncode 0 on clean fall-through), pop, and continue. This makes nested traversal automatic — no caller-side verb is needed in Phase 2.
3. **Per-kind command matching** in `gate_command`:
   - `code`: keep `command == step.command` (existing semantics).
   - `attested`: implement `match_attested_command(incoming: str, expected_prefix: str) -> tuple[bool, AttestedArgs]` that:
     - Tokenizes `incoming` via `shlex.split`.
     - Splits off recognized identity/evidence flags (`--agent <id>`, `--actor <name>`, `--evidence <path>` — repeatable).
     - Rejoins the remainder via `shlex.quote` and compares to `expected_prefix`.
     - Returns the parsed `AttestedArgs(agent: str | None, actor: str | None, evidence: tuple[str, ...])`.
   - `nested`: not caller-driven; the entry-loop in Step 4.2 handles it.
4. **Attested gating rules**:
   - Reject when neither `--agent` nor `--actor` is present, or both are present.
   - Reject when `step.ack.kind == "agent"` and only `--actor` was provided (or vice versa).
   - When `kind="actor"`: require `task_actor_env() == actor_value`. Reject as **self-ack** when `run_started.actor == actor_value` and `task_actor_env() == actor_value` (the operator who started the run is also the operator acking under the same identity).
   - Recovery for any of the above is `artagents next --project <slug>` (mismatch class), not `abort`.
   - On success, emit `step_attested` directly inside `gate_command`. There is no companion `record_dispatch_complete` for attested; the event itself advances the cursor.
5. **Path discipline on event emission**: every event the gate writes carries the path-qualified `plan_step_id` constructed from the current frame stack (e.g., `"s2/c1"`). For top-level steps the path equals the bare id, preserving Phase 1 wire format.
6. **Add** kernel-level helpers next to `record_dispatch_complete`:
   - `record_step_attested(decision, attestor_kind, attestor_id, evidence)` — public for symmetry but unused by the gate's inline emission; reserved for Phase 5 lifecycle verbs.
   - `record_nested_entered(decision, child_plan_hash)` and `record_nested_exited(decision, returncode)` — also reserved; the gate's auto-traversal calls private helpers internally.
7. **Note** in a one-line module comment that Phase 2 attested/nested are kernel-only and Phase 5 will add `artagents ack` / `artagents next` verbs that drive these helpers.
