**Root Cause**

The failing template is hand-authored and diverges from the cited Kijai source workflow.

In [wanvideo_wrapper_22_14b_t2i.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/ready_templates/video/wanvideo_wrapper_22_14b_t2i.py:44), metadata points at Kijai’s `wanvideo_2_2_14B_Pusa_extension_example_01.json`, but the graph uses an explicit `LoadWanVideoT5TextEncoder` node at [line 63](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/ready_templates/video/wanvideo_wrapper_22_14b_t2i.py:63) plus `WanVideoTextEncode` at [line 75](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/ready_templates/video/wanvideo_wrapper_22_14b_t2i.py:75).

Kijai’s actual Wan 2.2 14B Pusa example uses `WanVideoTextEncodeCached`, not a graph-level `LoadWanVideoT5TextEncoder`. Upstream source confirms `LoadWanVideoT5TextEncoder` is real and registered by `ComfyUI-WanVideoWrapper`, so the live error means the runtime did not have that class registered at validation time, and this template unnecessarily exposes that fragile loader as a workflow node.

There is also a catalog/manifest gap: [vibecomfy/node_packs.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/node_packs.py:20) lists only a subset of WanVideoWrapper classes. `install-plan` reports these as unmapped for this template: `WanVideoBlockSwap`, `WanVideoLoraSelectMulti`, `WanVideoSetBlockSwap`, `WanVideoSetLoRAs`. It also lacks `WanVideoTextEncodeCached`, which the patch should use.

**Patch Recommendation**

1. In `ready_templates/video/wanvideo_wrapper_22_14b_t2i.py`, replace node `11` + node `16` with one `WanVideoTextEncodeCached` node:
   - class type: `WanVideoTextEncodeCached`
   - widgets: model name, `bf16`, positive prompt, negative prompt, `disabled`, `True`, `gpu`
   - wire output `0` to both sampler `text_embeds` inputs.

2. Add `WanVideoTextEncodeCached`, `WanVideoBlockSwap`, `WanVideoLoraSelectMulti`, `WanVideoSetBlockSwap`, and `WanVideoSetLoRAs` to the `ComfyUI-WanVideoWrapper` class set in `vibecomfy/node_packs.py`.

3. For actual Kijai Pusa parity, also replace the LoRA/sampler settings:
   - add Pusa HIGH/LOW LoRA model assets;
   - use Pusa HIGH/LOW LoRAs plus Lightx2v as in upstream;
   - use scheduler value `flowmatch_pusa`, not plain `euler`;
   - consider the upstream `WanVideoAddPusaNoise` path if this template is meant to match the Pusa workflow rather than just “single-frame Wan 2.2”.

4. Apply the same text-encoder change to the VACE parity template: [wanvideo_wrapper_22_14b_vace_cocktail.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/ready_templates/video/wanvideo_wrapper_22_14b_vace_cocktail.py:87) has the same explicit T5-loader pattern.
