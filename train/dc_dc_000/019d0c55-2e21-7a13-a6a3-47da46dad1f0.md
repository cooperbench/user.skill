# Implementation Plan: `desloppify setup` CLI Command (v3)

## Context

Currently, the desloppify skill is only available as a Claude Code skill when working inside the desloppify repo itself, or after running `update-skill` (which downloads from GitHub per-project). The `setup` command makes it globally available on any machine right after `pip install desloppify`, using bundled files — no network required.

**Key distinction from `update-skill`:**
- `update-skill` = per-project, downloads latest from GitHub, installs relative to project root
- `setup` = machine-wide global install from **bundled** package data, installs to `~/` paths. Works offline.

**Who reads global skill files?** The AI tools themselves (Claude Code, Cursor, etc.) discover and load skills from home-directory paths. Desloppify's own `find_installed_skill()` currently only checks project-relative paths — the plan extends discovery to also check global paths so the scan workflow doesn't emit false "no skill document found" warnings.

## Step 2: Define and validate global target paths

### Path registry with provenance

Create a `GLOBAL_TARGETS` dict in `desloppify/app/commands/setup/cmd.py` with explicit documentation of where each path comes from:

```python
# Global install paths — where each AI tool discovers user-level skills.
#
# These paths are NOT validated by the desloppify repo itself; they depend
# on external tool behavior.  Sources:
#
#   claude: Claude Code reads ~/.claude/skills/<name>/SKILL.md
#           (same relative structure as the project-level .claude/skills/
#           path already in SKILL_TARGETS, but rooted at $HOME)
#   cursor: Cursor reads ~/.cursor/rules/<name>.md for global rules
#           (project-level equivalent: .cursor/rules/ in SKILL_TARGETS)
#
# The setup command validates that the parent tool directory exists (~/.claude/,
# ~/.cursor/) before writing, so it won't create orphan files for tools the
# user hasn't installed.

GLOBAL_TARGETS: dict[str, tuple[str, str, str]] = {
    # interface → (path relative to ~/, overlay name, tool config dir to check)
    "claude": (".claude/skills/desloppify/SKILL.md", "CLAUDE", ".claude"),
    "cursor": (".cursor/rules/desloppify.md", "CURSOR", ".cursor"),
}
```

### Pre-flight validation

Before writing each target, check that the tool's config directory exists at `Path.home() / tool_config_dir`. If it doesn't:
- **Single interface mode** (`--interface claude`): raise `CommandError` with "~/.claude/ not found — Claude Code doesn't appear to be installed."
- **All-targets mode** (no `--interface`): skip that target with a yellow warning: "Skipping claude (~/.claude/ not found)" and continue with other targets. If *all* targets are skipped, error with: "No supported AI tools detected. Install Claude Code or Cursor first, or use --interface to force."

This ensures we never silently write files into directories that no tool will ever read.

**Codex is excluded from global targets for now.** The existing `SKILL_TARGETS` maps codex to `.agents/skills/` (project-relative), while `runner_failures.py` references `~/.codex/skills` — these are inconsistent. The `--interface codex` flag will emit a clear message: "Codex global skill path is not yet confirmed. Use `desloppify update-skill codex` for per-project install."

## Step 3: Create the `setup` command module

**Create `desloppify/app/commands/setup/__init__.py`** and **`desloppify/app/commands/setup/cmd.py`**.

### Global mode (default: `desloppify setup`)

Logic:
1. Read bundled files via `importlib.resources.files('desloppify.data.global')`
2. For each target in `GLOBAL_TARGETS`:
   a. Check `Path.home() / tool_config_dir` exists (pre-flight, see Step 2)
   b. Assemble base SKILL.md + interface overlay (reuse `_build_section` from update_skill)
   c. Resolve `Path.home() / rel_path`, create parent directories
   d. Write file via `safe_write_text`
3. Print summary: which targets installed, which skipped, full paths written

Support `--interface` flag to install only one target (e.g. `desloppify setup --interface claude`).

### Local mode (`desloppify setup --local`)

**Uses project root, not cwd.** Consistent with the rest of the codebase: `get_project_root()` resolves the install target, so running from a subdirectory still writes to the correct location.

**Requires `--interface` to pick the overlay.** Because AGENTS.md is a shared target for windsurf, gemini, and hermes — each with distinct overlay content (e.g., Hermes has `delegate_task` instructions, Windsurf/Gemini have different workflows) — the command must know which overlay to apply.

Logic:
1. Require `--interface` when `--local` is set. Error with clear message if omitted: "AGENTS.md is shared by multiple interfaces. Specify one: --interface windsurf|gemini|hermes"
2. Read bundled SKILL.md + the specified overlay
3. Assemble with `_build_section`
4. Resolve `get_project_root() / "AGENTS.md"`
5. If AGENTS.md already exists, use `_replace_section` (begin/end markers) to replace only the desloppify section, preserving other content
6. If new file, write the assembled content directly
7. Print what was written and where

### Shared logic reuse

Import directly from `update_skill.cmd`:
- `_build_section()` — assembles base + overlay
- `_replace_section()` — section replacement for shared files
- `_ensure_frontmatter_first()` — for targets that need it

## Step 5: Extend skill discovery to cover global installs

**Addresses the scan workflow gap.** Currently `find_installed_skill()` only searches project-relative paths, and `auto_update_skill()` in `agent_context.py:420-426` calls it to decide whether to print "No skill document found." After `desloppify setup`, a user with a global install but no per-project install would still see that false warning during every scan.

### Changes to `desloppify/app/skill_docs.py`:

Add `GLOBAL_SKILL_SEARCH_PATHS` (paths relative to `Path.home()`):
```python
GLOBAL_SKILL_SEARCH_PATHS = (
    ".claude/skills/desloppify/SKILL.md",
    ".cursor/rules/desloppify.md",
)
```

Add `find_global_skill() -> SkillInstall | None` — same logic as `find_installed_skill()` but searches `Path.home() / path` instead of `get_project_root() / path`. Returns a `SkillInstall` with `rel_path` prefixed by `~/` for display purposes.

Update `check_skill_version()` to also check global installs. If no project-local install is found but a stale global install exists, warn: "Your global desloppify skill is outdated (vN, current vM). Run: desloppify setup"

### Changes to `desloppify/app/commands/scan/reporting/agent_context.py`:

Modify the post-check in `auto_update_skill()` (lines 419-432):

```python
install = skill_docs_mod.find_installed_skill()
if not install:
    # Check global install before warning.
    global_install = skill_docs_mod.find_global_skill()
    if global_install and not global_install.stale:
        return  # Global install is current — no warning needed.
    elif global_install and global_install.stale:
        print(
            f"Global skill document is outdated "
            f"(v{global_install.version}, current v{skill_docs_mod.SKILL_VERSION}). "
            f"Run: desloppify setup"
        )
    else:
        names = ", ".join(sorted(skill_docs_mod.SKILL_TARGETS))
        print(
            f"No skill document found. Install one for better workflow guidance: "
            f"desloppify update-skill <{names}>"
        )
elif install.stale:
    print(
        f"Skill document is outdated "
        f"(v{install.version}, current v{skill_docs_mod.SKILL_VERSION}). "
        f"Run: desloppify update-skill"
    )
```

**Do NOT change `_try_auto_update_skill()`'s auto-download behavior.** Auto-update remains project-scoped. Global installs are updated explicitly via `desloppify setup`.
