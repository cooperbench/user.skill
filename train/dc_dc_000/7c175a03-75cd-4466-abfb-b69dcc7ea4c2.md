     2→
     3→`desloppify` now treats the queue as one explicit cycle:
     4→
     5→`scan -> review -> workflow -> triage -> execute -> scan`
     6→
     7→## Rules
     8→
     9→- `scan` is a first-class queue phase.
    10→- `review` covers two entry paths:
    11→  - initial subjective assessment after a fresh scan
    12→  - post-execution non-objective review work after objective execution drains
    13→- `workflow` covers post-review workflow items such as score communication,
    14→  score import, and plan creation.
    15→- `triage` follows workflow and exposes only triage stages.
    16→- `execute` exposes only objective fix work and execution clusters.
    17→
    18→## Deferred Disposition
    19→
    20→Deferred disposition is part of the `scan` boundary, not a separate cycle
    21→phase. If deferred temporary skips exist, they block the scan step until the
    22→user reactivates or permanently dispositions them.
    23→
    24→## Persisted Phase vs Safety Net
    25→
    26→The current lifecycle phase is persisted in `plan.refresh_state.lifecycle_phase`

    28→phase from current visible items as a safety net, so stale saved phase state

    31→## Completion Authority
