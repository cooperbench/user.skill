        # Implementation Plan: Adjustment Layer / Effect Layer Clips

## Overview

Add a new `'effect-layer'` clip type to the video editor timeline. These clips live on visual tracks, carry no media asset, and apply a continuous effect to all visual content on tracks below them for their duration. The timeline stores everything as JSONB in a single `config` column — no DB migration is needed.

**Current state:**
- `ClipType = 'media' | 'hold' | 'text'` (`types/index.ts:38`)
- Clips carry optional `continuous`, `entrance`, `exit` effect fields, but these only affect the clip itself
- `TimelineRenderer.tsx` renders visual tracks independently in reverse z-order (bottom track first)
- Effects are applied per-clip via `wrapWithClipEffects()` in `effects/index.tsx:109`
- Clip duration for static content uses `hold` (seconds) — effect-layer clips will use the same mechanism
- No drag-from-effect-creator or effect-layer concept exists yet

**Key constraint:** The hardest part is rendering. Currently each track is independent. Effect layers must wrap _all lower-track content within a time range_ with an effect component. This requires restructuring `TimelineRenderer` to detect effect-layer clips and group lower tracks into wrapable segments.

## Phase 2: Rendering — Remotion Composition

### Step 6: Restructure `TimelineRenderer` to support effect layers (`src/tools/video-editor/compositions/TimelineRenderer.tsx`)
**Scope:** Large — this is the critical change
1. **Separate** effect-layer clips from regular clips in the `clipsByTrack` grouping (line 81).
2. **Build** a render plan that identifies effect-layer time ranges:
   - For each visual track (rendered bottom-to-top), check if any clip is `clipType === 'effect-layer'`
   - For each effect-layer clip, determine its frame range (`at` to `at + hold`)
   - All content from tracks below it within that frame range must be wrapped with the effect
3. **Implement** the wrapping strategy:
   - Render lower tracks into an `AbsoluteFill` group
   - Wrap that group with the continuous effect component using the existing `lookupEffect` + effect registry
   - Use Remotion's `Sequence` to scope the effect to the correct time range
   - Handle stacking: multiple effect layers compose top-down (each wraps everything below it)

   Concrete approach:
   ```tsx
   // Pseudocode for the new render flow:
   // 1. Sort visual tracks bottom-to-top (already done via .reverse())
   // 2. Start with the bottommost track's content
   // 3. For each track going up:
   //    a. If track has effect-layer clips, for each time range:
   //       wrap all accumulated content in that range with the effect
   //    b. If track has regular clips, render them on top
   // This requires splitting the flat track-by-track render into a
   // recursive/accumulative approach.
   ```

4. **Create** an `EffectLayerSequence` component that:
   - Takes `continuous` effect config + time range + children
   - Looks up the effect component from the registry
   - Wraps children with `<Sequence>` + effect component

### Step 7: Handle effect-layer clips in `VisualClip` rendering (`src/tools/video-editor/compositions/VisualClip.tsx`)

        # Implementation Plan: Adjustment Layer / Effect Layer Clips

## Overview

Add a new `'effect-layer'` clip type to the video editor timeline. These clips live on visual tracks, carry no media asset, and apply a continuous effect to all visual content on tracks below them for their duration. The timeline stores everything as JSONB in a single `config` column — no DB migration is needed.

**Current state:**
- `ClipType = 'media' | 'hold' | 'text'` (`src/tools/video-editor/types/index.ts:38`)
- Clips carry optional `continuous`, `entrance`, `exit` effect fields, but these only affect the clip itself
- `TimelineRenderer.tsx` renders visual tracks independently in reverse z-order (bottom track first)
- Effects are applied per-clip via `wrapWithClipEffects()` in `src/tools/video-editor/effects/index.tsx:109`
- Clip duration for static content uses `hold` (seconds) — effect-layer clips will use the same mechanism
- The footer of `TimelineCanvas.tsx:560-601` has a draggable text-tool circle — the effect-layer drag source follows this same pattern
- No effect-layer concept exists yet

**Settled decisions (from prior iteration):**
- Reuse existing `continuous` field on `TimelineClip` for the effect-layer's effect config (DECISION-001)
- Effect-layer clips use `hold` for duration (DECISION-002)
- Rendering uses React composition within Remotion (DECISION-003)

**Design decision — same-track overlap (FLAG-003 resolution):**
Effect-layer clips on the **same track** are forbidden from overlapping. The timeline already prevents media clip overlap on a track; effect layers follow the same rule. Stacking requires placing effect layers on **different visual tracks** — the higher track's effect wraps everything below, giving deterministic composition order via the existing track z-order. This avoids introducing a secondary ordering mechanism and matches user mental model (track stack = layer order).
