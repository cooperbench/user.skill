## Overview

The megaplan execute→review pipeline works but has friction points surfaced by real usage: gate decisions get re-litigated by the reviewer, executor notes describe actions instead of proving correctness, the path-extraction audit fires false positives, mock payloads are duplicated across 5 test files (~78 occurrences of task/evidence fields), and robustness level only changes critique tone without affecting workflow structure.

The repository is a single-package Python project (`megaplan/`) with 6 core modules, 5 test files, and a mock-worker system in `workers.py`. State flows through a linear state machine (`_core.py:442-466`) with handler functions in `handlers.py` (1616 lines). All changes are internal — no external API contracts change.

Constraints: keep the state machine transitions backward-compatible, ensure `test_workflow_mock_end_to_end` keeps passing throughout, and avoid schema changes that break existing plan directories.

## Phase 1: Cheap Fixes — Audit Check + Executor Notes Prompt

### Step 1: Evaluate and fix the path-extraction audit check (`megaplan/evaluation.py`)
**Scope:** Small
1. **Inspect** `_extract_note_paths` (`evaluation.py:108-120`) and the `_PATH_TOKEN_RE` regex (`evaluation.py:40`).
2. **Reproduce** the false positives: strings like `execute/review` and `258/258` match the unquoted-path branch of the regex because they contain `/` and no further filtering rejects them.
3. **Harden the regex** rather than removing the check — the phantom/unclaimed file checks are valuable, and the note-path check catches real references when it works. Specific fixes:
   - Add a minimum path-component length or require at least one component to look like a filename (contain `.` or be a known directory like `src/`, `tests/`, `megaplan/`).
   - Alternatively, require that at least one component of the slash-separated path has a file extension from `_FILE_SUFFIXES`, OR that the full path starts with a known top-level directory in the repo.
   - The simplest fix: in `_extract_note_paths`, after extracting `cleaned`, skip tokens where no component contains a `.` (i.e., no file extension anywhere in the path) AND the path doesn't start with a known prefix. This eliminates `execute/review`, `258/258`, `plan+critique+gate` etc.
