## Items to address

### 1. Executor notes prompt is too prescriptive
The prompt says 'say what you verified' so the executor literally starts every note with 'Verified...' — parroting, not reasoning. Fix: show 2-3 varied examples in the JSON block that demonstrate different verification styles (edge case catch, expected behavior confirmation, design choice explanation). Let the agent infer the pattern.

### 2. Perfunctory-note detector for executor_notes
We have _is_perfunctory_ack for sense checks (rejects 'ok', 'done', 'confirmed' etc.) but executor notes have no equivalent quality gate. A note like 'Verified. Done.' would pass today. The nonempty_fields check only ensures non-empty, not non-trivial. Add a quality gate.

### 3. Review prompt should positively frame settled decisions
The review prompt says 'do not re-litigate' settled decisions. It should be framed positively: 'verify the executor implemented these decisions correctly.' The reviewer's job is to check execution honored them, not to question them.

### 4. Remove _is_substantive_reviewer_verdict and unify with _is_perfunctory_ack
We have two separate quality heuristics: _is_perfunctory_ack (word blocklist for sense check acks) and _is_substantive_reviewer_verdict (char/word/unique-word counts for reviewer verdicts). They solve the same problem — detecting rubber stamps. Unify them into one function.

### 5. Critique should not waste iteration cycles on structural nitpicks
In our recent run, FLAG-004 was 'the plan fails the required step-section structure' because a step had prose instead of numbered substeps. This burned an entire critique→gate→revise cycle on formatting, not correctness. The critique prompt should distinguish structural nitpicks from real concerns — structural issues should be minor severity, not significant.
