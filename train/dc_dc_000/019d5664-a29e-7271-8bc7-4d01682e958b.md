## Overview

Review and simplify the recent selection/context-menu/shot-creation feature set across ~10 files (~2,500 LOC). The code is fundamentally sound — good memoization, test coverage, separation of concerns — but has accumulated some unnecessary complexity, redundancy, and mild abstraction mismatches during feature development.

**Key findings from audit:**

1. **GallerySelectionContext** (268 lines) — API surface is reasonable. `registerPeerClear` works but is a one-slot ref pattern that only supports one peer. This is fine for the current two-panel case, but the wiring could be slightly cleaner.
2. **useSelectedMediaClips + AgentChat merge** — `mergeSelectedClips` is a private function in AgentChat that dedupes by URL with an undocumented preference for gallery clips. Simple and fine, but the preference logic (`!existing.generationId && clip.generationId`) deserves a comment.
3. **SelectionContextMenu** (111 lines) — Clean, minimal, well-abstracted. Has its own `MenuItem` component. No changes needed.
4. **Shot creation paths** — `createShotWithGenerationsPath` uses serial `await` in a loop (N RPCs). Fits cleanly otherwise.
5. **GenerationsPaneGallery** (249 lines) — Under 300 LOC. Handles selection, lasso, context menu, shot creation, video modal. Well-composed but has two inline arrow function props that could be cleaned up (lines 180-185).
6. **ClipAction** (335 lines) — Growing. The context menu rendering is ~130 lines of conditional buttons inline in JSX. The shot action props integrate cleanly but the overall menu JSX is getting unwieldy.
7. **useExternalDrop** (791 lines) — Large but most of it is top-level pure handler functions extracted outside the hook. The hook itself is only ~130 lines. The structure is actually good — the file is just a natural accumulation point for drop handler variants.
8. **useTimelineState peer clear** — Clean 10-line pattern. Correct abstraction level.
9. **useLassoSelection** (155 lines), **useModifierKeys** (44 lines) — Both clean and minimal.
10. **dragDrop.ts** (329 lines) — `hasDataTransferType` has 4 fallback paths for cross-browser compat. `createDragPreview` builds DOM elements with inline styles (130 lines). The multi-generation type follows the same pattern as single — clean.

**Guiding principle:** Don't over-abstract. Only change things where there's a concrete clarity or maintainability win. Several items are fine as-is.
