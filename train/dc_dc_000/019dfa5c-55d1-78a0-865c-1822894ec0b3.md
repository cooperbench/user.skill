        # Implementation Plan: Sprint 0C — Assets, Capacity, and Deployment Baseline

## Overview

This sprint freezes infrastructure and asset assumptions for dual-stack (WGP + VibeComfy) validation. It has two coordinated but separate workstreams: `vibecomfy/` owns the asset/manifest/template audit and VibeComfy RunPod validation path, while `reigh-worker-orchestrator/` owns orchestrator pod defaults, startup disk logging, and the first-pod measurement runbook. `runpod-lifecycle/` is a shared package used by both paths, so the disk-default change must be made there as well as in the orchestrator.

The critique does not show that the plan targeted the wrong product area or wrong root cause: Sprint 0C still needs asset inventory, template inventory, custom-node audit, 200 GB disk defaults, and first-boot measurement. It does show that two details were materially wrong: the live ready-template inventory is 51 files unless smoke templates are intentionally excluded, and `RunPodConfig.from_env()` has explicit 20/50 fallback values that override dataclass default expectations. The revised approach keeps the original sprint scope, but makes the live inventory policy explicit and updates every default path that can create a RunPod pod for this sprint.

### Repo Layout (load-bearing)
- `vibecomfy/` — independent nested Git repo; owns ready templates, `custom_nodes.lock`, model assets, `template_index.json`, and VibeComfy RunPod validation scripts.
- `reigh-worker-orchestrator/` — independent nested Git repo; owns `gpu_orchestrator/worker_spawner.py`, `gpu_orchestrator/worker_startup.template.sh`, and orchestrator benchmark/e2e pod launch helpers.
- `runpod-lifecycle/` — shared package used by both the orchestrator and VibeComfy validation; owns `src/runpod_lifecycle/config.py` and `src/runpod_lifecycle/api.py`.

### Current State
- Live ready templates are **51 on-disk `*.py` files** under `vibecomfy/ready_templates/` when using the same discovery rule as `vibecomfy/vibecomfy/registry/ready.py`: every non-underscore Python file under `ready_templates`, including `ready_templates/smoke/empty_image_red.py`.
- `template_index.json` currently lists fewer templates than the registry can discover, so the sprint must either index all 51 discoverable templates or explicitly exclude smoke templates. This plan indexes all 51 because the runtime registry treats the smoke template as discoverable.
- RunPod disk defaults are effectively **20 GB pod disk / 50 GB container disk** in the shared `RunPodConfig.from_env()` path unless explicitly overridden.
- Orchestrator code also has hardcoded 50 GB fallbacks in `reigh-worker-orchestrator/gpu_orchestrator/worker_spawner.py` when env vars are absent.
- VibeComfy RunPod validation calls `RunPodConfig.from_env()` directly through `vibecomfy/scripts/runpod_runner.py` and only overrides disk sizes when `VIBECOMFY_RUNPOD_*` env vars are provided, so shared lifecycle defaults must become 200 GB for VibeComfy measurements to rely on defaults.
- `custom_nodes.lock` has 3 pinned entries: KJNodes, QwenTTS, and WanVideoWrapper.
