        # Implementation Plan: ArtAgents Thumbnail Maker Conductor

## Overview
Add a built-in `builtin.thumbnail_maker` conductor for generating reviewable YouTube-style thumbnail candidates from a user query and source video. The repo already has the right primitives: conductors live under `artagents/conductors/curated/*`, built-ins are registered in `artagents/conductors/registry.py`, video evidence can be produced by `scenes.py`, `shots.py`, `visual_understand.py`, and `video_understand.py`, and base image generation is handled by `artagents/generate_image.py`.

The simplest implementation should be a new Python conductor runtime plus a focused `artagents/thumbnail_maker.py` CLI/module. It should orchestrate existing tools, write explicit manifests, and avoid changing Reigh timeline/assets contracts.

## Phase 1: Core Thumbnail CLI and Data Contract

### Step 1: Define thumbnail run layout (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Add a new module with an argparse CLI accepting `--video`, `--query`, `--out`, `--count`, `--size`, `--quality`, `--env-file`, `--dry-run`, `--force`, and optional `--feedback` / `--previous-manifest` for refinement rounds.
2. Standardize output paths under the run directory:
   - `source-analysis/scenes.json`
   - `source-analysis/shots/shots.json`
   - `evidence/evidence-plan.json`
   - `evidence/reference-pack.json`
   - `prompts/prompts.json`
   - `generated/manifest.json`
   - `review/contact-sheet.jpg`
   - `thumbnail-manifest.json`
3. Keep generated files under `runs/` by default and store all absolute or repo-relative source refs in JSON for reviewability.

### Step 2: Plan source-search needs from the query (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Implement a deterministic first-pass planner that maps query terms and flags to evidence needs, without requiring an LLM for the basic path.
2. Support explicit user hints such as speaker/person, scene/object, emotion, text overlay, visual style, and thumbnail count.
3. Write `evidence-plan.json` with planned searches, chosen commands, and why each evidence type is needed.
4. If the query is too underspecified, continue with broad visual sampling rather than failing.

### Step 3: Build source evidence and reference packs (`artagents/thumbnail_maker.py`, existing `artagents/scenes.py`, `artagents/shots.py`, `artagents/visual_understand.py`)
**Scope:** Large
1. Reuse `scenes.detect_scenes` and `shots.build_shots` directly where practical, or shell through their CLIs only when dry-run planning needs command parity.
2. Use representative shot frames as default evidence.
3. Add helper functions to select a bounded set of candidate frames from `shots.json`, cap to the current `visual_understand.py` limit of 20, and build a contact sheet.
4. For speaker/face/person queries, create crop candidates from selected frames using the existing crop/contact-sheet logic in `visual_understand.py` where possible.
5. Write `reference-pack.json` listing every source frame/crop with timestamp, scene index, file path, selection reason, and whether it was used for prompt enrichment.

## Phase 2: Generation and Refinement

### Step 5: Call existing image generation (`artagents/thumbnail_maker.py`, `artagents/generate_image.py`)
**Scope:** Medium
1. Invoke `generate_image.generate()` programmatically or call the CLI with `--prompts-file`, `--n 1`, `--out-dir generated`, and `--manifest generated/manifest.json`.
2. Preserve support for multiple thumbnails through `--count` by writing multiple prompt jobs, not by hiding variants in one opaque call.
3. In `--dry-run`, emit the planned commands and JSON payloads without requiring API keys or network.

### Step 6: Add optional feedback/refinement round (`artagents/thumbnail_maker.py`)
**Scope:** Medium
