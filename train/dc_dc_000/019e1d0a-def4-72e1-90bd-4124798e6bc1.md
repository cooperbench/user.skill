## Interface contract (locked — do not change shape)
```python
async def ship_and_run_detached(
    config: RunPodConfig | None = None,
    remote_script: str = "",
    *,
    pod: Pod | None = None,       # NEW — reattach when provided
    local_root: Path | None = None,
    remote_root: str = "/workspace",
    exclude: set[str] | None = None,
    upload_mode: Literal["sftp_walk", "tarball"] = "sftp_walk",
    timeout: int = 3600,
    name_prefix: str = "pod",
    terminate_after_exec: bool = False,
    poll_interval: int = 30,
) -> ShipAndRunResult:
    """
    Either provision a new pod (config required, pod=None) and run the script,
    OR reattach to the given pod (pod required, config can supply api_key) and
    run the script on it. When pod is supplied, skip provisioning entirely.
    """
```

Exactly one of `config` (with provision intent) or `pod` (with reattach intent) must be supplied. If both supplied: use `pod`, log info that `config` is being treated as api_key source only. If neither: raise `ValueError`.

## Behavior when `pod` is supplied
- Skip `launch()` entirely. The Pod object already has ssh details (`pod._ssh_details` or `await pod._ensure_ssh_details()`).
- Skip storage attach / RAM-tier iteration — those happened at provision time.
- Proceed straight to: ssh + sftp upload (if `local_root`) → run `remote_script` → poll for completion → return result.
- `terminate_after_exec=True` still works: terminate the supplied pod after exec.
- Cost tracking: read `pod.hourly_rate` if available; otherwise leave the cost field as None (or `0.0` with a note).
