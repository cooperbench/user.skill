**Finding**

This is a Megaplan harness edge case, but not primarily because `status: "done"` was invalid. The recorded execute state failed because the chain phase-complete callback rejected claimed changes in nested git repos, then recorded `phase_callback_failed` and left execute recovery incomplete.

Exact callback failure path:

- [megaplan/auto.py](/Users/user_c042661f/Documents/megaplan/megaplan/auto.py:1154): `_drive_plan(...)` runs `on_phase_complete(...)` after `execute`.
- [megaplan/chain.py](/Users/user_c042661f/Documents/megaplan/megaplan/chain.py:920): `phase_callback(...)` calls `_commit_and_push_phase(...)`.
- [megaplan/chain.py](/Users/user_c042661f/Documents/megaplan/megaplan/chain.py:617): `_commit_and_push_phase(...)` raises when claimed paths are in dirty nested repos.
- [megaplan/auto.py](/Users/user_c042661f/Documents/megaplan/megaplan/auto.py:1157): callback exception is recorded as `phase_callback_failed`.

The stale `active_step` is from that failure boundary: normal execute cleanup is in [megaplan/handlers/execute.py](/Users/user_c042661f/Documents/megaplan/megaplan/handlers/execute.py:100), with cleanup at lines 129-133, but callback failure happens outside the execute handler.

**Batch Merge Path**

The batch execute payload merge path is:

- [megaplan/handlers/execute.py](/Users/user_c042661f/Documents/megaplan/megaplan/handlers/execute.py:104): dispatches per-batch execute.
- [megaplan/execute/core.py](/Users/user_c042661f/Documents/megaplan/megaplan/execute/core.py:667): `handle_execute_one_batch(...)` calls `_run_and_merge_batch(...)`.
- [megaplan/execute/core.py](/Users/user_c042661f/Documents/megaplan/megaplan/execute/core.py:463): worker returns payload.
- [megaplan/execute/core.py](/Users/user_c042661f/Documents/megaplan/megaplan/execute/core.py:485): `_merge_batch_results(...)`.
- [megaplan/execute/core.py](/Users/user_c042661f/Documents/megaplan/megaplan/execute/core.py:369): task updates are merged through `_validate_and_merge_batch(...)`.
- [megaplan/execute/core.py](/Users/user_c042661f/Documents/megaplan/megaplan/execute/core.py:403): sense checks are merged through the same helper.
- [megaplan/execute/merge.py](/Users/user_c042661f/Documents/megaplan/megaplan/execute/merge.py:9): aliases already include `task_id <- id` and `sense_check_id <- id`.

So if `execution_batch_4.json` reaches `_merge_batch_results`, the `id` fields should count. I dry-ran the current merge in memory against T3/T8 and SC3/SC8; it returns `(2, 2, 2, 2)` and marks both tasks/checks done.

**Why T3/T8 Did Not Count**

The stale `finalize.json` still had T3/T8 pending, while `execution_batch_4.json` had their evidence. That means the checkpoint/artifact existed, but the normal merge/persist path did not complete or was superseded by the chain callback failure. This is the edge case: a useful execute checkpoint can exist, but non-timeout execute failures/callback failures do not reliably reconcile the latest `execution_batch_N.json` back into `finalize.json`.

**Smallest Safe Patch**

Keep this narrow:

1. Normalize execute aliases at worker payload recovery/parsing, before validation and artifact use:
   - [megaplan/workers.py](/Users/user_c042661f/Documents/megaplan/megaplan/workers.py:945) already has the right shape now: normalize `task_updates[].id -> task_id`, `sense_check_acknowledgments[].id -> sense_check_id`, and `completed -> done`.
   - Test: [tests/test_workers.py](/Users/user_c042661f/Documents/megaplan/tests/test_workers.py:387).

2. Add one execute recovery test for non-timeout checkpoint reconciliation:
   - Use an `execution_batch_N.json` containing only `task_updates` and `sense_check_acknowledgments`, with `id` aliases and extra `verdict`.
   - Simulate an execute/callback failure after the checkpoint exists.
   - Assert recovery/next execute merges T3/T8 and SC3/SC8 into `finalize.json`.

Do not broaden schema strictness. The merge layer is already intentionally tolerant; the missing safety is making the recovery path use that same tolerant merge for checkpoint-shaped batch artifacts, not only clean worker returns/timeouts.
