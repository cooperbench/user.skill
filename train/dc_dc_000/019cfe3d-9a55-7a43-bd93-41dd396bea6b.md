> AGENT

**Findings**

1. The plan misses one immediate crash path: if `effectivePhaseConfig` becomes optional for LTX, the client will still validate it unconditionally before task creation. In [generateVideoService.ts](/Users/user_c042661f/Documents/reigh/src/tools/travel-between-images/components/ShotEditor/services/generateVideoService.ts#L220), `validatePhaseConfigConsistency(modelPhaseSelection.effectivePhaseConfig)` will fail unless you also change that call site.

2. Hiding phase controls for LTX is not enough, because timeline/by-pair runs can still inject stale per-pair WAN phase configs from existing shot metadata. [pairPayload.ts](/Users/user_c042661f/Documents/reigh/src/tools/travel-between-images/components/ShotEditor/services/generateVideo/pairPayload.ts#L130) and [pairPayload.ts](/Users/user_c042661f/Documents/reigh/src/tools/travel-between-images/components/ShotEditor/services/generateVideo/pairPayload.ts#L242) still harvest `overrides.phaseConfig`, and the worker gives that per-segment `phase_config` precedence in [task_registry.py](/Users/user_c042661f/Documents/Headless-Wan2GP/source/task_handlers/tasks/task_registry.py#L689) and parses it in [task_registry.py](/Users/user_c042661f/Documents/Headless-Wan2GP/source/task_handlers/tasks/task_registry.py#L706). If a user switches an existing shot from WAN to LTX, you need to clear or ignore pair phase overrides too.

3. The frame-count part of the plan is incomplete from the worker’s perspective. The frontend still hardcodes 4N+1 quantization in [videoUtils.ts](/Users/user_c042661f/Documents/reigh/src/shared/lib/media/videoUtils.ts#L5) and uses that in [BatchSettingsForm.tsx](/Users/user_c042661f/Documents/reigh/src/tools/travel-between-images/components/BatchSettingsForm.tsx#L366), but the worker quantizes per model step and explicitly calls out LTX-2 as a different `step*N+1` case in [orchestrator.py](/Users/user_c042661f/Documents/Headless-Wan2GP/source/task_handlers/travel/orchestrator.py#L718). Raising the slider max to `241` without making quantization/model-valid counts LTX-aware means the UI and worker will disagree on actual segment lengths.

4. The plan doesn’t cover round-tripping LTX tasks back into editor state. Current task readback only maps `orchestrator.steps ?? params.num_inference_steps` in [taskDataService.ts](/Users/user_c042661f/Documents/reigh/src/tools/travel-between-images/components/ShotEditor/services/applySettings/taskDataService.ts#L99), so `orchestrator.num_inference_steps` and `orchestrator.guidance_scale` would be lost. Separately, the runtime still rewrites `steerableMotionSettings.model_name` from `turboMode` in [useSteerableMotionHandlers.ts](/Users/user_c042661f/Documents/reigh/src/tools/travel-between-images/components/ShotEditor/hooks/actions/useSteerableMotionHandlers.ts#L103), and apply-settings still treats raw `model_name` as the thing to restore in [generationSettingsService.ts](/Users/user_c042661f/Documents/reigh/src/tools/travel-between-images/components/ShotEditor/services/applySettings/generationSettingsService.ts#L15). If `selectedModel` is the new source of truth, those paths need to be updated too.

**What Holds Up**

The core worker assumption is right. On the local worker checkout at `/Users/user_c042661f/Documents/Headless-Wan2GP` on branch `feat/worker-matrix-hardening`, LTX support is already there: model detection in [segment_processor.py](/Users/user_c042661f/Documents/Headless-Wan2GP/source/task_handlers/travel/segment_processor.py#L74), start/end image resolution in [task_registry.py](/Users/user_c042661f/Documents/Headless-Wan2GP/source/task_handlers/tasks/task_registry.py#L273), explicit `num_inference_steps` and `guidance_scale` pickup in [task_registry.py](/Users/user_c042661f/Documents/Headless-Wan2GP/source/task_handlers/tasks/task_registry.py#L641), and automatic SVI disablement for LTX in [orchestrator.py](/Users/user_c042661f/Documents/Headless-Wan2GP/source/task_handlers/travel/orchestrator.py#L161).

So the overall direction is sound, but I would not treat the current plan as complete until it also covers:
- skipping phase validation when LTX has no phase config,
- suppressing stale pair phase overrides for LTX,
- making frame quantization model-aware,
- updating task readback/state sync so LTX settings actually round-trip.
