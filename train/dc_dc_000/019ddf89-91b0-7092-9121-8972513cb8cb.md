        # Implementation Plan: Banodoco Website Database Backed Agent Nodes

## Overview
The website app is in `reigh-app`, with Supabase migrations under `supabase/migrations`, generated database types in `src/integrations/supabase/types.ts`, React routes in `src/app/routes.tsx`, resource/media patterns in `src/features/resources`, and LoRA sample upload UI under `src/domains/lora/.../SampleGenerationsSection.tsx`. The critique flags do not indicate that the plan is aimed at the wrong root cause. The root cause remains missing first-class Banodoco website DB support for agent nodes plus missing ArtAgents consumption/install support. The flags show that the previous plan left important contracts underspecified: the public catalog API must override the existing edge wrapper defaults, RLS must expose safe public catalog/install data explicitly, loader opt-in behavior must live at the shared `load_default_registry()` boundary, git install resolution must persist local metadata before dependency installation, and owner/service permissions must be precise.

This revision keeps Banodoco agent nodes separate from resources/assets while borrowing useful browser/form/media patterns. Git-backed install targets are v1 first-class: `repo_url`, optional `source_ref`/`commit`/`tag`/`branch`, `manifest_path`, deterministic cache/install paths, persisted checkout metadata, and manifest validation before registration. `manifest_url` and `archive_url` remain optional compatibility target types.

## Phase 1: Banodoco Website DB Foundation

### Step 1: Add dedicated agent-node schema (`reigh-app/supabase/migrations/`)
**Scope:** Large
1. Create a migration for dedicated Banodoco website DB tables, not rows in `resources`:
   - `agent_nodes`: owner/creator-attributed node records with `owner_user_id`, optional Discord creator attribution, slug/name/description/details, repo URL, manifest summary/details, visibility, review status, and timestamps.
   - `agent_node_catalog_metadata`: service/admin-controlled catalog fields such as `is_featured`, `is_default`, `is_mandatory`, `catalog_rank`, `catalog_source`, `review_status`, and any global service notes.
   - `agent_node_install_targets`: explicit install targets with `target_type` (`git`, `manifest_url`, `archive_url`), git fields (`repo_url`, `source_ref`, `commit`, `tag`, `branch`, `manifest_path`), URL/archive fields, target runtime, install priority, enabled state, owner-editable source fields, service-controlled catalog/default/mandatory fields, and local cache/install hints.
   - `agent_node_media_items`: ordered sample image/video rows with storage path or URL, thumbnail/poster URL, alt/caption, primary flag, and timestamps.
2. Add constraints that make malformed rows impossible where practical:
   - Git targets require `repo_url` and `manifest_path`.
   - Manifest URL targets require `manifest_url`.
   - Archive URL targets require `archive_url` and `manifest_path`.
   - Only one ref selector should be active unless `commit` is paired with a human label; define precedence as `commit`, then `tag`, then `branch`, then `source_ref`.
3. Add RLS policies and/or public-safe views explicitly for browse and catalog reads:
   - Public/anon users can select `agent_nodes` where `is_public = true` and review status is approved or otherwise public-safe.
   - Public/anon users can select media rows only when the parent node is public.
   - Public/anon users can read safe catalog metadata for public nodes through a view or direct SELECT policy, including featured/default/mandatory badges and rank but excluding private service notes.
   - Public/anon users can read enabled install-target summaries for public approved nodes through a view or direct SELECT policy, including source fields required for install but excluding private/admin-only metadata.
4. Implement the privilege split precisely:
   - Ordinary authenticated owners can create/update their own base `agent_nodes` and media rows.
   - Ordinary authenticated owners can create/update non-default, non-mandatory install target source fields for their own nodes, including repo URL/ref/manifest path, while those rows remain subject to review/enabled gating.
   - Service/admin role only can set `is_featured`, `is_default`, `is_mandatory`, `catalog_rank`, `review_status`, global enabled state, catalog source, and mandatory/default install priority.
   - Owners cannot self-promote nodes into public catalog/default/mandatory status by updating catalog metadata or global install state.
5. Add indexes for browse/API paths: slug, owner, public/featured/default/mandatory, creator/Discord attribution, target runtime, enabled install targets, and install priority.

### Step 2: Regenerate/update website DB and domain types (`reigh-app/src/integrations/supabase/types.ts`, `reigh-app/src/features/agent-nodes/types.ts`)
**Scope:** Small
1. Regenerate or update Supabase types for `agent_nodes`, `agent_node_catalog_metadata`, `agent_node_install_targets`, `agent_node_media_items`, and any public-safe views.
2. Add dedicated domain types in `src/features/agent-nodes/types.ts`, including a discriminated install-target union where git is first-class.
3. Represent service-controlled fields separately from owner-editable payloads so hooks/forms cannot accidentally write catalog/default/mandatory fields from ordinary user flows.

## Phase 2: Website API and Hooks

4. Query public browse data from the safe views or RLS-backed table relationships defined in Step 1 so featured/default/mandatory badges and enabled install target summaries are visible to public browser/API paths.

### Step 4: Add the public Banodoco catalog API for ArtAgents (`reigh-app/supabase/functions/agent-nodes-catalog/`)
**Scope:** Medium
1. Implement `agent-nodes-catalog` as an explicit `GET` endpoint. If using the shared edge wrapper, pass options that override defaults to `method: "GET"` and `auth.required: false`.

3. Accept query parameters such as `target_runtime=artagents` and `install_kind=default,mandatory`; ignore or reject unsupported values with typed errors.

5. Validate response rows before returning them:

   - Manifest URL rows require `manifest_url`.
   - Archive URL rows require `archive_url` and `manifest_path`.
6. Add edge-function tests that prove the endpoint is GET/no-user-auth, rejects POST unless intentionally supported, filters private/unapproved rows, returns only enabled default/mandatory public rows, and rejects malformed target records.
