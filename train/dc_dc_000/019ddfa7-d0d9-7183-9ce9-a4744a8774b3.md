        # Implementation Plan: Simple Folder-Many-Nodes for VibeComfy

## Overview
ArtAgents already has a small node system under `artagents/nodes/`: `NodeSpec` is the code-first authoring surface, `folder.py` discovers curated folder nodes by running `node.py` out of process, `install.py` creates `uv` environments, and `runner.py` expands `{python_exec}` into the installed node Python. The current folder loader only returns one node per folder via top-level `NODE` or `node`, and the extractor can accidentally treat the imported `node` decorator as metadata instead of discovering decorated callables.

The critique does not point to the wrong code or a different root cause. It identifies an over-broad install-path rule in the plan: attaching `folder_id` to every folder node and then using `folder_id` for every env path would move existing single-node Moirae installs from `.artagents/nodes/external.moirae/venv` to `.artagents/nodes/moirae/venv`. The revised approach keeps shared folder metadata on all folder nodes, but only uses an explicit shared `package_id` for install/env ownership. VibeComfy will set `PACKAGE_ID = "vibecomfy"`; legacy Moirae will keep its current node-id-based env path unless it is explicitly changed later.

The implementation should keep the abstraction exactly as requested: a folder is the ownership/install/docs/env boundary, and each `NodeSpec` is one executable action. No `ProviderSpec`, `ActionSpec`, or mode mega-node is needed. VibeComfy should be a curated folder package under `artagents/nodes/curated/vibecomfy/`, exporting action nodes such as `external.vibecomfy.run` and `external.vibecomfy.validate`, with all VibeComfy actions sharing one installed `uv` env through explicit shared package metadata.

VibeComfy reference checked from `https://github.com/peteromallet/VibeComfy`: current package entrypoint is `python -m vibecomfy.cli ...`; `pyproject.toml` declares package `vibecomfy` and dependencies; command registration includes `run`, `validate`, `session`, `runtime`, `logs`, etc. The ArtAgents integration should use this public CLI surface and should not vendor VibeComfy into this repo.

## Main Phase

### Step 1: Make folder discovery return many nodes (`artagents/nodes/folder.py`)
**Scope:** Medium
1. Change folder extraction to support multiple definitions from one `node.py`. Prefer keeping `load_folder_node(root)` source-compatible by returning a tuple of `NodeDefinition` objects and updating all internal call sites/tests accordingly.
2. Update `load_folder_nodes(root)` to flatten all node definitions from each discovered folder root.
3. In `_EXTRACT_SCRIPT`, support both `NODES = [...]` and `NODE = ...`:
   ```python
   if "NODES" in namespace:
       definitions = [normalize(item) for item in namespace["NODES"]]
   elif "NODE" in namespace:
       definitions = [normalize(namespace["NODE"])]
   else:
       definitions = discover_decorated_nodes(namespace)
   ```
4. Fix decorator discovery by scanning namespace values for callable/user objects that expose `.NODE` or `.node` metadata, while excluding the imported `artagents.nodes.node` decorator function itself. Emit a deterministic order based on node id or stable namespace names.
5. Update extractor output to print one JSON array payload, e.g. `[{node...}, {node...}]`, and preserve clear errors for folders with no node metadata.

### Step 2: Attach shared folder/package metadata without changing legacy env ownership (`artagents/nodes/folder.py`)
**Scope:** Medium
1. Extend folder metadata attachment so every discovered folder node receives:
   - `source: "folder"`
   - `node_root`
   - `node_file`
   - `folder_id`, derived from the folder basename such as `vibecomfy`
   - `requirements_file`, `pyproject_file`, and `skill_file` when present
2. Support an explicit package-level install id from `node.py`, preferably `PACKAGE_ID = "vibecomfy"`. Attach this as `metadata["package_id"]` to every node from that folder only when the export is present.
3. Do not derive `package_id` automatically from `folder_id` for all folder nodes. This is the [REDACTED] rule: `folder_id` is descriptive metadata, while `package_id` is an explicit shared env/install ownership signal.
4. Keep per-node metadata intact and merge shared metadata afterward only for reserved folder keys. Do not overwrite node-specific fields such as `homepage` unless explicitly intended.
5. Preserve legacy single-node folder behavior for Moirae: `external.moirae` must still load with its current metadata, no duplicate registry entries, and its current node-id-based env path.

### Step 3: Make install/env paths use explicit shared package id (`artagents/nodes/install.py`, `artagents/nodes/runner.py`)
**Scope:** Medium
1. Add a small helper in `install.py`, for example `node_install_id(node)`, that resolves the environment owner as:
   ```python
   node.metadata.get("package_id") or node.id
   ```
   Validate/sanitize through the existing `_safe_node_id`.
2. Change `node_environment_path(node)` and `node_python_path(node)` to use this install id. This makes VibeComfy nodes with `package_id = "vibecomfy"` share `.artagents/nodes/vibecomfy/venv`.
3. Keep the existing per-node env behavior for built-ins, legacy JSON manifests, external nodes without `package_id`, and existing Moirae. `folder_id` must not affect install paths by itself.
4. Ensure `NodeRunnerError` still tells users to install the requested node id, even if the physical env is shared. That keeps CLI UX direct: `python3 pipeline.py nodes install external.vibecomfy.run`.

### Step 4: Add the curated VibeComfy folder package (`artagents/nodes/curated/vibecomfy/`)
**Scope:** Medium
1. Create `artagents/nodes/curated/vibecomfy/node.py` with `PACKAGE_ID = "vibecomfy"` and `NODES = [...]` containing at least:
   - `external.vibecomfy.run`
   - `external.vibecomfy.validate`
2. Map commands to the installed env Python and VibeComfy CLI:
   ```python
   ["{python_exec}", "-m", "vibecomfy.cli", "run", "{workflow}"]
   ["{python_exec}", "-m", "vibecomfy.cli", "validate", "{workflow}"]
   ```
   Add only the minimal inputs needed for a useful dry-run, likely `workflow` plus optional explicit scalar inputs only if the existing runner already handles them cleanly.
3. Add `requirements.txt` that installs VibeComfy without vendoring it. Preferred starting point: a direct git dependency such as `vibecomfy @ git+https://github.com/peteromallet/VibeComfy.git`, unless a local sibling checkout dependency is confirmed as the intended development contract.
4. Add `SKILL.md` explaining the package boundary, install command, and supported actions. Keep it short and operational.
5. Add `external.vibecomfy.session_start`, `external.vibecomfy.status`, and `external.vibecomfy.stop` only if their VibeComfy CLI invocation is obvious from the reference and can be represented as one `NodeSpec` each without special runner logic. Otherwise defer them.

### Step 5: Update focused tests (`tests/test_nodes_registry.py`, `tests/test_nodes_cli.py`, `tests/test_nodes_runner.py`, `tests/test_nodes_schema.py`)
**Scope:** Medium
1. Add a temporary-folder discovery test where `node.py` exports `PACKAGE_ID = "examplepkg"` and `NODES = [NodeSpec(...), NodeSpec(...)]`; assert `load_folder_nodes()` returns both nodes, both have the same `package_id`, both have `folder_id`, and both have requirements/SKILL metadata.
2. Add a decorator discovery regression test where `node.py` imports `node` and defines:
   ```python
   @node(id="external.decorated", name="Decorated", command=["echo", "ok"])
   def run(): ...
   ```
   Assert discovery returns `external.decorated`, not an error about the imported decorator.
3. Add shared env install-plan tests: two VibeComfy nodes should have identical `node_environment_path()` and `node_python_path()` values ending in `.artagents/nodes/vibecomfy/venv`.
4. Add a legacy env test asserting `external.moirae` still ends in `.artagents/nodes/external.moirae/venv`. This guards against accidentally using `folder_id` as an implicit env owner.
5. Add VibeComfy registry/CLI dry-run tests asserting:
   - `external.vibecomfy.run` and `external.vibecomfy.validate` appear in `nodes list --kind external`
   - inspect JSON includes `source: folder`, `folder_id`, explicit `package_id`, and `requirements_file`
   - dry-run command starts with the supplied or installed Python and includes `-m vibecomfy.cli run` / `-m vibecomfy.cli validate`
6. Keep existing Moirae, built-in, and legacy JSON tests passing without changing unrelated expectations.

### Step 6: Validate cheaply, then broadly
**Scope:** Small
1. Run focused tests first:
   ```bash
   python3 -m pytest tests/test_nodes_schema.py tests/test_nodes_registry.py tests/test_nodes_runner.py tests/test_nodes_cli.py
   ```

