# Lifecycle Phase Cleanup — Implementation Plan

## Current State

The snapshot layer in `engine/_work_queue/snapshot.py` has **two phase derivation paths**:
1. `_derive_display_phase()` — used when persisted mode is "plan" or "execute" (the new path)
2. `_legacy_phase_inference()` — fallback for plans with no persisted mode (None)

Plus dead code: `_ordered_postflight_phase()` (defined but never called), `_DISPLAY_PHASE_ITEM_MAP` (defined but never read).

There are also **two duplicate constant sets** with identical values:
- `PHASE_*` in `snapshot.py` (7 constants, used by snapshot internals + policy.py + tests)
- `LIFECYCLE_PHASE_*` in `refresh_lifecycle.py` (7 constants, used by pipeline.py + app commands)

The reconciliation pipeline (`_resolve_reconcile_display_phase` in `engine/_plan/sync/pipeline.py`) derives display phase from `queue_order` contents — a **separate derivation** from the snapshot's item-partition-based derivation. These should agree but are maintained independently.

## Strategy

**Unify constants → eliminate legacy path → simplify snapshot → align reconciliation.**

The `LIFECYCLE_PHASE_*` constants in `refresh_lifecycle.py` are more widely imported (17 files vs 5 production files for `PHASE_*`). Keep `LIFECYCLE_PHASE_*` as canonical, eliminate `PHASE_*`.

The `_legacy_phase_inference` path handles `current_lifecycle_phase() → None`. Since `current_lifecycle_phase()` already handles this case by inferring from `postflight_scan_pending` and `plan_start_scores`, the None case means: no plan, no scores, no postflight — a truly fresh state. The legacy path's extra logic is unnecessary; `_derive_display_phase` already handles this correctly (falls through to SCAN).
