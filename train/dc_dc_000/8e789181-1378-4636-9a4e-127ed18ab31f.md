        # Implementation Plan: Model Profile System

## Overview

Add `--profile <name>` to every CLI entry point that already accepts `--phase-model`. A profile is a named TOML map from phase → `agent:model` spec that expands into the same `phase_model` list the CLI already consumes. The per-phase resolution logic at `megaplan/workers.py:1615-1651` does not change; profiles are a preset *loader* that feeds data into that path with precedence: ad-hoc `--phase-model` > `--profile` > `--hermes` > agent default.

Three config layers merge in order: built-ins shipped as package data under `megaplan/profiles/` (lowest) → user `~/.config/megaplan/profiles.toml` → project `.megaplan/profiles.toml` (highest). A later layer replaces the whole profile with the same name (no per-field merging).

Python is 3.11+ (pyproject.toml:9) → stdlib `tomllib` covers reads. No TOML writer (`config profiles` is read-only). No new dependencies.

**Key design decisions carried forward from critique (FLAG-001/002/003):**

1. **Module layout.** The loader lives inside the `megaplan/profiles/` **package** (`megaplan/profiles/__init__.py`), alongside the built-in TOML files. There is **no** `megaplan/profiles.py` module — a module and a package of the same dotted name collide (the package shadows the module). Package-based layout means `from megaplan.profiles import load_profiles, resolve_profile, apply_profile_expansion` and `importlib.resources.files("megaplan.profiles")` both target the same `megaplan/profiles/` directory.

2. **Target parser set (verified).** Parsers that actually carry `--phase-model` today (via `grep -n "phase-model" megaplan/**/*.py`):
   - `megaplan/cli.py:871` — `init_parser`
   - `megaplan/cli.py:900` — step-family loop (`plan/prep/critique/revise/gate/finalize/execute/review`)
   - `megaplan/cli.py:987` — `loop_init_parser`
   - `megaplan/cli.py:1004` — `loop_run_parser`
   - `megaplan/cli.py:1046` — `tb_run_parser`
   - `megaplan/prompts/tiebreaker_orchestrator.py:205` — `build_tiebreaker_parser`

   `megaplan/chain.py` and `megaplan/auto.py` do **not** carry `--phase-model`. They are out of scope for this plan. If a user wants profile-controlled routing inside a chain, they should set it via `config profiles` or edit `.megaplan/profiles.toml`, and the downstream `init`/`plan`/… calls that chain shells out to will pick it up naturally once their `--profile` support lands — *only if we thread it through*. Threading profile through chain requires plumbing in `_init_plan()` at `megaplan/chain.py:313-344` that is out of this plan's scope per the brief's "don't expand scope during revise" guidance.

3. **Expansion hook location.** The profile expansion **cannot** run in `main()`, because for non-`init` commands the project directory comes from `state["config"]["project_dir"]` loaded inside the handler (`megaplan/handlers/plan.py:18-35`, `handlers/execute.py:45-64`, `handlers/tiebreaker.py:36-55`). A single pre-dispatch hook would have to fall back to `Path.cwd()` and silently miss project-layer profiles whenever the user reruns a phase outside the source checkout. Instead, each handler that uses `resolve_agent_mode` calls `apply_profile_expansion(args, project_dir)` after it has resolved `project_dir`. The helper is idempotent (sets `args._profile_applied = True`) so repeated calls are safe.

**Dependency gate (unchanged):** the concurrent hermes vendor plan modifies `megaplan/workers.py`. Before executing this plan, re-verify the resolution site via `grep -n "phase_model" megaplan/workers.py` (currently `workers.py:1615-1651`).

Scope: package-ified loader (~120 LOC in `megaplan/profiles/__init__.py`), two profile TOMLs, six add-argument edits (one line each), one state-snapshot line, one `config profiles` handler branch (~40 LOC), `apply_profile_expansion` call-sites in each affected handler (~6 one-liners), and tests. ### Step 2: Create the profiles package and loader (`megaplan/profiles/__init__.py` — NEW)
**Scope:** Medium

1. **Create** the package directory `megaplan/profiles/` with a single loader module at `megaplan/profiles/__init__.py`. Do **not** create a sibling `megaplan/profiles.py`.
2. **Export** the following API from `megaplan/profiles/__init__.py`:
   - `VALID_PHASE_KEYS: frozenset[str]` — derived from `megaplan.types.DEFAULT_AGENT_ROUTING.keys()`.
   - `load_profiles(home: Path | None = None, project_dir: Path | None = None) -> dict[str, dict[str, str]]` — merges built-in + user + project layers and returns `{profile_name: {phase: "agent:model"}}`. Later layers replace earlier ones by name.
   - `load_profile_sources(home=None, project_dir=None) -> list[tuple[str, str, dict[str, str]]]` — returns `(source_label, profile_name, phase_map)` triples in layering order, so `config profiles list` can show which layer each definition comes from.
   - `resolve_profile(name: str, profiles: dict) -> dict[str, str]` — raises `CliError("unknown_profile", f"Unknown profile '{name}'. Known: {sorted(profiles)}")` on miss.
   - `profile_to_phase_models(profile: dict[str, str]) -> list[str]` — returns `[f"{phase}={spec}" for phase, spec in profile.items()]`.
   - `apply_profile_expansion(args, project_dir: Path | None) -> None` — idempotent hook; if `args._profile_applied` is True or `args.profile` is falsy, no-op. Otherwise load profiles, resolve, and **append** `profile_to_phase_models(...)` to `args.phase_model` (so pre-existing ad-hoc entries come first and win).
3. **Load** built-ins via `importlib.resources.files("megaplan.profiles")` iterating entries matching `*.toml`. Use stdlib `tomllib` (read-binary).
4. **Validate** on load: every key under `[profiles.<name>]` must be in `VALID_PHASE_KEYS`; each value must be parseable by `parse_agent_spec` and the `agent` segment must be in `KNOWN_AGENTS`. Raise `CliError("invalid_profile", ...)` with the offending file path, profile name, and key on failure. Missing user/project files are not errors.
5. **Layer paths:**
   - Built-in: `importlib.resources.files("megaplan.profiles")` filtered to `*.toml`.
   - User: `config_dir(home) / "profiles.toml"` (reuse `megaplan._core.io.config_dir`, honors XDG).
   - Project: `project_dir / ".megaplan" / "profiles.toml"` — `project_dir` is passed in by the caller.
