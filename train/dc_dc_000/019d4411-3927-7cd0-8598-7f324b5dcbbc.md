## Overview

The critique system currently runs all 8 `CritiqueCheckSpec` checks at every robustness level. The only differentiation is a softer instruction tone for `light`. This change makes robustness structurally meaningful: `heavy` gets all 8 checks, `standard` gets ~3-4 core checks, and `light` skips structured checks entirely (general review via `flags` array only).

**Key files:** `megaplan/checks.py` (registry + filtering), `megaplan/prompts/critique.py` (prompt rendering), `megaplan/handlers.py` (validation call site).

**Constraint:** Single code path, single data source — `CRITIQUE_CHECKS` remains the source of truth; robustness just filters it.

## Main Phase

### Step 1: Add `tier` field to `CritiqueCheckSpec` and tag all checks (`megaplan/checks.py`)
**Scope:** Small

1. **Add** `tier: str` to the `CritiqueCheckSpec` TypedDict (`checks.py:11-16`). Valid values: `"core"` or `"extended"`.
2. **Tag** each of the 8 checks in `CRITIQUE_CHECKS` (`checks.py:19-109`):
   - **Core** (4 checks): `issue_hints`, `correctness`, `scope`, `verification`
   - **Extended** (4 checks): `all_locations`, `callers`, `conventions`, `criteria_quality`

   Rationale: core checks cover the highest-signal axes (did it address the ask? is it correct? right scope? verified?). Extended checks are valuable but lower-signal for standard work.

3. **Add** the `checks_for_robustness()` function:
   ```python
   def checks_for_robustness(robustness: str) -> tuple[CritiqueCheckSpec, ...]:
       if robustness == "heavy":
           return CRITIQUE_CHECKS  # all 8
       if robustness == "standard":
           return tuple(c for c in CRITIQUE_CHECKS if c["tier"] == "core")
       return ()  # light: no structured checks
   ```
4. **Update** `build_empty_template()` to accept an optional `checks` parameter (defaulting to `CRITIQUE_CHECKS` for backward compat):
   ```python
   def build_empty_template(checks: tuple[CritiqueCheckSpec, ...] | None = None) -> list[dict[str, Any]]:
       source = checks if checks is not None else CRITIQUE_CHECKS
       return [{"id": c["id"], "question": c["question"], "findings": []} for c in source]
   ```
5. **Update** `validate_critique_checks()` to accept an optional `expected_ids` parameter. When provided, validate against that set instead of all check IDs. When `expected_ids` is empty (light mode), skip check validation entirely and return `[]`.
6. **Update** `__all__` to export `checks_for_robustness`.
