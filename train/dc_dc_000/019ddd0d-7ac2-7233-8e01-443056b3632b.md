### The loop
Per-turn flow exactly per spec: orient → read (multiple rounds) → decide → respond (passes through `check_oob` placeholder) → write (using the five-primitive framework — multiple primitives can apply to one piece of info) → schedule (one follow-up check-in or none) → end turn.

**No hard cap on tool calls or wallclock per turn.** Daily LLM spend caps (Plan 1) are the budgetary backstop. `bot_turns` records `tool_call_count` and turn duration so admin (Plan 6) can spot pathological loops, but nothing terminates the loop early.

- Use Anthropic SDK with Claude Sonnet (latest at build time — read the runtime config; default to `claude-sonnet-4-6`). Use the SDK's native tool-use loop or equivalent.
- Prompt caching: cache the system prompt + tool definitions block. Cache hot context too if it's large enough to benefit.
- Open a `bot_turns` row at the start with `prompt_snapshot`, `triggered_by_message_id`, `user_in_context`, `started_at`, `model_version`. Update `final_output_message_id`, `reasoning`, `completed_at` at end. On error, set `failure_reason`.
- For "what did you do" queries the user might raise (e.g., "why did you tell her that?"), the loop should call `get_bot_actions` rather than relying on memory.
- Silence is a valid output. For charged messages, the loop must record a justification in `bot_turns.reasoning`.
