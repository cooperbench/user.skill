**Phase 1: Create an Acyclic Domain Boundary**

Create `src/tools/video-editor/domain/` as the owning layer for canonical interpretation. It must be runtime-safe for both browser/editor tests and Supabase edge function source:

- No React imports.
- No browser APIs.
- No `@/` aliases.
- No imports from `lib/config-utils.ts`, `lib/timeline-data.ts`, hooks, components, or renderer files.
- Only import persisted/shared types from `src/tools/video-editor/types/index.ts` by relative path if needed.

Initial files:

- `diagnostics.ts`: stable `TimelineDiagnostic` types and codes.
- `registry.ts`: `AssetRegistry` normalization, validation, preservation rules, and diagnostics.
- `duration.ts`: registry-aware and registry-free duration helpers.
- `repair.ts`: lifted repair/migration primitives currently owned by `lib/migrate.ts`, moved only after characterization tests pin behavior.
- `normalize.ts`: `normalizeTimelineConfig(config, registry, options)` returning normalized in-memory config, registry, diagnostics, and repair metadata.
- `validate.ts`: hard errors and warnings over canonical timeline plus registry data.
- `serialize.ts`: explicit write serialization after normalization/validation.
- `index.ts`: public API.
- `README.md`: canonical source/projection/read/write rules.

Acyclic ownership rule:

- `domain/*` owns duration, registry interpretation, validation, repair, normalization, and serialization.
- `lib/config-utils.ts`, `lib/migrate.ts`, `lib/serialize.ts`, and `lib/timeline-data.ts` become compatibility/adaptation layers that may import `domain/*`.
- `domain/*` must never import those `lib/*` compatibility modules.

**Phase 2: Define AssetRegistry Semantics**

Because duration fallback and render URL resolution depend on `AssetRegistry`, Sprint 1 must define the registry half of the persisted source, not only timeline clips.

Canonical registry rules:

- Preserve unknown asset metadata unless it is impossible or unsafe to serialize.
- Hard error when `asset_registry` is not an object or `assets` is not an object.
- Warning for asset entries that are not objects; ignore them for duration and URL resolution.
- Warning for missing or non-string `file`; keep the entry but treat it as unresolved for render/import diagnostics.
- Warning for non-finite or negative `duration`; keep the original metadata if serialization currently allows it, but do not use it for duration fallback.
- Warning for unknown or malformed `type`; preserve it and treat the asset as unknown media unless an existing path requires a stricter type.
- Duration helpers may use only finite positive registry durations.

Add `domain/registry.test.ts` for malformed entries, unknown metadata preservation, invalid duration exclusion, missing `file`, and stable diagnostic codes/paths.

**Phase 3: Define Duration APIs Without Breaking Existing Callers**

Do not force registry fallback through old clip-only helpers. Add two explicit APIs:

- `getCanonicalClipDurationSeconds(clip, registry, options)`: registry-aware canonical helper for callers that have `AssetRegistry`.
- `getLegacyClipDurationSeconds(clip)` or compatibility wrapper behavior through `config-utils.ts`: preserves existing clip-only semantics where no registry is available.

Canonical duration rule:

- `hold` wins when finite and positive.
- Else, finite `from` and `to` produce `to - from`.
- Else, for media clips with a valid registry asset duration, use `asset.duration - from` when `from` exists, otherwise `asset.duration`.
- Invalid, missing, or non-positive `speed` is repaired to `1` with a warning on read and on write for Sprint 1, matching existing UI sanitization behavior and avoiding a new write rejection policy.
- Seconds-domain helpers may return `0` where canonical data is incomplete; frame helpers clamp only at render/frame conversion boundaries when a rendered sequence needs at least one frame.

Migration rule:

- Callers with only `clip` keep legacy behavior through compatibility wrappers.
- Callers with `config + registry` move to canonical helpers.
- Any call site that cannot receive registry without broad signature churn is listed in the final notes as a remaining non-canonical duration path.

**Phase 4: Preserve Existing Repair Semantics**

Lift existing repair behavior into `domain/repair.ts` only after characterization tests are in place. The lifted implementation must preserve current semantics for:

- `repairConfig` duplicate handling.
- `repairShotGroupContiguity`.
- `migrateToFlatTracks`.
- Legacy pinned-group conversion.
- Legacy track/background behavior.

Compatibility modules should delegate to these domain functions so existing imports continue to work. `normalizeTimelineConfig` should compose these exact repair steps and attach diagnostics; it should not invent new repair behavior in Sprint 1.

Read behavior remains non-persistent: normalization may repair in memory and report diagnostics, but UI load/poll/read paths must not write repaired data merely because they read it.

**Phase 5: Add a UI Save-Boundary Guard**

Route the actual UI persistence boundary through domain serialization, not just rows/config adapters.

In `useTimelinePersistence.ts`, before `provider.saveTimeline(timelineId, nextData.config, expectedVersion, registry)`, run the save payload through a small helper such as:

```ts
prepareTimelineForSave(nextData.config, registry)
```

That helper should normalize, validate, and serialize via `domain/serialize.ts`, then pass the serialized config and registry to `provider.saveTimeline`. This keeps edit-path internals stable while ensuring all explicit UI saves share the canonical write boundary.

Required tests:

- `useTimelinePersistence` save passes domain-serialized config to `provider.saveTimeline`.
- Read/load normalization does not call save by itself.
- Write-time warnings are available to the save path for logging or future UI surfacing, without adding new user-visible UI in Sprint 1.

Do not refactor `DataProvider.saveTimeline` broadly unless this local hook-level guard misses another concrete write path. If another UI write path bypasses `useTimelinePersistence.ts`, document it as a remaining non-canonical writer with file path and reason.
