**Strongest Approval** The plan is right to put validation before installation and deterministic discovery before runtime. As a user installing someone else’s Git-backed pack, that is the core trust boundary: Astrid should refuse unclear repos before they enter my tool surface. The manifest-first model, file-specific validation errors, declared content roots, and agent-facing index are exactly the right primitives. **Biggest Concerns Ranked** 1. **Security is treated too late.** Optional sandboxing in Sprint 8 is not enough. Users installing Git repos will immediately wonder: “Can this run arbitrary Python on my machine? Can it read my files? Can it exfiltrate secrets?” The plan currently validates shape, not behavior. That is fine technically, but it must be explicit in the UX from day one. 2. **Install UX lacks a trust review step.** `packs install https://github.com/...` should not silently clone, validate, and expose commands. A user needs a pre-install summary: pack id, source URL, commit SHA, provided tools, required secrets, declared dependencies, entrypoints, and whether runtime code is executable. 3. **Secrets need stronger semantics.** Listing `OPENAI_API_KEY` in `pack.yaml` is useful, but users need to know when it is required, which tool uses it, whether it is passed to subprocesses, and how to run a dry inspection without exposing it. “Required: true” at pack level is too blunt. 4. **Choosing the right tool is deferred too long.** Agent index in Sprint 6 is late for the user story. Installed pack components appearing in list/search/inspect is not enough; a user installing an unfamiliar pack needs “normal entrypoints” and “do not use this for” immediately, before any run. 5. **Updates are underspecified and scary.** `packs update my_project` can change executable code. The plan needs pinned commits, changelog/diff summary, revalidation before activation, rollback, and clear behavior when a pack changes ids or required secrets. 6. **Dependency handling cannot be merely informational without sharper warnings.** If install succeeds but run fails because `ffmpeg`, npm packages, or Python deps are missing, users will blame Astrid. Either provide `packs doctor <id>` early or make install report “installed but not runnable” with exact next steps. 7. **Error messages focus on builders, not consumers.** Validation errors are good for authors.
