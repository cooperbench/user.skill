1. A ready template Python file currently contains valid Python, but mostly as a serialized Comfy API graph:
   - `API_WORKFLOW`: a dict of Comfy nodes keyed by node id.
   - `READY_METADATA`: source/template/model metadata.
   - `READY_REQUIREMENTS`: models/custom nodes.
   - `build()`: calls `build_api_ready_workflow(...)`.
   See [flux2_klein_4b_t2i.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/ready_templates/image/flux2_klein_4b_t2i.py:6) and its `build()` at [line 118](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/ready_templates/image/flux2_klein_4b_t2i.py:118).

2. VibeComfy loads it as Python by importing the file with `importlib`, looking for `build()`, calling it, and requiring a `VibeWorkflow` return value.
   - Ready path: `workflow_from_ready()` in [vibecomfy/registry/ready.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/registry/ready.py:22).
   - General scratchpad path does the same shape via `load_scratchpad()` in [vibecomfy/scratchpad_loader.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/scratchpad_loader.py:11).
   - CLI/reference loading routes `--ready` directly to `workflow_from_ready()` in [vibecomfy/registry/library.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/registry/library.py:44).

3. HiddenSwitch does not receive this Python file. It receives a Comfy API dict/JSON prompt.
   - Embedded mode calls `self._comfy.queue_prompt_api(api_dict)` in [vibecomfy/runtime/session.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/runtime/session.py:98).
   - Server mode posts `{"prompt": prompt}` to `/prompt` in [vibecomfy/runtime/client.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/runtime/client.py:20).

4. Conversion happens in two places:
   - Ready template `API_WORKFLOW` -> `VibeWorkflow`: `build_api_ready_workflow()` calls `convert_to_vibe_format()` in [vibecomfy/registry/ready_template.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/registry/ready_template.py:10).
   - `VibeWorkflow` -> Comfy API dict: `_prepare_prompt()` calls `workflow.compile(...)` in [vibecomfy/runtime/session.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/runtime/session.py:325), implemented by `VibeWorkflow.compile()` in [vibecomfy/workflow.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/workflow.py:170).

5. The design is currently split. Mechanically, `flux2_klein_4b_t2i.py` fits the scratchpad contract because it is importable Python with `build()` returning `VibeWorkflow`. But semantically it does not match the intended authoring model. [docs/authoring.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/authoring.md:97) says ready templates should be hand-curated Python builders and that materialized API dictionaries were only a bootstrap. The ready template README still describes the current generated form at [ready_templates/README.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/ready_templates/README.md:7).

So: no, HiddenSwitch does not need or receive a Python wrapper. The current file is “proper Python” syntactically and operationally, but it is not the intended long-term native scratchpad style. The mismatch is in VibeComfy’s ready-template authoring layer, not in the HiddenSwitch submission boundary.
