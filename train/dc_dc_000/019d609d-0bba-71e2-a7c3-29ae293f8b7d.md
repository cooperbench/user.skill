        # Implementation Plan: Multi-Clip Drag to New Track

## Overview

**Goal:** Allow multi-clip drag to create new tracks above/below the timeline, matching single-clip drag behavior.

**Current state:**
- Single-clip cross-track drag checks `dropPosition.isNewTrack` and calls `createTrackAndMoveClip` (`useClipDrag.ts:366-367`).
- Multi-clip drag explicitly skips `isNewTrack` at line 383, falling back to `session.sourceRowId` when the drop targets a new track zone.
- `planMultiDragMoves` returns `canMove: false` if any clip's target index goes out of bounds (`multi-drag-utils.ts:71-72`), which naturally blocks moves to non-existent tracks.

**Approach:** When the anchor clip's drop position is `isNewTrack`, create a temporary `TimelineData` with the new track added (via `addTrack`), then run `planMultiDragMoves` + `applyMultiDragMoves` against that augmented data. Commit via the `type: 'config'` edit path (since we're changing both tracks and clip placements).

**Key constraint:** The two edit paths (`type: 'rows'` vs `type: 'config'`) are mutually exclusive. Multi-drag currently uses `type: 'rows'`. Since adding a track requires modifying `resolvedConfig.tracks`, the new-track branch of multi-drag must use the `type: 'config'` path — converting the planned moves into config-level clip updates.

## Main Phase

### Step 1: Add `planMultiDragMovesWithNewTrack` to multi-drag-utils.ts
**Scope:** Medium

1. **Add** a new exported function in `multi-drag-utils.ts` that:
   - Takes the same args as `planMultiDragMoves` plus `insertAtTop: boolean` and `trackKind: TrackKind`
   - Uses `addTrack()` on `data.resolvedConfig` to create an augmented config with the new track
   - Builds a temporary `TimelineData` (spread `data` with updated `tracks`, `rows`, and `resolvedConfig`) that includes the new empty row
   - The anchor's target row ID is the new track's ID
   - Calls the existing `planMultiDragMoves` on this temporary data
   - Returns `{ ...result, augmentedData, newTrackId }` so the caller can apply and commit
2. **Key detail:** When `insertAtTop` is true, the new track is at index 0, shifting all existing rows down by 1. The anchor targets index 0, secondary clips maintain relative offsets from the anchor. When `insertAtTop` is false, the new track is appended, anchor targets the last index.
3. **Track kind validation:** The new track's kind matches the source clips' kind. If the selection spans mixed kinds (visual + audio), reject (`canMove: false`).

### Step 2: Add `applyMultiDragMovesToConfig` to multi-drag-utils.ts
**Scope:** Small

1. **Add** a function that converts planned moves into a `ResolvedTimelineConfig` (for the `type: 'config'` edit path).
   - Takes the augmented `TimelineData` and the `PlannedMove[]` from step 1
   - Updates `resolvedConfig.clips` — for each move, update the clip's `track` and `at` fields
   - Runs overlap resolution on the resulting config
   - Returns the final `ResolvedTimelineConfig`
2. **Alternative (simpler):** Reuse `applyMultiDragMoves` on the augmented data (it returns `nextRows`), then convert rows back to config via `rowsToConfig` (already used in `materializeData`). This avoids duplicating the clip-moving logic. Check if `rowsToConfig` is exported and suitable.

### Step 3: Wire new-track multi-drag into useClipDrag.ts
**Scope:** Medium

1. **Modify** the multi-clip drag block (`useClipDrag.ts:378-412`):
   - When `crossTrackActiveRef.current && dropPosition?.isNewTrack`, instead of falling back to `session.sourceRowId`:
     - Call `planMultiDragMovesWithNewTrack(current, session.clipOffsets, session.clipId, session.sourceRowId, timeDelta, session.sourceKind, dropPosition.isNewTrackTop)`
     - If `canMove`, apply the result via the `type: 'config'` edit path (same as `createTrackAndMoveClip` does)
   - When `!dropPosition?.isNewTrack`, keep existing behavior unchanged
2. **Import** the new function from `multi-drag-utils.ts`

### Step 4: Fix ghost rendering for multi-drag near new-track edges
**Scope:** Small

1. **Inspect** `computeSecondaryGhosts` (`multi-drag-utils.ts:183-219`): it currently skips ghosts for out-of-bounds `targetIndex` (line 205). During a drag toward the new-track zone, secondary ghosts for clips that would land on the new track silently disappear.
2. **Fix:** When the anchor targets a new-track position, the ghost computation should account for the virtual extra row. Pass an optional flag or augmented row list to `computeSecondaryGhosts` so it can render ghosts for the new-track position. The ghost for clips landing on the new track should appear at the top/bottom edge of the timeline.
3. **Update** the call site in `useClipDrag.ts:302-313` to pass the augmented row list when in new-track territory.

### Step 5: Update tests
**Scope:** Medium

1. **Add unit tests** to `multi-drag-utils.ts` (create `multi-drag-utils.test.ts` if it doesn't exist) for:
   - `planMultiDragMovesWithNewTrack` with `insertAtTop: true` and `false`
   - Multi-clip selection spanning 2 source tracks where some clips land on the new track and others on existing tracks
   - Mixed-kind rejection
   - Single-clip-in-multi-selection edge case (should still work)

3. **Run** existing tests to verify no regressions: `npx vitest run --reporter=verbose src/tools/video-editor/lib/multi-drag-utils src/tools/video-editor/hooks/useClipDrag`
