```python
        deps = TRIAGE_STAGE_DEPENDENCIES.get(name, set())
        blocked_by = sorted(f"triage::{dep}" for dep in deps if ...)
        
        item: WorkQueueItem = {
            "id": sid,
            "tier": 1,
            "kind": "workflow_stage",
            "summary": f"Triage: {label}",
            ...
        }
        items.append(item)
    return items
```

**No Beginning/End Guards:** The code simply iterates through TRIAGE_STAGE_IDS in order — there are no special guards preventing triage stages from appearing at the beginning or end of the queue_order list.

### Key Invariants & Design Patterns

| Aspect | Details |
|--------|---------|
| **Injection Position** | Always appended to **back** of `queue_order` — never reorders existing items |
| **Atomicity** | Changes written to plan.json via atomic temp + replace operation |
| **Staleness Hashing** | Review issues tracked by SHA256 hash of sorted open IDs |
| **Mid-Cycle Logic** | Triage can be injected while objective work exists but is **hidden** by lifecycle filter |
| **Auto-Pruning** | Stale triage stages are removed only when no new issues remain AND no work is in progress |
| **Confirmed Tracking** | `epic_triage_meta["triage_stages"]` dict tracks completed stages by name |
| **Triple Sync Paths** | (1) Post-scan reconcile, (2) Review import, (3) Explicit command (`desloppify plan triage`) |
| **No Beginning Guard** | Triage stages can appear at position 0 if injected early AND all objective work is done |
| **No End Guard** | Triage stages can appear at the end if injected late |

### Summary: Where Triage Gets Injected

1. **Decision:** `sync_triage_needed()` checks if new review/concerns issues appeared since last triage
2. **Injection:** `_inject_pending_triage_stages()` appends stage IDs to `plan["queue_order"]` back
3. **Orchestration:** `reconcile_plan_post_scan()` calls sync after every scan (last sync operation)
4. **Visibility:** `apply_lifecycle_filter()` hides triage when objective work remains
5. **Display:** `build_triage_stage_items()` converts queued stage IDs into displayable work items
6. **Alternative Path:** `sync_plan_after_review_import()` can also trigger injection when reviews are imported mid-cycle
