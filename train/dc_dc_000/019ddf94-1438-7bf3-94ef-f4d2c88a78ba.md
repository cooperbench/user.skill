        # Implementation Plan: Banodoco Website Database-Backed Agent Nodes

## Overview
The work spans two local repos: `reigh-app` is the Banodoco website app and owns Supabase schema, Edge APIs, generated database types, hooks, and UI; `ArtAgents` owns executable node manifests, registry loading, CLI, runner, and local installation.

The existing website `resources` flow is a useful reference for browse/search/create patterns (`src/features/resources/hooks/useResources.ts`, `src/shared/hooks/resources/useResourceBrowserData.ts`, `src/features/resources/components/ResourceBrowserModalBase.tsx`), but Banodoco agent nodes should be separate first-class catalog tables, not another `resources.type`. ArtAgents currently loads only built-in and curated folder nodes at `artagents/nodes/registry.py:63`, installs dependency environments at `artagents/nodes/install.py:41`, and exposes node commands through `artagents/nodes/cli.py:12`.

Key constraints from the brief: public default/mandatory catalog rows must be fetchable via a GET API without auth, private/future catalog modes may use `BANODOCO_CATALOG_TOKEN`, default ArtAgents loading must have no network or install side effects, git-backed install targets are v1 requirements, and installed/fetched manifests must be rejected if their manifest id does not match the Banodoco catalog identity.

## Phase 1: Website Database Foundation

### Step 1: Add dedicated Banodoco agent-node tables (`reigh-app/supabase/migrations/`)
**Scope:** Large
1. **Create** a migration for separate tables:
   - `agent_nodes`: owner/attribution and human-facing node data: `id`, `owner_user_id`, `discord_creator_id`, `slug`, `name`, `description`, `repo_url`, `manifest`, `details`, `expected_manifest_id`, `is_public`, timestamps.
   - `agent_node_catalog_metadata`: service/admin-controlled fields: `agent_node_id`, `review_status`, `is_featured`, `is_default`, `is_mandatory`, `catalog_rank`, `catalog_enabled`, timestamps.
   - `agent_node_install_targets`: explicit install source rows: `agent_node_id`, `kind`, `repo_url`, `source_ref`, `commit_sha`, `tag`, `branch`, `manifest_path`, `manifest_url`, `archive_url`, `expected_node_id`, `local_cache_key`, `is_enabled`, timestamps.
   - `agent_node_media`: sample images/videos: `agent_node_id`, `owner_user_id`, `storage_bucket`, `storage_path`, `media_type`, `mime_type`, `size_bytes`, `width`, `height`, `duration_seconds`, `sort_order`, `alt_text`, timestamps.
2. **Add** constraints and indexes for slug uniqueness, public browsing, featured/default/mandatory catalog filters, enabled install targets, owner-node media integrity, and media ordering.
3. **Add** server/storage-side constraints for media MIME and size, not just UI validation. Use explicit image/video allowlists such as PNG/JPEG/WebP/GIF and MP4/WebM/QuickTime, separate image/video size caps, and node-scoped object paths like `<owner_user_id>/agent-nodes/<agent_node_id>/<media_id>/<filename>`.
4. **Keep** resources/assets untouched except for shared helper reuse where appropriate.

### Step 2: Implement RLS and public-safe views (`reigh-app/supabase/migrations/`)
**Scope:** Large
1. **Enable** RLS on all new tables.
2. **Allow** public SELECT or public-safe views for:
   - public `agent_nodes` rows where `is_public = true`,
   - media whose parent node is public,
   - safe catalog metadata fields for public nodes,
   - enabled install-target summaries needed by ArtAgents.
3. **Allow** ordinary owners to create/update their own base `agent_nodes`, their own media, and non-default install target source fields for their own nodes.
4. **Restrict** featured/default/mandatory/catalog rank/review status/global enabled install state to service/admin paths only.
5. **Test** the RLS model with SQL or migration-level checks where the repo already supports them; otherwise add focused Edge/API tests around the visible behavior.

### Step 3: Update generated website DB types (`reigh-app/src/integrations/supabase/types.ts`, `reigh-app/src/integrations/supabase/databasePublicTypes.ts` if generated/aliased)
**Scope:** Medium
1. **Regenerate or update** Supabase TypeScript table/view types for `agent_nodes`, catalog metadata, install targets, and media.
2. **Add** narrow app-facing types under a dedicated feature path such as `src/features/agent-nodes/types.ts` to avoid leaking raw row shapes everywhere.

## Phase 2: Website API, Hooks, And UI

### Step 4: Add public catalog GET API (`reigh-app/supabase/functions/agent-node-catalog/`)
**Scope:** Medium
1. **Create** an Edge Function using the existing shared handler style from `supabase/functions/_shared/edgeHandler.ts`.
2. **Set** method to `GET`, `auth.required = false`, and return only public-safe rows for default/mandatory/featured browsing.
3. **Support** optional private/future access with `BANODOCO_CATALOG_TOKEN`, but keep the public default/mandatory ArtAgents path unauthenticated.
4. **Return** install targets with git-first shape: `repo_url`, optional `source_ref`/`commit_sha`/`tag`/`branch`, `manifest_path`, `expected_node_id`, plus optional `manifest_url`/`archive_url` if populated.
5. **Add** tests for unauthenticated public GET, disabled/private row exclusion, token-gated future rows, and missing/invalid method handling.

### Step 5: Add website agent-node hooks (`reigh-app/src/features/agent-nodes/hooks/`)
**Scope:** Medium
1. **Implement** TanStack Query hooks mirroring the resource hook ergonomics without reusing the `resources` table: list public nodes, list my nodes, create/update owned node, create/update install target source fields, attach/delete/reorder media.
2. **Use** the generated Supabase types and explicit query keys, similar to `resourceQueryKeys` and `useListPublicResources`.
3. **Ensure** owner mutations cannot send service-only fields like `is_default`, `is_mandatory`, `is_featured`, `catalog_rank`, `review_status`, or global target enablement.

### Step 6: Add media upload helpers and tests (`reigh-app/src/features/agent-nodes/media/`, `reigh-app/supabase/functions/` or direct storage client)
**Scope:** Medium
1. **Implement** file validation shared by UI and tests: allowed MIME, image/video size caps, and required owner/node scoped path format.
2. **Persist** media rows only after path ownership and MIME constraints are satisfied server-side.
3. **Add** tests for invalid MIME, oversized media, mismatched owner path, mismatched node path, and valid image/video sample media.

### Step 7: Add browse/create UI (`reigh-app/src/features/agent-nodes/components/`, `reigh-app/src/pages/AgentNodesPage.tsx`, `reigh-app/src/app/routes.tsx`)
**Scope:** Large
1. **Create** an Agent Nodes page for browsing public nodes, featured/default filters, search, creator attribution, repo URL, manifest/details preview, and sample media gallery.
2. **Create** an owned-node form for adding/editing name, slug, description, repo URL, expected manifest id, manifest/details JSON, and install target source fields.
3. **Add** media attach/reorder/delete UI using the existing resource/media gallery patterns where helpful, but visually and data-wise keep it an agent-node catalog surface.
4. **Wire** a route such as `/agent-nodes` or `/tools/agent-nodes` in `src/app/routes.tsx` and add tests around browse/create/form behavior.

## Phase 3: ArtAgents Catalog Loading

### Step 8: Add Banodoco catalog client and config (`ArtAgents/artagents/nodes/catalog.py`, `ArtAgents/artagents/nodes/registry.py`)
**Scope:** Medium
1. **Introduce** a small stdlib HTTP catalog client that fetches the website GET API and validates response shape.
2. **Add** explicit config at the `load_default_registry` boundary, for example `load_default_registry(catalog_config=None)` and `BanodocoCatalogConfig(enabled=False, api_url=None, token=None, install_defaults=False, install_mandatory=False, cache_dir=...)`.
3. **Default** to built-in + curated only, with no network and no install side effects.
4. **Enable** website-backed default/mandatory loading only through explicit CLI flags or env such as `ARTAGENTS_BANODOCO_CATALOG=1`, `BANODOCO_CATALOG_URL`, and optional `BANODOCO_CATALOG_TOKEN`.
5. **Use** this same load boundary from CLI, runner, tests, and direct callers so behavior is consistent.

### Step 9: Validate catalog identity before registration (`ArtAgents/artagents/nodes/catalog.py`, `ArtAgents/artagents/nodes/registry.py`)
**Scope:** Small
1. **Load** each fetched/installed manifest through `load_node_manifest` or `validate_node_definition`.
2. **Reject** the catalog entry before registry registration if `manifest.id` does not match `agent_nodes.expected_manifest_id` or install target `expected_node_id`.
3. **Add** tests for matching id acceptance and mismatch rejection, including git-backed install targets.

## Phase 4: Git-Backed Installer

### Step 10: Extend local installer for git install targets (`ArtAgents/artagents/nodes/install.py`)
**Scope:** Large
1. **Add** install target dataclasses for git, manifest URL, and archive URL, with git as the primary v1 path.
2. **Implement** git behavior: clone or fetch `repo_url` into deterministic `.artagents/nodes/<safe-id>/source`, checkout optional `source_ref`/`commit_sha`/`tag`/`branch`, read `manifest_path`, validate manifest, and then build the dependency environment from the installed source.
3. **Persist** install metadata such as installed path, repo URL, requested ref, resolved commit SHA, manifest path, manifest id, and install timestamp in `.artagents/nodes/<safe-id>/install.json`.
4. **Keep** dry-run free of network and filesystem mutations beyond any existing harmless plan construction.
5. **Avoid** registering or running a node whose installed manifest fails validation or identity matching.

### Step 11: Wire installer into CLI and registry opt-in (`ArtAgents/artagents/nodes/cli.py`, `ArtAgents/tests/test_nodes_cli.py`)
**Scope:** Medium
1. **Add** CLI options to list/validate/install nodes with Banodoco catalog enabled, while preserving current default behavior.
2. **Ensure** mandatory/default install targets can be installed when the explicit Banodoco/ArtAgents mode opts in.
3. **Make** dry-run output show git commands and target paths without network.
4. **Add** CLI tests for default no-network behavior, opt-in catalog loading, dry-run git plan, and mismatch failures.

## Phase 5: Validation And Regression Coverage

### Step 12: Website tests and quality checks (`reigh-app`)
**Scope:** Medium
1. **Run** targeted hook/component tests for the new agent-node feature.
2. **Run** targeted Edge Function tests for `agent-node-catalog`.
3. **Run** migration/RLS validation available in the repo, plus `npm run build` or `npm run test` if feasible.
4. **Run** `npm run lint` or the narrow lint target for changed website files.

### Step 13: ArtAgents tests (`ArtAgents`)
**Scope:** Medium
1. **Run** existing node tests first: `python -m pytest tests/test_nodes_registry.py tests/test_nodes_runner.py tests/test_nodes_cli.py tests/test_nodes_schema.py`.
2. **Add/run** new tests for catalog parsing, public/default/mandatory registry integration, git dry-run install, persisted install metadata, and manifest-id mismatch rejection.
3. **Run** broader ArtAgents tests if the targeted tests pass and runtime is acceptable.
