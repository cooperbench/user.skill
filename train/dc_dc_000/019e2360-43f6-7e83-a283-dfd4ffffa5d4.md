# Defect

`topic_editor_runs` has a UNIQUE INDEX on `(environment, guild_id, live_channel_id) WHERE status = 'running'` — this is the concurrent-run lease. But there's no stale-lease handling: if a runner crashes mid-run, its `status='running'` row stays forever, and NO future runner can ever acquire the lease for that (env, guild, channel). One crash = permanent blockage.

Confirmed by Codex review: *"stale lease expiry is missing."*

# Fix

In `src/common/storage_handler.py`, the method `acquire_topic_editor_run` (around line 882-910) does an INSERT into `topic_editor_runs`. Before the insert, query for any existing 'running' row matching `(environment, guild_id, live_channel_id)` whose `started_at` is older than `TOPIC_EDITOR_LEASE_TIMEOUT_MINUTES` (default 30). If found:

1. UPDATE that row to `status='expired'`, set `metadata` to include `{"expired_by": "<this run's about-to-be-inserted run_id>", "expired_at": <now>}`.
2. Then proceed with the new INSERT.

If no stale lease is found and a current-running lease exists (started <30min ago), the unique index will block this insert as expected — return None from `acquire_topic_editor_run` (the existing behavior signals "lease not acquired, skip this run").

Add an env var `TOPIC_EDITOR_LEASE_TIMEOUT_MINUTES` (default `30`). Read it in the lease check.

# Constraints
