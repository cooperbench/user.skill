> AGENT

Found the intended path. For VibeComfy, the worker is not supposed to use `HeadlessTaskQueue`; it should use the outer DB claim loop in [source/runtime/worker/server.py](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/runtime/worker/server.py:817). That loop calls `poll_next_task(...)`, which sends `worker_backend=parse_worker_backend().value`, so with `REIGH_BACKEND=vibecomfy` it should claim via [source/core/db/task_claim.py](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/core/db/task_claim.py:324).

The bug is in startup ordering in [source/runtime/worker/server.py](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/runtime/worker/server.py:646). The VibeComfy branch logs:

`VibeComfy backend active; skipping WGP import and queue startup`

but then still falls through shared WGP-era startup code before the claim loop: LoRA cleanup, `HeadlessTaskQueue` import setup, warm-cache bookkeeping, preflight finalization, status display setup, and only then the claim loop. Since the heartbeat guardian is already started at [server.py:623](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/runtime/worker/server.py:623), a hang or early stop after [server.py:648](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/runtime/worker/server.py:648) leaves the worker heartbeating/preflight-visible but never reaching `poll_next_task`.

Execution after a successful VibeComfy claim is already present: `TaskRegistry.dispatch()` routes direct queue task types through [source/task_handlers/tasks/task_execution.py](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/task_handlers/tasks/task_execution.py:25), and VibeComfy-supported routes bypass the WGP queue and call `handle_vibecomfy_resolved_task(...)` at [task_execution.py:62](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/task_handlers/tasks/task_execution.py:62). Tests already assert this does not require `task_queue`.

Minimal fix strategy:

1. Split `server.py` startup into backend-specific paths.
2. For `REIGH_BACKEND=vibecomfy`, skip all WGP-only post-log work: LoRA cleanup, `HeadlessTaskQueue` import/start, WGP warm-cache preload handling.
3. Finalize preflight as ready, then enter the same `while True: poll_next_task(...)` loop with `task_queue=None`.
4. Add an essential log immediately before the poll loop, e.g. `Task claim loop started backend=vibecomfy worker_id=...`, so this failure mode is obvious.
5. Add a server startup contract test with `REIGH_BACKEND=vibecomfy` proving startup reaches `poll_next_task` without importing/starting `HeadlessTaskQueue`.
