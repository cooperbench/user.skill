> AGENT

Yes.

Hermes is vendored into this repo at [megaplan/agent](/Users/user_c042661f/Documents/megaplan/megaplan/agent). It was brought in with `git subtree add --prefix=megaplan/agent /Users/user_c042661f/Documents/hermes-agent main`, documented in [docs/hermes-vendoring.md](/Users/user_c042661f/Documents/megaplan/docs/hermes-vendoring.md:3). `git log -- megaplan/agent` confirms the subtree import from Hermes commit `980e6b1...`, plus a local shim commit.

The shim is [megaplan/agent/__init__.py](/Users/user_c042661f/Documents/megaplan/megaplan/agent/__init__.py:1): importing `megaplan.agent` prepends `megaplan/agent` to `sys.path`, so Hermes’ original top-level imports like `run_agent`, `hermes_state`, and `model_tools` work without rewriting vendored code. Megaplan activates that in [megaplan/hermes_worker.py](/Users/user_c042661f/Documents/megaplan/megaplan/hermes_worker.py:24), then instantiates Hermes `AIAgent`.

Fireworks support: partially.

Hermes itself has generic OpenAI-compatible custom endpoint support, and the vendored code has explicit Fireworks test/docs references:
- Fireworks custom endpoint test: [test_cli_provider_resolution.py](/Users/user_c042661f/Documents/megaplan/megaplan/agent/tests/test_cli_provider_resolution.py:223)
- Fireworks tool-call compatibility test: [test_provider_parity.py](/Users/user_c042661f/Documents/megaplan/megaplan/agent/tests/test_provider_parity.py:205)
- Docs list Fireworks base URL: `https://api.fireworks.ai/inference/v1`

But Megaplan’s Hermes wrapper does **not** have first-class Fireworks routing in its own key pool. [megaplan/key_pool.py](/Users/user_c042661f/Documents/megaplan/megaplan/key_pool.py:15) only knows direct prefixes for `zhipu`, `minimax`, `google`, and `openrouter`. So `hermes:fireworks/...` will likely be treated as an OpenRouter model slug, not direct Fireworks.

Practical answer: Fireworks can work through Hermes as a custom OpenAI-compatible endpoint, but Megaplan does not currently expose it as a clean direct provider prefix like `fireworks:<model>`. To make it first-class, add `fireworks` to `key_pool.py` with `FIREWORKS_API_KEY`, base URL `https://api.fireworks.ai/inference/v1`, and a `fireworks:` model prefix.
