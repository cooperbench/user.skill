## Overview
The latest critique does not show that the plan targets the wrong root cause. The core path is still correct: sequences should be trusted first-class timeline clips rendered through the existing Remotion/theme registry path. The remaining flags are narrower execution gaps: the Sequence panel must use the actual current attachment set instead of all timeline media, Edge tests must be added to the explicit Edge Vitest include list, and AI-editable animation refs must be removed or strictly validated so preview/render cannot crash.

This revision keeps scope tight and aligned with the original idea. The implementation should reuse existing editor pieces first: timeline mutation helpers, selected media hooks, current attachment store, existing dialog/control primitives, `RemotionPreview`/`TimelineRenderer` plumbing, current `THEME_PACKAGE_REGISTRY` dispatch, `ThemeChip`/theme patterns, and Edge function auth/rate-limit conventions. Effects remain wrapper clips (`effect-layer`); sequences are ordinary first-class clips with trusted `clipType`, `params`, and `hold`. No shot-theme source of truth and no arbitrary generated code are introduced.

3. Add a focused row/meta round-trip test proving `{ clipType: 'section-hook', hold: 3, params: { title: 'X' } }` survives `buildTimelineData()` and `rowsToConfig()`.

### Step 2: Carry theme data through resolved config (`src/tools/video-editor/types/index.ts`, `src/tools/video-editor/lib/config-utils.ts`, resolved-config fixtures/tests)
**Scope:** Medium
1. Extend `ResolvedTimelineConfig` to include optional `theme`, `theme_overrides`, and `generation_defaults` copied from `TimelineConfig`.
2. Update `resolveTimelineConfig()` and local resolved-config test helpers so preview/render callers receive the same top-level theme fields as the persisted timeline.
3. Add tests in `src/tools/video-editor/lib/config-utils.test.ts` or adjacent fixtures proving resolved configs retain theme fields while timelines without theme fields remain valid.

### Step 3: Resolve installed themes for Remotion (`src/tools/video-editor/compositions/TimelineRenderer.tsx`, `src/tools/video-editor/sequences/themeRegistry.ts`)
**Scope:** Medium
1. Repair any existing syntax issue in `TimelineRenderer.tsx` before modifying renderer behavior.
2. Add a small browser-safe installed theme registry that maps known installed theme ids to full `Theme`-shaped metadata, starting with `2rp` from `@banodoco/timeline-theme-2rp` metadata. Keep fallback to `DEFAULT_THEME` from `@banodoco/timeline-composition/theme-api` when no theme is set.
3. Resolve `ResolvedTimelineConfig.theme` and `theme_overrides` into a full composition `Theme` value; do not rely on shot data or a loose untyped object without ensuring the `ThemeProvider` shape is complete.
4. Wrap registered themed sequence rendering with `ThemeProvider` from `@banodoco/timeline-composition/theme-api`, and continue using `THEME_PACKAGE_REGISTRY` for component dispatch.
5. Add/expand `TimelineRenderer` tests for: registered clip renders without placeholder, params are passed through, theme overrides affect the provided theme, and missing theme fields fall back cleanly.

## Phase 2: Shared Trusted Sequence Metadata And Validation

### Step 4: Add Deno/browser-safe sequence metadata (`src/tools/video-editor/sequences/metadata.ts`)
**Scope:** Medium
1. Create pure TypeScript metadata with no React, TSX component imports, or browser-only dependencies so frontend code and Supabase Edge functions can share it where practical.
2. Define the first trusted sequence set from installed 2rp clip types: `section-hook`, `art-card`, `resource-card`, and `cta-card`.
3. Include editable field metadata for core params used by existing components: strings such as `title`, `subtitle`, `kicker`, `caption`, `credit`, `label`, `detail`, `action`, and `note`; asset-list fields such as `previewAssetKeys` for `resource-card`; and timing via top-level `hold`.
4. Do not expose `entrance` or `exit` animation refs as AI-editable draft params in v1. Let the installed components use their defaults. If a manual UI later exposes animation refs, validate them against known animation ids and phase compatibility before render.
5. In frontend-only code, cross-check this metadata against `THEME_PACKAGE_REGISTRY` so a sequence type is offered only when its component is actually registered.

### Step 5: Add strict draft, asset, and animation-safe validation (`src/tools/video-editor/sequences/validation.ts`)
**Scope:** Medium
1. Validate generated drafts against shared metadata: allowed `clipType`, positive finite `hold`, known params only, JSON-serializable scalar/list values, and no function/code/import/stringified JSX fields.
2. Reject model-supplied `entrance`, `exit`, `previews`, raw URL fields, or any unknown animation-ref params in v1. This prevents unknown animation ids or phase mismatches from reaching `composeAnimations()`.
3. Treat asset-valued params specially. The model may output only asset keys from the allowed asset set built from selected clips and current attachment chips, not arbitrary URLs and not every timeline clip.
4. Store registry-backed asset refs in `clip.params` as keys, for example `previewAssetKeys`, and materialize component-facing URLs only at preview/render time from `ResolvedTimelineConfig.registry`.
5. For existing components that expect URL params, such as `resource-card.params.previews`, add a renderer-side param materializer that derives `previews` from validated registry keys and never trusts model-supplied remote URLs.
6. Add tests covering unknown clip type rejection, arbitrary URL rejection in `previews`, animation-ref rejection, allowed selected/current-attachment asset key acceptance, disallowed timeline-wide asset rejection, and render-time URL materialization.

### Step 6: Add sequence generation Edge Function and test infrastructure (`supabase/functions/ai-generate-sequence/`, `config/testing/vitest.edge.config.ts`)
**Scope:** Medium
1. Mirror existing Edge auth, rate-limit, logging, and response conventions from `supabase/functions/ai-generate-effect/index.ts`.
2. Import only Deno-safe shared sequence metadata/validation or duplicate the exact metadata intentionally if import constraints require it; do not import `THEME_PACKAGE_REGISTRY` or TSX components from Edge code.
3. Request schema: `prompt`, optional compact `timeline`, optional `selected_clips`, optional `attached_clips`, optional `allowed_clip_types`, optional `allowed_assets`, optional `theme`, optional `theme_overrides`.
4. Response schema: `drafts: Array<{ clipType, params, hold, title?, assetRefs? }>`, optional `message`, `model`; no code fields and no animation-ref fields in v1.
5. Validate the model response server-side before returning it. Invalid drafts are dropped or returned as structured errors; arbitrary URLs, unknown params, and animation refs do not reach the client.
6. Add Edge tests for auth validation, bad prompt, unknown generated clip type rejection, arbitrary asset URL rejection, animation-ref rejection, and valid structured draft output.
7. Update the explicit `EDGE_UNIT_INCLUDE` list in `config/testing/vitest.edge.config.ts` to include `supabase/functions/ai-generate-sequence/**/*.test.ts`, so the standard Edge unit suite runs the new tests.
