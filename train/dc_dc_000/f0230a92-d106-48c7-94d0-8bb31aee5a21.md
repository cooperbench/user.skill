## Foundational decisions (locked, do not re-debate)

### The three-layer split

Draw the line cleanly between "extract the archive" (lifecycle) and "interpret the archive" (consumer):

- **`runpod-lifecycle`** owns: pod launch, stateless reattach by id, `PodGuard` + signal handlers, the entire upload mechanism (sftp_walk + tarball, exclude set, disk preflight), sync + detached-with-poll exec, artifact archive pull + extract.
- **`vibecomfy`** keeps: `_runpod_config_kwargs` (env-var conventions), `REMOTE_ROOT`, `DEFAULT_UPLOAD_EXCLUDES` as module constants, and the entire artifact-format reader stack (`_parse_tsv`, `_collect_outputs`, `_collect_run_metadata`, `_collect_watchdogs`, `_build_artifact_manifest`, `_write_artifact_report`, `_print_detached_summary`). These read vibecomfy-shaped paths and are genuinely consumer concerns.
- **`Astrid`** gets a new pack at `astrid/packs/external/runpod/` with four executors plus a sweeper. Consumes the lifted lifecycle directly; does not go through vibecomfy.

### One critical new flag

`terminate_after_exec: bool = True` on `ship_and_run` / `ship_and_run_detached`. Vibecomfy's current code always terminates; Astrid's split provision/exec/teardown trio needs to leave the pod alive between exec calls. **The flag is the only behavioral addition beyond the lift.**

### Storage volume creation

Today `runpod-lifecycle` handles discovery, attachment, expansion. Missing piece is **creation**. v0.2 adds `api.create_network_volume(api_key, name, size_gb, datacenter_id)` (POST against the same REST endpoint that PATCH already uses) plus `Pod.create_storage()` / `Pod.list_storages()` / `Pod.get_storage(name_or_id)` as composable surface methods. **Deletion stays out** — rare, scary, RunPod console handles it.

### Vibecomfy backward compat is non-negotiable

Post-shrink, `vibecomfy/scripts/runpod_runner.py` re-exports `run_pod`, `run_pod_detached`, `REMOTE_ROOT`, `DEFAULT_UPLOAD_EXCLUDES`, and the artifact-format readers. Every existing caller (`runpod_validate.py`, `runpod_model_matrix.py`, `runpod_corpus_matrix.py`) imports unchanged. Behavior is identical; only the engine room moves.

### Astrid pack shape

One folder, four executors in a single `executor.yaml` (matches the `external.vibecomfy.{run,validate}` precedent):

- **`external.runpod.session`** — workhorse, composite. provision → exec → download → terminate inside a single Python `try/finally`. Guaranteed cleanup. Day-one default for `lora_train` and most callers.
- **`external.runpod.provision`** — emits `pod_handle.json` (`{pod_id, ssh, name, terminate_at, config_snapshot}`). Does not terminate.
- **`external.runpod.exec`** — consumes `pod_handle.json`, reattaches via `discovery.get_pod`, ships `local_root` + `remote_script`, downloads artifacts. Leaves pod alive.
- **`external.runpod.teardown`** — consumes `pod_handle.json`. Idempotent.

### Sweeper is load-bearing

Astrid has no `try/finally` / `on_failure` / `cleanup` step kind at the plan level. Two consequences:

1. The composite `session` executor is **mandatory, not optional** — only honest way to guarantee teardown for callers that don't need a hot pod across steps.
2. The split provision/exec/teardown trio needs a **sweeper** as its safety net — a crashed orchestrator between `provision` and `teardown` would leak a paid GPU pod. Sweeper covers that case.

`astrid runpod sweep` walks every `astrid-projects/<project>/runs/<run-ulid>/steps/<step-id>/v<N>/[iterations/NNN/]produces/pod_handle.json`, parses, calls `runpod-lifecycle`'s `discovery.list_pods` with the pack's `name_prefix`, decides per-pod with a two-mode policy:

- **Default (safe) mode** — terminate only if **all** of: `terminate_at` has passed; no live session has the handle ack'd; no in-flight exec on the pod (lifecycle's `discovery.get_pod` reports idle, not running). Pods that fail any check are left alone and reported.
- **`--hard` mode** — bypasses the live-session and idle-exec checks. Terminates anything past `terminate_at` regardless.

Every termination — in either mode — appends a `pod_terminated_by_sweep` event to the owning run's `events.jsonl` with `{pod_id, terminate_at, mode: "default"|"hard", reason}`.

`astrid doctor` *reports* stale handles (read-only); the `sweep` verb *mutates*. Doctor is the alert; sweep is the broom.

### Cost emission

Each executor declares `cost: {amount, currency: "USD", source: "runpod", basis}` on its completion event per Sprint 3's cost contract. The trio's three partial costs sum to what `session` would emit as one. Hourly rates come from RunPod's pricing API with a pinned-table fallback shipped in the pack.

Cost basis is `wallclock_seconds * gpu_hourly_rate` for the session/exec window.
