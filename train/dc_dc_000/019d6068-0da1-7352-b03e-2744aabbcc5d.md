## Phase 2: Migrate `createShotWithFilesPath` to Use Direct Cache Update

### Step 3: Add post-upload cache hydration to `createShotWithFilesPath` (`src/shared/hooks/shotCreation/shotCreationPaths.ts:114-158`)
**Scope:** Medium

1. **Add `queryClient` to `CreateShotWithFilesPathInput`** (`shotCreationTypes.ts:110-130`).

2. **After upload completes**, fetch the created shot's full data and cache it:
   - Option A (simpler): After `uploadToShot` returns, call `upsertShotInCache` with the shot data we already have from `createShot` + the generationIds from `uploadToShot`. The shot object from `createShot` is already returned. The issue is we don't have the full generation data.
   - Option B (more robust): After upload, do a targeted query to fetch the shot's generation data (one query: `shot_generations` joined with `generations` for the new shot), then `upsertShotInCache` with complete data.
   - Option C (simplest): Call `invalidateShotsQueries` with `refetchType: 'all'` to force immediate refetch. This is the least surgical but avoids the complexity of fetching individual generation data post-upload.

   **Recommended: Option B** — fetch the shot's generations after all uploads complete, build a complete Shot object, call `upsertShotInCache`. This matches the atomic pattern without needing a new RPC.
