# Implementation Plan: Plan Template & Structural Validation

## Overview

Add a concrete markdown template to the plan prompt, a lightweight structural validator that runs after plan generation, and structural validation to the critique step. The template codifies the patterns already proven in high-quality plans (Overview, numbered Steps with file:line refs, Execution Order, Validation Order). The validator is a fast regex/heading check — no LLM needed — that catches structural gaps before the plan enters the critique loop.

Additionally, add an optional "plan notes" injection mechanism so the orchestrator or user can prepend/append context to the plan prompt.

## Step 1: Add the plan template to the prompt (`prompts.py`)
**~40 lines added to `_plan_prompt()`**

1. **Add** a `PLAN_TEMPLATE` constant string (or inline block) in `prompts.py` containing the expected markdown structure as a concrete example. The template should show:
   - `# Implementation Plan: [Title]`
   - `## Overview` — 2-3 sentence summary of what changes and why
   - `## Step N: [description] (\`filename.py\`)` — numbered steps with:
     - Scope estimate in bold: `**~X lines changed**`
     - Numbered substeps with **bold action verbs**: `**Remove**`, `**Add**`, `**Update**`
     - File:line references in parens: `(lines 30-45)`
     - Code snippets in fenced blocks when essential
   - `## Execution Order` — numbered list with rationale for sequencing and risk notes
   - `## Validation Order` — numbered "cheap first" list of verification steps
2. **Include** a brief instruction block explaining the template is a guide, not rigid: plans with 2-3 steps can collapse Execution/Validation into a single section, plans with 15+ steps should use them fully. The key invariants are: must have Overview, must have numbered Steps, must have at least one of Execution Order or Validation Order.
3. **Inject** the template into the prompt text returned by `_plan_prompt()`, after the Requirements block.

## Step 2: Plan notes injection (`prompts.py`, `types.py`)

## Step 3: Structural validator (`evaluation.py`)
**~50 lines added, new function `validate_plan_structure()`**

1. **Add** `validate_plan_structure(plan_text: str) -> list[str]` that returns a list of structural issues (empty = valid). Checks:
   - Has exactly one H1 heading (`# `)
   - Has `## Overview` section (case-insensitive match)
   - Has at least one `## Step N:` section (regex: `^## Step \d+`)
   - Has at least one of `## Execution Order` or `## Validation Order`
   - Each Step section contains at least one numbered substep (`^\d+\.`)
   - Optional (warning-level, not blocking): steps reference files (backtick patterns)
2. **Return** structure: list of strings like `"Missing required section: ## Overview"`, `"Step 2 has no numbered substeps"`. Empty list means structurally valid.
3. **Keep it pure** — no I/O, no LLM. Just string parsing with `re` module. This is intentionally shallow: it checks sections exist, not that their content is good (that's the critique's job).

## Step 4: Wire validator into plan handler (`handlers.py`)
**~15 lines changed in `handle_plan()`**

1. **After** `plan_text = payload["plan"].rstrip() + "\n"` (line 415), call `validate_plan_structure(plan_text)`.
2. **If** issues are returned, decide behavior:
   - **Option A (recommended)**: Log warnings to the plan metadata (add `"structure_warnings": [...]` to meta dict) and continue. The critique step will catch content issues. This avoids blocking on structural edge cases.
   - **Option B**: Raise `CliError` for hard failures (missing Overview, zero Steps) and warn for soft failures. Only use this for truly degenerate output (no steps at all).
   - Implement Option A with a special case for Option B: if there are zero `## Step` sections, that's a hard fail (the LLM produced something completely off-template).
3. **Add** `structure_warnings` to the meta.json artifact so it's visible in the audit trail.

2. **If** `structure_warnings` exist in the plan metadata, include them in the critique prompt context: "The following structural warnings were detected automatically: {warnings}. Evaluate whether these are actual problems."
