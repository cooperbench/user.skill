Between-batch quality trip-wires during execution

## Problem
Quality issues accumulate silently during execution. We shipped v0.9.0 with duplicated code, dead code, and broken timeout recovery because nothing checked between batches. The post-execution review only checks if the plan was implemented correctly, not if the code is well-engineered.

## Solution
Lightweight quality checks that run between batches in the execution loop, alongside the existing git observation:

1. After each batch completes and before starting the next, run quick static checks:
   - File growth: did any file grow by more than a configurable threshold (e.g. 200 lines)? Flag it.
   - Duplicate detection: do any new functions share >80% token similarity with existing ones? Flag it.
   - Dead imports: did the batch add imports that aren't used? Flag it.
   - Test coverage: did the batch add code files without corresponding test changes? Flag it.

2. These are advisory (logged as deviations, not blocking) for v1. The executor sees them in the next batch's context so it can self-correct.

3. Results are included in the batch artifact and the aggregate execution.json so the reviewer sees them.

4. Keep it fast — these should add <5 seconds per batch. Use AST analysis and line counting, not heavy linting tools.

5. Make checks configurable via megaplan config so projects can enable/disable specific checks.

## Overview
Megaplan's batch execution loop (`execution.py:983-1063`) runs batches sequentially, calling `_run_and_merge_batch()` for each. After each batch, git observation (`_observe_git_changes`, line 429) detects file-level mismatches between claimed and actual changes. Quality checks will slot into the same post-batch, pre-next-batch window — specifically inside `_run_and_merge_batch()` after git observation (line 439) and before evidence checking (line 447). Results are advisory deviations, logged exactly like git observation findings.

The checks analyze the `after_snapshot` diff against `before_snapshot` to detect file growth, duplicate functions, dead imports, and missing test changes. They run on the actual files in the project directory, not on the executor payload.

Config lives in the existing `~/.config/megaplan/config.json` under a new `"quality_checks"` key, with per-check enable/disable and thresholds.

## Phase 1: Quality check engine

### Step 1: Add the quality checks module (`megaplan/quality.py`)
**Scope:** Medium
1. **Create** `megaplan/quality.py` with a top-level function:
   ```python
   def run_quality_checks(
       project_dir: Path,
       before_snapshot: dict[str, str],
       after_snapshot: dict[str, str],
       config: dict[str, Any],
       batch_number: int,
       batches_total: int,
   ) -> list[str]:
   ```
   Returns a list of advisory deviation strings (same format as git observation issues).

2. **Implement** four check functions, each returning `list[str]`:

   - `_check_file_growth(project_dir, changed_paths, threshold)` — For each changed file, count lines now vs. lines in `git show HEAD:path`. If growth exceeds threshold (default 200), flag it. Uses `subprocess.run(["git", "show", ...])` and `wc -l` equivalent via `path.read_text().count('\n')`. Falls back gracefully if file is binary or git show fails.

   - `_check_duplicate_functions(project_dir, changed_paths)` — For `.py` files only (v1 scope), use `ast.parse` to extract function bodies from changed files, then compare against other functions in the same file using a simple token-similarity metric (normalize whitespace, compare line-by-line overlap). Flag pairs exceeding 80% similarity. Keep it fast: only compare within-file, skip files >1000 lines.

   - `_check_dead_imports(project_dir, changed_paths)` — For `.py` files, use `ast.parse` to collect `import X` / `from X import Y` names, then check if each imported name appears elsewhere in the file text. Flag unused ones. Skip `__init__.py` files (re-exports are normal).

   - `_check_test_coverage(project_dir, changed_paths)` — If batch added/modified files matching common code patterns (`src/**/*.py`, `megaplan/*.py`, etc.) but no file matching `test_*` or `*_test.*` was also changed, flag it as advisory. Simple path-based heuristic, not actual coverage measurement.

3. **Wire** the config: each check reads from `config.get("quality_checks", {})`. Structure:
   ```json
   {
     "quality_checks": {
       "file_growth": {"enabled": true, "threshold": 200},
       "duplicate_functions": {"enabled": true},
       "dead_imports": {"enabled": true},
       "test_coverage": {"enabled": true}
     }
   }
   ```
   All checks enabled by default when the key is absent. Each check is skipped if `{"enabled": false}`.

4. **Enforce** the speed budget: each check function has a 2-second timeout via a simple wall-clock check. The overall `run_quality_checks` function logs timing and skips remaining checks if cumulative time exceeds 5 seconds.

        Idea:
Between-batch quality trip-wires during execution

## Problem
Quality issues accumulate silently during execution. We shipped v0.9.0 with duplicated code, dead code, and broken timeout recovery because nothing checked between batches. The post-execution review only checks if the plan was implemented correctly, not if the code is well-engineered.

## Solution
Lightweight quality checks that run between batches in the execution loop, alongside the existing git observation:

1. After each batch completes and before starting the next, run quick static checks:
   - File growth: did any file grow by more than a configurable threshold (e.g. 200 lines)? Flag it.
   - Duplicate detection: do any new functions share >80% token similarity with existing ones? Flag it.
   - Dead imports: did the batch add imports that aren't used? Flag it.
   - Test coverage: did the batch add code files without corresponding test changes? Flag it.

2. These are advisory (logged as deviations, not blocking) for v1. The executor sees them in the next batch's context so it can self-correct.

3. Results are included in the batch artifact and the aggregate execution.json so the reviewer sees them.

4. Keep it fast — these should add <5 seconds per batch. Use AST analysis and line counting, not heavy linting tools.

5. Make checks configurable via megaplan config so projects can enable/disable specific checks.

## Overview
Megaplan's batch execution loop (`execution.py:983-1063`) runs batches sequentially, calling `_run_and_merge_batch()` for each. After each batch, git observation (`_observe_git_changes`, line 429) detects file-level mismatches between claimed and actual changes. Quality checks will slot into the same post-batch window — inside `_run_and_merge_batch()` after git observation (line 439) and before evidence checking (line 447). Results are advisory deviations, logged exactly like git observation findings.

The checks use the existing `before_snapshot`/`after_snapshot` model (DECISION-001) to scope all analysis to the current batch. File growth is measured by capturing line counts of dirty files before the batch runs and comparing against post-batch line counts, with `git show HEAD:path` as fallback for files that were clean at batch start.

Config lives in the existing global config (`~/.config/megaplan/config.json`) under a `"quality_checks"` key. It is loaded once at the execute entry points and threaded to `_run_and_merge_batch` via a new parameter.

## Phase 1: Quality check engine

### Step 1: Add the quality checks module (`megaplan/quality.py`)
**Scope:** Medium
1. **Create** `megaplan/quality.py` with a top-level function:
   ```python
   def run_quality_checks(
       project_dir: Path,
       changed_paths: set[str],
       before_line_counts: dict[str, int],
       quality_config: dict[str, Any],
       batch_number: int,
       batches_total: int,
   ) -> list[str]:
   ```
   `changed_paths` is the set of files this batch touched (derived from before/after snapshot comparison via `_observed_batch_paths`). `before_line_counts` maps paths to their line counts at batch start. `quality_config` is the `"quality_checks"` dict from global config (empty dict if absent — all checks enabled by default). Returns a list of `"Advisory quality: ..."` deviation strings.

2. **Implement** four check functions, each returning `list[str]`:

   - `_check_file_growth(project_dir, changed_paths, before_line_counts, threshold)` — For each path in `changed_paths`, count lines in the current file. Determine baseline: if path is in `before_line_counts`, use that; otherwise run `git show HEAD:<path>` and count lines (returns 0 on failure, covering new/untracked files). If `current - baseline > threshold` (default 200), flag it. Skip binary files (catch `UnicodeDecodeError`).

   - `_check_duplicate_functions(project_dir, changed_paths)` — For `.py` files in `changed_paths`, use `ast.parse` to extract function/method bodies, then compare all pairs within the same file using a normalized-line-set overlap metric (Jaccard on stripped, non-empty lines). Flag pairs exceeding 80% similarity. Skip files >1000 lines. Skip on `SyntaxError`.

   - `_check_dead_imports(project_dir, changed_paths)` — For `.py` files in `changed_paths`, use `ast.parse` to collect imported names (`import X` → `X`, `from X import Y` → `Y`, `from X import Y as Z` → `Z`). Search the rest of the file text (excluding import lines) for each name. Flag unused ones. Skip `__init__.py` files. Skip on `SyntaxError`.

   - `_check_test_coverage(changed_paths)` — Partition `changed_paths` into code files and test files using path heuristics: test files match `test_*` or `*_test.*` or live under `tests/` or `test/`. If any code `.py` files were changed but zero test files were changed, flag with the list of code files. No filesystem access needed — pure path analysis.

3. **Wire** the config: `run_quality_checks` reads from `quality_config`. Structure:
   ```json
   {
     "quality_checks": {
       "file_growth": {"enabled": true, "threshold": 200},
       "duplicate_functions": {"enabled": true},
       "dead_imports": {"enabled": true},
       "test_coverage": {"enabled": true}
     }
   }
   ```
   All checks enabled by default when `quality_config` is empty. Each check is skipped when `{"enabled": false}`.

4. **Enforce** the speed budget: `run_quality_checks` records `time.monotonic()` before and after each check. If cumulative time exceeds 5 seconds, skip remaining checks and append an `"Advisory quality: skipped remaining checks (time budget exceeded)"` deviation.

   For each path in `snapshot_paths`, read the file and count lines. Skip binary files. This is called at batch start in `_run_and_merge_batch` before the worker runs.
