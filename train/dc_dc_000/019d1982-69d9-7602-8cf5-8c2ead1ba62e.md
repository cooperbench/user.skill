## Overview

Add a `megaplan step` command with `add`, `remove`, and `move` subcommands that operate directly on plan markdown files (`plan_v*.md`). The command parses `## Step N:` sections with fence-aware boundary detection, performs the requested edit, preserves `plan_v*.meta.json` fields, bumps the plan version via `plan_versions`, and resets state to `STATE_PLANNED` so the plan re-enters the critique loop.

**Current repo shape:** The CLI (`cli.py`) uses `argparse` with subparsers. Commands dispatch through `COMMAND_HANDLERS` (line 310). Plan markdown is parsed for validation in `evaluation.py:95` (`validate_plan_structure`) using `_strip_fenced_blocks` (line 83). Plan versioning uses `next_plan_artifact_name` and `plan_versions` records in `handlers.py:290`. The `_override_replan` handler (line 1073) already implements the state-reset-to-PLANNED pattern we need. Meta JSON carries `questions`, `success_criteria`, `assumptions`, and `structure_warnings`.

**Key constraints:**
- Section parsing must be fence-aware (code blocks can contain `##` headers)
- After edit, structural validation must pass before committing the new version
- Meta fields carry forward from the previous version
- State resets to `STATE_PLANNED` with `last_gate` cleared (same as replan)

## Step 1: Build fence-aware section parser (`megaplan/evaluation.py`)
**Scope:** Medium — this is the core primitive everything else depends on.

1. **Implement** `parse_plan_sections(plan_text: str) -> list[PlanSection]` at `megaplan/evaluation.py:93` (after `_strip_fenced_blocks`). `PlanSection` is a simple dataclass: `id` (e.g. "S1"), `heading` (full heading text), `start_line` (0-based, inclusive), `end_line` (exclusive), `body` (raw text of section including heading).
2. **Reuse** the fence-tracking pattern from `_strip_fenced_blocks` (line 83–92) but instead of stripping, track `inside_fence` state while scanning for `^##\s+Step\s+\d+:\s+` boundaries. Only match headings when `inside_fence is False`.
3. **Also capture** non-step sections (Overview, Execution Order, etc.) as `PlanSection(id=None, ...)` so we can reconstruct the full document after edits.
4. **Add** `reassemble_plan(sections: list[PlanSection]) -> str` that joins sections back into a complete markdown document, preserving original whitespace.
5. **Add** `renumber_steps(sections: list[PlanSection]) -> list[PlanSection]` that updates both `id` fields and heading text to reflect sequential `Step 1, Step 2, ...` numbering.

```python
@dataclass
class PlanSection:

    body: str             # Full text including heading
```

## Step 2: Implement step manipulation logic (`megaplan/handlers.py`)
**Scope:** Medium

1. **Add** `handle_step(root, args) -> StepResponse` at end of `megaplan/handlers.py`. This dispatches to `_step_add`, `_step_remove`, `_step_move` based on `args.step_action`.
2. **`_step_add(plan_dir, state, args)`:** Parse latest plan, create a new section with auto-generated ID and the user's description text, insert it after the `--after` step (or append after last step if omitted). Renumber, reassemble, validate structure, then commit.
3. **`_step_remove(plan_dir, state, args)`:** Parse latest plan, remove the named step section. Renumber, reassemble, validate structure, then commit. Reject if it would leave zero steps.
4. **`_step_move(plan_dir, state, args)`:** Parse latest plan, extract the named step, insert it after the `--after` target. Renumber, reassemble, validate structure, then commit.
5. **Common "commit" logic** shared by all three: bump version via `next_plan_artifact_name`, write new `plan_v{N}.md`, copy forward meta fields from previous version's `.meta.json` (questions, success_criteria, assumptions) into new `.meta.json`, append to `plan_versions`, reset state to `STATE_PLANNED`, clear `last_gate`, record the edit in history, save state. Use `validate_plan_structure` on the result; raise `CliError` if the edit breaks structure.
