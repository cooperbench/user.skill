**Result**
Mixed, but the important runtime issue is an implementation regression/incomplete migration.

- `tests/test_scaling_decision_spawn.py` and `tests/test_scaling_decision_limits.py` pass as currently written:
  - `20 passed in 0.03s`
- Focused route/count/state tests also pass:
  - `30 passed in 1.24s`
- `tests/test_task_counts.py` does not exist anywhere under `reigh-worker-orchestrator`; running that path fails with:
  - `ERROR: file or directory not found: tests/test_task_counts.py`

**Root Cause**
The route-aware task-count change was applied to `gpu_orchestrator/control/phases/state.py::StatePhaseMixin._fetch_current_state`, but the live `gpu_orchestrator/control_loop.py::OrchestratorControlLoop._fetch_current_state` still reads aggregate `detailed_counts["totals"]` and ignores `selected_pool_totals`.

I confirmed with a small in-memory probe: when `totals.potentially_claimable=10` and `selected_pool_totals.potentially_claimable=2`, `OrchestratorControlLoop._fetch_current_state()` returns `TaskCounts(queued=10, active_cloud=0, total=10)`, so the live loop would overscale for all pools instead of only the selected pool.

**Affected Files/Functions**
- `reigh-worker-orchestrator/gpu_orchestrator/control_loop.py`
  - `OrchestratorControlLoop._fetch_current_state`: stale aggregate-only logic.
  - `_log_detailed_task_breakdown`: still logs aggregate totals, not selected pool totals.
- `reigh-worker-orchestrator/gpu_orchestrator/control/phases/state.py`
  - `StatePhaseMixin._fetch_current_state`: has the intended selected-pool logic.
- `reigh-worker-orchestrator/gpu_orchestrator/database.py`
  - `apply_selected_pool_totals`: likely incomplete contract handling. It does not filter by `worker_pool`, and it initializes but does not sum `blocked_by_capacity`, `blocked_by_deps`, or `blocked_by_settings`.

**Recommended Fix**
- Mirror the `selected_pool_totals` logic from `control/phases/state.py` into `control_loop.py::_fetch_current_state`, or make the live loop use the phase mixin path.
- Update detailed logging to use the same selected totals so diagnostics match scaling decisions.
- Harden `apply_selected_pool_totals`:
  - include `worker_pool` matching if `route_totals` exposes it,
  - sum blocked fields,
  - compute `potentially_claimable` as explicit value if present, otherwise `queued_only + blocked_by_capacity`.
- Update test command/path references: replace missing `tests/test_task_counts.py` with `tests/gpu_orchestrator/test_route_aware_task_counts.py`, unless the missing file is meant to be restored.
