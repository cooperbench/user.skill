        # Implementation Plan: Project + ProjectTimeline

## Overview
Add a persistent project layer so ArtAgents can organize executor/orchestrator runs and compose a canonical project timeline from source assets and prior run clips. The overall approach remains the right root cause: keep ProjectTimeline as an ArtAgents-only format, add `artagents/core/project/` for state and materialization, and materialize to the existing `TimelineConfig` + `AssetRegistry` consumed by render/validate.

The remaining critique does not require a new architecture, but it identifies two concrete adapter details the plan must handle. First, direct hype `--project` must prepare a project run before `resolve_args()` can raise validation errors, because `main()` currently calls `resolve_args()` before `pool_main()`. Second, hype writes final `hype.timeline.json`, `hype.assets.json`, and `hype.metadata.json` under `<out>/briefs/<brief_slug>/`, not necessarily at the run root, so project finalization must discover and mirror nested hype artifacts into canonical project run files.

Use the plural top-level CLI command `projects`. Top-level dispatch belongs in `artagents/pipeline.py`; `setup_cli.py` should only plan/apply project-root setup behavior.
