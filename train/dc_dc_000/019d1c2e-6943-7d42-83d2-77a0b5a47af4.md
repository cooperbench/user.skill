        # Implementation Plan: Card System Redesign — Fixed-Shell Expansion Architecture

## Overview

The homepage card grid (`Dashboard.tsx`) renders 5 card types (story, project, video, data, meme) that share a single monolithic `.card` CSS class (335 lines in `Cards.module.css`) with interleaved `:hover`, `.expanded`, and card-type-specific overrides. The expansion mechanism sets `height: auto` on the card element itself, which changes its hit-test area and causes the well-documented pointer-leave bug (cursor ends up inside the now-taller card, `pointerLeave` never fires).

**Root cause:** The element that owns the pointer events is the same element that changes height.

**Core fix:** Separate the pointer-event boundary (fixed-height outer shell) from the expanding content (inner region or overlay that grows beyond the shell). The shell never changes height, so `pointerLeave` always fires reliably when the cursor exits the original card footprint.

**Scope:** Medium

## Step 3: Restructure `Cards.module.css` — shell vs. card separation
**Scope:** Large (this is the bulk of the CSS work)

1. **Add** `.cardShell` rules (new):
   ```css
   .cardShell {
     position: relative;
     overflow: visible;  /* expanded content can overflow */
   }
   ```
   The shell is intentionally minimal — it exists for grid sizing and pointer events only.

2. **Modify** `:global(.card)` (lines 1-18) — remove `overflow: hidden` (move to a non-expanded state), remove the fixed height rules (shell handles height). Card becomes:
   ```css
   :global(.card) {
     position: relative;  /* for ::before/::after pseudo-elements */
     display: flex;
     flex-direction: column;
     min-height: 100%;    /* fill shell when collapsed */
     overflow: hidden;    /* clip content when not expanded */
     border: 1px solid var(--color-border-soft);
     border-radius: var(--radius-card);
     background: var(--color-surface);
     box-shadow: var(--shadow-card);
     cursor: pointer;
     padding: 1.5rem 1.5rem 1rem;
     transform-origin: top center;
     transition: transform 0.25s ease, box-shadow 0.25s ease, border-color 0.25s ease;
   }
   ```

3. **Modify** `.card.expanded` (lines 53-60) — no longer sets `height: auto` on the element that receives pointer events. The inner card naturally grows:
   ```css
   :global(.card.expanded) {
     z-index: 10;
     overflow: visible;
     transform: scale(1.02);
     box-shadow: var(--shadow-card-hover);
   }
   ```
   Note: `height: auto` is now implicit since `.card` uses `min-height: 100%` and naturally grows with content.

4. **Preserve** all existing `:hover` visual feedback (scale, shadow, border, filter) — these are purely cosmetic and don't cause the bug.

5. **Preserve** the `::before` top gradient and `::after` fade overlay exactly as-is.

6. **Audit** every rule that references `:global(.card.expanded)` or `:global(.card:not(.expanded))` (there are ~15 such rules) and verify they still work with the new structure. Key ones:
   - `.textContent` masking (lines 125-142): still works, references `.card` ancestor
   - `.linkRow` visibility (lines 204-209): still works
   - `.memeHoverContainer` (lines 279-284): still works
   - `.imageContainer` padding-bottom (lines 101-108): still works

7. **Remove** image container padding-bottom transitions on hover (lines 101-108). The padding-bottom changing from 50% → 56% → 65% causes layout shifts that contribute to the expansion height mismatch. Instead, use a fixed aspect ratio that works at all states:
   ```css
   .imageContainer {
     aspect-ratio: 16 / 9;   /* replaces padding-bottom hack */
     height: auto;
     padding-bottom: 0;
   }
   ```
   Or, if `aspect-ratio` is too aggressive a change, at minimum remove the hover/expanded padding-bottom transitions and keep a single value.

## Overview

The homepage card grid (`Dashboard.tsx`) renders 5 card types (story, project, video, data, meme) sharing a monolithic `.card` CSS class (335 lines in `Cards.module.css`). Two core problems:

1. **Pointer-leave bug:** `.card.expanded` sets `height: auto`, the element grows taller, the cursor ends up inside the now-taller element, and `pointerLeave` never fires. Previous fix attempts (polling, pointer-events:none, constraining height, safety timer) all failed.

2. **Dual state ownership:** Content layout changes (image sizing, text unclamping, link visibility, meme reveal, chart controls) are driven by BOTH CSS `:hover` and React's `.expanded` class, causing specificity wars and unpredictable behavior.

### Core fixes

**Fix 1 — Rect-check collapse:** Instead of relying on `pointerleave` (which fails when descendants overflow), use a `pointermove` document listener that checks the cursor position against a **stored fixed rect** of the card. The rect is captured on enter (before expansion changes geometry) and never updated during expansion. When the cursor leaves that rect, the card collapses. This avoids the fundamental DOM issue where `pointerleave` doesn't fire while cursor is over any descendant — even overflowed ones.

**Fix 2 — Single state owner:** Remove all `:hover`-driven content/layout rules. CSS `:hover` only controls cosmetic feedback (scale, shadow, border-color, image filter/desaturation). The React `.expanded` class is the sole driver of all content changes (text unclamping, link visibility, image sizing, meme container, chart controls). Since `onPointerEnter` sets `.expanded` immediately, the visual result is identical — but there's now one source of truth.

## Step 1: Replace pointer-leave with rect-check collapse (`src/hooks/useCardExpansion.ts`)
**Scope:** Medium — this is the critical bug fix

The current hook (`useCardExpansion.ts:36-61`) uses `onPointerEnter`/`onPointerLeave` callbacks that Dashboard binds to each card div. The leave callback sets a 150ms timer to collapse. This fails when the card expands and the cursor ends up inside the now-taller element.

1. **Add** a `shellRectsRef` (Map<string, DOMRect>) to store the bounding rect of each card at the moment of pointer enter, BEFORE expansion changes geometry.

2. **Add** a `pointermove` document listener (active only when a card is expanded) that checks cursor position against the stored rect:
   ```ts
   useEffect(() => {
     if (!expandedCardId || isMobile) return;
     const rect = shellRectsRef.current.get(expandedCardId);
     if (!rect) return;

     const onMove = (e: PointerEvent) => {
       if (
         e.clientX < rect.left || e.clientX > rect.right ||
         e.clientY < rect.top || e.clientY > rect.bottom
       ) {
         // Cursor left the original card footprint — check if it entered another card
         const enterTarget = document.elementFromPoint(e.clientX, e.clientY)?.closest('[data-card-id]');
         if (enterTarget) {
           const newId = enterTarget.getAttribute('data-card-id')!;
           shellRectsRef.current.set(newId, enterTarget.getBoundingClientRect());
           setExpandedCardId(newId);
         } else {
           setExpandedCardId(null);
         }
       }
     };

     document.addEventListener('pointermove', onMove);
     return () => document.removeEventListener('pointermove', onMove);
   }, [expandedCardId, isMobile]);
   ```

3. **Modify** `onCardMouseEnter` (`useCardExpansion.ts:36-47`) to capture the card's bounding rect into `shellRectsRef` before setting expanded state. The callback receives the card element (or its rect) from Dashboard.

4. **Remove** `onCardMouseLeave` entirely — it's replaced by the rect-check listener.

5. **Remove** the collapse timer (`collapseTimerRef`) — no longer needed since collapse is driven by cursor position, not leave events.

6. **Keep** `onCardToggle` for mobile tap behavior unchanged (`useCardExpansion.ts:63-69`).

7. **Keep** the outside-click listener for mobile (`useCardExpansion.ts:14-28`), but update the selector from `.closest('.card')` to `.closest('[data-card-id]')` for robustness.

**Why this works:** The rect is captured at pointer-enter time (before expansion). It represents the card's original footprint. The `pointermove` listener checks against this fixed rect, not the card's current (expanded) geometry. Even though the card grows taller, the collapse trigger is the original boundary.

**Edge case — card-to-card hover:** When the cursor moves from card A to card B, the `elementFromPoint` check detects card B and switches expansion directly, avoiding a flash of collapse.

**Edge case — scroll:** If the user scrolls while a card is expanded, the stored rect becomes stale. Add a scroll listener that recalculates: `shellRectsRef.current.set(expandedCardId, element.getBoundingClientRect())`.

## Overview

The homepage card grid (`Dashboard.tsx`) renders 5 card types (story, project, video, data, meme) sharing a monolithic `.card` CSS class (335 lines in `Cards.module.css`). Two core problems:

1. **Pointer-leave bug:** `.card.expanded` sets `height: auto`, the element grows taller, the cursor ends up inside the now-taller element, and `pointerLeave` never fires. Previous fix attempts (polling, pointer-events:none, constraining height, safety timer) all failed.

2. **Dual state ownership:** Content layout changes (image sizing, text unclamping, link visibility, meme reveal, chart controls) are driven by BOTH CSS `:hover` and React's `.expanded` class, causing specificity wars and unpredictable behavior.

### Core fixes

**Fix 1 — Rect-check collapse:** Instead of relying on `pointerleave` (which fails when descendants overflow), use a `pointermove` document listener that checks the cursor position against a **stored fixed rect** of the card. The rect is captured on enter (before expansion changes geometry) and never updated during expansion. When the cursor leaves that rect, the card collapses — regardless of what `elementFromPoint` returns. This avoids both the fundamental `pointerleave` DOM issue and the self-hit problem where `elementFromPoint` resolves back to the currently expanded card's overflow area.

**Fix 2 — Single state owner:** Remove all `:hover`-driven content/layout rules. CSS `:hover` only controls cosmetic feedback (scale, shadow, border-color, image filter/desaturation). The React `.expanded` class is the sole driver of all content changes (text unclamping, link visibility, image sizing, meme container, chart controls). Since `onPointerEnter` sets `.expanded` immediately, the visual result is identical — but there's now one source of truth.

## Step 1: Replace pointer-leave with rect-check collapse (`src/hooks/useCardExpansion.ts`)
**Scope:** Medium — this is the critical bug fix

The current hook (`useCardExpansion.ts:36-61`) uses `onPointerEnter`/`onPointerLeave` callbacks that Dashboard binds to each card div. The leave callback sets a 150ms timer to collapse. This fails when the card expands and the cursor ends up inside the now-taller element.

1. **Add** a `shellRectsRef` (`useRef<Map<string, DOMRect>>`) to store the bounding rect of each card at the moment of pointer-enter, BEFORE expansion changes geometry.

2. **Modify** `onCardMouseEnter` (`useCardExpansion.ts:36-47`) to accept a `DOMRect` parameter and store it in `shellRectsRef` before setting expanded state:
   ```ts
   const onCardMouseEnter = useCallback(
     (cardId: string, rect: DOMRect) => {
       if (isMobile) return;
       shellRectsRef.current.set(cardId, rect);
       setExpandedCardId(cardId);
     },
     [isMobile],
   );
   ```

3. **Add** a `pointermove` document listener (active only when a card is expanded) that checks cursor position against the stored rect. **Critical: when the cursor is outside the stored rect, collapse is the default. A different card is only expanded if `elementFromPoint` resolves to a card OTHER than the currently expanded one:**
   ```ts
   useEffect(() => {
     if (!expandedCardId || isMobile) return;
     const rect = shellRectsRef.current.get(expandedCardId);
     if (!rect) return;

     const onMove = (e: PointerEvent) => {
       const outside =
         e.clientX < rect.left || e.clientX > rect.right ||
         e.clientY < rect.top || e.clientY > rect.bottom;
       if (!outside) return;

       // Cursor left the original card footprint — default is collapse
       const enterTarget = document.elementFromPoint(e.clientX, e.clientY)
         ?.closest('[data-card-id]');
       const newId = enterTarget?.getAttribute('data-card-id') ?? null;

       if (newId && newId !== expandedCardId) {
         // Cursor entered a DIFFERENT card — expand it instead
         shellRectsRef.current.set(newId, enterTarget!.getBoundingClientRect());
         setExpandedCardId(newId);
       } else {
         // Cursor is over empty space, browser chrome, or the same card's
         // overflow area — collapse unconditionally
         setExpandedCardId(null);
       }
     };

     document.addEventListener('pointermove', onMove);
     return () => document.removeEventListener('pointermove', onMove);
   }, [expandedCardId, isMobile]);
   ```
   The `newId !== expandedCardId` guard is load-bearing: without it, `elementFromPoint` resolving to the same card's overflow area would re-expand instead of collapsing — reproducing the original bug under a different mechanism.

4. **Remove** `onCardMouseLeave` entirely (`useCardExpansion.ts:49-61`) — replaced by the rect-check listener.

5. **Remove** the collapse timer refs (`collapseTimerRef`, `hoverIntentRef`) and cleanup effect (`useCardExpansion.ts:30-34`) — no longer needed.

6. **Keep** `onCardToggle` for mobile tap behavior unchanged (`useCardExpansion.ts:63-69`).

7. **Keep** the outside-click listener for mobile (`useCardExpansion.ts:14-28`), but update the selector from `.closest('.card')` to `.closest('[data-card-id]')` for robustness.

8. **Add** a scroll listener inside the same effect that recalculates the stored rect, handling the edge case where scrolling makes the stored rect stale:
   ```ts
   const onScroll = () => {
     const el = document.querySelector(`[data-card-id="${expandedCardId}"]`);
     if (el) shellRectsRef.current.set(expandedCardId, el.getBoundingClientRect());
   };
   window.addEventListener('scroll', onScroll, { passive: true });
   ```
