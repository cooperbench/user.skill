**Root Cause**
The output frame count should be driven by task `num_frames`/`video_length`, mapped into the native Comfy node `WanAnimateToVideo.length`. `frame_window_size` is a context/window control in the Kijai wrapper path, not the output-frame contract.

The mismatch is introduced in the VibeComfy worker scratchpad/template boundary:

- The worker media contract expects `num_frames` because `_video_contract_for_resolved_task()` falls back through `expected_frame_count`, `num_frames`, `video_length`: [vibecomfy_adapter.py](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/models/comfy/vibecomfy_adapter.py:1235).
- The animate scratchpad never patches frame count into the template. It patches inputs, prompt, size, seed, steps, fps, and output options only: [vibecomfy_adapter.py](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/models/comfy/vibecomfy_adapter.py:818).
- The VibeComfy native template hard-codes `WanAnimateToVideo.length = 77`, so the run emits 77 frames: [wan22_animate_native_first_stage.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/ready_templates/video/wan22_animate_native_first_stage.py:128).

**Parity Call**
Keep the worker contract strict. Relaxing validation would hide a real semantic mismatch. Wan2GP uses `video_length` as the output frame count and separately has sliding-window controls; Reigh worker docs/tests also treat `num_frames` as canonical child frame count: [task_registry.py](/Users/user_c042661f/Documents/reigh-workspace/reigh-worker/source/task_handlers/tasks/task_registry.py:284).

**Recommended Fix**
This is a combined template/scratchpad fix, with an optional app pass-through fix.

- In [wan22_animate_native_first_stage.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/ready_templates/video/wan22_animate_native_first_stage.py:178), add `num_frames: "232:62.length"` to `READY_METADATA["unbound_inputs"]`.

Tests to change/add:
