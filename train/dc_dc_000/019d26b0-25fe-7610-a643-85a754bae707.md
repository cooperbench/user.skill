## Problem
The same subsystem gets flagged and point-fixed across multiple plans without being properly redesigned. In this session, timeout recovery was flagged in 4 separate plans. Each plan did a point fix. The critiquer had no way to know 'this has been flagged before — stop patching and redesign it.'

## Solution
A .megaplan/debt.json registry that persists across plans:

1. When a critique flag is accepted as a known limitation (force-proceed, or gate says 'accepted tradeoff'), it gets added to debt.json with the flag ID, concern, which plan accepted it, and when.

2. The critique prompt includes the debt registry as context: 'These are known accepted limitations — don't re-flag them unless the current plan makes them worse.'

3. The gate prompt includes it too: if the current plan's flags overlap with existing debt, the gate can note 'this is recurring debt, consider addressing it holistically.'

4. The executor prompt includes relevant debt items as watch items: 'Don't make these worse.'

5. A CLI command to manage debt: megaplan debt list, megaplan debt add, megaplan debt resolve. Resolving removes it and records which plan fixed it.

6. When debt items accumulate in the same subsystem (e.g. 3+ items tagged 'timeout-recovery'), surface this clustering to the critiquer as a signal to recommend redesign rather than another point fix.

        # Implementation Plan: Persistent Tech Debt Registry

## Overview
Megaplan's per-plan `faults.json` tracks flags within a single plan, but nothing persists across plans. When a concern is force-proceeded past or accepted as a tradeoff, it vanishes — so the same subsystem gets point-fixed repeatedly.

This adds `.megaplan/debt.json`, a cross-plan registry of accepted technical debt. Debt entries are structured by subsystem tag, deduplicated on add, and surfaced to critique/gate/execute prompts. A `megaplan debt` CLI manages the registry. Both force-proceed and normal gate PROCEED-with-unresolved-flags automatically register debt.

**Key design decisions addressing v1 critique:**
- **Storage root (FLAG-001):** All debt I/O uses `root` (the megaplan runtime root), not `project_dir`. Debt lives at `root/.megaplan/debt.json` alongside `root/.megaplan/plans/`. Prompt builders receive `root` as an additional parameter where needed.
- **Subsystem tagging (FLAG-002):** Subsystem tags are **never** auto-derived from flag `category`. On force-proceed/gate-accept, the subsystem tag is extracted from the flag's concern text by taking the prefix before the first colon (e.g. `"Timeout recovery: lacks retry"` → `timeout-recovery`), falling back to `"untagged"`. The gate LLM is prompted to include subsystem-meaningful prefixes in its `accepted_tradeoffs`. The CLI `debt add` requires an explicit `--subsystem` tag.
- **Escalation metric (FLAG-003):** Escalation checks **total occurrences** across a subsystem (sum of `occurrence_count` for all entries in that subsystem), not entry count. A single entry with `occurrence_count=4` triggers escalation at threshold 3.
- **Gate acceptance path (FLAG-004):** The gate schema gains an `accepted_tradeoffs` array field. `handle_gate` reads this after the LLM call and auto-registers each accepted tradeoff as debt. This covers the normal-gate path alongside force-proceed.

## Phase 1: Data Model and I/O

### Step 1: Define DebtEntry type and constants (`megaplan/types.py`)
**Scope:** Small
1. **Add** `DebtEntry` TypedDict (~`types.py:130`):
   ```python
   class DebtEntry(TypedDict):
       id: str                    # DEBT-001, DEBT-002, ...
       subsystem: str             # e.g. "timeout-recovery", "execute-paths"
       concern: str               # normalized concern string
       flag_ids: list[str]        # FLAG-xxx IDs that contributed
       plan_ids: list[str]        # plan slugs where this was accepted
       occurrence_count: int      # times this concern has been hit
       created_at: str            # ISO 8601
       updated_at: str            # ISO 8601
       resolved: bool             # False until explicitly resolved
       resolved_by: str | None    # plan slug that fixed it, or None
       resolved_at: str | None    # ISO 8601 or None
   ```
2. **Add** `DebtRegistry` TypedDict: `{"entries": list[DebtEntry]}`.
3. **Add** `DEBT_ESCALATION_THRESHOLD = 3` constant.

### Step 2: Debt I/O helpers (`megaplan/_core.py`)
**Scope:** Medium
1. **Add** `load_debt_registry(root: Path) -> DebtRegistry` — reads `root/.megaplan/debt.json`, returns `{"entries": []}` if missing. Parameter is `root` (megaplan runtime root), **not** `project_dir`.
2. **Add** `save_debt_registry(root: Path, registry: DebtRegistry)` — atomic write to `root/.megaplan/debt.json`.
3. **Add** `next_debt_id(registry: DebtRegistry) -> str` — returns `DEBT-{N+1}` based on max existing ID.
4. **Add** `extract_subsystem_tag(concern: str) -> str` — extracts subsystem from concern text: if concern contains a colon, take the prefix, normalize to kebab-case (lowercase, spaces/underscores to hyphens). If no colon prefix, return `"untagged"`. Examples: `"Timeout recovery: lacks retry"` → `"timeout-recovery"`, `"The executor might fail"` → `"untagged"`.
5. **Add** `find_matching_debt(registry, subsystem, concern) -> DebtEntry | None` — matches by exact subsystem tag AND word-set Jaccard similarity > 0.5 on normalized concern text (lowercase, split on whitespace, remove stopwords). This is the dedup check. Exact subsystem match is required — different subsystems never dedup.
6. **Add** `add_or_increment_debt(registry, subsystem, concern, flag_ids, plan_id) -> DebtEntry` — if `find_matching_debt` returns a match, increment `occurrence_count`, extend `flag_ids` (deduped) and `plan_ids` (deduped), update `updated_at`; otherwise create new entry via `next_debt_id`.
7. **Add** `resolve_debt(registry, debt_id, plan_id) -> DebtEntry` — marks entry resolved with plan slug and timestamp. Raises `CliError` if `debt_id` not found.
8. **Add** `debt_by_subsystem(registry) -> dict[str, list[DebtEntry]]` — groups **unresolved** entries by subsystem tag.
9. **Add** `subsystem_occurrence_total(entries: list[DebtEntry]) -> int` — returns `sum(e["occurrence_count"] for e in entries)`. This is the escalation metric.
10. **Add** `escalated_subsystems(registry) -> list[tuple[str, int, list[DebtEntry]]]` — for each subsystem group from `debt_by_subsystem`, compute `subsystem_occurrence_total`; return those where total `>= DEBT_ESCALATION_THRESHOLD`. Each tuple is `(subsystem_tag, total_occurrences, entries)`.
