        Plan:
        # Implementation Plan: LLM-Powered Custom Effects Editor

## Overview

The video editor has a working custom effects system: users manually write Remotion JSX code, compile it via Sucrase, and save to an `effects` DB table. The goal is to upgrade this into an LLM-powered workflow where users describe effects in natural language, get generated code back, validate/preview it, and save as a `resources` table entry (type: `'effect'`). Effects become shareable (public/private) and appear in the standard effect dropdowns alongside built-ins.

**Current state:**
- **Effects table** (`effects`): stores `slug`, `name`, `code`, `category`, `description`, `user_id`, `is_public`. Queried via `useEffects` hook (`src/tools/video-editor/hooks/useEffects.ts`).
- **Resources table** (`resources`): generic store with `type`, `metadata` (JSON), `user_id`, `is_public`. Types: `lora`, `phase-config`, `style-reference`, `structure-video`. Hooks in `src/features/resources/hooks/useResources.ts`.
- **Compile pipeline**: `compileEffect.tsx` uses Sucrase to transform JSX/TS → JS, wraps in Function constructor with injected Remotion globals.
- **DynamicEffectRegistry** (`DynamicEffectRegistry.ts`): merges built-in + dynamic effects. Used by `wrapWithClipEffects()` in `index.tsx`.
- **CustomEffectEditor** (`CustomEffectEditor.tsx`): manual code editor with name/slug/description/code fields. No LLM integration — just shows the prompt template as reference text.
- **Effect dropdowns** (`ClipPanel.tsx:119-161`): show only built-in effect types. Custom effects require the separate editor panel.
- **LLM edge function pattern**: `ai-prompt` uses Groq SDK with fallback model support (`supabase/functions/ai-prompt/index.ts`).

**Key constraints:**
- Must use the Sucrase compile pipeline (already proven).
- Resources table is the target storage (not effects table).
- Edge function for LLM calls (not client-side).
- Effects need category metadata (entrance/exit/continuous) for correct dropdown placement.

## Phase 1: Foundation — Storage Migration & Types

### Step 1: Define the effect resource type and metadata interface (`src/features/resources/hooks/useResources.ts`)
**Scope:** Small
1. **Add** `EffectMetadata` interface with fields: `name`, `slug`, `code`, `category` (`'entrance' | 'exit' | 'continuous'`), `description`, `created_by`, `is_public`.
2. **Extend** `ResourceType` union to include `'effect'`.
3. **Update** `ResourceMetadata` union to include `EffectMetadata`.
4. **Update** `isResourceType()` guard to accept `'effect'` (`useResources.ts:94-96`).

### Step 2: Create effect resource hooks (`src/tools/video-editor/hooks/useEffectResources.ts`)
**Scope:** Medium
1. **Create** `useEffectResources(userId)` hook that wraps `useListResources('effect')` and `useListPublicResources('effect')` to return combined, deduped effects.
2. **Add** `useCreateEffectResource()` and `useUpdateEffectResource()` mutations using `useCreateResource` / `useUpdateResource` from useResources.
3. **Add** `useDeleteEffectResource()` mutation.
4. **Ensure** query invalidation on mutations covers both user and public effect lists.
5. **Group** effects by category in the return value for easy consumption by dropdowns.

### Step 3: Update `useEffectRegistry` to consume resource-based effects (`src/tools/video-editor/hooks/useEffectRegistry.ts`)
**Scope:** Small
1. **Change** the `dbEffects` parameter type from `Array<{ slug: string; code: string }>` to accept both old effects table data and new resource-based effects (or just resource-based if migrating fully).
2. **Register** effects from resources into the `DynamicEffectRegistry` via `registerAsync()`.
3. **Update** `VideoEditorProvider.tsx` to pass resource-based effects instead of (or alongside) effects table data.

## Phase 2: LLM Edge Function

### Step 4: Create effect prompt templates (`supabase/functions/ai-generate-effect/templates.ts`)
**Scope:** Medium
1. **Create** system prompt that specifies the Remotion effect component contract:
   - Props interface (`EffectComponentProps`)
   - Available globals (React, useCurrentFrame, useVideoConfig, interpolate, spring, AbsoluteFill)
   - Output format (`exports.default = ComponentName`)
   - No import/export statements, no JSX (use `React.createElement`)
   - Category-specific guidance (entrance effects should animate in during `effectFrames`, exit effects animate out, continuous effects loop)
2. **Support** edit mode: include existing code in the prompt with user's change description.
3. **Add** code extraction logic (strip markdown fences, validate structure).

### Step 5: Create the `ai-generate-effect` edge function (`supabase/functions/ai-generate-effect/index.ts`)
**Scope:** Medium
1. **Bootstrap** with `bootstrapEdgeHandler` following the `ai-prompt` pattern.
2. **Accept** JSON body: `{ prompt: string, category: 'entrance' | 'exit' | 'continuous', existingCode?: string }`.
3. **Auth** required (JWT user auth).
4. **Rate limit** per user (reuse existing rate limit infrastructure).
5. **Call** Groq with the effect generation prompt, using `groqWithFallback` pattern.
6. **Extract** code from LLM response (strip markdown fences).
7. **Return** `{ code: string, model: string }`.
8. **Deploy** via `npx supabase functions deploy ai-generate-effect --project-ref wczysqzxlwdndgxitrvc`.

## Phase 3: Effect Creator/Editor UI

### Step 6: Build the LLM-powered effect editor panel (`src/tools/video-editor/components/EffectCreatorPanel.tsx`)
**Scope:** Large
1. **Replace** the current `CustomEffectEditor` with a new `EffectCreatorPanel` that supports:
   - Category selector (entrance/exit/continuous) — required before prompting.
   - Natural language prompt textarea.
   - "Generate" button that calls the edge function.
   - Loading state during generation.
   - Code display (read-only Monaco or syntax-highlighted textarea) showing generated code.
   - Error display if compilation fails.
   - "Edit" textarea for describing changes to existing code (re-prompts the LLM with existing code + change description).
   - "Preview" button that compiles via `compileEffectAsync()` and applies to a sample clip in the Remotion player.
   - "Save" button that creates/updates a resource entry.
   - Name and description fields (auto-populated from LLM if possible).
2. **Wire** the edge function call via `fetch` to `/functions/v1/ai-generate-effect`.
3. **Validate** generated code client-side using `compileEffectAsync()` before enabling save.
4. **Show** compilation errors inline if the LLM produces invalid code, with a "Retry" option.

### Step 7: Add inline preview for generated effects
**Scope:** Medium
1. **Create** a small preview component that renders the compiled effect wrapping a sample color block or the currently selected clip's thumbnail.
2. **Use** the existing Remotion `Player` component (or a lightweight version) to show a ~3-second loop.
3. **Wire** into `EffectCreatorPanel` — preview updates whenever code changes and compiles successfully.

### Step 8: Integrate the effect creator into ClipPanel (`src/tools/video-editor/components/PropertiesPanel/ClipPanel.tsx`)
**Scope:** Medium
1. **Replace** the "Custom effects" section (`ClipPanel.tsx:162-187`) with a launcher for the new `EffectCreatorPanel`.
2. **Add** a "Create Effect" button that opens the panel (could be inline expandable or a sheet/dialog).
3. **When** an existing custom effect is selected in a dropdown, show an "Edit" button that opens the panel pre-populated with that effect's code and metadata.

## Overview

The video editor has a working custom effects system: users manually write Remotion JSX code, compile it via Sucrase, and save to an `effects` DB table. The goal is to upgrade this into an LLM-powered workflow where users describe effects in natural language, get generated code back, validate/preview it, and save as a `resources` table entry (type: `'effect'`). Effects become shareable (public/private) and appear in the standard effect dropdowns alongside built-ins.

**Current state:**
- **Effects table** (`effects`): stores `slug`, `name`, `code`, `category`, `description`, `user_id`, `is_public`. Unique constraint is `(user_id, slug)`. Queried via `useEffects` hook (`src/tools/video-editor/hooks/useEffects.ts`).
- **Resources table** (`resources`): generic store with `type`, `metadata` (JSON), `user_id`, `is_public`. Types: `lora`, `phase-config`, `style-reference`, `structure-video`. Hooks in `src/features/resources/hooks/useResources.ts`.
- **Compile pipeline**: `compileEffect.tsx` uses Sucrase to transform JSX/TS → JS, wraps in Function constructor with injected Remotion globals. **Currently swallows all errors** — returns a fallback error component instead of surfacing failures programmatically.
- **DynamicEffectRegistry** (`DynamicEffectRegistry.ts`): merges built-in + dynamic effects, keyed by normalized name (strips `custom:` prefix). Used by `wrapWithClipEffects()` in `index.tsx`.
- **CustomEffectEditor** (`CustomEffectEditor.tsx`): manual code editor with name/slug/description/code fields. No LLM integration — just shows the prompt template as reference text.
- **Effect dropdowns** (`ClipPanel.tsx:119-161`): show only built-in effect types. Custom effects require the separate editor panel.
- **Clip references**: clips store effect type as `custom:{slug}` (`ClipPanel.tsx:174-183`), registry strips the prefix and looks up by bare slug.
- **LLM edge function pattern**: `ai-prompt` uses Groq SDK with fallback model support (`supabase/functions/ai-prompt/index.ts`).

**Key constraints:**
- Must use the Sucrase compile pipeline (already proven).
- Resources table is the target storage (not effects table).
- Edge function for LLM calls (not client-side).
- Effects need category metadata (entrance/exit/continuous) for correct dropdown placement.

**Identity scheme change:** Clips currently reference custom effects as `custom:{slug}`, but slugs are only unique per-user (`unique (user_id, slug)` in the effects table). Once public effects from multiple users are merged, slug collisions are inevitable. This plan switches to `custom:{resourceId}` as the clip reference and registry key. Resource IDs (UUIDs) are globally unique. Display names in dropdowns use the human-readable name from metadata.

## Phase 1: Foundation — Compile Pipeline Fix & Types

### Step 1: Add result-typed compilation function (`src/tools/video-editor/effects/compileEffect.tsx`)
**Scope:** Small

**Why first:** The LLM validation UI (Step 7) and save-gating logic both depend on programmatically detecting compilation failures. The current `compileWithTransform()` catches all errors and returns a fallback component — there is no way to distinguish success from failure.

1. **Add** a new exported function `tryCompileEffectAsync()` that returns a discriminated union:
   ```typescript
   type CompileResult =
     | { ok: true; component: FC<EffectComponentProps> }
     | { ok: false; error: string };
   ```
2. **Implement** by extracting the try/catch from `compileWithTransform()` (`compileEffect.tsx:41-77`) into a new `tryCompileWithTransform()` that returns `CompileResult` instead of always returning a component.
