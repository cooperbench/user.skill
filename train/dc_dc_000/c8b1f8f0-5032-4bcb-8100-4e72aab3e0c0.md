# Implementation Plan: Message Queue for Timeline Agent Chat

## Overview
Currently `AgentChat.tsx:675` disables the input while `isProcessing` or `sendMessage.isPending`. Goal: keep the input enabled, let the user submit additional messages, stack them above the input with delete + up/down reorder controls, and auto-send the head of the queue when the current turn completes. Attachments are snapshotted at queue time so the user can change selection between submissions. Local client-side state only; no server or hook-signature changes.

Key anchors:
- `handleSend` at `AgentChat.tsx:387`; attachments build at `AgentChat.tsx:391-404`.
- `sendingRef` at `AgentChat.tsx:386`.
- Optimistic clear effect at `AgentChat.tsx:375-384` (matches on `role==='user' && content===optimisticMessage.text` — text-only; unsafe for repeated prompts like "ok").
- `useSendMessage` (`hooks/useAgentSession.ts:348-354`): on error, only `localError` is set — the caller's `finally` is reached, but `optimisticMessage` is never cleared by today's effect on a failed send.
- Input/send `disabled` at `AgentChat.tsx:675` and `AgentChat.tsx:715`.
- Cancel button at `AgentChat.tsx:522`; `handleNewSession` at `AgentChat.tsx:419-426`.

Two robustness concerns surfaced by critique drive the revisions below:
- **FLAG-001:** a failed queued send must not vanish from the queue, and a stuck `optimisticMessage` must not block further draining.
- **FLAG-002:** text-only matching for clearing `optimisticMessage` is unreliable when queued messages share content; we need an identity-based match.

## Main Phase

### Step 1: Audit current send path (`AgentChat.tsx`, `hooks/useAgentSession.ts`)
**Scope:** Small
1. **Confirm** gating to change: input `disabled` (`AgentChat.tsx:675`), send button `disabled` (`AgentChat.tsx:715`).
2. **Confirm** completion signal: `sendMessage.mutateAsync` resolves AND `isProcessing` flips false (`AgentChat.tsx:184`) AND optimistic state clears. The optimistic-clear effect (`AgentChat.tsx:375-384`) is the piece we must harden.
3. **Confirm** error path: `useAgentSession.ts:348-354` only sets `localError`; our own `finally` must both release `sendingRef` and clear optimistic state on error so the drain effect can proceed.

### Step 2: Add queue state, types, and hardened optimistic identity (`AgentChat.tsx`)
**Scope:** Medium
1. **Add** type `QueuedMessage = { id: string; text: string; attachments: AgentChatAttachmentPreviewItem[] }` near `RenderedTurn`.
2. **Add** `const [queue, setQueue] = useState<QueuedMessage[]>([]);` next to `draft` / `optimisticMessage` (`AgentChat.tsx:139-141`).
3. **Harden `optimisticMessage`** to avoid FLAG-002. Change its shape to:
   ```ts
   type OptimisticMessage = {
     id: string;                    // same id as the queued item, or a fresh uuid for direct sends
     text: string;
     attachments: AgentChatAttachmentPreviewItem[];
     sentAtMs: number;              // Date.now() at send-time
     priorTurnCount: number;        // activeSession.data?.turns.length ?? 0 at send-time
   };
   ```
   This gives us three independent signals (count grew, new `timestamp` present, content matches) so duplicate-text sends can no longer prematurely satisfy the clear condition.
4. **Rewrite** the optimistic-clear effect (currently `AgentChat.tsx:375-384`): clear when `activeSession.data.turns.length > optimistic.priorTurnCount` AND there is a `user` turn at index `>= priorTurnCount` whose `content === optimistic.text` AND whose `timestamp` (ms) is `>= optimistic.sentAtMs - 1000` (small skew tolerance). This matches the *new* user turn produced by this specific send, not an older one with the same text.
5. **Id helper:** prefer `crypto.randomUUID()`; fall back to `${Date.now()}-${Math.random()}` only if unavailable.

### Step 3: Refactor `handleSend` and add `sendNow` (`AgentChat.tsx:387-417`)
**Scope:** Medium
1. **Extract** `sendNow(item: QueuedMessage)` as a `useCallback` with deps `[sendMessage, clearGallerySelection, activeSessionId, timelineId]`. Body:
   ```ts
   if (!activeSessionId || !timelineId) return;
   sendingRef.current = true;
   setOptimisticMessage({
     id: item.id,
     text: item.text,
     attachments: item.attachments,
     sentAtMs: Date.now(),
     priorTurnCount: activeSession.data?.turns.length ?? 0,
   });
   try {
     await sendMessage.mutateAsync({ message: item.text, attachments: item.attachments });
     clearGallerySelection();
   } catch {
     // FLAG-001: clear optimistic on error so the drain effect can proceed;
     // existing error banner (AgentChat.tsx:661-665) surfaces the failure.
     setOptimisticMessage((prev) => (prev && prev.id === item.id ? null : prev));
   } finally {
     sendingRef.current = false;
   }
   ```
   *Note:* the success path still relies on the hardened effect in Step 2 to clear optimistic on real-turn arrival, preserving the no-flash behavior.
2. **Rewrite** `handleSend(rawText?: string)`:
   - Compute `text = (rawText ?? draft).trim()`; early-return if empty or no session/timeline.
   - Build `attachments` snapshot from current `clips` exactly as today.
   - If `rawText === undefined`, clear `draft`.
   - If `sendingRef.current || isProcessing || sendMessage.isPending || optimisticMessage || queue.length > 0`: append `{ id, text, attachments }` to `queue` and return.
   - Else call `sendNow({ id, text, attachments })`.
3. **Voice path** at `AgentChat.tsx:174` still calls `handleSend(text)` — transcribed messages queue naturally when busy.

### Step 4: Auto-drain queue when idle — error-safe (`AgentChat.tsx`)
**Scope:** Small
1. **Add** effect:
   ```ts
   useEffect(() => {
     if (sendingRef.current) return;
     if (isProcessing || sendMessage.isPending || optimisticMessage) return;
     if (queue.length === 0) return;
     if (!activeSessionId || !timelineId) return;

     const next = queue[0];
     // FLAG-001: do NOT dequeue before sending. Dequeue only on resolve.
     void (async () => {
       try {
         await sendNow(next);
         setQueue((prev) => (prev[0]?.id === next.id ? prev.slice(1) : prev));
       } catch {
         // sendNow already swallows errors internally; this catch is defensive.
         // Keep the item at the head so the user can delete/reorder/retry.
         // Pause further draining until the user removes the failed item.
       }
     })();
   }, [queue, isProcessing, sendMessage.isPending, optimisticMessage, activeSessionId, timelineId, sendNow]);
   ```
2. **Semantics on error (FLAG-001):** the failed item stays at the head; the user can delete it (then drain resumes) or reorder. The `localError` banner from `useAgentSession.ts:350` auto-clears in 5s, but the queue does *not* auto-retry. This is the safer default — silent retry loops are worse than pausing.
3. **Success path:** `sendNow` resolves → optimistic clears via hardened effect in Step 2 → drain effect re-fires and pops the next head.

### Step 5: Render the queued-messages stack (`AgentChat.tsx`, above input bar)
**Scope:** Medium
1. **Insert** a new block immediately above the existing `clips.length > 0` attachment strip (`AgentChat.tsx:615-628`). Visual top-to-bottom order: queued cards → current selection strip → voice/error banners → input row.
2. **Render** `queue.map((item, index) => …)` as a vertical stack of compact rows:
   - Text with `line-clamp-2`.
   - Attachment count badge if `item.attachments.length > 0` (e.g. `📎 3`).
   - `ChevronUp` button, disabled when `index === 0`.
   - `ChevronDown` button, disabled when `index === queue.length - 1`.
   - `X` delete button.
3. **Handlers:**
   - `moveUp(index)` / `moveDown(index)`: swap adjacent items in a new array. Guard: never swap index 0 with index -1 (no-op at top); the drain effect only reads `queue[0]` at fire time, so reordering lower items is race-free.
   - `remove(id)`: `setQueue(prev => prev.filter(q => q.id !== id))`.
4. **Styling:** `bg-muted/50 rounded-lg px-3 py-2 text-xs`, `flex items-center gap-2`; no hardcoded colors (CLAUDE.md rule).
