    64→def detect_test_coverage(
    65→    graph: dict,
    66→    zone_map: FileZoneMap,
    67→    lang_name: str,

    72→
    73→    Args:

    75→        zone_map: FileZoneMap from lang._zone_map

    77→        extra_test_files: test files outside the scanned path (e.g. PROJECT_ROOT/tests/)
    78→
    79→    Returns:
    80→        (entries, potential) where entries are finding-like dicts and potential
    81→        is the count of production files (for scoring denominator).
    82→    """

    84→    root_prefix = str(PROJECT_ROOT) + os.sep
    85→    def _to_rel(p: str) -> str:
    86→        return p[len(root_prefix):] if p.startswith(root_prefix) else p
    87→
    88→    needs_norm = any(k.startswith(root_prefix) for k in list(graph)[:3])
    89→    if needs_norm:
    90→        norm_graph: dict = {}
    91→        for k, v in graph.items():
    92→            rk = _to_rel(k)
    93→            norm_graph[rk] = {
    94→                **v,
    95→                "imports": {_to_rel(imp) for imp in v.get("imports", set())},
    96→            }
    97→        graph = norm_graph
    98→
    99→    all_files = zone_map.all_files()
   100→    production_files = set(zone_map.include_only(all_files, Zone.PRODUCTION, Zone.SCRIPT))
   101→    test_files = set(zone_map.include_only(all_files, Zone.TEST))
   102→
   103→    # Include test files from outside the scanned path (normalize to relative)
   104→    if extra_test_files:
   105→        test_files |= {_to_rel(f) for f in extra_test_files}
   106→
   107→    # Only score production files that are substantial enough to warrant tests
   108→    scorable = {f for f in production_files if _file_loc(f) >= _MIN_LOC}
   109→
   110→    if not scorable:
   111→        return [], 0
   112→
   113→    # LOC-weighted potential: sqrt(loc) capped at 50 per file.
   114→    # This weights large untested files more heavily — a 500-LOC untested file
   115→    # contributes ~22x more to score impact than a 15-LOC file.
   116→    potential = round(sum(min(math.sqrt(_file_loc(f)), 50) for f in scorable))
   117→
   118→    # If zero test files, emit findings for top modules by LOC
   119→    if not test_files:

   127→    name_tested = _naming_based_mapping(test_files, production_files, lang_name)

   130→    # Step 3: Transitive coverage via BFS

   133→    # Step 4: Test quality analysis

   139→        test_quality, graph, lang_name,
   140→        complexity_map=complexity_map,
   141→    )
   142→
   143→    return entries, potential

   446→def _transitive_coverage(
   447→    directly_tested: set[str],
   448→    graph: dict,
   449→    production_files: set[str],

   451→    """BFS from directly-tested files through dep graph imports.
   452→
   453→    Returns production files reachable from tested files (transitively covered).

   455→    visited = set(directly_tested)

   462→            continue

   464→            if imp in production_files and imp not in visited:
   465→                visited.add(imp)
   466→                queue.append(imp)

   472→def _strip_py_comment(line: str) -> str:
   473→    """Strip Python # comments while respecting string literals."""
   474→    in_str = None

   488→def _analyze_test_quality(
   489→    test_files: set[str], lang_name: str,
   490→) -> dict[str, dict]:
   491→    """Analyze quality of each test file.
   492→
   493→    Returns {test_path: {"assertions": int, "mocks": int, "test_functions": int,
   494→                          "snapshots": int, "quality": str}}

   496→    assert_pats = PY_ASSERT_PATTERNS if lang_name == "python" else TS_ASSERT_PATTERNS

   504→            content = Path(tf).read_text()

   506→            continue

   508→        # Strip comments before pattern matching

   511→            stripped = _strip_ts_comments(content)
   512→        else:
   513→            stripped = "\n".join(_strip_py_comment(line) for line in content.splitlines())

   515→        lines = stripped.splitlines()

   518→        # match the same line (e.g. expect(el).toBeVisible() matching both)
   519→        assertions = sum(
   520→            1 for line in lines
   521→            if any(pat.search(line) for pat in assert_pats)

   524→            1 for line in lines

   532→        test_functions = len(test_func_re.findall(stripped))

   537→        elif assertions == 0:

   540→            quality = "over_mocked"

   543→        elif test_functions > 0 and assertions / test_functions < 1:
   544→            quality = "smoke"
   545→        elif assertions / test_functions >= 3:
   546→            quality = "thorough"
   547→        else:

   550→        quality_map[tf] = {
   551→            "assertions": assertions,
   552→            "mocks": mocks,
   553→            "test_functions": test_functions,

## Mathematical Consistency Analysis

I've found **ONE CRITICAL MATHEMATICAL INCONSISTENCY** in the LOC-weighted test coverage scoring:

### Issue: Unbounded Weighted Failures Due to Missing Per-File Cap

**Problem**: The test coverage detector uses `round()` on the potential (line 116 in `test_coverage.py`):
```python
potential = round(sum(min(math.sqrt(_file_loc(f)), 50) for f in scorable))
```

But the `scoring.py` pass_rate calculation accumulates `loc_weight` values **without any per-file cap** (line 115):
```python
if use_loc_weight:
    weighted_failures = sum(by_file.values())  # NO CAP
```

**The Root Cause**: 
A single production file can have multiple test coverage findings (e.g., "untested_critical" + "shallow_tests" + "over_mocked" if it's tested but with quality issues). When this happens, `by_file[file_key]` accumulates:

```python
by_file[file_key] = by_file.get(file_key, 0) + weight  # Line 110
```

If a file has N quality findings, each with `loc_weight = min(sqrt(loc), 50)`, the file's accumulated weight becomes:
```
by_file[file_key] = N * loc_weight
```

This **can exceed** the file's contribution to potential. For example:
- A file with 400 LOC contributes `sqrt(400) = 20` to potential
- But if that file has 2 quality findings (e.g., "assertion_free" + "shallow"), it contributes `20 + 20 = 40` to weighted_failures
- Result: `weighted_failures > potential` for that file

**Examples of Multiple Findings per File** (from `test_coverage.py` lines 607-712):
- A directly tested file can emit findings for each related test that has quality issues:
  - "assertion_free_test" (line 616)
  - "shallow_tests" (line 628)
  - "over_mocked" (line 642)
  - "snapshot_heavy" (line 654)
  - All for the **same production file**

### The Math Failure

Pass rate formula (line 130 in `scoring.py`):
```python
pass_rate = max(0.0, (potential - weighted_failures) / potential)
```

If `weighted_failures > potential`:
- Without `max()` guard: `pass_rate` would be **negative**
- With `max()`: `pass_rate` clamps to `0.0` (which is mathematically correct but masks the underlying inconsistency)

The `max()` **hides** the problem but doesn't solve it.

### Round-Trip Consistency Issue

**Minor Issue**: The potential is `round()`ed before it's ever used, but the accumulation of loc_weights is not. This means:
- Potential: `round(sum(min(sqrt(loc), 50) ...))` — one rounding operation on the entire sum
- Weighted failures: sum of individual `loc_weight` values (no rounding)

In practice this is less critical than Issue #2 because typically `weighted_failures ≤ potential`, but it creates a subtle asymmetry:
- If `potential = 100.5 → rounds to 101`
- If `weighted_failures = 100.4` (from accumulation of floats)
- Pass rate = `(101 - 100.4) / 101 = 0.6%` — passes barely

Versus if rounding were symmetric:
- `weighted_failures = 100.4 → round to 100`
- Pass rate = `(101 - 100) / 101 = 1%`

### Recommended Fix

Add a per-file cap for test_coverage in line 115 of `scoring.py`:
```python
if use_loc_weight:
    # Cap per-file at its potential contribution
    file_potentials = {f: min(math.sqrt(_file_loc(f)), 50) 
                       for f in by_file.keys()}
    weighted_failures = sum(
        min(by_file[f], file_potentials[f]) for f in by_file
    )
```

Or more pragmatically, cap when accumulating (in `test_coverage.py` line 110):
```python
lw = min(_loc_weight(loc), 1.0)  # Cap individual findings like other detectors
by_file[file_key] = by_file.get(file_key, 0) + lw
```

This would restore the mathematical property that each file's weighted failures ≤ its potential contribution.
