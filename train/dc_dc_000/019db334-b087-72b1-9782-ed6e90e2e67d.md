        # Implementation Plan: Wan2GP Fork Migration — Sprint 4 (Patch Consolidation, Upstream PRs, Sustainability)

## Overview
Sprint 4 closes the migration by (a) consolidating runtime fork behavior into a single `wgp_patches.py` registry AND wiring a concrete runtime-model-definition patch into the bootstrap so `get_wgp_patch_state()` after `apply_all_wgp_patches()` proves the single-registry invariant through the real production path, (b) drafting upstream PR bodies for the 118 bucket-(b) rows grouped into the 14 literal hunk themes already present in `docs/wan2gp-triage.csv`, (c) landing a weekly drift-detection workflow per SD-008, and (d) publishing the rebase runbook per SD-007.

**Explicit scope decision (resolves iter-3 architectural tension):** Sprint 4 uses a single default `context_id` for the production `apply_all_wgp_patches` call. Multi-context concurrent runtime-patch isolation (where the same model is patched under two different context_ids against a shared WGP runtime) is **out of scope** and deferred to a follow-up sprint. The rationale: `context_id` scopes only the registry bookkeeping; the underlying `runtime.models_def` / `runtime.wan_model.model_def` live targets are globally shared. Fixing that is a semantic redesign (runtime isolation or copy-on-write per context) that is not a Sprint 4 deliverable per `docs/WAN2GP_FORK_MIGRATION_PLAN.md:163-187`. The plan therefore (i) does not ship a test that exercises same-model multi-context apply, (ii) the bootstrap-records test exercises the non-default context_id registry path without triggering the shared-runtime pitfall, and (iii) the runbook flags the deferred work for follow-up.

- `source/models/wgp/wgp_patches.py` has `_register_patch_application`, `get_wgp_patch_state`, `rollback_wgp_patches`, `clear_wgp_patch_context`, and the context-scoped registry. `apply_all_wgp_patches` (`wgp_patches.py:536-580`) records seven module-level patches today.

   - `target_key = f"model_def:{model_name}"`.
   - Resolve the live runtime via the bridge. Snapshot BOTH targets the transaction would touch:
     - `live_models_def = runtime.models_def.get(model_name, {})`.
     - `is_active = getattr(runtime, "transformer_type", None) == model_name and getattr(runtime, "wan_model", None) is not None`.

This addresses FLAG-006 / correctness-v3 / callers-1-v3 / all_locations-v3.
   - **Guard B — registry says applied but any live target drifted:** call `rollback_wgp_patches(patch_name=patch_name, target_key=target_key, context_id=context_id)` to discard the stale closure AND restore the original pre-patch state the existing transaction captured, then fall through to fresh apply.
