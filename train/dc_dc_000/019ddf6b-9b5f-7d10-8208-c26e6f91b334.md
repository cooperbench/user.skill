        # Implementation Plan: Code-First Folder Nodes

## Overview
ArtAgents already has a small node MVP under `artagents/nodes/`: dataclass-backed schema validation in `schema.py`, built-in legacy step wrappers in `builtin.py`, curated JSON discovery in `registry.py`, command expansion/execution in `runner.py`, and `pipeline.py nodes ...` dispatch in `artagents/pipeline.py:1061`. The smallest practical evolution is to keep these contracts, add a folder-node discovery path, add a tiny code authoring API that can be executed in a separate Python process for metadata extraction, add explicit `nodes install <node_id>` dependency handling, and make external node runs resolve `{python_exec}` to the installed per-node environment when available.

The critique does not indicate the plan targets the wrong code or root cause. It identifies a missing integration point: installation and runtime command expansion must agree on where the external node environment lives. The revised plan therefore keeps the same node subsystem focus, but adds a narrow runner-side environment resolution step so `nodes install external.moirae` produces an environment that `nodes run external.moirae` can actually use.

The current worktree already has unrelated dirty and untracked files, including `artagents/nodes/` and node tests. Implementation must inspect before editing, patch only the node-related files needed for this feature, and avoid reverting unrelated changes.

## Main Phase

### Step 1: Preserve Current Behavior And Locate Exact Contracts (`artagents/nodes/*.py`, `tests/test_nodes_*.py`)
**Scope:** Small
1. **Inspect** `git status --short` and current node files before edits so existing dirty work is not overwritten.
2. **Confirm** the existing baseline tests for the node MVP still describe the intended legacy behavior: JSON manifests, built-ins using host Python, dry-run command expansion, and `pipeline.py nodes` CLI dispatch.
3. **Keep** the public `NodeDefinition.to_dict()` and existing JSON manifest loading behavior compatible so old curated JSON nodes still work during the transition.

### Step 2: Add A Minimal Code-First Authoring API (`artagents/nodes/api.py`, `artagents/nodes/__init__.py`)
**Scope:** Medium
1. **Create** a tiny public API around the existing schema dataclasses, likely exporting `NodeSpec` as a convenience builder or alias-compatible wrapper over `NodeDefinition`.
2. **Support** a minimal authoring pattern in `node.py`, for example:
   ```python
   from artagents.nodes import NodeSpec

   node = NodeSpec(
       id="external.moirae",
       name="Moirae",
       version="0.1.0",
       inputs=[...],
       outputs=[...],
       command=["{python_exec}", "-m", "moirae", "{screenplay}", "-o", "{output}"],
   )
   ```
3. **Normalize** the authoring API back into `NodeDefinition` through existing validation instead of creating a parallel schema.
4. **Export** only the small API surface needed for `node.py` authoring: `NodeSpec`, `NodePort`, `NodeOutput`, and existing validation errors.

### Step 3: Extract Folder Node Metadata Out Of Process (`artagents/nodes/folder.py` or `registry.py`)
**Scope:** Medium
1. **Discover** folders containing `node.py` under a curated folder-node root, preferably `artagents/nodes/curated/*/node.py` for package-local examples.
2. **Avoid importing node code in the main process** by adding a helper that runs a separate Python process to execute/extract metadata from `node.py` and prints validated JSON.
3. **Keep extraction simple:** the subprocess can use `runpy.run_path()` and require a top-level `node` or `NODE` variable that resolves to `NodeSpec`, `NodeDefinition`, or a plain dict.
4. **Validate** extracted metadata with `validate_node_definition()` in the subprocess and again in the parent before registration.
5. **Add clear errors** for missing `node` variable, invalid metadata, subprocess failure, and duplicate IDs.

### Step 4: Convert Moirae To A Real Folder Node (`artagents/nodes/curated/moirae/`)
**Scope:** Small
1. **Move or supplement** `artagents/nodes/curated/moirae.json` with `artagents/nodes/curated/moirae/node.py` as the source of truth.
2. **Add optional docs/dependency files** in the folder as needed: `SKILL.md` for human guidance and either `requirements.txt` or `pyproject.toml` for install metadata.
3. **Preserve metadata** from the current manifest: `external.moirae`, screenplay input, video output placeholder `output`, command shape, binary declarations, homepage, and non-network default.
4. **Decide** whether to leave `moirae.json` as a compatibility fixture or remove it after registry discovery supports folders; avoid registering both if they share the same ID.

### Step 5: Add Explicit Node Install Handling (`artagents/nodes/installer.py`, `artagents/nodes/cli.py`)
**Scope:** Medium
1. **Add** `pipeline.py nodes install <node_id>` to the node CLI.
2. **Use host env for built-ins:** built-in nodes should report no install action or a clear no-op because they run in the ArtAgents host environment.
3. **Use isolated per-node envs for external nodes by default:** derive a deterministic env path such as `.artagents/nodes/<node_id>/venv`, and make sure that path is ignored by git if it lives in the repo.
4. **Centralize env path calculation** in one helper used by both installer and runner, for example `node_environment_path(node)` and `node_python_path(node)`.
5. **Build uv commands explicitly** without running them in tests by default, for example `uv venv <env>` followed by `uv pip install --python <env>/bin/python -r requirements.txt`, or `uv pip install --python <env>/bin/python <requirement>` when only schema `isolation.requirements` exist.
6. **Prefer folder dependency files** over inline schema requirements when present: `pyproject.toml` or `requirements.txt` in the node folder should drive install commands.
7. **Add** `--dry-run` to print planned uv commands, env path, and resolved node Python path without creating an environment.
8. **Do not automatically install on `nodes run`** in this MVP; dependency installation remains explicit at `nodes install <node_id>` time.

### Step 6: Make External Runs Use Installed Node Environments (`artagents/nodes/runner.py`, `artagents/nodes/installer.py`)
**Scope:** Medium
1. **Update** `_placeholder_values()` or a narrow helper before command expansion so external nodes resolve `{python_exec}` to the per-node env Python when that env exists or when the node has folder/requirements metadata indicating an isolated env.
2. **Preserve override behavior:** if `NodeRunRequest.python_exec` or an explicit `python_exec` input is provided, that explicit value should win for tests and advanced/manual usage.
3. **Keep built-ins unchanged:** built-in legacy nodes should continue using the request or host interpreter because they rely on the ArtAgents host environment.
4. **Fail clearly when an external isolated node is run without an installed env** if its command depends on `{python_exec}` and no override is provided. The error should tell the user to run `pipeline.py nodes install <node_id>` or pass an explicit `python_exec`.
5. **Return dry-run evidence** showing the resolved interpreter path so tests can prove `external.moirae` would run with the isolated environment after install.

### Step 7: Wire Discovery Into Default Registry (`artagents/nodes/registry.py`)
**Scope:** Medium
1. **Extend** `load_curated_nodes()` so it loads legacy `*.json` manifests and folder nodes, with deterministic ordering.
2. **Attach folder metadata** to nodes, such as `metadata.node_root`, `metadata.source = "folder"`, and dependency file paths if useful for install and runtime env handling.
3. **Prevent duplicate registration** when both `moirae.json` and `moirae/node.py` exist; the simplest policy should be explicit and tested, likely folder node wins only if JSON is removed or skipped by filename.
4. **Keep** `load_default_registry()` behavior stable for built-ins and legacy JSON manifests.

### Step 8: Add Focused Tests (`tests/test_nodes_schema.py`, `tests/test_nodes_registry.py`, `tests/test_nodes_cli.py`, `tests/test_nodes_runner.py` or new `tests/test_nodes_folder.py`)
**Scope:** Medium
1. **Test folder discovery** with a temporary directory or curated Moirae folder fixture.
2. **Test code-first extraction** from `node.py` without importing untrusted node code into the main test process; use a sentinel side effect if practical to prove subprocess isolation.
3. **Test Moirae folder metadata** matches the old manifest contract: ID, inputs, output placeholder, command, requirements, binaries, and homepage metadata.
4. **Test install dry-run command construction** for external nodes and no-op behavior for built-ins.
5. **Test runtime env resolution:** after simulating an installed per-node env, dry-running `external.moirae` should expand `{python_exec}` to that env's Python rather than `sys.executable`.
6. **Test missing-env behavior:** running an isolated external node that needs `{python_exec}` without an installed env or explicit override should fail with an actionable install message.
7. **Retain existing tests** for JSON manifest validation, built-in registry metadata, dry-run command expansion, and CLI list/inspect/validate behavior.
