        # Implementation Plan: Shots Browser Panel in Video Editor Top Pane

## Overview

Replace the Remotion preview panel in the video editor's top pane with a compact shots browser panel when on pages other than the standalone video editor page (`/tools/video-editor`). The shots panel will show a horizontally-scrolling grid of project shots, support drag-to-timeline, and highlight shots related to the currently selected timeline clips.

**Current state:** `VideoEditorShell.tsx` renders `PreviewPanel` (Remotion preview + OverlayEditor) in the top-left cell of the standard layout grid (line 501-504) and in the condensed right panel (line 461-478). The `isOnEditorPage` flag (line 69) already distinguishes `/tools/video-editor` from other pages.

**Key constraint:** The Remotion preview portal must still exist (it drives playback/time sync), but can be hidden when the shots panel is shown. The preview portal is rendered at line 393-406 and mounted into whichever slot ref is active.

## Phase 1: Core Shots Panel Component

### Step 1: Create ShotsPanel component (`src/tools/video-editor/components/ShotsPanel.tsx`)
**Scope:** Medium

1. **Create** a new `ShotsPanel` component that:
   - Consumes `useShots()` for shot data and `useShotFinalVideos(projectId)` for thumbnails
   - Renders a horizontally-scrolling container with a compact grid (4-5 items per visible row using CSS grid with `grid-auto-flow: column` and fixed row count)
   - Each shot card shows: thumbnail (final video thumbnail if available via `finalVideoMap`, else first image from `shot.images`), shot name truncated
   - Uses native HTML5 drag (same pattern as `SortableShotItem.tsx:112-131`) calling `setShotDragData()` from `shared/lib/dnd/dragDrop.ts`
   - No dnd-kit needed — we only need drag-out (no reordering within this panel)

2. **Add search/filter input** at the top:
   - Text input that filters shots by name (case-insensitive substring match)
   - "Related only" toggle button that filters to shots matching the current timeline selection

3. **Props interface:**
   ```typescript
   interface ShotsPanelProps {
     projectId: string;
     highlightedShotIds?: ReadonlySet<string>;
     filterToShotIds?: ReadonlySet<string> | null;
     onFilterToggle?: (enabled: boolean) => void;
     filterEnabled?: boolean;
   }
   ```

4. **Shot card rendering** — build a minimal inline card (not reusing `SortableShotItem` which has too much drop/reorder machinery). Reuse `VideoShotDisplayParts` if it provides useful thumbnail rendering, otherwise a simple img tag with the shot's first image URL.

5. **Highlight treatment:** When `highlightedShotIds` contains the shot's ID, apply `ring-2 ring-primary` border.

### Step 2: Build `useSelectedShotIds` hook (`src/tools/video-editor/hooks/useSelectedShotIds.ts`)
**Scope:** Small

1. **Create** a hook that derives which shots correspond to the currently selected clips:
   - Input: `selectedClipIds` (from `useTimelineEditorData()`), `data` (TimelineData), `shots` (from `useShots()`)
   - Logic: For each selected clip → `data.meta[clipId].asset` → `data.registry.assets[assetKey].generationId` → find shot whose `images` array contains that `generation_id` (reuse `getClipGenerationId` pattern from `usePinnedShotGroups.ts:56-60`)
   - Also check `pinnedShotGroups` for a more direct clip→shot mapping (each `PinnedShotGroup` has `shotId` + `clipIds`)
   - Return: `{ highlightedShotIds: Set<string>, relatedShotIds: Set<string> }` — memoized

2. **Prefer pinnedShotGroups path** (faster, O(1) lookup): Build a `Map<clipId, shotId>` from `data.config.pinnedShotGroups` first, fall back to generation ID matching for clips not in any group.

## Phase 2: Integration into VideoEditorShell

### Step 3: Wire ShotsPanel into layout (`src/tools/video-editor/components/VideoEditorShell.tsx`)
**Scope:** Medium

1. **Standard (full) layout** — In the top-left grid cell (lines 501-504):
   - When `!isOnEditorPage`: render `ShotsPanel` instead of `PreviewPanel`
   - When `isOnEditorPage`: keep `PreviewPanel` as-is
   - The `RemotionPreview` portal still renders (line 393-406) and mounts into a hidden host div so playback continues to work. Create a hidden div ref for this case.

2. **Condensed layout** — In the right panel tabs (lines 441-485):
   - Add a third tab: "Shots" (alongside Preview and Properties)
   - When `!isOnEditorPage`, default the tab to "Shots" instead of "Preview"
   - Update `condensedRightPanel` state type: `'preview' | 'properties' | 'shots'`

3. **Preview toggle** — Add a small toggle button in the ShotsPanel header to switch to preview mode (and vice versa) so users can still access the Remotion preview when needed, even off the editor page.

4. **Hidden preview host** — When ShotsPanel is shown, the Remotion preview portal needs a mount point. Create a hidden `<div>` with `className="hidden"` and use it as the portal target when the preview panel is not visible. This keeps playback running.

### Step 4: Pass selection data through (`src/tools/video-editor/components/VideoEditorShell.tsx`)
**Scope:** Small

1. **Call `useSelectedShotIds`** in `FullEditorLayout` using `editorData.selectedClipIds`, `editorData.data`, and shots from `useShots()`
2. **Pass** `highlightedShotIds` and `relatedShotIds` to `ShotsPanel`
3. **Manage** `filterEnabled` state in `FullEditorLayout` and pass through

### Step 5: Ensure shot drops still work on timeline
**Scope:** Small (verification only)

1. **Verify** that `useExternalDrop` in `TimelineEditor` already handles shot drops — it does (lines 104-191 of `useExternalDrop.ts`). The new panel uses the same `setShotDragData()` format, so no changes needed.
2. **Test** drag from ShotsPanel → timeline drop creates clips correctly.

## Phase 3: Polish

### Step 6: Handle edge cases and polish
**Scope:** Small

1. **Empty state:** When no shots exist, show a brief message ("No shots yet") in the panel.
2. **Loading state:** Show skeleton cards while shots are loading.
3. **Responsive:** Ensure the panel works at the minimum preview height (`MIN_PREVIEW_HEIGHT = 180px` from VideoEditorShell).
4. **Keyboard:** Ensure search input doesn't capture global keyboard shortcuts (stop propagation on the input).

## Execution Order
1. Step 1 (ShotsPanel) and Step 2 (useSelectedShotIds) can be built in parallel — no dependencies.
2. Step 3 (layout wiring) depends on both Step 1 and Step 2.
3. Step 4 (selection passthrough) is small and done alongside Step 3.
4. Step 5 (verification) after Step 3.
5. Step 6 (polish) last.

## Validation Order
1. Visual check: ShotsPanel renders with correct thumbnails and horizontal scroll.
2. Drag test: Drag shot from panel → timeline creates clips (uses existing `useExternalDrop`).
3. Highlight test: Select clip on timeline → corresponding shot highlights in panel.
4. Filter test: Toggle "Related only" → only matching shots shown.
5. Page routing: On `/tools/video-editor` → PreviewPanel shown. On other pages → ShotsPanel shown.
6. Preview toggle: Can switch back to preview from shots panel.
7. Playback: Remotion preview continues to drive time sync even when hidden.
