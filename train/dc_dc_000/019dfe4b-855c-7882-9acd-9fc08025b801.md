**Recommended Schema**
Keep `bot_turns` as the turn summary. Add append-only event tables instead of overloading `tool_calls`.

```sql
CREATE TABLE IF NOT EXISTS turn_audit_events (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    turn_id uuid REFERENCES bot_turns(id) ON DELETE CASCADE,
    event_seq integer NOT NULL,
    event_type text NOT NULL,
    step text,
    severity text NOT NULL DEFAULT 'info'
        CHECK (severity IN ('debug', 'info', 'warning', 'error')),
    occurred_at timestamptz NOT NULL DEFAULT now(),
    duration_ms integer CHECK (duration_ms IS NULL OR duration_ms >= 0),
    actor text NOT NULL DEFAULT 'runner'
        CHECK (actor IN ('runner', 'llm', 'tool', 'provider', 'hook', 'scheduler')),
    message text,
    metadata jsonb NOT NULL DEFAULT '{}'::jsonb,
    sensitive_metadata_encrypted bytea,
    UNIQUE (turn_id, event_seq)
);

CREATE INDEX idx_turn_audit_events_turn_seq
    ON turn_audit_events (turn_id, event_seq);

CREATE INDEX idx_turn_audit_events_type_time
    ON turn_audit_events (event_type, occurred_at DESC);

CREATE INDEX idx_turn_audit_events_metadata_gin
    ON turn_audit_events USING gin (metadata);
```

**Event Design**
Use stable `event_type` values. Suggested core set:

- `turn.opened`: trigger ids, user id, model, prompt version, trigger kind, pacing context summary, hot-context counts, skeleton.
- `step.started`: step name, allowed tools, iteration cap, current plan checklist.
- `llm.requested`: step, model, max tokens, message count, tool count, prompt/hash metadata only.
- `llm.completed`: step, stop reason, content block types/counts, tool names requested, usage tokens, retry attempt, duration.
- `llm.failed`: exception class, retry count, failure category.
- `tool.requested`: name, tool_use_id, step, argument shape, redacted argument summary.
- `tool.completed`: name, status, result summary, created/updated entity ids, visible side effects, duration.
- `tool.rejected`: not allowed, validation error, read-before-write, self-consult, unknown tool.
- `plan.updated`: update_turn_plan changes, rendered checklist, previous/current step.
- `step.completed`: final text length/hash, tool count, plan transition.
- `outbound.oob_checked`: verdict, checker_failed, protected owner count, content hash, suggested rewrite present.
- `outbound.sent`: message id, channel/provider, part index/key, visible_to_user, content hash/length.
- `outbound.withheld`: reason, OOB verdict, interrupted/newer-inbound/spend-cap.
- `reaction.sent`: message id, emoji, provider status.
- `turn.completed`: final output id, duration, tool count, executed plan trace.
- `turn.failed`: failure reason, exception class, responded_to_user, whether retry/deferred job was created.
- `spend.recorded`: provider category, token usage, cost, cap status.

For `metadata`, keep queryable non-sensitive fields only. For anything containing raw message text, prompt text, user content, OOB content, full tool args/results, reasoning fragments, or provider response text, store either:

- a hash plus length in `metadata`, and
- ciphertext in `sensitive_metadata_encrypted`.

Example event:

```json
{
  "event_type": "tool.completed",
  "step": "record",
  "actor": "tool",
  "metadata": {
    "tool_name": "update_observation",
    "status": "success",
    "entity_type": "observation",
    "entity_ids": ["..."],
    "argument_keys": ["observation_id", "content"],
    "result_keys": ["id", "updated_at"],
    "input_text_sha256": "...",
    "output_text_sha256": "..."
  }
}
```

**What To Log At Each Runner Step**
`read`:
Log search/list/get tools, target user ids, filters, result counts, row ids surfaced, and whether any OOB/self-model/bot-actions access occurred. Do not log raw returned content in plaintext.

`consult`:
Log consult request, injected protected owner ids, whether consult tried to recurse, and result summary. Treat consult output as sensitive.

`respond`:
Log LLM final text hash/length, reaction directive extraction, incremental `send_message_part` attempts, OOB checks, final-send newer-inbound guard decisions, provider send result, and actual `messages.id` rows created.

`record`:
Log every durable mutation with before/after entity ids and semantic action: created, updated, superseded, retired. For memories, observations, OOB, distillations, bridge candidates, and feedback, encrypt full args/results.

`schedule`:
Log scheduled task/checkin decisions with job ids, recurrence summary, next fire time, cancellation/update status, and whether the schedule action came from a scheduled-task turn.

`done`:
Log executed plan trace, tool counts by step, final output ids, duration, failure status, and audit event count.

**Privacy And Encryption**
Use the existing AES-GCM helper pattern already used for prompt/reasoning encryption in [app/services/agentic.py](/Users/user_c042661f/Documents/Veas/app/services/agentic.py:378) and encrypted columns from migrations.

Principles:

- Plain JSON is for routing, indexes, counts, ids, statuses, hashes, and booleans.
- Ciphertext is for user text, prompt snapshots, model text, raw tool args/results, OOB sensitive cores, media explanations, private notes, and reasoning.
- Store deterministic hashes of sensitive text for dedupe/debugging without disclosure: `sha256(normalized_text)`, length, and maybe first-class `content_kind`, but no plaintext excerpt.
- Keep RLS and `FORCE ROW LEVEL SECURITY` consistent with `tool_calls`, `bot_turns`, and `pacing_events`.
- Admin pages should default to summaries; decrypted sensitive payloads should require an explicit detail route or query flag and remain admin-authenticated.
- Avoid logging provider request bodies verbatim. If needed for incident response, encrypt them as sensitive payloads and cap retention.
- Add retention policy: keep summary events long-term, purge encrypted raw payloads after a configured window unless tied to unresolved feedback/audit incidents.
