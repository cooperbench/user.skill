**Findings**

1. **`consult` is effectively unreachable and may run too late.**  
   [turn_plan.py](/Users/user_c042661f/Documents/Veas/app/services/turn_plan.py:85), [turn_plan.py](/Users/user_c042661f/Documents/Veas/app/services/turn_plan.py:13), [prompts.py](/Users/user_c042661f/Documents/Veas/app/services/prompts.py:276)  
   No skeleton includes `consult`, and `add_steps()` always inserts before `done`, not after the current step. If the model decides during `read` that explicit consult is needed, adding `consult` produces `read -> respond -> record -> schedule -> consult -> done`, which is too late.  
   Suggested implementation: support insertion after current step, e.g. `insert_after_current`, or make `add_steps()` insert immediately after `current_index` for non-terminal steps. Alternatively include `consult` in a skeleton only when trigger text explicitly asks for review/second opinion.

2. **Removing the current step can skip the next intended step.**  
   [turn_plan.py](/Users/user_c042661f/Documents/Veas/app/services/turn_plan.py:92), [agentic.py](/Users/user_c042661f/Documents/Veas/app/services/agentic.py:844)  
   If the model calls `update_turn_plan(remove_steps=["read"])` while in `read`, `remove_steps()` moves `current` to `respond`; then the runner calls `advance()`, marking `respond` done and jumping past it. A confused model may reasonably remove the current no-op step to “continue.”  
   Suggested implementation: reject removal of `plan.current`, or defer removals until after `advance()`. Tool wording should also say: “Do not remove the current step; return no text/no tools to complete it.”

3. **No-op steps require an extra LLM pass, but instructions say “continue immediately.”**  
   [prompts.py](/Users/user_c042661f/Documents/Veas/app/services/prompts.py:275), [mediator.py](/Users/user_c042661f/Documents/Veas/app/bots/mediator.py:72), [agentic.py](/Users/user_c042661f/Documents/Veas/app/services/agentic.py:741)  
   The runner advances only after a model call returns. “Continue immediately” is underspecified; models may emit process text or call `update_turn_plan`.  
   Suggested wording: “To complete this step when nothing is needed, return an empty assistant response and make no tool calls. The runner will advance automatically.”

4. **`silence_or_react` does unnecessary record work for acknowledgments.**  
   [turn_plan.py](/Users/user_c042661f/Documents/Veas/app/services/turn_plan.py:18), [turn_plan.py](/Users/user_c042661f/Documents/Veas/app/services/turn_plan.py:152)  
   Short acks and pacing silence/react triggers go through `respond -> record -> done`. For “thanks”, “ok”, or silence pacing, `record` is almost always an extra LLM call.  
   Suggested implementation: use `["respond", "done"]` for short acks. Only include `record` when hot-context signals or trigger classification indicate durable state, feedback, OOB, onboarding, or memory changes.

5. **OOB instructions encourage redundant `check_oob` calls.**  
   [prompts.py](/Users/user_c042661f/Documents/Veas/app/services/prompts.py:111), [agentic.py](/Users/user_c042661f/Documents/Veas/app/services/agentic.py:775), [messaging.py](/Users/user_c042661f/Documents/Veas/app/services/messaging.py:193), [registry.py](/Users/user_c042661f/Documents/Veas/app/services/tools/registry.py:223)  
   The system says every outbound must pass `check_oob`, while the runtime already checks normal final text and `send_message_part` is guarded via `send_outbound_part`. A cautious model may call `check_oob` on every routine reply.  
   Suggested wording: “The delivery path performs the final OOB check for normal replies and `send_message_part`. Call `check_oob` yourself only when drafting around sensitive cross-thread/OOB material or when you need a rewrite decision before choosing what to say.”

6. **Consult policy is contradictory between prompt and tool description.**  
   [prompts.py](/Users/user_c042661f/Documents/Veas/app/services/prompts.py:286), [mediator.py](/Users/user_c042661f/Documents/Veas/app/bots/mediator.py:90), [registry.py](/Users/user_c042661f/Documents/Veas/app/services/tools/registry.py:65)  
   Prompt/step instructions say consult only when explicitly requested; tool description says before charged, ambiguous, or one-sided responses.  
   Suggested wording for tool: “Use only in the `consult` step, and only when the user explicitly asks for a second opinion, critique, review, or another perspective.”

7. **Quick-reply skeleton can miss durable writes unless the model self-modifies the plan.**  
   [turn_plan.py](/Users/user_c042661f/Documents/Veas/app/services/turn_plan.py:14), [turn_plan.py](/Users/user_c042661f/Documents/Veas/app/services/turn_plan.py:46)  
   The regex catches some memory requests, but a factual statement like “Sarah’s dad has Parkinson’s” may route to `quick_reply`, leaving no `record` step unless the model notices and adds it.  
   Suggested implementation: add lightweight signal detection for concrete durable facts, OOB language, feedback, and sharing-default choices; route those to `standard`. Also add respond-step wording: “If this turn reveals durable state and there is no `record` step, call `update_turn_plan` to add `record` before ending the step.”

8. **Seed messages are dense and partially duplicated.**  
   [base.py](/Users/user_c042661f/Documents/Veas/app/bots/base.py:63), [mediator.py](/Users/user_c042661f/Documents/Veas/app/bots/mediator.py:39), [turn_plan.py](/Users/user_c042661f/Documents/Veas/app/services/turn_plan.py:163)  
   The seed contains `context`, separate `pacing`, and an `Orient` JSON that may repeat both. For an under-instructed model, the actionable part is buried below metadata.  
   Suggested wording/layout: put a short “Current task” first: `Current task: execute only the highlighted step. If no action is needed, return empty/no tools.` Then include compact trigger metadata after it.
