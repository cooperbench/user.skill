        # Implementation Plan: Professional AI Sequence Creator

## Overview
The video editor already has the right foundation: `TimelineClip.clipType` is an open string, `clip.params` and `clip.hold` are persisted by `src/tools/video-editor/lib/serialize.ts`, registered themed components render via `@banodoco/timeline-composition/registry.generated`, and `effect-layer` clips are already modeled as wrapper clips. The main gap is that editor row/meta conversion currently drops `params`, theme resolution is not wired into the Reigh Remotion renderer, and there is no safe prompt-to-structured-sequence flow.

The simplest implementation is to add a Sequence tool and panel that generates only trusted JSON drafts for installed registry clip types, previews those drafts by temporarily overlaying normal timeline clips, and inserts/replaces normal clips. Do not generate arbitrary React/code by default.

## Phase 1: Data Model And Render Foundation

### Step 1: Preserve sequence clip data in timeline conversion (`src/tools/video-editor/lib/timeline-data.ts`, `src/tools/video-editor/types/index.ts`)
**Scope:** Small
1. Extend `ClipMeta` and `PinnedShotImageClipSnapshot.meta` to carry schema-lift fields needed by sequences, especially `params`, plus any existing fields currently serialized but not represented in row/meta conversion.
2. Update `getDefaultClipMeta()` and `rowsToConfig()` so `clip.params` round-trips through editor edits, saves, undo/redo, and row rebuilds.
3. Add focused tests in `src/tools/video-editor/lib/serialize.test.ts` or a new `timeline-data` test proving a clip like `{ clipType: 'section-hook', hold: 3, params: { title: 'X' } }` survives build/edit/serialize.

### Step 2: Fix themed sequence render path (`src/tools/video-editor/compositions/TimelineRenderer.tsx`)
**Scope:** Medium

2. Wrap themed clip rendering in `ThemeProvider` from `@banodoco/timeline-composition/theme-api` so installed components using `useTheme()` render correctly.
3. Keep theme optional: timelines with no `theme` and no `theme_overrides` still render using default theme, and no shot-level theme becomes authoritative.
4. Add or expand `src/tools/video-editor/compositions/TimelineRenderer.test.tsx` to cover a registered sequence clip rendering without placeholder and with params passed through.

## Phase 2: Trusted Sequence Drafting

### Step 3: Add a local sequence registry facade (`src/tools/video-editor/sequences/`)
**Scope:** Medium
1. Create a small facade over `THEME_PACKAGE_REGISTRY` that exposes only sequence-capable registered clip types, initial supported ids likely `section-hook`, `art-card`, `resource-card`, and `cta-card`.

3. Add validation helpers that accept only registered `clipType` values and JSON-serializable `params`; reject unknown clip types instead of falling through to generated code.

### Step 4: Add sequence generation Edge Function (`supabase/functions/ai-generate-sequence/`)
**Scope:** Medium
1. Mirror the auth, rate-limit, error, and test style from `supabase/functions/ai-generate-effect/index.ts`, but return structured JSON only.

3. Response schema: `drafts: Array<{ clipType, params, hold, title?, assetRefs? }>`, optional `message`, `model`; no code fields.
4. Prompt the model with the sequence registry facade, timeline summary, and selected/attached asset refs. The model must choose existing registered clip types first and may only reference assets by timeline asset keys/URLs already supplied.
5. Add Edge tests for auth validation, bad prompt, unknown generated clip type rejection, and a valid structured draft.

## Phase 3: Editor UI And Insertion

### Step 5: Add sequence insertion helpers (`src/tools/video-editor/lib/sequence-drafts.ts`, `src/tools/video-editor/hooks/clip-editing/`)

## Overview
The prior plan was aimed at the right feature, but the critique exposed several root-cause gaps that would make a renderer-only or panel-only implementation fail. The revised approach keeps the original direction, but makes the foundation explicit: preserve sequence fields through timeline row/meta conversion, carry `theme` and `theme_overrides` through `ResolvedTimelineConfig`, provide a real installed-theme metadata source for Remotion, validate asset-valued params against existing registry/selected assets, and constrain sequence insertion/replacement to visual tracks.

The implementation should reuse existing editor pieces first: timeline mutation helpers, selected media/attachment hooks, existing dialog/control primitives, `RemotionPreview`/`TimelineRenderer` plumbing, current `THEME_PACKAGE_REGISTRY` component dispatch, `ThemeChip`/theme patterns, and Edge function auth/rate-limit conventions. Effects remain wrapper clips (`effect-layer`); sequences are ordinary first-class clips with trusted `clipType`, `params`, and `hold`. No shot-theme source of truth and no arbitrary generated code are introduced.
