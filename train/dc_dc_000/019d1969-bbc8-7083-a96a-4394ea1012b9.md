# Implementation Plan: `plan_checkpoint` — The Canonical Score Checkpoint (v4)

## Context

The progression log (`progression.jsonl`) captures score snapshots redundantly across `scan_complete`, `subjective_review_completed`, `triage_complete`, and `execution_drain`. This replaces all of them with a single canonical `plan_checkpoint` event — the sole score checkpoint in the progression log.

## Core Idea: Gate communicate-score on subjective queue presence

The key design decision: **`sync_communicate_score_needed()` should only auto-resolve on the scan path when there are no subjective items in the queue.** This means:

- **Subjective items in queue** → communicate-score does NOT auto-resolve during scan reconciliation → it resolves later via the review import path → checkpoint fires from the clean review path
- **No subjective items in queue** → communicate-score auto-resolves during scan reconciliation → checkpoint fires from the scan path

This ensures every boundary crossing is covered by a checkpoint, and the common case (subjective reviews exist) always goes through the review path which has no ordering issues.

## Changes

### 1. `desloppify/engine/_plan/sync/workflow.py` — Gate communicate-score on subjective queue

Add a `defer_if_subjective_queued` parameter to `sync_communicate_score_needed()`:

```python
def sync_communicate_score_needed(
    plan: PlanModel,
    state: StateModel,
    *,
    policy: SubjectiveVisibility | None = None,
    current_scores: ScoreSnapshot | None = None,
    defer_if_subjective_queued: bool = False,  # True on scan path
) -> QueueSyncResult:
```

Insert the check **before** the existing `_subjective_review_current_for_cycle` guard (line 486), since this is a caller-context gate, not a review-readiness check:

```python
if defer_if_subjective_queued and any(
    item.startswith("subjective::") for item in order
):
    return _EMPTY()
```

**Timing subtlety:** `sync_subjective_dimensions` runs BEFORE `sync_communicate_score_needed` in the reconcile pipeline (pipeline.py:226-232). It prunes scored `subjective::` placeholders from `queue_order`. So by the time this check runs, only *unscored* subjective items remain. This means:
- If all dimensions are scored → no subjective items left → defer check passes → scan path auto-resolves (correct: no reviews needed)
- If some dimensions are unscored → subjective items remain → defer check blocks → review path will handle it (correct: reviews still needed)

This is the desired behavior — the check is effective precisely when it needs to be.

**Issue 1 — `_clear_plan_start_scores_if_queue_empty` clears rebaseline fields:** Snapshot `plan_start_scores` and `previous_plan_start_scores` immediately after `reconcile_plan()` returns (line ~373), before `_sync_plan_start_scores_and_log` (line ~387) can invoke the clearing helper:

**Issue 2 — `save_plan()` failures are swallowed:** Track save success explicitly and gate checkpoint on it:

```python
    save_succeeded = False
    if dirty:
        try:
            save_plan(plan, plan_path)
            save_succeeded = True
        except PLAN_LOAD_EXCEPTIONS as exc:
            logger.warning("Plan reconciliation save failed: %s", exc)

    # --- Progression: plan_checkpoint (scan path) ---
    if _checkpoint_plan_start is not None and save_succeeded:
        try:
            append_progression_event(
                build_plan_checkpoint_event(
                    runtime.state,
                    plan,
                    phase_before=phase_before,
                    trigger="no_subjective_review_needed",
                    source_command="scan",
                    plan_start_scores_override=_checkpoint_plan_start,
                    previous_plan_start_scores_override=_checkpoint_prev_start,
                )
            )
        except Exception:
            logger.warning("Failed to append plan_checkpoint event", exc_info=True)
```

This replaces the existing `if dirty: try: save_plan(...)` block — the only change is tracking `save_succeeded`.

### 4. `desloppify/engine/_state/progression.py` — Add event builder

```python
def build_plan_checkpoint_event(
    state: dict[str, Any],
    plan: dict[str, Any],
    *,
    phase_before: str | None,
    trigger: str,
    source_command: str,
    plan_start_scores_override: dict[str, Any] | None = None,
    previous_plan_start_scores_override: dict[str, Any] | None = None,
) -> dict[str, Any]:
```

**Payload fields:**
- `scores` — `_scores_snapshot(state)` (overall, objective, strict, verified_strict)
- `dimension_scores` — `_dimensions_snapshot(state)` (per-dimension score + strict)
- `plan_start_scores` — `plan_start_scores_override or plan.get("plan_start_scores", {})` (allows scan path to pass pre-clearing snapshot)
- `previous_plan_start_scores` — `previous_plan_start_scores_override or plan.get("previous_plan_start_scores", {})` (allows scan path to pass pre-clearing snapshot)
- `open_count` — `_open_issue_count(state)`
- `queue_summary` — built by `_queue_summary(plan)`: iterates `queue_order`, classifies items via `is_synthetic_id()`. Non-synthetic → `"objective"`, synthetic → bucketed by prefix before `::`. Skipped items excluded.
- `trigger` — string identifying what caused this checkpoint

Add `_queue_summary()` helper and `build_plan_checkpoint_event` to `__all__`.
