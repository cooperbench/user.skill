        Idea:
Make the file upload + timeline insertion flow robust.

CURRENT PROBLEMS:
1. Uploading two files in quick succession: first skeleton disappears when second one loads
2. Can't upload multiple files at once (multi-select from file picker)
3. Each upload overwrites the previous skeleton state via commitDataNoSave
4. The edit sequence counter blocks polling, which means the second upload's real clip can't show because the first upload already incremented editSeqRef
5. The 500ms delay after upload is fragile — sometimes the registry hasn't refreshed
6. Skeleton clips use a hacky 'uploading:' prefix convention

DESIRED BEHAVIOR:
- Drop one or many files at once → all show as skeletons immediately
- Each skeleton persists independently until its upload completes
- When an upload finishes, its skeleton gets replaced with the real clip
- Other skeletons stay visible while their uploads are still in progress
- Multiple rapid drops should queue properly without interfering
- No leaked skeleton clips in timeline.json ever

APPROACH:
- Use an upload queue/tracker (Map of uploadId → {file, trackId, time, status})
- Skeletons are rendered as a React overlay on the timeline, NOT as actual clips in the data model. This avoids all the save/poll/serialize issues.
- When upload completes, add the real clip via handleAssetDrop and remove from the tracker
- Multi-file drops create multiple tracker entries
- The tracker is just React state — no timeline data mutation needed for skeletons

CONSTRAINTS:
- Don't break existing asset panel drag-and-drop
- Don't break existing clip editing
- Keep the drop position indicator (blue line + ghost)
- The skeleton visual should match the current pulsing gray clip design
