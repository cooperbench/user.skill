        # Implementation Plan: Timeline & Drag Performance Optimization

## Overview

The video editor becomes laggy with many clips (63+ image clips). The root causes are:

1. **`getActionRender` is not memoized** — `TimelineEditor.tsx:130` creates a new inline function every render, and each invocation creates fresh React elements + closure-captured callbacks (`onSelect`, `onDelete`). The `@xzdarcy/react-timeline-editor` library calls this for every visible action on every render cycle.
2. **`ClipAction` is not wrapped in `React.memo`** — every clip re-renders even when its props haven't changed.
3. **Remotion Player mounts ALL clips** — `TimelineRenderer.tsx:82-85` renders every clip as a `<Sequence>` regardless of the current frame. With 63 image clips, that's 63 `<Img>` elements mounted at all times.
4. **No thumbnails on timeline clips** — the `registry` prop was just wired up in uncommitted changes (`TimelineEditor.tsx:141`) but `ClipAction.tsx` doesn't use it yet. A prior thumbnail attempt was never committed.
5. **Resize divider** — already uses window-level listeners (uncommitted changes in `VideoEditorPage.tsx:54-88`), which is the right approach. The `pointer-events: none` on the Remotion iframe overlay may still steal events. Minor fix needed.

**Constraints:** Must not break drag-and-drop (asset panel drops, within-track drags), cross-track drag (`useCrossTrackDrag`), clip editing (properties panel), or preview playback.

## Step 1: Memoize `ClipAction` with `React.memo`
**Scope:** Small  
**Risk:** Low — pure presentational component

1. **Wrap** `ClipAction` in `React.memo()` (`ClipAction.tsx:14`). The component is already a pure function of its props.
2. **Verify** prop stability: `action` and `clipMeta` are objects from `data.rows` / `data.meta` — these are stable across renders when unchanged. `isSelected` is a boolean. `onSelect` and `onDelete` are inline closures (addressed in Step 2).
3. **Add** a custom comparator if needed to compare `action.id`, `action.start`, `action.end`, `clipMeta` by value, and `isSelected` by identity — avoiding re-renders from new object references.

## Step 2: Memoize `getActionRender` and stabilize callbacks
**Scope:** Medium  
**Risk:** Medium — touches the core render path

1. **Extract** `getActionRender` from the JSX into a `useCallback` (`TimelineEditor.tsx:130-151`). Dependencies: `data.meta`, `data.registry`, `selectedClipId`, `setSelectedClipId`, `setSelectedTrackId`, `handleDeleteClip`.
2. **Stabilize** the per-clip `onSelect` and `onDelete` callbacks. Two approaches:
   - **Option A (recommended):** Pass `clipId` and `trackId` as props to `ClipAction` and have it call generic `onSelect(clipId, trackId)` / `onDelete(clipId)` handlers — these can be stable `useCallback` refs.
   - **Option B:** Use a memoized map of callbacks keyed by clip ID (more complex, less benefit).
3. **Test:** Verify that selecting a clip still highlights it, and that the delete button works.

## Step 3: Add lazy-loaded thumbnails to `ClipAction`
**Scope:** Medium  
**Risk:** Medium — new visual feature, must not break layout or drag

1. **Accept** the `registry` prop already being passed (`TimelineEditor.tsx:141`) and add it to `ClipActionProps` interface (`ClipAction.tsx:6-12`).
2. **Resolve** a thumbnail URL: look up `clipMeta.asset` in `registry` to get the file path. For images, use the asset URL directly. For videos, use a poster frame or skip (just show the colored block).
3. **Render** an `<img>` with `loading="lazy"` and `decoding="async"` as a background element behind the text label. Use `object-fit: cover` and absolute positioning within the clip div.
4. **Add** an `onError` handler to gracefully fall back to the plain colored block.
5. **CSS:** Add a subtle gradient overlay so text remains readable over the thumbnail.
6. **Skip** thumbnails for uploading clips and text clips.

## Step 4: Optimize Remotion Player — skip off-screen Sequences
**Scope:** Medium  
**Risk:** Medium — affects preview playback correctness

1. **In `TimelineRenderer.tsx`:** Remotion's `<Sequence>` already handles frame-gating internally (it renders `null` for children outside its frame range). The real cost is mounting 63 `<Img>` components.
2. **Wrap** `VisualClipSequence` calls in a guard component that checks if the clip's frame range is within a window of the current frame (e.g., ±30 frames). Use `useCurrentFrame()` to get the current position.
   ```tsx
   const LazyClipSequence: FC<{clip, track, fps, predecessor}> = (props) => {
     const frame = useCurrentFrame();
     const from = secondsToFrames(props.clip.at, props.fps);
     const dur = getClipDurationInFrames(props.clip, props.fps);
     // Only mount if within ±BUFFER of current frame
     if (frame < from - BUFFER || frame > from + dur + BUFFER) return null;
     return <VisualClipSequence {...props} />;
   };
   ```
3. **Keep** the `<Sequence>` wrapper intact (it controls timing). Only skip the inner content.
4. **Buffer:** Use 30 frames (~1s at 30fps) to avoid visible pop-in during playback.
5. **Test:** Scrub through timeline and verify no visual glitches; all clips appear at correct times.

## Step 5: Reduce polling frequency / stabilize data references
**Scope:** Small  
**Risk:** Low

1. **Increase** polling intervals in `useTimelineData.ts`:
   - `refetchInterval` for timeline: 1000ms → 2000ms (`useTimelineData.ts:164`)
   - `refetchInterval` for asset registry: 2000ms → 5000ms (`useTimelineData.ts:170`)
2. **Add** `structuralSharing: true` (default in react-query v5, but verify) so unchanged responses don't create new object references.
3. **Memoize** `materializeData` output with a signature check — if the config signature hasn't changed, return the previous `TimelineData` object to avoid cascading re-renders.

## Step 6: Fix resize divider pointer event reliability
**Scope:** Small  
**Risk:** Low — already mostly implemented in uncommitted changes

1. **Verify** the current uncommitted divider code (`VideoEditorPage.tsx:54-88`) handles edge cases:
   - Add `pointer-events: none` to the Remotion Player iframe/container during divider drag (via a CSS class toggled on the container).
   - Ensure `onMouseUp` fires even if the mouse leaves the window (already using `window` listeners — good).
2. **Test:** Drag the divider rapidly and verify it never "sticks" or loses track of the mouse.

## Step 7: Validate all interactions
**Scope:** Small  

1. **Asset panel drag-and-drop:** Drag an asset from the panel onto the timeline. Verify it creates a clip at the correct position/track.
2. **Cross-track drag:** Drag a clip from one track to another. Verify the ghost, highlight, and final placement work.
3. **Within-track drag:** Drag a clip left/right within its track. Verify snapping and position update.
4. **Clip resize:** Drag clip edges to resize. Verify start/end update correctly.
5. **Clip selection + properties:** Click a clip, verify properties panel shows correct data, edit a property, verify it saves.
6. **Preview playback:** Play the timeline, verify all clips appear at correct times with no pop-in artifacts.
7. **Delete clip:** Click delete on a clip, verify removal.
8. **Divider resize:** Drag the preview/timeline divider, verify smooth resize.

6. Step 7 (validation) — after all changes are in place.

        # Implementation Plan: Timeline & Drag Performance Optimization

## Overview

The video editor becomes laggy with 63+ image clips. Four root causes are identified in the original idea, plus one architectural issue surfaced during review:

1. **`getActionRender` not memoized** — `TimelineEditor.tsx:130` creates a new inline function and fresh React elements per clip per render.
2. **`ClipAction` not wrapped in `React.memo`** — every clip re-renders on any parent change (`ClipAction.tsx:14`).
3. **Remotion Player mounts ALL clips** — `TimelineRenderer.tsx:82-86` renders every clip as `<Sequence>` regardless of the current frame.
4. **Resize divider can lose pointer events** — the Remotion Player iframe steals pointer events during divider drag (`VideoEditorPage.tsx:54-88`).
5. **Context coupling** — `TimelineContext` (`TimelineContext.tsx:4-8`) bundles playback state (`currentTime`) with editor state in a single context. `useTimelineState()` returns a new object literal every render (`useTimelineState.ts:109`), so every context consumer re-renders when *any* field changes — even `currentTime` during playback. `TimelineEditor` doesn't use `currentTime`, but still re-renders because the context object identity changes.

Additionally, the thumbnail feature needs to be built fresh using the asset registry data. Thumbnails are image-only; video clips keep the colored block.

**Constraints:** Must not break drag-and-drop, cross-track drag, clip editing, or preview playback.

## Step 1: Split `TimelineContext` into playback vs. editor contexts (`TimelineContext.tsx`, `useTimelineState.ts`)
**Scope:** Medium  
**Risk:** Medium — changes the context wiring for all consumers

The single `TimelineContext` creates a new object every render because `useTimelineState()` (`useTimelineState.ts:109-179`) returns a fresh object literal containing both `currentTime` (changes during playback at ~30fps) and editor data (changes only on user edits). This means `TimelineEditor` re-renders during playback even though it never reads `currentTime`.

1. **Split** `TimelineContext.tsx` into two contexts:
   - `TimelineEditorContext` — carries `data`, `selectedClipId`, `selectedTrackId`, refs, editing callbacks, track management callbacks. Value is memoized with `useMemo` keyed on the fields that actually change.
   - `TimelinePlaybackContext` — carries `currentTime`, `formatTime`, `onPreviewTimeUpdate`, `onCursorDrag`, `onClickTimeArea`, `previewRef`, `timelineRef`, `playerContainerRef`, `timelineWrapperRef`.
2. **Update** `TimelineProvider` (`TimelineContext.tsx:6-9`) to provide both contexts.
3. **Update** `useTimelineContext()` consumers:
   - `TimelineEditor.tsx:12-43` — switch to `useEditorContext()` (does not need playback).
   - `VideoEditorPage.tsx:16-34` — uses both, so reads from both contexts.
   - `PreviewPanel` / `RemotionPreview` — uses playback context.
   - `PropertiesPanel` — uses editor context.
4. **Memoize** each context value with `useMemo` so the object reference is stable when its constituent fields haven't changed.

This eliminates ~30fps re-renders of the entire timeline during playback.

## Step 2: Memoize `ClipAction` with `React.memo` and stabilize callbacks (`ClipAction.tsx`, `TimelineEditor.tsx`)
**Scope:** Small  
**Risk:** Low — pure presentational component

1. **Wrap** `ClipAction` in `React.memo()` (`ClipAction.tsx:14`).
2. **Refactor** `ClipAction` props to accept stable callbacks instead of per-clip closures:
   - Replace `onSelect: () => void` with `onSelect: (clipId: string, trackId: string) => void` and pass `action.id` + `clipMeta.track` as additional props.
   - Replace `onDelete: () => void` with `onDelete: (clipId: string) => void`.
   - Inside `ClipAction`, call `onSelect(clipId, trackId)` and `onDelete(clipId)` — these are now stable references.
3. **Add** a custom `areEqual` comparator to `React.memo` that compares: `action.id`, `action.start`, `action.end`, `clipMeta` fields by value (asset, track, from, to, speed, hold, volume, entrance, exit, transition, effects), `isSelected`, and `thumbnailSrc`. This avoids re-renders from new object references produced by the timeline library.

## Step 3: Memoize `getActionRender` (`TimelineEditor.tsx`)
**Scope:** Small  
**Risk:** Low

1. **Extract** `getActionRender` from inline JSX (`TimelineEditor.tsx:130-151`) into a `useCallback`.
2. **Define** stable `onSelect` and `onDelete` handlers with `useCallback`:
   ```tsx
   const handleClipSelect = useCallback((clipId: string, trackId: string) => {
     setSelectedClipId(clipId);
     setSelectedTrackId(trackId);
   }, [setSelectedClipId, setSelectedTrackId]);

   const handleClipDelete = useCallback((clipId: string) => {
     handleDeleteClip(clipId);
   }, [handleDeleteClip]);
   ```
3. **Pass** these stable refs through `getActionRender` to `ClipAction`. Combined with Step 2's `React.memo`, clips only re-render when their own data or selection state changes.
4. **Dependencies** for `getActionRender`: `data.meta`, `data.assetMap`, `data.registry`, `selectedClipId`, `handleClipSelect`, `handleClipDelete`.

## Step 4: Add lazy-loaded image thumbnails (`ClipAction.tsx`, `TimelineEditor.tsx`)
**Scope:** Medium  
**Risk:** Medium — new visual feature, must not break drag interactions

**URL resolution:** `ClipMeta.asset` is an asset ID. `data.registry.assets[assetId]` gives the raw `file` path (e.g., `inputs/foo.png`). The data provider's `resolveAssetUrl(file)` converts this to a browser-ready URL (e.g., `/inputs/foo.png`). The resolved URLs already exist on `data.resolvedConfig.clips[].assetEntry.src`, but looking these up per clip is expensive. Instead:

1. **Build** a `thumbnailMap: Record<string, string>` in `TimelineEditor.tsx` via `useMemo` — iterate `data.resolvedConfig.clips`, and for each image clip (where `assetEntry.type?.startsWith("image")`), map `clip.id → assetEntry.src`. Pass `thumbnailMap[action.id]` as a `thumbnailSrc?: string` prop to `ClipAction`.
2. **In `ClipAction.tsx`:** Accept `thumbnailSrc?: string` prop. When present, render:
   ```tsx
   <img
     src={thumbnailSrc}
     loading="lazy"
     decoding="async"
     draggable={false}
     className="pointer-events-none absolute inset-0 h-full w-full object-cover"
     onError={(e) => { (e.target as HTMLImageElement).style.display = "none"; }}
   />
   <div className="pointer-events-none absolute inset-0 bg-gradient-to-r from-black/50 via-black/25 to-transparent" />
   ```
3. **Critical interaction safety:** The `<img>` must have `draggable={false}` to prevent native browser drag, and `pointer-events: none` (via class) so it doesn't interfere with the `.clip-action` root's `onMouseDown` handler (`ClipAction.tsx:50`) or `useCrossTrackDrag.ts:216-247`'s `pointerdown` listener.
4. **Skip** thumbnails for uploading clips (`action.id.startsWith("uploading-")`) and text clips (`clipMeta.clipType === "text"`).

**Scope:** Medium  
**Risk:** Medium — affects preview playback correctness

   ```tsx
   const BUFFER_FRAMES = 30; // ~1s at 30fps

   const LazyVisualClip: FC<VisualClipProps & { predecessor?: ResolvedTimelineClip | null }> = (props) => {
   ```

3. **Note:** The `[...visualTracks].reverse()` ordering (line 83) must be preserved.
4. **Test:** Play through the timeline end-to-end. Scrub to various points. Verify no visual gaps or pop-in at normal playback speed.
