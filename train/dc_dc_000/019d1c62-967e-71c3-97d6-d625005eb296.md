        # Implementation Plan: Unify Editor into Viewer with Remotion Player

## Overview

**Goal:** Consolidate into ONE editor (the viewer at `viewer/`) powered by `@remotion/player` for preview, while keeping Remotion Studio as a standalone preview-only tool.

**Current state:**
- **viewer/** — Full NLE UI (react-timeline-editor, AssetPanel, OverlayEditor, drag-drop) but reads/writes **timeline.yaml** and uses a **canvas-based LivePreview** that manually composites video/audio/overlays.
- **remotion/** — Remotion compositions (Timeline, VideoTrack, AudioTrack, OverlayTrack, Background, Effects) plus an **EditorOverlay portal** with ClipPanel, split/mute/property editing, and JSON-based save-config. The editor features duplicate what the viewer already has, but add split, mute, and field-level property editing.
- **No shared types** — viewer uses `ClipMeta`/`RawClip`/YAML; remotion uses `TimelineClip`/`ResolvedTimelineClip`/JSON.

**Constraints:**
- `timeline.json` + `asset-registry.json` are the source of truth (per CLAUDE.md).
- The react-timeline-editor library stays — it's the drag-drop timeline UI.
- Remotion compositions (Timeline.tsx, VideoTrack, AudioTrack, OverlayTrack, Background, Effects) stay intact — they become what `@remotion/player` renders inside the viewer.
- `server.mjs` (port 3111) is the persistence backend for JSON saves.

---

## Phase 1: Foundation — Shared Types and JSON Data Layer

### Step 1: Extract shared type definitions
**Scope:** Small
1. **Create** `shared/types.ts` at the project root (or a location importable by both viewer and remotion).
2. **Unify** `TimelineClip`, `TimelineConfig`, `TimelineOutput`, `AssetRegistryEntry`, `ResolvedTimelineClip`, `ResolvedTimelineConfig`, and `TimelineTrack` from `remotion/src/load-config.ts` — these are the canonical JSON types.
3. **Export** viewer-specific types (`ClipMeta` equivalent mapped to `TimelineClip`, row-conversion helpers) from this shared module.
4. **Update** `remotion/src/load-config.ts` to re-export from shared types instead of defining inline.

### Step 2: Replace viewer's YAML data layer with JSON
**Scope:** Medium
1. **Rewrite** `viewer/src/timeline-data.ts`:
   - Remove `js-yaml` dependency and all YAML parsing/serialization (`parseTimeline`, `toYaml`).
   - Add `loadTimelineConfig()` and `loadAssetRegistry()` functions that fetch from the Vite dev server (proxied to `server.mjs` or read directly).
   - Add conversion functions: `configToRows(config) → TimelineRow[]` (for react-timeline-editor) and `rowsToConfig(rows, meta) → TimelineConfig` (for saving).
   - Keep `getAssetColor()`, `inferTrackType()`, `getNextClipId()`, `getSourceTime()`.
2. **Update** `viewer/vite.config.ts` API endpoints:
   - `GET /api/timeline` → read `timeline.json` (not .yaml).
   - `POST /api/save-timeline` → accept JSON, write to `timeline.json` (or proxy to `server.mjs` on port 3111).
   - `GET /api/asset-registry` → serve `asset-registry.json`.
   - Keep `/api/waveform`, `/api/upload`, `/api/render`, `/media/thumb/*` unchanged.
   - Update upload handler to register assets in `asset-registry.json` instead of timeline.yaml's asset_map.
3. **Update** `viewer/src/App.tsx`:
   - Change initial load from YAML fetch to JSON fetch (timeline.json + asset-registry.json).
   - Change auto-save to POST JSON instead of YAML.
   - Change external-change polling to compare JSON signatures.
4. **Validate:** Viewer loads, displays timeline from JSON, saves edits back to JSON. Canvas preview still works (will be replaced in Phase 2).

### Step 3: Port editor-utils into viewer
**Scope:** Small
1. **Copy** `remotion/src/timeline/editor-utils.ts` into `viewer/src/editor-utils.ts` (or import from shared location).
2. **Copy** `remotion/src/save-config.ts` serialization logic (`serializeClipForDisk`, `validateSerializedConfig`, `serializeForDisk`) into viewer's save path.
3. These are pure functions with no Remotion dependencies — they operate on the shared types.

## Phase 2: Replace Canvas Preview with Remotion Player

### Step 4: Add @remotion/player to viewer
**Scope:** Medium
1. **Install** `@remotion/player`, `remotion`, and `react` peer deps in `viewer/package.json`. Since both already use React 19, this should be compatible.
2. **Make Remotion composition code importable from viewer:**
   - Option A (recommended): Move composition source files (`timeline/VideoTrack.tsx`, `AudioTrack.tsx`, `OverlayTrack.tsx`, `Background.tsx`, `Effects.tsx`, and the main `Timeline.tsx` composition) into a shared location (e.g., `shared/compositions/`) that both `remotion/` and `viewer/` can import via TypeScript path aliases or relative imports.
   - Option B: Keep compositions in `remotion/src/timeline/` and configure viewer's Vite to resolve imports from there.
3. **Create** `viewer/src/RemotionPreview.tsx`:
   - Import `Player` from `@remotion/player`.
   - Import the Timeline composition component.
   - Accept the current `ResolvedTimelineConfig` as a prop.
   - Render `<Player component={Timeline} inputProps={{ config, preview: true }} .../>`.
   - Expose imperative handle matching `PreviewHandle` interface (seek, play, pause, togglePlayPause) by calling Player's ref methods.
   - Wire `onTimeUpdate` or `Player`'s frame callback to report current time back to parent (for timeline cursor sync).
4. **Replace** `LivePreview` usage in `App.tsx` with `RemotionPreview`.
   - The `<canvas>` element used by OverlayEditor for coordinate mapping needs to be replaced with the Player's container div. Update OverlayEditor to use the Player's container dimensions instead of canvas dimensions.
5. **Validate:** Preview shows pixel-perfect Remotion output. Play/pause/seek works. Timeline cursor syncs with player. Overlay editor still works for positioning.

### Step 5: Resolve asset file serving
**Scope:** Small
1. **Remotion Player** needs `staticFile()` URLs for media. In Remotion Studio, `staticFile("inputs/demo-one.mp4")` resolves via Remotion's dev server. In the viewer's Vite server, these paths don't exist.
2. **Solution:** Configure Vite to serve the project root's `inputs/` directory at `/inputs/` (already partially done via existing media serving). Ensure `asset-registry.json` file paths like `inputs/demo-one.mp4` resolve correctly when used as `src` attributes.
3. **Update** `loadTimelineConfig` for viewer context: resolve `file` paths from asset-registry to Vite-served URLs (e.g., `/inputs/demo-one.mp4` served by Vite's static middleware) rather than using Remotion's `staticFile()`.
4. The composition components currently use `clip.assetEntry.src` which is set by `loadTimelineConfig()` via `staticFile()`. For the viewer, this needs to be set to the Vite-served URL instead. This means the config-loading code must be environment-aware or accept a URL resolver function.
