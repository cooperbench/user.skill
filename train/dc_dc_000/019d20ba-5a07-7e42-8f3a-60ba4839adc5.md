        # Implementation Plan: X/Twitter OAuth Feedback Section

## Overview
Add a `/assorted/feedback` section to an existing React SSR + Express + Supabase personal website. Users sign in with X (Twitter) OAuth via Supabase Auth, submit text (max 1000 chars) + image feedback, and see a reverse-chronological listing. The site owner responds to feedback directly in the database (no admin UI). Feedback from users with <100 X followers is flagged as suspicious.

**Current stack:** React 19 / React Router 6 / Express SSR / Vite / Supabase (Postgres + Storage) / Tailwind CSS / Railway deployment. No auth system exists. Supabase is accessed via a thin REST wrapper (`src/lib/supabase.ts`) using the anon key. The `SUPABASE_SERVICE_ROLE_KEY` env var already exists in Railway but has no server-side helper. The `@supabase/supabase-js` SDK is not installed.

**Key constraint — follower count:** The free Twitter API tier allows 25 requests/24h to `GET /2/users/me?user.fields=public_metrics`. This call must happen server-side using the user's `provider_token` from the Supabase auth session. A new Express API route handles this, registered **before** the SSR catch-all at `src/server.ts:74`.

## Step 4: Create database table and storage bucket (`supabase/migrations/`)
**Scope:** Small
1. **Create** migration file `supabase/migrations/YYYYMMDD_create_feedback.sql` with:
   ```sql
   -- Feedback table
   create table feedback (
     id uuid default gen_random_uuid() primary key,
     user_id uuid references auth.users(id) not null,
     x_username text not null,
     x_user_id text not null,
     x_avatar_url text,
     x_followers_count int,
     is_suspicious boolean generated always as (
       coalesce(x_followers_count, 0) < 100
     ) stored,
     feedback_text text not null check (char_length(feedback_text) <= 1000),
     image_paths text[] default '{}',
     owner_response text,
     owner_response_at timestamptz,
     created_at timestamptz default now()
   );

   alter table feedback enable row level security;

   -- Anyone can read all feedback
   create policy "Public read feedback" on feedback
     for select using (true);

   -- Authenticated users can insert their own row
   create policy "Auth users insert own feedback" on feedback
     for insert with check (auth.uid() = user_id);

   -- No update/delete policy = only service_role can modify
   -- (owner writes responses directly in DB or via service-role helper)

   -- Storage bucket for feedback images
   insert into storage.buckets (id, name, public)
   values ('feedback-images', 'feedback-images', true)
   on conflict (id) do nothing;

   -- Public read on feedback-images bucket
   create policy "Public read feedback images"
   on storage.objects for select to public
   using (bucket_id = 'feedback-images');

   -- Authenticated users can upload to their own prefix: feedback-images/{user_id}/*
   create policy "Auth users upload own feedback images"
   on storage.objects for insert to authenticated
   with check (
     bucket_id = 'feedback-images'
     and (storage.foldername(name))[1] = auth.uid()::text
   );
   ```
2. **Run** the migration via `supabase db push` or apply directly in the Supabase SQL editor.
3. **Verify** in the Supabase dashboard: table exists with correct columns, RLS policies active, storage bucket created with correct policies.

## Step 7: Build the Feedback page components (`src/pages/Feedback.tsx`, `src/hooks/useAuth.ts`)
**Scope:** Large
1. **Create** `src/hooks/useAuth.ts` — a React hook wrapping Supabase Auth:
   - Exposes `user`, `session`, `loading`, `signInWithTwitter()`, `signOut()`.
   - On mount, calls `supabase.auth.getSession()` and subscribes to `onAuthStateChange`.
   - After successful sign-in, calls `POST /api/feedback/enrich` with `session.provider_token` to fetch X profile data (username, avatar, followers_count). Stores this enriched data in hook state.
   - Falls back gracefully if the enrich call fails (uses `user_metadata.user_name` and `user_metadata.avatar_url` from Supabase, `followers_count: null`).
2. **Create** `src/pages/Feedback.tsx` with these sections:
   - **Header** using existing `<Header activeTab="assorted" />` pattern (consistent with other assorted sub-pages like `src/pages/Assorted.tsx:8`).
   - **Sign-in button** (shown when not authenticated): "Sign in with X to leave feedback". Calls `signInWithTwitter()`.
   - **Submission form** (shown when authenticated): textarea (max 1000 chars, character counter), image upload input (max 3 files, max 5MB each, accept `image/jpeg,image/png,image/webp,image/gif`), submit button. Displays the user's `@username` and avatar.
   - On submit: uploads images to Supabase Storage at path `{user_id}/{uuid}.{ext}`, then inserts feedback row via `supabase.from('feedback').insert(...)` using the client SDK with the user's auth session.
   - **Feedback list** (always shown): reverse chronological, each entry shows X avatar, `@username` linked to `x.com/{username}`, relative timestamp, first 3 lines of feedback text (CSS `line-clamp`), suspicious badge if `is_suspicious` is true. If `owner_response` exists, show first 5 lines truncated.
   - **Expand behavior**: click on an entry to expand in-place showing full feedback text, all images inline, and full owner response. Uses a simple `useState` toggle per entry (similar to card expansion pattern in `src/hooks/useCardExpansion.ts`).
3. **Accept** `feedback` prop from initial data for SSR, with client-side re-fetch after submission to update the list.
