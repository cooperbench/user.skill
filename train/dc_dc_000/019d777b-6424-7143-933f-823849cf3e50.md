        # Implementation Plan: Spoofable End-to-End Preview Harness

## Overview

**Goal:** Build a single-script harness that replays the full worker lifecycle — from task claim through WGP generation to completion — across representative generation types, using spoofed DB and WGP layers so no real model execution or Supabase connectivity is needed. An operator runs one command and sees the real log sequence (plant animation, task claim, model switch, generation progress, completion) to validate that the visible experience is correct.

**Current state:**
- The worker already has `HEADLESS_WAN2GP_SMOKE` mode (`orchestrator.py:162`) which skips WGP imports and returns placeholder outputs. This is the generation-level spoof — it's necessary but not sufficient because it still requires a live Supabase connection, real task claiming, and the full `wgp.py` import chain.
- DB interactions go through `source.core.db.task_claim.poll_next_task` and `source.core.db.task_status.update_task_status_supabase` — both call Supabase edge functions via httpx.
- `scripts/create_test_task.py` has real task fixtures (`TEST_TASKS` dict) with full param payloads.
- The main loop is in `server.py:main()` (line 248) — it's one monolithic function that does CLI parsing, DB init, WGP import, queue init, and the poll loop. This is the main challenge: we need to run the same code paths but with spoofed DB and WGP layers.
- Existing tests use `monkeypatch` to stub individual functions. The harness needs to orchestrate multiple stubs together into a coherent scenario.

**Strategy:** Rather than refactoring `server.py:main()` (high risk, large blast radius), build a preview script that:
1. Injects spoof implementations for the DB layer (task_claim, task_status) and WGP layer (via existing smoke mode)
2. Feeds a sequence of task fixtures from `create_test_task.py`
3. Runs the real `process_single_task` function and surrounding logging code
4. Captures and validates the log output sequence

**Key constraint:** The harness must exercise the _real_ logging code paths — `source.core.log.core` functions, `WorkerStatusDisplay`, and `task_processor.py` log lines — not mock them. The DB and WGP layers are what get spoofed; the log layer stays real.

   - `requeue_task_for_retry` — no-op
