        # Implementation Plan: Asset Slots for AI-Generated Sequence Components

## Overview
The current implementation lets AI-generated sequence components declare loose `params.imageAssetKeys` / `params.videoAssetKeys`, then the host conventionally materializes them to `params.images` / `params.videos`. That behavior appears in `supabase/functions/ai-generate-sequence-component/templates.ts`, `supabase/functions/ai-generate-sequence-component/sequence-component-validation.ts`, `src/tools/video-editor/sequences/materialize.ts`, `src/tools/video-editor/components/SequenceCreator/CodePathPreview.tsx`, `src/tools/video-editor/components/SequenceCreator/CodePathParamEditor.tsx`, and `src/tools/video-editor/components/SequenceCreator/SequenceCreatorPanel.tsx`.

The cleaner fix is to make generated components self-describing with explicit slot metadata, persist that slot contract on `sequence-component` resources, and treat user choices as `params.assetSlotBindings` (or an equivalent single slot-binding param) rather than top-level loose image/video arrays. Existing built-in trusted sequences can keep descriptor-driven `asset-list` params unless the product wants to migrate them too. Backwards compatibility is explicitly not required, so new generated components and saved generated resources should use the slot contract only.

## Phase 1: Define the Contract — Types, Shapes, and Naming

### Step 1: Add shared asset-slot types (`src/tools/video-editor/sequences/assetSlots.ts`, `src/features/resources/hooks/useResources.ts`)
**Scope:** Medium
1. **Create** a focused asset slot module with types and helpers for:
   - `SequenceAssetSlot`: `{ id, label, mediaType: 'image' | 'video', minItems?, maxItems?, required?, defaultAssetKeys? }`.
   - `SequenceAssetSlotBindings`: `Record<string, string[]>` keyed by slot id.
   - `normalizeAssetSlots`, `normalizeAssetSlotBindings`, and `validateAssetSlotBindings`.
2. **Persist** `assetSlots?: unknown[]` on `SequenceComponentMetadata` in `src/features/resources/hooks/useResources.ts` alongside `controlsManifest`.
3. **Extend** `SequenceComponentResource` flow in `src/tools/video-editor/lib/sequence-component-catalog.ts` only if needed by types; the current metadata spread likely carries the new field automatically.

### Step 2: Choose the slot param name and URL materialization shape (`src/tools/video-editor/sequences/assetSlots.ts`)
**Scope:** Small
1. **Use** `params.assetSlotBindings` as the persisted key-binding object for generated components.
2. **Materialize** to `params.assetSlots` as a runtime object shaped like `Record<slotId, string[]>`, where each array contains resolved URLs in binding order.
3. **Reserve** `assetSlots` as host-injected URL data, not a user-authored schema field.
4. **Document** this in code comments near the contract helpers because the name collision risk is high.

## Phase 2: Edge Generation Contract and Validation

### Step 3: Update prompts to require `ASSET_SLOTS` metadata (`supabase/functions/ai-generate-sequence-component/templates.ts`)
**Scope:** Medium
1. **Replace** the current asset-key prompt block with a slot-based contract:
   - Metadata lines include `// ASSET_SLOTS: [...]` between `DEFAULTS` and `CONTROLS`.
   - Number allowed assets in the user prompt with media type and label, for example `1. [image] asset-a — Shot name`.
   - Instruct the model to put default selected keys in `DEFAULTS.assetSlotBindings`, not `imageAssetKeys` or `videoAssetKeys`.
   - Instruct render code to read URLs from `params.assetSlots.<slotId>`.
2. **Keep** URL arrays excluded from `CONTROLS`; slot pickers own them.
3. **Remove** prompt guidance that asks for `imageAssetKeys`, `videoAssetKeys`, `images`, or `videos` for generated components.

### Step 4: Parse and return `assetSlots` from generated code (`supabase/functions/ai-generate-sequence-component/templates.ts`, `supabase/functions/ai-generate-sequence-component/index.ts`)
**Scope:** Medium
1. **Extend** `ExtractedSequenceComponentMeta` with `assetSlots: unknown[]`.
2. **Require** `ASSET_SLOTS` to parse as a JSON array. Allow `[]` when no media is needed or no allowed assets exist.
3. **Include** `assetSlots` in the edge response shape and frontend service response type.
4. **Fail** generation if `ASSET_SLOTS` is missing, since backwards compatibility is not required for new generated components.
