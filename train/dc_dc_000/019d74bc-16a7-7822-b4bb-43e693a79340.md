## Overview
The plan is still aimed at the right code paths: the Windows worker-launch regression lives in the guardian subprocess path in `reigh-worker` and the Windows command builder in `reigh-app`. The critique does not point to a different root cause, but it does show the original fix was too narrow in two places:

1. `reigh-worker/source/runtime/worker/guardian.py:52-107` has two Windows subprocess sites, not one. If daemon crashes are caused by console-backed child processes on Windows, both `nvidia-smi` and the heartbeat `curl` call need the same no-window handling.
2. String/unit checks in `reigh-app` are necessary but not sufficient for a Windows-only regression. The existing Windows workflow in `reigh-worker/.github/workflows/test-windows-install.yml:1` already validates the `uv sync` and `uv run --extra ...` form on a real Windows runner, so the plan should require that path instead of leaving Windows execution as optional.
