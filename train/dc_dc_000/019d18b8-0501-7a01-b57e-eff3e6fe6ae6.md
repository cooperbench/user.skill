# Lifecycle Phase Cleanup — Implementation Plan (v2)

## Current State

The snapshot layer in `engine/_work_queue/snapshot.py` has **two phase derivation paths**:
1. `_derive_display_phase()` — used when persisted mode is "plan" or "execute"
2. `_legacy_phase_inference()` — fallback when `current_lifecycle_phase()` returns None

Plus dead code: `_ordered_postflight_phase()` (never called), `_DISPLAY_PHASE_ITEM_MAP` (never read).

Two duplicate constant sets with identical values:
- `PHASE_*` in `snapshot.py` (7 constants)
- `LIFECYCLE_PHASE_*` in `refresh_lifecycle.py` (7 constants)

## Strategy

1. Fix `current_lifecycle_phase()` to never return None → makes `_legacy_phase_inference` unreachable
2. Delete dead code (`_legacy_phase_inference`, `_ordered_postflight_phase`, `_DISPLAY_PHASE_ITEM_MAP`)
3. Unify constants (eliminate `PHASE_*`, use `LIFECYCLE_PHASE_*` everywhere)
4. Inline `_raw_persisted_phase`

Keep `_derive_display_phase` private (no public rename — scope creep).
Keep reconciliation pipeline's `_resolve_reconcile_display_phase` as-is (different layer, operates on queue_order strings).
Note dual-build threshold bug in `plan_aware_queue_breakdown` as out-of-scope known issue.
