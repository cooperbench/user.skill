        # Implementation Plan: Fix OverlayEditor Preview Interactions

## Overview

The OverlayEditor (`src/tools/video-editor/components/PreviewPanel/OverlayEditor.tsx`) handles preview-canvas clip manipulation (move, resize). Three issues need fixing, plus a new crop feature. All issues are within the preview overlay system, NOT the timeline.

**Root cause of issue #1 (shape changes during move):** Lines 215-232 use `state.mode.includes('e')` etc. to detect resize directions, but the checks run unconditionally after the `move` branch — and `'move'.includes('e')` is `true`. So every move also triggers east-resize, changing width.

**Root cause of issue #2 (ghost/shadow during drag):** Lines 297-313 explicitly render a `dragOriginStyle` div at the start position while dragging. This dashed-border ghost shows the original bounds. Removing or rethinking this removes the lingering shadow.

**Coordinate-space mismatch:** Lines 211-212 compute deltas in screen pixels (`event.clientX - startMouseX`) but apply them directly to composition-space coordinates. Move/resize speed doesn't match cursor when preview is scaled.

**New feature (edge crop):** No crop data model exists. Need edge handles that crop from sides, with dimmed ghost of full uncropped area shown when clip is selected.

## Phase 1: Fix Move & Resize Bugs

### Step 1: Fix the string-matching bug (`OverlayEditor.tsx:215-232`)
**Scope:** Small — root cause of issue #1.
**File:** `src/tools/video-editor/components/PreviewPanel/OverlayEditor.tsx`

Guard all resize branches with `state.mode !== 'move'` so that the `.includes()` checks only run for resize modes:

```typescript
// Before (buggy — 'move'.includes('e') is true):
if (state.mode === 'move') { ... }
if (state.mode.includes('e')) { ... }  // fires during move!

// After:
if (state.mode === 'move') {
  nextBounds.x += deltaX;
  nextBounds.y += deltaY;
} else {
  if (state.mode.includes('e')) { nextBounds.width = ... }
  if (state.mode.includes('s')) { nextBounds.height = ... }
  if (state.mode.includes('w')) { nextBounds.x = ...; nextBounds.width = ... }
  if (state.mode.includes('n')) { nextBounds.y = ...; nextBounds.height = ... }
}
```

### Step 2: Fix coordinate-space mismatch (`OverlayEditor.tsx:205-262`)
**Scope:** Small
**File:** `src/tools/video-editor/components/PreviewPanel/OverlayEditor.tsx`

1. Add `scaleX` and `scaleY` fields to the `dragState` ref type (line 47-55).
2. In `startDrag` (line 249-262), compute and store `scaleX = compositionWidth / layout.width` and `scaleY = compositionHeight / layout.height`.
3. In `onMouseMove` (line 211-212), scale deltas: `deltaX = (event.clientX - state.startMouseX) * state.scaleX`.

This ensures 1:1 cursor tracking at any preview zoom level.

### Step 3: Remove/fix the drag origin ghost (`OverlayEditor.tsx:297-313`)
**Scope:** Small — root cause of issue #3 (shadow lingering during drag).
**File:** `src/tools/video-editor/components/PreviewPanel/OverlayEditor.tsx`

Lines 297-313 render a dashed-border div at the clip's original position during drag. This is the "shadow" the user sees. For basic move/resize, remove this ghost entirely — it adds visual noise without value. Later (Phase 2), repurpose this concept for crop: show the full uncropped bounds as a dimmed ghost only when a cropped clip is selected.

Remove `dragOriginStyle` computation (lines 297-302) and the `{dragOriginStyle && ...}` JSX (lines 309-313).

## Phase 2: Add Edge Crop

### Step 4: Add crop fields to data model
**Scope:** Small
**Files:** `src/tools/video-editor/types/index.ts`, `src/tools/video-editor/lib/timeline-data.ts`, `src/tools/video-editor/lib/serialize.ts`

1. Add to `TimelineClip` type (`types/index.ts:61-83`):

   ```typescript
   cropTop?: number;    // 0-1, fraction of clip to crop from top
   cropBottom?: number;
   cropLeft?: number;

   ```

### Step 5: Add edge crop handles and drag logic (`OverlayEditor.tsx`)
**Scope:** Medium
**File:** `src/tools/video-editor/components/PreviewPanel/OverlayEditor.tsx`

1. Extend `DragMode`: `type DragMode = 'move' | 'resize-nw' | 'resize-ne' | 'resize-sw' | 'resize-se' | 'crop-n' | 'crop-s' | 'crop-e' | 'crop-w';`

2. Add 4 edge handle elements — invisible ~6px hit strips along each edge with visible line on hover. Only on non-text clips. Cursor: `cursor-ns-resize` for top/bottom, `cursor-ew-resize` for left/right.

3. Add crop drag logic in `onMouseMove`. Edge drags modify `cropTop/cropBottom/cropLeft/cropRight` as 0-1 fractions rather than position/size. Track crop values separately in `dragState` (not in `OverlayBounds`).

4. Commit crop values via `onOverlayChange(actionId, { cropTop, cropLeft, ... })` in `commitDragChange`.

5. Update `OverlayBounds`/visual overlay rendering to reflect crop: when a clip has crop values, the visible overlay rectangle should be the cropped sub-region.

### Step 6: Show full bounds ghost when cropped clip is selected
**Scope:** Small
**File:** `src/tools/video-editor/components/PreviewPanel/OverlayEditor.tsx`

When a clip with crop values is **selected** (not necessarily being dragged), render a dimmed ghost showing the full uncropped bounds behind the visible cropped area. This replaces the old `dragOriginStyle` concept with a more useful purpose. The ghost should:
- Show the full original clip area with reduced opacity / dashed border
- Only appear when the clip is selected AND has non-zero crop values
- Disappear when the clip is deselected

### Step 7: Wire crop into Remotion rendering
**Scope:** Small
**File:** `src/tools/video-editor/compositions/VisualClip.tsx`

Apply crop values in `getClipBoxStyle` (line 15-46) as CSS `clip-path: inset()`:

```typescript
const cropTop = clip.cropTop ?? 0;
const cropRight = clip.cropRight ?? 0;
const cropBottom = clip.cropBottom ?? 0;
const cropLeft = clip.cropLeft ?? 0;
const hasCrop = cropTop || cropRight || cropBottom || cropLeft;
if (hasCrop) {
  style.clipPath = `inset(${cropTop * 100}% ${cropRight * 100}% ${cropBottom * 100}% ${cropLeft * 100}%)`;
}
```

This works for both preview and final Remotion render since `clip-path` is standard CSS.

### Step 8: Validate all changes end-to-end
**Scope:** Small

1. Move a clip on preview — width/height unchanged, cursor tracks 1:1 regardless of zoom.
2. Corner resize — scales width/height, anchored at opposite corner.
3. No shadow/ghost at original position during move or resize.
4. Edge crop — dragging an edge inward visually crops from that side.
5. Selected cropped clip shows dimmed ghost of full uncropped bounds.
6. Deselected cropped clip shows only the cropped visible area.
7. Crop persists after save/load (verify serialize round-trip).
8. Regression: text clip move/resize, double-click to edit text, clip selection all still work.
