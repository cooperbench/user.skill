        # Implementation Plan: Resident Discord Operator Tool Layer

## Overview
Add the missing resident Discord operator tools through `MegaplanResidentProfile`, preserving the current constrained model: allowlisted users can read/search, while broad mutation, export/archive, reconciliation, repo, and cloud-start operations require admin authorization and exact confirmation before side effects.

The remaining critique does not change the root cause or the main integration point. The plan is still correctly centered on resident tools, Store-backed persistence, and durable repo metadata. The correction is in the cloud lifecycle detail: passing registered repo data into `CloudSpec.repo` is necessary, but chain/bootstrap callers do not deploy or restart the rendered entrypoint, so they must explicitly run a fixed internal ensure-repo checkout step before upload/exec. This keeps the work aligned with the original brief without adding a Discord-facing shell or broad remote command tool.

## Phase 1: Tool Surface And Security Foundation

### Step 1: Define resident input schemas and register tools (`megaplan/resident/profile.py`, `megaplan/resident/auth.py`)
**Scope:** Medium
1. Add focused `ToolInput` models for `search_messages`, `search_epics`, `search_plans`, `search_code_artifacts`, `list_codebases`, `list_repos`, `register_codebase`/`add_repo`, `read_plan_artifact`, `write_plan_artifact`, `reconcile_epic`, `reconcile_plan_storage`, `export_epic_bundle`, and `archive_cloud_logs`.
2. Add optional `codebase_id`, `repo_url`, `repo_branch`, and `repo_workspace` fields only to cloud start/bootstrap inputs that need registered repo selection.
3. Register all new tools in `MegaplanResidentProfile._register_default_tools`.

5. Assert no tool names expose shell, exec, remote shell, filesystem write, arbitrary clone, or arbitrary remote command capabilities.

### Step 2: Make high-impact confirmation explicit (`megaplan/resident/auth.py`, `megaplan/resident/config.py`, `megaplan/resident/profile.py`)
**Scope:** Medium
1. Extend `ActionKind` with explicit high-impact actions such as `repo_mutation`, `artifact_write`, `reconcile`, `export_bundle`, and `archive_logs`.
2. Update `ResidentAuthorizer.authorize_action` so `cloud_start`, `admin`, and the new high-impact actions require `admin_user_ids` membership after inbound allowlist checks.
3. Extend `ConfirmationManager.required_for` so `cloud_start` continues to use `require_cloud_start_confirmation`, and the new high-impact actions require exact confirmation by default through an explicit configured/default action set.
4. Add a generic `_require_exact_confirmation(payload, action, tool_name, target_summary, request_id, phrase)` helper and have `_require_cloud_confirmation` delegate to it.
5. Ensure handlers call authorization and confirmation before creating store records, invoking cloud backend, writing artifacts, exporting, archiving, reconciling, or preparing remote repo state.

## Phase 2: Store-Backed Read/Search Tools

### Step 3: Implement message, epic, plan, and codebase read tools (`megaplan/resident/profile.py`)
**Scope:** Medium
1. `search_messages`: call `Store.search_messages(query=..., epic_id=..., limit=...)`.
2. `search_epics`: call `Store.search_epics(query=..., active_only=..., limit=...)`.
3. `search_plans`: use `Store.list_plans(...)` and apply bounded in-memory matching over plan id, name, idea, current state, and metadata summary fields.
4. `list_codebases`: call `Store.list_codebases(...)` and return durable codebase metadata.
5. `list_repos`: return only codebases with `repo_url`, shaped as repo URL, branch, workspace if configured, scope, owner/name, and associated epic.
6. Cap all result limits in Pydantic schemas and return compact response objects rather than unbounded model dumps.

### Step 4: Implement redacted code artifact search (`megaplan/resident/profile.py`)
**Scope:** Medium
1. `search_code_artifacts`: call `Store.list_code_artifacts(...)` and filter over `file_path`, `content_summary`, `source`, metadata, and bounded content snippets.
2. Never return full `CodeArtifact.content` from search results by default.
3. Return only `id`, `codebase_id`, `epic_id`, `kind`, `source`, `file_path`, `line_range`, `scope`, `content_summary`, bounded matched snippet, metadata keys or allowlisted metadata fields, timestamps, and expiry.
4. Add a separate future-facing read-by-id path only if needed; keep it out of this task unless tests require it, and require admin confirmation if full content would be exposed.

## Phase 4: Safe Artifacts, Export, Reconcile, Archive

### Step 8: Add plan artifact tools (`megaplan/resident/profile.py`)
**Scope:** Medium
1. `read_plan_artifact`: authorize as read, load the plan, call `Store.read_plan_artifact`, and return UTF-8 text only when decodable and under a bounded size limit.
2. For binary or oversized artifacts, return metadata plus base64 only when within a configured small response limit; otherwise return size/hash metadata and require a narrower follow-up.
3. `write_plan_artifact`: require `artifact_write` admin authorization and exact confirmation, then call `Store.write_plan_artifact` with `expected_revision` and deterministic idempotency.
4. Reuse existing Store/FileStore/DBStore artifact path safety and add tests proving unsafe artifact names remain rejected.

### Step 9: Implement constrained epic export (`megaplan/resident/profile.py`, `megaplan/store/export.py`, `megaplan/resident/config.py`)
**Scope:** Medium

4. Call `write_epic_export_tar` only with that managed path after `export_bundle` admin authorization and exact confirmation.
5. Verify the resolved output path is inside the managed export root before writing.
6. Return export manifest summary, size, sha256, and managed relative path; never accept arbitrary absolute or `..` output paths from Discord.

### Step 10: Implement reconciliation wrappers (`megaplan/resident/profile.py`, `megaplan/store/multi.py`)

### Step 11: Implement cloud log archiving with a defined Store target (`megaplan/resident/profile.py`)
