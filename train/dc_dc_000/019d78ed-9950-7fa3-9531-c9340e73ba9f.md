## Overview

Today, task lifecycle lines are scattered across ~15 modules. Each handler (travel, join, qwen, z_image, edit_video, queue, model ops) emits its own "Starting X task" / "X completed" lines via `xxx_logger.essential(...)`, often duplicating the anchor that the central worker loop already has. Debug output uses `debug_block` / `debug_anomaly` (`source/core/log/core.py:199,209`) but with no aligned-column layout. Task IDs are raw UUIDs everywhere. Paths are mostly absolute. There is no final run summary.

The repo already has useful bones:
- `source/core/log/core.py` — `essential/success/debug/debug_block/debug_anomaly`, `ComponentLogger`, log-interceptor hooks.
- `source/core/log/tasks.py` — existing `get_display_name(model)` + stub `log_task_start/log_task_complete/log_task_error` that nothing in the handlers actually uses.
- Central dispatch loop at `source/runtime/worker/server.py:444-589` — where every top-level task gets claimed, run, and finalized. This is the natural single anchor.
- Task type vocabulary at `source/task_handlers/tasks/task_types.py` — the canonical list of task types to map to friendly names.

Goal: introduce three small modules (`display_names`, `DebugCard`, `TaskLifecycleEmitter`), wire the emitter into the central dispatch loop so every top-level task gets exactly one start and one done line in both modes, then delete/downgrade the duplicate lifecycle emissions scattered across handlers. In debug mode, start/done render as aligned-column cards; in essential mode they render as a single line. Anomalies continue to break the grid via the existing `debug_anomaly` path. A `RunSummary` accumulator flushes at shutdown.

Constraints:
- Must preserve the log-interceptor hook (DB-side log capture still wraps `essential/success/error/debug` in `core.py:330-384`). Emitter must route through these so the interceptor keeps tagging lines with the current task id.
- Must not break the existing test suite. No test currently exercises the old helpers, so refactor is mostly additive at the test layer.
- Must not regress the billing-critical model-switch telemetry in `source/models/wgp/model_ops.py` or the edge-function notification at line 130 — those are orthogonal and stay.
- Sub-task lifecycle inside orchestrators (travel segments, join transitions, inpaint_frames iterations) must NOT get their own anchor — only top-level claimed tasks do, else we re-introduce the clutter we're removing.

### Step 4: Create `TaskLifecycleEmitter` (`source/core/log/lifecycle.py`)
**Scope:** Medium
1. **Implement** the single-anchor emitter that every claimed top-level task flows through.
   ```python
   class TaskLifecycleEmitter:
       def __init__(self, component: ComponentLogger = task_logger): ...
       @contextmanager
       def task(self, task_id: str, task_type: str, **details) -> Iterator["_Handle"]:
           # emits start line (and debug card), yields handle, emits done/error
   class _Handle:
       def set(self, **details): ...        # add rows for the done card
       def anomaly(self, stage, msg): ...   # passthrough to debug_anomaly
   ```
2. **Essential mode** (`is_debug_enabled() == False`): emit exactly one `essential(...)` line at start and one `success(...)`/`error(...)` line at done. Format:
   ```
   ▶ Travel [travel#3a7f9b21] started
   ✓ Travel [travel#3a7f9b21] done in 42.1s → outputs/travel_segment/....mp4
   ```
   Paths via `rel_path`. Task id via `friendly_task_id`. Task label via `task_type_label`.
3. **Debug mode**: in addition to the single one-line anchor, emit a `DebugCard` at start (showing resolved params) and at done (showing output path, duration, counts, anomaly count). No second "starting"/"done" line — the card IS the expansion.
4. **Errors**: if the handler raises or returns failure, emit the error line once with category + message; record failure in the run summary.
5. **RunSummary integration**: the emitter appends an entry per task to a module-level `RunSummary` singleton (task_type, friendly id, outcome, duration, output path). `RunSummary.render()` produces a final aligned card grouped by task_type with counts + total duration.
6. **Interceptor safety**: emit via `essential/success/error/debug` from `core.py` so the DB log-interceptor continues to tag lines with the current task id. Do NOT write to stdout directly.
