        # Implementation Plan: Run Audit and Provenance

## Overview
The critique points at the right root cause: the original plan treated provenance as a pipeline-level scrape of sentinel files after subprocesses completed. That is useful as a safety net, but it is not enough for the requested node/asset model. In ArtAgents, real asset semantics are born inside child tools: `transcribe.py` creates transcript artifacts, analysis tools create source evidence, `arrange.py` creates prompt/model-backed arrangements, `cut.py` creates asset registries/timelines/metadata, `refine.py` mutates timeline and metadata, `render_remotion.py` creates renders, and `generate_image.py` creates prompt-linked image outputs.

The revised approach is a small audit creation/registration API that tools call at creation time. The pipeline still initializes run context and records step lifecycle/logs, but durable provenance comes from registered nodes/assets with stable ids, type/kind, label, path or text reference, parent ids, producing stage/tool, prompt/config refs, model/provider metadata, timestamps, practical content hashes, decision state, and renderer-friendly preview metadata. The audit report should trust the ledger graph instead of inferring the graph from filenames after the fact.

Audit data remains run-local under `<run>/audit/`, does not embed large artifacts, does not leak secrets, and preserves existing file-based run patterns.

## Phase 1: Foundation — Audit API and Ledger Schema

### Step 1: Add the audit creation API (`artagents/audit.py`)
**Scope:** Medium
1. **Implement** a new `artagents/audit.py` module with an `AuditContext` loaded from explicit args or environment (`ARTAGENTS_AUDIT_RUN`, `ARTAGENTS_AUDIT_STAGE`, `ARTAGENTS_AUDIT_SCOPE`, `ARTAGENTS_AUDIT_BRIEF_SLUG`).
2. **Store** append-only JSONL at `<run>/audit/ledger.jsonl`; keep generated report files under the same folder, e.g. `<run>/audit/report.html`.
3. **Expose** creation-first helpers:
   ```python
   ctx.register_asset(kind="transcript", path=path, parents=[audio_id], label="Transcript")
   ctx.register_node(kind="timeline", path=timeline_path, parents=[arrangement_id, asset_registry_id])
   ctx.register_decision(kind="selection", path=arrangement_path, parents=[pool_id], state="selected")
   ctx.register_prompt_ref(kind="brief", path=brief_path, parents=[source_id])
   ```
4. **Return stable ids** from registration. Use deterministic ids where practical: explicit semantic key if supplied, otherwise a stable hash of run-relative path, kind, producing stage/tool, and parent ids. Avoid random-only ids so repeated cached/report reads remain linkable.
5. **Record metadata fields** for each asset/node: `schema_version`, `id`, `event_type`, `kind`, `type`, `display_label`, `path`, `text_ref`, `parents`, `producing_stage`, `producing_tool`, `scope`, `brief_slug`, `prompt_refs`, `config_refs`, `model`, `provider`, `created_at`, `content_sha256`, `size_bytes`, `mtime`, `decision_state`, and `preview`.
6. **Keep content lightweight**: hash small text/JSON artifacts when practical, record size/mtime for large files, and never embed large media bytes.
7. **Redact** sensitive values in command/config metadata: API-key env vars, bearer-like tokens, authorization headers, and sensitive flag values such as `--env-file` contents.

### Step 2: Add graph loading and report rendering (`artagents/audit.py`)
**Scope:** Medium
1. **Implement** `load_ledger(run_dir)`, `build_graph(events)`, and `render_html_report(run_dir, out_path)` in the same module.
2. **Build** the graph from registered node/asset ids and parent ids, not from filename guessing. Filename classification can remain only as a display fallback for legacy entries.
3. **Render** a dependency-free, self-contained HTML report with summary, stage timeline, node/asset graph, artifact inventory, decisions, prompt/config refs, and previews where metadata is available.
4. **Support** `--json` summary output for tests and automation.
5. **Leave PNG optional** unless an existing local screenshot path is trivial without adding a browser dependency. HTML is the required first report format.
