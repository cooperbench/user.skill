# Implementation Plan: Visual Flares for Task Lifecycle Logging

## Overview
Add decorative, automatic visual flair to the worker log output centered on `TaskLifecycleEmitter` so every task type (travel, join, qwen, z_image, edit_video, magic_edit, …) inherits the treatment for free.

Concrete additions:
1. **❀ bloom** on task start (replacing `▶`) and **✿ bloom** on task done (replacing `✓`); `❌` retained for failure.
2. **Two blank-line "breath" separator** between consecutive tasks (currently one blank line, `lifecycle.py:173`).
3. **Heavy `━━━━` rules** for the task-lifecycle debug cards (Task Start / Task Done / Run Summary); the existing medium `────` rule stays as the default for chokepoint cards (e.g., SETUP, FFmpeg fallback).
4. **Harvest card** at end of run: the existing `RunSummary` card framed with a heavy rule and augmented with a **per-task duration sparkline** rendered from `▁▂▃▄▅▆▇█`.
5. **`··· idle ···` handoff line** emitted once, after task-done and before the dandelion animation resumes, in `WorkerStatusDisplay`.

Because `TaskLifecycleEmitter.task()` is the single wrapper around every task execution (`source/task_handlers/queue/task_processor.py:134`, `source/runtime/worker/server.py:482`), changes there are automatic across all task types — no per-handler edits are needed. `RunSummary` is already emitted at all four run-end sites in `server.py` (`:464, :609, :613, :616`) and in `task_queue.py`, so the harvest card flows through those unchanged.

Constraints:
- `DebugCard.render()` output must stay byte-stable for the default (medium) rule so `test_lifecycle.py::test_lifecycle_debug_cards_include_display_summary_rows_first` and callers that pattern-match on `Task Start` / `Task Done` headers keep working. The heavy variant is opt-in via a new argument.
- `test_lifecycle.py` asserts exact anchor strings starting with `▶` / `✓` / `❌` — these tests must be updated to match the new bloom glyphs.
- Log interceptor routes through `core._format_message`; the new characters are plain Unicode, no ANSI required.

   def _sparkline(values: list[float]) -> str:
       if not values: return ""
       hi = max(values); lo = min(values)
       span = hi - lo or 1.0
       return "".join(_SPARK_BARS[min(len(_SPARK_BARS)-1, int((v-lo)/span * (len(_SPARK_BARS)-1)))] for v in values)
