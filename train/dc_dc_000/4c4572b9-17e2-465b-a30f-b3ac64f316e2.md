# Implementation Plan: User Actions in Finalize Phase

## Overview

Add a top-level `user_actions` array to the finalize artifact for human-only setup/operational steps (env vars, secrets, migrations, manual UI smoke tests, deploys, approvals). The boundary is enforced through five mutually reinforcing layers: (1) schema, (2) prompt inclusion criteria + mode gating, (3) coverage validation rename so user_actions count toward plan-step coverage, (4) synthetic gate tasks injected at head/tail of `tasks` (mirrors `_ensure_verification_task`), and (5) per-task PREREQUISITE block injected into the executor prompt for tasks named in `blocks_task_ids`. Artifacts: `final.md` gets a User Actions section, and a separate `user_actions.md` is always written (data-parity stub when empty).

Key files identified:
- `megaplan/schemas.py:277` — finalize.json schema (rename `finalize_task_ids` → `finalize_item_ids`, add `user_actions` array). Note `strict_schema()` at `:752` makes every declared property required unless the item carries `x-preserve-explicit-required: True` (precedent at `:309`).
- `megaplan/handlers/finalize.py:23` (`_reconcile_validation_after_mutation`), `:44` (`_validate_finalize_payload`), `:72` (`_ensure_verification_task` precedent), `:207` (`_write_finalize_artifacts`).
- `megaplan/prompts/finalize.py:79` — Requirements block; mode gate via `state["config"]["mode"]`.
- `megaplan/_core/io.py:54-99` — `compute_task_batches` (dependency-edge scheduler — list order only sorts within a ready batch).
- `megaplan/_core/io.py:132` — `render_final_md`; add User Actions section after Sense Checks.
- `megaplan/prompts/execute.py:262` — `_execute_batch_prompt`; inject PREREQUISITE block per actionable task.
- `tests/test_finalize.py` — extend with new test cases.

The synthetic T0 gate task is the only enforcement that converts a passive list into runtime behavior: it forces the executor to programmatically verify each `before_execute` user_action before any real work begins.

## Main Phase

### Step 1: Audit current finalize touch points
**Scope:** Small
1. **Confirm** schema location at `megaplan/schemas.py:277` and the `finalize_task_ids` field at `:337`.
2. **Confirm** the `x-preserve-explicit-required` precedent at `megaplan/schemas.py:309` and the `strict_schema()` enforcement at `:752`. This is what allows finalize task `items` to declare a custom `required` list that is narrower than `properties`. The new `user_actions.items` schema MUST carry the same marker — without it `strict_schema` overwrites `required` with every property key, forcing `requires_human_only_reason` on every entry.
3. **Confirm** the `_ensure_verification_task` precedent and `_reconcile_validation_after_mutation` flow in `megaplan/handlers/finalize.py:72` and `:23`. Note the appended-task pattern: build task object, recompute next `T{n}` ID, append a corresponding `SC{n}` sense check.
4. **Confirm** at `megaplan/_core/io.py:54-99` that `compute_task_batches` schedules by dependency edges (a task runs as soon as its `depends_on` set is satisfied) and only uses list order to sort *within* a ready batch. This means the post-execute tail task must depend on **all** terminal tasks, or else parallel branches can leave terminals unfinished when the tail runs.
5. **Confirm** that `_execute_batch_prompt` is the per-batch executor prompt builder at `megaplan/prompts/execute.py:262`, and that batch tasks are passed through `batch_tasks` (a list of full task dicts).

### Step 3: Update the finalize prompt (`megaplan/prompts/finalize.py`)
**Scope:** Medium
