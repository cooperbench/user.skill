1	# Review Pipeline
2	
3	Three stages for processing open PRs and issues. Each item gets its own file. Stages 1 and 2 write separate files so they can't corrupt each other. Stage 3 reads both and adjudicates.
4	
5	```
6	Stage 1: Assess              Stage 2: Challenge             Stage 3: Adjudicate + Execute
7	(parallel sub-agents)        (parallel sub-agents)          (sequential, one at a time)
8	
9	 PR #486 ─→ agent            ACCEPT? ─→ challenger          reads pr-486.json + pr-486.stage2.json
10	 Issue #490 ─→ agent         REJECT? ─→ advocate            reads _cross-item.json for duplicates/ordering
11	 PR #484 ─→ agent            ...                            ─→ forms own opinion from the diff/issue
12	 ...                               ↓                        ─→ weighs stage1 vs stage2
13	       ↓                     orchestrator writes             ─→ decides + executes
14	 each writes                 _cross-item.json               ─→ test ─→ commit ─→ comment ─→ close
15	 pr-486.json                 (duplicates, ordering)
16	```
17	
18	## Key design decisions
19	
20	- **Separate files per stage.** Stage 1 writes `pr-486.json`. Stage 2 writes `pr-486.stage2.json`. Neither can corrupt the other. Stage 3 reads both.
21	- **Symmetric scrutiny.** Accepts get a devil's advocate (default NO). Rejects get an angel's advocate (default YES). Every item gets challenged from the opposite direction.
22	- **Cross-item metadata.** Duplicates, ordering, and interactions are recorded in `_cross-item.json` by the Stage 2 orchestrator (after reading sub-agent outputs) — the only agent that sees all items at once.
23	- **Stage 3 verifies, not rubber-stamps.** Duplicate groupings from `_cross-item.json` are suggestions — Stage 3 checks them. Missing `.stage2.json` files block execution (partial Stage 2 runs won't slip through).
24	- **No comments until Stage 3.** Contributors see one message: the final decision.
25	- **No bias toward action.** The goal is making the codebase better, not clearing a queue.
26	
27	## Folder structure
28	
29	```
30	review/
31	  README.md                        ← you are here
32	  schema.json                      ← JSON schema for all result files
33	  validate.py                      ← run after each stage to catch errors
34	  prompts/

36	    1-review-agent.md              ← one agent per item: honest assessment
37	    2-challenge-orchestrator.md    ← spawns parallel sub-agents for Stage 2
38	    2-devils-advocate.md           ← challenges items Stage 1 accepted (default: NO)
39	    2-angels-advocate.md           ← advocates for items Stage 1 rejected (default: YES)
40	    3-decide-and-execute.md        ← reads both stages, adjudicates, implements, comments
41	  results/                         ← created at runtime, gitignored

45	    issue-490.stage2.json
46	    _cross-item.json               ← duplicate groups, ordering, interactions
47	    execution-log.json             ← Stage 3 record of what happened
48	```

50	## How to run
51	
52	Prerequisites:
53	- On the release branch, not main (`git branch --show-current`)
54	- Clean working tree (`git status`)

58	Each stage is a separate conversation. Pass the orchestrator/adjudicate prompt to a `general-purpose` agent:
