        # Implementation Plan: Multi-Select Timeline Clips

## Overview

The video editor timeline currently supports **single clip selection only** (`selectedClipId: string | null`). All editing operations (delete, split, mute, move, drag) target a single clip. This plan adds marquee box selection, Ctrl+Click toggle selection, visual multi-select highlighting, and batch operations (drag, delete, bulk settings edit).

**Key architectural facts:**
- State flows through `TimelineEditorContext` → consumed by `TimelineEditor`, `ClipAction`, `PropertiesPanel`, `VideoEditorShell`
- Selection state lives in `useTimelineData` (`selectedClipId`, `selectedClip`), but **selection pruning is owned by `commitData` in `useTimelineSave.ts:175-205`** — it checks `nextData.meta[selectedClipIdRef.current]` and nulls stale IDs on every commit. Multi-select must integrate here, not bolt on afterward.
- `applyTimelineEdit(nextRows)` already accepts full row arrays — batch mutations are mechanically simple
- **Drag event ownership**: `useClipDrag` registers document-level `pointerdown` (capture phase) on `.clip-action` elements and **unconditionally calls `setSelectedClipId(clipId)` on pointer-up** (`useClipDrag.ts:263,272`), even on plain clicks. Click selection is currently split between `useClipDrag` (pointer-up) and `ClipAction` (onClick). Multi-select must unify this in `useClipDrag`'s pointer-up handler rather than fighting it from `ClipAction.onClick`.
- **Drop position pipeline**: `drop-position.ts` never returns `isReject: true` — kind mismatches silently reroute to the nearest compatible track or create a new one (`drop-position.ts:114-168`). Multi-drag constraint enforcement must happen in `useClipDrag`, not `drop-position.ts`.
- **Overlap resolution**: `resolveOverlaps()` (`resolve-overlaps.ts:75-147`) is single-clip — it treats one "moved clip" as yielding to immovable siblings. Multi-drag needs a group-aware variant.
- Clip rendering is in `TimelineCanvas.tsx` (rows → actions → divs) and `ClipAction.tsx` (individual clip UI)

**Insertion strategy:** Introduce a new `useMultiSelect` hook that owns `selectedClipIds: Set<string>`. Wire it into the save layer's `commitData` for pruning. Modify `useClipDrag`'s pointer-up handler to be the single authority on click-selection (removing the conflict with `ClipAction.onClick`). `primaryClipId` (last-clicked) remains source of truth for PropertiesPanel single-clip editing.

## Phase 1: Selection State & Save-Layer Integration

### Step 1: Create `useMultiSelect` hook (`src/tools/video-editor/hooks/useMultiSelect.ts`)
**Scope:** Small
1. **Create** new hook managing `selectedClipIds: Set<string>` via `useState` and a `selectedClipIdsRef` (for non-stale access in event handlers).
2. **Expose** methods:
   - `selectClip(clipId, opts?: { toggle?: boolean })` — replaces selection, or toggles membership when `toggle: true`
   - `selectClips(clipIds: string[])` — replaces entire selection (for marquee)
   - `addToSelection(clipIds: string[])` — union
   - `clearSelection()` — empties set
   - `isClipSelected(clipId: string): boolean`
   - `selectedClipIds: ReadonlySet<string>`
   - `primaryClipId: string | null` — last explicitly clicked clip
   - `pruneSelection(validIds: Set<string>)` — removes any IDs not in `validIds`; called by save layer
3. **Derive** `primaryClipId` as the most recently clicked clip that is still in the set.

### Step 2: Integrate `useMultiSelect` with save layer (`useTimelineSave.ts`, `useTimelineState.ts`, `useTimelineState.types.ts`)
**Scope:** Medium — **addresses flag `multi-select-selection-sync`**
1. **Pass** `pruneSelection` into `useTimelineSave` (or into `commitData`'s closure).
2. **Replace** the existing selection-pruning block in `commitData` (`useTimelineSave.ts:187-193`): instead of checking a single `selectedClipIdRef`, call `pruneSelection(new Set(Object.keys(nextData.meta)))`. This ensures all stale clip IDs are removed from the multi-select set on every data commit — covering saves, reloads, splits, external refreshes, and realtime sync.
3. **Keep** `primaryClipId` pruning in sync: if `primaryClipId` is pruned out, fall back to the first remaining member of `selectedClipIds` or `null`.
4. **Replace** `selectedClipId` / `setSelectedClipId` in `commitData` options with `selectedClipIds?: string[]` to allow callers (like split, which selects the new clip) to set selection atomically during commit.
5. **Extend** `TimelineEditorContextValue` with: `selectedClipIds`, `isClipSelected`, `selectClip`, `selectClips`, `addToSelection`, `clearSelection`, `primaryClipId`.
6. **Wire** existing `selectedClipId` reads throughout the codebase to use `primaryClipId` (backward-compat alias). `setSelectedClipId` calls become `selectClip(id)`.
7. **Ensure** `selectedClip`, `selectedTrack`, `selectedClipHasPredecessor` continue to derive from `primaryClipId` so PropertiesPanel works unchanged.

### Step 3: Unify click-selection in `useClipDrag` pointer-up (`useClipDrag.ts`)
**Scope:** Medium — **addresses flag `multi-select-click-drag-conflict`**

The core problem: `useClipDrag` owns pointer-down/up on `.clip-action` at the document capture phase. On pointer-up (even with no drag), it calls `setSelectedClipId(session.clipId)` (`useClipDrag.ts:263,272`). Adding Ctrl+Click in `ClipAction.onClick` would create two competing selection paths.

**Solution:** Make `useClipDrag`'s pointer-up the **sole authority** on click-selection:
1. **Store** modifier keys (`metaKey`, `ctrlKey`) on the `DragSession` object at pointer-down time (`useClipDrag.ts:144`).
2. **In `handlePointerUp`** (`useClipDrag.ts:244-274`): when `!session.hasMoved` (click, not drag), check modifiers:
   - If `session.metaKey || session.ctrlKey`: call `selectClip(session.clipId, { toggle: true })`.
   - Else: call `selectClip(session.clipId)` (replaces selection).
3. **When `session.hasMoved`** (actual drag completed): call `selectClip(session.clipId)` after repositioning (selects just the dragged clip, or the anchor clip in multi-drag — see Step 9).
4. **Remove** any `onClick`-based selection logic from `ClipAction.tsx` — the click is handled by `useClipDrag`'s pointer-up path. `ClipAction` retains `onClick` only for non-selection concerns (e.g., double-click to edit, if any).
5. **Pass** the multi-select functions (`selectClip`, `selectedClipIdsRef`) to `useClipDrag` via its options interface, replacing the current `setSelectedClipId` / `setSelectedTrackId` params.

### Step 4: Update `ClipAction` visual highlighting (`ClipAction.tsx`)
**Scope:** Small
1. **Change** `isSelected` prop to use `isClipSelected(clipId)` from context.
2. **Add** `isPrimary` prop: `primaryClipId === clipId`.
3. **Style**: primary selected clip gets `border-sky-400`, other selected clips get `ring-2 ring-sky-300/60`.
4. **Remove** `onClick`-based selection (now in `useClipDrag` pointer-up — Step 3).

### Step 5: Update `TimelineEditor` and `VideoEditorShell` wiring (`TimelineEditor.tsx`, `VideoEditorShell.tsx`)
**Scope:** Small
1. **Wire** `clearSelection` to background click on empty timeline area.
2. **Update** `useKeyboardShortcuts` call: `hasSelectedClip` becomes `selectedClipIds.size > 0`.
3. **Update** `deleteSelectedClip` callback to use batch delete (see Step 8).

## Phase 3: Batch Operations

### Step 8: Batch delete (`useClipEditing.ts`, `useKeyboardShortcuts.ts`)
**Scope:** Small
1. **Add** `handleDeleteClips(clipIds: string[])` to `useClipEditing` — filters all matching clip IDs from all rows in one pass, deletes their meta entries.
2. **Refactor** `handleDeleteClip` to delegate to `handleDeleteClips([clipId])`.
3. **Update** keyboard shortcut: Delete/Backspace calls `handleDeleteClips([...selectedClipIds])`.
4. **Selection after delete**: `commitData` pruning (Step 2) automatically clears deleted IDs from multi-select.

### Step 9: Multi-clip drag (`useClipDrag.ts`, `snap-edges.ts`, `resolve-overlaps.ts`)
**Scope:** Large — **addresses flags `multi-select-drop-targeting` and `multi-select-overlap-resolution`**

This is the most complex step. The approach treats the dragged group as a rigid block.

**9a. Extend DragSession and drag-start logic (`useClipDrag.ts:144-176`):**
1. **Add** to `DragSession`: `draggedClipIds: string[]`, `clipOffsets: Array<{ clipId: string; rowId: string; deltaTime: number }>`.
2. **On pointer-down**: if the initiating clip is in `selectedClipIds`, populate `draggedClipIds` from the set and compute `clipOffsets` (each clip's `start` minus the anchor clip's `start`). If not in selection, set `draggedClipIds = [clipId]` (single drag, implicitly deselects on pointer-up).

**9b. Enforce same-track-only constraint in `useClipDrag`, NOT in `drop-position.ts` (addresses `multi-select-drop-targeting`):**
1. **During multi-clip drag** (`draggedClipIds.length > 1`): skip cross-track activation entirely — ignore the vertical threshold check (`useClipDrag.ts:229`). The drag remains horizontal-only.
2. **Do not modify `drop-position.ts`** — it continues to operate on single-clip semantics. For multi-drag, `useClipDrag` computes the anchor clip's new start time directly from pointer delta + snapping, bypassing the coordinator's drop-position pipeline for track targeting.
3. **Visual feedback**: keep the existing single ghost for the anchor clip. Add a count badge on the ghost showing "N clips" to indicate batch drag.

**9c. Update snap logic (`snap-edges.ts`):**
1. **Extend** `snapDrag` signature to accept `excludeClipIds: string[]` (default `[clipId]` for backward compat).
2. **During multi-drag**: pass all `draggedClipIds` as excluded IDs so dragged clips don't snap to each other.

**9d. Group-aware overlap resolution (`resolve-overlaps.ts`) — addresses `multi-select-overlap-resolution`:**
1. **Add** `resolveGroupOverlaps(rows, movedClips: Array<{rowId, clipId, newStart, newEnd}>, meta)` — a new export.
2. **Algorithm**: for each affected row, treat ALL moved clips on that row as a rigid group. Siblings = actions NOT in the moved set. Find gaps large enough for the group's total span. If the group fits at the requested position, use it. If not, slide the group to the nearest valid position (like `findBestGap` but for a group footprint). If no valid position exists, reject the move (return rows unchanged).
3. **Key invariant**: relative spacing between dragged clips on the same row is preserved — they move as a unit.
4. **Clips spanning multiple rows**: each row's subset is resolved independently (they share the same time delta but different sibling sets).

**9e. Wire drop logic in `handlePointerUp`:**
1. **Single drag** (`draggedClipIds.length === 1`): existing behavior unchanged — `moveClipToRow`, `resolveOverlaps`.
2. **Multi-drag**: compute `timeDelta = anchorSnappedStart - anchorInitialStart`. For each clip in `clipOffsets`, compute `newStart = clip.initialStart + timeDelta`. Build updated rows with all clips repositioned. Call `resolveGroupOverlaps`. Apply via `applyTimelineEdit`.
3. **After drop**: select all dragged clips (keep multi-selection intact).

### Step 10: Bulk mute toggle (`useClipEditing.ts`)
**Scope:** Small
1. **Add** `handleToggleMuteClips(clipIds: string[])` — toggles mute for all specified clips via batch meta update.
2. **Wire** M shortcut to operate on `[...selectedClipIds]`.

### Step 11: Bulk settings panel (`PropertiesPanel`)
**Scope:** Medium

2. **Show** shared editable fields: opacity, speed, mute. For fields where values differ across selected clips, show a "mixed" placeholder.
3. **On change**: apply the setting to all selected clips via batch `applyTimelineEdit` with `metaUpdates` for all selected IDs.
4. **When** `selectedClipIds.size === 1`, keep existing single-clip PropertiesPanel behavior unchanged.
