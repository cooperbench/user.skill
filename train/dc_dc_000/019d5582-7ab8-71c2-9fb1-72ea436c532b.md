        # Implementation Plan: Gallery Media Selection for Timeline Agent Context

## Overview

The video editor has a working multi-select system for timeline clips (`useMultiSelect` → `selectedClipIds` → `useSelectedMediaClips` → AgentChat attachments). We need to extend this so gallery items (in the GenerationsPane) can also be selected and attached to agent messages.

**Current flow:** Timeline clip click → `useMultiSelect` → `TimelineEditorContext.selectedClipIds` → `useSelectedMediaClips` resolves clip IDs to `{url, mediaType}` via `resolvedConfig.clips/registry` → AgentChat reads `useSelectedMediaClips()` → sends as `selected_clips` to agent.

**Key insight:** `useMultiSelect` is a generic Set-of-IDs manager — it doesn't care what the IDs represent. `useSelectedMediaClips` is the clip-specific resolver that looks up URLs from `resolvedConfig`. The simplest approach is to add a parallel gallery selection state and a parallel resolver hook, then merge both sources in AgentChat.

Gallery items are `GeneratedImageWithMetadata` objects with `id`, `url`, and `type`/`isVideo` fields — they already have the URL and media type info, so resolving is trivial compared to timeline clips.

## Phase 1: Gallery Selection State

### Step 1: Create `useGallerySelection` hook (`src/tools/video-editor/hooks/useGallerySelection.ts`)
**Scope:** Small
1. **Create** a new context + hook that manages gallery selection state using a `Set<string>` of generation IDs, mirroring `useMultiSelect`'s interface but simplified.
2. **Store** a map of `id → { url, mediaType }` alongside the Set so we can resolve selections without a separate lookup step (gallery items carry their own URLs, unlike timeline clips which need registry lookup).
3. **Expose:** `selectedGalleryIds: ReadonlySet<string>`, `selectGalleryItem(id, meta, opts?: { toggle })`, `clearGallerySelection()`, `selectedGalleryClips: SelectedMediaClip[]`, `gallerySummary: string`.
4. **Reuse** the `SelectedMediaClip` type and `buildSummary` helper from `useSelectedMediaClips.ts` — export `buildSummary` so both hooks can share it.
5. **Filter:** Only allow selection of images and videos (check `type`/`isVideo` field). Skip effects/music.

### Step 2: Create `GallerySelectionProvider` and wire into video editor tree (`src/tools/video-editor/contexts/`)
**Scope:** Small
1. **Create** `GallerySelectionContext` with provider component.
2. **Mount** the provider in the video editor component tree (in `VideoEditorShell.tsx` or equivalent), wrapping the area that contains both GenerationsPane and AgentChat.
3. **Ensure** the provider is a sibling/ancestor to both the gallery pane and the agent chat panel so both can consume the context.

## Phase 2: Gallery Click Handling

### Step 3: Wire selection into `GenerationsPaneGallery` (`src/features/gallery/components/GenerationsPane/components/GenerationsPaneGallery.tsx`)
**Scope:** Medium
1. **Pass** `onImageClick` callback to `MediaGallery` — this is the existing prop that fires on single-click when `enableSingleClick: true`.
2. **Set** `config.enableSingleClick: true` on the MediaGallery in GenerationsPaneGallery (this switches click behavior from "open lightbox" to "call onImageClick").
3. **In the `onImageClick` handler:** Read `event.metaKey` (Cmd) to decide between replace-selection and toggle-selection. Since `onImageClick` receives `(image: GeneratedImageWithMetadata)` without the event, we need a small adjustment — either:
   - (a) Add a keyboard modifier state tracker (simpler: use a ref that tracks current metaKey state via a `keydown`/`keyup` listener), or
   - (b) Extend `onImageClick` signature to pass the event through. This touches shared code but is cleaner.
   - **Preferred: (a)** — a `useModifierKeys()` hook that tracks metaKey state, consumed in the GenerationsPane click handler. Avoids touching the shared MediaGalleryItem interface.
4. **Call** `selectGalleryItem(image.id, { url: image.url, mediaType }, { toggle: metaKeyDown })`.

### Step 4: Visual selection highlighting on gallery items (`src/shared/components/MediaGalleryItem.tsx`)
**Scope:** Small
1. **Add** an `isSelected?: boolean` prop to `MediaGalleryItemProps`.
2. **Apply** a selection ring/border when `isSelected` is true — use a style similar to timeline clip selection (e.g., `ring-2 ring-sky-400` or `border-2 border-sky-400`).
3. **Pass** `isSelected` from `MediaGalleryGrid` → `MediaGalleryItem` by checking if the item's ID is in the gallery selection set.
4. **The selection set** should be passed into MediaGallery via a new `selectedIds?: ReadonlySet<string>` prop (keep it generic — the shared component doesn't need to know about the agent system).

## Phase 3: Agent Chat Integration

### Step 5: Merge gallery selections into AgentChat (`src/tools/video-editor/components/AgentChat/AgentChat.tsx`)
**Scope:** Medium
1. **Import** `useGallerySelection` in AgentChat alongside the existing `useSelectedMediaClips`.
2. **Merge** the two sources: combine `clips` from `useSelectedMediaClips()` with `selectedGalleryClips` from `useGallerySelection()`. Deduplicate by URL if needed (a gallery item could also be on the timeline).
3. **Build** a combined summary string using the shared `buildSummary` helper.
4. **Update** the summary display (line 384-387) and the `attachments` construction (line 208-212) to use the merged list.
5. **The rest of the pipeline is unchanged** — `useSendMessage` already accepts any `attachments` array and sends it as `selected_clips` to the edge function.

### Step 6: Clear gallery selection after send
**Scope:** Small
1. **After** a successful `sendMessage.mutateAsync()` call in `handleSend`, call `clearGallerySelection()` so the selection doesn't persist across messages.
2. **Timeline clip selection** already handles its own clearing behavior — don't change that.

## Phase 4: Edge Cases & Polish

### Step 7: Mutual exclusivity decision
**Scope:** Small
1. **Decide** whether timeline selection and gallery selection are mutually exclusive or additive. **Recommendation: additive** — user can select clips on timeline AND items in gallery, and all get attached. This is simpler (no cross-clearing logic) and more powerful.
2. **If mutually exclusive is desired later**, add a `clearGallerySelection()` call in `useMultiSelect.selectClip()` and vice versa.

### Step 8: Lightbox access preservation
**Scope:** Small
1. **Since `enableSingleClick: true` hijacks single-click from lightbox**, ensure users can still open lightbox via double-click or an explicit button. The existing `onOpenLightbox` callback should still work via the image's action buttons.
2. **Verify** that the existing "eye" or "expand" button on gallery items still opens the lightbox when `enableSingleClick` is enabled.

## Execution Order
1. Step 1-2 (selection state) — foundation, no UI changes yet
2. Step 3-4 (click handling + visual) — gallery becomes interactive
3. Step 5-6 (agent chat integration) — selections flow to agent
4. Step 7-8 (polish) — edge cases

## Validation Order

2. Manual: Cmd+click multiple items, verify multi-select works
3. Manual: verify "attaching N images" shows in agent chat input bar
4. Manual: send a message with gallery selections, verify `selected_clips` payload includes gallery items
5. Manual: verify lightbox still accessible via double-click or button
6. Run existing tests: `useSelectedMediaClips`, `useItemInteraction`, `useMediaGalleryViewInteractions` tests should still pass
