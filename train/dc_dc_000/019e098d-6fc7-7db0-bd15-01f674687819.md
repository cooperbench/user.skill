        # Implementation Plan: Capability Contracts and Workflow Workbench Reporting

## Overview
Build a worker-local capability-contract source of truth and report loop that separates product capabilities from task types, route keys, VibeComfy template bindings, live cases, and artifact expectations. The repo already has the raw ingredients: route decisions in `source/task_handlers/tasks/template_routing.py`, live matrix definitions in `scripts/live_test/matrix.py`, live report JSON/Markdown under `scripts/live_test/runs/`, VibeComfy subprocess boundaries in `source/models/comfy/vibecomfy_adapter.py`, and worker preflight checks for `../vibecomfy/template_index.json` plus `../vibecomfy/workflow_corpus/manifests/coverage.json`.

The simplest useful first slice is not a UI workbench. It is a durable registry plus a validator/report generator that can answer: which app capability maps to which route, which VibeComfy template or WGP-only path implements it, which variant axes are covered or fail-closed, which live case proves it, and what blocks parity. This creates real leverage for future import/fork/scratch workflow tooling without duplicating VibeComfy’s graph validators.

## Phase 1: Foundation — Contract Data and Importable Helpers

### Step 1: Add the contract package (`scripts/capability_contracts/`)
**Scope:** Medium
1. **Create** `scripts/capability_contracts/__init__.py`, `scripts/capability_contracts/model.py`, `scripts/capability_contracts/loaders.py`, and `scripts/capability_contracts/report.py`.
2. **Use only stdlib** (`json`, `dataclasses`, `argparse`, `pathlib`) so the tool remains cheap in CI and live-test environments.
3. **Model** the status vocabulary as constants: `unknown`, `inventoried`, `routed`, `template_bound`, `static_valid`, `runtime_green`, `parity_reviewed`, `app_ready`, `wgp_only_contract_validated`, `unsupported_fail_closed`.
4. **Keep VibeComfy validation as evidence consumption**, not reimplementation: load `template_index.json` and `workflow_corpus/manifests/coverage.json`; optionally expose command hints such as `python -m vibecomfy.cli validate <template>` but do not inspect workflow graph internals in worker.

### Step 2: Add the machine-readable registry (`scripts/capability_contracts/contracts.json`)
**Scope:** Large
1. **Define** one contract row per product capability or justified exception, with fields like:
   ```json
   {
     "capability_id": "video.travel_segment.wan22_vace.video_source.flow",
     "name": "Travel segment, Wan 2.2 VACE flow, video source continuity",

     "artifact_contract": {"kind": "video", "extensions": [".mp4", ".webm"], "storage_class": "intermediate", "generation_row": "required"},
     "app_sources": [{"path": "../reigh-app/supabase/functions/create-task", "note": "resolver/enqueue surface"}],
     "live_cases": ["travel_segment_wan22_vace_flow_video_source"],
   ```

        # Implementation Plan: Capability Contracts and App-Parity Reporting

## Overview
Build a worker-local capability-contract source of truth and report loop that separates product capabilities from task types, route keys, VibeComfy template bindings, live cases, app enqueue surfaces, and artifact expectations. The root approach is still correct: the problem is not missing VibeComfy graph validation, it is missing worker-owned product/app parity accounting across routing, app task creation, variant axes, artifact semantics, and live evidence. The gate flags do not point to a different root cause; they show the first plan was too weak on three execution details: structured app inventory, import-safe live matrix evidence, and alias/duplicate route handling.

The revised first slice remains bounded and executable. It adds a worker-local registry and report CLI, a lightweight app capability inventory from selected `../reigh-app` enqueue/resolver surfaces, an import-safe live matrix manifest consumed by the report tool, drift tests that can use heavier imports in pytest, generated tracker docs, and discoverability notes. It still does not duplicate VibeComfy workflow validators: worker code consumes VibeComfy `template_index.json`, `workflow_corpus/manifests/coverage.json`, and command hints, while VibeComfy remains the owner of template/workflow mechanics.

**Scope:** Medium
