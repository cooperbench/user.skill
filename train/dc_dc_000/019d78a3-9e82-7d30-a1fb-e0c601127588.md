        # Implementation Plan: Structured Chokepoint-Based DEBUG Logging

## Overview

The codebase has ~1,475 `debug()` calls across 105 files. Current DEBUG output is flat: consecutive per-field dumps (e.g., 11-line phase_config loops), normal-path confirmations ("Model loaded", "Guide video created"), and ad-hoc `[SECTION_NAME]` bracket tags with no consistent structure. The goal is to replace this with chokepoint-based blocks — compact header-delimited summaries at pipeline stage boundaries — and silence normal-path plumbing between chokepoints.

**Current state:**
- `ComponentLogger.debug()` is the only debug method (`source/core/log/core.py:198`)
- `source/core/log/safe.py` provides `safe_dict_repr()`, `safe_json_repr()` but no block abstraction
- `source/core/log/tasks.py` has utility helpers (`log_task_start`, `log_generation_params`) but no stage/block concept
- Ad-hoc `[TAG]` prefixes exist everywhere but are inconsistent and mixed with multi-line dumps

**Design approach:**
Add a `debug_block(stage, items)` method to `ComponentLogger` that prints a compact header + key-value summary in 1-3 lines. Use it at defined chokepoints per task type. Delete or silence normal-path plumbing logs between chokepoints.

**Canonical chokepoints** (not all apply to every task type):
1. `SETUP` — task received, key identifiers
2. `PARAMS` — parameter resolution result
3. `VLM` — VLM prompt enhancement result
4. `GUIDE` — guide/mask video construction
5. `MODEL` — model loading/switching
6. `GENERATE` — generation launch summary
7. `OUTPUT` — post-processing, output path, duration

## Phase 1: Core Infrastructure — Add `debug_block` to ComponentLogger

### Step 1: Add `debug_block` method to ComponentLogger (`source/core/log/core.py`)
**Scope:** Small
1. **Add** a `debug_block(stage, items, task_id=None)` method to `ComponentLogger` (after line 205) that:
   - Takes a `stage` string (e.g. `"PARAMS"`) and `items` dict of key-value pairs
   - Formats as: `──── STAGE ──── key1=val1 | key2=val2 | key3=val3`
   - If the items line exceeds ~120 chars, wraps to a second line with 4-space indent
   - Uses `safe_repr()` from `source/core/log/safe.py` for each value
   - Only prints when `_debug_mode` is True (same gate as `debug()`)
   - Also sends to interceptor via `_intercept_log`
2. **Add** a `debug_anomaly(stage, message, task_id=None)` method that logs between chokepoints ONLY when something unexpected happens (non-default path taken, fallback triggered, value overridden). Format: `  ⚡ STAGE: message` (indented to visually nest under the preceding block).
3. **Export** `debug_block` in `__all__` and update the interceptor-wrapped `debug` function section to also wrap `debug_block`.
4. **Update** the redefined ComponentLogger instances at lines 212-218 — no change needed since they're instances of the same class.
