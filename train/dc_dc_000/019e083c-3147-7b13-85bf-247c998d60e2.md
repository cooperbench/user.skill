7. **Clone child segment generations** where `parent_generation_id` points to a cloned parent video. Preserve `child_order`, `is_child`, locations, thumbnails, remapped params, tasks, names, starred state, and other relevant fields. Set `based_on` to the source segment generation ID and remap `parent_generation_id` to the cloned parent generation.
8. **Remap typed relationship fields** after inserts:
   - `parent_generation_id`: old parent video ID -> cloned parent video ID.
   - `pair_shot_generation_id`: old source image slot ID -> cloned image slot ID.
   - `children`: rewrite old child generation IDs to cloned child generation IDs if this JSON stores IDs.
9. **Implement a focused recursive SQL JSONB params remap helper** inside the migration, or equivalent local logic, and use it for every cloned parent/segment `generations.params` value and every cloned parent/segment `generation_variants.params` value before insertion. The helper should walk JSON objects and arrays and rewrite values for known relationship key names wherever they occur in nested objects:
   - `shot_id`: source shot ID -> cloned shot ID.
   - `parent_generation_id`: source parent/final video generation ID -> cloned parent/final video generation ID, and source child segment generation IDs -> cloned child segment generation IDs when present in the generation map.
   - `child_generation_id`: source child segment generation ID -> cloned child segment generation ID.
   - `pair_shot_generation_id`: source `shot_generations.id` -> cloned `shot_generations.id`.
   - `pair_shot_generation_ids`: array values source `shot_generations.id` -> cloned `shot_generations.id`.
10. **Preserve shared image generation arrays intentionally.** For keys such as `input_image_generation_ids`, keep source image generation IDs unchanged because image generation rows are shared. Only rewrite a value in those arrays if it is present in the cloned video/segment generation map.
11. **Apply the same remap contract to variants.** When cloning `generation_variants`, pass `generation_variants.params` through the same recursive helper before insert. This prevents primary-variant sync triggers from copying source shot/parent/pair/child IDs back into `generations.params`.
12. **Clone variants** for each cloned parent/segment generation, preserving `location`, `thumbnail_url`, remapped `params`, `variant_type`, `name`, primary status, and semantic ordering. Then set each cloned generation’s `primary_variant_id` to the cloned counterpart of its source primary variant.
13. **Account for primary-variant sync triggers.** Because primary variant inserts/updates can sync params back to `generations.params`, either insert cloned primary variants with already-remapped params from the start or perform a final post-clone update that leaves both `generations.params` and the cloned primary variant’s `params` remapped and consistent.
14. **Cover legacy and nested relationship surfaces with the recursive helper and fixtures.** The helper must handle relationship keys under examples like root params, `orchestrator_details`, `originalParams.orchestrator_details`, `individual_segment_params`, `orchestration_contract`, and `full_orchestrator_payload` without requiring separate bespoke `jsonb_set` calls for every path.
15. **Do not copy storage objects.** Reuse `location` and `thumbnail_url` values while ensuring videos, segments, and variants have new database IDs where required.
