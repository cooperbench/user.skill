        # Implementation Plan: Tier-Based Critique Check Filtering

## Overview

The critique system currently runs all 8 `CritiqueCheckSpec` checks at every robustness level. The only differentiation is a softer instruction tone for `light`. This change makes robustness structurally meaningful: `heavy` gets all 8 checks, `standard` gets 4 core checks, and `light` skips structured checks entirely (general review via `flags` array only, with `checks: []`).

**Key files:** `megaplan/checks.py` (registry + filtering), `megaplan/prompts/critique.py` (prompt rendering), `megaplan/handlers.py` (validation call site), `megaplan/workers.py` (mock payload builder).

**Constraint:** Single code path, single data source — `CRITIQUE_CHECKS` remains the source of truth; robustness just filters it.

**Settled decisions (from gate):**
- Core tier: `issue_hints`, `correctness`, `scope`, `verification` (4 checks). Extended: `all_locations`, `callers`, `conventions`, `criteria_quality`.
- Light mode emits `checks: []` (empty list), not omitting the field. Schema stays unchanged.

## Main Phase

### Step 1: Add `tier` field and filtering function (`megaplan/checks.py`)
**Scope:** Small

1. **Add** `tier: str` to the `CritiqueCheckSpec` TypedDict (`checks.py:11-16`). Valid values: `"core"` or `"extended"`.
2. **Tag** each of the 8 checks in `CRITIQUE_CHECKS` (`checks.py:19-109`):
   - **Core** (4): `issue_hints`, `correctness`, `scope`, `verification`
   - **Extended** (4): `all_locations`, `callers`, `conventions`, `criteria_quality`
3. **Add** `checks_for_robustness()`:
   ```python
   def checks_for_robustness(robustness: str) -> tuple[CritiqueCheckSpec, ...]:
       if robustness == "heavy":
           return CRITIQUE_CHECKS
       if robustness == "standard":
           return tuple(c for c in CRITIQUE_CHECKS if c["tier"] == "core")
       return ()  # light
   ```
4. **Update** `build_empty_template()` (`checks.py:126-134`) to accept an optional `checks` parameter defaulting to `CRITIQUE_CHECKS`:
   ```python
   def build_empty_template(checks: tuple[CritiqueCheckSpec, ...] | None = None) -> list[dict[str, Any]]:
       source = checks if checks is not None else CRITIQUE_CHECKS
       return [{"id": c["id"], "question": c["question"], "findings": []} for c in source]
   ```
5. **Update** `validate_critique_checks()` (`checks.py:152-193`) to accept an optional `expected_ids: list[str] | None` parameter. When provided, use that list instead of `get_check_ids()`. **When `expected_ids` is empty** (light mode), enforce that the `checks` array in the payload is also empty — if it contains any entries, return those IDs as invalid. This prevents stray checks from leaking into `update_flags_after_critique()`.
   ```python
   def validate_critique_checks(payload: Any, *, expected_ids: list[str] | None = None) -> list[str]:
       raw_checks = payload.get("checks") if isinstance(payload, dict) else payload
       if not isinstance(raw_checks, list):
           return expected_ids if expected_ids is not None else get_check_ids()
       if expected_ids is not None and not expected_ids:
           # Light mode: checks must be empty
           return [rc.get("id", "?") for rc in raw_checks if isinstance(rc, dict)] if raw_checks else []
       # ... rest uses expected_ids or get_check_ids() as before
   ```
6. **Update** `__all__` to export `checks_for_robustness`.
