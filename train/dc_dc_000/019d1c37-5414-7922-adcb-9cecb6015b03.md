        # Implementation Plan: Interactive Timeline Editing in Remotion Studio

## Overview

The Remotion project at `remotion/` has a read-only `Timeline` composition that fetches `timeline.json` + `asset-registry.json` via static files and renders video/audio/overlay tracks. There is **no write path** from the browser back to disk — `setup-public.sh` **copies** (not symlinks) the JSON files into `public/`, and `load-config.ts` only reads.

The legacy `viewer/` (Vite + `@xzdarcy/react-timeline-editor`) already solves drag/trim/save for YAML, including a full API server in `vite.config.ts` with `POST /api/save-timeline`. That architecture is the reference but targets `timeline.yaml`, not `timeline.json`.

**Constraints:**
1. All edits write to the **root** `timeline.json` (shared with Python tools).
2. UI runs inside Remotion Studio (`npx remotion studio`).
3. Keep it simple — basic NLE controls, not a full editor.
4. Remotion Studio is not designed for custom panels; we must inject UI via an overlay component rendered inside the composition or a separate floating panel using a React portal.

**Key architectural challenge:** Remotion Studio serves static files from `public/` but has no built-in write API. We need a sidecar server or Remotion Studio middleware to write `timeline.json` back to disk.

---

## Phase 1: Write Path (Backend)

### Step 1: Sidecar API server for timeline persistence
**Scope:** Medium  
**Files:** `remotion/server.mjs` (new), `remotion/package.json`

Remotion Studio doesn't expose middleware hooks. The simplest approach is a lightweight sidecar Express/Hono server on a separate port (e.g., 3111) that the browser UI calls.

1. **Create** `remotion/server.mjs` — a minimal Node.js server with two endpoints:
   - `GET /api/timeline` → reads and returns `../timeline.json`
   - `POST /api/timeline` → writes request body to `../timeline.json`, then copies to `public/timeline.json` so Remotion's static server picks up the change on next poll
   - CORS headers allowing Remotion Studio origin
2. **Add** a `"server"` script to `package.json`: `node server.mjs`
3. **Update** `"dev"` script to launch both: `npm run setup-public && concurrently \"npx remotion studio\" \"node server.mjs\"` (add `concurrently` as a dev dependency, or use a simple `&` background approach in a shell script)
4. **Validate:** Start the server, POST a modified timeline, confirm `timeline.json` on disk updates and Remotion Studio's 1.5s poll picks up the change.

### Step 2: Client-side save utility
**Scope:** Small  
**Files:** `remotion/src/save-config.ts` (new)

1. **Create** `remotion/src/save-config.ts` exporting:
   ```typescript
   export const saveTimeline = async (config: TimelineConfig): Promise<void> => {
     await fetch("http://localhost:3111/api/timeline", {
       method: "POST",
       headers: { "Content-Type": "application/json" },
       body: JSON.stringify(config, null, 2),
     });
   };
   ```
2. **Add** a debounced wrapper (300ms) so rapid drag events don't spam writes.
3. **Validate:** Import in Timeline.tsx temporarily, trigger a save, confirm disk file updates.

## Phase 2: Editing UI Shell

### Step 3: Editor overlay component
**Scope:** Medium  
**Files:** `remotion/src/timeline/EditorOverlay.tsx` (new), `remotion/src/timeline/Timeline.tsx`

Remotion compositions render inside an `<AbsoluteFill>`. We add a transparent overlay on top that captures editing interactions and renders controls. This overlay is only active in Studio (detected via `typeof window !== 'undefined'` + not in render mode).

1. **Create** `EditorOverlay.tsx`:

   - Renders a floating toolbar (bottom of viewport) with: track labels, clip bars, and action buttons

   - Maintains local editing state; calls `onConfigChange` which triggers debounced save

   - Only render the overlay when `process.env.NODE_ENV !== 'production'` (skip during render)

## Phase 3: The Five Editing Features

### Step 5: DRAG — reposition clips on the timeline
**Scope:** Medium  
**Files:** `remotion/src/timeline/EditorOverlay.tsx`

1. **Implement** horizontal drag on clip bars in the overlay:
   - `onPointerDown` → capture initial `clip.at` and pointer X
   - `onPointerMove` → compute delta in seconds from pixel delta (using timeline scale)
   - `onPointerUp` → commit new `clip.at`, trigger save
2. **Snap** to 0.1s increments (shift key for frame-level precision)
3. **Validate:** Drag a clip, release, confirm `timeline.json` updated `at` value. Preview reflects new position after 1.5s reload.

### Step 6: CROP/TRIM — adjust clip start and end
**Scope:** Medium  
**Files:** `remotion/src/timeline/EditorOverlay.tsx`

1. **Add** left/right resize handles on clip bars:
   - Left handle: adjusts `clip.from` (source start) and `clip.at` (keeps playback position correct)
   - Right handle: adjusts `clip.to` (source end)
2. **Clamp** values: `from >= 0`, `to <= asset duration` (from `assetEntry.duration`), `from < to`
3. **Validate:** Trim a clip, confirm `from`/`to` in `timeline.json`, preview shows trimmed result.

### Step 7: SPEED control
**Scope:** Small  
**Files:** `remotion/src/timeline/ClipPanel.tsx`

1. **Add** a speed slider/input to the clip panel (range 0.25–4.0, step 0.25, default 1)
2. **On change:** update `clip.speed`, save. The clip bar width in the overlay should reflect the speed-adjusted duration (`(to - from) / speed`).
3. **Validate:** Change speed to 2x, confirm `speed` in JSON, clip plays at double speed in preview.

### Step 8: SPLIT clip at playhead
**Scope:** Medium  
**Files:** `remotion/src/timeline/EditorOverlay.tsx`, `remotion/src/timeline/ClipPanel.tsx`

1. **Add** a "Split" button in the clip panel (enabled when playhead is within selected clip)
2. **On click:**
   - Calculate split point in source time: `splitSource = clip.from + (playheadSeconds - clip.at) * clip.speed`
   - Create two clips:
     - Clip A: same `id`, same `at`, `from` unchanged, `to = splitSource`
     - Clip B: new `id` (e.g., `{originalId}-b`), `at = playheadSeconds`, `from = splitSource`, `to = originalTo`
     - Both inherit `speed`, `volume`, `track`, `asset`, overlay position
   - Replace original clip with the two new clips in `config.clips`
   - Save
3. **Validate:** Split a clip, confirm two clips in `timeline.json`, preview shows seamless playback at the split point.

### Step 9: MUTE toggle
**Scope:** Small  
**Files:** `remotion/src/timeline/ClipPanel.tsx`

1. **Add** a mute toggle button in the clip panel
2. **On click:** set `clip.volume = 0` if currently > 0, or `clip.volume = 1` if currently 0
3. **Visual indicator:** muted clips show a muted icon on their bar in the overlay
4. **Validate:** Mute an audio clip, confirm `volume: 0` in JSON, no audio in preview.

        # Implementation Plan: Interactive Timeline Editing in Remotion Studio

## Overview

The Remotion project at `remotion/` has a read-only `Timeline` composition that fetches `timeline.json` + `asset-registry.json` via static files and renders video/audio/overlay tracks. There is **no write path** from the browser back to disk — `setup-public.sh` copies the JSON files into `public/`, and `load-config.ts` only reads.

The composition uses a `ResolvedTimelineConfig` type (`load-config.ts:61`) that enriches clips with `assetEntry` data and adds a top-level `registry` — these are runtime-only fields that must be stripped before writing back to `timeline.json`.

**Constraints:**
1. All edits write to the **root** `timeline.json` (shared with Python tools).
2. UI runs inside Remotion Studio (`npx remotion studio`).
3. Keep it simple — basic NLE controls, not a full editor.
4. Remotion Studio has no built-in write API — a sidecar server is needed.
5. Overlay clips may use `hold` (static duration) instead of `from`/`to` — editing features must handle both semantics.

**Clip duration semantics:** Clips use either `from`/`to` (media range) or `hold` (static display duration). `getClipSourceDuration` in `load-config.ts:148` already handles this. Trim and split operations apply only to `from`/`to` clips; for `hold` clips, trim adjusts `hold` directly and split divides `hold` into two portions.

## Step 1: Sidecar API server for timeline persistence

**Scope:** Medium  
**Files:** `remotion/server.mjs` (new), `remotion/package.json`

1. **Create** `remotion/server.mjs` — a minimal Node.js HTTP server (no framework, use `node:http`) with two endpoints:
   - `GET /api/timeline` → reads and returns `../timeline.json`
   - `POST /api/timeline` → validates the body has `output` and `clips` keys (basic schema check), writes to `../timeline.json`, then copies to `public/timeline.json`
   - CORS headers allowing `http://localhost:3000` (Remotion Studio default)
2. **Add** a `"server"` script to `package.json`: `node server.mjs`
3. **Update** `"dev"` script: `npm run setup-public && node server.mjs & npx remotion studio` (background the sidecar with `&`, no extra dependency needed)
4. **Validate:** Start the server, POST a modified timeline, confirm `../timeline.json` on disk updates and Remotion Studio's 1.5s poll picks up the change.

## Step 2: Client-side save utility with serializer

**Scope:** Small  
**Files:** `remotion/src/save-config.ts` (new)

The key challenge here is that the component state is `ResolvedTimelineConfig` (with `assetEntry` on each clip and a top-level `registry`), but `timeline.json` stores bare `TimelineConfig` (just `output` + `clips` with no resolved asset data). We must strip the resolved fields before saving.

1. **Create** `remotion/src/save-config.ts` exporting:
   - `serializeForDisk(resolved: ResolvedTimelineConfig): TimelineConfig` — strips `assetEntry` from each clip and removes the top-level `registry`, returning a clean `{ output, clips }` object. For each clip, only the properties defined in `TimelineClip` (`load-config.ts:10-26`) are kept: `id`, `at`, `track`, `asset`, `from`, `to`, `speed`, `hold`, `volume`, `x`, `y`, `width`, `height`, `opacity`, `effects`.
   - `saveTimeline(config: ResolvedTimelineConfig): Promise<void>` — calls `serializeForDisk`, then POSTs to `http://localhost:3111/api/timeline`.
   - A debounced wrapper (300ms) so rapid drag events don't spam writes.
2. **Validate:** Import in Timeline.tsx temporarily, serialize the current config, confirm the output matches the shape in `timeline.json` exactly (no `assetEntry`, no `registry`, no `src`). POST it and confirm disk file round-trips correctly.

## Step 3: Editor overlay component

**Scope:** Medium  
**Files:** `remotion/src/timeline/EditorOverlay.tsx` (new), `remotion/src/timeline/Timeline.tsx`

Remotion compositions render inside an `<AbsoluteFill>`. We add a transparent overlay on top that captures editing interactions and renders controls.

**Render-gating:** The overlay must NOT appear during `npx remotion render`. The current composition already receives a `preview` prop via `TimelineCompositionProps` (`load-config.ts:67`), and `Root.tsx:28` sets `defaultProps={{ preview: false }}`. However, `calculateMetadata` does not currently forward a render-vs-studio signal. The correct approach: use Remotion's `getRemotionEnvironment()` API which returns `{ isStudio, isRendering, isPlayer }`. Gate the overlay on `getRemotionEnvironment().isStudio === true`.

1. **Create** `EditorOverlay.tsx`:
   - Receives current `config` (ResolvedTimelineConfig) and an `onConfigChange(config: ResolvedTimelineConfig)` callback
   - Gates rendering on `getRemotionEnvironment().isStudio` — returns `null` if not in Studio
   - Renders a floating toolbar (bottom of viewport, outside the composition's visual area using a React portal to `document.body`) with: track labels, clip bars, and action buttons
   - Uses `useCurrentFrame()` and config's `fps` to compute playhead position in seconds
   - Maintains local editing state (selectedClipId); calls `onConfigChange` on edits
2. **Update** `Timeline.tsx` (`remotion/src/timeline/Timeline.tsx:54-74`):
   - Add `<EditorOverlay>` as the topmost layer
   - Pass `config` and a `handleConfigChange` that: (a) updates local state via `setConfig`, (b) calls the debounced `saveTimeline()` from Step 2
3. **Validate:** Overlay appears in Studio, does NOT appear during `npx remotion render`. Confirm by running a test render.

## Step 4: Clip selection and property panel

**Scope:** Small

## Step 5: DRAG — reposition clips on the timeline

**Scope:** Medium  
**Files:** `remotion/src/timeline/EditorOverlay.tsx`

1. **Implement** horizontal drag on clip bars in the overlay:

   - `onPointerMove` → compute delta in seconds from pixel delta (using timeline scale: pixels per second)
   - `onPointerUp` → commit new `clip.at`, trigger save
   - Drag is horizontal only (within same track), not cross-track
2. **Snap** to 0.1s increments (hold Shift for frame-level precision at 1/fps)
3. **Clamp** `at >= 0`
4. **Validate:** Drag a clip, release, confirm `timeline.json` updated `at` value. Preview reflects new position after poll reload.

## Step 6: CROP/TRIM — adjust clip start and end

**Scope:** Medium  
**Files:** `remotion/src/timeline/EditorOverlay.tsx`

Two behaviors depending on clip type:

**For `from`/`to` clips (video, audio):**
1. **Add** left/right resize handles on clip bars:
   - Left handle: adjusts `clip.from` (source start). Also adjusts `clip.at` by the same delta to keep the clip's visual start in sync with the source trim.
   - Right handle: adjusts `clip.to` (source end)
2. **Clamp** values: `from >= 0`, `to <= assetEntry.duration` (from resolved asset), `from < to`

**For `hold` clips (overlays):**
1. Right handle adjusts `clip.hold` directly (minimum 0.1s)
2. Left handle adjusts `clip.at` and `clip.hold` together (moving start while keeping end position fixed)

3. **Validate:** Trim a from/to clip, confirm `from`/`to` in `timeline.json`. Trim a hold clip (if any exist), confirm `hold` updates. Preview shows trimmed result.

## Step 8: SPLIT clip at playhead

**Scope:** Medium

   - Clip B: new `id` = `{originalId}-b`, `at = playheadSeconds`, `hold = originalHold - elapsed`
   - Both inherit position/visual props
4. **Replace** original clip with the two new clips in `config.clips`, save
5. **Validate:** Split a clip, confirm two clips in `timeline.json`, preview shows seamless playback at the split point.
