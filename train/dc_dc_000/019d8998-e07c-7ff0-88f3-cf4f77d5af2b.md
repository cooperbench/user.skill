        # Implementation Plan: Fix Video Editor Final-Video Duration Model

## Overview

When a shot with a final video is dropped onto the video editor timeline, three problems can occur:

1. **Drop defaults to images instead of video** — Already fixed in commits `32986aa22` and `416e2836d`. No further work needed.
2. **Deadspace / frozen tail** — Video clips can extend past their actual media duration. Remotion freezes on the last frame, creating a visible "frozen tail." This happens because (a) resize clamping only exists for audio clips, not video, and (b) the fallback duration of 5s may not match the actual video length.
3. **Duration model is fragile** — Duration is derived in 3+ places with different fallback chains. `getDurationSecondsFromFinalVideoParams` searches 10 nested paths in the params JSON. The switch-to-video and update-to-latest-video mutations each have their own duration arithmetic.

## Phase 3: Simplify the Duration Model

### Step 6: Add `duration_seconds` column to `shot_final_videos` (`supabase/migrations/`)
**Scope:** Medium
1. **Create migration** adding `duration_seconds numeric` column to `shot_final_videos` table.
2. **Add backfill query** that extracts duration from `params` JSON using the same field priority as `getDurationSecondsFromFinalVideoParams`:
   ```sql
   UPDATE shot_final_videos
   SET duration_seconds = COALESCE(
     (params->>'duration_seconds')::numeric,
     (params->'metadata'->>'duration_seconds')::numeric,
     (params->>'trimmed_duration')::numeric,
     (params->>'duration')::numeric
   )
   WHERE duration_seconds IS NULL
     AND params IS NOT NULL;
   ```
3. **Push** with `npx supabase db push --linked`.
