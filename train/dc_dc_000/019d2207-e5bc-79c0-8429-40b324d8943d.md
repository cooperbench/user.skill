## Overview

The timeline editor has three drag-and-drop paths (internal asset, external file, cross-track) that independently calculate which track to place a clip on. The core bugs are:

1. **Row detection divergence**: `getDropPosition` (used by asset/file drops) measures Y against `.ReactVirtualized__Grid`, while `useCrossTrackDrag.updateDropTarget` measures against `.timeline-editor-edit-area`. These are different DOM elements with potentially different `top` offsets.
2. **Aggressive fallback in `getCompatibleTrackId`** (`coordinate-utils.ts:89-93`): When `desiredTrackId` is incompatible (wrong kind) OR undefined, it hardcodes V2/A1 instead of using the first compatible track contextually. This means a wrong row detection (giving an audio track ID when dropping visual) silently redirects to V2.
3. **Indicator vs. final position mismatch**: The drag-over indicator uses `getDropPosition` but the final drop also runs `getCompatibleTrackId`, which may override the row the indicator showed.

```typescript
// New behavior:
export const getCompatibleTrackId = (
  tracks: TrackDefinition[],
  desiredTrackId: string | undefined,
  assetKind: TrackKind,
  selectedTrackId: string | null,
): string | null => {
  const compatibleTracks = tracks.filter((t) => t.kind === assetKind);
  if (compatibleTracks.length === 0) return null;

  // Explicit target: honor it if compatible, reject if not
  if (desiredTrackId) {
    const exact = compatibleTracks.find((t) => t.id === desiredTrackId);
    return exact?.id ?? null; // ← was: fall through to V2/A1
  }

  // No explicit target: try selected track, then first compatible
  if (selectedTrackId) {
    const selected = compatibleTracks.find((t) => t.id === selectedTrackId);
    if (selected) return selected.id;
  }

  return compatibleTracks[0].id;
};
```

## Step 2: Fix `getCompatibleTrackId` fallback logic (`coordinate-utils.ts:64-94`)
**Scope:** Medium — highest-value fix
1. **New behavior**:
   - If `desiredTrackId` is provided AND matches a compatible track → use it (existing, correct).
   - If `desiredTrackId` is provided but incompatible (cross-kind) → return `null`. The caller already handles `null` by skipping the drop. This prevents silent redirection.

2. **Remove** the hardcoded `"V2"` and `"A1"` defaults at lines 89-93.
3. **No signature change needed** — the existing `desiredTrackId: string | undefined` parameter already distinguishes explicit targeting (string) from no targeting (undefined).

```typescript
export const getCompatibleTrackId = (
  tracks: TrackDefinition[],
  desiredTrackId: string | undefined,
  assetKind: TrackKind,
  selectedTrackId: string | null,
): string | null => {
  const compatibleTracks = tracks.filter((t) => t.kind === assetKind);
  if (compatibleTracks.length === 0) return null;

  // Explicit target: honor if compatible, reject if not
  if (desiredTrackId) {
    const exact = compatibleTracks.find((t) => t.id === desiredTrackId);
    return exact?.id ?? null;
  }

  // No explicit target: try selected track, then first compatible
  if (selectedTrackId) {
    const selected = compatibleTracks.find((t) => t.id === selectedTrackId);
    if (selected) return selected.id;
  }

  return compatibleTracks[0].id;
};
```

## Step 2: Fix `getCompatibleTrackId` fallback logic (`coordinate-utils.ts:64-94`)
**Scope:** Medium — highest-value fix
1. **New behavior**:

   - If `desiredTrackId` is provided but incompatible (cross-kind) → return `null`. The caller already handles `null` by skipping the drop. This prevents silent redirection.

```typescript
export const getCompatibleTrackId = (
  tracks: TrackDefinition[],
  desiredTrackId: string | undefined,
  assetKind: TrackKind,
  selectedTrackId: string | null,
): string | null => {
  const compatibleTracks = tracks.filter((t) => t.kind === assetKind);
  if (compatibleTracks.length === 0) return null;

  // Explicit target: honor if compatible, reject if not
  if (desiredTrackId) {
    const exact = compatibleTracks.find((t) => t.id === desiredTrackId);
    return exact?.id ?? null;
  }

  // No explicit target: try selected track, then first compatible
  if (selectedTrackId) {
    const selected = compatibleTracks.find((t) => t.id === selectedTrackId);
    if (selected) return selected.id;
  }

  return compatibleTracks[0].id;
};
```
