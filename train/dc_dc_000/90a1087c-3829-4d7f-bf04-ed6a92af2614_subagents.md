18	  --out runs/x/answer.json
19	```
20	
21	**Structured-output (schema-constrained):** pass `--response-schema PATH` to
22	force the model's reply to be JSON validating against your schema. Uses the
23	OpenAI Responses API `text.format = json_schema` (strict mode).
24	
25	```bash
26	python3 -m astrid executors run builtin.visual_understand \
27	  --input image=path/to.jpg \
28	  --query "Classify into one bucket from this list." \
29	  --response-schema my_schema.json \
30	  --out runs/x/answer.json
31	```
32	
33	Schema file may be either the raw JSON schema or an object of the form

37	## Use cases

97	Two schemas live next to `vocabulary.yaml`:
98	
99	- `schemas/bucket_judge.json` — enums sourced from `vocabulary.yaml`'s `scenes`
100	  and `characters`. Fields: `accept`, `bucket`, `confidence`, `reasons`.
101	- `schemas/caption.json` — enums for `scene`, per-character `outfit`,
102	  `shot_type`; free-text `action`. Matches the `caption_template` shape.
103	
104	Both schemas are passed to `builtin.visual_understand --response-schema`.
105	
106	Generating them from `vocabulary.yaml` is a small build step inside
107	`dataset_build.run` (or a one-shot script next to it). Don't hand-edit both
108	in parallel — the yaml is the source of truth.
109	
110	## Orchestrator logic (run.py shape)
111	
112	```
113	1. Load criteria from --vocabulary and --bucket-targets.
114	2. Track per-bucket counts in a state file (resumable).
115	3. While any bucket < target:
116	   a. Pick under-filled buckets, derive search queries.
117	      (e.g., for bucket "monks_diner × jerry+george", query = "seinfeld monk's diner jerry george scene").
118	   b. seinfeld.youtube_search → candidate URLs.
119	   c. For each URL not already processed:
120	      - seinfeld.youtube_video → mp4
121	      - builtin.scenes → scenes.json
122	      - cheap_filter (in-process): drop scenes <2s or >12s, transcript keyword check if available.
123	      - For each surviving scene clip:
124	        - seinfeld.vlm_bucket_judge → reject or assign bucket
125	        - if accepted and bucket not full:
126	          - seinfeld.vlm_caption → schema-checked caption
127	          - record clip + caption
128	   d. Persist state.
129	4. Attested human gate: review N random clip+caption pairs.
130	   Produces `human_review.json` with approve/reject per sampled pair.
131	   If reject-rate > threshold, rewind and retune queries/judge.
132	5. seinfeld.dataset_manifest → manifest.json.
133	```
134	
135	## Inputs / outputs
136	
137	```bash
138	python3 -m astrid orchestrators run seinfeld.dataset_build -- \
139	  --vocabulary astrid/packs/seinfeld/vocabulary.yaml \
140	  --bucket-targets '{"jerrys_apt": 80, "monks_diner": 80, ...}' \
141	  --out runs/seinfeld-dataset
142	```
143	
144	Output tree:
145	```
146	runs/seinfeld-dataset/
147	  state.json
148	  candidates/                       # downloaded mp4s, scene jsons
149	  accepted/<bucket>/<clip-id>.mp4
150	  accepted/<bucket>/<clip-id>.caption.json
151	  human_review.json
152	  manifest.json
153	```

156	
157	- Training itself — that's `seinfeld.lora_train`.

159	- Anything to do with rendering or script generation.
