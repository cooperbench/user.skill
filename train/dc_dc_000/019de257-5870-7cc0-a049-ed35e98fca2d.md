        # Implementation Plan: PAT-Accessible Reigh Data Fetch Surface

## Overview
Add a read-only Supabase edge function in `reigh-app` that lets PAT callers fetch the same project data shapes the UI already reads through Supabase: project/shot settings, shot media with image/video separation and `timeline_frame`, project media, task `settings`/`params`/`output`/`status`, and video-editor timeline `config`/`asset_registry`.

The repo already has the right building blocks: PAT auth in `supabase/functions/_shared/auth.ts`, edge lifecycle helpers in `supabase/functions/_shared/edgeHandler.ts`, ownership helpers such as `verifyProjectOwnership`, and UI query shapes in `src/shared/hooks/shots/useShotsQueries.ts`, `src/shared/hooks/shots/useShotImages.ts`, `src/shared/hooks/projects/useProjectGenerations.ts`, `src/shared/hooks/tasks/paginatedTaskRepository.ts`, and `src/tools/video-editor/data/SupabaseDataProvider.ts`. The simplest implementation is a single read-only edge function that authenticates by PAT/service role, verifies project ownership once, then returns a composed snapshot using service-role Supabase reads plus local mappers.

## Main Phase

### Step 1: Define the API contract (`supabase/functions/reigh-data-fetch/`)
**Scope:** Medium
1. **Create** a new edge function directory, likely `supabase/functions/reigh-data-fetch/`, following `get-completed-segments` and `get-task-output` conventions.
2. **Use** `withEdgeRequest` with `parseBody: "strict"` and normal PAT/service-role auth.
3. **Accept** a project-scoped POST body as the stable base contract:
   ```json
   {
     "project_id": "uuid",
     "shot_id": "uuid optional",
     "task_id": "uuid optional",
     "timeline_id": "uuid optional",
     "include": ["project", "shots", "shot_media", "project_media", "tasks", "timeline"]
   }
   ```
4. **Keep** the endpoint read-only. Do not add new write behavior or mutate timelines/assets.

### Step 2: Centralize authorization and request parsing (`supabase/functions/reigh-data-fetch/index.ts`)
**Scope:** Medium
1. **Validate** `project_id` for all user-token calls; reject missing or non-string IDs with `400`.
2. **Authorize** non-service callers using `verifyProjectOwnership` from `supabase/functions/_shared/auth.ts` before any data reads.
3. **Allow** service-role callers to fetch any project, consistent with existing worker-facing edge functions.
4. **For optional scoped IDs**, verify they belong to the authorized project by filtering reads through `project_id` or related project joins instead of trusting caller-supplied IDs.

### Step 3: Reuse UI query shapes for project and shot data (`src/shared/hooks/shots/useShotsQueries.ts`, `src/shared/hooks/shots/useShotImages.ts` as references)
**Scope:** Medium
1. **Fetch** the project with UI-relevant columns, including `id`, `name`, `user_id`, `aspect_ratio`, `settings`, `created_at`, `updated_at` if present.
2. **Fetch** shots with the same ordering as `useListShots`: `shots.select('*').eq('project_id', project_id).order('position')`.
3. **Fetch** shot media via `shot_generations` joined to `generations` and `primary_variant`, matching the query in `useShotImages`/`useListShots`:
   - `shot_generations.id`, `shot_id`, `generation_id`, `timeline_frame`, `metadata`
   - generation `id`, `location`, `thumbnail_url`, `type`, `created_at`, `starred`, `name`, `based_on`, `params`, `primary_variant_id`
   - primary variant `location`, `thumbnail_url`
4. **Map** media using a server-side equivalent of `mapShotGenerationToRow` so clients receive the same effective `location`, `thumbnail`, `type`, `params`, `metadata`, `position`, and `timeline_frame` semantics.
5. **Separate** shot media into `images`, `videos`, and optionally `unpositioned_images` using the same type/timeline intent as `selectTimelineImages`, `selectUnpositionedImages`, and `selectVideoOutputs`.

### Step 4: Add project media and task slices (`src/shared/hooks/projects/useProjectGenerations.ts`, `src/shared/hooks/tasks/paginatedTaskRepository.ts` as references)
**Scope:** Medium
1. **Fetch** project media from `generations` using the gallery fields from `useProjectGenerations`: location/thumbnail, primary variant, storage/local fields, type, timestamps, params, starred, tasks, based_on, shot_data, name, parent/child fields.
2. **Default** to media rows with available media (`location` not null or `storage_mode = local`) and `is_child = false`, matching the main gallery behavior unless the final contract explicitly asks for children.
3. **Fetch** task rows by project, exposing raw enough data for external clients without inventing a divergent model: `id`, `task_type`, `status`, `params`, `output_location`, `dependant_on`, `created_at`, `updated_at`, `generation_started_at`, `generation_processed_at`, `error_message`, `project_id`.
4. **Expose** a `settings` field only if it exists in the task row or is clearly derived from `params`; otherwise do not synthesize a fake task-settings contract.

### Step 5: Add timeline config/assets slice (`src/tools/video-editor/data/SupabaseDataProvider.ts`, `src/tools/video-editor/hooks/useTimelinesList.ts` as references)
**Scope:** Medium
1. **Fetch** timelines from `timelines` by `project_id`, ordered by `updated_at desc`, or a single `timeline_id` constrained to the same project.
2. **Return** `id`, `project_id`, `user_id`, `name`, `config`, `asset_registry`, `config_version`, `created_at`, `updated_at`.
3. **Preserve** the existing `config` and `asset_registry` shapes exactly. Do not transform ArtAgents/Reigh timeline contracts inside this endpoint.
4. **Optionally** validate timeline config using the same `validateSerializedConfig` logic if it can be imported or duplicated safely in the edge runtime; otherwise return stored JSON unchanged and cover shape preservation in tests.

### Step 6: Add focused edge tests (`supabase/functions/reigh-data-fetch/index.test.ts`)
**Scope:** Medium
1. **Follow** existing Vitest edge-entrypoint tests such as `supabase/functions/get-task-output/index.test.ts` and `supabase/functions/get-completed-segments/index.test.ts`.
2. **Test** lifecycle passthrough from `withEdgeRequest`.

5. **Test** successful response composition for a project with:
   - one shot with positioned image media

   - one timeline with `config` and `asset_registry`
6. **Test** that optional `shot_id`, `task_id`, and `timeline_id` filters do not leak rows from another project.

### Step 7: Add ArtAgents integration as a thin client, if this plan scope includes sibling repo edits (`/Users/user_c042661f/Documents/reigh-workspace/ArtAgents`)
**Scope:** Small
