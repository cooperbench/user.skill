## Overview
Phase 8 adds an opt-in `runs/<run-id>/inbox/` JSON completion channel for active task runs. The current V1 lifecycle already has hash-chained events in `artagents/core/task/events.py:25`, read-only cursor peeking in `artagents/core/task/gate.py:454`, attested completion in `artagents/core/task/gate.py:904`, `status` output in `artagents/core/task/lifecycle.py:245`, `next` output in `artagents/core/task/lifecycle.py:367`, and the generated run `AGENT.md` template in `artagents/core/task/lifecycle.py:53`.

The smallest durable implementation is additive: introduce inbox parsing/consumption beside the task kernel, factor the existing attested-event write path enough for inbox reuse, then wire `status` and `next` without changing `ack` semantics.

## Main Phase

### Step 1: Add the inbox module (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Define `InboxEntry` and `EventRecord` types around the requested JSON shape: `step_id`, `decision`, `evidence`, `submitted_at`, `submitted_by`, plus `source_path` and source-content hash for consumption bookkeeping.
2. Implement `inbox_dir(run_dir) -> Path` as `<run_dir>/inbox`.
3. Implement `scan_inbox(run_dir) -> list[InboxEntry]` so absence of `inbox/` returns `[]`; only regular non-dot JSON files are read; malformed JSON/schema/type/timestamp/decision files are logged with stdlib `logging` and skipped.
4. Use deterministic ordering by path name so tests and operators see stable behavior.
5. Document the consumed-file policy in the module docstring: processed files move to `inbox/.consumed/<sha256>.json` rather than being deleted.

### Step 2: Reuse attested event recording safely (`artagents/core/task/gate.py`)
**Scope:** Medium
1. Extract the shared core of `_dispatch_attested` at `artagents/core/task/gate.py:904` into a helper that records a prevalidated attestation for the current `AttestedStep`, preserving `step_attested`/`item_attested`, inline produces checks, iteration feedback behavior, and hash-chained writes.
2. Keep `gate_command` identity validation unchanged for explicit `ack`/gate paths.
3. Let inbox consumption call the new helper with `attestor_kind=peek.step.ack.kind` and `attestor_id=entry.submitted_by` after it has verified `entry.step_id` matches the current cursor and the current step is attested.

### Step 3: Consume actionable inbox files (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. Implement `consume_inbox_entry(run_dir, entry) -> EventRecord` by deriving `project_root`, `projects_root`, and `run_id` from `<project>/runs/<run-id>`; then load `plan.json`, `events.jsonl`, and `peek_current_step`.
2. Validate current expectations before mutation: active run exists, cursor is an `AttestedStep`, `entry.step_id == STEP_PATH_SEP.join(peek.path_tuple)`, and the entry decision is valid for the cursor.
3. For `approve`, append the attested event through the shared gate helper, then move the source file to `.consumed`.
4. For `retry`, mirror existing `ack retry` semantics: only consume if the latest event for the current path is `produces_check_failed`; append `cursor_rewind`; otherwise log and leave the file in place.
5. For `abort`, consume only when the `step_id` matches the current attested cursor; append `run_aborted`, clear `active_run.json`, and move the file.
6. Stale entries whose `step_id` does not match the current cursor are logged and left untouched, not consumed.

### Step 4: Wire lifecycle surfaces (`artagents/core/task/lifecycle.py`, `artagents/core/task/__init__.py`)
**Scope:** Medium
1. In `cmd_next`, after resolving the active run and before printing the final current-step instructions, scan the active run inbox, consume at most one actionable entry for the current attested cursor, reread events/active-run state, and recompute the cursor so output reflects advancement.
2. If an inbox `abort` clears the active run, print a concise aborted/consumed message after the mandatory preamble and return without falling through to normal next-step output.
3. In `cmd_status`, scan read-only and print `inbox:    N pending` where `N` is the number of structurally valid, currently actionable entries; do not mutate `events.jsonl` or move files.
4. Export inbox helpers from `artagents/core/task/__init__.py` only if tests or local style benefit from package-level imports.
5. Do not change `cmd_ack` in `artagents/core/task/lifecycle_ack.py`.

### Step 5: Update generated operator docs (`artagents/core/task/lifecycle.py`)
**Scope:** Small
1. Extend `_AGENT_MD_TEMPLATE` at `artagents/core/task/lifecycle.py:53` with an `INBOX` section showing the JSON file shape and explaining that files dropped into `runs/<run-id>/inbox/` are scanned by `next` and surfaced by `status`.
2. State the consumed-file behavior: valid consumed submissions move to `inbox/.consumed/<sha256>.json`; malformed and stale files remain for inspection.

### Step 6: Add focused tests (`tests/test_inbox_scan.py`, `tests/test_inbox_consume.py`, `tests/test_inbox_stale.py`)
**Scope:** Medium
1. `tests/test_inbox_scan.py`: create `run_dir/inbox`, write 3 valid JSON files and 1 malformed file, assert `scan_inbox` returns 3 entries and logs/skips the malformed file without raising.
2. `tests/test_inbox_consume.py`: use `tests/_lifecycle_fixtures.py:45` to create an attested step followed by a code step, drop a valid `approve` inbox entry, call `cmd_next`, assert a hash-chained `step_attested` event exists, the inbox file moved to `.consumed`, and the output/cursor advances to the following step.
3. Add a status assertion in the consume flow or a separate small test: before `next`, `cmd_status` prints `inbox:    1 pending` and does not mutate `events.jsonl`.
4. `tests/test_inbox_stale.py`: drop a valid entry for a non-current `step_id`, call `cmd_next`, assert no attested event is recorded, the file remains in inbox, and no exception occurs.

## Execution Order
1. Add parser-only `inbox.py` and `test_inbox_scan.py` first; this is the cheapest validation and avoids lifecycle complexity.
2. Factor the gate attestation helper before wiring `next`, so inbox approval reuses the same event/check behavior as explicit attestation.
3. Wire `status` read-only behavior before mutating `next` behavior, preserving the existing `test_status_does_not_mutate_events_jsonl` invariant.
4. Wire `next` consumption and then add consume/stale integration tests.
5. Update the `AGENT.md` template after behavior is stable.

## Overview

The current V1 lifecycle already has hash-chained events in `artagents/core/task/events.py:25`, cursor peeking in `artagents/core/task/gate.py:454`, gate dispatch in `artagents/core/task/gate.py:510`, `status` in `artagents/core/task/lifecycle.py:245`, `next` in `artagents/core/task/lifecycle.py:367`, and the generated run `AGENT.md` template in `artagents/core/task/lifecycle.py:53`.

The critique does not show the plan targeting the wrong files, but it does show the mutation boundary must be stricter. The right root cause remains in the task gate/lifecycle layer: valid inbox approval must persist the same traversal events as `gate_command`, but stale/non-current inbox files must be rejected before any mutating `_auto_traverse_to_leaf` call can append traversal events. The revised plan therefore uses a two-stage flow: read-only current-leaf validation first, then mutating gate traversal and attestation only for entries already proven actionable.

Phase 8 remains approval-focused. The JSON format accepts `decision: approve | retry | abort`, but only `approve` is actionable in this phase because the design describes an external completion-signal protocol. `retry` and `abort` entries are structurally valid files, logged as non-actionable, not counted as pending, and not consumed.

### Step 2: Add a preflight-safe gate external attestation path (`artagents/core/task/gate.py`)
**Scope:** Medium

5. Keep `retry` and `abort` out of Phase 8 consumption. They remain parse-valid decisions so producers can use the declared schema, but they are not completion signals and require future explicit semantics/tests before they mutate verifier or active-run state.
