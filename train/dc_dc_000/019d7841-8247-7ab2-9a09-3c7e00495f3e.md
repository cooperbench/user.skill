        # Implementation Plan: Clean Up DEBUG Mode Logging

## Overview

The project has ~940 `logger.debug()` calls across 50 source files. The worst offenders are concentrated in 8-10 files in the task handler and model layers. The core problem is several anti-patterns that produce verbose, low-signal debug output:

1. **Per-field parameter dumps** — 5-7 sequential `.debug()` lines logging individual variables that should be one summary line
2. **Leftover diagnostic dumps** — Lines tagged `AGGRESSIVE`, `DIAGNOSTIC`, `DEEP_DIAG`, `CRITICAL DEBUG` (39 occurrences across 9 files) that are clearly debugging artifacts, not structured logging
3. **ASCII table formatting** — Multi-line box-drawing character tables in debug output (final_stitch.py)
4. **Loop-per-item logging** — One debug line per segment/transition/video that scales linearly with data
5. **Redundant pre/post pairs** — Logging the same data structure before and after an operation
6. **Duplicate state logging** — Same collection logged twice in different formats (count then full dump)

The logging system is custom (`source/core/log/core.py`) — simple `ComponentLogger` wrappers around print statements gated on a `_debug_mode` boolean. There's already `safe.py` with truncation helpers (`safe_dict_repr`, `safe_json_repr`). No structured logging library — just formatted strings.

**Goal:** Reduce debug noise by ~50-60% while keeping anchor points (entry/exit, key decisions, parameter summaries, timing, errors). Debug should read like a structured event log, not a variable dump.

**Approach:** Work file-by-file through the worst offenders. For each file: (1) remove leftover diagnostic dumps, (2) consolidate per-field dumps into single summary lines, (3) collapse loop logging into aggregate summaries, (4) remove redundant duplicates. No new abstractions or helper functions needed — the existing `safe_dict_repr`/`safe_json_repr` helpers already handle truncation.
