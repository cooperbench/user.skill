Goal: introduce the composable system underneath the existing surface so `megaplan plan --robustness=standard` keeps working bit-for-bit while new workflows become possible. The trick is to make the old hardcoded state machine *one specific instance* of the new system, not a parallel codepath. ## The shape of the refactor Three layers, introduced in order, each leaving the old flow intact. **Layer A — Step primitives.** Wrap each existing handler in a thin `Step` interface: `id`, `kind` (`plan`/`critique`/`revise`/`gate`/`finalize`/`execute`/`review`/`tiebreaker`), `params` (perspective, check set, agent override), `inputs` (which prior artifacts to read), `outputs` (what files it writes). Steps stay pure-ish: state + params + inputs → artifacts + state delta. The handlers in `megaplan/handlers/*` already mostly fit this shape — this phase is mechanical extraction. **Layer B — Workflow as data.** A workflow is an ordered list of step instances with conditional edges. YAML/JSON in `megaplan/data/workflows/`. Crucially, conditional edges are needed — not just sequences — because gate routes (`ITERATE`/`PROCEED`/`TIEBREAKER`/`ESCALATE`) and review's rework loop have to be expressible. Format roughly: each step declares `on_result: {iterate: <step_id>, proceed: <step_id>}`. Loops are just back-edges with a bounded counter. **Layer C — Workflow runner / cursor.** Replaces `infer_next_steps()` in `_core/workflow.py:250`. Tracks `(workflow_id, step_index, run_id)` in `state.json`. Old `current_state` field stays populated as a derived view ("kind of last step") so legacy reporting and any external readers don't break. ## Migration sequence — keeping flow active at every step **Phase 0: extract Step interfaces, no behavior change.** Each handler gets a `Step` wrapper.
