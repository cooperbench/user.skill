        # Implementation Plan: Database-Backed Agent Node Catalog and Installer

## Overview
Reigh currently stores reusable user assets in a generic `resources` table (`reigh-app/src/features/resources/hooks/useResources.ts`), with browser/form patterns for LoRAs, phase configs, style references, and structure videos. ArtAgents already has a first-class node manifest schema and registry under `ArtAgents/artagents/nodes/`, but curated external nodes are bundled JSON files. Wan2GP already has a plugin installer path in `reigh-worker/Wan2GP/shared/utils/plugins.py`, including `PluginManager.install_plugin_from_url()` and an empty `auto_install_and_enable_default_plugins()` hook.

The simplest durable implementation is to keep agent nodes separate from `resources`, model them as a dedicated catalog with separate media rows, expose a small typed app API/hook layer, then teach ArtAgents and the worker to fetch only the default/mandatory public catalog entries they need. Routing/profile changes stay Codex-only; this plan does not introduce Claude-facing phase or profile paths.
