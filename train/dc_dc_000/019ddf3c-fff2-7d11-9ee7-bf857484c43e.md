        # Implementation Plan: ArtAgents Node Architecture MVP

## Overview
ArtAgents currently has a cache-aware pipeline orchestrator in `artagents/pipeline.py` with a `Step` dataclass, hard-coded `STEP_ORDER`, hard-coded command builders, sentinel-based caching, and subprocess execution (`artagents/pipeline.py:29`, `artagents/pipeline.py:68`, `artagents/pipeline.py:465`, `artagents/pipeline.py:777`, `artagents/pipeline.py:816`). The root `pipeline.py` is only a compatibility launcher, so CLI exposure should be added through `artagents/pipeline.py` while preserving every existing legacy invocation.

The pragmatic MVP is to add a node layer beside the existing orchestrator, not replace the pipeline engine in one sweep. Built-in pipeline stages become discoverable `NodeDefinition`s backed by the existing command builders and cache/sentinel behavior. The new CLI subcommand can list, inspect, validate, and run a single node through the same subprocess/logging isolation path. Graph/condition support should be represented in typed metadata now, with minimal sequential graph validation, while full graph orchestration can evolve later without breaking the schema.

Moirae is a good external boundary fixture because its README describes a terminal-demo video pipeline invoked as `python -m moirae screenplay.yaml -o demo.mp4`, with external prerequisites like `asciinema`, `agg`, and `ffmpeg`. The MVP should include a curated manifest for Moirae but tests must not require cloning it or installing those binaries.

## Phase 1: Define Node Metadata And Validation

### Step 1: Add the node package skeleton (`artagents/nodes/`)
**Scope:** Medium
1. **Create** `artagents/nodes/__init__.py`, `artagents/nodes/schema.py`, `artagents/nodes/registry.py`, `artagents/nodes/builtin.py`, `artagents/nodes/runner.py`, and `artagents/nodes/cli.py`.
2. **Use** stdlib `dataclasses`, `json`, and explicit validators rather than adding Pydantic, because this repo does not currently depend on Pydantic and the MVP does not need a new runtime dependency.
3. **Model** the core typed schema:
   - `NodeDefinition`: `id`, `label`, `kind` (`built_in` or `external`), `version`, `description`, `inputs`, `outputs`, `command`, `cache_policy`, `conditions`, `graph`, `isolation`, `source`.
   - `NodePort`: `name`, `type`, `required`, `default`, `description`, `path_role`.
   - `NodeOutput`: `name`, `type`, `mode` (`mutate`, `create`, `create_or_replace`), `path`, `description`.
   - `CachePolicy`: `sentinels`, `always_run`, `per_brief`, and optional dependency hints.
   - `Condition`: minimal declarative checks such as `requires_input`, `requires_file`, and `skip_when` for built-in discovery and future graph execution.
   - `Isolation`: `subprocess` as the only MVP execution backend, plus `requires_binaries` and `env_passthrough` metadata.
4. **Implement** `validate_node_definition(raw)` and `load_node_manifest(path)` with clear error messages and no defensive coercions beyond JSON parsing.

### Step 2: Add curated external manifest support (`artagents/nodes/curated/moirae.json`)
**Scope:** Small
1. **Create** a packaged curated manifest directory under `artagents/nodes/curated/`.
2. **Add** `moirae.json` describing Moirae as an external wrapped node:
   - input `screenplay` as a required YAML path.
   - optional `output` path defaulting to an MP4 output path supplied at run time.
   - output `video` with `create_or_replace` mode.
   - command template equivalent to `python -m moirae {screenplay} -o {output}`.
   - isolation metadata listing external requirements (`moirae`, `asciinema`, `agg`, `ffmpeg`) but marking tests as manifest-only.
3. **Keep** this as a fixture/curated descriptor, not an installer or clone step, to avoid making ArtAgents tests depend on network access or Moirae binaries.

## Phase 2: Register Built-In Pipeline Stages

### Step 3: Convert existing pipeline step metadata into built-in nodes (`artagents/nodes/builtin.py`, `artagents/pipeline.py`)
**Scope:** Medium
1. **Preserve** `artagents/pipeline.py` legacy behavior first: `pipeline.py --video ... --brief ... --out ...` must continue to hit `resolve_args()` and `pool_main()` exactly as it does today (`artagents/pipeline.py:1052`).
2. **Add** a helper in `artagents/pipeline.py` that exposes current built-in `Step` objects plus command builders as node definitions. The initial implementation can call existing `build_pool_steps()` (`artagents/pipeline.py:465`) and map `Step.name`, `Step.sentinels`, `Step.per_brief`, and `Step.always_run` into `NodeDefinition.cache_policy`.
3. **Represent** built-in node inputs/outputs manually for the important stages rather than trying to infer every CLI argument from lambdas. Start with `transcribe`, `scenes`, `arrange`, `cut`, `render`, and `validate`, then include the rest with basic metadata so listing is complete.
4. **Record** output modes precisely: analysis files are `create_or_replace`, `refine` is `mutate` for timeline/assets/metadata plus `create_or_replace` for `refine.json`, and `pool_merge` is `mutate` for `pool.json`.

### Step 4: Implement registry discovery (`artagents/nodes/registry.py`)
**Scope:** Medium
1. **Implement** `NodeRegistry` with `register()`, `get(id)`, `list(kind=None)`, and `validate_all()`.
2. **Load** built-in nodes from `builtin.py` and curated external manifests from `artagents/nodes/curated/*.json`.
3. **Fail** on duplicate IDs, invalid output modes, invalid cache policy shape, missing required fields, or command templates referencing undeclared inputs.
4. **Add** a stable JSON serialization method so `nodes inspect` can print the same object shape tests assert against.

## Phase 3: Runner And CLI Exposure

### Step 5: Add a node runner that reuses subprocess isolation (`artagents/nodes/runner.py`, `artagents/pipeline.py`)
**Scope:** Medium
1. **Implement** `NodeRunRequest` with `node_id`, `inputs`, `out`, optional `brief_out`, `python_exec`, `dry_run`, and `verbose`.
2. **For built-in nodes**, adapt existing `Step.build_cmd(args)` where the node corresponds to an existing pipeline stage, and run through the same log-writing subprocess behavior as `run_step()` (`artagents/pipeline.py:816`).
3. **For external nodes**, expand the curated command template only after validation confirms all required inputs exist and all placeholders are declared.
4. **Return** a structured result containing `node_id`, `command`, `returncode`, `log_path`, and expected output paths.
5. **Support** validation-only mode that checks metadata, required inputs, output modes, command template consistency, and required binary availability when requested, without running expensive APIs or external binaries by default.

### Step 6: Expose node commands through the main pipeline CLI (`artagents/nodes/cli.py`, `artagents/pipeline.py`)
**Scope:** Medium
1. **Add** a `nodes` subcommand branch before legacy parsing in `main()` (`artagents/pipeline.py:1052`), similar to the existing `publish` branch.
2. **Implement** subcommands:
   - `python pipeline.py nodes list [--json] [--kind built_in|external]`
   - `python pipeline.py nodes inspect NODE_ID [--json]`
   - `python pipeline.py nodes validate [NODE_ID] [--check-binaries]`
   - `python pipeline.py nodes run NODE_ID --out DIR --input name=value [--dry-run] [--verbose]`
3. **Keep** the command namespace isolated under `nodes` so current flags like `--video`, `--brief`, `--render`, `--skip`, and `--from` are not reinterpreted.
4. **Make** `nodes run` support at least one cheap built-in execution path in tests by using a small fixture node or a built-in node whose core function can be monkeypatched, rather than requiring ffmpeg, OpenAI keys, Remotion, or Moirae.

## Phase 4: Minimal Graph And Condition Support

### Step 7: Add graph schema validation without replacing orchestration (`artagents/nodes/schema.py`, `artagents/nodes/runner.py`)
**Scope:** Small
1. **Define** graph metadata as an optional sequential DAG descriptor: `nodes`, `edges`, and `conditions`.
2. **Validate** that graph references point to known node IDs and declared ports.
3. **Support** simple condition evaluation helpers for `requires_input` and `requires_file` so built-in stages can document why source-only or audio-only stages are skipped, matching current behavior in `build_steps()` (`artagents/pipeline.py:753`).
4. **Do not** port `pool_main()` to graph execution in the MVP; that would be riskier than the requirement needs and would threaten legacy behavior.

## Phase 5: Tests And Documentation

### Step 8: Add focused node tests (`tests/test_nodes_registry.py`, `tests/test_nodes_cli.py`, `tests/test_nodes_runner.py`)
**Scope:** Medium
1. **Test** built-in discovery includes all names from `STEP_ORDER` (`artagents/pipeline.py:29`) and exposes typed inputs/outputs for representative nodes.
2. **Test** curated Moirae manifest loads and validates without checking binaries by default.
3. **Test** invalid manifests fail on missing required fields, invalid output mode, duplicate ID, and undeclared command placeholders.
4. **Test** CLI list/inspect/validate output using direct calls into `pipeline.main(["nodes", ...])` and captured stdout.
5. **Test** one node execution/validation path without expensive dependencies by monkeypatching subprocess execution or using `--dry-run` plus a small temporary file input.

### Step 9: Protect legacy pipeline tests (`tests/test_pipeline_caching.py`)
**Scope:** Small
1. **Add** a regression test that a normal legacy invocation still calls the same ordered steps and does not enter the node CLI.
2. **Add** a regression test that `pipeline.main(["nodes", "list"])` does not require `--out` or `--brief`, proving the subcommand dispatch happens before `resolve_args()`.
3. **Run** the focused tests first:

### Step 10: Update user-facing docs (`README.md`)
**Scope:** Small
1. **Add** a compact “Nodes” section showing list, inspect, validate, and dry-run examples.
2. **Document** that Moirae is curated metadata in the MVP and requires a separate local install before actual execution.
3. **Avoid** editing unrelated generated Remotion files or existing dirty files unless the node docs genuinely need the touched README section.

## Execution Order
1. Add schema and validation first, because every later change depends on stable object shapes.
2. Add the Moirae curated manifest before registry tests, so external-node behavior is covered early.
3. Register built-in nodes from existing `Step` metadata while leaving legacy pipeline execution untouched.
4. Add the CLI dispatch under `nodes` before legacy `resolve_args()` so node commands do not inherit pipeline required flags.
5. Add runner support after list/inspect/validate work, because execution has the highest risk.
6. Add tests alongside each layer, then update README last.

## Validation Order

2. Run CLI tests next to prove the new command namespace works and legacy parsing is preserved.
3. Run runner tests with dry-run or mocked subprocess execution.
4. Run `tests/test_pipeline_caching.py` to catch regressions in existing step order and caching semantics.
5. Run the broader non-slow suite after the focused checks pass.
