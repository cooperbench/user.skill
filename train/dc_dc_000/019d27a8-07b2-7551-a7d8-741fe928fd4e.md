        # Implementation Plan: Refactor ai-timeline-agent to Modular Structure

## Overview

The `ai-timeline-agent` edge function is an 850-line monolith (`index.ts`) that mixes HTTP handling, LLM client, tool dispatch, session persistence, and the agent loop. The existing satellite files (`session-tools.ts`, `timeline-tools.ts`, `tools.ts`, `prompts.ts`) already extract some logic but the core loop, types, DB access, and LLM client remain tangled in `index.ts`.

**Goal:** Pure restructuring into focused modules with a unified tool interface. No behavior changes. Same API contract, same DB operations, same turn format.

**Current file sizes:**
- `index.ts` — 850 lines (monolith)
- `timeline-tools.ts` — 362 lines (clean, already modular)
- `session-tools.ts` — 125 lines (mostly clean)
- `tools.ts` — 173 lines (tool schemas, clean)
- `prompts.ts` — 21 lines (clean)

**Key issues to fix during restructure:**
1. Dead Llama fallback parser (`index.ts:22-24`, `index.ts:679-702`)
2. `message_user`/`done` duplicate turns (`index.ts:779-781` — pushes both tool_result AND assistant turn with same content)
3. Hand-typed Supabase client interfaces repeated 5 times (`index.ts:309-318`, `:344-349`, `:371-380`, `:396-403`, `:426-443`)
4. Tool dispatch via if/else chain (`index.ts:747-770`) with special-casing per tool name
5. `createGenerationTask` throws on HTTP error (`session-tools.ts:108`) instead of returning error result
6. No unified tool interface — timeline tools take `(config, registry, args)`, session tools take ad-hoc signatures

## Phase 1: Foundation — Types and Shared Context

### Step 1: Create shared types and context (`ai-timeline-agent/types.ts`)
**Scope:** Small
1. **Create** `types.ts` with:
   - `ToolResult` — unified return type: `{ result: string; config?: TimelineConfig; stopLoop?: boolean; nextStatus?: AgentSessionStatus }`
   - `ToolContext` — everything a tool needs: `{ config: TimelineConfig; configVersion: number; registry: AssetRegistry; projectId: string; timelineId: string; supabase: SupabaseAdmin }` 
   - `SupabaseAdmin` — single typed interface replacing the 5 hand-typed inline interfaces in `index.ts`. Extract the union of all `.from()` and `.rpc()` shapes used.
   - `ToolHandler` — unified signature: `(args: Record<string, unknown>, ctx: ToolContext) => ToolResult | Promise<ToolResult>`
   - `LlmMessage`, `OpenRouterParams`, `OpenRouterResponse` — moved from `index.ts:33-166`
   - `TimelineState` — moved from `index.ts:26-31`
   - Re-export `AgentSession`, `AgentSessionStatus`, `AgentTurn` from the source types
2. **Key decision:** The `SupabaseAdmin` interface should use the narrow shapes actually needed (`.from().select().eq().maybeSingle()`, `.from().update().eq()`, `.rpc().maybeSingle()`), not a generic `SupabaseClient` import. This keeps Deno's type-checking happy without importing the full Supabase SDK types.

### Step 2: Create LLM client module (`ai-timeline-agent/llm/client.ts`)
**Scope:** Small

2. **Import** `OpenRouterParams`, `OpenRouterResponse` from `types.ts`.
3. **Export** `invokeLlmWithRetry` as the public API (keep `callOpenRouter` internal).

## Phase 2: Unified Tool Interface and Registry

### Step 4: Adapt timeline tools to unified interface (`ai-timeline-agent/tools/timeline.ts`)
**Scope:** Medium
1. **Rename** existing `timeline-tools.ts` → `tools/timeline.ts`.
2. **Wrap** each exported function to match `ToolHandler` signature `(args, ctx) => ToolResult`. The wrapper passes `ctx.config` and `ctx.registry` to the existing pure functions, keeping all current logic.
3. **Merge** `TimelineToolResult` into the unified `ToolResult` type (they're already compatible — just add the optional `stopLoop`/`nextStatus` fields which timeline tools don't use).
4. **Keep** the internal pure functions (`viewTimeline`, `moveClip`, etc.) as-is — just add wrapper exports that conform to `ToolHandler`.

Example wrapper pattern:
```typescript
export const handlers: Record<string, ToolHandler> = {
  view_timeline: (args, ctx) => viewTimeline(ctx.config, ctx.registry),
  move_clip: (args, ctx) => moveClip(ctx.config, ctx.registry, args),
  // ...
};
```

### Step 5: Adapt session tools to unified interface (`ai-timeline-agent/tools/session.ts`)
**Scope:** Small
1. **Move** `messageUser` and `done` from `session-tools.ts` → `tools/session.ts`, adapted to `ToolHandler` signature.
2. `message_user(args, ctx)` → extracts `args.text`, returns unified `ToolResult` with `stopLoop: true, nextStatus: "waiting_user"`.
3. `done(args, ctx)` → extracts `args.summary`, returns unified `ToolResult` with `stopLoop: true, nextStatus: "done"`.

### Step 6: Extract generation tool (`ai-timeline-agent/tools/generation.ts`)
**Scope:** Small
1. **Move** `createGenerationTask` from `session-tools.ts` → `tools/generation.ts`, adapted to `ToolHandler`.
2. **Fix** the error handling: change the `throw new Error(errorText)` at `session-tools.ts:108` to `return { result: \`Failed to create task: \${errorText}\` }` — tools should return errors, not throw.
3. The `sha256Hex`, `getIdempotencyKey`, `requireEnv` helpers move with it.

### Step 7: Create tool registry (`ai-timeline-agent/tools/registry.ts`)
**Scope:** Medium
1. **Create** a registry that maps tool names → `ToolHandler`:
   ```typescript
   import { handlers as timelineHandlers } from "./timeline.ts";
   import { handlers as sessionHandlers } from "./session.ts";
   import { handlers as generationHandlers } from "./generation.ts";

   export const TOOL_REGISTRY: Record<string, ToolHandler> = {
     ...timelineHandlers,
     ...sessionHandlers,
     ...generationHandlers,
   };
   ```
2. **Create** `executeTool(name, args, ctx)` that:
   - Looks up the handler in `TOOL_REGISTRY`
   - Returns `{ result: "Unknown tool {name}." }` for unknown tools
   - For timeline tools that return `config`, handles the versioned save + retry logic (extracted from `executeTimelineTool` at `index.ts:426-497`)
   - Catches thrown errors and converts to `{ result: "Tool error: ..." }` for consistent error handling
3. **Move** `loadTimelineState` (`index.ts:309-342`) and `saveTimelineConfigVersioned` (`index.ts:344-369`) into this module as private helpers (they're only used by the version-conflict retry logic).

## Phase 3: Loop and Entrypoint

### Step 8: Extract agent loop (`ai-timeline-agent/loop.ts`)
**Scope:** Large — this is the core extraction
1. **Extract** the agent loop from `index.ts:614-791` into `runAgentLoop(options)` function.
2. **Parameters:** `{ session, userMessage, supabase, logger }` — everything the loop needs.
3. **Returns:** `{ status, turns, summary }` — the final state.
4. **Key logic that moves here:**
   - The `for` loop with `LOOP_LIMIT` and `SOFT_TIMEOUT_MS` checks
   - LLM invocation via `invokeLlmWithRetry` (imported from `llm/client.ts`)
   - Message building via `buildInitialMessages` (imported from `llm/messages.ts`)
   - Tool dispatch via `executeTool` (imported from `tools/registry.ts`)
   - Turn recording (tool_call, tool_result turns)
   - Cancellation checks via `loadSessionStatus`
5. **Remove** the Llama fallback parser (`index.ts:679-702`). The `LLAMA_TOOL_CALL_RE` regex and its parsing block are dead code — we use minimax via OpenRouter which always returns structured tool_calls.
6. **Fix** the `message_user`/`done` duplicate turn issue (`index.ts:779-781`). Currently, after recording a tool_result turn, the code also pushes an assistant turn with the same content. This creates duplicate information in the DB turns array. The fix: remove the special-case `if (toolName === "message_user" || toolName === "done")` block. The tool_result turn already contains the text. If the frontend needs the text as an "assistant" role for display, that should be handled in the frontend's turn rendering, not by duplicating data.
7. **Move** `loadSessionStatus` (`index.ts:371-394`) and `persistSessionState` (`index.ts:396-424`) into `loop.ts` as private helpers (or into a `db.ts` if preferred, but they're only used by the loop).

### Step 9: Slim down entrypoint (`ai-timeline-agent/index.ts`)
**Scope:** Medium
1. **Reduce** `index.ts` to ~50-70 lines: just the `serve()` handler with request validation, session loading, and delegation to `runAgentLoop`.
2. **Keep** in `index.ts`:

   - Duplicate message guard
   - Call to `runAgentLoop`
