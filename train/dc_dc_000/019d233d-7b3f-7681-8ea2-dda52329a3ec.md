        # Implementation Plan: Execute/Review Pipeline Improvements (5 items)

## Overview

The megaplan execute→review pipeline works but has friction points surfaced by real usage: gate decisions get re-litigated by the reviewer, executor notes describe actions instead of proving correctness, the path-extraction audit fires false positives, mock payloads are duplicated across 5 test files (~78 occurrences of task/evidence fields), and robustness level only changes critique tone without affecting workflow structure.

The repository is a single-package Python project (`megaplan/`) with 6 core modules, 5 test files, and a mock-worker system in `workers.py`. State flows through a linear state machine (`_core.py:442-466`) with handler functions in `handlers.py` (1616 lines). The workflow is orchestrated by calling individual handlers (`handle_plan`, `handle_critique`, `handle_gate`, etc.) in sequence, guided by `infer_next_steps()` and `data/instructions.md`. The `megaplan step` command is a separate markdown editor for plan sections and is not part of the workflow orchestration.

Constraints: keep the state machine transitions backward-compatible, ensure `test_workflow_mock_end_to_end` keeps passing throughout, and avoid schema changes that break existing plan directories.

## Phase 1: Cheap Fixes — Remove Noisy Audit Check + Executor Notes Prompt

### Step 1: Remove the path-extraction audit check (`megaplan/evaluation.py`, `tests/test_evaluation.py`)
**Scope:** Small
1. **Delete** `_extract_note_paths()` (`evaluation.py:108-120`), the `_PATH_TOKEN_RE` regex (`evaluation.py:40`), and the `_FILE_SUFFIXES` tuple (`evaluation.py:41-65`).
2. **Remove** the note-path audit loop in `validate_execution_evidence()` (`evaluation.py:200-209`) — the block that iterates `_extract_note_paths(note)` for each task and appends "references missing artifact" findings.
3. **Keep** the phantom/unclaimed file cross-checks (`evaluation.py:186-198`) — these compare `files_claimed` against `git status` output and are the real value of the audit.
4. **Remove or update** any tests in `tests/test_evaluation.py` that assert on `_extract_note_paths` behavior or expect "references missing artifact" findings.
5. **Verify** `pytest tests/test_evaluation.py` passes after removal.

### Step 2: Shift executor notes guidance from description to verification (`megaplan/prompts.py`)
**Scope:** Small
1. **Update** the execute prompt instruction at `prompts.py:461` from:
   > Keep `executor_notes` specific enough that a reviewer can map each update to the actual code and commands you ran.

   to guidance emphasizing verification-focused notes:
   > Write `executor_notes` as verification evidence: state what you verified is correct, what edge cases you considered, and what behavior you observed. The diff already shows what changed — notes should explain why the change is correct and what a reviewer should look for.
2. **Update** the example `executor_notes` in the JSON shape (`prompts.py:473`) from a description-style note to a verification-style note:
   ```json
   "executor_notes": "Verified: handle_execute now merges per-task evidence before checking blocking conditions. Tested that a done task with commands_run but no files_changed passes the FLAG-006 softening path. Edge case: empty string in commands_run is treated as no evidence."
   ```
3. **No schema change needed** — `executor_notes` is still a string field. This is purely prompt guidance.

## Phase 2: Settled Decisions + Mock Payload Builder

### Step 3: Inject settled decisions via gate LLM output (`megaplan/schemas.py`, `megaplan/prompts.py`, `megaplan/evaluation.py`, `megaplan/types.py`)
**Scope:** Medium
1. **Add `settled_decisions` to the gate output schema** (`schemas.py:31-43`). The gate LLM will explicitly produce this array alongside its existing `warnings`:
   ```python
   "settled_decisions": {
       "type": "array",
       "items": {
           "type": "object",
           "properties": {
               "id": {"type": "string"},
               "decision": {"type": "string"},
               "rationale": {"type": "string"}
           },
           "required": ["id", "decision"]
       }
   }
   ```
   Make it a required field in the schema so the LLM always produces it (even as `[]`).
2. **Update the gate prompt** (`prompts.py:235-287`) to instruct the gate LLM to populate `settled_decisions` with any design choices, trade-offs, or flag resolutions that downstream steps should treat as settled. Add to the prompt requirements:
   > Populate `settled_decisions` with design choices and trade-offs that the reviewer should not re-litigate. Each entry needs an `id` (use the flag ID if applicable, or a short descriptive ID), a `decision` summarizing what was decided, and an optional `rationale`.
3. **Update the gate JSON example** in the prompt to include a `settled_decisions` example entry.
4. **Update `GatePayload` in `types.py:140-144`** to document `settled_decisions` as a field.
5. **Thread `settled_decisions` into `build_gate_artifact()`** (`evaluation.py:565-588`) — pass through from `gate_payload["settled_decisions"]` directly into the artifact dict.
6. **Thread `settled_decisions` into the review prompts** (`prompts.py:499-583`, `prompts.py:586-666`). After the gate summary block, add a dedicated section:
   ```
   Settled decisions (from gate approval — do not re-litigate these):
   - FLAG-006: Done tasks may rely on commands_run alone without files_changed
   ```
   If `settled_decisions` is empty, omit the section.
7. **Add explicit instruction** to the review prompt requirements: "The decisions listed above were settled at the gate stage. Verify that execution honors these decisions, but do not question the decisions themselves."

### Step 4: Build a mock payload builder (`megaplan/workers.py`)
**Scope:** Medium
1. **Create** `_build_mock_payload(step, state, plan_dir, **overrides)` in `workers.py` (near line 196, before the individual mock functions). This private function returns a complete valid payload for any step with sensible defaults:
   ```python
   def _build_mock_payload(step: str, state: PlanState, plan_dir: Path, **overrides: object) -> dict:
       builder = _MOCK_DEFAULTS[step]
       defaults = builder(state, plan_dir)
       return _deep_merge(defaults, overrides)
   ```
2. **Extract** the default payload dicts from existing `_mock_plan`, `_mock_critique`, `_mock_revise`, `_mock_gate`, `_mock_finalize`, `_mock_execute`, `_mock_review` (`workers.py:199-451`) into `_MOCK_DEFAULTS` — a dict mapping step names to functions that return the default payload dict.
3. **Refactor** each `_mock_*` function to call `_build_mock_payload` internally. Each becomes a thin wrapper. The `_mock_execute` side-effect (writing `IMPLEMENTED_BY_MEGAPLAN.txt`) stays in `_mock_execute` before calling the builder.
4. **Add `_deep_merge` helper** (simple recursive dict merge, ~10 lines) near the builder. List-typed overrides replace rather than extend.
5. **Keep `_build_mock_payload` private** — tests import it directly via `from megaplan.workers import _build_mock_payload` where needed, but it's not a public API commitment.
6. **Migrate test files** (`test_megaplan.py`, `test_workers.py`, `test_evaluation.py`, `test_prompts.py`) to use the builder where they currently construct full mock payloads inline. Tests that only need one field override become one-liners.

## Phase 3: Robustness-Scaled Workflow

### Step 6: Create a combined plan+critique+gate prompt and schema for light robustness (`megaplan/prompts.py`, `megaplan/schemas.py`)
**Scope:** Medium
1. **Create** `_plan_light_prompt()` in `prompts.py` that combines plan, self-critique, and gate-recommendation into a single prompt. The prompt tells the LLM to:
   - Produce the plan (same structure as standard).
   - Flag its own concerns in a `self_flags` array (same shape as critique flags: `id`, `concern`, `category`, `severity_hint`, `evidence`).
   - Produce a `gate_recommendation` of `"PROCEED"` or `"ITERATE"` with a `gate_rationale`.
   - Produce `settled_decisions` (same shape as the gate output from Step 3).
   The prompt should say: "Plan this, critique your own work honestly, then decide whether the plan is ready to execute or needs revision."
2. **Update the plan output schema** (`schemas.py`): add optional fields `self_flags` (array, same shape as critique flags), `gate_recommendation` (enum: `"PROCEED"` / `"ITERATE"`), `gate_rationale` (string), and `settled_decisions` (array, same shape as gate). These are optional so existing plans and standard-robustness plans are unaffected.
3. **Wire the prompt selection**: in the prompt dispatch (`prompts.py`), when `step == "plan"` and `robustness == "light"`, use `_plan_light_prompt()` instead of the standard plan prompt.

### Step 7: Wire light-mode fast-forward in `handle_plan` (`megaplan/handlers.py`, `megaplan/_core.py`, `megaplan/data/instructions.md`)
**Scope:** Medium

At light robustness, `handle_plan` does the work of plan+critique+gate in a single handler call (backed by the one LLM call from Step 6), then fast-forwards state to `STATE_GATED`. This avoids the three precondition barriers: `handle_critique` requires `STATE_PLANNED`, `handle_gate` requires `STATE_CRITIQUED`, and gate signals read from `faults.json`.

1. **Add a light-mode fast-forward block in `handle_plan()`** (`handlers.py:823-897`). After the normal plan writing and validation, check if `robustness == "light"` and the payload contains `self_flags` and `gate_recommendation`. If so:
   - **Write self_flags into faults.json** by calling `update_flags_after_critique(plan_dir, {"flags": payload["self_flags"], "verified_flag_ids": [], "disputed_flag_ids": []}, iteration=version)` (`handlers.py:407`). This reuses the existing critique→flag-registry pipeline so gate signals work unchanged.
   - **Build gate signals** by calling `build_gate_signals(plan_dir, state)` (`evaluation.py:448`) — this reads the faults.json we just wrote.
   - **Build gate checks** by calling `run_gate_checks(plan_dir, state, command_lookup=find_command)` (`evaluation.py:536`).
   - **Build a gate artifact** from the payload's `gate_recommendation` and `gate_rationale`, using `build_gate_artifact()` (`evaluation.py:565`) and `build_orchestrator_guidance()` (`evaluation.py:591`). The gate_payload passed to these functions is synthesized from the plan output:
     ```python
     synthetic_gate_payload = {
         "recommendation": payload["gate_recommendation"],
         "rationale": payload.get("gate_rationale", ""),
         "signals_assessment": "Light-mode combined plan+critique+gate.",
         "warnings": [],
         "settled_decisions": payload.get("settled_decisions", []),
     }
     ```
   - **Write the gate artifact** to `gate.json` and `gate_signals_v{version}.json`.
   - **Advance state** through `STATE_PLANNED` → `STATE_CRITIQUED` → `STATE_GATED` (set `state["current_state"] = STATE_GATED`). Record history entries for the synthetic critique and gate steps so the audit trail is complete.
   - **Store** `state["last_gate"]` with the recommendation (same as `handle_gate` does).
   - **Return** `next_step: "finalize"` instead of `next_step: "critique"`.

2. **Important**: the normal (non-light) path in `handle_plan` is unchanged — the fast-forward block is gated on `robustness == "light"` and presence of `self_flags` in the payload.

3. **Update `infer_next_steps()`** (`_core.py:442-466`): no change needed here since `handle_plan` at light robustness advances state to `STATE_GATED`, and `infer_next_steps` for `STATE_GATED` already returns `["finalize", ...]` (`_core.py:461`).

4. **Update `data/instructions.md`** (`instructions.md:16-23`): add a note under the workflow section:
   > At light robustness, `plan` produces a combined plan+critique+gate in one call and advances directly to `gated`. Proceed to `finalize`.

5. **Update mock workers** (`workers.py`): `_mock_plan` at light robustness (check `configured_robustness(state)`) should include `self_flags`, `gate_recommendation: "PROCEED"`, `gate_rationale`, and `settled_decisions: []` in its output. At standard/thorough robustness, `_mock_plan` output stays as-is.

### Step 8: Scale review prompt depth by robustness (`megaplan/prompts.py`)
**Scope:** Small
1. **For `light` review:** Add a robustness-conditional block to `_review_claude_prompt()` and `_review_codex_prompt()` (`prompts.py:499-666`). At light robustness: trust executor evidence by default, focus on "did the success criteria pass", do not require deep cross-referencing or dig deeper on perfunctory acks.
2. **For `thorough` review:** At thorough robustness: add explicit instructions to cross-reference every claimed file against the diff line-by-line, verify sense-check acknowledgments against actual code behavior, and flag any executor note that describes rather than verifies.
3. **Standard stays as-is** — the current review prompt is the standard-depth behavior.
4. **Thread robustness** into the review prompt functions via `configured_robustness(state)` (already available).

### Step 9: Add tests for robustness-scaled workflows (`tests/test_megaplan.py`)
**Scope:** Medium

   - `faults.json` exists and contains the self-flags.
   - `gate.json` exists with the plan's `gate_recommendation`.
   - The workflow completes plan→finalize→execute→review without calling `handle_critique` or `handle_gate`.
2. **Add** `test_workflow_thorough_robustness_review_prompt` — runs with `robustness="thorough"`, verifies the review prompt contains the thorough-specific instructions (line-by-line cross-referencing language).
3. **Verify** existing `test_workflow_mock_end_to_end` still works at `robustness="standard"` (default) — no changes to this test.
