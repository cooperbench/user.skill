        # Implementation Plan: In-Progress Task Spinners on Timeline Clips

## Overview

**Goal:** Show a spinner overlay on timeline clips when there are active tasks (queued/in-progress) targeting the generation shown in that clip. The spinner should appear immediately when a task is created and disappear when it completes or fails.

**Current state:** The codebase already has most of the building blocks:
- `usePendingGenerationTasks` hook (`src/shared/hooks/tasks/usePendingGenerationTasks.ts`) — queries active tasks for a given generation ID, polls every 5s, uses realtime invalidation.
- `useStaleVariants` hook (`src/tools/video-editor/hooks/useStaleVariants.ts`) — provides the exact pattern we need: iterates asset registry entries with `generationId`, builds a `Set<string>` of asset keys with a certain condition, passes that set into `getActionRender` → `ClipAction`.
- `ClipAction` component (`src/tools/video-editor/components/TimelineEditor/ClipAction.tsx:349-362`) — already renders an absolute-positioned badge in the top-right corner for stale variants. The spinner should follow the same positioning pattern.
- Asset registry entries have `generationId` field linking clips to generations.
- `useProjectSelectionContext` available in the video editor tree for `projectId`.

**Approach:** Create a new hook `useActiveTaskClips` (analogous to `useStaleVariants`) that builds a `Set<string>` of asset keys with active tasks. This avoids calling `usePendingGenerationTasks` per-clip (which would be N separate queries). Instead, do a single bulk query for all active tasks in the project, then match them against the asset registry's generation IDs client-side — exactly how `usePendingGenerationTasks` already works internally, but for all generations at once.

## Main Phase

### Step 1: Create `useActiveTaskClips` hook (`src/tools/video-editor/hooks/useActiveTaskClips.ts`)
**Scope:** Medium

1. **Create** a new hook modeled on the pattern in `useStaleVariants` (`src/tools/video-editor/hooks/useStaleVariants.ts:28-61`).
2. **Accept** `registry: Record<string, ResolvedAssetRegistryEntry> | undefined` as input (same as useStaleVariants).
3. **Extract** all unique `generationId` values from the registry (reuse the same iteration pattern as `useStaleVariants:34-61`).
4. **Query** active tasks using React Query: `SELECT id, status, task_type, params FROM tasks WHERE project_id = ? AND status IN ('Queued', 'In Progress')`. Use `useProjectSelectionContext()` for the project ID. Poll every 5s with `staleTime: 0` (matching `usePendingGenerationTasks:110-116`).
5. **Filter** client-side using the existing `taskReferencesGeneration` function from `usePendingGenerationTasks.ts:35-74`. Import and reuse it (will need to export it).
6. **Return** `activeTaskAssetKeys: Set<string>` — the set of asset keys whose generation has at least one active task.
7. **Subscribe** to realtime task events for immediate updates (via `realtimeEventProcessor.onEvent` listening for task inserts/updates, same pattern as `useStaleVariants:117-141`).
