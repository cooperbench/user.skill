        # Implementation Plan: Test Baseline Capture in Finalize Phase

## Overview

The executor is told "if a test fails and you determine the failure is pre-existing" (execute.py:83, :383) but has no mechanism to actually determine this — it must guess. The fix captures a test baseline in the harness during the finalize phase (before execution begins), records failing test IDs in finalize.json as `baseline_test_failures`, and updates the execute/review prompts to reference concrete baseline data instead of vague heuristics.

The finalize.json payload is already mutated post-LLM by `_write_finalize_artifacts` (handlers.py:348-354), which calls `_ensure_verification_task` and `_reconcile_validation_after_mutation`. Adding baseline capture here follows the established pattern — harness-side enrichment of the LLM's output before writing artifacts.

Key constraints:
- Baseline capture must be best-effort. Projects may have no tests, a broken test runner, or an unusual test command. Failure to capture baseline must not block finalize.
- `null` means "capture failed/skipped" (unknown state); empty array `[]` means "captured successfully, zero failures found." This distinction matters for downstream prompts.
- Baseline capture runs once during `handle_finalize`. The rework path (`handle_review` → `STATE_FINALIZED` → `execute`) reuses the existing `finalize.json` without re-running finalize, so the baseline persists unchanged across rework cycles.
- megaplan is language-agnostic. Auto-detection should follow a "confident detection or skip" policy: detect `pytest` on PATH → use it; otherwise skip capture with a note. No unittest fallback — that would be a Python-specific guess for non-Python repos.
- Existing finalize tests run under `MEGAPLAN_MOCK_WORKERS=1`. The baseline capture subprocess must be stubbed in those tests to avoid real side effects.

## Phase 2: Baseline Capture Logic

### Step 2: Implement `_capture_test_baseline` in `megaplan/handlers.py`
**Scope:** Medium
1. **Add** a new function `_capture_test_baseline(project_dir: Path) -> dict` that:
   - Auto-detects test runner: check if `pytest` is on PATH via `shutil.which("pytest")`.
   - If pytest is found: run `pytest --tb=no -q --no-header` with `subprocess.run(cwd=project_dir, timeout=120, capture_output=True, text=True)`.
   - Parse pytest `-q --tb=no` output to extract failing test IDs — lines containing `FAILED` have the format `path/test.py::test_name FAILED`. Extract the test node ID (everything before ` FAILED`).
   - If no test runner is detected: return `{"baseline_test_failures": None, "baseline_test_command": None, "baseline_test_note": "No supported test runner detected on PATH (looked for: pytest). Configure execution.test_command to specify one."}`.
   - On success with failures: return `{"baseline_test_failures": ["test_a::test_1", ...], "baseline_test_command": "pytest --tb=no -q --no-header"}`.
   - On success with no failures: return `{"baseline_test_failures": [], "baseline_test_command": "pytest --tb=no -q --no-header"}`.
   - On subprocess error or timeout: return `{"baseline_test_failures": None, "baseline_test_command": cmd_string, "baseline_test_note": "Baseline capture failed: <reason>"}`.
   - The entire function body is wrapped in `try: ... except Exception as exc:` that returns `{"baseline_test_failures": None, "baseline_test_command": None, "baseline_test_note": f"Baseline capture crashed: {exc}"}` — this must never crash finalize.

2. **Config override**: if `state["config"]` contains a `test_command` key (string), use that command verbatim instead of auto-detection. When a custom command is used, still run it with `--tb=no -q --no-header` appended only if the command starts with `pytest`; otherwise run it as-is and attempt the same FAILED-line parsing. The config key is read-only from `state["config"]` — no CLI `set` plumbing is added in this iteration (see assumptions). This keeps the feature usable via `megaplan init --config test_command="make test"` or direct state.json editing without requiring new CLI infrastructure.

### Step 3: Wire baseline capture into `_write_finalize_artifacts` (`megaplan/handlers.py:348-354`)
**Scope:** Small
1. **Reorder** `_write_finalize_artifacts` to: capture baseline → ensure verification task → reconcile validation → write files. This order lets `_ensure_verification_task` see the baseline data in the payload.
   ```python
   def _write_finalize_artifacts(plan_dir, payload, state):
       baseline = _capture_test_baseline(Path(state["config"]["project_dir"]))
       payload.update(baseline)
       _ensure_verification_task(payload, state)
       _reconcile_validation_after_mutation(payload)
       atomic_write_json(plan_dir / "finalize.json", payload)
       atomic_write_json(plan_dir / "finalize_snapshot.json", payload)
       atomic_write_text(plan_dir / "final.md", render_final_md(payload))
       return sha256_file(plan_dir / "finalize.json")
   ```
2. No signature change needed — `state` is already a parameter.
