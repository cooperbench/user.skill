     ```sql
       _user_count int;
       _dyad_id uuid;
       _user_ids uuid[];

       SELECT id INTO _existing_binding_id

       IF _existing_binding_id IS NOT NULL THEN
         RAISE NOTICE 'mediator dyad binding already exists (%); skipping seed', _existing_binding_id;
         RETURN;
       END IF;
       SELECT count(*) INTO _user_count FROM users;
       IF _user_count <> 2 THEN
         RAISE NOTICE 'skipping dyad seed: user count is %, expected 2', _user_count;
         RETURN;
       END IF;
       SELECT array_agg(id ORDER BY created_at) INTO _user_ids FROM users;
       INSERT INTO dyads (id) VALUES (gen_random_uuid()) RETURNING id INTO _dyad_id;
       INSERT INTO dyad_members (dyad_id, user_id) VALUES (_dyad_id, _user_ids[1]), (_dyad_id, _user_ids[2]);
     ```

### Step 6: Migration `0024_backfill.sql` + resumable runner (`migrations/0024_backfill.sql`, `scripts/backfill_artifact_topics.py`)
**Scope:** Large
1. **Create** progress table in `0024`:

2. **Author** `scripts/backfill_artifact_topics.py` (asyncpg). For each artifact table in `['memories','themes','observations','watch_items','out_of_bounds','distillations']`:
   - **Phase A — record start time** (one-time, no-op if already set): `INSERT INTO migration_progress (table_name, backfill_started_at) VALUES ($1, now()) ON CONFLICT (table_name) DO UPDATE SET backfill_started_at = COALESCE(migration_progress.backfill_started_at, now()) RETURNING backfill_started_at;` Capture as `$started_at`.
   - **Phase B — UUID-cursor batch insert, INSERT + UPDATE in ONE transaction.** Each batch iteration must execute inside a single explicit `async with conn.transaction():` block so the cursor advance is atomic with the inserts; otherwise a crash between commits permanently skips rows. Pseudocode (the transaction wrapper is REQUIRED):
     ```python
     while True:
         async with conn.transaction():
             rows = await conn.fetch(
                 """
                 WITH ins AS (
                   INSERT INTO artifact_topics (artifact_table, artifact_id, topic_id, tagged_by_bot_id, status, created_at)
                   SELECT $1, a.id, (SELECT id FROM topics WHERE slug='relationship'),
                          'mediator', 'active', now()
                   FROM <table> a
                   WHERE a.id > $2
                   ORDER BY a.id
                   LIMIT 10000
                   ON CONFLICT DO NOTHING
                   RETURNING artifact_id
                 ),
                 -- Also need the source-table cursor advance even when ON CONFLICT skipped everything
                 src AS (
                   SELECT a.id FROM <table> a WHERE a.id > $2 ORDER BY a.id LIMIT 10000
                 )
                 SELECT (SELECT max(id) FROM src) AS new_cursor,
                        (SELECT count(*) FROM src) AS scanned
                 """, table_name, last_id)
             new_cursor, scanned = rows[0]["new_cursor"], rows[0]["scanned"]
             if scanned == 0:
                 break
             await conn.execute(
                 "UPDATE migration_progress SET last_id=$2 WHERE table_name=$1",
                 table_name, new_cursor)
             last_id = new_cursor
     ```
     Cursor advance is keyed off `src` (rows scanned), not `ins` (rows inserted), so a fully-conflicting batch still advances the cursor. The single `async with conn.transaction()` makes the insert and the cursor update commit together — no possibility of "inserted but cursor not advanced" on crash.
   - **Phase C — catch-up pass** (covers rows whose UUID sorted below the cursor at insert time on a hot DB):
     ```sql
     INSERT INTO artifact_topics (artifact_table, artifact_id, topic_id, tagged_by_bot_id, status, created_at)
     SELECT $1, a.id, (SELECT id FROM topics WHERE slug='relationship'), 'mediator', 'active', now()
     FROM <table> a
     WHERE a.created_at >= $2  -- $started_at
       AND NOT EXISTS (SELECT 1 FROM artifact_topics at2
                       WHERE at2.artifact_table=$1 AND at2.artifact_id=a.id)
     ON CONFLICT DO NOTHING;
     ```
   - After Phase C, mark `completed_at = now()`.
   - **Advisory lock** the runner key `pg_try_advisory_lock(42424242 + table_index)`. Sleep 0–100 ms between batches (configurable).
