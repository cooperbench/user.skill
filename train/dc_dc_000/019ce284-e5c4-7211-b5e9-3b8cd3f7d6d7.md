 Unify Issue Lifecycle Status & Surface History to Reviewers                                                                           
                                                        
 Context

 Issue lifecycle is tracked in two places with overlapping semantics:
 - State: issue.status — open/fixed/wontfix/false_positive/auto_resolved
 - Plan: plan.skipped[id].kind — temporary/permanent/false_positive/triaged_out

 When plan skip --permanent runs, it sets BOTH plan.skipped[id].kind = "permanent" AND issue.status = "wontfix". But temporary and
 triaged_out skips leave issue.status = "open" — creating a lie. An issue can appear "open" in state while being intentionally
 deferred in plan. This means:
 - Reviewers see [open] for deferred issues with no way to know they were already triaged
 - count_open_by_detector() overcounts (includes secretly-deferred issues)
 - Any state-only code (no plan access) gets a wrong picture

 Fix: Add deferred and triaged_out to the Status enum. Make all skip operations update state status. plan.skipped continues to exist
 for queue management and metadata (review_after, attestation, etc.), but state is always the authoritative source for disposition.

 Separately, review agents have no visibility into historical issues by default (--retrospective is opt-in) and no CLI exploration
 tools. Fix that too.

     # Before: temporary → None, triaged_out → None
     # After:

         "permanent": "wontfix",
         "false_positive": "false_positive",
         "temporary": "deferred",        # NEW
