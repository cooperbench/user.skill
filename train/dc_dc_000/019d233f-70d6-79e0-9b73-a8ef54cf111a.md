Agent-driven incremental execution persistence

## Problem
During execute, the agent does all the work (modifies files, runs tests, completes tasks) but never saves its progress to finalize.json. The prompt explicitly says 'Do not create or rewrite tracking artifacts directly.' Instead, the agent returns one big JSON blob at the end, and the handler merges task_updates into finalize.json. If the agent times out or crashes, ALL tracking is lost even though the actual code changes are in the repo.

## Solution: Make the agent save as it goes
Flip the prompt instruction. Tell the executor agent to update finalize.json directly after completing each task:
1. After finishing each task: update that task's entry in finalize.json with status, executor_notes, files_changed, commands_run. Save the file.
2. After each sense check acknowledgment: update that sense_check's entry in finalize.json with executor_note. Save the file.
3. The agent checks off tasks and adds notes in real-time as part of its natural workflow.

## Handler changes
- On timeout: read finalize.json from disk (which the agent has been updating). Whatever tasks are marked done are genuinely done. Use that as the source of truth.
- On success: the handler already re-reads finalize.json at line 1247. The structured JSON output's task_updates become a validation/reconciliation layer, not the sole source of truth.
- On timeout recovery: persist session ID, save state, leave state as 'finalized' so re-execution works. The re-run prompt already handles done vs pending tasks.

## Key insight
The handler at handlers.py:1247 already does read_json(plan_dir / 'finalize.json') after the agent finishes. If the agent updates that file during execution, those updates are already there. We just need to:
1. Tell the agent to do it (prompt change)
2. Handle the timeout path to read what's on disk instead of just re-raising
3. Reconcile agent-written updates with structured output on success

- megaplan/handlers.py — Timeout recovery in handle_execute(): read finalize.json from disk, persist session, save state

        # Implementation Plan: Agent-Driven Incremental Execution Persistence

## Overview
During execute, the agent does all the real work (edits files, runs tests) but never persists tracking to `finalize.json`. The handler merges a single structured JSON blob into `finalize.json` only after the agent completes (`handlers.py:1247-1306`). If the agent times out (`workers.py:102-107`, CliError code `worker_timeout`), the `except CliError` at `handlers.py:1242` re-raises — losing all tracking even though code changes are on disk.

**Goal:** Tell the agent to update `finalize.json` incrementally during execution. On timeout, read what's on disk, validate evidence, and return a recoverable response. On success, reconcile disk state with structured output.

**Repo shape:** Prompt in `prompts.py:371-496`. Handler in `handlers.py:1226-1371`. Workers in `workers.py` (timeout at line 102). Plan artifacts live under `plans_root(root)` (`_core.py:231-232`), which is separate from `project_dir`. The prompt currently shows `finalize.json` contents but not its filesystem path.

**Key constraint:** The handler already reads `finalize.json` at line 1247 and merges structured output on top. If the agent writes directly to `finalize.json`, those updates are already there when the handler reads. The structured output merge becomes reconciliation, not the sole source.

## Phase 1: Expose Artifact Path and Update Prompt

### Step 1: Expose `finalize.json` path in the execute prompt (`megaplan/prompts.py:371-496`)
**Scope:** Small
1. **Compute** `finalize_path = str(plan_dir / "finalize.json")` at `prompts.py:373` (where `plan_dir` is already available).
2. **Add** the absolute path to the prompt body, e.g. after line 438:
   ```
   Execution tracking file path (for incremental saves):
   {finalize_path}
   ```
3. **Replace** the instruction at line 458 (`"Do not create or rewrite tracking artifacts directly."`) with incremental-save instructions:
   - After completing each task: read `finalize.json` from the path above, update that task's `status`, `executor_notes`, `files_changed`, `commands_run`, write the full JSON back.
   - After each sense check acknowledgment: update that sense check's `executor_note` in the same file.
   - Always read the full file, update the specific entry, write the full file back. Do not use partial writes.
4. **Keep** the structured output requirement — the agent still returns `task_updates` and `sense_check_acknowledgments` in its final JSON. State explicitly that the structured output is the authoritative final summary; the disk saves are a progress checkpoint.
5. **Preserve** the re-run guidance logic (`prompts.py:399-418`) unchanged — it already reads task status from `finalize.json`, which will now reflect incremental saves from prior (possibly timed-out) runs.
6. **Note on Codex:** Codex runs with `-C project_dir` and `--full-auto` (`workers.py:575-579`). The plan directory is outside `project_dir`. If Codex's sandbox blocks writes outside the project dir, incremental saves silently fail and the feature degrades to current behavior (structured output only). The prompt should frame incremental saves as "if possible" — not a hard requirement — so Codex runs don't error on sandbox restrictions. This is acceptable degradation: Codex timeouts lose tracking as they do today; Claude timeouts gain recovery.

### Step 2: Verify schema needs no changes (`.megaplan/schemas/execution.json`)
**Scope:** Small
1. **Confirm** the structured output schema stays unchanged — the agent still returns the same JSON shape (`task_updates`, `sense_check_acknowledgments`, etc.).
2. **Confirm** no new fields are needed in the finalize schema (`.megaplan/schemas/finalize.json`) — the agent writes the same task fields (`status`, `executor_notes`, `files_changed`, `commands_run`) that the handler currently merges.

## Phase 2: Worker-Level Session Propagation

### Step 3: Resolve agent/mode/refreshed before the worker call (`megaplan/handlers.py:1240-1241`, `megaplan/workers.py:663-669`)
**Scope:** Small
1. **Extract** the `resolve_agent_mode` call from inside `run_step_with_worker` so the handler has access to `agent`, `mode`, and `refreshed` even on timeout. In `handle_execute`, call `resolve_agent_mode` directly before `run_step_with_worker`:
   ```python
   agent, mode, refreshed = worker_module.resolve_agent_mode("execute", args)
   ```
2. **Pass** these values through to `run_step_with_worker` (or call the underlying `run_claude_step`/`run_codex_step` directly). The simplest approach: add an optional `resolved` parameter to `run_step_with_worker` that skips its internal `resolve_agent_mode` call when provided.
3. **Store** `agent`, `mode`, `refreshed` in local variables available to both the success path and the except block.

### Step 4: Propagate session_id through timeout errors (`megaplan/workers.py:510-539`, `542-613`)
**Scope:** Small
1. **In `run_claude_step`** (`workers.py:526`): wrap the `run_command` call to catch `CliError` with code `worker_timeout` and attach `session_id` to `error.extra` before re-raising. Session ID is already known at line 518-524.
   ```python
   try:
       result = run_command(command, cwd=project_dir, stdin_text=prompt)
   except CliError as error:
       if error.code == "worker_timeout":
           error.extra["session_id"] = session_id
       raise
   ```
2. **In `run_codex_step`** (`workers.py:584`): same pattern. For persistent mode, `session_id` is available from `session.get("id")` at line 563. For ephemeral, session_id is None (acceptable — ephemeral sessions can't be resumed anyway).
   ```python
   try:
       result = run_command(command, cwd=Path.cwd(), stdin_text=prompt)
   except CliError as error:
       if error.code == "worker_timeout":
           error.extra["session_id"] = session.get("id")
       raise
   ```

## Phase 3: Timeout Recovery in Handler

### Step 5: Implement timeout recovery path in `handle_execute` (`megaplan/handlers.py:1240-1244`)
**Scope:** Medium
1. **Replace** the current catch-all CliError handler with timeout-specific recovery:
   ```python
   except CliError as error:
       if error.code != "worker_timeout":
           record_step_failure(plan_dir, state, step="execute",
                               iteration=state["iteration"], error=error)
           raise
       # --- Timeout recovery: read incremental progress from disk ---
   ```
2. **Read** `finalize.json` from disk (which the agent may have been updating):
   ```python
   finalize_data = read_json(plan_dir / "finalize.json")
   ```
3. **Run evidence validation** on the disk state — same checks as the success path:
   - Call `_check_done_task_evidence(finalize_data.get("tasks", []), ...)` to detect tasks claiming "done" without any evidence.
   - Call `validate_execution_evidence(finalize_data, project_dir)` to cross-check against git state.
   - Any tasks marked done but failing evidence checks get their status reset to `"pending"` with an `executor_notes` annotation like `"Reset: marked done before timeout but missing evidence"`. This prevents hallucinated checkpoints from persisting.
4. **Rewrite** `finalize.json` with the validated state:
   ```python
   atomic_write_json(plan_dir / "finalize.json", finalize_data)
   ```
5. **Count** progress for the response:
   ```python
   done_tasks = [t for t in finalize_data.get("tasks", []) if t["status"] in ("done", "skipped")]
   total_tasks = len(finalize_data.get("tasks", []))
   ```
6. **Persist session** for re-execution continuity using the values from Step 3:
   ```python
   session_id = error.extra.get("session_id")
   apply_session_update(state, "execute", agent, session_id,
                        mode=mode, refreshed=refreshed)
   ```
7. **Record** history entry with `result="timeout"` and partial progress:
   ```python
   append_history(state, make_history_entry(
       "execute", duration_ms=0, cost_usd=0.0, result="timeout",
       message=f"Timeout with {len(done_tasks)}/{total_tasks} tasks tracked on disk",
   ))
   save_state(plan_dir, state)
   ```
8. **Return** a recoverable `StepResponse` — `success=False`, `next_step="execute"`, `state=STATE_FINALIZED`:
   ```python
   return {
       "success": False,
       "step": "execute",
       "summary": f"Execute timed out. {len(done_tasks)}/{total_tasks} tasks saved from incremental progress. Re-run to continue.",
       "artifacts": ["finalize.json"],
       "next_step": "execute",
       "state": STATE_FINALIZED,
       "deviations": [f"Execution timed out after partial completion ({len(done_tasks)}/{total_tasks} tasks)"],
       "warnings": [error.message],
   }
   ```

### Step 6: Add reconciliation check on the success path (`megaplan/handlers.py:1247-1267`)
**Scope:** Small
1. **Snapshot** pre-merge task statuses right after reading `finalize.json` at line 1247:
   ```python
   pre_merge_statuses = {
       task["id"]: task.get("status", "pending")
       for task in finalize_data.get("tasks", [])
   }
   ```
2. **Keep** existing merge logic unchanged — `_validate_and_merge_batch` overwrites disk values with structured output (last-write-wins). Structured output is authoritative on success.
3. **After** the merge, compare and log advisory deviations for any discrepancies:
   ```python
   for task in finalize_data.get("tasks", []):
       pre = pre_merge_statuses.get(task["id"], "pending")
       post = task.get("status", "pending")
       if pre != "pending" and pre != post:
           deviations.append(
               f"Advisory: task {task['id']} was '{pre}' on disk but '{post}' in structured output"
           )
   ```
