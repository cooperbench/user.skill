### `remote-artifact` adapter — full implementation lands here

Schema reservation existed in S3 (the stub at `astrid/core/adapter/remote_artifact.py` rejects with the deferral message). Now it becomes real.

**The adapter owns:**
- **Dispatch** — submit the remote job (the executor pack handles the actual API calls; the adapter is the framework wrapper).
- **Status polling** — periodic check of remote job state.
- **Artifact fetch** — pull outputs into the canonical `produces/` path on completion.
- **Checksum verification** — sha256 each fetched artifact; compare against the remote-declared checksum if provided. Mismatch → `check_status: mismatch` + step fails.
- **Partial-failure semantics** — if 3 of 5 artifacts arrive cleanly and 2 are missing/corrupt, the step is in `awaiting-fetch` with the missing/corrupt items enumerable.

**Step states added:**
- `awaiting-fetch` — remote job done, but at least one artifact is missing or failed checksum. Step does NOT complete; cursor does NOT advance.

**New verb:**
- `astrid step retry-fetch <step-id>` — re-attempt fetch + checksum for a step in `awaiting-fetch`. Idempotent. Promotes step to `completed` if all artifacts now resolve.

**Completion contract:** "remote done AND artifacts pulled AND checksums match." Anything less leaves the step in `awaiting-fetch`.

## Overview

### Step 2: Stand up the `remote-artifact` adapter shell (`astrid/core/adapter/remote_artifact.py`)
**Scope:** Medium
1. **Replace** the stub class at `astrid/core/adapter/remote_artifact.py:9-40` with a real `RemoteArtifactAdapter` that conforms to the `Adapter` protocol used by `LocalAdapter` (`astrid/core/adapter/local.py:34-156`) and `ManualAdapter` (`astrid/core/adapter/manual.py:34-116`):
   - `dispatch(step, run_ctx) -> DispatchResult` — invoke the pack command (same subprocess pattern as `local.py`) but record the returned remote-job handle (job_id + endpoint) in a `dispatch.json` sidecar in the step root.
   - `poll(step, run_ctx) -> PollResult` — run the pack's poll subcommand using `poll_interval_seconds` (default 30s) from the step record; structured stdout returns `{state, artifacts: [{name, url, sha256?}]}`.
   - `complete(step, run_ctx) -> CompleteResult` — when remote state is terminal, fetch each declared artifact into `steps/<id>/v<N>/produces/`, sha256 it, compare to declared checksum if present, and decide:
     - all artifacts present + checksums match → `CompleteResult` indicating `completed`.
     - any artifact missing or checksum mismatch → emit `step_awaiting_fetch`, do NOT signal completion. Enumerate missing/corrupt items in the event payload.
2. **Document** failure modes in a one-line docstring. Parallelize fetches with a `concurrent.futures.ThreadPoolExecutor` — failures in one artifact do not abort others.
3. **Add** new step field `poll_interval_seconds: int | None` to the step schema (validator I1 accepts it; default 30s).

**Scope:** Medium
