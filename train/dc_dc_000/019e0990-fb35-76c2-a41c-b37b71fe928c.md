        # Implementation Plan: Capability Contracts and Workflow Workbench Reporting

## Overview
Build a worker-local capability-contract source of truth and report loop that separates product capabilities from task types, route keys, VibeComfy template bindings, live cases, and artifact expectations. The repo already has the raw ingredients: route decisions in `source/task_handlers/tasks/template_routing.py`, live matrix definitions in `scripts/live_test/matrix.py`, live report JSON/Markdown under `scripts/live_test/runs/`, VibeComfy subprocess boundaries in `source/models/comfy/vibecomfy_adapter.py`, and worker preflight checks for `../vibecomfy/template_index.json` plus `../vibecomfy/workflow_corpus/manifests/coverage.json`.

The simplest useful first slice is not a UI workbench. It is a durable registry plus a validator/report generator that can answer: which app capability maps to which route, which VibeComfy template or WGP-only path implements it, which variant axes are covered or fail-closed, which live case proves it, and what blocks parity. This creates real leverage for future import/fork/scratch workflow tooling without duplicating VibeComfy’s graph validators.

## Phase 1: Foundation — Contract Data and Importable Helpers

### Step 1: Add the contract package (`scripts/capability_contracts/`)
**Scope:** Medium
1. **Create** `scripts/capability_contracts/__init__.py`, `scripts/capability_contracts/model.py`, `scripts/capability_contracts/loaders.py`, and `scripts/capability_contracts/report.py`.
2. **Use only stdlib** (`json`, `dataclasses`, `argparse`, `pathlib`) so the tool remains cheap in CI and live-test environments.
3. **Model** the status vocabulary as constants: `unknown`, `inventoried`, `routed`, `template_bound`, `static_valid`, `runtime_green`, `parity_reviewed`, `app_ready`, `wgp_only_contract_validated`, `unsupported_fail_closed`.
4. **Keep VibeComfy validation as evidence consumption**, not reimplementation: load `template_index.json` and `workflow_corpus/manifests/coverage.json`; optionally expose command hints such as `python -m vibecomfy.cli validate <template>` but do not inspect workflow graph internals in worker.

### Step 2: Add the machine-readable registry (`scripts/capability_contracts/contracts.json`)
**Scope:** Large
1. **Define** one contract row per product capability or justified exception, with fields like:
   ```json
   {
     "capability_id": "video.travel_segment.wan22_vace.video_source.flow",
     "name": "Travel segment, Wan 2.2 VACE flow, video source continuity",
     "task_types": ["travel_segment"],
     "route_keys": ["travel_segment__model-wan22_vace__guidance-vace_flow__continuity-video_source__profile-default"],
     "implementation": "vibecomfy",
     "template_id": "video/wanvideo_wrapper_22_14b_vace_cocktail",
     "variant_axes": {"control": ["flow"], "source_media": ["video_source"], "lora": ["fail_closed_dynamic_user_lora"]},
     "artifact_contract": {"kind": "video", "extensions": [".mp4", ".webm"], "storage_class": "intermediate", "generation_row": "required"},
     "app_sources": [{"path": "../reigh-app/supabase/functions/create-task", "note": "resolver/enqueue surface"}],
     "live_cases": ["travel_segment_wan22_vace_flow_video_source"],
     "status": "runtime_green",
     "notes": "Wan2GP parity review still pending."
   }
   ```
2. **Seed** all currently live-green VibeComfy-supported cases from `scripts/live_test/matrix.py`, including direct image/edit/video routes and Wan VACE travel/join routes.
3. **Add WGP-only contract rows** for orchestration/stitching paths (`travel_orchestrator`, `join_clips_orchestrator`, `edit_video_orchestrator`, `travel_stitch`, `join_final_stitch` where applicable) with `implementation: "wgp"` and artifact/DB behavior expectations instead of `template_id`.
4. **Represent fail-closed variant axes explicitly**, especially dynamic LoRAs, multiple LoRAs beyond supported slots, Flux Klein non-4B variants, missing control videos, and unsupported LTX/Wan rows.

## Phase 2: Evidence Loaders and Drift Detection

### Step 3: Load route and live matrix evidence (`template_routing.py`, `scripts/live_test/matrix.py`)
**Scope:** Medium
1. **Import** `SPRINT_2_SELECTOR_MAP`, `SECTION3A_ROUTE_SUPPORT_MAP`, and `RouteSupportState` from `source/task_handlers/tasks/template_routing.py` without importing WGP or VibeComfy.
2. **Import** `MATRIX` or `build_matrix()` from `scripts/live_test/matrix.py` and normalize `MatrixCase.name`, `task_type`, `route_key`, `support_state`, and `selected_template_id`.
3. **Validate** that every route with `vibecomfy_supported` has exactly one or more contract rows, or a contract row with an explicit exception status.
4. **Validate** that matrix case `selected_template_id` agrees with the registry and route selector entry where all three are present.

### Step 4: Load VibeComfy static evidence (`../vibecomfy/template_index.json`, `../vibecomfy/workflow_corpus/manifests/coverage.json`)
**Scope:** Medium
1. **Read** VibeComfy files from `VIBECOMFY_PATH` when set, otherwise `../vibecomfy`.
2. **Mark** `template_bound` when a contract has a template id, and `static_valid` only when that template appears in `template_index.json` or the contract includes a narrowly justified static-evidence exception.
3. **Flag current likely gaps**: several worker route template ids are not in the inspected `template_index.json` (`image/z_image_img2img`, Wan 2.2 T2I/I2V/VACE, animate, basic upscale/enhance). The implementation should make these visible as report blockers or require regenerating/updating VibeComfy’s index, not silently pass them.
4. **Cross-link** coverage manifest workflows where possible by template id, workflow id, capability, or declared model family, but treat missing corpus links as a report warning unless the contract status claims `static_valid` or higher.

### Step 5: Parse latest live evidence (`scripts/live_test/runs/*/report.json`)
**Scope:** Medium
1. **Prefer** `report.json` over Markdown because `scripts/live_test/report.py` writes structured `results` with `case_name`, `task_type`, final status, output, and generation IDs.
2. **Select** the newest passing evidence per live case where `final_status == "Complete"`, output exists, generation IDs exist, and no error summary is present.
3. **Attach** evidence refs to contract rows and downgrade/flag any `runtime_green` row whose live case lacks passing evidence.
4. **Keep Markdown parsing out of the first slice** unless an old run has no JSON counterpart.

## Phase 3: CLI, Generated Tracker, and Agent UX

### Step 6: Implement the report CLI (`python -m scripts.capability_contracts.report`)
**Scope:** Large
1. **Add** subcommands or flags:
   ```bash
   python -m scripts.capability_contracts.report validate
   python -m scripts.capability_contracts.report status --json
   python -m scripts.capability_contracts.report render --out docs/vibecomfy-app-parity-tracker.md
   python -m scripts.capability_contracts.report next-actions
   ```
2. **Make `validate` fail nonzero** for hard drift: missing contract rows for supported routes, template mismatch, missing artifact contract, missing variant accounting, invalid status, or `runtime_green` without passing live evidence.
3. **Make `status --json` deterministic** with stable sort order by status, capability id, and route key.
4. **Make `next-actions` actionable**, grouping blockers by missing app source, route binding, VibeComfy template index, live evidence, artifact contract, and parity review.

### Step 7: Generate the tracker (`docs/vibecomfy-app-parity-tracker.md`)
**Scope:** Medium
1. **Replace** hand-maintained live-green tables with generated sections from registry plus evidence.
2. **Include** status legend, summary counts, app-ready/runtime-green/static blockers, WGP-only validated paths, unsupported fail-closed paths, and next actions.
3. **Preserve** useful human context from the current tracker where it is still true, but clearly mark the file as generated and point edits to `scripts/capability_contracts/contracts.json`.
4. **Run** the generator and inspect the diff for accidental loss of important parity notes.

## Phase 4: Tests, Critique, Gate, and Finalize

### Step 8: Add drift tests (`tests/test_capability_contracts.py`)
**Scope:** Large
1. **Assert** every `vibecomfy_supported` route in `SPRINT_2_SELECTOR_MAP` and `SECTION3A_ROUTE_SUPPORT_MAP` has at least one contract row or explicit justified exception.
2. **Assert** every `vibecomfy_supported` live matrix case has a matching contract row and live evidence pointer when the contract status is `runtime_green` or higher.
3. **Assert** every VibeComfy contract has a `template_id`, artifact contract, variant axes, and either template-index evidence or an explicit static-evidence blocker.
4. **Assert** WGP-only contracts have no `template_id` and do have DB/artifact behavior expectations.
5. **Assert** `docs/vibecomfy-app-parity-tracker.md` is regenerated from current data by comparing generated text to file contents.

### Step 9: Run cheap validation first, then targeted tests
**Scope:** Small
1. **Run** JSON validation on `contracts.json`.
2. **Run** `python -m scripts.capability_contracts.report validate`.
3. **Run** `pytest tests/test_capability_contracts.py tests/test_template_routing.py scripts/live_test/tests/test_primitives.py`.
4. **Only then run broader tests** if the targeted set is green and the changes touched shared routing behavior.

### Step 10: Critique and close obvious gaps
**Scope:** Medium
1. **Use** `next-actions` output after the first passing implementation to identify obvious missing rows or stale template-index refs.
2. **Close data gaps in worker registry/reporting** when they are clearly contract/evidence problems.
3. **Do not modify reigh-app** unless the report proves app enqueue truth cannot be referenced from worker-local metadata; record app source refs instead.
4. **Do not modify VibeComfy workflow/template mechanics** unless the only blocker is a stale generated index and the fix is to run/commit the appropriate VibeComfy-owned artifact on its branch.
