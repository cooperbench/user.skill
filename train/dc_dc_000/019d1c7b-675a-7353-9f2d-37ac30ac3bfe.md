## Overview

Currently, lifecycle phase is determined by **three independent code paths** that can disagree:

1. **`current_lifecycle_phase()`** (`refresh_lifecycle.py:100`) — returns persisted mode (`"plan"` / `"execute"`) from `refresh_state["lifecycle_phase"]`. Also performs legacy migration **with mutation on read** (line 131: writes back migrated value). Falls back to heuristics based on `postflight_scan_pending()` and `plan_start_scores`.

2. **`_resolve_reconcile_display_phase()`** (`pipeline.py:99`) — derives display phase from queue contents during reconciliation.

3. **`_derive_display_phase()`** (`snapshot.py:313`) — derives display phase from materialized queue item partitions. Must be kept manually in sync with #2.

**Key problems:**
- `current_lifecycle_phase()` mutates plan data on read (legacy migration writes)
- No single function takes (plan, state) → (persisted_mode, display_phase)
- Display-phase derivation rules are duplicated between pipeline.py and snapshot.py with no shared code
- Marker invariants (postflight_scan_completed_at, subjective_review_completed_at, lifecycle_phase) are undocumented

**Constraints:**
- Data migration code must be preserved (backward compat policy)
- `_set_lifecycle_phase` is already single-writer via `pipeline.reconcile_plan()` (enforced by prior refactor)
- Display phase constants are never persisted — only `"plan"` / `"execute"` are persisted

## Step 2: Make `current_lifecycle_phase()` a pure reader (`engine/_plan/refresh_lifecycle.py`)
**Scope:** Small

1. **Remove** the mutation block (lines 106-132) from `current_lifecycle_phase()`. Replace with a pure read: check `refresh_state["lifecycle_phase"]`, return if valid.
2. **Preserve** the heuristic fallback (lines 133-137) for plans that have never had a phase set (fresh/empty plans). Explicit default rule:
   - If `postflight_scan_pending(plan)` → return `"plan"`
   - If `plan.get("plan_start_scores")` → return `"execute"`
   - Else → return `"execute"`

   This matches the existing behavior tested in `test_refresh_lifecycle.py:106-121`: empty plan returns `"plan"`, plan with `plan_start_scores` returns `"execute"`.
3. **No callers change** — they all still call `current_lifecycle_phase()` with the same semantics. The only difference: no mutation occurs on read.

```python
def current_lifecycle_phase(plan: PlanModel) -> str:
    """Return the persisted lifecycle mode: 'plan' or 'execute'.

    Pure reader — never mutates plan. Legacy migration runs at
    _load_validated_plan() time via migrate_legacy_phase().
    For fresh plans without a persisted marker, falls back to heuristics.
    """
    refresh_state = plan.get("refresh_state")
    if isinstance(refresh_state, dict):
        phase = refresh_state.get(_LIFECYCLE_PHASE_KEY)
        if isinstance(phase, str) and phase in _VALID_PHASES:
            return phase
    # Fallback for plans that haven't been through reconcile yet.
    if postflight_scan_pending(plan):
        return "plan"
    if plan.get("plan_start_scores"):
        return "execute"
    return "execute"
```

## Step 3: Create `derive_display_phase()` shared pure function (`engine/_plan/refresh_lifecycle.py`)
**Scope:** Medium

1. **Create** `derive_display_phase()` — a pure function that takes boolean phase signals and returns a display phase string. The priority chain **matches the existing snapshot ordering** (`snapshot.py:331-350`):

```python
def derive_display_phase(
    *,
    has_initial_review: bool,
    has_postflight_assessment: bool,
    has_workflow: bool,
    has_triage: bool,
    has_review_postflight: bool,
    has_execution: bool,
    fresh_boundary: bool,
    prefer_scan: bool,
) -> str:
    """Canonical display-phase derivation from abstract signals.

    Priority order matches snapshot._derive_display_phase (the user-visible
    path). Both pipeline and snapshot compute boolean signals from their
    respective inputs and call this function.

    Priority chain:
      initial_review > prefer_scan > assessment > workflow > triage
      > review_postflight > execute > scan (default)
    """
    if fresh_boundary and has_initial_review:
        return LIFECYCLE_PHASE_REVIEW_INITIAL
    if prefer_scan:
        return LIFECYCLE_PHASE_SCAN
    if has_postflight_assessment:
        return LIFECYCLE_PHASE_ASSESSMENT_POSTFLIGHT
    if has_workflow:
        return LIFECYCLE_PHASE_WORKFLOW_POSTFLIGHT
    if has_triage:
        return LIFECYCLE_PHASE_TRIAGE_POSTFLIGHT
    if has_review_postflight:
        return LIFECYCLE_PHASE_REVIEW_POSTFLIGHT
    if has_execution:
        return LIFECYCLE_PHASE_EXECUTE
    return LIFECYCLE_PHASE_SCAN
```

**Critical signal-mapping rules** (derived from snapshot.py:230-255 and existing test assertions):
- `workflow::run-scan` and `workflow::deferred-disposition` → `prefer_scan=True` (NOT `has_workflow`). These are scan-phase items. Tests: `test_sync_split_modules_direct.py:998-1004` and `:1201-1203` assert `LIFECYCLE_PHASE_SCAN`.

**Note:** The current pipeline code (line 116) incorrectly collapses ALL `PRE_REVIEW_WORKFLOW_IDS` into workflow phase, which disagrees with snapshot's scan/workflow split. This refactor **fixes** that pre-existing disagreement by aligning pipeline with snapshot's signal semantics.

```python
# Constants for scan-phase workflow items (snapshot treats these as scan_items)
_SCAN_PHASE_WORKFLOW_IDS = {
    WORKFLOW_DEFERRED_DISPOSITION_ID,
    WORKFLOW_RUN_SCAN_ID,
}

def _resolve_reconcile_display_phase(plan, state, *, result, policy) -> str:
    order = [item for item in plan.get("queue_order", []) if isinstance(item, str)]
    subjective_ids = [item for item in order if item.startswith("subjective::")]
    unscored_ids = set(getattr(policy, "unscored_ids", ()) or ())
    skipped = plan.get("skipped") or {}

    # Split workflow IDs: scan-phase vs true workflow
    has_scan_workflow = any(item in _SCAN_PHASE_WORKFLOW_IDS for item in order)
    has_true_workflow = (
        any(
            item.startswith("workflow::") and item not in _SCAN_PHASE_WORKFLOW_IDS
            for item in order
        )
        or bool(result.workflow_injected_ids)
    )

    # Review-postflight: triage-gated review findings first, bare open_review_ids
    # ONLY as fallback when no real execution work exists (see priority chain below)
    triage_snapshot = build_triage_snapshot(plan, state)
    triage_gated_review = (
        triage_snapshot.triage_has_run
        and not triage_snapshot.has_triage_in_queue
        and not triage_snapshot.is_triage_stale
        and bool(triage_snapshot.live_open_ids)
    )

    has_real_work = any(
        not item.startswith(("subjective::", "workflow::", "triage::"))
        for item in order if item not in skipped
    )

    # open_review_ids fallback: only when no real execution work exists
    has_review_postflight = triage_gated_review or (
        not has_real_work and bool(open_review_ids(state))
    )

    return derive_display_phase(
        has_initial_review=any(sid in unscored_ids for sid in subjective_ids),
        has_postflight_assessment=(
            bool(subjective_ids)
            and not any(sid in unscored_ids for sid in subjective_ids)
        ),
        has_workflow=has_true_workflow,
        has_triage=(
            bool(result.triage and (result.triage.injected or result.triage.deferred))
            or any(item.startswith("triage::") for item in order)
        ),
        has_review_postflight=has_review_postflight,
        has_execution=has_real_work,
        fresh_boundary=not bool(plan.get("plan_start_scores")),
        prefer_scan=has_scan_workflow,
    )
```

```python
"""Helpers for the persisted queue lifecycle phase.

Marker invariants
-----------------
Three markers live in ``plan["refresh_state"]``:

``lifecycle_phase`` : ``"plan"`` | ``"execute"``
    The persisted lifecycle mode.  Written ONLY by ``_set_lifecycle_phase()``
    (called from ``reconcile_plan()`` in pipeline.py).  Legacy values are
    migrated at ``_load_validated_plan()`` time by ``migrate_legacy_phase()``.

    Transitions:
    - plan → execute: planning work drains from queue
      (no workflow/triage items remain)
    - execute → plan: ``invalidate_postflight_scan()`` clears the scan marker,
      or new review items trigger re-planning via reconcile

``postflight_scan_completed_at_scan_count`` : int
    Set by ``mark_postflight_scan_completed()``.
    Cleared by ``invalidate_postflight_scan()``
    (when objective queue work changes).

``subjective_review_completed_at_scan_count`` : int
    Set by ``mark_subjective_review_completed()``.
    Carried forward by ``carry_forward_subjective_review()``
    across cycle boundaries.

Display phase (never persisted)
-------------------------------
Display phases (review_initial, assessment, workflow, triage, execute, scan)
are derived from queue contents by ``derive_display_phase()`` — a shared pure
function called by both ``pipeline._resolve_reconcile_display_phase()`` and
``snapshot._derive_display_phase()``.  Priority order::

    initial_review > prefer_scan > assessment > workflow > triage
    > review_postflight > execute > scan

``user_facing_mode()`` collapses display phases back to ``"plan"``
or ``"execute"`` for user output.
"""
```
