        # Implementation Plan: Document Subagent Orchestration Mode

## Overview

Megaplan has two orchestration modes — **inline** (default) and **subagent** — but documentation coverage is uneven. The critique revealed a critical file-targeting error in v1: the plan treated `.claude/skills/megaplan.md` as the authoritative source, but it is a **derived mirror**. The actual packaging pipeline is:

```
megaplan/data/instructions.md                    → shared base (ALL agents: Claude, Codex, Cursor, AGENTS.md)
megaplan/data/claude_subagent_appendix.md        → Claude-only addition
bundled_global_file("claude_skill.md")           → SKILL_HEADER + instructions.md + appendix → ~/.claude/skills/megaplan/SKILL.md
bundled_global_file("skill.md")                  → SKILL_HEADER + instructions.md            → ~/.codex/skills/megaplan/SKILL.md
bundled_agents_md()                              → instructions.md                            → AGENTS.md (local setup)
```

**Key constraints from packaging:**
- `instructions.md` feeds ALL consumers. Adding Claude-specific subagent content there would bleed into Codex, Cursor, and local AGENTS.md installs.
- `claude_subagent_appendix.md` is the correct place for all Claude-specific subagent content. It is already appended only to the Claude skill output.
- `.claude/skills/megaplan.md` (checked into this repo) is a convenience mirror. It must be regenerated after editing the source files.

**Key constraint from implementation:**
- The subagent protocol (breakpoints, resume, safeguards) is a **documentation-level contract** — there is no Python runtime implementation. Breakpoint type strings exist only in docs. Validation means doc-to-doc consistency, not doc-to-code matching.

**Worker agents are mode-agnostic** (settled decision SD-001). Workers receive identical prompts from `megaplan/prompts/*.py` regardless of orchestration mode. The per-stage documentation requirement is satisfied by explicitly stating this fact, not by adding mode-awareness to worker prompts.
