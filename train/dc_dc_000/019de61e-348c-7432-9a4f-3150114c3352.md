        # Implementation Plan: Discord Typing/WPM Pacing Throttler

## Overview
Veas already has the right shape for this: Discord-specific pacing is centralized in `app/services/pacer.py`, final outbound sends route through `app/services/agentic.py` into `app/services/messaging.py`, and incremental bubbles route through `app/services/tools/read_tools.py` into `send_outbound_part`. The existing hooks already suppress low-level Discord typing indicators when high-level pacing is active, so the simplest fix is to strengthen the pacer’s deterministic timing model and keep send-time stale-turn checks at the existing hook boundaries.

The main gap is that `answer_typing_delay_s` currently returns `len(text) / chars_per_s` clamped by min/max, but there is no explicit jitter/cap setting and the long-message pulse loop can spend configured off-gap time as part of the total composition budget instead of preserving the intended visible composition duration. Incremental follow-up bubbles also use a short fixed pulse instead of a length-based composition duration.

## Main Phase

### Step 1: Lock Down Current Call Paths (`app/services/pacer.py`, `app/main.py`, `app/services/agentic.py`, `app/services/tools/read_tools.py`, `app/services/messaging.py`)
**Scope:** Small
1. **Confirm** that only Discord live turns get `before_paced_send` from `app/main.py:67` and that it calls `DiscordPacer.perform_send_typing` before provider send at `app/main.py:78`.
2. **Preserve** the final-send stale-turn checks around `before_provider_send` in `app/services/agentic.py:702` and `app/services/agentic.py:711`.
3. **Preserve** incremental stale-turn checks before and after paced waits in `app/services/tools/read_tools.py:116` and `app/services/tools/read_tools.py:143`.
4. **Do not** move provider-specific logic into `app/services/messaging.py`; keep non-Discord providers unaffected by leaving `send_outbound` and `send_outbound_part` generic beyond invoking `before_provider_send`.

### Step 2: Add Explicit Composition Settings (`app/config.py`, `app/models/user.py`)
**Scope:** Small
1. **Add** a jitter setting such as `discord_pacing_answer_typing_jitter_ratio` or `discord_pacing_answer_typing_jitter_s` near `app/config.py:65`.
2. **Keep** existing settings for chars/sec, min, max, visible pulse duration, off-gap duration, and pulse-gap caps as the primary control surface.
3. **Optionally expose** jitter through user pacing preferences in `app/models/user.py:89` only if per-user jitter is needed; otherwise keep it app-level to avoid over-expanding the preference schema.
4. **Update** `tests/test_config.py` and `tests/test_pacing_storage.py` only for settings/preference fields actually added.

### Step 3: Centralize Timing Computation (`app/services/pacer.py`)
**Scope:** Medium
1. **Replace or extend** `answer_typing_delay_s` at `app/services/pacer.py:294` with a deterministic, testable composition-duration helper that accepts `send_kind` and uses `answer_chars_per_s`, min, max, and jitter.
2. **Inject randomness safely** through the pacer, for example by accepting an optional random function in `DiscordPacer.__init__`, so tests can force zero jitter or known jitter without monkeypatching global `random`.
3. **Apply** the same composition-duration helper to final, incremental first, and incremental next sends. Incremental next should still honor `discord_multi_message_delay_s` and `discord_pacing_incremental_typing_pulse_min_gap_s`, but it should not bypass length-based composition entirely.
4. **Record** computed durations in pacing event snapshots where useful, for example `composition_s`, `send_kind`, and `part_index`, without changing persisted schema.

### Step 4: Make Long-Message Pulses Match the Composition Budget (`app/services/pacer.py`)
**Scope:** Medium
1. **Refactor** `_perform_answer_typing_after_user_wait` at `app/services/pacer.py:407` into a reusable pulse runner that waits for the computed composition duration while sending typing pulses.
2. **Ensure** long messages emit a typing pulse, wait visible duration, record a `typing_stop`, wait a short off-gap, and then restart typing when there is still composition time remaining.
3. **Respect** Discord typing expiry by keeping `discord_pacing_typing_visible_s` at or below the expiry window and continuing to use `discord_pacing_typing_pulse_min_gap_s` as the normal restart cap.
4. **Avoid** counting off-gap pauses as visible typing time if the requirement is interpreted as minimum composition duration; the wall-clock wait can be composition plus natural pauses, but visible pulse time should still be bounded by expiry.

### Step 5: Preserve Stale-Turn Interruptions After Waits (`app/services/agentic.py`, `app/services/tools/read_tools.py`)
**Scope:** Small
1. **Keep** final sends checking `_newer_inbound_exists` before paced wait and immediately after paced wait at `app/services/agentic.py:702` and `app/services/agentic.py:714`.
2. **Keep** incremental sends checking `_newer_inbound_exists` before any wait and after `ctx.before_paced_send` at `app/services/tools/read_tools.py:116` and `app/services/tools/read_tools.py:145`.
3. **Add focused tests** that simulate a new inbound arriving during the pacer’s sleep and assert no provider send occurs for both final and incremental paths.

### Step 6: Add Focused Tests (`tests/test_pacer.py`, `tests/test_agentic_lifecycle.py` or `tests/test_send_outbound.py`)
**Scope:** Medium
1. **Add pacer unit tests** for computed duration: short text clamps to min, long text clamps to max, chars/sec changes duration, and jitter is bounded/deterministic under injected randomness.
2. **Extend long-message pulse tests** in `tests/test_pacer.py` to assert multiple `typing_start` events, `typing_stop` gaps, and total waited time meets the computed composition behavior.
3. **Update incremental tests** around `test_incremental_followup_typing_uses_short_gap` to verify incremental next bubbles use length-based composition while still honoring short inter-bubble rhythm.
4. **Add interruption tests** for final and `send_message_part` paths where fake sleep inserts a newer inbound before `before_provider_send` returns, then assert the result is interrupted/skipped and provider send is not called.

### Step 7: Validation Pass
**Scope:** Small
1. **Run** targeted tests first: `pytest tests/test_pacer.py tests/test_agentic_lifecycle.py tests/test_send_outbound.py`.
2. **Run** config/storage tests if settings or preferences changed: `pytest tests/test_config.py tests/test_pacing_storage.py`.
3. **Finish** with the full test suite if targeted checks pass: `pytest`.
