§A. **Did The Fixes Hold?**

**1. Cursor semantics on plan mutation: partially closed.**  
The doc now says `plan.json` is initial-only, mutations replay into an effective plan, and cursor stores `(step_id, step_version, dispatch_event_hash)` instead of an index ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:52), [idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:175)). That closes the obvious “insert before cursor moves current work” bug. But it still lacks a precise replay model: no mutation base revision, no conflict semantics for two plan mutations against the same effective plan, no ordering model for nested children, repeats, and inserted steps. “Adding behind the cursor is a no-op for execution” ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:183)) is especially under-specified: behind relative to which versioned effective tree?

**2. Location-agnostic execution: partially closed.**  
The three adapters are a real improvement ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:56), [idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:184)). `remote-artifact` now has actual completion semantics. But `manual` still hand-waves the hardest part: “agent is responsible for landing outputs” ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:186)) means provenance and artifact transfer are outside the framework. Also, “LLM calls = local or manual” in the hype port ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:223)) leaks uncertainty back into orchestration.

**3. Takeover race: partially closed, with a new race.**  
The lease epoch is the right primitive ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:53), [idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:91)). But it only works if epoch check + event append + any side effects are one critical section. Current `append_event` verifies, rereads, computes previous hash, then appends without a file lock or compare-on-last-hash ([events.py](/Users/user_c042661f/Documents/reigh-workspace/Astrid/astrid/core/task/events.py:25)). A stale writer can pass epoch, a takeover can bump epoch, and the stale writer can still append unless the proposed CAS wraps the append itself.

**4. Sprint 4 over-stuffed: closed.**  
Splitting 4a/4b is materially better ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:213), [idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:241)). The one-week hype soak gate is also good ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:245)). 4b is still chunky, but no longer absurd.

**5. Executor/orchestrator distinction collapsed too aggressively: partially closed.**  
The authoring/runtime split fixes the conceptual over-collapse ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:55), [idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:171)). But “same pack layout on disk” plus “legacy `OrchestratorDefinition` YAML removed” ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:258)) hides a migration cliff: the current validator still distinguishes executor/orchestrator folders ([plan.py](/Users/user_c042661f/Documents/reigh-workspace/Astrid/astrid/core/task/plan.py:17), [plan.py](/Users/user_c042661f/Documents/reigh-workspace/Astrid/astrid/core/task/plan.py:272)). The abstraction is cleaner in prose than in the file model.

§B. **New Gaps Introduced By The Edits**

- Step version storage is bolted on, not integrated. New versions live under `steps/<id>/v2/` ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:181)), but current pathing has no version dimension and puts iterations/items directly under the step path ([plan.py](/Users/user_c042661f/Documents/reigh-workspace/Astrid/astrid/core/task/plan.py:115)). You need a canonical path rule for `steps/<id>/vN/iterations/NNN` vs legacy `steps/<id>/iterations/NNN`.

- `superseded_by: str?` is too weak ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:164)). Supersession needs at least `(step_id, from_version, to_version, scope)` because repeats introduce “future iterations only” semantics ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:179)).

- Inbox semantics will break under nested/versioned steps unless fixed. Current inbox compares only the final step id, not full path/version ([inbox.py](/Users/user_c042661f/Documents/reigh-workspace/Astrid/astrid/core/task/inbox.py:232)). That was already fragile; versioned nested steps make it wrong.

- The event hash chain is treated as an audit backbone, but it does not serialize concurrent writers. The proposal leans harder on events for mutations and claims ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:175), [idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:190)), while current appends are not atomic across read/verify/append ([events.py](/Users/user_c042661f/Documents/reigh-workspace/Astrid/astrid/core/task/events.py:31)).

§C. **Things Both Review Passes Missed**

1. **No state machine.** There are statuses scattered through prose: dispatched, awaiting-fetch, completed, aborted, tombstoned, superseded. There is no authoritative run/step state transition table. That is load-bearing.

2. **Artifact audit is still path-based.** Final outputs are just `{path, kind, ...}` ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:126)). For an audit claim, record size/hash/check result at finalize time, not only a mutable filesystem pointer.

3. **Plan mutation validation is absent.** Adding/editing steps must re-run schema validation, duplicate path checks, produces reference checks, adapter validation, and repeat-source validation against the effective tree. The deliverables mention verbs, not invariants ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:195)).

4. **Session identity is underspecified.** Assignees are explicit ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:64)), but “current session’s identity” for claim default ([idea.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/idea.md:190)) has no schema. Single-user does not remove the need for stable agent ids.
