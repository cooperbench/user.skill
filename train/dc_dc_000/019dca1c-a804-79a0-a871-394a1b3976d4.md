**Root Cause**

Not one issue. I’d group them into three families:

1. **Gesture/input abstraction is underbuilt**: bugs 1 and 2. Modifier state and click intent should be derived from the actual pointer/click event, not ambient React state or native `click` behavior. The right pattern already exists in `useLassoSelection` at `src/features/gallery/components/GenerationsPane/hooks/useLassoSelection.ts:37` and `:140`; the weaker pattern remains in `useModifierKeys` at `src/features/gallery/components/GenerationsPane/hooks/useModifierKeys.ts:17`.

2. **Selection/composer state is split across inconsistent reactive channels**: bugs 3, 4, 5. The store has real cross-surface policy, but exposes it as `clearGallery?: boolean` flags on low-level timeline mutations at `src/shared/state/selectionStore.ts:450` and `:501`. Then chat composes gallery from Zustand and timeline from React context at `src/tools/video-editor/components/AgentChat/AgentChat.tsx:144` and `:175`, which explains the one-commit lag noted at `:185`.

3. **Query-composition bug is separate**: bug 6. It is the same *style* of problem, low-level API composition leaking upward, but not the same architectural root as selection. The fix in `src/shared/hooks/projects/useProjectGenerations.ts:71` correctly centralizes PostgREST OR composition.

**Abstraction Level**

Pick **(b): abstractions are slightly too low**.

The decomposition is not wrong. Gallery, timeline, and agent chat are legitimate surfaces. The problem is that the domain operates at “selection intent changes current attachment set,” while the code exposes “mutate this slice, maybe clear that slice.”

Concrete evidence:

- `selectTimelineClip(..., syncOptions?: { clearGallery?: boolean })` makes every caller remember policy: `src/shared/state/selectionStore.ts:98`.
- The wrapper hook only forwards low-level behavior: `src/tools/video-editor/hooks/useTimelineSelection.ts:35`.
- Chat removes attachments by manually editing both timeline and gallery surfaces: `src/tools/video-editor/components/AgentChat/AgentChat.tsx:281`, `:296`.
- The bridge treats timeline attachment data as React context override state: `src/shared/contexts/AgentChatContext.tsx:52`, `src/tools/video-editor/contexts/VideoEditorProvider.tsx:101`.
- `AgentChat` then patches over timing with `displayedClips`: `src/tools/video-editor/components/AgentChat/AgentChat.tsx:192`.

Your framing, “selection events + composer + consumers + policies,” is mostly right. I’d rename “events” to **intents**. The durable abstraction should not be an event bus; it should be command APIs whose names encode user/system/composer intent.

**Target Architecture**

1. **Intent-based selection facade**
   Add `src/shared/state/selectionActions.ts` or fold into `selectionStore.ts`.

   Replace public calls like:
   - `selectTimelineClip(id, opts, { clearGallery })`
   - `selectGalleryItem(id, meta, { toggle })`
   - `clearGallerySelection()`

   With commands like:
   - `userSelectGalleryItem(item, { additive })`
   - `userSelectTimelineClip(clipId, { additive, preserveIfSelected })`
   - `composerRemoveAttachment(match)`
   - `composerClearAttachments()`
   - `systemPruneTimelineSelection(validIds)`
   - `editorReplaceTimelineAttachmentSelection(ids)`

   Keep low-level reducers private. Policy becomes centralized: user timeline selection clears gallery; composer timeline replacement does not.

   Estimate: **250-450 LOC**, **4-8 files** touched.

2. **Single current-attachment selector**
   Add `src/shared/state/currentAttachmentSet.ts`.

   It should expose:
   - `useCurrentAttachmentSet()`
   - `useCurrentAttachmentActions()`

   `AgentChat` should stop merging `timelineClips` from context with `selectedGalleryClips` directly at `src/tools/video-editor/components/AgentChat/AgentChat.tsx:181`. The merge/dedupe logic at `:40` belongs in this selector/composer module.

   The timeline side still needs rich clip metadata from `useSelectedMediaClips` at `src/tools/video-editor/contexts/VideoEditorProvider.tsx:80`. Register that with an external-store style source, not React context state pushed through `useEffect`. Either use `useSyncExternalStore`, or push timeline attachment snapshots into Zustand synchronously from the provider. The current context bridge at `src/shared/contexts/AgentChatContext.tsx:43` is the wrong reactive primitive for this specific data.

   Estimate: **300-600 LOC**, **5-10 files**.

3. **Shared gesture primitives**
   Add `src/shared/interactions/selectionGesture.ts`.

   Include:
   - `isAdditiveSelectionEvent(event)`
   - `isPrimaryPointer(event)`
   - `isClickLikePointerGesture(start, end, threshold)`
   - maybe `usePointerClickIntent`

   Replace `useModifierKeys` fallback in `GenerationsPaneGallery` at `src/features/gallery/components/GenerationsPane/components/GenerationsPaneGallery.tsx:84` and unify the desktop wrapper logic at `src/shared/components/MediaGalleryItem.tsx:342` with the mobile path at `src/shared/components/MediaGalleryItem/hooks/useItemInteraction.ts:31`.

   Estimate: **150-300 LOC**, **4-6 files**.

4. **PostgREST filter helper**
   Extract the OR accumulation from `useProjectGenerations` into `src/integrations/supabase/postgrestFilters.ts`.

   Estimate: **60-120 LOC**, **2-3 files**.

**Cost / Benefit**

- Intent-based selection facade: **medium effort / high payoff**. Do it. This addresses the recurring policy bugs.
- Single current-attachment selector: **medium-high effort / high payoff**. Do it next. This removes the flicker class and stops chat from knowing too much about surfaces.
- Shared gesture primitives: **low-medium effort / medium payoff**. Do it, but keep it small. No framework, just functions/hooks.
- PostgREST helper: **low effort / medium payoff**. Do it opportunistically; it prevents a repeat, but it’s not part of the selection architecture.

I would not rewrite the whole selection store. The current Zustand store is close enough. The fix is to stop exporting policy-shaped booleans and stop making `AgentChat` be the attachment composer.
