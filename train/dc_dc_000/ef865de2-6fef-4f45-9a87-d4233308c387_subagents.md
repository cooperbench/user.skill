## 3. Phase Routing by Robustness
Standard robustness workflow:
- `init -> prep -> plan -> critique -> gate`
- Then follow the gate decision tree.
- `prep` may return `skip: true`; do not skip the command yourself.
- When you reach `gated`, run `finalize`.
- Then run `execute`.
- Then run `review`.
- If `review` returns `needs_rework`, loop back to `execute` until it passes or cap.

Gate decision tree:
- `gate_unset`: state is `critiqued` and `valid_next` includes `gate`. Run `gate`.
- `gate_iterate`: gate said ITERATE, `valid_next` includes `revise`. Run `revise` then back to `critique`/`gate`.
- `gate_escalate`: gate said ESCALATE, `valid_next` offers override commands. Stop with `BREAKPOINT: GATE_ESCALATE`.
- `gate_proceed_blocked`: gate said PROCEED but preflight blocked. Fix blocking checks via `revise`, or break out if unsafe.
- `gate_proceed`: gate said PROCEED and preflight passed, state is `gated`. Run `finalize`.

Review routing: if `review` succeeds, done. If `needs_rework`, CLI returns to `finalized`; run `execute` then `review` again. Capped at 3 rework cycles.

## 5. Breakpoints
Format:
`BREAKPOINT: <type>`
`Plan: <name>`
`State: <state>`
`Summary: <short reason>`
`Context: <artifacts, warnings, or exact user decision needed>`

Types:
- `GATE_ESCALATE`: gate recommends ESCALATE.
- `GATE_BLOCKED`: gate_proceed_blocked and need user decision between revision vs force-proceed.
- `EXECUTE_APPROVAL`: finalize succeeded in review mode and execute needs approval. (Not applicable here — we're auto-approve.)
- `PHASE_ESCALATE`: non-execute phase still fails after required retry.
- `EXECUTE_ESCALATE`: execute reaches no-progress cap (3 consecutive attempts without forward progress).

## 6. Safeguards
Non-execute: retry once with `--fresh` on failure; if same error twice, next retry must use `--fresh`; if still failing, `BREAKPOINT: PHASE_ESCALATE`.

Execute: count forward progress (new completed tasks, completed batch, state advance). 3 consecutive no-progress attempts → `BREAKPOINT: EXECUTE_ESCALATE`. Timeouts/blocks retry up to the same cap.

Review: `needs_rework` is normal, not failure — follow the rework loop. Blocked/unusable review output uses the non-execute retry rule.

Notes/interruption: on relaunch, run status immediately, read full notes array, treat the most recent note as the relaunch explanation.
