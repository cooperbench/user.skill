## Foundational decisions (locked, do not re-debate)

### The new Step shape

```
Step {
  id: str
  version: int                       # bumped when a dispatched step is superseded
  adapter: "local" | "manual" | "remote-artifact"
  requires_ack: bool
  assignee: "system" | "agent:<id>" | "any-agent" | "human:<name>" | "any-human"
  produces: [{name, path, check}]
  repeat: until | for_each | none
  command: str?                      # leaf step: the thing to run; interpreted by adapter
  children: [Step]?                  # group step: nesting; replaces old `nested` kind
  cost: {amount, currency, source}?  # recorded at completion
  superseded_by: {
    to_version: int,
    scope: "all" | "future-iterations" | "future-items"  # REQUIRED; no default
  }?
}
```

- Leaf step has `command`, no `children`.
- Group step has `children`, no `command`. Its `produces` aggregates from descendants.
- `code` / `attested` / `nested` step kinds are **gone** (migrated forward — see Migration).
- `version` starts at 1 for the initial step; bumps to 2+ on supersede.

### Supersession scope is mandatory

A `supersede-step` verb without an explicit `scope` is rejected at the verb. Three scopes:
- `"all"` — aborts in-flight iterations/items and restarts at iter/item 1 of the new version.
- `"future-iterations"` — `repeat.until` only; current iteration finishes against old version, iter+1 uses new version.
- `"future-items"` — `repeat.for_each` only; current item finishes against old version, next item uses new version.

### Plan mutation rules

- `plan.json` is the *initial* plan, written once at run start.
- The *effective* plan = `plan.json` + replayed mutation events from `events.jsonl`.
- **Append-only once dispatched.** A step is "dispatched" the moment `astrid next` returns its payload (event: `step_dispatched`). After dispatch:
  - `remove-step` is rejected. Use `abort` on the run instead, or `supersede-step`.
  - `edit-step` is rejected. Use `supersede-step` to bump version.
  - The original `steps/<id>/v1/` directory is **never deleted**.
- **Undispatched steps** can be added, edited, or removed freely. `remove-step` writes a tombstone event; the cursor skips tombstoned steps.
- **Canonical step path is always versioned**: every step lives at `steps/<id>/v<N>/...`. Iterations and items live under `steps/<id>/v<N>/iterations/NNN/` and `steps/<id>/v<N>/items/<item-id>/`.

### The six plan-mutation invariants

Single function (call it `validate_mutation` or similar) runs **all six** invariants against the proposed effective tree:

1. **Schema validation** — full re-validate of the proposed effective tree (not a diff).
2. **Sibling-id uniqueness** at every frame (existing `plan.py:_assert_unique_paths` rule, applied to effective tree).
3. **`produces` reference integrity** — no dangling refs to deleted/tombstoned steps.
4. **Adapter validation** — declared adapter is `local | manual | remote-artifact`, command shape matches adapter (e.g. `manual` cannot have empty `command` string).
5. **Repeat-source validation** — `repeat.for_each.from_ref` resolves to a real prior `produces` in the effective tree.
6. **Lease epoch CAS** — the writer's epoch matches current (Sprint 1's lease).

Mutations that fail **any** check are rejected at the verb. No partial application. The verb returns a non-zero exit with the specific invariant that failed.

### Three adapters; only two ship this sprint

- **`local`** — `command` is a shell command run as a subprocess in the project root. Outputs land in `produces/`. Completion = exit code 0 + produces checks pass.
- **`manual`** — agent (or human) runs the work out-of-band; `command` is the dispatch payload (instructions). The agent is responsible for landing outputs in `produces/`. Completion = `astrid ack` (sync) or completion JSON in inbox (async).
- **`remote-artifact`** — schema-reserved here, **rejected at runtime** in Sprint 3 with: `astrid start / astrid next: step '<id>' declares adapter 'remote-artifact'; not yet implemented (Sprint 5a). Use --adapter local or manual.` Full implementation lands in Sprint 5a alongside the hype port.

Adapters are first-class code, not config.

### Ack identity at ack time, not author time

`astrid ack <step> --decision {approve,retry,iterate,abort} --agent <id>|--actor <name> [--evidence <path>]`. Both `--agent` and `--actor` are required (one or the other) — **no anonymous acks**. Every ack carries the `writer_epoch` it read; stale acks are rejected by the kernel.

### Authoring split

- **Leaf-template** — what we used to call an executor. One concrete unit of work. Same pack layout on disk (`pack/<name>/run.py` + `executor.yaml`).
- **Plan-template** — what we used to call an orchestrator: a reusable composition. Materializes into a step subtree at plan-build or plan-mutation time.

Runtime never sees templates — only the resulting step tree. During Sprint 3, the new template kinds land **alongside** the legacy `OrchestratorDefinition` YAML — both readable. Legacy YAML is materialized into the new step tree on the way in. (Sprint 5b removes legacy YAML acceptance.)

### Capture-everything rule

Anything producing an audit-worthy artifact = a step. The friction is small: `astrid plan add-step --command '...' --produces '...'` + `astrid next`. The alternative — agent runs python ad-hoc, artifact appears with no provenance — is what we're eliminating. Truly ephemeral commands don't need it.

### Plan-mutation verbs + event

- `astrid plan add-step` — insert a step into the effective tree at a given path. Position via `--after <step-path>` / `--before <step-path>` / `--into <group-path>`.
- `astrid plan edit-step` — modify an undispatched step (fields specifiable as flags).
- `astrid plan remove-step` — write a tombstone event for an undispatched step. Rejected on dispatched steps.
- `astrid plan supersede-step` — bump version on a dispatched (or any) step. **Requires `--scope {all,future-iterations,future-items}`.**
- All four verbs emit a single `plan_mutated` event in `events.jsonl` carrying: actor, writer_epoch, diff (the specific operation), timestamp. The hash chain extends to plan mutations.

### Plan-mutation validator

- Single entry point that runs all six invariants. Every verb routes through it. Rejection is total.
- Returns structured error: which invariant failed + the specific element that triggered it.
- Test: each invariant has at least one positive (passes) and one negative (rejects with the right error code) case.

### Cursor

- Cursor stores `(step_id, step_version, dispatch_event_hash)` per dispatched step.
- Walks the effective plan respecting tombstones and supersedes (honoring `scope` per repeat semantics).
- `astrid status` shows the cursor's current step at its current version.

### Inbox path+version match

- Rewrite `astrid/core/task/inbox.py` so entries match on `(plan_step_path, step_version, item_id?)` not just the leaf step id.
- Inbox entries from before a supersede event route to the original version's directory; entries after route to the new version.
- Stale entries that target a tombstoned or fully-superseded step move to `.rejected/` (existing pattern — extend it).

### Adapters

### Claim verb
