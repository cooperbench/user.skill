**How It Actually Works**

- The overlap counts are policy-driven: WAN uses `guide_overlap_masked` with `10` frames, LTX uses `prefix_video_source` with `24` frames.  
  [modelCapabilities.ts](/Users/user_c042661f/Documents/reigh/src/tools/travel-between-images/modelCapabilities.ts#L57)  
  [generation_policy.py](/Users/user_c042661f/Documents/reigh-worker/source/core/params/generation_policy.py#L37)

- The worker turns that into per-segment state with `frame_overlap_from_previous`, and for continued segments it inflates `segment_frames_target` by the overlap.  
  [orchestrator.py](/Users/user_c042661f/Documents/reigh-worker/source/task_handlers/travel/orchestrator.py#L1960)

- The actual auto-stitch path is already continuation-aware: `travel_stitch` receives `frame_overlap_settings_expanded` and crossfades those overlap frames directly.  
  [orchestrator.py](/Users/user_c042661f/Documents/reigh-worker/source/task_handlers/travel/orchestrator.py#L2255)  
  [stitch.py](/Users/user_c042661f/Documents/reigh-worker/source/task_handlers/travel/stitch.py#L105)  
  [stitch.py](/Users/user_c042661f/Documents/reigh-worker/source/task_handlers/travel/stitch.py#L608)

- Manual Join Segments is currently blind to all of that. It just collects clip URLs and hands them to the join-clips VACE flow.  
  [useJoinSegmentsHandler.ts](/Users/user_c042661f/Documents/reigh/src/tools/travel-between-images/components/ShotEditor/hooks/actions/useJoinSegmentsHandler.ts#L128)  
  [joinClips/index.ts](/Users/user_c042661f/Documents/reigh/src/shared/lib/tasks/families/joinClips/index.ts#L273)

**Recommended Plan Adjustments**

- Reframe the problem as: “overlap count/strategy already exists; add predecessor *variant* identity and wire consumers.”
- Keep the metadata in JSON params unless you need SQL-level querying. A new column is not obviously necessary.
- Derive predecessor variant ID in `complete_task` from the predecessor task/generation relationship, or explicitly extend the completion contract. The current “worker writes it on completion” wording is not implementable as-is.
- Change the join task contract from “`crossfade_boundaries`” to an explicit mixed boundary model, because the worker needs to know both boundary mode and the trimming/accounting rules.
- Fix the frontend data path first: either preserve `primary_variant_id` in the segment mapper or query `id, location, params, primary_variant_id` in the join handler.
- Move the auto-enable stitch behavior to the join-settings owner or a higher controller that has both SC state and join state.

One extra note: the docs are not fully reliable here. In particular, the task lifecycle docs still describe SQL-trigger generation creation, while the live code is doing generation creation inside `complete_task`, so I treated code as source of truth.
