        # Implementation Plan: Phase 9 Author Test With Golden Dry Runs

## Overview
Phase 9 should replace the current `author test` scaffold in `artagents/orchestrate/cli.py` with a real golden-run harness. The latest critique does not mean the plan is targeting the wrong root cause; the dry-run harness, gate-level auto-approval, scratch-build behavior, and orchestrator-scoped fixture/golden resolver remain the right approach. The missing piece is a supporting authoring location: `author new` currently scaffolds pack-level `fixtures/` and `golden/` files, so it must be updated to create the same orchestrator-scoped layout that `author test` reads.

The repository already has the pieces to reuse: compiled DSL plans in `artagents/orchestrate/compile.py`, task lifecycle start state in `artagents/core/task/lifecycle.py`, cursor/gate behavior in `artagents/core/task/gate.py`, and hash-chained events in `artagents/core/task/events.py`. The implementation should drive the gate directly in a documented dry-run path: code steps emit dispatch/completion events with return code 0 without spawning subprocesses; attested steps are auto-approved only when `ARTAGENTS_AUTHOR_TEST=1`; inline produces checks are satisfied by copying declared fixture outputs from the orchestrator-scoped fixture directory into the exact task step directories before completion/attestation checks run.
