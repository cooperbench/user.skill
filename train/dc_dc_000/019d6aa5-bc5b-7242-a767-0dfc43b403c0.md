## Overview
Local (personal-token) workers should release VRAM/RAM/CUDA when idle by having the worker process fully exit after N idle minutes and be re-launched by a tiny stdlib supervisor. Cloud (service-key) workers must behave exactly as today.

Current shape (confirmed by inspection):
- Entry shim `worker.py` → `source.runtime.entrypoints.worker:main` → `source.runtime.worker.server:main` (server.py:245).
- Poll loop lives at server.py:405–533. The no-task branch is server.py:413–415 (`if not task_info: time.sleep(...); continue`).
- Auth gate helper already exists: `_resolve_worker_db_client_key` at server.py:45. Cloud/service detection = `WORKER_DB_CLIENT_AUTH_MODE=="service"` OR resolved key equals `SUPABASE_SERVICE_ROLE_KEY`/`SUPABASE_SERVICE_KEY`.
- Guardian heartbeat process is started around server.py:318–334 and torn down in the outer `finally` (server.py:540–552). Task queue has `task_queue.stop()` (server.py:554).
- Argparse is in `parse_args()` around server.py:210–243 (not fully read; extend there).

Design: reserve exit code **75** as the "idle release, please restart" signal. Supervisor is a new stdlib-only `run_worker.py` that execs the same Python interpreter with the same argv[1:], env, and cwd, distinguishes exit codes, forwards signals, and applies backoff only to real crashes.

### Step 3: Create supervisor (`run_worker.py` at repo root)
**Scope:** Medium
1. **New file** `run_worker.py`, stdlib-only (`os`, `sys`, `signal`, `subprocess`, `time`, `collections.deque`). No third-party imports so it can start instantly with ~20 MB RSS.
2. **Child command**: `[sys.executable, "-u", "-m", "source.runtime.entrypoints.worker", *sys.argv[1:]]`. Preserve `env=os.environ.copy()` and `cwd=os.getcwd()`. Re-use the exact same args each restart (requirement: byte-identical).
3. **Exit code semantics** (requirement 4):
   - `75` → restart immediately, no backoff, do not count against circuit breaker. Log "idle-release restart".
   - `0` → clean stop. Exit supervisor with 0.
   - Negative return code (POSIX: `proc.returncode < 0` means killed by signal `-rc`) → propagate: supervisor re-raises that signal on itself (or `sys.exit(128 + sig)`), does not restart. Covers SIGINT/SIGTERM from user.
   - Any other non-zero → crash path: apply exponential backoff (1s, 2s, 4s, 8s, capped at 30s) and record timestamp in a circuit-breaker `deque`. If ≥5 crashes within 300 seconds, log "[SUPERVISOR] circuit open, giving up" and exit with the child's last exit code.
4. **Signal forwarding** (requirement 5): install handlers for `SIGINT` and `SIGTERM` in the supervisor that forward via `child.send_signal(sig)` and then set a `shutdown_requested=True` flag. After the child exits, if `shutdown_requested` is set, do not restart — exit with the child's returncode (or `128+sig`). On Windows, fall back to `child.terminate()`.
5. **Main loop**:
   ```python
   while True:
       proc = subprocess.Popen(cmd, env=env, cwd=cwd)
       rc = _wait_forwarding_signals(proc)
       if rc == 75: continue  # idle restart, no backoff
       if rc == 0 or shutdown_requested: sys.exit(rc if rc >= 0 else 128 + (-rc))
       if rc < 0: sys.exit(128 + (-rc))  # killed by signal
       # crash → backoff + circuit breaker
       crashes.append(time.monotonic())
       while crashes and crashes[0] < time.monotonic() - 300: crashes.popleft()
       if len(crashes) >= 5: sys.exit(rc)
       time.sleep(min(2 ** (len(crashes)-1), 30))
   ```
6. **Document usage**: add a 3-line docstring at the top. No README changes unless the user asks.
