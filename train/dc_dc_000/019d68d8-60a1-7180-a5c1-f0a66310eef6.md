        # Implementation Plan: Idle-Release for Personal-Token Workers

## Overview
**Goal:** When a worker is authenticated with a personal/PAT token and has been idle (no claimed task) for N minutes, aggressively release all RAM and VRAM held by the worker process so the host machine is free for other workloads. When a new task arrives, lazy-reload only what's needed.

**Repository shape (relevant pieces):**
- Entrypoint & main poll loop: `source/runtime/worker/server.py` (parse_args at L209, main loop at L405-415).
- Existing soft cleanup (caches only, keeps models loaded): `source/task_handlers/queue/memory_cleanup.py`.
- WGP runtime model holder + existing clear helper: `source/runtime/wgp_ports/runtime_registry.py:151` (`clear_wgp_loaded_model_state`).
- Task queue object instantiated in main: `HeadlessTaskQueue` from `source/task_handlers/queue/task_queue.py` with `start()` (L329) and `stop()` (L333).
- Auth-mode signal: `--reigh-access-token` / `--supabase-access-token` is the personal-token path (server.py L262); `SUPABASE_SERVICE_ROLE_KEY` env var is the orchestrator/shared path.
- Polling already returns `None` on no-task at server.py L413, with sleep at L414 — natural place to update the idle clock.

**Constraints:**
- Must not break shared/service-mode workers. Idle-release is gated to personal-token mode.
- Must not interrupt an in-flight task. The check happens only on the no-task branch of the loop.
- Reload after release must be transparent; the next task processes normally even if it has to pay first-load cost.
- Heartbeat guardian process must keep running while idle (don't tear it down with the models).

### Step 1: Audit existing cleanup + model-holder surface (`source/task_handlers/queue/memory_cleanup.py`, `source/runtime/wgp_ports/runtime_registry.py`, `source/task_handlers/queue/task_queue.py`)
**Scope:** Small
1. **Confirm** `cleanup_memory_after_task` only does `torch.cuda.empty_cache()` + `gc.collect()` and explicitly leaves models loaded (`source/task_handlers/queue/memory_cleanup.py:5`).
2. **Confirm** `clear_wgp_loaded_model_state()` nulls `runtime.wan_model` and `runtime.offloadobj` (`source/runtime/wgp_ports/runtime_registry.py:151`).
3. **Inspect** `HeadlessTaskQueue.stop()` (`source/task_handlers/queue/task_queue.py:333`) and any orchestrator instance held on the queue. Identify (a) whether stopping it cleanly tears down its worker thread(s) without losing the queue object, and (b) any other large allocations (e.g., uni3c cache via `source/runtime/wgp_bridge.clear_uni3c_cache_if_unused`, mmgp `offloadobj` reserved buffers).
4. **Note** any other module-level caches: text encoder, VAE, LoRA weights cached on the runtime module, mmgp pinned memory.

### Step 2: Add a deep-release helper (`source/task_handlers/queue/memory_cleanup.py`)
**Scope:** Medium
1. **Add** a new function `release_all_models_and_memory(queue, *, reason: str)` next to `cleanup_memory_after_task`. It must:
   - Log VRAM/RAM before.
   - Call `queue.orchestrator.unload_model()` if such an API exists, else manually drop the orchestrator's cached model references (set to `None`) and any handles the queue holds.
   - Call `clear_wgp_loaded_model_state()` from `source/runtime/wgp_ports/runtime_registry.py`.
   - `del` local references; run `clear_uni3c_cache_if_unused()`; reset any other discovered module caches found in Step 1.
   - Run `gc.collect()` twice (cycles).
   - If CUDA: `torch.cuda.empty_cache()`, `torch.cuda.ipc_collect()`, `torch.cuda.synchronize()`, then log allocator stats.
   - Optionally call `malloc_trim(0)` via `ctypes` on Linux to return CPU heap to the OS (best-effort; wrapped in try/except — only useful on glibc).
   - Log VRAM/RAM after and the delta.
2. **Export** the helper so server.py can import it.
   ```python
   from source.task_handlers.queue.memory_cleanup import release_all_models_and_memory
   ```
3. **Do not** call any teardown on the heartbeat guardian process or DB client — those must survive idle.

### Step 3: Add CLI arg + idle tracking in main loop (`source/runtime/worker/server.py`)
**Scope:** Medium
1. **Add** new arg in `parse_args()` (`source/runtime/worker/server.py:242`):
   ```python
   parser.add_argument("--idle-release-minutes", type=float, default=15.0,
       help="Personal-token workers free all RAM/VRAM after this many idle minutes. 0 disables.")
   ```
2. **Detect** personal-token mode in `main()` near L262 — `personal_token_mode = bool(access_token) and not os.environ.get("SUPABASE_SERVICE_ROLE_KEY")`. Store this on a local variable.
3. **Initialize** before the loop (near L405):
   ```python
   idle_release_seconds = cli_args.idle_release_minutes * 60.0
   idle_release_enabled = personal_token_mode and idle_release_seconds > 0
   last_task_claimed_at = time.monotonic()
   models_released = False
   ```
4. **Update** the no-task branch at L413-415:
   ```python
   if not task_info:
       if idle_release_enabled and not models_released:
           if (time.monotonic() - last_task_claimed_at) >= idle_release_seconds:
               release_all_models_and_memory(task_queue, reason="idle-timeout")
               models_released = True
       time.sleep(cli_args.poll_interval)
       continue
   ```
5. **On task claim** (immediately after `if not task_info: continue`, before processing):
   ```python
   last_task_claimed_at = time.monotonic()
   models_released = False
   ```
   No explicit reload call is needed — the existing lazy-load path inside `process_single_task` → orchestrator will reinitialize the model on demand because `runtime.wan_model is None`.
6. **Verify** the existing code path that handles `runtime.wan_model is None` actually re-loads (it should, since this is how startup loads it the first time when `--preload-model` is not set). If a code path assumes the model is loaded post-start, fix it to re-load when the cached value is `None`. (Discovery in Step 1 informs this.)

### Step 4: Targeted unit tests (`tests/test_idle_release.py`)
**Scope:** Small
1. **Add** a new test file. Two tests, both using fakes (no real CUDA, no real DB):
   - `test_idle_release_triggers_after_timeout`: monkeypatch `time.monotonic`, drive the loop's idle-check logic via a small extracted helper (see Step 5), assert `release_all_models_and_memory` is called exactly once after N minutes of `task_info=None` returns.
   - `test_idle_release_skipped_for_service_mode`: same fixture but `personal_token_mode=False`; assert release is never called.
   - `test_idle_release_resets_on_task_claim`: simulate a task arriving after release; assert `models_released` flag clears and a subsequent idle period triggers a *second* release.
2. **Run** `pytest tests/test_idle_release.py -x` first as the cheapest gate.

### Step 5: Refactor the idle decision into a tiny pure function (`source/runtime/worker/idle_release.py`)
**Scope:** Small
1. **Extract** the decision (is it time to release?) out of the loop into a small pure helper so it's testable without spinning up the whole worker:
   ```python
   def should_release_now(*, enabled: bool, already_released: bool,
                          now_monotonic: float, last_claimed_at: float,
                          idle_seconds: float) -> bool:
       return (enabled and not already_released
               and (now_monotonic - last_claimed_at) >= idle_seconds)
   ```
2. **Call** it from server.py's no-task branch. This keeps `server.py` thin and the test in Step 4 trivial.

### Step 6: Manual smoke verification (info-only)
**Scope:** Small
1. **Run** the worker locally with `--idle-release-minutes 1 --reigh-access-token <pat>` and confirm via `nvidia-smi` (or platform equivalent) that VRAM drops to baseline ~60-90 seconds after the last task.
2. **Submit** a task after release; confirm it executes successfully (maybe slower on first run) and VRAM rises again.
3. **Run** the worker with `SUPABASE_SERVICE_ROLE_KEY` set and confirm release is *not* triggered.
