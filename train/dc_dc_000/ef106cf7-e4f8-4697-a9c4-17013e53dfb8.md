   238→    return """\
   239→## ENRICH Stage Instructions
   240→
   241→Your task: make EVERY step executor-ready. The test: could a developer who has never seen
   242→this codebase read your step detail and make the change without asking a single question?
   243→
   244→If the answer is "they'd need to figure out which file" or "they'd need to understand the
   245→context" — your step is not ready. Be specific enough that the work is mechanical.
   246→
   247→### Requirements (ALL BLOCKING — confirmation will reject if not met)
   248→
   249→1. Every step MUST have `--detail` with 80+ chars INCLUDING at least one file path (src/... or supabase/...)
   250→2. Every step MUST have `--issue-refs` linking it to specific review issue hash(es)
   251→3. Every step MUST have `--effort` tag (trivial/small/medium/large) — set INDIVIDUALLY, not bulk
   252→4. File paths in detail MUST exist on disk (validator checks this)
   253→5. No step may reference a skipped/wontfixed issue in its issue_refs
   254→
   255→### How to enrich
   256→
   257→**USE SUBAGENTS — one per cluster.** Each subagent MUST:
   258→
   259→1. Run `desloppify plan cluster show <name>` to get current steps and issue list
   260→2. **Read the actual source file for every step** — not just the issue description.
   261→   The issue says what's wrong; you need to see the code to say what to DO.
   262→3. Write detail that includes: the file path, the specific location (line range or
   263→   function name), and the exact change to make
   264→4. Set effort based on the ACTUAL complexity you see in the code, not a guess
   265→
   266→### Common lazy patterns to avoid
   267→
   268→**Copying the issue description as step detail.** The issue says "useGenerationsPaneController
   269→returns 60+ values mixing concerns." That's a PROBLEM description. The step detail should say
   270→"In src/shared/components/GenerationsPane/hooks/useGenerationsPaneController.ts (283 lines),
   271→extract lines 45-89 (filter state: activeFilter, setActiveFilter, filterOptions, applyFilter)
   272→into a new useGenerationFilters hook. The controller imports and spreads the sub-hook's return."
   273→

   275→"Extract lines 45-89 into useGenerationFilters", "delete lines 12-18", "rename the file
   276→from X to Y and update the 3 imports in A.tsx, B.tsx, C.tsx" are actions.
   277→
   278→**Guessing file paths.** If you write `src/shared/lib/jsonNarrowing.ts` and it doesn't exist,
   279→confirmation will block. READ the file system. Only reference files you've verified exist.
   280→
   281→**Bulk effort tags.** Don't mark everything "small". A file rename with 2 imports is "trivial".
   282→Decomposing a 400-line hook into 3 sub-hooks is "medium" or "large". Think about each one.
   283→
   284→### Examples
   285→
   286→**GOOD step detail:**

   290→previous state and change showToast from false to true."
   291→--issue-refs 79baeebf --effort small
   292→```
   293→
   294→**BAD step detail (will be rejected):**
   295→```
   296→--detail "Fix silent error swallowing"  # No file, no location, no action

   302→

   305→
   306→### File path rules
   307→
   308→Only reference files that exist RIGHT NOW. Do not reference files that a step will create
   309→(e.g., a new shared module) or rename targets (the new filename after a rename). Reference
   310→the current source file and describe what will change. The path validator will block
   311→confirmation if paths don't exist on disk.
   312→
   313→When done, run:
   314→```
   315→desloppify plan triage --stage enrich --report "<enrichment summary>" --attestation "<80+ chars mentioning cluster names>"
   316→```

   363→def build_stage_prompt(
   364→    stage: str,
   365→    triage_input: TriageInput,
   366→    prior_reports: dict[str, str],
   367→    *,
   368→    repo_root: Path,
   369→) -> str:
   370→    """Build a complete subagent prompt for a triage stage."""
   371→    parts: list[str] = []
   372→
   373→    # Preamble
   374→    parts.append(_PREAMBLE.format(stage=stage.upper(), repo_root=repo_root))
   375→
   376→    # Issue data
   377→    issue_data = build_triage_prompt(triage_input)
   378→    parts.append("## Issue Data\n\n" + issue_data)
   379→
   380→    # Prior stage reports
   381→    if prior_reports:
   382→        parts.append("## Prior Stage Reports\n")
   383→        for prior_stage, report in prior_reports.items():
   384→            parts.append(f"### {prior_stage.upper()} Report\n{report}\n")
   385→
   386→    # Stage-specific instructions
   387→    instruction_fn = _STAGE_INSTRUCTIONS.get(stage)
   388→    if instruction_fn:
   389→        parts.append(instruction_fn())
   390→
   391→    # CLI reference
   392→    parts.append(_CLI_REFERENCE)
   393→
   394→    # Validation requirements
   395→    parts.append(_validation_requirements(stage))
   396→
   397→    return "\n\n".join(parts)

   400→def cmd_stage_prompt(
   401→    args: argparse.Namespace,
   402→    *,
   403→    services: TriageServices | None = None,
   404→) -> None:
   405→    """Print the current prompt for a triage stage, built from live plan data."""
   406→    stage = args.stage_prompt
   407→    resolved_services = services or default_triage_services()
   408→    plan = resolved_services.load_plan()
   409→    runtime = resolved_services.command_runtime(args)
   410→    state = runtime.state
   411→    si = resolved_services.collect_triage_input(plan, state)
   412→    repo_root = get_project_root()
   413→
   414→    # Extract real prior reports from plan.json
   415→    meta = plan.get("epic_triage_meta", {})
   416→    stages = meta.get("triage_stages", {})
   417→    prior_reports: dict[str, str] = {}
   418→    for prior_stage in _STAGES:
   419→        if prior_stage == stage:
   420→            break
   421→        report = stages.get(prior_stage, {}).get("report", "")
   422→        if report:
   423→            prior_reports[prior_stage] = report
   424→
   425→    prompt = build_stage_prompt(stage, si, prior_reports, repo_root=repo_root)
   426→    print(prompt)
