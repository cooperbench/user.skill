# Wan2GP Fork Migration — Closeout Summary

## What shipped
- `Wan2GP/` stopped being a flat vendored copy and is now a git submodule at the same mount path, pointing to the `banodoco/Wan2GP` fork.
- The landed pin is the fork’s `reigh-sprint-3` line, currently at submodule commit `181bb71a`.
- Sprint 3 added targeted regression coverage for IC-LoRA override behavior, IC-LoRA dedup behavior, and `clear_conditioning` byte identity, plus the saved oracle fixture those tests use.
- The migration did not change the expected import/path contract: callers still rely on the exact `reigh-worker/Wan2GP/` mount and `ensure_wan2gp_on_path()` inserting that directory itself.
- The independent regression audit’s conclusion was additive-only: no audited pre-existing Wan2GP behavior changed, and the only audited content delta on pre-existing files was `.gitignore`.

## Commits

| Sprint | Commit SHA | One-line summary | Tag |
| --- | --- | --- | --- |
| 1 | `9656cc90` | Pre-migration rollback anchor; no migration code landed in `reigh-worker` yet | `wan2gp-mig-sprint-1-baseline` |
| 2 | `253e9fba` | Replace vendored `Wan2GP/` tree with submodule on `banodoco/Wan2GP` | `wan2gp-mig-sprint-3-baseline` |
| 3 | `550320a3` | Bump submodule for `ltx2/` hot-zone resync and add regression tests/fixture | `wan2gp-mig-sprint-4-baseline` |
| 4 | `<SPRINT4_SHA>` | Planned: patch consolidation, upstream PRs, drift CI, rebase runbook | pending |

## Architectural changes
The migration landed the SD-001 shape from the plan: `reigh-worker/Wan2GP/` remains the runtime mount point, but it is now a submodule instead of a copied tree. The fork lives at `https://github.com/banodoco/Wan2GP.git`. Drift is now visible by comparing the pinned submodule SHA against the fork or upstream; the planned weekly drift CI job is still Sprint 4 work, not landed yet.

## Test coverage added
- `tests/test_travel_guidance_ic_lora_override.py`: pins the cameraman IC-LoRA auto-injected URL and the pose fallback to union-control.
- `tests/test_task_registry_ic_lora_dedup.py`: pins basename-based dedup behavior so existing entries are updated instead of duplicated.
- `tests/test_clear_conditioning_byte_identity.py`: proves `clear_conditioning` stays byte-for-byte identical against `tests/fixtures/clear_conditioning_oracle.pt`.

## What you should know
- The `wan2gp-mig-sprint-*` tags are rollback baselines, not simple “end of sprint” labels. In practice, the post-Sprint-2 state is tagged `wan2gp-mig-sprint-3-baseline`, and the post-Sprint-3 state is tagged `wan2gp-mig-sprint-4-baseline`.
- The load-bearing rule from SD-001 remains in force: future Wan2GP divergence should live either in the `banodoco/Wan2GP` fork or in `source/models/wgp/wgp_patches.py`, not as ad hoc edits inside the checked-out submodule.
- SD-004 and SD-005 also matter operationally: `ltx2_22B_distilled_1_1.json`, `res_2s`, and refreshed `self_refiner` support are available-but-not-default. The migration was not used to change defaults.

## What's left for the user to do
- Update any local clone with `git submodule update --init --recursive` after pulling the migration commits.
- Finish Sprint 4: land the drift CI workflow, publish the rebase runbook, and review any upstreamable fork changes before opening or merging PRs.
- Treat future Wan2GP work as fork maintenance, not vendored-tree maintenance.
