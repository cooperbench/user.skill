        # Implementation Plan: Sprint 9 Control-Rail and Travel-Matrix Parity

## Overview
This sprint spans three concrete areas in the current repo: create-time route materialization in `reigh-app-cloud-chain/supabase/functions/create-task`, worker route dispatch in `reigh-worker/source/task_handlers/tasks`, and travel/control/media handling in `reigh-worker/source/task_handlers/travel` plus `reigh-worker/source/media`. The current shape already has route keys and selector/capability checks, travel guidance parsing, Canny/Depth/Pose/Flow preprocessors, and VibeComfy fail-closed behavior. The work is to close the parity gaps: make every non-FALL-BACK Section 3A row route through the dispatcher, prove or block LTX control rows, preserve media contracts around Comfy outputs, and add replay/smoke tooling that can be run before promotion.

## Phase 1: Matrix and Route Contracts

### Step 1: Codify Section 3A as executable data (`reigh-worker/scripts/dual_run_compare/`, `reigh-app-cloud-chain/supabase/functions/create-task/resolvers/shared/routeKeys.test.ts`)
**Scope:** Medium
1. **Create** a single matrix fixture for Section 3A rows with fields for task type, model family, guidance kind, continuity case, profile, expected backend class, and status (`PROMOTED`, `NEW`, `BLOCKED`, `WGP_ONLY`, or `FALL_BACK`).
2. **Use** the existing route-key derivation in both stacks as the source of truth: `deriveRouteKey` in `reigh-app-cloud-chain/supabase/functions/create-task/resolvers/shared/routeKeys.ts` and `derive_route_key` in `reigh-worker/source/task_handlers/tasks/template_routing.py`.
3. **Add parity tests** that assert equivalent route keys for every matrix row across TypeScript and Python fixtures, especially dimensional child rows like `individual_travel_segment__model-...__guidance-...__continuity-...__profile-...`.
4. **Fail fast** when a non-FALL-BACK row has no explicit expected support state.

### Step 2: Seed and validate route capabilities (`reigh-app-cloud-chain/supabase/migrations/`, `reigh-app-cloud-chain/supabase/functions/create-task/index.test.ts`)
**Scope:** Medium
1. **Add or update migration data** for all Section 3A non-FALL-BACK route keys in `route_backend_capabilities` and, where promoted to canary, `route_backend_selectors`.
2. **Keep fallback explicit:** missing-selector WGP is already guarded by `supports_missing_selector`; do not rely on missing rows to imply support for canary routes.
3. **Extend create-task tests** so each non-FALL-BACK row materializes `selector_namespace`, `route_key`, `selected_backend`, `selector_version`, and `route_selection_snapshot` before insert.
4. **Add negative tests** proving disabled, expired, missing, or unsupported selector/capability rows block task creation instead of silently falling back.

### Step 3: Keep worker route support in lockstep (`reigh-worker/source/task_handlers/tasks/template_routing.py`, `reigh-worker/tests/`)
**Scope:** Medium
1. **Update** `SPRINT_2_SELECTOR_MAP` or replace it with a generated/fixture-backed registry for Section 3A route keys.
2. **Classify** every LTX control route as either `VIBECOMFY_SUPPORTED` with a real template id, `WGP_ONLY`, `VIBECOMFY_UNSUPPORTED`, or `BLOCKED` in the fixture.
3. **Preserve fail-closed behavior** in `resolve_task_route` and `preflight_parent_child_route`: explicit VibeComfy selection must not fall back to WGP when support is unproven.
4. **Add tests** around `route_support_state`, `resolve_task_route`, and parent-derived child snapshots for all promoted rows.

## Phase 2: Control Guidance and Continuity

### Step 4: Normalize control guidance propagation (`reigh-app-cloud-chain/supabase/functions/create-task/resolvers/travelBetweenImages.ts`, `reigh-app-cloud-chain/supabase/functions/create-task/resolvers/individualTravelSegment.ts`)
**Scope:** Medium
1. **Remove the TODO gaps** for `structure_guidance`, `structure_videos`, `chain_segments`, and relevant continuity fields so full orchestration and standalone segment tasks preserve the same control payload.
2. **Include** `structure_guidance` and `structure_videos` in the read contract in `taskContracts.ts` and in generated `orchestrator_details` where currently only `travel_guidance` is consistently propagated.
3. **Keep payload precedence unchanged:** segment-specific overrides win over top-level params, which win over nested `orchestrator_details`, matching `task_registry.py`.
4. **Add resolver tests** for WAN VACE flow/canny/depth/raw/uni3c, LTX control video/pose/depth/canny/uni3c, LTX unguided, and continuity sub-cases.

### Step 5: Prove Canny/Depth/Pose/Flow preprocessing paths (`reigh-worker/source/media/structure/preprocessors.py`, `reigh-worker/source/media/structure/generation.py`, `reigh-worker/source/media/structure/compositing.py`)
**Scope:** Medium
1. **Add lightweight tests** using monkeypatched annotator classes from `source.runtime.wgp_bridge` to verify Canny, Depth, Pose, Flow, Raw, and Uni3C preprocessors return exactly the requested frame count.
2. **Assert modifier semantics:** Canny intensity scales edge frames, Depth contrast adjusts depth maps, Flow handles the N-1 model output without changing final count, Pose raises clearly when required models are absent.
3. **Add composite-guidance tests** that build tiny synthetic videos and verify output frame count, FPS, and resolution for each preprocessing mode without invoking real model weights.
4. **Keep model-download behavior out of unit tests** by mocking annotator/model lookups.

### Step 6: Harden LTX control handoff (`reigh-worker/source/core/params/travel_guidance.py`, `reigh-worker/source/task_handlers/travel/guide_builder.py`, `reigh-worker/source/task_handlers/tasks/task_registry.py`)
**Scope:** Large
1. **Verify** LTX distilled control rows use `travel_guidance.kind='ltx_control'` and valid modes from `pose`, `depth`, `canny`, `video`, or `cameraman`.
2. **Ensure** `_create_ltx_control_guide_video` creates a real full-length control clip and that downstream generation params use WGP’s control-capable path, not first/last-only image prompting.
3. **Assert** `video_prompt_type`, guide-video fields, IC-LoRA injection, anchor fields, and audio/control fields in `_build_generation_params` for each LTX control row.
4. **For any LTX row without a real control-capable VibeComfy template**, mark it `WGP_ONLY`, `NEW`, or `BLOCKED` in the matrix fixture and fail closed for VibeComfy.
5. **Add tests** using a fake `TravelSegmentProcessor` context to cover LTX control guide materialization and WGP handoff params.

### Step 7: Validate continuity sub-cases (`reigh-worker/source/task_handlers/travel/orchestrator.py`, `reigh-worker/source/task_handlers/tasks/task_registry.py`, `reigh-worker/source/task_handlers/travel/predecessor_resolver.py`)
**Scope:** Large
1. **Exercise** first/last, video-source continuation, SVI continuation, join bridge, and independent segment paths using deterministic task payload fixtures.
2. **Assert** continuity fields affect route keys through `continuity_case` and do not disappear during worker-created child task creation.
3. **Add regression coverage** for `segment_frames_expanded`, `frame_overlap_expanded`, `stitched_start_frame`, and `guidance_start_frame` in standalone segment regeneration.
4. **Verify** LTX rows do not use unproven first/last-only behavior when a control guide is required.

## Phase 3: Native Comfy Media Post-Processing

3. **Keep existing upload flow intact** by returning the original path unless a post-processing step is explicitly required.

3. **Preserve audio** when input route params require audio, and explicitly record `audio_present=false` for routes that do not require it.
4. **Ensure thumbnail generation still flows** through `complete_task` for video outputs and that existing local-file completion can request/upload thumbnails for large files.
5. **Add tests** with fake VibeComfy subprocess output and local fixture videos.

### Step 10: Preserve output contracts through completion (`reigh-worker/source/core/db/lifecycle/task_status_complete_local.py`, `reigh-worker/source/core/db/lifecycle/task_status_complete_remote.py`, `reigh-app-cloud-chain/supabase/functions/complete_task/`)
**Scope:** Medium

3. **Add tests** that a completed video task returns a public output URL and thumbnail URL without losing route snapshot fields.

## Phase 4: Replay and Smoke Reporting

### Step 11: Build persisted-row compatibility replay (`reigh-worker/scripts/`, `reigh-app-cloud-chain/supabase/functions/create-task/resolvers/__tests__/`)
**Scope:** Medium
1. **Create** a replay script that reads a fixture of persisted task rows, normalizes params through current dispatch/route derivation, and reports pass/fail/WGP-only without inserting tasks by default.
2. **Include** historical shapes: legacy `structure_videos`, new `structure_guidance`, new `travel_guidance`, worker-created passthrough segments, standalone individual segments, and rows with pinned route snapshots.
3. **Assert** every persisted non-FALL-BACK row either replays green or is explicitly marked WGP-only/BLOCKED with a reason.
4. **Store** replay output as JSON plus a compact Markdown smoke report.

### Step 12: Add Section 3A matrix smoke runner (`reigh-worker/scripts/dual_run_compare/` or `reigh-worker/scripts/`)
**Scope:** Large
1. **Implement** a dry-run mode that validates route key, backend support state, guidance payload, continuity fields, and media expectations for every matrix row.
2. **Implement** an optional live mode that can enqueue smoke tasks through `create-task` and observe status/logs, but keep live GPU execution out of the mandatory unit test path.
3. **Produce** a full matrix report with columns for route key, backend, support state, dispatcher path, guidance mode, continuity case, replay result, media-contract result, and blocking reason.
