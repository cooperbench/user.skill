        # Implementation Plan: Clean Up Normal-Mode Log Output for Human Readability

## Overview

The worker's normal-mode (non-debug) log output is noisy and developer-focused. The goal is to make it clean, concise, and human-readable by:

1. **Consolidating redundant generation lines** (currently 4 per task → target 1-2)
2. **Demoting QWEN_HANDLER config dump** from INFO → DEBUG
3. **Replacing internal model names** with human-readable names in user-facing logs
4. **Demoting PATH_CHECK and STRUCTURE_VIDEO warnings** to DEBUG
5. **Consolidating travel orchestrator** internal essential-level noise
6. **Dropping internal module prefixes** (e.g. `[TASK_PROCESSING]`, `[BILLING]`) from user-facing output
7. **Consistent clean voice** across all essential/info/success-level messages

### Logging architecture

The project uses a custom logging system in `source/core/log/core.py`. Key facts:
- `essential()`, `success()`, `warning()`, `info()` always print. `debug()` only prints when `_debug_mode = True`.
- `ComponentLogger` instances (e.g. `generation_logger`, `model_logger`, `travel_logger`, `queue_logger`) wrap these functions with a component prefix.
- Output format: `[HH:MM:SS] LEVEL COMPONENT [Task ID] message`
- There is no standard Python `logging.getLogger(__name__)` in the hot path — component loggers dominate.

### Current generation lifecycle (4 lines per task, user-visible):

Lines 2-3 are WGP callbacks and 4-5 are post-extraction — these overlap with line 1.
