        # Implementation Plan: Declarative Workflow Routing

## Overview

The megaplan codebase currently embeds robustness-based routing decisions in 4 places across `handlers.py` and a hand-coded state machine in `_core.py:662-686`. The `is_light = configured_robustness(state) == "light"` pattern appears at:
- `handlers.py:806` — `handle_critique`: skips gate, writes synthetic gate artifact, routes to `revise` instead of `gate`
- `handlers.py:854,897,945` — `handle_revise`: skips gate precondition check, sets state to `STATE_GATED` instead of `STATE_PLANNED`, routes to `finalize` instead of `critique`
- `handlers.py:1179,1205` — `handle_execute`: transitions to `STATE_DONE` instead of `STATE_EXECUTED`, skips review

Meanwhile, `infer_next_steps` (`_core.py:662-686`) is a separate hand-coded state machine that doesn't account for robustness at all — it always returns standard-flow options.

**Goal:** Replace scattered conditionals with a declared workflow definition. Each handler does its job and asks the workflow "what's next?" Derive `infer_next_steps` from the same definition.

**Constraint:** The standard workflow has conditional branching (gate recommendation → ITERATE/ESCALATE/PROCEED) and override options (replan, force-proceed, abort, add-note). The declarative model must handle these — a simple linear list won't suffice.

## Phase 1: Foundation — Workflow Definition and Router

### Step 1: Audit and document the two actual flows (`megaplan/_core.py`)
**Scope:** Small
1. **Verify** the exact state transitions for each robustness level by tracing both paths through handlers. The current flows are:
   - **Light:** `initialized → plan → critique → revise → finalize → execute → DONE`
   - **Standard:** `initialized → plan → critique → gate → [revise → critique loop] → finalize → execute → review → DONE`
2. **Confirm** the conditional edges:
   - `critique → gate` (standard) vs `critique → revise` (light)
   - `gate` outcome: ITERATE → `revise`, ESCALATE → overrides, PROCEED+passed → `finalize`, PROCEED+!passed → `revise`/`force-proceed`
   - `revise → critique` (standard loop) vs `revise → finalize` (light)
   - `execute → review` (standard) vs `execute → DONE` (light)
3. **Confirm** `infer_next_steps` returns (standard-only, no robustness awareness): note that it always offers `step` as an option and override actions contextually.

### Step 2: Design and implement the workflow definition (`megaplan/_core.py`)
**Scope:** Medium
1. **Add** a `WorkflowDef` data structure near the existing state constants (`_core.py:~600`). The definition needs to express:
   - Ordered step sequence per robustness level
   - Conditional transitions (gate outcomes)
   - Override options available at each state
   - The "step" escape hatch (always available after planning)

   Proposed shape — a dict mapping `(state, robustness)` → transition rules:
   ```python
   @dataclass(frozen=True)
   class Transition:
       next_step: str
       next_state: str
       condition: str | None = None  # e.g. "gate:ITERATE", "gate:ESCALATE"

   WORKFLOW: dict[str, list[Transition]] = {
       STATE_INITIALIZED: [Transition("plan", STATE_PLANNED)],
       STATE_PLANNED: [Transition("critique", STATE_CRITIQUED)],
       # ... etc
   }

   WORKFLOW_OVERRIDES: dict[str, dict[str, list[Transition]]] = {
       "light": {
           STATE_CRITIQUED: [Transition("revise", STATE_GATED)],  # skip gate
           STATE_EXECUTED: [Transition(None, STATE_DONE)],  # skip review
       },
   }
   ```

2. **Implement** a `workflow_next(state: PlanState) -> list[str]` function that:
   - Reads `configured_robustness(state)` once
   - Looks up transitions from the workflow definition
   - Applies robustness overrides
   - Returns the valid next steps (replacing `infer_next_steps`)

3. **Keep** `infer_next_steps` as a thin wrapper or alias for backwards compatibility (it's exported in `__init__.py:40,63` and used in `cli.py:27,73,167`).

### Step 3: Validate the workflow definition with tests (`tests/test_megaplan.py`)
**Scope:** Small
1. **Update** `test_infer_next_steps_matches_new_state_machine` (`test_megaplan.py:160-182`) to test both robustness levels.

3. **Add** a test that verifies `workflow_next` returns the same results as the current hard-coded `infer_next_steps` for all standard-flow states (regression guard before we swap callers).
