## Overview
This sprint is a decision gate, not full Wan-family migration. The repo already documents the hypothesis in `docs/migration-vibecomfy.md`: existing Wan 2.2 VibeComfy templates use one `WanVideoModelLoader`, while WGP Wan 2.2 VACE uses HIGH and LOW checkpoints with sigma cut-over. The smallest useful implementation is therefore a focused, manual dry-run ready template that proves or disproves the two-stage `WanVideoSampler` chain before investing in the full `wanvideo_wrapper_22_14b_vace_cocktail.py` template.

The source of truth for pass/fail is `reigh-worker/scripts/dual_run_compare/migration-thresholds.yaml`, validated through `python -m scripts.dual_run_compare.check_thresholds --strict`. The dry run should use one 49-frame Wan VACE route, compare WGP reference output against the VibeComfy candidate, and write `dry-run-report.md` with an explicit `PROCEED` or `FALL-BACK` decision.
