        # Implementation Plan: Onboarding, Admin, Audit, Feedback, and Ops Finalization

## Overview
This plan completes the launch-readiness layer for the mediator bot: first-use onboarding, read-only operator/admin views, audit visibility, reaction feedback, deep health checks, backup tooling, staging replay, spend-cap behavior, and README runbook polish.

The critique flags do not indicate the plan is aimed at the wrong code or root cause. They identify three missing implementation details in the current codebase: spend caps need a durable retry/deferred path because `app/services/agentic.py` marks triggering messages processed before LLM calls; reaction feedback needs a durable idempotency key because `migrations/0001_init.sql` has no uniqueness for reaction events; and `get_bot_actions` must be expanded because `tool_schemas.py` and `app/services/tools/read_tools.py` currently expose only `final_output_message_id`, not outbound content. The revised plan keeps the same approach but makes those three fixes explicit.

Existing touch points are FastAPI routers in `app/routers/admin.py`, `app/routers/health.py`, and `app/routers/whatsapp.py`; inbound parsing in `app/services/inbound.py`; the agent loop in `app/services/agentic.py`; hot context in `app/services/hot_context.py`; outbound sending in `app/services/messaging.py`; spend helpers in `app/services/spend.py`; tools in `app/services/tools/read_tools.py`, `app/services/tools/write_tools.py`, and `tool_schemas.py`; user helpers in `app/models/user.py`; recovery in `app/services/recovery.py`; migrations in `migrations/`; and current tests in `tests/`.
