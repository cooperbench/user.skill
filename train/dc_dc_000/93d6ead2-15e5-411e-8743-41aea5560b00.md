# Implementation Plan: Phase 8 — Inbox Surface

## Overview

Phase 8 adds an external completion-signal protocol at `runs/<run-id>/inbox/`. External processes (humans, scripts, other tools) drop JSON files into that directory; on the next `artagents next` (or `status`) call, the kernel parses them, validates against the current cursor, and — for valid entries that match the current attested step — appends a `step_attested` event so the cursor advances. Malformed and stale entries are logged and skipped (never raised).

The work is purely additive. Five concrete touch points:
1. New module `artagents/core/task/inbox.py` (parser + consumer + dir helper).
2. Wire `scan_inbox` into `cmd_status` (read-only, count surface) and `cmd_next` (consume-then-re-read-active-run-then-derive).
3. Update the `AGENT.md` template in `lifecycle.cmd_start` to document the inbox surface.
4. Three new tests under `tests/`.
5. Re-export from `artagents/core/task/__init__.py` *and update its explicit `__all__`*.

Because the inbox is honor-based (V1 SD-025) and lives next to identity-pinned ack, an inbox entry produces a `step_attested` event with `attestor_kind="external"` and `attestor_id=submitted_by`. It does NOT go through `validate_attested_identity` — the trust model is filesystem write access. This intentional lower-trust path is exclusive to the inbox channel; the existing `cmd_ack` path remains identity-pinned and unchanged.

Inline produces checks already run inside `_run_inline_checks` after `step_attested` events are appended via `append_event` directly inside the gate. To preserve that for inbox-attested steps, `consume_inbox_entry` constructs a transient `GateDecision` exactly the way `_dispatch_attested` does and calls `_run_inline_checks` on it after appending the event.

Critical critique-driven safety points (see flags addressed):
- `cmd_next` must **re-read `active_run.json` after the inbox loop** because an inbox `abort` entry can clear it; the function then returns the same `aborted` codepath as `cmd_abort` instead of falling through to print step details against a stale local dict.
- `consume_inbox_entry`'s `retry` path **skips** the `produces_check_failed` prerequisite that `cmd_ack` enforces (`lifecycle_ack.py:257-264`). This divergence is intentional (inbox is the lower-trust channel); it is documented as an explicit assumption so test authors do not encode `cmd_ack` retry parity.

### Step 2: Implement the inbox module (`artagents/core/task/inbox.py`)
**Scope:** Medium
1. **Define** the on-disk schema and parser:
   ```python
   from dataclasses import dataclass

   INBOX_FILE_GLOB = "*.json"
   CONSUMED_DIRNAME = ".consumed"
   _ALLOWED_DECISIONS = ("approve", "retry", "abort")

   @dataclass(frozen=True)
   class InboxEntry:
       path: Path                # source file
       step_id: str              # STEP_PATH_SEP-joined plan path
       decision: str             # "approve" | "retry" | "abort"
       evidence: tuple[str, ...] # flattened from JSON list/dict
       submitted_at: str
       submitted_by: str
   ```
2. **Implement** `inbox_dir(run_dir: Path) -> Path` returning `run_dir / "inbox"` (no mkdir — opt-in by presence).
3. **Implement** `scan_inbox(run_dir: Path) -> list[InboxEntry]`:
   - If `inbox_dir(...)` is not a directory, return `[]` immediately (opt-in).
   - Iterate top-level `*.json` files (skip `.consumed/` subdir and any dotfile/dotdir).
   - Parse + validate each: must be a JSON object with required string fields `step_id`, `decision`, `submitted_at`, `submitted_by`; `decision` ∈ `_ALLOWED_DECISIONS`; `evidence` (optional) must be a list of strings or a `{key: value}` dict whose keys/values are strings (flatten dict to `["k=v", ...]`).
   - On any exception (bad JSON, bad schema, OSError), `logging.getLogger(__name__).warning(...)` with the file path + reason and skip — do NOT raise.
   - Return entries sorted by filename for deterministic processing order.
4. **Implement** `consume_inbox_entry(run_dir, entry, *, slug, run_id, project_root, projects_root) -> dict | None`:
   - Re-load `plan.json`, `events.jsonl`, run `peek_current_step`.
   - **Stale-or-malformed gates** (return `None` and leave the file in place):
     - run is exhausted, OR
     - cursor step is not an `AttestedStep` (e.g., code step), OR
     - `STEP_PATH_SEP.join(peek.path_tuple) != entry.step_id`.
   - For `decision="approve"`:
     - if `peek.item_id is not None` → `make_item_attested_event(peek.path_tuple, peek.item_id, attestor_kind="external", attestor_id=entry.submitted_by, evidence=entry.evidence)`.
     - else → `make_step_attested_event(STEP_PATH_SEP.join(peek.path_tuple), "external", entry.submitted_by, entry.evidence)`.
     - Then build a transient `GateDecision` mirroring `_dispatch_attested` and call the public-promoted inline-checks helper from `gate.py` if `peek.step.produces` is non-empty.
   - For `decision="retry"`: append `make_cursor_rewind_event(peek.path_tuple, reason="inbox retry")`. **Note**: this skips the `latest event must be produces_check_failed` prerequisite that `_ack_retry` (`lifecycle_ack.py:257-264`) enforces. This divergence is intentional and documented (see assumptions and FLAG-P8-003).
   - For `decision="abort"`: append `make_run_aborted_event(run_id, reason=f"inbox: {entry.submitted_by}")` and call `clear_active_run(slug, root=projects_root)`. Return the appended event so the caller (`cmd_next`) can detect the abort and short-circuit.
   - **Move** the file: `entry.path.replace(run_dir / "inbox" / ".consumed" / f"{event_hash}.json")` (mkdir parents). Hash-named for collision-free audit retention.
   - Return the appended event dict (or `None` for stale/no-op).
5. **Add** module-level docstring documenting (a) JSON shape, (b) lower-trust honor model (no identity pinning, no produces_check_failed prerequisite for retry), (c) `.consumed/` retention, (d) opt-in semantics.
