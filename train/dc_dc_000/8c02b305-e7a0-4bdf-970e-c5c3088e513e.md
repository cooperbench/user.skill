When you click a shot in the list, `useListShots` has already fetched that shot's full row from the DB — including `settings`. So the correct `generationMode` is sitting in memory. But the editor doesn't use that data. It calls `useShotSettings`, which calls `useToolSettings`, which fires a fresh `useQuery` with a different cache key. That query starts from scratch — empty cache, shows hardcoded defaults (`timeline`), fetches the DB, then finally resolves to the real value (`batch`). That's the flash. The fix: right before `useShotSettings` runs, `useSeedSettingsCache` takes the settings that are already in memory on the shot object and writes them into the React Query cache under the key that `useToolSettings` is about to look up. So when `useQuery` runs, it finds data already there — cache hit, no loading state, no flash. The real background fetch still happens, but the UI never shows wrong defaults. One line version: we connect the data that Pipeline 1 already has to the cache that Pipeline 2 is about to read from.
