**Findings**

1. High: `--explain` is not built from the same scoped queue inputs as the rendered queue. [`queue_flow.py:43`](file:///Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/queue_flow.py#L43) calls `build_queue_snapshot()` with only `state`, `plan`, and `target_strict`, while the real queue is built with `scope`, `status`, `include_skipped`, and `context` in [`queue_flow.py:318`](file:///Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/queue_flow.py#L318). That means `next --scope ... --explain` can report phase/counts for the whole repo instead of the actual queue the user is looking at.

2. High: `backlog --explain` does not actually share the same queue preamble as `next --explain`. Backlog disables plan context in [`queue_flow.py:77`](file:///Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/queue_flow.py#L77), `_plan_data_for_view()` then returns `None` in [`queue_flow.py:290`](file:///Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/queue_flow.py#L290), and that `None` is what gets passed into `explain_queue()` in [`queue_flow.py:153`](file:///Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/queue_flow.py#L153). In execute phase, [`policy.py:50`](file:///Users/user_c042661f/Documents/desloppify/desloppify/engine/_work_queue/policy.py#L50) then reports zero auto-queued/triage-promoted clusters because it has no plan to inspect. The added “backlog shares preamble” test never exercises the backlog flow; it just calls `explain_queue(snapshot, None)` twice.

3. Medium: markdown output drops the explanation entirely. The payload gets `queue_explanation` in [`queue_flow.py:153`](file:///Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/queue_flow.py#L153), but markdown rendering ignores payload and only prints the item table in [`output.py:181`](file:///Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/output.py#L181) and [`output.py:226`](file:///Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/output.py#L226). So `--explain --format md` diverges from terminal/JSON.

4. Medium: the execute-phase explanation still uses registry-wide detector names instead of the persisted active auto-queued clusters. [`policy.py:70`](file:///Users/user_c042661f/Documents/desloppify/desloppify/engine/_work_queue/policy.py#L70) lists every detector with `auto_queue=True`, and [`policy.py:96`](file:///Users/user_c042661f/Documents/desloppify/desloppify/engine/_work_queue/policy.py#L96) prints those names whenever `auto_count > 0`. If only `unused` is active, the text can still imply `logs` is present. That undercuts the “truthful explainability” goal.
