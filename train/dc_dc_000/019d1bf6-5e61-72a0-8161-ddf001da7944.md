## Overview

**Current state:** A YAML-driven video editing pipeline with Python CLI tools (`render.py`, `view.py`, `ingest.py`, `search.py`, `imagegen.py`, `tts.py`, `place.py`), an ffmpeg-based render engine, and a React/Vite timeline viewer using `@xzdarcy/react-timeline-editor`. The timeline viewer already has drag-drop, resize, overlay editing, and live preview — it reads/writes `timeline.yaml` via Vite dev server API endpoints.

**Goal:** Replace the ffmpeg render pipeline with Remotion compositions that read a shared JSON config. Use Remotion Studio for preview/playback. Keep Python tools and natural-language editing working against the same config. The React viewer becomes Phase 2 (visual editing layered on top).

**Key constraints:**
- Two edit paths (AI agent + eventual visual UI) writing to the same JSON config
- Remotion is the sole render engine — reads config, produces video
- Python tools continue to work, writing to a shared asset registry
- Start with Remotion Studio + natural language editing; visual editing later
- Open source

**Current data flow:**
```
timeline.yaml → render.py → ffmpeg filter_complex → output/render.mp4
                view.py → text inspection
                viewer/ (React) → visual preview + editing → timeline.yaml
```

**Target data flow:**
```
timeline.json + asset-registry.json
    ← Python tools (ingest, place, view, search, imagegen, tts)
    ← AI agent (Claude editing JSON directly)
    → Remotion compositions → Remotion Studio (preview) / Remotion render (output)

```

## Step 1: Design and write the JSON config schemas
**Scope:** Small — schema design, no code changes yet

1. **Design `timeline.json`** — a direct translation of the current `timeline.yaml` structure to JSON, with these sections:
   - `output`: resolution, fps, file path, background settings
   - `clips[]`: each clip with `id`, `at`, `track`, `asset`, `from`, `to`, `speed`, `hold`, `volume`, position/size for overlays, `effects`
   - Keep the schema flat and explicit — no nesting beyond what exists in YAML

2. **Design `asset-registry.json`** — extracted from the current `asset_map` in timeline.yaml plus metadata from asset profiles:
   - `assets`: keyed by asset ID, each entry has `file` (path), `type` (video, audio, image), `duration`, `resolution`, `fps`
   - This is the bridge between Python ingest tools and Remotion

3. **Write a migration script** (`tools/migrate_yaml_to_json.py`) that converts the existing `timeline.yaml` + `asset_profiles/*.yaml` into the two JSON files. This validates the schema design against real data immediately.

4. **Validate:** Run the migration script, inspect the output JSON, confirm round-trip fidelity (all 64 assets, all clips, all effects preserved).

**Files created:** `timeline.json`, `asset-registry.json`, `tools/migrate_yaml_to_json.py`

## Step 3: Build the core Remotion composition — video track
**Scope:** Large — this is the main rendering logic

1. **Create `remotion/src/VideoTrack.tsx`** — a Remotion `<Sequence>` per video clip:
   - Read clips from `timeline.json` where `track === 'video'`
   - For each clip: position via `<Sequence from={frameAt} durationInFrames={frameDuration}>`
   - Handle `from`/`to` trim via `startFrom` prop on `<Video>`
   - Handle `speed` via Remotion's `playbackRate`
   - Handle `hold` for images via `<Img>` inside a `<Sequence>`
   - Handle gaps between clips (black frames — just empty sequences)

2. **Create `remotion/src/AudioTrack.tsx`** — same pattern for audio clips:
   - `<Audio>` components in `<Sequence>` wrappers
   - Handle `volume`, `from`/`to` trim, `speed`

3. **Create `remotion/src/OverlayTrack.tsx`** — overlays with position/size:
   - `<AbsoluteFill>` with positioned `<Img>` or `<Video>` components
   - Handle `x`, `y`, `width`, `height`, `opacity`

4. **Create `remotion/src/Effects.tsx`** — fade_in / fade_out:
   - Use `interpolate()` on opacity for fade effects
   - Applied as wrappers around clip content

5. **Create `remotion/src/Background.tsx`** — background image compositing:
   - Reads `output.background` and `output.background_scale` from config
   - Renders background image full-frame, then scales content layer

6. **Wire into `remotion/src/Timeline.tsx`** — the main composition:
   - Composes VideoTrack + AudioTrack + OverlayTrack + Background
   - Calculates total duration from clips (matching `render.py`'s `total_dur` logic)
   - Registers as a Remotion composition in `Root.tsx`

7. **Validate:** Open Remotion Studio, verify the existing timeline plays back correctly. Compare a few key timestamps against the current ffmpeg render output. Check: first clip plays, audio syncs, overlays appear at correct positions, fades work.

**Files created:** `remotion/src/{VideoTrack,AudioTrack,OverlayTrack,Effects,Background,Timeline}.tsx`
