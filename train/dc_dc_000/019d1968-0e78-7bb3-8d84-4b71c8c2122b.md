# Implementation Plan: Plan Template & Structural Validation

## Overview

Add a concrete markdown template to the plan prompt, a lightweight fence-aware structural validator that runs after plan generation (and revision), and structural validation guidance to the critique prompt. The template codifies the patterns already proven in high-quality plans (Overview, numbered Steps with file:line refs, Execution Order, Validation Order). The validator is a fast regex check on non-fenced lines — no LLM needed — that catches structural gaps before the plan enters the critique loop.

## Step 0: Baseline
**Files**: none (read-only)
- Run `pytest` to confirm green.

## Step 1: Add the plan template to the prompt (`prompts.py`)
**~40 lines added to `_plan_prompt()`**

1. **Add** a `PLAN_TEMPLATE` constant string in `prompts.py` containing the expected markdown structure as a concrete example. The template should show:
   - `# Implementation Plan: [Title]`
   - `## Overview` — 2-3 sentence summary of what changes and why
   - `## Step N: [description] (\`filename.py\`)` — numbered steps with:
     - Scope estimate in bold: `**~X lines changed**`
     - Numbered substeps with **bold action verbs**: `**Remove**`, `**Add**`, `**Update**`
     - File:line references in parens: `(lines 30-45)`
     - Code snippets in fenced blocks when essential
   - `## Execution Order` — numbered list with rationale for sequencing and risk notes
   - `## Validation Order` — numbered "cheap first" list of verification steps
2. **Include** a brief instruction block explaining the template is a guide, not rigid: plans with 2-3 steps can collapse Execution/Validation into a single section, plans with 15+ steps should use them fully. The key invariants are: must have Overview, must have numbered Steps, must have at least one of Execution Order or Validation Order.
3. **Inject** the template into the prompt text returned by `_plan_prompt()`, after the Requirements block.

## Step 2: Structural validator (`evaluation.py`)
**~60 lines added, new function `validate_plan_structure()`**

1. **Add** a helper `_strip_fenced_blocks(text: str) -> str` that removes content inside triple-backtick fences. Implementation: iterate lines, track a boolean `in_fence` toggled by lines starting with ` ``` `, and only yield lines where `in_fence` is False. This prevents headings or numbered items inside code examples from triggering false positives or hiding real structural gaps.
2. **Add** `validate_plan_structure(plan_text: str) -> list[str]` that:
   - Calls `_strip_fenced_blocks()` first, then runs all checks on the stripped text.
   - Has exactly one H1 heading (`# `)
   - Has `## Overview` section (case-insensitive match on stripped lines)
   - Has at least one `## Step N:` section (regex: `^## Step \d+`)
   - Has at least one of `## Execution Order` or `## Validation Order`
   - Each Step section contains at least one numbered substep (`^\d+\.`)
   - Optional (warning-level, not blocking): steps reference files (backtick patterns)
3. **Return** list of strings like `"Missing required section: ## Overview"`, `"Step 2 has no numbered substeps"`. Empty list means structurally valid.
4. **Keep it pure** — no I/O, no LLM. The fence-stripping is a simple state toggle, not a full markdown parser.

## Step 3: Wire validator into plan and revise handlers (`handlers.py`)
**~20 lines changed across `handle_plan()` and `handle_revise()`**

1. **In `handle_plan()`** — after `plan_text = payload["plan"].rstrip() + "\n"` (line 415), call `validate_plan_structure(plan_text)`. If issues are returned, add `"structure_warnings": [...]` to the meta dict. If there are zero `## Step` sections, raise `CliError("structure_error", ...)` — this is the only hard failure.
2. **In `handle_revise()`** — after `plan_text = payload["plan"].rstrip() + "\n"` (line 560), add the same validation call and `structure_warnings` to meta. Same hard-fail rule for zero steps.
3. **Both paths** write `structure_warnings` into their respective `plan_vN.meta.json`, so the audit trail and downstream prompts (critique, gate) always have visibility.
