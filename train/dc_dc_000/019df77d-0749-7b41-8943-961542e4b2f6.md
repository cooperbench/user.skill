PHASE 7 SCOPE (from docs/orchestrator-v1-plan.md):

- Per-project content-addressable store at `<project_slug>/.cas/<sha256>` for produces artifacts.
- When a step's produces check accepts a file, the file is moved into `.cas/<hash>` and a symlink replaces the original path. Subsequent steps that produce identical content reuse the same CAS entry (no duplication).
- Per-project, NOT a shared CAS across projects (per SD: V1 stays single-host file-based with per-project scope).
- Files touched: `artagents/core/task/`, `artagents/core/project/run.py`.

EXIT CRITERIA (from design doc):
- Artifacts stored once and linked into step produces.
- No shared CAS exists across projects.
- Symlinks resolve to `.cas/<sha256>`.
- Identical content from different steps shares one CAS entry.

WHAT TO IMPLEMENT:

1. New module `artagents/core/task/cas.py` (or similar) with:
   - `cas_path(project_dir, sha256) -> Path` — returns `<project_dir>/.cas/<sha256>`
   - `intern(project_dir, source_path) -> Path` — moves file into CAS by content hash, returns CAS path. Idempotent: if hash already exists, leaves the existing entry and discards the source.
   - `link_into_produces(cas_path, target_path)` — symlinks `target_path -> cas_path` (relative symlink so the run dir stays portable).

2. Hook the produces flow (in the runner that handles produces checks):
   - After a produces check passes for a file artifact, intern the file and replace the original path with a symlink to the CAS entry.
   - Update `events.jsonl` records to include the CAS hash for each interned artifact.

3. Tests:
   - `tests/test_cas_intern.py`: writes a file, calls intern twice with identical content, asserts only one CAS entry exists and the second call discards the duplicate source.
   - `tests/test_cas_symlink.py`: full produces flow — step writes a file, post-check it's a symlink into `.cas/<hash>`.
   - `tests/test_cas_per_project.py`: two project slugs with identical content produce two separate CAS entries (per-project scope, NOT shared).

4. Update `artagents/structure.py` to acknowledge `.cas/` as a known per-project directory if there's a directory whitelist; otherwise leave structure alone.

5. Update `.gitignore` to exclude `*/runs/*/.cas/` and `**/.cas/` if not already.

CONSTRAINTS:
- Stay within Phase 7 scope. Do NOT touch Phase 8 inbox or Phase 9 golden tests.
- Additive only. Existing tests must continue to pass.
- No new dependencies (use stdlib `hashlib` and `os.symlink`).
- Honor existing patterns: hash-chained events, gate above dispatch, file-based state.
- The CAS is per-project. There is no shared CAS across projects. Reject any design that introduces one.

STOP CONDITION: Phase 7 done when `pytest tests/` passes with new tests + the produces flow uses `.cas/<sha256>` symlinks.

        # Implementation Plan: Phase 7 Per-Project CAS

## Overview
Add a per-project content-addressable store under `<project>/.cas/<sha256>` and wire task produces checks so accepted file artifacts are interned once, then replaced at their declared produces path with a relative symlink to the CAS object. The runtime insertion point is `artagents/core/task/gate.py` around `_run_inline_checks()` after `entry.check.run(artifact_path)` succeeds and before `make_produces_check_passed_event(...)` is appended. Project-attached hype artifact mirroring in `artagents/core/project/run.py` should continue to write normal files into the step `produces/` directory; the gate should be responsible for interning after checks pass.

The design stays per-project only: CAS root is derived from `decision.project_root / ".cas"`, never from repo root, user home, global cache, or a shared service.

## Main Phase

### Step 1: Add the CAS helper module (`artagents/core/task/cas.py`)
**Scope:** Small
1. Implement `cas_path(project_dir, sha256) -> Path` as `Path(project_dir) / ".cas" / sha256`, validating only enough to keep the helper direct and predictable.
2. Implement `intern(project_dir, source_path) -> Path` using stdlib `hashlib.sha256()` streaming reads.
3. In `intern`, create `<project>/.cas/`, move the source into `.cas/<hash>` when absent, and when present delete the duplicate source file. Keep it idempotent for the case where `source_path` already resolves to the target CAS entry.
4. Implement `link_into_produces(cas_path, target_path)` by unlinking the target path and creating a relative symlink from the target’s parent to the CAS entry. Ensure parent directories exist.
5. Avoid new dependencies and avoid any shared cache abstraction.

### Step 2: Extend produces-passed events (`artagents/core/task/events.py`)
**Scope:** Small
1. Update `make_produces_check_passed_event(...)` to accept optional CAS metadata, likely `cas_hash: str | None = None` and optionally `cas_path: str | None = None` if useful for audit.
2. Prefer the required hash as the durable event field. Keep existing call sites compatible by making the new parameter optional.
3. Preserve hash-chained event behavior by adding fields before `append_event()` computes the event hash; do not mutate stored events afterward.

### Step 3: Intern artifacts after successful inline checks (`artagents/core/task/gate.py`)
**Scope:** Medium
1. Import the new CAS helper module.
2. In `_run_inline_checks()` near `artagents/core/task/gate.py:1128`, after `result.ok` is true for `artifact_path`, intern the artifact using `decision.project_root` as the project directory.
3. Replace the original produces path with a relative symlink to the returned CAS entry using `link_into_produces(...)`.
4. Append `produces_check_passed` with the CAS hash, derived from the CAS entry name.
5. Only intern file artifacts after their check passes. If the declared produces path is missing or not a regular file, let the existing verifier failure path handle it instead of adding a parallel error mode.
6. Keep cursor behavior unchanged: failures still append `produces_check_failed` and rewind or mark iteration failure; successes still advance only after every declared produces entry has a passed event.

### Step 4: Keep project mirroring compatible (`artagents/core/project/run.py`)
**Scope:** Small
1. Leave `mirror_hype_artifacts(...)` copying artifacts into task step `produces/` as regular files.
2. Confirm that task-attached runs still write to `step_dir_for(...)` via `prepare_project_run(...)`, so the gate sees those mirrored files and interns them during the produces check phase.
3. Only touch this file if tests show mirrored artifacts bypass the inline check path or if path handling needs a small adjustment.

### Step 5: Update repository ignore and structure guardrails (`.gitignore`, `artagents/structure.py`)
**Scope:** Small
1. Add `.gitignore` entries for `**/.cas/` and, if needed for explicit project-run layout coverage, `*/runs/*/.cas/`.
2. Inspect whether `artagents/structure.py` has any project directory whitelist. Current repo structure checks focus on repository packages and local legacy directories, so likely no code change is required there.
3. If a project-local directory whitelist exists elsewhere, add `.cas/` as a known per-project state directory without allowing a shared repo-level CAS.

### Step 6: Add focused tests (`tests/test_cas_intern.py`, `tests/test_cas_symlink.py`, `tests/test_cas_per_project.py`)
**Scope:** Medium
1. `tests/test_cas_intern.py`: create a temp project directory, write two files with identical bytes, call `intern()` on both, assert both calls return the same `<project>/.cas/<sha256>`, only one CAS entry exists, first source moved, second duplicate source removed, and CAS content is unchanged.
2. `tests/test_cas_symlink.py`: use the existing task run test style from `tests/test_task_inline_checks.py`; create a code step with a `json_file` produces check, write valid JSON to the step produces path, call `record_dispatch_complete()`, assert the produces path is a symlink, resolves under `<project>/.cas/<sha256>`, and the `produces_check_passed` event includes that hash.
3. `tests/test_cas_per_project.py`: create two separate project slugs with identical produced content, run the same helper or flow for each, and assert each project has its own `.cas/<sha256>` entry with no shared parent and no cross-project symlink target.
4. Add one duplicate-content full-flow assertion if cheap: two steps in the same project produce identical content and both symlinks resolve to the same single CAS entry.

### Step 7: Validate incrementally
**Scope:** Small
1. Run targeted tests first: `pytest tests/test_cas_intern.py tests/test_cas_symlink.py tests/test_cas_per_project.py tests/test_task_inline_checks.py`.
2. Run project-run coverage if `artagents/core/project/run.py` changed: `pytest tests/test_project_runs.py`.
3. Finish with the required full suite: `pytest tests/`.

## Execution Order
1. Add `cas.py` and unit-test it before touching the gate.
2. Extend event construction with optional CAS fields while preserving existing callers.
3. Wire `_run_inline_checks()` to intern and relink only after verifier success.
4. Add full-flow tests for symlink and per-project behavior.
5. Update `.gitignore`, then run targeted and full tests.

## Validation Order
1. `pytest tests/test_cas_intern.py` for pure CAS behavior.
2. `pytest tests/test_cas_symlink.py tests/test_task_inline_checks.py` for produces flow and event compatibility.
3. `pytest tests/test_cas_per_project.py` for per-project isolation.
4. `pytest tests/` as the stop-condition gate.
