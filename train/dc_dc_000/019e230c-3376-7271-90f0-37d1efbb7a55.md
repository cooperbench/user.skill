        # Implementation Plan: Live-Update Topic Editor Cutover

## Overview

The latest critique does not show that the plan is targeting the wrong code or wrong root cause: the root problem is still the legacy editor's prompt/JSON/candidate architecture, and the requested fix is still a new topic editor. The runbook still matters for operational checks and rollback, but it must be edited so operators are not asked to satisfy stale cutover gates. Invalid `update_topic_source_messages` and `discard_topic` calls must not invent `rejected_update_*` or `rejected_discard` actions. ### Step 2: Add Phase-1 topic schema migration (`.migrations_staging/20260513*_live_update_topic_editor_phase1.sql`)
**Scope:** Large
1. Create the five topic tables from v6: `topics`, `topic_sources`, `topic_aliases`, `topic_transitions`, and `editorial_observations`.

4. Add `topic_editor_runs` columns needed for operations: `run_id`, `environment`, `guild_id`, `live_channel_id`, `trigger`, `status`, `started_at`, `completed_at`, `lease_expires_at`, `checkpoint_before`, `checkpoint_after`, counts, error fields, and `metadata` for cost/latency/tool-call summaries.

7. Include required indexes: topic state/revisit/headline trigram, source message lookup, transition topic/run/action indexes, topic-editor run status/created indexes, and checkpoint uniqueness.
8. Enable `pg_trgm` in the migration if not already enabled, because collision detection depends on trigram similarity.
9. Define `topic_transitions.action` to allow accepted/base actions (`post_simple`, `post_sectioned`, `watch`, `update_sources`, `discard`, `override`, `observation`) plus only the locked rejected actions (`rejected_post_simple`, `rejected_post_sectioned`, `rejected_watch`). Do not add `rejected_update_sources` or `rejected_discard` unless the sprint decisions are explicitly changed.

### Step 7: Implement dispatcher invariants and audit mapping (`src/features/summarising/topic_editor.py`)
**Scope:** Large
1. Reject `post_simple_topic` when source messages include `>= 2` distinct authors or `>= 3` source messages; write `topic_transitions.action='rejected_post_simple'` with `topic_id=NULL` and rejection details in `payload`.

Run canonical/alias/similarity collision scans for every `post_simple_topic`, `post_sectioned_topic`, and `watch_topic` write, returning a tool error unless matching `override_collisions` are provided. 6. For invalid `discard_topic` calls, return a tool error and write a `topic_transitions` row with `action='discard'`, `topic_id` when resolvable, `to_state` unchanged or NULL, and `payload.outcome='tool_error'`. Do not invent `rejected_discard`.
7. For accepted actions, write normal transition rows using `post_simple`, `post_sectioned`, `watch`, `update_sources`, `discard`, `override`, or `observation` as appropriate.
8. Cap `record_observation` by prompt guidance to roughly 3/run and store observations for later 30-day retention cleanup.
