        # Implementation Plan: Clean-by-Default Logging Policy

## Overview

The reigh-worker and reigh-worker-orchestrator repos have two separate logging systems:
- **Worker**: Custom print-based system in `source/core/log/core.py` with a global `_debug_mode` flag. Levels: `essential`, `success`, `warning`, `error`, `critical` (always-on), `debug` (gated), `progress`/`status` (always-on).
- **Orchestrator**: Standard Python `logging` module with `LOG_LEVEL` env var and JSON/plain formatting in `gpu_orchestrator/logging_config.py`.

**Problem**: Normal production runs are noisy. The main offenders are:
1. Orchestrator `control_loop.py` prints `===` separators and task counts (some at CRITICAL level) every 30-second cycle.
2. Worker `task_processor.py` logs detailed per-task diagnostics at INFO level (lock acquisition, phase config, SVI2PRO patching, worker loop retrieval/start/completion).
3. The worker has no intermediate level between "always show" and "debug only" — `progress()` and `status()` are always-on but many callers use `essential()`/`info()` for things that should be quiet by default.

**Approach**: Rather than adding new log levels or restructuring the logging system, the cleanest fix is to **demote noisy call sites** to `debug()` (worker) or `logging.debug()` (orchestrator), and convert the orchestrator's raw `print()` calls to proper logger calls gated by level. The existing `--debug` flag and `LOG_LEVEL=DEBUG` env var already provide the "verbose mode" toggle — we just need to move things behind it.
