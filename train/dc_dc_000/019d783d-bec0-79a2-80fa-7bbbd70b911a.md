        # Implementation Plan: Clean Logging with REIGH_DEBUG

## Overview

The Reigh Worker has a custom `ComponentLogger` system (`source/core/log/core.py`) with two tiers: `essential()`/`info()` (always printed) and `debug()` (only when `_debug_mode` is True). The problem is that ~190 calls across 41 source files use `essential()`/`info()` for what are really diagnostic/internal messages, making non-debug output very noisy.

**Current state:**
- `--debug` CLI flag already calls `enable_debug_mode()` / `disable_debug_mode()`
- No env var mechanism exists — `REIGH_DEBUG` needs to be added
- Wan2GP vendored code (~98 `logger.info()` calls across 30 files) uses standard Python `logging` and is partially suppressed in `capture.py` (diffusers, transformers, torch, PIL only)
- The supervisor process uses standard `logging.basicConfig(level=logging.INFO)`
- The preview harness (`scripts/preview/run_preview.py`) is a separate entry point that also needs the env var

**Design approach:** The `ComponentLogger` already has the debug/essential split. The work is (a) wire `REIGH_DEBUG` env var to toggle `_debug_mode`, (b) audit every `.essential()` and `.info()` call and demote diagnostic ones to `.debug()`, (c) suppress Wan2GP standard-logging noise when not in debug mode, (d) set supervisor logging level based on debug flag.

## Phase 1: REIGH_DEBUG Env Var Mechanism

### Step 1: Wire REIGH_DEBUG into the logging core (`source/core/log/core.py`)
**Scope:** Small
1. **Add** an `init_from_env()` function that reads `REIGH_DEBUG` env var and calls `enable_debug_mode()` if truthy (e.g., `REIGH_DEBUG=1`, `REIGH_DEBUG=true`).
2. **Keep** the existing `enable_debug_mode()` / `disable_debug_mode()` API unchanged — `init_from_env()` is additive.

### Step 2: Call `init_from_env()` from all entry points
**Scope:** Small
1. **Update** `source/runtime/worker/server.py:main()` (~line 289): check `REIGH_DEBUG` env var alongside `cli_args.debug`. The env var should be an OR — either `--debug` or `REIGH_DEBUG=1` enables debug mode.
2. **Update** `source/runtime/supervisor.py:main()` (~line 31): after `basicConfig`, check `REIGH_DEBUG` to set the standard logging level to `DEBUG` instead of `INFO`.
3. **Update** `scripts/preview/run_preview.py`: early in startup, check `REIGH_DEBUG` and call `enable_debug_mode()` if set.

## Phase 2: Demote Diagnostic Logs to DEBUG

### Step 3: Audit and demote `source/task_handlers/` logs
**Scope:** Large — 9 files, ~50 calls
1. **Demote to `.debug()`** all internal operational messages: lock acquisition, phase config application, parameter resolution, sampler/preset details, PNG conversion details, SVI2PRO internals.
2. **Keep as `.essential()`** user-facing lifecycle: task claimed, generation starting, generation complete, task failed, upload complete, waiting for work.
3. **Files to touch:** `task_processor.py`, `task_queue.py`, `queue_lifecycle.py`, `wgp_init.py`, `task_registry.py` (in `source/task_handlers/`), plus `task_conversion.py`, `extract_frame.py`, `rife_interpolate.py`, `magic_edit.py`.

### Step 4: Demote `source/models/` logs
**Scope:** Large — 8 files, ~30 calls
1. **Demote to `.debug()`** all messages with diagnostic prefixes: `[DEBUG_*]`, `[INIT_DEBUG]`, `[AGGRESSIVE]`, `[SMOKE]`, `[UNI3C_CACHE]`, `[PASSTHROUGH_DEBUG]`, `[OUTPUT_DIR]`, `[LORA_APPLICATION_TRACE]`, `[PARAM_RESOLUTION]`.
2. **Demote** ComfyUI server start/stop internals, LoRA cleanup details.
3. **Keep as `.essential()`** model loading/unloading, download progress, generation start/complete.
4. **Files to touch:** `orchestrator.py`, `model_ops.py`, `wgp_params.py`, `comfy_utils.py`, `comfy_handler.py`, `lora_utils.py`, `preflight.py`, `generation_strategies.py`, `output.py`.

### Step 5: Demote `source/core/` and `source/media/` logs
**Scope:** Medium — ~15 files, ~40 calls
1. **Demote** internal DB query details, parameter config application, VLM prompt construction details, video transform internals, frame utility details, download progress per-chunk.
2. **Keep** download start/complete, DB connection errors, high-level media processing milestones.

### Step 6: Demote `source/runtime/` logs
**Scope:** Small — 2 files, ~5 calls
1. **Demote** `[SUPERVISOR] idle-release restart` to debug.
2. **Demote** `[WORKER] Idle release suppressed` and similar internal state messages.
3. **Keep** worker startup, worker shutdown, fatal errors.

## Phase 3: Quiet Wan2GP Downstream Logging

### Step 7: Suppress Wan2GP standard-logging noise when not in debug mode (`source/models/wgp/generators/capture.py`, `source/runtime/worker/server.py`)
**Scope:** Medium
1. **Expand** the existing library logger suppression in `capture.py` (lines 201-206) to also cover Wan2GP's own loggers. Add a broader suppression: set the root-level `Wan2GP` logger (and known noisy children) to `WARNING` when debug mode is off.
2. **Add** a centralized function `quiet_wan2gp_logging()` in `source/core/log/core.py` (or a new `source/core/log/library_logging.py`) that sets `logging.getLogger("Wan2GP").setLevel(logging.WARNING)` and also bumps the general third-party loggers (mmgp, triton, etc.) to WARNING. Call this early in `server.py:main()` when not in debug mode.
3. **When debug mode IS enabled**, leave Wan2GP loggers at their default level (INFO) so developers can see everything.

## Phase 4: Validation

### Step 8: Manual smoke test
**Scope:** Small
1. **Run** the worker without `--debug` and without `REIGH_DEBUG` — verify output is minimal: only lifecycle events (startup, task claim, generation progress, completion, shutdown).
2. **Run** with `REIGH_DEBUG=1` — verify all diagnostic output reappears.
3. **Run** the preview harness both ways to confirm it respects the env var.

### Step 9: Run existing tests
**Scope:** Small
1. **Run** any existing test suite to ensure nothing breaks from the log level changes.
2. **Update** any tests that assert on specific log output strings if the calls were demoted from `essential()` to `debug()`.

## Execution Order

2. Steps 3-6 in parallel (bulk demotion work) — independent file sets.
3. Step 7 after Step 1 (needs debug mode check).
4. Steps 8-9 last (validation).

## Validation Order

2. After Steps 3-7: run worker, eyeball output cleanliness.
3. Step 9: run test suite.
