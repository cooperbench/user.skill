## Overview

**Goal.** Replace the rigid Phase A / Phase B agent loop with a single adaptive orchestrator driven by a small, model‑visible **TurnPlan**. A TurnPlan is an ordered checklist of steps drawn from a closed vocabulary (`orient`, `read`, `consult`, `respond`, `record`, `schedule`, `done`). The runner picks a default *skeleton* per trigger (quick / standard / charged / crisis / silence), injects step‑local instructions only when that step is active, and lets the agent revise the plan via an in‑memory `update_turn_plan` tool. Read‑before‑write and outbound safety stay intact, enforced at the tool dispatcher rather than by a phase split.

**Current shape.**
- `app/services/agentic.py:611` — `_run_agentic` makes two `run_phase` calls (Phase A read+respond with `read_phase_tools`; Phase B write‑only with `write_phase_tools`). Phase B seed re‑sends the conversation plus a "you sent X" recap (`app/services/agentic.py:766–782`).
- `app/services/tools/registry.py:206–213` — `_phase_allowed` keys off `ctx.phase` ("read" | "write" | "consult").
- `app/bots/base.py:17–80` — `BotSpec` exposes `phase_a_instruction` / `phase_b_instruction` and `build_phase_a_seed` / `build_phase_b_seed_message`.
- `app/services/prompts.py:95–108` — system prompt hard‑codes the "Two‑Phase Turn Shape" section.

**Constraints that matter.**
- `run_phase` is generic and good — keep it. The orchestration above it is what changes.
- Outbound guardrails (`_resolve_outbound_text`, `_newer_inbound_exists`, paced send hooks, `send_message_part` interruption) must keep working.
- `bot_turns` reasoning, tool‑call accounting, spend cap, and `claim_onboarding_welcome` semantics must be preserved.
- Tests already pin Phase A / Phase B vocabulary — they need updates, not workarounds.

**Design hypothesis.** The cheapest elegant design is *not* to throw away phase gating. It is to:
1. Generalize phases into a tiny ordered TurnPlan (vocabulary above).
2. Pre‑select a skeleton based on the triggering signal so simple turns stay one‑LLM‑call cheap.
3. Make the plan visible to the model as a checklist appended to the seed and updatable via one in‑memory tool, so the agent reasons in steps the same way the runner does (this is the "elegance" lever).
4. Keep read‑before‑write at the dispatcher (per‑write‑tool prerequisite map), not at the phase boundary, so a quick reply can skip reads entirely without losing the safety property.

## Phase 2: Adaptive Orchestrator

### Step 5: Replace phase gating with step‑aware tool gating (`app/services/tools/registry.py`)
**Scope:** Small
1. **Define** `STEP_ALLOWED_TOOLS: dict[TurnStep, set[str]]`:
   - `orient`: `{}` (no tool calls; only thinking)
   - `read`: current `READ_PHASE_TOOLS` minus `send_message_part`
   - `consult`: current `CONSULT_PHASE_TOOLS`
   - `respond`: `{"send_message_part", "search_emojis", "check_oob"}`
   - `record`: current `WRITE_PHASE_TOOLS` minus scheduling tools, plus all read tools (so the model can confirm before writing without re‑gating)

2. **Add** a `READ_BEFORE_WRITE: dict[str, set[str]]` mapping each "must search first" write tool to the set of read tools that satisfy the prerequisite. Examples:
   - `add_memory` / `update_memory` / `supersede_memory` → `{"get_memories"}`
   - `log_observation` / `update_observation` → `{"get_observations"}`

3. **Track** read tool calls in `TurnContext.tool_call_log` (new field — list of names). In `call_tool`, before dispatching a write tool, check `READ_BEFORE_WRITE`; if no satisfying read in this turn, return a `_tool_error` instructing the model to call the matching read first. This preserves "search before write" without needing a phase split.
4. **Update** `_phase_allowed` → `_step_allowed(ctx)` returning `STEP_ALLOWED_TOOLS[ctx.current_step] | {"update_turn_plan"}`.

### Step 6: Rewrite the orchestrator (`app/services/agentic.py`)
**Scope:** Medium
1. **Replace** `_run_agentic` (`app/services/agentic.py:611–864`) with a step‑driven loop. Pseudocode:
   ```python
   plan = bot_spec.pick_default_skeleton(trigger_metadata, charge, hot_context)
   ctx.turn_plan = plan
   seed = bot_spec.build_initial_seed(trigger_metadata, triggering_message_ids, charge, plan)
   messages: list[dict] = list(seed)
   total_tool_count = 0
   while plan.current_step() != "done":
       ctx.current_step = plan.current_step()
       step_messages, step_tool_count = await run_step(
           client, ctx, system_prompt, rendered_hot_context,
           STEP_ALLOWED_TOOLS[ctx.current_step] | {"update_turn_plan"},
           messages,
           max_tool_iterations=STEP_ITERATION_CAPS[ctx.current_step],
       )
       messages = step_messages
       total_tool_count += step_tool_count
       _advance_plan(plan, step_messages)        # marks current step done unless model added new steps
       if plan.current_step() in {"record", "schedule"} and not _has_remaining_writes(plan):
           break
       if plan.current_step() != "done":
           messages.append(bot_spec.build_step_transition_message(plan, sent_summary=...))
   ```
2. **Reuse** the existing `run_phase` body as a step runner — rename to `run_step` and let the caller pass `max_tool_iterations` and the allowed tool set. The text‑extraction logic at `app/services/agentic.py:300–306` already returns final assistant text; the orchestrator captures it only for steps where it matters (`respond`).
3. **Wire** outbound resolution exactly where it lives now. After the `respond` step:

   - Run `_extract_reaction_directive`, `clean_user_facing_text`, `_resolve_outbound_text`, `_newer_inbound_exists` checks (`app/services/agentic.py:696–761`) **unchanged**. The fact that this happens after the `respond` step rather than at end‑of‑Phase‑A is the only structural change.

4. **Compute** `sent_summary` (today: `app/services/agentic.py:768–779`) once, after `respond`, and pass it into `build_step_transition_message` only when transitioning into `record`. This preserves the existing accountability nudge ("you actually sent N messages: …").
5. **Keep** spend cap fallback, paced send, NewerInbound handling, and `_complete_turn` semantics. The `phase_a_sent` flag becomes `responded_to_user` and is set after `respond`.
6. **Persist** the final plan trace into `bot_turns.reasoning` alongside existing reasoning fragments. No new column required — append a single line like `Turn plan executed: orient → read → respond → record (skipped: consult, schedule)`.
