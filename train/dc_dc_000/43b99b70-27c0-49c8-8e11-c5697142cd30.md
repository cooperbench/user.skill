### 6. **The Root Cause**

The `detect_lang_security_detailed()` method receives a `files` list that has already been filtered by exclusions, BUT:

1. It extracts `scan_root` from those files (line 145)
2. Then calls `detect_with_bandit(scan_root, zone_map)` (line 149)
3. **Bandit rescans the entire `scan_root` directory** (not just the filtered files)
4. Bandit is invoked WITHOUT any exclusion flags

So `.venv` and other excluded directories get scanned anyway because bandit doesn't know about desloppify's exclusions.

## The Fix Strategy

To fix this bug, you need to pass the **already-filtered `files` list** to bandit instead of letting bandit rescan the entire directory. There are two approaches:

1. **Pass filtered files to bandit**: Modify `detect_with_bandit()` to accept a `files` parameter and invoke bandit with explicit file arguments instead of directory recursion
2. **Use .bandit config**: Generate a `.bandit` config file with exclusions before running bandit

The first approach is cleaner and maintains consistency with how other detectors work.
