        # Implementation Plan: ArtAgents Thumbnail Maker Conductor

## Overview
Implement a built-in `builtin.thumbnail_maker` conductor that takes a thumbnail query and video, finds query-relevant visual evidence in the source video, generates multiple thumbnail candidates, writes reviewable manifests/contact sheets, and supports feedback-driven regeneration from prior outputs.

The remaining critique does not point to the wrong root cause or a different subsystem. The conductor/runtime target is still correct; the gap is a narrow runtime argument-mapping issue. `ConductorRunRequest.out` is separate from `request.inputs` and `request.conductor_args`, so the thumbnail conductor runtime must explicitly propagate generic conductor `--out` into the thumbnail CLI's required `--out` argument, just as existing built-in runtimes inject conductor-level values into legacy argv.

## Phase 1: Thumbnail CLI and Run Contract

### Step 1: Add the thumbnail module and root wrapper (`artagents/thumbnail_maker.py`, `thumbnail_maker.py`)
**Scope:** Medium
1. Add `artagents/thumbnail_maker.py` with an argparse CLI accepting `--video`, `--query`, `--out`, `--count`, `--size`, `--quality`, `--env-file`, `--dry-run`, `--force`, `--previous-manifest`, and `--feedback`.
2. Set the thumbnail-specific default size to a GPT-image-2-valid YouTube-style 16:9 value, `1536x864`, instead of inheriting `generate_image.py`'s square `1024x1024` default.
3. Add a root `thumbnail_maker.py` compatibility launcher that delegates to `artagents.thumbnail_maker.main`, because the conductor metadata will use `legacy_entrypoint="thumbnail_maker.py"`.
4. Standardize output paths under the run directory:
   - `source-analysis/scenes.json`
   - `source-analysis/shots/shots.json`
   - `evidence/evidence-plan.json`
   - `evidence/candidates.json`
   - `evidence/query-selection.json`
   - `evidence/reference-pack.json`
   - `prompts/prompts.json`
   - `generated/manifest.json`
   - `review/evidence-contact-sheet.jpg`
   - `review/contact-sheet.jpg`
   - `thumbnail-manifest.json`
5. Keep generated media and contact sheets under the caller's `--out` directory, with examples and default docs pointing at ignored `runs/` paths.

### Step 2: Resolve video inputs before source analysis (`artagents/thumbnail_maker.py`, `artagents/asset_cache.py`)
**Scope:** Small
1. Resolve `--video` through `asset_cache.resolve_input(video, want="path")` before calling lower-level scene/shot helpers, matching behavior in existing source-analysis CLIs.
2. Record both the user-provided video value and the resolved local path in `thumbnail-manifest.json` and `evidence-plan.json`.
3. In dry-run mode, record the planned resolution and downstream commands without requiring the source video to be analyzed.

### Step 3: Plan evidence needs from the query (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Implement a deterministic planner that classifies query needs into broad scene search, person/speaker composition, object/location search, emotion/action search, text-overlay needs, and refinement mode.
2. Write `evidence/evidence-plan.json` with the query, chosen evidence types, planned source-analysis steps, planned visual selection steps, and generation settings.
3. Treat underspecified queries as broad visual search, not failure.
4. Do not claim face or speaker detection. If the query mentions a person or speaker, plan frame-level person/speaker relevance scoring plus optional composition crops from selected frames.

## Phase 2: Query-Relevant Source Search

### Step 4: Build scene and shot candidates (`artagents/thumbnail_maker.py`, `artagents/scenes.py`, `artagents/shots.py`)
**Scope:** Medium
1. Generate or reuse `source-analysis/scenes.json` and `source-analysis/shots/shots.json` from the resolved video path.
2. Prefer direct calls to `scenes.detect_scenes()` and `shots.build_shots()` after explicit asset-cache resolution; in dry-run, emit equivalent planned commands for review.
3. Build `evidence/candidates.json` containing a bounded candidate frame set with timestamp, scene index, frame path, and initial deterministic selection reason.
4. Cap candidate frames to the current `visual_understand.py` practical limit of 20 per contact sheet.

### Step 5: Add an explicit query-relevance selection pass (`artagents/thumbnail_maker.py`, `artagents/visual_understand.py`)
**Scope:** Large
1. Build `review/evidence-contact-sheet.jpg` from candidate frames using the existing visual contact-sheet pattern.
2. Run a visual selection pass against the user query with `visual_understand.py` or equivalent imported helpers, asking the model to rank frames by thumbnail relevance, identify useful source references, and flag uncertainty.
3. Write the raw selection result to `evidence/query-selection.json` and normalize it into selected evidence records with candidate IDs, ranks, relevance reasons, and source timestamps.
4. In dry-run mode, write the planned visual-understanding payload and select deterministic placeholder candidates so the rest of the pipeline can be tested without model/API calls.
5. If the visual result is unparseable or empty in non-dry-run execution, preserve the raw result, fall back to top deterministic candidates, and mark the fallback in `query-selection.json`.

### Step 6: Build reference packs without overstating crop support (`artagents/thumbnail_maker.py`, `artagents/visual_understand.py`)
**Scope:** Medium
1. Write `evidence/reference-pack.json` from query-selected evidence, including selected full frames, timestamps, scene IDs, and relevance reasons.
2. For person/speaker-style queries, create broad composition crops only from already selected frames, using fixed aspect/position crop variants such as left/center/right. Label them as `composition_crop`, not face/speaker detections.
3. Optionally score crop variants with a second visual-understanding contact sheet when the query asks for person/speaker framing.
4. Include every generated crop path and crop box metadata in the reference pack.

## Phase 3: Generation and Refinement

### Step 7: Generate thumbnail prompt jobs (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Generate one prompt object per requested thumbnail candidate and write `prompts/prompts.json` in the existing `generate_image.py` prompt-list format.
2. Include user query, selected evidence summaries, selected frame/crop references, 16:9 composition constraints, requested count, and candidate-specific creative variation.
3. Keep prompts reproducible and self-contained so `python3 generate_image.py --prompts-file prompts/prompts.json` can rerun the batch.

### Step 8: Generate base thumbnails (`artagents/thumbnail_maker.py`, `artagents/generate_image.py`)
**Scope:** Medium
1. Invoke `generate_image.generate()` programmatically or call the CLI with `--prompts-file`, `--n 1`, `--size 1536x864`, `--out-dir generated`, and `--manifest generated/manifest.json`.
2. Preserve multiple-thumbnail support by writing multiple prompt jobs, one per candidate.
3. In dry-run mode, emit the generation payloads and expected output paths without loading API keys or making network calls.

### Step 9: Support feedback refinement (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Accept `--previous-manifest` plus `--feedback` for regeneration rounds.
2. Read prior prompts, generated outputs, evidence refs, and reference packs from the previous manifest.
3. Generate new prompt jobs that incorporate feedback while preserving lineage to previous candidate IDs.
4. Write `refinement.json` describing feedback, prior candidates, prompt deltas, reused source evidence, and new output paths.
5. Keep MVP refinement as prompt/evidence-guided regeneration. Do not expand `generate_image.py` into image editing for this conductor.
