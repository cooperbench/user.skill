**2. Likely Upstream Sources**

Researched current upstream. Likely sources are:

- `kijai/ComfyUI-WanVideoWrapper`: current main includes `uni3c/nodes.py` with `WanVideoUni3C_ControlnetLoader` and `WanVideoUni3C_embeds`, plus `uni3c/controlnet.py`: https://github.com/kijai/ComfyUI-WanVideoWrapper
- Upstream issue proving Uni3C exists in WanVideoWrapper runtime, but with attention-mode caveats: https://github.com/kijai/ComfyUI-WanVideoWrapper/issues/831
- Upstream issue indicating Wan 2.2 Uni3C model support is not clearly settled; Wan 2.1 Uni3C can mismatch Wan 2.2 tensor dimensions: https://github.com/kijai/ComfyUI-WanVideoWrapper/issues/945
- Available referenced model appears to be Wan 2.1, not proven Wan 2.2: `Wan21_Uni3C_controlnet_fp16.safetensors` on Kijai/WanVideo_comfy, surfaced via SeaArt/HF link: https://huggingface.co/Kijai/WanVideo_comfy/blob/main/Wan21_Uni3C_controlnet_fp16.safetensors
- Official Comfy templates have Wan2.2 and Wan2.2 Fun Control/VACE-related templates, but I did not find a native official Wan2.2 Uni3C VACE template: https://github.com/Comfy-Org/workflow_templates and https://docs.comfy.org/tutorials/video/wan/wan2_2

**3. Needed For Parity**

Implementing parity would require:

- Add VibeComfy node-pack awareness/schema support for upstream `WanVideoUni3C_ControlnetLoader` and `WanVideoUni3C_embeds`.
- Create or port a VibeComfy template/patch that loads the Uni3C ControlNet, converts the worker’s guide video into the expected render latent/mask or image conditioning, and connects `UNI3C_EMBEDS` into every relevant `WanVideoSampler`.
- Resolve model provenance: either confirm a compatible Wan 2.2 Uni3C controlnet exists or validate whether the Wan 2.1 controlnet is acceptable for the exact Wan2.2 VACE route. Current upstream issue evidence suggests this is not safe to assume.
- Add worker adapter logic mapping `uni3c_*` params to VibeComfy template fields, including guide-video staging, frame policy, start/end percent, strength, zero-empty/blackout-last-frame behavior.
- Add static validation plus a GPU smoke/visual parity run before promoting the route.
