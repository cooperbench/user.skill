        # Implementation Plan: Run Audit and Provenance

## Overview
ArtAgents is already file-based: `pipeline.py` delegates to `artagents/pipeline.py`, writes source-level artifacts under `<out>/`, and writes brief-level artifacts under `<out>/briefs/<slug>/`. The cleanest implementation is a small audit module plus pipeline hooks around existing step execution and sentinel files. This avoids changing child tools just to duplicate artifact knowledge the orchestrator already has.

The audit ledger should live under `<out>/audit/`, not beside logs or hidden cache folders. It should record metadata only: paths relative to the run when possible, file size, mtime, sha256 for reasonably small text/JSON artifacts, artifact kind, producing step, and redacted command metadata. It should not embed file contents, API keys, raw env values, or large media bytes.

## Main Phase

### Step 1: Define the ledger contract (`artagents/audit.py`)
**Scope:** Medium
1. Add a new `artagents/audit.py` module with helpers such as `audit_dir(run_dir)`, `append_event(...)`, `record_asset(...)`, `record_step_start(...)`, `record_step_end(...)`, `load_ledger(...)`, and `render_html_report(...)`.
2. Store append-only JSONL at `<run>/audit/ledger.jsonl`; keep generated report artifacts in the same folder, e.g. `<run>/audit/report.html`.
3. Represent events with a small stable schema: `schema_version`, `event_id`, `timestamp`, `run_dir`, `scope` (`source` or `brief`), `brief_slug`, `step`, `event_type`, `status`, `artifact`, and optional `parents`/`metadata`.
4. Add command redaction for known sensitive flags and values: `--env-file`, API-key-like tokens, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `Authorization`, and bearer-looking strings.
5. Add artifact classification by filename and extension: source input, brief/prompt input, transcript, analysis, arrangement, timeline, asset registry, metadata, render, validation, generated image manifest, image, log.

### Step 2: Wire audit initialization into the pipeline (`artagents/pipeline.py`)
**Scope:** Medium
1. Add `--no-audit` to `build_parser()` near the existing pipeline options (`artagents/pipeline.py:95`). Leave audit on by default for real runs.
2. Normalize `args.audit_enabled` and `args.audit_dir` in `resolve_args()` after `args.out` is resolved (`artagents/pipeline.py:289`).
3. At the start of `pool_main()` (`artagents/pipeline.py:976`), create `<out>/audit/` and record a `run_started` event with sanitized CLI/config metadata.
4. Record source inputs before prefetch and step execution: `--video`, `--audio`, extra `--asset`, theme path, and copied brief path. Use metadata refs, not file contents.
5. Record `brief.txt` when `prepare_brief_artifacts()` copies it (`artagents/pipeline.py:396`) so the report can show the prompt/brief entering the per-brief flow.

### Step 3: Record step provenance from existing sentinels (`artagents/pipeline.py`)
**Scope:** Medium
1. Hook `run_step()` (`artagents/pipeline.py:816`) to append `step_started` before launching the subprocess and `step_finished` after it exits.
2. On success, call `sentinel_paths(step, args)` (`artagents/pipeline.py:772`) and record each existing sentinel as a produced artifact. This captures transcript, scene analysis, shots, quote candidates, pool, arrangement, timeline, assets, metadata, refine report, render, editor review, and validation without modifying every child script.
3. Record each step log path under the audit ledger as a log artifact but keep log contents out of the ledger.
4. For skipped validation (`write_skip_log()` at `artagents/pipeline.py:840`) and cached steps (`should_rerun()` at `artagents/pipeline.py:777`), record `step_skipped` events with reason `explicit_skip`, `not_requested`, or `cache_hit` where available.
5. In the editor review loop (`artagents/pipeline.py:1014`), record revision events when review rotates, micro-fix mutates `arrangement.json`, or `arrange_revise` runs. This makes iterative provenance visible instead of only showing the final files.

### Step 4: Add the audit report CLI (`artagents/audit.py`, `artagents/pipeline.py`)
**Scope:** Medium
1. Add `python3 pipeline.py audit --run runs/<name>` routing in `main()` next to existing subcommands (`artagents/pipeline.py:1052`).
2. Support `--out` for report path, defaulting to `<run>/audit/report.html`; support `--json` to print summarized ledger data for tests and automation.
3. Render a dependency-free HTML report using the standard library: summary cards, chronological events, step status table, artifact inventory, and a simple SVG/HTML journey graph grouped by source-level and per-brief artifacts.
4. Keep report assets self-contained; no external CDN or network fetches.
5. Treat PNG as out of first-pass scope unless a reliable existing local screenshot command is already present. The HTML report is the required deliverable; add a future-ready `--png` flag only if implementation is trivial without new heavy dependencies.

### Step 5: Add tool-level audit helper usage where it materially improves coverage (`artagents/generate_image.py`)
**Scope:** Small
1. Instrument `generate_image.py` around manifest writing (`artagents/generate_image.py:312`) so GPT Image runs can append to a ledger when `--manifest` or `--out-dir` is under a run directory, or when an optional `--audit-run runs/<name>` is supplied.
2. Record prompt text only as a short redacted preview or hash, unless the prompt is already stored in an artifact file. Do record generated image paths and the manifest path.
3. Avoid changing the API call shape or image generation behavior.

### Step 6: Tests (`tests/test_audit.py`, `tests/test_pipeline_caching.py`, `tests/test_generate_image.py`)
**Scope:** Medium
1. Add focused unit tests for `artagents.audit`: append/load ledger, path normalization, artifact metadata extraction, large-file non-embedding, and command redaction.
2. Extend mocked pipeline tests around `tests/test_pipeline_caching.py:78` so fake step execution creates sentinels and verifies `<out>/audit/ledger.jsonl` records step events and artifacts.
3. Add a CLI test for `pipeline.main(["audit", "--run", ...])` producing `audit/report.html` and `--json` output.
4. Add a generate-image dry or mocked test to verify manifest/image artifact recording without calling the API.
5. Keep tests cheap: no ffmpeg, no Remotion render, no real image API calls.

### Step 7: Documentation (`README.md`)
**Scope:** Small
1. Add a short “Run audit reports” section near the main pipeline README flow.
2. Document default ledger location, report command, privacy guarantees, and the fact that audit records metadata and file references rather than embedding large artifacts or secrets.
