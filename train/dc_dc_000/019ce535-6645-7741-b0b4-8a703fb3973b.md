Not for a normal finding. In desloppify, queue-tracked issues are marked complete by an explicit action like `desloppify plan resolve <pat>`, `plan skip --permanent`, or `plan reopen` behavior, not by finishing the action plan itself. That’s stated in [docs/QUEUE_LIFECYCLE.md](/Users/user_c042661f/Documents/desloppify/docs/QUEUE_LIFECYCLE.md#L33) and reinforced in [README.md](/Users/user_c042661f/Documents/desloppify/README.md#L40). The one nuance is workflow items. If `next` is currently showing something like `workflow::create-plan` or a triage stage, those steps do need to be completed before later work is surfaced in the queue, because the queue enforces phase order; see [docs/DEVELOPMENT_PHILOSOPHY.md](/Users/user_c042661f/Documents/desloppify/docs/DEVELOPMENT_PHILOSOPHY.md#L48). So: - For a finding: `plan resolve` marks it complete. - For a workflow step: complete that workflow step to advance the queue.
