        # Implementation Plan: Phase 7 — Per-project CAS

## Overview

Add a per-project content-addressable store at `<project_slug>/.cas/<sha256>` with symlink-based produces. When a `produces_check_passed` event fires for a regular-file artifact, intern the file into the CAS with atomic rename and replace the original path with a relative symlink. Subsequent steps producing identical content reuse the same CAS entry. The store is per-project, NOT shared across projects.

### Scope boundary: what Phase 7 does NOT touch

- **`artagents/core/project/run.py`:** `mirror_hype_artifacts` copies project-level hype metadata (timeline.json, assets.json, metadata.json) into a `produces/` mirror directory at `finalize_project_run`. These are not step produces artifacts — they are orchestration system metadata, generated by the system itself rather than step code. CAS is wired for step-level produces; making hype metadata go through CAS would be a Phase 8 / project-level storage concern, not Phase 7. Document this explicitly in the CAS module docstring.
- **`artagents/structure.py`:** `validate_repo_structure` validates the `artagents/` package layout. It does not validate per-project output directories under the projects root. The `.cas/` directory lives under per-project directories (`<projects_root>/<slug>/.cas/`), not under the `artagents/` package. No change needed; the original assumption is verified by code inspection.
- **Attested steps:** `record_dispatch_complete` returns early for `step_kind == "attested"` (gate.py:1098-1100), so `_run_inline_checks` — and thus CAS interning — only applies to code steps. This is deliberate: attested steps produce artifacts via human acknowledgment, not file output. The CAS module itself is step-kind-agnostic, but the gate hook is naturally scoped to code steps.

## Main Phase

### Step 1: Create `artagents/core/task/cas.py` with CAS primitives

**Scope:** Small — new module, no dependencies outside stdlib

1. **Implement** `cas_path(project_dir: Path, sha256: str) -> Path` — returns `<project_dir>/.cas/<sha256>`. The sha256 is the hex digest (64 chars, no prefix). The CAS directory name on disk uses bare hex; the `sha256:` prefix is reserved for event payloads per settled decision SD-1.

2. **Implement** `intern(project_dir: Path, source_path: Path) -> Path`:
   - **Guard:** If `source_path` is already a symlink to an existing CAS entry under `project_dir/.cas/`, return the CAS path immediately (no-op for re-runs where the produces path is already CAS-linked).
   - **Guard:** If `source_path` is not a regular file (`not source_path.is_file()`), raise `ValueError` — CAS only supports file artifacts in this phase.
   - Computes SHA-256 of `source_path` via `hashlib.sha256()` reading in 64KB chunks.
   - If `<project_dir>/.cas/<digest>` already exists, removes `source_path` (discards the duplicate) via `source_path.unlink()` and returns the existing CAS path. Idempotent on content.
   - Otherwise: creates `<project_dir>/.cas/` if needed, atomically renames `source_path` into `<project_dir>/.cas/<digest>` using `os.replace` (atomic on same filesystem, avoids `shutil.move` cross-device fallback). Returns the CAS path.

3. **Implement** `link_into_produces(cas_path: Path, target_path: Path) -> None`:
   - Computes relative path from `target_path.parent` to `cas_path` using `os.path.relpath`.
   - If `target_path` already exists as a symlink resolving to the same `cas_path.resolve()`, no-op.
   - If `target_path` exists (regular file or different symlink), raise `FileExistsError` — caller is responsible for ensuring the target is clear (which `intern` guarantees by moving/removing the source).
   - Creates the relative symlink at `target_path`.
   - This handles deep iteration paths automatically: `os.path.relpath` computes the correct `../../../../.cas/<hash>` chain regardless of nesting depth.

### Step 2: Add CAS hash to `produces_check_passed` event

**Scope:** Small — one function signature change in `events.py`

1. **Update** `make_produces_check_passed_event` at `artagents/core/task/events.py:185` to accept an optional `cas_hash: str | None = None` keyword argument. When not None, include `"cas_hash": cas_hash` in the returned event dict (positioned after `check_id`). The value uses the `"sha256:<hex>"` format for consistency with existing hash convention (see `compute_plan_hash` at plan.py:112).

### Step 3: Hook `_run_inline_checks` to intern and symlink after check passes

**Scope:** Medium — the core integration point

1. **Update** `_run_inline_checks` at `artagents/core/task/gate.py:1110`:
   - After `make_produces_check_passed_event` is appended (line 1159-1166), if the check passed:
     - **Guard:** Only proceed if `artifact_path.is_file()` — skip CAS for directories or non-regular paths. The CAS is for file artifacts only; non-file artifacts (future directory checks, etc.) quietly bypass CAS.
     - Compute the project directory: `project_dir = decision.project_root` (already available).
     - Call `cas.intern(project_dir, artifact_path)` to move the file into CAS.
     - Call `cas.link_into_produces(cas_result, artifact_path)` to create the symlink at the produces path.
     - Pass `cas_hash = f"sha256:<digest>"` into `make_produces_check_passed_event` (the digest extracted from the CAS path).
   - **Replay safety:** If `intern()` detects the source is already a symlink into the same CAS entry (re-run of a previously-interned step), it returns the CAS path without error, and `link_into_produces` no-ops. The produces event gains a `cas_hash` field.
   - This is additive — the existing event emission and cursor logic remain unchanged.
   - **Iteration path resolution:** The relative symlink computed by `os.path.relpath` correctly resolves from deep iteration dirs (e.g., `steps/step-1/iterations/001/out.json`) back to `project_root/.cas/<hash>` — no special-casing needed.
   - **Attested step scope:** `_run_inline_checks` is only called for non-attested steps (`record_dispatch_complete` returns early at gate.py:1098 for attested). CAS applies only to code/nested step produces.
