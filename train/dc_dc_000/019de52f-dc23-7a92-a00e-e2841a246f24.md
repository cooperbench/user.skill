As of May 1, 2026, the official Discord docs say: - **Start typing:** `POST /channels/{channel.id}/typing` triggers a typing indicator. It returns **204 empty response** on success and fires a **Typing Start** Gateway event. Source: https://docs.discord.com/developers/resources/channel#trigger-typing-indicator - **Duration:** the indicator **expires after 10 seconds**. Discord’s docs do not document a separate shorter duration or a “keep until stopped” mode. Source: https://docs.discord.com/developers/resources/channel#trigger-typing-indicator - **Stop typing:** there is **no official REST endpoint or Gateway send event documented for explicitly stopping typing**. The documented control is only “trigger typing”; stopping is by expiry, and in practice by sending the actual message. - **Recommended usage:** Discord explicitly says bots **generally should not use this route**, except when responding to a command and computation will take a few seconds. Source: https://docs.discord.com/developers/resources/channel#trigger-typing-indicator - **Gateway typing events:** `TYPING_START` is a receive event: “Sent when a user starts typing in a channel.” It includes `channel_id`, optional `guild_id`, `user_id`, `timestamp`, and optional `member`. Source: https://docs.discord.com/developers/events/gateway-events#typing-start - **Gateway intents:** receiving typing events requires `GUILD_MESSAGE_TYPING (1 << 11)` for guilds or `DIRECT_MESSAGE_TYPING (1 << 14)` for DMs. Source: https://docs.discord.com/developers/events/gateway#gateway-intents - **Rate limits:** no typing-specific cadence limit is documented. Discord says not to hard-code REST limits; parse rate-limit headers and respect `Retry-After`. Bots also have a documented global REST limit of **50 requests/sec**. Source: https://docs.discord.com/developers/topics/rate-limits **Practical implementation implication:** model typing as a soft, expiring signal. If a response may take more than a few seconds, call typing once, then refresh at roughly **8-9 second intervals** only while work is still active. Stop refreshing when work is done, then send the message. Do not try to implement “stop typing” as an API call; cancel your refresh timer and let Discord expire the indicator. For natural behavior, avoid typing for instant replies and cap long-running typing loops so failures do not create unnecessary API traffic.
