        # Implementation Plan: Incremental Watch-Mode Scoring for Eval Harness

## Overview

Currently, the parallel eval pipeline in `evals/parallel.py` follows a two-phase approach: (1) all workers generate predictions, then (2) a single batch call to `swebench.harness.run_evaluation` scores everything at once. This means you can't see pass rates until the entire run completes.

The goal is a **watch mode** that monitors the predictions directory, scores each prediction as it lands, writes incremental results, and exits when all tasks are scored or a timeout fires. This sits alongside the existing batch scoring — it's an alternative scoring strategy, not a replacement.

**Key repo facts:**
- Predictions land as individual `.jsonl` files in `results/{run_name}/_swebench_predictions/`
- Manifest at `results/{run_name}/_task_manifest.json` tracks total task count and per-task status
- Scoring uses `python -m swebench.harness.run_evaluation` via subprocess (local Docker only — no Modal exists in the codebase despite the brief mentioning it)
- `_run_batch_scoring()` in `parallel.py:406` is the current batch scorer
- `consolidate.py` reads scores from `logs/run_evaluation/*/report.json`

## Phase 1: Core Watch Loop

### Step 1: Create `evals/watch_scoring.py` — the incremental scorer
**Scope:** Large (core of the feature)

1. **Create** `evals/watch_scoring.py` with the main watch loop function:
   ```python
   def watch_and_score(
       results_root: Path,
       manifest_path: Path,
       *,
       poll_interval: int = 15,
       timeout: int = 4 * 3600,
       max_workers: int = 1,
       cleanup_docker: bool = True,
   ) -> dict[str, Any]:
   ```
2. **Implement** the poll loop:
   - Load manifest via `TaskManifest.load(manifest_path)` to get total expected count
   - Track `scored_ids: set[str]` — predictions already scored
   - Each iteration: glob `_swebench_predictions/*.jsonl`, diff against `scored_ids`
   - For each new prediction file, call `_score_single_prediction()` which invokes:
     ```python
     subprocess.run([
         sys.executable, "-m", "swebench.harness.run_evaluation",
         "--predictions_path", str(pred_path),
         "--instance_ids", instance_id,
         "--max_workers", "1",
         "--run_id", f"hermes-watch-{instance_id}",
         "--namespace", "",
     ], timeout=1800)
     ```
   - After scoring, parse the result from `logs/run_evaluation/hermes-watch-{instance_id}/` report
   - Optionally clean up Docker images after each score (reuse `_cleanup_docker_images` pattern from `swe_bench.py:509`)
3. **Write incremental results** after each score:
   - Maintain a `_watch_scores.json` file at `results_root/_watch_scores.json`:
     ```json
     {
       "total_expected": 100,
       "scored": 42,
       "resolved": 18,
       "failed": 24,
       "pass_rate": 0.4286,
       "last_updated": "2026-03-29T...",
       "tasks": {
         "django__django-11099": {"resolved": true, "scored_at": "..."},
         ...
       }
     }
     ```
   - Use atomic write (temp + rename) for safe concurrent reads
4. **Print progress** to stderr on each score: `[42/100] django__django-11099: RESOLVED (pass rate: 42.9%)`
5. **Exit conditions:**
   - `len(scored_ids) >= manifest.summary()["total_tasks"]` → all scored
   - Elapsed time > timeout → exit with partial results
   - All manifest tasks are done/error AND all available predictions are scored → exit
   - KeyboardInterrupt → graceful exit with partial results

### Step 2: Add `_parse_swebench_report()` helper (`evals/watch_scoring.py`)
**Scope:** Small

1. **Implement** report parsing that reads from the swebench log directory:
   - Look for `logs/run_evaluation/hermes-watch-{instance_id}/{instance_id}/report.json`
   - Parse the report to determine resolved/failed status
   - This mirrors the logic in `consolidate.py:58-60` and `swe_bench.py`'s `_check_resolved()`
2. **Handle** missing reports gracefully (scoring subprocess failure → mark as error, don't block)

## Phase 2: CLI Integration

### Step 3: Add `--watch` CLI entry point (`evals/watch_scoring.py`)
**Scope:** Medium

   ```
   python -m evals.watch_scoring --results-root results/my-run [options]

   Arguments:

     --poll-interval SEC     Seconds between directory checks (default: 15)
     --timeout SEC           Max total runtime (default: 14400 / 4 hours)
     --max-workers N         Concurrent Docker scoring slots (default: 1)
     --no-cleanup            Skip Docker image cleanup between scores
   ```
2. **Validate** on startup: check that `_task_manifest.json` and `_swebench_predictions/` exist in the results root
3. **Print** initial status summary from manifest before entering the loop

### Step 4: Wire watch mode into `parallel.py` as an alternative to batch scoring
**Scope:** Small

### Step 5: Support launching watch mode concurrently with workers
**Scope:** Medium

1. **Add** `--watch` flag to `run_evals.py` parallel mode that starts the watch scorer in a background thread/process alongside workers
2. **In** `run_parallel_workers()`, when watch mode is active:
   - Start `watch_and_score()` in a `threading.Thread` immediately after manifest creation (before waiting for workers)
   - The watch loop naturally handles the "predictions arrive over time" case
   - After all workers exit AND the watch thread completes, skip the batch scoring step
3. **Alternatively**, support running watch mode as a standalone process: `python -m evals.watch_scoring --results-root results/my-run` while workers are still running in another terminal

        # Implementation Plan: Incremental Watch-Mode Scoring for Eval Harness

## Overview

The parallel eval pipeline in `evals/parallel.py` follows a two-phase approach: (1) workers generate predictions, then (2) a single batch call to `swebench.harness.run_evaluation` scores everything. You can't see pass rates until the entire run completes.

The goal is a **watch mode** that monitors the predictions directory, scores each prediction as it lands, writes incremental results, and exits when done or timed out.

**Key repo facts:**
- Predictions land as individual `.jsonl` files in `results/{run_name}/_swebench_predictions/`
- Manifest at `results/{run_name}/_task_manifest.json` tracks total task count and per-task status (pending/claimed/done/error)
- Tasks that fail without producing a patch are marked `done` in manifest but write **no** `.jsonl` (`swe_bench.py:271-277`)
- Batch scoring filters predictions through `manifest.done_task_ids()` (`parallel.py:102`)
- Scoring uses `python -m swebench.harness.run_evaluation` via subprocess — local Docker only
- Report path layout: `logs/run_evaluation/{run_id}/{model_name}/{instance_id}/report.json`
- Existing `_check_resolved()` filters by `run_id` to avoid cross-run contamination (`swe_bench.py:574`)
- `_cleanup_run_artifacts(run_id)` removes stale logs before scoring (`swe_bench.py:541`)
- Docker image cleanup is global (removes all non-base `*sweb*` images) — unsafe for concurrent scoring (`swe_bench.py:509-538`)

**Scope decisions (settled):**
- Docker-only scoring (no Modal — doesn't exist in the codebase)
- Sequential scoring only (max_workers=1); no `--max-workers` flag since global Docker cleanup makes concurrency unsafe
- `_watch_scores.json` is a lightweight progress file, not a consolidation replacement

## Phase 1: Core Watch Loop

### Step 1: Create `evals/watch_scoring.py` — the incremental scorer
**Scope:** Large (core of the feature)

1. **Create** `evals/watch_scoring.py` with the main watch loop function:
   ```python
   def watch_and_score(
       results_root: Path,
       *,
       poll_interval: int = 15,
       timeout: int = 4 * 3600,
       cleanup_docker: bool = True,
   ) -> dict[str, Any]:
   ```
   Derive `manifest_path` and `predictions_dir` from `results_root` (conventions: `_task_manifest.json`, `_swebench_predictions/`).

2. **Implement** the poll loop with **manifest-gated prediction filtering** (addresses DEBT-017):
   - Load manifest via `TaskManifest.load(manifest_path)`
   - Track `scored_ids: set[str]` — instance IDs already scored (seeded from existing `_watch_scores.json` on restart for idempotency)
   - Each iteration:
     1. Refresh `done_ids = manifest.done_task_ids()` — the set of tasks the manifest says are legitimately complete in this run
     2. Glob `_swebench_predictions/*.jsonl`, extract instance IDs from filenames
     3. Compute `scorable = done_ids - scored_ids` intersected with available `.jsonl` files — **only score predictions for tasks the manifest confirms are done**, matching the existing batch path's `valid_ids=manifest.done_task_ids()` filter
     4. For each scorable prediction, call `_score_single_prediction()`

3. **Implement** `_score_single_prediction(pred_path, instance_id, run_id, cleanup_docker)`:
   - **Pre-score cleanup**: Call `_cleanup_run_artifacts(run_id)` pattern to remove stale logs for this run_id before scoring (addresses DEBT-021)
   - Extract `model_name_or_path` from the prediction JSONL to construct the correct report path
   - Invoke scoring:
     ```python
     subprocess.run([
         sys.executable, "-m", "swebench.harness.run_evaluation",
         "--predictions_path", str(pred_path),
         "--instance_ids", instance_id,
         "--max_workers", "1",
         "--run_id", run_id,
         "--namespace", "",
     ], timeout=1800)
     ```
     Use a single consistent `run_id` (e.g., `"hermes-watch"`) for the entire watch session, not per-instance — this matches how the batch scorer uses one `run_id`
   - Parse result via `_parse_swebench_report(instance_id, run_id)` (Step 2)
   - Optionally clean Docker images after scoring (reuse `_cleanup_docker_images` pattern from `swe_bench.py:509`)

4. **Implement exit conditions** that account for no-patch tasks (addresses watch-exit-semantics):
   - The watch loop **cannot** use `total_tasks` as the expected prediction count because tasks that fail without a patch produce no `.jsonl`
   - Instead, exit when: `manifest.all_done()` AND all predictions matching `done_task_ids()` have been scored — i.e., every `.jsonl` file that exists for a done task has been processed
   - Also exit on: elapsed time > timeout, or KeyboardInterrupt (graceful, write partial results)
   - The loop naturally handles the gap: if manifest has 100 tasks, 80 produce patches, and 20 fail with no patch, we exit after scoring the 80 predictions once all 100 manifest tasks reach terminal status

5. **Write incremental results** after each score — atomic write (temp + rename) to `results_root/_watch_scores.json`:
   ```json
   {
     "manifest_total": 100,
     "manifest_done": 85,
     "manifest_error": 3,
     "scored": 42,
     "resolved": 18,
     "failed": 24,
     "pass_rate": 0.4286,
     "last_updated": "2026-03-30T...",
     "tasks": {
       "django__django-11099": {"resolved": true, "scored_at": "..."},
       ...
     }
   }
   ```
   Include manifest progress (done/error counts) alongside scoring progress so the user can see both worker progress and scoring progress.

6. **Print progress** to stderr: `[scored 42 | resolved 18/42 = 42.9%] [manifest 85/100 done, 3 error] django__django-11099: RESOLVED`

### Step 2: Add `_parse_swebench_report()` helper (`evals/watch_scoring.py`)

2. **This ensures** restart doesn't produce false positives from stale report.json files
