That scratchpad patches first image, last image, prompt, negative, seed, frames, size, fps, and strengths into the Runexx first/last template: [vibecomfy_adapter.py](/tmp/reigh-worker/source/models/comfy/vibecomfy_adapter.py:1280). Existing tests explicitly assert LTX control rows must not use the first/last template: [test_control_preprocessing_and_continuity.py](/tmp/reigh-worker/tests/test_control_preprocessing_and_continuity.py:144).

VibeComfy has useful pieces, but not a safe route-complete template:

- `ltx2_3_runexx_first_last_frame` supports first/last anchors via `LTXVImgToVideoInplaceKJ` and `LTXVAddGuide`, not full-length IC-LoRA control: [ltx2_3_runexx_first_last_frame.py](/tmp/vibecomfy/ready_templates/video/ltx2_3_runexx_first_last_frame.py:438) and [ltx2_3_runexx_first_last_frame.py](/tmp/vibecomfy/ready_templates/video/ltx2_3_runexx_first_last_frame.py:491).
- `ltx2_3_lightricks_iclora_union_control` has the right IC-LoRA guide node family: `LTXICLoRALoaderModelOnly` plus `LTXAddVideoICLoRAGuide`: [ltx2_3_lightricks_iclora_union_control.py](/tmp/vibecomfy/ready_templates/video/ltx2_3_lightricks_iclora_union_control.py:132) and [ltx2_3_lightricks_iclora_union_control.py](/tmp/vibecomfy/ready_templates/video/ltx2_3_lightricks_iclora_union_control.py:207). But it is image-to-video plus guide control, not first/last. It also currently feeds the Canny branch into the guide node; DWPose and Depth nodes exist but are not selected by route mode in this generated template: [ltx2_3_lightricks_iclora_union_control.py](/tmp/vibecomfy/ready_templates/video/ltx2_3_lightricks_iclora_union_control.py:148).
- `ltx2_3_lightricks_iclora_motion_track` is motion-track control with `LTXVSparseTrackEditor` and drawn tracks, not an external full-length control-video first/last route: [ltx2_3_lightricks_iclora_motion_track.py](/tmp/vibecomfy/ready_templates/video/ltx2_3_lightricks_iclora_motion_track.py:152).

Required nodes/inputs before promotion:

- Keep Runexx first/last anchor wiring: node `45` first image, node `47` last image, node `2078` frames, `2079` height, `2080` width, `2076` fps, `2108` and `2110` strengths.
- Add IC-LoRA control path using `LoadVideo`/`GetVideoComponents`, mode-specific preprocessing, `LTXICLoRALoaderModelOnly`, and `LTXAddVideoICLoRAGuide`.
- For `pose`, route preprocessed frames from `DWPreprocessor`.
- For `depth`, route frames from `DepthAnything_V2`.
- For `canny`, route frames from `CannyEdgePreprocessor`.
- For `video`, define whether raw full-length control should use an IC-LoRA at all; worker currently says `needs_ic_lora()` is false for `video`: [travel_guidance.py](/tmp/reigh-worker/source/core/params/travel_guidance.py:297).
- For `cameraman`, add/verify a cameraman-specific VibeComfy template or LoRA path. Worker maps cameraman to raw preprocessing but an IC-LoRA entry: [travel_guidance.py](/tmp/reigh-worker/source/core/params/travel_guidance.py:331).

Recommendation: keep all five blocked. Promote only after a new/manual VibeComfy template or scratchpad proves combined first/last anchors plus full-length LTX control guide, with per-mode node selection.

Minimum evidence to unblock: adapter unit tests for each route’s template id and scratchpad node patching, VibeComfy build/API snapshot tests showing exact guide input branch per mode, and real tiny RunPod/Comfy smoke runs for all five routes producing valid video artifacts while preserving first and last frame conditioning.
