## Problem Recap

The HEAD commit has `desloppify/data/global/` with manually-copied .md files read via `importlib.resources`. The working tree deletes those in favor of GitHub downloads. Both approaches have problems:
- **Checked-in copies** drift from `docs/` and `CLAUDE.md` is caught by `.gitignore` line 43 (`CLAUDE.md`)

## Step 7: Add pytest sync guard

**File:** `desloppify/tests/commands/test_bundled_sync.py` (new)

```python
"""Guard: bundled skill docs in data/global/ must match docs/."""

from pathlib import Path

import pytest

DOCS_DIR = Path(__file__).resolve().parents[3] / "docs"
DATA_DIR = Path(__file__).resolve().parents[2] / "data" / "global"


def _overlay_files() -> list[str]:
    return sorted(p.name for p in DOCS_DIR.glob("*.md"))


@pytest.mark.parametrize("filename", _overlay_files())
def test_bundled_matches_docs(filename: str) -> None:
    docs_content = (DOCS_DIR / filename).read_text(encoding="utf-8")
    bundled_path = DATA_DIR / filename
    assert bundled_path.exists(), f"Missing bundled copy: {filename}"
    assert bundled_path.read_text(encoding="utf-8") == docs_content, (
        f"Bundled {filename} has drifted from docs/{filename}. "
        "Run `make sync-docs` to fix."
    )


def test_no_extra_bundled_files() -> None:
    docs_names = {p.name for p in DOCS_DIR.glob("*.md")}
    bundled_names = {p.name for p in DATA_DIR.glob("*.md")}
    extra = bundled_names - docs_names
    assert not extra, f"Extra bundled files not in docs/: {extra}"
```

This test serves as a safety net for anyone running `pytest` directly (without `make`). The error message points to `make sync-docs`. In CI (which uses `make tests`), the sync always runs first, so this guard never fails there — it's purely a local-dev safety net.

**Validation:** `pytest desloppify/tests/commands/test_bundled_sync.py -v` — all green after `make sync-docs`.
