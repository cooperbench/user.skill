        # Implementation Plan: Phase 7 Per-Project CAS

## Overview
Phase 7 adds a per-project content-addressable store under `<project_slug>/.cas/<sha256>` for task-mode produced file artifacts. The critique does not show that the CAS approach is targeting the wrong root cause; it shows that the root cause includes two task-run lifecycle boundaries: produces acceptance must be all-or-nothing, and nested produces must be committed only by a mutating gate path, never by read-only cursor simulation.

The plan therefore keeps the CAS design but tightens the insertion points. Successful produces handling will be centralized in `artagents/core/task/gate.py`: run every produces check for a step first, mutate nothing if any check fails, then intern accepted files into the per-project CAS and replace produce paths with relative symlinks. Nested produces remain in Phase 7 scope because `NestedStep.produces` already exists and design examples declare nested outputs, but the implementation must not put CAS work into any helper used by `peek_current_step()`, `cmd_status`, `cmd_next`, or `cmd_ack` in read-only mode.

No shared CAS, daemon, database, Phase 8 inbox, or Phase 9 golden-test work is included.

## Main Phase

### Step 1: Add CAS primitives (`artagents/core/task/cas.py`)
**Scope:** Small
1. Implement `cas_path(project_dir, sha256) -> Path` as `Path(project_dir) / ".cas" / sha256`.
2. Implement `intern(project_dir, source_path) -> Path`:
   - stream-hash file bytes with `hashlib.sha256()`;
   - create `<project_dir>/.cas/` as needed;
   - move the first normal file into `.cas/<hash>`;
   - if `.cas/<hash>` already exists, unlink the duplicate source and return the existing CAS path;
   - treat an existing CAS-created symlink as idempotent by returning its resolved `.cas/<hash>` entry without moving the symlink object.
3. Implement `link_into_produces(cas_path, target_path)` with `os.symlink()` and a relative target from `target_path.parent` to the CAS entry.
4. Keep helper behavior file-focused; directories are not Phase 7 produce artifacts.

### Step 2: Make produces definitions unambiguous (`artagents/core/task/plan.py`)
**Scope:** Small
1. Extend `_validate_produces()` to reject duplicate `path` values within one step, for both dict-form produces and legacy code-step list produces.
2. Keep duplicate-name validation unchanged.
3. Use a clear `TaskPlanError` message that tells authors to use an `all_of` check when one artifact needs multiple checks.
4. Add a focused plan-schema regression test for duplicate produce paths.

### Step 3: Enrich produces events (`artagents/core/task/events.py`)
**Scope:** Small
1. Extend `make_produces_check_passed_event(...)` with optional `cas_hash: str | None = None`.
2. Include `cas_hash` only for interned file artifacts.
3. Store `cas_hash` as the raw SHA-256 hex string matching the `.cas/<sha256>` filename.
4. Leave hash-chain mechanics unchanged; `append_event()` will canonicalize and hash the enriched event as it does today.

### Step 4: Replace per-entry mutation with all-or-nothing produces handling (`artagents/core/task/gate.py`)
**Scope:** Medium
1. Refactor `_run_inline_checks()` into an explicit all-or-nothing helper, for example `_complete_produces(decision, produces)`.
2. Phase A: resolve every `ProducesEntry` path, run every check, and collect accepted file artifacts without moving or linking anything.
3. If any check fails, append the existing `produces_check_failed` event and the existing `cursor_rewind` or `iteration_failed` event, then return `False` with no CAS mutation.
4. Phase B: after every produces entry has passed, intern each collected file into `decision.project_root / ".cas"`, replace the produce path with a relative symlink, and append `produces_check_passed` with `cas_hash`.
5. Preserve current event ordering for code and attested steps: `step_completed` or `step_attested` first, then produces events.
6. Ensure symlink replacement happens only after all checks pass so a retried step cannot write through a partial CAS symlink left by a failed multi-produce attempt.

### Step 5: Split read-only traversal from mutating nested completion (`artagents/core/task/gate.py`)
**Scope:** Medium
1. Audit `_auto_traverse_to_leaf()`, `peek_current_step()`, `cmd_status`, `cmd_next`, and `cmd_ack` before editing nested behavior.
2. Do not run CAS interning, real produces checks, real event appends, or file replacement from a code path that read-only peek/status/next/ack calls can execute.
3. Keep read-only traversal as simulation only: if a nested child appears exhausted, it may compute the pending cursor state in memory, but it must not create `.cas/`, replace files, or persist `nested_exited` / produces events.
4. Add an explicit mutating nested-completion path, for example `_record_nested_exited_with_produces(decision, returncode)`, used by real gate execution and exported `record_nested_exited()`.
5. In the mutating path, append `nested_exited` and then run the same all-or-nothing produces helper for `NestedStep.produces`.
6. If nested produces fail, append the same failure and rewind events used by code/attested produces and leave cursor replay on the nested step.
7. If cursor replay needs to understand `nested_exited` with pending produces, update it directly; do not rely on read-only traversal to perform side effects.

### Step 6: Confirm project-run artifact mirroring still composes (`artagents/core/project/run.py`)
**Scope:** Small
1. Audit `finalize_project_run()` and `mirror_hype_artifacts()` to ensure task-attached artifacts copied under `steps/<step>/produces/` remain valid when the gate later replaces accepted files with symlinks.
2. Preserve run-record artifact paths; they should continue to point at the produce path, which may become a symlink after the produces check accepts it.
3. Do not duplicate CAS interning in `run.py` unless a focused test proves that project-run artifact mirroring bypasses the gate’s produces acceptance path.

### Step 7: Add focused tests (`tests/test_cas_intern.py`, `tests/test_cas_symlink.py`, `tests/test_cas_per_project.py`, existing task tests)
**Scope:** Medium
1. `tests/test_cas_intern.py`: create a project dir and two files with identical bytes, call `intern()` for both, assert both return the same `.cas/<hash>`, only one CAS file exists, and the duplicate source is gone.
2. `tests/test_cas_symlink.py`: use the existing task inline-check fixture pattern, write a produced file, call `record_dispatch_complete()`, then assert the produce path is a relative symlink that resolves to `<project>/.cas/<hash>` and the passed event includes `cas_hash`.
3. Add a multi-produce regression: first artifact would pass, second artifact fails, and neither artifact is moved or symlinked after the failure.
4. Add a duplicate produce-path validation test in the existing task plan or inline-check test area.
5. Add a mutating nested produces regression: `record_nested_exited()` or the real gate nested-completion path checks, interns, symlinks, and emits `cas_hash` for `NestedStep.produces`.
6. Add read-only nested regression coverage: `peek_current_step()`, `cmd_status`, `cmd_next`, and `cmd_ack` over an exhausted nested step with declared produces do not append events, create `.cas/`, run CAS interning, or replace files with symlinks.
7. `tests/test_cas_per_project.py`: two project slugs with identical content each get their own `.cas/<hash>` entry and no shared CAS root.
8. Add same-project reuse coverage: two different steps in one project produce identical bytes and share one CAS entry.

### Step 8: Ignore generated CAS directories (`.gitignore`, `artagents/structure.py`)
**Scope:** Small
1. Add `.gitignore` entries for `*/runs/*/.cas/` and `**/.cas/` if absent.
2. Leave `artagents/structure.py` unchanged unless implementation uncovers an actual project-directory whitelist. Current inspection shows it validates repository package layout, not per-project local cache directories.
