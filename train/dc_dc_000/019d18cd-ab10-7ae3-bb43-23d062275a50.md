## Step 2: Simplify display phases from 7 to 3 internal + 2 user-facing

The 7 display phases map to the user's mental model like this:

| Current display phase | User-facing label | Persisted mode |

| `assessment` | plan | plan |
| `workflow` | plan | plan |
| `triage` | plan | plan |
| `review` (postflight) | plan | plan |
| `scan` | plan | plan |
| `execute` | execute | execute |

**Keep the 7 display phases internally** — they drive item selection logic in `_execution_items_for_phase()` and `score_display_mode()`. But introduce a **user-facing label function**:

def user_facing_mode(display_phase: str) -> str:

## Step 4: Auto-resolve housekeeping workflow items

This is the core UX improvement. Currently, workflow items like `communicate-score`, `create-plan`, `score-checkpoint`, `run-scan`, and `deferred-disposition` show up as manual queue items the user resolves one at a time. They should be **automatic system actions**.

### 4a: Classify workflow items as auto vs. interactive

| Workflow item | Auto-resolvable? | Why |
|---|---|---|
| `run-scan` | **No** — user must trigger scan | Scan can be slow, user controls timing |
| `deferred-disposition` | **No** — user decides on skipped items | Requires human judgment |
| `score-checkpoint` | **Yes** | Pure bookkeeping — import scores that are already computed |
| `communicate-score` | **Yes** | Shows score delta — can be folded into scan output |
| `create-plan` | **Yes** | Generates plan from triage results — purely mechanical |
| `import-scores` | **Partially** — already has automation path | Can auto-import if results exist |

### 4b: Auto-resolve at reconcile time

In `engine/_plan/sync/pipeline.py:reconcile_plan()`, after workflow items are synced, immediately resolve the auto-resolvable ones instead of injecting them into the queue:

1. **`score-checkpoint`**: Call the checkpoint logic directly after review completion detection. Skip queue injection entirely.
2. **`communicate-score`**: Fold the score communication into the scan reveal output. Remove from queue.
3. **`create-plan`**: Auto-generate the plan after triage completes. The plan is deterministic from triage output.

### 4c: Change rendering for remaining workflow items

For `run-scan` and `deferred-disposition` (which stay in the queue):
- `render_workflow_action()` (render_workflow.py:125-140) — Instead of `"(Workflow step)"`, use contextual labels:
  - `run-scan` -> `"Ready to scan"` with message: "Run desloppify scan to start the next cycle."
  - `deferred-disposition` -> `"Deferred items need attention"` with message about reviewing skipped items.

### 4d: Implementation detail — auto-resolve in reconcile

Add an `_auto_resolve_workflow_items(plan, state)` step in `reconcile_plan()` between sync and phase resolution that executes the effects of auto-resolvable items and removes them from `queue_order`.

### Risk and mitigation:
- Add logging so `desloppify plan show` reveals what was auto-resolved.
