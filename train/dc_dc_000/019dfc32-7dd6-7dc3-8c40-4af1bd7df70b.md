        # Implementation Plan: Sprint 5 Qwen, Edit-Mode, VLM, and LoRA Preprocessing Parity

## Overview
Sprint 5 should still be implemented primarily in `reigh-worker`, with `vibecomfy` touched only for ready-template input patching and validation. The new critique does not mean the plan is targeting the wrong subsystem; it shows that the LoRA manifest rule must account for all existing LoRA callers, not only Qwen. Since Wan SVI and LTX IC-LoRA paths already carry LoRAs today, mandatory manifest-backed sanitation must either provide manifests for those active architectures or it would break unrelated but in-scope travel/join/edit-video preprocessing parity. The revised approach keeps manifest enforcement mandatory, but expands the manifest deliverable to Qwen plus the active Wan/LTX architectures exercised by current LoRA callers and tests.

Current important touch points are `source/task_handlers/tasks/task_types.py`, `source/task_handlers/tasks/task_conversion.py`, `source/models/model_handlers/qwen_handler.py`, `source/task_handlers/tasks/template_routing.py`, `source/models/comfy/vibecomfy_adapter.py`, `source/media/vlm/`, `source/task_handlers/travel/orchestrator.py`, `source/task_handlers/join/vlm_enhancement.py`, `source/task_handlers/edit_video_orchestrator.py`, `source/task_handlers/travel/svi_config.py`, `source/core/params/lora.py`, and `source/core/params/phase_config_parser.py`.
