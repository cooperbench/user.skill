## Phase 1: Bug Fix — Selection Ring

### Step 1: Diagnose the CSS conflict (`MediaGalleryItem.tsx:349-356`)
**Scope:** Small
1. **Inspect** the container div at line 352: it applies `hover:shadow-md transition-all duration-200` alongside conditional `ring-2 ring-sky-400`. In Tailwind, both `ring-*` and `shadow-*` compile to the `box-shadow` CSS property via CSS variables (`--tw-ring-shadow`, `--tw-shadow`). `transition-all` transitions `box-shadow`, meaning ring appearance/removal is *animated* rather than instant — causing visible flicker on state changes.
2. **Fix**: Change `transition-all` → `transition-[shadow,opacity,transform]` to transition only the hover shadow and drag states, not the ring. This makes selection ring changes instant.
3. **Remove** the redundant `rounded-lg` inside the `isSelected` conditional (already on the base classes at line 352).

### Step 2: Verify state flow stability (`GallerySelectionContext.tsx`, `GenerationsPaneGallery.tsx`, `MediaGalleryGrid.tsx`)
**Scope:** Small

2. **Check** whether `loading.isLoading` toggling at `GenerationsPaneGallery.tsx:106` causes re-renders that could interfere (it applies `pointer-events-none` but shouldn't clear state).
3. **Trace** the `onImageClick` → `selectGalleryItem` → `setGallerySelectionMap` flow to confirm no stale closures. `handleImageClick` depends on `modifierKeys.isMultiSelectModifier` — verify this doesn't cause spurious re-creation.

## Phase 1: Bug Fix — Selection Ring

### Step 1: Fix the CSS transition conflict (`src/shared/components/MediaGalleryItem.tsx:349-356`)
**Scope:** Small
1. **Root cause**: The container div at line 352 applies `transition-all duration-200` which transitions the `box-shadow` CSS property. In Tailwind, both `ring-2 ring-sky-400` and `hover:shadow-md` compile to `box-shadow` via CSS variables (`--tw-ring-shadow` + `--tw-shadow`). When `isSelected` toggles, `transition-all` *animates* the ring in/out instead of showing it instantly — causing the visible flash. On hover, the shadow-md transition also perturbs the composed box-shadow, making the ring appear to flicker.
2. **Fix**: Replace `transition-all duration-200` with `transition-[opacity,transform] duration-200` at line 352. This limits transitions to only the properties needed for drag state (`opacity-50 scale-75`) and lets both ring and hover shadow changes be instant. The `hover:shadow-md` losing its animation is an acceptable tradeoff for correct selection feedback.
3. **Remove** the redundant `rounded-lg` inside the `isSelected` conditional at line 353 (already on base classes at line 352).

### Step 2: Verify state flow stability (`src/shared/contexts/GallerySelectionContext.tsx`, `src/features/gallery/components/GenerationsPane/components/GenerationsPaneGallery.tsx`, `src/shared/components/MediaGallery/components/MediaGalleryGrid.tsx`)
**Scope:** Small

## Phase 2: Feature — AgentChat in Locked Pane

### Step 4: Portal AgentChat to document body (`src/tools/video-editor/components/AgentChat/AgentChat.tsx`)
**Scope:** Medium
1. **Root cause**: `AgentChat` renders inside `EditorPaneTab.tsx`'s pane surface div (`EditorPaneTab.tsx:138-151`). This div has `transform` in its className (line 148) and `pane.transformClass` (line 149) which applies `translate-y-0` when open or `-translate-y-full` when closed (from `useSlidingPane.ts:252-253`). Per CSS spec, *any* `transform` value (including `translate-y-0`) creates a new containing block, causing `fixed` children to position relative to the pane container, not the viewport. When the pane is locked, the pane has `translate-y-0` — the pane is on-screen but AgentChat's `fixed bottom-5 right-5` positions relative to the pane bounds, not the viewport.
2. **Fix**: Wrap the component's returned JSX in `createPortal(…, document.body)`. This lifts all three fixed-positioned elements (recording overlay ~line 272, floating bubble ~line 311, expanded panel ~line 329) out of the transform context. Import `createPortal` from `react-dom`.
3. **React context preservation**: React portals preserve the React component tree (and thus all context providers) regardless of DOM position. AgentChat's access to timeline context, session hooks, etc. remains intact.
4. **Positioning**: The chat appears at the same `bottom-5 right-5` viewport position in all contexts (full editor page, unlocked pane, locked pane) — matching user expectation.

     dataRef: MutableRefObject<TimelineData>,

## Phase 1: Bug Fix — Selection Ring

### Step 1: Fix the CSS transition conflict (`src/shared/components/MediaGalleryItem.tsx:349-356`)
**Scope:** Small
1. **Root cause**: The container div at line 352 applies `transition-all duration-200` which transitions the `box-shadow` CSS property. In Tailwind, both `ring-2 ring-sky-400` and `hover:shadow-md` compile to `box-shadow` via CSS variables (`--tw-ring-shadow` + `--tw-shadow`). When `isSelected` toggles, `transition-all` *animates* the ring in/out instead of showing it instantly — causing the visible flash. On hover, the shadow-md transition also perturbs the composed box-shadow, making the ring appear to flicker.
2. **Fix**: Replace `transition-all duration-200` with `transition-[opacity,transform] duration-200` at line 352. This limits transitions to only the properties needed for drag state (`opacity-50 scale-75`) and lets both ring and hover shadow changes be instant. The `hover:shadow-md` losing its animation is an acceptable tradeoff for correct selection feedback.
3. **Remove** the redundant `rounded-lg` inside the `isSelected` conditional at line 353 (already on base classes at line 352).

## Phase 2: Feature — AgentChat in Locked Pane

### Step 4: Portal AgentChat to document body (`src/tools/video-editor/components/AgentChat/AgentChat.tsx`)
**Scope:** Medium
1. **Root cause**: `AgentChat` renders inside `EditorPaneTab.tsx`'s pane surface div (`EditorPaneTab.tsx:138-151`). This div has `transform` in its className (line 148) and `pane.transformClass` (line 149) which applies `translate-y-0` when open or `-translate-y-full` when closed (from `useSlidingPane.ts:252-253`). Per CSS spec, *any* `transform` value (including `translate-y-0`) creates a new containing block, causing `fixed` children to position relative to the pane container, not the viewport. When the pane is locked, the pane has `translate-y-0` — the pane is on-screen but AgentChat's `fixed bottom-5 right-5` positions relative to the pane bounds, not the viewport.
2. **Fix**: Wrap the component's returned JSX in `createPortal(…, document.body)`. This lifts all three fixed-positioned elements (recording overlay ~line 272, floating bubble ~line 311, expanded panel ~line 329) out of the transform context. Import `createPortal` from `react-dom`.
3. **React context preservation**: React portals preserve the React component tree (and thus all context providers) regardless of DOM position. AgentChat's access to timeline context, session hooks, etc. remains intact.
4. **Positioning**: The chat appears at the same `bottom-5 right-5` viewport position in all contexts (full editor page, unlocked pane, locked pane) — matching user expectation.
