        # Implementation Plan: Consolidate Lifecycle Phase Derivation

## Overview

Currently, lifecycle phase is determined by **three independent code paths** that can disagree:

1. **`current_lifecycle_phase()`** (`refresh_lifecycle.py:100`) — returns persisted mode (`"plan"` / `"execute"`) from `refresh_state["lifecycle_phase"]`. Also performs legacy migration **with mutation on read** (line 131: `refresh_state[_LIFECYCLE_PHASE_KEY] = migrated`). Falls back to heuristics based on `postflight_scan_pending()` and `plan_start_scores`.

2. **`_resolve_reconcile_display_phase()`** (`pipeline.py:99`) — derives display phase (`review`, `assessment`, `workflow`, `triage`, `execute`, `scan`) from queue contents during reconciliation. Used only in `reconcile_plan()`.

3. **`_derive_display_phase()`** (`snapshot.py:313`) — derives display phase from materialized queue item partitions. Has a comment "Keep this equivalent to `pipeline._resolve_reconcile_display_phase`" but uses completely different inputs (item lists vs queue IDs). Called by `_phase_for_snapshot()` which also reads `current_lifecycle_phase()`.

**Key problems:**
- `current_lifecycle_phase()` mutates plan data on read (legacy migration writes, heuristic fallbacks)
- No single function takes (plan, state) → (persisted_mode, display_phase) 
- `snapshot._derive_display_phase` and `pipeline._resolve_reconcile_display_phase` must be kept in sync manually
- Marker invariants (postflight_scan_completed_at, subjective_review_completed_at, lifecycle_phase) are undocumented

**Constraints:**
- Data migration code must be preserved (backward compat policy)
- `_set_lifecycle_phase` is already single-writer via pipeline.py (enforced by prior refactor)
- Display phase constants are never persisted — only `"plan"` / `"execute"` are persisted
- snapshot.py's `_derive_display_phase` takes *materialized item lists*, not raw queue IDs, so full unification into one function requires either (a) always materializing items first, or (b) a shared interface that both paths can call

## Step 1: Extract migration into a separate pure function
**Scope:** Small  
**Files:** `engine/_plan/refresh_lifecycle.py`

1. **Create** `migrate_legacy_phase(plan: PlanModel) -> bool` — a standalone function that migrates legacy phase values exactly once. Extracts lines 106-132 from `current_lifecycle_phase()`. Returns True if migration occurred.
2. **Create** `persisted_lifecycle_mode(plan: PlanModel) -> str` — pure reader that returns `"plan"` or `"execute"` from `refresh_state["lifecycle_phase"]`. No mutation, no fallback heuristics. Returns the raw persisted value or raises if not set.
3. **Modify** `current_lifecycle_phase()` to call `migrate_legacy_phase()` first, then delegate to `persisted_lifecycle_mode()`. The heuristic fallback (lines 133-137) becomes the only remaining "guess" path for plans that have never had a phase set.
4. **Add** docstring block at module top documenting marker invariants:
   - `lifecycle_phase`: `"plan"` | `"execute"`, set only by `_set_lifecycle_phase` via `reconcile_plan()`
   - `postflight_scan_completed_at_scan_count`: int, set by `mark_postflight_scan_completed()`, cleared by `invalidate_postflight_scan()`
   - `subjective_review_completed_at_scan_count`: int, set by `mark_subjective_review_completed()`

## Step 2: Create `derive_lifecycle_state()` pure function
**Scope:** Medium  
**Files:** `engine/_plan/refresh_lifecycle.py`

1. **Create** `derive_lifecycle_state(plan, state, *, queue_order, policy=None, triage_snapshot=None) -> LifecycleState` where `LifecycleState` is a `NamedTuple(mode=str, display_phase=str)`.
   - `mode`: the persisted mode (`"plan"` / `"execute"`) — derived from the current `refresh_state["lifecycle_phase"]` value
   - `display_phase`: derived from queue contents using the logic currently in `_resolve_reconcile_display_phase()`
2. **Move** the display-phase derivation logic from `pipeline._resolve_reconcile_display_phase()` into this function. The pipeline version becomes a thin wrapper calling `derive_lifecycle_state().display_phase`.
3. The function is **pure** — it reads plan/state but writes nothing. Migration must have already run.

```python
class LifecycleState(NamedTuple):

```

    Pure reader — never mutates plan. Legacy migration runs at

    WORKFLOW_DEFERRED_DISPOSITION_ID,
    WORKFLOW_RUN_SCAN_ID,
}

def _resolve_reconcile_display_phase(plan, state, *, result, policy) -> str:
    order = [item for item in plan.get("queue_order", []) if isinstance(item, str)]
    subjective_ids = [item for item in order if item.startswith("subjective::")]
    unscored_ids = set(getattr(policy, "unscored_ids", ()) or ())
    skipped = plan.get("skipped") or {}

    # Split workflow IDs: scan-phase vs true workflow
    has_scan_workflow = any(item in _SCAN_PHASE_WORKFLOW_IDS for item in order)
    has_true_workflow = (
        any(
            item.startswith("workflow::") and item not in _SCAN_PHASE_WORKFLOW_IDS
            for item in order
        )
        or bool(result.workflow_injected_ids)
    )

    # Review-postflight: triage-gated review findings first, bare open_review_ids
    # ONLY as fallback when no real execution work exists (see priority chain below)
    triage_snapshot = build_triage_snapshot(plan, state)
    triage_gated_review = (
        triage_snapshot.triage_has_run
        and not triage_snapshot.has_triage_in_queue
        and not triage_snapshot.is_triage_stale
        and bool(triage_snapshot.live_open_ids)
    )

    has_real_work = any(
        not item.startswith(("subjective::", "workflow::", "triage::"))
        for item in order if item not in skipped
    )

    # open_review_ids fallback: only when no real execution work exists
    has_review_postflight = triage_gated_review or (
        not has_real_work and bool(open_review_ids(state))
    )

    return derive_display_phase(
        has_initial_review=any(sid in unscored_ids for sid in subjective_ids),
        has_postflight_assessment=(
            bool(subjective_ids)
            and not any(sid in unscored_ids for sid in subjective_ids)
        ),
        has_workflow=has_true_workflow,
        has_triage=(
            bool(result.triage and (result.triage.injected or result.triage.deferred))
            or any(item.startswith("triage::") for item in order)
        ),
        has_review_postflight=has_review_postflight,
        has_execution=has_real_work,
        fresh_boundary=not bool(plan.get("plan_start_scores")),
        prefer_scan=has_scan_workflow,
    )
