        # Implementation Plan: Megaplan Skill → Subagent Architecture (Opt-In)

## Overview

**Current state:** The canonical megaplan skill instructions live in `megaplan/data/instructions.md` and are installed identically to Claude, Codex, and Cursor targets via `megaplan/cli.py:306-309`. The instructions tell the host LLM to orchestrate `megaplan` CLI calls inline, phase by phase, in the main context window.

**Goal:** Add an **opt-in** subagent mode for Claude Code that wraps the workflow in a subagent. Inline orchestration remains the default. When subagent mode is active, the outer skill launches an Agent, handles breakpoint returns (gate ESCALATE, finalize-to-execute approval in review mode), and reports the final result. Auto-approve + subagent = fully hands-off.

**Key constraint from user:** Current inline behavior stays the default. Subagent is opt-in via a persistent setting (`megaplan config set orchestration.mode subagent`) or per-run user request ("use subagent mode"). Default can be overridden per-run in either direction.

**Design:** Install a **unified Claude skill file** = `_SKILL_HEADER` + `instructions.md` (inline mode, unchanged) + subagent appendix from new `megaplan/data/claude_subagent_appendix.md`. The appendix is conditional — the LLM activates it only when the user opts in or `megaplan config show` returns `orchestration.mode: subagent`. Codex and Cursor targets are unchanged (they don't support Agent+SendMessage).

**Real workflow per robustness level** (from `megaplan/_core/workflow.py:31-86`):
- **Light:** init → plan → critique → revise → finalize → execute (no gate, no review)
- **Standard:** init → plan → critique → gate → [revise loop] → finalize → execute → review
- **Heavy:** init → prep → plan → critique → gate → [revise loop] → finalize → execute → review

**Breakpoint model** (subagent mode only):
- **Finalize-to-execute in review mode:** agent pauses after `finalize`, returns for user approval
- **Gate ESCALATE (standard/heavy):** agent always pauses, returns for user decision (force-proceed / replan / abort)
- **Auto-approve + non-escalated happy path:** zero breakpoints — agent runs to completion
- **Review needs_rework:** agent auto-continues (re-execute), capped at 3 cycles by CLI
- **Execute timeout/blocked:** agent auto-retries same batch, max 3 consecutive retries without progress → escalate to user

**Safeguards** (ported from hermes-agent `run_megaplan_loop` pattern):
- Phase retry cap: if a CLI call fails, retry once with `--fresh` session. If it fails again, escalate to user.
- Execute loop cap: max 3 consecutive `next_step=execute` responses without new tasks completing → escalate breakpoint to user.
- Stuck-session detection: if same phase returns identical output/error twice, force `--fresh` session on next attempt.
