        # Implementation Plan: Handler Evidence-Checking Cleanup

## Overview

`handle_execute` (handlers.py:1105-1270, 165 lines) and `handle_review` (handlers.py:1273-1413, 140 lines) share structural duplication in three areas: (1) validate→merge→completeness-check pipelines, (2) done-task evidence scanning with FLAG-006 advisory/blocking split, and (3) blocking-reason accumulation. The `_is_substantive_reviewer_verdict` heuristic (handlers.py:264-266) uses magic numbers and is trivially gameable (e.g. repeated words pass).

Existing helpers `_validate_merge_inputs` (handlers.py:184) and `_merge_validated_entries` (handlers.py:239) already factor out low-level merge logic. This plan extracts the *higher-level* patterns that call those helpers and the evidence-checking loops, and hardens the verdict heuristic.

**Constraints:** No behavior changes to blocking/advisory classification logic — deviations/issues messages, blocking semantics, and test assertions must remain identical. The user's META notes are out of scope.

### Step 2: Extract `_validate_and_merge_batch` helper (`megaplan/handlers.py:~185`)
**Scope:** Medium
1. **Implement** a single helper that wraps the validate→merge→completeness-report pipeline. Both handlers repeat this 3-call pattern (validate, merge, check completeness) for both tasks and sense checks — that's 4 occurrences total.
   ```python
   def _validate_and_merge_batch(

   ) -> int:
       """Validate, merge, and report completeness. Returns merged count."""
   ```
2. **Replace** the 4 validate→merge→completeness-check sequences in `handle_execute` (lines 1128-1174) and `handle_review` (lines 1288-1326) with calls to this helper.

### Step 3: Extract `_check_done_task_evidence` helper (`megaplan/handlers.py:~210`)
**Scope:** Medium

The two evidence loops have different shapes that must be preserved:

- **Execute** (lines 1176-1196): Every done task is classified. Two-way split: has `files_changed` → OK; has only `commands_run` → advisory; has neither → blocking.
- **Review** (lines 1328-1351): Done tasks with a **blank** `reviewer_verdict` are **skipped entirely** (left to coverage enforcement, not evidence enforcement). Only tasks with a non-blank verdict enter classification: has `evidence_files` → OK; substantive verdict without files → advisory; non-substantive verdict without files → blocking.

1. **Implement** a shared evidence-checking function with an explicit `should_classify` predicate to handle the review handler's blank-verdict skip:
   ```python
   def _check_done_task_evidence(
       tasks: list[dict[str, Any]],
       *,
       should_classify: Callable[[dict[str, Any]], bool],
       has_evidence: Callable[[dict[str, Any]], bool],
       has_advisory_evidence: Callable[[dict[str, Any]], bool],
       missing_message: str,
       advisory_message: str,
       issues: list[str],
   ) -> list[str]:
       """Check done-task evidence completeness. Returns list of blocking task IDs.

       For each done task where should_classify returns True:
       - has_evidence → skip (sufficient)
       - has_advisory_evidence → append to advisory list
       - neither → append to blocking list
       Tasks where should_classify returns False are ignored (e.g. blank verdicts
       in review, which are handled by coverage enforcement instead).
       """
   ```
   - For **execute**: `should_classify = lambda t: True` (all done tasks enter classification), `has_evidence = lambda t: bool(t.get("files_changed"))`, `has_advisory_evidence = lambda t: bool(t.get("commands_run"))`
   - For **review**: `should_classify = lambda t: bool(t.get("reviewer_verdict", "").strip())` (blank verdicts skip), `has_evidence = lambda t: bool(t.get("evidence_files"))`, `has_advisory_evidence = lambda t: _is_substantive_reviewer_verdict(t.get("reviewer_verdict", ""))`
2. **Replace** the evidence-checking loops in `handle_execute` (lines 1176-1196) and `handle_review` (lines 1328-1351) with calls to this helper.

### Step 4: Harden `_is_substantive_reviewer_verdict` (`megaplan/handlers.py:264-266`)
**Scope:** Small

The current heuristic (`len > 20 and words >= 4`) is trivially gameable — `"ok ok ok ok ok ok ok"` passes despite containing no real information. Replace with a more robust check:

1. **Extract** thresholds into named constants:
   ```python
   _MIN_VERDICT_CHARS = 20
   _MIN_VERDICT_WORDS = 4
   _MIN_VERDICT_UNIQUE_WORDS = 3
   ```
2. **Update** `_is_substantive_reviewer_verdict` to also require a minimum number of **unique** (case-insensitive) words:
   ```python
   def _is_substantive_reviewer_verdict(text: str) -> bool:
       stripped = text.strip()
       words = stripped.split()
       unique_words = set(w.lower() for w in words)
       return (
           len(stripped) >= _MIN_VERDICT_CHARS
           and len(words) >= _MIN_VERDICT_WORDS
           and len(unique_words) >= _MIN_VERDICT_UNIQUE_WORDS
       )
   ```
   This rejects degenerate strings like repeated filler while still accepting any real reviewer sentence. The unique-word check is the minimal addition that meaningfully hardens the heuristic without over-engineering.
3. **Add** a focused unit test for `_is_substantive_reviewer_verdict` covering: a real verdict (pass), a short string (fail), repeated words (fail), and the boundary case.

3. **Verify** FLAG-006 softening assertions (test_megaplan.py:2071, :2194) still pass, confirming message strings are preserved.
