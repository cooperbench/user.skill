        Idea:
Fix cross-track clip dragging and track system to work like a standard NLE.

CURRENT PROBLEM: The @xzdarcy/react-timeline-editor library only supports horizontal dragging within a single row. When users try to drag clips vertically to another track, it causes duplication (clip appears in both the original and target row). The library's onChange fires with the horizontal move applied to the original row, but there's no native cross-row move support.

GOAL: Users should be able to fluidly drag clips between tracks vertically, just like in Premiere/Final Cut/DaVinci. Each track has its own settings (scale, fit, opacity, blend mode) that apply to all clips on that track, but individual clips can override those settings.

APPROACH OPTIONS TO CONSIDER:
1. Work within @xzdarcy/react-timeline-editor - intercept the drag events, detect Y movement, and manually move the clip data between rows before onChange fires
2. Replace @xzdarcy/react-timeline-editor with a custom timeline component that natively supports cross-row dragging (more work but cleaner)
3. Use a different library that supports this natively
4. Hybrid: keep the library for time-based operations but overlay a custom drag layer for cross-row movement

REQUIREMENTS:
- Fluid drag-and-drop of clips between any visual tracks
- Visual feedback during drag showing which track the clip will land on
- Auto-create new tracks when dragging below the last track
- Track-level settings (scale, fit, opacity, blend) inherited by clips
- Per-clip setting overrides
- No duplication bugs
- Works alongside existing horizontal drag, resize, and timeline scrubbing
