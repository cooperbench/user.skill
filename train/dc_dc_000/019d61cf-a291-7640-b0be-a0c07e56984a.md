        # Implementation Plan: Clean Up Final Video Badge & Shot Creation Flow

## Overview
Three bugs in the video editor timeline: (1) shot groups don't appear after creation because cache invalidation skips active queries, (2) the "final video available" badge reappears after dismiss because dismiss state is in React useState that resets on remount, (3) the badge shows even after the user has already switched to the final video. All three are small, targeted fixes in 4 files.

## Main Phase

### Step 1: Fix shot query invalidation (`src/shared/hooks/shotCreation/shotCreationPaths.ts`)
**Scope:** Small
1. **Remove `{ refetchType: 'inactive' }`** from `invalidateShotsQueries` calls on lines 204 and 264.
   - Line 204: `invalidateShotsQueries(queryClient, selectedProjectId)` (no second arg)
   - Line 264: same change
2. The `upsertShotInCache` call above each invalidation already puts the shot in cache optimistically, so the refetch just confirms server state. Removing the filter lets the active `ShotsContext` query pick up the new shot.

### Step 2: Move dismissed state to module-level and key by finalVideo.id (`src/tools/video-editor/hooks/useFinalVideoAvailable.ts`)
**Scope:** Small
1. **Replace `useState<Set<string>>`** with a module-level `Set<string>` (same pattern as `useStaleVariants.ts:30` uses `dismissedAssetKeys`, though that one is useState — the brief calls for module-level to survive remounts).
2. **Change dismiss key from shotId to finalVideo.id.** The caller currently does `dismissShot(group.shotId)`. Change the API so `dismissFinalVideo(finalVideoId: string)` is the dismiss function. Update the filtering in `useFinalVideoAvailable` to check `dismissedIds.has(finalVideo.id)` instead of `dismissedShotIds.has(shotId)`.
3. **Use `useSyncExternalStore`** (or a simple `useReducer` + module ref pattern) to trigger re-renders when the module-level Set changes. Simplest: a module-level Set + a counter in useState that increments on dismiss to force re-render.

   ```ts
   const dismissedFinalVideoIds = new Set<string>();

   export function useFinalVideoAvailable() {
     const { selectedProjectId } = useProjectSelectionContext();
     const { finalVideoMap } = useShotFinalVideos(selectedProjectId);
     const [, forceRender] = useState(0);

     const dismissFinalVideo = useCallback((finalVideoId: string) => {
       dismissedFinalVideoIds.add(finalVideoId);
       forceRender((n) => n + 1);
     }, []);

     return { finalVideoMap, dismissedFinalVideoIds, dismissFinalVideo };
   }
   ```

### Step 3: Suppress badge when final video is already on the timeline (`src/tools/video-editor/components/TimelineEditor/TimelineEditor.tsx`)
**Scope:** Small
1. **Update the `finalVideoShotIds` memo** (line 269-277) to also exclude shots whose final video asset is already on the timeline. The registry (`data?.registry?.assets`) contains all assets with their `generationId`. In `useSwitchToFinalVideo` line 55, the final video asset is registered with `generationId: finalVideo.id`. So check:
   ```ts
   const finalVideoShotIds = useMemo(() => {
     const shotIds = new Set<string>();
     // Collect all generationIds currently on the timeline
     const timelineGenerationIds = new Set<string>();
     const assets = data?.registry?.assets;
     if (assets) {
       for (const entry of Object.values(assets)) {
         if (entry?.generationId) timelineGenerationIds.add(entry.generationId);
       }
     }
     for (const [shotId, finalVideo] of finalVideoMap) {
       if (dismissedFinalVideoIds.has(finalVideo.id)) continue;
       // If the final video is already on the timeline, don't show badge
       if (timelineGenerationIds.has(finalVideo.id)) continue;
       shotIds.add(shotId);
     }
     return shotIds;
   }, [dismissedFinalVideoIds, finalVideoMap, data?.registry?.assets]);
   ```
2. **Update callers of `dismissShot`** to pass `finalVideo.id` instead of `shotId`. On line 548-549, the `onShotGroupSwitchToFinalVideo` and `onShotGroupDismissFinalVideo` callbacks need to look up the finalVideo for the group's shotId and pass its id. Since `finalVideoMap` is already in scope, this is straightforward:
   ```ts
   onShotGroupSwitchToFinalVideo={(group) => {
     const fv = finalVideoMap.get(group.shotId);
     if (fv) dismissFinalVideo(fv.id);
     handleSwitchToFinalVideo(group);
   }}
   onShotGroupDismissFinalVideo={(shotId) => {
     const fv = finalVideoMap.get(shotId);
     if (fv) dismissFinalVideo(fv.id);
   }}
   ```
