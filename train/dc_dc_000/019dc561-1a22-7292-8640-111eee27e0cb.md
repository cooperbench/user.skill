**Existing LLM Usage**
- `ANTHROPIC_API_KEY` is the only LLM API env var currently used.

- API pattern is:
  - `client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])`
  - `client.messages.create(model=..., max_tokens=..., system=..., messages=[{"role": "user", "content": ...}])`
  - parse `resp.content[0].text`
- Existing concurrency pattern: `ThreadPoolExecutor` with a shared Anthropic client, progress every N completions.

**Relevant Config/Data**
- v3.2 config already points at `data/pairs_v3_2/{train,val,test}.jsonl` in [configs/stage1_v3_2_no_trunk_smoke.yaml](/Users/user_c042661f/Documents/reigh-workspace/text-ip-adapter/configs/stage1_v3_2_no_trunk_smoke.yaml:21).
- That directory is not present locally in this checkout, but the script should target it by default.
- Pair rows use at least: `register`, `author`, `ref_doc_id`, `target_doc_id`, `ref_text`, `target_text`, `instruction`, often `instruction_rule_based`.

**Minimal Script Shape**
Add `scripts/audit_pairs_llm.py` with:

```text
args:
  --in-dir data/pairs_v3_2
  --out-dir data/pairs_v3_2/audit
  --splits train val test
  --model claude-haiku-4-5
  --workers 8
  --max-pairs 0
  --resume
```

Outputs:
- `audit/{split}.audit.jsonl`: one audit record per input row.
- optionally `audit/{split}.kept.jsonl` or leave filtering to a later deterministic script.
- `audit/summary.json`: counts by decision/register/reason.

Per-row output shape:

```json
{
  "split": "train",
  "index": 123,
  "decision": "keep",
  "confidence": "high",
  "reasons": ["clean_content_instruction", "good_style_pair"],
  "edit_instruction": null,
  "notes": "short explanation",
  "pair": { "... original row ..." }
}
```

Prompt contract should force strict JSON only:

```text
Classify this training pair as:
- keep: usable as-is
- delete: harmful/noisy/leaky/boilerplate/bad pairing
- edit: usable if the instruction is replaced

Judge:
1. target_text quality and boilerplate
2. instruction matches target content
3. instruction does not mention style/voice/author/form
4. ref_text and target_text share author/register style but not same content
5. no obvious reference leakage into instruction

Return exactly JSON:
{"decision":"keep|delete|edit","confidence":"low|medium|high","reasons":["..."],"edit_instruction":null|string,"notes":"..."}
```

For cost control, truncate aggressively:
- `ref_text[:1000]`
- `target_text[:1200]`
- `instruction[:300]`
- `max_tokens=160`

Use Haiku, not Sonnet, for the first pass. This is a classification/edit task with short constrained output, and the repo already treats `claude-haiku-4-5` as the cheap batch model. Run command should look like:

```bash
ANTHROPIC_API_KEY=... python scripts/audit_pairs_llm.py \
  --in-dir data/pairs_v3_2 \
  --out-dir data/pairs_v3_2/audit \
  --splits train val test \
  --model claude-haiku-4-5 \
  --workers 8
```

I would not wire this into configs yet. Keep it as an offline dataset audit artifact first, then decide whether to materialize `*.audited.jsonl` for training once you inspect delete/edit rates.
