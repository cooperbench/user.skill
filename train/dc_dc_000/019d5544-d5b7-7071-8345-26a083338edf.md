        # Implementation Plan: Timeline Agent Task Creation from Selected Media

## Overview

The timeline agent currently has a single `run` tool with text commands for timeline editing. It has a basic `generate` command that creates image generation tasks, but it:
1. Uses the **old** `task_type`/`params` API format — the `create-task` edge function now requires `family`/`input`, so the current generate command is likely broken
2. Only supports basic text-to-image generation — no reference images, no style/subject/scene transfer, no image-to-video
3. Has no shot creation capability

The `image_generation` family resolver (`create-task/resolvers/imageGeneration.ts`) already supports `reference_mode` (style, subject, scene, style-character, custom) with `style_reference_image`/`subject_reference_image` parameters. There are no separate transfer task families — it's all the `image_generation` family with reference mode settings.

**Approach:** Add a structured `create_task` LLM tool (separate from the text-based `run` tool) that accepts JSON parameters for task creation. This is better than extending the text command parser because task creation has complex parameters (URLs, modes, counts) that are more reliably expressed as structured JSON. Also fix the existing `generate` command to use the new `family`/`input` API format.

## Phase 1: Fix existing generation + extend for reference modes

### Step 1: Update `createGenerationTask` to use `family`/`input` format (`supabase/functions/ai-timeline-agent/tools/generation.ts`)
**Scope:** Medium

1. **Refactor** the `createGenerationTask` function (lines 42-97) to:
   - Accept extended args including `reference_image_url`, `reference_mode`, `shot_id`, `model_name`
   - Build the request body using `{ family: "image_generation", project_id, input: { ... } }` format
   - Map the input to match `BatchImageGenerationTaskInput` expected by the resolver:
     - `prompts: [{ id: crypto.randomUUID(), fullPrompt: prompt }]`
     - `imagesPerPrompt: count`
     - `reference_mode` (style/subject/scene)
     - `style_reference_image` (from attached clip URL)
     - `shot_id` (if provided)
     - `model_name` (default to "qwen-image" when using reference images, since only qwen-image and z-image support reference params per `supportsReferenceParams()` at `imageGeneration.ts:102-104`)
2. **Update** the `CreateGenerationTaskArgs` interface (lines 3-10) to include the new fields.
3. **Keep** backward compatibility: existing `generate` command still works (just prompt + count), but now also supports the extended params.

### Step 2: Add shot creation capability (`supabase/functions/ai-timeline-agent/tools/shots.ts` — new file)
**Scope:** Small

1. **Create** a `createShot` function that:
   - Takes `project_id`, `shot_name`, optional `generation_id`
   - Calls the `insert_shot_at_position` RPC via supabase admin client (or `create_shot_with_image` if linking a generation)
   - Returns the new `shot_id`
2. **Note:** The agent runs with service-role key, so it has full DB access. Pass the supabase admin client through.

## Phase 2: Add structured `create_task` tool for LLM

### Step 3: Add `create_task` tool schema (`supabase/functions/ai-timeline-agent/tool-schemas.ts`)
**Scope:** Small

1. **Add** a second tool definition to `TIMELINE_AGENT_TOOLS` array (currently only has `run`):
   ```typescript
   {
     type: "function",
     function: {
       name: "create_task",
       description: "Create a generation task. Use with selected clip URLs for style/subject/scene transfer, or standalone for text-to-image.",
       parameters: {
         type: "object",
         properties: {
           prompt: { type: "string", description: "What to generate" },
           task_type: { type: "string", enum: ["text-to-image", "style-transfer", "subject-transfer", "scene-transfer"], description: "Type of generation" },
           reference_image_url: { type: "string", description: "URL of the reference image (from selected clips)" },
           count: { type: "number", description: "Number of images to generate (default 1)" },
           shot_name: { type: "string", description: "Optional: create a new shot with this name to hold results" },
         },
         required: ["prompt", "task_type"],
       },
     },
   }
   ```

### Step 4: Wire `create_task` tool in the agent loop (`supabase/functions/ai-timeline-agent/loop.ts`)
**Scope:** Medium

1. **Update** the tool call extraction and execution logic. Currently, the loop extracts commands from `run` tool calls and executes them via `executeCommand`. For `create_task` tool calls, route to a dedicated handler.
2. **Key change** in the loop's command extraction (around lines 203-215): when a tool call has `name: "create_task"`, don't parse it as a text command — instead call `createGenerationTask` directly with the structured args.
3. **Map** `task_type` to `reference_mode`:
   - `"text-to-image"` → no reference mode
   - `"style-transfer"` → `reference_mode: "style"`, `style_reference_image` from `reference_image_url`
   - `"subject-transfer"` → `reference_mode: "subject"`, `style_reference_image` + `subject_reference_image` from `reference_image_url`
   - `"scene-transfer"` → `reference_mode: "scene"`, `style_reference_image` from `reference_image_url`
4. **If `shot_name` provided**: create the shot first via the shots utility, then pass `shot_id` to the task creation.

### Step 5: Update the system prompt (`supabase/functions/ai-timeline-agent/prompts.ts`)
**Scope:** Small

1. **Add** instructions explaining the `create_task` tool to the system prompt (lines 24-44):
   - When user selects images and asks for style/subject/scene transfer, use `create_task`
   - Explain the task types and when to use each
   - Show example tool calls:
     ```
     create_task(prompt="a sunset beach", task_type="style-transfer", reference_image_url="<url from selected clips>")
     ```
   - Remind the agent that selected clip URLs are available in the context

### Step 6: Update command extraction to handle multi-tool responses (`supabase/functions/ai-timeline-agent/loop.ts`)
**Scope:** Small

1. **Ensure** the loop's tool call handling (lines 162-282) correctly processes both `run` and `create_task` tool calls in the same response.
2. The existing extraction handles structured `tool_calls` from the LLM response (line 203). This already supports multiple tool names in principle — verify it routes `create_task` calls to the right handler instead of trying to parse them as text commands.

## Phase 3: Integration and testing

### Step 7: Update the `run` tool description to exclude generate overlap (`supabase/functions/ai-timeline-agent/tool-schemas.ts`)
**Scope:** Small

1. **Remove** `generate` from the `run` tool description since `create_task` supersedes it. Keep the `generate` command parser working for backward compat with in-flight sessions, but don't advertise it.
2. **Update** the `run` description to mention that generation should use `create_task` instead.

### Step 8: Manual testing checklist
**Scope:** Info

1. Select an image on the timeline → ask "make variations in this style" → verify `create_task` is called with `style-transfer` and the clip URL
2. Select an image → ask "put this character in a forest" → verify `subject-transfer`
3. Select an image → ask "recreate this scene with different lighting" → verify `scene-transfer`
4. Ask "generate a sunset" with no selection → verify basic `text-to-image` still works
5. Ask "generate in this style and put it in a new shot called 'sunset'" → verify shot creation + task creation
