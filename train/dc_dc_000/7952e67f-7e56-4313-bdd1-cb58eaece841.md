### 2. **How `runtime_scope()` works** (desloppify/base/runtime_state.py, lines 132-140)

`runtime_scope()` is a context manager that:
- Creates or reuses a `RuntimeContext` object
- Sets it in a `ContextVar` (thread/async-local storage)
- Yields the active runtime object
- Resets the context on exit

It does NOT manage `project_root` — that comes from `get_project_root()`.

### 3. **The actual bug is in `_resolve_default_path`:**

**Problem scenario:**
```bash

  --state /actual/project/.desloppify/state-python.json \
  --path .
```

**What happens:**
1. Line 118: `runtime_root = get_project_root()` → `/some/other/project` (from cwd)
2. Line 121: `state_file = state_path(args)` → `/actual/project/.desloppify/state-python.json` ✓ correct
3. Line 123: `load_state(state_file)` → reads saved state from `/actual/project`
4. Line 124: `saved_path = saved.get("scan_path")` → e.g., `"src"` (relative to `/actual/project`)
5. **Line 126 (BUG):** `args.path = str((runtime_root / saved_path).resolve())`

   - Should be: `/actual/project/src` ✓ 

### 4. **How `review --prepare` uses the path:**

- But it loads `saved_path` from a state file in a different project
- The saved_path is then resolved against the wrong project root
- Downstream file discovery uses the wrong base directory

`_resolve_default_path()` should extract the project root **from the state file's directory** when `--state` is from outside the cwd, not from the cwd itself.
