## Settled design decisions (DO NOT debate during planning)

These were debated and decided in the outer conversation. The plan must respect them.

### SD-001 — Mixed-mode arrange uses ONE LLM call with kind-aware context blocks

The `arrange` step gets a single prompt with the pool partitioned by `classified_kind`, plus per-kind guidance text in the prompt (e.g., *"VIDEO clips have transcripts and are best for spoken content; IMAGE clips are generative and best for B-roll, transitions, or title cards."*). Not separate LLM calls per kind. Not one homogeneous prompt that ignores kinds. The LLM stays the dispatcher; it just gets structured framing. Pure-generative briefs see a pool with only IMAGE/EFFECT entries (no VIDEO partition shown); source-cut briefs see only VIDEO entries — same behavior as today for those paths. _load_bearing: true_

### SD-002 — `--from <step>` operates against the dynamic computed step set, not legacy `STEP_ORDER`

If the user runs `--from refine` on a brief that doesn't need refine, they get a clear error: *"step 'refine' is not in this brief's computed step set: [transcribe, arrange, cut, render]"*. Not a silent skip-to-end. Not a "step unknown" error. The computed set is the source of truth; the static `STEP_ORDER` is preserved as a topological-order hint only. _load_bearing: true_

### SD-003 — `allow_generative_visuals` lives in brief metadata, default false; CLI `--allow-generative-effects` is a transient override

Mixed-mode is an editorial decision, not a runtime one. The brief gets a top-level optional field `allow_generative_visuals: true|false` (default false). The CLI gains a flag `--allow-generative-effects` that overrides the brief for the current run only (does not write back to the brief). When `allow_generative_visuals` is false (default), source-cut behavior is unchanged for existing briefs. When true, the arrange step includes generative IMAGE entries in the pool and the cut step accepts mixed-kind arrangements. _load_bearing: true_

## Constraints (non-negotiable, from earlier Reigh compatibility analysis)

1. **Reigh compatibility — `clip.kind` is NEVER persisted.** Reigh's clip allowlist (`reigh-app/src/tools/video-editor/lib/serialize.ts:8-42`) is closed and throws on unknown clip keys. 2. **Backwards-compat user-facing CLI** — `python3 -m artagents --video X.mp4 --brief brief.txt`, `--audio X.wav --brief brief.txt`, and `--brief brief.txt --target-duration 28` (pure-generative) all keep working with current behavior. 3. **Topological order preserved** — current pipeline ordering has real dependencies (e.g. `pool_merge` after `pool_build` for sources AND any generative pool); manifest-driven discovery must produce the same order when the same step set is needed. The static `STEP_ORDER` constant in `hype/run.py` (or wherever it lives now) becomes a topological-order *hint*, not the source of truth for which steps to run.
4. **Schema package unchanged** — clip kinds are runtime-derived. No `@banodoco/timeline-schema` changes.
5. **Timeline round-trip stays byte-equivalent** — `tests/test_timeline_roundtrip_fixture.py` is the regression gate.
