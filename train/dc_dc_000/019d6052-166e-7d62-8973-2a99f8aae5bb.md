        # Implementation Plan: Video Editor Context Menu — Existing Shot Awareness

## Overview

The video editor's right-click context menus (`ClipAction` and `SelectionContextMenu`) currently only support *creating* a new shot from selected clips. Once a shot is created, `clearSelection()` wipes the selection state, and subsequent right-clicks show no shot actions because `canCreateShotFromSelection` depends on `selectedClipIds` being non-empty. There is no mechanism to look up existing shots that contain the selected clips' generation IDs.

**Goal:** When right-clicking clips, look up existing shots containing those generation IDs and display them at the top of the shot actions section with "Jump to Shot" and "Generate Video" buttons. Keep "Create Shot" and "Generate Video" below. Fix the `clearSelection()` bug so shot actions remain available after creating a shot.

**Key files:**
- `src/tools/video-editor/components/TimelineEditor/TimelineEditor.tsx` — wires shot creation, calls `clearSelection()`
- `src/tools/video-editor/components/TimelineEditor/ClipAction.tsx` — clip context menu
- `src/shared/components/SelectionContextMenu.tsx` — gallery selection context menu
- `src/shared/contexts/ShotsContext.tsx` — provides `shots` array with `images` (GenerationRow[])

**Architecture:** Shots are available via `useShots()` which returns `Shot[]` with `images?: GenerationRow[]` where each image has a `generation_id`. We can do a client-side lookup: for a set of generation IDs, filter `shots` to find any whose `images` contain matching `generation_id` values. No new DB queries needed.

## Phase 1: Fix the clearSelection() Bug

### Step 1: Remove premature clearSelection() from shot creation handlers (`TimelineEditor.tsx`)
**Scope:** Small

1. **Remove** `clearSelection()` from `handleCreateShotFromSelection` (line 249) and `handleGenerateVideoFromSelection` (line 267).
2. The selection should persist after shot creation — the user can dismiss it by clicking elsewhere. The context menu's local `createdShot` state already handles the UI transition from "Create Shot" to "Jump to Shot".
3. This fixes the root cause: `clearSelection()` → empty `selectedClipIds` → `canCreateShot: false` → no shot actions on next right-click.

## Phase 2: Add Existing Shot Lookup

### Step 2: Create a utility to find shots containing given generation IDs (`TimelineEditor.tsx`)
**Scope:** Small

1. **Add** a `useMemo` in `TimelineEditorComponent` that computes `existingShotsForSelection`:
   ```typescript
   const existingShotsForSelection = useMemo(() => {
     if (!shots || selectionShotCreationState.generationIds.length === 0) return [];
     const genIdSet = new Set(selectionShotCreationState.generationIds);
     return shots.filter(shot =>
       shot.images?.some(img => genIdSet.has(img.generation_id))
     );
   }, [shots, selectionShotCreationState.generationIds]);
   ```
2. This reuses the already-available `shots` from `useShots()` (line 87) and `selectionShotCreationState.generationIds`.

### Step 3: Thread existing shots through ClipAction props (`TimelineEditor.tsx`, `ClipAction.tsx`)
**Scope:** Medium

1. **Add** `existingShots?: Shot[]` to `ClipActionProps` interface in `ClipAction.tsx`.
2. **Pass** `existingShotsForSelection` to `ClipAction` in `getActionRender` (around line 327).
3. **Add** `existingShots?: Shot[]` to `ClipContextMenuProps` type.
4. **Pass** `existingShots` through to `ClipContextMenu`.
5. **Snapshot** `existingShots` in `shotActionsSnapshotRef` so they persist while the menu is open.

### Step 4: Render existing shots in ClipContextMenu (`ClipAction.tsx`)
**Scope:** Medium

1. **Add** existing shot items at the TOP of the shot actions section (before "Create Shot"), inside the `props.showShotActions` block.
2. For each existing shot, render two inline buttons:
   - "Jump to [ShotName]" using `ArrowRight` icon → calls `onNavigateToShot(shot)` + `closeMenu()`
   - "Generate Video" using `Clapperboard` icon → calls `onOpenGenerateVideo(shot)` + `closeMenu()`
3. **Keep** the existing "Create Shot" and "Generate Video" buttons below, unchanged.
4. Add a visual separator between existing shots and creation actions if both are present.

### Step 5: Add existing shots support to SelectionContextMenu (`SelectionContextMenu.tsx`, `GenerationsPaneGallery.tsx`)
**Scope:** Medium

1. **Add** `existingShots?: Shot[]` to `SelectionContextMenuProps`.
2. **Render** existing shot items at the TOP of the menu (before "Create Shot"), same pattern as ClipAction.
3. **In GenerationsPaneGallery.tsx**, compute `existingShotsForSelection` using `useShots()` and the selected gallery generation IDs:
   - The gallery selection context provides `selectedGalleryIds` which are generation IDs.
   - Filter `shots` by matching `images[].generation_id`.
4. **Pass** `existingShots` to `SelectionContextMenu`.

### Step 6: Ensure canCreateShotFromSelection remains true with active selection (`TimelineEditor.tsx`)
**Scope:** Small

1. **Verify** that after removing `clearSelection()` in Step 1, `canCreateShotFromSelection` stays true when clips are selected. Since it depends on `selectedClipIds` which now won't be cleared, this should work automatically.
2. **Verify** the snapshot mechanism in ClipAction still correctly captures `showShotActions: true` on right-click even after a shot was just created (the `createdShot` local state handles menu item switching).

## Phase 3: Validation

### Step 7: Manual testing scenarios

2. Click "Create Shot" → verify menu shows "Jump to [Shot]" and "Generate Video" for the created shot.

4. Select 2+ clips that belong to different existing shots → verify all matching shots listed.
5. Select clips with no existing shots → verify only "Create Shot" and "Generate Video" appear.
6. Test in gallery SelectionContextMenu → same behavior.

2. Steps 2–4 (ClipAction existing shots) as a unit.
3. Step 5 (SelectionContextMenu) can be done after ClipAction since it follows the same pattern.
4. Steps 6–8 (validation) after all changes.
