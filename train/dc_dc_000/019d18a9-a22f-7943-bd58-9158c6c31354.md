## Phase 1: Deduplicate Gate Response Fields

**Problem:** In `handle_gate` (cli.py:784-796), the response dict is built with:
```python
"gate_recommendation": gate_summary["recommendation"],   # line 793
"gate_rationale": gate_summary["rationale"],             # line 794
**gate_summary,                                          # line 795 — spreads recommendation & rationale again
```
This means `response["recommendation"]` and `response["gate_recommendation"]` are identical. Same for `rationale`/`gate_rationale`.

**Plan:**
1. **Audit all consumers** of `gate_recommendation` and `gate_rationale` across the codebase (tests, prompts, workers, instructions.md, the skill file). Determine which name is canonical.
2. **Pick canonical names.** The `**gate_summary` spread uses `recommendation`/`rationale` (matching the schema and gate.json). The `gate_`-prefixed fields exist only in the StepResponse. Decision: keep the `gate_`-prefixed names in StepResponse (they're namespaced and clear in a response that also has `step`, `summary`, etc.), and stop spreading raw `gate_summary` fields that collide.
3. **Refactor `handle_gate`:** Replace `**gate_summary` spread with explicit fields that don't collide. Only include `gate_recommendation`, `gate_rationale`, `passed`, `orchestrator_guidance`, `warnings`, `robustness` — the fields the caller actually needs.
4. **Refactor `_override_force_proceed`:** Same pattern — uses `gate["orchestrator_guidance"]` directly. Align field names.
5. **Update tests** that assert on both `response["recommendation"]` and `response["gate_recommendation"]`. Keep only the canonical name.
6. **Run tests.**

**Files touched:** `cli.py`, `test_megaplan.py`, possibly `test_evaluation.py`.

## Phase 4: Normalize Test Style

**Problem:** 5 test files with 3 different conventions for fixtures, naming, and assertions.

**Plan:**
1. **Audit current conventions across all test files:**
   - `test_megaplan.py`: `plan_fixture` pytest fixture, `make_args` factory, `load_state` helper
   - `test_evaluation.py`: `_state()`, `_scaffold()`, `_signals()` plain functions (not fixtures)
   - `test_workers.py`: `_make_args()`, `_mock_state()` plain functions
   - `test_schemas.py`: Inline setup, no fixtures
   - `test_prompts.py`: TBD (need to read)

2. **Pick the target convention:**
   - **Fixtures:** Use `pytest.fixture` for shared setup (plan dirs, states). Convert `_scaffold()`, `_mock_state()` to fixtures where reused across tests.
   - **Naming:** `test_<unit>_<behavior>` everywhere (e.g., `test_flag_weight_security_returns_3`).
   - **Assertions:** Plain `assert` with clear comparisons. No `assertEqual`. Use `pytest.raises(XError, match=...)` for exceptions.
   - **Helpers:** Private `_make_*` factory functions are fine for parameterized data; promote to fixtures only when they need tmp_path or other fixture deps.

3. **Normalize each file** one at a time, running tests after each:
   - `test_evaluation.py` — convert `_scaffold` to fixture, align naming
   - `test_workers.py` — convert `_mock_state` to fixture, align naming
   - `test_schemas.py` — minor naming alignment
   - `test_prompts.py` — align to convention
   - `test_megaplan.py` — already closest to target, minor tweaks

4. **Add `conftest.py`** if 2+ test files share the same fixture (e.g., plan directory scaffolding).
5. **Run full suite after each file.**

## Phase 4: Normalize Test Style

**Target convention:**

**Steps — normalize each file one at a time:**
1. `test_evaluation.py` — align test function naming to `test_<unit>_<behavior>`.
2. `test_workers.py` — align naming.
3. `test_schemas.py` — align naming.
4. `test_prompts.py` — align naming and assertion style.
5. `test_megaplan.py` — already closest to target, minor naming tweaks only.

**Scope guard:** This phase changes naming and assertion style only. No fixture-to-helper or helper-to-fixture conversions. No new conftest.py unless a concrete shared fixture emerges naturally.
