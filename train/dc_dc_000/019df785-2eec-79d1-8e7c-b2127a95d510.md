        # Implementation Plan: Phase 7 Per-Project CAS

## Overview
Add a per-project content-addressable store under `<project>/.cas/<sha256>` and wire task produces checks so accepted file artifacts are interned once, then replaced at their declared produces path with a relative symlink to the CAS object. The runtime insertion point remains the produces-check flow in `artagents/core/task/gate.py`, specifically `_run_inline_checks()` around the successful `entry.check.run(artifact_path)` path. The critique does not point to the wrong root cause; it points to two missing edge cases in the same root path: successful checks may still refer to non-regular paths, and attested steps already call `_run_inline_checks()` directly during `_dispatch_attested()` even though `record_dispatch_complete()` returns early for attested decisions.

The revised approach is still the same core design, with two corrections: add an explicit regular-file guard immediately before CAS interning, and make the shared `_run_inline_checks()` helper the only CAS hook so both code-step completion and attested-step approval get identical CAS behavior. The design stays per-project only: CAS root is derived from `decision.project_root / ".cas"`, never from repo root, user home, global cache, database, daemon, network service, or a shared cache.

The scope tension is resolved by following the later explicit implementation requirements: `.gitignore` should be updated for generated `.cas/` directories, and `artagents/structure.py` should be touched only if a relevant per-project directory whitelist actually exists.

## Main Phase

### Step 1: Add the CAS helper module (`artagents/core/task/cas.py`)
**Scope:** Small
1. Implement `cas_path(project_dir, sha256) -> Path` as `Path(project_dir) / ".cas" / sha256`.
2. Implement `intern(project_dir, source_path) -> Path` using stdlib `hashlib.sha256()` with streaming reads.
3. In `intern`, create `<project>/.cas/`, move the source into `.cas/<hash>` when absent, and when present delete the duplicate source file. Preserve idempotency when `source_path` already resolves to the target CAS entry.
4. Implement `link_into_produces(cas_path, target_path)` by unlinking `target_path` and creating a relative symlink from `target_path.parent` to the CAS entry. Ensure the target parent directory exists.
5. Use only stdlib file APIs. Do not add a shared CAS abstraction, dependency, database, or background service.

### Step 2: Extend produces-passed events (`artagents/core/task/events.py`)
**Scope:** Small
1. Update `make_produces_check_passed_event(...)` to accept optional `cas_hash: str | None = None`.
2. Add `cas_hash` only when an artifact was interned. Keep the parameter optional so existing call sites and tests that do not involve file interning can remain compatible.
3. Preserve hash-chained event behavior by building the event payload before `append_event()` computes and stores the event hash.

### Step 3: Intern artifacts inside the shared produces-check helper (`artagents/core/task/gate.py`)
**Scope:** Medium
1. Import the new CAS helper module into `artagents/core/task/gate.py`.
2. In `_run_inline_checks()` near the successful check path, after `result.ok` is true and before appending `produces_check_passed`, verify `artifact_path.is_file()`.
3. If `artifact_path` is not a regular file, append `produces_check_failed` using the same failure handling as a verifier failure, with a clear reason such as `produces artifact is not a regular file: <path>`, then rewind or mark iteration failure exactly as existing failures do. This prevents directory artifacts that pass `file_nonempty` from crashing CAS interning.
4. If it is a regular file, call `intern(decision.project_root, artifact_path)`, then `link_into_produces(cas_entry, artifact_path)`.
5. Append `produces_check_passed` with `cas_hash=cas_entry.name`.
6. Keep `_run_inline_checks()` as the single hook for CAS. Code steps reach it through `record_dispatch_complete()`, and attested steps already reach it through `_dispatch_attested()` immediately after `step_attested` / `item_attested` is appended.
7. Keep cursor behavior unchanged: failures still append `produces_check_failed` and either `cursor_rewind` or `iteration_failed`; successes still advance only after every declared produces entry has a passed event.

### Step 4: Confirm attested produces coverage (`artagents/core/task/gate.py`, tests)
**Scope:** Small
1. Do not add a second attested-only CAS hook in `record_dispatch_complete()`, because attested dispatch currently returns early by design and `_dispatch_attested()` already invokes `_run_inline_checks()` for declared produces.
2. Add a focused test proving an attested step with a semantic file produces check is interned and symlinked through the same `_run_inline_checks()` path.
3. Confirm `record_step_attested()` remains a reserved helper and is not treated as the lifecycle path that runs produces checks.

### Step 5: Keep project mirroring compatible (`artagents/core/project/run.py`)
**Scope:** Small
1. Leave `mirror_hype_artifacts(...)` copying artifacts into task step `produces/` as regular files.
2. Confirm task-attached project runs still write under `step_dir_for(...)` via `prepare_project_run(...)`, so the gate sees mirrored files and interns them during the produces check phase.
3. Touch `artagents/core/project/run.py` only if tests show mirrored artifacts bypass the inline check path or if path handling needs a small compatibility adjustment.

### Step 6: Update repository ignore and structure guardrails (`.gitignore`, `artagents/structure.py`)
**Scope:** Small
1. Add `.gitignore` entries for generated CAS directories, including `**/.cas/` and the explicit requested `*/runs/*/.cas/` pattern if not already covered.
2. Inspect `artagents/structure.py` for a project-local directory whitelist. If none exists, leave it unchanged and document that no structure update was needed.
3. If a relevant whitelist exists, add `.cas/` as a known per-project state directory only. Do not permit or introduce a repo-level/shared CAS directory.

### Step 7: Add focused tests (`tests/test_cas_intern.py`, `tests/test_cas_symlink.py`, `tests/test_cas_per_project.py`)
**Scope:** Medium
1. `tests/test_cas_intern.py`: create a temp project directory, write two files with identical bytes, call `intern()` on both, assert both calls return the same `<project>/.cas/<sha256>`, only one CAS entry exists, the first source moved, the duplicate source removed, and CAS content is unchanged.
2. `tests/test_cas_symlink.py`: follow the task run style in `tests/test_task_inline_checks.py`; create a code step with a `json_file` produces check, write valid JSON to the step produces path, call `record_dispatch_complete()`, assert the produces path is a symlink, resolves under `<project>/.cas/<sha256>`, and the `produces_check_passed` event includes `cas_hash`.
3. Add a non-regular artifact regression test: create a directory at the declared produces path with a check that can otherwise pass, then assert the run records `produces_check_failed` plus the normal rewind/iteration failure behavior rather than raising from CAS internals.
4. Add an attested produces regression test: create an attested step with a semantic `json_file` produces check, write the artifact before approval, run the ack/gate path, and assert the artifact is symlinked into the project-local CAS and the passed event contains `cas_hash`.
5. `tests/test_cas_per_project.py`: create two separate project slugs with identical produced content, run the same helper or flow for each, and assert each project has its own `.cas/<sha256>` entry with no shared parent and no cross-project symlink target.
6. Add one duplicate-content same-project full-flow assertion if cheap: two steps in the same project produce identical content and both symlinks resolve to the same single CAS entry.

### Step 8: Validate incrementally
**Scope:** Small
1. Run targeted tests first: `pytest tests/test_cas_intern.py tests/test_cas_symlink.py tests/test_cas_per_project.py tests/test_task_inline_checks.py`.
2. Run attested lifecycle coverage if the attested test is placed outside the CAS files: `pytest tests/test_lifecycle_ack.py tests/test_task_kernel_attested.py`.
