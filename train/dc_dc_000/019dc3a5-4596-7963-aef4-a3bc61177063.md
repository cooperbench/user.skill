# Implementation Plan: Phase 11 — Code signing, notarization, updater, release infrastructure

## Overview

Phase 11 adds the release pipeline that turns the existing unsigned local Tauri build into a signed, notarized, auto-updating distributable. The unsigned PR build already works in `.github/workflows/test.yml:22-60` (matrix `[macos-14, macos-13]` with `APPLE_SIGNING_IDENTITY: ""`), so this phase must layer release-only artifacts on top without breaking that path.

**Existing state:**
- `app/src-tauri/tauri.conf.json` — has `externalBin` and bundle targets but no `macOS.signingIdentity` block and no `plugins.updater`.
- `app/src-tauri/Cargo.toml` — has `tauri-plugin-shell/fs/notification` and `keyring` but **no** `tauri-plugin-updater`.
- `app/src-tauri/src/main.rs:6-25` — registers shell/fs/notification plugins, no updater plugin and no update commands.
- `app/src-tauri/capabilities/default.json` — grants `shell/fs/notification/event` perms but no `updater:default`.
- `app/package.json:11-19` — `@tauri-apps/plugin-shell/fs/notification` deps; **no** `@tauri-apps/plugin-updater`.
- `Makefile:1-13` — `build-sidecar` and `build-app` targets exist; no `release-local`/`release-signed`.
- `.github/workflows/test.yml:48-50` — already passes `APPLE_SIGNING_IDENTITY: ""` for PR builds (Step 56 already largely done; we'll add a guard test).
- `docs/` — only contains `expansion-design.md` and `SKILL.md`. **No** `RELEASING.md`.
- No `entitlements.plist`, no `release.yml`, no `latest.json` builder script.

**Constraint:** existing `make build-app` and `pnpm tauri build` (with `APPLE_SIGNING_IDENTITY=""`) must keep producing an unsigned `.app`/`.dmg` after these changes. That means signing config in `tauri.conf.json` must be conditional/empty-string-tolerant, and the updater plugin must not block startup if no `pubkey` is configured (or the dev pubkey must be a benign placeholder).

## Main Phase

### Step 1: Document release process (`docs/RELEASING.md`)
**Scope:** Small
1. **Create** `docs/RELEASING.md` covering: (a) one-time Apple Developer enrollment + Developer ID Application certificate export (`.p12`), (b) App Store Connect API key creation (`.p8`, Key ID, Issuer ID, Team ID), (c) Tauri ed25519 updater key generation via `pnpm -C app tauri signer generate -w ~/.tauri/dataclaw.key`, (d) base64-encoding the `.p12` and `.p8` for GitHub Secrets, (e) the full secrets schema (table below), (f) tagging (`git tag v0.4.0 && git push --tags`) → workflow flow, (g) updater key rotation steps.
2. **Secrets table:** `APPLE_DEVELOPER_ID_CERT_P12_BASE64`, `APPLE_DEVELOPER_ID_CERT_PASSWORD`, `APPLE_API_KEY_P8_BASE64`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER`, `APPLE_TEAM_ID`, `APPLE_SIGNING_IDENTITY` (e.g. `Developer ID Application: ACME Inc (TEAMID)`), `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
3. **Note** that `APPLE_SIGNING_IDENTITY` is the documented Tauri 2 env name — do not introduce a custom indirection.

### Step 2: Add hardened-runtime entitlements (`app/src-tauri/entitlements.plist`)
**Scope:** Small
1. **Create** `app/src-tauri/entitlements.plist` with hardened-runtime defaults: `com.apple.security.cs.allow-jit=false`, `com.apple.security.cs.allow-unsigned-executable-memory=false`, `com.apple.security.cs.disable-library-validation=false`, `com.apple.security.cs.allow-dyld-environment-variables=false`. Include a top-of-file comment noting that `disable-library-validation=true` should only be flipped if the bundled PyInstaller sidecar fails to load shared libraries (and document the why inline if so).

### Step 3: Wire signing + updater into `tauri.conf.json` (`app/src-tauri/tauri.conf.json`)
**Scope:** Small
1. **Extend** the `bundle` block to add a `macOS` sub-object with `signingIdentity`, `entitlements: "entitlements.plist"`, `hardenedRuntime: true`, `providerShortName`. Use Tauri's documented env interpolation: `"signingIdentity": "${APPLE_SIGNING_IDENTITY-}"` if supported, otherwise rely on Tauri 2's behavior of skipping codesign when the env var is empty (validate this — see Validation step). The empty-string fallback is what keeps `make build-app` working.
2. **Add** a top-level `"plugins"` section with `"updater": { "active": true, "endpoints": ["https://github.com/banodoco/dataclaw/releases/latest/download/latest.json"], "dialog": false, "pubkey": "" }`. The empty `pubkey` is acceptable for unsigned local dev (updater is a no-op without a key); the signed release supplies it via `TAURI_SIGNING_PRIVATE_KEY` at build time, which Tauri injects into the bundle.
3. **Do not** introduce custom env vars beyond the documented Tauri/Apple ones.

### Step 4: Add `tauri-plugin-updater` Rust dep + frontend dep (`app/src-tauri/Cargo.toml`, `app/package.json`)

### Step 5: Wire updater into Tauri runtime (`app/src-tauri/src/main.rs`, `app/src-tauri/src/lib.rs`, new `app/src-tauri/src/updater.rs`)
**Scope:** Medium

   - `check_for_updates(app: tauri::AppHandle) -> Result<Option<UpdateInfo>, String>` — calls `app.updater()?.check().await` and returns `{version, body, date}` if an update is available.
   - `install_update(app: tauri::AppHandle) -> Result<(), String>` — calls `update.download_and_install(...).await` then `app.restart()`.
   ```rust
   use tauri_plugin_updater::UpdaterExt;
   #[tauri::command]
   async fn check_for_updates(app: tauri::AppHandle) -> Result<Option<serde_json::Value>, String> { ... }
   ```
