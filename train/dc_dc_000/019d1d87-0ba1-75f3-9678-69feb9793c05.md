The track scale and clip positioning are fighting each other. CORRECT MENTAL MODEL: Track settings are DEFAULTS that clips inherit. Clip-level settings OVERRIDE track settings, they don't stack on top. Specifically: 1. SCALE: Track scale=0.95 means 'by default, show clips at 95% zoom'. If a clip has its own scale/size override, use THAT instead, not track_scale * clip_scale. The clip override replaces the track default. 2. POSITION: Track scale affects where content appears (centered, scaled down). But if a clip has x/y set, those coordinates should be in the full composition space (1280x720), and the clip should render at those absolute coordinates regardless of track scale. 3. FIT: Track fit=contain means 'by default, letterbox clips'. If a clip has explicit width/height, use those instead. The key insight: track settings define the DEFAULT rendering for clips that have no overrides. Once a clip has ANY position/size override, it should render in absolute composition space, completely bypassing track scale/fit. IMPLEMENTATION: The current approach in TimelineRenderer.tsx wraps ALL clips in a div with transform:scale(trackScale). This is wrong because it scales even overridden clips. Instead: - Clips WITHOUT overrides: render inside the scaled track wrapper (inheriting track defaults) - Clips WITH overrides: render in absolute composition space, bypassing the track wrapper entirely The OverlayEditor canvas interaction should always work in composition space (1280x720). ALSO FIX: The overlay drag box alignment - it needs to correctly show where the clip IS (accounting for track scale for non-overridden clips) and where it WILL BE (in composition space for overridden clips).
