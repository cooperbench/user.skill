## Overview
ArtAgents already has strong foundations for two public roles: `conductors` in `artagents/conductors/` and `performers` in `artagents/performers/`. Built-in conductors include `builtin.hype`, `builtin.event_talks`, and `builtin.thumbnail_maker`; built-in performers are generated from `STEP_ORDER`; curated external performers already include Moirae and VibeComfy via folder manifests. The missing piece is a first-class `elements` domain that formalizes existing Remotion primitives (`effects`, `animations`, `transitions`) and makes onboarding/alias discoverability obvious.

The simplest durable approach is to keep conductors and performers as the canonical runtime model, add aliases only at CLI/docs/discovery boundaries, and build `elements` as a sibling registry with the same folder-manifest style as performers/conductors. Avoid changing performer internals: VibeComfy remains an external performer package exposing ArtAgents metadata at its public manifest/API boundary.
