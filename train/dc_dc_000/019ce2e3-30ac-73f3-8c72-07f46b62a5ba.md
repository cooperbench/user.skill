 Context

 The triage workflow has multiple independent state representations that drift apart, causing contradictory UX. The disposition map
 (just implemented) fixed observe/reflect state unification, but broader issues remain:

 1. Stage progression has two sources of truth: TRIAGE_STAGE_DEPENDENCIES (playbook.py, presence-only) vs _STAGE_PREREQUISITES
 (stage_policy.py, with require_confirmation). Display shows organize as "current" but enrich command requires confirmed organize —
 users see a stage marked current that they can't actually run.
 2. Three independent coverage counters: plan_aware_queue_breakdown(), triage_coverage(), undispositioned_triage_issue_ids() each walk
  plan state independently with different inclusion rules.
 3. Mid-cycle "new issues" confusion: compute_new_issue_ids() compares against triaged_ids (set at triage completion), not
 active_triage_issue_ids (set at triage start). Issues frozen into the active cycle still appear as "N new review issues not yet
 triaged."
 4. Queue messaging divergence: plan, next, guardrails, and triage_phase_banner() each independently derive their view of triage
 state.

 Goal: One shared snapshot that answers all triage-status questions, one stage-progression policy used by both display and commands,
 and corrected new-issue detection.
