## Overview

**Goal.** Replace the rigid Phase A / Phase B agent loop with a single adaptive orchestrator driven by a small, model‑visible **TurnPlan**. A TurnPlan is an ordered checklist of steps drawn from a closed vocabulary (`orient`, `read`, `consult`, `respond`, `record`, `schedule`, `done`). The runner picks a default *skeleton* per trigger (quick / standard / charged / crisis / silence), injects step‑local instructions only when that step is active, and lets the agent revise the plan via an in‑memory `update_turn_plan` tool. Read‑before‑write and outbound safety stay intact, enforced at the tool dispatcher rather than by a phase split.

**Current shape.**
- `app/services/agentic.py:611` — `_run_agentic` makes two `run_phase` calls (Phase A read+respond with `read_phase_tools`; Phase B write‑only with `write_phase_tools`). Phase B seed re‑sends the conversation plus a "you sent X" recap (`app/services/agentic.py:766–782`).
