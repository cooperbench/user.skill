   - Append to result
  4. Return combined result (non-cluster items + cluster meta-items)

**Queue Building Flow** (lines 254-364, `build_work_queue()`):
1. Build finding items from state findings
2. Build subjective items from dimensions (calls `build_subjective_items()`)
3. Apply living plan ordering via `_apply_plan_order()`
   - Reorder per `queue_order`
   - Annotate with plan metadata (description, note, cluster info)
   - Filter to cluster if requested
4. **Collapse auto-clusters** (lines 305-313):
   - Only if: `collapse_clusters=True` AND plan provided AND not drilling into cluster
   - Calls `_collapse_clusters(all_items, plan)`
5. Filter by tier/count
6. Return result with items, total, tier_counts, grouped

## **Natural Place for Stale Subjective Dimension Clustering**

Based on the architecture:

1. **Option A: Extend stale_dimensions.py** (Lines 1-6 suggest this is the right module)
   - Add a second sync function: `cluster_stale_subjective_dimensions(plan, state)`
   - Call it **after** `sync_stale_dimensions()` but **before** `auto_cluster_findings()`
   - Would group stale subjective dimensions (currently injected one-by-one) into a single "stale dimensions review" cluster

   - Add special handling for `subjective::*` IDs in `auto_cluster_findings()`
   - Detect when multiple stale subjective IDs should cluster together
   - Group key: `"review::subjective_stale"` or similar
   - Would cluster stale dimensions alongside other review findings

3. **Option C: Pre-clustering in stale_dimensions.py**
   - Before injecting individual stale dimension IDs into `queue_order`
   - Create a cluster for all stale dimensions at once (if ≥2)
   - Inject cluster ID into queue instead of individual dimension IDs
