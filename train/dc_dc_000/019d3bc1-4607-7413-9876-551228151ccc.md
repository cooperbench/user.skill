        Idea:
Build an auto-improve loop for the megaplan+hermes SWE-bench pipeline. The goal: iteratively run experiments, analyze failures, implement generalized improvements, and track everything via git worktrees on GitHub.

Architecture — 3 simple processes that compose:

1. **run_experiment.py** — Launches N workers on a fixed set of 20 SWE-bench tasks with the current code. Writes predictions to a results dir. Simple wrapper around existing parallel.py.

2. **score_experiment.py** — Watches for predictions and scores them (the watch_scoring.py we just built, or a simpler version). Produces a scores.json with pass/fail per task.

3. **analyze_and_improve.md** — A process doc (checklist) that a Claude Code session runs through after each iteration:
   - Read scores.json, identify failures
   - For each failure, analyze the megaplan audit trail (what went wrong at which stage)
   - Categorize failures into patterns (narrow fix, wrong type, missing scope, etc.)
   - Write findings to iterations/NNN/analysis.md
   - Propose generalized improvements (NOT task-specific hacks)
   - Implement changes to megaplan prompts/code
   - Commit to a new git worktree branch (auto-improve/iteration-NNN)
   - Push to GitHub

Key design constraints:
- Same model (GLM-5.1) and same 20 tasks across iterations (to measure improvement)
- Each iteration = a git worktree branch with all code + results, so you can jump back to the best one
- Changes must be general (prompt improvements, workflow changes) — constraint: no task-specific patches
- A FINDINGS.md accumulates learnings across iterations (like autoresearch's program.md)
- Keep it dead simple — the loop should be runnable by a single Claude Code session doing: run experiment → wait → score → analyze → improve → commit → next iteration
- The 20 tasks should be a representative sample (mix of django, sympy, astropy, requests)

This should live in auto_improve/ directory in hermes-agent.

        Idea:
Build an auto-improve loop for the megaplan+hermes SWE-bench pipeline. The goal: iteratively run experiments, analyze failures, implement generalized improvements, and track everything via git worktrees on GitHub.

Architecture — 3 simple processes that compose:

1. **run_experiment.py** — Launches N workers on a fixed set of 20 SWE-bench tasks with the current code. Writes predictions to a results dir. Simple wrapper around existing parallel.py.

2. **score_experiment.py** — Watches for predictions and scores them (the watch_scoring.py we just built, or a simpler version). Produces a scores.json with pass/fail per task.

3. **analyze_and_improve.md** — A process doc (checklist) that a Claude Code session runs through after each iteration:
   - Read scores.json, identify failures
   - For each failure, analyze the megaplan audit trail (what went wrong at which stage)
   - Categorize failures into patterns (narrow fix, wrong type, missing scope, etc.)
   - Write findings to iterations/NNN/analysis.md
   - Propose generalized improvements (NOT task-specific hacks)
   - Implement changes to megaplan prompts/code
   - Commit to a new git worktree branch (auto-improve/iteration-NNN)
   - Push to GitHub

Key design constraints:
- Same model (GLM-5.1) and same 20 tasks across iterations (to measure improvement)
- Each iteration = a git worktree branch with all code + results, so you can jump back to the best one
- Changes must be general (prompt improvements, workflow changes) — constraint: no task-specific patches
- A FINDINGS.md accumulates learnings across iterations (like autoresearch's program.md)
- Keep it dead simple — the loop should be runnable by a single Claude Code session doing: run experiment → wait → score → analyze → improve → commit → next iteration
- The 20 tasks should be a representative sample (mix of django, sympy, astropy, requests)

This should live in auto_improve/ directory in hermes-agent.

Build an auto-improve loop for the megaplan+hermes SWE-bench pipeline. The goal: iteratively run experiments, analyze failures, implement generalized improvements, and track everything via git worktrees on GitHub.

Architecture — 3 simple processes that compose:

1. **run_experiment.py** — Launches N workers on a fixed set of 20 SWE-bench tasks with the current code. Writes predictions to a results dir. Simple wrapper around existing parallel.py.

2. **score_experiment.py** — Watches for predictions and scores them (the watch_scoring.py we just built, or a simpler version). Produces a scores.json with pass/fail per task.

3. **analyze_and_improve.md** — A process doc (checklist) that a Claude Code session runs through after each iteration:
   - Read scores.json, identify failures
   - For each failure, analyze the megaplan audit trail (what went wrong at which stage)
   - Categorize failures into patterns (narrow fix, wrong type, missing scope, etc.)
   - Write findings to iterations/NNN/analysis.md
   - Propose generalized improvements (NOT task-specific hacks)
   - Implement changes to megaplan prompts/code
   - Commit to a new git worktree branch (auto-improve/iteration-NNN)
   - Push to GitHub

Key design constraints:
- Same model (GLM-5.1) and same 20 tasks across iterations (to measure improvement)
- Each iteration = a git worktree branch with all code + results, so you can jump back to the best one
- Changes must be general (prompt improvements, workflow changes) — constraint: no task-specific patches
- A FINDINGS.md accumulates learnings across iterations (like autoresearch's program.md)
- Keep it dead simple — the loop should be runnable by a single Claude Code session doing: run experiment → wait → score → analyze → improve → commit → next iteration
