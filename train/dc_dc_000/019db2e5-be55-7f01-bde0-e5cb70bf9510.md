        # Implementation Plan: Add `--mode joke` for Film Scene Scripts

## Overview

Add a third top-level mode to megaplan alongside `code` and `doc`: `--mode joke`, scoped to short film-scene scripts whose deliverable is a single prose file at `--output`. The phase graph (prep → plan → critique → revise → gate → execute → review → finalize) is reused end-to-end. The invention is that **critique flips from evaluative to generative**: a new `JOKE_CRITIQUE_CHECKS` registry in `audits/robustness.py` holds chaos-lens personas (absurdist, twist-ending, hyper-specific-detail, genre-swap, subtext-inversion, prop-as-character, bathos, scale-shift, narrator-reveal) that each emit a single generative `FLAG` as a committed proposal. `revise_joke` is load-bearing: it must explicitly license *rejecting* flags that fight a declared "primary criterion" (e.g. "weirdest coherent", "most bathetic"). That primary criterion is set in prep and threaded through plan → critique lenses → revise selection → review scoring, playing the same structural role as doc mode's `output_path` contract at `megaplan/prompts/planning.py:93`.

Shape of the repo we're slotting into:
- Mode is plumbed via `state["config"]["mode"]` and read at ~30 sites (see `rg '"mode"' megaplan/`). The CLI enum is enforced only in `megaplan/cli.py:840` (argparse `choices`); `megaplan/handlers/init.py:46–60` normalizes (`metaplan` → `doc`) and validates `--output`. There is no schema-level mode enum to extend; the brief's reference to `schemas.py:385` was an `evidence_type` enum inside `tiebreaker_researcher.json` — unrelated.
- Mode-specific prompt dispatch lives in `megaplan/prompts/__init__.py:113` (`_resolve_builder`), which today overrides `prep`, `execute`, and `review` for doc. Other phases use universal builders that branch internally (e.g. `prompts/planning.py:91`, `prompts/finalize.py:31`, `prompts/review.py:84`).
- The critique check registry and its `checks_for_robustness(robustness)` selector live in `megaplan/audits/robustness.py:20,139`. Parallel-hermes critique drives each check through `single_check_critique_prompt` (`megaplan/prompts/critique.py:354`) via `megaplan/parallel_critique.py:_run_check`. Sequential critique uses `_critique_prompt` which also calls `checks_for_robustness`.
- Execute schema for doc is derived from code-mode by `_build_execution_doc_schema` (`megaplan/schemas.py:608–626`) and registered as `execution_doc.json`. `get_execution_schema_key(mode)` at `schemas.py:629` picks the schema by mode. Joke mode will reuse `execution_doc.json` (single-file output, `sections_written` fits scene beat IDs).
- Evaluation branch: `megaplan/evaluation.py:123` switches on mode for execution-evidence validation; joke should use the doc path (single output file, no git diff).

Constraints that matter:
- Do not fork parallel-critique infrastructure. The instruction in the brief is explicit: plug joke lenses into existing `single_check_critique_prompt` machinery.
- `revise` is shared; adding a mode branch at the prompt level is the right lever rather than a second revise driver.
- Data parity with doc mode on artifacts (state.json schema, finalize.json shape, execution_checkpoint.json path) so list/status/audit tooling keeps working without per-mode branches.
- Do not touch short-form piece ideas (tweets, one-liners). Defer.
