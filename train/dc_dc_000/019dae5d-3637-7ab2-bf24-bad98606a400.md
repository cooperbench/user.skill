## Overview

Goal: introduce a new `megaplan/cloud/` subpackage that generalises the working-but-hardcoded Railway deployment at `~/Documents/reigh-megaplan-dev/` into a reusable, spec-driven cloud runner exposed through the existing `megaplan` CLI. Sprint 1 ships only the Railway provider; the abstraction is built so sprint 2 can drop in fly/ssh/local providers without churn.

Repo shape (relevant): the `megaplan` package uses argparse subcommands wired in `megaplan/cli.py` (`build_parser`, `cli.py:826`), with multi-action subcommands defined per-module via `build_<X>_parser(subparsers)` + `run_<X>_cli(root, args)` (see `megaplan/chain.py:528` and dispatch at `megaplan/cli.py:1133-1138`). Package data is loaded with `importlib.resources.files("megaplan")` (`megaplan/cli.py:600`). PyYAML is already a runtime dependency (`pyproject.toml:22`). `.gitignore` lists `__pycache__/`, `.megaplan/`, `dist/`, `*.egg-info/`, `activity-summary-*.md`.

Hard contracts the plan must respect (verified against the codebase):
- **Remote command name**: container installs `megaplan` globally (reigh `Dockerfile:61-63`); use bare `megaplan ...`, NOT `./.venv/bin/python -m megaplan`.
- **Config namespace**: `megaplan config set` only accepts `agents.<step>` validated against `DEFAULT_AGENT_ROUTING` (`cli.py:758-777`, `types.py:296-309`).
- **`next_step` translation**: `megaplan/auto.py:128-136` (`_phase_command`) is the canonical translator; `cloud resume` reuses it.
- **Active-plan resolution**: `handle_status` (`cli.py:353-367`) auto-resolves when `args.plan is None`; cloud passes `--plan` through if supplied, omits otherwise.
- **Railway service/session targeting**: every railway invocation includes `--service <service>`; ssh/attach include `--session <session>`.
- **Workspace path is data**: `repo.workspace` carries the container checkout path; templates and remote commands read from it.
- **Volume teardown is part of `destroy`**: `Provider.destroy(*, volume=None)` honors a configured volume.
- **`megaplan auto` requires `--plan <name>`** (`auto.py:489`): mode=auto needs an explicit plan name in the spec OR the entrypoint must bootstrap one via `megaplan init` first.
- **No dead knobs**: `railway.project` wires to `railway link --project <project>` at deploy time when set.
- **Docker build context is the staged deploy dir**, not the repo root: the Dockerfile's `COPY` paths must match what `materialize_deploy_dir()` actually writes into the staging dir.

Other constraints:
- Sprint 1 must be independently shippable.
- Idempotency contract preserved (clone-if-missing, codex config always overwritten, megaplan always upgraded).
- Codex `sandbox_mode = "danger-full-access"` retained with explanatory comment.
- `MEGAPLAN_REF` pin surfaced as `megaplan.ref` (default `main`).
