        # Implementation Plan: Timeline Media Selection Context for Agent Tasks

## Overview

When users select media clips (images/videos) on the timeline and interact with the timeline agent, the selected items should be shown as context in the agent chat UI and their asset URLs sent alongside the task payload.

**Current state:** Selection (`selectedClipIds`) is managed by `useMultiSelect` and exposed via `TimelineEditorContext`. `AgentChat` is rendered inside this context tree, so it can access selection state. The agent edge function (`ai-timeline-agent`) currently receives only `session_id` and `user_message` — no selection context. The system prompt includes a full timeline summary but no concept of "selected clips."

**Key constraint:** Only image and video clips qualify — not audio tracks, text, effects, or holds. Filtering uses `AssetRegistryEntry.type` (e.g., `image/png`, `video/mp4`).

## Phase 1: Frontend — Selection Context in Agent Chat

### Step 1: Create a helper to resolve selected media clips (`src/tools/video-editor/hooks/useSelectedMediaClips.ts`)
**Scope:** Small
1. **Create** a new hook `useSelectedMediaClips()` that:
   - Reads `selectedClipIds` and `resolvedConfig` (or `data`) from `useTimelineEditorContext()`
   - Filters to only clips where `clipType` is `'media'` (or undefined, which defaults to media) AND the asset registry entry's `type` starts with `'image/'` or `'video/'`
   - Returns `{ selectedMediaClips: Array<{ clipId: string; assetKey: string; assetUrl: string; mediaType: 'image' | 'video' }>; summary: string }` where `summary` is e.g. "2 images selected" or "1 image and 1 video selected"
2. The hook should be cheap — derive from existing context, no new state.

### Step 2: Show selection context in AgentChat UI (`src/tools/video-editor/components/AgentChat/AgentChat.tsx`)
**Scope:** Medium
1. **Call** `useSelectedMediaClips()` inside `AgentChat` (it's within the `TimelineEditorContext` provider tree — confirmed via `VideoEditorProvider.tsx:45`).
2. **Render** a selection context badge/pill above the input bar (around line 370, before the input `div`). Show the summary text (e.g., "2 images selected") with a small dismiss/clear button. Only show when `selectedMediaClips.length > 0`.
3. **Style** consistently with existing UI: use `text-xs text-muted-foreground` with a subtle `bg-muted/50 rounded-lg px-3 py-1.5` container, matching the existing voice/error banner patterns at lines 371-399.

### Step 3: Pass selection context through `useSendMessage` (`src/tools/video-editor/hooks/useAgentSession.ts`)
**Scope:** Medium
1. **Change** `useSendMessage` signature: the mutation function currently takes `userMessage: string`. Change it to accept an object or add a second parameter for selected clip context. Simplest: change `mutateAsync` call to accept `{ message: string; selectedClipUrls?: string[] }`.
2. **Update** the `invokeAgent` call at line 254 to include `selected_clips` in the request body:
   ```typescript
   body: {
     session_id: sessionId,
     ...(nextUserMessage ? { user_message: nextUserMessage } : {}),
     ...(selectedClipUrls?.length ? { selected_clip_urls: selectedClipUrls } : {}),
   }
   ```
3. **Update** `AgentChat.handleSend` (line 202) to pass the current `selectedMediaClips` URLs when calling `sendMessage.mutateAsync`.
4. Only send clip URLs on the initial message of a conversation turn (when `nextUserMessage` is present), not on auto-continuations.

## Phase 2: Backend — Incorporate Selection in Agent Prompt

### Step 4: Accept `selected_clip_urls` in the edge function (`supabase/functions/ai-timeline-agent/index.ts`, `types.ts`)
**Scope:** Small
1. **Extend** `AgentInvocationBody` in `types.ts:76` to include `selected_clip_urls?: unknown`.
2. **Parse** and validate in `index.ts`: extract as `string[]` (filter to strings only), pass to `runAgentLoop`.

### Step 5: Include selection context in the system prompt (`supabase/functions/ai-timeline-agent/loop.ts`, `prompts.ts`)
**Scope:** Small
1. **Extend** `RunAgentLoopOptions` to include `selectedClipUrls?: string[]`.
2. **Pass** to `buildTimelineAgentSystemPrompt` at `loop.ts:138`.
3. **Extend** `buildTimelineAgentSystemPrompt` in `prompts.ts` to append a "Selected clips" section when URLs are provided:
   ```
   Selected media (user is referring to these):
   - https://...image1.png
   - https://...video1.mp4
   ```
4. This gives the LLM context about which clips the user is likely referring to in their message.

### Step 6: Match URLs back to clip IDs in the prompt (`supabase/functions/ai-timeline-agent/prompts.ts`)
**Scope:** Small
1. Rather than just listing URLs, cross-reference with the timeline summary to identify clip IDs. The timeline summary already lists clips with their asset keys. Add a line like:
   ```
   User has selected: clip-0 (image, V1 at 0s), clip-2 (video, V1 at 5s)
   ```
2. This is more useful to the agent than raw URLs since it operates on clip IDs.
3. **Alternative simpler approach:** Just pass clip IDs (not URLs) from the frontend, and annotate them in the prompt. This avoids URL-to-clip reverse lookup. The frontend already has clip IDs from `selectedMediaClips`. URLs can be included as supplementary info.

**Decision:** Pass both clip IDs and asset URLs from frontend. The prompt uses clip IDs (which the agent already understands); the URLs are available if the agent needs to reference the actual media.

## Execution Order
1. Step 1 first (new hook, no dependencies)
2. Steps 2-3 together (frontend wiring)
3. Steps 4-5 together (backend wiring)
4. Step 6 last (prompt refinement, depends on steps 4-5)

2. Manual: select non-media clips (text, audio) → verify they are filtered out
3. Manual: submit a message with selection → verify payload includes clip context
4. Manual: verify agent response references selected clips appropriately
