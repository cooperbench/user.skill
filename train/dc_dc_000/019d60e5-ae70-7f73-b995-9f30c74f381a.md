        # Implementation Plan: Audio-Reactive Effects for Video Editor

## Overview
Add an audio analysis layer that extracts frequency/amplitude/beat data from all timeline audio tracks and exposes it to compiled custom effects via a `useAudioReactive()` hook. The hook is injected as a new global into the `new Function()` sandbox in `compileEffect.tsx`, documented in both `effectPromptTemplate.ts` and the edge function's `supabase/functions/ai-generate-effect/templates.ts`, and supported by a new `audio-binding` parameter type. A companion `useAudioParam()` helper is also injected to resolve audio-binding parameter configs into frame-synchronized numeric values. The existing effect wrapping pipeline (`wrapWithEffect`/`wrapWithClipEffects` in `effects/index.tsx`) remains untouched — audio data flows through React context, not props.

**Approach:** Web Audio API for offline analysis (no new Remotion packages). Audio is decoded via `OfflineAudioContext`, the resulting `AudioBuffer` is manually sliced into frame-sized windows for RMS/band-energy computation (no `AnalyserNode` — it doesn't work deterministically in offline contexts). Results are stored in a frame-indexed array. Remotion's `delayRender`/`continueRender` gates rendering until analysis completes.

**Settled decisions from gate review:**
- Audio data flows through React context + `useAudioReactive()` hook, not effect props. `wrapWithEffect`/`wrapWithClipEffects` untouched.
- EffectCreatorPanel preview uses synthetic oscillating audio data only — no real audio file picker for v1.
- Web Audio API only, no new Remotion audio packages.

### Step 2: Create AudioAnalysisProvider context (`src/tools/video-editor/compositions/AudioAnalysisProvider.tsx`)
**Scope:** Large — core audio engine
1. **Define** the `AudioAnalysisData` type:
   ```typescript
   type AudioAnalysisData = {
     frequency: Float32Array;  // raw FFT magnitude bins (e.g. 128)
     amplitude: number;        // 0-1 RMS amplitude
     bass: number;             // 0-1 low-frequency energy (0-250Hz)
     mid: number;              // 0-1 mid-frequency energy (250-4000Hz)
     treble: number;           // 0-1 high-frequency energy (4000Hz+)
     isBeat: boolean;          // beat detected this frame
     beatConfidence: number;   // 0-1 confidence
   };
   ```
2. **Define** `AudioAnalysisContext` holding `AudioAnalysisData[]` (frame-indexed array) plus `ready: boolean`.
3. **Implement** `AudioAnalysisProvider` component:
   - Props: `clips: ResolvedTimelineClip[]` (audio clips), `fps: number`, `totalDurationInFrames: number`, `children`.
   - **Render-gating:** Calls `delayRender()` from Remotion on mount. Calls `continueRender(handle)` once analysis is complete (or immediately if no audio clips). Calls `cancelRender(handle)` on unmount if still pending. This prevents the Player/renderer from rendering frames before audio data is available.
   - **Audio pipeline (no AnalyserNode):**
     a. Fetch each audio source URL via `fetch()` + `audioContext.decodeAudioData()`.
     b. Create an `OfflineAudioContext` with `totalDurationInFrames / fps` seconds duration, 1 channel, sample rate 44100.
     c. For each audio clip: create a `BufferSourceNode`, apply trim (`clip.from`), playback rate (`clip.speed`), and volume (`clip.volume` via `GainNode`). Connect to destination. Schedule `start(clipStartSeconds, trimStartSeconds)`.
     d. Call `offlineCtx.startRendering()` to get the mixed-down `AudioBuffer`.
     e. **Manual per-frame analysis:** Slice the rendered buffer into frame-sized windows (`sampleRate / fps` samples per frame). For each window:
        - Compute RMS amplitude (square root of mean squared samples).
        - Compute band energies by running a simple DFT or using pre-computed frequency bin ranges on the window samples. Bass = energy in bins 0-250Hz, mid = 250-4kHz, treble = 4kHz+.
        - For FFT: implement a small radix-2 FFT on each window (window size = nearest power of 2 ≤ samples-per-frame, e.g. 512 or 1024 at 44.1kHz/30fps ≈ 1470 samples → 1024-point FFT). Store magnitude spectrum as `frequency` array.
        - Beat detection: track rolling average of bass energy; flag `isBeat` when current bass exceeds 1.5× rolling average with ≥300ms cooldown.
     f. Store results in `AudioAnalysisData[]` indexed by frame number.
   - **No-audio fast path:** When `clips` is empty, provide a static silent `AudioAnalysisData` for all frames and call `continueRender` immediately.
4. **Export** `useAudioAnalysisContext()` — the internal context consumer.
5. **Export** `SILENT_AUDIO_DATA` constant for use in the hook's fallback path.

### Step 3: Create `useAudioReactive` hook and `useAudioParam` helper (`src/tools/video-editor/effects/useAudioReactive.ts`)
**Scope:** Small
1. **`useAudioReactive()`:**
   - Calls `useCurrentFrame()` from Remotion.
   - Reads from `AudioAnalysisContext` via `useContext()` with a null default (not `useAudioAnalysisContext()` which would throw).
   - Returns `AudioAnalysisData` for the current frame, or `SILENT_AUDIO_DATA` if context is null. This graceful fallback means the hook works outside the provider (e.g. in tests, in preview without audio).
2. **`useAudioParam(binding)`:**
   - Takes an `AudioBindingValue` object (or `undefined`/`null`).
   - Calls `useAudioReactive()` internally.
   - Returns a number: `interpolate(audio[binding.source], [0, 1], [binding.min, binding.max])`.
   - Returns `0` if binding is falsy.
   - This is the **runtime resolution path** for `audio-binding` parameters — effects receive the `AudioBindingValue` config in `params` and call `useAudioParam(params.myParam)` to get a frame-synchronized number.
3. **Export** both as named exports for injection into `compileEffect.tsx`.
