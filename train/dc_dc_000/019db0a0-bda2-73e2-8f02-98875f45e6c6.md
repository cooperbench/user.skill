### Sprint 2 deliverables

Core megaplan additions (must work locally without any cloud dependency):
1. megaplan chain start --spec <path> — validate spec, resolve referenced idea files, kick auto-loop per milestone. Replaces the 'init + auto' pair for chain runs.
2. megaplan chain status --spec <path> — read chain_state.json, pretty-print current_milestone, completed, remaining, per-milestone status. Unit tests against synthetic chain states.
3. megaplan init --idea-file <path> with optional --auto-start flag — read idea from a file instead of the positional CLI arg.

Cloud additions (thin wrappers over the new core commands):
4. megaplan cloud chain <spec.yaml> — upload spec, then cloud exec to call megaplan chain start remotely.
5. megaplan cloud bootstrap <idea-file> — upload idea file, then cloud exec to call megaplan init --idea-file --auto-start remotely.
6. megaplan cloud status --chain — fetch remote chain_state.json, invoke the core chain-status formatter on it. Do NOT reinvent the parser.

New providers:
7. Local provider (docker compose) — fastest iteration target, no Railway/cloud dependency. Becomes the CI-friendly smoke-test target.
8. SSH provider (plain docker-over-ssh) — 'any host with docker + ssh access' story.

Toolchain extensibility:
9. toolchains: block in cloud.yaml — declares one or more toolchains (rust, go, java, or custom with user-provided install snippet). Template renderer appends corresponding Dockerfile stages. Without this, the image is Python/Node only.

Hardening + retirement:
