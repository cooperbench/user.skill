# Queue Lifecycle, Phase Inference, and Post-flight Behavior Summary

This document synthesizes the key code patterns for understanding how desloppify infers phases, manages queue lifecycle, and orchestrates post-flight behavior.

---

## 1. PHASE INFERENCE: "DISCOVER PHASE FROM ITEM PRESENCE" PATTERN

The tool **infers the current phase implicitly from what items are present in the queue**. There is no explicit phase enum or state machine — the phase is discovered by checking item presence in priority order.

### The Lifecycle Filter (desloppify/engine/_work_queue/lifecycle.py)

The function `apply_lifecycle_filter()` is the single source of truth for phase gating. It returns filtered items based on implicit lifecycle rules:

```python
def apply_lifecycle_filter(items: list[WorkQueueItem]) -> list[WorkQueueItem]:
    """Enforce lifecycle visibility rules."""
    # Phase 1: Initial review (unassessed subjective dimensions)
    if _has_initial_reviews(items):
        return [item for item in items 
                if item.get("kind") == "subjective_dimension" 
                and item.get("initial_review")]
    
    # Phase 2: Objective work (mechanical fixes)
    if _has_objective_items(items):
        return [item for item in items 
                if not _is_postflight_phase_item(item) 
                or _is_force_visible(item)]
    
    # Phase 3: Post-flight sequence
    # Explicit ordering: deferred → scan → subjective review → workflow → triage
    if _has_deferred_disposition(items):
        return [item for item in items 
                if _is_deferred_disposition(item) or _is_force_visible(item)]
    
    if _has_postflight_scan(items):
        return [item for item in items 
                if _is_postflight_scan(item) or _is_force_visible(item)]
    
    if _has_postflight_non_objective_items(items):
        return [item for item in items 
                if _is_postflight_non_objective_item(item) or _is_force_visible(item)]
    
    if _has_postflight_workflow(items):
        return [item for item in items 
                if _is_postflight_workflow(item) or _is_force_visible(item)]
    
    if _has_triage_stages(items):
        return [item for item in items 
                if _is_triage_stage(item) or _is_force_visible(item)]
    
    return items  # All items visible (end of cycle or no plan)
```

**Key insight:** The phase is inferred by **checking for presence of certain item types**, NOT by storing an explicit phase enum. This is pure discovery-based classification.

## 2. IMPLICIT PHASES DEFINED TODAY

### Phase 1: INITIAL_REVIEW (subjective::* items)
- **Trigger:** Any unassessed subjective dimension (`initial_review=True`)
- **Purpose:** Users must assess each dimension before mechanical work starts
- **Gating:** Blocks all non-subjective items
- **Item kind:** `"subjective_dimension"` with `initial_review: True`

### Phase 2: OBJECTIVE (mechanical work)
- **Trigger:** Any issue with detector NOT in `NON_OBJECTIVE_DETECTORS`
- **Purpose:** Execute mechanical fixes (auto_fix, quick_fix, judgment, major_refactor)
- **Gating:** Blocks post-flight items
- **Item kinds:** `"issue"`, `"cluster"` (containing non-subjective issues)
- **Detectors excluded (non-objective):**
  ```python
  NON_OBJECTIVE_DETECTORS = {
      "review",           # assessment results (holistic + dimension-specific)
      "concerns",         # tool artifacts for review context
      "subjective_review",# deprecated alias
      "subjective_assessment",  # internal enum
  }
  ```

### Phase 3: POST-FLIGHT (after objective work drained)
Explicit sequence: **deferred → scan → subjective review → workflow → triage**

#### 3a. DEFERRED_BACKLOG_DISPOSITION
- **Item ID:** `"workflow::deferred-disposition"`
- **Trigger:** `plan.skipped` contains any `"temporary"` skip entries
- **Purpose:** Surface deferred work (temporarily skipped during plan) for final disposition
- **Decision:** Reactivate or mark permanent (wontfix)
- **Gating:** Must be resolved before scan runs

#### 3b. POSTFLIGHT_SCAN
- **Item ID:** `"workflow::run-scan"`
- **Trigger:** Lifecycle state tracks `refresh_state.postflight_scan_completed_at_scan_count`
- **Purpose:** Refresh queue after objective work completes, surface follow-up work
- **Gating:** Must complete before subjective review surfaces
- **Marker:** Stored in `plan.refresh_state["postflight_scan_completed_at_scan_count"]`

#### 3c. SUBJECTIVE_REVIEW (non-initial)
- **Item kind:** `"subjective_dimension"` with `initial_review: False`
- **Trigger:** Any dimension below target score OR stale (needs re-review)
- **Purpose:** Re-assess dimensions to improve dimension scores
- **Gating:** Only surfaces after objective work drained
- **Detectors:** "review" issues grouped by dimension

#### 3d. WORKFLOW_ACTIONS (generic workflow steps)
- **Item IDs:**
  - `"workflow::score-checkpoint"` — show current strict score vs plan-start
  - `"workflow::import-scores"` — import assessment results with attestation
  - `"workflow::communicate-score"` — notify user of final score
  - `"workflow::create-plan"` — trigger triage if needed
- **Purpose:** Coordination, attestation, communication
- **Gating:** Can overlap with triage, but score-checkpoint usually before triage

#### 3e. TRIAGE_STAGES (epic-level planning)
- **Item IDs:** `"triage::observe"`, `"triage::reflect"`, `"triage::organize"`, `"triage::enrich"`, `"triage::sense-check"`, `"triage::commit"`
- **Trigger:** `plan.queue_order` contains any `triage::*` ID
- **Purpose:** Cluster and plan review issues using multi-stage triage
- **Dependencies:** Each stage blocks downstream stages until confirmed
- **Marker:** `plan.epic_triage_meta.triage_stages[stage_name].confirmed_at`
