### Step 2: Add the `wf.node(...)` typed authoring wrapper (`vibecomfy/workflow.py`)
**Scope:** Small

1. **Add** a private helper class `_NodeBuilder` (in `vibecomfy/workflow.py`) holding a back-ref to the `VibeNode` it just produced, exposing `id` (the node id) and `out(name_or_index: str | int = 0) -> Handle`. `out()` returns `Handle(node_id=self._node.id, output_slot=name_or_index, output_type=None, name=None)`.
2. **Add** `VibeWorkflow.node(self, class_type: str, **kwargs: Any) -> _NodeBuilder` immediately after `add_node` (`vibecomfy/workflow.py:122-126`). It accepts the same `**kwargs` shape as `add_node` PLUS `Handle` values: any kwarg whose value is a `Handle` is wired as an edge instead of a literal input, mirroring how `_utils.connect` does it today (`vibecomfy/blocks/_utils.py:36-47`). Concrete logic:
   ```python
   def node(self, class_type: str, **kwargs: Any) -> "_NodeBuilder":
       handle_kwargs = {k: v for k, v in kwargs.items() if isinstance(v, Handle)}
       literal_kwargs = {k: v for k, v in kwargs.items() if not isinstance(v, Handle)}
       node = self.add_node(class_type, **literal_kwargs)
       for input_name, h in handle_kwargs.items():
           self.connect(str(h), f"{node.id}.{input_name}")
       return _NodeBuilder(self, node)
   ```
3. **Document** `_NodeBuilder` as the canonical authoring entry point per the plan's API Concepts (`docs/python_composition_dsl_plan.md:103-114`).
