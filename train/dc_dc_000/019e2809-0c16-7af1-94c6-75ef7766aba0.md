        # Implementation Plan: VibeComfy Workflow Lens, LTX Contract, and Reigh LTX First/Last Parity

## Overview

Build the first vertical slice of the workflow onboarding/parity tooling around the existing LTX 2.3 first/last parity path. The repository already has `VibeWorkflow`, `VibeEdge`, `VibeInput`, `VibeOutput`, `vibecomfy.analysis.graph`, pure-Python ready-template checks, and a manual template at `VibeComfy/ready_templates/video/ltx2_3_lightricks_first_last_parity.py`. The remaining gap is that app-intent validation still lives in ad hoc test helpers and one-off raw compiled API assertions, while `reigh-worker` still routes no-control LTX first/last to `video/ltx2_3_runexx_first_last_frame` in `source/task_handlers/tasks/template_routing.py` and generates Runexx node-id scratchpads in `source/models/comfy/vibecomfy_adapter.py`.

The critique flag does not change the root cause or target approach. It shows the validation plan missed an active runtime adapter test file: `reigh-worker/tests/test_vibecomfy_adapter.py` currently asserts the old Runexx template and Runexx node ids for the no-control LTX scratchpad. The implementation must update both scratchpad-focused tests and adapter-level tests, and the targeted gate must run both, otherwise the route migration can leave stale failures behind.

The simplest implementation is still not a broad workflow schema or full CLI family. Start with a thin reusable lens over `VibeWorkflow`, one focused LTX first/last two-stage contract, a small discoverable `vibecomfy workflows lens` / `vibecomfy workflows contract-validate` surface, then migrate the no-control LTX first/last route and live-test matrix to `video/ltx2_3_lightricks_first_last_parity`. Keep raw-video guide and IC-LoRA control routes on their current dedicated templates.

## Phase 1: Semantic Lens Foundation

### Step 1: Add a thin lens package (`VibeComfy/vibecomfy/lens/`)
**Scope:** Medium
1. **Create** `vibecomfy/lens/__init__.py` and `vibecomfy/lens/graph.py` with `WorkflowLens` built directly on `VibeWorkflow.nodes`, `VibeWorkflow.edges`, `workflow.inputs`, and `workflow.outputs`.
2. **Implement** reusable queries: `edge_source(to_node, to_input)`, `edge_targets(from_node, from_output=None)`, `registered_input_target(name)`, `upstream(node_id, depth=None)`, `downstream(node_id, depth=None)`, `output_nodes()`, `node_value(node_id, field)`, and `diagnostic(...)` helpers.
3. **Reuse** existing traversal logic from `vibecomfy.analysis.graph` where possible, but keep the lens object ergonomic for tests and contracts.
4. **Return** small typed dataclasses or frozen records for sources/targets instead of raw tuples so diagnostics can name node id, class type, field, and output slot.

### Step 2: Test lens behavior (`VibeComfy/tests/test_workflow_lens.py`)
**Scope:** Small
1. **Add** focused unit tests using a tiny authored `VibeWorkflow` that covers edge source, multiple edge targets, registered input lookup, upstream/downstream traversal, and output discovery.
2. **Add** one ready-template smoke against `video/ltx2_3_lightricks_first_last_parity` to prove the lens can express the first-frame and last-frame conditioning path without compiling API JSON.

## Phase 2: Focused Contract Layer

### Step 3: Add contract primitives (`VibeComfy/vibecomfy/contracts/base.py`)
**Scope:** Medium
1. **Create** `vibecomfy/contracts/__init__.py` and `vibecomfy/contracts/base.py` with `ContractIssue`, `ContractReport`, and a base validator helper that accumulates clear `code`, `severity`, `message`, and `detail` fields.
2. **Make** contracts callable from tests and CLI with `validate(workflow) -> ContractReport` and `raise_for_errors()` optional sugar.
3. **Use** `ValidationIssue`-compatible fields where practical so contract failures can be rendered next to existing schema/source-purity failures.

### Step 4: Implement the LTX two-stage first/last contract (`VibeComfy/vibecomfy/contracts/ltx.py`)
**Scope:** Medium
1. **Implement** `LTXFirstLastTwoStageContract` for the existing official-spine parity template.
2. **Validate** required named inputs: `start_image`, `end_image`, `prompt`, `negative`, `seed`, `stage2_seed`, `width`, `height`, `frames`, `fps`, `first_frame_strength`, and `last_frame_strength`.
3. **Validate** semantic graph intent through `WorkflowLens`: start image feeds stage-1 `LTXVImgToVideoConditionOnly`, end image feeds stage-2 `LTXVImgToVideoConditionOnly`, prompt/negative feed `LTXVConditioning` and both guiders, seeds feed both samplers, dimensions/frames/FPS feed latent/video/audio path, and at least one video output is materialized.
4. **Validate** parity-sensitive constants: stage-2 sigmas equal `0.909375, 0.725, 0.421875, 0.0`; first/last strengths default to `1.0`; custom nodes include `ComfyUI-KJNodes` and `ComfyUI-LTXVideo`; incompatible Runexx-only packs such as `rgthree-comfy` are absent for this no-control path.
5. **Keep** the contract route-focused and configurable by node classes/input names; do not create a universal workflow schema.

### Step 5: Replace brittle LTX test assertions (`VibeComfy/tests/test_ready_templates.py`)
**Scope:** Small
1. **Rewrite** `test_ltx_lightricks_first_last_parity_exposes_worker_patch_points` to call `LTXFirstLastTwoStageContract().validate(workflow)` and use lens queries for stage input paths.
2. **Leave** compiled API checks only for runtime materialization smoke where necessary, not for app intent.
