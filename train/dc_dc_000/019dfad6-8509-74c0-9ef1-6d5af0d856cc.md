        # Implementation Plan: Sprint 2 Adapter Seam and Local Selector Skeleton

## Overview
The remaining critique does not indicate the root cause is wrong. Backend selection still must happen before WGP-specific conversion and queue pre-validation. It does show that the prior travel-child plan risked expanding beyond Sprint 2 by implying real VibeComfy `travel_segment` execution without preserving travel-specific post-processing and chaining.

This revision narrows travel child scope deliberately. Sprint 2 will wire `travel_segment` and `individual_travel_segment` into the local selector at the real submission point in `source/task_handlers/tasks/task_registry.py`, but production travel child VibeComfy execution remains unsupported/fail-closed. The required child smoke is template-independent: it proves child route derivation and fail-closed behavior before WGP queue submission, so it avoids Wan VACE/cocktail without pretending full travel completion parity exists. Direct VibeComfy execution is limited to `z_image_turbo` and `qwen_image_2512`.

`reigh-worker/` remains the implementation and validation root. External Supabase task contracts stay unchanged. `REIGH_BACKEND=vibecomfy` is the canonical feature flag value; unset or `wgp` preserves current WGP behavior. Explicit VibeComfy selection is strict fail-closed for unsupported routes. The VibeComfy adapter runs across a Python 3.11 subprocess boundary because `reigh-worker` is Python 3.10-constrained while `vibecomfy` requires Python 3.11.

## Phase 1: Routing Foundation

### Step 1: Add backend-neutral routing (`source/task_handlers/tasks/template_routing.py`)
**Scope:** Medium
1. Define route support states: `WGP_ONLY`, `VIBECOMFY_SUPPORTED`, and `VIBECOMFY_UNSUPPORTED`.
2. Add a backend-neutral `ResolvedTask` dataclass with executor-facing fields: `task_id`, `task_type`, `route_key`, `backend`, `support_state`, `template_id`, `model`, `prompt`, `params`, `memory_profile`, and optional `failure_reason`.
3. Add `resolve_task_backend(...)` that accepts raw or already-resolved task context and returns a `ResolvedTask` before any WGP conversion.
4. Implement production-local route derivation in this module, using the same route-key semantics as `scripts/dual_run_compare/route_keys.py` but not importing script/test utilities into worker runtime code.
5. Add the static Sprint 2 selector map:
   - `z_image_turbo` -> `image/z_image`, VibeComfy-supported.
   - `qwen_image_2512` -> `image/qwen_image_2512`, VibeComfy-supported.
   - `travel_segment` and `individual_travel_segment` -> route derivation only, VibeComfy-unsupported for production execution in Sprint 2.
   - `wan_2_2_t2i` -> WGP-only unless the single-frame VibeComfy patch is implemented and tested in this same change.
6. Parse `REIGH_BACKEND` with canonical values: unset/`wgp` means WGP; `vibecomfy` means strict VibeComfy selection. Do not introduce fallback-to-WGP behavior under explicit `vibecomfy`.
7. For travel child routes under `REIGH_BACKEND=vibecomfy`, return `VIBECOMFY_UNSUPPORTED` with a reason that full travel child execution/chaining is out of scope for Sprint 2.

### Step 2: Cover route derivation (`tests/test_template_routing.py`)
**Scope:** Small
1. Prove `z_image_turbo` and `qwen_image_2512` resolve to VibeComfy-supported template IDs under `REIGH_BACKEND=vibecomfy`.
2. Prove unsupported direct routes fail closed with `VIBECOMFY_UNSUPPORTED` and an explicit reason under `REIGH_BACKEND=vibecomfy`.
3. Prove `travel_segment` and `individual_travel_segment` derive stable child route keys from model/guidance context but remain VibeComfy-unsupported for production execution.
4. Prove the template-independent child smoke route avoids Wan VACE/cocktail route keys and does not mark travel execution as supported.
5. Prove `wan_2_2_t2i` remains WGP-only unless the single-frame patch is explicitly added.
6. Prove unset and `REIGH_BACKEND=wgp` preserve WGP routing.

## Phase 2: Direct Executor Seam

### Step 3: Add a direct resolved-task executor (`source/task_handlers/tasks/task_execution.py`)
**Scope:** Medium
1. Add a small executor helper for direct queue tasks that receives a `ResolvedTask`, dispatch context, and a WGP `GenerationTask` builder callback.
2. For `backend == wgp`, call the existing WGP builder and submit to `HeadlessTaskQueue` exactly as today.
3. For `backend == vibecomfy` and `support_state == VIBECOMFY_SUPPORTED`, call the VibeComfy adapter directly and bypass `HeadlessTaskQueue.submit_task()` so `_convert_to_wgp_task()` is not reached.
4. For unsupported VibeComfy routes, return `(False, <explicit unsupported route message>)` without WGP fallback.
5. Keep this helper independent of Supabase schema and claim logic so Sprint 6 can replace only the selector source.

### Step 4: Wire direct queue dispatch (`source/task_handlers/tasks/task_registry.py`)
**Scope:** Medium
1. In `TaskRegistry._handle_direct_queue_task()`, resolve backend before calling `db_task_to_generation_task()`.
2. Preserve current WGP behavior for unset/`wgp`, including `wan_2_2_t2i` `video_length=1`, colour matching, and mask-active params.
3. Under `REIGH_BACKEND=vibecomfy`, route `z_image_turbo` and `qwen_image_2512` through the direct resolved-task executor and adapter.
4. Add tests that monkeypatch the adapter and queue to assert VibeComfy-selected direct routes never submit to the WGP queue.

## Phase 3: Travel Child Selector Seam

### Step 5: Wire travel child fail-closed selection at the real submission point (`source/task_handlers/tasks/task_registry.py`)
**Scope:** Medium
1. Treat `source/task_handlers/travel/segments/segment_queue.py` as wrapper/caller context only. The implementation touch point is `_handle_travel_segment_via_queue_impl()` in `source/task_handlers/tasks/task_registry.py`, where the concrete `GenerationTask(...)` is prepared and `task_queue.submit_task(generation_task)` is called.
2. Resolve backend after the travel child `GenerationTask` has been fully prepared, so routing sees the resolved model, prompt, `_source_task_type`, image refs, guidance, continuation fields, and output directory context actually passed to WGP today.
3. For unset/`wgp`, preserve current travel behavior, including queue submission, wait semantics, SVI latent-tail upload, and `handle_travel_chaining_after_wgp()`.
4. For explicit `REIGH_BACKEND=vibecomfy`, fail closed before `task_queue.submit_task()` for `travel_segment` and `individual_travel_segment` because real travel child VibeComfy execution and post-adapter chaining are out of Sprint 2 scope.
5. Add a template-independent child smoke test that exercises this real seam by proving the child route is derived, the unsupported VibeComfy error is returned, `task_queue.submit_task()` is not called, and Wan VACE/cocktail generation is not entered.
6. Do not add a partial production VibeComfy travel execution path in Sprint 2. If future work wants real LTX child execution, it must add equivalent post-adapter output handling, latent-tail behavior where applicable, and travel chaining semantics.

## Phase 4: VibeComfy Adapter Boundary

### Step 6: Add the Python 3.11 subprocess adapter (`source/models/comfy/vibecomfy_adapter.py`)
**Scope:** Medium
1. Implement `handle_vibecomfy_resolved_task(resolved, main_output_dir_base) -> tuple[bool, str | None]` for supported direct routes only.
2. Use an explicit interpreter boundary. Read `VIBECOMFY_PYTHON` first, then fall back to `python3.11`; never import VibeComfy into worker module import paths.
3. Run the command from the VibeComfy project/install context, configurable with `VIBECOMFY_CWD` or package installation. Tests should monkeypatch subprocess execution rather than requiring local VibeComfy installation.
4. Match the current `vibecomfy run` CLI surface. Do not pass unsupported `--resolution` or `--output-directory` arguments.
5. Pass only supported CLI options for Sprint 2, such as ready template id, prompt, seed, steps, and `build_memory_profile_cli_args()` output where supported.
6. For resolution or other template-specific values not exposed by the current CLI, generate a temporary VibeComfy scratchpad/input file only if the current VibeComfy CLI supports running that file; otherwise leave those fields out of the adapter command and document them as not wired for Sprint 2.
7. Since the current CLI has no output-directory option, run in an isolated per-task working directory or inspect the VibeComfy result/stdout/default output location to discover the produced artifact. Return the resolved artifact path to the existing worker completion flow.
8. Capture stdout/stderr/exit code and return a normal task failure string with backend, template, profile, and error summary.
9. Keep `source/models/comfy/comfy_handler.py` unchanged for raw `task_type == "comfy"` workflow payloads.

### Step 7: Add adapter command tests (`tests/test_vibecomfy_adapter.py`)
**Scope:** Small
1. Assert the adapter uses `VIBECOMFY_PYTHON` or `python3.11`, not the worker interpreter by default.
2. Assert the subprocess command does not include unsupported `--resolution` or `--output-directory` flags.

4. Assert subprocess failures include backend/template/profile/error telemetry in the returned message.
5. Assert output discovery returns a produced artifact path from the isolated run directory or parsed command result.

3. Add automated tests that monkeypatch the logger and assert the key telemetry fields are emitted for successful direct route selection, adapter failure, and travel child fail-closed selection.
4. Do not add Supabase columns or mutate queue payload contracts.

### Step 9: Add direct and child smoke tests (`tests/test_vibecomfy_backend_selection.py`)
**Scope:** Medium
