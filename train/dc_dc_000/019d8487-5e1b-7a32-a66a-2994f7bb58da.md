        # Implementation Plan: Wire useClipResizeGesture hook into TimelineCanvas, replacing inline resize handlers

## Overview

**Goal:** Replace ~325 lines of inline resize handler code in `TimelineCanvas.tsx` (lines 659–984) with the already-implemented `useClipResizeGesture` hook. The hook uses a state machine (`idle` → `pending` → `resizing`) with AbortController-based listener lifecycle, matching the pattern established by the `useClipDrag` refactor.

**Current state:** `useClipResizeGesture.ts` (802 lines) is fully implemented but not wired up. `TimelineCanvas.tsx` still has the old pattern: `useCallback` + manual refs (`resizeSessionRef`, `resizeActivationRef`) + React synthetic event props (`handleResizePointerDown`, `handleResizePointerMove`, `endResize`) passed to `TrackListRenderer`. These props are already absent from `TrackListRenderer`'s TypeScript interface (silently dropped).

**Bugs fixed by this refactor:**
1. **Session leaks** — Old code has no AbortController; if `endResize` is never called, window listeners persist. Hook uses `controller.abort()` for guaranteed cleanup.
2. **Pointer capture races** — Old code sets pointer capture on `activation.target` AND checks `event.currentTarget`, creating double-capture scenarios. Hook uses window-level listeners, no pointer capture at all.
3. **Stale closures** — Old `useCallback` deps include `gestureOwner`, `rows`, `updateResize`, etc. During a gesture, React may re-create these callbacks with new closure values, but the event handlers hold stale references. Hook uses `latestRef` pattern — single `useEffect` with `[dataRef, timelineWrapperRef]` deps, reads current values via `.current`.
4. **GestureOwner lockout** — If `endResize` is never called (pointerId mismatch, element removed), `gestureOwner` stays `'trim'` forever, blocking all other gestures. Hook's `endSession` always releases, plus window `blur` handler catches browser-level session interrupts.
5. **Missing pointercancel handler at window level** — Old code relies on React's `onPointerCancel` on the element, which misses cases where the browser cancels the pointer stream outside the element (e.g., system dialog). Hook adds explicit `window.addEventListener('pointercancel', ...)`.
6. **Missing blur handler** — Tab-away or focus loss leaves old handler in mid-resize with no cleanup. Hook adds `window.addEventListener('blur', handleBlur)`.
7. **Activation state not part of session** — Old code uses separate `resizeActivationRef` that can drift from `resizeSessionRef`. Hook combines them into a single `InternalResizeSession` inside the state machine.
8. **positionedShotGroups stale during gesture** — Old code reads `positionedShotGroups` (a prop) to resolve context, but the memo depends on `resizePreviewSnapshot`, creating circular staleness. Hook's `resolveClipEdgeResizeContext` reads from `shotGroups` directly and derives positioned bounds from `resizePreviewStore.getSnapshot()`.
9. **No automatic cleanup on unmount during active gesture** — Old code's `useCallback`s don't run cleanup. Hook's `useEffect` return calls `endSession({ cancelled: true })` and aborts the effect controller.

**Architecture decision:** Call `useClipResizeGesture` inside `TimelineCanvas.tsx` (not `TimelineEditor.tsx`). Rationale: the resize preview state is consumed locally by `TimelineCanvas` and its children. The hook needs a wrapper ref to scope events — `scrollContainerRef` (the tracks scroll area, already exists) works for this. This keeps the change surface smaller than lifting to the parent.
