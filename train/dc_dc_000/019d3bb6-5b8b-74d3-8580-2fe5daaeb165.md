        # Implementation Plan: Auto-Improve Loop for Megaplan+Hermes

## Overview

Build a self-improving experiment loop in `auto_improve/` that iteratively runs the same 20 SWE-bench tasks, scores them, analyzes failures against megaplan audit trails, proposes generalized improvements, and commits each iteration to a git worktree branch. The loop composes 3 simple processes: run → score → analyze+improve.

**Current state:** The repo already has `evals/parallel.py` (manifest-based N-worker orchestration), `evals/watch_scoring.py` (incremental scoring), `evals/audit.py` (per-phase audit trails), and a prior 20-task GLM-5.1 run at `results/glm51-20tasks/` with the exact task list we'll reuse. The MEGALOOP.md doc describes the philosophy but there's no automated loop implementation yet.

**Key constraint:** Same model (GLM-5.1), same 20 tasks, every iteration. Changes must be general (prompt/workflow), never task-specific hacks.

## Phase 2: Core Scripts

### Step 3: Implement `run_experiment.py` (`auto_improve/run_experiment.py`)
**Scope:** Medium
1. **Write** a thin wrapper around `evals.parallel.run_parallel_workers()`:
   - Takes `--iteration N` (required) and optional `--workers N` (default 3), `--scoring-mode` (default "watch")
   - Reads `base_config.json`, injects `run_name: "auto-improve/iteration-{N:03d}"`, `results_dir`, `evals_to_run` from `tasks.json`
   - Writes the materialized config to a temp file, calls `run_parallel_workers(config_path, eval_names=None, workers=W, scoring_mode=mode)`
   - On completion, copies the watch scores / batch scores to `iterations/{N:03d}/scores.json`
2. **Handle** the config write carefully — `run_parallel_workers` expects a file path, not a dict. Write to `iterations/{N:03d}/config.json` and pass that path.
3. **Return** exit code 0 on success, non-zero on failure. Print summary line (tasks done, pass rate) to stdout.

```python
# Core flow
iteration_dir = Path(f"auto_improve/iterations/{iteration:03d}")
iteration_dir.mkdir(parents=True, exist_ok=True)
config = build_iteration_config(iteration)
config_path = iteration_dir / "config.json"
config_path.write_text(json.dumps(config, indent=2))
result = run_parallel_workers(str(config_path), eval_names=None, workers=workers, scoring_mode=scoring_mode)
```

### Step 4: Implement `score_experiment.py` (`auto_improve/score_experiment.py`)
**Scope:** Small
1. **Write** a script that either:
   - (a) Reads the `_watch_scores.json` from a completed watch-mode run, or
   - (b) Triggers batch scoring on an already-completed run's predictions
2. **Normalize** output to a simple `scores.json`:
   ```json
   {
     "iteration": 1,
     "timestamp": "2026-03-30T...",
     "total": 20,
     "resolved": 8,
     "failed": 11,
     "errors": 1,
     "pass_rate": 0.40,
     "tasks": {
       "django__django-11099": {"resolved": true, "duration_s": 312},
       "django__django-11179": {"resolved": false, "duration_s": 845}
     }
   }
   ```
3. **Takes** `--iteration N` or `--results-dir PATH`. Writes to `iterations/{N:03d}/scores.json`.
4. **Note:** If `run_experiment.py` uses watch mode, scoring happens inline. This script is mainly for re-scoring or normalizing existing results.

### Step 5: Create the analysis process doc (`auto_improve/analyze_and_improve.md`)
**Scope:** Medium
1. **Write** a structured checklist that a Claude Code session follows post-scoring. This is NOT code — it's a process document / prompt. Sections:

   **A. Read scores** — Load `iterations/{N}/scores.json`, compare to previous iteration's scores (if any). Call out regressions and improvements.

   **B. Analyze failures** — For each failed task:
   - Read the audit trail at `results/auto-improve/iteration-{N:03d}/worker-*/{instance_id}/*/summary.json`
   - Identify which megaplan phase failed or produced weak output (plan too vague? execution missed files? review didn't catch the bug?)
   - Note the specific failure mode

   **C. Categorize into patterns** — Group failures:
   - `narrow_fix` — correct diagnosis, patch too narrow (missed related code)
   - `wrong_type` — misidentified the bug type
   - `missing_scope` — didn't explore enough files
   - `execution_error` — correct plan, flawed execution
   - `test_mismatch` — fix works but tests still fail (environment issue)
   - `timeout` — ran out of time
   - Other patterns as discovered

   **D. Write analysis** — Save `iterations/{N}/analysis.md` with: per-task breakdown, pattern summary, comparison to prior iteration.

   **E. Propose improvements** — Based on patterns, propose GENERAL changes to:
   - Megaplan phase prompts (plan, critique, gate, finalize, execute, review)
   - Phase routing logic in `evals/run_evals.py`
   - Tool configurations or constraints
   - Constraint: NO task-specific patches. Every change must help across multiple tasks.

   **F. Implement changes** — Make the code/prompt changes.

   **G. Update FINDINGS.md** — Append iteration summary to `auto_improve/FINDINGS.md`.

   **H. Commit** — Create git worktree branch `auto-improve/iteration-{N:03d}`, commit all changes, push to GitHub.

### Step 6: Create the orchestrator script (`auto_improve/loop.py`)
**Scope:** Medium
1. **Write** a simple orchestrator that a Claude Code session can invoke to run one full iteration:
   ```
   python -m auto_improve.loop --iteration N [--skip-run] [--skip-score] [--skip-analyze]
   ```
2. **Steps:** 
   - Determine current iteration number (scan `iterations/` for highest existing + 1, or use `--iteration`)
   - Run experiment (`run_experiment.py`)
   - Score experiment (`score_experiment.py` or read watch scores)
   - Print scores summary and pause for human/Claude analysis
3. **The analysis step is manual** — the loop.py prints the scores and tells the Claude Code session to follow `analyze_and_improve.md`. This keeps analysis in the Claude Code context where it has access to file reading, code editing, and git operations.
4. **Git worktree management:**
   - Before running: ensure we're on the right branch or create `auto-improve/iteration-{N:03d}` worktree
   - After analysis+changes: commit to the worktree branch, push

## Phase 3: Git Worktree Integration

### Step 7: Add worktree helpers (`auto_improve/worktree.py`)
**Scope:** Small
1. **Write** utilities for:
   - `create_iteration_branch(iteration: int) -> Path` — creates `git worktree add` for branch `auto-improve/iteration-{N:03d}` 
   - `commit_iteration(iteration: int, message: str)` — stages changes in the worktree, commits, pushes
   - `list_iterations()` — returns list of iteration branches with their pass rates from FINDINGS.md
2. **Design decision:** Worktrees are created under `auto_improve/worktrees/iteration-{N:03d}/` (gitignored). Each worktree is a full copy of the repo at that iteration's state.
3. **Alternative (simpler):** Just use regular branches without worktrees — commit iteration changes to `auto-improve/iteration-{N:03d}` branch from main. Worktrees add complexity; branches alone provide the "jump back to best" capability via `git checkout`.

The MEGALOOP.md doc describes the philosophy but there's no automated loop implementation yet.

**Key constraints:**
- Same model (GLM-5.1), same 20 tasks, every iteration. Changes must be general (prompt/workflow), never task-specific hacks.
- **Task set:** Use `REPRESENTATIVE_SAMPLE` from `evals/benchmarks/swe_bench.py:18-50` (5 django, 3 sympy, 2 matplotlib, 2 scikit-learn, 2 pytest, 1 each sphinx/astropy/requests/pylint/xarray/flask) — NOT the prior glm51-20tasks config which was 16/20 Django.
- **Scoring:** Watch mode is the primary scoring path (emits per-task `_watch_scores.json`). `evals/consolidate.py` is the fallback for post-hoc scoring when watch mode wasn't used.
- **Workspace isolation:** Each iteration gets its own workspace dir to prevent cross-contamination from stale repo caches.
- **Iteration branches** commit code changes + a compact `consolidated/` snapshot (per-task scores, costs, patches, audit summaries) — not raw traces, but enough to revisit and compare iterations.

**Settled decisions (from gate):**
- Simple git branches, not worktrees (DECISION-001)
- Analysis executed by Claude Code following a process doc (DECISION-002)
- `auto_improve/` is a new top-level directory (DECISION-004)

## Phase 2: Core Scripts

### Step 3: Implement `run_experiment.py` (`auto_improve/run_experiment.py`)
**Scope:** Medium
1. **Write** a thin wrapper around `evals.parallel.run_parallel_workers()`:
   - Takes `--iteration N` (required) and optional `--workers N` (default 3)
   - Reads `base_config.json`, injects:
     - `run_name: "auto-improve/iteration-{N:03d}"`
     - `evals_to_run` from `tasks.json`
     - `workspace_dir: "evals/workspaces-auto-improve/iteration-{N:03d}"` (per-iteration isolation)
     - `results_dir: "results"`
   - Writes the materialized config to `iterations/{N:03d}/config.json`
   - Calls `run_parallel_workers(config_path, eval_names=None, workers=W, scoring_mode="watch")` — watch mode is hardcoded as the primary scoring path
   - Creates symlink `iterations/{N:03d}/results` → `results/auto-improve/iteration-{N:03d}/`
2. **On completion:** run `evals.consolidate.consolidate(results_root)` to produce the compact `consolidated/` snapshot, then copy it to `iterations/{N:03d}/consolidated/`
3. **Normalize** watch scores into `iterations/{N:03d}/scores.json` with this format:
   ```json
   {
     "iteration": 1,
     "timestamp": "2026-03-30T...",
     "total": 20,
     "resolved": 8,
     "failed": 11,
     "errors": 1,
     "pass_rate": 0.40,
     "tasks": {
       "django__django-11099": {"resolved": true},
       "django__django-11179": {"resolved": false}
     }
   }
   ```
4. **Return** exit code 0 on success, non-zero on failure. Print summary line (tasks done, pass rate) to stdout.

```python
# Core flow
iteration_dir = Path(f"auto_improve/iterations/{iteration:03d}")
iteration_dir.mkdir(parents=True, exist_ok=True)

shutil.copytree(results_root / "consolidated", iteration_dir / "consolidated")

```

### Step 4: Implement `score_experiment.py` (`auto_improve/score_experiment.py`)
**Scope:** Small
1. **Write** a standalone re-scoring/normalization utility for when watch mode wasn't used or scores need to be regenerated:
   - Takes `--iteration N` or `--results-dir PATH`
   - **Primary path:** read `_watch_scores.json` from the results dir, normalize into `scores.json`
   - **Fallback path:** if no watch scores exist, run `evals.consolidate.consolidate()` which mines SWE-bench report.json files from `logs/run_evaluation/` and produces per-task scores
   - Writes to `iterations/{N:03d}/scores.json`
2. **Note:** This script is mainly for re-scoring or normalizing existing results. When `run_experiment.py` completes normally with watch mode, `scores.json` is already produced.

### Step 5: Create the analysis process doc (`auto_improve/analyze_and_improve.md`)
**Scope:** Medium
1. **Write** a structured checklist that a Claude Code session follows post-scoring. This is NOT code — it's a process document / prompt. Sections:

   **A. Read scores and compare** — Load `iterations/{N}/scores.json`. If prior iteration exists, load `iterations/{N-1}/scores.json` and diff: call out regressions (tasks that went from pass→fail), improvements (fail→pass), and stable results.

   **B. Triage failures into two buckets:**
   - **Infrastructure failures** — Check `iterations/{N}/scores.json` for tasks with `"errors"` status. Also check the manifest at `results/auto-improve/iteration-{N:03d}/_task_manifest.json` for tasks with `status: "error"` (these failed before any audit trail was created — e.g., workspace clone races, Docker issues). Check worker summary files `results/.../worker-*/summary_*.json` for error entries. These are NOT megaplan failures — they need infra fixes.
   - **Megaplan failures** — Tasks that ran to completion but produced wrong patches. These are the improvement targets.

   **C. Analyze megaplan failures** — For each failed task:
   - Read the consolidated audit at `iterations/{N}/consolidated/tasks/{instance_id}/audit.json` (phase costs, durations, models)
   - Read the patch at `iterations/{N}/consolidated/tasks/{instance_id}/patch.diff`
   - If deeper analysis needed, read the full audit trail at `results/auto-improve/iteration-{N:03d}/worker-*/{instance_id}/*/summary.json`
   - Identify which megaplan phase failed or produced weak output (plan too vague? execution missed files? review didn't catch the bug?)

   **D. Categorize into patterns** — Group failures:
   - `narrow_fix` — correct diagnosis, patch too narrow (missed related code)
   - `wrong_type` — misidentified the bug type
   - `missing_scope` — didn't explore enough files
   - `execution_error` — correct plan, flawed execution
   - `test_mismatch` — fix works but tests still fail (environment issue)
   - `timeout` — ran out of time
   - `infra_error` — workspace setup / Docker / clone failure
   - Other patterns as discovered

   **E. Write analysis** — Save `iterations/{N}/analysis.md` with: per-task breakdown, pattern summary, comparison to prior iteration.

   **F. Propose improvements** — Based on patterns, propose GENERAL changes to:
   - Megaplan phase prompts (plan, critique, gate, finalize, execute, review)
   - Phase routing logic in `evals/run_evals.py`
   - Tool configurations or constraints
   - Infrastructure robustness (if infra errors dominate)
   - **Constraint: NO task-specific patches.** Every change must help across multiple tasks.

   **G. Implement changes** — Make the code/prompt changes. Write `iterations/{N}/changes.md` summarizing what changed and why.

   **H. Update FINDINGS.md** — Append iteration summary to `auto_improve/FINDINGS.md`: iteration number, pass rate, delta from prior, top patterns, changes made, key learnings.

   **I. Commit and push** — Create branch `auto-improve/iteration-{N:03d}` from current HEAD, commit all changes (code + iteration metadata + consolidated results), push to GitHub.

### Step 6: Create the orchestrator script (`auto_improve/loop.py`)
**Scope:** Medium
1. **Write** a simple orchestrator that a Claude Code session can invoke to run one full iteration:
   ```
   python -m auto_improve.loop --iteration N [--skip-run] [--skip-score]
   ```
2. **Steps:**
   - Determine current iteration number (scan `iterations/` for highest existing + 1, or use `--iteration`)
   - Run experiment via `run_experiment.py` (unless `--skip-run`)
   - Normalize scores via `score_experiment.py` (unless `--skip-score`)
   - Print scores summary table to stdout
   - Print instructions: "Follow auto_improve/analyze_and_improve.md to complete this iteration"
3. **The analysis step is manual** — `loop.py` prints the scores and tells the Claude Code session to follow `analyze_and_improve.md`. This keeps analysis in the Claude Code context where it has access to file reading, code editing, and git operations.
4. **No git worktree management in the script** — branching and committing happen in the analyze step (step I of the process doc), driven by the Claude Code session.
