## Overview

DataClaw today is a Python CLI that discovers coding-agent sessions (`claude`/`codex`/`gemini`/`opencode`/`openclaw`/`kimi`/`custom`), anonymizes paths & usernames (`dataclaw/anonymizer.py`), runs regex + entropy redaction (`dataclaw/secrets.py`), writes a single flat `dataclaw_conversations.jsonl`, and pushes `conversations.jsonl` + `metadata.json` + `README.md` to one HF dataset repo (`dataclaw/cli.py:409–456`). Config is a TypedDict at `~/.dataclaw/config.json` (`dataclaw/config.py:8–54`). The publish gate is `confirm` (`dataclaw/cli.py:941–1108`) — three text attestations + full-name scan + regex PII scan — which flips `stage="confirmed"` before `export` (`dataclaw/cli.py:1329–1595`) pushes.

This plan: (1) replaces the human `confirm` gate with a policy check so runs can happen automatically on a schedule; (2) augments regex redaction with the `openai/privacy-filter` MoE token classifier whose **new** findings drive the policy; (3) splits the single JSONL into `{bucket}/{source}/YYYY-MM-DD.jsonl` dated shards with an incremental cutoff and a manifest for directory-aware review; (4) lets the user group projects into buckets; (5) wraps it all in a Tauri menubar app that edits config, shows last run, and manages the launchd plist.

### Hard constraints (back-compat contract)
- **Function signatures preserved.** `export_to_jsonl(projects, output_path, anonymizer, include_thinking, custom_strings)` and `push_to_huggingface(jsonl_path, repo_id, meta)` keep their exact current call shapes — existing tests and any external importers continue to work. New behavior lives in **new functions**: `export_to_shards(projects, root_dir, config, anonymizer, ...)` and `push_shards_to_huggingface(root_dir, repo_id, manifest)`. The legacy functions gain a one-line delegation to the new path when a `DATACLAW_SHARDED=1` env var is set or when `config.auto.enabled`, but their default behavior is byte-identical.
- **Review path keeps working for one file AND a directory.** `confirm` auto-detects sharded exports via a manifest file at `{root_dir}/.dataclaw/manifest.json`; if present, it aggregates across shards. Otherwise it behaves as today.
- **Privacy-filter is opt-in.** Base `pip install dataclaw` must not import `torch`/`transformers`. Enforced by a dedicated test.
- **Tauri shells out only.** All writes go through the CLI. To make that work, the CLI gains the missing verbs (replace-list, remove-from-list, show-secrets).
- **User-facing copy stays in sync.** Every source enumeration, `next_steps` list, `SETUP_TO_PUBLISH_STEPS`, `EXPORT_REVIEW_PUBLISH_STEPS`, `AUTO_MODE_STEPS` (new), and help text lists the full canonical set `claude|codex|gemini|opencode|openclaw|kimi|custom|all`.

### Settled decisions (from gate, locked here)
- **Auto-mode default = strict** (new findings block push; user acks via `dataclaw confirm` or `--force`).
- **Folder rules primary form = explicit buckets**, with optional tag fallback; bucket matching normalizes project identity across sources.
- **Shard date = session end-time UTC date** (`end_time[:10]`); sessions with unparseable or missing `end_time` are skipped with a warning.
- **`last_export_cutoff` only advances on HF push success.**
- **Tauri: Rust never writes config or plists directly** — it invokes the CLI.
- **Optional extra name: `pii`** (opt-in for the OpenAI Privacy Filter model).
- **Cooled-session definition**: file mtime ≥ 24h for file-based sources; for opencode, latest-message-timestamp ≥ 24h. Covers **all** parser paths including Claude subagent-only directories.
- **Auto exit codes**: 0 success/noop, 2 missing deps or not enabled, 3 policy block, 4 HF push failure.

   import time
   from datetime import datetime, timezone

   COOL_DOWN_SECONDS = 24 * 60 * 60

   def _parse_iso(ts: str | None) -> datetime | None:
       """Robust parse of ISO-8601 timestamps from heterogeneous sources. None on bad input."""
       if not ts or not isinstance(ts, str):
           return None
       try:
           s = ts.rstrip("Z") + "+00:00" if ts.endswith("Z") else ts
           dt = datetime.fromisoformat(s)
           return dt if dt.tzinfo else dt.replace(tzinfo=timezone.utc)
       except (ValueError, TypeError):
           return None

   def _is_cooled_path(p: Path, now: float | None = None) -> bool:
       try:
           return (now or time.time()) - p.stat().st_mtime >= COOL_DOWN_SECONDS
       except OSError:
           return False

   def _is_cooled_ts(ts: str | None, now: float | None = None) -> bool:
       dt = _parse_iso(ts)
       return bool(dt and (now or time.time()) - dt.timestamp() >= COOL_DOWN_SECONDS)

### Step 8: Bucket resolver with project-identity normalization (`dataclaw/cli.py`)
**Scope:** Medium
1. **Add** (new helper, after source-choice helpers ~`dataclaw/cli.py:62`):
   ```python
   def _project_candidates(session: dict) -> list[str]:
       """Possible keys a bucket rule might use. Order: dir_name > raw project > stripped prefix."""
       out = []
       if session.get("_project_dir_name"):
           out.append(session["_project_dir_name"])
       p = session.get("project") or ""
       if p:
           out.append(p)
           # codex/opencode/kimi/custom use "<source>:<basename>" display form
           if ":" in p:
               out.append(p.split(":", 1)[1])
       return out

   def _bucket_for_project(session: dict, config: DataClawConfig) -> str | None:
       rules = config.get("folder_rules") or {}
       buckets = rules.get("buckets") or {}
       candidates = _project_candidates(session)
       for bucket, members in buckets.items():
           if any(c in members for c in candidates):
               return bucket
       tags_map = config.get("project_tags") or {}
       tags_of_project = set()
       for c in candidates:
           tags_of_project.update(tags_map.get(c, []))
       if tags_of_project:
           for bucket, bucket_tags in (rules.get("buckets_by_tag") or {}).items():
               if tags_of_project.intersection(bucket_tags):
                   return bucket
       return rules.get("default_bucket")
   ```

## Phase 4: Privacy-filter PII detection

### Step 17: `dataclaw/privacy_filter.py` — decoder via HF pipeline (`dataclaw/privacy_filter.py` — new)
**Scope:** Medium
1. **Create** the module with lazy imports:
   ```python
   from __future__ import annotations
   import hashlib, sys
   from dataclasses import dataclass
   from pathlib import Path

   MODEL_ID = "openai/privacy-filter"
   _PIPE = None

   @dataclass(frozen=True)
   class Finding:
       kind: str; text: str; start: int; end: int
       score: float; session_id: str; field: str
       def fingerprint(self) -> str:
           return hashlib.sha256(f"{self.kind}|{self.text}".encode()).hexdigest()[:12]

   def is_available() -> bool:
       try:
           import transformers, torch  # noqa: F401
           return True
       except ImportError:
           return False

   def _load(device: str = "auto"):
       """Load as a token-classification pipeline. The pipeline decodes the model's
       BIOES labels via aggregation_strategy='simple', which merges contiguous spans
       of the same entity type and computes per-span scores. This matches the model
       card's intended operating-point behavior closely enough for our new/known
       diffing purpose; exact-Viterbi reproduction is not needed because fingerprints
       are computed on final text spans, not on tag probabilities."""
       global _PIPE
       if _PIPE is not None: return _PIPE
       import torch
       from transformers import pipeline
       if device == "auto":
           device = "mps" if torch.backends.mps.is_available() else "cpu"
       print(f"dataclaw: loading {MODEL_ID} on {device} (first run downloads ~1.5GB)", file=sys.stderr)
       _PIPE = pipeline("token-classification", model=MODEL_ID, aggregation_strategy="simple", device=device)
       return _PIPE

   def scan_text(text: str, session_id: str, field: str, min_score: float = 0.5) -> list[Finding]:
       pipe = _load()
       # chunk at 512 tokens to respect MPS memory on long conversations
       findings = []
       for chunk_start, chunk in _chunk_by_tokens(text, pipe.tokenizer, max_tokens=480):
           for r in pipe(chunk):
               if r["score"] < min_score: continue
               findings.append(Finding(kind=r["entity_group"], text=r["word"],
                                       start=chunk_start + r["start"], end=chunk_start + r["end"],
                                       score=r["score"], session_id=session_id, field=field))
       return findings

   def scan_session(session: dict, min_score: float = 0.5) -> list[Finding]: ...
   def scan_shards(root_dir: Path, min_score: float = 0.5) -> list[Finding]: ...
   def scan_jsonl(path: Path, min_score: float = 0.5) -> list[Finding]: ...  # legacy single-file
   ```
2. **Decoder rationale (locked)**: Transformers' `pipeline(aggregation_strategy="simple")` handles BIOES/BIO label merging natively — using the pipeline is cheaper to maintain than writing our own Viterbi and still produces valid, contiguous spans tagged with the correct entity group. If the model card insists on strict Viterbi for score calibration, swap `aggregation_strategy` to `"first"` which still respects label transitions; there is no scenario in this plan where our fingerprint-based diffing requires Viterbi-exact decoding.
3. **Never mutate the session.** `scan_*` only returns `Finding` objects; redaction is a separate decision made by `confirm`/`auto`.

## Risk & tradeoff notes

- **Manifest-based confirm** keeps `confirm` backward-compat while enabling directory review. Trade-off: two code paths inside `confirm` — mitigated by extracting `_summarize_single_file` and `_summarize_shards` helpers sharing a result schema.
- **Pipeline-based decoding** (simple aggregation) may produce slightly different span boundaries than the model card's Viterbi. Fingerprints are computed on final text content, so the new/known diff remains stable across minor decoder differences. If calibration matters later, swap to `aggregation_strategy="first"` or a custom Viterbi helper without changing the public API.
- **Transformers floor (≥4.57)**: if the actual release shipping the `openai_privacy_filter` arch has a different number, bump in pyproject during the Phase 4 PR — verify by `pip install transformers==X.Y && python -c "from transformers import OpenaiPrivacyFilterForTokenClassification"`.
- **launchd env capture**: we copy only an allowlist of env vars (`PATH`, `HF_*`, `HOME`, `TMPDIR`, `LANG`, `LC_ALL`) into the plist to avoid leaking secrets from the install shell into a persisted file readable by the user. If `HF_TOKEN` is set at install time, it's copied — same trust boundary as `~/.dataclaw/config.json`.
- **Config-CLI surface growth**: the new set-/remove-/show-secrets verbs add ~8 flags. Mitigation: group them visually in `--help` and document the Tauri-driven rationale.
- **Bucket normalization via `_project_dir_name`**: requires every parser to stamp that field. Test coverage ensures no source path is missed.
