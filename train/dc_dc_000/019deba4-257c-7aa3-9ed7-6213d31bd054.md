## Design constraints (non-negotiable)

1. **Reigh compatibility** — `clip.kind` is NEVER persisted. Reigh's clip allowlist (`reigh-app/src/tools/video-editor/lib/serialize.ts:8-42`) is closed and throws on unknown clip keys. All kind-based dispatch is runtime-only on the ArtAgents side. The Phase 2 `classified_kind` is a `TimelineClipView` property, not a JSON field.
2. **Backwards-compat user-facing CLI** — `python3 -m artagents --video X.mp4 --brief brief.txt`, `--audio X.wav --brief brief.txt`, and `--brief brief.txt --target-duration 28` (pure-generative) all keep working. They become hints that influence which clips get added to the timeline; behind the scenes they all converge on one path.
3. **Step capability discovery is manifest-driven** — each `executor.yaml` declares `produces_for: [VIDEO, AUDIO, ...]` (or equivalent shape — name is a design call). The pipeline computes the union of needed steps over all timeline clips, then runs only those. No hardcoded STEP_ORDER as the source of truth (it can remain as a topological-order hint).
4. **Topological order preserved** — current pipeline ordering (`transcribe → scenes → quality_zones → shots → triage → scene_describe → quote_scout → pool_build → pool_merge → arrange → cut → refine → render → editor_review → validate`) has real dependencies; manifest-driven discovery must produce the same order when the same step set is needed.
5. **Schema package unchanged** — clip kinds are runtime-derived. No `@banodoco/timeline-schema` changes.

## What "do it RIGHT" means concretely

### Part A: Manifest-driven step capability

- Add `produces_for` (or `clip_kinds_supported` — design call) to the executor manifest schema. Update `artagents/executors/schema.py` and the JSON-Schema validator.
- Update each pipeline-stage executor.yaml that declares it (15 hype-pipeline executors: transcribe, scenes, quality_zones, shots, triage, scene_describe, quote_scout, pool_build, pool_merge, arrange, cut, refine, render, editor_review, validate). Most produce for `VIDEO` only, some for `AUDIO`, `arrange`/`cut`/`refine`/`render` produce for ALL (they handle every clip kind).
- Other executors (generate_image, sprite_sheet, audio_understand, etc.) can declare `produces_for` too where meaningful, but it's not required for the unified pipeline since they're not invoked by `STEP_ORDER` today.

### Part B: Unified pipeline that dispatches on clip kinds

- Today: `pipeline.py` has `if args.video:` / `if not args.video:` branches and `is_all_generative_arrangement` checks. Replace with: compute the set of `classified_kind` values across all timeline clips, ask the registry for the union of needed steps, run them in topological order.
- Skip-step plumbing (`--from`, `--skip`) keeps working with dynamic step sets. `--from <step>` means "skip everything topologically before this step in the computed set."
- `--video` / `--audio` / pure-generative invocations all converge on one code path. The flags become hints that influence which clips get seeded into the initial pool.

### Part C: Mixed-mode arrange

- `arrange` and `cut` currently reject mixed source/generative pools (`is_all_generative_arrangement` is the canary). Remove these checks and update arrange to handle a pool with mixed clip kinds.
- Add a fixture test: brief that produces a timeline with both a `VIDEO` clip (from a source) and a `GENERATIVE_IMAGE` clip (from a prompt) — render passes.

### Part D: Extract hype orchestration to orchestrators/hype/

- Move the hype-specific orchestration code out of `pipeline.py` and into `artagents/orchestrators/hype/run.py` (currently a 6-line re-export of `pipeline.main`).
- `pipeline.py` becomes a thin CLI router: parse args, dispatch to orchestrators_cli / executors_cli / elements_cli, plus minimal shared utilities. Target: ~200 lines, down from 1293.
- The hype orchestrator's `run.py` is now where source-cut + pure-generative + mixed-mode collapsed pipeline lives.
- Update `artagents/orchestrators/hype/orchestrator.yaml` so the entrypoint argv points at the orchestrator's run.py module, not back at `artagents.pipeline:main`.
