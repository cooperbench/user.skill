        # Implementation Plan: Refactor Clip Resize to State Machine + AbortController

## Overview

The clip resize handler lives inline in `TimelineCanvas.tsx` (~lines 473-985) as a set of `useCallback` handlers (`handleResizePointerDown`, `handleResizePointerMove`, `endResize`) with manual pointer capture, mutable activation refs, and stale closure risks from `useCallback` dependency arrays capturing props like `gestureOwner`, `rows`, and `onActionResizing`.

The `useClipDrag` hook (492 lines) was already refactored to a clean pattern: a 3-phase state machine (`idle`/`pending`/`dragging`), per-session `AbortController` for automatic listener cleanup, a `latestRef` to avoid stale closures, document-level listeners instead of pointer capture, and pointerId matching for event ownership. This refactor applies the same pattern to resize.

### Bug inventory mapped to root causes
1. **Session leaks** — No AbortController; if `endResize` never fires (e.g., element removed, pointercancel missed), listeners/refs linger. Fixed by AbortController signal on all listeners.
2. **Pointer capture races** — `setPointerCapture` on activation target (line 969) races with browser's implicit capture and other gestures. Fixed by removing pointer capture entirely; use pointerId matching like useClipDrag.
3. **Stale closures on `gestureOwner`** — `handleResizePointerMove` captures `gestureOwner` in its useCallback deps (line 976). If another gesture claims ownership between renders, the move handler reads a stale value. Fixed by reading from `latestRef.current.gestureOwner`.
4. **Stale closures on `rows`** — `handleResizePointerDown` captures `rows` (line 928). If rows change between pointerdown and the next render, session creation uses stale data. Fixed by reading from `latestRef`.
5. **Stale closures on callbacks** — `onActionResizing`, `onActionResizeStart`, `onClipEdgeResizeEnd` are captured in useCallback deps. Fixed by latestRef.
6. **gestureOwner lockout** — If resize ends abnormally (no pointerup), `claimedOwnership` flag is lost and gestureOwner stays `'trim'` forever, blocking all other gestures. Fixed by tracking claim in the state machine session and cleaning up in `endSession` which is always called via AbortController.
7. **`onLostPointerCapture` double-fires `endResize`** — TrackListRenderer wires `onLostPointerCapture` to `endResize` (line 168, 177). After removing pointer capture, this event won't fire, but we should also stop wiring it as a safety measure.
8. **Missing `pendingOpsRef` management** — `endResize` lists `pendingOpsRef` in deps (line 874) but never increments/decrements it, unlike useClipDrag. This is either dead code or a missing feature.
9. **useCallback re-creation churn** — Every prop change (`rows`, `gestureOwner`, `shotGroups`) recreates the callbacks, which is wasteful. The effect+latestRef pattern eliminates this.

### Key constraints
- The resize preview store (`createResizePreviewStore` + `useSyncExternalStore`) is a good pattern and stays. It just needs to be accessed from inside the new hook.
- `TrackListRenderer` currently receives resize handlers as React props and wires them to individual clip handle elements. After the refactor, the new hook will use document-level pointerdown (like useClipDrag) to detect resize handle interactions via `data-*` attributes, eliminating the need to pass handlers as props.
- The `useClipResize` hook (405 lines) handles resize metadata (speed/from/to patching). It is a consumer of resize events, not the gesture handler. It stays unchanged — we just call its callbacks from the new hook.
