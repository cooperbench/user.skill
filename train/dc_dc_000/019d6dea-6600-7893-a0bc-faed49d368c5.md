## Overview
The current bug is localized to live resize preview, but the repo state confirms the structural cause described in the brief: preview math is duplicated in [TimelineCanvas.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx#L649), commit math is duplicated in [useClipResize.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useClipResize.ts#L275) and [useClipResize.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useClipResize.ts#L420), preview reads from both `resizePreviewRef` and `resizeOverrides` in [TimelineCanvas.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx#L442), and resize start currently stores `initialClientX` but no cursor-to-handle offset in [TimelineCanvas.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx#L850).

**Group-edge semantic asymmetry (resolved into the contract):** the live preview rescales every child of the pinned group across `[start, end]` ([TimelineCanvas.tsx#L710-L735](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx#L710)), while the commit path only mutates the first or last clip ([useClipResize.ts#L420-L479](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useClipResize.ts#L420)) and existing tests lock that behavior in ([useClipResize.test.tsx#L334-L387](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useClipResize.test.tsx#L334)). Reconciling those two behaviors is out of scope for this cleanup. The shared helper `computeGroupEdgeResize` therefore owns **only the outer `[start, end]` calculation** (clamping, direction, min-duration, snap inputs) — both preview and commit call it for that. Child projection stays a preview-only concern in `TimelineCanvas` and is explicitly documented as such.

The simpler symptom-only fix would be to patch `TimelineCanvas` with cursor offset and force-sync rendering. That would probably stop the visible lag, but it would keep the same duplicated boundary math that already caused this class of bug. The smallest durable fix is still the brief's direction: extract the resize math first, then make preview and commit consume the same outer-boundary result, then remove the second preview source of truth.
