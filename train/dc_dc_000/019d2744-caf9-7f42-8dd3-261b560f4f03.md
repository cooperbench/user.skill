        # Implementation Plan: Turn-Based Timeline Editing Agent

## Overview

Build an AI-powered timeline editing agent that operates through a turn-based conversation model. The agent runs as a Supabase Edge Function (`ai-timeline-agent`), reads/writes timeline config via JSONB in the existing `timelines` table, and communicates with users through a chat UI embedded in `VideoEditorShell`. Sessions are stored in a new `timeline_agent_sessions` table with optimistic locking. Groq handles fast LLM calls; Claude Sonnet handles complex reasoning. Voice input reuses extracted Whisper transcription.

**Current repo shape:**
- `timelines` table exists (`supabase/migrations/20260325090000`) with `config` JSONB, `asset_registry` JSONB, RLS, and realtime enabled. No `config_version` column yet.
- `SupabaseDataProvider` reads/writes timeline config via Supabase client.
- `ai-voice-prompt` edge function has Groq Whisper transcription (lines 96-104) tightly coupled with prompt enhancement.
- `bootstrapEdgeHandler` / `withEdgeRequest` provide standard edge function scaffolding.
- `useVoiceRecording` hook handles browser audio capture, submits to `ai-voice-prompt`.
- `VideoEditorShell` is a 3-panel layout (preview, properties, timeline) with realtime conflict detection.
- `useTimelineRealtime` subscribes to `timelines-updated` realtime events.
- Python tools (`place.py`, `view.py`, `common.py`) contain the clip manipulation logic to port — not readable from this repo, will need user to provide or copy in.

**Key constraints:**
- Edge functions are stateless — DB is the continuity mechanism.
- Edge function timeout is ~60s (Supabase default), so agent must checkpoint and set `status=continue` for multi-turn work.
- Optimistic locking needed to prevent agent and user from clobbering each other's edits.
- Agent writes to `timelines.config` directly (same JSONB the UI reads), so changes appear via existing realtime subscription.

## Phase 2: Edge Function — Agent Core

### Step 4: Create `ai-timeline-agent` edge function scaffold
**Scope:** Medium
1. **Create** `supabase/functions/ai-timeline-agent/index.ts`:
   - Use `withEdgeRequest` pattern from `_shared/edgeHandler.ts`.
   - Accept `POST` with body: `{ session_id: string, user_message?: string, audio?: File }`.
   - Auth required (JWT).
   - Load session from DB, verify ownership, check `status !== 'cancelled'`.
   - If audio provided, transcribe via shared module (parallel with session load).
   - Append user message to turns, set `status='processing'`, save.
2. **Create** `supabase/functions/ai-timeline-agent/tools.ts`:
   - Define tool schemas as Groq/Anthropic tool-use format.
   - Each tool is a function `(session, timeline, args) => { result, configMutated }`.

### Step 5: Implement timeline manipulation tools
**Scope:** Large — this is the core logic
1. **Create** `supabase/functions/ai-timeline-agent/timeline-tools.ts`:
   - `view_timeline(config, assetRegistry)`: Build enriched view — list clips with computed durations (from asset registry), track assignments, timestamps. Return as structured text for LLM context.
   - `move_clip(config, clipId, at)`: Find clip by ID, update `at` field. Return confirmation with old/new position.
   - `trim_clip(config, clipId, { from?, to?, duration? })`: Adjust source range. If `duration` given without `from`/`to`, adjust `to = from + duration`. Validate against asset duration from registry.
   - `set_clip_property(config, clipId, property, value)`: Generic setter for volume, speed, opacity, position, etc. Whitelist allowed properties.
   - `delete_clip(config, clipId)`: Remove from clips array. Return deleted clip info.
   - `add_text_clip(config, track, at, duration, text)`: Create new `TimelineClip` with `clipType: 'text'`, generate UUID for id.
   - `find_issues(config, assetRegistry)`: Detect gaps between clips on same track, overlapping clips, clips extending past asset duration.
2. **Create** `supabase/functions/ai-timeline-agent/session-tools.ts`:
   - `message_user(session, text)`: Append assistant message, set `status='waiting_user'`. Signal to stop the tool-use loop.
   - `done(session, summary)`: Set `status='done'`, store summary. Signal to stop.
   - `create_generation_task(supabaseAdmin, session, { prompt, count })`: Call existing `create-task` edge function or insert directly into tasks table via admin client.

### Step 6: Implement the tool-use loop
**Scope:** Medium
1. **In** `ai-timeline-agent/index.ts`, after appending user message:
   - Load `timelines.config` and `timelines.config_version` via admin client.
   - Build LLM messages from session turns.
   - System prompt: describe available tools, current timeline state (via `view_timeline`), user's request.
   - Enter loop (max ~8 iterations to stay within edge function timeout):
     a. Call Groq (or Claude if `model='claude'`) with tools.
     b. If response is text-only (no tool calls): append as assistant turn, call `message_user`, break.
     c. If tool calls: execute each, append tool_call + tool_result turns.
     d. If any tool mutated config: save via versioned RPC. If version conflict, reload and retry once.
     e. If `message_user` or `done` was called: break.
     f. Check session status (re-read from DB) — if `cancelled`, break immediately.
   - If loop hits iteration limit: set `status='continue'`, save session, return.
   - Final: save updated turns to session, return response.
2. **Timeout safety**: Track wall-clock time. If approaching 50s, checkpoint and set `status='continue'`.

   - Network errors on send: show error toast, allow retry.
   - Session in `error` state: show error message with "Retry" button.
