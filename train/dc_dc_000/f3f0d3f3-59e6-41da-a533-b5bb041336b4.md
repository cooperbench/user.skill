# recent-convos

## What it does

Inspects session JSONLs and classifies each by the trailing state of the
last real turn (system/attachment/summary/wrapper lines are stripped first):

- `COMPLETED (assistant text — awaiting user)` — normal clean stop
- `DROPPED (killed mid tool call)` — assistant issued a tool/function call and the
  session ended before a result came back
- `DROPPED (tool result, no reply)` — tool result present but the
  assistant never got a turn to respond
- `DROPPED (tool error at cutoff)` — final tool result had `is_error: true` (Claude only)
- `DROPPED (mid-reasoning, no reply)` — Codex emitted a reasoning chunk and stopped
- `AWAITING REPLY (user prompt, no answer)` — user typed, model never responded
- `MEGAPLAN-SUB (...)` — first user message is the megaplan harness preamble;
  one-shot sub-agent run, not a convo to resume standalone (Claude only)
- `EXEC (...)` — Codex `codex_exec` (non-interactive) session
- `ACTIVE? <60s (...)` — mtime within the last 60s (likely running)

`MEGAPLAN-SUB` and `ACTIVE?` prefixes wrap the inner status and suppress
the session from the resume-candidate list.

Sources:
- **Claude Code:** `~/.claude/projects/<slug>/*.jsonl`. Default scans
  the `$PWD`-derived slug; `--all-projects` walks every folder.
- **Codex:** `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`. By default
  `codex_exec` (non-interactive) sessions are skipped — pass
  `--include-codex-exec` to include them.

## How to run it

```bash
~/.claude/skills/recent-convos/scan.sh                            # top 10 Claude convos for $PWD
~/.claude/skills/recent-convos/scan.sh --all-projects              # every Claude project folder
~/.claude/skills/recent-convos/scan.sh --source codex              # Codex only
~/.claude/skills/recent-convos/scan.sh --source all --all-projects # everything
~/.claude/skills/recent-convos/scan.sh --source all --all-projects --since 1h
~/.claude/skills/recent-convos/scan.sh --since 2d --only-dropped
~/.claude/skills/recent-convos/scan.sh --project-dir /path/to/other/repo
```

Flags:
- `--source claude|codex|all` (default: `claude`)
- `--all-projects` — Claude: walk every folder, not just `$PWD`'s
- `--project-dir PATH` — override `$PWD`
- `--since DURATION` — `Ns`/`Nm`/`Nh`/`Nd` (e.g. `1h`, `30m`, `2d`).
  When set, the default `--limit` jumps from 10 → 200.
- `--limit N` — cap sessions inspected
- `--only-dropped` — print only flagged-as-dropped/awaiting
- `--include-codex-exec` — also classify `codex_exec` sessions

Output ends with a `═════ CANDIDATES TO RESUME ═════` block listing
ready-to-paste `claude --resume <id>` / `codex resume <id>` commands for
the dropped ones.

## Instructions for the agent

1. Run `bash ~/.claude/skills/recent-convos/scan.sh` with whichever
   flags fit the user's ask:
   - "what was I working on?" / "what did I lose?" → `--source all --all-projects --since <window>`
     (pick window from context: "last hour" → `1h`, "today" → `1d`, "since the crash" → ask or guess `2h`)
   - "this project only" → omit `--all-projects`
   - "just Codex" / "just Claude" → set `--source` accordingly

2. **ALWAYS tail-review the COMPLETED sessions before reporting.** The
   structural classifier systematically misses loose threads. For every
   session marked `COMPLETED (assistant text — awaiting user)` in the
   scan output, look at the `Tail:` block (or `jq` the JSONL directly)
   and flag it for resume if any of these hit:
   - Forward-looking time phrases: "before the next check-in", "in the
     next few minutes", "landing soon", "I'll relay", "will relay",
     "report back when X"
   - Mid-investigation phrasing: "I'm going to next…", "Let me check…",
     "Continuing with…"
   - Megaplan / gate phrasing: "paused at a gate escalation", "BREAKPOINT",
     "awaiting your decision", "needs your input", "awaiting_human_verify"
   - Last assistant turn asked the user a question with no reply
   - A subagent or background task was launched and the parent never
     received the report
   - Truncated mid-sentence status line (vs a clean wrap-up with bullets)
   - Repeated babysit cadence ("still healthy / is it stuck") around an
     external long-running job

   When the COMPLETED set is large (>5), spawn a subagent to do the
   tail review in parallel rather than reading every JSONL inline.

3. **Cross-reference structured signals where they exist:**
   - `~/.claude/sessions/<pid>.json` — definitive "this Claude session
     is running RIGHT NOW" signal (more reliable than `mtime<60s`).
     If a session id appears here, treat it as ACTIVE, not resumable.
   - `~/Documents/.megaplan/plans/<plan>/state.json` — every megaplan
     run writes one with `current_state` ∈ {planned, executed,
     finalized, **awaiting_human_verify**, aborted, done} and a
     `sessions` map linking to the claude/codex session IDs it spawned.
     If a parent session's child megaplan is `awaiting_human_verify`,
     the parent is a hot resume candidate even if it looks COMPLETED.

4. Show the user the output, including any loose threads you found in
   step 2 and any megaplan-state hits from step 3. Use the same
   `cd "<cwd>" && <resume cmd> --dangerously-skip-permissions` /
   `--dangerously-bypass-approvals-and-sandbox` shape, grouped by folder.

5. If the user wants deeper context on a specific convo, read its
   `.jsonl` tail directly with `jq` rather than re-running the skill.

6. Don't auto-launch `claude --resume` or `codex resume` yourself —
   they're interactive commands the user runs in their own terminal.
