        # Implementation Plan: Harden Execute→Review Evidence Pipeline

## Overview

**Goal:** When a plan reaches DONE, `finalize.json` contains complete, auditable, programmatically-verified evidence of what was done and whether it checks out.

**Current state:** The pipeline has good structural bones — executor returns `task_updates` with `executor_notes`, reviewer fills `reviewer_verdict` and `sense_check` verdicts, coverage gaps block state transitions. Three gaps remain:

1. **Evidence is flat, not per-task.** `files_changed` and `commands_run` live at the top level of `execution.json`, not tied to individual tasks.
2. **No programmatic validation.** Executor claims are trusted at face value. Nobody checks whether claimed files actually appear in git status.
3. **Sense-check acknowledgments are one-directional.** The executor sees sense checks as "nudges" (`prompts.py:380`) but never formally acknowledges them.

**Key design decision — required fields, not optional:** `strict_schema()` (`schemas.py:189-196`) forces all declared properties to be required and sets `additionalProperties: false` on agent-facing schemas. Rather than fighting this, we *embrace* it: all new evidence fields are **required** in the schema. This is better for agentic clarity — the executor always knows exactly what to return, no ambiguity. Empty arrays (`[]`) are the valid value for skipped tasks.

**DONE enforcement strategy:** Three layers ensure the DONE guarantee:
1. **Schema layer:** Agent-facing schemas require all evidence fields — agent cannot return a valid payload without them.
2. **Handler layer:** `handle_execute` blocks if any "done" task has empty `files_changed` (not just missing task coverage). `handle_review` blocks if any task verdict has empty `evidence_files`. Sense-check acknowledgment coverage blocks execute.
3. **Audit layer:** Programmatic cross-check of executor claims vs git status surfaces advisory findings for the reviewer.

**Merge helper extension:** `_validate_merge_inputs()` (`handlers.py:183-228`) currently only handles string fields — it iterates `required_fields`, checks `isinstance(value, str)`, and copies to a normalized dict. Array evidence fields (`files_changed`, `commands_run`, `evidence_files`) need a new `array_fields` parameter so the helper can validate and carry them through without breaking existing string-field behavior.

**Constraints:** No new CLI flags, no interactive prompts, enforcement is automatic. Happy path feels invisible.

## Phase 2: Handler Merge Logic and Validation

### Step 6: Extend `_validate_merge_inputs` to support array fields (`megaplan/handlers.py:183-228`)
**Scope:** Medium — This is the prerequisite for Steps 7 and 10. Without it, array evidence fields silently disappear during merge.

The current function only handles string fields:
- Line 206-217: iterates `required_fields`, checks `isinstance(value, str)`, copies to `normalized` dict.
- Line 249-250 in `_merge_validated_entries`: copies `merge_fields` from validated entry to target.

If `files_changed: ["foo.py"]` is in `required_fields`, it fails `isinstance(value, str)` and the entire entry is skipped as malformed.

**Fix — add an `array_fields` parameter:**
1. **Add** `array_fields: tuple[str, ...] = ()` parameter to `_validate_merge_inputs()` (`handlers.py:183`).
2. **Update** the validation loop (`handlers.py:206-217`) to handle array fields separately from required string fields:
   ```python
   # After the existing required_fields string loop (lines 208-217):
   for field in array_fields:
       value = entry.get(field)
       if not isinstance(value, list):
           malformed = True
           break
       normalized[field] = value
   ```
3. **Also check** that array fields are present in the entry (`handlers.py:202`): extend the missing-field check to include `array_fields`.
4. **Update** the return type annotation from `list[dict[str, str]]` to `list[dict[str, Any]]` (`handlers.py:191`) since normalized dicts now contain lists too.
5. **Update** `_merge_validated_entries` type annotation (`handlers.py:231`) from `list[dict[str, str]]` to `list[dict[str, Any]]` to match.
6. **No changes** to `_merge_validated_entries` logic itself — it already does `target[field] = entry[field]` which works for any type.

### Step 7: Update `handle_execute` to merge per-task evidence and enforce completeness (`megaplan/handlers.py:1110-1139`)
**Scope:** Medium
1. **Extend** the `_validate_merge_inputs` call for task_updates (`handlers.py:1113-1119`) to include the new array fields:
   ```python
   task_updates = _validate_merge_inputs(
       worker.payload.get("task_updates"),
       required_fields=("task_id", "status", "executor_notes"),
       array_fields=("files_changed", "commands_run"),  # NEW

       nonempty_fields={"executor_notes"},
       deviations=deviations,
       label="task_updates",

   ```
2. **Extend** `merge_fields` in the `_merge_validated_entries` call (`handlers.py:1127`) to include `"files_changed"` and `"commands_run"`:
   ```python
   merged_count = _merge_validated_entries(
       task_updates,
       targets_by_id=tasks_by_id,
       id_field="task_id",
       merge_fields=("status", "executor_notes", "files_changed", "commands_run"),
       issues=deviations,
       label="task_update",
   )
   ```
3. **Add** a new merge block after the task merge (after line 1130) for `sense_check_acknowledgments`:
   - Validate: `_validate_merge_inputs(required_fields=("sense_check_id", "executor_note"), nonempty_fields={"executor_note"})`.
   - Merge: `_merge_validated_entries(id_field="sense_check_id", merge_fields=("executor_note",))`.
   - Track coverage: `unacked_checks = total_checks - ack_count`. If `unacked_checks > 0`, add deviation and set blocked.
4. **Add** per-task evidence completeness enforcement (after merge, before writing finalize.json): iterate merged tasks, check each task with `status == "done"`. If `files_changed` is empty (`len(task.get("files_changed", [])) == 0`), add deviation and set `blocked = True`. This enforces the DONE guarantee — a "done" task must claim at least one file changed. `commands_run` is allowed to be empty (some tasks are pure file edits with no commands). `evidence_files` is enforced on the review side (Step 10).

### Step 8: Add `validate_execution_evidence()` to `megaplan/evaluation.py`
**Scope:** Medium
1. **Implement** `validate_execution_evidence(finalize_data, project_dir) -> dict` returning `{"findings": [...], "files_in_diff": [...], "files_claimed": [...], "skipped": bool, "reason": str | None}`.
2. **Git file detection:** Use `git status --short` (matching `collect_git_diff_summary` at `_core.py:402-419`) to get changed/untracked files. Parse the two-character status prefix and extract file paths (column 3 onward, handling `->` for renames). This catches modified, added, deleted, renamed, and untracked files.
3. **Non-fatal fallback — all four paths explicitly:**
   - If `(project_dir / ".git").exists()` is False: return `{"findings": [], "skipped": True, "reason": "Not a git repository"}`.
   - If `FileNotFoundError` (git not on PATH): return `{"findings": [], "skipped": True, "reason": "git not found on PATH"}`.
   - If `subprocess.TimeoutExpired`: return `{"findings": [], "skipped": True, "reason": "git status timed out"}`.
   - If `process.returncode != 0`: return `{"findings": [], "skipped": True, "reason": f"git status failed: {process.stderr.strip() or process.stdout.strip()}"}`.

   This covers all four failure modes, including the non-zero returncode from empty `.git` directories used in test scaffolds at `tests/test_prompts.py:54` and `tests/test_megaplan.py:67`.
4. **Check 1 — files_changed vs git status:** Collect union of all per-task `files_changed` from finalize.json tasks. Compare against actual files from git status. Flag:
   - Phantom claims: "executor says T2 changed `foo.py` but it is not in git status."
   - Unclaimed changes: "`bar.py` in git status but not claimed by any task."
5. **Check 2 — executor_notes artifact references:** For each task's `executor_notes`, extract path-like tokens (regex: word chars, slashes, dots, with a file extension). Check existence relative to `project_dir`. Flag non-existent paths. Keep regex simple — false positives are acceptable since findings are advisory.
6. **Check 3 — sense-check acknowledgment quality:** Flag any `executor_note` that is very short (< 10 chars) or matches a generic pattern ("done", "yes", "acknowledged") as "possibly perfunctory."

3. **Append** each finding to the `deviations` list so it appears in the step response. Do **not** block based on audit findings — they are advisory for the reviewer. (Handler-level blocking in Step 7 already covers the structural guarantees.)
4. **Add** `execution_audit.json` to the artifacts list.
