        # Implementation Plan: First-Class Conductors

## Overview
ArtAgents already has a first-class `artagents/nodes/` package with schema, folder discovery, registry, CLI, runner, package exports, and tests. The orchestration layers are still separate legacy CLIs: the hype pipeline is implemented in `artagents/pipeline.py` and launched by root `pipeline.py`; event-talk orchestration is implemented in `artagents/event_talks.py` and launched by root `event_talks.py`.

The critique does not point to the wrong root cause: conductors still belong parallel to nodes. It does show that the first plan was underspecified around runtime contracts. The revised approach keeps the same architecture but makes the execution model explicit: conductor folders serialize metadata out-of-process, conductor runtime targets are validated as JSON-serializable entrypoints or commands, `builtin.hype` gets a real dry-run planner based on existing pipeline step builders, and `builtin.event_talks` exposes its existing subcommands through conductor passthrough args.

Conductor IDs will use the existing built-in node ID convention: `builtin.hype` and `builtin.event_talks`. The kind value remains `built_in`, matching node schema kind values without leaking that spelling into IDs.

## Phase 1: Foundation — Schema, API, Folder Loading

### Step 1: Add conductor schema and code-first API (`artagents/conductors/schema.py`, `artagents/conductors/api.py`)
**Scope:** Medium
1. **Create** `ConductorDefinition`, `ConductorSpec`, and a `conductor(...)` decorator analogous to node authoring helpers.
2. **Reuse** existing node primitives where they are already correct: `NodePort`, `NodeOutput`, `CachePolicy`, `CommandSpec`, and `IsolationMetadata`.
3. **Add** conductor-specific graph metadata with `child_nodes`, `child_conductors`, `provides`, and `consumes`.
4. **Add** a validated runtime target field instead of relying on callable objects that cannot survive out-of-process folder extraction:
   ```python
   RuntimeSpec(kind="python", module="artagents.conductors.curated.hype.runtime", function="main")
   RuntimeSpec(kind="command", argv=("{python_exec}", "pipeline.py", "..."))
   ```
5. **Validate** that `RuntimeSpec(kind="python")` has non-empty `module` and `function`, and `RuntimeSpec(kind="command")` has non-empty `argv`.
6. **Keep** node schema conductor-blind: do not add conductor fields to `NodeDefinition` or node graph metadata.

### Step 2: Add conductor folder discovery (`artagents/conductors/folder.py`)
**Scope:** Medium
1. **Mirror** node folder loading, but discover `conductor.py` files under conductor package roots.
2. **Support** top-level `CONDUCTOR`, `CONDUCTORS`, lowercase `conductor`, and decorated callables.
3. **Extract** metadata in a subprocess and serialize only validated definitions, exactly like node folder discovery.
4. **Attach** folder metadata: `source`, `conductor_root`, `conductor_file`, `folder_id`, plus optional `requirements_file`, `pyproject_file`, and `skill_file`.
5. **Test** that subprocess extraction does not leak environment mutations back into the parent process.

### Step 3: Add package exports (`artagents/conductors/__init__.py`)
**Scope:** Small
1. **Export** the first-class conductor API in parallel with `artagents/nodes/__init__.py`: schema types, API helpers, folder discovery helpers, registry helpers, runner request/result/error types, and `run_conductor`.
2. **Avoid** install helper exports unless conductor installation support is actually implemented; command-backed conductors can declare binaries and requirements without adding a new install system in this scope.

## Phase 2: Registry And Graph Validation

### Step 4: Add conductor registry (`artagents/conductors/registry.py`)
**Scope:** Medium
1. **Implement** `ConductorRegistry` with `register`, `get`, `list`, `validate_all`, `to_dict`, `to_json`, and `as_mapping` methods matching node registry ergonomics.
2. **Load** curated conductor folders from `artagents/conductors/curated/`.
3. **Validate** `child_nodes` against `artagents.nodes.registry.load_default_registry()`.
4. **Validate** `child_conductors` against the conductor registry.
5. **Detect** conductor graph cycles, including indirect cycles such as `A -> B -> A`, not only direct self-references.
6. **Test** duplicate conductor IDs, unknown child nodes, unknown child conductors, direct self-references, and indirect cycles.

## Phase 3: Runner And CLI

### Step 5: Add conductor runner (`artagents/conductors/runner.py`)
**Scope:** Medium
1. **Add** `ConductorRunRequest` with fields for `conductor_id`, `out`, `brief`, `inputs`, `conductor_args`, `dry_run`, `python_exec`, and `verbose`.
2. **Preserve** real legacy argument surfaces by allowing passthrough args after the conductor ID:
   ```bash
   python3 pipeline.py conductors run builtin.hype -- --video src.mp4 --brief brief.txt --out runs/a --render
   python3 pipeline.py conductors run builtin.event_talks -- render --manifest talks.json --out-dir rendered --dry-run
   ```
3. **Keep** `--out`, `--brief`, and `--input NAME=VALUE` as conveniences for simple conductors, but do not require hype/event-talks to squeeze their full CLI surface into generic inputs.
4. **Implement** `RuntimeSpec(kind="python")` by importing the validated module/function and calling it with the `ConductorRunRequest` or normalized argv contract.
5. **Implement** `RuntimeSpec(kind="command")` by expanding placeholders and running or dry-running a subprocess.
6. **Return** structured dry-run data: conductor ID, planned commands, skipped steps when known, and return code `None` for no execution.
7. **Ensure** only conductor code imports and calls node runner APIs; node code must not import `artagents.conductors`.

### Step 6: Add conductor CLI dispatch (`artagents/conductors/cli.py`, `artagents/pipeline.py`)
**Scope:** Medium
1. **Implement** `pipeline.py conductors list`, `inspect`, `validate`, and `run` with output conventions parallel to `pipeline.py nodes ...`.
2. **Dispatch** `pipeline.main(["conductors", ...])` before legacy required-argument validation, next to the existing `nodes` dispatch.
3. **Support** `list --json --kind`, `inspect ID --json`, `validate [ID]`, and `run ID --out ... --brief ... --input NAME=VALUE --dry-run --verbose -- ...`.
4. **Return** clear status-2 errors for unknown conductor IDs and invalid input syntax.
