        # Implementation Plan: Sense Check Validation Gate

## Overview

Currently, megaplan's execute phase blocks progression when the executor's JSON self-report is incomplete (missing `task_updates`, `sense_check_acknowledgments`, or evidence). This fails models that do the work but can't report it properly. The goal is to decouple "did the work happen on disk?" from "did the executor report it?"

**Current flow:** `execute → blocking validation → review`
**Target flow:** `execute → best-effort merge (warnings only) → sense_check → review`

The codebase uses a declarative workflow state machine (`megaplan/_core.py:672-701`) with `Transition` dataclasses. A new `STATE_SENSE_CHECKED` state and `sense_check` step slot cleanly into this pattern. The key validation logic lives in `megaplan/execution.py:273-294` (`build_blocking_reasons`) and the two `dispatch_execute_*` functions.

**Key constraint:** Backward-compatible. Executors producing perfect self-reports sail through the sense check with minimal overhead.

## Phase 3: Implement Sense Check Step

### Step 5: Build the sense check prompt (`megaplan/prompts.py`)
**Scope:** Medium
1. **Add** `build_sense_check_prompt()` function (after the execute prompt section, ~line 680):
   - Input: `finalize.json` (tasks + sense checks), `execution_audit.json` (git status audit), git diff output, `execution.json` (executor self-report if available), batch artifacts.
   - Instructions to the sense checker:
     - For each task: read the actual files mentioned in `files_changed` (or discovered via git diff). Does the code match what the task asked for?
     - For each sense check: read the actual code and answer the sense check `question` independently. Don't trust the executor's `executor_note`.
     - If `task_updates` are missing/incomplete: reconstruct them from git diff (which files changed, what was done).
     - Output verdict: `complete` / `incomplete` / `wrong`.
     - If `incomplete`: list which tasks aren't done and what's missing.
     - If `wrong`: list what's wrong and whether it's fixable.

### Step 6: Build the sense check handler and worker dispatch (`megaplan/handlers.py`, `megaplan/execution.py`)
**Scope:** Medium-Large
1. **Add** `handle_sense_check()` in `megaplan/handlers.py` (after `handle_execute`, ~line 1220):
   - `require_state(state, "sense_check", {STATE_SENSE_CHECKED})`
   - Load `finalize.json`, `execution_audit.json`, `execution.json` (if exists).
   - Run git diff to get actual changes.
   - Call worker with sense check prompt.
   - Parse sense check output.
   - **If verdict = "complete":**
     - Merge any `reconstructed_task_updates` into `finalize.json` (fill gaps the executor left).
     - Merge sense check assessments.
     - Write `sense_check.json` artifact.
     - Transition to `STATE_EXECUTED`, `next_step="review"`.
   - **If verdict = "incomplete":**
     - Set `state["meta"]["sense_check_incomplete"] = True` and `state["meta"]["sense_check_feedback"] = issues`.
     - Transition to `STATE_FINALIZED`, `next_step="execute"` (re-execute with feedback).
   - **If verdict = "wrong":**
     - Write `sense_check.json` with issues.
     - Transition to `STATE_EXECUTED`, `next_step="review"` (let reviewer see issues).
     - Or surface to user for decision — see assumptions.
2. **Register** the handler in the step dispatch (likely `megaplan/handlers.py` step registry or `megaplan/cli.py`).
3. **Add** `dispatch_sense_check` in `megaplan/execution.py` (or a new `megaplan/sense_check.py` if execution.py is already large):
   - Collect inputs (finalize.json, audit, git diff).
   - Call worker with sense check prompt.
   - Parse and validate output against schema.
   - Return structured result.
