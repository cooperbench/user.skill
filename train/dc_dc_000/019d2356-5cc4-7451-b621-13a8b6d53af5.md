## Items to address

### 1. Executor notes prompt is too prescriptive
The prompt says 'say what you verified' so the executor literally starts every note with 'Verified...' — parroting, not reasoning. Fix: show 2-3 varied examples in the JSON block that demonstrate different verification styles (edge case catch, expected behavior confirmation, design choice explanation). Let the agent infer the pattern.

### 2. Perfunctory-note detector for executor_notes
We have _is_perfunctory_ack for sense checks (rejects 'ok', 'done', 'confirmed' etc.) but executor notes have no equivalent quality gate. A note like 'Verified. Done.' would pass today. The nonempty_fields check only ensures non-empty, not non-trivial. Add a quality gate.

### 3. Review prompt should positively frame settled decisions
The review prompt says 'do not re-litigate' settled decisions. It should be framed positively: 'verify the executor implemented these decisions correctly.' The reviewer's job is to check execution honored them, not to question them.

### 4. Remove _is_substantive_reviewer_verdict and unify with _is_perfunctory_ack
We have two separate quality heuristics: _is_perfunctory_ack (word blocklist for sense check acks) and _is_substantive_reviewer_verdict (char/word/unique-word counts for reviewer verdicts). They solve the same problem — detecting rubber stamps. Unify them into one function.

### 5. Critique should not waste iteration cycles on structural nitpicks
In our recent run, FLAG-004 was 'the plan fails the required step-section structure' because a step had prose instead of numbered substeps. This burned an entire critique→gate→revise cycle on formatting, not correctness. The critique prompt should distinguish structural nitpicks from real concerns — structural issues should be minor severity, not significant.

## Phase 2: Unify quality heuristics

### Step 4: Create unified `is_rubber_stamp` function (`megaplan/evaluation.py`)
**Scope:** Medium
1. **Create** a new function `is_rubber_stamp(text: str) -> bool` in `evaluation.py` that combines both checks:
   - First: blocklist check (current `_is_perfunctory_ack` logic — normalize, check `_GENERIC_ACKS`, check length < 10)
   - Second: substance check (current `_is_substantive_reviewer_verdict` logic inverted — if not enough chars/words/unique-words, it's a rubber stamp)
   - Returns `True` if either the text is a known generic ack OR it fails the substance thresholds.
2. **Move** the `_MIN_VERDICT_CHARS`, `_MIN_VERDICT_WORDS`, `_MIN_VERDICT_UNIQUE_WORDS` constants from `handlers.py:553-555` into `evaluation.py` alongside `_GENERIC_ACKS`.
3. **Keep** `_is_perfunctory_ack` as a thin wrapper or alias of `is_rubber_stamp` for backwards compatibility within `validate_execution_evidence` (avoid renaming in test files unnecessarily).
4. **Replace** `_is_substantive_reviewer_verdict` in `handlers.py` with a thin wrapper: `not evaluation.is_rubber_stamp(text)`.
5. **Update** imports in `handlers.py` to pull from `evaluation`.

### Step 5: Add executor_notes quality gate (`megaplan/evaluation.py`, `megaplan/handlers.py`)
**Scope:** Medium
1. **Add** a call to `is_rubber_stamp` in `validate_execution_evidence` (after `evaluation.py:162`) for each task's `executor_notes`, similar to the existing sense-check loop at lines 159-168.
2. **In** the task-processing loop within `validate_execution_evidence`, after checking each task's `executor_notes` is non-empty, add:
   ```python
   if is_rubber_stamp(executor_notes):
       findings.append(f"Task {task_id} executor_notes are perfunctory: {executor_notes.strip()!r}.")
   ```
3. **Note:** The existing `nonempty_fields={"executor_notes"}` check at `handlers.py:1641` remains — it catches empty strings. The new check catches non-empty but trivial notes like "Verified. Done." or "Looks good."

## Phase 3: Tests

### Step 6: Add and update tests (`tests/test_evaluation.py`, `tests/test_megaplan.py`)
**Scope:** Medium
1. **Add** tests for `is_rubber_stamp` in `tests/test_evaluation.py`:
   - Known generic acks ("ok", "verified", "done") → True
   - Short strings (< 10 chars) → True
   - Low-substance ("Verified done good") → True (fails unique word count)
   - Real notes ("Tested edge case where empty array triggers FLAG-006 path") → False
2. **Update** existing `_is_substantive_reviewer_verdict` tests in `tests/test_megaplan.py:1819-1833` to also test through the new wrapper, or migrate them to test `is_rubber_stamp` directly.
3. **Add** a test for `validate_execution_evidence` that includes a task with perfunctory executor_notes and verifies the finding is reported.
4. **Run** `pytest` to verify all existing tests still pass.

### 1. Executor notes prompt is too prescriptive
The prompt says 'say what you verified' so the executor literally starts every note with 'Verified...' — parroting, not reasoning. We have two separate quality heuristics: _is_perfunctory_ack (word blocklist for sense check acks) and _is_substantive_reviewer_verdict (char/word/unique-word counts for reviewer verdicts). They solve the same problem — detecting rubber stamps. Unify them into one function.

In our recent run, FLAG-004 was 'the plan fails the required step-section structure' because a step had prose instead of numbered substeps. This burned an entire critique→gate→revise cycle on formatting, not correctness.
