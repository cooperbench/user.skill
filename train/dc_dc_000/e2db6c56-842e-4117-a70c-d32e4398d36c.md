158	## Why This Split
159	
160	VibeComfy cloud mode already solves the expensive and failure-prone part: GPU pod lifecycle, remote installation, model/template execution, long-running matrix polling, artifact download, and forced termination. Reusing it avoids maintaining two divergent RunPod runners.
161	
162	The worker live harness solves a different problem: it proves the Reigh worker still respects the database, auth, task insertion, task claim, task completion, generation linking, and rollback contracts. Those checks are invisible to a pure VibeComfy matrix.
163	
164	The migration should connect the two layers through shared fixtures, shared artifact schemas, and shared pass/fail gates, not by merging the harnesses.

179	## Fixture Strategy
180	
181	Use deterministic, versioned fixtures for every task type.
182	
183	### Fixture Sources
184	
185	- Existing `reigh-worker/scripts/worker_matrix_cases.json` and `worker_matrix_db_snapshots.json`.
186	- Existing worker live-test anchor images from `scripts/live_test/config.py`.
187	- VibeComfy `workflow_corpus/input/` fixtures where they already match the target template.
188	- New ArtAgents-generated reference images where the current fixture is too ambiguous for semantic grading.
189	
190	### Fixture Generation
191	
192	For semantic tests, each fixture should carry:
193	
194	- `intent`: one-sentence expected output description.
195	- `must_include`: visible objects/attributes that must appear.
196	- `must_not_include`: visible objects/attributes that must not appear.
197	- `reference_roles`: e.g. `style`, `subject`, `start_frame`, `end_frame`, `mask`, `annotation`.
198	- `output_modality`: `image` or `video`.
199	- `rubric`: task-specific scoring instructions.
200	
201	Use ArtAgents `builtin.generate_image` only for missing or weak fixtures. Prefer stable committed fixtures when they already exercise the production path.

203	## Semantic Validation
204	
205	### Image Outputs
206	
207	After output download, call ArtAgents visual understanding:
208	
209	```bash
210	cd ArtAgents
211	python3 -m artagents.packs.builtin.visual_understand.run \
212	  --image /path/to/output.png \
213	  --query "$(cat /path/to/rubric.txt)" \
214	  --mode best \
215	  --detail high \
216	  --out /path/to/semantic.json
217	```
218	
219	The query should request structured JSON:
220	
221	```json
222	{
223	  "description": "short factual description",
224	  "matches_intent": true,
225	  "required_elements_present": [],
226	  "forbidden_elements_present": [],
227	  "reference_preservation": 0.0,
228	  "artifact_severity": "none|minor|major|fatal",
229	  "score": 0,
230	  "reasons": []
231	}
232	```
233	
234	### Video Outputs
235	
236	Sample frames before calling visual understanding:
237	
238	- first frame
239	- 25% frame
240	- midpoint
241	- 75% frame
242	- final frame
243	- additional frames around stitch boundaries for travel/join outputs
244	
245	Use one contact sheet per video so the model can judge temporal coherence cheaply. The ArtAgents visual understand tool already supports multiple images/contact sheets and timestamp labels.
246	
247	Required video checks:
248	
249	- Output duration within allowed tolerance.
250	- Output resolution and frame count match contract.
251	- Start and end frames preserve the intended anchors for travel tasks.
252	- Motion is coherent across sampled frames.
253	- Stitch boundaries are not blank, frozen, or visibly reordered.
254	
255	### Scoring Policy
256	
257	Use a two-tier policy:
258	
259	- `pass`: score >= 4/5, no fatal artifacts, all required elements present.
260	- `human_review_required`: score 3/5 or model uncertainty; keep the output for sampled human review.
261	- `fail`: score <= 2/5, missing required content, forbidden content present, blank output, severe artifacts, or incoherent video.
262	
263	Promotion requires all Layer 1 and Layer 2 structural gates to pass, plus either semantic `pass` or documented human approval for each `human_review_required` case.

309	## Implementation Plan
310	
311	### Step 1: Make VibeComfy Cloud Mode Reigh-Aware
312	
313	Add a Reigh migration matrix entrypoint in VibeComfy, using existing cloud mode:
314	
315	```text
316	vibecomfy/scripts/runpod_reigh_matrix.py
317	```
318	
319	It should:
320	
321	- Reuse `run_pod_detached()` from `scripts/runpod_runner.py`.
322	- Materialize one case per production-used task type/cohort.
323	- Translate Reigh fixture params into VibeComfy template inputs.
324	- Run the same template locally enough to validate before remote execution.
325	- Execute on RunPod.
326	- Download artifacts.
327	- Emit `reigh_results.json` and `reigh_results.md`.
328	
329	Do not add new pod lifecycle code unless `runpod_runner.py` is missing a narrow reusable hook.
330	
331	### Step 2: Add Worker Backend Matrix Mode
332	
333	Extend `reigh-worker/scripts/live_test/main.py` with:
334	
335	```text
336	--backend wgp|vibecomfy|dual
337	--validation-artifacts /path/to/vibecomfy/out/runpod_artifacts/<run>
338	--semantic-validation off|fast|best
339	```
340	
341	The worker harness should:
342	
343	- Start the worker with `REIGH_BACKEND=<backend>`.
344	- Preserve the existing `fresh` and `update` variants.
345	- Run only task types in the selected cohort.
346	- Require VibeComfy telemetry in logs when backend is `vibecomfy`.
347	- Attach semantic validation records to the existing report.
348	
349	### Step 3: Add Artifact Fetch/Resolve
350	
351	Layer 2 currently records `output_location` and linked generation ids. Add a helper that resolves each generation location to a local media file for ArtAgents validation.
352	
353	Resolution order:
354	
355	1. Supabase storage signed URL/download, if the location is remote.
356	2. Worker pod artifact fetch for local-only outputs.
357	3. VibeComfy artifact directory from `--validation-artifacts`, for dual-run comparisons.
358	
359	### Step 4: Add ArtAgents Semantic Scorer
360	
361	Add a small scorer module, preferably outside the worker runtime path:
362	
363	```text
364	reigh-worker/scripts/live_test/semantic_validation.py
365	```
366	
367	It should shell out to ArtAgents, never import ArtAgents into the worker server. The scorer takes local media paths and a rubric JSON, writes raw ArtAgents output, parses the structured JSON answer, and returns `pass`, `human_review_required`, or `fail`.
368	
369	### Step 5: Dual-Run Comparison
370	
371	For high-risk cohorts, run `--backend dual`:
372	
373	- WGP output remains the control.
374	- VibeComfy output is the candidate.
375	- ArtAgents describes both outputs with the same rubric.
376	- The comparison prompt asks whether both satisfy the same intent, not whether they are pixel-identical.
377	
378	Dual-run pass means both outputs are structurally valid and semantically acceptable, and VibeComfy is not materially worse on required elements, reference preservation, or motion coherence.
379	
380	Live canary output-divergence checks require an isolated shadow-run path: the WGP reference run must write to isolated storage and must not trigger completion, billing, uploads to user-visible destinations, or duplicate product side effects. If that isolation is not implemented for a cohort, output divergence remains sampled/offline evidence; automatic canary rollback is limited to latency, OOM, and classified error triggers from `migration-vibecomfy.md` §11.
