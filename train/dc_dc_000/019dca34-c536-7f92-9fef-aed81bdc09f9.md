**Design Critique** VibeComfy already has the right center of gravity: `VibeWorkflow` is the editable IR, JSON is import/export, blocks create graph structure, patches apply policy/topology adjustments, and `compile("api")` is an escape hatch rather than the authoring surface ([docs/authoring.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/authoring.md:3), [vibecomfy/workflow.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/workflow.py:73)). The main risk is that the current API still lets users fall back into stringly node-id programming too easily. **1. Common Workflow Intents** Users will commonly want: - Run a ready template with small overrides: ```python wf = workflow_from_ready("image/z_image") wf.set_prompt("studio product photo of a red chair") result = run_embedded_sync(wf) ``` This aligns with current `set_prompt`, `set_seed`, `set_steps`, `set_model` helpers ([vibecomfy/workflow.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/workflow.py:84)). - Compose multiple Comfy executions in Python: ```python image = await run(t2i(prompt)) video = await run(i2v(start_image=image.outputs[0], prompt=motion_prompt)) audio = await run(t2a(prompt=music_prompt)) final = await run(mux(video=video.outputs[0], audio=audio.outputs[0])) ``` This is where Python orchestration should shine: graph execution boundaries are explicit, outputs are concrete files/handles, and the next graph consumes them. - Graph -> Python -> graph: generate images, inspect/select/crop/rename/score in Python, then feed chosen artifacts into another graph. Arbitrary Python belongs between runs, not inside the Comfy graph abstraction unless represented as an actual custom node. - Reuse subgraphs/custom-node templates without unpacking everything. Current `subgraph.opaque()` is a good escape hatch for UUID class-type subgraphs ([docs/authoring.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/authoring.md:80), [vibecomfy/blocks/subgraph.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/blocks/subgraph.py:23)). - Migrate materialized ready templates into hand-authored templates. The docs say this is intentional because copied API dicts hide authoring decisions ([docs/authoring.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/authoring.md:97)); that should become a guided manual workflow, not an automatic rewrite promise. **2. How The API Should Guide Users** The public happy path should look like: ```python from vibecomfy import Pipeline from vibecomfy.ready import image, video async def build(): async with Pipeline.session() as pipe: still = await pipe.run(image.z_image(prompt="glass sculpture", seed=4)) clip = await pipe.run(video.wan_i2v(start_image=still.image, prompt="slow orbit")) return clip.video ``` Under the hood this can still be `VibeWorkflow`, `RunResult`, and blocks, but the user-facing concepts should be: - `Template`: builds one graph. - `Handle[T]`: typed reference to either a graph output or node output. - `RunResult`: concrete files/artifacts from one execution. - `Pipeline`/ordinary async Python: orchestration across executions. Inside one graph, blocks should return typed handles instead of plain strings. Today `Handles` is immutable and ergonomic, but its values are `Any` and usually node-id strings ([vibecomfy/blocks/__init__.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/blocks/__init__.py:11)). That means users will hit errors late: wrong slot, wrong type, missing node, accidental `"99"` latent. Add lightweight types like `NodeOutput[Image]`, `NodeOutput[Latent]`, `Artifact[ImageFile]`, while preserving `.node_id`, `.slot`, and `str()` compatibility for escape hatches. **3.
