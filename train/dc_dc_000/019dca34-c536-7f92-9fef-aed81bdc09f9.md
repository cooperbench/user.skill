**Design Critique**

VibeComfy already has the right center of gravity: `VibeWorkflow` is the editable IR, JSON is import/export, blocks create graph structure, patches apply policy/topology adjustments, and `compile("api")` is an escape hatch rather than the authoring surface ([docs/authoring.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/authoring.md:3), [vibecomfy/workflow.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/workflow.py:73)). The main risk is that the current API still lets users fall back into stringly node-id programming too easily.

**1. Common Workflow Intents**

Users will commonly want:

- Run a ready template with small overrides:
  ```python
  wf = workflow_from_ready("image/z_image")
  wf.set_prompt("studio product photo of a red chair")
  result = run_embedded_sync(wf)
  ```
  This aligns with current `set_prompt`, `set_seed`, `set_steps`, `set_model` helpers ([vibecomfy/workflow.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/workflow.py:84)).

- Compose multiple Comfy executions in Python:
  ```python
  image = await run(t2i(prompt))
  video = await run(i2v(start_image=image.outputs[0], prompt=motion_prompt))
  audio = await run(t2a(prompt=music_prompt))
  final = await run(mux(video=video.outputs[0], audio=audio.outputs[0]))
  ```
  This is where Python orchestration should shine: graph execution boundaries are explicit, outputs are concrete files/handles, and the next graph consumes them.

- Graph -> Python -> graph:
  generate images, inspect/select/crop/rename/score in Python, then feed chosen artifacts into another graph. Arbitrary Python belongs between runs, not inside the Comfy graph abstraction unless represented as an actual custom node.

- Reuse subgraphs/custom-node templates without unpacking everything. Current `subgraph.opaque()` is a good escape hatch for UUID class-type subgraphs ([docs/authoring.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/authoring.md:80), [vibecomfy/blocks/subgraph.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/blocks/subgraph.py:23)).

- Migrate materialized ready templates into hand-authored templates. The docs say this is intentional because copied API dicts hide authoring decisions ([docs/authoring.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/authoring.md:97)); that should become a guided manual workflow, not an automatic rewrite promise.

**2. How The API Should Guide Users**

The public happy path should look like:

```python
from vibecomfy import Pipeline
from vibecomfy.ready import image, video

async def build():
    async with Pipeline.session() as pipe:
        still = await pipe.run(image.z_image(prompt="glass sculpture", seed=4))
        clip = await pipe.run(video.wan_i2v(start_image=still.image, prompt="slow orbit"))
        return clip.video
```

Under the hood this can still be `VibeWorkflow`, `RunResult`, and blocks, but the user-facing concepts should be:

- `Template`: builds one graph.
- `Handle[T]`: typed reference to either a graph output or node output.
- `RunResult`: concrete files/artifacts from one execution.
- `Pipeline`/ordinary async Python: orchestration across executions.

Inside one graph, blocks should return typed handles instead of plain strings. Today `Handles` is immutable and ergonomic, but its values are `Any` and usually node-id strings ([vibecomfy/blocks/__init__.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/blocks/__init__.py:11)). That means users will hit errors late: wrong slot, wrong type, missing node, accidental `"99"` latent. Add lightweight types like `NodeOutput[Image]`, `NodeOutput[Latent]`, `Artifact[ImageFile]`, while preserving `.node_id`, `.slot`, and `str()` compatibility for escape hatches.

**3. First-Class vs Escape Hatch**

First-class:

- Ready templates as Python builders.
- Blocks for reusable graph structure.
- Patches for policy/topology decoration, matching the current rule: “changes handles -> new template; decorates handles -> patch” ([docs/authoring.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/authoring.md:42)).
- Typed model/custom-node requirements.
- Multi-run Python orchestration.
- Artifact passing between graph executions.
- Runtime/session configuration using typed `SessionConfig`.

Escape hatch:

- Raw `wf.add_node`, `wf.connect`, `disconnect`, `replace_edge`.
- Raw node refs like `"12.0"`.
- `subgraph.opaque()`.
- `compile("api")` and `compile("graphbuilder")`.
- Direct API dict import/export.
- Raw HiddenSwitch config keys via `SessionConfig.extra`.

The key is not hiding escape hatches. It is making them visually obvious and lintable.

**4. Likely Failure Modes**

Users will hit these:

- Confusing ready-template with runtime-green. The repo already calls this out: ready Python source is not proof of GPU execution ([docs/structural_issues.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/structural_issues.md:19)).
- Passing a graph node handle where a completed file artifact is required.
- Expecting `wf.set_prompt()` to affect custom video/audio templates whose prompt input is not registered as `"prompt"`.
- Forgetting `finalize_metadata()` after manual edits, so requirements/inputs/outputs are stale ([docs/authoring.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/authoring.md:70)).
- Widget-index fragility when custom nodes change hidden widgets; this is already documented as a converter risk ([docs/structural_issues.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/structural_issues.md:48)).
- Assuming HTTP queue success means output success. The docs explicitly say HTTP queue submission is not enough ([docs/structural_issues.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/structural_issues.md:174)).
- Custom node installed but wrong commit or changed input contract.
- Model file present but wrong path, wrong alias, zero bytes, or license-gated download.

**5. Guardrails, Lints, Doctor Messages**

Add a DSL-aware lint layer beyond schema validation:

- `untyped_raw_ref`: “`latent='99'` is a raw node ref; use a typed handle or `raw_ref('99.0')`.”
- `stale_metadata`: “workflow nodes changed after last finalize; call `wf.finalize_metadata()`.”
- `unbound_input_unused`: “`set_prompt()` stored unbound input; no registered prompt input was found.”
- `artifact_vs_node_handle`: “graph node output cannot be passed to next run until the graph has executed.”
- `ready_not_runtime_green`: “template imports, but no runtime-green evidence is recorded.”
- `widget_index_escape`: “node uses positional widget_N fields; prefer named block settings or schema-backed input.”
- `unknown_custom_node_commit`: “pack is known but not pinned/installed at expected commit.”
- `http_queue_only`: “server run queued prompt; use embedded/baseline execution for completed-output proof.”

Current doctor already reports scratchpad import/build, validation, missing models, unknown classes, and suggested packs ([vibecomfy/commands/doctor.py](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/vibecomfy/commands/doctor.py:18)). It should grow toward the finer distinctions already requested in `structural_issues`: missing package, installed package but missing class, changed input contract, missing model, undersized model ([docs/structural_issues.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/structural_issues.md:99)).

**6. Custom-Node And Model Dependency UX**

Treat a ready template’s environment as a lockable unit:

```python
requirements = wf.requirements()
requirements.install_plan()
requirements.assert_ready()
```

This should include:

- custom node pack name, repo, commit, pip packages
- model name, URL, expected subdir, optional size/hash
- input fixture/media requirements
- runtime flags and VRAM profile
- compatibility patches applied

The repo already has `custom_nodes.lock` and docs for pinned KJNodes/WanVideoWrapper ([docs/custom_nodes.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/custom_nodes.md:3)), plus a catalog-backed install plan ([docs/custom_nodes.md](/Users/user_c042661f/Documents/reigh-workspace/vibecomfy/docs/custom_nodes.md:12)). The missing piece is reload UX: after install/update, tell the user whether they must restart the Comfy server, reload node definitions, clear schema cache, or re-run `sources sync`.

**7. Where Arbitrary Python Belongs**

Arbitrary Python belongs at orchestration boundaries:

- build graph A
- run graph A
- inspect/select/transform files in Python
- build graph B using those artifacts
- run graph B

Inside a graph builder, Python should be limited to deterministic graph construction: choosing blocks, parameters, branches, and patches. If runtime computation must happen inside Comfy execution, it should be a custom node dependency, not hidden Python in the DSL.

This preserves debuggability: every queued graph remains inspectable as `VibeWorkflow` and API JSON.

**8. Elegance With Debuggability**

Keep three layers, all inspectable:

- High-level pipeline/template API for normal users.
- `VibeWorkflow`/blocks/patches for authors.
- Raw API dict/custom node/subgraph escape hatches for experts.

The elegant API should make the common path short, but every object should reveal its lower layer:

```python
template.workflow          # VibeWorkflow
handle.node_id, handle.slot
result.outputs
wf.compile("api")
wf.explain()
wf.doctor()
```

The most important design move is typed handles plus explicit run boundaries. That keeps Python orchestration clean, enables graph -> Python -> graph composition, prevents stringly wiring from becoming the default, and still leaves the current low-level surfaces available when users need them.
