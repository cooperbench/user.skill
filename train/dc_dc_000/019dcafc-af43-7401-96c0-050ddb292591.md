# Implementation Plan: `vibecomfy.runpod` package — one-call RunPod template runner

## Overview
Lift the ad-hoc `scripts/runpod_runner.py` glue into a clean importable `vibecomfy.runpod` package so any caller can do `async with RunPodTemplate.launch(template_id, gpu=...) as result:` and get a typed `RunResult` back. Move `PodGuard` and the `runpod_lifecycle` import helper into the package, declare `runpod-lifecycle` as a real dependency (preserving the env-var fallback for dev), add a thin (~<100 line) remote script that runs one ready template and emits a JSON result, and scaffold one opt-in `@pytest.mark.gpu` test for Flux Klein 4B T2I (do NOT execute it in this run — it burns RunPod credentials/budget).

Constraints baked into this plan:
- **Zero file overlap with P1.** P1 owns `vibecomfy/blocks/`, `vibecomfy/workflow.py`, `vibecomfy/runtime/session.py`, `tests/smoke/test_p1_runpod.py`. New test goes under `tests/gpu/`, never `tests/smoke/`.
- **Backward compatibility.** `scripts/runpod_runner.py`, `scripts/runpod_validate.py`, `scripts/runpod_corpus_matrix.py`, `scripts/runpod_model_matrix.py` import `PodGuard`, `run_pod`, `run_pod_detached`, `_runpod_lifecycle`, `ROOT`, `REMOTE_ROOT` from `scripts.runpod_runner`. All those names must keep resolving from that module.
- **Out of scope.** Don't rewrite `scripts/runpod_corpus_matrix.py`'s 750-line `_remote_script`; don't redo `vibecomfy/commands/runpod.py` discovery (touch only if a clean import lands cleanly). Don't execute the GPU test.

Repository shape (relevant parts):
- `scripts/runpod_runner.py:1-376` — current home of `PodGuard`, `_runpod_lifecycle()`, `runpod_lifecycle_root()`, `run_pod()`, `run_pod_detached()`, plus tarball/SFTP upload helpers.

## Phase 2: `RunResult`, `RunPodTemplate`, and the small remote script

### Step 4: Define `RunResult` (`vibecomfy/runpod/result.py`)
**Scope:** Small
1. **Create** `vibecomfy/runpod/result.py` with a frozen dataclass:
   ```python
   from dataclasses import dataclass, field
   from pathlib import Path
   from typing import Literal

   Status = Literal["ok", "error", "timeout"]

   @dataclass(frozen=True)
   class RunResult:
       status: Status
       template_id: str
       pod_id: str
       elapsed: float
       media_files: list[Path]
       artifact_dir: Path
       logs: Path
       error_message: str | None = None
   ```
2. **Add** a `from_remote_payload(...)` classmethod that takes the JSON blob produced by the remote script + the local `artifact_dir` + `logs` path + `pod_id` + `template_id` and returns a `RunResult`. Map `media_files` to absolute local `Path` objects (after the SFTP download in Step 6).

### Step 5: Build the small remote script (`vibecomfy/runpod/_remote.py`)
**Scope:** Medium
1. **Create** `vibecomfy/runpod/_remote.py` exposing one function `build_remote_script(template_id: str, *, remote_root: str, payload_path: str, output_dir: str) -> str`.
2. **Render** a bash script that:
   1. `set -e`, `cd $REMOTE_ROOT`.
   2. `pip install -e '.[dev,runpod-local]'` and `pip install 'comfyui@git+https://github.com/hiddenswitch/ComfyUI.git' 'comfy-script[default]'` (mirroring `scripts/runpod_validate.py:13`).
   3. Runs an inline `python - <<'PY' ... PY` block that:
      - Calls `vibecomfy.registry.ready.workflow_from_ready(template_id)`.
      - Calls `workflow.validate()`; on failure, writes a JSON payload with `status="error"` and the validation message and exits 1.
      - Compiles to API graph and executes it via the embedded runtime exactly like `scripts/runpod_validate.py:22-26` (e.g. through `vibecomfy.cli run` invoked as a subprocess, or directly via `vibecomfy.runtime.run` if simpler — pick the lowest-friction path while staying in-process).
      - Walks `output/` (and any other known media targets) for image/video/audio files created since the run started; collects them into a list.
      - Writes a JSON blob to `$payload_path`: `{status, template_id, pod_id, elapsed_seconds, media_files: [...relative paths under remote_root...], error_message}`.
   4. Always emits the JSON blob (even on error) so the local side has something to parse.
3. **Target** under 100 lines (the brief's bar). Keep the bash thin; let the inline Python carry the logic. Add a one-line module docstring naming the contract: "Renders the per-template remote script. Inputs: template_id, remote_root, payload_path. Output: writes a JSON RunResult payload to payload_path; never longer than ~100 lines of remote bash/python."

### Step 6: Build `RunPodTemplate` (`vibecomfy/runpod/runner.py`)
**Scope:** Medium
1. **Create** `vibecomfy/runpod/runner.py` with class `RunPodTemplate` that holds: `template_id`, `gpu`, `name_prefix`, `timeout`, `exclude` set, `pod_guard`, `pod`, `_artifact_dir`, `_logs_path`, `_result`.
2. **Expose** classmethod `launch(cls, template_id: str, *, gpu: str | None = None, timeout: int = 1800, name_prefix: str = "vibecomfy-template", exclude: set[str] | None = None) -> "_LaunchCtx"`. Returning value is an async-context-manager helper that wraps the lifecycle so the public surface matches the doc:
   ```python
   async with RunPodTemplate.launch("image/flux2_klein_4b_t2i", gpu="RTX 4090") as result:
       ...
   ```
3. **Implement** the context manager (`__aenter__` / `__aexit__`):
   - In `__aenter__`: instantiate `PodGuard` (passing the GPU through via `os.environ['VIBECOMFY_RUNPOD_GPU'] = gpu` for the duration of the call, or by extending `PodGuard.__init__` to accept a `gpu_type` override — prefer the latter; it's the cleanest seam and matches what callers expect). `await guard.launch()`, `await pod.wait_ready(timeout=300)`, upload the local checkout via the existing helpers re-exported from `scripts.runpod_runner` (or, cleaner, lift `upload_dir`/`should_skip` into `vibecomfy.runpod.upload` — see Step 7), run the Step 5 remote script over SSH with `pod.exec_ssh`, SFTP the JSON payload + collected media files down to `out/runpod_template/<ts>-<template-id-slug>/`, return a `RunResult`.
   - In `__aexit__`: `await guard.terminate()` in a `finally`, log `terminated_launched_pod=true`.
4. **Stream** stdout/stderr from `pod.exec_ssh` to a local log file at `<artifact_dir>/run.log`; expose that path as `RunResult.logs`.
5. **On timeout** of the SSH exec call, return `RunResult(status="timeout", ..., error_message="ssh exec exceeded timeout")` and still terminate the pod in `__aexit__`.

### Step 7: Optionally lift upload helpers (`vibecomfy/runpod/upload.py`)
