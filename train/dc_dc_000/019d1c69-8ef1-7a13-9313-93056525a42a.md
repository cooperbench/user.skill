        # Implementation Plan: CSS Module → Tailwind Migration

## Overview

The site has 21 CSS module files (~2,710 lines) plus global.css (189 lines). Tailwind is configured with CSS custom property references but barely used (2 lines in `tailwind.css`). The goal is to move **one-off layout/spacing/simple typography** into Tailwind classes while keeping CSS modules for anything complex (animations, keyframes, pseudo-elements, nth-child, multi-state hover/expansion, `:global()` selectors tied to JS class names).

**Key constraint:** Many components use `:global(.className)` selectors that JS/hooks depend on — those class names must remain as string `className` attributes, but Tailwind can be composed alongside them via template literals or `clsx`.

After auditing all 21 files, **11 files have no convertible rules** (all complex) and **10 files have extractable simple rules**. Total CSS removed: ~80-100 rules across ~10 files. Two files (Home, MuteList) become empty and can be deleted entirely.
