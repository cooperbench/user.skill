# Problem

Model staging and aliasing knowledge is currently spread across:

1. **Four near-identical heredoc Python blocks** in `scripts/runpod_corpus_matrix.py` (lines ~380, ~447, ~521, ~647) that each define a local `materialize_model(repo, filename, targets, min_size)` function and a hardcoded `downloads = [...]` list. Adding a new model means editing all four (or remembering which one applies). Drift is inevitable.

2. **Inline name-normalization rules** in `scripts/runpod_matrix_remote.py` (lines ~143–195) that hardcode "if value is `ltx-2.3-22b-dev.safetensors` map it to X" branching — one branch per known alias. Adding a new model that ships under multiple node-pack names means appending another `elif` branch.

3. **Module-level constants** at the top of `scripts/runpod_matrix_remote.py` (lines 12–19) — `LTX_CHECKPOINT`, `LTX_TEXT_ENCODER`, etc. — that pin canonical names per model. These are referenced from the normalization branches.

4. **Workflow-embedded URLs** that the materializer already extracts via `vibecomfy/model_assets.py` (this work is done; do not redo it). But the *staging* path on RunPod still doesn't read from those — it uses the hardcoded heredoc lists instead.

The result: a "downloaded but invisible" failure class (entry `model_layout` in `docs/hiddenswitch_incompatibilities.md`) where a model is correctly downloaded but lives at the wrong path for the node pack that needs it. Each new node pack adds another inline branch instead of declaring its expected paths once.

# Goal

One YAML file that staging and normalization both consume. Five mechanical steps:

1. Define a YAML schema: canonical model id → source (HF repo + filename or generic URL) → list of `(node_pack, target_path)` pairs that should be created via hardlink/symlink → minimum size for sanity check → optional list of accepted alias names that should be normalized to the canonical filename.
2. Author the registry by extracting the existing four `downloads = [...]` lists and the existing alias branches from the two scripts. Verify exhaustively against current matrix behavior.
3. Replace the four heredoc `materialize_model` blocks in `runpod_corpus_matrix.py` with a single loader that reads the YAML and runs the same `hardlink-or-symlink, size-check, fail-loud` logic.
4. Replace the alias-normalization branches in `runpod_matrix_remote.py` with a single lookup against the YAML's `aliases` field.
5. Add a one-shot `vibecomfy models stage <registry.yaml>` CLI command that any local dev box (not just RunPod) can use to materialize the registry into a target models root.

The registry is **append-only and flat**. No resolver service. No background daemon. No precedence rules across multiple registries. One file, in repo, edited via PR.

## Overview
Collapse the four duplicated `materialize_model` heredoc blocks in `scripts/runpod_corpus_matrix.py` and the inline alias-normalization rules in `scripts/runpod_matrix_remote.py` into a single declarative YAML registry consumed by both staging and normalization. No resolver service, no runtime indirection — one flat file in repo, edited via PR.

The bar is **bit-for-bit behavioral parity** with the current matrix run. Three behaviors flagged during critique that the schema and loader must preserve:
- **Restaging is legal.** The current heredocs unlink any existing target before linking, and at least one path (`models/vae/flux2-vae.safetensors`) is intentionally restaged across phases by different sources. The loader must mirror this — not raise on a "collision" that the current code overwrites.
- **Alias normalization is more than exact-string match.** `runpod_matrix_remote.py` already does suffix matches (any value ending in `/taeltx2_3.safetensors`) and multi-token-contains-with-basename-strip (`ltx-2.3-22b-distilled` + `transformer_only` → basename). The schema needs structured matchers, not just an `aliases:` string list.
- **Some entries are conditionally staged.** `Lightricks/LTX-2.3-22b-IC-LoRA-HDR` is only staged when `HF_TOKEN` is set and the scope is not `ltx_official_public` or `ltx_iclora_public`. The schema needs per-entry `gates:` so the loader skips (with a log message) rather than failing or always-downloading.

A `--legacy-staging` escape hatch ships in the same PR and is removed after one passing matrix run.

### Step 2: Define the YAML schema and add the loader (`vibecomfy/registry/__init__.py`, `vibecomfy/registry/models_loader.py`)
**Scope:** Medium

2. **Define** the schema. Per entry:
   ```yaml
   - id: ltx_preview_vae
     source: { kind: huggingface, repo: ..., filename: taeltx2_3.safetensors }
     min_size: 100_000_000
     targets:
       - { node_pack: kjnodes, path: models/vae_approx/taeltx2_3.safetensors }
     aliases: [taeltx2_3.safetensors]                # exact-string matches
     alias_match:                                     # structured matchers
       - kind: suffix
         value: /taeltx2_3.safetensors                # any slash-normalized value ending with this → canonical filename
       - kind: contains_all_strip_path

   ```
   Three matcher kinds in v1 (extend later only if needed): `exact`, `suffix` (after slash-normalization), `contains_all_strip_path` (returns `os.path.basename(value)` rather than a fixed canonical). Two gate kinds in v1: `env_required`, `scope_excluded`.
3. **Create** `vibecomfy/registry/models_loader.py` exposing:
   - Frozen dataclasses: `ModelEntry`, `Source`, `Target`, `AliasMatch`, `Gate`.
   - `load_registry(path) -> list[ModelEntry]` — parses YAML, validates required fields, fails loud on duplicate ids and on duplicate exact aliases, caches on a module-level dict keyed by resolved absolute path.
   - `stage_entry(entry, *, models_root, source_path) -> list[Path]` — for each `target`: ensure parent dir, **`os.path.lexists(target_full)` → unlink first** (mirroring heredoc behavior; this includes regular files, symlinks, and hardlinks), then `os.link(source_path, target_full)`, fall back to `os.symlink` on `OSError(EXDEV)`, then `os.stat` and assert `>= entry.min_size` raising `RegistrySizeError` on mismatch. Only raise `RegistryCollisionError` if `unlink` itself fails (e.g., target is a directory or permission denied) — never on the mere existence of a prior file. Return staged paths.
   - `stage_many(entries, *, models_root, ids, scope, downloader, log) -> None` — for each selected entry: evaluate `gates` against `(os.environ, scope)`; on gate-fail, call `log.skipped(entry, reason)` and continue (no download, no stage). Otherwise call `downloader(entry)` then `stage_entry`.
   - `normalize_alias(value, *, registry) -> str | None` — walks entries in declaration order. For each entry, checks (a) exact `aliases` membership, (b) each `alias_match` rule. First hit wins. Returns the canonical filename (`exact`/`suffix`) or `os.path.basename(value)` (`contains_all_strip_path`). Memoizes the precomputed exact-alias index on a sibling cache dict keyed by `id(registry)`. **V1: not node-pack-aware** (per brief's open-question lean).
   - `evaluate_gates(entry, *, env, scope) -> tuple[bool, str | None]` — returns `(allow, reason)`. `env_required` requires the named var present and non-empty; `scope_excluded` requires `scope not in values`.
