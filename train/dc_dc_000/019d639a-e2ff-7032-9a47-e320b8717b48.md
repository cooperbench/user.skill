        # Implementation Plan: Megaplan Skill → Subagent Architecture

## Overview

**Current state:** The megaplan skill (`.claude/skills/megaplan.md`) is a set of instructions that tell the main Claude Code conversation how to orchestrate `megaplan` CLI calls. Each phase (init, plan, critique, gate, revise, finalize, execute, review) runs as a separate Bash tool call **in the main context window**. This means the main conversation accumulates all the CLI output, prompts, and orchestration reasoning across every phase — polluting context and making auto-approve runs require babysitting.

**Goal:** Move the entire workflow into a Claude Code Agent (subagent). The skill becomes a thin launcher that:
1. Triages the request (same as today)
2. Asks mode + robustness (same as today)  
3. Launches a single Agent with a comprehensive prompt containing all workflow logic
4. Handles "breakpoint returns" — moments where the agent pauses and returns to the main conversation for user input (gate escalate, execute approval in review mode)
5. Relays user answers back to the agent via SendMessage
6. Reports the final result

**Key constraint:** The megaplan CLI, handlers, workers, and state machine are untouched. Only the Claude Code skill file changes. The CLI is already a clean state machine with `next_step` routing — the agent just drives it instead of the main conversation.

**Reference pattern:** The MegaLoop engine (`megaplan/loop/engine.py`) demonstrates the autonomous loop: `while should_continue → run phase → save state → check breakpoints`. The agent replicates this pattern but uses Claude Code's Agent tool + SendMessage instead of subprocess + feedback-injection.

### Step 3: Handle auto-approve vs review mode divergence
**Scope:** Small
1. **Auto-approve mode:** Agent runs fully autonomously. The Agent tool call completes when the workflow reaches STATE_DONE or a terminal state. Main conversation just reports the result. No SendMessage needed.
2. **Review mode:** Agent runs until the gate-to-execute breakpoint. Returns to main conversation. User approves/rejects. Main conversation sends decision via SendMessage. Agent continues. This may happen multiple times if review triggers rework cycles.
3. **Gate ESCALATE (either mode):** Agent always returns with breakpoint. User decides force-proceed/replan/abort. Main conversation relays via SendMessage.

**Scope:** Small

2. **Error recovery:** If a CLI call fails, the agent should:

   - Check `megaplan status --plan <name>` for state
   - Retry once if transient, otherwise return a breakpoint with the error for user guidance
3. **Timeout handling:** Execute phase uses `timeout: 600000` (10 min). If it times out, agent checks status and continues with next batch or reports failure.
