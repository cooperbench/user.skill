        # Implementation Plan: Unify Clip Edge Resize Session

## Overview
The current resize flow is structurally split across three session kinds in [TimelineCanvas.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx#L55), three update branches in [TimelineCanvas.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx#L711), three end branches in [TimelineCanvas.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx#L854), and a separate outer-edge commit closure in [useClipResize.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useClipResize.ts#L423). Shared math is already extracted in [resize-math.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/lib/resize-math.ts#L38), so the missing cleanup is to collapse session lifecycle and commit wiring, not to invent new resize math.

Two behaviors must be preserved carefully during the collapse: (a) snap-to-neighbor for both free clips ([TimelineCanvas.tsx:805](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx#L805)) and outer-group edges against non-group siblings ([TimelineCanvas.tsx:757](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx#L757)), and (b) the existing editor callback surface (`onActionResizeEnd`, `startGroupEdgeResize`) which is too narrow to carry the unified payload. Both are addressed explicitly below.
