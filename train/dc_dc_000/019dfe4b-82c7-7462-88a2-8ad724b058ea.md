No files edited. I inspected the runner, bot instructions, tool gates, messaging, and scheduled handlers.

**Likely Root Cause**
High confidence: the leak can happen in the `respond` step after `send_message_part` already sent the real user-facing message.

Flow:

1. Assistant uses `send_message_part` to send something like “I’ll check in at 9pm.”
2. Anthropic then returns final text for the same `respond` step, e.g. `Now at the schedule step.`
3. In [app/services/agentic.py](/Users/user_c042661f/Documents/Veas/app/services/agentic.py:754), the runner treats any non-empty `step_text` from `respond` as another final outbound.
4. It only suppresses exact duplicates of prior `send_message_part` content at [app/services/agentic.py](/Users/user_c042661f/Documents/Veas/app/services/agentic.py:776). `Now at the schedule step.` is not a duplicate, so it can be sent.

The actual `schedule` step is probably not directly sending it: schedule-step tools are limited to scheduling tools in [app/services/tools/registry.py](/Users/user_c042661f/Documents/Veas/app/services/tools/registry.py:214), and `send_message_part` is not allowed there.

**Contributing Issues**
The text safety filter does not classify step-transition narration like `Now at the schedule step.`, `Next step: schedule`, or `Current step: record` as internal. See [app/services/text_safety.py](/Users/user_c042661f/Documents/Veas/app/services/text_safety.py:7).

`send_message_part` also relies on that same filter before sending at [app/services/tools/read_tools.py](/Users/user_c042661f/Documents/Veas/app/services/tools/read_tools.py:195), so a model could directly send that process narration during `respond`.

Scheduled handlers are relevant but probably secondary. A `checkin` job runs `run_agentic_job` at [app/services/scheduled_job_handlers.py](/Users/user_c042661f/Documents/Veas/app/services/scheduled_job_handlers.py:98); a `scheduled_task` job runs the standard adaptive plan at [app/services/scheduled_job_handlers.py](/Users/user_c042661f/Documents/Veas/app/services/scheduled_job_handlers.py:160). If the leak occurred at 9pm rather than immediately, the same `send_message_part` plus final-text leak can happen inside that scheduled job’s `respond` step.

**Concrete Fixes**
1. In `agentic.py`, if `ctx.sent_message_parts` is non-empty, do not send additional final `assistant_text` from the same `respond` step. Treat it as reasoning only, except maybe reaction directives if desired.
2. Add internal-process patterns for `schedule step`, `record step`, `read step`, `current step`, `next step`, `turn plan`, `now at the ... step`, etc.
3. Keep the tool guard in `send_message_part`, but strengthen it with the same expanded process-text detection.
4. Tighten the mediator instruction after `send_message_part`: once all intended bubbles are sent, return an empty assistant response.

**Tests To Add**
1. `test_run_agentic_suppresses_final_text_after_send_message_part`: fake `respond` calls `send_message_part("I'll check in at 9pm.")` then returns `"Now at the schedule step."`; assert only the first message is sent.
2. `test_clean_user_facing_text_drops_step_transition_leak`: assert `clean_user_facing_text("Now at the schedule step.") == ""`.
3. `test_send_message_part_withholds_step_transition_text`: direct tool call with `"Now at the schedule step."` returns `withheld`.
4. Scheduled-job regression: a `scheduled_task` or `checkin` turn using incremental send plus final process text should not emit the final process text.
