        ### Suggested Approach
        **Phase 1: Create the state machine and unified pointer coordinator**

Create a new `usePointerCoordinator.ts` hook that owns ALL timeline pointer events via a single set of window listeners managed by AbortController. It implements an explicit state machine:
- **idle**: listening for pointerdown. Determines target (clip, empty area, label) and transitions to pending-clip-drag or pending-marquee.
- **pending-clip-drag**: pointer is down on a clip but hasn't moved past threshold. On threshold cross → dragging. On pointerup without threshold → handle as click (select/toggle).
- **pending-marquee**: pointer is down on empty area. On threshold cross → marquee-active.
- **dragging**: clip drag in progress. Calls coordinator.update(), snapDrag(), auto-scroll. On pointerup → commit (existing move/applyEdit logic). On pointercancel → abort.
- **marquee-active**: marquee selection in progress. Existing useMarqueeSelect logic. On pointerup → commit selection. On pointercancel → abort.

Each state transition creates a new AbortController for its listeners. When a session ends (any path to idle), `controller.abort()` atomically removes all listeners — no manual removeEventListener, no leaked sessions.

The state machine replaces gestureOwner entirely for clip/marquee coordination. Other gesture owners (trim, ruler, preview) can still use the existing gestureOwner mechanism externally, with the coordinator checking `gestureOwner === 'none'` before claiming.

**Phase 2: Extract DragSession into derived state**

Split the current 24-field DragSession into:
1. **DragIntent** (immutable, set on pointerdown): clipId, sourceRowId, sourceKind, draggedClipIds, clipOffsets, groupDragEntry, transactionId, inputModality, wasSelectedOnPointerDown, ctrlKey, metaKey
2. **PointerState** (updated on pointermove): clientX, clientY, hasCrossedThreshold
3. **Derived values** (pure functions, not stored): ghost position = f(pointerState, dragIntent, timelineData), snapped start = f(dropPosition, siblings, snapThreshold), cross-track active = f(pointerState.dy, threshold)

This eliminates the mutable grab-bag and makes the system statically traceable.

**Phase 3: Replace pointer capture with coordinator ownership**

Remove all setPointerCapture/releasePointerCapture calls. The coordinator already listens on window, so it receives all pointer events regardless. The state machine's ownership model (only one active gesture) replaces pointer capture's exclusivity guarantee.

**Phase 4: Change ClipAction button → div[role=button]**

In ClipAction.tsx, change `<button>` to `<div role="button" tabIndex={0}>`. Remove the `onPointerDown stopPropagation` since the unified coordinator no longer needs capture-phase ordering tricks. Keep keyboard handlers (Enter/Space for activation) on the div for a11y.

**Phase 5: Remove ref-of-ref pattern**

The unified coordinator hook can use `useRef` for truly stable values and `useCallback` with explicit deps for functions. The key insight: since the hook manages all pointer events internally, it doesn't need a never-re-running useEffect. Instead, use event handler refs (a single `handlersRef` object) updated on each render, with stable window listener functions that read from the ref.

**Phase 6: Replace pendingOps with dragState check**

Expose `isDragging` (derived from state machine state !== idle) as a signal for the save scheduler instead of the manual counter. Update useTimelineCommit to check this signal.

**Testing strategy**: Run existing tests after each phase. The tests mock the DOM and fire pointer events directly — they should work with the new hook as long as the external contract (pendingOps, interactionState, selectClip/moveClipToRow/applyEdit calls) is preserved. Some tests may need minor updates to account for the changed hook signature or the removal of pointer capture.

## Overview

The video editor's clip drag system (`useClipDrag.ts`, 759 lines) has accumulated significant complexity: a capture-phase document listener competing with `useMarqueeSelect`'s bubble-phase handler, pointer capture that races with React re-renders, a native `<button>` element whose behaviors fight the custom pointer system, a 24-field mutable `DragSession` object, and 15 ref-of-ref indirections smuggling values into a never-re-running `useEffect`.

The refactor replaces this with: an explicit state machine (`idle → pending → dragging → idle`), `AbortController`-based listener cleanup, `div[role=button]` instead of native button, no pointer capture, and a consolidated ref pattern. The two hooks (`useClipDrag` + `useMarqueeSelect`) remain separate — they are genuinely different concerns — but the coordination between them becomes simpler once the capture-phase hack and `stopPropagation` are removed.

**Key constraint**: `pendingOpsRef` is shared with resize operations in `TimelineCanvas`, so it cannot be replaced with a simple `isDragging` boolean. We keep `pendingOpsRef` as the external interface but make its lifecycle airtight.

**Key constraint**: All 17 tests in `useClipDrag.test.tsx` define the behavioral contract. Tests fire `pointerDown` directly on clip elements and `pointerMove`/`pointerUp` on `window` — this pattern will still work with a bubble-phase wrapper listener since events bubble from clip → wrapper.

        **Phase 1: Create the state machine and unified pointer coordinator**

Create a new `usePointerCoordinator.ts` hook that owns ALL timeline pointer events via a single set of window listeners managed by AbortController. It implements an explicit state machine:
- **idle**: listening for pointerdown. Determines target (clip, empty area, label) and transitions to pending-clip-drag or pending-marquee.
- **pending-clip-drag**: pointer is down on a clip but hasn't moved past threshold. On threshold cross → dragging. On pointerup without threshold → handle as click (select/toggle).
- **pending-marquee**: pointer is down on empty area. On threshold cross → marquee-active.
- **dragging**: clip drag in progress. Calls coordinator.update(), snapDrag(), auto-scroll. On pointerup → commit (existing move/applyEdit logic). On pointercancel → abort.
- **marquee-active**: marquee selection in progress. Existing useMarqueeSelect logic. On pointerup → commit selection. On pointercancel → abort.

Each state transition creates a new AbortController for its listeners. When a session ends (any path to idle), `controller.abort()` atomically removes all listeners — no manual removeEventListener, no leaked sessions.

The state machine replaces gestureOwner entirely for clip/marquee coordination. Other gesture owners (trim, ruler, preview) can still use the existing gestureOwner mechanism externally, with the coordinator checking `gestureOwner === 'none'` before claiming.
