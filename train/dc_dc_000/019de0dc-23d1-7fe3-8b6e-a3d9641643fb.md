**Current Flow**

On the first inbound message from a whitelisted user, `process_inbound` upserts them into `users` with `onboarding_state='pending'` by default, then stores the inbound message.

If their first text is exactly a simple greeting after normalization, like `hi`, `hello`, `hey`, `good morning`, etc.:

1. The inbound message is inserted as `raw`.
2. `claim_onboarding_welcome()` flips that user from `pending` to `welcomed`.
3. The bot sends the static `WELCOME_MESSAGE` from [inbound.py](/Users/user_c042661f/Documents/Veas/app/services/inbound.py:23).
4. The inbound greeting is marked `processed`.
5. No agentic/LLM turn runs.

The exact welcome text is:

> Hi, I'm here as a reflection and mediation assistant for the two of you. I'm not a therapist, and I'll sometimes get things wrong, so please correct me. Message me naturally; I'll help reflect, track context, and occasionally ask a clarifying question.

If their first text is not a greeting, for example `I’m really upset about last night`:

1. The inbound message is inserted.
2. The code still calls `claim_onboarding_welcome()` before checking greeting-ness, so the user is flipped to `welcomed`.
3. Because the text is not greeting-only, no static welcome is sent.
4. The message is added to the coalescer.
5. The normal agentic turn runs, using the updated system prompt with the new relational/Orna-inspired voice.

So the persona change affects that first real agent response, but not the static welcome message.

**Media First**

For first `audio`, `image`, or `document` messages:

1. The inbound media row is inserted.
2. If the system is not paused and the user is still `pending`, they are flipped to `welcomed`.
3. The static welcome is sent.
4. The media handler continues, and the message can still be processed/coalesced afterward.

**Other Edges**

Only whitelisted senders get any of this; non-whitelisted senders are dropped before user creation.

If the system is paused, text/media messages are stored, but onboarding welcome is skipped.

Duplicate webhook redelivery will not send another welcome because message insertion uses `ON CONFLICT DO NOTHING`, and onboarding can only be claimed once.
