A sync effect (lines 64-76) tries to patch staleness but is incomplete — it only compares URLs and variant IDs, missing changes to frames, positions, or other fields.

The same "snapshot at event boundary" anti-pattern exists in:
- **PairRegionsLayer** (lines 131-150): reconstructs PairData from raw `GenerationRow` objects at click time instead of passing the canonical `pairDataByIndex` entry

## Overview

`useSegmentSlotMode` stores `activePairData` in `useState`, creating a denormalized copy of data that already exists in `pairDataByIndex` (the canonical source from `usePairData`). A sync effect (lines 64-76) tries to patch staleness but is incomplete — it only compares URLs and variant IDs, missing changes to frames, positions, or other fields.

The same "snapshot at event boundary" anti-pattern exists at 5 call sites that construct PairData at click time: PairRegionsLayer, PairRegion, TrailingEndpointLayer, ImageGrid, and usePairSettingsHandler.

### Scope decision

The critique identified two valid approaches:
- **(A) Minimal**: Remove stale URL/variant snapshots while preserving frame overrides
- **(B) Full**: Move live frame derivation into the canonical source, then remove overrides

**This plan chooses (B) with a key insight that makes it tractable**: `pairDataByIndex` computes frames from `shotGenerations.timeline_frame`, while the timeline UI computes from `imagePositions`. Both read from the same persisted DB positions. They can diverge briefly after a drag (before the async save + React Query refetch), but users cannot open the lightbox during a drag. The existing sync effect already doesn't sync frame data, so this is not a regression — it's the current behavior. The real bugs this fixes (stale image URLs, variant IDs, and positions after variant changes) are high-impact.

|--------|-----------|-------------|
| `pairDataByIndex` | `shotGenerations.timeline_frame` | React Query refetch after DB write |
| `imagePositions`/`pairInfo` | `framePositions` local state | Immediately on drag |
| `imagePositionsWithPending` | `imagePositions` + pending frame | Pending image insertion |

- `usePairSettingsHandler` receives non-pending `pairInfo`, not `pairInfoWithPending`
