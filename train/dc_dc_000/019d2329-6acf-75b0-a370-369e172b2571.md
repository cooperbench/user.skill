## Problem
During execute, the agent does all the work (modifies files, runs tests, completes tasks) but never saves its progress to finalize.json. The prompt explicitly says 'Do not create or rewrite tracking artifacts directly.' Instead, the agent returns one big JSON blob at the end, and the handler merges task_updates into finalize.json. If the agent times out or crashes, ALL tracking is lost even though the actual code changes are in the repo.

## Solution: Make the agent save as it goes
Flip the prompt instruction. Tell the executor agent to update finalize.json directly after completing each task:
1. After finishing each task: update that task's entry in finalize.json with status, executor_notes, files_changed, commands_run. Save the file.
2. After each sense check acknowledgment: update that sense_check's entry in finalize.json with executor_note. Save the file.
3. The agent checks off tasks and adds notes in real-time as part of its natural workflow.

## Handler changes
- On timeout: read finalize.json from disk (which the agent has been updating). Whatever tasks are marked done are genuinely done. Use that as the source of truth.
- On success: the handler already re-reads finalize.json at line 1247. The structured JSON output's task_updates become a validation/reconciliation layer, not the sole source of truth.
- On timeout recovery: persist session ID, save state, leave state as 'finalized' so re-execution works. The re-run prompt already handles done vs pending tasks.

1. Tell the agent to do it (prompt change)

## Overview
During execute, the agent does all the real work (edits files, runs tests) but never persists tracking to `finalize.json`. The handler merges a single structured JSON blob into `finalize.json` only after the agent completes (`handlers.py:1247-1306`). If the agent times out (`workers.py:102-107`, CliError code `worker_timeout`), the `except CliError` at `handlers.py:1242` re-raises — losing all tracking even though code changes are on disk.

**Goal:** Tell the agent to update `finalize.json` incrementally during execution. On timeout, read what's on disk. On success, reconcile disk state with structured output.

**Repo shape:** Prompt lives in `prompts.py:371-496`. Handler in `handlers.py:1226-1371`. Workers in `workers.py` (timeout at line 102). Structured output schema in `.megaplan/schemas/execution.json`. Tests in `tests/test_megaplan.py`.

**Key constraint:** The handler already reads `finalize.json` at line 1247 and merges structured output on top. If the agent writes directly to `finalize.json`, those updates are already there when the handler reads. The structured output merge becomes reconciliation, not the sole source.

## Phase 3: Reconciliation on Success

### Step 5: Reconcile disk state with structured output on success (`megaplan/handlers.py:1247-1267`)
**Scope:** Small
1. **Current behavior** at line 1247: reads `finalize.json` (which now may have agent-written updates), then merges structured output on top via `_validate_and_merge_batch`. This already works correctly — the merge is last-write-wins by task_id, so structured output values overwrite disk values.
2. **Add a reconciliation check:** After merging, compare the structured output task statuses against what was on disk before merge. If they differ, log an advisory deviation (not blocking). This catches cases where the agent's incremental save disagrees with its final summary.
3. **Implementation:**
   ```python
   finalize_data = read_json(plan_dir / "finalize.json")
   # Snapshot pre-merge state for reconciliation
   pre_merge_statuses = {
       task["id"]: task.get("status", "pending")
       for task in finalize_data.get("tasks", [])
   }
   # ... existing merge logic ...
   # After merge: check for discrepancies
   for task in finalize_data.get("tasks", []):
       pre = pre_merge_statuses.get(task["id"], "pending")
       post = task.get("status", "pending")
       if pre != "pending" and pre != post:
           deviations.append(
               f"Advisory: task {task['id']} was '{pre}' on disk but '{post}' in structured output"
           )
   ```
