**Findings**

1. **Worker render routing exists, but UI render does not actually enqueue it.**
   `decideRenderRoute()` routes themed/generated-module clips to `banodoco` in [renderRouter.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/lib/renderRouter.ts:87), and `enqueueBanodocoRenderTimeline()` exists in the same file at [line 253](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/lib/renderRouter.ts:253). But `useRenderState()` turns any `banodoco` route into an error instead of calling that enqueue path: [useRenderState.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useRenderState.ts:51). This makes “add a new worker-rendered clip type” incomplete from the editor render button.

2. **Clip rendering dispatch is reasonably centralized, but native clip types are still hardcoded in multiple places.**
   Main dispatch lives in [TimelineRenderer.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/compositions/TimelineRenderer.tsx:174): generated module, `effect-layer`, `text`, registered sequence component, unknown placeholder, then media. That is good. But native support is duplicated in `BUILTIN_CLIP_TYPES` at [types/index.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/types/index.ts:67) and `NATIVE_BUILTIN_CLIP_TYPES` at [renderRouter.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/lib/renderRouter.ts:72). Adding a new browser-native clip type would touch routing, renderer dispatch, likely property panels/tools, and tests.

3. **Effects are the strongest modularity story.**
   Built-ins are simple maps in [effects/index.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/effects/index.tsx:39), [line 53](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/effects/index.tsx:53), and [line 62](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/effects/index.tsx:62). Dynamic effects are registered through `DynamicEffectRegistry` at [DynamicEffectRegistry.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/effects/DynamicEffectRegistry.ts:45), loaded from resources in [useEffectRegistry.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/hooks/useEffectRegistry.ts:42), and parameter-coerced via schema in [validateParams.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/effects/validateParams.ts:16). Developers can add custom effects without touching render code if they fit `entrance | exit | continuous`.

4. **Sequences are registry-based at render time, but metadata/validation is duplicated and closed.**
   Render lookup merges package-generated and local sequence registries in [sequences/registry.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/sequences/registry.ts:18). However trusted sequence metadata is defined in the frontend at [metadata.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/sequences/metadata.ts:41) and duplicated in the edge function at [sequence-validation.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/supabase/functions/ai-generate-sequence/sequence-validation.ts:38). Adding a new AI-generatable sequence means updating at least frontend metadata, edge validation, likely prompts/tests, and possibly a local/package registry entry.

5. **Sequence params are only partially schema-driven.**
   `SequenceParamEditor` renders from metadata, which is good, but supports only `string` and `asset-list`, with textarea behavior hardcoded by param key: [SequenceParamEditor.tsx](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/components/PropertiesPanel/SequenceParamEditor.tsx:13). Validation similarly only accepts those kinds: [validation.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/src/tools/video-editor/sequences/validation.ts:8). New param types require coordinated UI and edge/client validator changes.

6. **Agent commands are not modular yet.**
   A command must be represented in several parallel structures: schema prose in [tool-schemas.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/supabase/functions/ai-timeline-agent/tool-schemas.ts:14), parser union and parsers in [command-parser.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/supabase/functions/ai-timeline-agent/command-parser.ts:3), command mapping in [tools/registry.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/supabase/functions/ai-timeline-agent/tools/registry.ts:13), and handlers in [tools/timeline.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/supabase/functions/ai-timeline-agent/tools/timeline.ts:839). Adding commands will touch multiple unrelated-looking files unless this is consolidated into command descriptors.

7. **Agent timeline edits are media/text-oriented; themed edits are only param patching.**
   `set` is intentionally limited to numeric media properties at [command-parser.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/supabase/functions/ai-timeline-agent/command-parser.ts:22), while themed clip edits go through `set_params` at [tools/timeline.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/supabase/functions/ai-timeline-agent/tools/timeline.ts:756). That is a clean split, but there is no first-class “add sequence/themed clip” command; bulk creation is punted to `delegateToBanodocoAgent` at [delegateToBanodocoAgent.ts](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/supabase/functions/ai-timeline-agent/tools/delegateToBanodocoAgent.ts:79).

Overall: effects are fairly extensible, render dispatch is centralized but not fully wired for worker routes, sequences are halfway modular, and agent commands are the most coupled area.
