Project directory: /Users/user_c042661f/Documents/megaplan Idea: Batched sub-agent execution and simplicity-first critique ## Problem 1: Monolithic execution The execute step runs ALL tasks in a single agent subprocess that can last hours. This forces complex recovery machinery (incremental saves, session persistence, reconciliation, timeout recovery) and prevents the harness from observing between tasks. The harness should be the one tracking progress, not the agent. ## Solution: Batched execution with harness observation The finalize step already produces an ordered task list with depends_on relationships. The orchestrator should: 1. Group tasks into dependency-respecting batches (independent tasks can batch together, dependent tasks sequence) 2. Run each batch as a separate agent subprocess 3. Between batches: harness runs git diff, checks what changed, updates finalize.json based on OBSERVATION not agent self-report 4. If a batch times out or fails, only that batch is lost — prior batches are already persisted This eliminates most of the timeout recovery, incremental save, and reconciliation machinery we just built. The harness becomes the source of truth. ## Problem 2: Planning loop is a local optimizer Critique→gate→revise is great at finding bugs within a plan but cannot question whether the plan is the right approach.
