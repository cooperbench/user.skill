        # Implementation Plan: First Practical Generated Sequence Unlock

## Overview
The current Reigh implementation already has the trusted v1 spine the architecture doc wants to preserve: `SequenceCreatorPanel` calls `ai-generate-sequence`, validates returned data-only drafts, previews trusted drafts through existing Remotion components, and inserts ordinary timeline clips through `sequence-drafts`. Timeline persistence already preserves `params`, `pool_id`, `clip_order`, `source_uuid`, and `generation` metadata through `TimelineConfig` round-trips.

The critiques show the root cause is broader than the initial router helper target. Generated-lane safety must cover every browser execution surface, not just export/render start. The live render button currently goes through `useRenderState()` to `useClientRender()`, while editor preview goes through `RemotionPreview` to `TimelineRenderer`. The revised approach keeps the render-entrypoint fix and adds lane-aware preview blocking before any native, sequence, or theme `clipType` dispatch. This is still within the original scope because the user explicitly required future generated Remotion module lanes without executing untrusted code in the browser.

Existing dirty files include `.megaplan/schemas/*`, `SequenceCreatorPanel.tsx`, `SequenceParamEditor.tsx`, and `ClipPanel.sequence.test.tsx`. Treat those as current workspace state and do not touch unrelated `.megaplan` schema dirtiness.

## Phase 1: Trusted V1 Authoring UX And Request Contract

### Step 1: Add explicit intent capture to `SequenceCreatorPanel` (`src/tools/video-editor/components/SequenceCreator/SequenceCreatorPanel.tsx`)
**Scope:** Medium

3. Send intent to `ai-generate-sequence` as `animation_intent: { freeform: animationIntent.trim() }` only when non-empty, while keeping `allowed_clip_types: AVAILABLE_SEQUENCE_CLIP_TYPES` unchanged.

### Step 3: Keep repeated asset reuse visible as counts (`src/tools/video-editor/components/PropertiesPanel/SequenceParamEditor.tsx`)
**Scope:** Small

## Phase 3: Generated-Lane Contracts And Browser Safety Boundaries

### Step 6: Add shared generated-lane helpers (`src/tools/video-editor/lib/generated-lanes.ts`)
**Scope:** Small
1. Create a small shared helper module for lane metadata checks so router, render entrypoint, and preview renderer use one definition.

3. Export `isGeneratedRemotionModuleClip(clip)` and `getGeneratedRemotionModuleArtifactId(clip)` or equivalent helpers that require `sequence_lane === 'remotion_module'` and a non-empty string `artifact_id` for valid module clips.
4. Keep `trusted_v1`, `schema_sequence`, unknown lane strings, null, and absent lane metadata non-module by default.

### Step 7: Add an explicit blocked render-route contract (`src/tools/video-editor/lib/renderRouter.ts`)
**Scope:** Medium
1. Use the shared generated-lane helpers before theme-package or native `clipType` checks.
2. Extend `RenderRoute` to include a non-rendering route, e.g. `RenderRoute = 'client' | 'banodoco' | 'blocked'`.
3. Extend `RenderRouteDecision.reason` with typed generated-lane reasons such as `generated_remotion_module`, `remotion_module_missing_artifact`, and `remotion_module_artifact_invalid` if artifact validation state is represented locally.
4. Return `route: 'blocked'` for `sequence_lane === 'remotion_module'` with missing, empty, or non-string `artifact_id`; never return `client` for malformed module-lane clips.
5. Return the worker route (`banodoco`) with `reason: 'generated_remotion_module'` for valid module-lane clips with a non-empty string `artifact_id`, regardless of whether `clipType` is unknown, native, or registered theme-package.
6. Keep unknown `clipType` without module lane on the existing client loud-placeholder fallback.

### Step 8: Wire route decisions into the live render entrypoint (`src/tools/video-editor/hooks/useRenderState.ts`, render-button caller in `src/tools/video-editor/components/VideoEditorShell.tsx` or `src/tools/video-editor/hooks/useTimelineState.ts`)
**Scope:** Medium
1. Replace the direct `startRender = useClientRender(...)` exposure with a routed `startRender` wrapper that calls `decideRenderRoute(resolvedConfig)` at click time.
2. For `route: 'client'`, call the existing `useClientRender()` callback exactly as before.
3. For `route: 'blocked'`, set `renderStatus` to `error`, set a clear `renderLog` message containing the route reason, and do not call `useClientRender()`.
4. For `route: 'banodoco'`, do not call `useClientRender()`. Use the existing `buildRenderTimelinePayload()` and `enqueueBanodocoRenderTimeline()` path if the hook/caller already has the required `timelineId`, `projectId`, `assetRegistry`, user JWT, and orchestrator URL available; otherwise return a structured render error stating that worker render dispatch is unavailable in this UI context.
5. If adding those runtime inputs is small and already available in `useTimelineState` or `VideoEditorShell`, thread them into `useRenderState()` with minimal signature changes. Do not invent new persistence, artifact APIs, or browser execution fallbacks.
6. Add a focused hook test proving malformed `remotion_module` clips are blocked at `useRenderState().startRender()` and the mocked client renderer is not invoked.
7. Add a focused hook test proving valid `remotion_module` clips do not call the client renderer; they either enqueue through the worker path when required context is provided or produce the explicit worker-unavailable error when context is absent.

### Step 9: Block generated-module clips in browser preview before `clipType` dispatch (`src/tools/video-editor/compositions/TimelineRenderer.tsx`, `src/tools/video-editor/components/PreviewPanel/RemotionPreview.tsx`)
**Scope:** Medium

2. In `TimelineRenderer`, check `clip.generation.sequence_lane === 'remotion_module'` at the top of the per-clip render path, before any native, sequence, or theme `clipType` dispatch.
3. For module-lane clips, render a non-executing placeholder/block component that shows a safe message such as “Generated module preview is worker-only” and optionally the artifact id/version if present. Do not pass module source, props intended for generated code, imports, or raw source text into browser components.
4. Keep trusted v1, schema-sequence compiled ordinary clips, native media/text, and registered theme-package preview behavior unchanged when they do not carry `sequence_lane === 'remotion_module'`.
5. Prefer the `TimelineRenderer` guard as the primary enforcement point because all `RemotionPreview` callers flow through it; only add `RemotionPreview` filtering if needed for clearer tests or user messaging.
6. Add tests proving a module-lane clip with a native `clipType`, a registered sequence/theme `clipType`, and an unknown `clipType` all render the safe placeholder rather than the normal browser preview path.
