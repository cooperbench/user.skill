        # Implementation Plan: Atomic Shot Creation with Generations

## Overview

Shot creation with multiple generations currently uses a two-phase approach: `useCreateShot` creates an empty shot row (cached with `images: []`), then `createShotWithGenerationsPath` serially calls `insertAutoPositionedShotGeneration` for each generation, and finally uses a 1500ms `setTimeout` to invalidate the shots list. This causes shots appearing without thumbnails, cache races, and UI flicker.

**Root fix:** A new `create_shot_with_generations` Supabase RPC creates the shot AND inserts all generations in one DB transaction. The client calls this single RPC, builds a complete cache entry from the result + already-cached generation data, and inserts it via a new `upsertShotInCache` helper. No optimistic partials, no serial RPCs, no timers.

**Existing precedent:** `create_shot_with_image` RPC already does this for 1 generation. We extend the pattern to N generations.

**Key constraints:**
- Must call `ensure_shot_parent_generation` (as `insert_shot_at_position` does)
- `timeline_frame` has a unique partial index per shot and `>=0` constraint; spacing is 50 units
- `add_generation_to_shot` uses SECURITY DEFINER with ownership check — new RPC needs similar auth
- Cache entries need computed fields (`imageCount`, `positionedImageCount`, etc.) matching `useListShots` shape
- Serial insertion for timeline_frame calculation is handled inside the RPC (single transaction, no race)

```sql
CREATE OR REPLACE FUNCTION public.create_shot_with_generations(
  p_project_id uuid,
  p_shot_name text,
  p_generation_ids uuid[]
)
RETURNS jsonb
LANGUAGE plpgsql
AS $function$
DECLARE
  v_shot_id uuid;
  v_position integer;
  v_result jsonb;
  v_gen_id uuid;
  v_sg_id uuid;
  v_frame integer := 0;
  v_shot_gens jsonb := '[]'::jsonb;
BEGIN
  -- Auth check (same pattern as create_shot_with_image)
  IF auth.role() <> 'service_role' AND NOT EXISTS (
    SELECT 1 FROM public.projects p
    WHERE p.id = p_project_id AND p.user_id = auth.uid()
  ) THEN
    RAISE EXCEPTION 'Not authorized';
  END IF;

  -- Calculate position (append to end)
  SELECT COALESCE(MAX(s.position), -1) + 1 INTO v_position
  FROM public.shots s WHERE s.project_id = p_project_id;

  -- Create shot
  INSERT INTO public.shots (name, project_id, position)
  VALUES (p_shot_name, p_project_id, v_position)
  RETURNING id INTO v_shot_id;

  -- Insert all generations with 50-unit timeline_frame spacing
  FOREACH v_gen_id IN ARRAY p_generation_ids LOOP
    INSERT INTO public.shot_generations (shot_id, generation_id, timeline_frame, metadata)
    VALUES (v_shot_id, v_gen_id, v_frame, '{"auto_positioned": true}'::jsonb)
    RETURNING id INTO v_sg_id;

    v_shot_gens := v_shot_gens || jsonb_build_object(
      'id', v_sg_id,
      'generation_id', v_gen_id,
      'timeline_frame', v_frame
    );
    v_frame := v_frame + 50;
  END LOOP;

  -- Ensure parent generation (same as insert_shot_at_position)
  PERFORM public.ensure_shot_parent_generation(v_shot_id, p_project_id);

  -- Return complete result
  RETURN jsonb_build_object(
    'shot_id', v_shot_id,
    'shot_name', p_shot_name,
    'shot_position', v_position,
    'shot_generations', v_shot_gens,
    'success', true
  );
EXCEPTION WHEN OTHERS THEN
  RETURN jsonb_build_object('success', false, 'error', SQLERRM);
END;
$function$;
```

2. **Key design decisions:**
   - Returns `jsonb` (not `TABLE`) to include the array of shot_generation mappings in one row
   - Uses `FOREACH` loop inside a single transaction — no race condition on timeline_frame since it's sequential within the function
   - Calculates position as MAX+1 (same as `useCreateShot` does client-side at `useShotsCrud.ts:102-116`)
   - Inherits auth pattern from `create_shot_with_image` (`supabase/migrations/20260218143000_ensure_shot_parent_generation.sql:154-161`)

```typescript
/**
 * Insert or replace a complete Shot in all cached shot lists for a project.
 * Inserts at the correct position (sorted by shot.position).
 */
export function upsertShotInCache(
  queryClient: QueryClient,
  projectId: string,
  shot: Shot,
): void {
  updateAllShotsCaches(queryClient, projectId, (oldShots = []) => {
    // Replace if exists, insert at correct position if new
    const filtered = oldShots.filter(s => s.id !== shot.id);
    const insertIdx = filtered.findIndex(s => (s.position || 0) > (shot.position || 0));
    if (insertIdx === -1) {
      return [...filtered, shot];
    }
    const result = [...filtered];
    result.splice(insertIdx, 0, shot);
    return result;
  });

  // Also set the detail cache
  queryClient.setQueryData(queryKeys.shots.detail(shot.id), shot);
}
```

This follows the existing `updateAllShotsCaches` pattern already used in `useShotsCrud.ts:157` and `shotCacheUpdate.ts:63-65`.
