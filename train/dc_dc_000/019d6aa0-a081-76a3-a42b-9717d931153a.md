## Overview
Today the only way to set execution mode and robustness is via the `megaplan init` CLI flags (`--auto-approve`, `--robustness`). We want users to persist these as config defaults with `megaplan config set execution.auto_approve true` / `megaplan config set execution.robustness heavy`, so the harness no longer has to ask every time.

Current shape of the relevant code:
- `megaplan/types.py:287` — `DEFAULTS` dict (currently numeric + `orchestration.mode`). `_SETTABLE_NUMERIC` at `:296`. `ROBUSTNESS_LEVELS = ("light", "standard", "heavy")` at `:269`.
- `megaplan/_core/io.py:250` — `get_effective(section, key)` reads config then falls back to `DEFAULTS`. Works for any key registered in `DEFAULTS`.
- `megaplan/cli.py:475` — `init` parser: `--auto-approve` is `action="store_true"` (so it defaults to `False`, indistinguishable from "user omitted"), `--robustness` has `default="standard"` (same problem).
- `megaplan/cli.py:401` — `handle_config` `set` branch only understands `agents.*`, `orchestration.mode`, and `_SETTABLE_NUMERIC` keys.
- `megaplan/handlers.py:592` — `handle_init` reads `args.robustness` and `args.auto_approve` directly, then falls back to `"standard"` / `False` without checking config.
- `megaplan/data/instructions.md:10-14` — tells the harness to always ask execution mode before `init`.

Constraints that matter:
- `get_effective` requires the key to live in `DEFAULTS`, so both new keys must be registered there.
- The init parser can't use `store_true` with `default=False` for `--auto-approve`, because we need to distinguish "flag not passed" from "flag passed". Use `default=None` with an explicit `store_const` (or equivalent) for auto-approve, and `default=None` for robustness.
- Existing tests (e.g. `tests/test_config.py`, plus anything in `tests/` that calls `handle_init` with omitted flags) may rely on "standard" / `False` being the hard default — we need to keep behavior identical when no config override is set.
