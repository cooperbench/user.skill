## Design constraints from the Reigh compatibility analysis

The timeline shape is shared with the Reigh editor via `@banodoco/timeline-schema`. The Phase 2 design **must** respect:

1. **Do NOT add `clip.kind` as a persisted field.** Reigh's clip allowlist (`reigh-app/src/tools/video-editor/lib/serialize.ts:8-42`) is closed and throws on unknown clip keys. ArtAgents' `_CLIP_ALLOWED` matches it byte-equivalent. Any "kind" must be a runtime-derived view, not persisted.

2. **`.for_render()` default-theme injection must be transient.** Reigh routinely persists timelines without a theme and uses its own renderer-side fallback (`reigh-app/.../renderRouter.ts:194-199`). If ArtAgents writes back a defaulted theme, Reigh users see a silent theme switch on next load. Default-theme is a render-time view, never round-trips to disk.

3. **The shared schema is the source of truth.** `artagents/timeline.py:30,858` already validates against the package's JSON Schema (`_shared_validate_timeline`). Phase 2 should keep using that, not maintain a separate Python allowlist.

4. **Round-trip must remain byte-equivalent.** The Prereq B fixture test is the regression gate.

## What the `Timeline` class should be

- Owns load/dump. Construction reads JSON, dump writes JSON.
- **Preserves unknown top-level fields by construction** (the `_phase2_canary` xfail in Prereq B should flip to passing, and the xfail marker should be removed).
- `.for_render()` returns a transient view with theme defaulted to a renderable value if missing. Never mutates self. Never round-trips.
- Exposes typed access to known fields (`.theme`, `.clips`, `.tracks`, `.theme_overrides`, `.generation_defaults`, `.pinnedShotGroups`, `.output`).
- Provides a runtime `clip.classified_kind` (or equivalent) computed from `clipType` + asset registry MIME — for internal dispatch only, never persisted. Should include an `OPAQUE` arm for unknown clipTypes (Reigh's `clipType` is intentionally open-string).
- Direct `json.load` of `hype.timeline.json` becomes the wrong way to do it everywhere. The migration scope is roughly ~12 executors that touch timelines (`cut`, `arrange`, `refine`, `render`, `validate`, `editor_review`, `human_notes`, `inspect_cut`, plus anything in `pipeline.py` that reads/writes timeline JSON directly).

Find the actual scope by grepping for `hype.timeline.json` and `load_timeline`/`save_timeline` callers.

## Design constraints from the Reigh compatibility analysis

The timeline shape is shared with the Reigh editor via `@banodoco/timeline-schema`. The Phase 2 design **must** respect:

1. **Do NOT add `clip.kind` as a persisted field.** Reigh's clip allowlist (`reigh-app/src/tools/video-editor/lib/serialize.ts:8-42`) is closed and throws on unknown clip keys. ArtAgents' `_CLIP_ALLOWED` matches it byte-equivalent. Any "kind" must be a runtime-derived view, not persisted.

2. **`.for_render()` default-theme injection must be transient.** Reigh routinely persists timelines without a theme and uses its own renderer-side fallback (`reigh-app/.../renderRouter.ts:194-199`). If ArtAgents writes back a defaulted theme, Reigh users see a silent theme switch on next load. Default-theme is a render-time view, never round-trips to disk.

3. **The shared schema is the source of truth.** `artagents/timeline.py:30,858` already validates against the package's JSON Schema (`_shared_validate_timeline`). Phase 2 should keep using that, not maintain a separate Python allowlist.

4. **Round-trip must remain byte-equivalent.** The Prereq B fixture test is the regression gate.

## What the `Timeline` class should be

- Owns load/dump. Construction reads JSON, dump writes JSON.
- **Preserves unknown top-level fields by construction** (the `_phase2_canary` xfail in Prereq B should flip to passing, and the xfail marker should be removed).
- `.for_render()` returns a transient view with theme defaulted to a renderable value if missing. Never mutates self. Never round-trips.
- Exposes typed access to known fields (`.theme`, `.clips`, `.tracks`, `.theme_overrides`, `.generation_defaults`, `.pinnedShotGroups`, `.output`).
- Provides a runtime `clip.classified_kind` (or equivalent) computed from `clipType` + asset registry MIME — for internal dispatch only, never persisted. Should include an `OPAQUE` arm for unknown clipTypes (Reigh's `clipType` is intentionally open-string).
- Direct `json.load` of `hype.timeline.json` becomes the wrong way to do it everywhere. The migration scope is roughly ~12 executors that touch timelines (`cut`, `arrange`, `refine`, `render`, `validate`, `editor_review`, `human_notes`, `inspect_cut`, plus anything in `pipeline.py` that reads/writes timeline JSON directly).

## Design constraints from the Reigh compatibility analysis

The timeline shape is shared with the Reigh editor via `@banodoco/timeline-schema`. The Phase 2 design **must** respect:

1. **Do NOT add `clip.kind` as a persisted field.** Reigh's clip allowlist (`reigh-app/src/tools/video-editor/lib/serialize.ts:8-42`) is closed and throws on unknown clip keys. ArtAgents' `_CLIP_ALLOWED` matches it byte-equivalent. Any "kind" must be a runtime-derived view, not persisted.

2. **`.for_render()` default-theme injection must be transient.** Reigh routinely persists timelines without a theme and uses its own renderer-side fallback (`reigh-app/.../renderRouter.ts:194-199`). If ArtAgents writes back a defaulted theme, Reigh users see a silent theme switch on next load. Default-theme is a render-time view, never round-trips to disk.

3. **The shared schema is the source of truth.** `artagents/timeline.py:30,858` already validates against the package's JSON Schema (`_shared_validate_timeline`). Phase 2 should keep using that, not maintain a separate Python allowlist.

4. **Round-trip must remain byte-equivalent.** The Prereq B fixture test is the regression gate.

## What the `Timeline` class should be

- Owns load/dump. Construction reads JSON, dump writes JSON.
- **Preserves unknown top-level fields by construction** (the `_phase2_canary` xfail in Prereq B should flip to passing, and the xfail marker should be removed).
- `.for_render()` returns a transient view with theme defaulted to a renderable value if missing. Never mutates self. Never round-trips.
- Exposes typed access to known fields (`.theme`, `.clips`, `.tracks`, `.theme_overrides`, `.generation_defaults`, `.pinnedShotGroups`, `.output`).
- Provides a runtime `clip.classified_kind` (or equivalent) computed from `clipType` + asset registry MIME — for internal dispatch only, never persisted. Should include an `OPAQUE` arm for unknown clipTypes (Reigh's `clipType` is intentionally open-string).
- Direct `json.load` of `hype.timeline.json` becomes the wrong way to do it everywhere. The migration scope is roughly ~12 executors that touch timelines (`cut`, `arrange`, `refine`, `render`, `validate`, `editor_review`, `human_notes`, `inspect_cut`, plus anything in `pipeline.py` that reads/writes timeline JSON directly).
