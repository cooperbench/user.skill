# Epic: ArtAgents ↔ reigh-app Bidirectional Editing

## Goal

A user can edit a project timeline from **either** ArtAgents (CLI, agent-driven) **or** reigh-app (visual editor). Edits in one are seen by the other. Both render the project with identical output.

This is non-negotiable. Solutions that achieve only one-way authoring are out of scope.

## Status: most of the platform already exists

Reigh-app's `megaplan/video-editor-dx-sprint-08` branch already ships nearly all the cross-tool integration plumbing. Earlier conversations in this epic assumed otherwise; that framing was wrong. The remaining work is **AA-side integration** plus a single renderer swap.

- Reigh-app's video-editor types are aliased re-exports of `@banodoco/timeline-schema` (`src/tools/video-editor/types/index.ts:1-13`). Single source of truth, no parallel structures.

7. **Sequence support.** Sprint-08 introduces formalized sequences (`src/tools/video-editor/sequences/`). AA may want to author sequences as well as raw clips. The `ai-generate-sequence` edge function suggests sequences are themselves agent-generable. AA's worker may receive sequence-shaped requests — handle them, materialize via `applySequenceDraftToTimeline`, push via `timeline-import`.

## What's shared vs not

### Shared (canonical)
- **Data:** Supabase `timelines` table + storage buckets. AA's local cache reflects one row.
- **Schema:** `@banodoco/timeline-schema` Zod source of truth. Both tools validate against it.
- **Renderer:** `@banodoco/timeline-composition` React+Remotion components. Both consume the same effect/transition/animation registries.
- **Ops:** `@banodoco/timeline-ops` for pure-functional timeline mutations. Both tools should use it instead of hand-rolling clip-list edits.

### Not shared (deliberate)
- **UI:** reigh-app is the visual editor; AA is the CLI + worker. Same data, different ways to drive it.
- **Provenance store:** AA's local `runs/`, `sources/` directories track full run history (prompts, models, generation metadata) that doesn't belong on the timeline. The breadcrumb (`source_uuid`, `generation`) lives on the clip so reigh-app sees and preserves it.
- **Sync timing:** local cache is only as fresh as the last fetch. Optimistic versioning catches conflicts on push, but it's not real-time.

## Edge cases to handle

1. **Reigh-app duplicates a clip with `source_uuid` set.** Two clips share provenance. AA's worker, on next regenerate, must treat both as referring to the same generation OR drop `source_uuid` from the duplicate during materialize.
2. **Reigh-app deletes an AA-generated clip.** The run still exists in AA's local history; the timeline just doesn't reference it. No action needed; AA history is append-only.
3. **Reigh-app edits clip fields after AA generation.** When AA regenerates that clip via a delegated task, AA must preserve user edits unless the regeneration explicitly intends to overwrite. A `baseline_snapshot` digest (sha256 of clip-as-AA-wrote-it) stored in AA's local run record allows drift detection.
4. **Concurrent edit / version conflict.** `timeline-import` rejects on `expected_version` mismatch. AA retries: re-fetch, re-apply ops on the new base, re-push. Bound retries to N=3; surface to user/agent on exhaustion.

## Rejected alternatives (with reasons)

### Local `timeline.json` as AA source of truth, sync layer to/from Supabase
Two sources of truth, sync bugs, drift. `timeline-import` already gives AA a single canonical store; opting out is paying coordination cost without coordination benefit. Local cache stays for offline read, but never as authoritative state.

### New `source: SourceRef | RunRef` field on `TimelineClip`
Redundant. `source_uuid` already exists on the schema and is already preserved by reigh-app's allowlist. AA's run/source IDs can resolve via local lookup against `runs/` and `sources/` directories. Adding a new field for structure that already exists in flat form costs a coordinated multi-repo PR for no net gain.

### Sidecar mapping (`<project>/run_index.json` keyed by `clip.id`)
Two-file consistency hazard. Rename or delete in reigh-app and the sidecar dangles. Hides provenance behind a join. The on-clip `source_uuid` field already covers this without a separate file.

### `clip_overrides` / two-layer placement
Was the leading proposal earlier in this conversation. Made obsolete by the realization that reigh-app already shipped the integration platform. There's no AA-side placement layer to extend.

### One-way authoring (AA composes, reigh-app renders only)
Violates the user's hard requirement.

### Forking the renderer in AA
The hand-rolled `Root.tsx` exists today. Keeping it forces AA to reimplement every effect, transition, and animation reigh-app adds. `@banodoco/timeline-composition` is already a dependency; using it is a smaller patch than maintaining a parallel renderer.
