# Problem
Today vibecomfy has a half-built model-distribution story:
- Upstream Comfy-Org workflow JSONs in `workflow_corpus/official/*.json` already carry inline `"url": "https://huggingface.co/..."` fields per model-loader node (see workflow_corpus/official/video/wan_t2v.json:38, ltx2_3_i2v.json:699, flux2_klein_4b_t2i.json:1082, etc.) plus markdown notes in human-readable form.
- The materializer in `scripts/materialize_ready_templates.py` builds `ready_templates/*/*.py` from those JSONs but never extracts the URLs — every scratchpad has `READY_REQUIREMENTS = {"models": [], "custom_nodes": [...]}` with `models` empty.
- There is no downloader. `vibecomfy doctor` checks runtime readiness but doesn't check model presence.
- The de-facto convention is HuggingFace via the upstream Comfy-Org URL fields, but nothing in vibecomfy reads or enforces it.

# Goal
Close the loop in five mechanical steps:
1. Materializer extracts URLs from workflow JSON and populates `READY_REQUIREMENTS["models"]` with structured entries.
2. A small `vibecomfy.fetch` module downloads missing models from URLs to the right ComfyUI subdir.
3. `vibecomfy fetch <workflow>` CLI command resolves a workflow's model list and downloads the missing ones.
4. `vibecomfy doctor <workflow>` reports missing models with their URLs.
5. Tests for extraction, fetch (mocked httpx), and doctor.

The bundle/manifest format and SHA pinning are explicitly OUT of scope — they're a separate plan.

# Steps

## S1: Extract URLs during materialization
- In `scripts/materialize_ready_templates.py`, walk the source JSON and collect `(node_id, url)` entries from any node that has a top-level `"url"` field.
- For each URL, parse it to derive:
  - `name`: the basename (e.g. `wan2.1_t2v_1.3B_fp16.safetensors`)
  - `subdir`: the ComfyUI models subdir to land it in. Derive from the URL path — for HF Comfy-Org `split_files/<subdir>/<name>` URLs, use `<subdir>` (text_encoders, diffusion_models, vae, clip_vision, loras, latent_upscale_models, etc.). For other URL shapes, fall back to a heuristic based on the loader's `class_type` (CheckpointLoaderSimple → `checkpoints`, CLIPLoader → `text_encoders`, VAELoader → `vae`, LoraLoader → `loras`, ControlNetLoader → `controlnet`, UNETLoader → `diffusion_models`).
  - `url`: the URL as-is (drop `?download=true` query param if present).
- Emit `READY_REQUIREMENTS["models"]` as a list of `{"name": ..., "url": ..., "subdir": ...}` dicts in materialization order, deduplicated by `(name, subdir)`.
- Re-materialize all existing scratchpads as part of this step.

## S2: vibecomfy.fetch module
- New file `vibecomfy/fetch.py`:
  - `models_root() -> Path` — discover ComfyUI's models root via `comfy.cmd.folder_paths.folder_names_and_paths` if importable, else fall back to `os.environ["COMFY_MODELS_ROOT"]`, else `Path("ComfyUI/models")`.
  - `local_path(entry: dict) -> Path` — `models_root() / entry["subdir"] / entry["name"]`.
  - `is_present(entry: dict) -> bool` — checks the local path exists and has nonzero size.
  - `download(entry: dict, *, force: bool = False) -> Path` — uses `httpx.stream("GET", url, follow_redirects=True)` to download to a `.tmp` sibling file, then rename atomically. Raises `RuntimeError` with a clear message on 401/403 (license gating) and on 404. Skips if `is_present(entry)` and not `force`.
  - `download_many(entries: list[dict], *, force: bool = False) -> list[Path]` — sequential for v1 (parallel is a follow-up). Reports per-entry status via stdout (one line per entry: skipped/downloaded/failed).
- No `huggingface_hub` dep. Use plain HTTP + `Authorization: Bearer $HF_TOKEN` if the env var is set (for license-gated repos).

## S3: vibecomfy fetch CLI command
- New file `vibecomfy/commands/fetch.py`:
  - `vibecomfy fetch <workflow>` — resolves the workflow (same resolution as `inspect`/`doctor`), reads `READY_REQUIREMENTS["models"]`, calls `download_many`, reports counts.
  - Flags: `--force` (re-download present), `--dry-run` (print what would be fetched).
  - Register in `vibecomfy/cli.py` alongside the other commands.

## S4: doctor integration
- Extend `vibecomfy/commands/doctor.py` to:
  - Read `READY_REQUIREMENTS["models"]` from the resolved workflow.
  - For each entry, call `is_present`. Report missing entries with name + url + expected local path.
  - Exit nonzero (or surface a flag in the existing doctor output schema) when models are missing.

# Design constraints
- Default to HF, but the downloader is URL-driven, not provider-driven. A Civitai/R2/S3 URL works too — only the subdir derivation has an HF-aware fast path.
- Strip `?download=true` query params (Comfy-Org sometimes appends these).
- Strip `split_files/` prefix when deriving subdir from HF Comfy-Org URLs.
- License-gated repos (FLUX.2-klein-base-9b is one): download() returns a clear error pointing at the URL when 401/403, doesn't try to handle the agreement flow.
- Atomic writes (rename from .tmp). No partial files left behind on Ctrl-C.
- No new top-level deps. httpx is already there.
- Sequential downloads; this is v1 not perf-critical.

# Implementation Plan: vibecomfy model-distribution v1

## Overview

Close the loop on model distribution by extracting `{name, url, subdir}` entries from upstream Comfy-Org workflow JSONs into each generated scratchpad's `READY_REQUIREMENTS["models"]`, then add a downloader (`vibecomfy.fetch`), a `vibecomfy fetch <workflow>` CLI, and missing-model reporting in `vibecomfy doctor`. Bundles, manifests, SHA pinning, parallel downloads, and auto-fetch are explicitly out of scope.

**Repo shape that matters:**
- Materializer entry: `scripts/materialize_ready_templates.py` builds `ready_templates/{image,video,edit}/<id>.py`. It loads each raw JSON via `load_template`, normalises through `convert_to_vibe_format`, applies per-template policy, then writes the literal `READY_REQUIREMENTS = {"models": sorted(workflow.requirements.models), "custom_nodes": sorted(...)}` (`scripts/materialize_ready_templates.py:237-240`). Models is currently always `[]` because `_infer_requirements` in `vibecomfy/metadata.py:28-37` only looks at `*_name` widget keys, and the API workflows store model widgets as `widget_0`/`widget_1`.
- Upstream URL convention is `properties.models = [{ "name": "...", "url": "...", "directory": "..." }]` per loader node in the **raw** (UI-shape) JSON — see `workflow_corpus/official/video/wan_t2v.json:38`, `ltx2_3_i2v.json` and `flux2_klein_4b_t2i.json`. Not at the `class_type`/`inputs` level (the brief got that detail wrong; `class_type`/`inputs` only exist in the API form, but `properties.models` is on the UI form).
- CLI registration is explicit and ordered (`vibecomfy/commands/__init__.py:14-29`); `tests/test_cli.py:25-41` asserts the exact list — must be updated when we add `fetch`.
- Doctor reads via `load_workflow_reference(args.path, ..., allow_scratchpad=True)` (`vibecomfy/commands/doctor.py:14-53`). It returns a `VibeWorkflow`, whose `requirements.models: list[str]` is name-only. Structured download metadata can't piggyback there cleanly — it must come from a side channel.
- Scratchpad consumers go through `vibecomfy/registry/ready_template.py:49-57 _merge_requirements`, which currently calls `workflow.requirements.models.sort()`. Storing dicts there will break sorting and the typed `list[str]`. Cleanest fix: keep `WorkflowRequirements.models` as `list[str]` (names), and surface structured entries via `workflow.metadata["model_assets"]` (and via the scratchpad's own `READY_REQUIREMENTS["models"]` literal).

**Constraints recap:** httpx already a dep; no `huggingface_hub`; sequential downloads; atomic `.tmp` → rename; `Authorization: Bearer $HF_TOKEN` if env set; strip `?download=true`; respect `VIBECOMFY_MODELS_ROOT` then `COMFY_MODELS_ROOT` then `Path("ComfyUI/models")`; license-gated 401/403 must produce a clear error with the URL.

## Main Phase

### Step 1: Add a model-entry extractor used by both materializer and fetch (`vibecomfy/model_assets.py`)
**Scope:** Medium

1. **Create** `vibecomfy/model_assets.py` exposing two pure functions and one constant:
   - `HF_SPLIT_FILES_DIRS` — known HF Comfy-Org `split_files/<dir>/` second-level dirs (`text_encoders`, `diffusion_models`, `vae`, `clip_vision`, `loras`, `latent_upscale_models`, `controlnet`, `checkpoints`, `unet`).
   - `extract_from_raw_workflow(raw: dict) -> list[dict]` — walks `raw["nodes"]` (UI form), reads each node's `properties.models` list of `{name, url, directory?}`, normalises into `{"name", "url", "subdir"}`. Skips entries without `url` or `name`. Strips `?download=true` query param from URL. Subdir resolution order:
     a) `entry["directory"]` if non-empty.
     b) HF `split_files/<dir>/` regex on the URL path → `<dir>`.
     c) Fallback by node `type` (CheckpointLoaderSimple → checkpoints, CLIPLoader → text_encoders, VAELoader → vae, LoraLoader → loras, ControlNetLoader → controlnet, UNETLoader → diffusion_models). If still unknown, default to `"checkpoints"` and tag the entry (don't fail).
     Walk in node-id ascending integer order for stable output. De-duplicate by `(name, subdir)` while preserving first-seen order.
   - `entries_from_scratchpad_path(path: Path) -> list[dict]` — given a scratchpad `.py` path, import it via `importlib.util` and return `module.READY_REQUIREMENTS.get("models", [])`. Used by `fetch` and `doctor` when given a ready template.

2. **No coupling to the API form:** the extractor only looks at the raw UI JSON (`raw["nodes"]`). If `raw` looks API-shaped (no `nodes` list), return `[]`. Lets us reuse the helper without touching `normalize_to_api`.

### Step 4: Build the downloader (`vibecomfy/fetch.py`)
**Scope:** Medium

1. **Create** `vibecomfy/fetch.py` with:
   - `models_root() -> Path` — fall through `VIBECOMFY_MODELS_ROOT` env, then `COMFY_MODELS_ROOT` env, then attempt `from comfy.cmd.folder_paths import folder_names_and_paths; folder_names_and_paths["checkpoints"][0][0]`'s parent (best-effort, wrapped in try/except), then `Path("ComfyUI/models")`. No filesystem touch beyond reading env.
   - `local_path(entry: dict) -> Path` → `models_root() / entry["subdir"] / entry["name"]`.
   - `is_present(entry: dict) -> bool` → `path.is_file() and path.stat().st_size > 0`.
   - `download(entry: dict, *, force: bool = False, client: httpx.Client | None = None) -> Path`:
     - Skip if `is_present` and not `force`; print `"skipped {name}"` and return path.
     - Build `headers = {}`; if `os.environ.get("HF_TOKEN")` set, add `Authorization: Bearer …`.
     - Strip `?download=true` from URL (defence in depth — extractor already strips, but accept entries built by hand).
     - Open `httpx.stream("GET", url, follow_redirects=True, headers=headers, timeout=httpx.Timeout(60, read=None))`. Use the supplied `client` if given (for tests).
     - On status 401/403 → `raise PermissionError(f"License-gated download blocked for {url} — set HF_TOKEN or accept the license at the source URL.")`.
     - On 404 → `raise FileNotFoundError(f"Asset not found at {url}")`.
     - For other non-2xx → `raise RuntimeError(f"HTTP {status} fetching {url}")`.
     - Stream into `path.with_suffix(path.suffix + ".tmp")`, then `os.replace(tmp, path)`. Make the parent dir.
     - On any exception during streaming, attempt `tmp.unlink(missing_ok=True)` and re-raise. KeyboardInterrupt also goes through this cleanup path.
     - Return final `path`.
   - `download_many(entries: list[dict], *, force: bool = False) -> list[Path]` — sequential. For each entry, print one line: `skipped <name>`, `downloaded <name> -> <path>`, or `failed <name>: <error>`. Continue past failures; raise an aggregate `RuntimeError("N failures")` only at the end so partial progress is preserved.
2. **No new pyproject dep.** `httpx` is already declared (`pyproject.toml:11`).

### Step 5: Add `vibecomfy fetch` command (`vibecomfy/commands/fetch.py`, `vibecomfy/commands/__init__.py`)

   - Otherwise call `download_many(entries, force=args.force)` and return 0 on success, 1 if `download_many` raised an aggregate failure.
2. **Register** `CommandSpec("fetch", "vibecomfy.commands.fetch")` in `vibecomfy/commands/__init__.py:14-29`. Slot it after `doctor` to read naturally.
