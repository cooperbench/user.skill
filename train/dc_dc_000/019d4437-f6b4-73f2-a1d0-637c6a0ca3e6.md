## Problem Statement
Three issues in the video editor need fixing:

### Issue 1: Number inputs missing stepper arrows
In ClipPanel.tsx (timing tab), all number inputs use plain Input type=number instead of the shared NumberInput component from src/shared/components/ui/number-input.tsx which has up/down chevron arrows. Fields affected: Start, Speed, Source In, Source Out, X, Y, Width, Height, Duration (effect layer). BulkClipPanel already uses a custom approach but should also use NumberInput.

### Issue 2: Speed change leaves dead space instead of shortening clip
Root cause found: In useClipEditing.ts (line 178), handleSelectedClipChange only updates timeline action positions when patch.at is defined. When speed changes via onChange({ speed: 2 }), there is no at in the patch, so the timeline action end position is never recalculated. The clip metadata updates but the action keeps its old duration, leaving dead space.

Fix: When the speed property changes in handleSelectedClipChange, recalculate action.end based on the new speed: action.end = action.start + getClipSourceDuration(clip) / newSpeed.

### Issue 3: Dropped videos default to 5 seconds instead of actual duration
In useExternalDrop.ts line 249, defaultClipDuration = 5 is used as a skeleton placeholder. After upload completes, it calls handleAssetDrop which does use the actual duration. However, the skeleton cleanup plus re-creation flow may not properly update the duration. The user reports the 5-second duration persists.

        # Implementation Plan: Video Editor — Three Fixes

## Overview

Three bugs in the video editor need fixing:
1. **NumberInput migration** — ClipPanel and BulkClipPanel use plain `<Input type="number">` instead of the shared `<NumberInput>` component with stepper arrows.
2. **Speed/trim change dead space** — `handleSelectedClipChange` and `handleUpdateClips` only update timeline action positions when `patch.at` is defined. When speed, from, to, or hold change, the timeline action keeps its old duration, leaving dead space. Both single-clip and bulk paths are affected.
3. **Dropped video 5s default** — `extractAssetRegistryEntry` only extracts video duration when `file.type.startsWith('video/')`. Files with missing or blank MIME types (common on some OSes for `.webm`, `.mov`, etc.) fall through to the generic handler, producing `duration: undefined`, which causes `handleAssetDrop` to fall back to 5 seconds.

## Phase 1: NumberInput Migration

**Scope:** Small

2. **Add** an optional `onValueCommitted?: (value: number | null) => void` prop. Wire it to `NumberField.Root`'s native `onValueCommitted` callback. This gives BulkClipPanel its commit-on-blur/pointer-release behavior without needing `onBlur`/`onKeyDown`.
3. **Keep** `onChange` firing on every keystroke as before (existing behavior for ClipPanel).

## Phase 2: Timing Duration Sync Fix

### Step 4: Create a shared action-duration recalculation helper (`src/tools/video-editor/hooks/useClipEditing.ts`)
**Scope:** Small
1. **Add** a helper function `recalcActionEnd` near the top of the file that computes the correct action `end` for a clip given its merged metadata:
   ```typescript
   function recalcActionEnd(action: TimelineAction, merged: ClipMeta): number {
     const sourceDur = typeof merged.hold === 'number'
       ? merged.hold
       : (merged.to ?? 0) - (merged.from ?? 0);
     return action.start + sourceDur / (merged.speed ?? 1);
   }
   ```
   This inlines the same logic as `getClipSourceDuration` / `getClipTimelineDuration` from `config-utils.ts` but works with `ClipMeta` directly (avoids a type cast).
2. **Define** a constant for the set of duration-affecting patch keys:
   ```typescript
   const DURATION_KEYS: (keyof ClipMeta)[] = ['speed', 'from', 'to', 'hold'];
   const patchAffectsDuration = (patch: Partial<ClipMeta>) =>
     DURATION_KEYS.some((k) => k in patch);
   ```

### Step 5: Fix `handleSelectedClipChange` for all duration-affecting properties (`src/tools/video-editor/hooks/useClipEditing.ts:166–201`)
**Scope:** Small
1. **Change** the gate at line 179 from `patch.at === undefined` to `patch.at === undefined && !patchAffectsDuration(metaPatch)`. When either `at` changes or a duration-affecting property changes, map the actions.
2. **In the action mapping** (line 184), when `action.id === selectedClipId`:
   - Compute `newStart = patch.at ?? action.start`.
   - If `patchAffectsDuration(metaPatch)`: merge current meta with patch and call `recalcActionEnd(action with newStart, merged)` to get `newEnd`.
   - Else (only `at` changed): preserve current duration: `newEnd = newStart + (action.end - action.start)`.
   - Return `{ ...action, start: newStart, end: newEnd }`.

### Step 6: Fix `handleUpdateClips` for bulk duration-affecting edits (`src/tools/video-editor/hooks/useClipEditing.ts:94–110`)
**Scope:** Small
1. **When** `patchAffectsDuration(patch)`, update `current.rows` before passing to `applyTimelineEdit`:
   ```typescript
   const nextRows = patchAffectsDuration(patch)
     ? current.rows.map((row) => ({
         ...row,
         actions: row.actions.map((action) => {
           if (!validClipIds.includes(action.id)) return action;
           const merged = { ...current.meta[action.id], ...patch };
           return { ...action, end: recalcActionEnd(action, merged) };
         }),
       }))
     : current.rows;
   applyTimelineEdit(nextRows, metaUpdates);
   ```
2. This ensures bulk speed/from/to/hold changes update both metadata AND action end positions.

## Phase 3: Drop Duration Fix

### Step 7: Add extension-based fallback in `extractAssetRegistryEntry` (`src/tools/video-editor/lib/mediaMetadata.ts:37–74`)
**Scope:** Small
1. **Root cause**: `extractAssetRegistryEntry` dispatches on `file.type` (MIME), but some OSes/browsers leave `file.type` blank for video files (especially `.webm`, `.mov`, `.mkv`). When `file.type` doesn't start with `video/`, the function falls through to the generic handler (line 70), returning no duration. `handleAssetDrop` then falls back to `assetEntry?.duration ?? 5`.
2. **Fix**: Add extension-based detection before the generic fallback. After the `audio/` check and before the generic return:
   ```typescript
   // Extension-based fallback for video files with missing/blank MIME
   const ext = file.name.slice(file.name.lastIndexOf('.')).toLowerCase();
   const videoExts = ['.mp4', '.webm', '.mov', '.mkv', '.avi', '.m4v', '.ogv'];
   if (videoExts.includes(ext)) {
     try {
       const metadata = await extractVideoMetadata(file);
       return {
         file: storagePath,
         type: file.type || `video/${ext.slice(1)}`,
         duration: metadata.duration_seconds,
         resolution: `${metadata.width}x${metadata.height}`,
         fps: metadata.frame_rate,
       };
     } catch {
       // Fall through to generic if video metadata extraction fails
     }
   }

   // Extension-based fallback for audio files with missing/blank MIME
   const audioExts = ['.mp3', '.wav', '.aac', '.m4a', '.ogg', '.flac'];
   if (audioExts.includes(ext)) {
     try {
       const metadata = await loadAudioMetadata(file);
       return {
         file: storagePath,
         type: file.type || `audio/${ext.slice(1)}`,
         duration: metadata.duration,
       };
     } catch {
       // Fall through to generic
     }
   }
   ```
3. **No changes** to `handleAssetDrop` or `useExternalDrop` — the registry chain already works correctly. The fix is at the source: ensuring `extractAssetRegistryEntry` always extracts duration for media files regardless of MIME availability.
