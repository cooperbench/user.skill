        # Implementation Plan: Replace @xzdarcy/react-timeline-editor with Custom TimelineCanvas

## Overview

**Goal:** Eliminate `@xzdarcy/react-timeline-editor` (~250KB minified, bundles interact.js and react-virtualized) by replacing its `<Timeline>` component with a custom `<TimelineCanvas>` that reuses the existing custom hooks.

**Current state:** The library is used as a thin rendering shell. Almost all behavior is already custom:
- **Drag** — fully custom (`useClipDrag` with pointer capture, `useExternalDrop` with HTML5 DnD)
- **Resize** — delegates to library via `onActionResizeStart/End` callbacks (the only real behavioral dependency)
- **Cursor/playhead** — library renders the cursor line; sync uses `timelineRef.current.setTime(time)` — the only method called on `TimelineState`
- **Ruler** — library renders the time ruler (scale ticks + labels)
- **Row layout** — library uses react-virtualized to render rows; each action rendered via `getActionRender` callback (fully custom `<ClipAction>`)
- **onChange** — only fires during resize (since `movable: false` on all actions)

**What the library actually provides (that we must replicate):**
1. **Time ruler** — tick marks at `scaleSplitCount` intervals, scale labels
2. **Row grid** — rows of `rowHeight` px, horizontally scrollable, actions positioned by `start`/`end` × `pixelsPerSecond`
3. **Action positioning** — absolute-positioned divs for each action with left/width computed from time
4. **Resize handles** — left/right drag handles on actions (via interact.js), fires `onActionResizeStart/Resizing/End`
5. **Cursor line** — vertical line at current time, draggable via pointer on ruler
6. **Click-on-ruler** — `onClickTimeArea` callback
7. **Scroll sync** — header ruler syncs scroll with edit area
8. **Virtualization** — react-virtualized `Grid` for the edit area (only matters with many tracks)

**What we DON'T need to replicate:**
- Built-in drag (`movable: false` everywhere)
- Row drag reordering (custom track management)
- Timeline engine/playback engine (we use Remotion)
- `dragLine` assist lines
- Effect system (custom ClipMeta)

**Key constraint:** The `drop-position.ts` module queries `.timeline-editor-edit-area` and `.ReactVirtualized__Grid` DOM nodes for scroll offsets. These selectors must be replaced with refs or new class names.

## Phase 1: Foundation — Types, Ruler, Grid Shell

### Step 1: Define own types to replace `@xzdarcy/timeline-engine` types
**Scope:** Small
1. **Create** `src/tools/video-editor/types/timeline-canvas.ts` with:
   ```ts
   // Drop-in replacements — same shape, our own ownership
   export interface TimelineAction { id: string; start: number; end: number; effectId: string; }
   export interface TimelineRow { id: string; actions: TimelineAction[]; }
   // Replaces TimelineState ref — only setTime is used
   export interface TimelineCanvasHandle { setTime(time: number): void; getTime(): number; target: HTMLElement | null; }
   ```
2. **Update** all imports across ~11 files from `@xzdarcy/timeline-engine` → `@/tools/video-editor/types/timeline-canvas`.
3. **Update** `useTimelineSync.ts` and `useTimelinePlayback.ts` to import `TimelineCanvasHandle` instead of `TimelineState`.
4. **Validate:** `tsc --noEmit` passes with zero library references remaining in video-editor source files.

### Step 2: Build `<TimeRuler>` component
**Scope:** Medium
1. **Create** `src/tools/video-editor/components/TimelineEditor/TimeRuler.tsx`.
2. **Implement** a horizontal ruler that:
   - Accepts `scale`, `scaleWidth`, `scaleSplitCount`, `startLeft`, `scrollLeft`, `totalWidth`.
   - Renders major ticks at each `scaleWidth` interval with formatted time labels (`formatTime` from coordinate-utils).
   - Renders minor ticks at `scaleWidth / scaleSplitCount` intervals.
   - Syncs horizontal scroll position via a shared `scrollLeft` value (not its own scroll — controlled by parent).
   - Handles `onClick` → computes time from clientX and calls `onClickTimeArea`.
   - Handles pointer drag on cursor → calls `onCursorDrag` with computed time.
3. **Style** using Tailwind + the existing dark theme colors from `timeline-overrides.css`.
4. **Validate:** Render in isolation with static props; visual parity with library ruler.

### Step 3: Build `<TimelineCanvas>` grid shell
**Scope:** Large — this is the core replacement
1. **Create** `src/tools/video-editor/components/TimelineEditor/TimelineCanvas.tsx`.
2. **Implement** a scrollable grid that:
   - Accepts `rows: TimelineRow[]`, `scale`, `scaleWidth`, `startLeft`, `rowHeight`, `scaleCount`.
   - Computes `totalWidth = scaleCount * scaleWidth + startLeft`.
   - Renders a vertical stack of row containers, each `rowHeight` px tall.
   - Inside each row, positions action divs absolutely: `left = action.start * pixelsPerSecond + startLeft`, `width = (action.end - action.start) * pixelsPerSecond`.
   - Calls `getActionRender(action, row)` for each action's content.
   - Horizontal + vertical scroll via native `overflow: auto` on the grid container.
   - Syncs scroll position with `<TimeRuler>` via a shared ref or callback.
   - Background grid lines at `scaleWidth / scaleSplitCount` intervals using `background-image: repeating-linear-gradient(...)`.
3. **Expose** `ref: TimelineCanvasHandle` via `useImperativeHandle`:
   - `setTime(t)` — updates cursor position state.
   - `getTime()` — returns current cursor time.
   - `target` — the grid container DOM node.
4. **Render cursor line** as an absolute-positioned div at `currentTime * pixelsPerSecond + startLeft` within the grid, updating on every `setTime` call via a ref (not state, for perf during playback).
5. **Skip virtualization initially** — the video editor typically has 2–8 tracks. If needed later, add windowing for rows.
6. **Wire** `editAreaRef` to the grid container's DOM node (replaces `.timeline-editor-edit-area` queries).

## Phase 2: Resize + Interaction Wiring

### Step 4: Build pointer-event resize handles
**Scope:** Medium
1. **Add** left and right resize handles to each action wrapper in `<TimelineCanvas>`:
   - Thin (8px) absolute-positioned divs at left and right edges, `cursor: ew-resize`.
   - On `pointerdown`: capture pointer, record initial `action.start`/`action.end` and `clientX`.
   - On `pointermove`: compute new `start` or `end` based on delta, clamp to `>= 0` and maintain minimum width.
   - Fire `onActionResizing({ action: updatedAction, row, start, end, dir })` during drag for live preview.
   - On `pointerup`: fire `onActionResizeEnd({ action: updatedAction, row, dir })`.
   - On `pointerdown` also fire `onActionResizeStart({ action, row, dir })`.
2. **Keep** the same callback signatures as the library so `useClipResize.ts` needs zero changes.
3. **Validate:** Resize a clip and confirm `useClipResize` receives correct start/end/dir values and persists correctly.

### Step 5: Update `drop-position.ts` DOM queries
**Scope:** Small
1. **Replace** `.timeline-editor-edit-area` query with a ref passed from `TimelineCanvas` (or a stable class like `.timeline-canvas-edit-area`).
2. **Replace** `.ReactVirtualized__Grid` scroll queries with the grid container ref's `scrollLeft`/`scrollTop`.
3. **Update** `TimelineEditor.tsx:116-121` (`clientXToTime`) similarly.
4. **Update** `getTimelineDomNodes` cache in `drop-position.ts` to use new selectors.
5. **Validate:** Internal clip drag and external drop still compute correct positions.

### Step 6: Wire `TimelineCanvas` into `TimelineEditor.tsx`
**Scope:** Medium
1. **Replace** the `<Timeline>` import and JSX with `<TimelineCanvas>`:
   - Pass same props: `ref={timelineRef}`, `rows={immovableRows}` (can drop `immovableRows` mapping since we no longer need `movable: false`), `effects`, `scale`, `scaleWidth`, etc.
   - Pass `getActionRender`, `onCursorDrag`, `onClickTimeArea`, `onActionResizeStart`, `onActionResizeEnd`, `onChange`.
2. **Remove** the `immovableRows` memo (no longer needed — library was the only consumer of `movable`).
3. **Remove** imports of `@xzdarcy/react-timeline-editor` and its CSS.
4. **Validate:** Full editor loads, clips render at correct positions, ruler shows correct times.

## Phase 3: Cleanup + Validation

### Step 7: Migrate CSS and remove library styles
**Scope:** Small
1. **Remove** `@xzdarcy/react-timeline-editor/dist/react-timeline-editor.css` import.
2. **Update** `timeline-overrides.css`:
   - Remove rules targeting `.timeline-editor-*` classes that no longer exist.
   - Keep drop indicator, ghost, and drag-over styles (these are our own).
   - Add any new styles needed for `TimelineCanvas` grid/ruler.
3. **Validate:** No unstyled or broken elements.

### Step 8: Remove the library dependency
**Scope:** Small

### Step 9: End-to-end behavioral validation
**Scope:** Medium
1. **Test** each interaction path:
   - Click ruler to set playhead
   - Drag cursor on ruler to scrub
   - Resize clip from left edge (should adjust `from` time)
   - Resize clip from right edge (should adjust `to` time)

   - Zoom (if scaleWidth is adjustable)
   - Playback sync between timeline cursor and Remotion preview
2. **Verify** no regressions in `useClipDrag`, `useExternalDrop`, `useDragCoordinator`.
3. **Verify** `useTimelineSync` still syncs preview ↔ timeline cursor correctly with new `TimelineCanvasHandle`.
