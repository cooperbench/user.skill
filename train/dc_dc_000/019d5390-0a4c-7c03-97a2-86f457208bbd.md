        # Implementation Plan: Dynamic API Key Pool

## Overview

Currently, both `hermes_worker.py` and `parallel_critique.py` resolve API keys at call time by reading env vars / `~/.hermes/.env`. There's only one key per provider — no rotation, no cooldown on 429s, no hot-reload. The model resolution logic is also duplicated between the two files.

This plan introduces a new `megaplan/key_pool.py` module that both files import from. It provides:
- A thread-safe key pool per provider (zhipu, minimax, google, openrouter)
- Periodic re-reading of `~/.hermes/.env` (every 60s, not every call)
- Round-robin key selection with 429 cooldown
- Failed-key skipping

The key pool manages multiple keys per provider by convention: `ZHIPU_API_KEY`, `ZHIPU_API_KEY_2`, `ZHIPU_API_KEY_3`, etc. in `~/.hermes/.env`.

## Main Phase

### Step 1: Create the key pool module (`megaplan/key_pool.py`)
**Scope:** Medium

1. **Create** `megaplan/key_pool.py` with a `KeyPool` class:
   - Thread-safe (uses `threading.Lock`)
   - Stores keys per provider as a list of `KeyEntry` dataclasses: `(key: str, last_used: float, cooldown_until: float, failed: bool)`
   - `_load_keys()` method: reads `~/.hermes/.env`, finds all keys for a provider by pattern (`ZHIPU_API_KEY`, `ZHIPU_API_KEY_2`, etc.), plus `os.environ` overrides. Caches result with a 60-second TTL.
   - `acquire(provider: str) -> str`: returns the best available key (least-recently-used among non-cooled-down, non-failed keys). Updates `last_used`. Raises if no keys available.
   - `report_429(provider: str, key: str, cooldown_secs: float = 60)`: sets `cooldown_until` on that key entry.
   - `report_failure(provider: str, key: str)`: marks key as permanently failed for this session.

2. **Expose** a module-level singleton: `_pool = KeyPool()` with public functions `acquire_key(provider)`, `report_429(provider, key, cooldown)`, `report_failure(provider, key)`.

3. **Move** `_load_hermes_env()` and `_get_api_credential()` into this module (they're the foundation).

4. **Create** a new `resolve_model(model: str | None) -> tuple[str, dict[str, str]]` function that replaces the duplicated `_resolve_model` logic. It calls `acquire_key(provider)` instead of `_get_api_credential()` for the `api_key` field. Base URLs still use `_get_api_credential()` (no pooling needed for URLs).
