        # Implementation Plan: Banodoco Website Database Backed Agent Nodes

## Overview
The website app is in `reigh-app`, with Supabase migrations under `supabase/migrations`, generated database types in `src/integrations/supabase/types.ts`, React routes in `src/app/routes.tsx`, and resource/media patterns in `src/features/resources` plus LoRA sample upload UI under `src/domains/lora/.../SampleGenerationsSection.tsx`. ArtAgents already has executable node schema, curated/built-in registry, CLI, and local venv install behavior in `ArtAgents/artagents/nodes/{schema.py,registry.py,folder.py,install.py,cli.py}`.

The implementation should keep Banodoco agent nodes separate from website resources/assets, but borrow the resource browser/media ergonomics. The key v1 correction is that install targets must support git-backed repos: `repo_url`, optional `source_ref`/`commit`/`tag`/`branch`, `manifest_path`, and deterministic local cache/install behavior. `manifest_url` and `archive_url` can remain optional alternatives.

## Phase 1: Banodoco Website DB Foundation

### Step 1: Add dedicated agent-node schema (`reigh-app/supabase/migrations/`)
**Scope:** Large
1. Create a migration for dedicated tables, not rows in `resources`:
   - `agent_nodes`: user-owned/creator-attributed node records with slug/name/description/details, `repo_url`, manifest summary/details, visibility flags, and timestamps.
   - `agent_node_install_targets`: service-controlled or owner-editable install target rows with `target_type` (`git`, `manifest_url`, `archive_url`), git fields (`repo_url`, `source_ref`, `commit`, `tag`, `branch`, `manifest_path`), local cache/install hints, `is_default`, `is_mandatory`, `install_priority`, and enabled state.
   - `agent_node_media_items`: ordered sample media rows with `media_type`, storage path or URL, thumbnail/poster URL, alt/caption, and primary flag.
   - Optional `agent_node_catalog_metadata` or service-controlled columns on `agent_nodes` for `is_featured`, `is_public`, `is_default`, `is_mandatory`, `catalog_rank`, and `catalog_source`.
2. Add RLS matching the existing resources ownership/public-read pattern: public users can read public enabled nodes/media; owners can manage their nodes/media; service role can manage catalog/default/mandatory metadata and install targets.
3. Add indexes for browse paths: public/featured/default/mandatory, slug, owner, creator/Discord attribution, and install target priority.

### Step 2: Regenerate/update website DB types (`reigh-app/src/integrations/supabase/types.ts`)
**Scope:** Small
1. Update generated Supabase types so the app can type `agent_nodes`, `agent_node_install_targets`, and `agent_node_media_items` directly.
2. Add domain types in a new module such as `src/features/agent-nodes/types.ts`, including a v1 install-target union where git is first-class.

## Phase 2: Website API and Hooks

### Step 3: Add query keys and hooks (`reigh-app/src/features/agent-nodes/`, `src/shared/lib/queryKeys/`)
**Scope:** Medium
1. Add `agentNodeQueryKeys` separate from `resourceQueryKeys`.
2. Implement hooks for listing public/catalog nodes, listing current user nodes, fetching node details, creating/updating nodes, creating/updating install targets, and attaching/deleting/reordering media.
3. Keep metadata normalization minimal: use typed payloads and Supabase structured fields instead of hiding important install fields in JSON.

### Step 4: Add website API endpoints for ArtAgents consumers (`reigh-app/supabase/functions/agent-nodes-*`)
**Scope:** Medium
1. Add a read API for default/mandatory install targets that returns only enabled public/service-approved targets and includes enough data for ArtAgents to fetch manifests.
2. Add a detail API for a single node/slug if the UI or installer needs it.
3. Validate responses so git targets always include `repo_url` and `manifest_path`, and URL/archive targets include their URL fields.
4. Add edge-function unit tests following the existing `supabase/functions/*/index.test.ts` style.

## Phase 3: Website UI

### Step 5: Build browse/detail UI (`reigh-app/src/pages/`, `src/features/agent-nodes/components/`)
**Scope:** Large
1. Add routes in `src/app/routes.tsx`, likely `/agent-nodes` and `/agent-nodes/:slug`, behind the normal app layout if creation requires auth.
2. Build a browser grid using the resource-browser search/filter/pagination pattern, but with agent-node-specific fields: name, creator/Discord attribution, repo URL, featured/default/mandatory badges, install target summary, and sample media previews.
3. Build a create/edit form for authenticated users with repo URL, manifest path/details, description, creator attribution, public flag, and media upload/attachment.
4. Mirror `SampleGenerationsSection.tsx` for image/video sample management, but store rows in `agent_node_media_items` rather than embedding samples in resource metadata.

### Step 6: Add storage/media behavior (`reigh-app/src/shared/lib/media/`, Supabase storage migration if needed)
**Scope:** Medium
1. Reuse existing media upload helpers where practical.
2. If existing buckets/policies do not fit public sample media, add a dedicated `agent-node-media` bucket with owner-write and public-read policy for public node media.
3. Store durable public URLs or bucket paths consistently in `agent_node_media_items`.

## Phase 4: ArtAgents DB-Backed Registry

### Step 7: Add Banodoco website client (`ArtAgents/artagents/nodes/website_catalog.py`)
**Scope:** Medium
1. Add a small stdlib HTTP client that reads the Banodoco website API base URL and auth token from environment/config.
2. Fetch default and mandatory ArtAgents node install targets from the Banodoco website DB/API.
3. Parse API payloads into a local install target model that supports git targets plus optional `manifest_url`/`archive_url` targets.
4. Keep failures clear: unavailable website catalog should not obscure built-in node validation unless mandatory install mode explicitly requires it.

### Step 8: Support git-backed install targets (`ArtAgents/artagents/nodes/install.py`, `registry.py`)
**Scope:** Large
1. Add deterministic local cache paths under `.artagents/nodes/<node_id>/source` or `.artagents/catalog/<stable-target-id>`.
2. For git targets, clone/fetch `repo_url`, check out `commit` if present, otherwise `tag`/`branch`/`source_ref`, then load `manifest_path` through existing `load_node_manifest` or folder-node loading if the manifest path points to a folder/node.py contract.
3. Preserve existing venv install behavior: after source resolution, install dependencies from `pyproject.toml`, `requirements.txt`, or node isolation metadata.
4. Ensure mandatory/default targets can be installed automatically when appropriate, while normal external nodes still support explicit `pipeline.py nodes install <node_id>`.

### Step 9: Merge website nodes into the ArtAgents registry (`ArtAgents/artagents/nodes/registry.py`, `cli.py`)
**Scope:** Medium
1. Extend `load_default_registry()` to load built-ins, bundled curated nodes, then enabled Banodoco website default/mandatory nodes.
2. Decide duplicate precedence explicitly: built-ins should win over website nodes; duplicate external IDs from website should fail loudly or be skipped with diagnostics.
3. Add CLI affordances such as `pipeline.py nodes sync` or `pipeline.py nodes install-defaults --dry-run` if automatic install needs an explicit command path.
4. Add tests for built-in + curated + website node merge order and duplicate handling.

## Phase 5: Validation and Tests

### Step 10: Website tests (`reigh-app`)
**Scope:** Medium
1. Add hook tests for list/create/update/media attach behavior.
2. Add component tests for browse grid, create/edit form validation, git install-target fields, and media display.
3. Add edge-function tests for public/default/mandatory catalog payloads.
4. Run targeted tests first, then `npm run test` and type/lint checks as feasible.

### Step 11: ArtAgents tests (`ArtAgents/tests`)
**Scope:** Medium
1. Add unit tests for git target normalization, clone/cache path planning, manifest loading from a checked-out repo, and dry-run installer output.
2. Add registry tests with mocked Banodoco website API responses for default and mandatory nodes.
3. Add CLI tests for install-default/default sync behavior and ensure existing curated `external.moirae` tests still pass.
4. Run targeted node tests before the broader ArtAgents test suite.

## Execution Order
1. Start with the database migration and TypeScript/Python target models, because UI/API/installer work depends on stable shapes.
2. Build the read API before the full website UI so ArtAgents integration can be developed against a real contract early.
3. Implement website hooks and browse/create UI after the table/API contracts are settled.
4. Add ArtAgents fetch/registry support before automatic installer behavior, so validation can prove manifests load before anything is installed.
5. Add local installer download/cache behavior last, behind dry-run tests first.

## Validation Order
1. SQL migration syntax/type review and generated type compile.
2. Targeted website hook/component/edge tests.
3. Targeted ArtAgents node registry/install tests.
4. Website typecheck/lint/test commands.
5. ArtAgents targeted tests, then broader Python test suite if runtime permits.
