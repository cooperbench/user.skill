# Implementation Plan: Authoring Layer (Composition + Verb-Native) on Top of VibeComfy

## Overview

Goal: introduce a higher-abstraction authoring layer over `VibeWorkflow` so curated workflows are composed from named, editable fragments and exposed as ordinary Python verbs that return typed artifacts. Two sequenced layers stack on the same IR: **(1) Composition** (`blocks/`, `patches/`, refactored `ready_templates/`, `recipes/`), and **(2) Verb-native** (`ops/{image,video,audio,edit}` returning `Image | Video | Audio | Latent | Mask` artifacts, with a router and lazy `preview_workflow()`/`compile()` escape hatches).

Repository shape today (April 2026):
- `vibecomfy/workflow.py:71` defines `VibeWorkflow` with `set_prompt`, `set_seed`, `set_steps`, `set_input`, `add_node`, `connect`, `compile("api")`, `compile("graphbuilder")`, and `validate()`.
- `vibecomfy/registry/ready.py:9` discovers `ready_templates/{image,video,edit}/*.py` as importable modules; each module owns a giant `API_WORKFLOW` dict + `READY_METADATA` and a `_ready_template_policy` mutator. Eight templates exist (z_image, flux2_klein_4b/9b, qwen_image_edit, flux2_klein_4b_image_edit_distilled, wan_t2v, wan_i2v, ltx2_3_t2v, ltx2_3_i2v).
- `vibecomfy/ingest/normalize.py:72` is the only constructor that turns API dicts into `VibeWorkflow`. Today every ready template calls it.
- CLI entry points are wired in `vibecomfy/commands/__init__.py:5` (`sources/workflows/nodes/analyze/search/inspect/convert/validate/doctor/run/runtime/logs/runpod`) and exposed via `vibecomfy/cli.py:9`. Runpod helpers in `vibecomfy/commands/runpod.py:69` and `scripts/runpod_runner.py:1` are public entry points and must keep working.
- The repo top-level `__init__.py` in `vibecomfy/__init__.py:1` defines what is publicly importable today.
- Tests live in `tests/test_workflow_core.py:1`, `tests/test_ready_templates.py:1`, etc. The third ready-template test (`test_ready_template_uses_real_python_before_comfy_compile`) verifies that the Python policy runs *before* compile — refactored templates must keep that property.

Constraints to honour:
- `VibeWorkflow` is the only editable IR. Blocks/patches/ops produce or mutate a `VibeWorkflow`; nothing else gets edited.
- Embedded ComfyUI is the default runtime (`run_embedded` in `vibecomfy/runtime/run.py:101`).
- Existing CLI commands and runpod scripts keep working unchanged from a user's POV.
- Repo is not a git repo. Do not run `git init`.
- `.megaplan/` references in the brief are external — do not depend on them.

The plan is split into four phases. Phases 1–2 are the substantive build; phases 3–4 cover contributor surface and verification.

## Phase 1: Composition Foundation — Blocks, Patches, Refactored Templates, Recipes

### Step 1: Define the block + patch contracts (`vibecomfy/blocks/__init__.py`, `vibecomfy/patches/__init__.py`, `docs/authoring.md`)
**Scope:** Small

1. **Decide the block contract** in code as a small protocol module (`vibecomfy/blocks/__init__.py`). A *block* is a function `block(workflow: VibeWorkflow, **kwargs) -> Handles`, where `Handles` is a frozen dataclass exposing the named outputs the block produced (e.g., `LatentSampler.handles.samples == "3.0"`, `LoaderTriple.handles.{model, clip, vae}`). Blocks must mutate a `VibeWorkflow` via `add_node` / `connect` (preserving `VibeWorkflow` as the only IR) and never return raw dicts.
2. **Decide the patch contract** in `vibecomfy/patches/__init__.py`. A *patch* is `Patch(name, applies_to(workflow) -> bool, apply(workflow) -> VibeWorkflow)`. `applies_to` returns True when the patch is safe/relevant (e.g., `ltx_lowvram.applies_to` checks for `LTXVideo` class types and < 24GB VRAM hint). `apply` mutates and returns the same workflow. Decorators registered via a module-level `register(patch)` populate a patch registry (`vibecomfy/patches/registry.py`) for later doctor + router lookup.
3. **Capture the rule** "changes handles → new template; decorates handles → patch" in a short `docs/authoring.md` (≤80 lines) with one image template, one video patch, and one mistake counter-example (using LTX policy as the illustration). Skip an AGENTS.md file at this step — that lands in Phase 3.

### Step 2: Add shared blocks (`vibecomfy/blocks/{loaders,sampling,encoding,save,empty_latent}.py`)
**Scope:** Medium

1. **Extract** the patterns that recur across `ready_templates/`. Confirmed by reading the eight existing files:
   - `loaders.unet_clip_vae(workflow, *, unet, clip, vae, clip_type="wan", clip_device="default")` → `Handles(model, clip, vae)` (used by every WAN/LTX/Flux2 template).
   - `loaders.clip_vision(workflow, *, name)` → `Handles(clip_vision)` (wan_i2v).
   - `encoding.text_pair(workflow, *, clip, positive, negative)` → `Handles(positive, negative)` (every video template).
   - `sampling.ksampler(workflow, *, model, positive, negative, latent, seed, steps, cfg, sampler_name, scheduler, denoise=1.0)` → `Handles(samples)`.
   - `sampling.model_sampling_sd3(workflow, *, model, shift)` → `Handles(model)`.
   - `empty_latent.hunyuan_video(workflow, *, width, height, length, batch=1)` → `Handles(latent)`.
   - `save.image(workflow, *, images, prefix)`; `save.video(workflow, *, video, prefix, format="auto", codec="auto")`; `decode.vae(workflow, *, samples, vae)` → `Handles(images)`; `video.create(workflow, *, images, fps)` → `Handles(video)`.
2. **Each block** records `block_id`, `widget_kwargs`, and `metadata.block = "loaders.unet_clip_vae"` on the produced nodes so analysis tools can later round-trip ready templates back to block calls.
3. **Keep** node IDs deterministic by routing through `VibeWorkflow.add_node` (which uses `_next_node_id` at `vibecomfy/workflow.py:167`). Do not hand-pick IDs.

### Step 3: Add the first patches (`vibecomfy/patches/{ltx_lowvram,gguf_unet,resolution,seed,save_prefix}.py`)
**Scope:** Medium

1. **Port** the policy logic currently embedded in `scripts/materialize_ready_templates.py:58-93` into real `Patch` objects:
   - `gguf_unet`: replaces `UNETLoader` with `UnetLoaderGGUF`, swaps unet_name, appends `ComfyUI-GGUF` requirement.
   - `ltx_lowvram`: applies the dimension/widget tweaks and `comfy_configuration={reserve_vram, cache_none, fp8_e4m3fn_text_enc}`.
   - `resolution(width, height, length=None)`: rewrites width/height widgets on `EmptyHunyuanLatentVideo` / scaling nodes; `applies_to` returns True when at least one such node is present.
   - `seed(value)`: thin wrapper around `workflow.set_seed`, useful for the router.
   - `save_prefix(value)`: rewrites `widget_0` on `SaveImage`/`SaveVideo`.
2. **Register** each via `vibecomfy.patches.registry.register(patch)`. Add a `find_applicable(workflow)` helper that returns `[Patch]` for doctor's later use.
3. **Public import:** re-export from `vibecomfy/patches/__init__.py`. Keep names short (e.g., `from vibecomfy.patches import gguf_unet, ltx_lowvram`).

### Step 4: Refactor `ready_templates/` into fragment-style builders (`ready_templates/image/*.py`, `ready_templates/video/*.py`, `ready_templates/edit/*.py`)
**Scope:** Large

1. **Replace** the giant `API_WORKFLOW = {...}` dictionaries with `build()` functions that compose blocks. Worked example for `ready_templates/video/wan_t2v.py`:
   ```python
   from vibecomfy.workflow import VibeWorkflow, WorkflowSource
   from vibecomfy.blocks import loaders, encoding, empty_latent, sampling, decode, save, video as video_blocks

   READY_METADATA = {"ready_template": "wan_t2v", "capability": "text_to_video", "source_role": "curated_python_template"}

   def build() -> VibeWorkflow:
       wf = VibeWorkflow(id="wan_t2v", source=WorkflowSource(id="wan_t2v", path=__file__, source_type="ready_template"))
       core = loaders.unet_clip_vae(wf, unet="wan2.1_t2v_1.3B_fp16.safetensors", clip="umt5_xxl_fp8_e4m3fn_scaled.safetensors", clip_type="wan", vae="wan_2.1_vae.safetensors")
       sampled_model = sampling.model_sampling_sd3(wf, model=core.model, shift=8).model
       cond = encoding.text_pair(wf, clip=core.clip, positive="a fox moving quickly...", negative="色调艳丽,...")
       lat = empty_latent.hunyuan_video(wf, width=832, height=480, length=33).latent
       samples = sampling.ksampler(wf, model=sampled_model, positive=cond.positive, negative=cond.negative, latent=lat, seed=82628696717253, steps=30, cfg=6, sampler_name="uni_pc", scheduler="simple").samples
       images = decode.vae(wf, samples=samples, vae=core.vae).images
       video = video_blocks.create(wf, images=images, fps=16).video
       save.video(wf, video=video, prefix="video/ComfyUI")
       wf.metadata.update(READY_METADATA)
       wf.metadata["ready_template_path"] = __file__
       return wf
   ```
2. **Apply policy patches** instead of inlined mutators: `ltx2_3_t2v.build()` ends with `return ltx_lowvram.apply(resolution(width=384, height=256, length=9).apply(wf))`. The `_ready_template_policy` mutator in each existing file goes away.
3. **Preserve** the exact node-id determinism that downstream tests depend on by emitting blocks in the same order as the legacy dicts where a test asserts on it. Where IDs are not asserted, allow blocks to assign their own.
4. **Drop** `convert_to_vibe_format(API_WORKFLOW, ...)` from each ready template — `VibeWorkflow` is now the editable IR, no JSON round-trip needed for hand-written templates. This is the change the brief explicitly calls out.
5. **Update** `scripts/materialize_ready_templates.py` to emit block-based Python instead of `pformat`-ed dicts — or, if too lossy for auto-generated ones, keep the API-dict path *only* for templates that aren't yet hand-curated and document that gap in `docs/authoring.md`. (See Question 3.)

### Step 5: Add `recipes/` for worked compositions (`recipes/`, `recipes/README.md`, ~3 recipe files)
**Scope:** Small

1. **Create** `recipes/` at repo root (sibling to `ready_templates/`) with three illustrative scripts that compose blocks/patches *without* being a ready template:
   - `recipes/wan_i2v_lowres.py` — wan_i2v base + `resolution(384, 256, 9)` patch.
   - `recipes/dual_pass_t2i.py` — z_image followed by an upscaling chain (uses `image.t2i` op once Phase 2 lands; keep this as a TODO until then or use raw blocks now).
   - `recipes/wan_t2v_long.py` — wan_t2v + `resolution(832, 480, 81)` + custom seed.
2. **Make recipes** runnable directly with `python recipes/wan_i2v_lowres.py`, calling `run_embedded_sync(build())`.
3. **Document** the difference from `ready_templates/` in `recipes/README.md`: "ready templates change handles, recipes decorate handles." This is the on-disk rule statement.

### Step 6: Tests for blocks/patches/refactored templates (`tests/test_blocks.py`, `tests/test_patches.py`, `tests/test_ready_templates.py`)
**Scope:** Medium

1. **`tests/test_blocks.py`**: smoke each block builder; assert the produced workflow `compile("api")` matches expected node count and widget keys.
2. **`tests/test_patches.py`**: instantiate a minimal workflow, run each patch's `applies_to` (positive + negative), then `apply`; assert workflow diff matches the policy that used to live in `materialize_ready_templates.py`.
3. **Keep** the existing `tests/test_ready_templates.py` assertions (`ids include`, `validate().ok`, `external_python_marker` round-trip). The marker test (`tests/test_ready_templates.py:19`) must keep passing — confirm by running before/after.

## Phase 2: Verb-Native — Typed Artifacts, Ops, Router, Escape Hatches

### Step 7: Typed artifacts (`vibecomfy/artifacts.py`)
**Scope:** Small

1. **Define** `Artifact` as a frozen dataclass: `workflow: VibeWorkflow`, `node_id: str`, `output_slot: int`, `kind: Literal["image","video","audio","latent","mask"]`, `metadata: dict`.
2. **Subclasses** are thin tags: `Image(Artifact)`, `Video(Artifact)`, `Audio(Artifact)`, `Latent(Artifact)`, `Mask(Artifact)`. They give type-checkers + agents something concrete to read; runtime behaviour is identical.
3. **Add** `Artifact.preview_workflow() -> VibeWorkflow` (returns `self.workflow`) and `Artifact.compile() -> dict` (calls `self.workflow.compile("api")`). This is the explicit escape hatch the brief calls out.
4. **Add** `Artifact.run(*, runtime="embedded", **kwargs)` that delegates to `vibecomfy.runtime.run_embedded_sync` / `run_sync` based on `runtime`. Default is embedded per the constraint.

### Step 8: Verb ops (`vibecomfy/ops/__init__.py`, `vibecomfy/ops/image.py`, `vibecomfy/ops/video.py`, `vibecomfy/ops/audio.py`, `vibecomfy/ops/edit.py`)
**Scope:** Large

1. **Define** verb functions that return artifacts:
   - `image.t2i(prompt, *, model=None, width=1024, height=1024, steps=None, seed=None, **overrides) -> Image`.
   - `image.edit(image, instruction, *, model=None, **overrides) -> Image`.
   - `video.t2v(prompt, *, model=None, width=None, height=None, length=None, fps=16, seed=None, **overrides) -> Video`.
   - `video.i2v(image, prompt, *, model=None, length=None, fps=16, seed=None, **overrides) -> Video`.
   - `audio.t2a(...) -> Audio` (stub returning `NotImplementedError("no audio template registered")` until an audio template ships — flagged in `docs/authoring.md`).
   - `edit.qwen(image, instruction, **overrides) -> Image` (delegated through `image.edit`).
2. **Op body** delegates to the router (Step 9): pick a `(template_id, [patch, ...])` for the verb + inputs + environment, build the `VibeWorkflow`, set the prompt/seed/etc., apply patches, and return the typed artifact pointing at the workflow's terminal save node.
3. **Pipelines as ordinary Python**: e.g., `video.i2v(image=image.t2i("a fox").run().outputs[0], prompt="walking", length=33).run()`. Two cases must both work:
   - chain through artifact metadata path (lazy: `op.preview_workflow()` includes everything composed so far) — Phase 2.5 stretch, keep simple for first pass.
   - chain through file paths returned by `Artifact.run()` — required for first cut.
4. **Public surface**: re-export from `vibecomfy/__init__.py` so `from vibecomfy import image, video, audio, edit` works. The brief says "everything publicly importable."

### Step 9: Router (`vibecomfy/router.py`)
**Scope:** Medium

1. **Inputs:** `verb: str`, `inputs: dict` (presence of an `image`, requested model name, requested resolution/length), `environment: dict` (available models on disk + GPU memory hint, both pluggable; default detector reads `vibecomfy.runtime` + filesystem).
2. **Logic:** start with a hand-written decision table keyed on `(verb, requested_model_or_capability)`. For example: `("image", "t2i", model in {"z_image", None}) -> "image/z_image"`, `("video", "t2v", model in {"wan", None}) -> "video/wan_t2v"`, `("video", "i2v", model="ltx") -> ("video/ltx2_3_i2v", [ltx_lowvram, resolution(384, 256, 9)])`. Fall back to `KeyError("no template for verb={...}")` instead of guessing.
3. **Patch suggestion:** also call `vibecomfy.patches.registry.find_applicable(workflow)` *after* template selection, so doctor (Step 13) and router share the same probe. The router applies a configurable subset (e.g., `auto_patches=True` default for memory-related patches, `auto_patches=False` for resolution/seed which the user is overriding explicitly).
4. **Make** the table data-driven (`vibecomfy/router_rules.py` or a small `routes.py` list) so plugins (Step 11) can extend it via `register_route(verb, predicate, template_id, patches=())`.

### Step 10: Tests for ops + router (`tests/test_ops.py`, `tests/test_router.py`)
**Scope:** Small

1. **`tests/test_router.py`**: assert `router.pick("image", "t2i") == ("image/z_image", [])` and `router.pick("video", "i2v", model="ltx") == ("video/ltx2_3_i2v", [ltx_lowvram_patch_instance, resolution_patch_instance])`. Cover `KeyError` path.
2. **`tests/test_ops.py`**: call `image.t2i("hello")` *without* running, assert `Image.preview_workflow()` returns a valid `VibeWorkflow` whose `compile("api")` has a `SaveImage` node and a node carrying the prompt.
3. **Skip** end-to-end runs in CI (those are runpod-only). Include a `@pytest.mark.runpod` marker on a single golden-path runpod test for hand-running.

## Execution Order

1. Phase 1 lands first as a single PR-equivalent: blocks → patches → refactored ready templates → recipes → tests. Each ready template is converted one-by-one with a per-template snapshot diff to catch widget drift. The refactor stays mechanical (no new behaviour) so failures point at the block/patch contract, not at the porting.
2. Phase 2 lands second: artifacts → ops → router → tests. It depends on Phase 1's blocks/patches.
3. Phase 3 lands third: plugin discovery → AGENTS.md → JSON output → doctor suggestions. This is contributor surface; nothing in Phase 1/2 depends on it.
4. Phase 4 is the validation pass; it touches public exports last so partially-built APIs aren't accidentally surfaced earlier.

## Validation Order

1. Cheapest first: per-block unit tests, per-patch unit tests.
2. Then ready-template tests (refactored builders still produce equivalent compiled API dicts).
3. Then ops + router tests using `preview_workflow()` (no GPU runs).
4. Then full pytest suite.
5. Then CLI smoke (`--help` on every command, `inspect --json`, `doctor --json` on a known template).
6. Last: a single hand-launched runpod execution of `image.t2i("smoke prompt").run()` to confirm the end-to-end embedded path still works (info-level criterion — outside CI).

# Implementation Plan: Authoring Layer (Composition + Verb-Native) on Top of VibeComfy

## Overview

Goal: introduce a higher-abstraction authoring layer over `VibeWorkflow` so curated workflows are composed from named, editable fragments and exposed as ordinary Python verbs that return typed artifacts. Two sequenced layers stack on the same IR: **(1) Composition** (`blocks/`, `patches/`, refactored `ready_templates/`, `recipes/`), and **(2) Verb-native** (`ops/{image,video,audio,edit}` returning `Image | Video | Audio | Latent | Mask` artifacts, with a router and lazy `preview_workflow()`/`compile()` escape hatches).

Repository shape today (April 2026):
- `vibecomfy/workflow.py:71` defines `VibeWorkflow` with `set_prompt`, `set_seed`, `set_steps`, `set_input`, `add_node`, `connect`, `compile("api")`, `compile("graphbuilder")`, and `validate()`. It does **not** currently register `inputs`/`outputs`/`requirements` at `add_node` time — that registration lives in `vibecomfy/ingest/normalize.py:107-118` and `:139-161` and runs only when constructing through `convert_to_vibe_format`.

### Step 1: Define block + patch contracts and add `VibeWorkflow.finalize_metadata()` (`vibecomfy/blocks/__init__.py`, `vibecomfy/patches/__init__.py`, `vibecomfy/workflow.py`, `docs/authoring.md`)
**Scope:** Medium

1. **Block contract** (`vibecomfy/blocks/__init__.py`). A *block* is a function `block(workflow: VibeWorkflow, **kwargs) -> Handles`, where `Handles` is a frozen dataclass exposing the named outputs the block produced (e.g., `LoaderTriple.handles.{model, clip, vae}`, `KSampler.handles.samples`). 3. **Add `VibeWorkflow.finalize_metadata()`** on the IR itself in `vibecomfy/workflow.py`. This addresses FLAG-001 / correctness-1: block-built workflows must register the same `inputs`/`outputs`/`requirements` data that `convert_to_vibe_format` produces today. Implementation:

   ```python
   def opaque(workflow, *, class_type, widgets=None, inputs=None, outputs=("out",)) -> Handles:
       node = workflow.add_node(class_type)
       node.widgets.update(widgets or {})
       for input_name, ref in (inputs or {}).items():
           workflow.connect(ref, f"{node.id}.{input_name}")
       return _Handles({name: f"{node.id}.{idx}" for idx, name in enumerate(outputs)})
   ```
