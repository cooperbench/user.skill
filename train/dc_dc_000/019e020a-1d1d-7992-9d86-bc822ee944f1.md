Yeah, but can you just try a bunch of broad, narrow different types of queries then come up with a recommendation based on that?  
• For Hivemind specifically, the slow queries are likely because we’re doing
  ilike.*term* over content.

  A normal Postgres btree index will not help much with leading-wildcard searches
  like:

  content ILIKE '%VACE%'

  That usually needs one of these:

  CREATE EXTENSION IF NOT EXISTS pg_trgm;

  CREATE INDEX CONCURRENTLY message_feed_content_trgm_idx
  ON message_feed USING gin (content gin_trgm_ops);

  Also useful:

  CREATE INDEX CONCURRENTLY message_feed_channel_created_idx
  ON message_feed (channel_name, created_at DESC);

  CREATE INDEX CONCURRENTLY message_feed_author_created_idx
  ON message_feed (author_name, created_at DESC);

  If we want proper full-text search instead of substring search, we should add a
  generated/search column and GIN index:

  CREATE INDEX CONCURRENTLY message_feed_content_fts_idx
  ON message_feed USING gin (to_tsvector('english', content));

  Then query with fts/plfts only after confirming PostgREST uses that expression/
  index cleanly.

  So: not fundamentally bad to expose this via PostgREST, but broad all-channel
  substring search without trigram/full-text indexes will be slow. The UX fix is: add
  trigram + channel/date indexes, keep queries channel-scoped by default, and avoid
  huge or=(content.ilike...) searches unless the DB has the trigram index.

> AGENT

Not enough context to say “true,” but the quoted claim is too confident.

A better version would be:

> “It may run into Reddit policy and privacy-law issues, especially if it scrapes, republishes, stores, profiles, or bulk-searches user content without a compliant basis. Reddit might remove/block it for ToS/API/privacy reasons. GDPR/DSA is possible context, but not an automatic reason by itself.”

Why:

- **GDPR:** Public Reddit posts can still be personal data if tied to identifiable users. If the tool stores, indexes, republishes, profiles, or lets people search users, GDPR obligations can apply: lawful basis, privacy notice, deletion/DSAR handling, retention limits, security, etc.
- **DSA:** The DSA mostly imposes obligations on online platforms like Reddit and creates reporting/illegal-content mechanisms. It is less likely to be the direct reason a random app is “removed,” unless the app is involved in illegal-content handling, dark patterns, ad transparency, recommender/platform obligations, etc.
- **Reddit policy is the bigger practical risk:** Reddit’s Developer/Data API terms are restrictive. They allow API use only under their terms, require privacy disclosures, restrict misuse/bulk commercialization, and Reddit can suspend/terminate access. Devvit rules also require compliance with privacy/data-protection requirements.

So: **maybe, depending on what the concept does.** If it’s just a Reddit app feature using approved APIs and not exporting/storing personal data weirdly, the claim is probably overstated. If it scrapes Reddit, builds a searchable database of users/posts, republishes deleted content, trains AI, profiles users, or sends Reddit data off-platform, then yes, it’s at real risk.

- Reddit Developer Terms: https://redditinc.com/policies/developer-terms

- Reddit Devvit Rules: https://developers.reddit.com/docs/devvit_rules
