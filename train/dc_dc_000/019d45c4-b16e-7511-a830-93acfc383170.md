        # Implementation Plan: Audio-Reactive Visual Effects System

## Overview

Add an audio-reactive effects pipeline to the Remotion video editor. The system pre-loads waveform data for audio clips via `@remotion/media-utils`, exposes per-frame amplitude/frequency data through a React context + hook, ships 5 built-in audio-reactive continuous effects, and integrates with the existing dynamic effects compilation pipeline.

**Current state:** Effects system is mature (11 entrance, 6 exit, 5 continuous effects), with a dynamic compilation pipeline (`compile.ts`) that injects globals and an LLM prompt template. Audio tracks render via `AudioTrack.tsx` but are not analyzed. `@remotion/media-utils` is a transitive dep in `remotion/node_modules` only — not declared directly in any package.json.

**Key architectural decisions (revised from v1 critique):**

1. **Clip-based, not track-based audio data.** The v1 plan keyed audio data by track ID, but audio playback is clip-based with per-clip `at`, `from`, `speed`, and `volume`. The provider must index by clip ID and expose clip metadata so `visualizeAudio()` can be called with the correct source offset for each frame.

2. **Global frame context, not clip-local frames.** Effects run inside `Sequence`s where `useCurrentFrame()` returns clip-local frames (starting at 0). Audio sampling needs the global timeline frame. The provider will store clip start offsets and the hook will compute `globalFrame = clipLocalFrame + clipStartFrame` to sample the right audio position. This is passed via context, not by modifying the Remotion `Sequence` tree.

3. **`getAudioData()` (imperative) instead of `useAudioData()` (hook).** The `useAudioData()` hook calls `useDelayRender()`, which blocks the entire render until audio loads. Instead, we call `getAudioData()` directly in a `useEffect` with `useState`, so visuals render immediately with zero-valued audio data while audio loads asynchronously.

4. **Dependency in both `viewer/` and `remotion/`.** `shared/` code is compiled by both apps, so `@remotion/media-utils` must be added to both `viewer/package.json` and `remotion/package.json`.

### Step 3: Create `AudioDataProvider` context (`shared/compositions/AudioDataProvider.tsx`)
**Scope:** Medium — this is the core data pipeline and the most complex new file.

**Data model:** Index by `clipId`, not `trackId`. Each audio clip gets its own `AudioData` entry plus metadata needed for correct frame-to-source mapping.

1. **Define** the context value type:
   ```typescript
   type AudioClipEntry = {
     audioData: AudioData | null;  // from getAudioData(), null while loading
     clipAt: number;               // clip.at in seconds (timeline start)
     clipFrom: number;             // clip.from in seconds (source trim start)
     speed: number;                // clip.speed (playback rate)
     volume: number;               // clip.volume
     trackId: string;              // which audio track this clip belongs to
   };

   type AudioDataContextValue = {
     clipEntries: Map<string, AudioClipEntry>;  // keyed by clip ID
     trackClipIds: Map<string, string[]>;       // trackId -> [clipId, ...]
   };
   ```

2. **Implement** the provider component:
   - Accept `config: ResolvedTimelineConfig` and `fps: number` as props.
   - On mount (and when config changes), iterate all audio track clips. For each clip with a valid `assetEntry.src`, call `getAudioData(src)` via `useEffect` + `useState`. Store results in state keyed by clip ID.
   - Build `trackClipIds` map for track-level targeting.
   - Use a stable child component pattern: render one `<AudioClipLoader clipId={...} src={...} onLoaded={...} />` per audio clip. Each loader calls `getAudioData()` in its own `useEffect` and reports back via callback — no `useDelayRender()`, no render blocking.

3. **Export** `AudioDataContext` and `useAudioDataContext()` convenience hook.

### Step 4: Create global frame context (`shared/compositions/GlobalFrameContext.tsx`)
**Scope:** Small

Effects run inside `Sequence`s where `useCurrentFrame()` returns clip-local frame 0. The audio hook needs global timeline frames. Two approaches:
- **(A)** A context that provides the clip's start frame offset, letting the hook compute `globalFrame = localFrame + offset`.
- **(B)** A context that directly provides the current global frame.

**Choose (A)** — the offset is static per clip, cheaper to provide, and the hook computes global frame from `useCurrentFrame() + offset`.

1. **Create** `GlobalFrameContext` with `clipStartFrame: number` value.
2. **Export** `GlobalFrameProvider` and `useClipStartFrame()` hook.

## Phase 2: Core Hook + Built-in Effects

### Step 6: Create `useAudioReactivity` hook (`shared/effects/useAudioReactivity.ts`)
**Scope:** Medium

1. **Implement** the hook:
   ```typescript
   function useAudioReactivity(options?: {
     audioTrack?: string;       // target track ID (e.g. "A1"), defaults to first audio track
     numberOfSamples?: number;  // default 16
     smoothing?: boolean;       // default true
   }): {
     amplitude: number;         // 0-1, average of all frequency bins
     frequencyBins: number[];   // raw bins from visualizeAudio()
     bass: number;              // 0-1, average of low bins (indices 0-3)
     mid: number;               // 0-1, average of mid bins
     treble: number;            // 0-1, average of high bins
   }
   ```

2. **Internal logic:**
   - Call `useClipStartFrame()` to get the clip's timeline offset.
   - Call `useCurrentFrame()` to get clip-local frame.
   - Compute `globalFrame = clipLocalFrame + clipStartFrame`.
   - Call `useAudioDataContext()` to get audio clip entries.
   - **Clip selection:** if `audioTrack` is specified, find all clips on that track. Otherwise use the first audio track. Among the matching clips, find the one whose timeline range (`at` to `at + duration`) contains the current global time. If multiple clips overlap, use the first one found.
   - **Source offset:** For the active audio clip, compute the source-relative frame: `sourceFrame = (globalFrame - clipStartFrame_audio) * clip.speed + secondsToFrames(clip.from, fps)`.
   - Call `visualizeAudio({ fps, frame: sourceFrame, audioData, numberOfSamples })` with the clip's `AudioData`.
   - **Compute derived values:** `amplitude` = mean of all bins. Split bins into thirds for `bass`/`mid`/`treble` averages.

3. **When no audio data** (loading, no audio clips, no matching track): return `{ amplitude: 0, frequencyBins: [], bass: 0, mid: 0, treble: 0 }`.
