## Overview
Add a fourth robustness level, `tiny`, that sits below `light` on the same pipeline. Hard constraint: tiny must write the same artifact set as every other level — `state.json` (state machine trail), `faults.json` (the flag registry; the brief calls this `flags.json` but the on-disk name is `faults.json` per `megaplan/_core/registries.py:32`), `critique_v{n}.json`, `gate.json`, and `review.json`. When tiny skips a step, the handler must write a stub instead of omitting the file, mirroring the existing light-gate stub at `megaplan/handlers.py:760-768` (the brief cited 736-744 but the stub now lives at 760-768).

Repo shape relevant to this work:
- `megaplan/types.py:269` — `ROBUSTNESS_LEVELS = ("light", "standard", "heavy")` and `_SETTABLE_ENUM` at line 302.
- `megaplan/_core/workflow.py:73` — `_ROBUSTNESS_OVERRIDES` and `_ROBUSTNESS_WORKFLOW_LEVELS` at line 88 drive which steps each level executes.

- `megaplan/cli.py:479` — `--robustness` argparse choices come from `ROBUSTNESS_LEVELS`, so the constant change alone enables the CLI flag.

Design choice (see questions): tiny will exercise the full state machine but with *all* critique and review work stubbed out. The workflow goes INITIALIZED → plan → PLANNED → critique(stub) → CRITIQUED → (auto-skip gate via existing stub path) → GATED → finalize → FINALIZED → execute → EXECUTED → (skip review, stub review.json) → DONE. This keeps tiny on the same pipeline (per the brief) while producing every artifact.
