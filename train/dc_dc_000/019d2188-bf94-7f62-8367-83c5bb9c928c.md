        # Implementation Plan: Robust Multi-File Upload Queue

## Overview

The current upload flow in `useTimelineEditing.ts:361-465` injects skeleton clips directly into the timeline data model via `commitDataNoSave`, then replaces them after upload completes. This causes multiple interleaved problems: skeletons overwrite each other, `editSeqRef` blocks polling so real clips can't appear, and a fragile 500ms delay gates the replacement.

The fix: extract skeleton rendering into a pure React overlay (no data model mutation), backed by an upload tracker Map. Real clips are added only when each individual upload resolves — no batch wait, no sequence counter conflicts.

**Key files:**
- `viewer/src/tools/video-editor/hooks/useTimelineEditing.ts` — drop handler, skeleton creation, handleAssetDrop
- `viewer/src/tools/video-editor/hooks/useTimelineData.ts` — commitDataNoSave, editSeqRef, uploadFiles
- `viewer/src/tools/video-editor/components/TimelineEditor/TimelineEditor.tsx` — timeline render, action rendering
- `viewer/src/tools/video-editor/components/TimelineEditor/ClipAction.tsx` — skeleton visual (animate-pulse, Loader2)
- `viewer/src/tools/video-editor/lib/timeline-data.ts` — serialization filter for `uploading-` prefix
- `shared/config-utils.ts` — `uploading:` guard in resolveTimelineConfig
- `shared/data-providers/local.ts` — uploadAsset returns assetId + entry

**Constraints:**
- Internal asset drag-and-drop from AssetPanel (lines 442-464 of useTimelineEditing) must be untouched

## Step 1: Create the upload tracker hook
**Scope:** Small — new file  
**File:** `viewer/src/tools/video-editor/hooks/useUploadTracker.ts`

1. **Define** the `UploadEntry` type:
   ```typescript
   interface UploadEntry {
     id: string;           // unique upload ID
     file: File;
     trackId: string;
     time: number;         // drop position in seconds
     status: "uploading" | "done" | "error";
     kind: TrackKind;      // "audio" | "visual"
   }
   ```
2. **Implement** `useUploadTracker()` returning:
   - `uploads: Map<string, UploadEntry>` — React state
   - `addUpload(entry: Omit<UploadEntry, "status">): void` — adds with status "uploading"
   - `completeUpload(id: string): void` — removes the entry
   - `failUpload(id: string): void` — sets status to "error", auto-removes after 3s
3. **Use** `useState<Map<string, UploadEntry>>` for the tracker — no refs, no external state. This is purely React state so skeleton overlays re-render reactively.

## Step 2: Create the skeleton overlay component
**Scope:** Small — new file  
**File:** `viewer/src/tools/video-editor/components/TimelineEditor/UploadSkeletonOverlay.tsx`

1. **Implement** a component that takes `uploads: Map<string, UploadEntry>`, `scale`, `scaleWidth`, and `timelineWrapperRef`.
2. **For each upload entry**, render an absolutely-positioned overlay div matching the position of the target track row and time offset — same geometry as a real clip.

5. **Use `pointer-events: none`** so the overlay doesn't interfere with timeline interactions.
6. **Render** this component inside the `timeline-wrapper` div, after the `<Timeline>` component.

## Step 3: Refactor the drop handler to use per-file async uploads
**Scope:** Medium — modifying `useTimelineEditing.ts`  

1. **Remove** the skeleton clip creation block (lines 386-421) — no more `commitDataNoSave` for skeletons.
2. **Remove** the bulk `await uploadFiles(files)` + 500ms delay (lines 423-427).
3. **Remove** the bulk real-clip loop (lines 429-438).
4. **Replace** with: for each file, call `addUpload(...)` then fire an async upload. Each upload is independent:
   ```typescript
   for (const file of files) {
     const uploadId = `upload-${Date.now()}-${Math.random().toString(36).slice(2, 6)}`;
     const kind = inferKindFromExt(file.name);
     const compatibleTrackId = getCompatibleTrackId(...);
     addUpload({ id: uploadId, file, trackId: compatibleTrackId, time, kind });

     // Fire and forget — each upload is independent
     uploadSingleFile(file, uploadId, compatibleTrackId, time);
   }
   ```
5. **Implement** `uploadSingleFile` as a local async function:
   - Calls `provider.uploadAsset(file)` — this already returns `{ assetId, entry }`
   - On success: invalidate queries, call `handleAssetDrop(assetId, trackId, time)`, then `completeUpload(uploadId)`
   - On error: `failUpload(uploadId)`, log error
   - No 500ms delay needed — the `uploadAsset` response already includes the assetId and the registry entry is written by the server before the response
6. **Keep** the internal asset drag path (lines 442-464) completely untouched.

## Overview

The current upload flow in `useTimelineEditing.ts:361-465` injects skeleton clips directly into the timeline data model via `commitDataNoSave`, then replaces them after upload completes.
