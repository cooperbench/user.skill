## Overview

Simplify the workflow from `init → clarify → plan → critique → evaluate → integrate → gate → execute → review` to `init (implicit) → plan → critique → revise → execute → review`, with a new LLM-based **gate** step replacing both `evaluate` and the old mechanical `gate`.

### New State Machine

```
INITIALIZED → plan → PLANNED → critique → CRITIQUED → gate:
  PROCEED → GATED → execute → EXECUTED → review → DONE
  ITERATE → revise → PLANNED → critique (loop)
  ESCALATE → override options (stays CRITIQUED)
```

States: `INITIALIZED`, `PLANNED`, `CRITIQUED`, `GATED`, `EXECUTED`, `DONE`, `ABORTED`

Removed states: `CLARIFIED`, `EVALUATED`. Note: `revise` transitions to `PLANNED` (same as current `integrate`), so no `REVISED` state constant is needed — "revise" is a step name, not a state.

### 5e. Rewrite `handle_gate` (lines 732-794)
This is the most significant change. Gate becomes an LLM-based step:

1. `require_state`: `{STATE_CRITIQUED}` (was `{STATE_EVALUATED}`).
2. Compute gate signals via `build_gate_signals(plan_dir, state)`.
3. Run preflight checks via existing `run_gate_checks()` (keep this function).
4. Bundle signals + preflight results into a context dict, save as `gate_v{N}.json`.
5. Call the LLM worker: `run_step_with_worker("gate", state, plan_dir, args, root=root)`.
6. Parse LLM response: `recommendation` (PROCEED/ITERATE/ESCALATE), `rationale`, `warnings`.
7. Route on recommendation:
   - **PROCEED**: if preflight checks pass → transition to `STATE_GATED`, write `final.md`, `next_step: "execute"`.
   - **PROCEED but preflight fails**: stay `CRITIQUED`, report blocked, suggest revise or force-proceed.
   - **ITERATE**: stay `CRITIQUED`, `next_step: "revise"`.
   - **ESCALATE**: stay `CRITIQUED`, `next_step: override options`.
8. Save gate LLM output in `state["last_gate"]` (replaces `last_evaluation`).
9. Append weighted_score to `meta["weighted_scores"]` (moved from evaluate handler).
10. Record history entry with gate recommendation.

## Overview

Simplify the workflow from `init → clarify → plan → critique → evaluate → integrate → gate → execute → review` to `init (implicit) → plan → critique → revise → execute → review`, with a new LLM-based **gate** step replacing both `evaluate` and the old mechanical `gate`.

### New State Machine

```
INITIALIZED → plan → PLANNED → critique → CRITIQUED → gate:
  PROCEED → GATED → execute → EXECUTED → review → DONE
  ITERATE → revise → PLANNED → critique (loop)
  ESCALATE → override options (stays CRITIQUED)
```

States: `INITIALIZED`, `PLANNED`, `CRITIQUED`, `GATED`, `EXECUTED`, `DONE`, `ABORTED`

Removed states: `CLARIFIED`, `EVALUATED`. Note: `revise` transitions to `PLANNED` (same as current `integrate`), so no `REVISED` state constant is needed — "revise" is a step name, not a state.

### 5e. Rewrite `handle_gate` (lines 732-794)
This is the most significant change. Gate becomes an LLM-based step with a two-artifact contract:

**Artifact 1: `gate_signals_v{N}.json`** — computed before the LLM call. Contains the same fields downstream prompts (execute, review) already consume: `preflight_results`, `criteria_check`, `unresolved_flags`, plus the new evaluation signals (`weighted_score`, `plan_delta`, `recurring_critiques`, `loop_summary`, `warnings`). This is written to disk before calling the LLM and passed into the gate prompt as context.

**Artifact 2: `gate.json`** — the stable downstream contract. After the gate LLM responds, merge the LLM's `recommendation` and `rationale` into a copy of the signals artifact and write it to `gate.json`. This file is what `_execute_prompt` and `_review_prompt` already read. The contract: `gate.json` always has `passed` (bool), `preflight_results`, `criteria_check`, `unresolved_flags`, plus the new `recommendation` and `rationale` fields. Set `passed = (recommendation == "PROCEED" and all preflight checks pass)`.

Handler flow:
1. `require_state`: `{STATE_CRITIQUED}` (was `{STATE_EVALUATED}`).
2. Compute gate signals via `build_gate_signals(plan_dir, state)`.
3. Run preflight checks via existing `run_gate_checks()` (keep this function).
4. Bundle signals + preflight results into `gate_signals_v{N}.json`.
5. Call the LLM worker: `run_step_with_worker("gate", state, plan_dir, args, root=root)`.
6. Parse LLM response: `recommendation` (PROCEED/ITERATE/ESCALATE), `rationale`, `warnings`.
7. Merge into `gate.json` with `passed` field for downstream consumers.
8. Route on recommendation:
   - **PROCEED**: if preflight checks pass → transition to `STATE_GATED`, write `final.md`, `next_step: "execute"`.
   - **PROCEED but preflight fails**: stay `CRITIQUED`, report blocked, suggest revise or force-proceed.
   - **ITERATE**: stay `CRITIQUED`, `next_step: "revise"`.
   - **ESCALATE**: stay `CRITIQUED`, `next_step: override options`.
9. Save gate LLM output in `state["last_gate"]`.
10. Append weighted_score to `meta["weighted_scores"]` (moved from evaluate handler).
11. Record history entry with gate recommendation.

```python
INITIALIZED → ["plan"]                    # was ["clarify"]
PLANNED → ["critique"]                    # same
CRITIQUED:

  if last_gate.recommendation == "ITERATE" → ["revise"]
```

### 5e. Rewrite `handle_gate` (lines 732-794)
This is the most significant change. Gate becomes an LLM-based step with a two-artifact contract:

**Artifact 1: `gate_signals_v{N}.json`** — computed before the LLM call. Contains the same fields downstream prompts (execute, review) already consume: `preflight_results`, `criteria_check`, `unresolved_flags`, plus the new evaluation signals (`weighted_score`, `plan_delta`, `recurring_critiques`, `loop_summary`, `warnings`). This is written to disk before calling the LLM and passed into the gate prompt as context.

**Artifact 2: `gate.json`** — the stable downstream contract. After the gate LLM responds, merge the LLM's `recommendation` and `rationale` into a copy of the signals artifact and write it to `gate.json`. This file is what `_execute_prompt` and `_review_prompt` already read. The contract: `gate.json` always has `passed` (bool), `preflight_results`, `criteria_check`, `unresolved_flags`, `recommendation`, `rationale`, and `override_forced` (bool, default false). Set `passed = (recommendation == "PROCEED" and all preflight checks pass)`.

**Weighted score append rule**: append `weighted_score` to `meta["weighted_scores"]` only on the **first** gate call for a given iteration. Check `len(meta["weighted_scores"]) < iteration` before appending. This prevents duplicate entries when gate is retried (after add-note, blocked PROCEED, or ESCALATE → retry).

Handler flow:
1. `require_state`: `{STATE_CRITIQUED}` (was `{STATE_EVALUATED}`).
2. Compute gate signals via `build_gate_signals(plan_dir, state)`.
3. Run preflight checks via existing `run_gate_checks()` (keep this function).
4. Bundle signals + preflight results into `gate_signals_v{N}.json`.
5. Call the LLM worker: `run_step_with_worker("gate", state, plan_dir, args, root=root)`.
6. Parse LLM response: `recommendation` (PROCEED/ITERATE/ESCALATE), `rationale`, `warnings`.
7. Merge into `gate.json` with `passed` and `override_forced: false` for downstream consumers.
8. Route on recommendation:
   - **PROCEED**: if preflight checks pass → transition to `STATE_GATED`, write `final.md`, `next_step: "execute"`.
   - **PROCEED but preflight fails**: stay `CRITIQUED`, report blocked, suggest revise or force-proceed.
   - **ITERATE**: stay `CRITIQUED`, `next_step: "revise"`.
   - **ESCALATE**: stay `CRITIQUED`, `next_step: override options`.
9. Save gate LLM output in `state["last_gate"]`.
10. Append weighted_score to `meta["weighted_scores"]` only if `len(meta["weighted_scores"]) < iteration`.
11. Record history entry with gate recommendation.

### 5e. Rewrite `handle_gate` (lines 732-794)
Gate becomes an LLM-based step with a two-artifact contract:

**Artifact 1: `gate_signals_v{N}.json`** — computed before the LLM call. Contains: `preflight_results`, `criteria_check`, `unresolved_flags`, plus evaluation signals (`weighted_score`, `plan_delta`, `recurring_critiques`, `loop_summary`, `warnings`).

**Artifact 2: `gate.json`** — the stable downstream contract. After the gate LLM responds, merge the LLM's `recommendation` and `rationale` into a copy of the signals artifact. Contract: `gate.json` always has `passed` (bool), `preflight_results`, `criteria_check`, `unresolved_flags`, `recommendation`, `rationale`, and `override_forced` (bool, default false). Set `passed = (recommendation == "PROCEED" and all preflight checks pass)`.

**Weighted score append rule**: append `weighted_score` to `meta["weighted_scores"]` only on the **first** gate call for a given iteration. Guard: `len(meta["weighted_scores"]) < iteration`. Since `iteration` is only incremented by `handle_plan` (from INITIALIZED) and `handle_revise`, and plan reruns from PLANNED do not increment, `iteration` always equals the number of completed critique cycles. This means the guard correctly prevents duplicates on gate retries.

Handler flow:
1. `require_state`: `{STATE_CRITIQUED}`.
2. Compute gate signals via `build_gate_signals(plan_dir, state)`.
3. Run preflight checks via existing `run_gate_checks()`.
4. Bundle signals + preflight results into `gate_signals_v{N}.json`.
5. Call the LLM worker: `run_step_with_worker("gate", state, plan_dir, args, root=root)`.
6. Parse LLM response: `recommendation`, `rationale`, `warnings`.
7. Merge into `gate.json` with `passed` and `override_forced: false`.
8. Route on recommendation:
   - **PROCEED**: if preflight checks pass → `STATE_GATED`, write `final.md`, `next_step: "execute"`.
   - **PROCEED but preflight fails**: stay `CRITIQUED`, report blocked.
   - **ITERATE**: stay `CRITIQUED`, `next_step: "revise"`.
   - **ESCALATE**: stay `CRITIQUED`, `next_step: override options`.
9. Save gate LLM output in `state["last_gate"]`.
10. Append weighted_score to `meta["weighted_scores"]` only if `len(meta["weighted_scores"]) < iteration`.
11. Record history entry with gate recommendation.
