        # Implementation Plan: External Pack Runtime Contract

## Overview
Implement the `kind: external` runtime contract described in `/tmp/external-runtime-contract-brief.md` without undoing the existing staged work. The new critique still does not point to the wrong root cause: the root problem remains the missing executable contract across schema, install, runner, and external manifests. It does identify one implementation-model issue in the revised install plan: source materialization cannot be represented as unconditional raw `git clone` command tuples because `build_executor_install_plan()` feeds dry-run display, tests, and real install execution. This revision keeps the same target code but changes the install approach: planning computes deterministic paths and display metadata without mutation; real install invokes an idempotent materialization helper before running the venv/pip commands.

## Phase 1: Schema And Contract Foundation

### Step 1: Add typed external runtime metadata (`artagents/core/executor/schema.py`, `artagents/contracts/schema.py`)
**Scope:** Medium
1. **Extend** the shared `Output` dataclass in `artagents/contracts/schema.py:26` with `extension: str | None = None`, since executor outputs are imported from the shared contract.
2. **Parse** `outputs[].extension` in `_parse_output()` at `artagents/core/executor/schema.py:231`.
3. **Add** typed dataclasses in `artagents/core/executor/schema.py` for `ExternalRuntimeMetadata`, `ExternalRuntimeSource`, and `ExternalRuntimeInstall`, then parse `metadata.external_runtime` into `ExecutorDefinition.external_runtime` while preserving the raw `metadata` dict for backwards compatibility.
4. **Define** `external_runtime.mode` as `package` or `api`; default to `package` when omitted. Package-backed external executors require `source` and `install`; API-backed external executors must not require fake source/install metadata.
5. **Validate** package runtime source requirements: `git` requires `url` and `ref`, `path` requires `path`, and `pypi` requires `package`.
6. **Validate** install requirements: strategy is one of `pyproject`, `requirements`, or `pip_args`; `target` is required for `pyproject` and `requirements`; `pip_args` requires a non-empty target string that will be split with `shlex.split()`.
7. **Validate** `import_check` as a dotted Python import path, `binary_check` as non-empty strings, and `extension` as a string starting with `.` with length <= 16.
8. **Keep** legacy `isolation.requirements` and `isolation.binaries` valid as compatibility metadata, but make migrated package-backed external packs rely on `external_runtime` for new behavior.

## Phase 2: Dry-Run-Safe Install Contract

### Step 2: Represent source materialization separately from install commands (`artagents/core/executor/install.py`)
**Scope:** Large
1. **Extend** `ExecutorInstallPlan` at `artagents/core/executor/install.py:35` with a structured optional source plan, for example `source_path`, `source_kind`, `source_display_actions`, and enough typed metadata for real materialization.
2. **Keep** `ExecutorInstallPlan.commands` for commands that can be executed blindly in order: `uv venv ...` and `uv pip install ...` only. Do not put unconditional `git clone` command tuples in `commands`.
3. **Make** `build_executor_install_plan()` compute deterministic cache paths and pip target paths without creating directories, cloning, fetching, or checking out source. This preserves dry-run semantics because plan construction remains non-mutating.
4. **For** `source.kind: git`, compute a deterministic cache path such as `.artagents/external-sources/<safe-pack-or-executor-id>/<source-digest>/repo`, and compute the later pip target path inside that cache.
5. **For** `source.kind: path`, resolve and validate the local path enough to build the pip target path, without copying or mutating anything.
6. **For** `source.kind: pypi`, skip source materialization and construct the pip target directly from `source.package`.
7. **Map** install strategies after target resolution: `pyproject` installs the source directory containing the target `pyproject.toml`; `requirements` runs `uv pip install --python <venv-python> -r <resolved-target>`; `pip_args` appends `shlex.split(target)` after `uv pip install --python <venv-python>`.
8. **Preserve** existing metadata-based fallbacks (`pyproject_file`, `requirements_file`, `isolation.requirements`) only for executors without package-mode `external_runtime`.
9. **Keep** `executor_environment_path()` and `executor_python_path()` unchanged; VibeComfy still shares one venv via `metadata.pack_id`.

### Step 3: Materialize sources idempotently during real install only (`artagents/core/executor/install.py`, `artagents/core/executor/cli.py`)
**Scope:** Large
1. **Add** an internal helper such as `_materialize_external_source(plan.source)` that is called only by `install_executor()` when `dry_run=False` and before pip install commands run.
2. **For** git sources, make the helper repeat-safe: clone if the cache path is missing; if it exists, fetch/prune tags and then checkout/reset to the declared ref. Avoid failing just because the cache already exists.
3. **For** git refs, verify the checkout ends at the requested ref or raises `ExecutorInstallError` with captured git stderr/stdout detail.
4. **For** path sources, verify the resolved path and install target exist during real install; do not mutate.
5. **For** pypi sources, the helper is a no-op.
6. **Keep** `install_executor(dry_run=True)` returning the plan without source mutation and without running package managers.
7. **Update** `_cmd_install()` to print source display actions from the source plan during dry-run and normal install, then print the existing command lines. The displayed actions can describe clone/fetch/checkout intent, but only real install executes the helper.
8. **Ensure** repeated `install_executor(external.moirae, dry_run=False)` is safe: second run updates/checks out the existing cache and reruns pip install without failing on an existing destination.

## Phase 3: External Runner Behavior

### Step 4: Preflight external executors before execution (`artagents/core/executor/runner.py`)
**Scope:** Medium
1. **Add** `_preflight_external_runtime()` called from `_run_external_executor()` after command expansion and before subprocess execution; dry runs should return the expanded command without probing the system.
