# Implementation Plan: Event-Driven Hero Animation Sequencing

## Current State (what's broken)

The hero animation uses a fragile `inviteStage` state (0 → 1 → 2) driven by two hardcoded `setTimeout` calls at 1500ms and 2800ms after invite resolution. This creates several problems:

- **Invite path**: subtitle words animate over ~1.2s, but ADOS letters start at `delayOffset: 0.7` (i.e., 0.7 + 0.3 + index×0.2 = 1.0–1.6s after mount). The last subtitle word finishes at ~1.15s while the first ADOS letter starts at 1.0s — **they overlap**.
- **Stage 2 at 2800ms** is a guess for when ADOS letters finish (last letter: 0.7 + 0.3 + 3×0.2 + 0.8s duration = 2.4s). The bottom subtitle can appear before the "S" lands.
- **Non-invite path**: date words finish at ~0.62s, ADOS letters start at 0.3s — **they also overlap**.
- **SplashCursor** at 1500ms is unrelated to actual animation progress.
- While invite is resolving, the subtitle branch checks `inviteName` (which is null during fetch), so the **default date text renders and animates** before the invite response arrives — violating the user requirement to never show fallback text during resolution.

## Architecture: Phase State Machine

Replace `inviteStage` (number + setTimeout) with an explicit phase enum driven by `onAnimationComplete` callbacks. No new context file needed — this is local state in `ADOSLanding`.

```typescript
type HeroPhase = 'waiting' | 'subtitle' | 'letters' | 'reveal' | 'complete';
```

### Phase transitions:
1. **`waiting`** → **`subtitle`**: When `inviteResolved` becomes true (after a brief ~200ms settling delay so the component renders cleanly). Nothing animates or renders subtitle content during `waiting`.
2. **`subtitle`** → **`letters`**: When the **subtitle slide container** `motion.div` fires `onAnimationComplete` — this is the parent that animates `y` (1.4s) and `opacity` (0.8s). It fires at 1.4s, which is **after** all child word spans have finished their opacity fade-ins (invite: ~1.2s, non-invite: ~1.15s). This guarantees both the slide and all word opacities are settled.
3. **`letters`** → **`reveal`**: When the **last** ADOS letter's animation completes (`onAnimationComplete` on the "S" `GlowingLetter`).
4. **`reveal`** → **`complete`**: When the bottom subtitle finishes animating in (triggers SplashCursor).

**1d. Gate ALL subtitle content on phase — not just animation triggers:**

The subtitle container's `motion.div` (line 198) currently always renders its children, branching on `inviteName`. During `waiting` phase while an invite is being fetched, `inviteName` is null, so the default date text would render and animate. Fix: **render no subtitle content during `waiting` phase.**

```tsx
<motion.div
  animate={{
    y: heroPhase !== 'waiting' ? 0 : (isMobile ? 60 : 200),
    opacity: heroPhase !== 'waiting' ? 1 : 0,
  }}
  initial={{ y: isMobile ? 60 : 200, opacity: 0 }}
  transition={{ y: { duration: 1.4, ease: [0.16, 1, 0.3, 1] }, opacity: { duration: 0.6, delay: 0.2 } }}
  onAnimationComplete={() => {
    if (heroPhase === 'subtitle') setHeroPhase('letters');
  }}
>
  {heroPhase !== 'waiting' && (
    inviteName ? (
      <p>
        {words.map((word, i) => (
          <motion.span
            key={i}
            className="inline-block mr-[0.35em]"
            initial={{ opacity: 0 }}
            animate={{ opacity: 1 }}
            transition={{ duration: i === 0 ? 0.7 : 0.4, delay: i === 0 ? 0.2 : 0.5 + i * 0.05 }}
          >
            {word}
          </motion.span>
        ))}
      </p>
    ) : (
      <p>
        {dateWords.map((word, i) => (
          <motion.span
            key={i}
            className="inline-block mr-[0.35em]"
            initial={{ opacity: 0 }}
            animate={{ opacity: 1 }}
            transition={{ duration: 0.6, delay: 0.2 + i * 0.07 }}
          >
            {word}
          </motion.span>
        ))}
      </p>
    )
  )}
</motion.div>
```

Key details:
- `{heroPhase !== 'waiting' && (...)}` prevents any subtitle text from mounting until the phase advances. By that time `inviteResolved` is true, so `inviteName` is either set (invite found) or null (no invite / failed fetch) — the correct branch is chosen.
- `onAnimationComplete` on this container fires when the slide (1.4s) and opacity (0.8s) both finish, i.e. at 1.4s. All child word spans finish before that (invite: ~1.2s, non-invite: ~1.15s). The guard `if (heroPhase === 'subtitle')` ensures it only advances once and doesn't re-trigger on later re-renders.

**1e. Keep the invisible ADOS placeholder — but use `visibility: hidden`:**

The `motion.h1` participates in the flex column layout. Removing its content during `waiting`/`subtitle` phases would collapse the row and cause a reflow when ADOS letters mount. Instead, **always render the ADOS letters but control their visibility:**

```tsx
<motion.h1
  className="font-pilowlava text-[18vw] md:text-[20vw] ..."
  style={{ opacity: adosOpacity, y: adosY, pointerEvents: adosPointerEvents }}
>
  {['letters', 'reveal', 'complete'].includes(heroPhase) ? (
    ['A', 'D', 'O', 'S'].map((letter, index) => (
      <GlowingLetter
        key={letter}
        letter={letter}
        index={index}
        className="text-[18vw] md:text-[20vw]"
        isHero
        onAnimationComplete={index === 3 ? () => setHeroPhase('reveal') : undefined}
      />
    ))
  ) : (
    <span className="invisible">ADOS</span>
  )}
</motion.h1>
```

The invisible placeholder remains for **layout reservation only** during `waiting` and `subtitle` phases. It uses `visibility: hidden` (via Tailwind's `invisible` class) so it takes up space but is not visible — matching the user's requirement. This is not "fallback text" shown to the user; it's a layout spacer that is never painted.

### Step 3: Timing Audit

**Expected timeline (invite path):**
| Phase | Starts at | Duration | Ends at |
|-------|-----------|----------|---------|
| `waiting` | 0ms | Until invite resolves | Variable |
| `subtitle` | resolve + 200ms | 1.4s (parent slide completes, all words done by ~1.2s) | +1.6s |
| `letters` | subtitle container done | ~1.7s (last letter: delay 0.9s + 0.8s) | +3.3s |
| `reveal` | letters complete | ~1.0s (bottom subtitle duration) | +4.3s |
| `complete` (cursor) | reveal complete | immediate | +4.3s |

**Expected timeline (non-invite path):**
| Phase | Starts at | Duration | Ends at |
|-------|-----------|----------|---------|
| `waiting` | 0ms | 0ms (already resolved) | 0ms |
| `subtitle` | 200ms | 1.4s (parent slide; words done by ~1.15s) | 1.6s |
| `letters` | 1.6s | ~1.7s | ~3.3s |
| `reveal` | ~3.3s | ~1.0s | ~4.3s |
| `complete` | ~4.3s | immediate | ~4.3s |

Total time is ~4.3s vs current ~2.8s. The increase is the cost of proper sequencing — each phase waits for the previous to fully complete rather than overlapping. If this feels too slow after visual testing, each phase's individual durations (word stagger, letter stagger, slide duration) can be tightened without breaking the architecture.
