## Phase 1: Pause/Resume Foundation

### Step 1: Add DB-backed system state (`app/services/system_state.py`, `app/services/hooks.py`, `app/services/scheduled_jobs.py`)
**Scope:** Medium
1. **Create** `app/services/system_state.py` with helpers around the existing `system_state` singleton row:
   - `is_paused(pool) -> bool`
   - `paused_for_user(pool, user_id) -> bool` as a global pause check for compatibility with user-scoped callers.
   - `pause(pool, user_id, reason=None, now=None)` that sets `paused_at`, `paused_by_user_id`, `pause_reason`, and `updated_at`.
   - `resume(pool, now=None)` that clears pause fields and updates `updated_at`.

3. **Replace** `scheduled_jobs.is_globally_paused()` direct SQL with the new `system_state.is_paused(pool)` helper so pause logic has one source.

### Step 2: Add pause-aware outbound bypass (`app/services/messaging.py`)
**Scope:** Small
1. **Add** `ignore_pause: bool = False` to `send_outbound(...)`.
2. **Keep** ordinary outbound withheld while paused.
3. **Allow** pause/resume/system-control confirmations through when `ignore_pause=True`; still run the existing OOB/template/window behavior unless the code path already bypasses it.
4. **Update** tests and monkeypatch fakes that spy on `send_outbound` to accept the new keyword.

### Step 3: Handle `/pause` and `/resume` after inbound persistence (`app/services/inbound.py`, `app/services/scheduled_job_handlers.py`)
**Scope:** Medium
1. **Detect** literal text commands only after `_insert_message(...)` succeeds, so the command message itself is persisted and duplicates remain idempotent.
2. **On `/pause`:** call `system_state.pause`, supersede all pending user-facing jobs for both partners, fetch both users, and send the spec confirmation to both partners with `ignore_pause=True` and `TemplateCall("pause_confirmation", [...])` if the template exists or after adding it to `app/services/templates.py`.
3. **On `/resume`:** clear pause, restore weekly summaries via existing durable per-user schedule fields (`seed_weekly_summaries` / `schedule_next_weekly_summary`), send a resume confirmation if current product copy already supports it, and do not enqueue the stored backlog.
4. **Gate enqueue paths** for text and document directly in `inbound.py` using DB-backed pause checks.
5. **Gate media paths** so voice/image messages still fetch/store/transcribe/analyze as applicable but do not call `coalescer.add(...)` while paused. This likely means adding a pause check in `handle_voice` and `handle_image`, because those functions enqueue after async media processing.
6. **Ensure** `recover_on_startup` also respects pause before replaying old raw messages or crashed turns, so restart does not bypass the pause kill switch.

## Phase 2: Write-Tool Tightening

### Step 4: Make `schedule_checkin` transactional and UTC-aware (`app/services/tools/write_tools.py`, `tool_schemas.py`, `tests/conftest.py`)
**Scope:** Medium
1. **Reject** naive datetimes at schema or tool boundary. Prefer Pydantic validation in `ScheduleCheckinInput`; otherwise reject at the top of `schedule_checkin` with `ToolCallRejected`.
2. **Normalize** aware datetimes to UTC before storing, preserving absolute instants.
3. **Wrap** supersede-plus-insert in one DB transaction using `async with pool.acquire() as conn, conn.transaction(): ...` so concurrent calls cooperate with `idx_scheduled_jobs_one_pending_checkin_per_user`.
4. **Use** a partial-unique-compatible SQL pattern: supersede existing pending check-ins for the user, then insert exactly one pending check-in. If an asyncpg unique-violation race can still happen, retry the supersede/insert once inside the same helper rather than broad fallback behavior.
5. **Update** `FakePool`/`FakeConnection` narrowly to support `fetchrow`, `execute`, and `transaction()` on acquired connections.

### Step 5: Gate escalation from trusted turn metadata (`app/services/turn_context.py`, `app/services/agentic.py`, `app/services/tools/write_tools.py`)
**Scope:** Medium
1. **Extend** `TurnContext` with trusted fields derived before Phase B, such as `trigger_charge`, `trigger_metadata`, and `explicit_partner_alert_requested`.
2. **Populate** those fields in `_run_agentic(...)` from `hot_context.trigger_metadata` and trigger message rows, not from model tool arguments.
3. **Accept** `escalate_to_partner` only if `ctx.trigger_charge == "crisis"` or `ctx.explicit_partner_alert_requested is True`.
4. **Reject** before any `send_outbound(...)` call, log the rejected tool call, and return a typed tool error through the existing `ToolCallRejected` path.
5. **Always** send allowed escalations to `ctx.partner` with `TemplateCall("escalation", [ctx.partner.name, ctx.user.name, args.content])`, ignoring model-supplied IDs except for warning/audit.
6. **Append** a distinguished reasoning line such as `ESCALATION_SENT gate=crisis reason=...` after send succeeds, keeping the existing admin search behavior intact.
