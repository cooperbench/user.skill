# Prebuilt VibeComfy Validation Environment

We are migrating Reigh's app-active AI generation paths from direct Wan2GP execution to VibeComfy-backed pure-Python workflow templates. The user wants absolute feature parity with the Wan2GP path, actual RunPod validation, and tooling that prevents future agents/developers from rediscovering the same problems manually.

Current reality:
- `reigh-worker` branch: `megaplan/vibecomfy-sprint-09-control-rail-travel-matrix`
- `vibecomfy` branch: `megaplan/production-parity-templates`
- `runpod-lifecycle` branch: `megaplan/prebuilt-validation-env`
- Existing prebuilt RunPod validation volume has already proven useful but is not yet a clean, repeatable developer experience.
- Fresh installs repeatedly hit slow or flaky setup problems: network-volume stale file handles, missing system packages such as `ffmpeg`, missing custom-node assets, missing model directories in `extra_model_paths.yaml`, optional attention backends such as SageAttention, and pod lifecycle sprawl.
- A recent local fix in `reigh-worker` moved fresh/update VibeComfy virtualenvs from `/workspace/.../.venv` to `/opt/reigh-vibecomfy-live-test-venv` so package installs happen on local disk instead of the RunPod network volume. That was tested with 152 local tests and pushed.

Goal:
Build and validate a robust, reusable prebuilt environment path for Reigh VibeComfy validation. It should make the rest of the parity work easier and safer, not add a rigid second source of truth.

The target design should:
1. Provide a standard prebuilt environment for 4090-class RunPod validation.
   - Prefer RTX 4090 as the normal target because that is the user's realistic production/developer bar.
   - Keep the design able to run on larger GPUs when explicitly requested.
   - Make the environment portable when advanced kernels are unavailable, while still allowing a SageAttention-capable profile if it can be installed and validated cleanly.
2. Keep the VibeComfy workflow source pure Python.
   - No app-active workflow should rely on executing JSON blobs as the workflow implementation.
   - JSON may exist only as reference/corpus/import material, not the runtime source of truth.
3. Make environment dependencies explicit but not burdensome.
   - Capture system packages, Python version, CUDA/Torch profile, ComfyUI/VibeComfy commits, custom node lockfile state, extra model paths, optional acceleration profile, and model asset expectations in one generated or easily maintained manifest.
   - Avoid forcing developers to update a fragile hand-written manifest every time a workflow changes. Prefer deriving information from templates, contracts, lockfiles, and validation output.
4. Make validation fail early.
   - Before running expensive workflows, check the environment can import VibeComfy, restore/list custom nodes, read required model paths, validate node input schemas against the installed node classes, and resolve model assets.
   - The onboarding/check path should catch missing required connections and missing required node inputs before RunPod execution.
   - If a model asset is missing, the tool should report the exact expected asset and where it looked. If a URL is known, it should be able to reconcile/fetch or print a precise remediation.
5. Make pod lifecycle safe.
   - Never kill unrelated user pods.
   - Tag/label/name pods launched by this tooling clearly.
   - Provide a safe cleanup/status command that only targets pods launched for this validation flow.
6. Integrate with current Reigh live-test tools instead of creating a parallel universe.
   - Existing code lives primarily in `reigh-worker/scripts/live_test`, `runpod-lifecycle`, and `vibecomfy`.
   - Use the existing live-test matrix and reports.
   - Prebuilt should become the easy/default validation path when the volume/profile exists; fresh should remain a fallback and a way to validate bootstrap correctness.
7. Be documented for agents and developers.
   - Update the relevant README/skill/docs so a future agent knows when to use the prebuilt path, how to build/update it, how to validate it, and what evidence counts.
   - Document the "workflow onboarding" checklist: derive/convert/fork Python workflow, validate node schemas, validate assets, run cheap env checks, run smoke, run matrix, record contract evidence.

Expected implementation shape:
- Improve or add CLIs/scripts around prebuilt env build/check/update/reconcile/status/cleanup.
- Add tests for the new behavior.
- Where possible, use existing abstractions in VibeComfy: template registry, model asset extraction, node lock restore, node schema inspection, workflow validation/doctor/converter tools.
- If missing abstractions are found, add the smallest useful abstraction that removes repeated manual friction.
- Keep changes scoped and avoid unrelated refactors.

Validation requirements:
- Local unit tests for any changed Python modules.
- At least one remote RunPod prebuilt environment health check.
- At least one VibeComfy workflow smoke run using the prebuilt environment.
- Evidence should be written to the existing live-test report structure or a similarly discoverable report path.
- Pods launched for validation must be terminated at the end unless intentionally preserved and clearly documented.
