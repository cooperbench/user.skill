### Step 5: Make multi-batch auto-loop call `_handle_execute_one_batch` iteratively
**Scope:** Large

   ```python
   for batch_idx, batch_task_ids in enumerate(global_batches, 1):
       response = _handle_execute_one_batch(
           ..., batch_number=batch_idx, ...

       if response.get("next_step") == "execute" and not auto_loop_should_continue(response):
           return response  # partial — blocked or incomplete

   ```
2. **Preserve** the existing behaviors:
   - Accumulate trace chunks across batches
   - Track total duration/cost across batches
   - Stop the loop early if a batch has incomplete tracking
   - Write aggregate `execution.json` on final batch (already handled by `_handle_execute_one_batch`)

After unification, `_handle_execute_one_batch` already writes individual batch artifacts AND builds the aggregate on the final batch by reading all batch artifacts from disk (lines 2070–2071). So the loop just needs to call it iteratively — no separate aggregation needed.
4. **Handle session/history entries:** Currently the multi-batch loop records one history entry per batch (inside the loop). `_handle_execute_one_batch` already records its own history entry (line 2087). Verify this works correctly when called iteratively.
