# Implementation Plan: Phase 3 — Inline Produces Checks + `repeat` Body Attributes

## Overview

Phase 3 turns the frozen-plan kernel (Phases 1 + 2 already shipped) into a useful runner by adding two orthogonal additions on top of the existing three step kinds (`code`, `attested`, `nested`):

1. **Inline produces with checks.** `produces` becomes a dict `name -> {path, check}` where `check` is a callable verifier from a new `artagents.verify` package (`file_nonempty`, `json_schema`, `json_file`, `audio_duration_min`, `image_dimensions`, `all_of`). The gate runs each check after `step_completed` (code) or `step_attested` (attested); failure records a `produces_check_failed` event and **rewinds the cursor** (does not advance). Sentinel-existence-only checks are rejected at *definition time* for non-trivial attested produces.
2. **`repeat` as body attribute.** Any step (code, attested, nested) can carry `repeat: {until: ...}` or `repeat: {for_each: ...}`. `until` retries the body and writes attempts under `iterations/NNN/` with cumulative `feedback.json`. `for_each` expands a runtime input set and writes per-item state under `items/<item-id>/`, supporting partial approval via `--item <id>`. `on_exhaust` selects between `escalate` (park, require attested override) and `fail` (abort).

Three things are load-bearing across this revision and addressed explicitly below: (a) the existing `step_dir_for(slug, run_id, plan_step_id)` helper validates its single id with `validate_run_id`, which rejects `/` — Phase 3 needs path-tuple inputs and iteration/item suffixes (FLAG-P3-001); (b) `repeat.for_each` over a code body must inject a per-item env var so the same command can disambiguate which item it is processing (FLAG-P3-002); (c) `_step_to_dict` must keep its existing omit-when-empty discipline so legacy plan hashes are unchanged (FLAG-P3-003).

The work stays additive: existing Phase-1/2 plans (legacy `produces: [...]` list, no `repeat`, no `check` field) continue to load and run unchanged, and their `compute_plan_hash` value is byte-identical to today. No DSL (Phase 4). No new lifecycle verbs (Phase 5) — only data-model, gate plumbing, env contract additions, and event kinds.

- `artagents/core/task/plan.py` (Phase 1/2 schema) — `CodeStep`, `AttestedStep`, `NestedStep`, `_validate_*` chain, `step_dir_for` at lines 82-92, `_step_to_dict` at lines 108-128.
- `artagents/core/task/gate.py` — `_Frame` / `CursorPath` / `derive_cursor` event-replay model; emission points `record_dispatch_complete`, `_dispatch_attested`.
