        Idea:
Fix the fundamental cache coordination issue in shot creation. Currently, shot creation is split across mutation layer (useCreateShot creates row, optimistic cache with images:[]) and composition layer (createShotWithGenerationsPath inserts generations into DB, uses invalidation+setTimeout as glue). This causes: shots appearing without thumbnails, shots disappearing from list, 1500ms setTimeout hacks. Root fix: create an atomic create_shot_with_generations Supabase RPC that creates the shot AND inserts all generations in one DB call, returns the complete shot object with images. Client does one call, gets complete data, puts it in cache via new upsertShotInCache helper. No optimistic partials, no invalidation races, no timers. Key constraints discovered: insert_shot_at_position calls ensure_shot_parent_generation (new RPC must too), useListShots joins shot_generations->generations->generation_variants(primary_variant) via mapShotGenerationToRow, cache entries need computed fields (imageCount, positionedImageCount etc), add_generation_to_shot uses SECURITY DEFINER with auth.uid() ownership check, timeline_frame has unique partial index and >=0 constraint with 50-unit spacing.
