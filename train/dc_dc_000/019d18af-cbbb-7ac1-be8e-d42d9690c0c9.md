## Phase 1: Deduplicate Gate Response Fields

**Problem:** In `handle_gate` (cli.py:784-796), the response dict is built with:

```python
"gate_recommendation": gate_summary["recommendation"],   # line 793

**gate_summary,                                          # line 795 — spreads recommendation & rationale again
```
This means `response["recommendation"]` and `response["gate_recommendation"]` are identical. Same for `rationale`/`gate_rationale`.

**Decision (per user):** Keep the original `build_gate_artifact` names (`recommendation`, `rationale`, etc. via `**gate_summary` spread). Drop the `gate_`-prefixed duplicates (`gate_recommendation`, `gate_rationale`). Existing tests already assert on `response["recommendation"]` (test_megaplan.py:163,167), so this is the lower-churn path.

**Steps:**
1. **Grep all consumers** of `gate_recommendation` and `gate_rationale` across the entire codebase (source, tests, instructions.md, skill files) to confirm they are only set in cli.py:793-794 and declared in _core.py:172-173.
2. **Remove `gate_recommendation` and `gate_rationale`** from the `handle_gate` response dict (delete lines 793-794). The `**gate_summary` spread already provides `recommendation` and `rationale`.
3. **Remove `gate_recommendation` and `gate_rationale`** from the `StepResponse` TypedDict in `_core.py` if they appear there.
4. **Update any tests** that assert on the `gate_`-prefixed names to use the unprefixed names. (Likely none based on evidence — tests already use `response["recommendation"]`.)

## Phase 3: Split cli.py into Focused Modules

**Problem:** cli.py is ~1414 lines with 5 distinct concerns.

**New module layout under `megaplan/`:**

| New module | Contents (moved from cli.py) | ~Lines |

| `cli.py` (remains) | `build_parser`, `COMMAND_HANDLERS`, `main`, `cli_entry`, `handle_status`, `handle_audit`, `handle_list`, `render_response`, `error_response` + **compatibility re-exports** | ~250 |

**Compatibility re-exports in slimmed cli.py (critical):**

The slimmed `cli.py` must import and re-export every symbol that tests or external code patches via `megaplan.cli.*`. Specifically:
- `from megaplan.handlers import *` (or explicit list) — covers `run_step_with_worker`, all `handle_*` functions, `normalize_flag_record`, `update_flags_after_critique`, `update_flags_after_revise`, `_append_to_meta`, etc.
- `from megaplan.state_machine import *` — covers `infer_next_steps`, `require_state`
- `from megaplan.overrides import *` — covers `handle_override`
- `from megaplan.setup_commands import *` — covers setup handlers
- `import shutil` at module level — tests monkeypatch `megaplan.cli.shutil.which`
- `from megaplan.workers import run_step_with_worker` — tests patch `megaplan.cli.run_step_with_worker`

This preserves all existing `megaplan.cli.X` patch targets without any test changes.

**Steps:**
1. Create `state_machine.py` — move `infer_next_steps`, `require_state`, `find_command`.
2. Create `handlers.py` — move step handlers and their private helpers. Import from `_core`, `evaluation`, `state_machine`, `workers`.
3. Create `overrides.py` — move override handlers. Import from `handlers` (for shared helpers like `_append_to_meta`) and `state_machine`.
4. Create `setup_commands.py` — move setup/config/instructions functions.
5. Slim `cli.py` — keep parser, dispatch, entry points, status/audit/list handlers. **Add compatibility re-exports for all moved symbols and `shutil`/`run_step_with_worker` so `megaplan.cli.*` patch targets still resolve.**
6. **Update `__init__.py`** — change import sources for moved symbols. Public API stays identical.
7. **Run tests.** No test changes should be needed because cli.py re-exports preserve patch targets.

**Dependency order:** `_core` ← `state_machine` ← `evaluation` ← `handlers` ← `overrides` ← `cli`. No circular deps.

## Phase 4: Normalize Test Style

**Problem:** 5 test files with inconsistent naming and assertion conventions.

**Target convention:**
- **Naming:** `test_<unit>_<behavior>` everywhere (e.g., `test_flag_weight_security_returns_3`).
- **Assertions:** Plain `assert` with clear comparisons. Use `pytest.raises(XError, match=...)` for exceptions.
- **Helpers vs fixtures:** Keep plain helper functions (`_scaffold()`, `_state()`, `_make_args()`) where they're clearer — only use fixtures for actual pytest deps (tmp_path, monkeypatch). Do not convert helpers to fixtures for uniformity's sake.

**Steps — normalize each file one at a time:**
1. `test_evaluation.py` — align test function naming to `test_<unit>_<behavior>`.
2. `test_workers.py` — align naming.
3. `test_schemas.py` — align naming.
4. `test_prompts.py` — align naming and assertion style.
5. `test_megaplan.py` — already closest to target, minor naming tweaks only.
6. **Run full suite after each file.**

**Scope guard:** This phase changes naming and assertion style only. No fixture-to-helper or helper-to-fixture conversions. No new conftest.py unless a concrete shared fixture emerges naturally.
