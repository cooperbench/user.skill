        # Implementation Plan: Mediator Bot Foundation — Scaffold, Schema, Infra

## Overview
This is a from-scratch Python/FastAPI project that will host a private WhatsApp-based reflection assistant for two partners. The working directory currently holds only `mediator-bot-spec.md` (authoritative spec) and `tool_schemas.py` (Pydantic v2 schemas — read-only reference for later plans). This plan delivers the foundation: project scaffolding, the complete Postgres schema (11 tables) on Supabase, RLS policies, env-driven configuration, an `is_under_cap`/`record_llm_cost` helper, a `/health` endpoint, an `/admin` stub, a phone-number whitelist helper, deployment config for Railway, a README, and pytest smoke tests. No webhook, LLM calls, OOB checker, or job execution — those land in later plans.

**Stack choices (committed):** Python 3.11, FastAPI async, `asyncpg` + raw SQL (no ORM), `pydantic-settings` for config, Pydantic v2 (already pinned by `tool_schemas.py`), single forward-only SQL migration applied via `psql`, `uvicorn` web command, Railway deploy with healthcheck.

**Hard constraint (user-confirmed):** No vector store, no embedding column, no `pgvector` extension. Dedup is agentic-search only and lives in Plan 3 — do not add embedding infrastructure speculatively.

## Phase 1: Project Scaffold

### Step 1: Create `pyproject.toml` and project tree (`pyproject.toml`, `app/`, `tests/`, `migrations/`)
**Scope:** Small
1. Write `pyproject.toml` with deps: `fastapi`, `uvicorn[standard]`, `asyncpg`, `pydantic>=2`, `pydantic-settings`, `httpx`; dev deps: `pytest`, `pytest-asyncio`, `anyio`. Python `>=3.11`.
2. Create directories: `app/{__init__.py,main.py,config.py,db.py,models/__init__.py,routers/{__init__.py,health.py,admin.py},services/{__init__.py,spend.py,whitelist.py}}`, `tests/{__init__.py,conftest.py}`, `migrations/`.
3. Move `tool_schemas.py` → `app/tool_schemas.py` unchanged so the package can import its `TOOL_REGISTRY` later.
4. Create `.env.example`, `.gitignore`, `Procfile`, `railway.json`.

### Step 2: Procfile + Railway config (`Procfile`, `railway.json`)
**Scope:** Small
1. `Procfile`: `web: uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
2. `railway.json`: NIXPACKS builder, `startCommand` matching the Procfile, `healthcheckPath: "/health"`, restart on failure.

## Phase 2: Configuration & DB Wiring

### Step 3: Settings loader (`app/config.py`, `.env.example`)
**Scope:** Small
1. Implement `Settings(BaseSettings)` with all spec env vars: `env_name`, `database_url`, `supabase_url`, `supabase_service_role_key` (SecretStr), `anthropic_api_key`, `openai_api_key`, `groq_api_key`, `whatsapp_token`, `whatsapp_phone_number_id`, `whatsapp_verify_token`, `whatsapp_app_secret`, `admin_password` (SecretStr), `partner_phone_a`, `partner_phone_b`, `text_llm_daily_cap_usd=10.0`, `vision_daily_cap_usd=2.0`, `transcription_daily_cap_usd=1.0`, optional `sentry_dsn`, `log_destination`. Use `SettingsConfigDict(env_file=".env", extra="ignore")`.
2. Expose `get_settings()` (lru_cache).
3. Mirror every field in `.env.example` with a one-line comment.

### Step 4: DB connection + lifespan (`app/db.py`, `app/main.py`)
**Scope:** Small
1. `app/db.py` exposes async `db_lifespan(app)` that creates an `asyncpg.create_pool(settings.database_url)` and stores it on `app.state.pool`; `get_pool(request)` dependency; `ping(pool)` helper running `SELECT 1`.
2. `app/main.py`: `app = FastAPI(lifespan=db_lifespan)`; include health + admin routers; on startup spawn the heartbeat task (Step 11).

## Phase 3: Database Schema

### Step 5: Forward-only migration SQL (`migrations/0001_init.sql`, `migrations/teardown.sql`)
**Scope:** Large
1. Wrap in `BEGIN;`/`COMMIT;`. Enable only `pgcrypto`. **Do not** create the `vector` extension.
2. Create all 11 spec tables verbatim (`users`, `messages`, `memories`, `themes`, `watch_items`, `observations`, `out_of_bounds`, `scheduled_jobs`, `bot_turns`, `tool_calls`, `feedback`) with `timestamptz` everywhere, `gen_random_uuid()` defaults, FKs to `users(id)`, self-FKs (`messages.in_reply_to`, `memories.supersedes_memory_id`), array columns (`uuid[]`), and CHECK constraints on every enum-like column listed in the spec (direction, processing_state, charge, media_type when not null, status fields, severity, confidence, sentiment, health, target_type, sentiment for feedback, source, job_type). `observations.significance int CHECK (significance BETWEEN 1 AND 5)` nullable for the failed-scoring path. Include `bot_turns.system_prompt_version`, `tool_call_count`, `duration_ms`, `failure_reason`. Use `IF NOT EXISTS` for table+index creation.
3. Create every index from spec §"Index Strategy", including the 6 partial indexes and GIN indexes on `observations.related_theme_ids`, `observations.supporting_message_ids`, `memories.related_theme_ids`, `watch_items.related_theme_ids`.
4. Enable RLS on every table; add a deny-anon `FOR ALL` policy on each. Service role bypasses RLS — note this in a SQL comment. Wrap policy creates in `DO $$ … EXCEPTION WHEN duplicate_object THEN NULL; END $$;` so re-runs don't error.
5. Add `llm_spend_log(provider text, day date, total_usd numeric(10,4) not null default 0, updated_at timestamptz not null default now(), primary key (provider, day))` for spend tracking. Enable RLS + deny-anon. Comment notes this is operational, not part of the spec data model.
6. Write `migrations/teardown.sql` with `DROP TABLE IF EXISTS … CASCADE` in reverse-FK order for local dev only.

### Step 10: Heartbeat + ops doc (`app/main.py`, `docs/ops.md`)
