        # Implementation Plan: External Pack Runtime Contract

## Overview
Implement the `kind: external` runtime contract described in `/tmp/external-runtime-contract-brief.md` without undoing the existing staged work. The current shape is close but incomplete: `runner.py` already knows about `executor_python_path()` only when `{python_exec}` is used, `install.py` already creates deterministic per-executor venvs, executor schema stores arbitrary `metadata`, and external manifests/wrappers still encode runtime assumptions in inconsistent ways. The simplest durable fix is to type the new manifest contract, use it in the external runner path, keep built-in executors untouched, and migrate only the three existing external packs.

## Phase 1: Schema And Contract Foundation

### Step 1: Add typed external runtime metadata (`artagents/core/executor/schema.py`, `artagents/contracts/schema.py`)
**Scope:** Medium
1. **Extend** the shared `Output` dataclass in `artagents/contracts/schema.py:26` with `extension: str | None = None`, since executor outputs are imported from the shared contract.
2. **Parse** `outputs[].extension` in `_parse_output()` at `artagents/core/executor/schema.py:231`.
3. **Add** typed dataclasses in `artagents/core/executor/schema.py` for `ExternalRuntimeMetadata`, `ExternalRuntimeSource`, and `ExternalRuntimeInstall`, then parse `metadata.external_runtime` into `ExecutorDefinition.external_runtime` while preserving the raw `metadata` dict for backwards compatibility.
4. **Validate** external runtime only for `kind: external`: require `metadata.external_runtime` unless the executor is explicitly exempted as API-only; validate source strategy requirements, install strategy/target, `import_check`, `binary_check`, and `outputs[].extension`.
5. **Keep** legacy `isolation.requirements` and `isolation.binaries` valid during migration so existing install/check paths do not break before the new fields are wired.

### Step 2: Update install planning to understand `external_runtime.install` (`artagents/core/executor/install.py`)
**Scope:** Medium
1. **Refactor** `_dependency_install_command()` at `artagents/core/executor/install.py:155` to prefer `executor.external_runtime.install` when present.
2. **Map** `pyproject`, `requirements`, and `pip_args` to the existing `uv pip install --python <venv-python> ...` command shapes.
3. **Preserve** current metadata-based fallbacks (`pyproject_file`, `requirements_file`, `isolation.requirements`) for manifests that have not adopted the new contract.
4. **Keep** `executor_environment_path()` and `executor_python_path()` unchanged; tests already assert VibeComfy shares one venv via `metadata.pack_id`.

## Phase 2: External Runner Behavior

### Step 3: Preflight external executors before command expansion (`artagents/core/executor/runner.py`)
**Scope:** Medium
1. **Add** `_preflight_external_runtime()` called from `_run_external_executor()` before `dry_run` execution is skipped or before subprocess execution, with dry-run returning the expanded command but not probing the system.
2. **Resolve** the pinned interpreter with `executor_python_path(executor)` for every `kind: external` executor declaring an `import_check`, not only when `{python_exec}` appears.
3. **Run** `<venv-python> -c "import <module>"` for `import_check`; on failure raise `ExecutorRunnerError` with the executor id, module name, and `python3 -m artagents executors install <id>`.
4. **Check** `binary_check` entries with `shutil.which`; on failure raise `ExecutorRunnerError` naming the missing binary and pointing at `executor.metadata.stage_file` or the install command.
5. **Do not** auto-install during run.

### Step 4: Apply output extensions during placeholder expansion (`artagents/core/executor/runner.py`)
**Scope:** Small
1. **Update** `_output_value()` at `artagents/core/executor/runner.py:441` so the default output path becomes `<out>/<name>{extension}` when `extension` is set.
2. **Preserve** existing behavior for explicit `request.outputs`, placeholder overrides, and `path_template`.
3. **Ensure** `{output}` for Moirae resolves to `video.mp4`, while executors without `extension` still receive `<out>/<name>`.

### Step 5: Capture wrapper output and surface failures (`artagents/core/executor/runner.py`, `artagents/core/executor/cli.py`)
**Scope:** Medium
1. **Change** the external subprocess call at `artagents/core/executor/runner.py:308` to `capture_output=True, text=True`.
2. **Store** stdout/stderr tails in `ExecutorRunResult.payload` when non-empty or on failure.
3. **On non-zero return**, print or raise with the last 2 KB of stdout and stderr so CLI users see useful diagnostics instead of only `returncode`.
4. **Keep** command echo and JSON payload behavior in `_cmd_run()` compatible with existing tests.
