## Why

`scripts/runpod_corpus_matrix.py:91` already pip-installs `'comfyui_manager>=4.1,<5'` into the comfy runtime, so `cm-cli` is on PATH inside the embedded venv. ComfyUI-Manager already has install/uninstall/update/save-snapshot/restore-snapshot verbs. We're hand-rolling all of it, with a tiny ~9-entry `KNOWN_NODE_PACKS` registry vs Manager's catalog of thousands. This is a clear "shell out to the existing tool" refactor.

## Files in scope

- `vibecomfy/node_packs_install.py` (176 lines — gut and replace; aim for <80 lines after)
- `vibecomfy/commands/nodes.py` (CLI, surface mostly unchanged; add `nodes restore`)

## Deliverables

1. **`install_pack()` shells out to `cm-cli install <name>` when cm-cli is on PATH.** Resolves cm-cli via the embedded comfy runtime's python first, system PATH second. Translates cm-cli's output into the existing `InstallResult` dataclass so callers don't change.
2. **Falls back to current clone+pip path when cm-cli is unavailable** (e.g. local dev with no comfy runtime). Same `InstallResult` contract.
3. **New `vibecomfy nodes restore [--lockfile <path>]` verb** that actually honors lockfile pins — checks out the recorded SHA per entry. Either via `cm-cli restore-snapshot` after translating our text lockfile into Manager's snapshot JSON, OR via explicit `git clone && git checkout <sha>` fallback. This closes the "lockfile is descriptive not prescriptive" gap.
4. **Fix `_known_schema_classes` silent-fail.** Currently returns `set()` when `node_index.json` is missing (`node_packs_install.py:153-162`), which makes every workflow look like every class is missing → `ensure` would try to install the world. Change to raise a clear error.
5. **Reconcile install-root.** `install_pack` hardcodes `Path("custom_nodes")` (`:44`); `commands/nodes.py:_installed_nodepack_dir` (`:165-174`) searches three locations including `vendor/ComfyUI/custom_nodes/`. Pick one source of truth, document it.
6. **Optional: fetch Manager's `extension-node-map.json` at install time** when a `class_type` isn't in `KNOWN_NODE_PACKS`. Use it as a *fallback resolver*, not a bundled catalog — query the live data, don't vendor it. If this adds meaningful complexity, drop it and report.
