## Overview

The executor is told "if a test fails and you determine the failure is pre-existing" (execute.py:83, :383) but has no mechanism to actually determine this — it must guess. The fix captures a test baseline in the harness during the finalize phase (before execution begins), records failing test IDs in finalize.json as `baseline_test_failures`, and updates the execute/review prompts to reference concrete baseline data instead of vague heuristics.

The finalize.json payload is already mutated post-LLM by `_write_finalize_artifacts` (handlers.py:348-354), which calls `_ensure_verification_task` and `_reconcile_validation_after_mutation`. Adding baseline capture here follows the established pattern — harness-side enrichment of the LLM's output before writing artifacts.

Key constraint: baseline capture must be best-effort. Projects may have no tests, a broken test runner, or an unusual test command. Failure to capture baseline should not block finalize.

## Phase 2: Baseline Capture Logic

### Step 3: Implement `_capture_test_baseline` in `megaplan/handlers.py`
**Scope:** Medium
1. **Add** a new function `_capture_test_baseline(project_dir: Path, state: PlanState) -> dict` that:
   - Reads `execution.test_command` from state config (via the DEFAULTS mechanism).
   - If empty, auto-detects: check if `pytest` is on PATH (`shutil.which("pytest")`), else fall back to `python -m unittest discover`.
   - Runs the detected command with compact output flags. For pytest: `pytest --tb=no -q --no-header`. For unittest: `python -m unittest discover -v` (then parse).
   - Uses `subprocess.run` with `cwd=project_dir`, `timeout=120`, `capture_output=True`, `text=True`.
   - Parses the output to extract failing test IDs. For pytest with `-q --tb=no`: lines matching `FAILED` contain test IDs. For unittest: lines containing `FAIL:` or `ERROR:`.
   - Returns `{"baseline_test_failures": [...ids...], "baseline_test_command": cmd_string}` on success.
   - Returns `{"baseline_test_failures": None, "baseline_test_command": cmd_string, "baseline_test_note": "...reason..."}` on any failure (timeout, no runner found, parse error, subprocess error).
   - The entire function is wrapped in a try/except that catches `Exception` and returns the null/note fallback — this must never crash finalize.

2. **Keep it focused on pytest** — pytest is the dominant runner in the ecosystem and the only one referenced in megaplan prompts (execute.py:28,82). Auto-detecting unittest as a fallback is fine, but don't over-engineer multi-runner parsing.
