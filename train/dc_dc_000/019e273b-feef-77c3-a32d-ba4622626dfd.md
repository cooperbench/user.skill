- Cause: the accepted structured topic payload had the same media ref repeated in 3 blocks:
  `{"message_id": "1504495461351035119", "kind": "embed", "index": 0}`.
  That message’s embed URL is `https://www.youtube.com/watch?v=fZgtkRcu4_k`, so the renderer emitted it three times.

- Not caused by repeated topic sources: the stored source ids are 5 distinct messages. Only `1504495461351035119` had an embed; the others had no attachments/embeds.

- Not caused by `render_topic_publish_units` inventing duplicates independently. It emits one media unit for every block media ref, with no global dedupe: [src/features/summarising/topic_editor.py:3771](/Users/user_c042661f/Documents/banodoco-workspace/brain-of-bndc/src/features/summarising/topic_editor.py:3771).

- Not caused by `flat_messages` intentionally publishing all media after text. The code flattens units in render order and sends `flat_messages` sequentially: [src/features/summarising/topic_editor.py:2816](/Users/user_c042661f/Documents/banodoco-workspace/brain-of-bndc/src/features/summarising/topic_editor.py:2816), [src/features/summarising/topic_editor.py:2865](/Users/user_c042661f/Documents/banodoco-workspace/brain-of-bndc/src/features/summarising/topic_editor.py:2865). If they appeared visually after the text, that is likely Discord embed/render timing, not batching in this code.

- Default media attachment may be a contributing path in general. `_attach_default_media_refs_to_blocks` adds a first available media ref to any block without one: [src/features/summarising/topic_editor.py:1933](/Users/user_c042661f/Documents/banodoco-workspace/brain-of-bndc/src/features/summarising/topic_editor.py:1933). But for this stored topic, the final accepted payload already contains the duplicate ref on intro, community, and watch blocks. The “Watch” block’s media ref could not have come from the default fallback because its block source list only cites `1504493399527653456`, which has no embed.

Likely fix direction: add global de-duping of media refs or resolved URLs during structured publish rendering, keeping only the first occurrence per topic. A stricter follow-up would make default media attachment track already-used refs and optionally reject/block media refs whose `message_id` is not in that block’s `source_message_ids`.
