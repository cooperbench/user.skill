        # Implementation Plan: Sprint 2 Adapter Seam and Local Selector Skeleton

## Overview
`reigh-worker/` already has a single WGP boundary for direct generation tasks: `TaskRegistry._handle_direct_queue_task()` builds a `GenerationTask` through `source/task_handlers/tasks/task_conversion.py`, submits it to `HeadlessTaskQueue`, and the worker later enters `HeadlessTaskQueue._convert_to_wgp_task()` via `source/task_handlers/queue/task_processor.py`. There is also an older generic `source/models/comfy/comfy_handler.py`, but it expects a raw workflow payload and is not the worker-side VibeComfy route selector this sprint needs.

The simplest shape is to add a backend-neutral resolved-task layer before WGP conversion, then let a local selector choose either the existing WGP executor or a new VibeComfy adapter. Supabase queue task types and params stay unchanged; unsupported Comfy routes fail closed by selector state instead of falling through to WGP silently when `REIGH_BACKEND` asks for Comfy.

## Phase 1: Routing Foundation

### Step 1: Add `template_routing.py` (`source/task_handlers/tasks/template_routing.py`)
**Scope:** Medium
1. Define route support states, for example `WGP_ONLY`, `COMFY_SUPPORTED`, and `COMFY_UNSUPPORTED`.
2. Add a backend-neutral `ResolvedTask` dataclass with the fields the executors need: `task_id`, `task_type`, `route_key`, `backend`, `support_state`, `template_id`, `model`, `prompt`, `params`, `memory_profile`, and optional `failure_reason`.
3. Implement local route derivation from existing task payloads. Start from the same semantics as `scripts/dual_run_compare/route_keys.py`, but keep production code in `source/task_handlers/tasks/template_routing.py` rather than importing test/comparison script code.
4. Add a static local selector map:
   - `z_image_turbo` -> Comfy template `image/z_image`.
   - `qwen_image_2512` -> Comfy template `image/qwen_image_2512`.
   - one LTX child route, preferably `individual_travel_segment` or `travel_segment` when model family resolves to `ltx2`, mapped to an LTX ready template such as `video/ltx2_3_t2v` only for the smoke-friendly shape.
   - `wan_2_2_t2i` remains WGP-only unless the single-frame patch is part of this implementation.
5. Parse `REIGH_BACKEND` locally with conservative values: unset/`wgp` keeps current behavior; `comfy` selects Comfy only for `COMFY_SUPPORTED`; unsupported routes return a closed failure; optional `auto` can behave like WGP for this sprint unless explicitly requested otherwise.

### Step 2: Add route derivation tests (`tests/test_template_routing.py`)
**Scope:** Small

4. Prove `wan_2_2_t2i` is WGP-only unless implemented in the same patch.

## Phase 2: Executor Seam

### Step 3: Split direct queue preparation from WGP execution (`source/task_handlers/tasks/task_registry.py`)
**Scope:** Medium
1. Keep `TaskRegistry.dispatch()` external behavior unchanged.
2. In `_handle_direct_queue_task()`, build a `ResolvedTask` before building or submitting a WGP `GenerationTask`.
3. If the resolved backend is WGP, call the existing `db_task_to_generation_task()` and queue submission path unchanged, including the existing `wan_2_2_t2i` single-frame override.
4. If the resolved backend is Comfy, bypass `HeadlessTaskQueue.submit_task()` and do not enter `_convert_to_wgp_task()`.
5. If the resolved backend is Comfy but support state is not supported, return `(False, <explicit unsupported route message>)` without running WGP.

### Step 4: Add the VibeComfy adapter (`source/models/comfy/vibecomfy_adapter.py`)
**Scope:** Medium
1. Implement a small adapter function, for example `handle_vibecomfy_resolved_task(resolved, main_output_dir_base) -> tuple[bool, str | None]`.
2. Build runtime input from the resolved task: template ID, prompt, seed, steps, resolution, output directory, and `build_memory_profile_cli_args()` from `source/runtime/vibecomfy_profile.py`.
3. Prefer a subprocess CLI boundary for Sprint 2 unless the repo already has a stable vendored Python API available on worker images. This keeps the worker from importing VibeComfy at module import time and preserves the existing profile boundary.
4. Capture adapter errors into normal task failure strings. Do not add retry/fallback to WGP for Comfy-selected unsupported or failed routes in this sprint.
5. Keep the existing raw-workflow `handle_comfy_task()` intact for `task_type == "comfy"`; the new adapter is for selected production routes.

### Step 5: Add executor/adapter tests (`tests/test_vibecomfy_adapter_routing.py` or extend `tests/test_additional_coverage_modules.py`)
**Scope:** Small
1. Monkeypatch the adapter subprocess call and assert `REIGH_BACKEND=comfy` routes `z_image_turbo` and `qwen_image_2512` to the adapter.
2. Assert the WGP queue path is not called for those Comfy-supported routes.
3. Assert `REIGH_BACKEND=wgp` or unset preserves the existing direct queue behavior.
4. Assert a Comfy-unsupported route returns a closed failure and does not submit to WGP.

## Phase 3: Telemetry and Smokes

### Step 6: Add minimal telemetry (`source/task_handlers/tasks/task_registry.py`, `source/task_handlers/tasks/template_routing.py`, `source/models/comfy/vibecomfy_adapter.py`)
**Scope:** Small

2. On adapter failure, include backend/template/profile/error in the returned failure message and logs.

        # Implementation Plan: Sprint 2 Adapter Seam and Local Selector Skeleton

## Overview
The critique does not show that the plan targeted the wrong root cause; it shows the seam was too narrow. The root cause is still the same: backend selection must happen before any WGP-specific `GenerationTask` reaches `HeadlessTaskQueue.submit_task()`, because `submit_task()` pre-validates through `_convert_to_wgp_task()`. The revised approach keeps the backend-neutral resolved-task layer, but moves the execution seam into every queue-backed generation path that can submit WGP work: direct queue dispatch in `source/task_handlers/tasks/task_registry.py` and travel child queue submission in `source/task_handlers/travel/segments/segment_queue.py`.

`reigh-worker/` remains the implementation and validation root. External Supabase task contracts stay unchanged. `REIGH_BACKEND=vibecomfy` is the canonical feature flag value; unset or `wgp` preserves current WGP behavior. Explicit VibeComfy selection is strict fail-closed for unsupported routes. The VibeComfy adapter must run across a Python 3.11 subprocess boundary because `reigh-worker` is Python 3.10-constrained while `vibecomfy` requires Python 3.11.

**Scope:** Medium
