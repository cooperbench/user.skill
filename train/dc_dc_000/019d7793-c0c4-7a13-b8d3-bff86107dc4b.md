        # Implementation Plan: Phase-start stderr notices

## Overview

When a megaplan phase begins (prep, plan, critique, revise, gate, finalize, execute, review), print a human-friendly notice to **stderr** with the phase name, expected duration range, and a brief status guidance hint. Stdout remains untouched — it only ever emits the final JSON `StepResponse`.

The infrastructure already exists:
- `PHASE_RUNTIME_POLICY` in `megaplan/_core/phase_runtime.py` has expected durations per phase.
- `format_duration_hint()` already produces human-readable duration strings.
- All existing diagnostic output already goes to `sys.stderr`.

The simplest approach: in `cli.py:main()`, right before calling the handler, emit a stderr notice for commands that are in `PHASE_RUNTIME_POLICY`. This is a single insertion point — no handler changes needed.

## Main Phase

### Step 1: Add a `_emit_phase_notice()` helper and call it in `main()` (`megaplan/cli.py`)
**Scope:** Small

1. **Add** a helper function `_emit_phase_notice(step: str)` near the top of `cli.py` (after `render_response`, around line 73). It should:
   - Check if `step` is in `PHASE_RUNTIME_POLICY` — if not, return silently (handles non-phase commands like `status`, `list`, `watch`, `audit`).
   - Use `format_duration_hint(step, configured_timeout_seconds=DEFAULT_NON_EXECUTE_TIMEOUT_CAP_SECONDS)` for the duration string.
   - Print to stderr: `[megaplan] Starting {step}... {duration_hint}` (single line, bracketed prefix matching existing `[parallel-review]`/`[hermes-worker]` conventions).
   - Import `PHASE_RUNTIME_POLICY`, `format_duration_hint`, and `DEFAULT_NON_EXECUTE_TIMEOUT_CAP_SECONDS` from `megaplan._core.phase_runtime` (most are already re-exported via `megaplan._core`).

2. **Call** `_emit_phase_notice(args.command)` in `main()` at `cli.py:893`, just before `return render_response(handler(root, args))`. This is the single insertion point — no changes needed in individual handlers.

3. **For `execute` phase** (which has no max), the message should say something like `"Starting execute... Expected minimum duration: 5m (depends on task count)."` — this is already what `format_duration_hint` returns for unbounded phases, so no special-casing needed.

### Step 2: Add a test for the stderr notice (`tests/test_megaplan.py` or new `tests/test_cli_notices.py`)
**Scope:** Small

1. **Write** a focused test that calls `_emit_phase_notice("plan")` and captures stderr (using `capsys` or `io.StringIO` redirect), asserting:
   - Output goes to stderr, not stdout.
   - Contains the phase name.
   - Contains a duration hint.
2. **Write** a negative test: `_emit_phase_notice("status")` produces no output (not a phase command).
3. **Run** the existing test suite to verify no regressions: `python -m pytest tests/`.
