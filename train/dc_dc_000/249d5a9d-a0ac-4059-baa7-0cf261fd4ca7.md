**File:** `reigh-app/src/domains/media-lightbox/hooks/useLightboxNavigation.ts:89-90`

```ts
const topOverlayType = getTopmostKnownOverlayType();
if (topOverlayType && topOverlayType !== 'lightbox') return;
```

This guard bails on **any** non-lightbox overlay being topmost — including **non-modal** ones like `tooltip`, `preview-card`, `popover`. Every UI primitive in `src/shared/components/ui/overlay/*` registers via `useOverlayBridge` and gets pushed onto the stack (I checked — tooltip, hover-card, popover, select, dropdown-menu, alert-dialog, dialog, lightbox all push entries). `getTopOverlay()` returns the **last-pushed** entry regardless of modality (`overlayStack.ts:84-86`).

**The sequence that breaks it:**
1. Keyboard arrow navigates — fine.
2. At some point focus lands on a button with a Tooltip (lots of them in the lightbox toolbar/NavigationArrows), or the user hovers one → tooltip pushes `{type: 'tooltip'}` onto the stack.
3. Tooltip is now topmost. Guard fires, bails on all keydowns — including Escape (Escape check is below the overlay-type guard, so it's blocked too).
4. Until that tooltip is dismissed cleanly (mouseout away, refocus), the keys stay dead.

**How to confirm:** open devtools while reproducing — the stack logs `[OverlayStack] PUSH { type: 'tooltip', ... }` on every push/pop. When arrows/Esc die, a non-lightbox entry will be at the top.

**Fix direction:** make the guard bail only on *modal* overlays above the lightbox, e.g. swap to `hasKnownModalOverlay()` plus "is the topmost modal me?", so tooltips/hover-cards don't steal keyboard control.
