**Findings**

1. The `auto_queue=True only for unused` change is not just cleanup; it changes product behavior and would narrow current autopromotion semantics substantially. The draft says this explicitly in [staged-wobbling-babbage.md:21](/Users/user_c042661f/.claude/plans/staged-wobbling-babbage.md#L21) and [staged-wobbling-babbage.md:33](/Users/user_c042661f/.claude/plans/staged-wobbling-babbage.md#L33). Today, auto-generated auto-fix clusters default to `ephemeral_autopromote` via [cluster_semantics.py:81](/Users/user_c042661f/Documents/desloppify/desloppify/engine/_plan/cluster_semantics.py#L81), and that behavior is asserted in [test_auto_cluster.py:134](/Users/user_c042661f/Documents/desloppify/desloppify/tests/plan/test_auto_cluster.py#L134). Built-ins already include more than `unused`, for example [catalog_entries.py:19](/Users/user_c042661f/Documents/desloppify/desloppify/base/registry/catalog_entries.py#L19) and [catalog_entries.py:292](/Users/user_c042661f/Documents/desloppify/desloppify/base/registry/catalog_entries.py#L292), and generic plugin detectors with `fix_cmd` also register as `auto_fix` in [registration.py:46](/Users/user_c042661f/Documents/desloppify/desloppify/languages/_framework/generic_support/registration.py#L46). If you want explicit metadata, the plan should preserve current defaults or call this out as a deliberate migration.

2. The proposed trace plumbing still misses a real exclusion path. The draft says to trace `executable_objective_ids()` in [staged-wobbling-babbage.md:68](/Users/user_c042661f/.claude/plans/staged-wobbling-babbage.md#L68), but snapshot applies an additional clustered-ID subtraction afterwards in [snapshot.py:585](/Users/user_c042661f/Documents/desloppify/desloppify/engine/_work_queue/snapshot.py#L585). That means a queue trace built only around schema branch selection will still fail to explain some “why isn’t this in `next`?” cases.

3. The `--explain` scope is underspecified for non-terminal consumers, and the plan does not explicitly include tests. `opts.explain` is already threaded into queue building in [queue_flow.py:289](/Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/queue_flow.py#L289), but payload serialization in [output.py:115](/Users/user_c042661f/Documents/desloppify/desloppify/app/commands/next/output.py#L115) only carries item-level explain data today. If queue-level trace matters, it should be added to JSON/query output too, with targeted test updates in the existing queue, auto-cluster, and `next` suites.

Directionally, the plan is good: the README rewrite and queue-level trace are worth doing. I’d revise it to keep autopromotion backward-compatible unless you intentionally want a behavior change, trace snapshot-level exclusions rather than only schema branches, and make payload/tests first-class scope. Minor note: the file list in the markdown uses package-relative paths; in this repo the real paths are under `desloppify/...`.
