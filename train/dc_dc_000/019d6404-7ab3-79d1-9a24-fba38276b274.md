        # Implementation Plan: `megaplan watch` — Human-Friendly Plan Monitor

## Overview

When megaplan runs inside a background subagent, the user has no way to check progress without parsing raw JSON. The existing `status` and `progress` commands return structured JSON (designed for machine consumption). We need a `watch` command that combines both into a human-readable text summary printed to stderr/stdout as plain text, not JSON.

**Current state:** `handle_status()` (cli.py:77-98) returns state, notes, next steps. `handle_progress()` (cli.py:112-173) returns task/batch execution progress. Both return `StepResponse` dicts rendered as JSON.

**Approach:** Add a `handle_watch()` function that reuses the same data-fetching logic but formats it as human-readable text. Print it directly instead of going through `render_response()` (which JSON-dumps). Register it as a new subcommand.

## Main Phase

### Step 1: Add `handle_watch()` handler (`megaplan/cli.py:98`)
**Scope:** Small (30-50 lines)

1. **Implement** `handle_watch()` at `megaplan/cli.py:98` (after `handle_status`). It should:
   - Call `load_plan(root, args.plan)` to get plan_dir and state
   - Extract from state: `name`, `current_state`, `iteration`, `history` (last entry's step + timestamp), notes count
   - If `current_state == "executed"` or finalize.json exists, compute execution progress (reuse logic from `handle_progress`: tasks done/total, batches done/total)
   - Format as multi-line human-readable text, e.g.:
     ```
     Plan: my-plan-name
     State: finalized (iteration 2)
     Last phase: gate — 2026-04-06T14:23:00
     Notes: 2 pending
     Execution: 5/12 tasks done, 2/4 batches complete
     Next: execute
     ```
   - Return a `StepResponse` with `"step": "watch"` and a `"display"` key containing the formatted text

2. **Print human-readable output.** Two options:
   - (a) Print the display text to stdout before returning, then return a minimal JSON response — but this mixes formats.
   - (b) Better: add a `--human` flag or have `render_response` check for a `"display"` key and print that instead of JSON. Simplest: just print the text and `sys.exit(0)` directly from the handler, bypassing `render_response`. But that breaks the handler contract.
   - **Decision:** Have `handle_watch` return a normal `StepResponse` with a `"display"` field. In `main()`, special-case the `watch` command to print `response["display"]` as plain text instead of JSON. This is ~3 lines in `main()`.
