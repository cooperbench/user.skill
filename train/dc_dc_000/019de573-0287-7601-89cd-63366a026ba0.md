        # Implementation Plan: Incremental Agent-Led Discord Sending

## Overview
Design and document a lightweight architecture for incremental Discord sends in `docs/incremental-agent-sending-plan.md`. The current repo has a two-phase agent lifecycle in `app/services/agentic.py`: Phase A reads and produces one final user-facing text, that text is OOB-checked and sent through `app/services/messaging.py`, then Phase B writes state using a seed of what was sent. Discord delivery is currently a provider branch inside `send_outbound`, backed by `app/services/discord.py`, and Discord-specific conversational pacing already exists around `run_agentic_turn_with_metadata` and `before_paced_send`.

The core architectural shift to document is not paragraph splitting. It should add a first-class incremental-send contract: the agent can intentionally emit send actions while it reasons, the runtime records the actual send ledger after provider acknowledgement, Phase A can continue with an accurate transcript of sent content, interruption checks run between send opportunities, and Phase B is seeded from the actual send ledger rather than the model's planned text.

The likely implementation touch points are `app/services/agentic.py`, `app/services/messaging.py`, `app/services/discord.py`, `app/services/prompts.py`, migrations under `migrations/`, fake DB support in `tests/conftest.py`, lifecycle tests in `tests/test_agentic_lifecycle.py`, transport tests in `tests/test_send_outbound.py`, and focused Discord transport tests if needed.
