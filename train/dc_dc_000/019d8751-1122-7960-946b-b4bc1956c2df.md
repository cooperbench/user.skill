        # Implementation Plan: Drop Image as Variant

## Overview

Add the ability to drop an image (from filesystem or GenerationsPane) onto an existing image in either Timeline or Batch view to create a variant relationship, instead of adding it as a new standalone image. When dragging over an existing image, a two-region overlay appears: the main area creates a new variant, and a bottom strip replaces the current main image (demoting the old main to a variant).

### Current state
- **Drop system**: Timeline uses `useUnifiedDrop.ts` → `useDropActions.ts` handlers. Batch uses `BatchDropZone.tsx` → same `useDropActions.ts` handlers. Both support file and generation drops, always creating new standalone images.
- **Variant system**: `generation_variants` table tracks variants per generation. Each generation has one `is_primary: true` variant. DB trigger auto-unsets old primary when a new one is set. Variants are created via direct `supabase().from('generation_variants').insert(...)`.
- **Image rendering**: Timeline items render in `TimelineItem.tsx` with absolute positioning. Batch items render in `ShotBatchItemDesktop.tsx` inside `ImageGrid.tsx` with `data-sortable-item` wrappers.

### Key constraint
The current drop handlers (`handleTimelineImageDrop`, `handleBatchImageDrop`, etc.) always create new generations. The variant-drop feature needs to intercept drops that land *on* an existing image and route to new variant-creation logic instead.

## Phase 1: Variant Drop Actions (`useDropActions.ts`)

### Step 1: Add variant drop handlers to `useDropActions.ts`
**Scope:** Medium

1. **Add** two new handlers to `useDropActions.ts`:
   - `handleVariantFileDrop(files: File[], targetGenerationId: string, mode: 'variant' | 'main')` — uploads the file, then inserts into `generation_variants` for the target generation. If `mode === 'main'`, sets `is_primary: true` (DB trigger demotes old primary). If `mode === 'variant'`, sets `is_primary: false`.
   - `handleVariantGenerationDrop(sourceGenerationId: string, imageUrl: string, thumbUrl: string | undefined, targetGenerationId: string, mode: 'variant' | 'main')` — copies the source generation's image as a new variant on the target generation. Same `mode` logic.

2. **Implementation details** for file variant drop:
   - Reuse existing `cropImagesToShotAspectRatio` for processing.
   - Upload the file using the same storage upload pattern as `externalImageDrop.ts:createGenerationForUploadedImage`, but **skip** creating a new `generations` row — only insert into `generation_variants`.
   - Actually, we need to upload the file to storage first. Look at `useHandleExternalImageDrop` for the upload-to-storage path and extract/reuse just the upload portion. The variant insert needs: `generation_id` (target), `location` (uploaded URL), `thumbnail_url`, `is_primary`, `variant_type: 'dropped'`, `params: { source: 'drop', ... }`.

3. **Implementation details** for generation variant drop:
   - The source generation already has a `location` URL. Insert a new `generation_variants` row pointing to the target generation but using the source's image URL.
   - Set `variant_type: 'dropped'` and `params: { source_generation_id: sourceGenerationId }`.

4. **Return** the new handlers from `useDropActions` alongside the existing four.

### Step 2: Add `'dropped'` to variant types (`src/shared/constants/variantTypes.ts`)
**Scope:** Small

1. **Inspect** `variantTypes.ts` for the `VARIANT_TYPE` constant and `VariantType` type.
2. **Add** `DROPPED: 'dropped'` to `VARIANT_TYPE` and add `'dropped'` to `VariantType`.

## Phase 2: Per-Image Drop Zone Overlay Component

### Step 3: Create `VariantDropOverlay` component
**Scope:** Medium

1. **Create** `src/shared/components/VariantDropOverlay.tsx` — a reusable overlay component that renders on top of an image when a compatible drag is detected over it.

2. **Component structure**:
   ```tsx
   interface VariantDropOverlayProps {
     isVisible: boolean;
     activeRegion: 'variant' | 'main' | null;
     onRegionChange: (region: 'variant' | 'main' | null) => void;
   }
   ```
   - Renders `absolute inset-0 z-30` overlay with two regions:
     - **Top ~75%**: "+ Variant" label with icon, highlighted when `activeRegion === 'variant'`
     - **Bottom ~25%**: "Main" label, highlighted when `activeRegion === 'main'`
   - Use semi-transparent backgrounds (`bg-primary/20` for inactive, `bg-primary/40` for active region).
   - Region detection: The parent handles `onDragOver` to determine mouse Y position relative to the image, calculates which region (top 75% = variant, bottom 25% = main), and passes to overlay.

3. **Styling**: Use existing design system — `bg-primary`, `text-primary-foreground`, borders. No hardcoded colors.

## Phase 3: Wire Into Timeline View

### Step 4: Add per-image variant drop detection to `TimelineItem.tsx`
**Scope:** Medium

1. **Add** drag event handlers to the outer `div` in `TimelineItem.tsx:178`:
   - `onDragEnter`: Detect drag type (file or generation). Set local state `isVariantDropTarget: true`.
   - `onDragOver`: Prevent default. Calculate mouse Y position relative to the item to determine active region (`variant` vs `main`). Update state.
   - `onDragLeave`: Clear state.
   - `onDrop`: Call the appropriate variant drop handler from `useDropActions` with the image's `generation_id` and the active region mode.

2. **Props addition**: `TimelineItem` needs two new optional props:
   - `onVariantFileDrop?: (files: File[], generationId: string, mode: 'variant' | 'main') => Promise<void>`
   - `onVariantGenerationDrop?: (sourceGenId: string, imageUrl: string, thumbUrl: string | undefined, targetGenId: string, mode: 'variant' | 'main') => Promise<void>`

3. **Render** `<VariantDropOverlay>` inside the item when `isVariantDropTarget` is true.

4. **Important**: The per-item drop handlers must call `e.stopPropagation()` to prevent the parent timeline container from also handling the drop (which would create a new standalone image).

### Step 5: Thread variant drop callbacks through Timeline component tree
**Scope:** Small

1. **Trace** the prop chain: `ShotEditor` → `TimelineContainer` → `TimelineTrackContent` → `TimelineItem`.
2. **Pass** the two new variant drop handlers from `useDropActions` down through each level.
3. The handlers at the `ShotEditor` level already have access to `useDropActions`, so wire them there and pass down.

## Phase 4: Wire Into Batch View

### Step 6: Add per-image variant drop detection to `ShotBatchItemDesktop.tsx`
**Scope:** Medium

1. **Add** the same drag event handler pattern as Step 4 to `ShotBatchItemDesktop.tsx:157` (the outer sortable div).
   - `onDragEnter`, `onDragOver`, `onDragLeave`, `onDrop` with region detection.
   - Render `<VariantDropOverlay>` when active.

2. **Props addition**: Add variant drop callbacks to `ShotBatchItemDesktopActions`:
   - `onVariantFileDrop?: (files: File[], generationId: string, mode: 'variant' | 'main') => Promise<void>`
   - `onVariantGenerationDrop?: (sourceGenId: string, imageUrl: string, thumbUrl: string | undefined, targetGenId: string, mode: 'variant' | 'main') => Promise<void>`

3. **Interaction with existing BatchDropZone**: When a drop lands on a specific image (handled by `ShotBatchItemDesktop`'s `onDrop` with `stopPropagation`), the `BatchDropZone`'s drop handler should NOT fire. When a drop lands in empty grid space, `BatchDropZone` handles it normally (adds new image). This is naturally achieved by `stopPropagation()` in the per-item handler.

### Step 7: Thread variant drop callbacks through Batch component tree
**Scope:** Small

1. **Trace**: `ShotEditor` → `ShotImageManagerDesktop` → `ImageGrid` → `ShotBatchItemDesktop`.
2. **Pass** variant drop handlers from `useDropActions` through the chain.
3. `ShotImageManagerDesktop` already receives drop callbacks; add the variant ones alongside.

## Phase 5: Edge Cases and Polish

### Step 8: Handle self-drop prevention
**Scope:** Small

1. **In** the per-item `onDrop` handlers (Steps 4, 6): If the dragged generation ID equals the target generation ID, ignore the drop (no-op). This prevents creating a variant of an image onto itself.

### Step 9: Handle file upload for variant drops
**Scope:** Medium

1. **The file variant drop** path needs to upload files to Supabase storage without creating a new `generations` row. Extract the upload logic from `externalImageDrop.ts` into a reusable helper, or call the existing upload path and then insert the variant.
2. **Alternative simpler approach**: Create a full generation (using `createGenerationForUploadedImage`), then move it to be a variant of the target:
   - Upload file → get new generation with `location` URL
   - Insert a variant on the target generation using the uploaded URL
   - Delete the temporary standalone generation (or keep it hidden)
   - This is more complex. Better approach: extract just the storage upload from `externalImageDrop.ts` and reuse it.
3. **Simplest approach**: Use the upload portion of `useHandleExternalImageDrop` to get a storage URL, then insert directly into `generation_variants`. Investigate `useHandleExternalImageDrop` implementation to see if the upload can be used independently.

### Step 10: Cache invalidation after variant drop
**Scope:** Small

1. **After** inserting a variant, call `enqueueVariantInvalidation(queryClient, { generationId: targetGenerationId, shotId, reason: 'variant-drop' })` to ensure the UI updates.
2. **Also** invalidate the shot's generation list query if the variant changes the primary image (mode === 'main'), since the thumbnail displayed in the grid/timeline will change.
