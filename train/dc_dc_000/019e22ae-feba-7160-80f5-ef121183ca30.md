# The bug

In `megaplan/profiles/__init__.py`, `apply_profile_expansion()` calls `apply_vendor_rewrite()` on profiles that have premium (claude/codex) slots, unless the profile is marked `vendor_locked = true` in metadata. The rewrite swaps every premium slot's vendor to the effective vendor (CLI > state > `[defaults].vendor` in user config.toml > hardcoded `"claude"`).

The `all-codex` profile at `megaplan/profiles/all-codex.toml` defines every phase as `codex`, but the toml file is missing `vendor_locked = true`. So when a user runs `megaplan init --profile all-codex` with no `--vendor` flag and no `[defaults].vendor` set in `~/.config/megaplan/config.toml`, the default vendor resolves to `"claude"` (via `megaplan/_core/user_config.py:72`), and `apply_vendor_rewrite()` silently converts every `codex` slot in the profile back to `claude`. Result: `--profile all-codex` runs entirely on Claude.

Real-world impact just observed: a $19+ megaplan run hit a Claude rate-limit on the `finalize` phase because the user thought they were on `all-codex`. Investigation showed `state.json` `config.phase_model` contained `["plan=claude:high", "finalize=claude", "execute=claude", ...]` for a run invoked with `--profile all-codex`. The persistent agent sessions named in `state.json.session_summaries` were all `claude_*` (planner, critic, gatekeeper).

## Part 2 — make `apply_profile_expansion` smarter (defensive)

This is the deeper fix that defends against future profiles forgetting the annotation. In `megaplan/profiles/__init__.py` around line 451-452:

```python
if _profile_has_premium_slots(resolved):
    resolved = apply_vendor_rewrite(resolved, vendor)
```

Replace with: only run the rewrite when the user explicitly passed `--vendor`, OR when the profile is genuinely vendor-mixed (so the rewrite has work to do). Don't silently convert a vendor-uniform profile to a different vendor just because the default vendor differs from the profile's chosen vendor.

Suggested logic:
```python
if _profile_has_premium_slots(resolved):
    profile_vendors = _premium_vendors_in_profile(resolved)  # new helper
    profile_is_vendor_uniform = len(profile_vendors) == 1
    user_explicitly_chose_vendor = cli_vendor is not None or state_vendor is not None
    if user_explicitly_chose_vendor or not profile_is_vendor_uniform:
        resolved = apply_vendor_rewrite(resolved, vendor)
```

Define `_premium_vendors_in_profile()` to return the set of `{"claude", "codex"}` slots appearing in the profile. If the profile has only `codex` slots (or only `claude` slots), it's vendor-uniform.

Rationale: the rewrite exists to apply a user's `--vendor` choice (or default) to a tier profile that hasn't picked a vendor. If a profile HAS picked a vendor (uniform), the rewrite should only fire when the user explicitly asks for a different one. Anything else is silently overriding profile-author intent.
