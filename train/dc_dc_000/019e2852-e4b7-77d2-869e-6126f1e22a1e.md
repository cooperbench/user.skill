> AGENT

I would not make a generic executor the main standard for arbitrary “code we make on the fly.”

The better split is:

1. **One-off code inside a run**: put the script under the run/step scratch area and execute it as a task-mode `local` adapter step.
2. **Repeated or named capability**: promote it to a real executor in a pack.
3. **Reusable workflow**: compose executors with an orchestrator.

A generic executor like `builtin.run_script` sounds convenient, but it blurs Astrid’s contract: executors are supposed to be inspectable, documented units with known inputs/outputs. A generic “run whatever script” executor mostly duplicates what task-mode `local` adapter already does, while making the executor registry less meaningful.

The current place is effectively `runs/` / task-mode step dirs. The local adapter creates:

```text
<project-root>/runs/<run-id>/steps/<step-id>/v<N>/
  dispatch.json
  subprocess.log
  produces/
```

See [local.py](/Users/user_c042661f/Documents/reigh-workspace/Astrid/astrid/core/adapter/local.py:18). The repo also explicitly says one-off scratch belongs under `runs/` in [creating-tools.md](/Users/user_c042661f/Documents/reigh-workspace/Astrid/docs/creating-tools.md:82).

The gap I see: the local adapter does not currently give the subprocess an obvious `ARTAGENTS_STEP_DIR` or `ARTAGENTS_PRODUCES_DIR` env var. So an ad hoc script has to hardcode or be passed its output path. I’d make the durable fix there, not by adding a generic executor:

```text
ARTAGENTS_RUN_ROOT=<project>/runs/<run-id>
ARTAGENTS_STEP_DIR=<project>/runs/<run-id>/steps/<step-id>/v<N>
ARTAGENTS_PRODUCES_DIR=<step-dir>/produces
```

Then the convention becomes clean:

```bash
python3 -m astrid plan add-step \
  --project <slug> \
  --run-id <id> \
  --step-id quick_probe \
  --command 'python3 runs/<run-id>/scratch/quick_probe.py' \
  --adapter local
```

And the script writes artifacts to `$ARTAGENTS_PRODUCES_DIR`.

So: **no generic executor as the default**. Use `local` adapter for on-the-fly code, store scratch code under `runs/<run-id>/scratch/` or the step dir, and promote anything worth keeping into a pack executor.
