### 4. **Where Circular Import Risk Occurs**

**CRITICAL POINT: Line 151 in `generic.py`**

```python
def generic_lang(...) -> LangConfig:
    from desloppify.languages import register_generic_lang  # ← LAZY IMPORT
```

This import is **inside the function**, not at module-level. This is intentional to avoid a circular dependency:

**Why this matters:**
- When `desloppify/languages/__init__.py` is loaded, it imports `discovery`, `registry_state`, `resolution` at the top level (lines 10-14)
- `resolution.py` imports `discovery.load_all()` at module-level
- `discovery.load_all()` triggers `importlib.import_module()` for each plugin
- When a generic plugin like `rust/__init__.py` is imported, it runs the module-level code: `generic_lang(name="rust", ...)`
- If line 151 were a **top-level import**, then:
  ```
  generic.py module load
    → tries to import desloppify.languages
    → desloppify.languages tries to import discovery
    → discovery gets called during load
    → plugins get imported
    → rust/__init__.py calls generic_lang()
    → but generic.py is still initializing... CIRCULAR!
  ```

```python
def generic_lang(...):
```

The framework is well-designed to handle this. The error logging in `discovery.py` gracefully catches any plugin failures without aborting the entire system.
