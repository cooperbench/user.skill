        # Implementation Plan: Structured JSON Tracking Layer for Finalize/Execute/Review

## Overview

Replace the LLM-edits-markdown-checklist approach with a structured JSON artifact that flows mechanically through finalize → execute → review. The plan narrative stays markdown; the tracking layer becomes pure data.

## Current State

- **Finalize** produces `final.md` (prose markdown with `- [ ]` checklist + `> _notes:_` lines) and a minimal `finalize.json` (task_count, watch_items, meta_commentary).
- **Execute** tells the LLM to edit `final.md` in-place — checking off `- [ ]` → `- [x]` and filling `> _notes:_`. Also produces `execution.json` (output, files_changed, commands_run, deviations).
- **Review** tells the LLM to read the edited `final.md`, verify checked-off items, fill in `> _verdict:_` lines, and produce `review.json`.

**Problems:** Brittle markdown parsing, no machine-readable task state, no structured link between tasks and executor/reviewer feedback.

## Step 7: Add deep validation for merge inputs

**File:** `megaplan/handlers.py` (new helper, used by execute and review handlers)

Address the Codex resume path gap: `validate_payload()` only checks top-level required keys, so malformed nested arrays could slip through on the Codex resume path (which skips `--output-schema`).

Add a `_validate_merge_inputs()` helper called in the execute and review handlers *before* merging into finalize.json:

```python
def _validate_merge_inputs(items: list, required_keys: set[str], label: str) -> list:
    """Validate and filter merge input arrays. Skip malformed entries with a warning."""
    valid = []
    for item in items:
        if not isinstance(item, dict):
            continue
        missing = required_keys - item.keys()
        if missing:
            continue  # skip malformed entry — logged in deviations or issues
        valid.append(item)
    return valid
```

Usage in execute handler:
```python
task_updates = _validate_merge_inputs(
    worker.payload.get("task_updates", []),
    {"task_id", "status", "executor_notes"},
    "task_updates",
)
```

Usage in review handler:
```python
task_verdicts = _validate_merge_inputs(
    worker.payload.get("task_verdicts", []),
    {"task_id", "reviewer_verdict"},
    "task_verdicts",
)
sense_check_verdicts = _validate_merge_inputs(
    worker.payload.get("sense_check_verdicts", []),
    {"sense_check_id", "verdict"},
    "sense_check_verdicts",
)
```

This is defensive filtering at the merge boundary — if the Codex resume path delivers garbage in nested arrays, we skip those entries rather than corrupting finalize.json. The merge itself already tolerates unknown task_ids (no match → no update), so the combination is robust.
