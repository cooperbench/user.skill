Non-negotiable goals:
1. A minimal but strong workflow lifecycle/checklist should exist in agent-facing docs. It must cover four entry points: raw JSON import, existing ready template fix, fork of an existing template, and from-scratch Python workflow.
2. The checklist must clearly separate programmatic gates from agentic responsibilities:
   - Programmatic: port preflight, schema validation, unresolved widgets, required inputs/connections, unknown classes, node-pack suggestions, model asset declarations, output artifacts, index freshness, tests, worker contract validation, live RunPod evidence.
   - Agentic: source quality, choosing official/Kijai/community workflows, interpreting model provenance, deciding smoke adaptations, deciding whether missing nodes are legitimate custom nodes or helper/UI junk, comparing behavior to Wan2GP/app semantics, and documenting intentional differences.
3. The existing CLI/tooling should make that process harder to miss. Prefer thin wrappers or strict modes over a new parallel system. If already adequate, document and wire it. If inadequate, implement the smallest robust improvement.
4. Ready templates intended for production/app parity must not silently pass with unresolved positional `widget_*` fields where live Comfy requires named inputs. Add checks/tests for this class of issue.

- VibeComfy owns workflow correctness: import, widget alias resolution, schema validation, model/node requirements, output artifact declarations, ready-template metadata.
- Reigh worker owns app capability parity: route/task mapping, semantic runtime patching, LoRA/control/video/image variable behavior, product artifact contract, live evidence.
- RunPod/live tests are final end-to-end proof, not the first place obvious graph-shape errors appear.
- Worker-side code should patch semantic fields, not know arbitrary `widget_3` meanings. If you find ad hoc widget mapping in worker code that should live in VibeComfy, propose or implement a safe migration step.
- The developer experience should be: “I want to onboard/fork/fix/build this workflow” -> run a small set of commands -> get a clear report -> fix what it says -> promote only after local checks and focused live evidence.
