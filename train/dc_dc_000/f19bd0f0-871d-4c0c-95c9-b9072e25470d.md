# Implementation Plan: Seed new shots with `lastEditedLora` instead of full inheritance

## Overview
Today a new shot inherits the full LoRA array from the "last active" shot because `shotSettingsInheritance.ts:160-168` spreads `mainSettings.loras` into sessionStorage, while only prompt fields are explicitly zeroed. We will:
1. Track a single project-scoped `lastEditedLora` written only on explicit edits made in the travel shot editor.
2. Strip `loras` from inherited `mainSettings` and seed new shots with `[lastEditedLora]` (or `[]`).
3. Also seed unopened shots (those with no DB settings row) at first open via the existing `!hasShotSettings` seam in `useShotSettings.ts`.

Constraints confirmed against the repo:
- `useLoraManager` is shared across tools (travel, image gen, edit-video, lightbox — see `useImageGenForm.ts:154`, `useReplaceMode.ts:115`, `useImageLightboxEnvironment.ts:75`). The write path must not fire for non-travel consumers.
- `handleLoraStrengthChange` (`useLoraManager.tsx:127-134`) has no `isManualAction` parameter and always calls `markAsUserSet()`. `handleLoadProjectLoras` (`loraPersistence.tsx:141-145`) calls it during Load Saved — that path must be teachable to skip "explicit edit" tracking.
- `shotSettingsInheritance.ts:117-136` only fetches `projects.settings` when localStorage doesn't already supply `mainSettings`/`uiSettings` — we can't rely on that fetch to surface `lastEditedLora`. Mirror the value to localStorage on write and read it there first.
- `shotSettingsInheritance` only runs at shot creation (`shotCreationEffects.ts:27-38`). First-open of a legacy unopened shot is covered by adding a small seeding branch in `useShotSettings.ts` where `hasShotSettings === false`.
- Normalized settings cannot distinguish "loras absent" vs "loras = []" (`settings.ts:247-272,368-409`) — that's fine because the seeding branch gates on `!hasShotSettings` (DB-level), not on the normalized value.

## Main Phase

### Step 1: Add `isManualAction` to strength change and an explicit-edit callback (`reigh-app/src/domains/lora/hooks/useLoraManager.tsx`, `reigh-app/src/domains/lora/types/loraManager.ts`)
**Scope:** Medium
1. **Extend** `handleLoraStrengthChange` to accept `(loraId, newStrength, isManualAction = true)` and only call `markAsUserSet()` when `isManualAction`. Update the `LoraManagerState` / `LoraPersistenceManagerHandle` types to match (`loraStateHelpers`/`loraPersistence` consumers).
2. **Add** an optional `onExplicitLoraEdit?: (event: { kind: 'add' | 'remove' | 'strength'; lora: ActiveLora | null; current: ActiveLora[] }) => void` to `LoraManagerOptions`.
3. **Invoke** `onExplicitLoraEdit` from:
   - `handleAddLora` when `isManualAction === true` → `{ kind: 'add', lora: newLora, current: nextLoras }`.
   - `handleRemoveLora` when `isManualAction === true` → `{ kind: 'remove', lora: removed, current: remaining }`.
   - `handleLoraStrengthChange` when `isManualAction === true` → `{ kind: 'strength', lora: updated, current: nextLoras }`.
4. **Update** `loraPersistence.tsx:141-145` to pass `false` as the new third arg on `handleLoraStrengthChange` inside `handleLoadProjectLoras`, so Load Saved does not look like an explicit edit.

### Step 2: Wire the write only from the travel-shot surface (`reigh-app/src/tools/travel-between-images/components/ShotEditor/hooks/editor-state/useLoraSync.tsx`, new helper `reigh-app/src/shared/lib/lastEditedLora.ts`)
**Scope:** Medium
1. **Add** a small helper module `lastEditedLora.ts` with:
   - `async function writeLastEditedLora(projectId: string, lora: ShotLora | null): Promise<void>` — updates `projects.settings['travel-between-images'].lastEditedLora` via the same pattern `useToolSettings` uses for project-scoped writes, and mirrors the value to `localStorage` under a new key `STORAGE_KEYS.LAST_EDITED_LORA(projectId)`.
   - `function readLastEditedLoraFromLocalStorage(projectId: string): ShotLora | null` — used by the inheritance path to avoid a forced round-trip.
   - `async function readLastEditedLoraFromProject(projectId: string): Promise<ShotLora | null>` — fallback when localStorage is empty.
2. **Wire** `onExplicitLoraEdit` inside `useLoraSync.tsx` only:
   - Determine the target LoRA: `kind === 'remove'` → pick `current[current.length - 1] ?? null` (see Q2 assumption); otherwise use `event.lora`.
   - Debounce `strength` events ~500ms trailing so slider drags produce ≤ 2 writes.
   - Call `writeLastEditedLora(projectId, target)`; no-op if `projectId` is falsy.
3. **Do not** wire `onExplicitLoraEdit` in `useImageGenForm.ts`, `useReplaceMode.ts`, or `useImageLightboxEnvironment.ts`. Those consumers stay behavior-identical.

### Step 3: Stop full LoRA inheritance and seed from `lastEditedLora` at shot creation (`reigh-app/src/shared/lib/shotSettingsInheritance.ts`)
**Scope:** Medium
1. **Strip** `loras` from the `mainSettings` spread into `defaultsToApply` — treat it like `prompt`/`pairConfigs` (`:160-168`).
2. **Read** `lastEditedLora`:
   - First try `readLastEditedLoraFromLocalStorage(projectId)` (synchronous, cheap).
   - If null, always issue the project-settings fetch (drop the `!mainSettings || !uiSettings` guard for this one value, or add a dedicated second fetch — cheaper: unconditionally fetch project settings for `lastEditedLora` when localStorage has none).
3. **Seed** `defaultsToApply.loras = lastEditedLora ? [lastEditedLora] : []` in all branches.
4. **Soft-migration fallback** (see Q3): when `lastEditedLora` is absent and `mainSettings?.loras?.length > 0`, seed `[mainSettings.loras[0]]` as a one-time best-effort so the first new shot post-deploy isn't visibly empty for existing users.
5. **Add/update** tests in `reigh-app/src/shared/lib/__tests__/shotSettingsInheritance.test.ts`: inherited multi-LoRA `mainSettings` → seeded length ≤ 1; `lastEditedLora` in localStorage → seeded as 1-element array; neither present → `[]`; fallback branch.

### Step 4: Seed unopened legacy shots at first open (`reigh-app/src/tools/travel-between-images/hooks/settings/useShotSettings.ts`)
**Scope:** Small
