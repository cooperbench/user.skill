        # Implementation Plan: Subagent Note Injection (inject-after + kill-and-inject)

## Overview
The megaplan subagent runs autonomously in the background, executing phases via CLI. Users need two ways to steer it mid-flight:

1. **inject-after**: Add a note from the main conversation; the subagent picks it up before the next phase.
2. **kill-and-inject**: Kill the currently running phase, inject a note, and the subagent re-reads state before retrying.

The `override add-note` command already writes notes to `state["meta"]["notes"]`, and `intent_and_notes_block()` already renders them into every worker prompt. The missing pieces are:
- The subagent prompt doesn't instruct the agent to check for new notes between phases
- `handle_status` doesn't surface notes (so the subagent can't see them via `megaplan status`)
- No defined kill+reinject flow exists

**Constraint**: The subagent is controlled via a prompt template in `claude_subagent_appendix.md` — it's not a code path. Most changes are to the prompt spec and the status output, not deep runtime logic.

## Main Phase

### Step 1: Surface notes in status output (`megaplan/cli.py:77-90`)
**Scope:** Small
1. **Modify** `handle_status` to include `notes` and `pending_notes_count` fields in its response. Pull from `state["meta"].get("notes", [])`. Include full note objects (timestamp + text) so the subagent can see what's new.
2. **Add** a `last_note_at` convenience field — the timestamp of the most recent note, or `null`. This gives the subagent a quick way to detect new notes without diffing arrays.

### Step 2: Add a `notes_last_seen` cursor to plan state (`megaplan/types.py`, `megaplan/handlers.py`)
**Scope:** Small  
1. **Add** optional `notes_last_seen` field to `PlanMeta` in `types.py` — an integer index tracking how many notes the subagent has acknowledged.
2. **Add** a new CLI command or flag: `megaplan override ack-notes --plan <name>` that sets `notes_last_seen` to the current length of the notes array. This lets the subagent explicitly mark notes as seen.
3. **Update** `handle_status` to compute `pending_notes_count = len(notes) - notes_last_seen` so the subagent can see at a glance whether new notes exist.

### Step 3: Update the subagent prompt for inject-after (`megaplan/data/claude_subagent_appendix.md`)
**Scope:** Medium
1. **Add** a "Note injection" section to the appendix between "Phase rules" and "Execution rules", instructing the subagent to:
   - After every phase completes, check `megaplan status --plan <name>` before starting the next phase (this is already partially implied but should be explicit).
   - If `pending_notes_count > 0`, read and honor the notes. Notes from the user are authoritative guidance — treat them like `SendMessage` instructions.
   - After reading notes, run `megaplan override ack-notes --plan <name>` to reset the pending count.
   - If a note contradicts the current plan direction, treat it as a soft breakpoint — pause and evaluate whether to continue, replan, or escalate.
2. **Add** a prominent banner format to the status output: when `pending_notes_count > 0`, the `summary` field should include `⚠ N pending user note(s)` so it's impossible to miss even in a quick status poll.

### Step 4: Define the kill-and-inject flow (`megaplan/data/claude_subagent_appendix.md`, `megaplan/cli.py`)
**Scope:** Medium
1. **Document** the kill-and-inject pattern in the appendix under a new "Kill and reinject" section:
   - The user kills the running phase from the main conversation (via `TaskStop` on the subagent, or Ctrl+C relay).
   - The subagent's in-flight CLI call fails (non-zero exit, timeout, or error response).
   - Before retrying, the subagent MUST re-read `megaplan status --plan <name>` and check for pending notes.
   - If notes are pending, honor them before deciding whether to retry the failed phase, skip it, or take a different action.
   - This piggybacks on the existing "retry with `--fresh`" safeguard — the key addition is checking notes before retry.
2. **Update** the safeguard section (lines 75-79) to explicitly mention: "If a phase fails or is interrupted, check for pending notes before retrying."
3. **Add** a `megaplan override kill-phase --plan <name> --note "..."` convenience command that combines add-note + sets a `phase_killed` flag in meta. This is optional but gives the subagent a clear signal that the interruption was intentional (vs a random crash).
   - In `handlers.py`, implement `_override_kill_phase` that writes `{"action": "kill-phase", "timestamp": ..., "note": ...}` to overrides and sets `meta["phase_killed"] = true`.
   - `handle_status` surfaces `phase_killed: true` when set.
   - The subagent prompt instructs: if `phase_killed` is true in status, do NOT retry — read the note and decide next action.
   - Any successful phase start clears `phase_killed`.

### Step 5: Update the outer skill handling section (`megaplan/data/claude_subagent_appendix.md:133-138`)
**Scope:** Small
1. **Add** instructions for the outer skill (main conversation) to document the two injection flows:
   - **inject-after**: Run `megaplan override add-note --plan <name> --note "..."` — the subagent will pick it up after the current phase.
   - **kill-and-inject**: Run `megaplan override kill-phase --plan <name> --note "..."`, then kill the subagent's current task. The subagent will re-read state on failure and see the note.
2. **Add** these commands to the command reference section (lines 110-131).

### Step 6: Tests (`tests/test_megaplan.py`)
**Scope:** Medium
1. **Test** `handle_status` includes `notes`, `pending_notes_count`, and `last_note_at` fields.
2. **Test** `ack-notes` override updates `notes_last_seen` and that `pending_notes_count` decrements accordingly.
3. **Test** `kill-phase` override sets `phase_killed` in meta and that it surfaces in status.
4. **Test** `phase_killed` is cleared on next phase start (add a unit test for the clearing logic).
5. **Test** status summary includes the pending-notes banner when notes are pending.
