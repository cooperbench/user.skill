# Defect

`src/features/summarising/topic_editor.py` has in-memory-only idempotent-replay protection. The current implementation (look for `_is_idempotent_replay` and `dispatcher_context["seen_tool_call_ids"]`) tracks tool_use_ids seen within a single Python process. If the runner crashes mid-run and restarts, the new process has an empty `seen_tool_call_ids` set and will re-dispatch the same tool calls, double-writing topics/transitions/observations.

Confirmed by Codex review: *"Idempotent replay is only in-memory and does not return the prior result."*

# Fix

Make `_is_idempotent_replay` check the DATABASE instead of (or in addition to) the in-memory set:

1. On every dispatch entry for a write tool (`post_*`, `watch_topic`, `update_topic_source_messages`, `discard_topic`, `record_observation`, `finalize_run`), query `topic_transitions` for an existing row matching `(run_id, tool_call_id)`. If found, return the prior outcome rather than re-executing.

2. Add a method to `src/common/db_handler.py` + `src/common/storage_handler.py` named `get_topic_transitions_by_tool_call_ids(run_id, tool_call_ids, environment)` that returns a dict mapping `tool_call_id → transition_row`. The dispatcher can batch-look-up all tool_call_ids at the start of a turn to avoid N queries per tool call.

3. Update `_dispatch_tool_call` so the FIRST thing it does is check this map (build once per turn via a `dispatcher_context["idempotent_results"]` cache populated at the top of each turn iteration in `run_once`). If the tool_call_id is present, return `{"tool_call_id": id, "tool": name, "outcome": "idempotent_replay", "action": prior_row.get("action"), "topic_id": prior_row.get("payload", {}).get("topic_id")}`.

4. The existing `_is_idempotent_replay` helper can stay as a fast-path in-memory check WITHIN a run (so a single turn doesn't double-dispatch). The DB check is for cross-restart safety.

# Constraints

- Read tools (`search_topics`, `search_messages`, `get_author_profile`, `get_message_context`) are NOT idempotent — they're cheap to re-execute. Skip the DB check for them. Decision tools only.
- `finalize_run` IS idempotent — if the run already has an accepted finalize_run transition row, return idempotent_replay and signal the loop to terminate.
- Add a regression test in `tests/test_topic_editor_runtime.py` simulating a crashed-and-restarted run by pre-seeding a `topic_transitions` row with a known tool_call_id and verifying the second dispatch returns `idempotent_replay` instead of writing a duplicate.
