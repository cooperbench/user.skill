        # Implementation Plan: Final Canonical Folderized Architecture

## Overview
ArtAgents is mid-migration. Canonical packages exist under `artagents/executors`, `artagents/orchestrators`, and `artagents/elements`, but executors and orchestrators still depend heavily on legacy `performers` and `conductors`. The bootstrap check currently fails immediately: `python3 pipeline.py doctor` imports `artagents.executors.registry`, which expects `builtin_executors` from `artagents.executors.builtin`, but that package still exports `builtin_performers` instead.

The critique flags do not point to the wrong root cause or a different migration strategy. They identify two real omissions inside the same target architecture: `upload.youtube` is also an executor and must be folderized, and deleting top-level executor modules requires explicitly rewiring `bin/` launchers and tests to canonical executor entrypoints. The revised plan keeps the original approach but closes those gaps.

The target is a clean public model with only orchestrators, executors, and elements. Every executor, including pipeline stages, external tools, actions, and service executors, lives in a self-contained folder under `artagents/executors/<slug>/`. Every orchestrator lives similarly under `artagents/orchestrators/<slug>/`. Public compatibility aliases and curated performer/conductor folders are removed. Root `pipeline.py` and necessary `bin/` launchers remain, but they import canonical folder entrypoints.

Hard constraint: no shims. Do not create or preserve public compatibility wrappers, facade packages, alias modules, re-export-only files, or legacy command routes for `performers`, `instruments`, `conductors`, or `primitives`. If a short-lived private bridge is absolutely unavoidable while moving code, it must be private, undocumented, named as migration-only, and removed before this plan is considered complete.

Resolved decisions:
- Legacy command tokens (`performers`, `instruments`, `conductors`, `primitives`) should not receive special compatibility dispatch. They may fail as ordinary unknown/invalid commands, but should not be advertised or routed.
- `executor.yaml` and `orchestrator.yaml` should use a stdlib-friendly JSON-compatible YAML subset unless the repo already has a YAML dependency. Do not add a parser dependency just for metadata.
- Folder names should be simple filesystem slugs, while manifest IDs remain stable.
