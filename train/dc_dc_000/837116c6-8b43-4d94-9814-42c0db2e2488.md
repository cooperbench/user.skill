You're right. I know both tools well enough to reason about this. **qlty** (and tools like it — SonarQube, CodeClimate, Semgrep) are **linter aggregators**. They wrap dozens of existing static analysis tools into a unified interface and give you a dashboard. The unit of work is a **violation**: "line 42 has a complexity of 15", "this function has too many parameters." Each issue is independent. The workflow is CI — gate PRs on new violations. **desloppify** operates at a fundamentally different level: 1. **Relationships, not violations.** Orphaned files, import cycles, single-use abstractions, coupling violations, facade patterns — these aren't things any linter detects because they require understanding the *dependency graph* across the whole project. A file isn't "bad" in isolation; it's orphaned because nothing imports it. 2. **Trajectory, not snapshot.** qlty tells you "here are today's issues." Desloppify tracks state across scans — what's been fixed, what regressed, what's stagnant. The score has a direction. 3. **Agent-native, not human-native.** qlty outputs for humans to read in a dashboard. Desloppify outputs structured JSON with narrative context, prioritized actions, and tool suggestions — designed for an AI agent to consume and act on. The agent reads query.json and knows "run this command next for +3.2 pts." 4. **Refactoring tools, not just detection.** `desloppify move` rewrites imports across the codebase. The `fix` commands auto-apply changes. It's a workbench, not just a report. The short version: qlty finds **leaves** (this line is bad). Desloppify finds **forests** (your codebase has a coupling problem in this dimension, here's the most impactful structural fix, and here's the tool to do it). They're complementary, not competing. A project could use qlty for line-level lint gating in CI and desloppify for structural health tracking with an AI agent.
