        Idea:
Fix two issues with SWE-bench test verification in the megaplan pipeline:

ISSUE 1: The finalize step doesn't consistently create test verification tasks, and when it does, it doesn't include specific test commands. The FAIL_TO_PASS test IDs from the SWE-bench dataset are available in the workspace metadata (prepared.metadata['fail_to_pass']) but never reach the prompt. The planner/finalizer needs to see the exact test IDs so it creates a concrete final task like 'Run python -m pytest path/to/test.py::test_name -x and fix any failures.'

Fix: In evals/benchmarks/swe_bench.py read_prompt(), include the FAIL_TO_PASS test IDs in the prompt with a clear instruction: 'Your plan MUST include a final task that runs these specific tests to verify the fix. If they fail, iterate until they pass.'

ISSUE 2: When the executor runs 'verification' tasks, it often writes its own test files instead of running the repo's actual test suite. This happens because the task description says 'verify the fix' without specifying HOW.

Fix: The test IDs in the prompt should include the exact pytest command, so the finalizer creates a task like 'Run: python -m pytest tests/test_foo.py::test_bar -x -q. If any test fails, read the error and fix your code. Do NOT write new test files.'

Both fixes are in evals/benchmarks/swe_bench.py — specifically the read_prompt() method. The FAIL_TO_PASS data comes from the SWE-bench dataset instance and is already stored in prepared.metadata. The prompt just needs to surface it.

Key constraint: Different repos use different test runners. Django uses django's test runner, not pytest. The prompt should include the raw test IDs and let the executor figure out the right command, but explicitly say 'run the EXISTING tests, do NOT create new test files.'

        Plan:
        # Implementation Plan: Surface SWE-bench FAIL_TO_PASS Tests in Prompt

## Overview
The megaplan pipeline has no SWE-bench evaluation infrastructure yet — `evals/` doesn't exist. The core pipeline works by flowing `state['idea']` (set at init time) through `intent_and_notes_block()` into every prompt stage (plan, finalize, execute, review). The fix is straightforward: create a `read_prompt()` helper in a new `evals/benchmarks/swe_bench.py` that builds an idea string enriched with FAIL_TO_PASS test IDs and explicit instructions not to write new test files. Since `state['idea']` propagates to all stages, the finalize and execute prompts will automatically see the test verification requirements.

No changes to the core pipeline (`megaplan/prompts.py`, `megaplan/handlers.py`, etc.) are needed — the test IDs just need to be part of the idea text that enters the pipeline.

## Main Phase

### Step 1: Create the evals package structure
**Scope:** Small
1. **Create** `evals/__init__.py`, `evals/benchmarks/__init__.py` (empty init files).

### Step 2: Implement `evals/benchmarks/swe_bench.py` with `read_prompt()` (`evals/benchmarks/swe_bench.py`)
**Scope:** Medium
1. **Create** `evals/benchmarks/swe_bench.py` with a `read_prompt(prepared)` function that:
   - Extracts `prepared.metadata['fail_to_pass']` (a list of test IDs like `tests/test_foo.py::TestBar::test_baz` or Django-style `tests.test_foo.TestBar.test_baz`).
   - Extracts the problem statement from the SWE-bench instance.
   - Builds a combined prompt string that includes:
     - The original problem statement
     - A clearly delimited section listing FAIL_TO_PASS test IDs
     - An explicit instruction: "Your plan MUST include a final task that runs these specific tests to verify the fix. If they fail, iterate until they pass."
     - An explicit constraint: "Run the EXISTING repo tests listed above. Do NOT create new test files."
   - The raw test IDs are included without assuming a test runner (no hardcoded `pytest` command), since different repos use different runners (Django uses `./tests/runtests.py`, etc.).
2. **Example output** of `read_prompt()`:
   ```
   Fix the following issue in the repository:

   <problem statement from SWE-bench instance>

   ---
   VERIFICATION TESTS (must pass after your fix):
   - tests/utils/test_foo.py::TestBar::test_baz
   - tests/utils/test_foo.py::TestBar::test_qux

   Your plan MUST include a final task that runs these exact tests to verify
   the fix works. Run the EXISTING repo tests listed above — do NOT create
   new test files. If any test fails, read the error and iterate until all
   pass.
   ---
   ```
3. **Return** the assembled string so it can be passed as `args.idea` to `handle_init()`.

### Step 3: Add a lightweight test (`tests/test_swe_bench.py`)
**Scope:** Small
1. **Write** a unit test that calls `read_prompt()` with a mock `prepared` object containing sample `fail_to_pass` test IDs and a problem statement.
2. **Assert** the output string contains the test IDs, the "do NOT create new test files" instruction, and the "MUST include a final task" instruction.
3. **Test** edge case: empty `fail_to_pass` list — prompt should still work but omit the verification section (or include a note that no specific tests were provided).

### Step 4: Run tests and validate
**Scope:** Small
1. **Run** `pytest tests/test_swe_bench.py -x -q` to verify the new test passes.
2. **Run** `pytest tests/ -x -q` to verify no regressions in the existing suite.
