It's NOT a literal while loop — it's an agentic process where the loop state machine drives the agent through phases, and sub-agents do the deep work. The main thread stays high-level: reading summaries, updating the plan, dispatching workers. ## Key design requirements 1. Two phases: plan and execute, cycling. The first plan phase captures the loop spec (goal, command, success criteria, allowed changes, optimization strategy, bug-finding approach, philosophy). Subsequent plan phases UPDATE the spec based on what the last execution found. Execute runs the command, observes results, spawns sub-agents to investigate/fix, and produces structured iteration results. Then back to plan. 2. State machine grounding. The loop spec is a living document — it captures the goal, how we measure success, what strategies to use, known issues, tried-and-failed approaches, current best results. This is continuously updated as we iterate. It's the compressed context that makes iteration 50 as informed as iteration 1. 3. Sub-agents for all deep work. The main thread orchestrates. Sub-agents investigate failures, fix code, compare results. Reuse megaplan's existing worker dispatch (run_step_with_worker with Claude/Codex/Hermes routing). 4. Strong bias to continue. The default is to keep going. Only pause for genuine decision points (risky changes, genuinely stuck, goal met). 5. Git integration. Commit before each fix. If results are worse, revert.
