## Step 2: Simplify Phase Resolution

**File:** `engine/_plan/sync/pipeline.py`

Rewrite `_resolve_reconcile_phase()`:

```python
def _resolve_reconcile_phase(plan, state, *, result, policy) -> str:
    order = [item for item in plan.get("queue_order", []) if isinstance(item, str)]
    has_plan_work = any(
        item.startswith("subjective::") or item.startswith("workflow::") or item.startswith("triage::")
        for item in order
    )
    if has_plan_work:
        return LIFECYCLE_PHASE_PLAN
    return LIFECYCLE_PHASE_EXECUTE
```

This directly fixes the bug: the resolver no longer returns `assessment_postflight` when stale items are present — it returns `plan`, and once plan work is drained it returns `execute`.

**Validation:** Existing `test_reconcile_pipeline.py` tests updated to assert `"plan"` or `"execute"` instead of fine-grained phases. Write a regression test: stale subjective items in queue → phase is `plan`, complete them → phase is `execute`.

## Step 3: Gate Stale Subjective Synthesis to Plan-Mode Entry

**File:** `engine/_plan/sync/dimensions.py` (modify `sync_subjective_dimensions()`)  
**File:** `engine/_plan/sync/pipeline.py` (modify `reconcile_plan()`)

Currently `sync_subjective_dimensions()` runs unconditionally on every reconcile, re-injecting stale items. Change:

1. In `reconcile_plan()`, pass the current lifecycle phase to `sync_subjective_dimensions()`
2. In `sync_subjective_dimensions()`, skip stale injection/promotion when the current phase is `execute` AND we're mid-cycle:
   - Unscored items: still inject at cycle boundaries (unchanged)
   - Stale items: **only inject when entering plan mode** (phase is `plan` OR not mid-cycle)
   - Under-target items: follow existing deferral logic (unchanged)

The trigger for plan-mode entry:
- First scan (no plan exists yet)
- Queue empties → postflight scan → reconcile (not mid-cycle)
- Explicit user action (`plan` command triggers reconcile with `force_rescan=True`)
