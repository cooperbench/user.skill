# Lifecycle State Machine Enforcement (v3)

## Problem Summary

Five deviation vectors let code change lifecycle mode or advance the pipeline outside the canonical `reconcile_plan()` path:

| # | Vector | Location | Mechanism |
|---|--------|----------|-----------|
| 1 | **resolve_workflow side-channel** | `resolve_workflow.py:364-390` | Directly calls `inject_triage_stages()` + `set_lifecycle_phase(plan, "plan")` when WORKFLOW_CREATE_PLAN_ID resolved with open reviews — bypasses reconcile entirely |
| 2 | **clear_postflight_scan_completion** | `refresh_lifecycle.py:210-224`, 5 call sites | Directly writes `refresh_state["lifecycle_phase"] = "execute"` AND clears scan marker — bypasses even `set_lifecycle_phase()` |
| 3 | **Dual phase derivation** | `snapshot.py:263-346` vs `pipeline.py:97-149` | Two independent functions derive display phase from queue contents with different logic and priority ordering |
| 4 | **synthetic.py phase read** | `synthetic.py:240-261` | Reads persisted mode to suppress stale refreshes — read-only, correct pattern |
| 5 | **Unguarded set_lifecycle_phase** | `refresh_lifecycle.py:141-149` | Public function, any caller can set mode to any valid value |

## Design Principles

1. **Single writer**: Only `reconcile_plan()` in pipeline.py may call `_set_lifecycle_phase()`. Enforcement: `_` prefix + removal from `__all__` + elimination of all other callers. Sufficient for an internal tool.
2. **Reconcile is state-driven**: `reconcile_plan()` derives all behavior from `plan` + `state` dicts. No function parameters carry command-context side-channels. When a caller needs to influence reconcile, it writes a marker to plan state BEFORE calling reconcile.
3. **Two derivation paths, one invariant**: Pipeline derives display phase from `queue_order` prefixes. Snapshot derives from materialized item partitions. They produce equivalent results because sync preconditions ensure the same items exist in both representations. This equivalence is enforced by test, not by forcing them through the same function.
4. **One-shot data migration is exempt**: `current_lifecycle_phase()` persists a migrated value on first read of legacy state. This is a one-shot data fixup, not a control flow side-channel.

### Step 2: Eliminate the resolve_workflow side-channel via plan-state marker

**Problem**: resolve_workflow.py:364-390 directly calls `inject_triage_stages()` + `set_lifecycle_phase(plan, "plan")` outside reconcile when WORKFLOW_CREATE_PLAN_ID is resolved with open reviews.

**v2 approach (rejected)**: Added `workflow_plan_resolved` parameter to `reconcile_plan()`. This is still a side-channel — identical plan state reconciles differently depending on which caller invoked it.

**v3 fix**: Make reconcile purely state-driven. The caller writes a marker to plan state; `sync_triage_needed()` reads it from the plan dict.

1. **Move `ensure_active_triage_issue_ids()`** from `app/commands/plan/triage/review_coverage.py` to `engine/_plan/triage/` (pure plan/state manipulation — belongs in engine, not app).

2. **resolve_workflow.py** — before calling reconcile, write a marker:
   ```python
   # Before: manual inject + set_lifecycle_phase (lines 364-390)
   # After: write marker, then call reconcile
   if WORKFLOW_CREATE_PLAN_ID in synthetic_ids and has_open_review_issues(state_data):
       plan.setdefault("refresh_state", {})["workflow_plan_just_resolved"] = True
   result = reconcile_plan(
       plan, state_data,
       target_strict=target_strict_score_from_config(state_data.get("config")),
   )
   ```
   Delete the entire special-case branch (inject_triage_stages, set_lifecycle_phase, separate save_plan).

3. **`sync_triage_needed()` in triage.py** — read and consume the marker:
   ```python
   # At the top of sync_triage_needed(), before existing logic:
   marker = meta.get("workflow_plan_just_resolved") or
            plan.get("refresh_state", {}).get("workflow_plan_just_resolved")
   if marker:
       # Clear marker so it doesn't fire on subsequent reconcile calls
       plan.get("refresh_state", {}).pop("workflow_plan_just_resolved", None)
       if has_open_review_issues(state):
           ensure_active_triage_issue_ids(plan, state)
           inject_triage_stages(plan)
           return QueueSyncResult(injected=True)
   # ... existing hash-change detection follows
   ```

4. **No new parameters** on `reconcile_plan()` or `sync_triage_needed()`. Both remain purely state-driven.

```python
# Before (all sites):

# After (all sites):

```

Preserves the early-return: if `invalidate_postflight_scan` returns False, no reconcile runs.

### Step 4: Add equivalence test for pipeline vs snapshot derivation

**Problem**: pipeline.py and snapshot.py have separate display-phase derivation functions. v2 tried to force them through the same function via an adapter, but the snapshot's item-partition logic is richer than what pipeline can reconstruct from queue_order prefixes (active-cluster handling, triage-current gating, etc.).

**v3 fix**: Accept that they're separate implementations of the same rule. Enforce equivalence with a test, not structural unification.

1. **Keep both functions as-is**: `_resolve_reconcile_display_phase()` in pipeline.py and `_derive_display_phase()` in snapshot.py.

This catches drift if either function is modified.
3. **Document the invariant** with a comment at the top of each function: "This function must produce the same display phase as [the other]. See test_phase_derivation_equivalence."
