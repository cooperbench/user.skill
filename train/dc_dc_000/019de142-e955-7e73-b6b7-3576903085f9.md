        # Implementation Plan: ArtAgents Thumbnail Maker Conductor

## Overview
Add a built-in `builtin.thumbnail_maker` conductor for generating reviewable YouTube-style thumbnail candidates from a user query and source video. The repo already has the right primitives: conductors live under `artagents/conductors/curated/*`, built-ins are registered in `artagents/conductors/registry.py`, video evidence can be produced by `scenes.py`, `shots.py`, `visual_understand.py`, and `video_understand.py`, and base image generation is handled by `artagents/generate_image.py`.

The simplest implementation should be a new Python conductor runtime plus a focused `artagents/thumbnail_maker.py` CLI/module. It should orchestrate existing tools, write explicit manifests, and avoid changing Reigh timeline/assets contracts.

## Phase 1: Core Thumbnail CLI and Data Contract

### Step 1: Define thumbnail run layout (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Add a new module with an argparse CLI accepting `--video`, `--query`, `--out`, `--count`, `--size`, `--quality`, `--env-file`, `--dry-run`, `--force`, and optional `--feedback` / `--previous-manifest` for refinement rounds.
2. Standardize output paths under the run directory:
   - `source-analysis/scenes.json`
   - `source-analysis/shots/shots.json`
   - `evidence/evidence-plan.json`
   - `evidence/reference-pack.json`
   - `prompts/prompts.json`
   - `generated/manifest.json`
   - `review/contact-sheet.jpg`
   - `thumbnail-manifest.json`
3. Keep generated files under `runs/` by default and store all absolute or repo-relative source refs in JSON for reviewability.

### Step 2: Plan source-search needs from the query (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Implement a deterministic first-pass planner that maps query terms and flags to evidence needs, without requiring an LLM for the basic path.
2. Support explicit user hints such as speaker/person, scene/object, emotion, text overlay, visual style, and thumbnail count.
3. Write `evidence-plan.json` with planned searches, chosen commands, and why each evidence type is needed.
4. If the query is too underspecified, continue with broad visual sampling rather than failing.

### Step 3: Build source evidence and reference packs (`artagents/thumbnail_maker.py`, existing `artagents/scenes.py`, `artagents/shots.py`, `artagents/visual_understand.py`)
**Scope:** Large
1. Reuse `scenes.detect_scenes` and `shots.build_shots` directly where practical, or shell through their CLIs only when dry-run planning needs command parity.
2. Use representative shot frames as default evidence.
3. Add helper functions to select a bounded set of candidate frames from `shots.json`, cap to the current `visual_understand.py` limit of 20, and build a contact sheet.
4. For speaker/face/person queries, create crop candidates from selected frames using the existing crop/contact-sheet logic in `visual_understand.py` where possible.
5. Write `reference-pack.json` listing every source frame/crop with timestamp, scene index, file path, selection reason, and whether it was used for prompt enrichment.

## Phase 2: Generation and Refinement

### Step 4: Generate base thumbnail prompts (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Generate one prompt object per requested thumbnail candidate and write `prompts/prompts.json` in the existing `generate_image.py` prompt-list format.
2. Include user query, selected source evidence summaries, aspect/size, and thumbnail-specific composition instructions.
3. Keep prompts self-contained so `generate_image.py --prompts-file` can reproduce the batch.

### Step 5: Call existing image generation (`artagents/thumbnail_maker.py`, `artagents/generate_image.py`)
**Scope:** Medium
1. Invoke `generate_image.generate()` programmatically or call the CLI with `--prompts-file`, `--n 1`, `--out-dir generated`, and `--manifest generated/manifest.json`.
2. Preserve support for multiple thumbnails through `--count` by writing multiple prompt jobs, not by hiding variants in one opaque call.
3. In `--dry-run`, emit the planned commands and JSON payloads without requiring API keys or network.

### Step 6: Add optional feedback/refinement round (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Accept `--previous-manifest` plus `--feedback` to start from prior outputs.
2. Read previous prompts, generated paths, and reference-pack evidence.
3. Generate a new prompt set that explicitly incorporates feedback while preserving links to prior candidate IDs.
4. Write `refinement.json` describing the feedback, previous candidates used, new prompt deltas, and new output paths.
5. Treat source-reference refinement as prompt/evidence-guided regeneration for the MVP. Do not add a new image-edit API path unless the existing `generate_image.py` API is intentionally expanded later.

## Phase 3: Conductor Integration

### Step 7: Add built-in conductor metadata (`artagents/conductors/curated/thumbnail_maker/conductor.py`, `runtime.py`)
**Scope:** Medium
1. Create a new curated built-in conductor with id `builtin.thumbnail_maker` and Python runtime `artagents.conductors.curated.thumbnail_maker.runtime.run`.
2. Declare inputs for `video`, `query`, optional `env_file`, optional `previous_manifest`, and optional `feedback`.
3. Declare outputs for `manifest`, `contact_sheet`, `reference_pack`, and generated image directory.
4. Use `child_performers` conservatively. Since `generate_image`, `visual_understand`, and `video_understand` are not currently registered built-in performers, either leave them as conductor-owned tools in metadata or add performer definitions in a separate small step only if registry validation requires first-class child performers.

### Step 8: Register and expose the conductor (`artagents/conductors/registry.py`, optional root `thumbnail_maker.py`)
**Scope:** Small
1. Import the new built-in conductor in `load_builtin_conductors()` and attach metadata with `legacy_entrypoint="thumbnail_maker.py"`.
2. Add a root compatibility launcher `thumbnail_maker.py` only if the project wants parity with existing root launchers such as `generate_image.py` and `visual_understand.py`.
3. Verify `python3 pipeline.py conductors list` includes `builtin.thumbnail_maker`.

## Phase 4: Review Outputs

### Step 9: Build reviewable manifest and contact sheet (`artagents/thumbnail_maker.py`)
**Scope:** Medium
1. Use PIL to build a final contact sheet from generated thumbnails, with candidate labels matching manifest IDs.
2. Write `thumbnail-manifest.json` containing query, video path, run options, evidence refs, prompt refs, generated outputs, review contact sheet, and refinement lineage when present.
3. Make the manifest stable enough for tests: deterministic IDs, sorted paths where possible, and explicit timestamps.

## Phase 5: Tests and Validation

### Step 10: Add focused tests (`tests/test_thumbnail_maker.py`)
**Scope:** Medium
1. Unit test query planning without media files.
2. Unit test prompt-list creation for `--count 3`.
3. Unit test dry-run output without API keys.
4. Unit test refinement manifest generation from a fake previous manifest and feedback.
5. Unit test contact-sheet generation using temporary PIL images.

### Step 11: Add conductor registry and CLI tests (`tests/test_conductors_registry.py`, `tests/test_conductors_cli.py`, new `tests/test_thumbnail_maker_conductor.py`)
**Scope:** Small
1. Update expected built-in conductor list to include `builtin.thumbnail_maker`.
2. Test `inspect builtin.thumbnail_maker --json` exposes expected inputs and outputs.
3. Test dry-run conductor execution returns planned commands and does not call OpenAI APIs, ffmpeg, or scene extraction.

### Step 12: Run validation
**Scope:** Small
1. Start with `python3 -m pytest tests/test_thumbnail_maker.py tests/test_thumbnail_maker_conductor.py`.
2. Then run `python3 -m pytest tests/test_conductors_registry.py tests/test_conductors_cli.py tests/test_generate_image.py tests/test_visual_understand.py`.
3. Finish with `python3 -m pytest` if the targeted suite passes.

### Step 6: Build reference packs without overstating crop support (`artagents/thumbnail_maker.py`, `artagents/visual_understand.py`)
**Scope:** Medium
