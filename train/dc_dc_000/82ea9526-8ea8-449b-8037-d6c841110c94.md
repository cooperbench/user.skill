        # Implementation Plan: MediaLightbox Edit Panel Cleanup (4 phases)

## Overview
The user cannot reliably type into the edit-panel textarea, and the model `Select` snaps shut when opened. Root cause (confirmed by brief): `LoraSelectorModal` and `PhaseConfigSelectorModal` early-return `null` while still mounted with `open={true}`, so Base UI Dialog skips its cleanup (body `pointer-events:none`, focus scope) and strands the page. A silent contributor is `useImageEditFormSafe` returning `EMPTY_FORM` with no-op setters when a provider is missing — typing disappears. Phase 1 ships those fixes alone so the user can confirm the bug is gone before Phases 2–4.

Critique incorporated:
- **FLAG-001:** Phase 3 was overclaiming. Other text inputs (Img2Img prompt, custom LoRA URL) still route per-keystroke through the same debounced autosave, and `hasPendingFor()` is ALSO the loader-side guard that prevents async loads from overwriting local edits. The plan now (a) extends the on-blur/on-generate/on-close save pattern to every free-text input, not just the main prompt, and (b) explicitly preserves the load-race branches of `hasPendingFor` / pending-ref tracking. Only the per-save edit-version comparator (the "newer edits during save" guard at `useDebouncedSettingsSave.ts:166-171`) is safe to remove once all free-text fields stop debouncing.
- **FLAG-002:** Phase 2 step 7 was incomplete. `EditModePanel` consumes three contexts — `useImageEditFormSafe`, `useLightboxCoreSafe`, `useLightboxVariantsSafe` — and `InlineEditView` currently supplies `coreState.onClose` and `imageEditState` via `stateOverrides` because it sits outside `LightboxStateProvider`. Simply deleting `stateOverrides` would regress the inline-edit close handler and variants controls to safe no-op defaults. Plan now: wrap `InlineEditView` in all three providers (or a minimal `LightboxStateProvider` shim supplying just the fields it needs) and only then delete `stateOverrides`. If that provider surface is larger than the override payload, keep `stateOverrides` and instead formalize it as the one source (pure-props) — decision made during step 7 after reading the provider shapes.
