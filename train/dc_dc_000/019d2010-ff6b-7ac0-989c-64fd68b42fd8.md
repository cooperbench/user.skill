Fix timeline interaction bugs and add inline text editing.

THREE ISSUES:

1. CLIPS JUMP BACK THEN FORWARD: When moving clips on the timeline, they visually snap back to their original position for a moment before jumping to the new position. This happens both in the timeline UI and the video preview. The likely cause is a state update race: the library's onChange fires with the new position, but then the React Query refetch or the polling mechanism overwrites it with the old saved state before the save completes. The fix needs to ensure optimistic updates persist without being overwritten by stale server state.

2. TEXT CLIPS JUMP BACK AFTER MOVE: Same as above but worse for text clips - they consistently jump back to their original position. The text clip handling in the move/resize handlers may not be correctly updating the clip data.

3. INLINE TEXT EDITING: Currently text content is only editable in the ClipPanel sidebar. Users should be able to double-click a text clip on the preview canvas to edit it inline. Need: (a) double-click on a text clip overlay opens an inline text editor, (b) the editor is a contenteditable div or textarea positioned exactly over the text clip, (c) edits update the clip's text.content in real-time, (d) clicking away or pressing Escape closes the inline editor, (e) the ClipPanel text field stays in sync.

ROOT CAUSE ANALYSIS NEEDED:
- Check how onChange in the timeline library interacts with React Query refetch
- Check if the save debounce + refetch creates a write-then-read race
- Check if the signature comparison in the polling is working correctly
- Check if applyTimelineEdit and the React Query mutation are coordinated properly

The fix should ensure:
- Optimistic updates are never overwritten by stale fetched data
- The save mutation marks the query as stale only AFTER the save completes
- The polling/refetch skips updates when there are pending local changes
