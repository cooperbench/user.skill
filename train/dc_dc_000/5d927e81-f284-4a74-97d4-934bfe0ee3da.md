        # Implementation Plan: Inline media (images, videos, links, carousels) in Recommendations body_markdown

## Overview

**Goal:** Let `body_markdown` for a recommendation include:
- A single image (optionally wrapped in a link).
- A single video.
- A carousel mixing images and videos with prev/next navigation.

Each element supports a width (`full | half | third`) and a layout (`block` on its own line, or `wrap-left`/`wrap-right` floated with text wrapping around it).

**Approach (per brief):** Custom block-directive syntax `:::media{...}` and `:::carousel{...}` is preprocessed in `Recommendations.tsx` *before* marked runs. `:::media` blocks compile to raw HTML; `:::carousel` blocks are replaced with a placeholder that, after marked + sanitization, gets split out and rendered as a React component (so prev/next can be interactive). One new Supabase migration seeds a single example recommendation that exercises all three element types.

**Repo shape that matters:**
- `src/pages/Recommendations.tsx` — `renderBody()` currently does `sanitizeHtml(marked.parse(...))` and is wired via `dangerouslySetInnerHTML` (single blob). Will change to a segmented renderer.
- `src/styles/global.css` — `.recommendation-image` lives at line 2918; new layout classes go adjacent.
- `supabase/migrations/` — pattern is `YYYYMMDDNNNNNN_*.sql`. Last existing is `20260330000006_add_recommendation_status.sql`. Next file: `20260330000007_seed_media_demo_recommendation.sql`.
- `src/types/index.ts` and `src/lib/recommendations.ts` — no schema column added; no changes needed.
- Page is rendered both SSR (`entry-server.tsx`) and hydrated client-side (`useState` already present in `RecommendationsPage`), so a client carousel component is fine.
- Tests exist for `Header`, `Home`, `Posts`, `Post`, `App`, but no `Recommendations.test.tsx` currently — adding focused unit tests for the directive preprocessor is the cheapest validation.

**Constraints:**
- Body is rendered through a regex-based sanitizer; new HTML produced by our preprocessor (`<video>`, `<source>`, anchor-wrapped `<img>`, target=_blank links, class/data attrs) must survive it. We control the emitted HTML, so the sanitizer must let `<video>`/`<source>` and the new `class="..."` / `data-*` attrs through but still strip `<script>` and `on*` handlers.
- Recommendation thumb above body (`rec.image_url`) is unchanged.
- Existing recommendations have no directives — must continue rendering identically.

### Step 2: Define directive syntax and parser (`src/pages/Recommendations.tsx`)
**Scope:** Medium
1. **Specify** the on-disk syntax that authors will write inside `body_markdown`:
   - `:::media{type=image src="..." width=half wrap=right alt="..." link="..."}` ... `:::`
   - `:::media{type=video src="..." width=full wrap=block poster="..." autoplay=true loop=true muted=true}` ... `:::`
   - `:::carousel{width=half wrap=left}` body is a list of `- type=image src="..."` / `- type=video src="..."` lines, then `:::`.
   - `width` ∈ `full | half | third` (default `full`).
   - `wrap` ∈ `block | left | right` (default `block`; `left`/`right` apply CSS float).
2. **Implement** a small attribute parser (regex over `(\w+)=(?:"([^"]*)"|(\S+))`) and a block parser that walks line-by-line, detecting `:::media{...}` / `:::carousel{...}` open lines and `:::` close lines. ~80 LOC, no dependency.
3. **Capture** the contract for tests:
   - `MediaItem = { kind, src, alt?, link?, poster?, autoplay?, loop?, muted? }`.
   - `Block = MediaBlock | CarouselBlock` with `width` and `wrap`.
4. **Reject** unknown `type` or missing `src` with a console warning; skip the block. Do not crash the render.

### Step 3: Preprocess directives and rebuild the render pipeline (`src/pages/Recommendations.tsx`)
**Scope:** Medium
1. **Replace** single-string `renderBody(markdown): string` with `renderBody(markdown): Array<{type:'html', html:string} | {type:'carousel', data:CarouselBlock}>`.
2. **Pipeline:** extract directives in source order. For each `:::media`, compile to a raw HTML snippet (`<img>`, `<a target="_blank" rel="noopener noreferrer"><img></a>`, or `<video>` with the right `class="media media-{width} media-wrap-{wrap}"`) and substitute inline. For each `:::carousel`, replace with the placeholder format chosen in Step 1 and stash the parsed `CarouselBlock` in an indexed array. Run `marked.parse(...)` on the rewritten markdown. Run the (extended) sanitizer. Split the resulting HTML on the placeholder pattern and interleave HTML segments with `{type:'carousel', data}` entries.
3. **Render** in `RecommendationCard` at `src/pages/Recommendations.tsx:128`: replace the single `<div dangerouslySetInnerHTML />` with a map over the segments — HTML segments via `<span dangerouslySetInnerHTML />`, carousel segments via `<Carousel items=... width=... wrap=... />`.
4. **Note:** marked may wrap the placeholder in a `<p>` tag. Make the splitter tolerant to that (split on the placeholder regardless of surrounding `<p>` / `</p>`), and let the carousel emit a top-level wrapper that's valid even if it ends up adjacent to a stray empty paragraph.
