        # Implementation Plan: Shot Bounding Boxes on Timeline

## Overview
Add colored bounding boxes around groups of adjacent clips on the same track that belong to the same shot and appear in shot-image order. This is a purely visual overlay — no interaction changes.

**Current state:** Clips are absolutely positioned in `TimelineCanvas.tsx` within `SortableRow` components. Clips reference generation IDs indirectly via `meta[clipId].asset` → `registry.assets[assetKey].generationId`. Shots are available via `useShots()` and contain `images[]` arrays with `generation_id` fields. The marquee selection overlay (`z-30`, `pointer-events-none absolute`) is the closest existing pattern.

**Key constraint:** The bounding box must use `pointer-events-none` so it doesn't interfere with clip selection, dragging, resizing, or context menus. It sits in the same coordinate space as clips (absolutely positioned within the grid background div).

## Phase 1: Core Logic — Shot Group Detection Hook

### Step 1: Create `useShotBoundingBoxes` hook (`src/tools/video-editor/hooks/useShotBoundingBoxes.ts`)
**Scope:** Medium

1. **Create** a new hook that takes `rows`, `meta`, `registry`, `shots`, `startLeft`, `pixelsPerSecond`, `rowHeight`, and `resizeOverrides` as inputs.
2. **Implement** the core algorithm (memoized with `useMemo`):
   - For each clip across all rows, build a map: `clipId → generationId` (via `meta[clipId].asset` → `registry.assets[assetKey].generationId`).
   - For each shot, build a map: `generationId → imageIndex` (position in `shot.images` array).
   - For each row (track), iterate through actions sorted by `start` time:
     - Find maximal contiguous runs where: (a) every clip maps to the same shot, (b) clips are adjacent (previous clip's `end` equals next clip's `start`, within a small epsilon like 0.001s), and (c) the image indices are strictly increasing (same order as shot images).
     - A qualifying group must have **2+ clips**.
   - For each qualifying group, compute a `ShotBoundingBox`:
     ```typescript
     interface ShotBoundingBox {
       shotId: string;
       left: number;    // startLeft + firstClip.start * pixelsPerSecond
       top: number;     // rowIndex * rowHeight
       width: number;   // (lastClip.end - firstClip.start) * pixelsPerSecond
       height: number;  // rowHeight
       color: string;   // deterministic from shotId
     }
     ```
3. **Implement** deterministic color assignment: hash the shot ID to pick from a palette of ~8 distinct colors (purple, red, green, teal, orange, pink, yellow, blue). Use a simple string hash modulo palette length.
4. **Account for resize overrides**: apply `resizeOverrides` to clip start/end before computing box positions (same as `TimelineCanvas` does at line 172).
5. **Return** `ShotBoundingBox[]`.

**Adjacency check detail:** Two clips are adjacent if `Math.abs(prevAction.end - nextAction.start) < 0.001`. This handles floating-point imprecision without false positives.

## Phase 2: Rendering

### Step 2: Pass shot bounding box data into TimelineCanvas (`TimelineCanvas.tsx`, `TimelineEditor.tsx`)
**Scope:** Small

1. **Call** `useShotBoundingBoxes` in `TimelineEditor.tsx` (near line 87 where `useShots()` is already called), passing the required data from `timelineData` and layout params.
2. **Pass** the resulting `ShotBoundingBox[]` as a new prop `shotBoundingBoxes` to `TimelineCanvas`.
3. **Add** `shotBoundingBoxes` to `TimelineCanvasProps` interface (line ~82).

### Step 3: Render bounding box overlays in TimelineCanvas (`TimelineCanvas.tsx:504-522`)
**Scope:** Small

1. **Render** bounding boxes as `pointer-events-none absolute` divs inside the grid background div (same container as the marquee overlay, around line 511).
2. **Style** each box with:
   - `pointer-events-none` — critical for non-interference
   - `absolute` positioning using the pre-computed `left`, `top`, `width`, `height`
   - `z-index: 1` — **below** clips (z-7) so the box appears as a background highlight behind the clips, not on top of them
   - Border: `2px solid` with the shot's color at ~60% opacity
   - Background: shot color at ~8% opacity (subtle fill)
   - `rounded-md` for visual polish
   - Small padding offset: expand the box by ~2px in each direction beyond the clip edges so the border doesn't overlap with clip borders
3. **Example JSX:**
   ```tsx
   {shotBoundingBoxes.map((box) => (
     <div
       key={`shot-box-${box.shotId}-${box.left}`}
       className="pointer-events-none absolute rounded-md"
       style={{
         left: box.left - 2,
         top: box.top,
         width: box.width + 4,
         height: box.height,
         border: `2px solid ${box.color}`,
         backgroundColor: `${box.color}10`,
         zIndex: 1,
       }}
     />
   ))}
   ```

## Phase 3: Tests

### Step 4: Unit test the hook (`src/tools/video-editor/hooks/useShotBoundingBoxes.test.ts`)
**Scope:** Medium

1. **Test** basic case: 3 clips on same track, all in same shot, in order → produces 1 bounding box.
2. **Test** non-adjacent clips: gap between clips → no bounding box (or two separate groups).
3. **Test** wrong order: clips in different order than shot images → no bounding box.
4. **Test** mixed shots: clips from different shots on same track → separate bounding boxes for each qualifying group.
5. **Test** single clip: one clip from a shot → no bounding box (minimum 2 required).
6. **Test** cross-track: same shot's clips on different tracks → no bounding box (same-track constraint).
7. **Test** deterministic colors: same shot ID always produces same color.
8. **Test** resize overrides: verify box positions respect overrides.

## Execution Order
1. Step 1 first (hook with algorithm — can be tested independently).
2. Step 4 in parallel with Step 2+3 (tests can be written against the hook directly).
3. Steps 2 and 3 together (wiring and rendering).

## Validation Order
1. Run Step 4 unit tests first.
2. Visual verification in the app with a timeline containing shot-grouped clips.
