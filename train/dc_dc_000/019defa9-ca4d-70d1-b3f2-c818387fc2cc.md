## Overview
Add a persistent project layer without changing executor/orchestrator bodies or the shared `@banodoco/timeline-schema`. The repo already has clean choke points: `artagents/pipeline.py` dispatches top-level CLI commands, `artagents/core/orchestrator/cli.py` parses canonical orchestrator runs, `artagents/core/orchestrator/runner.py` executes them, and `artagents/timeline.py` owns validation/loading/saving for existing `hype.timeline.json` and `hype.assets.json`.

The simplest durable approach is to add a new `artagents/core/project/` module for project state and materialization, then wire it only at CLI and runner boundaries. Existing `--out` behavior remains ad hoc and existing executor outputs stay unchanged.

        # Implementation Plan: Project + ProjectTimeline

## Overview
Add a persistent project layer so ArtAgents can organize runs and compose a canonical project timeline from source assets and prior run clips. The core approach is still correct: add `artagents/core/project/` for project state, keep ProjectTimeline as an ArtAgents-only format, and materialize to the existing `TimelineConfig` + `AssetRegistry` consumed by render/validate.

The critique does not show that the plan targeted the wrong root cause, but it does show the original run-integration step was too shallow. `builtin.hype` is a command-runtime orchestrator whose manifest forwards only `{orchestrator_args}`, so merely setting `OrchestratorRunRequest.out` will not reach `hype.run`. The revised approach introduces a shared project-run preparation/finalization layer used by both orchestrator and executor runners, resolves project output paths before validation and dry-run command construction, injects `--out <project-run-dir>` where `builtin.hype` requires passthrough arguments, and records project run metadata on success, nonzero exits, and exceptions.

Use the plural top-level CLI command `projects`. Top-level dispatch belongs in `artagents/pipeline.py`; `setup_cli.py` should only gain setup planning for the projects root if needed.

## Phase 1: Project Skeleton + CLI

### Step 1: Add project paths and JSON helpers (`artagents/core/project/paths.py`, `artagents/core/project/jsonio.py`)
**Scope:** Medium
1. Implement `projects_root()` using `ARTAGENTS_PROJECTS_ROOT` or `~/Documents/reigh-workspace/artagents-projects/`.
2. Implement slug validation for project slugs and source ids using a conservative lowercase slug pattern.
3. Implement `project_dir(slug)`, `source_dir(project, source_id)`, and `run_dir(project, run_id)` helpers.
4. Add deterministic JSON read/write helpers with sorted keys, stable indentation, parent directory creation, and temp-file replace.

### Step 2: Define project schemas (`artagents/core/project/schema.py`)
**Scope:** Medium
1. Define validators/builders for `project.json`, `timeline.json`, `source.json`, and project `run.json`.
2. Make `source.json` strict enough to materialize valid registry entries:
   - `id`
   - `kind`: `video`, `audio`, `image`, or `other`
   - `asset`: object containing exactly one of `file` or `url`, plus optional `type`, `duration`, `resolution`, `fps`, `content_sha256`, `etag`, `url_expires_at`
   - optional `metadata`
3. Define ProjectTimeline placements with `id`, `track`, `at`, `from`, `to`, `source`, `entrance`, `exit`, `transition`, `effects`, and `params`.
4. Validate `source.kind` as either:
   - `{ "kind": "source", "source_id": "..." }`
   - `{ "kind": "run", "run_id": "...", "clip_id": "..." }`
5. Validate placement timing with `at >= 0`, `from >= 0` when present, and `to > from` when `to` is present.

### Step 3: Add project persistence APIs (`artagents/core/project/project.py`, `source.py`, `timeline.py`, `run.py`)
**Scope:** Medium
1. Implement `create_project()`, `load_project()`, `require_project()`, and `show_project_tree()`.
2. Ensure project creation writes the fixed layout:
   - `project.json`
   - `timeline.json`
   - `sources/`
   - `runs/`
3. Implement `add_source()` that writes `sources/<source_id>/source.json` and creates `analysis/`.
4. Implement placement add/remove helpers that validate referenced sources/runs before saving.
5. Make missing-resource errors name the next command, for example `python3 -m artagents projects create <slug>` or `python3 -m artagents projects source add --project <slug> --path PATH`.

### Step 4: Add project CLI and setup/doctor surface (`artagents/core/project/cli.py`, `artagents/pipeline.py`, `artagents/setup_cli.py`, `artagents/doctor.py`)
**Scope:** Medium
1. Add top-level `projects` dispatch in `artagents/pipeline.py` and update `_print_entrypoint_help()`.
2. Add `setup_cli.py` planning for the project root only: dry-run reports the root; `setup --apply` may create it if the project setup step is included.
3. Add doctor checks that project support imports and the configured root can be resolved without mutating the filesystem.
4. Implement CLI commands:
   - `projects create <slug> [--title TITLE]`
   - `projects show --project <slug> [--json]`
   - `projects source add --project <slug> --path PATH [--id SOURCE_ID] [--kind video|audio|image|other] [--type TYPE] [--duration SECONDS]`
   - `projects timeline show --project <slug> [--json]`
5. Print a project header for every project command.
6. Require `--project` for state-changing project commands except `projects create`, where the positional slug is the project identity.

## Phase 2: ProjectTimeline + Source-Only Materialization

### Step 5: Implement materialization API (`artagents/core/project/materialize.py`, `artagents/timeline.py`)
**Scope:** Medium
1. Implement `materialize_project_timeline(project_dir) -> tuple[TimelineConfig, AssetRegistry]` in project code and re-export or wrap it from `artagents/timeline.py` for the requested touchpoint.
2. For `kind: source` placements, generate media clips that reference stable asset keys like `source:<source_id>`.
3. Build registry entries directly from `source.json.asset`, preserving `file` or `url` so `validate_registry()` passes.
4. Resolve relative source file paths relative to the source file’s project directory or store absolute paths consistently at add time.
5. Copy placement fields into materialized clips: `id`, `track`, `at`, `from`, `to`, `entrance`, `exit`, `transition`, `effects`, and `params`.
6. Validate the materialized timeline with `validate_timeline()` and the registry with `validate_registry()` before returning or writing.

### Step 6: Add source placement editing and materialize CLI (`artagents/core/project/cli.py`)
**Scope:** Medium
1. Add `projects timeline place-source --project <slug> --source <source_id> --track v1 --at 0 --from 0 --to 5 [--id ID]`.
2. Add `projects timeline remove --project <slug> <placement_id>`.
3. Add `projects materialize --project <slug> --out <dir>` writing `hype.timeline.json` and `hype.assets.json` for render compatibility.
4. Add `--json` output for placement commands so tests do not scrape prose.
5. Keep materialized files separate from project-native `timeline.json`.

## Phase 3: Project Run Integration

### Step 7: Add shared project-run lifecycle (`artagents/core/project/run.py`)
**Scope:** Medium
1. Implement `prepare_project_run(project_slug, kind, tool_id, explicit_out=None)` that mints a ULID run id, resolves `<project>/runs/<run_id>`, and returns an effective output directory.
2. If `--project` and explicit `--out` are both supplied, require the explicit output to be the prepared project run directory or reject the combination; project runs should not write project metadata for arbitrary ad-hoc output paths.
3. Write an initial project `run.json` before executing with status `running` and fields for `schema_version`, `project_slug`, `run_id`, `kind`, `executor_id` or `orchestrator_id`, `out_path`, `started_at`, redacted CLI args, and inputs.
4. Finalize project `run.json` in both result and exception paths with `succeeded`, `failed`, or `error`, plus `returncode`, `ended_at`, and error details.
5. After successful or failed completion, mirror existing runtime artifacts into project canonical names when present:
   - `hype.timeline.json` -> `timeline.json`
   - `hype.assets.json` -> `assets.json`
   - `hype.metadata.json` -> `metadata.json`
6. Define run-record ownership: for project runs, `<project>/runs/<run_id>/run.json` is the project run record. Update thread wrapping to skip writing its own `run.json` for requests carrying a project slug or project run id, preventing collisions when `ARTAGENTS_PROJECTS_ROOT` is under the repo.

### Step 8: Wire orchestrator `--project` into command building and execution (`artagents/core/orchestrator/cli.py`, `artagents/core/orchestrator/runner.py`)
**Scope:** Medium
1. Add `project: str | None` and internal `project_run_id: str | None` fields to `OrchestratorRunRequest`.
2. Add `--project` to `python3 -m artagents orchestrators run`.
3. Resolve the effective project run output before `_validate_out_requirement()`, `_request_values()`, `_expand_command_runtime()`, and `build_orchestrator_command()`.
4. Ensure dry-run planning and real execution use the same effective request.
5. For command runtimes that use `{out}` placeholders, the resolved project output should flow through existing placeholder expansion.
6. For `builtin.hype`, whose manifest forwards only `{orchestrator_args}`, append `--out <project-run-dir>` to `orchestrator_args` when `--project` is set and neither `--out` nor `--project` was already provided in the passthrough args.
7. Reject unsupported project command runtimes that neither use `{out}` nor have an explicit adapter, rather than silently creating an unused project run directory.
8. Wrap `_run_orchestrator_inner()` with project-run finalization in the same try/except shape as thread finalization so validation errors and runtime exceptions update project `run.json`.

### Step 9: Wire executor `--project` into executor runs (`artagents/core/executor/cli.py`, `artagents/core/executor/runner.py`)
**Scope:** Medium
1. Add `project: str | None` and internal `project_run_id: str | None` fields to `ExecutorRunRequest`.

4. For built-in pipeline-step executors and external executors, the resolved output should flow through the existing `out` placeholder and `build_pipeline_context()`.
5. Keep executor bodies unchanged.
6. Preserve legacy ad-hoc `--out` executor runs without requiring a project.
7. Add project-run finalization for executor success, nonzero exit, skip, and exception paths.

### Step 10: Add direct hype `--project` support (`artagents/orchestrators/hype/run.py`)
**Scope:** Medium
1. Add `--project` to `build_parser()`.
2. In `resolve_args()`, translate `--project` into `merged["out"] = <project>/runs/<run_id>` before the existing missing-`--out` check.
3. Create/write the initial project run record before `pool_main()` begins, and finalize it around `pool_main()` result and `SystemExit`/exception paths.
4. Keep all child executor/orchestrator bodies unchanged and keep pipeline outputs named `hype.timeline.json`, `hype.assets.json`, and `hype.metadata.json`.
5. Ensure direct `--out` behavior remains unchanged and does not write project metadata.

### Step 11: Materialize run placements (`artagents/core/project/materialize.py`, `artagents/core/project/cli.py`)
**Scope:** Medium
1. Add `projects timeline place-run --project <slug> --run <run_id> --clip <clip_id> --track v1 --at 0 [--from SEC] [--to SEC] [--id ID]`.
2. Resolve run placements by loading `<project>/runs/<run_id>/timeline.json` and `assets.json`.
3. Require `--clip` to match a clip `id`; if a run timeline contains clips without ids, error with a command/action hint rather than guessing by index.

6. Validate the final materialized TimelineConfig and AssetRegistry.
