# Implementation Plan: Phase 3 — Inline Produces Checks + `repeat` Body Attributes

## Overview

Phase 3 turns the frozen-plan kernel (Phases 1 + 2 already shipped) into a useful runner by adding two orthogonal additions on top of the existing three step kinds (`code`, `attested`, `nested`):

1. **Inline produces with checks.** `produces` becomes a dict `name -> {path, check}` where `check` is a callable verifier from a new `artagents.verify` package (`file_nonempty`, `json_schema`, `json_file`, `audio_duration_min`, `image_dimensions`, `all_of`). The gate runs each check after `step_completed` (code) or `step_attested` (attested); failure records a `produces_check_failed` event and **rewinds the cursor** (does not advance). Sentinel-existence-only checks are rejected at *definition time* for non-trivial attested produces.
2. **`repeat` as body attribute.** Any step (code, attested, nested) can carry a `repeat: {until: ...}` or `repeat: {for_each: ...}` block. `until` retries the body and writes attempts under `iterations/NNN/` with cumulative `feedback.json`. `for_each` expands a runtime input set and writes per-item state under `items/<item-id>/`, supporting partial approval via `--item <id>`. `on_exhaust` selects between `escalate` (park, require attested override) and `fail` (abort).

The work stays additive: existing Phase-1/2 plans (legacy `produces: [...]` list, no `repeat`, no `check` field) continue to load and run unchanged. No DSL (Phase 4). No new lifecycle verbs (Phase 5) — only data-model, gate plumbing, and event kinds. Tests cover: failed check rewinds; sentinel-only rejected at definition; `repeat.until` golden iteration with cumulative feedback; `repeat.for_each` golden with partial approval; `on_exhaust` escalate vs fail.

Key architectural notes from the existing kernel:

- `artagents/core/task/plan.py` already has `CodeStep`, `AttestedStep`, `NestedStep` dataclasses and a `_validate_*` chain. Schema additions land here.
- `artagents/core/task/gate.py` already has the `_Frame` / `CursorPath` / `derive_cursor` event-replay model. Iteration and fan-out add new frame kinds: an iteration frame (no path segment, `iterations/NNN/`) and a per-item frame (path segment `items/<item-id>/`). Both replay deterministically from new event kinds.
- `artagents/core/task/events.py` already canonicalizes events via `canonical_event_json` + `_event_hash`; new `make_*_event` helpers are additive.
- `artagents/structure.py` doctor guardrail must accept the new top-level `verify` package or `python3 -m artagents doctor` and `tests/test_doctor_setup.py` will fail.

## Phase 1: Foundation — `artagents.verify` Package + Schema Extensions

### Step 1: Create `artagents/verify/` package (`artagents/verify/__init__.py`, `artagents/verify/checks.py`, `artagents/structure.py`, `tests/test_doctor_setup.py`)
**Scope:** Medium

1. **Create** `artagents/verify/checks.py` containing six callables. Each takes a `(step_dir: Path, name: str, declared_path: str)` triple and returns a `CheckResult(ok: bool, reason: str | None, details: dict)`. Callables are dataclasses/closures so they serialize to a deterministic `(check_id, params)` pair for plan hashing — the *callable identity itself* must hash, not just the result.
   - `file_nonempty()` — `(step_dir/declared_path).stat().st_size > 0`. Marked `sentinel=True` on the returned check object.
   - `json_file()` — file exists, is valid UTF-8 JSON. `sentinel=False`.
   - `json_schema(schema: dict)` — `json_file` then validates against schema (use stdlib for `type`/`required`/`properties` shallow check; full jsonschema lib not required for Phase 3). `sentinel=False`.
   - `audio_duration_min(seconds: float)` — uses `wave`/`audioop` for `.wav`, falls back to `ffprobe` subprocess otherwise; `sentinel=False`.
   - `image_dimensions(min_w: int = 0, min_h: int = 0)` — reads PNG/JPEG header bytes (no Pillow dep); `sentinel=False`.
   - `all_of(*checks)` — runs all in order, fails on first failure. `sentinel = all(c.sentinel for c in checks)`.
2. **Define** the public `Check` protocol in `artagents/verify/__init__.py`:
   ```python
   @dataclass(frozen=True)
   class Check:
       check_id: str           # e.g. "file_nonempty", "json_schema", "all_of"
       params: dict[str, Any]  # canonicalized schema/threshold args; sorted-keys-stable
       sentinel: bool
       def __call__(self, step_dir: Path, name: str, declared_path: str) -> CheckResult: ...
   ```
   Re-export the six factories. The `(check_id, params)` tuple is what gets serialized into `plan.json` so plan-hash stability survives across helper-impl edits.
3. **Add** `"verify"` to `TOP_LEVEL_ARTAGENTS_DIRS` in `artagents/structure.py:27` and update `tests/test_doctor_setup.py` to expect it. (Phase 4 will add `"orchestrate"`; do not add it now.)
4. **Capture** the canonical-serialization rule in a one-line module docstring on `artagents/verify/__init__.py` so authors know `params` ordering matters for plan hash determinism.

## Phase 2: Gate Plumbing — Inline Checks + Repeat Frames

**Scope:** Medium

1. **Insert** a `_run_inline_checks()` helper that:

   - Calls each `Check` callable; on first failure, appends `produces_check_failed` (containing `{check_id, name, reason, details}`) and returns `False`.
   - On all-pass, appends one `produces_check_passed` per name and returns `True`.
2. **Hook** the helper into two existing emission points:
   - `record_dispatch_complete()`: after appending `step_completed` (code), call checks. If failed, also append `cursor_rewind` and the cursor-replay logic in `derive_cursor` interprets `produces_check_failed` as a "do not advance" marker. **Concretely:** modify `derive_cursor` so that the pair `(step_completed, produces_check_failed)` does *not* advance `top.child_index`. (The simpler implementation: `step_completed` advances tentatively, and any subsequent `produces_check_failed` for the same `plan_step_id` decrements `child_index`. 3. **Update** `derive_cursor()` to recognize a step as "advance-eligible" only when its terminal `step_completed`/`step_attested` event is followed (in the same plan-step-id contiguous block) by a successful set of `produces_check_passed` events covering every declared produces name. A `produces_check_failed` for that step blocks the advance and signals "rewind to redispatch". Re-dispatch of the same `plan_step_id` is allowed when the latest event for that path is `produces_check_failed`.
4. **Update** `_dispatch_code` reentry guard so that a redispatch after a failed check passes the "incoming command must match" check by inspecting the latest *event for this step path* rather than only `events[-1]` (insertion-order may now have `produces_check_failed` between `step_dispatched` events from prior attempts).

### Step 5: Add iteration frames for `repeat.until` (`artagents/core/task/gate.py`, `artagents/core/task/plan.py`)
**Scope:** Medium

1. **Extend** the `_Frame` model with two new optional fields without breaking the existing replay logic:
   ```python
   @dataclass
   class _Frame:
       plan: TaskPlan
       path_prefix: tuple[str, ...]
       child_index: int = 0
       iteration: int | None = None        # NNN when this frame is iterating a single step
       item_id: str | None = None          # set on for_each item subframes
       repeat_step_id: str | None = None   # the host step id, when iteration/item is active
   ```
   For a step `s2` with `repeat.until`, after we land on `s2` we *push* a new frame whose `plan` is a synthetic single-step plan containing `s2`'s body, with `path_prefix = (..., "s2", f"iterations/{iteration:03d}")`. This means produces and child events all carry the iteration-qualified path, which is what `step_dir_for` needs to write under `iterations/NNN/`.
2. **Replay** logic in `derive_cursor`: when an `iteration_started` event is seen, push the iteration frame; when `iteration_failed` is seen, pop the frame and advance the iteration counter on the parent host (do not advance host's child_index). When `iteration_exhausted` event is seen with `on_exhaust=fail`, raise `TaskRunGateError` (recovery: `artagents abort --project <slug>`). With `on_exhaust=escalate`, mark the host frame as "parked" — no advance until a follow-up `step_attested` event with `--actor` resolves the override (added as a synthetic attested gate inside the host).
3. **Termination check** for `repeat.until`:
   - `verifier_passes`: the host iteration's produces checks all pass on first try → advance host. (Effectively standard inline-check + repeat acts as a max_iterations bound.)
   - `user_approves`: requires an attested ack on the host step itself. The ack consumes the iteration frame and advances the host. Prior failed iterations stay on disk under `iterations/NNN/` with `feedback.json` for the next iteration to read.
   - `quorum`: requires `quorum_n` `step_attested` events from distinct attestors before advance. Phase 3 stub: validate at definition; runtime advances when N distinct attestor IDs have signed off in this host's iterations.
4. **Cumulative feedback**: when a `step_attested` event with `iterate_feedback` evidence string is seen on a `user_approves` host (only valid for `repeat.until=user_approves` per SD-020), write the feedback into `iterations/NNN/feedback.json` and emit `iteration_failed`. The next iteration starts with `iterations/(NNN+1)/feedback.json` containing the cumulative array of all prior feedback entries. (The `iterate --feedback` lifecycle verb itself ships in Phase 5; for Phase 3 we expose only the underlying mechanism via direct `append_event` from tests.)

### Step 6: Add per-item frames for `repeat.for_each` (`artagents/core/task/gate.py`, `artagents/core/task/plan.py`)
**Scope:** Medium

1. **Resolve** the item set lazily on first arrival at the host step:
   - `items_source="static"`: use the literal tuple from the plan.
   - `items_source="from"`: parse `"<step-id>.produces.<name>"`, locate that step's produces JSON file at `step_dir_for(...) / produces / <path>` (resolved at the time we encounter the for_each host), and read it as a list of strings. 4. **Partial approval**: support `--item <id>` on attested commands by extending `match_attested_command()` to strip `--item`. The gate routes the ack to that item's frame regardless of its insertion order in `for_each_expanded`. The host advances only after every item's frame is satisfied (or after explicit partial-acceptance escalation, deferred to Phase 5).
5. **Test scenarios**:
   - `for_each` with three items, two get acked individually, host does not advance until third arrives.
   - `for_each_expanded` is replay-deterministic: writing the events file by hand and calling `derive_cursor` reproduces the same frame stack.

### Step 7: `on_exhaust` semantics (`artagents/core/task/gate.py`)
**Scope:** Small

1. **`on_exhaust=fail`**: when iteration count exceeds `max_iterations`, append `iteration_exhausted` and raise `TaskRunGateError(reason="repeat.until max_iterations exhausted", recovery="artagents abort --project <slug>")`. 48	Iteration and fan-out are body attributes, not kinds. `repeat.until` supports `user_approves`, `verifier_passes`, and `quorum`, with `max_iterations` and `on_exhaust`; attempts write under `iterations/NNN/`. `repeat.for_each` expands a body over an input set and writes per-item state under `items/<item-id>/`; `ack --item <id>` supports partial approval.
49	
50	## 6. Produces & Inline Checks
51	
52	`produces` declares artifacts and checks beside the step that creates or attests them, using `artagents.verify` helpers: `file_nonempty`, `json_schema`, `json_file`, `audio_duration_min`, `image_dimensions`, and `all_of`. The gate runs checks after completion or ack; failure records the verifier output and rewinds the cursor. `passes_test` remains a normal `code` step. Sentinel-existence-only checks are rejected for non-trivial attested outputs.
53	
54	## 7. Gate Above Dispatch
55	
56	The gate checks: `active_run.json` exists; `plan.json` hash matches the pin; `events.jsonl` chain is intact; and the incoming command matches `plan[derived_cursor].command`. Any failure exits non-zero and prints one exact recovery command: start for missing active run, abort for integrity failure, or `artagents next --project <slug>` for command mismatch.
57	
58	Ordering is load-bearing. The first gate sits in `artagents/pipeline.py:15`; a defensive decorator re-checks at `artagents/core/orchestrator/runner.py:132`, the top of `run_orchestrator()`, before `_prepare_project_request()` at line 135 and `thread_wrapper.begin_orchestrator_run()` at line 136. Rejection writes zero project-run files. `events.jsonl` is the single task-mode provenance surface; `artagents/threads/wrapper.py:21-26` keeps existing thread env provenance in `runs/<id>/run.json`.
59	
60	## 8. Lifecycle Verbs
61	
62	Task-mode verbs extend top-level `artagents/pipeline.py:15`, not `artagents orchestrators`. Existing `artagents orchestrators run|list|inspect|validate` in `artagents/core/orchestrator/cli.py` stays unchanged.
63	
64	Agent mid-run verbs: `next`, `ack`, `status`, `abort`. Operator verbs: `start`, `abort`, `status`, `runs ls`. Author verbs: `author new`, `author check`, `author describe`, `author test`, `author compile`, `author explain`.
65	
66	## 9. Ack Decisions
67	
68	`approve` advances when the current step is awaiting approval and checks pass. `retry` is only valid after verifier failure and reruns with stderr/verifier output as feedback. `iterate --feedback` is only valid for `repeat.until=user_approves` and appends to cumulative constraints. `abort` ends the run. Attested steps require `--agent` or `--actor` as above; `--item <id>` targets one `repeat.for_each` item.
69	
70	## 10. Authoring
71	
72	`artagents.orchestrate` is the only committed representation for new task plans. `artagents author compile` writes gitignored `<pack>/build/<orch>.json`, and runtime hashes that compiled artifact. Pack additions are `<pack>/<orch>.py`, `<pack>/build/<orch>.json`, `<pack>/fixtures/<name>/`, and `<pack>/golden/<name>.events.jsonl`.
73	
74	`author check` is sub-second static validation: schema, references, nested plan resolution, semantic checks for non-trivial attested produces, sentinel-only rejection, and rejection of `code` argv to `artagents orchestrators run`. `author describe` prints the DAG. `author test --fixture` runs `--dry-run --auto-approve` and diffs `events.jsonl` against the fixture golden.
75	
76	## 11. Stop-Hook Nudge
77	
78	V1 nudge is out-of-process and Claude Code only. A Stop hook runs `artagents next`; every `next` response includes the prohibition preamble verbatim, including repeated calls, so context decay is countered by re-injection.

182	
183	| Risk | Trigger | Mitigation |
184	| --- | --- | --- |
185	| Single-host assumption | No daemon means two operators can race. | Validate the chain before each command and print recovery commands. |

25	def append_event(path: str | Path, event: dict[str, Any]) -> dict[str, Any]:
26	    events_path = Path(path)
27	    ok, _last_index, error = verify_chain(events_path)

53	def verify_chain(path: str | Path) -> tuple[bool, int, str | None]:
54	    events_path = Path(path)
55	    try:
56	        handle = events_path.open("r", encoding="utf-8")
57	    except FileNotFoundError:
58	        return True, -1, None
59	    except OSError as exc:
60	        return False, -1, f"failed to read {events_path}: {exc}"
61	
62	    prev_hash = ZERO_HASH
63	    last_index = -1
64	    with handle:
65	        for index, line in enumerate(handle):
66	            if not line.endswith("\n"):
67	                return False, index, f"event log line {index + 1} is not newline-terminated"
68	            raw = line[:-1]
69	            if not raw:
70	                return False, index, f"event log line {index + 1} is empty"
71	            try:
72	                event = json.loads(raw)
73	            except json.JSONDecodeError as exc:
74	                return False, index, f"invalid JSON on event log line {index + 1}: {exc.msg}"
75	            if not isinstance(event, dict):

86	                )
