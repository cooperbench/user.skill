## Phase 4: createShotWithFiles Atomic RPC

### Step 6: Design the `create_shot_with_files` approach (`supabase/migrations/`)
**Scope:** Medium
1. **Review** the existing `create_shot_with_generations` RPC (in `20260406_create_shot_with_generations.sql`) as a template — it already returns fully hydrated data in one call.
2. **Key constraint:** File uploads go to Supabase Storage (client-side), which means the RPC can't handle the actual file upload. The RPC can only handle: create shot → create generation records → create shot_generation links → return hydrated data.
3. **Approach:** Keep client-side file upload (unavoidable), but have the upload pipeline return the generation IDs and metadata it creates. Then call a new `create_shot_with_uploaded_files` RPC that takes `(project_id, shot_name, generation_data[])` and atomically: inserts the shot, creates shot_generation links, and returns the full hydrated result — eliminating the second roundtrip (`shotCreationPaths.ts:199-226`).
4. Alternatively: modify `uploadToShot` to return complete generation data (location, thumbnail_url, type, params, created_at) alongside generation IDs. Then hydrate the cache directly from the upload response without re-fetching. This is simpler but less atomic.

### Step 7: Implement the RPC and update the path (`supabase/migrations/`, `src/shared/hooks/shotCreation/shotCreationPaths.ts`)
**Scope:** Large

4. **Update** tests in `src/shared/hooks/shotCreation/shotCreationPaths.test.ts`.

**Scope:** Small
