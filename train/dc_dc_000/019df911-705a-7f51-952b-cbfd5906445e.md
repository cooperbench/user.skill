> AGENT

Megaplan “chaining” is a serial milestone runner.

You give it a YAML spec like [chain.yaml](/Users/user_c042661f/Documents/reigh-workspace/reigh-app/chain.yaml:1):

```yaml
milestones:
  - label: sprint-01
    idea: /workspace/.../sprint-01-idea.md
    branch: megaplan/sprint-01
  - label: sprint-02
    idea: /workspace/.../sprint-02-idea.md
    branch: megaplan/sprint-02

on_failure:
  abort: stop_chain

driver:
  robustness: standard
  auto_approve: true
```

Mechanically:

1. `megaplan chain start --spec chain.yaml` reads the milestone list.
2. For each milestone, it refreshes `main`, checks out/creates the milestone branch, and runs `megaplan init --idea-file ...`.
3. It drives that plan through the normal `megaplan auto` loop until terminal state.
4. After each phase, if a branch is configured, it commits/pushes progress and ensures a PR exists.
5. If the milestone finishes, it marks the PR ready and either enables auto-merge or waits for manual merge depending on `merge_policy`.
6. It persists chain progress under `.megaplan/plans/.chains/...json`, so rerunning resumes the current milestone instead of starting over.
7. Failure/escalation policy decides whether to stop, skip, or retry the milestone.

The command surface is tiny:

```bash
PYENV_VERSION=3.11.11 python -m megaplan chain start --spec chain.yaml
PYENV_VERSION=3.11.11 python -m megaplan chain status --spec chain.yaml
```

Separate but related: `--from-doc` is “conceptual chaining” between runs. A metaplan doc can define `## Settled Decisions`; the next run can do `megaplan init --from-doc docs/design.md ...`, and those decisions become success criteria.
