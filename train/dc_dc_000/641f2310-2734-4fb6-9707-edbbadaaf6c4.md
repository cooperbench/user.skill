        # Implementation Plan: Phase 5 — Lifecycle Verbs Split by Audience

## Overview
Phase 5 lands the audience-scoped task-mode CLI on top of the Phase 1-4 kernel. The kernel (`artagents/core/task/`) already exposes `gate_command`, `derive_cursor`, `compute_plan_hash`, `read_active_run`/`write_active_run`/`clear_active_run`, the full event-maker set including `make_run_started_event`, and the `iter_steps_with_path` plan walker. Author CLI in `artagents/orchestrate/cli.py` already implements `compile`, `check`, `describe`, `new`. Phase 5 adds (a) lifecycle verbs `start`, `next`, `ack`, `abort`, `status`, `runs ls` directly in `artagents/pipeline.py`, (b) author verbs `test` (scaffold + diff against existing golden) and `explain` to the author CLI, and (c) the prohibition-preamble constant printed verbatim by `next`.

The kernel's gate currently runs in `pipeline.main` whenever `--project <slug>` is present. The new lifecycle verbs themselves carry `--project` but must not be matched against `plan[cursor].command` — `next`, `status`, `abort`, `runs ls`, `start`, `author *` are out-of-band. The exception is `ack --decision approve` for attested steps, which routes back into the gate's `_dispatch_attested` path. So `pipeline.main` short-circuits the gate for known lifecycle verbs and `cmd_ack` re-enters the gate explicitly when (and only when) the decision is `approve`.

Constraints:
- `artagents orchestrators run|list|inspect|validate` paths in `artagents/core/orchestrator/cli.py` stay untouched.
- Author `test` golden-run capture is Phase 9; the verb must scaffold but emit a clear "implement Phase 9" message when no golden file exists.
- Stop-hook wiring is Phase 6; only the verbatim preamble constant lands here.
- Run-id is operator-supplied via `--name` if given (slugified), otherwise generated as `run-<UTC timestamp>-<8 hex>` to satisfy `validate_run_id` regex `^[A-Za-z0-9][A-Za-z0-9_.:-]{0,127}$`.
- `start <orchestrator-id>` consumes the compiled `<packs_root>/<pack>/build/<name>.json`. If absent, the verb prints the exact `artagents author compile <id>` recovery and exits non-zero — does not silently call compile (compile is gitignored output, materializing it during start crosses the additive line).

Three significant correctness issues from critique are folded in:

1. **`ack approve` command synthesis (FLAG-P5-001)** — `match_attested_command` (`gate.py:914-950`) strips identity flags from the incoming command and compares the literal remainder to the authored `step.command` (e.g. `"review.sh"`, NOT `"ack --project ... --step ..."`). The plan now synthesizes the gate-bound incoming command as **the step's literal `step.command` followed by identity/evidence/item tokens**, not the canonical `ack --step ...` shape that only `_make_exhaust_override_step` uses internally.
2. **`ack` identity validation across all decisions (FLAG-P5-002)** — every `ack` decision targeting an attested cursor (approve / retry / iterate) must validate `--agent`/`--actor`/`ARTAGENTS_ACTOR`/self-ack rules before mutating events. The plan factors a public `validate_attested_identity` helper out of `gate.py` so `cmd_ack` can call it directly for retry/iterate (approve still goes through `_dispatch_attested` which calls it transitively).
3. **Read-only cursor peek (FLAG-P5-003)** — instead of a vague mirror, the plan refactors the auto-traverse loop in `gate_command` to take an `append_fn` callable. Default is the existing `append_event(path, ev)`; peek mode passes a list-capturing sink, then re-runs `derive_cursor(plan, events + captured)` to find the leaf. The same code path is used by `gate_command` and `peek_current_step`, so there is one source of truth.
