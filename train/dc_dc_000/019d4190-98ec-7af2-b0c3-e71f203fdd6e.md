        # Implementation Plan: Fix unsafe .maybeSingle() calls in complete_task

## Overview
A `.maybeSingle()` call crashes when multiple rows match. The `derivePredecessorVariantId` query was already fixed with `order()+limit(1)`, but one remaining query in `findExistingGenerationAtPosition` has the same vulnerability. Additionally, we should investigate whether a unique DB constraint on `(parent_generation_id, child_order)` is feasible to prevent duplicates at the source.

### Audit Results
Of 20 `.single()`/`.maybeSingle()` calls in `supabase/functions/complete_task/`:
- **14** query on primary key (`id`) — inherently safe
- **2** are INSERT `.single()` — safe (returns inserted row)
- **3** already have `.order().limit(1)` — already fixed
- **1 needs fixing**: `generation-child.ts:173-179`

## Main Phase

### Step 1: Fix the unsafe query in `findExistingGenerationAtPosition` (`generation-child.ts`)
**Scope:** Small
1. **Fix** the pairShotGenId branch at `generation-child.ts:173-179`. Add `.order('created_at', { ascending: false }).limit(1)` before `.maybeSingle()`, matching the pattern already used in the childOrder branch on lines 194-195.
   ```typescript
   // Before (crashes if multiple rows)
   .eq('pair_shot_generation_id', pairShotGenId)
   .maybeSingle();

   // After
   .eq('pair_shot_generation_id', pairShotGenId)
   .order('created_at', { ascending: false })
   .limit(1)
   .maybeSingle();
   ```

### Step 3: Investigate unique constraint on `(parent_generation_id, child_order)` (`supabase/migrations/`)
**Scope:** Small-Medium
1. **Query** the production database (or a recent dump) to check for existing duplicates:
   ```sql
   SELECT parent_generation_id, child_order, count(*)

   WHERE parent_generation_id IS NOT NULL AND child_order IS NOT NULL
   GROUP BY parent_generation_id, child_order

   ```
2. **If no duplicates exist**: create a migration adding a partial unique index:
   ```sql
   CREATE UNIQUE INDEX idx_unique_parent_child_order
   ```
