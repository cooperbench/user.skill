## Overview

Currently the Hermes agent executes code locally (macOS, Python 3.11) but SWE-bench scores in Docker (Linux, Python 3.9). This mismatch causes false passes. The fix: route the execute phase through the same Docker image SWE-bench uses for scoring, using the existing `TERMINAL_ENV=docker` backend.

**Revised approach: Use the container's own `/testbed` — no bind-mount**

The v1 plan proposed bind-mounting the host workspace at `/testbed`. This has two fatal problems:
1. **Worktree `.git` pointer**: `prepare_workspace()` creates git worktrees (`swe_bench.py:257`). The `.git` file contains an absolute host path like `gitdir: /Users/.../worktrees/...` which breaks inside the container.
2. **`/root` clobber**: The Docker backend mounts tmpfs or bind-mount over `/root` (`docker.py:288-309`), destroying the conda/Python environment that SWE-bench installs there.

**New approach**: Don't mount anything. The SWE-bench Docker image already has the repo at `/testbed` at the correct commit with all dependencies installed. The agent works entirely inside the container. After execution, extract the git diff from inside the container via the Hermes terminal tool (which is already running `docker exec`), then write the patch to the host for scoring. This requires:
- A Docker backend change to add a `skip_home_overlay` flag that preserves the image's `/root` and `/home` contents
- Relaxing sandbox limits (`--pids-limit`, tmpfs sizes, memory) for SWE-bench parity
- A new `_extract_patch_from_container()` step before scoring
- Computing the SWE-bench image name via subprocess (matching existing codebase patterns)

**Settled decisions from gate:**
- Docker exec approach (Option A) using existing `TERMINAL_ENV=docker` backend
- Docker execution is opt-in via config flag, not default
- Continue shelling out to swebench via subprocess, not direct imports
- Image prebuild must NOT go in `prepare_workspace()` — use a separate method
