**1. Mental Model**
Custom elements are folder-based render primitives: `effects`, `animations`, or `transitions`, each with `component.tsx`, `schema.json`, `defaults.json`, and `meta.json` [schema.py](/Users/user_c042661f/Documents/reigh-workspace/ArtAgents/artagents/elements/schema.py:11). Resolution is deterministic: active theme, overrides, managed, then bundled [registry.py](/Users/user_c042661f/Documents/reigh-workspace/ArtAgents/artagents/elements/registry.py:117). Remotion consumes generated registries from that resolved view, with aliases for theme/override/managed/bundled sources [webpack-alias.mjs](/Users/user_c042661f/Documents/reigh-workspace/ArtAgents/remotion/webpack-alias.mjs:18).

**2. Happy Path**
Best intended path:

1. `python3 -m pip install -r requirements.txt`
2. `python3 pipeline.py setup --apply`
3. `python3 pipeline.py elements list`
4. `python3 pipeline.py elements inspect effects text-card --json`
5. `python3 pipeline.py elements fork effects text-card`
6. Edit `.artagents/elements/overrides/effects/text-card/*`
7. Declare deps in `meta.json.dependencies`
8. `python3 pipeline.py elements install effects text-card --apply`
9. `python3 scripts/gen_effect_registry.py`
10. `cd remotion && npm run typecheck && npm run smoke`

The direct element CLI works in a lean env via `python3 -m artagents.elements.cli ...`; 11 focused element/generator unittest tests passed that way.

**3. Dependency/Install Risks**
- Documented `pipeline.py elements ...` failed here before dispatch because `artagents/pipeline.py` imports the full pipeline at module import time, including `jsonschema` transitively [pipeline.py](/Users/user_c042661f/Documents/reigh-workspace/ArtAgents/artagents/pipeline.py:23), while element dispatch happens much later [pipeline.py](/Users/user_c042661f/Documents/reigh-workspace/ArtAgents/artagents/pipeline.py:1243). This makes inspect/install fragile before full project deps are installed.
- JS dependency install is isolated but not wired into Remotion module resolution. `npm install --prefix .artagents/elements/<kind-id>/node ...` [install.py](/Users/user_c042661f/Documents/reigh-workspace/ArtAgents/artagents/elements/install.py:58) creates `node/node_modules`, but webpack only adds `remotion/node_modules` [webpack-alias.mjs](/Users/user_c042661f/Documents/reigh-workspace/ArtAgents/remotion/webpack-alias.mjs:44). Element imports may not resolve.
- Generated registries can depend on ignored local `.artagents/elements/managed` state, so one user may generate `@managed-elements-*` imports while a fresh clone without setup would not have those files.
- ID validation is looser than TypeScript codegen. `foo.bar` can pass element validation [schema.py](/Users/user_c042661f/Documents/reigh-workspace/ArtAgents/artagents/elements/schema.py:14) but generates invalid component identifiers via `_component_name` [gen_effect_registry.py](/Users/user_c042661f/Documents/reigh-workspace/ArtAgents/scripts/gen_effect_registry.py:67).

**4. Simplifications / Docs Needed**
- Add a “create custom element from scratch” doc or `elements new effects my-id` scaffold. Forking is clear; greenfield creation is implied.
- Make `elements inspect` show shadowed sources/conflicts and the generated import alias, not just the winning root.
- Either dispatch lightweight subcommands before full pipeline imports, or document `python3 -m artagents.elements.cli` as the no-full-env fallback.
- Clarify whether `managed` is required before rendering. If not, generated registries should prefer bundled defaults unless an actual override/custom source exists.
- Provide one real rendered bundled element. Current bundled `text-card` returns `null`, so the forked example is not a useful working template.
