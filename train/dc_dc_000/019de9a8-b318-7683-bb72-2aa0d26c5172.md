            **Implementation Plan: Sprint 1 Canonical Timeline Domain**

**Intent Check**
This sprint remains a foundation slice, not a rewrite. The persisted canonical source stays `TimelineConfig + AssetRegistry`. `TimelineData`, renderer-resolved clips, rows/meta/clipOrder, and agent command views are projections/adapters. The goal is to centralize interpretation while preserving current editor behavior and documenting any call sites that cannot be safely migrated in this slice.

**Phase 0: Baseline and Characterization**

Run targeted tests first, then add characterization tests before changing behavior:

```bash
npm run test -- src/tools/video-editor/lib/config-utils.test.ts src/tools/video-editor/lib/timeline-data.test.ts src/tools/video-editor/lib/migrate.test.ts src/tools/video-editor/lib/serialize.test.ts src/tools/video-editor/hooks/usePollSync.test.ts src/tools/video-editor/hooks/useTimelineCommit.test.tsx
npm run test:edge:unit -- supabase/functions/timeline-import supabase/functions/ai-timeline-agent
```

Add characterization coverage for existing load/repair behavior before moving any repair logic:

- Duplicate track IDs and duplicate clip IDs, including cascading `-dup-N` suffix cleanup.
- Legacy pinned group `children` conversion.
- `repairShotGroupContiguity` behavior.
- `migrateToFlatTracks` behavior, including legacy track names and background hold clip injection.
- Current UI zero-duration behavior for clips missing `to` when no registry is available.
- Current agent duration behavior for clips missing `to` when registry duration is available.

These tests decide where Sprint 1 can safely change behavior and where compatibility wrappers must preserve legacy behavior.

**Phase 1: Create an Acyclic Domain Boundary**

Create `src/tools/video-editor/domain/` as the owning layer for canonical interpretation. It must be runtime-safe for both browser/editor tests and Supabase edge function source:

- No React imports.
- No browser APIs.
- No `@/` aliases.
- No imports from `lib/config-utils.ts`, `lib/timeline-data.ts`, hooks, components, or renderer files.
- Only import persisted/shared types from `src/tools/video-editor/types/index.ts` by relative path if needed.

Initial files:

- `diagnostics.ts`: stable `TimelineDiagnostic` types and codes.
- `duration.ts`: registry-aware and registry-free duration helpers.
- `repair.ts`: lifted repair/migration primitives currently owned by `lib/migrate.ts`, moved or duplicated only after characterization tests pin behavior.
- `normalize.ts`: `normalizeTimelineConfig(config, registry, options)` returning normalized in-memory config, registry, diagnostics, and `repaired` metadata.
- `validate.ts`: hard errors and warnings over canonical data.
- `serialize.ts`: explicit write serialization after normalization/validation.
- `index.ts`: public API.
- `README.md`: canonical source/projection/read/write rules.

Acyclic ownership rule:

- `domain/*` owns duration, validation, repair, normalization, and serialization.
- `lib/config-utils.ts`, `lib/migrate.ts`, `lib/serialize.ts`, and `lib/timeline-data.ts` become compatibility/adaptation layers that may import `domain/*`.
- `domain/*` must never import those `lib/*` compatibility modules.

**Phase 2: Define Duration APIs Without Breaking Existing Callers**

Do not force registry fallback through old clip-only helpers. Add two explicit APIs:

- `getCanonicalClipDurationSeconds(clip, registry, options)`: registry-aware canonical helper for callers that have `AssetRegistry`.
- `getLegacyClipDurationSeconds(clip)` or compatibility wrapper behavior through `config-utils.ts`: preserves existing clip-only semantics where no registry is available.

Canonical duration rule:

- `hold` wins when finite and positive.
- Else, finite `from` and `to` produce `to - from`.
- Else, for media clips with a registry asset duration, use `asset.duration - from` when `from` exists, otherwise `asset.duration`.
- Invalid, missing, or non-positive `speed` is repaired to `1` with a warning on read and on write for Sprint 1, matching existing UI sanitization behavior and avoiding a new write rejection policy.
- Seconds-domain helpers may return `0` where canonical data is incomplete; frame helpers clamp only at render/frame conversion boundaries when a rendered sequence needs at least one frame.

Migration rule:

- Callers with only `clip` keep legacy behavior through compatibility wrappers.
- Callers with `config + registry` move to canonical helpers.
- Any call site that cannot receive registry without broad signature churn is listed in the final notes as a remaining non-canonical duration path.

**Phase 3: Preserve Existing Repair Semantics**

Lift existing repair behavior into `domain/repair.ts` only after characterization tests are in place. The lifted implementation must preserve current semantics for:

- `repairConfig` duplicate handling.
- `repairShotGroupContiguity`.
- `migrateToFlatTracks`.
- Legacy pinned-group conversion.
- Legacy track/background behavior.

Compatibility modules should delegate to these domain functions so existing imports continue to work. `normalizeTimelineConfig` should compose these exact repair steps and attach diagnostics; it should not invent new repair behavior in Sprint 1.

Read behavior remains non-persistent: normalization may repair in memory and report diagnostics, but UI load/poll/read paths must not write repaired data merely because they read it.

**Phase 4: Route Editor and Renderer Call Sites Deliberately**

First migrate low-risk call sites that already have or can cheaply receive `AssetRegistry`:

- `buildTimelineData` / row assembly paths where both `TimelineConfig` and `AssetRegistry` are available.
- `useDerivedTimeline` timeline-duration calculations.
- Renderer sequence duration calculations in `TimelineRenderer.tsx` and related Remotion components where resolved clips or registry-backed metadata are available.
- Attachment and selected-media helpers if they already have asset registry context.

Keep `configToRows(config)` signature stable if broad churn is required. Add a registry-aware sibling or options parameter only where call sites can be updated safely, for example `configToRows(config, { assetRegistry })`, while preserving old behavior when omitted.

Audit and classify all direct duration call sites from `rg`, including:

- `VideoEditorProvider.tsx`
- `RemotionPreview.tsx`
- `CompactPreview.tsx`
- `VideoEditorShell.tsx`
- `useTimelineClipsForAttachments.ts`
- `useSelectedMediaClips.ts`
- `editor-utils.ts`
- `EffectLayerSequence.tsx`
- `TextClip.tsx`
- `UnknownClipPlaceholder.tsx`
- `AudioTrack.tsx`
- `supabase/functions/ai-timeline-agent/selectedClips.ts`

Each call site must either use the canonical helper or be documented as intentionally legacy/registry-unavailable with a follow-up. This avoids pretending the migration is complete when it is not.

**Phase 5: Route Agent Semantics, Not Just Load/Save**

Replace the private registry-aware duration helper in `supabase/functions/ai-timeline-agent/tools/timeline.ts` with the domain duration helper, but preserve current command behavior unless tests show a clear bug.

Normalize once after DB load, carry diagnostics into `findIssues` or logs, and serialize through domain serialization before `saveTimelineConfigVersioned`.

Pin command-level behavior with tests for operations that depend on duration:

- `splitClip` bounds and mutation output.
- `trimClip` validation and mutation output.
- `duplicateClip` placement.
- `queryTimeline` gap/overlap reporting.
- `findIssues` duration-related messages.
- `selectedClips.ts` live timeline duration context.

This is required because duration differences can change agent edits before the save boundary.

**Phase 6: Route Import Without Persisting Raw Parsed Shape**

Keep `@banodoco/timeline-schema` validation as the first shape gate, but use its parsed output and the domain serialized output for persistence:

1. Parse `body.timeline` with `TimelineConfigSchema.safeParse`.
2. Parse or normalize `body.asset_registry` consistently.
3. Run domain normalization/validation on parsed timeline plus registry.
4. Reject hard errors with structured `details`.
5. Persist `serializeCanonicalTimeline(...)` output, not the raw body timeline and not only `validated.timeline` if that object still reflects raw input.

Warnings may be logged in Sprint 1 to avoid response-contract churn. Exposing warnings in the API response is a Sprint 2/API compatibility decision unless an existing response field already supports it.

**Phase 7: Narrow Pinned Groups and Poll Sync**

Pinned groups:

- Sprint 1 only validates and warns on stale `clipIds`, missing clips, wrong `trackId`, stale snapshots, and legacy shapes.
- Do not prune `clipIds`, drop empty groups, or mutate pinned group state during serialization in Sprint 1.
- Backend clip CRUD consistency remains a documented follow-up unless a tiny, already-tested fix is discovered during implementation.

Poll sync:

- Keep this scoped to the known conflict-detection issue.
- Add or update a focused test showing `configVersionRef` only advances after accepting a polled payload.
