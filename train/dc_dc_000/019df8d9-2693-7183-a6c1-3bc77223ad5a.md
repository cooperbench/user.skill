        # Implementation Plan: Distillations Memory Primitive

## Overview
Veas currently has a clean five-primitive memory model wired through Postgres migrations, `tool_schemas.py`, read/write tools, tool registry descriptions, hot context rendering, admin pages, and eval snapshot/assertion helpers. Distillations fit as a sixth primitive, but should stay lighter than observations: they are provisional synthesized explanations that connect multiple facts/patterns/domains, not new evidence and not durable life-domain themes.

The critique does not show that the plan targets the wrong root cause. The table/tool/prompt/hot-context approach is still the right implementation path. It does show that distillations need a privacy/provenance design from the start because synthesized explanations can leak partner-private interpretation even when raw messages are hidden. The revised plan therefore adds distillation-specific provenance, visibility, and hot-context gating without trying to solve provenance for all existing primitives in this light implementation.

The pragmatic implementation should add a first-class `distillations` table, read/write tools, prompt guidance, privacy-aware hot-context inclusion, admin/eval visibility, and focused tests. For conservative revision support, use row versioning by supersession instead of in-place destructive rewrites: minor reinforcement can update the same row; substantive revisions create a new row and mark the old row `revised`.

## Main Phase

### Step 1: Add the database primitive (`migrations/0015_distillations.sql`)
**Scope:** Medium
1. **Create** a `distillations` table with:
   - `id uuid primary key default gen_random_uuid()`
   - `content text not null` plus `content_encrypted bytea`
   - `shareable_summary text` for privacy-safe cross-thread rendering when full content is not visible
   - `about_user_id uuid references users(id)` nullable for couple-level explanations
   - `source_user_ids uuid[] not null default '{}'::uuid[]` identifying whose private context materially supports the synthesis
   - `visibility text not null default 'private' check in ('private','dyad_shareable')`
   - `confidence text check in ('high','medium','low')`
   - `status text default 'active' check in ('active','revised','contradicted','retired')`
   - `related_memory_ids uuid[]`, `related_observation_ids uuid[]`, `related_theme_ids uuid[]`
   - `supporting_message_ids uuid[]`
   - `supersedes_distillation_id uuid references distillations(id)`
   - `revision_note text`, `created_at`, `updated_at`, `last_reinforced_at`
2. **Add constraints** that keep privacy data meaningful: `source_user_ids` must not be empty for new rows, and `visibility='dyad_shareable'` should require a non-empty `shareable_summary`.
3. **Index** active retrieval paths: status/recency, `about_user_id/status`, GIN indexes for all related id arrays, and a GIN index for `source_user_ids`.
4. **Enable and force RLS**, and add the same deny-anon policy pattern used by existing primitive tables.
5. **Do not migrate existing observations here.** Leave conversion to the manual workflow in Step 8.

### Step 2: Extend schemas and row helpers (`tool_schemas.py`, `app/services/tools/common.py`)
**Scope:** Medium
1. **Add** `DistillationStatus`, `DistillationVisibility`, `DistillationRow`, `GetDistillationsInput/Output`, `AddDistillationInput/Output`, `UpdateDistillationInput/Output`, and `ReviseDistillationInput/Output`.
2. **Keep inputs explicit:** require `content`, `confidence`, `source_user_ids`, and at least one related memory/observation/theme/message id for `add_distillation`; require `revision_note` for `revise_distillation`.
3. **Validate privacy shape:** `source_user_ids` cannot be empty, and `visibility='dyad_shareable'` requires `shareable_summary`.
4. **Add** `distillation_row()` to `app/services/tools/common.py` to normalize nullable arrays, privacy fields, and timestamps.
5. **Register** new tools in `TOOL_REGISTRY`.

### Step 3: Implement read/write tools (`app/services/tools/read_tools.py`, `app/services/tools/write_tools.py`)
**Scope:** Medium
1. **Implement** `get_distillations(ctx, args)` with filters for `about_user_id`, `theme_id`, `observation_id`, `memory_id`, `source_user_id`, `status`, and `limit`, ordered by `COALESCE(last_reinforced_at, updated_at, created_at) DESC`.
2. **Implement** `add_distillation(ctx, args)` inserting encrypted content, source ownership, visibility, shareable summary, and defaulting `supporting_message_ids` from the triggering messages when omitted.
3. **Implement** `update_distillation(ctx, args)` for conservative in-place edits: status, confidence, links, visibility/shareable summary, or `mark_reinforced=true`; allow `content` only for wording-level clarification.
4. **Implement** `revise_distillation(ctx, args)` as a CTE that marks the old row `revised`, inserts a new active row with `supersedes_distillation_id`, and logs both ids.
5. **Use** existing `encrypt_value()` and `_log_tool_call()` conventions.

### Step 4: Wire tool access and descriptions (`app/services/tools/registry.py`)
**Scope:** Small
1. **Add** `get_distillations` to `READ_PHASE_TOOLS` and dispatch.
2. **Add** `add_distillation`, `update_distillation`, and `revise_distillation` to `WRITE_PHASE_TOOLS` and dispatch.
3. **Write descriptions** that enforce the settled model:
   - memories = concrete facts
   - observations = grounded patterns
   - themes = durable life domains
   - watch items = follow-ups
   - style notes = communication/process preferences
   - distillations = provisional explanations that connect multiple primitives
4. **Tell the model** to search existing distillations before adding or revising, mirroring observation/memory dedup guidance.
5. **Tell the model** to set `source_user_ids` conservatively and only mark a distillation `dyad_shareable` when the `shareable_summary` is safe to show across threads.

### Step 5: Add privacy-aware hot-context support (`app/services/hot_context.py`, `app/services/cross_thread_privacy.py`)
**Scope:** Medium
1. **Add** `distillations` to the `HotContext` dataclass.
2. **Add** a small helper, either in `hot_context.py` or `cross_thread_privacy.py`, that determines whether a distillation is visible to the current user:
   - Full `content` is visible when every `source_user_id` is the current user or belongs to a partner whose `cross_thread_sharing_default` is `opt_in`.
   - If a partner source is `opt_out` or unset, render only `shareable_summary` when `visibility='dyad_shareable'` and a summary exists.
   - Otherwise omit the distillation from hot context rather than exposing hidden synthesized content.
3. **Fetch** active distillations relevant to the dyad, limited to a small number, e.g. 20, ordered by recent reinforcement/update.
4. **Render** a `## Distillations` section after observations or between observations and bridge candidates.
5. **Include** ids, confidence, about-user id, visibility, source user ids, linked primitive ids, and the privacy-filtered display text.
6. **Update** truncation logic so distillations can be dropped under prompt-budget pressure before core trigger/recent-message context.

### Step 6: Update the system prompt (`app/services/prompts.py`)
**Scope:** Small
1. **Rename** “The Five Knowledge Primitives” to “The Knowledge Primitives”.
2. **Add** distillations as the sixth primitive with concise examples and non-examples.
3. **Update** turn-shape write guidance from “five-primitive decision framework” to the expanded model.
4. **Add** a rule that distillations must remain tentative and evidence-linked, and should be revised or retired when new evidence contradicts them.
5. **Add** privacy guidance: distillations must track source users, must not smuggle opt-out/unset partner context into another thread, and need a deliberately safe `shareable_summary` before cross-thread display.

### Step 7: Add admin and eval visibility (`app/routers/admin.py`, `evals/state.py`, `evals/scenario.py`, `evals/assertions.py`)
**Scope:** Medium
1. **Add** `/admin/distillations` and a nav link showing recent distillations, source users, visibility, shareable summary, links, status, confidence, supersession, timestamps, and revision note.
2. **Add** `distillations` to `PRIMITIVE_TABLES` and `STATE_TABLES` snapshot support.
3. **Allow** `kind: distillation` in eval primitive write expectations.
4. **Map** `distillation` to the `distillations` table in eval assertions.
5. **Include** distillation searchable fields in `_searchable_text()`: `content`, `shareable_summary`, and `revision_note`.

### Step 8: Document the manual migration workflow (`docs/distillations-migration.md`)
**Scope:** Small
1. **Document** a manual LLM-assisted review flow for existing high-level observations:
   - Query candidate active observations that read like broad explanations rather than grounded patterns.
   - Ask an LLM to propose distillations with linked observation/theme/memory ids and conservative `source_user_ids`.
   - Ask the LLM to propose a separate `shareable_summary` only when the synthesis is safe for dyad-level display.
   - Human reviews each proposed row, especially source ownership and visibility.
   - Insert approved distillations via `add_distillation` or a reviewed operator SQL workflow.
   - Do not delete or mutate original observations.
2. **Include** a conservative prompt template for the migration assistant.
3. **Call out** that originals remain as evidence and can be linked from the distillation.
4. **Warn** that migrated distillations derived from opt-out/unset partner context should default to `visibility='private'` unless a human explicitly approves a safe summary.

### Step 9: Update focused tests and evals (`tests/`, `evals/scenarios/`)
**Scope:** Medium
1. **Add schema/registry tests** in `tests/test_tool_schemas_importable.py` covering tool registration, enums, required source users, required supporting links, and `dyad_shareable` summary validation.
2. **Extend fake pool support** in `tests/conftest.py` for distillation insert/update/revise/read queries, including privacy fields.
3. **Add tool tests** in `tests/test_tools.py` covering `add_distillation`, `update_distillation`, `revise_distillation`, and `get_distillations`.
4. **Update hot-context tests** in `tests/test_hot_context.py` to confirm active distillations render when sources are visible, render only `shareable_summary` when partner context is not raw-visible but explicitly shareable, and are omitted when partner context is opt-out/unset and not shareable.
5. **Update eval parser/assertion tests** for `kind: distillation`.
6. **Add one eval scenario** where a high-level explanatory synthesis should call `get_distillations` then `add_distillation` or `revise_distillation`, while not deleting or replacing the underlying observations.
