## Overview

Add an opt-in file-based external completion-signal protocol under `runs/<run-id>/inbox/`. External processes (humans, scripts, other tools) drop JSON files into this directory. On the next `next` call, `inbox.py` scans, validates, and consumes exactly one valid matching entry per call by recording a hash-chained `step_attested` event to `events.jsonl` — bypassing `validate_attested_identity` since inbox is by definition an external channel (no terminal operator identity check). Stale entries (wrong step_id, non-AttestedStep cursor) are drained to `.consumed/.stale/` on detection. Malformed files are logged and skipped at scan time. The `cmd_status` surface reports valid pending count via `count_pending_inbox`, which filters `scan_inbox` results against the current cursor step_id so stale entries never inflate the count. The inbox directory triggers scanning only when it exists; its absence is a no-op.

**Trust model**: In V1's single-host file-based architecture, filesystem permissions on `runs/<run-id>/inbox/` are the auth boundary. Anyone with write access can attest as anyone. This is intentional for Phase 8 — the inbox is an external channel by design, not a terminal-identity-checked channel like `ack`.

**Key design decisions from Revision 2 carried forward**:
- Inbox consumption writes `step_attested` events directly via `record_inbox_attested` in gate.py that skips `validate_attested_identity`. The inbox file carries its own identity (`attestor_kind`, `submitted_by`).
- `evidence` in inbox format is `list[str]` (paths) to match `AttestedArgs.evidence: tuple[str, ...]`. This is a deliberate deviation from the brief's dict shape, required for gate compatibility.
- Inbox file format requires `attestor_kind` (`"agent"` | `"actor"`).
- `retry` and `abort` decisions are scoped out for Phase 8: logged and drained to stale, not consumed. Only `approve` is consumable.
- Stale entries drained to `.consumed/.stale/` on detection.
- `scan_inbox` returns entries sorted by mtime then filename.
- Consumed filenames are content-addressed: `sha256(<content>)[:16]`.
- AGENT.md embeds the full inbox schema inline.

**Key changes in Revision 3**:
1. Renamed `_record_inbox_attested` → `record_inbox_attested` (public name per convention).
2. Returns `bool` instead of `GateDecision` (caller only needs success/failure).
3. Explicitly documents that `record_inbox_attested` is success-only — no `iterate_feedback` handling since inbox `decision` is always `"approve"`.
4. `consume_pending_inbox` consumes exactly one entry per call (not all-matching). After one consumption the cursor advances; subsequent entries for the same step are stale.
5. New `count_pending_inbox(run_dir, *, plan, events, slug, project_root, run_id) -> int` helper that filters `scan_inbox` by current cursor step_id, so `cmd_status` never counts stale entries.
6. `cmd_status` inbox print moved after produces line (before "recent events:").
7. AGENT.md template uses escaped `{{` / `}}` for all JSON braces to prevent `.format()` KeyError.
8. `docs/orchestrator-v1-plan.md` Phase 8 section updated with next-only consumption note and evidence format change.
9. Inbox module docstring documents trust model (FS permissions = auth).
10. AGENT.md notes evidence is `list[str]` of paths (deliberate deviation from brief).
11. Explicit documentation that inbox attestation is restricted to cursor's current item (no out-of-order for_each).

**Key constraints**: additive only, no new dependencies, Phase 8 scope only, existing tests must pass, opt-in by directory presence.

## Phase 2: Core Inbox Module

### Step 2: Create `artagents/core/task/inbox.py`
**Scope:** Medium (~170 lines)

Implement the inbox module with these components:

**Module docstring** must include trust-model note:
```
In V1's single-host file-based model, filesystem permissions on
runs/<run-id>/inbox/ are the auth boundary. Anyone with write access
can attest as anyone. The inbox bypasses validate_attested_identity
by design — it is an external channel, not a terminal-identity-checked
channel like `ack`.
```

1. **`InboxEntry` dataclass**:
   ```python
   @dataclass(frozen=True)
   class InboxEntry:
       step_id: str
       decision: str  # "approve" | "retry" | "abort"
       attestor_kind: str  # "agent" | "actor"
       evidence: tuple[str, ...]
       submitted_at: str
       submitted_by: str
       file_path: Path
   ```

2. **`inbox_dir(run_dir: Path) -> Path`** — returns `<run_dir>/inbox/`.

3. **`scan_inbox(run_dir: Path) -> list[InboxEntry]`**:
   - Returns `[]` if `inbox_dir(run_dir)` does not exist.
   - Reads all `.json` files, sorted by `(mtime, filename)`.
   - Validates required fields: `step_id` (str), `decision` (str, one of approve/retry/abort), `attestor_kind` (str, one of agent/actor), `submitted_by` (str), `submitted_at` (str).
   - `evidence` defaults to `()` if absent or not a list of strings.
   - Malformed/invalid files are logged at `WARNING` level and skipped (no raise).
   - Checks `decision` and `attestor_kind` against allowed values; violations logged and skipped.

4. **`count_pending_inbox(run_dir: Path, *, plan: TaskPlan, events: list[dict], slug: str, project_root: Path, run_id: str) -> int`**:
   - Calls `scan_inbox(run_dir)`.
   - If no entries or `inbox_dir` absent, return `0`.
   - Calls `peek_current_step(plan, events, slug, project_root=project_root, run_id=run_id)`.
   - If `peek.exhausted` or `peek.step is None`, return `0`.
   - If `not isinstance(peek.step, AttestedStep)`, return `0`.
   - Count entries where `entry.step_id == peek.step.id`.
   - This ensures stale entries (wrong step_id) never inflate the `cmd_status` count.

5. **`consume_inbox_entry(run_dir: Path, entry: InboxEntry, *, plan: TaskPlan, events_path: Path, slug: str, projects_root: Path) -> bool`**:
   - Derive `project_root = run_dir.parent.parent`, `run_id = run_dir.name`.
   - Read `events = read_events(events_path)`.
   - Call `peek = peek_current_step(plan, events, slug, project_root=project_root, run_id=run_id)`.
   - **Guard 1**: If `peek.exhausted` or `peek.step is None`, log and `_drain_stale`, return `False`.
   - **Guard 2**: If `not isinstance(peek.step, AttestedStep)`, log and `_drain_stale`, return `False`.
   - **Guard 3**: If `peek.step.id != entry.step_id`, log and `_drain_stale`, return `False` (stale).
   - **Guard 4**: If `entry.decision != "approve"`, log unsupported decision, `_drain_stale`, return `False`.
   - Compute `path_str = STEP_PATH_SEP.join(peek.path_tuple)`.
   - Call `record_inbox_attested(slug=slug, step=peek.step, path_str=path_str, path_tuple=peek.path_tuple, events_path=events_path, run_id=run_id, project_root=project_root, attestor_kind=entry.attestor_kind, attestor_id=entry.submitted_by, evidence=entry.evidence, iteration=peek.iteration, item_id=peek.item_id)`.
   - On success: compute `sha256(json.dumps(<entry-data>))[:16]`, move inbox file to `<run_dir>/inbox/.consumed/<hash>`.
   - Return `True` on success, `False` otherwise.

6. **`consume_pending_inbox(run_dir: Path, *, plan: TaskPlan, events_path: Path, slug: str, projects_root: Path) -> int`**:
   - Calls `scan_inbox(run_dir)`.
   - Iterates entries in order; calls `consume_inbox_entry` for each.
   - **Returns immediately after first successful consumption** (returns 1). Only one entry per `next` call — after consumption the cursor advances, making subsequent same-step entries stale.
   - Returns `0` if no entry consumed.

7. **`_drain_stale(run_dir: Path, entry: InboxEntry, *, reason: str) -> None`**:
   - Helper to move an inbox file to `<run_dir>/inbox/.consumed/.stale/<sha256-hex[:16]>`.
   - Logs the reason at `INFO` level.

**File**: `artagents/core/task/inbox.py` (new)
