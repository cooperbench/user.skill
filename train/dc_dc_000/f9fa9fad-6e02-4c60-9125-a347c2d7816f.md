## The flicker: two effects fighting over `?timeline=` in `VideoEditorPage.tsx`

**File:** `reigh-app/src/tools/video-editor/pages/VideoEditorPage.tsx`

Two `useEffect`s write to the `timeline` URL param and trigger each other:

1. **Strip effect** (lines 206–222): when `timelineId` is set but NOT found in `timelines.data`, it clears `lastTimelineId` in settings and deletes `?timeline=` from the URL.
2. **Restore effect** (lines 224–236): when `timelineId` is empty but `settings?.lastTimelineId` exists, it immediately puts `?timeline=<lastTimelineId>` back.

### The loop
1. You click into the editor — `ToolsPane.tsx:321` / `useGlobalPaneShortcuts.ts:52` seed `/tools/video-editor?timeline=<id>`.
2. Strip effect sees `timelines.data` doesn't yet contain that id (stale cache from previous project, or list still reconciling) → deletes `?timeline=`.
3. Now `timelineId` is null, so the restore effect runs and reads `settings?.lastTimelineId` — which is still the same id because `update('project', { lastTimelineId: undefined })` is async and hasn't committed → re-adds `?timeline=<same-id>`.
4. Back to step 2. Meanwhile the page renders `null` at line 299 whenever `timelineId` is absent, so you see a blank screen.

### Why refresh fixes it
Hard refresh boots directly on the URL with caches cold → React Query and settings finish loading in an order where `timelines.data` already contains the id the first time the strip effect evaluates, so it falls through the "persist" branch at line 211–213 instead of the "delete" branch. Client-side nav loses that alignment.

### Minimal fix (codex's recommendation, which I agree with)
The strip effect at 206–222 is too eager. It shouldn't delete the URL param while state is still settling. Concrete options, cheapest first:

- **Gate on `isFetching`/staleness**: only strip if `!timelines.isFetching && timelines.data` for the *current* `selectedProjectId`. Right now it can act on stale data from a previous project.
- **Single writer**: make the strip effect only persist `lastTimelineId` (don't touch the URL), and let the restore effect be the sole URL writer. If the id is invalid, clear settings and let restore pick `timelines.data[0]?.id`.
- **Await the settings update**: `await update(..., { lastTimelineId: undefined })` before `setSearchParams`, so the restore effect doesn't see the stale `settings.lastTimelineId` on the next render.
