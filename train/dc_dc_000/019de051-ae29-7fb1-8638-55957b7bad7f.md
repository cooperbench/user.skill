        # Implementation Plan: First-Class Conductor Cleanup

## Overview
The current conductor implementation works but has a few leaky boundaries:

- `artagents.conductors.schema` imports shared primitives directly from `artagents.nodes.schema` (`CachePolicy`, `CommandSpec`, `IsolationMetadata`, `NodePort`, `NodeOutput`), so conductors are structurally dependent on nodes even though nodes should stay conductor-blind.
- Built-in conductors use `builtin.*` ids and `kind="built_in"`, but discovery is under `artagents/conductors/curated/`; `load_builtin_conductors()` is empty while `load_curated_conductors()` loads the built-ins.
- `pipeline.py conductors run` requires `--out` unconditionally, even for `builtin.event_talks --dry-run` where the real output is supplied in passthrough args like `ados-sunday-template --out talks.json` or `render --out-dir rendered`.
- Dry-runs already return `ConductorRunResult.planned_commands`, but there is no structured conductor plan object beyond shell command tuples.
- Existing legacy `pipeline.py` and `event_talks.py` flows must remain the execution path. This plan only cleans the conductor/node contract layer and CLI behavior.

## Main Phase

### Step 1: Extract Shared Schema Primitives (`artagents/contracts/schema.py` or `artagents/components/schema.py`)
**Scope:** Medium

1. Create a neutral module for reusable schema primitives currently owned by nodes:
   - `NodePort`
   - `NodeOutput`
   - `CommandSpec`
   - `CachePolicy`
   - `IsolationMetadata`
   - shared constants for port types, output modes, cache modes, isolation modes where useful.
2. Move only neutral dataclasses and common validators/helpers that both node and conductor schemas need. Keep node-only concepts in `artagents/nodes/schema.py`:
   - `NodeDefinition`
   - `ConditionSpec`
   - `GraphMetadata`
   - `NodeValidationError`
   - node command placeholder policy.
3. Preserve backward-compatible aliases from `artagents.nodes.schema` and `artagents.nodes` so existing imports keep working:
   ```python
   from artagents.contracts.schema import CachePolicy, CommandSpec, IsolationMetadata, NodeOutput, NodePort
   ```
4. Update `artagents.conductors.schema`, `artagents.conductors.api`, and `artagents.conductors.__init__` to import neutral primitives from the new shared module instead of `artagents.nodes.schema`.
5. Add focused tests proving identity-compatible aliases still hold:
   - `artagents.nodes.CommandSpec is artagents.contracts.schema.CommandSpec`
   - `artagents.conductors.CommandSpec is artagents.contracts.schema.CommandSpec`
   - existing `NodeSpec` and `ConductorSpec` construction still serializes the same JSON shapes.

### Step 2: Make Built-In Conductor Source Semantics Honest (`artagents/conductors/registry.py`, conductor package files)
**Scope:** Medium

1. Decide on the smallest honest source model without changing public conductor ids:
   - Keep `builtin.hype` and `builtin.event_talks` as ids.
   - Keep `kind="built_in"` for CLI filters and compatibility.
   - Stop treating these as curated folder conductors internally.
2. Implement `load_builtin_conductors()` so it returns the built-in conductor definitions directly from the existing Python modules:
   - `artagents.conductors.curated.hype.conductor.conductor`
   - `artagents.conductors.curated.event_talks.conductor.conductor`
3. Adjust `load_curated_conductors()` so it does not rediscover those built-in packages as curated folder conductors. The cleanest implementation is to skip curated folders whose loaded conductor definitions have `kind == "built_in"` or whose ids start with `builtin.` once they are loaded by `load_builtin_conductors()`.
4. Add explicit metadata on built-in conductor definitions, for example:
   ```python
   metadata={"source": "built_in", "legacy_entrypoint": "pipeline.py"}
   ```
   and similarly for `event_talks.py`.
5. Update registry tests to prove:
   - `load_builtin_conductors()` returns `builtin.hype` and `builtin.event_talks`.
   - `load_curated_conductors()` no longer owns those built-ins.
   - `pipeline.py conductors list --kind built_in` still shows the same ids.
   - no duplicate registration occurs in `load_default_registry()`.

### Step 3: Relax `conductors run --out` Only Where Safe (`artagents/conductors/cli.py`, `artagents/conductors/runner.py`)
**Scope:** Medium

1. Change the CLI parser so `--out` is optional at argparse level.
2. Move required-output validation into `_cmd_run`/runner preparation based on actual need:
   - Required for non-dry-run execution.
   - Required when the conductor runtime or its outputs use `{out}` or derived output path defaults.
   - Required for `builtin.hype`, because the legacy pipeline path always needs an output directory and the runtime injects `--out` when absent.
   - Not required for `builtin.event_talks --dry-run` because it only validates/plans passthrough `event_talks.py` commands and does not need the generic conductor output root.
3. Make `ConductorRunRequest.out` optional only if needed by this validation model:
   ```python
   out: Path | str | None = None
   ```
4. Keep `_placeholder_values()` strict: if a conductor command needs `{out}` and no output was provided, raise a clear `ConductorRunnerError` instead of inventing a default.
5. Add CLI tests for:
   - `pipeline.py conductors run builtin.event_talks --dry-run -- ados-sunday-template --out talks.json` succeeds without generic `--out`.
   - `pipeline.py conductors run builtin.hype --dry-run -- --target-duration 12` still fails clearly without `--out`.
   - command-runtime conductors using `{out}` still fail clearly without `--out`.
   - existing `--out` flows still work unchanged.

7. Add tests for `ConductorRunResult.to_dict()` including structured plan data, while asserting CLI stdout still prints shell commands only.

   - Built-in source metadata is `built_in`; curated/folder/catalog conductor sources remain distinct.
   - `event_talks` dry-run can omit generic `--out` when passthrough args carry the relevant output path.
