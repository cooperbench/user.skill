# Post-Migration Risk Register (Independent)

## Severity: HIGH — watch weekly
1. **Green bootstrap, broken Qwen lane**
   - Failure mode: migration looks done because travel/LTX tests pass, but `qwen_image_*` and `image_inpaint` fail later or load through the wrong path because patch application is explicitly non-fatal.
   - Detection: exact logs `QWEN_LOAD Failed to apply ...` or `WGP_PATCHES Failed (non-fatal): qwen_model_routing, qwen_lora_directory, qwen_inpainting_lora`.
   - Mitigation: make Qwen patch failures startup-fatal on Qwen-capable workers; add one smoke that boots the orchestrator and touches `qwen_image_edit_20B`.
   - Evidence this is real: `source/models/wgp/wgp_patches.py:554-569`; Qwen task types are live at `source/task_handlers/tasks/task_types.py:105-113`; only two patch behaviors are actually lifecycle-tested in `tests/test_wgp_patch_lifecycle.py:11-84`.

2. **LoRA strength changes silently ignored**
   - Failure mode: same LoRA file is reused with a different strength across jobs/segments, but cache identity ignores `lora_multi`, so the old strength stays resident and output looks “wrong” without an exception.
   - Detection: a job that should change strength still logs `[LORA_CACHE] Skipping LoRA reload — same N LoRAs already loaded`.
   - Mitigation: include multipliers in the cache key, or force unload/reload when requested strengths differ.
   - Evidence this is real: `source/models/wgp/wgp_patches.py:429-447`.

3. **New LoRA formats get silently neutered**
   - Failure mode: generation succeeds, but a new fork/upstream LoRA has keys that the tolerance patch strips, so style/control effect disappears instead of failing loudly.
   - Detection: exact `LORA_TOLERANCE` log `Stripping N non-standard/incompatible keys from LoRA...`.
   - Mitigation: review stripped-key samples before accepting new fork bumps or LoRA families; add suffix/prefix coverage instead of silent deletion.
   - Evidence this is real: `source/models/wgp/wgp_patches.py:315-381`.

## Severity: MEDIUM — watch monthly
4. **Runtime startup dirties the submodule**
   - Failure mode: worker boot rewrites `Wan2GP/wgp_config.json`, leaving the submodule dirty and muddying drift review, rebases, and “what changed?” debugging.
   - Detection: `git status --short Wan2GP/wgp_config.json` after a normal worker init.
   - Mitigation: move hygiene to a generated local file or explicitly exempt that file from drift checks.
   - Evidence this is real: `source/models/wgp/orchestrator.py:198-220`.

5. **Patch state overstates rollback safety**
   - Failure mode: `get_wgp_patch_state()` says patches are applied, but only two patches register actual rollback handlers, so emergency rollback is partial.
   - Detection: `get_wgp_patch_state()` shows applied patches while `rollback_wgp_patches()` restores `0` or less than expected.
   - Mitigation: either add rollback handlers for the rest, or stop presenting them as reversible state.
   - Evidence this is real: state registration at `source/models/wgp/wgp_patches.py:571-578`; only rollback helpers at `source/models/wgp/wgp_patches.py:518-533`.

## Severity: LOW — might never fire, but worth naming
6. **Qwen LoRAs become “downloaded but unused”**
   - Failure mode: Qwen handlers download into `Wan2GP/loras_qwen`, but routing back there depends on `"qwen"` appearing in `model_type`; a naming shift falls back to the generic LoRA dir.
   - Detection: LoRA exists under `Wan2GP/loras_qwen`, but runtime behaves as if it is missing; watch for `QWEN_LOAD` directory-check errors.
   - Mitigation: route by resolved model family/base type, not substring match.
   - Evidence this is real: `source/models/model_handlers/qwen_handler.py:76-79,136-154`; `source/models/wgp/wgp_patches.py:205-214`.

## Counter-risks (things the user might over-worry about)
The submodule mount itself is not the scariest part now. The plan already put explicit guardrails around path contract, `ltx_anchor`, `clear_conditioning`, and the travel suite. The tail risk is the headless patch layer: it is broader than the migration matrix, partly non-fatal on failure, and much easier to regress without tripping the migration’s main tests.
