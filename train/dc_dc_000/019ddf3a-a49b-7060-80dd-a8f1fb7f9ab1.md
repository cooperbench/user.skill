        # Implementation Plan: ArtAgents Node Architecture MVP

## Overview
ArtAgents currently has a cache-aware pipeline orchestrator in `artagents/pipeline.py` with a `Step` dataclass, hard-coded `STEP_ORDER`, hard-coded command builders, sentinel-based caching, and subprocess execution (`artagents/pipeline.py:29`, `artagents/pipeline.py:68`, `artagents/pipeline.py:465`, `artagents/pipeline.py:777`, `artagents/pipeline.py:816`). The root `pipeline.py` is only a compatibility launcher, so CLI exposure should be added through `artagents/pipeline.py` while preserving every existing legacy invocation.

The pragmatic MVP is to add a node layer beside the existing orchestrator, not replace the pipeline engine in one sweep. Built-in pipeline stages become discoverable `NodeDefinition`s backed by the existing command builders and cache/sentinel behavior. The new CLI subcommand can list, inspect, validate, and run a single node through the same subprocess/logging isolation path. Graph/condition support should be represented in typed metadata now, with minimal sequential graph validation, while full graph orchestration can evolve later without breaking the schema.

Moirae is a good external boundary fixture because its README describes a terminal-demo video pipeline invoked as `python -m moirae screenplay.yaml -o demo.mp4`, with external prerequisites like `asciinema`, `agg`, and `ffmpeg`. The MVP should include a curated manifest for Moirae but tests must not require cloning it or installing those binaries.

## Phase 1: Define Node Metadata And Validation

### Step 1: Add the node package skeleton (`artagents/nodes/`)
**Scope:** Medium
1. **Create** `artagents/nodes/__init__.py`, `artagents/nodes/schema.py`, `artagents/nodes/registry.py`, `artagents/nodes/builtin.py`, `artagents/nodes/runner.py`, and `artagents/nodes/cli.py`.
2. **Use** stdlib `dataclasses`, `json`, and explicit validators rather than adding Pydantic, because this repo does not currently depend on Pydantic and the MVP does not need a new runtime dependency.
3. **Model** the core typed schema:
   - `NodeDefinition`: `id`, `label`, `kind` (`built_in` or `external`), `version`, `description`, `inputs`, `outputs`, `command`, `cache_policy`, `conditions`, `graph`, `isolation`, `source`.
   - `NodePort`: `name`, `type`, `required`, `default`, `description`, `path_role`.
   - `NodeOutput`: `name`, `type`, `mode` (`mutate`, `create`, `create_or_replace`), `path`, `description`.
   - `CachePolicy`: `sentinels`, `always_run`, `per_brief`, and optional dependency hints.
   - `Condition`: minimal declarative checks such as `requires_input`, `requires_file`, and `skip_when` for built-in discovery and future graph execution.
   - `Isolation`: `subprocess` as the only MVP execution backend, plus `requires_binaries` and `env_passthrough` metadata.
4. **Implement** `validate_node_definition(raw)` and `load_node_manifest(path)` with clear error messages and no defensive coercions beyond JSON parsing.

### Step 2: Add curated external manifest support (`artagents/nodes/curated/moirae.json`)
**Scope:** Small
1. **Create** a packaged curated manifest directory under `artagents/nodes/curated/`.
2. **Add** `moirae.json` describing Moirae as an external wrapped node:
   - input `screenplay` as a required YAML path.
   - optional `output` path defaulting to an MP4 output path supplied at run time.
   - output `video` with `create_or_replace` mode.
   - command template equivalent to `python -m moirae {screenplay} -o {output}`.
   - isolation metadata listing external requirements (`moirae`, `asciinema`, `agg`, `ffmpeg`) but marking tests as manifest-only.
3. **Keep** this as a fixture/curated descriptor, not an installer or clone step, to avoid making ArtAgents tests depend on network access or Moirae binaries.

## Phase 2: Register Built-In Pipeline Stages

### Step 3: Convert existing pipeline step metadata into built-in nodes (`artagents/nodes/builtin.py`, `artagents/pipeline.py`)
**Scope:** Medium

4. **Record** output modes precisely: analysis files are `create_or_replace`, `refine` is `mutate` for timeline/assets/metadata plus `create_or_replace` for `refine.json`, and `pool_merge` is `mutate` for `pool.json`.
