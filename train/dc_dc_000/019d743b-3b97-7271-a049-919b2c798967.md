First of all, what are the different categories of things? For example, dragging an item, moving the edge of it, selecting it, and how should they  actually translate to mobile at a high level?

> AGENT

The right mobile strategy is not “make every desktop gesture work on touch.” It’s to separate `browsing`, `selection`, `editing`, and `precision` so scrolling the timeline stays easy and accidental edits stay rare.

**Interaction Model**
On mobile, the default state should be `navigate`, not `edit`. A finger drag on the timeline should usually mean “scroll,” not “move this clip.” Editing actions should happen only after an explicit selection or mode change.

That usually means:
- `Tap` selects a clip.
- `Second tap` or `Edit` opens clip controls.
- `Drag` on the timeline background scrolls.
- `Drag` on a dedicated handle moves or trims.
- `Long press` is optional for advanced actions, but it should not be the primary path.

**Main Categories**
These are the useful buckets:

- `Navigation`
  Timeline pan, zoom, scrub/playhead movement, jumping between clips.
  Mobile translation: swipe to scroll, pinch or +/- buttons to zoom, tap ruler to seek, large scrub handle.

- `Selection`
  Single select, deselect, maybe multi-select.
  Mobile translation: single tap selects, tap empty area clears, multi-select should be action-based like `Select more` instead of desktop-style modifier keys.

- `Inspection`
  Seeing clip settings, effects, timing, track info.
  Mobile translation: bottom sheet / modal inspector. Don’t keep a permanent side panel.

- `Move / Reorder`
  Shifting a clip in time or moving it to another track.
  Mobile translation: only start move from a visible drag handle or explicit `Move` mode. While dragging, lock the editor into that interaction and auto-scroll the timeline near edges.

- `Trim / Resize`
  Adjusting start/end.
  Mobile translation: big left/right trim handles, magnified feedback, and optional nudge buttons for fine control. Tiny desktop resize edges are not enough.

- `Create / Insert`
  Add text, media, effects, tracks.
  Mobile translation: use floating add buttons and insertion menus, then place with a simplified step like `Add at playhead` or `Add to selected track`.

- `Contextual Actions`
  Delete, duplicate, split, mute, apply effect.
  Mobile translation: action bar or bottom sheet for selected clip. Avoid hidden hover-only actions.

- `Precision Editing`
  Frame-accurate trims, exact timing, exact position.
  Mobile translation: don’t rely only on drag. Offer stepper controls like `-1f / +1f`, time inputs, snapping, and zoomed-in trim mode.

**Recommended Translation Per Action**
- `Select a clip`
  Tap the clip.

- `Open properties/effects`
  Tap selected clip again, or use a top-right `Clip` button.

- `Move a clip`
  Drag a dedicated move affordance, not the whole clip body by default.

- `Trim left/right edge`
  Drag oversized trim handles; also expose fine nudges in the inspector.

- `Split clip`
  Keep as a button: `Split at playhead`.

- `Delete / duplicate / mute`
  Put in a contextual bottom action bar once selected.

- `Move to another track`
  Either drag vertically in move mode or use `Move to track` from a menu if touch drag feels crowded.

**Practical Rule**
Use this priority order on mobile:
1. `Tap to select`
2. `Sheet to inspect/edit`
3. `Handles for direct manipulation`
4. `Buttons for destructive or precise actions`

- `Precision` is inspector-driven: nudge by frame/time, split at playhead, exact duration/start/end edits.
- Never make “dragging the clip body” the default on phone. That causes constant conflict with scroll.

**Interaction Categories**
- `Navigation`: pan timeline, zoom timeline, scrub playhead, jump to selection.
- `Selection`: single select, deselect, optional multi-select.
- `Clip Edit`: move clip, trim edges, split, delete, mute, duplicate.
- `Track Edit`: target track, move clip to track, add/remove track, track settings.
- `Inspector`: effects, timing, position, audio, text.
- `Precision`: frame nudges, numeric fields, snap toggles, zoomed trim.
- `Context`: destructive actions and secondary actions.

**Phone Strategy**
- One primary surface at a time: preview + timeline remain visible, inspector is a bottom sheet.
- Tap clip once: select it and show an action bar plus oversized trim/move affordances.
- Tap selected clip or `Clip` button: open inspector sheet.
- Drag on empty timeline: horizontal scroll.
- Drag on selected clip body: still scroll, not move.
- Move clip only from a visible move handle or `Move` action.
- Trim only from oversized left/right handles on the selected clip.
- Track changes should mostly be menu-based first: `Move to track`, `Add track above/below`.
- Multi-select should not be a v1 phone gesture. Use `Select more` from action mode if needed later.

**iPad Strategy**
- Keep preview and timeline visible together.
- Inspector can be a collapsible side sheet instead of full bottom sheet.
- iPad can support more direct manipulation than phone, but still keep `Browse` as default.
- Allow drag-to-move from selected clip body on iPad only if the clip is already selected.
- Keep trim on explicit handles, not generic edge grabbing.
- Pinch-to-zoom timeline is reasonable on iPad; on phone prefer zoom buttons/slider.
- iPad can add optional marquee/multi-select later, but only after core touch behavior is stable.

**Gesture Mapping**
- `Tap clip`: select.
- `Tap empty space`: clear selection.
- `Tap ruler`: move playhead.
- `Drag ruler/playhead handle`: scrub.
- `Drag timeline background`: pan.
- `Pinch`: zoom timeline on iPad only.
- `Drag move handle`: move clip in time, with edge auto-scroll.
- `Drag trim handles`: trim start/end, with snapping and magnified feedback.
- `Long press`: optional secondary trigger for context menu, not primary editing path.
- `Double tap`: open inspector or zoom to clip; avoid giving it destructive meaning.

**Conflict Rules**
- Scroll must always win unless the touch started on a dedicated editing affordance.
- Only explicit handles enter move/trim capture.
- Selected state should increase hit targets before allowing editing.
- Use a small drag threshold before committing to move/trim.
- While moving/trimming, freeze competing gestures and show strong visual state.
- Auto-scroll near timeline edges during active move/trim only.

**Precision Model**
- Add inspector controls for `start`, `end`, `duration`, `track`, `volume`, `x/y`, etc.
- Add `-1f / +1f` and `-0.1s / +0.1s` nudges.
- Add `Split at playhead` as a button, not a gesture.
- Add a zoomed trim sub-mode for phone if needed before supporting more advanced drag.
- Keep snapping on by default, with a temporary “hold to ignore snap” equivalent only if touch UX stays clear.
