## Overview
Build `scripts/compare_critique.py` — a simple ~100-150 line script that replays critique phase inputs from iteration-007 against multiple models (GLM-5.1 and MiniMax M2.7) to compare their bug-catching ability on 4 known critique failures.

**Trace format** (verified from `results/auto-improve/iteration-007/worker-7/django__django-10999/.../traces/critique_v1.json`):
- JSON array of OpenAI-style chat messages
- Each message has `role`, `content`, and assistants may also have `reasoning`, `finish_reason`, `tool_calls`
- Tool results have `role: "tool"`, `tool_call_id`, `content`
- Final message is the assistant's critique response — we take `messages[0:-1]` as replay input

**Traces located at:**
- `results/auto-improve/iteration-007/worker-8/django__django-10097/.../traces/critique_v1.json`
- `results/auto-improve/iteration-007/worker-7/django__django-10999/.../traces/critique_v1.json`
- `results/auto-improve/iteration-007/worker-6/django__django-10973/.../traces/critique_v1.json`
- `results/auto-improve/iteration-007/worker-2/astropy__astropy-13977/.../traces/critique_v1.json`

**API keys:** GLM from `auto_improve/api_keys.json` (array of `{key, base_url}` objects) or `ZHIPU_API_KEY` env. MiniMax from `OPENROUTER_API_KEY` env.

## Main Phase

### Step 1: Create the script (`scripts/compare_critique.py`)
**Scope:** Medium

1. **Write** the script with this structure (all inline, no classes):
   - **Config block**: Define the 4 tasks with their task IDs, expected keywords from FAILURE_CATALOG, and the glob pattern to find their traces
   - **Trace loading**: `glob.glob("results/auto-improve/iteration-007/worker-*/TASK_ID/*/traces/critique_v1.json")` for each task, load JSON, take `messages[0:-1]`
   - **Message cleaning**: Strip `reasoning` and `finish_reason` keys from assistant messages (these are GLM-specific fields not in the OpenAI spec). Keep `role`, `content`, `tool_calls`, `tool_call_id` only.
   - **Model config**: Two models — GLM-5.1 (`base_url` from api_keys.json or env, `model=glm-5.1`) and MiniMax (`base_url=https://openrouter.ai/api/v1`, `model=minimax/minimax-m2.7`, key from `OPENROUTER_API_KEY`)
   - **API call**: Use `openai.OpenAI(api_key=..., base_url=...)` for each model. Call `client.chat.completions.create(model=..., messages=replay_messages)`. Wrap in try/except for API errors.
   - **Response parsing**: Get `response.choices[0].message.content`. Search the text (case-insensitive) for each keyword from the task's keyword list. Record which keywords were found.
   - **Output**: Write `results/model-compare/critique_comparison.json` with structure: `{task_id: {model: {response: str, keywords_found: [str], keywords_missed: [str]}}}`. Create output dir if needed.
   - **Summary table**: Print a table to stdout showing task × model, with keyword hit count and pass/fail assessment.

2. **Key implementation details:**
   - Use `argparse` minimally: `--dry-run` flag to just show what would be called (print message count per task) without hitting APIs
   - API key loading: try env var first, fall back to `auto_improve/api_keys.json` for GLM (use first key in array)
   - No retry logic needed — if a call fails, print the error and continue
   - Keep response text in output JSON for manual inspection

**Scope:** Small

1. **Run** `python scripts/compare_critique.py --dry-run` to verify trace loading and message cleaning work correctly for all 4 tasks
2. Verify it finds all 4 traces and reports correct message counts
