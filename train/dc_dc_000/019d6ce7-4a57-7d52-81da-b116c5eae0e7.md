This is "cohesion by re-projection," which means: 1. Two parallel data shapes for the same thing. pinnedShotGroups[i].children[j].duration vs clips[k].hold. Any edit that bypasses the projection (a free-clip resize fallback, a stale closure, a missing prop) gets silently reverted because the next projection re-derives from children. 2. Users expect: drag the right edge of the last clip → only that clip's duration changes. The current code shrinks every clip in the group. 5. Three different views of the same data (PinnedShotGroup → ShotGroup → PositionedShotGroup), each with its own filter that can drop the group from view, each with its own slightly different fields.
