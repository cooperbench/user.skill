        # Implementation Plan: Phase 7 Per-Project CAS

## Overview
Phase 7 adds a per-project content-addressable store under `<project_slug>/.cas/<sha256>` for task-mode produced file artifacts. The current produces flow is centralized in `artagents/core/task/gate.py` via `_run_inline_checks()`: it resolves the step directory with `step_dir_for_path()`, runs each `ProducesEntry.check`, and appends `produces_check_passed` / `produces_check_failed` events. Project-attached child runs already mirror hype artifacts into `steps/<step>/produces/` in `artagents/core/project/run.py`, so the CAS hook should preserve that path contract by replacing accepted files with symlinks in place.

The simplest implementation is additive: introduce a small stdlib-only CAS helper, call it only after a produces check passes, and enrich the existing passed event with the CAS hash. No shared CAS, daemon, database, or Phase 8/9 work is needed.

## Main Phase

### Step 1: Add CAS primitives (`artagents/core/task/cas.py`)
**Scope:** Small
1. Implement `cas_path(project_dir, sha256) -> Path` as `Path(project_dir) / ".cas" / sha256`.
2. Implement `intern(project_dir, source_path) -> Path`:
   - stream-hash file bytes with `hashlib.sha256()`;
   - create `<project_dir>/.cas/` as needed;
   - move the first copy into `.cas/<hash>`;
   - if `.cas/<hash>` already exists, unlink the duplicate source and return the existing CAS path.
3. Implement `link_into_produces(cas_path, target_path)` with a relative symlink from `target_path` to the CAS entry, so moved run directories remain portable.
4. Keep helpers focused on file artifacts; directories are outside Phase 7.

### Step 2: Enrich produces events (`artagents/core/task/events.py`)
**Scope:** Small
1. Extend `make_produces_check_passed_event(...)` with optional `cas_hash: str | None = None`.
2. Include `cas_hash` only when a file was actually interned, preserving current event shape for non-interned cases.
3. Do not alter hash-chain mechanics; the existing `append_event()` canonicalization will include the new field automatically.

### Step 3: Wire CAS after successful inline checks (`artagents/core/task/gate.py`)
**Scope:** Medium
1. In `_run_inline_checks()`, after `result.ok` and before appending `produces_check_passed`, intern `artifact_path` under `decision.project_root / ".cas"` through the new helper.
2. Replace the original produce path with a relative symlink to `.cas/<sha256>`.
3. Pass the raw hex hash, derived from `cas_entry.name`, into `make_produces_check_passed_event()`.
4. Leave failure behavior unchanged: failed checks still append `produces_check_failed` and rewind or fail the iteration without touching the artifact.
5. Ensure the logic applies to code, attested, repeat, and nested paths because they already converge through `_run_inline_checks()`.

### Step 4: Confirm project-run artifact mirroring still composes (`artagents/core/project/run.py`)
**Scope:** Small
1. Audit `finalize_project_run()` and `mirror_hype_artifacts()` to ensure copied task-attached artifacts under `steps/<step>/produces/` remain valid once the gate later replaces them with symlinks.
2. Avoid duplicating CAS work in `run.py` unless tests show a real gap; the authoritative acceptance point is the produces check in `gate.py`.
3. Preserve existing run-record artifact paths; they should continue to point at the produce path, which becomes a symlink.

### Step 5: Add focused tests (`tests/test_cas_intern.py`, `tests/test_cas_symlink.py`, `tests/test_cas_per_project.py`)
**Scope:** Medium
1. `tests/test_cas_intern.py`: create a project dir and two files with identical bytes, call `intern()` for both, assert both return the same `.cas/<hash>`, only one CAS file exists, and the duplicate source is gone.
2. `tests/test_cas_symlink.py`: use the existing task inline-check fixture pattern, write a produced file, call `record_dispatch_complete()`, then assert the produce path is a symlink, resolves to `<project>/.cas/<hash>`, and the `produces_check_passed` event includes `cas_hash`.
3. `tests/test_cas_per_project.py`: create two project slugs with identical produced content and assert each project has its own `.cas/<hash>` file with no shared root.
4. Add a reuse assertion in either symlink or per-project coverage: two different steps in the same project producing identical bytes should share one CAS entry.

### Step 6: Ignore generated CAS directories (`.gitignore`, `artagents/structure.py`)
**Scope:** Small
1. Add `.gitignore` entries for `*/runs/*/.cas/` and `**/.cas/` if absent.
2. Leave `artagents/structure.py` unchanged unless implementation uncovers a project-directory whitelist. Current inspection shows it validates repository package layout, not per-project local cache directories.

## Execution Order
1. Add and unit-test `cas.py` first because it is isolated and cheap to validate.
2. Extend the event factory before changing the gate call site.
3. Wire `_run_inline_checks()` after helper behavior is proven.
4. Add full-flow and per-project tests once the gate emits symlinks and `cas_hash`.
5. Update `.gitignore` last because it is independent of runtime behavior.

## Overview
Phase 7 adds a per-project content-addressable store under `<project_slug>/.cas/<sha256>` for task-mode produced file artifacts. The current plan was aimed at the right root cause, but the critique exposed that the produces lifecycle is broader than the first draft captured: `ProducesEntry` exists for code, attested, and nested steps, while the current gate only runs inline checks for code completion and attested approval. The revision keeps the same CAS design but makes the produces acceptance path authoritative and all-or-nothing.

The core change is to centralize successful produces handling in `artagents/core/task/gate.py`: run every produces check for a step first, mutate nothing if any check fails, and only then intern accepted files into the per-project CAS and replace produce paths with relative symlinks. Nested produces are included because `NestedStep.produces` is part of the current plan model and design examples. Duplicate produce paths are rejected at validation time because one file needing multiple checks should use `all_of`, and allowing duplicate paths conflicts with move-then-symlink CAS semantics.

No shared CAS, daemon, database, Phase 8 inbox, or Phase 9 golden-test work is included.

## Overview
Phase 7 adds a per-project content-addressable store under `<project_slug>/.cas/<sha256>` for task-mode produced file artifacts. The critique does not show that the CAS approach is targeting the wrong root cause; it shows that the root cause includes two task-run lifecycle boundaries: produces acceptance must be all-or-nothing, and nested produces must be committed only by a mutating gate path, never by read-only cursor simulation.

The plan therefore keeps the CAS design but tightens the insertion points. Successful produces handling will be centralized in `artagents/core/task/gate.py`: run every produces check for a step first, mutate nothing if any check fails, then intern accepted files into the per-project CAS and replace produce paths with relative symlinks. Nested produces remain in Phase 7 scope because `NestedStep.produces` already exists and design examples declare nested outputs, but the implementation must not put CAS work into any helper used by `peek_current_step()`, `cmd_status`, `cmd_next`, or `cmd_ack` in read-only mode.

No shared CAS, daemon, database, Phase 8 inbox, or Phase 9 golden-test work is included.
