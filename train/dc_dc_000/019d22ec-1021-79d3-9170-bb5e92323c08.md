        # Implementation Plan: Editor + Generations Pane Coexistence

## Overview

**Goal:** When editor and generations panes are both visible, they share the viewport without overlapping. Editor takes 90% when alone, shrinks when generations is also visible. Each pane's control handle stays inside its own pane boundary.

**Current behavior (broken):**
- `editorPaneHeight` is fixed at `90% viewport` regardless of other panes (`PanesContext.tsx:100`)
- Only generations adapts via `effectiveGenerationsPaneHeight` (`PanesContext.tsx:124-126`), capping to `max(viewport - editorHeight, 120px)`
- On a 600px viewport: editor=540px + generations=120px = 660px → **60px overlap**
- Control handles position via `translateY(dimension - 44)` — they sit at the edge of their pane, but with overlap they can collide

**Fix approach:** Introduce a budget-based allocator in PanesContext that distributes `window.innerHeight` between both panes when coexisting, with a guaranteed conservation rule: `effectiveEditorHeight + effectiveGensHeight <= viewport` in all cases. Add `effectiveEditorPaneHeight` to the context and wire it through EditorPaneTab and LayoutMainContent.

**Test baseline status:** Existing tests are stale — written against a previous 0.75 editor multiplier and aspirational paddingTop logic. Step 1 reconciles them before any feature work to establish a true green baseline.

## Phase 2: Core Logic

### Step 2: Add budget-based pane allocator to PanesContext (`src/shared/contexts/PanesContext.tsx`)
**Scope:** Medium — core logic change

1. **Add** `effectiveEditorPaneHeight` to `PanesContextType` interface (after line 18) and `PaneLayoutContextType` (line 61-71).
2. **Replace** the current independent height logic (lines 99-126) with a budget-based allocator that enforces `effectiveEditor + effectiveGens <= viewport`:
   ```ts
   const EDITOR_VIEWPORT_RATIO = 0.9;
   const MIN_GENS_HEIGHT = 120;
   const MIN_EDITOR_HEIGHT = 200;

   const editorPaneHeight = Math.round(window.innerHeight * EDITOR_VIEWPORT_RATIO);
   const editorVisible = locks.editor || isEditorPaneOpenState;
   const gensVisible = locks.gens || isGenerationsPaneOpenState;

   let effectiveEditorPaneHeight = editorPaneHeight;
   let effectiveGenerationsPaneHeight = generationsPaneHeight;

   if (editorVisible && gensVisible) {
     const budget = window.innerHeight;
     if (editorPaneHeight + generationsPaneHeight <= budget) {
       // Both fit at ideal sizes — no adjustment needed
     } else if (budget >= MIN_EDITOR_HEIGHT + MIN_GENS_HEIGHT) {
       // Shrink editor to fit. Give gens its configured height (clamped to leave editor its minimum).
       effectiveGenerationsPaneHeight = Math.min(generationsPaneHeight, budget - MIN_EDITOR_HEIGHT);
       effectiveEditorPaneHeight = budget - effectiveGenerationsPaneHeight;
     } else {
       // Degraded: viewport too small for both minimums.
       // Proportional split preserving the minimum ratio.
       effectiveEditorPaneHeight = Math.round(budget * (MIN_EDITOR_HEIGHT / (MIN_EDITOR_HEIGHT + MIN_GENS_HEIGHT)));
       effectiveGenerationsPaneHeight = budget - effectiveEditorPaneHeight;
     }
   } else if (editorVisible) {
     // Editor alone — keep 90%, no change to gens
   } else if (gensVisible) {
     // Gens alone — keep configured height, no change to editor
   }
   ```
3. **Expose** `effectiveEditorPaneHeight` in `layoutValue` memo (line 165-188), and add it to the dependency array.
4. **Key invariant:** When both visible, `effectiveEditorPaneHeight + effectiveGenerationsPaneHeight <= window.innerHeight`. Always. No exceptions.
