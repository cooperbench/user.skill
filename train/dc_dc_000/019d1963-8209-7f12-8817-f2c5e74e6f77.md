Critical constraints:
- Every frozen CSS class (`.card`, `.dashboard`, `.loading-element`, `.video-card`, `.filter-btn`, `.square-image-container`, etc.) MUST appear as className props — legacy JS queries these by class name

1. Extract each card from HOME_BODY_HTML into a typed component

4. Dashboard component maps over card data, renders appropriate card component

## Phase 3: React Query + Supabase Data Layer

Goal: Replace ad-hoc fetch patterns with a proper caching data layer.

### Step 3.1: Install and Configure

Install @tanstack/react-query and @supabase/supabase-js as npm dependencies.

- `src/lib/supabase-client.ts` — Create typed Supabase client singleton from window.__APP_CONFIG__ (client) or env vars (server)
- `src/lib/query-client.ts` — Create QueryClient with sensible defaults (staleTime: 5min, gcTime: 30min)
- Wrap app in QueryClientProvider in both entry-client.tsx and entry-server.tsx

### Step 3.2: SSR Data Hydration Strategy

React Query supports SSR hydration:

1. Server prefetches data into QueryClient, dehydrates to JSON
2. Client receives dehydrated state, hydrates QueryClient
3. No double-fetch on initial load

Changes to server.ts:
- Create per-request QueryClient
- Prefetch route data using queryClient.prefetchQuery()
- Dehydrate: dehydrate(queryClient) injected as window.__REACT_QUERY_STATE__
- Client: wrap app in HydrationBoundary with dehydrated state

This replaces the current window.__INITIAL_DATA__ pattern.

### Step 3.3: Query Hooks

- `src/hooks/usePosts.ts` — useQuery for posts list with draft=false filter, ordered by date desc
- `src/hooks/usePost.ts` — useQuery for single post by slug with markdown rendering
- `src/hooks/useMeasurements.ts` — useQuery for weight measurements with pagination
- `src/hooks/usePostNavigation.ts` — Derives prev/next from usePosts query cache (no separate fetch)

### Step 3.4: Migrate Pages

- PostsPage.tsx — Replace useState/useEffect/fetch with usePosts(). Remove initialData prop.
- PostPage.tsx — Replace manual fetch with usePost(slug) + usePostNavigation(slug). Loading/error states from React Query.
- WeightsChart.tsx — Replace manual pagination fetch with useMeasurements()
- Delete window.__INITIAL_DATA__ injection pattern from server.ts and entry-client.tsx

### Step 3.5: Remove Old Data Fetching

- Delete src/lib/posts.ts (SSR fetch logic)
- Delete src/lib/local-posts.ts (local markdown fallback)
- Delete src/lib/supabase.ts (raw REST helper — replaced by Supabase client)

## Phase 4: Re-enable React StrictMode

Goal: Client-side StrictMode enabled without double-mount bugs.

### Step 4.1: Enable StrictMode

Add React.StrictMode wrapper in entry-client.tsx around the BrowserRouter and HydratedApp.

### Step 4.2: Fix Double-Mount Issues

StrictMode in development will mount, unmount, and remount every component. This will surface:

- Canvas animations: Ensure useEffect cleanup tears down animation loop, clears canvas
- Chart.js: Ensure chart is destroyed on cleanup, re-created on mount
- Event listeners: All must be added in useEffect and cleaned up in return function
- Scroll observers: ResizeObserver, MutationObserver, IntersectionObserver — all must disconnect on cleanup
- React Query: Already StrictMode-compatible by design

Approach: Enable StrictMode, run full Playwright suite in dev mode, fix any visual glitches or console warnings.

- No console warnings about missing cleanup

## Step 24: SSR Hydration Migration (`src/server.ts`, `src/entry-client.tsx`)
**Scope:** Large

`window.__INITIAL_DATA__` is not just a data dump — it's part of the SSR routing contract: `App.tsx` passes it as props, `entry-client.tsx` reads it on hydration, `server.ts` builds it per request. Migration in three deployable sub-steps:

**24a — Add React Query alongside existing pattern:**
- Server creates per-request `QueryClient`, prefetches route data via `prefetchQuery()`.
- `dehydrate(queryClient)` injected as `window.__REACT_QUERY_STATE__` (NEW, alongside existing `__INITIAL_DATA__`).
- Client wraps app in `<HydrationBoundary>`. Both patterns coexist. Deploy gate: site works identically.

**24b — Migrate pages one at a time** (Step 25):
- Each page switches from `initialData` prop to React Query hook.
- `CryptoConversationPage` already uses `useParams()` (from Step 7).

**24c — Remove old pattern:**
- Once all pages use hooks: remove `initialData` prop threading from `App.tsx`.
- Remove `window.__INITIAL_DATA__` injection from `server.ts` and reading from `entry-client.tsx`.
- `window.__APP_CONFIG__` stays (Supabase configuration, not data).
