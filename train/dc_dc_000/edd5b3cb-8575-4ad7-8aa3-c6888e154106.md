        # Implementation Plan: Phase 9 — Author Test with Golden Runs

## Overview

Phase 9 turns the existing `artagents author test` scaffold (`artagents/orchestrate/cli.py:311-371`) into a real runtime replay path: it must drive a compiled task plan to completion in a scratch directory with auto-approval on all attested steps, normalize the resulting `events.jsonl`, and diff against `<pack>/golden/<fixture>.events.jsonl`. The kernel pieces it needs (gate, peek, ack synthesis, inline produces checks, hash chain) all already exist (`artagents/core/task/{gate.py,events.py,lifecycle.py,lifecycle_ack.py}`); the new code is the test-mode driver, an env-gated identity bypass for auto-approval, an event normalizer, and one canonical fixture/golden under `artagents/packs/builtin/hype/`.

Key design decisions:

- **Code steps in author-test are simulated, not subprocess-executed.** The driver writes `step_dispatched`, copies fixture-supplied stub artifacts into the step's produces dir, then calls `record_dispatch_complete(decision, 0)` which runs the inline produces checks and writes `step_completed`. This keeps tests fast/deterministic and matches the design-doc `--dry-run --auto-approve` framing in §10.
- **Auto-approval identity.** A new env-gated bypass inside `validate_attested_identity` (`artagents/core/task/gate.py`) accepts a synthetic `--actor author_test` / `--agent author_test` when `ARTAGENTS_AUTHOR_TEST=1`, skipping `ARTAGENTS_ACTOR` match and self-ack checks. The synthetic ack writes `source=author_test` into the `step_attested.evidence` list — no event-schema change needed.
- **Hash-chain volatility.** The normalizer **strips** `hash` entirely (also `ts`, `run_id`, `attestor_id`, `child_plan_hash`, and rewrites the absolute project root to `<RUN_DIR>`). Keeps kind/plan_step_id/plan_step_path/returncode/check_id/produces_name/attestor_kind/evidence/reason/iteration/item_id/max_iterations/on_exhaust/cas_sha256.
- **DSL produces syntax** (FLAG-001 fix): the DSL accepts a bare `Check` (path defaults to the produces name) or a `(check, path)` tuple — see `artagents/orchestrate/dsl.py:317-332`. The hype.py DSL must use the bare-Check form (`json_file()`) or the tuple form (`(json_file(), "transcript.json")`), NOT `json_file("transcript.json")`.
- **Missing-golden semantics** (FLAG-002 fix): when the golden file is absent and `--regenerate` is NOT passed, `_cmd_test` returns 1 with a clear message pointing at the regenerate flag. With `--regenerate`, the golden is created.
- **Nested steps** (FLAG-004 fix): the test driver explicitly raises `NotImplementedError` if peek surfaces a non-Code/non-Attested step kind, so author-test on plans with as-yet-unsupported kinds fails loudly rather than looping silently.
- **Existing `tests/test_author_test_scaffold.py`** asserts the Phase-9-deferred message and is deleted (its surface is fully covered by the four new tests).
- **Canonical hype.py DSL**: a new `artagents/packs/builtin/hype/hype.py` is added beside the legacy `orchestrator.yaml`/`run.py` (additive, both keep loading). It uses real `python3 -m artagents executors run builtin.<x>` argv per design §13, but author-test never executes that argv — it materializes produces from fixture stubs. The smoke fixture orchestrator omits `nested` steps to stay within the driver's supported kinds.


     - Source candidate: `fixture_dir/"produces"/<step_path_segment_join>/entry.path` where `step_path_segment_join = "/".join(peek.path_tuple)`.
