**What Exists** DataClaw has per-run identifiers and structured event logs for auto runs. `dataclaw/logging.py` writes daily JSONL logs under `~/.dataclaw/logs/auto-YYYY-MM-DD.jsonl`, with `run_id`, `phase`, and `extra` fields. Auto mode logs discovery, export, PII scan, privacy filter progress, push attempts, retries, remote manifest checks, and finish/error states. Local run directories are created under `~/.dataclaw/staging/<run_id>` and successful runs are moved to `~/.dataclaw/staging/published/<run_id>`. Each sharded export writes `.dataclaw/manifest.json` with: - `export_id`, `started_at`, `finished_at` - shard list with `path`, `source`, `date`, `sessions_new`, `sessions_total`, `bytes` - `sources`, `buckets`, `models` - `total_sessions_new`, `total_sessions_in_shards`, `total_redactions` - `max_end_time_by_source` - `include_thinking`, `merge_source` Auto push success/failure writes `RUN_SUMMARY.json` into the run directory with `run_id`, start/finish timestamps, result, total new sessions, staging dir, and push retry fields when relevant. Config stores only the latest run/update state: `last_auto_run`, `last_dataset_update`, and `last_export_cutoff`. `last_dataset_update` captures repo, URL, sources, shard count, session counts, manifest export id, manifest finish time, and cutoff-style max end times.
