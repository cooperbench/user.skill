Two root causes: **Hang (60+ seconds):** `gossamer clean` calls `Command::new("entire").arg("clean").arg(session_id).status()` and blocks waiting for it to finish. If you have `entire` installed, the real binary runs — possibly making network calls or doing git work before exiting. The `clean` test was stuck here. **Garbled output:** `entire` can print ANSI-colored progress output to its stdout, which gossamer inherits (since it just calls `.status()` without redirecting the subprocess's I/O). That output reaches the terminal directly, corrupting what cargo test is showing. **Fix:** `TestEnv` now creates a temp directory containing a one-line `entire` stub (`#!/bin/sh\nexit 0`) and prepends it to `PATH` for every gossamer subprocess. The real `entire` is never reached. Same fix covers any other gossamer command that shells out to `entire` (`init` wizard, `attach`).
