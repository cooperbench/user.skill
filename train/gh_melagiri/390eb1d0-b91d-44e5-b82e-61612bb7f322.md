`★ Insight ─────────────────────────────────────`
**Cross-cutting agent integration pattern**: The LLM Expert follows a "conditional participation" pattern — it's wired into the ceremony infrastructure but only activates when LLM code is touched. This is different from the TA (always participates) or devtools-cofounder (on-demand, no ceremony role). The key design choice was making it a **Phase 1 parallel reviewer** rather than a sequential gate, so it doesn't add latency to reviews that don't need it.

**TA as synthesis authority**: Even with a 4th reviewer, the TA remains the single synthesizer. This avoids the "too many cooks" problem — all review findings funnel through one authority who can AGREE or PUSHBACK with domain context. The LLM Expert's findings get the same treatment as outsider comments.
