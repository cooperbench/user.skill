## Security Audit: CLI → Supabase Connection

`★ Insight ─────────────────────────────────────`
The codebase migrated to local-first (SQLite) in v3.0.0. The **only remaining Supabase touchpoint** is a single Edge Function endpoint at `telemetry.ts:8` used for anonymous usage stats. There are no Supabase client libraries, no anon keys, no auth, and no RLS — just a raw `fetch()` POST.
`─────────────────────────────────────────────────`

---

### Current State

**Endpoint:** `cli/src/utils/telemetry.ts:8`
```
POST https://xrbkoqjfolxiyfxubiom.supabase.co/functions/v1/cli-telemetry
```

**No authentication headers sent.** The Edge Function accepts unauthenticated POSTs from any CLI installation. No `Authorization: Bearer <anon-key>`, no API key, nothing.

### Security Findings

#### CRITICAL — Open write endpoint with no auth

| # | Issue | Severity | Location |
|---|-------|----------|----------|
| 1 | **No authentication on the Edge Function** — anyone who discovers the URL can POST arbitrary data to your Supabase table | Critical | `telemetry.ts:315` |

| 3 | **No rate limiting** — an attacker can flood the endpoint with garbage events, poisoning your analytics and potentially exceeding Supabase free tier quotas | High | Edge Function (server-side) |
| 4 | **No payload validation on client side** — while the `buildEvent()` function constructs valid events, the endpoint itself must validate since anyone can call it | High | Edge Function (server-side) |
| 5 | **Supabase project ID exposed in URL** — `xrbkoqjfolxiyfxubiom` is visible in the compiled JS distributed via npm | Medium | `telemetry.ts:8` |

### What the Edge Function MUST Enforce (Server-Side)

Since the client is untrusted (any npm user has the URL), **all security must live on the Edge Function**. Here's what standard measures look like:

**1. Payload Schema Validation**
```
Reject anything that doesn't match the TelemetryEvent shape exactly.
Enforce field lengths, enum values, and types. Drop unknown fields.
```

**2. Rate Limiting (per IP or per machineId)**
```
- Per IP: max ~60 events/minute (generous for real CLI usage)
- Per machineId: max ~20 events/minute
- Return 429 on excess; attacker can't poison your dataset
```

**3. Request Signing (HMAC)**
```
CLI sends: X-Signature: HMAC-SHA256(payload, embedded-secret)
Edge Function verifies signature before accepting.
Not bulletproof (secret is in npm package), but raises the bar
significantly — casual abuse becomes non-trivial.
```

**4. Row-Level Security on the Supabase Table**
```
Even though the Edge Function writes (not the client directly),
RLS on the underlying table adds defense-in-depth:
- INSERT only (no SELECT, UPDATE, DELETE from anon role)
- Column-level constraints (enum checks, string length limits)
```

**5. Anomaly Detection / Deduplication**
```
- Flag machineIds sending >N events/day
- Deduplicate identical events within a window
- Monitor for payload patterns that don't match real CLI behavior
```

**6. Rotate/Scope the Edge Function URL**
```
- Use a versioned path: /functions/v1/cli-telemetry/v1
- Allows deprecating a compromised endpoint without breaking old CLIs
```
