## Code Review: `attach-session-id` branch

**Overall**: Well-structured feature that adds an `entire attach` command for importing existing agent sessions. The decomposition is clean, tests are thorough, and the refactoring (trailer dedup, lifecycle backfill consolidation) is sensible.

### Issues

**1. `condenseAndFinalizeSession` takes `*strategy.ManualCommitStrategy` directly** (`attach.go:315`)

The comment explains why, but this couples the attach command to a specific strategy implementation. If another strategy is added, this will silently break. Consider adding `CondenseSessionByID` to the `Strategy` interface, or at minimum add a type assertion with a clear error message rather than relying on `GetStrategy()` always returning `*ManualCommitStrategy`.

**2. `promptAmendCommit` uses `exec.CommandContext` for `git commit --amend`** (`attach.go:453`)

This silently amends commits. If the user has pre-commit hooks, `--amend --only` will still trigger them, which could fail or have side effects. The `--no-gpg-sign` flag is also missing — per CLAUDE.md, the codebase normally disables GPG in tests, but this runs in production. If the user has commit signing configured, the amend will prompt for a GPG passphrase, which may not work in non-interactive contexts (e.g., `--force` mode).

**3. `IsTrailerLine` has a false positive** (`trailers.go:260-262`, `trailers_test.go:63-65`)

The test acknowledges `"error: connection refused"` matches as a trailer. The regex `^[A-Za-z][A-Za-z0-9-]*: ` treats any `Word: ` pattern as a trailer. This is inherent to the approach but worth noting — `AppendCheckpointTrailer` could incorrectly detect body text as a trailer block if a paragraph ends with a line like `"Note: this is important"`. The heuristic requiring a blank line above mitigates this for most cases but isn't bulletproof.

**4. `resolveAgentAndTranscript` returns the original error, not the detection error** (`attach.go:191`)

When auto-detection fails, it returns `err` (the original resolve error for the specified agent), not `detectErr`. This means the user sees "transcript not found for agent claude-code" even when the real issue is "transcript not found for any agent." The original error is arguably more useful, but it could be confusing when `--agent` was wrong and auto-detection was the intended path.

**5. `searchTranscriptInProjectDirs` depth calculation** (`transcript.go:56-69`)

The depth calculation uses `strings.Count(filepath.Separator)` which counts path separators. On systems with trailing slashes or double separators, this could be off-by-one. `filepath.Clean` handles double separators but not trailing ones from `WalkDir`. Probably fine in practice but fragile.

### Nits

- `attach.go:88` — `GetGitAuthor` is called but the author info is only used for `StepContext`. If the step doesn't require author info (transcript-only checkpoint), this is wasted work + an unnecessary error path.
- `attach_transcript.go:46` — `extractTranscriptMetadata` falls through to Gemini format when JSONL parsing succeeds but finds zero turns. This is correct but a JSONL transcript with no user messages (edge case: only tool_result messages) would incorrectly try Gemini parsing.
- `attach_test.go:480-534` and `536-590` — `TestAttach_CursorSuccess` and `TestAttach_FactoryAIDroidSuccess` are nearly identical. Could be a table-driven test to reduce duplication.

### Good Patterns

- Extracting trailer logic to `trailers/` package and deduplicating with `manual_commit_hooks.go` is a clean refactor
- The `transcriptMetadata` struct for single-pass extraction is nice
- Consolidating the backfill logic in `lifecycle.go` to a single `LoadSessionState` call is a good simplification
- Test coverage across agents (Claude, Gemini, Cursor, Factory AI Droid) with both flat and nested layouts
- `NormalizeTranscript` operating on raw JSON to preserve unknown fields is the right call
