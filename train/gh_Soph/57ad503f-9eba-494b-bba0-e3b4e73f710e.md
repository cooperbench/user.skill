how would we differentiate between worktrees?

> AGENT

That's a good catch. `refs/stash` (and `.git/logs/refs/stash`) is shared across all worktrees. If worktree A stashes `auth.go` and worktree B has `auth.go` in its carry-forward, you'd get a false "keep alive" signal for worktree B. A few options: 1. **Check the stash entry's parent commit.** Each stash entry's first parent is the HEAD at stash time. If that parent is on the same branch / matches the session's base commit, it's likely from the same worktree. But "likely" isn't great. 2. **Accept false positives.** If any stash entry overlaps with carry-forward files, keep it alive regardless of worktree. Worst case: carry-forward lingers until the stash is popped/dropped, then gets cleaned up on next check. For the "stash is empty" path this isn't an issue — an empty stash is empty for all worktrees. 3. **Don't use the stash reflog at all for the worktree-aware case.** Only do the working-tree-clean check (which is inherently worktree-scoped), and treat "stash exists with overlapping files" as a conservative "don't end yet." In multi-worktree setups, the false positive just means carry-forward lives a bit longer — it still gets cleaned up by the 7-day timeout or Option B's session-start cleanup.
