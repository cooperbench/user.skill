> DEVELOPER

what is "count=1" doing?

> AGENT

`-count=1` disables Go's test result caching.

By default, Go caches test results and skips re-running tests if the code hasn't changed. This is great for unit tests, but problematic for E2E tests that call external services (like Claude) because:

- The test might pass/fail based on external factors (API availability, rate limits, model behavior changes)
- You want to actually run the test each time to verify the real integration works

With `-count=1`, Go will always execute the tests fresh instead of returning cached "ok" results from previous runs.

That said, since you mentioned E2E tests don't run in CI anyway, this is mainly a convenience for local development - ensuring `mise run test:e2e` actually runs the tests rather than saying "cached". If you think caching is fine (e.g., you'd just delete the cache manually when needed), I can remove it.
