<title>Fix watch mode — run claude directly in tmux pane</title>
<description>
## What

When `drain-cycle` runs with `--watch`, open a tmux pane that runs the claude session directly, instead of tailing a log file.

## Why

The current `--watch` implementation was built incorrectly. It opens a tmux pane that runs `tail -f` on an intermediate log file produced by an internal formatter. This means the operator sees a processed, filtered view of activity rather than the actual claude process. The intended behavior is for the watch pane to *be* the claude session — operators should see claude working in real time, not a secondhand summary.

## Acceptance Criteria

1. Running `drain-cycle --watch` opens a tmux split pane per issue that shows the live output of the `claude` process (stream-json events scrolling) rather than a `tail -f` of a log file.
2. drain-cycle still parses the stream-json output in the background for usage tracking, cost accounting, and breach detection — with the same fidelity as today.
3. If tmux is not available or pane creation fails, drain-cycle falls back to normal (non-watch) subprocess execution without crashing.
4. Pane lifecycle is preserved: the previous issue's pane is closed when the next issue starts; the final issue's pane is left open for scrollback.
5. The intermediate watch log file and the `_WatchWriter` formatter are removed — no unused artifacts remain.
6. All existing tests pass; watch-mode tests are updated to reflect the new behaviour.

## How

**Mechanism:** Replace the `tail -f <watch.log>` pane command with the full `claude -p ...` invocation piped through `tee <fifo>`. A named pipe (FIFO) connects the pane's claude process to drain-cycle's stream-json reader, which opens the FIFO instead of a subprocess pipe. The pane's terminal receives the tee'd output (stream-json scrolling); drain-cycle's reader thread processes the same bytes from the FIFO.

**Key changes:**

* `orchestrator._open_watch_pane`: accepts `(argv, cwd)` instead of a log-file path; creates a FIFO, runs `claude ... | tee <fifo>` in the split pane, returns `(pane_id, fifo_path)`.
* `orchestrator._drain_one_issue`: opens the FIFO with a 10-second startup timeout (non-blocking select); passes the file object and a `kill_fn` to the worker instead of a watch log path; falls back to the normal subprocess path on timeout.
* `worker.run_issue`: gains `external_stream` and `kill_fn` parameters; when `external_stream` is set, skips `subprocess.Popen` and reads from the stream directly; breach kills call `kill_fn()` instead of `kill_process_group`.
* `worker._WatchWriter` and `runlog.watch_path()` are deleted.
* Tests in `test_orchestrator_watch.py` updated to assert the new pane command shape and worker call signature.

94	def _resume_attempts(cycle_id: str, identifier: str) -> int:
95	    """Count prior halted attempts for ``identifier`` across this cycle's run logs.
96	
97	    Globs ``~/.drain-cycle/runs/<cycle_id>-*.json`` and tallies entries
98	    whose ``issue_identifier`` matches and whose ``final_linear_state``
99	    is not ``"Done"`` — the same shape every halt path writes. The
100	    orchestrator compares this against ``limits.max_resume_attempts``
101	    before spawning, so a perma-stuck issue stops consuming attempts
102	    once its budget is spent.
103	
104	    Unreadable, unparseable, or shape-corrupted log files are skipped
105	    rather than failed: a partial-write file from a SIGKILL'd earlier
106	    run, or a file whose ``entries`` is missing/null/non-list, must
107	    not pin the operator out of running the cycle. The shape checks
108	    are isinstance-guarded so a JSON file that parses but doesn't
109	    match :class:`RunLog`'s on-disk schema is treated as opaque rather
110	    than crashing the helper.
111	    """
112	    count = 0
113	    for path in runlog.runs_dir().glob(f"{cycle_id}-*.json"):
114	        try:
115	            payload = json.loads(path.read_text())
116	        except (OSError, json.JSONDecodeError):
117	            continue
118	        if not isinstance(payload, dict):
119	            continue
120	        entries = payload.get("entries")
121	        if not isinstance(entries, list):
122	            continue
123	        for entry in entries:
124	            if not isinstance(entry, dict):
125	                continue
126	            if (
127	                entry.get("issue_identifier") == identifier
128	                and entry.get("final_linear_state") != "Done"
129	            ):
130	                count += 1

293	    limits: Limits,

303	    issue reached Done (the caller then runs the cycle-wide circuit breaker and
304	    proceeds to the next issue), or an exit code when the run must halt.
305	    ``pane_id`` is the tmux pane ID opened for this issue (or ``None``).
306	    Each halt path is also marked on the span with a static ``exception.slug``.

277	    proc: subprocess.Popen[str],
278	    accumulator: _UsageAccumulator,
279	    *,
280	    started: float,
281	    token_limit: int | None,
282	    time_limit_seconds: float | None,
283	    poll_interval_seconds: float,
284	) -> Breach | None:
285	    """Wait for the session, returning the per-issue cap it breaches (if any).
286	
287	    With both caps off there is nothing to watch for, so we block on the
288	    process directly. Otherwise we wake every ``poll_interval_seconds`` to
289	    compare the live cumulative-token tally and elapsed wall-clock against
290	    the caps; the first crossed cap is returned for the caller to kill on.
291	    Returns ``None`` when the session exits on its own first.
292	    """

306	        if time_limit_seconds is not None:

## What I did

Rebuilt `--watch` so the tmux pane *is* the claude session instead of a `tail -f` of a formatted log.

**Mechanism:** the orchestrator opens a split pane running `claude … | tee <fifo>`; drain-cycle reads the same stream-json bytes off the FIFO. One claude process, two consumers (the operator's terminal and the usage parser) — so accounting is byte-for-byte identical to the normal path.

**Key changes:**
- `worker.build_argv()` — extracted shared argv assembly for both spawn paths.
- `worker.run_issue()` gained `external_stream` / `kill_fn`: skips `Popen` when given a stream, and breaches call `kill_fn` (tmux kill-pane) instead of a process-group SIGKILL. `_monitor` is now process-agnostic via a `wait` predicate (`proc.wait` or reader-EOF).
- `orchestrator` opens the FIFO `O_RDONLY|O_NONBLOCK` with a 10 s `select` startup window; on timeout / pane failure / no `$TMUX` it tears the pane down and falls back to a normal subprocess spawn. Pane lifecycle preserved (`; exec $SHELL` keeps the final pane's scrollback).
- Deleted `_WatchWriter` and `runlog.watch_path()` — no intermediate log.

**Verification:** all 233 tests pass; rewrote `test_orchestrator_watch.py` (FIFO-pane handshake, lifecycle, fallback) and the worker tests (external-stream path, `build_argv`, `kill_fn`). Empirically verified the macOS FIFO + `select` semantics the whole design rests on before committing.
