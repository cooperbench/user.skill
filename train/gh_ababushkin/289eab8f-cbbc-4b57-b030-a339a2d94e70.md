Plan clear. Add iTerm2 cask + config. Two config approaches — want to confirm before writing:

**A.** Ship full `com.googlecode.iterm2.plist` in repo, point iTerm2 at it via `PrefsCustomFolder`. Pro: everything tracked (font, colors, profile). Con: opaque blob, overwrites any manual tweaks.

**B.** `defaults write` only tmux-critical flags (true-color/mouse/quit-prompt/option-as-meta/FiraCode Nerd Font on default profile). Pro: minimal, diffable. Con: profile dict edits are finicky via `defaults`.

Prefer B? Or want A with a tracked plist?

> DEVELOPER

which is the best

> AGENT

**A** best for dotfiles.

Why: iTerm2 profile = big nested dict in array. `defaults write` on nested keys = brittle, verbose, breaks on iTerm2 schema bumps. Plist + `PrefsCustomFolder` = iTerm2-official pattern, survives upgrades, one source of truth.

Tradeoff: plist is XML (readable, diffable) but big. Manual UI tweaks need re-export to repo. Fine for dotfiles workflow.

Proceed A?

> DEVELOPER

how would i re-export to the repo

> AGENT

Two ways:

**Auto (recommended):** iTerm2 → Settings → General → Preferences → "Load preferences from custom folder" = `~/src/dotfiles` + check "Save changes to folder when iTerm2 quits". Every quit writes `com.googlecode.iterm2.plist` back to repo. Just `git diff` + commit.

**Manual:** Same panel, uncheck auto-save. Click "Save Current Settings to Folder" button when you want snapshot. Or CLI: `defaults export com.googlecode.iterm2 ~/src/dotfiles/com.googlecode.iterm2.plist`.

Install script sets `PrefsCustomFolder=~/src/dotfiles` + `LoadPrefsFromCustomFolder=true` via `defaults write` before first launch. iTerm2 picks up plist from repo on boot.
