Intended outcome: one invocation can drain a cycle whose issues touch any subset of the operator's repos, with each issue's agent landing in the correct tree. ## Decisions 1. **Encoding** — Linear label `repo:<name>` on each issue. Title-prefix considered but adds clutter to every title. Project-affected-repos inheritance ambiguous for multi-repo projects and the Ops container. 2. **Missing repo** — halt the whole run (same machinery as other pre-spawn failures). 3. **Invocation** — operator runs `drain-cycle` from anywhere; repo paths live in `~/.drain-cycle/repos.yml`.
