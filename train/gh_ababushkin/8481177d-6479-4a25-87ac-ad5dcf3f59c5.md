## The shared problem: `skills/shape:design/` has a colon in the directory name

Both PR40 and PR46 add (or touch) a skill at **`skills/shape:design/SKILL.md`** — a directory name containing a colon. That breaks the repo's established convention and is genuinely unsafe:

- **No other skill directory has a colon.** All 18 dirs on main are plain slugs (`exec-pickup`, `project`, `delivery`, …). The colon namespace lives *only* in the frontmatter `name:` field — e.g. directory `skills/exec-pickup/` carries `name: exec:pickup`. The new skill should be `skills/design/` (or `skills/shape-design/`) on disk, with `name: shape:design` in the frontmatter if you want the namespace.
- **A colon in a path can't be checked out on Windows** and is invalid in many tools — it makes a clone fail rather than just look untidy. This is the strongest reason to fix it before merge.
- CLAUDE.md states the flat layout matches the plugin loader's `skills/<name>/SKILL.md` scan; `<name>` everywhere else is a plain slug.

**Fix:** `git mv "skills/shape:design" skills/design` (or `shape-design`), keep `name: shape:design` in the frontmatter, and update the `references/design-spike-templates.md` citation paths and the command wrapper accordingly.

Side note: the merged skill uses a `shape:` frontmatter prefix that none of its siblings (`project`, `idea`, `delivery`, `plan-review`) use — only the `exec:` skills namespace. Worth deciding whether `shape:design` or plain `design` is the intended name, but that's a consistency call, not a blocker like the directory colon.
