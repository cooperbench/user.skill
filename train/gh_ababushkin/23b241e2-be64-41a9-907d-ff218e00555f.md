## Problem

yfinance returns `stock_based_compensation: null` for some companies — observed on KSPI ([Kaspi.kz](<http://Kaspi.kz>), Nasdaq ADR) across all 4 fiscal years on 2026-05-13. This appears to be more common for non-US filers (20-F filings) where Yahoo's normalisation doesn't reliably surface the SBC line from the cash flow reconciliation.

The /signal skill requires SBC for the Clean EPS calc. Today it falls back to "N/A — SBC not returned by yfinance," which is technically correct but means we can never produce a clean PEG for any company in this category.

## Proposal

Extend the EDGAR MCP (or its planned successor for foreign filers) to pull `StockBasedCompensation` from the XBRL cash-flow facts in 10-K / 20-F / 10-Q filings:

```
get_sbc(ticker: str, periods: int = 4) -> {
  "ticker": "KSPI",
  "filing_type": "20-F",
  "currency": "KZT",
  "periods": [
    {"fiscal_year": "2025-12-31", "sbc": 12500000000, "source": "edgar_xbrl"},
    ...
  ]
}
```

When yfinance returns null SBC, /signal should fall back to this tool before declaring N/A.

## Foreign-filer caveat

Many non-US issuers file 20-F with EDGAR (Kaspi does — they're a Nasdaq-listed FPI). Those will work with the existing EDGAR plumbing planned in <issue id="afcac464-a217-4668-a472-4f62a7c14b54">ABA-13</issue>/14. But truly foreign-listed-only tickers (LSE-only, HKEX-only) will need a separate data source — out of scope here.

## Done when

* `get_sbc("KSPI", 4)` returns 4 years of non-null SBC values pulled from the 20-F XBRL facts (or returns an explicit "SBC line not present in filing" if it's truly absent — some issuers genuinely have $0 SBC).
* /signal calls this fallback automatically when yfinance returns null SBC, and the result is tagged `source: "edgar"` in the SIGNAL OUTPUT block.

# DESIGN.md — Equity Research Skill-Pack

This document is the **architectural reference** for the equity research skill-pack. It covers project structure, data contracts, MCP specs, the playbook layer, UI architecture, testing strategy, and skill-authoring conventions. For product positioning, scope boundaries, and locked design decisions, see `CHARTER.md`.

---

## Architecture Overview

```
/stock-equity    → Router        orchestrates full chain or dispatches to sub-skills
/stock-screen    → Screen        fast go/no-go; two variants by profit stage
/stock-signal    → Signal        GARP signal analysis; outputs MODEL_READY flag
/stock-model     → Model         conviction-building model; two variants by profit stage
/stock-timing    → Timing        when-to-act overlay; standalone invocation
```

Two routing dimensions are inferred before any skill executes:
- **Profit stage**: established (>2yr FCF history) vs emerging/pre-profit
- **Track**: growth (almost always) vs yield (rare edge case)

Router infers both from user phrasing and available data. States its inference. Does not ask.

---

## Namespace Convention

All skills in this pack are namespaced under the `stock-` prefix (e.g. `/stock-screen`, `/stock-signal`, `/stock-timing`, `/stock-model`, `/stock-equity`).

**Reason:** Generic command names (`/model`, `/review`, `/init`, `/ship`) collide with built-in Claude Code commands and with other installed skill packs. The `stock-` prefix gives the pack a stable, conflict-free namespace. The decision was taken pre-M5 (ABA-71) — `/model` would have shadowed both the built-in model-switcher and `agent-skills:model`. The convention was originally a `stock:` colon-style namespace; ABA-114 switched to `stock-` because the bare slug after the colon (e.g. `model`) still showed up in the loaded-skill list and confused triggering.

**Rule:** Every new skill added to this pack MUST use the `stock-` prefix in its SKILL.md `name:` frontmatter field. References to skills in `CHARTER.md`, `DESIGN.md`, `CLAUDE.md`, and other skill descriptions MUST also use the prefixed form. Report JSON schema keys (`stages.screen`, `stages.signal`, etc.) are NOT prefixed — they are JSON keys, not invocations.

# Coverage

**The skills will run on any ticker.** Off-coverage tickers fall back to generic ESTABLISHED / EMERGING logic — they get a valid output, just without the ticker-specific depth (capex-cycle position, segment splits, catalyst-aware scenarios, sell-side disagreement axes). Confidence caps at MEDIUM by default for off-coverage runs; users should expect a less informative answer than for a name with a playbook.

## Playbook structure

Each `playbooks/TICKER.md` encodes:

1. **Business architecture** — segments with revenue / operating-income mix and per-segment growth rates
2. **Capex cycle position** — where in the AI / infrastructure investment arc (ramp / peak / digest / steady) and implications for normalised margin
3. **Active catalysts** — specific named events with probability and IV impact estimates
4. **Sell-side disagreement axes** — the 3–5 real arguments the sell-side is having about this name right now
5. **Failure modes** — what breaks the thesis, and what to monitor
6. **Ticker-specific overrides** — base WACC, growth ceiling, terminal margin, scenario narratives (replacing the generic defaults)
7. **Historical reset-and-recover priors** — past drawdowns and recovery patterns, calibrating mean-reversion expectations

Full file-format and loader spec lives in `DESIGN.md` → *Playbook Layer*. See `playbooks/META.md` for a complete working example.

153	def _extract_section(html_text: str, section: str) -> str:
154	    """Find the named section in filing HTML; return stripped plain text.
155	
156	    Disambiguation between TOC entries and actual section body: the TOC entry
157	    has very little content before the next Item marker; the actual body has
158	    thousands of characters.  We pick the match with the longest span.
159	    """
160	    key = section.strip().lower()
161	    patterns = _SECTION_ALIASES.get(key, [re.escape(section)])
162	
163	    best_start: int | None = None
164	    best_end: int = 0
165	    best_span: int = -1
166	
167	    for pattern in patterns:
168	        for m in re.finditer(pattern, html_text, re.IGNORECASE):
169	            # Look for the NEXT item boundary, skipping a small offset so we
170	            # don't immediately re-match the same item number.
171	            next_b = _ITEM_BOUNDARY_RE.search(html_text, m.end() + 200)
172	            end = next_b.start() if next_b else m.start() + _MAX_SECTION_CHARS
173	            span = end - m.start()
174	            if span > best_span:
175	                best_span = span
176	                best_start = m.start()
177	                best_end = end
178	
179	    if best_start is None:
180	        raise EDGARNoDataError(f"section {section!r} not found in filing")
181	
182	    raw = html_text[best_start : min(best_end, best_start + _MAX_SECTION_CHARS)]
183	    return re.sub(r"\s+", " ", _html_to_text(raw)).strip()

186	def _primary_doc_url(accession_number: str, cik: str | None = None) -> str:

192	    """
193	    accn_nodash = accession_number.replace("-", "")
194	    # cik_path is the unpadded CIK used in EDGAR archive URLs.
195	    # When cik is provided (zero-padded 10-digit string from _get_cik), strip
196	    # leading zeros; otherwise derive from the accession's first segment.
197	    cik_padded = cik if cik is not None else accession_number.split("-")[0].zfill(10)
198	    cik_path = str(int(cik_padded))  # strip leading zeros for URL path

209	                f"/{accn_nodash}/{doc}"
210	            )
211	
212	    # Fallback: directory index, skipping non-primary files.
213	    index_url = f"https://www.sec.gov/Archives/edgar/data/{cik_path}/{accn_nodash}/index.json"
214	    resp2 = requests.get(index_url, headers=_HEADERS)

223	            continue

241	    """Convert XBRL member string to human-readable segment name."""
242	    if ":" in raw:

250	def _parse_segment_revenues(text: str) -> list[dict]:
251	    """Extract segment revenues from the plain-text segment note.
252	
253	    Looks for patterns of the form:
254	      <Segment Name> ... Revenue $ AMOUNT1 $ AMOUNT2 ...
255	    where AMOUNT1 is the most-recent year's figure (in millions).
256	    Skips the "Total" consolidated row.
257	
258	    Returns [] if no segment revenue pattern is found.
259	    """
260	    # Match: (segment label)(optional text)(Revenue $ AMOUNT) on the same run of text.
261	    # The segment label is a multi-word title-cased phrase without $ or digits.
262	    pattern = re.compile(
263	        r"([A-Z][A-Za-z &,()'-]{4,80}?)\s+"
264	        r"Revenue\s+\$\s*([\d,]+)",
265	    )
266	    results = []
267	    for m in pattern.finditer(text):
268	        label = m.group(1).strip().rstrip()
269	        # Skip "Total" rows, header artifacts, and percentage-change context rows
270	        if re.search(
271	            r"\bTotal\b|\bYear\b|\bIn millions\b|\bJun\b|^\s*\d"
272	            r"|\bPercent|\bChange\b|\bConsolidat|\bCorporat|\bElimin",
273	            label, re.IGNORECASE,
274	        ):
275	            continue
276	        # Clean residual whitespace/punctuation
277	        label = re.sub(r"\s+", " ", label).strip(" .")
278	        if len(label) < 3:
279	            continue
280	        revenue_str = m.group(2).replace(",", "")
281	        try:
282	            revenue = int(revenue_str) * 1_000_000  # note: values are in millions
283	        except ValueError:
284	            continue
285	        results.append({"name": label, "revenue": revenue})
286	
287	    # Deduplicate by name (keep highest revenue, i.e., most recent year typically)
288	    seen: dict[str, dict] = {}
289	    for r in results:
290	        if r["name"] not in seen or r["revenue"] > seen[r["name"]]["revenue"]:
291	            seen[r["name"]] = r
292	
293	    return sorted(seen.values(), key=lambda x: -x["revenue"])

296	def get_revenue_segments(ticker: str) -> list[dict]:
297	    """Return revenue breakdown by business segment.
298	
299	    First tries the EDGAR companyfacts API (works for companies that tag
300	    segment revenue with srt:StatementBusinessSegmentsAxis). Falls back to
301	    parsing the segment note from the 10-K filing HTML.
302	
303	    Returns [] for single-segment companies — never raises for missing segments.
304	    """
305	    cik = _get_cik(ticker)
306	
307	    # --- Try 1: EDGAR companyfacts API (dimensional XBRL) ---
308	    try:
309	        cf_url = f"{EDGAR_BASE}/api/xbrl/companyfacts/CIK{cik}.json"
310	        resp = requests.get(cf_url, headers=_HEADERS)
311	        resp.raise_for_status()
312	        us_gaap = resp.json().get("facts", {}).get("us-gaap", {})
313	
314	        segmented: list[dict] = []
315	        for concept in _REVENUE_CONCEPTS:
316	            if concept not in us_gaap:
317	                continue
318	            for entry in us_gaap[concept].get("units", {}).get("USD", []):
319	                if entry.get("form") not in _ANNUAL_FORMS:
320	                    continue
321	                seg = entry.get("segment")
322	                if seg and seg.get("dimension") == _SEGMENT_AXIS:
323	                    segmented.append(entry)
324	            if segmented:
325	                break
326	
327	        if segmented:
328	            latest_end = max(e["end"] for e in segmented)
329	            latest = [e for e in segmented if e["end"] == latest_end]
330	            by_seg: dict[str, dict] = {}
331	            for entry in latest:
332	                key = entry["segment"]["value"]
333	                if key not in by_seg or entry["filed"] > by_seg[key]["filed"]:
334	                    by_seg[key] = entry
335	            return [
336	                {"name": _clean_segment_name(v), "revenue": e["val"]}
337	                for v, e in sorted(by_seg.items(), key=lambda x: -x[1]["val"])
338	            ]
339	    except Exception:
340	        pass
341	
342	    # --- Try 2: Parse segment revenue table from the full 10-K filing HTML ---
343	    # _extract_section can pick an MD&A reference instead of the actual note, so
344	    # we run _parse_segment_revenues on the entire plain-text document instead.
345	    try:
346	        filings = search_filings(ticker, "10-K")
347	        if not filings:
348	            return []
349	        accn = filings[0]["accession_number"]
350	        doc_url = _primary_doc_url(accn, cik)
351	        resp = requests.get(doc_url, headers=_HEADERS)
352	        resp.raise_for_status()
353	        full_text = re.sub(r"\s+", " ", _html_to_text(resp.text))
354	        results = _parse_segment_revenues(full_text)
355	        return results
356	    except Exception:
357	        return []

When an MCP tool returns null (or raises `YFNoDataError`) on a field a skill needs, the skill MUST NOT silently degrade to N/A and MUST NOT fabricate the value. It MUST offer the user a structured paste-in fallback.

## Summary

Added `get_sbc(ticker, periods=4)` to the EDGAR MCP and wired it into `/stock-signal` as the fallback for when yfinance returns null SBC.

**The core insight** (verified live before designing): KSPI and other 20-F foreign filers report XBRL facts under the `ifrs-full` namespace in local currency, not `us-gaap`/USD — so the tool searches both namespaces (`us-gaap:ShareBasedCompensation` → `ifrs-full:ExpenseFromSharebasedPaymentTransactionsWithEmployees`), handles non-USD units, and includes 20-F forms.

**A gap I found and closed:** the EDGAR server existed in code (built under ABA-13/14) but was never registered in `.mcp.json` — only `yf` was. Without registering it, the `/signal` fallback would have been inert, so I added it.

**Done-when, all verified live:**
- `get_sbc("KSPI", 4)` → 4 years from the 20-F XBRL facts in KZT ✅
- US 10-K sanity check → NVDA / CRM / AAPL in USD ✅
- `/signal` calls it automatically and tags `source: edgar` ✅

**Review:** 5-axis sub-agent review surfaced 1 Critical + 3 Required + 3 Nice-to-have. The Critical was a genuine landmine — the FX-conversion direction in the skill was unspecified, risking an SBC figure wrong by ~5 orders of magnitude (KZT↔USD). Fixed with explicit multiply-direction + a magnitude sanity-check. All Required findings addressed (deterministic currency selection, documented + tested us-gaap-first precedence, semantic-proxy caveat). 46 tests pass (was 29).
