9	text; the run log then records exit code and wall-clock and nothing about
10	spend. ``--output-format stream-json`` (requires ``--verbose``) emits one
11	JSON event per line — per-turn ``assistant`` messages plus a terminal
12	``result`` — from which we reconstruct exactly what the session cost.
13	
14	**Token accounting.** Each ``assistant`` event carries ``message.usage``,
15	but the same assistant message is emitted *once per content block*
16	(thinking, text, tool_use) — every copy repeats the identical usage under
17	the identical ``message.id``. Summing per event therefore double- (or
18	triple-) counts a turn; we key by ``message.id`` so each turn's usage is
19	counted exactly once. ``cumulative`` is the sum across turns of all four
20	token components — the real billed-token figure, dominated in long
21	tool-use loops by cache reads re-paid every turn. ``peak_context`` is the
22	largest single-turn context (input + cache_read + cache_create), i.e. how
23	close the session came to the context-window ceiling.
24	
25	The terminal ``result`` event is authoritative for ``cost_usd``
26	(``total_cost_usd``), ``num_turns``, ``session_id`` and ``is_error``. Note
27	``result.usage`` is only the *final* turn's snapshot, not the session
28	total, so it is deliberately not used for the token figures — those come
29	from the accumulated per-turn stream, which is also what survives a kill
30	before any ``result`` arrives.
31	
32	**Guardrails — belt and suspenders.** ``per_issue_cost_usd`` is handed to
33	``claude`` as ``--max-budget-usd`` so the session self-terminates on cost
34	(the native belt). The token and time caps are the orchestrator's
35	suspenders: a poll loop watches the live cumulative-token tally and the
36	elapsed wall-clock, and SIGKILLs the session the moment either is crossed.
37	Any cap passed as ``None`` is not enforced; with both token and time caps
38	off the worker simply waits for the session to exit on its own. A crossed
39	cap is reported back as a ``Breach`` so the orchestrator can name it in the
40	halt entry. See ``limits.py`` for the thresholds and their precedence.
41	
42	**Process-group kill.** The worker is launched with
43	``start_new_session=True`` so it leads its own process group. On a breach
44	the whole group is SIGKILLed via ``os.killpg``, reaping grandchildren —
45	MCP servers, sub-agents — that a kill of the direct child alone would
46	orphan to keep burning tokens. SIGKILL (not a SIGTERM grace) is used
47	deliberately: a session being force-terminated past a guardrail has no
48	clean-shutdown work worth waiting for, and SIGKILL is the only signal a
49	misbehaving grandchild cannot ignore. Killing the whole group also closes
50	the stdout pipe those grandchildren inherited, which is what lets the
51	reader thread reach EOF instead of blocking forever.

228	def _monitor(
229	    proc: subprocess.Popen[str],
230	    accumulator: _UsageAccumulator,
231	    *,
232	    started: float,
233	    token_limit: int | None,
234	    time_limit_seconds: float | None,
235	    poll_interval_seconds: float,
236	) -> Breach | None:
237	    """Wait for the session, returning the per-issue cap it breaches (if any).
238	
239	    With both caps off there is nothing to watch for, so we block on the
240	    process directly. Otherwise we wake every ``poll_interval_seconds`` to
241	    compare the live cumulative-token tally and elapsed wall-clock against
242	    the caps; the first crossed cap is returned for the caller to kill on.
243	    Returns ``None`` when the session exits on its own first.
244	    """
245	    if token_limit is None and time_limit_seconds is None:
246	        proc.wait()
247	        return None
248	    while True:
249	        try:
250	            proc.wait(timeout=poll_interval_seconds)
251	            return None
252	        except subprocess.TimeoutExpired:
253	            pass
254	        if token_limit is not None:
255	            observed = accumulator.cumulative()
256	            if observed >= token_limit:
257	                return Breach("per-issue", "token", token_limit, observed)
258	        if time_limit_seconds is not None:
259	            elapsed = time.monotonic() - started
260	            if elapsed >= time_limit_seconds:
261	                return Breach("per-issue", "time", time_limit_seconds, elapsed)

264	def _kill_process_group(proc: subprocess.Popen[str]) -> None:
265	    """SIGKILL the worker's whole process group, reaping grandchildren.
266	
267	    No-ops if the leader has already exited (its pid — and thus the group
268	    id — is gone). SIGKILL is sent before the caller reaps the leader, so
269	    the group still exists and its id cannot have been reused.
270	    """
271	    try:
272	        pgid = os.getpgid(proc.pid)
273	    except ProcessLookupError:
274	        return
275	    try:
276	        os.killpg(pgid, signal.SIGKILL)
277	    except ProcessLookupError:
278	        pass

281	def _drain_stream(
282	    stream: TextIO | None,
283	    accumulator: _UsageAccumulator,
284	    sink: TextIO,
285	    on_progress: Callable[[int, int, int, float | None], None] | None = None,
286	) -> None:
287	    """Read the worker's merged output line by line until EOF.
288	
289	    Recognised JSON object events feed the usage accumulator; everything
290	    else (non-JSON diagnostics, JSON that isn't an object) is echoed to
291	    ``sink`` so the operator keeps the visibility a captured pipe would
292	    otherwise hide. ``on_progress`` is called once per new turn (deduplicated
293	    by message id) with a live usage snapshot.
294	    """
295	    if stream is None:
296	        return
297	    last_message_id: str | None = None
298	    try:
299	        for line in stream:
300	            line = line.rstrip("\n")
301	            if not line:
302	                continue
303	            try:
304	                event = json.loads(line)
305	            except json.JSONDecodeError:
306	                _echo(sink, line)
307	                continue
308	            if isinstance(event, dict):
309	                accumulator.feed(event)
310	                if on_progress is not None and event.get("type") == "assistant":
311	                    mid = (event.get("message") or {}).get("id")
312	                    if mid != last_message_id:
313	                        last_message_id = mid
314	                        snap = accumulator.live_snapshot()
315	                        on_progress(*snap)
316	            else:
317	                _echo(sink, line)
318	    finally:
319	        try:
320	            stream.close()
321	        except OSError:
322	            pass

326	    try:
327	        print(line, file=sink)
328	    except (OSError, ValueError):

333	    return value if isinstance(value, int) else 0

335	
336	class _UsageAccumulator:
337	    """Reconstruct session usage from the streamed events.
338	
339	    Per-turn usage is keyed by ``message.id`` so a turn emitted once per
340	    content block is counted once; the last copy wins (later events carry
341	    the more complete snapshot). The ``result`` event overwrites the
342	    session-summary fields each time it is seen.
343	
344	    All mutation happens on the reader thread and all reads happen on the
345	    main thread after it is joined — but the join is bounded, so a group
346	    member that escaped the kill (e.g. via ``setsid``) could keep the
347	    reader alive past the join. The lock makes the concurrent case safe
348	    rather than a ``dictionary changed size during iteration`` crash.
349	    """
350	
351	    def __init__(self) -> None:
352	        self._lock = threading.Lock()
353	        self._turns: dict[str, dict[str, int]] = {}
354	        self._anon = 0
355	        self.cost_usd: float | None = None
356	        self.num_turns: int | None = None
357	        self.session_id: str | None = None
358	        self.is_error: bool | None = None
359	
360	    def feed(self, event: dict[str, Any]) -> None:
361	        event_type = event.get("type")
362	        if event_type == "assistant":
363	            self._feed_assistant(event)
364	        elif event_type == "result":
365	            self._feed_result(event)
366	
367	    def _feed_assistant(self, event: dict[str, Any]) -> None:
368	        message = event.get("message")
369	        if not isinstance(message, dict):
370	            return
371	        usage = message.get("usage")
372	        if not isinstance(usage, dict):
373	            return
374	        message_id = message.get("id")
375	        turn = {field: _coerce_int(usage.get(field)) for field in _TOKEN_FIELDS}
376	        with self._lock:
377	            if isinstance(message_id, str):
378	                key = message_id
379	            else:
380	                key = f"_anon-{self._anon}"
381	                self._anon += 1
382	            self._turns[key] = turn
383	
384	    def _feed_result(self, event: dict[str, Any]) -> None:
385	        with self._lock:
386	            self.cost_usd = event.get("total_cost_usd")
387	            self.num_turns = event.get("num_turns")
388	            self.session_id = event.get("session_id")
389	            self.is_error = event.get("is_error")
390	
391	    def cumulative(self) -> int:
392	        """Live billed-token total across turns — the per-issue token cap is
393	        compared against this on every poll, so it reads under the lock and
394	        stays cheap (no peak-context / per-component breakdown)."""
395	        with self._lock:
396	            turns = list(self._turns.values())
397	        return sum(turn[field] for turn in turns for field in _TOKEN_FIELDS)
398	
399	    def live_snapshot(self) -> tuple[int, int, int, float | None]:
400	        """Current ``(turns, cumulative_tokens, peak_context_tokens, cost_usd)``.
401	
402	        Called from the reader thread after each new assistant turn. Reads
403	        under the lock so the main-thread monitor cannot see a torn state.
404	        """
405	        with self._lock:
406	            turn_count = len(self._turns)
407	            turns_list = list(self._turns.values())
408	            cost = self.cost_usd
409	        cumulative = sum(t[f] for t in turns_list for f in _TOKEN_FIELDS)
410	        peak = max(
411	            (
412	                t["input_tokens"]
413	                + t["cache_read_input_tokens"]
414	                + t["cache_creation_input_tokens"]
415	                for t in turns_list
416	            ),
417	            default=0,
418	        )
419	        return turn_count, cumulative, peak, cost
420	
421	    def usage(self) -> dict[str, int]:
422	        totals = {field: 0 for field in _TOKEN_FIELDS}
423	        peak_context = 0
424	        with self._lock:
425	            turns = list(self._turns.values())
426	        for turn in turns:
427	            for field in _TOKEN_FIELDS:
428	                totals[field] += turn[field]
429	            context = (
430	                turn["input_tokens"]
431	                + turn["cache_read_input_tokens"]
432	                + turn["cache_creation_input_tokens"]
433	            )
434	            peak_context = max(peak_context, context)
435	        return {
436	            **totals,
437	            "cumulative": sum(totals.values()),
438	            "peak_context": peak_context,
439	        }
440	
441	    def summary(self) -> tuple[float | None, int | None, str | None, bool | None]:
442	        """Read the result-event fields under the lock, as a snapshot."""
443	        with self._lock:
444	            return self.cost_usd, self.num_turns, self.session_id, self.is_error

78	    """Topological sort over ``issues`` respecting blocks/blocked-by.
79	
80	    Returns an ``ExecutionPlan`` with ``order`` (runnable, topo-sorted by
81	    ``(sortOrder, id)`` tiebreak) and ``deferred`` (issues skipped because
82	    an external unresolved blocker exists, or because a blocking issue in
83	    the drain was itself deferred — cascade).
84	
85	    Raises ``DependencyCycleError`` when the intra-set blocks graph contains
86	    a cycle (self-loops included).
87	    """
88	    P: set[str] = {i["id"] for i in issues}
89	    by_id: dict[str, dict[str, Any]] = {i["id"]: i for i in issues}
90	
91	    # Build de-duped intra-P edges: blocker_id → set of blocked_ids
92	    children: dict[str, set[str]] = {i["id"]: set() for i in issues}
93	    # Per-issue unique set of intra-P blocker ids (for cascade check + in-degree)
94	    intra_blockers: dict[str, set[str]] = {i["id"]: set() for i in issues}
95	    indegree: dict[str, int] = {i["id"]: 0 for i in issues}

97	    for issue in issues:
98	        for blocker in issue.get("blockers", []):

102	                    intra_blockers[issue["id"]].add(bid)
103	                    indegree[issue["id"]] += 1
104	                    children[bid].add(issue["id"])

106	    # Kahn's algorithm: ready = in-degree-0 issues, sorted by (sortOrder, id)
107	    ready: list[dict[str, Any]] = sorted(

109	        key=lambda i: (i["sortOrder"], i["id"]),
110	    )

121	        cascade_blocker = next(

123	            None,

This depends on a precondition: every configured path must be gitignored in the target repo. The defaults (`.claude`, `.mcp.json`) and `.entire` are gitignored in a typical repo, so the symlink is invisible to git in the worktree (it shares the repo's tracked `.gitignore`) and the worker's `git add` never stages it. A non-ignored, untracked entry would be the opposite: the worker would stage the symlink into the commit it pushes, and `git worktree remove` would then refuse the dirty worktree. The link step doesn't enforce this — it skips a name only when it's absent in the repo or already present in the worktree — so the requirement is documented (`repos.yml` comment, README) rather than coded. The link step is also not transactional: if `os.symlink` fails partway through the set, the already-created links remain and the failure surfaces as a pre-spawn "setup failed" halt, leaving the worktree in place for inspection.

The linked set is configurable. It defaults to `[.claude, .mcp.json]` — sensible for any repo — and is overridden by an optional `worktree_config_paths` list in `repos.yml`. `.entire` is not a default, because not every repo uses entire.io; an operator who does adds it there. Entries must be relative paths without `..`, since they are resolved inside the repo and linked into the worktree.

Symlink beat the alternatives. Passing `--settings <repo>/.claude/settings.json` loads only one file and leaves four other surfaces broken: `settings.local.json`, project agents/skills/commands, hook scripts whose paths are relative to `$CLAUDE_PROJECT_DIR`, and `.mcp.json`. Copying the config (rather than linking) isolates the worker but discards entire's checkpoint writes when the worktree is removed. Tracking `.claude/` in git would commit machine-specific config. The accepted tradeoff: a worker runs `--dangerously-skip-permissions`, so it shares — and could mutate — the live config dirs, exactly as a non-worktree run would (decision 2).

## 11. Active-run marker lives above `runs/` as `~/.drain-cycle/active.json`

Without a live-run signal there is no way to distinguish a working run from a hung one: the run-log gains an entry only on issue completion, and the orchestrator emits only sparse stderr lines. The fix is an active-run marker — a small JSON file written before each spawn and removed in the worker's try/finally — that a second terminal can read with `drain-cycle status`.

**Why `~/.drain-cycle/active.json`, not inside `runs/`.** The `grade` command globs `runs/*.json` and groups files by `cycle_id`. A marker placed in `runs/` would either corrupt a grading run (if it looks like a run log) or require `grade` to skip it by sentinel field (fragile coupling). Placing the marker at `~/.drain-cycle/active.json` — one level above `runs/` — means `grade`'s glob never sees it and the two concerns share no code path.

**Why not `runs/active.json`.** Same issue: inside `runs/` it's in the glob's scope. A separate directory (`~/.drain-cycle/live/`) was considered but adds a layer without benefit; a single well-named file at the parent level is enough.

**Why atomic write (temp-file rename).** `drain-cycle status` reads the marker from a different process, potentially mid-write. `Path.write_text` is not atomic: the file is truncated before the new content is written, so a reader arriving between those two steps sees an empty file. Rename is atomic on POSIX filesystems: the reader sees either the old complete content or the new complete content, never a partial write. The temp file uses a `.tmp` extension adjacent to the marker (`active.json.tmp → active.json`), not a different directory, so the rename is always within the same filesystem mount.

**Why the progress block is updated on every new turn, not on every raw JSON line.** The worker's stream-json output emits one event per content block per turn (thinking, text, tool_use) — a single turn with a thinking + tool_use block produces two events carrying the identical usage. Firing the callback on every raw event would write the file multiple times per turn with the same data, wasting I/O and producing redundant stderr lines. The reader thread deduplicates by message id: the callback fires once per unique message id, which is once per turn. The first event in a turn records the turn; subsequent events with the same id are no-ops for the callback.

**Stale marker detection.** A crash or SIGKILL leaves the marker on disk (the try/finally doesn't run on SIGKILL). `drain-cycle status` checks `os.kill(pid, 0)` — if the pid is gone it reports a stale marker rather than a live run. It does not delete the marker automatically; the operator removes it with `rm`, preserving forensic evidence of the interrupted run.

## 12. Execution order: manual drag-order only, blocks-aware

Before this change the orchestrator ordered issues by `(priority, sortOrder)` and ignored blocks/blocked-by entirely. Priority overrode the operator's manual drag-order, and a blocked issue could run before its blocker — wasting a worker on work that couldn't succeed.

**Decision.** Order purely by manual `sortOrder` ascending; drop `priority` from sorting. Overlay a topological pass (Kahn's algorithm) using `(sortOrder, id)` as the tiebreak among ready issues: each issue is "ready" once all its intra-drain blockers have been scheduled. This preserves the operator's intended drag-order as far as dependencies allow.

**External unresolved blocker → defer.** If a pending issue is blocked by an issue not in this drain's runnable set — including an In Progress issue in the same cycle, which the drain won't complete — the blocked issue is deferred: left Todo, not spawned, logged to stderr. Deferral cascades: if X is deferred and X intra-drain-blocks Y, Y defers too (falls out naturally from Kahn, since Y's in-degree never reaches zero while X is treated as permanently deferred). The exclusion rule is "defer unless the blocker is `completed` or `canceled`" — so `started`/`unstarted`/`backlog`/`triage` external blockers all defer. Deferred issues are not run-logged: they were never attempted, and counting them in `done/attempted` would corrupt `grade`'s completion signal.

**Intra-drain cycle → halt.** If the blocks graph among the pending issues contains a cycle (self-loop included), `DependencyCycleError` is raised, the orchestrator sets `cycle_halt_reason`, prints a `Halt:` line naming the involved issues, and exits 1. Nothing runs.

**`pending_issues` return type changed from `list[dict]` to `ExecutionPlan`.** The pure function `_plan(issues) -> ExecutionPlan` replaces `_sort_pending_issues`. `ExecutionPlan` is a frozen dataclass carrying `order: list[dict]` (runnable issues, topo-sorted) and `deferred: list[dict]` (each entry has `issue`, `blocker_identifier`, `blocker_state_type`). `DependencyCycleError(RuntimeError)` carries `identifiers: list[str]` for the cycle report. The `inverseRelations` GraphQL field is fetched in `pending_issues`, flattened to `issue["blockers"] = [{id, identifier, state_type}]`, and the raw key dropped — wire shape stays local to `pending_issues`, like `labels`.

**All-deferred → exit 0.** If `plan.order` is empty but `plan.deferred` is not, the run emits the stderr deferral lines and returns 0: the cycle isn't broken, it's just blocked externally. An empty `plan.order` with an empty `plan.deferred` is also exit 0 ("nothing to do").

**Alternatives considered.**

- *Keep priority in the sort key.* Rejected: the operator has one predictable knob — the manual drag-order — and priority overriding it is surprising and undesirable.
- *Ignore blocks entirely.* Rejected: running a blocked issue wastes a worker on work that can't succeed by definition.
- *Best-effort run instead of defer/halt.* Rejected: silently violating a dependency the operator encoded is worse than a loud skip or stop.
- *Record deferrals in the run log.* Rejected: a deferred issue was never attempted; counting it as an entry corrupts `done/attempted` in `grade`.

189	## 12. Execution order: manual drag-order only, blocks-aware
190	
191	Before this change the orchestrator ordered issues by `(priority, sortOrder)` and ignored blocks/blocked-by entirely. Priority overrode the operator's manual drag-order, and a blocked issue could run before its blocker — wasting a worker on work that couldn't succeed.
192	
193	**Decision.** Order purely by manual `sortOrder` ascending; drop `priority` from sorting. Overlay a topological pass (Kahn's algorithm) using `(sortOrder, id)` as the tiebreak among ready issues: each issue is "ready" once all its intra-drain blockers have been scheduled. This preserves the operator's intended drag-order as far as dependencies allow.
194	
195	**External unresolved blocker → defer.** If a pending issue is blocked by an issue not in this drain's runnable set — including an In Progress issue in the same cycle, which the drain won't complete — the blocked issue is deferred: left Todo, not spawned, logged to stderr. Deferral cascades: if X is deferred and X intra-drain-blocks Y, Y defers too (falls out naturally from Kahn, since Y's in-degree never reaches zero while X is treated as permanently deferred). The exclusion rule is "defer unless the blocker is `completed` or `canceled`" — so `started`/`unstarted`/`backlog`/`triage` external blockers all defer. Deferred issues are not run-logged: they were never attempted, and counting them in `done/attempted` would corrupt `grade`'s completion signal.
