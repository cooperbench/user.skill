Here's a review of `init.vim` — grouped by impact.

## Dead / broken config
- **Lines 126–129 (airline)** and **135–136 (better_whitespace)**: config is set but the plugins aren't in your `plug#begin` block. Either add the plugins or delete the config.
- **Line 31 (`:cab gb Gblame`)**: `Gblame` was renamed to `Git blame` in fugitive years ago. Update to `:cab gb Git blame`.

## Redundant in modern Neovim
- **Lines 33–37**: `syntax on`, `filetype on/indent/plugin on`, and `runtime macros/matchit.vim` are all on by default in Neovim. Delete.
- **Line 19 (`set lazyredraw`)**: no longer recommended in nvim — can cause rendering glitches with async plugins.
- **Lines 61–66 (pbcopy/pbpaste)**: replace with `set clipboard=unnamedplus` — nvim handles macOS clipboard natively.
- **`djoshea/vim-autoread` (line 117)**: drop it; `set autoread` + a tiny `FocusGained,BufEnter * checktime` autocmd covers it.
- **`tpope/vim-commentary` (line 116)**: nvim 0.10+ ships built-in `gc`/`gcc` commentary.

## Big modernization opportunities
- **Migrate to `init.lua`**. Lua config is faster, better typed, and the whole plugin ecosystem assumes it.
- **Plugin manager**: swap vim-plug → **lazy.nvim** (lazy loading, lockfile, UI).
- **Plugins path** `~/.vim/plugged` (line 107) should be under `stdpath('data')` on nvim.
- **NERDTree → `nvim-tree.lua`, `neo-tree.nvim`, or `oil.nvim`** (oil is great if you like editing directories as buffers).
- **FZF → `telescope.nvim`** (or `fzf-lua` if you want to keep fzf). Much better previews and pickers.
- **Add `nvim-treesitter`** for real syntax highlighting/indent.
- **Add LSP** via `nvim-lspconfig` + `mason.nvim`, with **`blink.cmp`** (or `nvim-cmp`) for completion — which lets you delete the `InsertTabWrapper` function (lines 85–94).
- **`prettier/vim-prettier` → `conform.nvim`** for unified formatting across languages.

## Smaller cleanups
- **Line 24 (`set spell` globally)**: consider scoping to filetypes (markdown, gitcommit) via autocmd — global spellcheck in code gets noisy.
- **Line 78 (`textwidth=100`)**: auto-wraps text on insert; if you only wanted the visual ruler, use `set colorcolumn=100` and drop `textwidth`.
- **Lines 100–102 ("Get off my lawn")**: missing `<Down>`. Either add it or drop the block.

Want me to draft a migrated `init.lua` with lazy.nvim + treesitter + LSP + telescope as a starting point?

`#{claude_sessions}` is a leftover from the notification system we ripped out. The current file is mostly documentation of options you haven't changed. Slimming makes real customizations visible at a glance and lets upstream template improvements show up in the default codepath.

**3. Missing QoL options worth turning on**

- `tmux_conf_new_window_retain_current_path=true` — you already have this for panes (line 53), inconsistent that new windows don't.
- `tmux_conf_copy_to_os_clipboard=true` — on macOS, copy-mode selections go to the OS clipboard. Big workflow win.
- `set -g history-limit 50000` in the user customizations block — default 2000 is painful when scrolling back through build output.

**4. Session persistence**

If you ever reboot and lose your tmux session layout, TPM + `tmux-resurrect` + `tmux-continuum` auto-saves and restores across reboots. Oh-my-tmux has built-in TPM support (lines 414–454) — just uncomment `@plugin` lines. Opinionated suggestion, not everyone wants it.

## Current installer — what works / what to improve

**Works well:**
- Single script, `set -euo pipefail`, idempotent-ish (copies are unconditional = repo propagates)
- Brewfile separates package list from logic
- Clear sectioning by concern

**Rough edges:**
1. **No macOS `defaults` section** — you're about to add keyboard repeat; this is its natural home. Needs `killall` for some domains to apply live, and full effect often needs logout.
2. **Mid-script `sudo` surprise** (Java symlink). Better to `sudo -v` upfront so the prompt happens early and stays cached.
3. **No end-of-run verification** — a final block echoing `mise --version`, `rtk --version`, `fish --version`, `gh auth status` would catch silent failures.
4. **Script will grow past "one file is fine"** once you add keybindings + macOS defaults + github. Either split into `install-core.sh` (orchestrator) + `macos-defaults.sh` + `setup-git.sh` + `setup-keys.sh`, or keep one file with very clear `# -- section --` headers and optional `--only <section>` flag. I'd lean toward splitting — re-running just one section is common.
5. **README is two lines** — doesn't mention manual post-install steps (gh auth, restart for defaults, Karabiner permissions). Worth adding a "manual steps" section.
