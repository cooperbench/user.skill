2	
3	A single-file, stdlib-only tool for cleaning up passwords when migrating to Apple
4	Passwords. Point it at one or more CSV exports (1Password, Apple Passwords, or

8	
9	It is meant to be run **once** for a migration. After you've migrated, Apple
10	Passwords does compromised/weak/reused monitoring natively and continuously
11	(Settings → Passwords → Security Recommendations), so the lasting value here is
12	the one-shot consolidated report and the cross-vault de-duplication Apple doesn't do.
13	
14	## What it does
15	
16	1. **Merge** — combines every CSV you pass and de-duplicates across them, so a
17	   login that exists in both 1Password and Apple collapses to one entry.
18	2. **Compromised** — checks each password against HaveIBeenPwned (see the security
19	   note below — your passwords never leave the machine).
20	3. **Weak** — local heuristics: length, character variety, a ~150-entry
21	   common-password list, keyboard walks/sequences, and repeated patterns.
22	4. **Reused** — the same password used across more than one site.
23	5. **De-duplicated** — collapses login/`www` subdomain variants of one site
24	   (`signin.ebay.com.au`, `www.ebay.com.au`, `accounts.ebay.com.au` → one `ebay.com.au`)
25	   so same-site, same-username, same-password rows merge. Drops exact duplicates from
26	   the output; flags *near*-duplicates (same site + username, different password) for
27	   you to review rather than guessing which is current. Title-only entries with no URL
28	   (e.g. a bare `Sonos` from Apple that likely matches `login.sonos.com`) are **flagged
29	   for manual review, never auto-dropped** — there's no URL or username to merge on safely.
30	6. **Dead sites** *(opt-in)* — flags accounts whose website looks gone so you can
31	   delete them.
32	
33	**Local-network credentials are exempt.** Anything on a private IP
34	(`192.168.x`, `10.x`, `172.16–31.x`, loopback), `localhost`, an `*.local` name, or

358	    `site` collapses login/www subdomain variants, so signin.ebay.com.au and
359	    www.ebay.com.au for the same user are treated as one site.
360	    Order is preserved; the first occurrence of each exact key is kept.
361	    """
362	    seen_exact = set()
363	    by_identity = defaultdict(set)  # (site, username) -> set of passwords seen
364	    kept, dropped = [], []
365	    for e in entries:
366	        ident = (e["site"], e["username"].lower())
367	        exact = (e["site"], e["username"].lower(), e["password"])
368	        if exact in seen_exact:
369	            dropped.append(e)
370	            continue
371	        seen_exact.add(exact)
372	        by_identity[ident].add(e["password"])
373	        kept.append(e)
374	    near = [
375	        (ident, count)
376	        for ident, count in ((i, len(pws)) for i, pws in by_identity.items())
377	        if count > 1
378	    ]
379	    near.sort(key=lambda x: x[1], reverse=True)
380	    return kept, dropped, near

383	def normalize_title(title):
384	    """Collapse a free-text title to a comparison token: drop bracketed/parenthesised
385	    suffixes (e.g. '[ANTON]', '(Anton)'), lowercase, keep alphanumerics only."""
386	    base = re.sub(r"[\(\[\{].*", "", title)  # drop '... [tag]' / '... (note)'
387	    return re.sub(r"[^a-z0-9]", "", base.lower())

390	def find_title_dupes(entries):
391	    """
392	    Best-effort: title-only entries (no URL) that probably duplicate a URL entry.
393	    Returns [(title_entry, [site, ...]), ...]. Flagged for manual review, never dropped.
394	    Matches a title's token (or its first word) against the brand label (first label of
395	    `site`, e.g. sonos.com -> 'sonos') of a real URL entry.
396	    """
397	    brands = defaultdict(set)  # brand token -> set of site strings
398	    for e in entries:
399	        if e["url_host"] and not e["local"]:
400	            brand = e["site"].split(".", 1)[0]
401	            if len(brand) >= 3:
402	                brands[brand].add(e["site"])
403	    matches = []
404	    for e in entries:
405	        if e["url_host"]:
406	            continue  # only title-only entries (no URL) are ambiguous
407	        tokens = {normalize_title(e["title"])}
408	        first_word = re.split(r"[^a-z0-9]+", e["title"].lower(), maxsplit=1)[0]
409	        tokens.add(first_word)
410	        sites = sorted({s for tok in tokens if len(tok) >= 3 for s in brands.get(tok, ())})
411	        if sites:
412	            matches.append((e, sites))
413	    matches.sort(key=lambda x: label(x[0]).lower())
414	    return matches

419	def probe_host(host):
420	    """
421	    Probe one public hostname. Returns a 'dead' reason string, or None if alive / can't classify.
422	    Conservative on purpose: only unambiguous signals count, so we never tell the user to delete a
423	    live account. Sends NO usernames, passwords, or cookies — DNS + one anonymous GET to the root.
424	    """
425	    try:
426	        socket.getaddrinfo(host, None)
427	    except socket.gaierror:
428	        return "no DNS record"
429	    except (OSError, UnicodeError):
430	        return None  # can't resolve cleanly but not a clear NXDOMAIN -> don't flag
431	    req = urllib.request.Request(
432	        f"https://{host}/",
433	        method="GET",
434	        headers={"User-Agent": "password-audit-local-cleanup"},
435	    )
436	    try:
437	        with urllib.request.urlopen(req, timeout=DEAD_TIMEOUT):
438	            return None  # 2xx / 3xx -> alive
439	    except urllib.error.HTTPError as exc:
440	        return "site returns HTTP 410 Gone" if exc.code == 410 else None  # other 4xx/5xx: uncertain
441	    except (urllib.error.URLError, OSError):
442	        return "resolves but unreachable"  # refused / timeout / TLS failure after DNS resolved

445	def check_dead(entries, enabled, offline):
446	    """Return {host: reason} for hosts judged dead. Probes each distinct public host once, in parallel."""
447	    if not enabled:
448	        return {}
449	    if offline:
450	        sys.stderr.write("WARNING: --check-dead needs the network; skipped because --offline is set.\n")
451	        return {}
452	    hosts = sorted({e["url_host"] for e in entries if is_public_host(e["url_host"])})
453	    if not hosts:
454	        return {}
455	    dead = {}
456	    with ThreadPoolExecutor(max_workers=DEAD_WORKERS) as pool:
457	        for host, reason in zip(hosts, pool.map(probe_host, hosts)):
458	            if reason:
459	                dead[host] = reason
460	    return dead

# Security Review: `password-audit`

No HIGH or MEDIUM findings at or above the confidence threshold (≥8/10).

This is a single-file, stdlib-only local CLI that operates exclusively on the user's own password CSV exports. There is no network service, no authentication boundary, and no untrusted input source — the only inputs are CLI flags (trusted) and the user's own vault exports. That threat model eliminates most of the categories in scope.

## What was examined and cleared

- **Password exfiltration / data exposure** — The HaveIBeenPwned check (`hibp_lookup`, `check_compromised`, lines 216–269) correctly implements k-anonymity: passwords are SHA-1 hashed locally and only the 5-char prefix is sent (`digest[:5]`), with `Add-Padding: true` set. The 35-char suffix is matched offline. `report.md` is generated only via `label()`/`display_name()` (lines 465–476), which derive from site/title/username and never touch `entry["password"]`. Plaintext only ever lands in `cleaned.csv`, which is the intended import artifact and is documented for deletion. No leak path found.
- **SSRF in the dead-site probe** (`probe_host`/`check_dead`, lines 419–460) — `check_dead` gates probing on `is_public_host()` (line 452), and `is_local()` (lines 153–168) treats RFC1918, loopback, link-local (so `169.254.169.254` cloud-metadata is exempted via `ipaddress.is_private`), `localhost`, `*.local`, and bare hostnames as local and excludes them. Only public hosts are probed, and the request is an anonymous GET to the root with no credentials/cookies. Even so, the host originates from the user's own export — a trusted source — so this is not an exploitable SSRF.
- **TLS** — `urllib.request.urlopen` is used with defaults; certificate validation is on. No `ssl._create_unverified_context` or verification bypass.
- **Crypto** — SHA-1 is used solely as the HIBP range-API contract, not as a security primitive; correct in context.
- **Path handling** — Output paths are fixed filenames under a CLI-supplied `--out-dir` (trusted). No untrusted-input-driven path traversal.
- **Injection** — No `eval`/`exec`, no `shell=True`/subprocess, no SQL, no deserialization (`pickle`/`yaml.load`), no XML parsing. CSV is read/written with the `csv` module.

## Sub-threshold note (not reported as a finding)

CSV formula injection in `cleaned.csv` (`write_cleaned_csv`, lines 606–611) is theoretically possible if a title/field begins with `=`/`+`/`-`/`@`, but the input is the user's own vault and the intended consumer is Apple Passwords' importer (not a spreadsheet). Confidence of real exploitation is well below 8; excluded.
