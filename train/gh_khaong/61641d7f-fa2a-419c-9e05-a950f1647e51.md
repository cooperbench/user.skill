   145→- **Metadata stored separately** — all session data lives on the `entire/checkpoints/v1` branch
   146→
   147→### Git Worktrees
   148→
   149→Entire works seamlessly with [git worktrees](https://git-scm.com/docs/git-worktree). Each worktree has independent session tracking, so you can run multiple AI sessions in different worktrees without conflicts.
   150→
   151→### Concurrent Sessions
   152→
   153→Multiple AI sessions can run on the same commit. If you start a second session while another has uncommitted work, Entire warns you and tracks them separately. Both sessions' checkpoints are preserved and can be rewound independently.

   229→

   295→## Security & Privacy
   296→
   297→**Your session transcripts are stored in your git repository** on the `entire/checkpoints/v1` branch. If your repository is public, this data is visible to anyone.
   298→
   299→Entire automatically redacts detected secrets (API keys, tokens, credentials) when writing to `entire/checkpoints/v1`, but redaction is best-effort. Temporary shadow branches used during a session may contain unredacted data and should not be pushed. See [docs/security-and-privacy.md](docs/security-and-privacy.md) for details.

   237→When condensing multiple concurrent sessions:
   238→- All sessions are stored in numbered subdirectories using 0-based indexing (`0/`, `1/`, `2/`, ...)

   244→### Checkpoint ID Linking
   245→
   246→The checkpoint ID is the **stable identifier** that links user commits to metadata across branches.
   247→
   248→**Format:** 12-hex-character random ID (e.g., `a3b2c4d5e6f7`)
   249→
   250→**Generation:**
   251→- Manual-commit: Generated during condensation (post-commit hook)
   252→- Auto-commit: Generated when creating the commit
   253→
   254→**Usage:**
   255→
   256→1. **User commit trailer** (both strategies):
   257→   - `Entire-Checkpoint: a3b2c4d5e6f7` added to user's commit message
   258→   - Auto-commit: Added programmatically
   259→   - Manual-commit: Added by `prepare-commit-msg` hook (user can remove)
   260→
   261→2. **Directory sharding** on `entire/checkpoints/v1`:
   262→   - Path: `<id[:2]>/<id[2:]>/` (e.g., `a3/b2c4d5e6f7/`)
   263→   - First 2 chars = shard (256 possible shards)
   264→   - Remaining 10 chars = directory name
   265→
   266→3. **Commit subject** on `entire/checkpoints/v1`:
   267→   - Format: `Checkpoint: a3b2c4d5e6f7`
   268→   - Makes `git log entire/checkpoints/v1` readable
   269→
   270→**Bidirectional Lookup:**
   271→
   272→```
   273→User commit → Metadata:
   274→  1. Extract "Entire-Checkpoint: a3b2c4d5e6f7" from commit message
   275→  2. Read entire/checkpoints/v1 tree at a3/b2c4d5e6f7/
   276→
   277→Metadata → User commits:
   278→  Given checkpoint ID a3b2c4d5e6f7
   279→  → Search branch history for commits with "Entire-Checkpoint: a3b2c4d5e6f7"
   280→```
   281→
   282→Note: Commit subjects on `entire/checkpoints/v1` (e.g., `Checkpoint: a3b2c4d5e6f7`)
   283→are for human readability in `git log` only. The CLI always reads from the tree at HEAD.
   284→
   285→**Example Flow:**
   286→
   287→```
   288→                    User creates commit
   289→                           ↓
   290→           prepare-commit-msg hook adds trailer
   291→                           ↓
   292→┌──────────────────────────────────────────────────┐
   293→│ Commit on main branch:                           │
   294→│   "Implement login feature                       │
   295→│                                                   │
   296→│   Entire-Checkpoint: a3b2c4d5e6f7"               │
   297→└──────────────────────────────────────────────────┘
   298→                           ↓
   299→                  post-commit hook runs
   300→                           ↓
   301→          Condense shadow → entire/checkpoints/v1
   302→                           ↓
   303→┌──────────────────────────────────────────────────┐
   304→│ Commit on entire/checkpoints/v1:                 │
   305→│   Subject: "Checkpoint: a3b2c4d5e6f7"            │
   306→│                                                   │
   307→│   Tree: a3/b2c4d5e6f7/                           │
   308→│     ├── metadata.json                            │
   309→│     │   (checkpoint_id: "a3b2c4d5e6f7")          │
   310→│     ├── 0/                                       │
   311→│     │   ├── full.jsonl                           │
   312→│     │   ├── prompt.txt                           │
   313→│     │   └── context.md                           │
