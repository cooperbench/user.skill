## What I found

Two independent failures recur on every PR (both merged #603 and #604 hit them):

### 1. `CI / Quality` — turbo boundaries (4 violations → blocks "CI Success")

All 4 violations collapse to **one import**:

```
vendor/observability/src/trpc.ts:3
  import { nanoid } from "@repo/lib";
```

`@repo/lib` is tagged `packages`, and `turbo.json:92` denies `packages` from any `vendor`. The 3 other vendors (`@vendor/mcp`, `@vendor/next`, `@vendor/pinecone`) fail transitively — they all depend on `@vendor/observability`.

**Subtle constraint:** `@repo/lib`'s `nanoid` is *not* raw `nanoid` — it's a `customAlphabet` with a 62-char alphabet (`0-9a-zA-Z`). Swapping to `import { nanoid } from "nanoid"` would change generated ID format. This is a behavior change, not a free swap.

### 2. `Core CI / Test` — flaky timing assertion (hit #603, passed #604)

`core/ai-sdk/src/core/primitives/tool.test.ts:149`:
```ts
expect(end - start).toBeGreaterThanOrEqual(10); // got 9 on fast runner
```
`setTimeout(10ms)` can resolve in 9ms on GitHub runners. Classic timing flake.

## Fix options for failure 1

| Option | Change | Tradeoff |
|---|---|---|
| **A. Re-tag `@repo/lib`** as `foundation` (or `shared`), leave outside all denylists | 1 line in `packages/lib/turbo.json`, no code moves | Signals `@repo/lib` is pure-utility (true — just nanoid/uuid/encryption/datetime/errors). Preserves `packages` meaning for the other 16 packages. |
| **B. Untag `@repo/lib`** entirely | 1 line | Same effect as A but less explicit — future rules could silently include/exclude it. |
| **C. Inline the 4-line nanoid helper** into `vendor/observability`, remove `@repo/lib` dep | ~10 lines across 2 files | Respects rules as written. Duplicates a utility if other vendors need it later. |

**My recommendation: A** — `@repo/lib` genuinely is a zero-dep utility distinct from the other `packages/*` scope; tag it accordingly. One-line turbo.json change, no runtime/behavior risk.
