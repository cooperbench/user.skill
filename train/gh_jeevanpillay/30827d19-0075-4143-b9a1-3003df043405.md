Research complete. Here's my understanding of the problem and proposed fix:

**Root Cause:** `/api/connect/*` is missing from the `isPublicRoute` matcher in `apps/app/src/proxy.ts`. Clerk middleware intercepts the callback before the Next.js rewrite to platform can fire. If the popup's Clerk session cookie is absent or expired after the GitHub redirect, the user gets a 307 to `/sign-in` (which manifests as the observed 404 in the popup context).

**Why this is safe to fix:** The platform callback route (`processOAuthCallback`) performs **zero** Clerk auth. Its entire security model is the `nanoid` state token — ~125 bits entropy, single-use via atomic Redis `HGETALL+DEL`, 10-minute TTL, with `orgId`/`connectedBy` embedded at authorize-time by a service-token-authenticated tRPC procedure. Making the callback public in app middleware changes nothing about security — the platform already runs no auth on this route.

**Precedent:** `/api/ingest(.*)` is already in `isPublicRoute` for the same reason — it's a platform-proxied route that handles its own auth.

**The fix:** Add `"/api/connect(.*)"` to `isPublicRoute` in `apps/app/src/proxy.ts:25-33`.
