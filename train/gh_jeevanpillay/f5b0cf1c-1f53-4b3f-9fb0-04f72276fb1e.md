1	# @repo/app-test-data
2	
3	Local simulated E2E sandbox for webhook-driven Lightfast flows.
4	
5	This package is no longer an event injector. The main loop is:
6	
7	1. Start local services with `pnpm dev:full`
8	2. Seed minimal DB state for the scenario
9	3. Replay raw fixtures from [`packages/webhook-schemas`](../webhook-schemas)
10	   as real signed HTTP POSTs to `/api/ingest/:provider`
11	4. Assert delivery + ingest state in Postgres
12	
13	That means the sandbox now exercises the actual ingress route, signature
14	verification, delivery persistence, Inngest handoff, and ingest log creation.
15	
16	## Commands
17	
18	```bash
19	# List available scenarios
20	pnpm --filter @repo/app-test-data sandbox:list
21	
22	# Check local runtime surfaces
23	pnpm --filter @repo/app-test-data sandbox:doctor
24	
25	# Seed the minimal installation + integration rows for a scenario
26	pnpm --filter @repo/app-test-data sandbox:seed -- github-pr-closed
27	
28	# Replay a scenario without assertions
29	pnpm --filter @repo/app-test-data sandbox:replay -- github-pr-closed
30	
31	# Full loop: seed -> replay -> assert
32	pnpm --filter @repo/app-test-data sandbox:run -- github-pr-closed
33	pnpm --filter @repo/app-test-data sandbox:run -- vercel-deployment-succeeded
34	```
35	
36	## Options
37	
38	```bash
39	--target platform|app   Replay against platform (4112) or app/proxy (3024)
40	--base-url URL          Override the default base URL for the selected target
41	--timeout-ms NUMBER     Assertion timeout for `run` (default: 20000)
42	--json                  Print JSON instead of human-readable output
43	```
44	
45	## Current Scope
46	
47	Implemented now:
48	- minimal DB seeding for `gatewayInstallations` and `orgIntegrations`
49	- real signed webhook replay for GitHub, Vercel, Linear, and Sentry
50	- polling assertions for `gatewayWebhookDeliveries` and `orgIngestLogs`
51	- first-class scenarios for GitHub PR and Vercel deployment flows
52	
53	Not implemented yet:
54	- outbound provider stubs for backfill and proxy-heavy scenarios
55	- token seeding for flows that need live provider fetches
56	- Clerk browser auth automation and UI verification
57	- full scenario reset/cleanup
58	
59	## Fixture Source Of Truth
60	
61	Fixtures live in [`packages/webhook-schemas/fixtures`](../webhook-schemas/fixtures).
62	This package treats them as canonical raw payloads and does not transform them
63	before replay.
64	
65	## Scenario Shape
66	
67	Scenarios live in [`src/scenarios`](./src/scenarios) and define:
68	- `connections`: the minimal seeded provider/resource rows
69	- `replays`: the fixture files to send and the expected delivery outcomes
70	
71	The first scenarios are intentionally narrow. The goal is a fast local loop for
72	one boundary at a time, not a giant synthetic story dataset.

## What the sandbox is now

After the in-flight rewrite (deletes + new files in git status), `packages/app-test-data` is a **CLI-only sandbox**: seed minimal DB rows → replay signed fixtures from `packages/webhook-schemas` against `/api/ingest/:provider` → poll `gatewayWebhookDeliveries` + `orgIngestLogs` to assert. ## Issues I found (ordered by severity)

1. **Deep relative import bypasses `server-only`.** `src/seed.ts:3` and `src/lib/fixtures.ts:4` do `from "../../../app-providers/src/registry"` because `@repo/app-providers` root has `import "server-only"` which throws under `tsx` without `--conditions react-server`. `packages/webhook-schemas` already solves this with `tsx --conditions react-server`. The `sandbox:*` scripts don't.
2. **Dead `datasets/` directory.** 9 JSON files / ~14k lines under `packages/app-test-data/datasets/` — leftover from the synthetic-story era. Zero references in source. `knip.json` still points `entry` at `src/cli/**/*.ts` (the deleted old CLI tree).
3. **Barrel `src/index.ts`** re-exports everything incl. db-touching modules, but no other package imports `@repo/app-test-data` — it's CLI-only. Barrel is a landmine for future consumers.
4. **Duplicated base-URL config.** `DEFAULT_APP_BASE_URL` / `DEFAULT_PLATFORM_BASE_URL` in both `doctor.ts` and `replay.ts`.
5. **Homegrown CLI arg parser** (`src/cli.ts:27-93`) — works, but Node 22 has `util.parseArgs` built in; the loop has a minor bug surface (e.g. `--base-url --json` consumes `--json` as the URL).
6. **`doctor` checks URLs but not env vars.** `GITHUB_WEBHOOK_SECRET`, `LINEAR_WEBHOOK_SIGNING_SECRET`, `SENTRY_CLIENT_SECRET`, `VERCEL_CLIENT_INTEGRATION_SECRET` are only required at replay time — failure surfaces mid-run instead of up-front.

9. **`assert.ts` timeout error is a string**, loses structure (provider, url, lastStatus vs. lastIngestLogs for CI logs).

## Proposed cleanup phasing

**Phase 1 — Dead code + config hygiene:** delete `datasets/`, drop `src/index.ts` barrel, fix `knip.json` entry to `src/cli.ts`.
