The core issue is that the plan builds a database browser when the mission calls for an operating view. Here's what I'd do instead — same backend investment, fundamentally different UI contract. ## The shift: from "what exists" to "what's happening" **Rename the page from "Entities" to "Activity."** This isn't cosmetic — it changes what the page is for. The entity table asks "what nouns does the system know about?" The activity view asks "what happened, what matters, and what should I look at?" ## Concrete changes from the current plan ### 1. Add an `activity` tRPC procedure (Phase 1) The plan's entity router (`list`, `get`, `getEvents`, `getRelatedEntities`) is fine and useful. But the primary feed needs a different query — recent enriched events joined with their primary entity: ``` orgEvents → orgEventEntities → orgEntities ``` Returns recent events decorated with entity context, sorted by `significanceScore DESC, occurredAt DESC`. This is the feed data. One query, two joins, both indexed. The entity `list` procedure becomes a secondary view, not the primary one. Add an `activityScore` sort option (significance × occurrence velocity) instead of just `lastSeenAt`. ### 2.
