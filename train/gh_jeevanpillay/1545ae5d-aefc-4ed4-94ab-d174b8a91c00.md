## Current State

**8 tRPC mutations** across `apps/app/` — **zero use optimistic updates**. Every mutation follows the same pessimistic pattern: show loading spinner → wait for server → `invalidateQueries` → UI updates.

## What Should Be Optimistic

### Yes — make optimistic (3)

| Mutation | Pattern | Why |
|---|---|---|
| `orgApiKeys.revoke` | `variables` (simple) | Binary state flip, client knows outcome |
| `orgApiKeys.delete` | `variables` (simple) | Remove from list, predictable outcome |
| `organization.updateName` | `onMutate` cache | Name consumed by sidebar + header + useActiveOrg — needs cross-component cache update |

### Borderline (2)

| Mutation | Verdict |
|---|---|
| `connections.updateBackfillConfig` | Low impact — "Saving..." spinner is adequate |
| `orgApiKeys.rotate` | No — returns server-generated key value |

### Keep pessimistic (3)

| Mutation | Why |
|---|---|
| `organization.create` | Server-generated IDs, Clerk `setActive()`, navigation |
| `orgApiKeys.create` | Server-generated API key must be displayed |
| `connections.resources.bulkLink` | Multi-provider `Promise.allSettled`, partial failures possible |

## Prefetch Layer Findings

The prefetch layer is solid. Key improvement opportunities:

1. **`refetchOnMount: false` + `refetchOnWindowFocus: false` repeated 14 times** — should be global defaults in `createQueryClient`
2. **Events "load more" uses manual `fetchQuery` + local state** — should use `useInfiniteQuery`
3. **Jobs polling uses `setInterval` + `invalidateQueries`** — should use `refetchInterval`
4. **Inconsistent `queryKey()` vs `queryOptions().queryKey`** — needs standardization
