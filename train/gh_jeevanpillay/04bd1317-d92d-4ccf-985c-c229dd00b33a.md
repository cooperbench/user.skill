### Why isolated is the right call here

1. **Your vendor abstraction rule depends on it.** CLAUDE.md says "never import `@planetscale/*` directly → use `@vendor/db`". In **hoisted** mode, any transitive dep anywhere in the graph becomes importable from anywhere — that guardrail silently evaporates. Isolated mode is what enforces it.
2. **Phantom-dependency detection.** Isolated catches packages importing things not in their `package.json`. Hoisted hides these until a dep tree changes and the import breaks in prod.
3. **Turborepo cache correctness.** Stricter dep graphs → more accurate hash inputs → fewer spurious cache hits across 23 `@repo/app-*` packages.
4. **The one real edge case is already solved.** You have `publicHoistPattern` for `import-in-the-middle` / `require-in-the-middle` (Sentry/OTel instrumentation needs these at the top level). That's exactly the pattern for "isolated by default, hoist only what must be hoisted" — keep it.
5. **Next.js 16 + Vercel + React 19 all work fine with isolated.** The historical reasons to switch (React Native, older bundlers, broken Yarn PnP-adjacent tooling) don't apply to your stack.

### When hoisted would actually be correct

- React Native / Expo apps (symlink-hostile Metro bundler) — you have none.
