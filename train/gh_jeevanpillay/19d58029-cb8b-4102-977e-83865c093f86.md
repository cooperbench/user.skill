   492→## Part 5: TUI Design — What's Needed
   493→
   494→### 5.1 Current Interface
   495→
   496→CLI-only. No TUI library in dependencies. Output via `tracing::info!()` with Unicode status symbols:
   497→- `●` (green) = attached
   498→- `●` (blue) = running
   499→- `○` (yellow) = stopped
   500→- `◌` (dim) = lazy
   501→
   502→The SPEC (Phase 4, line 397) defers TUI to "Polish" phase.
   503→
   504→### 5.2 TUI Requirements (from user's description)
   505→
   506→1. Run `dual` → shows TUI
   507→2. Tree view: repos at root, branches nested underneath
   508→3. Selecting a branch opens/attaches to session
   509→4. Must work from inside tmux (no nested issues)
   510→5. Must coexist with user's existing tmux (`Meta+s` switching)
   511→6. Quick return path from session back to TUI
   512→
   513→### 5.3 Three TUI Models (from existing research)
   514→
   515→**Model 1: Full Takeover**
   516→- `dual` takes over terminal with alternate screen
   517→- Tree view + preview pane
   518→- Enter → exits TUI, attaches tmux session
   519→- Meta-key → detaches tmux, returns to TUI
   520→
   521→**Model 2: Overlay/Popup**
   522→- Quick picker overlay (like tmux choose-tree)
   523→- Appears on meta-key, dismisses on selection
   524→- No persistent dashboard
   525→
   526→**Model 3: Hybrid (recommended in existing research)**
   527→- `dual` → full TUI home screen
   528→- Select branch → transitions to tmux session
   529→- Within tmux, meta-key → lightweight overlay picker
   530→- Esc → returns to TUI home
   531→
   532→### 5.4 TUI ↔ Tmux Transition Challenge
   533→
   534→The critical design problem. Three options from existing research:
   535→
   536→**Option A: Dual Runs Inside Tmux**
   537→```
   538→Outer tmux session (dual-control)
   539→├── Window 0: Dual TUI
   540→├── Window 1: lightfast-main session
   541→├── Window 2: lightfast-feat-auth session
   542→└── Window 3: agent-os-main session
   543→```
   544→Pros: Instant switching via tmux window switch. Cons: Nested tmux if user already uses tmux.
   545→
   546→**Option B: Dual Manages Terminal Directly**
   547→```
   548→Terminal
   549→├── State A: Dual TUI (alternate screen)
   550→└── State B: tmux attach (tmux controls terminal)
   551→    └── Meta-key → tmux detach → back to State A
   552→```
   553→Pros: Clean separation, no nested tmux. Cons: Terminal state transitions, potential flicker.
   554→
   555→**Option C: Dual Replaces Tmux**
   556→```
   557→Terminal
   558→└── Dual TUI (full control)
   559→    ├── Tree view
   560→    └── Embedded PTY terminal pane
   561→```
   562→Pros: Complete control. Cons: Massive effort, reimplementing terminal emulation.
   563→
   564→### 5.5 Ratatui Stack (from existing research)
   565→
   566→```toml
   567→ratatui = "0.29"          # TUI framework
   568→crossterm = "0.28"        # Terminal backend
   569→tui-tree-widget = "0.22"  # Tree view for repos/branches
   570→tui-input = "0.11"        # Text input for search/filter
