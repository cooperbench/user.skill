   492→## Part 5: TUI Design — What's Needed
   493→
   494→### 5.1 Current Interface
   495→
   496→CLI-only. No TUI library in dependencies. Output via `tracing::info!()` with Unicode status symbols:
   497→- `●` (green) = attached
   498→- `●` (blue) = running
   499→- `○` (yellow) = stopped
   500→- `◌` (dim) = lazy
   501→
   502→The SPEC (Phase 4, line 397) defers TUI to "Polish" phase.
   503→
   504→### 5.2 TUI Requirements (from user's description)
   505→
   506→1. Run `dual` → shows TUI
   507→2. Tree view: repos at root, branches nested underneath
   508→3. Selecting a branch opens/attaches to session
   509→4. Must work from inside tmux (no nested issues)
   510→5. Must coexist with user's existing tmux (`Meta+s` switching)
   511→6. Quick return path from session back to TUI
   512→
   513→### 5.3 Three TUI Models (from existing research)
   514→
   515→**Model 1: Full Takeover**
   516→- `dual` takes over terminal with alternate screen
   517→- Tree view + preview pane
   518→- Enter → exits TUI, attaches tmux session
   519→- Meta-key → detaches tmux, returns to TUI
   520→
   521→**Model 2: Overlay/Popup**
   522→- Quick picker overlay (like tmux choose-tree)
   523→- Appears on meta-key, dismisses on selection
   524→- No persistent dashboard
   525→
   526→**Model 3: Hybrid (recommended in existing research)**
   527→- `dual` → full TUI home screen
   528→- Select branch → transitions to tmux session
   529→- Within tmux, meta-key → lightweight overlay picker
   530→- Esc → returns to TUI home
   531→
   532→### 5.4 TUI ↔ Tmux Transition Challenge
   533→
   534→The critical design problem. Three options from existing research:
   535→
   536→**Option A: Dual Runs Inside Tmux**
   537→```
   538→Outer tmux session (dual-control)
   539→├── Window 0: Dual TUI
   540→├── Window 1: lightfast-main session
   541→├── Window 2: lightfast-feat-auth session
   542→└── Window 3: agent-os-main session
   543→```
   544→Pros: Instant switching via tmux window switch. Cons: Nested tmux if user already uses tmux.
   545→
   546→**Option B: Dual Manages Terminal Directly**
   547→```
   548→Terminal
   549→├── State A: Dual TUI (alternate screen)
   550→└── State B: tmux attach (tmux controls terminal)
   551→    └── Meta-key → tmux detach → back to State A
   552→```
   553→Pros: Clean separation, no nested tmux. Cons: Terminal state transitions, potential flicker.
   554→
   555→**Option C: Dual Replaces Tmux**
   556→```
   557→Terminal
   558→└── Dual TUI (full control)
   559→    ├── Tree view
   560→    └── Embedded PTY terminal pane
   561→```
   562→Pros: Complete control. Cons: Massive effort, reimplementing terminal emulation.
   563→

   565→

   567→ratatui = "0.29"          # TUI framework

   569→tui-tree-widget = "0.22"  # Tree view for repos/branches

   188→## Architecture Documentation
   189→
   190→### Port Isolation Design
   191→
   192→The port isolation relies on Docker's network namespace isolation:
   193→
   194→1. **No port publishing**: Containers are created without `-p` flags, so container ports are NOT exposed on the host
   195→2. **Bridge network**: Each container gets a unique IP on Docker's bridge network (172.17.0.x)
   196→3. **Direct IP routing**: The reverse proxy connects directly to container IPs — `TcpStream::connect(format!("{container_ip}:{port}"))`
   197→4. **Subdomain routing**: Browser access uses `{workspace_id}.localhost:{port}` which the proxy resolves to the correct container
   198→
   199→### Command Routing Design
   200→
   201→Commands are split between host and container:
   202→
   203→| Runs on Host | Runs in Container (via docker exec) |
   204→|---|---|
   205→| git, cat, ls, vim, nvim, ssh | npm, npx, pnpm, node, python, python3, pip, pip3, curl, make |
   206→
   207→Shell functions are injected into the tmux session shell. They wrap each intercepted command with `docker exec -w /workspace {container_name} {command} "$@"`.
   208→
   209→### End-to-End Flow
   210→
   211→1. User runs `dual launch repo-branch`
   212→2. Dual resolves/clones workspace, creates/starts container, writes shell RC
   213→3. Dual creates a tmux session and sends `source ~/.config/dual/rc/dual-repo-branch.sh` via send_keys
   214→4. User types `pnpm dev` in the tmux session
   215→5. The shell function intercepts it and runs `docker exec -w /workspace dual-repo-branch pnpm dev`
   216→6. Next.js starts inside the container, binding to port 3000 inside the container's network namespace
   217→7. The `dual proxy` command (run separately) listens on host port 3000
   218→8. Browser requests to `repo-branch.localhost:3000` are routed through the proxy to `172.17.0.x:3000`
   219→
   220→### Where The User's Scenario Fits
   221→
   222→In a monorepo with 5 apps:
   223→- Dual creates **one workspace per branch** — the entire monorepo is cloned once
   224→- **One container** serves all 5 apps for that branch
   225→- Inside the container, each app can bind its own port (3000, 3001, etc.) without conflict with other containers
   226→- The `.dual.toml` `ports` array should list ALL ports used by apps in the monorepo (e.g., `ports = [3000, 3001, 3002, 3003, 3004]`)
   227→
   228→For two branches of the same monorepo:
   229→- Two separate containers are created, each with their own network namespace
   230→- Both can internally listen on ports 3000-3004 without conflict
   231→- The proxy differentiates them by subdomain: `repo-main.localhost:3000` vs `repo-feature.localhost:3000`

    68→    loop {
    69→        // Reload state each iteration (workspaces may have changed while in tmux)
    70→        let st = match state::load() {
    71→            Ok(s) => s,
    72→            Err(e) => {
    73→                error!("{e}");
    74→                info!("Run `dual add` inside a repo to get started.");
    75→                return 1;
    76→            }
    77→        };
    78→
    79→        if st.all_workspaces().is_empty() {
    80→            info!("No workspaces. Run `dual add` inside a repo to get started.");
    81→            return 0;
    82→        }
    83→
    84→        match tui::run(&st, backend) {
    85→            Ok(Some(workspace_id)) => {
    86→                // TUI already called ratatui::restore() — terminal is in normal mode
    87→                let exit_code = cmd_launch(Some(&workspace_id), backend);
    88→
    89→                if inside_tmux {
    90→                    // switch-client is instant — don't loop back to TUI
    91→                    return exit_code;
    92→                }
    93→
    94→                if exit_code != 0 {
    95→                    eprintln!("Launch failed (exit code {exit_code}). Press Enter to continue...");
    96→                    let _ = std::io::stdin().read_line(&mut String::new());
    97→                }
    98→
    99→                // tmux attach returned (user detached) — loop back to TUI
   100→                continue;
   101→            }
   102→            Ok(None) => return 0, // User quit
   103→            Err(e) => {
   104→                error!("TUI error: {e}");
   105→                return 1;
   106→            }
   107→        }
   108→    }
   109→}

   111→/// Register the current repo as a dual workspace.
   112→fn cmd_add(name: Option<&str>) -> i32 {
   113→    // Detect git repo info from current directory
   114→    let (repo_root, url, branch) = match detect_git_repo() {
   115→        Ok(info) => info,
   116→        Err(e) => {
   117→            error!("{e}");
   118→            return 1;
   119→        }
   120→    };
   121→
   122→    // Derive repo name
   123→    let repo_name = match name {
   124→        Some(n) => n.to_string(),
   125→        None => derive_repo_name(&repo_root),
   126→    };
   127→
   128→    // Load or create state
   129→    let mut st = match state::load() {
   130→        Ok(s) => s,
   131→        Err(e) => {
   132→            error!("{e}");
   133→            return 1;
   134→        }
   135→    };
   136→
   137→    // Check for duplicates
   138→    if st.has_workspace(&repo_name, &branch) {
   139→        error!("workspace {}/{} already exists", repo_name, branch);
   140→        return 1;
   141→    }
   142→
   143→    // Check for .dual.toml — if missing, create a default one with helpful comments
   144→    let hints_path = repo_root.join(".dual.toml");
   145→    if !hints_path.exists() {
   146→        if let Err(e) = config::write_default_hints(&repo_root) {
   147→            warn!("failed to write .dual.toml: {e}");
   148→        } else {
   149→            info!("Created .dual.toml with defaults (image: node:20)");
   150→            info!("Edit it to customize ports, image, setup command, and env vars.");
   151→        }
   152→    }
   153→
   154→    // Initialize shared directory if [shared] is configured
   155→    let hints = config::load_hints(&repo_root).unwrap_or_default();
   156→    if let Some(ref shared_config) = hints.shared
   157→        && !shared_config.files.is_empty()
   158→    {
   159→        match shared::ensure_shared_dir(&repo_name) {
   160→            Ok(shared_dir) => {
   161→                match shared::init_from_main(&repo_root, &shared_dir, &shared_config.files) {
   162→                    Ok(moved) => {
   163→                        for f in &moved {
   164→                            info!("  shared: {f} → ~/.dual/shared/{repo_name}/");
   165→                        }
   166→                    }
   167→                    Err(e) => warn!("shared init failed: {e}"),
   168→                }
   169→            }
   170→            Err(e) => warn!("could not create shared directory: {e}"),
   171→        }
   172→    }
   173→
   174→    // Add workspace entry
   175→    let entry = state::WorkspaceEntry {
   176→        repo: repo_name.clone(),
   177→        url,
   178→        branch: branch.clone(),
   179→        path: Some(repo_root.to_string_lossy().to_string()),
   180→    };
   181→
   182→    if let Err(e) = st.add_workspace(entry) {
   183→        error!("{e}");
   184→        return 1;
   185→    }
   186→
   187→    // Save state
   188→    if let Err(e) = state::save(&st) {
   189→        error!("failed to save state: {e}");
   190→        return 1;
   191→    }
   192→
   193→    let ws_id = config::workspace_id(&repo_name, &branch);
   194→    info!("Added workspace: {ws_id}");
   195→    info!("Use `dual launch {ws_id}` to start.");
   196→    0
   197→}

   266→/// Launch a specific workspace: clone → container → shell RC → tmux → attach.
   267→fn cmd_launch(workspace_arg: Option<&str>, backend: &dyn MultiplexerBackend) -> i32 {
   268→    let st = match state::load() {
   269→        Ok(s) => s,
   270→        Err(e) => {
   271→            error!("{e}");
   272→            return 1;
   273→        }
   274→    };
   275→
   276→    // Resolve workspace: use arg if provided, otherwise auto-detect from cwd
   277→    let entry = if let Some(ws) = workspace_arg {
   278→        match st.resolve_workspace(ws) {
   279→            Some(e) => e,
   280→            None => {
   281→                error!("unknown workspace '{ws}'");
   282→                info!("Configured workspaces:");
   283→                for w in st.all_workspaces() {
   284→                    let id = config::workspace_id(&w.repo, &w.branch);
   285→                    info!("  {id}");
   286→                }
   287→                return 1;
   288→            }
   289→        }
   290→    } else {
   291→        match detect_workspace(&st) {
   292→            Some(e) => {
   293→                let ws_id = config::workspace_id(&e.repo, &e.branch);
   294→                info!("Auto-detected workspace: {ws_id}");
   295→                st.resolve_workspace(&ws_id).unwrap()
   296→            }
   297→            None => {
   298→                error!("could not detect workspace from current directory");
   299→                info!("Usage: dual launch [workspace]");
   300→                return 1;
   301→            }
   302→        }
   303→    };
   304→
   305→    let workspace_root = st.workspace_root();
   306→    let container_name = config::container_name(&entry.repo, &entry.branch);
   307→    let session_name = config::session_name(&entry.repo, &entry.branch);
   308→    debug!(
   309→        repo = %entry.repo,
   310→        branch = %entry.branch,
   311→        "resolved workspace"
   312→    );
   313→
   314→    // Step 1: Resolve workspace directory
   315→    let workspace_dir = if let Some(ref path) = entry.path {
   316→        let dir = PathBuf::from(path);
   317→        if !dir.join(".git").exists() {
   318→            error!(
   319→                "workspace path {} does not contain a git repo",
   320→                dir.display()
   321→            );
   322→            return 1;
   323→        }
   324→        dir
   325→    } else {
   326→        // Try to clone from local main workspace first (fast, hardlinks)
   327→        let target_dir = config::workspace_dir(&workspace_root, &entry.repo, &entry.branch);
   328→        let main_workspace_path = st
   329→            .workspaces_for_repo(&entry.repo)
   330→            .into_iter()
   331→            .find(|ws| ws.path.is_some())
   332→            .and_then(|ws| ws.path.as_ref().map(PathBuf::from));
   333→
   334→        match main_workspace_path {
   335→            Some(main_path) if main_path.join(".git").exists() => {
   336→                info!("Cloning from local main workspace...");
   337→                match clone::clone_from_local(&main_path, &target_dir, &entry.branch) {
   338→                    Ok(dir) => dir,
   339→                    Err(e) => {
   340→                        error!("local clone failed: {e}");
   341→                        return 1;
   342→                    }
   343→                }
   344→            }
   345→            _ => {
   346→                // Fallback: clone from remote URL
   347→                match clone::clone_workspace(
   348→                    &workspace_root,
   349→                    &entry.repo,
   350→                    &entry.url,
   351→                    &entry.branch,
   352→                ) {
   353→                    Ok(dir) => dir,
   354→                    Err(e) => {
   355→                        error!("clone failed: {e}");
   356→                        return 1;
   357→                    }
   358→                }
   359→            }
   360→        }
   361→    };
   362→
   363→    // Step 2: Handle shared files
   364→    let hints = config::load_hints(&workspace_dir).unwrap_or_default();
   365→    if let Some(ref shared_config) = hints.shared
   366→        && !shared_config.files.is_empty()
   367→        && let Ok(shared_dir) = shared::ensure_shared_dir(&entry.repo)
   368→    {
   369→        if entry.path.is_some() {
   370→            // Main workspace: ensure shared files are initialized
   371→            match shared::init_from_main(&workspace_dir, &shared_dir, &shared_config.files) {
   372→                Ok(moved) => {
   373→                    for f in &moved {
   374→                        info!("  shared: {f} → ~/.dual/shared/{}/", entry.repo);
   375→                    }
   376→                }
   377→                Err(e) => warn!("shared init failed: {e}"),
   378→            }
   379→        } else {
   380→            // Branch workspace: copy shared files
   381→            match shared::copy_to_branch(&workspace_dir, &shared_dir, &shared_config.files) {
   382→                Ok(copied) => {
   383→                    for f in &copied {
   384→                        info!("  shared: copied {f}");
   385→                    }
   386→                }
   387→                Err(e) => warn!("shared copy failed: {e}"),
   388→            }
   389→        }
   390→    }
   391→
   392→    // Step 3: Ensure container exists and is running
   393→    let is_new_container = matches!(
   394→        container::status(&container_name),
   395→        container::ContainerStatus::Missing
   396→    );
   397→    match container::status(&container_name) {
   398→        container::ContainerStatus::Missing => {
   399→            info!("Creating container {container_name}...");
   400→            if let Err(e) = container::create(
   401→                &container_name,
   402→                &workspace_dir,
   403→                &hints.image,
   404→                &hints.env,
   405→                &hints.anonymous_volumes,
   406→            ) {
   407→                error!("container create failed: {e}");
   408→                return 1;
   409→            }
   410→            if let Err(e) = container::start(&container_name) {
   411→                error!("container start failed: {e}");
   412→                return 1;
   413→            }
   414→        }
   415→        container::ContainerStatus::Stopped => {
   416→            info!("Starting container {container_name}...");
   417→            if let Err(e) = container::start(&container_name) {
   418→                error!("container start failed: {e}");
   419→                return 1;
   420→            }
   421→        }
   422→        container::ContainerStatus::Running => {}
   423→    }
   424→
   425→    // Step 3.5: Run setup command on new containers
   426→    if is_new_container && let Some(ref setup) = hints.setup {
   427→        info!("Running setup: {setup}");
   428→        if let Err(e) = container::exec_setup(&container_name, setup) {
   429→            error!("setup failed: {e}");
   430→            return 1;
   431→        }
   432→    }
   433→
   434→    // Step 4: Write shell RC file
   435→    let rc_path = match shell::write_rc_file(&container_name, &hints.extra_commands) {
   436→        Ok(p) => p,
   437→        Err(e) => {
   438→            error!("failed to write shell RC: {e}");
   439→            return 1;
   440→        }
   441→    };
   442→
   443→    // Step 5: Create tmux session if not alive
   444→    if !backend.is_alive(&session_name) {
   445→        let source_cmd = shell::source_file_command(&rc_path);
   446→        if let Err(e) = backend.create_session(&session_name, &workspace_dir, Some(&source_cmd)) {
   447→            error!("session creation failed: {e}");
   448→            return 1;
   449→        }
   450→    }
   451→
   452→    // Step 6: Attach
   453→    info!("Attaching to {session_name}...");
   454→    if let Err(e) = backend.attach(&session_name) {
   455→        error!("attach failed: {e}");
   456→        return 1;
   457→    }
   458→
   459→    0
   460→}

   482→/// Destroy a workspace: tmux → container → clone.
   483→fn cmd_destroy(workspace_arg: Option<&str>, backend: &dyn MultiplexerBackend) -> i32 {
   484→    let mut st = match state::load() {
   485→        Ok(s) => s,
   486→        Err(e) => {
   487→            error!("{e}");
   488→            return 1;
   489→        }
   490→    };
   491→
   492→    // Resolve workspace: use arg if provided, otherwise auto-detect from cwd
   493→    let workspace;
   494→    let entry = if let Some(ws) = workspace_arg {
   495→        workspace = ws.to_string();
   496→        match st.resolve_workspace(ws) {
   497→            Some(e) => e.clone(),
   498→            None => {
   499→                error!("unknown workspace '{ws}'");
   500→                return 1;
   501→            }
   502→        }
   503→    } else {
   504→        match detect_workspace(&st) {
   505→            Some(e) => {
   506→                workspace = config::workspace_id(&e.repo, &e.branch);
   507→                info!("Auto-detected workspace: {workspace}");
   508→                e
   509→            }
   510→            None => {
   511→                error!("could not detect workspace from current directory");
   512→                info!("Usage: dual destroy [workspace]");
   513→                return 1;
   514→            }
   515→        }
   516→    };
   517→
   518→    let workspace_root = st.workspace_root();
   519→    let container_name = config::container_name(&entry.repo, &entry.branch);
   520→    let session_name = config::session_name(&entry.repo, &entry.branch);
   521→
   522→    // Destroy tmux session
   523→    if backend.is_alive(&session_name) {
   524→        info!("Destroying session {session_name}...");
   525→        if let Err(e) = backend.destroy(&session_name) {
   526→            warn!("session destroy failed: {e}");
   527→        }
   528→    }
   529→
   530→    // Stop and remove container
   531→    match container::status(&container_name) {
   532→        container::ContainerStatus::Running => {
   533→            info!("Stopping container {container_name}...");
   534→            if let Err(e) = container::stop(&container_name) {
   535→                warn!("container stop failed: {e}");
   536→            }
   537→            info!("Removing container {container_name}...");
   538→            if let Err(e) = container::destroy(&container_name) {
   539→                warn!("container remove failed: {e}");
   540→            }
   541→        }
   542→        container::ContainerStatus::Stopped => {
   543→            info!("Removing container {container_name}...");
   544→            if let Err(e) = container::destroy(&container_name) {
   545→                warn!("container remove failed: {e}");
   546→            }
   547→        }
   548→        container::ContainerStatus::Missing => {}
   549→    }
   550→
   551→    // Remove clone (only for non-explicit-path workspaces)
   552→    if entry.path.is_none() && clone::workspace_exists(&workspace_root, &entry.repo, &entry.branch)
   553→    {
   554→        info!("Removing clone...");
   555→        if let Err(e) = clone::remove_workspace(&workspace_root, &entry.repo, &entry.branch) {
   556→            error!("failed to remove clone: {e}");
   557→            return 1;
   558→        }
   559→    }
   560→
   561→    // Remove from state
   562→    st.remove_workspace(&entry.repo, &entry.branch);
   563→    if let Err(e) = state::save(&st) {
   564→        warn!("failed to save state: {e}");
   565→    }
   566→
   567→    info!("Workspace '{workspace}' destroyed.");
   568→    0
   569→}

   571→/// Open workspace services in the default browser.
   572→fn cmd_open(workspace: Option<String>) -> i32 {
   573→    let st = match state::load() {
   574→        Ok(s) => s,
   575→        Err(e) => {
   576→            error!("{e}");
   577→            return 1;
   578→        }
   579→    };
   580→
   581→    let url_groups = proxy::workspace_urls(&st);
   582→    if url_groups.is_empty() {
   583→        info!("No URLs configured. Add 'ports' to .dual.toml in your repo.");
   584→        return 0;
   585→    }
   586→
   587→    // Filter by workspace if specified
   588→    let filtered: Vec<_> = match &workspace {
   589→        Some(ws) => url_groups.into_iter().filter(|(id, _)| id == ws).collect(),
   590→        None => url_groups,
   591→    };
   592→
   593→    if filtered.is_empty() {
   594→        if let Some(ws) = &workspace {
   595→            error!("no URLs for workspace '{ws}'");
   596→        }
   597→        return 1;
   598→    }
   599→
   600→    for (_, urls) in &filtered {
   601→        for url_line in urls {
   602→            // Extract the URL part (after the status icon)
   603→            let url = url_line
   604→                .trim()
   605→                .trim_start_matches('\u{25cf}')
   606→                .trim_start_matches('\u{25cb}')
   607→                .trim();
   608→            let http_url = format!("http://{url}");
   609→            #[cfg(target_os = "macos")]
   610→            let _ = std::process::Command::new("open").arg(&http_url).spawn();
   611→            #[cfg(target_os = "linux")]
   612→            let _ = std::process::Command::new("xdg-open")
   613→                .arg(&http_url)
   614→                .spawn();
   615→            info!("Opening {http_url}");
   616→        }
   617→    }
   618→
   619→    0
   620→}

   919→/// Detect git repo info from the current directory.
   920→fn detect_git_repo() -> Result<(PathBuf, String, String), String> {
   921→    // Get repo root
   922→    let root_output = std::process::Command::new("git")
   923→        .args(["rev-parse", "--show-toplevel"])
   924→        .output()
   925→        .map_err(|_| "git not found".to_string())?;
   926→    if !root_output.status.success() {
   927→        return Err("not inside a git repository".to_string());
   928→    }
   929→    let root = PathBuf::from(String::from_utf8_lossy(&root_output.stdout).trim());
   930→
   931→    // Get remote URL
   932→    let url_output = std::process::Command::new("git")
   933→        .args(["remote", "get-url", "origin"])
   934→        .output()
   935→        .map_err(|_| "git not found".to_string())?;
   936→    let url = if url_output.status.success() {
   937→        String::from_utf8_lossy(&url_output.stdout)
   938→            .trim()
   939→            .to_string()
   940→    } else {
   941→        root.to_string_lossy().to_string() // local-only repo, use path as URL
   942→    };
   943→
   944→    // Get current branch
   945→    let branch_output = std::process::Command::new("git")
   946→        .args(["rev-parse", "--abbrev-ref", "HEAD"])
   947→        .output()
   948→        .map_err(|_| "git not found".to_string())?;
   949→    let branch = String::from_utf8_lossy(&branch_output.stdout)
   950→        .trim()
   951→        .to_string();
   952→
   953→    Ok((root, url, branch))
   954→}

## 1. tmux set-option default-command

### How It Works
`default-command` specifies the command to run when a new window or pane is created, instead of starting the default shell directly.

### Syntax
```bash
# Session-specific
tmux set-option -t session-name default-command "command to run"

# Global (affects all sessions)
tmux set-option -g default-command "command to run"
```

### Can It Wrap the Shell?
**Yes**, but with caveats:

```bash
# Approach 1: Shell with inline source
tmux set-option -t dual-repo-branch default-command \
  "bash --rcfile ~/.dual/rc/dual-repo-branch.sh -i"

# Approach 2: Wrapper command
tmux set-option -t dual-repo-branch default-command \
  "bash -c 'source ~/.dual/rc/dual-repo-branch.sh && exec bash'"
```

### Issues with default-command Approach
1. **Shell-specific**: Different syntax for bash (`--rcfile`) vs zsh (no native `--rcfile`)
2. **Overrides user shell**: User's `$SHELL` and their config may not load
3. **Breaks on shell switch**: If user types `zsh` or `bash` in a pane, interception is lost
4. **Hard to set per-session before creation**: Must be set after `new-session` but before panes exist

### Concrete Example
```bash
# Create session with default-command
tmux new-session -d -s dual-myapp-main -c /workspace/myapp

# Set default-command for this session (bash-specific)
tmux set-option -t dual-myapp-main default-command \
  "bash --init-file ~/.dual/rc/dual-myapp-main.sh -i"

# Now all new panes/windows in this session will use this command
tmux split-window -t dual-myapp-main
```

**Verdict**: Possible but fragile. Better for controlled environments where shell is known.

## 2. tmux set-environment

### How It Works
Sets environment variables at the session level. New panes/windows inherit these variables.

### Syntax
```bash
# Set session-level environment variable
tmux set-environment -t session-name VAR_NAME value

# Remove a variable
tmux set-environment -u -t session-name VAR_NAME

# Global (affects all new sessions)
tmux set-environment -g VAR_NAME value
```

### Do New Panes Inherit?
**Yes**, absolutely. This is the most reliable way to pass workspace context to all panes.

### Concrete Example for Dual
```bash
# Create session
tmux new-session -d -s dual-myapp-main -c /workspace/myapp

# Set environment variables for this session
tmux set-environment -t dual-myapp-main DUAL_ACTIVE 1
tmux set-environment -t dual-myapp-main DUAL_CONTAINER dual-myapp-main
tmux set-environment -t dual-myapp-main DUAL_RC_PATH ~/.dual/rc/dual-myapp-main.sh
tmux set-environment -t dual-myapp-main DUAL_WORKSPACE myapp-main

# All new panes will have these env vars
tmux split-window -t dual-myapp-main
```

### Verify Inheritance
```bash
# In any pane of the session
echo $DUAL_CONTAINER  # Output: dual-myapp-main
```

**Verdict**: This is the most robust approach and pairs perfectly with shell RC detection.

## 3. tmux Hooks

### Available Hooks
tmux supports hooks for many events. Relevant ones:

```bash
# Hook runs AFTER a window is created
after-new-window

# Hook runs AFTER a pane is split
after-split-window

# Hook runs AFTER a session is created
after-new-session

# Hook runs when a pane is selected
after-select-pane
```

### Syntax
```bash
# Session-specific hook
tmux set-hook -t session-name hook-name "command"

# Global hook
tmux set-hook -g hook-name "command"

# Remove hook
tmux set-hook -u -t session-name hook-name
```

### Can Hooks Source RC Files?
**Yes**, but with limitations:

```bash
# Hook to send source command when pane is created
tmux set-hook -t dual-myapp-main after-split-window \
  "send-keys -t '#{pane_id}' 'source ~/.dual/rc/dual-myapp-main.sh' Enter"

# Hook for new windows
tmux set-hook -t dual-myapp-main after-new-window \
  "send-keys -t '#{window_id}.1' 'source ~/.dual/rc/dual-myapp-main.sh' Enter"
```

### Hook Variables
tmux provides variables in hooks:
- `#{session_name}` - Session name
- `#{window_id}` - Window ID
- `#{pane_id}` - Pane ID
- `#{hook}` - Hook name that triggered

### Issues with Hook Approach
1. **Visible command**: User sees `source ~/.dual/rc/...` echoed in terminal
2. **Timing**: Hook runs after shell starts, so there's a brief moment without interception
3. **Command prompt pollution**: The source command appears in history
4. **Race conditions**: If user types fast, they might execute before source completes

### Concrete Example
```bash
# Create session
tmux new-session -d -s dual-myapp-main -c /workspace/myapp

# Set hooks for this session only
tmux set-hook -t dual-myapp-main after-split-window \
  "send-keys -t '#{pane_id}' 'source ~/.dual/rc/dual-myapp-main.sh' Enter"

tmux set-hook -t dual-myapp-main after-new-window \
  "send-keys -t '#{window_id}.1' 'source ~/.dual/rc/dual-myapp-main.sh' Enter"

# Now split a pane - hook will auto-source
tmux split-window -t dual-myapp-main
```

**Verdict**: Functional but ugly. User-visible and pollutes command history.

## 5. default-shell vs default-command

### default-shell
- Sets which shell binary to execute: `/bin/bash`, `/bin/zsh`, etc.
- **Does not** affect shell initialization
- **Does not** change how RC files are sourced
- Default: inherits from `$SHELL` environment variable

```bash
# Global
tmux set-option -g default-shell /bin/zsh

# Session-specific (must be set before creating session)
tmux set-option -s default-shell /bin/bash
```

### default-command
- Sets the **command** to run instead of the shell
- Can be a shell wrapper that pre-sources files
- Overrides `default-shell` if set

```bash
# Run bash with custom rcfile
tmux set-option -g default-command "bash --rcfile ~/.dual/rc/current.sh"
```

### Can default-command Wrap Shell Startup?
**Yes**, but shell-specific:

```bash
# Bash: Use --rcfile or --init-file
tmux set-option -t dual-session default-command \
  "bash --init-file ~/.dual/rc/dual.sh -i"

# Zsh: No native --rcfile, must use ZDOTDIR
tmux set-option -t dual-session default-command \
  "ZDOTDIR=~/.dual/rc/zsh zsh"

# Fish: Use --init-command
tmux set-option -t dual-session default-command \
  "fish --init-command='source ~/.dual/rc/dual.fish'"
```

### Key Difference
- `default-shell`: What to execute
- `default-command`: How to execute it (or execute something else entirely)

**Verdict**: Use `default-shell` to respect user's shell choice, avoid `default-command` complexity.

## 6. set-option Scopes: -s vs -g vs session-specific

### Option Scopes

| Flag | Scope | Affects | Example |
|------|-------|---------|---------|
| (none) | Session-specific | Only named session | `tmux set-option -t mysession ...` |
| `-g` | Global | All sessions and new sessions | `tmux set-option -g ...` |
| `-s` | Server | Server-wide settings | `tmux set-option -s ...` |

### Session-Specific Options
```bash
# Only affects dual-myapp-main session
tmux set-option -t dual-myapp-main default-command "bash --init-file ~/.dual/rc/dual.sh"

# Other tmux sessions are unaffected
tmux set-option -t personal-session default-command "zsh"
```

### How to Keep Dual Sessions Isolated
```bash
# GOOD: Session-specific, doesn't affect other sessions
tmux new-session -d -s dual-myapp-main
tmux set-option -t dual-myapp-main status-style "bg=blue"
tmux set-environment -t dual-myapp-main DUAL_ACTIVE 1

# BAD: Global, affects all sessions
tmux set-option -g status-style "bg=blue"  # Don't do this
```

### Environment Variables are Inherently Scoped
```bash
# This ONLY affects dual-myapp-main session
tmux set-environment -t dual-myapp-main DUAL_CONTAINER dual-myapp-main

# Other sessions don't see this variable
```

**Verdict**: Always use session-specific (`-t session-name`) for Dual sessions. Never use `-g` for Dual features.

## The Problem

Today, shell interception only works in the **first pane**. The chain is:

1. `cmd_launch()` writes RC file to `~/.dual/rc/dual-repo-branch.sh`
2. `create_session()` creates tmux session, sends `source ~/.dual/rc/...` via `send_keys` into pane 0
3. User splits a pane → new shell starts → **no interception** → `pnpm dev` runs on host

The `DUAL_CONTAINER` env var is set inside the first pane's shell process, not in tmux's session environment. New panes don't inherit it.

## The Fix — Two Parts

### Part 1: `tmux set-environment` (code change)

After creating the session, set session-level env vars that **all new panes automatically inherit**:

```
tmux set-environment -t {session} DUAL_ACTIVE 1
tmux set-environment -t {session} DUAL_RC_PATH ~/.dual/rc/{container}.sh
tmux set-environment -t {session} DUAL_CONTAINER {container}
```

This goes in `tmux_backend.rs` after the `new-session` call.

### Part 2: Shell RC snippet (user setup)

User adds 3 lines to their `~/.bashrc` or `~/.zshrc`:

```bash
# Dual workspace command interception
if [ -n "$DUAL_ACTIVE" ] && [ -n "$DUAL_RC_PATH" ] && [ -f "$DUAL_RC_PATH" ]; then
    source "$DUAL_RC_PATH"
fi
```

Every new pane inherits `DUAL_ACTIVE` + `DUAL_RC_PATH` from tmux → shell RC detects them → auto-sources the interception file. Non-Dual sessions don't have these vars, so the snippet is a no-op everywhere else.

### Why not tmux hooks or `default-command`?

- **Hooks** (`after-split-window` + `send-keys`): Works but the `source` command is visible to the user and pollutes shell history
- **`default-command`**: Shell-specific (bash `--init-file` vs zsh `ZDOTDIR`), may break user's shell config

The `set-environment` + shell RC approach is invisible, shell-agnostic, and doesn't affect non-Dual sessions.
