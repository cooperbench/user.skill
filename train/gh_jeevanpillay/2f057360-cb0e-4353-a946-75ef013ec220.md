Good question. Currently the plan only adds realtime to the **entity list** page (live prepend when new entities are upserted). The entity detail page's events timeline is static — it fetches on load and doesn't update.

**Should the entity detail events timeline also be realtime?**

Two options:

1. **Yes, live events on entity detail** — When a new event is ingested that links to the entity you're viewing, it prepends to the timeline. This would reuse the existing `org.event` realtime channel, filtering on the client side by checking if the event's entities include the current entity. The challenge: the `org.event` notification payload contains `sourceEvent` (the raw `PostTransformEvent`), not the entity junction data, so we'd need to either:
   - Add entity references to the `org.event` payload (heavier notification)
   - Create a separate `org.entity.event` realtime event emitted after junction rows are created in `platform-event-store.ts`

2. **No, just polling or manual refresh** — Simpler. Entity detail pages are typically viewed briefly, not left open for monitoring. A manual refresh or short polling interval (e.g., 30s `refetchInterval`) would be pragmatic.

Which approach do you prefer? Or would you like a different tradeoff (e.g., realtime for the entity list but polling for entity detail)?
