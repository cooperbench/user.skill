## Unit tests for `parseDotLightfast`

Test fixture: an in-memory `Fetcher` that returns pre-seeded path → `FetcherResult` mappings. No network, no I/O.

**Happy path / shape**
- Full config (SPEC + 2 skills, one with command, one without) → returns expected `{spec, skills[]}` with correct manifest shape.
- `SkillManifest.path` is `skills/<name>/` — no `.lightfast/` prefix (regression guard for the prefix fix).
- Fetcher invoked with exactly these paths: `SPEC.md`, `skills`, `skills/<name>/SKILL.md`, `skills/<name>/command/<name>.md` (assert call args — regression guard).

**Missing-config branches (these drive the consumer's `no_dotlightfast_config` skip)**
- SPEC missing + skills missing → `{spec: null, skills: []}`.
- SPEC missing + skills present → `{spec: null, skills: [...]}`.
- SPEC present + skills dir missing → `{spec, skills: []}`.

**SPEC-specific edge cases**
- SPEC is a directory → throws `DotLightfastParseError` with path `SPEC.md`.
- SPEC larger than `MAX_SPEC_BYTES` (32_000) → truncated to exactly 32_000 chars.
- SPEC exactly at limit → not truncated.

**Skills filtering / caps**
- `skills/` contains mix of dirs + files → files silently skipped.
- 60 skill dirs → first 50 loaded, extras dropped (`MAX_SKILLS` cap).
- Skill dir missing `SKILL.md` → silently skipped, no throw.

**Frontmatter resilience (all should silently skip, never throw)**
- Skill with no frontmatter block → skipped.
- Skill with malformed YAML frontmatter → skipped.
- Skill frontmatter is a YAML array/scalar (not an object) → skipped.
- Skill frontmatter fails `SkillFrontmatterSchema` (e.g. missing `name`/`description`) → skipped.
- Skill frontmatter with CRLF line endings → parsed correctly (regex has `\r?\n`).

**Command-probe branching**
- Skill with command file at `skills/<name>/command/<name>.md` → `hasCommand: true`.
- Skill with command path that's a directory → `hasCommand: false`.
- Skill with no command file → `hasCommand: false`.

**Fetcher contract**
- Fetcher throws → error propagates (not swallowed).
