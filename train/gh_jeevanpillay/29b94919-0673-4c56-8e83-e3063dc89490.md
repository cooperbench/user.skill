## `@repo/app-test-data` sandbox — capabilities A CLI-only package for locally replaying signed provider webhooks through the real ingest path. Not an app dependency; invoked via `pnpm --filter @repo/app-test-data sandbox:<command>`. ### Commands - **`sandbox:list`** — Prints the registered scenarios (currently `github-pr-closed`, `vercel-deployment-succeeded`) with descriptions. - **`sandbox:doctor`** — Health check. Reports (a) whether `platform` (4112) and `app` (3024) dev URLs are reachable, and (b) which provider signing secrets are present in the env (`GITHUB_WEBHOOK_SECRET`, `LINEAR_WEBHOOK_SIGNING_SECRET`, `SENTRY_CLIENT_SECRET`, `VERCEL_CLIENT_INTEGRATION_SECRET`). Exit code 0 either way — diagnostic only. - **`sandbox:seed -- <scenario>`** — Seeds DB rows (`gateway_installations`, `org_integrations`) so the ingest path has a connection to match against. Uses `onConflictDoUpdate` so it's rerunnable. - **`sandbox:replay -- <scenario>`** — Loads the fixture from `packages/webhook-schemas/fixtures`, signs it with the provider's real signing algorithm (HMAC-sha1/sha256), and POSTs to `/api/ingest/<provider>` on the chosen target. No DB assertions. - **`sandbox:run -- <scenario>`** — Full E2E: `seed` → `replay` → poll `gateway_webhook_deliveries` + `org_ingest_logs` until the expected delivery status/log counts land. Throws `AssertionTimeoutError` with structured fields (deliveryId, lastStatus, lastIngestLogs, elapsedMs, provider, scenario, url) on timeout. ### Flags (replay/run) - `--target platform|app` — which ingress to hit (default `platform`). - `--base-url <url>` — override the target's base URL. - `--timeout-ms <n>` — assertion timeout (default 20s). - `--json` — JSON output instead of `console.dir`. ### Provider support Per-provider sandbox modules under `src/lib/providers/` own signing, event-type derivation, and resource-ID overrides for `github`, `linear`, `sentry`, `vercel`. Adding a fifth webhook provider = add one file to that folder and register it in `providers/index.ts`. ### What it doesn't do No outbound provider stubs, no token seeding, no Clerk UI automation, no test framework — the CLI E2E run *is* the integration test. Requires `pnpm dev:full` running to exercise `replay`/`run`.
