> AGENT

`#[ignore]` in Rust marks a test as **skipped by default** in `cargo test`. To run ignored tests you must explicitly opt in with `--include-ignored`. The reason it's combined with proptest here: proptest runs **hundreds of randomized iterations** per test (`parse_rust_source_never_panics`, etc.), making the suite slow. By tagging them `#[ignore]`, normal `cargo test` stays fast (unit/integration tests only), while the slow property sweep is opt-in: ``` # normal fast run cargo test # explicit property run cargo test --test parse_rust_source_property_test -- --include-ignored ``` The comment at the top of `tests/parse_rust_source_property_test.rs:2` documents exactly this. The architect's retro item was confirming this separation was the right design — the architect had used it during the session and it worked, so no rule change was needed.

> DEVELOPER

its the proper way? its strange to have ignored tests

> AGENT

It's a legitimate pattern but not the only one, and it has a real downside worth knowing. **Why it works here:** `cargo test` runs all integration test files by default, so without `#[ignore]`, plain `cargo test` would invoke hundreds of proptest iterations and be slow every time. `#[ignore]` opts them out of the default run while keeping them in the same repo. **The real problem with `#[ignore]`:** it's easy to forget. If CI just runs `cargo test`, the property tests never execute. They become dead code that nobody runs. **More explicit alternatives:** Feature flag — opt-in at compile time, CI can add a separate job: ```toml # Cargo.toml [features] property-tests = [] ``` ```rust #[cfg(feature = "property-tests")] mod property_tests { ... } ``` ``` cargo test --features property-tests ``` Environment variable via `ProptestConfig` — always compiles, controls iteration count: ```rust ProptestConfig::with_cases( std::env::var("PROPTEST_CASES").ok() .and_then(|v| v.parse().ok()) .unwrap_or(10) ) ``` Fast locally (10 cases), thorough in CI (1000 cases). **Verdict:** `#[ignore]` is idiomatic Rust and the standard library uses it too, but it only makes sense if CI explicitly passes `--include-ignored` in a dedicated job. If the pipeline just runs `cargo test`, those tests are silently never running. Worth checking whether CI actually invokes them.
