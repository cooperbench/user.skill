# QA Suite: Soft Drop

End-to-end verification of player soft drop: one-row descent per press, +1 point per row,
blocking when the piece is at rest, and phase-gating when not playing.

All verification is performed through the terminal UI. No API or internal state access.
The surface harness drives the real `tetris` binary in a tmux session: `send-keys -l` for
raw input bytes at controlled timing, `capture-pane` for screen state, asserting on captures
over time. Use `./tetris --qa` (or the project's QA launch command) to start the game in a
state that allows deterministic piece and board control via command-line flags where noted.

The soft drop key is `↓` (Down Arrow), bound to `PlayerSoftDrops()` per EXPERIENCE.md.
Score is a stat block that updates instantly with no count-up animation.

---

## QA-SD-1: Soft drop steps the piece one row down

**Precondition:** Game is playing. The active piece is in the upper board with empty rows below it
(not at rest). Note its current top row position on-screen and the current score value.

**Steps:**
1. Press `↓` (down arrow) once.

**Expected:**
- The piece glyphs (`██`) move down by exactly one cell row.
- The gap between the piece and its ghost (`░░`) shrinks by exactly one row.
- No horizontal shift, no rotation, no other board cells change.

---

## QA-SD-2: Soft drop awards one point per row

**Precondition:** Game is playing. The active piece is not at rest. Note the current score value `S`.

**Steps:**
1. Press `↓` once.
2. Read the score stat block.

**Expected:**
- The score increases by exactly 1 (now `S + 1`).
- The score field updates instantly with no count-up animation and stays within its fixed width.

---

## QA-SD-3: Repeated soft drops accumulate one point each

**Precondition:** Game is playing. The active piece has at least 5 empty rows below it. Note score `S`.

**Steps:**
1. Press `↓` five times, with a brief pause between presses (distinct keypresses, not a hold).

**Expected:**
- The piece moves down 5 rows total (one per press), stopping if it reaches rest before 5.
- For each row actually descended, the score increases by exactly 1 — after 5 free rows, score is `S + 5`.
- No points are awarded for any press that did not move the piece (e.g. once at rest).

---

## QA-SD-4: Soft drop is blocked when the piece is at rest

**Precondition:** Game is playing. The active piece is resting on the floor or on locked cells

**Steps:**
1. Press `↓` once.

**Expected:**
- The piece does not move.
- The score does not change (remains `S`) — no point is awarded for a blocked soft drop.
- The piece does not lock early as a result of the soft drop; it locks only when the lock
  countdown elapses (soft-drop-into-rest does not force an immediate lock).
- No visual glitch, flash, or error state appears.

---

## QA-SD-5: Soft drop is faster and more controlled than hard drop

**Precondition:** Game is playing. The active piece is high on the board with many empty rows below.

**Steps:**
1. Press `↓` once and observe.

**Expected:**
- A single `↓` press moves the piece exactly one row — it does NOT snap to the bottom.
- This is visibly distinct from a hard drop (`Space`), which would snap the piece to the floor instantly.

---

## QA-SD-6: Soft drop is ignored when paused

**Precondition:** Game is playing. Pause the game with `P` (or `Esc`). Board content is hidden
behind the paused fill; `PAUSED` is centered. Note the score value shown in the stats.

**Steps:**
1. Press `↓` while paused.

**Expected:**
- No piece movement occurs (board content remains hidden under the paused fill).
- The score does not change.
- When resumed (`P` or `Esc`), the piece is in the same position it held when paused.

---

## QA-SD-7: Soft drop is ignored on the waiting and game-over screens

**Precondition:** Game is at the waiting screen (TETRIS art) OR at the game-over screen.

**Steps:**

**Expected:**
- No piece movement, no score change, no transition.

## QA-SD-8: Held soft drop descends continuously

**Expected:**
- The piece descends smoothly row by row while the key is held (treated as continuous

- Terminal scrollback does not grow — the game renders in place, not by appending lines.

# observation-harness/soft_drop

Tmux-based regression scenarios for the soft-drop feature. Each script drives the real `tetris`
binary in a tmux session, sends raw key bytes with `send-keys -l`, captures pane output with
`capture-pane`, and asserts on the result.

## Scenarios

| Script | QA ref | What it verifies |
|---|---|---|
| `baseline.sh` | QA-SD-9 | Idle waiting screen — consecutive captures identical, scrollback stable |
| `sd1_step_one_row.sh` | QA-SD-1 | After one ↓ press, piece glyphs move down and frame is structurally intact |
| `sd6_paused.sh` | QA-SD-6 | ↓ while paused has no effect; PAUSED overlay remains |

## Prerequisites

- `tmux` installed
- `./tetris` binary built at the project root (`go build -o tetris ./cmd/tetris`)
- Run from the project root directory

## Running

```sh
go build -o tetris ./cmd/tetris
chmod +x observation-harness/soft_drop/*.sh
./observation-harness/soft_drop/baseline.sh
./observation-harness/soft_drop/sd1_step_one_row.sh
./observation-harness/soft_drop/sd6_paused.sh
```

## Key byte reference

| Input | Raw bytes | tmux send-keys |
|---|---|---|
| Down arrow (↓) | `0x1b 0x5b 0x42` | `send-keys -lt $SESSION $'\x1b[B'` |
| Enter | `0x0d` | `send-keys -lt $SESSION $'\r'` |
| P (pause) | `0x70` | `send-keys -lt $SESSION "p"` |
```

# Surface: TUI / terminal (tmux + capture-pane)
# Precondition: Game binary running in a tmux pane. Game is on the waiting screen.

  echo "--- capture 2 ---" >&2

echo "PASS: idle waiting screen is stable across consecutive captures"

// When GHERKIN_FEATURE_JSON is set, example values are loaded from that file,
// enabling gherkin-mutator to drive differential mutation.
package soft_drop_test

import (
	"encoding/json"
	"math/rand"
	"os"
	"strconv"

// --- Feature JSON loader ---

type gherkinFeature struct {
	Scenarios []gherkinScenario `json:"scenarios"`
}

type gherkinScenario struct {
	Examples []map[string]string `json:"examples"`
}

var loadedFeature *gherkinFeature

func featureExamples(scenarioIndex, exampleIndex int) map[string]string {
	if loadedFeature == nil {
		path := os.Getenv("GHERKIN_FEATURE_JSON")
		if path == "" {
			return nil
		}
		f, err := os.Open(path)
		if err != nil {
			return nil
		}
		defer f.Close()
		var feat gherkinFeature
		if err := json.NewDecoder(f).Decode(&feat); err != nil {
			return nil
		}
		loadedFeature = &feat
	}
	if scenarioIndex >= len(loadedFeature.Scenarios) {
		return nil
	}
	s := loadedFeature.Scenarios[scenarioIndex]
	if exampleIndex >= len(s.Examples) {
		return nil
	}
	return s.Examples[exampleIndex]
}

func exStr(scenarioIndex, exampleIndex int, key, def string) string {
	ex := featureExamples(scenarioIndex, exampleIndex)
	if v, ok := ex[key]; ok {
		return v
	}
	return def
}

func exInt(scenarioIndex, exampleIndex int, key string, def int) int {
	v := exStr(scenarioIndex, exampleIndex, key, "")
	if v == "" {
		return def
	}
	i, err := strconv.Atoi(v)
	if err != nil {
		return def
	}
	return i
}

// --- Helpers ---

func sessionInPhase(t *testing.T, phase string) *game.Session {
	t.Helper()
	s := game.NewSession(rand.New(rand.NewSource(42)))
	switch phase {
	case "playing":
		s.PlayerStartsGame()
	case "paused":
		s.PlayerStartsGame()
		s.PlayerPauses()
	default:
		t.Fatalf("unknown phase: %s", phase)
	}
	return s
}

// pieceNotAtRest places an O-piece at the given origin row and asserts it is not at rest.
// The O-piece (2×2) is safe: on an empty board it is not at rest until its bottom reaches row 19.
func pieceNotAtRest(t *testing.T, s *game.Session, row int) {
	t.Helper()
	s.ActivePiece = &game.ActivePiece{
		Kind:     game.KindO,
		Origin:   game.Position{Col: 4, Row: row},
		Rotation: game.RotationNorth,
	}
	if s.ActivePiece.AtRest(s.Board) {
		t.Errorf("board setup: O-piece at row %d is already at rest — example not applicable", row)
		return
	}
}

// pieceAtRest places an O-piece at the ghost position from row 0 (the floor) so AtRest is true.
// The ghost is determined by the board; on an empty board the O-piece rests at row 18.
func pieceAtRest(t *testing.T, s *game.Session, wantRow int) {
	t.Helper()
	ap := &game.ActivePiece{
		Kind:     game.KindO,
		Origin:   game.Position{Col: 4, Row: 0},
		Rotation: game.RotationNorth,
	}
	ghost := ap.GhostOrigin(s.Board)
	if ghost.Row != wantRow {
		t.Errorf("board setup: O-piece ghost row = %d, want %d", ghost.Row, wantRow)
		return
	}
	s.ActivePiece = &game.ActivePiece{
		Kind:     game.KindO,
		Origin:   ghost,
		Rotation: game.RotationNorth,
	}
	if !s.ActivePiece.AtRest(s.Board) {
		t.Errorf("board setup: O-piece at ghost row %d is not at rest", ghost.Row)
		return
	}
}
