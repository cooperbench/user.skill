## Claude Code の rules ファイルの条件付き適用について

公式ドキュメント確認の結果、**path-specific rules（パス固有のルール）機能が実装されている**ことが確認できました。以下が詳細です。

---

### 1. **Path-specific rules の仕組み（実装済み）**

`.claude/rules/` ディレクトリ内のマークダウンファイルに **YAML frontmatter** を使用して、適用対象ファイルを指定できます。

**基本的な構文：**

```markdown
---
paths:
  - "src/api/**/*.ts"
  - "lib/**/*.ts"
---

# API 開発ルール

- すべての API エンドポイントには入力検証を含める
- 標準的なエラーレスポンス形式を使用する
- OpenAPI ドキュメントコメントを含める
```

**glob パターンサポート：**

| パターン | マッチ対象 |
|---------|----------|
| `**/*.ts` | すべてのディレクトリの TypeScript ファイル |
| `src/**/*` | `src/` ディレクトリ配下のすべてのファイル |
| `*.md` | プロジェクトルートの Markdown ファイル |
| `src/**/*.{ts,tsx}` | `src/` 配下の .ts と .tsx ファイル（ブレース展開対応） |

---

### 2. **複数パターンの指定**

```markdown
---
paths:
  - "src/**/*.{ts,tsx}"
  - "tests/**/*.test.ts"
  - "{src,lib}/**/*.ts"
---
```

---

### 3. **プロジェクトタイプによる条件付け（注意：標準機能なし）**

**重要：** Cargo.toml が存在するプロジェクトなど、**ファイルの存在有無による動的な条件付けは標準機能として存在しません。

代わりに以下の方法を検討してください：

#### **方法 A：手動でプロジェクトを分別する**
```bash
# Rust プロジェクト用 rules
.claude/rules/rust-specific.md

# Node.js プロジェクト用 rules  
.claude/rules/nodejs-specific.md
```

各ファイルに `paths` frontmatter で対象ファイルパターンを限定。

#### **方法 B：hooks を使った動的ルール適用**

`PreToolUse` または `SessionStart` フックを使用して、セッション開始時に条件をチェック：

```bash
# hooks/detect-project-type.sh
#!/bin/bash
if [ -f "Cargo.toml" ]; then
  # Rust プロジェクト処理
elif [ -f "package.json" ]; then
  # Node.js プロジェクト処理
fi
```

---

### 4. **organization-level rules（組織レベルのルール）**

`.claude/rules/` 以外に、ユーザーレベルのルール も指定可能：

```
~/.claude/rules/
├── preferences.md     # 個人の基本設定
└── workflows.md       # 個人のワークフロー
```

組織レベルでは管理者が以下に配置：
- macOS: `/Library/Application Support/ClaudeCode/CLAUDE.md`
- Linux: `/etc/claude-code/CLAUDE.md`
- Windows: `C:\Program Files\ClaudeCode\CLAUDE.md`

---

### 5. **settings.json での条件付け**

`settings.json` には **ルールファイル直接の条件指定機能はありません**。代わりに `permissions` セクションでパス制限が可能です：

```json
{
  "permissions": {
    "allow": [
      "Read(src/**/*.ts)",
      "Bash(cargo:*)"
    ],
    "deny": [
      "Read(.env)"
    ]
  }
}
```

---

### 推奨される構成

あなたのプロジェクト（`dotnix`）では以下のような構成が最適です：

```
.claude/
├── CLAUDE.md
└── rules/
    ├── general.md                    # 全プロジェクト共通
    ├── nix-development.md            # paths: "**/*.nix"
    ├── rust-specific.md              # paths: "**/*.rs"
    ├── lua-neovim.md                 # paths: "nvim/**"
    └── shell-scripts.md              # paths: "**/*.{sh,zsh}"
```

各ファイルで `paths` frontmatter を指定することで、**ファイルタイプごとの条件付け**が実現できます。

## 結論

**`paths` frontmatter で glob パターン指定が可能**ですが、「Cargo.toml が存在するかどうか」という動的な条件判定はできません。

### paths frontmatter の仕組み

rules ファイルの先頭に YAML frontmatter で `paths` を指定すると、そのパターンにマッチするファイルを扱っているときだけルールが適用されます。

```markdown
---
paths:
  - "**/*.rs"
  - "**/Cargo.toml"
---

# ルール内容
```

### 今回のケースの問題

ただし、今回のルールは「`.cargo/registry/src/` を読んでよい」という一般的な許可であり、特定のファイルパスに対する作業指示ではありません。`paths` は「このパターンのファイルに触れているときにルールを表示する」という仕組みなので、`**/*.rs` や `**/Cargo.toml` を指定すれば Rust ファイルを扱う文脈でのみ適用されるようにはできます。
