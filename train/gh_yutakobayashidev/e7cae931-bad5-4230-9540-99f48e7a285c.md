Perfect! I found the documentation. Here's what you need to know about Claude Code rules frontmatter:

## Available Frontmatter Fields

Based on the official Claude Code documentation, the **only frontmatter field currently available for rules** is:

```yaml
---
paths:
  - "glob-pattern-1"
  - "glob-pattern-2"
---
```

## Scoping Rules to Directories

The `paths` field uses **glob patterns** to restrict rules to specific files and directories. Here are the key details:

### Basic Syntax

```markdown
---
paths:
  - "src/api/**/*.ts"
  - "lib/**/*.ts"
---

# Your rule content here
```

### Glob Pattern Examples

| Pattern | Matches |
|---------|---------|
| `src/**/*.ts` | All TypeScript files under `src/` directory |
| `src/**/*` | All files under `src/` directory |
| `**/*.ts` | All TypeScript files anywhere in the project |
| `*.md` | Markdown files in project root only |
| `src/components/*.tsx` | React components in specific directory |

### Multiple Patterns & Brace Expansion

You can use multiple patterns and brace expansion:

```markdown
---
paths:
  - "src/**/*.{ts,tsx}"
  - "{src,lib}/**/*.ts"
---
```

This expands to match both `.ts` and `.tsx` files in `src/lib/`.

## Answer to Your Specific Question

To scope a global rule (from `~/.config/claude/rules/`) to only apply within a certain directory tree like `/home/user/ghq/`:

**Unfortunately, there is no `globs` or `path` field that works at the filesystem level for user-level rules.** The `paths` field only works within a project context to scope rules to specific file patterns.

For global directory-level scoping, your options are:

1. **Place the rule in a project's `.claude/rules/` directory** instead of your user-level `~/.config/claude/rules/`, and use `paths` to scope it to specific files/directories.

2. **Use project-level `.claude/rules/` files** that apply to all files in that project (no `paths` field needed).

3. **Add a condition in the rule text itself** explaining when it should apply, though Claude won't automatically enforce this.

Sources:
- [Claude Code Memory Documentation](https://code.claude.com/docs/en/memory.md#modular-rules-with-claude-rules)

| Pattern Type | Meaning | Example |
|---|---|---|

**Tilde expansion IS documented as supported** — the `~` syntax explicitly expands to the user's home directory.

### 2. **Known Issues with Tilde Expansion**

Despite documented support, there are **known bugs** with tilde expansion:

**Issue #19531** - [Glob tool inconsistently handles tilde expansion](https://github.com/anthropics/claude-code/issues/19531): The Glob tool expands `~` in the `path` parameter but NOT in the `pattern` parameter, causing silent failures.

**Issue #15499** - [Permission patterns with ~ paths don't match when paths are converted to relative](https://github.com/anthropics/claude-code/issues/15499): The permission system converts absolute paths to relative paths before matching, causing patterns like `Write(~/.claude/**)` to fail because the converted relative path (`handoffs/test.md`) doesn't match the `~` pattern.

**Issue #15421** - [Global permission rules not matching paths under ~/Code/](https://github.com/anthropics/claude-code/issues/15421): Permission rules configured with tilde paths don't work correctly in practice, requiring absolute paths instead.

### 3. **Root Cause of the Tilde Problem**

The implementation has a **path normalization mismatch**:

```
Tool call path:     /Users/user/.claude/handoffs/test.md
                           ↓
                    Convert to relative
                           ↓
Checked path:       handoffs/test.md
Pattern:            Write(~/.claude/**)
Result:             NO MATCH ❌
```

The patterns with `~` are matched **literally** against relative paths, but the tilde expansion happens (if at all) as a preprocessing step that doesn't get normalized to match the converted paths.

### 4. **YAML Syntax Issues**

**Issue #13905** - [Invalid YAML syntax in claude/rules frontmatter `paths` property](https://github.com/anthropics/claude-code/issues/13905): Glob patterns starting with `{` or `*` cannot be used unquoted in YAML. These must be quoted:

```yaml
# WRONG - invalid YAML
paths: **//*.ts
paths: {src,lib}/**//*.ts

# CORRECT - quoted strings
paths: "**//*.ts"
paths: "src/**/*.ts"

# CORRECT - sequence format (preferred)
paths:
  - "src/**/*.ts"
  - "tests/**/*.test.ts"
```

Claude Code is a **compiled binary** (ELF 64-bit executable) distributed through:

### 6. **Glob Pattern Support**

The documented glob syntax follows **gitignore conventions**:
- `*` matches files in a single directory
- `**` matches recursively across directories
- `?` matches any single character
- `[abc]` matches any character in brackets
- `{a,b,c}` matches any of the comma-separated patterns (must be quoted in YAML)
