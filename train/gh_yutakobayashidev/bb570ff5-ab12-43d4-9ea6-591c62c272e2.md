## Research Results: `darwin.installApplication` in Nix/nixpkgs

### 1. What It Is

`darwin.installApplication` is **not an official part of nixpkgs**. It is a community-developed helper function pattern for packaging macOS `.app` bundles (distributed as `.dmg` or `.zip` files) as Nix derivations. It originated from **John Wiegley's** (`jwiegley`) personal nix-config repository, specifically from an overlay file historically named `overlays/30-apps.nix`.

In February 2021, a NixOS Discourse thread titled "Feedback: darwin.installApplication" proposed formalizing this pattern for upstream inclusion in nixpkgs. However, it was **never merged into the official nixpkgs repository** -- there is no `pkgs.darwin.installApplication` in nixpkgs today.

There are two notable implementations:

- **jwiegley's original** (`jwiegley/nix-config`, overlay `30-apps.nix`, now possibly removed from current master)
- **ldeck's fork/refinement** (`ldeck/nix-functions`, at `functions/darwin/installers/app.nix`)

A more advanced version was proposed on the Discourse thread by user `spease` that handles DMG, ZIP, and PKG archives more robustly.

#### ldeck's `app.nix` (simpler, closer to jwiegley's original)

File: `ldeck/nix-functions` at `/functions/darwin/installers/app.nix`

```nix
  name,              # Package name (string)
  appname ? name,    # The .app bundle name, defaults to name (string)
  version,           # Version string
  src,               # Source archive, typically from fetchurl (derivation)
  description,       # Package description for meta (string)
  homepage,          # Homepage URL for meta (string)
  postInstall ? "",  # Additional shell commands after install (string)
  sourceRoot ? ".",   # Root directory after unpack (string)
  pkgs,
  stdenv,
  lib,
  undmg,
  unzip,
  ...
}:

if stdenv.isDarwin then
  (stdenv.mkDerivation {
    name = "${name}-${version}";
    version = "${version}";
    src = src;
    buildInputs = [ undmg unzip ];
    sourceRoot = sourceRoot;
    phases = [ "unpackPhase" "installPhase" ];
    installPhase = ''
      mkdir -p "$out/Applications/${appname}.app"
```

#### Discourse `spease` version (more robust, handles DMG/ZIP/PKG)

From the NixOS Discourse thread, a more complete implementation:

```nix
{ cpio, fetchurl, fixDarwinDylibNames, lib, stdenvNoCC, undmg, unpkg, unzip }:
s@{ description, homepage, license, maintainers, name, version, postInstall ? "", ... }:

stdenvNoCC.mkDerivation rec {
  inherit name version;

  nativeBuildInputs = [ cpio fixDarwinDylibNames undmg unpkg unzip ];

  sourceRoot = ".";
  src = if builtins.hasAttr "src" s then s.src else fetchurl {
    name = builtins.replaceStrings [ "%20" ] [ "-" ]
      (builtins.head (builtins.match ".*/([^/]+)" s.url));
    url = s.url;
    sha256 = s.sha256;
  };

  phases = [ "unpackPhase" "installPhase" ];

  installPhase = if builtins.hasAttr "installPhase" s then s.installPhase else ''
    app=( ./*.app )
    if [ ! -z "$app" ]; then
      mkdir -p $out/Applications
      mv -n "$app" $out/Applications/
    fi

    if [ -d "./usr/local" ]; then
      mv -n ./usr/local/* $out/
    fi

    if [ ! -L "./Applications" ] && [ -d "./Applications" ]; then
      mkdir -p $out/Applications
      mv -n ./Applications/* $out/Applications/
    fi
  '' + postInstall;

  meta = with lib; {
    description = description;
    homepage = homepage;
    license = licenses."${license}";
    platforms = platforms.darwin;
  };
}
```

### 3. Appcast / Sparkle Support

**There is no automatic update support via appcast/Sparkle in any of these implementations.** The `appcast` parameter exists only in `ldeck/nix-functions` and is used purely as **metadata** -- it stores a URL where a human can check for new releases. It does not trigger automatic downloads or version bumping.

Example from ldeck's Firefox installer:

```nix
pkgs.callPackage functions.darwin.installers.app rec {
  name = "Firefox";
  sourceRoot = "Firefox.app";
  version = "92.0";
  src = pkgs.fetchurl {
    url = "https://download-installer.cdn.mozilla.net/pub/firefox/releases/${version}/mac/en-US/Firefox+${version}.dmg";
    sha256 = "0kln28330jhmpdvsdsnrqnl0fkpb18i9vi1n98v99aq61ncqr5v8";
    name = "Firefox-${version}.dmg";
  };
  description = "The Firefox web browser";
  homepage = https://www.mozilla.org/en-US/firefox/;
  appcast = https://www.mozilla.org/en-US/firefox/releases/;
};
```

The `appcast` field here is informational only -- analogous to how Homebrew Cask uses `appcast` URLs to track upstream versions, but Nix being declarative and reproducible means version updates must always be explicit (changing `version` and `sha256` in the derivation). There is no Sparkle integration or automatic update mechanism.

```nix
    sourceRoot = ".";

    installPhase = ''
      runHook preInstall
      mkdir -p $out/Applications
      cp -r "MyApp.app" $out/Applications/
      runHook postInstall

    meta = with prev.lib; {
      description = "My macOS application";
      homepage = "https://example.com";
      license = licenses.unfree;
      platforms = platforms.darwin;
    };
  };
}
```

## `darwin.installApplication` について

**nixpkgs の公式関数ではない。** jwiegley 氏の個人 nix-config にあったコミュニティパターンで、upstream には取り込まれていません。

ldeck 版に `appcast` パラメータがあるが、**単なるメタデータ**（人間が確認するための URL）であり、自動バージョン検出は一切しない。Nix は宣言的なので version と hash は常に明示的に更新する必要がある。

> AGENT

変更点:

- **`stdenv` → `stdenvNoCC`** — コンパイラ不要なバイナリ配布パッケージなので CC ツールチェイン不要
- **`finalAttrs` パターン** — URL 内のバージョンを `finalAttrs.version` で参照（バージョン更新時に1箇所だけ変えれば済む）
- **`phases` を明示** — `unpackPhase` + `installPhase` のみ（ビルドフェーズ不要）
- **`cp -pR`** — パーミッションとシンボリックリンクを保持
- **`meta.appcast`** — Sparkle appcast URL をメタデータとして記録。将来 CI で自動更新スクリプトを書く際の手がかりになる
