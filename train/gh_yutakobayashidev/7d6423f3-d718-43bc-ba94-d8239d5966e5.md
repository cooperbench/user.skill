## 何が起きてるか

あなたのログには大きく2段階あります。

### (A) `No handler for set-lang-from-info-string!`

Tree-sitter のクエリ（`*.scm`）には、`#something!` みたいな“命令（directive）”を書けます。

その中に `#set-lang-from-info-string!` という命令が出てきているんだけど、Neovim がそれを処理するときに

* 「その命令を処理する関数（handler）が登録されてない」
* だから「知らない命令だ」としてエラーになる

これが `No handler for set-lang-from-info-string!` の意味です。

ここで重要なのは：

* `set-lang-from-info-string!` は **Neovim本体の標準命令ではなく**、主に **nvim-treesitter が追加で提供する命令**です
  （nvim-treesitter は Lua で “この directive が来たらこう処理する” を追加できます）

なのでこのエラーが出る典型パターンは

* **クエリファイルが新しくて、その directive を使っている**
* でも **nvim-treesitter 側が古い / 読み込まれてない / 無効化されてる**せいで handler が登録されていない

という「クエリと nvim-treesitter の不整合」です。

### (B) `Parser could not be created ... language "sh"`

(A)で Tree-sitter ハイライト処理が途中で落ちた結果として、Telescope のプレビュー側が `sh` を解析しようとしても

* `sh` 用の parser がない/ロードできない

みたいな状態になって、追加でこのエラーが出ています。

ただ、順序的に見ると **最初の原因は (A)** で、(B) は巻き添えになっている可能性が高いです。

## `.scm` ファイルとは

**Scheme（スキーム）言語で書かれた Tree-sitter のクエリファイル**です。

### 役割

Tree-sitter は2段階で動きます：

1. **Parser** がソースコードを AST（構文木）に変換する
2. **クエリ（`.scm`）** がその AST から「どのノードをどう扱うか」を指定する

例えば `highlights.scm` はこんな感じです：

```scheme
; 関数名をキャプチャして "function" としてハイライトする
(function_definition name: (identifier) @function)

; 文字列リテラルを "string" としてハイライトする
(string) @string
```

これにより Neovim は「この部分は関数名だから青」「ここは文字列だからオレンジ」と色分けできます。

### 種類

```
queries/<言語名>/
├── highlights.scm    # シンタックスハイライト
├── injections.scm    # 言語の埋め込み（Markdown内のコードブロック等）
├── indents.scm       # 自動インデント
└── folds.scm         # 折りたたみ
```

### 今回の問題との関係

`#set-lang-from-info-string!` は主に `injections.scm` で使われる directive です。Markdown のコードブロックで ` ```python ` と書かれたら Python として解析する、といった「言語の切り替え」を指示するものです。

Nix が提供する新しい `.scm` ファイルにはこの directive が書かれているのに、lazy.nvim 側の古い nvim-treesitter にはそれを処理する Lua コードがない、というのが今回のズレです。

## なぜ `prepend` だと壊れるのか

`runtimepath` は Neovim が設定ファイルを探す順番を決めるリストです。同じ名前のファイルが複数箇所にある場合、**リストの先頭に近い方が優先**されます。

### 今回の状況

nvim-treesitter 関連のファイルが **2箇所** にあります：

```
runtimepath の順序:
  1. Nix (withAllGrammars)   ← prepend で先頭に追加されていた
  2. lazy.nvim (~/.local/share/nvim/lazy/nvim-treesitter/)
```

それぞれが持っているもの：

| | Nix 側 (2026-02) | lazy.nvim 側 (2024-08) |
|---|---|---|
| grammar バイナリ (.so) | ある | ない |
| クエリ (.scm) | ある（新しい） | ある（古い） |
| Lua コード (handler) | ある（でも読まれない）| ある（こっちが使われる） |

### `prepend` の場合

Nix が先頭に来るので、クエリ（`.scm`）は **Nix の新しい版** が使われます。しかし handler を登録する Lua コードは lazy.nvim 側のものが実行されます。

結果、新しいクエリが `#set-lang-from-info-string!` を呼び出すのに、古い Lua コードにはその handler がない → エラー。

### `append` の場合

lazy.nvim が先に来るので、クエリ（`.scm`）は **lazy.nvim と同じバージョン** のものが使われます。Lua コードも lazy.nvim 側。両方同じバージョンなので整合性が保たれます。

Nix 側は grammar バイナリ（`.so`）だけが使われる形になります。

### 一言でまとめると

**クエリと handler が別々のバージョンから読み込まれていた**のが原因です。`append` にすることで、両方とも lazy.nvim 側から読まれるように揃えます。
