# Portless: Stable Named URLs for Development

## Purpose

Portless is a development tool that replaces traditional port numbers with stable, named `.localhost` URLs. Instead of accessing your app via `http://localhost:3000`, you'd use `http://myapp.localhost:1355`.

## How It Works

The system operates through a simple three-step architecture:

1. **Proxy Layer**: A central proxy runs on port 1355, listening for all incoming requests
2. **App Registration**: When you launch an app with portless, it assigns a random port (4000-4999) and registers that mapping with the proxy
3. **Request Routing**: Browser requests to `<name>.localhost:1355` get routed through the proxy to the correct backend service

Apps receive their assigned port via `PORT` and `HOST` environment variables, which most frameworks respect automatically.

## Key Features

- **Auto-starting proxy**: The proxy launches automatically when you run your first app
- **HTTP/2 + HTTPS support**: Enables faster development with optional TLS certificates
- **Framework compatibility**: Auto-injects necessary flags for frameworks that ignore standard port environment variables (Vite, Astro, etc.)
- **Subdomain support**: Run services like `api.myapp.localhost:1355` and `docs.myapp.localhost:1355` simultaneously

## Problems Solved

Portless addresses multiple friction points in local development:

- **Port conflicts**: Eliminates `EADDRINUSE` errors from competing services
- **URL stability**: Applications keep consistent URLs regardless of underlying port assignment
- **Cookie isolation**: Each named domain maintains separate storage from others
- **AI-friendly**: Provides reliable URLs that agents can programmatically depend on
- **Team collaboration**: Named URLs eliminate "what port is that on?" conversations

   139→
   140→Claude Code が worktree を作成/削除するとき、自動的にフックが発火する:
   141→
   142→```zsh
   143→# claude/hooks/worktree.zsh
   144→input=$(cat)
   145→hook_event=$(printf '%s' "$input" | jq -r '.hook_event_name')
   146→
   147→case "$hook_event" in
   148→WorktreeCreate)
   149→  wt_name=$(printf '%s' "$input" | jq -r '.name')
   150→  wt_abs_path=$(git wt "$wt_name" --nocd 2>/dev/null | tail -n 1 | xargs)
   151→  echo "$wt_abs_path"
   152→  ;;
   153→WorktreeRemove)
   154→  wt_path=$(printf '%s' "$input" | jq -r '.worktree_path')
   155→  git wt -d "$wt_path" 2>/dev/null || true
   156→  ;;
   157→esac

   162→### シェル関数
   163→
   164→日常的な worktree 操作用のシェル関数も用意されている。
   165→
   166→**gwt** — fzf で worktree を選択して移動:
   167→
   168→```zsh
   169→function gwt() {
   170→  local worktree=$(git wt | fzf --header-lines=1 | awk '{if ($1 == "*") print $2; else print $1}')
   171→  [[ -n "$worktree" ]] && cd "$worktree"
   172→}
   173→```
   174→
   175→**git-wt-clean** — リモートでマージ済み (gone) の worktree とブランチを一括削除:
   176→
   177→```zsh
   178→function git-wt-clean() {
   179→  git fetch --prune
   180→  local branches=$(git branch -vv | grep ': gone]' | sed 's/^[* +]*//' | awk '{print $1}')
   181→  # 対話的に確認してから削除
   182→  echo "$branches" | while read -r branch; do
   183→    git wt -d "$branch" 2>/dev/null || git branch -d "$branch" 2>/dev/null || true
   184→  done
   185→}
   186→```

## 記事の概要
