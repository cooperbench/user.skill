## 調査結果：commitizen (Python) の scope 必須化

以下は、commitizen で scope を必須にするための各質問についての調査結果です。

---

### 1. `.cz.toml` や `pyproject.toml` で scope を必須にする公式な設定方法

**結論：明示的な「scope 必須」フラグは存在せず、`cz_customize` で実装する必要があります。**

commitizen Python には公式な `scope_required` や同等の設定はありません。ただし、`cz_customize` プラグインを使うことで以下のように実装できます：

```toml
[tool.commitizen.customize]
# ... その他の設定 ...

[[tool.commitizen.customize.questions]]
type = "input"
name = "scope"
message = "What is the scope of this change?"
validator = "not empty"  # これで scope を必須にする
```

- **validator オプション**：`"not empty"` を指定することで、ユーザーが空の入力を許しません
- **schema_pattern によるバリデーション**：スキーマパターンを設定して、コミット時に scope を含める必須とすることもできます（例：`^(feat|fix|docs)(\(.+\)):`）

---

### 2. `schema_pattern` をカスタマイズ以外にもっとクリーンな方法

**結論：現状、`schema_pattern` + `questions` の組み合わせが最適解です。**

`cz_customize` で利用可能なオプション：

| オプション | 用途 |
|-----------|------|
| **schema_pattern** | コミットメッセージの正規表現パターン。scope を含める場合は `type(scope): message` 形式を強制 |
| **questions** | インタラクティブなプロンプト。各質問に `validator` を付けて必須化 |
| **message_template** | Jinja2 テンプレート。最終的なコミットメッセージの形式を定義 |
| **commit_parser** | 既存コミットを解析する正規表現（changelog 生成用） |

**推奨アプローチ**：
1. `questions` で `scope` 入力を必須化（validator で制御）
2. `message_template` で scope の位置を保証
3. `schema_pattern` でコミット時の検証を行う

より詳細には、[DeepWiki の commitizen ドキュメント](https://deepwiki.com/commitizen-tools/commitizen/3-core-concepts) で「Commit Message Conventions」セクションを参照できます。

---

### 3. git-hooks.nix (cachix) の commitizen hook に設定を渡す方法

**結論：git-hooks.nix の commitizen hook は設定パラメータを直接受け取れません。プロジェクト設定ファイルに依存します。**

git-hooks.nix での commitizen hook は以下のように定義されています：

```nix
hooks.commitizen = {
  name = "commitizen check"
  description = "Check whether the current commit message follows committing rules."
  entry = "${hooks.commitizen.package}/bin/cz check --allow-abort --commit-msg-file"
  stages = ["commit-msg"]
}
```

**key points：**
- hook は `cz check --allow-abort --commit-msg-file` を実行
- hook 自体には設定を渡せない
- commitizen は自動的に `.cz.toml` / `pyproject.toml` / `.cz.json` を読み込む

**実装方法：**
```nix
# flake.nix
checks = forEachSupportedSystem ({ pkgs, system }:
  {
    git-hooks = inputs.git-hooks.lib.${system}.run {
      src = ./.;
      hooks.commitizen.enable = true;
      # ここでは設定を渡せない - pyproject.toml に定義
    };
  }
);
```

設定は **プロジェクトの `pyproject.toml` に記述する必要があります**。

---

### 4. commitizen 以外のツール（commitlint）での Nix-friendly な実現

**結論：commitlint は JavaScript ベースで、Nix 統合は commitizen より簡潔ですが、git-hooks.nix に明示的なサポートはありません。**

#### commitlint の scope 必須化

commitlint では scope を簡潔に必須化できます：

```javascript
// .commitlintrc.js または .commitlintrc.json
module.exports = {
  extends: ["@commitlint/config-conventional"],
  rules: {
    "scope-empty": [2, "never"],  // scope を必須に
    "scope-enum": [2, "always", ["core", "ui", "docs", "build"]],  // 任意：スコープを制限
  },
};
```

**commitizen との比較：**

| 項目 | commitizen (Python) | commitlint (JavaScript) |
|------|------------------|----------------------|
| scope 必須化 | `cz_customize` + validator | `"scope-empty": [2, "never"]` |
| 複雑度 | 中（複数オプション組み合わせ） | 低（ルール名で直感的） |
| Nix サポート | git-hooks.nix に プリセット | サポートなし（カスタム hook 必要） |
| インタラクティブ性 | あり（プロンプト表示） | なし（検証のみ） |

#### git-hooks.nix での commitlint 統合

git-hooks.nix には commitlint の プリセットがないため、カスタム hook として定義します：

```nix
hooks = {
  commitizen.enable = true;  # Python ベース - プリセットあり
  
  # commitlint はカスタムで定義
  custom-commitlint = {
    enable = true;
    name = "commitlint";
    entry = "${pkgs.nodePackages.commitlint}/bin/commitlint --edit";
    language = "system";
    stages = ["commit-msg"];
    pass_filenames = false;
  };
};
```

**Nix-friendly な構成：**
- commitizen：Python スタック、npm/Node.js 非依存 → シンプル
- commitlint：Node.js 必須 → flake.nix に明示的なパッケージ管理が必要

## まとめ

| 質問 | 回答 |
|------|------|
| **1. 公式な scope 必須設定** | なし。`cz_customize` の `questions` + `validator: "not empty"` で実装 |
| **2. クリーンな方法** | `schema_pattern` + `questions` + `message_template` の組み合わせが最適 |
| **3. git-hooks.nix との統合** | hook は設定を受け取れず、プロジェクトの `pyproject.toml` に `[tool.commitizen.customize]` を記述 |
| **4. commitlint との比較** | commitlint のほうが設定は簡潔（`scope-empty: [2, "never"]`）だが、Nix ではカスタム hook 定義が必要 |

### 推奨方針

- **commitizen (Python) を継続使用**：既に flake.nix で設定済みで、Python スタックに統合しやすい
- **scope 必須化**：`pyproject.toml` に `[tool.commitizen.customize]` を追加し、questions で validator を指定
- **git-hooks.nix**：commitizen hook はそのまま使用可。設定は `pyproject.toml` で管理
