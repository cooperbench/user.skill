# OOM 原因解读

看报错关键两行：
```
GPU 0 has a total capacity of 83.05 GiB of which 18.38 MiB is free.
this process has 10.98 GiB memory in use.
```

自己只用了 11 GB，但整张卡只剩 18 MB 空闲 → **沙盒 GPU 上还有另一个进程占了 ~72 GB**。常见可能：

1. **平台的前置 workload / 验证器** 在 prepare_model 运行时还没释放（比如平台先跑了 BF16 基线跑分或 probe）
2. **前一次失败重试遗留进程** 没退干净
3. **模型加载方式问题**：`device_map="auto"` 会试图把整个 BF16 模型（~60 GB）塞进 GPU，哪怕本来 GPU 是空的也吃紧

**列语义**：
- `progress`: 分段彩条 = 正确(绿)/错(红)/空(黄)/未到(灰)
- `acc`: ≥80 绿 / 60-80 黄 / <60 红；未开始显 `—`
- `empty`: 0 灰；>0 红加粗 `✘`（告警）
- `last`: `✓` 正确 / `✗` 错 / `∅` 空响应 + `#{index}`

```

[12:04:03] ✓ niah  #33  out=1420
```

## 刷新 & 增量逻辑
- `Live(refresh_per_second=2)`，tick=0.5s
- 记 `last_offset`：每次 `os.stat().st_size` 变了才 `seek+readlines` 解析增量
- per-task 维护 dict：`{done, correct, empty, out_sum, in_sum, last_record}`
- 全局吞吐：`deque[(ts,1)]` 只保留最近 60s，`len/60 * 60` = 每分钟完成

## ETA / Throughput
- `elapsed = now - summary.start`（summary 有就用；无则 `predictions.ctime`）
- `rate = done / elapsed`
- `eta = (total - done) / rate`（done=0 时显 `—`）

## 评分逻辑一致性
`run_public_eval_full.py` 里的 `extract_final_answer / extract_mcq_answer / score_mcq / score_exact_match` 是从 `toolkit/eval_model.py` **逐字节复制**（我刚 diff 了），规则：
- `extract_final_answer`: 取 `</think>` 之后的段落
- `extract_mcq_answer`: 3 种正则（`ANSWER: X`、`\boxed{\text{X}}`、`\boxed{X}`）
- `mcq`: 1/0 二值
- `qa/niah/lcx`: 命中任一 gold 即 1.0
- `cwe/fwe`: **覆盖率** `hits / len(gold)`，是 **0-1 连续小数**

Dashboard 本身**不重新打分**，直接读 `predictions_incremental.jsonl` 里 run_public_eval_full 写入的 `score` 字段，所以 per-sample 与官方一致。

聚合口径：`ori_accuracy = mean(score) * 100` — 也一致。
