**1. Prefill 改动影响面**
- **target prefill -> draft seed**：prefill/extend 会在 `forward_target_extend` 捕获 `FULL` hidden，再用 `forward_draft_extend` 初始化 draft KV/cache。任何 prefill attention、GLA、量化数值变化，都会改变 draft 的初始 hidden 分布，影响后续 acceptance。关键路径在 [eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:723) 和 [eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:1031)。
- **verify 也是 prefill-like 路径**：EAGLE `TARGET_VERIFY` 把 draft token 当一段 extend/prefill 跑 target，不是普通 decode。`prepare_for_verify` 会分配 target KV slot、写 `req_to_token`，再进 target forward；verify 后根据 logits 决定 accept/rollback。见 [eagle_info.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:150) 和 [eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:1722)。
- **standard attention sparse prefill 强耦合**：SALA 在 `--dense-as-sparse` 下，标准注意力 prefill 会走 InfLLM-v2 sparse/topK/block table；这直接影响长上下文 hidden 和 logits。verify 时还会走 causal prefill wrapper 或 custom mask wrapper。相关逻辑在 [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:840) 和 [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:1315)。
- **rollback / recurrent state**：SimpleGLA/Mamba-like 分支在 verify 中写 `intermediate_ssm`，accept 后再把被接受 step 的状态拷回 persistent state。tree/topk 场景还要避免 sibling state 污染。相关代码在 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:66)、[hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:2331)、[hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:1896)。
- **hidden-state 采集 / EAGLE 训练分布**：MiniCPM 会捕获 aux layers，默认 `[1,10,22]`，训练和 onestage 采集依赖这些 hidden + top logits。prefill 数值变化会传导到 draft 训练数据和 draft acceptance。见 [minicpm.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/models/minicpm.py:363)、[minicpm.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/models/minicpm.py:1421)、[docs/eagle/training/pipeline.md](/user_4813494d/openbmb/docs/eagle/training/pipeline.md:64)。

**2. Accuracy 风险分层**
几乎不影响 accuracy，但仍要做等价校验：
- 纯 metadata/调度开销优化：例如 TARGET_VERIFY replay 去掉重复 `plan()`、复用 wrapper、把 `kv_indices/indptr/last_page_len` 构造从 CPU loop 移到 GPU，只要输出完全一致。当前热区在 [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:2861)。
- buffer 预分配、profile/logging、Python tail bookkeeping 减少、accepted-index/slot-free 的等价 tensor 化。
- 数学等价 fusion：qk_norm+RoPE、o_norm+sigmoid、metadata fill/copy fusion，但要比对 hidden/logits max error。
- 采集管线的 IO/上传/压缩吞吐优化，只要 token_ids、aux hidden 解码、top logits 内容一致。

必须重评 accuracy：
- sparse attention 的 topK、block table、dense-as-sparse、page_size、window、compress_k、split/num_splits、prefill chunk 边界。
- verify 语义：causal flat vs custom tree mask、D5/D7、topk、spec steps、MARS theta、ngram route mask。
- GLA/SSM recurrent state、rollback、`intermediate_ssm` 布局、accepted step 拷贝。
- 目标模型 prefill 数值 kernel、FP4/CUTLASS/cuDNN dispatch、KV dtype。特别是 NVFP4 KV 不适合当前 SALA sparse/page_size=1 路径，文档也明确建议继续用 fp8 KV，见 [docs/quant/nvfp4.md](/user_4813494d/openbmb/docs/quant/nvfp4.md:57)。
- aux layer 选择、capture 时机、RoPE 对齐、shift alignment。EAGLE 文档里 aux `[1,10,22]` 是当前稳定基线，v3 `[4,9,24]` 虽 probe NLL 更好但 e2e acceptance 更差，见 [docs/eagle/architecture.md](/user_4813494d/openbmb/docs/eagle/architecture.md:7)。

**3. 可做机会**
- 首推 **TARGET_VERIFY replay de-plan**：保持同样 `kv_indices/indptr/last_page_len/qo_indptr`，减少每轮 verify CPU flatten + `plan()`。这是高收益、低语义风险方向。
- 做 **D5/D7 形状特化**：当前生产形态固定集中在 dtn=7/11，加 NO_SPEC；可以为这些形状预建 buffer、cu_seqlens、parent/retrieve 表，减少通用 tree bookkeeping。
- 优化 **verify tail 和 sparse slot 分配**：accepted index、free slots、sparse K1/K2 allocation 可更多 tensor/kernel 化；但 Req、grammar、stop check 最后仍留 Python 更稳。
- 继续压 **SimpleGLA verify bandwidth**：现有代码已经支持 tree-aware parent state 和 direct write `intermediate_ssm`，下一步是减少 verify o_buf/sum 和 state copy 带宽。
- EAGLE 采集侧机会不是继续追 KV 压缩，而是用 onestage NVFP4 hook 快速做 **prefill kernel drift 数据集**：同 prompt 比对 aux `[1,10,22]` hidden、top logits、accept histogram。direct NVFP4 aux storage 已作为默认路线，见 [docs/eagle/training/data-compression.md](/user_4813494d/openbmb/docs/eagle/training/data-compression.md:63)。
- 不建议把 prefill 加速押在 NVFP4 KV/page_size 改造上；SALA 的 sparse/page_size=1 和 FlashInfer dense NVFP4 KV 路径不匹配，收益风险比差，见 [docs/quant/nvfp4.md](/user_4813494d/openbmb/docs/quant/nvfp4.md:79)。
