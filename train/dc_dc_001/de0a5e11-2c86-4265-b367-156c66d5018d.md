这是 SGLang 上一个新的 RFC（`#22044`，2026-04 提交，目前 OPEN 未合并，论文还在 coming-soon 状态）。和我们刚聊的 P-EAGLE 是**完全不同维度**的思路——讲一下。 ## SPECTRE 是什么 **S**peculative **P**arallel **E**xecution with **C**oncurrent **T**enant **R**emote draft**E**r。 作者团队 @feng397 / @xq25478 / @GoGoldenx / @zhangfeiyu5610，明显冲着生产 serving 场景做的，参考的两篇前作是 PEARL（2408.11850）和 SSD（2603.03251）。 **核心点：把 drafter 和 verifier 拆成两个独立的 SGLang HTTP server，用 ZMQ 异步通信。** 不动模型，纯系统/调度层改造。 ## 两个关键创新 ### 1. Cross-Round Parallel Overlap（跨轮并行） 传统 spec decode 是同步死循环： ``` [draft k] → [verify k] → [draft k+1] → [verify k+1] → ... ``` 两个 forward 必须串行，drafter 和 verifier 都有 "对方在干活时我闲着" 的状态。 SPECTRE 用**乐观并发**——假设 acceptance 高，verifier 在验证第 k 轮的时候，drafter 同时已经在为第 k+1 轮算 draft： ``` verifier: [verify k] → [verify k+1] → ... drafter: [draft k+1] → [draft k+2] → ... ``` 真正把两边 forward 重叠掉。代价是猜错时要回滚 KV——所以代码里有 `SpectreKVRollbacker`。 ### 2. Drafter Dual-Mode Drafter 不只为 verifier 干活，自己也接独立用户请求。两种流量（remote draft + 本地用户）**混进同一个 GPU running batch**。两种调度： - **Mixed mode**（默认）：draft 请求并入 drafter 的 running batch，最大化 GPU 利用率，但重载时 verifier 可能 timeout -
