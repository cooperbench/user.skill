| P0 | FlashQLA/TFLA compatibility probe for GLA | SALA has GLA/Lightning path; local profile shows GLA qkv + chunk kernel is material. | P0 | NVFP4 MLP/GEMM prefill tactics | NVFP4 GEMM is already a top prefill GPU cost. Speed proof must include scorer overhead. | Proxy ranking misses SALA’s existing selected blocks; speedup vanishes because current bottleneck is not just scoring. |
| P1 | UniPrefill block-wise dynamic sparsification | Interesting because it explicitly targets hybrid architectures and continuous batching, unlike pure sparse-attention papers. | Read paper/code, then build an offline oracle that skips or compresses token blocks only in prefill and measures final-logit impact. | Must show controllable accuracy curve at several sparsity levels and at least a theoretical wall-time model tied to SALA hotspots. | If it skips rows/tokens, it may break long-context retrieval and final-token dependence; scheduler integration may dominate. |
| P2 | MInference pattern taxonomy | MInference is strong for full-attention long-context models, but SALA already has model-specific sparse attention. | Use its A-shape / vertical-slash / block-sparse taxonomy only to classify SALA attention heads and compare with existing block selections. | Must beat current sparse block selection at equal retained KV blocks, not a dense baseline. | Patterns learned on Transformer full attention do not transfer to SALA’s hybrid layers or existing sparse metadata. |
| P2 | SeerAttention gates | Trainable block gates may outperform heuristics, but it adds training and kernel integration. | Freeze target model, train only gates by self-distillation on SALA calibration prompts, evaluate sparse block masks offline. | Gate overhead < saved attention work; accuracy retained on long-context tasks; no change to base weights. | Gate training overfits calibration; gate compute/metadata overhead eats savings; custom kernel not compatible with current page layout. |
| P3 | FlexPrefill dynamic budget | Dynamic sparse budget is attractive, but SALA docs already warn that reducing candidates/top-k is not acceptable without proof. | Treat as diagnostic only: produce budget-vs-accuracy curves per layer/head on real prompts. | Must preserve answer quality and show speedup after index-selection overhead. | Cumulative-attention thresholds change selected evidence; “average accuracy” hides bad long-context failures. |
| P4 | NSA | NSA is a natively trained architecture, not a drop-in prefill optimization for a fixed SALA checkpoint. | Only useful as future-model research or kernel inspiration. | Requires retraining/pretraining-scale proof, outside submission path. | Retrofitting sparse structure onto dense-trained/full-trained layers loses capability. |

**Proof Bar**

For exact kernel/scheduling changes: require output equality or BF16-noise equivalence, smoke chat sanity, A/B/A interleaved runs, and nsys showing the claimed hotspot moved.

For approximate sparse methods: require block-selection audits, hidden/logit drift, long-context answer accuracy, and then speed. A speedup that changes selected evidence is not a win.
