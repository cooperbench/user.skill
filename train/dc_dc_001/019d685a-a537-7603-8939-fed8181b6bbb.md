> AGENT

这个项目是一个 **把 Codex 放在 Mac 上运行、用 iPhone 远端控制** 的工具。

## 一句话说明

**Remodex = iPhone app + Mac 端桥接程式 + 可自架的 relay。**

它不是把代码工作搬到云端，而是把 **操作界面搬到手机**：  
真正执行 Codex、读写仓库、跑 git，还是在你的 Mac 上。

## 使用者能感受到的功能

- 在 iPhone 上查看与控制 Codex
- 第一次用 QR 配对，之后可自动重连
- 边跑边看结果，不用一直守在电脑前
- 可从手机发新指令、接着上一轮继续
- 支援 Plan mode、Fast mode、`/subagents`
- 可从手机做 git 动作，例如 commit、push、pull、切 branch
- 任务完成或需要注意时，手机会收到通知
- 可把同一条对话接回 Mac 上继续

## 这个仓库主要分成什么

| 目录 | 作用 |
|---|---|
| `CodexMobile/` | iPhone app，本体介面就在这里 |
| `phodex-bridge/` | Mac 端桥接程式，命令是 `remodex` |
| `relay/` | 中继服务，负责手机和 Mac 找到彼此、维持连接 |
| `Docs/` | 说明文件 |
| `Legal/` | 法务与上架相关资料 |
| `assets/` | 资源档 |

## 这个项目的核心取向

### 1. 明确是 **local-first**
重点不是做一个托管平台，而是让你保留本机控制权。  
仓库里反覆强调：

- Codex 运行在本机 Mac
- git 和文件操作都在本机
- relay 只是传递连接，不负责替你执行任务
- 不希望把产品重新做成依赖固定线上服务的形式

### 2. iPhone 体验是重点
这个项目不是单纯“命令列工具”，而是完整的手机控制体验：

- 配对
- 自动重连
- 时间线/聊天记录
- 通知
- 扫码连接
- 把线程接回桌面继续

### 3. macOS 支援最完整
目前最成熟的是 **Mac + iPhone** 这条路线。  
README 明说：

- macOS 有背景服务，可关掉终端后继续用
- Linux / Windows 可以跑桥接，但没有同等级的背景服务体验

## 我对当前维护重点的判断

目前最在意的是这三件事：

1. **本机连接与自动重连要稳定**  
   配对、信任、重连、背景恢复，是反覆被强调的重点。

2. **手机与 Mac 的连续体验不能断**  
   包括线程恢复、历史同步、继续上一轮、把对话交回桌面。

3. **继续维持 self-host / open-source 路线**  
   relay 代码公开，仓库避免写死线上域名，也不想把产品改回“必须依赖官方托管服务”的形态。

## 适合怎么理解它

把它想成：

> **“Codex 的 iPhone 遥控器 + Mac 本机执行中枢”**

不是新的 AI 平台，也不是单纯聊天 app。  
它的价值在于：**你离开电脑时，还是能继续控制正在 Mac 上跑的 Codex。**
