**Executive Takeaway**

For MiniCPM-SALA, the most plausible acceleration beyond existing prefill/refill work is not generic KV eviction. SALA already mixes sparse attention and GLA, so the high-value area is **decode-time KV/page selection inside the sparse-attention layers**, plus **KV reuse/offload for repeated long prompts**. The best candidates to test first are:

1. **Quest-style query-aware page selection** for sparse-attention decode.
2. **PyramidKV/SnapKV-style per-layer/head budgeted cache retention**, used conservatively only on sparse-attention layers.
3. **MInference/XAttention-style dynamic block sparsity** for long prefill only if current FlashInfer sparse prefill still spends meaningful time in attention.
4. **Cache reuse layer** for repeated benchmark prompts or RAG-like workloads, probably via SGLang RadixAttention/LMCache ideas.
5. **NSA-like trainable sparse attention** is strategically relevant but too invasive for a short competition cycle.

**Landscape**

| Method | Core Idea | Claimed Result | Fit For MiniCPM-SALA | Risk |
|---|---:|---:|---|---|
| H2O | Keep recent tokens + heavy-hitter tokens by accumulated attention | KV memory reduction | Medium-low | Attention history may not transfer cleanly to SALA sparse+GLA; eviction can hurt retrieval |
| StreamingLLM | Keep attention sinks + sliding window | Stable streaming over very long sequences | Low-medium | More useful for infinite streaming than fixed long-context QA |
| SnapKV | Use prompt attention to select clustered important KV positions before generation | Faster decode / smaller KV | Medium | Needs head/layer calibration on SALA; risk on long needle tasks |
| PyramidKV | Allocate larger KV budgets to lower layers, smaller to higher layers | Full-cache-like accuracy with much less KV in reported settings | Medium-high | Good experiment shape, but SALA layer roles may differ |

**Fit Analysis For MiniCPM-SALA**

MiniCPM-SALA is not a normal full-attention Llama-family model. It already uses sparse attention plus linear/GLA-style global mixing. That changes the calculus:

- Methods that assume dense attention matrices may overestimate speedup.
- KV eviction can damage sparse layers disproportionately because sparse attention may be the high-fidelity retrieval path while GLA handles broad global mixing.
- Query-aware methods are more promising than static eviction because long-context retrieval importance depends on the current generated token.
- Layer-wise budgets are promising because SALA likely has non-uniform layer roles; some sparse layers may be much more sensitive than others.
- Anything affecting speculative verification must be tested with EAGLE enabled and disabled. A small attention approximation can become a larger acceptance-rate or rollback problem.

**Concrete Experiments**

1. **Attention/KV Sensitivity Map**
   Instrument sparse-attention layers to run controlled ablations:
   - full current sparse cache
   - sliding window only
   - sink + window
   - top attention-mass tokens
   - random same-budget tokens

   Measure public eval accuracy, needle retrieval, and per-layer output cosine/KL. This tells whether SALA tolerates KV pruning at all.

2. **PyramidKV Budget Sweep**
   Apply per-layer KV retention only to sparse-attention layers:
   - budgets: 100%, 50%, 25%, 12.5%
   - schedules: uniform, pyramid decreasing with depth, inverse-pyramid, learned-from-sensitivity
   - always keep sink tokens + recent window

   Acceptance criterion: less than 0.5-1.0 public accuracy drop with measurable decode memory-bandwidth reduction.

3. **Quest-Lite Page Selector**
   Add page-level metadata for sparse KV pages:
   - per page/head min/max key summaries
   - current query scores pages
   - load top-K pages + recent pages + mandatory sink/global pages

   First implement as an experimental Python/Triton or debug path if kernel work is expensive. Then move scoring into the existing FlashInfer/minicpm sparse path only if accuracy and selected-page sparsity look good.

4. **SnapKV Prompt Compression Probe**
   During prefill, collect last-N prompt-query attention over candidate KV tokens. Cluster/select per head. Freeze selected KV for decode.
   Test especially:
   - long-context QA
   - needle
   - mixed batch
   - EAGLE verify/rollback

   This is easier than Quest but less adaptive, so it is a lower-risk prototype and likely lower ceiling.

5. **Spec Decode Compatibility Matrix**
   For each KV/sparse approximation, run:
   - no-spec baseline
   - EAGLE3 enabled
   - same prompts, compare exact/semantic output
   - record draft acceptance rate, rollback count, ori_accuracy, tok/s

   Reject methods that increase tok/s but lower acceptance or accuracy enough to erase benefit.

6. **Cache Reuse Benchmark**
   If evaluation has repeated system prompts, repeated long prefixes, or RAG-like chunk reuse:
   - profile SGLang RadixAttention hit rate
   - test chunk-level reuse idea from CacheBlend for non-prefix reused documents
   - estimate TTFT saved versus transfer/recompute cost

   This may give large wins without changing model math, but only if workload overlap exists.

7. **MInference/XAttention Prefill Gate**
   Only pursue if profiling shows prefill attention remains a top bottleneck after current chunked-prefill/FlashInfer work.
   Test block-sparse prefill on a small subset:
   - compare dense/sparse logits on prefill
   - measure public eval and needle
   - inspect whether SALA sparse masks already capture the same blocks

**Priority Order**

1. **Quest-Lite page selection for decode sparse attention**
2. **PyramidKV/SnapKV conservative KV retention**
3. **Cache reuse if benchmark workload has overlap**
4. **MInference/XAttention only if prefill still dominates**
5. **NSA/learned sparse attention as post-competition research**

The highest-probability useful path is: build a sensitivity map, then implement page-level query-aware selection with mandatory recent/sink/global retention, and validate under no-spec plus EAGLE3.
