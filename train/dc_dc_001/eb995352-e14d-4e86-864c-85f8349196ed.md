# "训练感知 α-threshold" 的含义 核心意思：**MiniCPM-SALA 不是普通 dense attention 模型，它是被"教会"在固定 top-K 稀疏模式下工作的**。改变稀疏策略 = 改变了它的"工作接口"，可能掉精度。 ## 具体展开 ### MiniCPM-SALA 是 native sparse trained - 模型训练时，8 层 standard attention 的 forward 就走 InfLLM-v2：compress_k → stage1 score → **固定 top-K blocks** → stage2 sparse FA - Loss 是在这个稀疏输出上算的，反向传梯度也是在这个 sparse pattern 下 - 模型权重（Q/K/V/O proj、compress_k 的 pooling kernel）都是在"**每个 query 恰好看 K 个 block**"这个假设下收敛的 - 这和 Qwen2.5-VL（FlashPrefill 的 target）完全不同：Qwen 是 dense 训练的，推理时稀疏化本身就是事后近似，α-threshold 动态 vs 固定 top-K 只是"近似方法二选一"，没有 train-infer mismatch ### α-threshold 改变的是什么 | 维度 | 固定 top-K | α-threshold | |---|---|---| | 每个 query 看的 block 数 | 恒定（比如 K=64） | 动态（可能 10，可能 200） | | Score 最低的那些 block | **必选 K 个**（哪怕分数很低） | 分数 <α·max 的全丢 | | 对"注意力分散"的 query（找不到明显焦点） | 填 K 个近噪 block | 只保留 α·max 以上 + min_budget 兜底 | | 对"注意力集中"的 query | 浪费算力在 K-1 个无关 block 上 | 只保留几块，非常稀疏 | ### mismatch 在哪里 推理时 attention 输出 = softmax(QK) · V，如果选的 block 集合和训练时分布不同： 1. **分母变化**：训练时 softmax 在固定 K 个 block 的 logit 上归一；推理时 block 数变动，同一 query 的 softmax 分布不一样 → output 向量偏离训练时的分布 2. **O-proj 下游**：O_proj 权重是拿"固定 top-K 下的 attention 输出"训练的，现在喂它一个分布不同的输入，下游 MLP/下一层 attention 会级联放大误差 3. **累积效应**：32 层、128K token 逐层累积，单层 1-2% 的输出分布偏移在最后 logit 上可能变成明显掉点 ### 如何量化风险（不是一定就掉） **乐观情况**：训练时 top-K 里的 K 个 block 中，后半段分数其实很低（接近 padding noise），模型已经学会"忽略它们"。那 α-threshold 剔除低分 block 反而对齐了模型的实际注意力，精度不掉甚至更好。 **悲观情况**：top-K 的 K 个 block 都有实质贡献，α-threshold 剔除部分 = 丢信息。 **怎么验证**： 1. Dump 真实请求的 stage1 block_score 分布：看 top-K 的第 K 名分数 vs 第 1 名的比值，如果常年 <0.05，说明低分 block 是噪声，α-threshold 安全 2. 在长 prompt (≥64K) 上跑 MCQ + 人话 check，对比固定 top-K vs α-threshold 的输出 3. 如果不放心，用 **α-threshold + 强制 min_budget = 当前 top-K**，这样"最少也选 K 块"，只在有富余的 query 上增加 block —— 这其实是**单向放松**，只可能不变或变慢，不会掉精度；但也就失去了稀疏率收益 ## 一句话总结 **固定 top-K 是 MiniCPM-SALA 的训练契约**；α-threshold 动态稀疏要么收益大（减计算量），要么掉精度（破坏契约），先 dump score 分布才能判断走哪条路。
