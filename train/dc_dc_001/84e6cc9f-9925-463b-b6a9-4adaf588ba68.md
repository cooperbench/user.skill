## 1. 冗余拷贝 / 重复访存

### 1.1 `compress_k` Triton：同一段 KV 被多读、多算

`/root/shared-nvme/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_sparse_kernels.py` 里，**NEW chunk** 路径：

- **PHASE 3**（约 174–200 行）：每个 `head_idx` 对 `kernel_size` 个 token 做 mean，写进寄存器 `acc`（仅当前 head）。
- **PHASE 4**（约 206–240 行）：仅 `head_idx == 0` 时，再对**所有 head** 重复同样的 token 遍历与 load，写入 `key_cache`。
- **PHASE 5**（约 246–271 行）：再次从 `key_cache` 读出刚写入的 compressed slot，写入 `full_compressed_k`。

也就是说：**同一 chunk 的源 token 在 PHASE 3（按 head 重复）+ PHASE 4（head0 包办所有 head）上被多次从 global memory 读取；写 KV 后再读回做 `full_compressed_k`。** 这是当前实现里最明显的「逻辑冗余」。

- **建议**：单 chunk 单 pass：按 token 循环一次，一次性累加/写出所有 head 的 mean 到 `key_cache`，并**可选**直接写到 `full_compressed_k`（避免 PHASE 5 再读 KV）。  
- **可行性**：中高；需小心 `head_idx` 并行与「只 head0 写 KV」的约定，可改为「每 chunk 一个 block 或 cooperative 模式写多 head」。

`get_compress_k_v2` 对 k1/k2 **各 launch 一次**完整 grid（`minicpm_sparse_utils.py` 约 168–207 行），属于两次独立 kernel；融合为一次需两套 stride/size 参数，收益取决于 launch 开销占比。

### 3.2 `convert_sparse_to_flashinfer`

`/root/shared-nvme/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_sparse_kernels.py`：

- **534–549** `cumsum_kernel`：注释已写「sequential」，单 block 做前缀和，`sparse_bs` 大时 CPU 侧 launch 虽轻，但**并行度差**。  
- **552–583** `flatten_and_fill_kernel`：按行拷贝，合理。

**建议**：用并行 scan（CUB / Triton）替代 sequential cumsum；或 **cumsum + flatten 单 kernel**（先写 indptr 再各 row copy，仍常分两阶段，但可去掉一次全局同步路径上的低效实现）。

**可行性**：高（仅 indptr）；与 FlashInfer wrapper 的 buffer 约定不变。

**与运行路径的关系**：`minicpm_attention_kernels.py` **326–370** 在 **`params.decode_wrapper is not None`** 时仍调用转换；若 `kv_indptr` 真为静态预计算，理论上可只更新 `kv_indices`，需对照 wrapper 是否每次依赖 indptr 内容（注释称 indptr 静态）——这里有**减少重复工作**的空间，属**中与平台绑定**。

### 3.3 Stage1 + pooling + topk（decode / prefill）

- **未 fuse（`fuse_topk=False`）**：`compressed_attention`（`minicpm_sparse_utils.py` **503–534**）= `infllmv2_attn_stage1`（CUDA，`infllmv2_sparse_attention.py` **548–560** 对 `q` 还有一次 `reshape+contiguous`）→ `max_pooling_1d_varlen`（`max_pooling_1d.py` **89–92** 对 input/cu_seqlens 等 **`contiguous()`**）→ `topk`+`sort`+`int32`。

- **Tilelang 路径残余**：**705–711** 的 post-sort `clone`（见 1.3）。
