短结论：

我把 `branch-aware speculative verification` 理解为“验证阶段并行检查一棵 token tree，并共享前缀/分支状态”。按这个口径看，`Medusa` 和 `EAGLE` 官方材料里都明确站在 `tree` 路线上，但表述不完全一样：`Medusa` 更直接写的是 `tree-based attention` + 同步验证多条候选；`EAGLE-2` 明确把重点放到 `dynamic draft tree`；`EAGLE-3` 主要升级的是 drafter 训练方式（`training-time test`），官方 repo 仍强调用 `official draft tree setups` 比较。换句话说，`EAGLE-3` 不是重新发明 verify，而是把树式 speculative 的 drafter 做强。

关于 `linear attention / recurrent state`：我没在 `Medusa` / `EAGLE` 官方 repo 或论文里找到专门面向这类模型的 branch-aware verifier 实现。`EAGLE` 官方 repo 只说可与 `Mamba` 组合，但没给出对应验证算法或实现细节。真正更接近你要找的公开一手材料有两条：`ReDrafter` 用 `RNN drafter + dynamic tree attention`，但目标模型仍是常规 LLM；`STree` 则明确声称是首个面向 `SSM / hybrid SSM-Transformer` 的可扩展 tree-based speculative decoding，这个是目前最像“recurrent/state-aware branch verification”的主线。`linear attention` 这边我找到的是 `Linearized-LLM`，它解决的是“让 linear attention 兼容 speculative decoding”，复现实验仍沿用 `Medusa` 路线，没有提出新的 branch-aware tree verifier。
