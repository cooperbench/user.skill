结论：公开资料里的 SAM/Suffix/ngram + EAGLE 组合，主流是“按置信度二选一路由 / fallback”，不是把 SAM/ngram 塞进 EAGLE tree 当一枝一起 verify。 **SAM-EAGLE 怎么选** SAM-Decoding 论文是《SAM Decoding: Speculative Decoding via Suffix Automaton》（ACL 2025 / arXiv:2411.10666）。它维护： - dynamic SAM：基于当前已生成文本，通常给线性 draft - static SAM：基于离线语料，通常给 tree draft - auxiliary SD：论文实验里用 Token Recycling 或 EAGLE-2 选择规则是启发式 match length 路由： - static vs dynamic：若 `l_static > l_dynamic + l_bias` 用 static SAM，否则用 dynamic SAM。 - SAM vs auxiliary/EAGLE：给 auxiliary 一个固定“虚拟匹配长度” `l_threshold`，每轮按 SAM 的真实 match length 与 auxiliary 的虚拟长度比较，选择一个 draft 源。 - 论文也明确说这是 heuristic，未来想训练 classifier 来选方法。 出处： - SAM arXiv 摘要：说明“based on match length”自适应选择，并称与 EAGLE-2 结合可额外提速 3.28%-11.13%。https://arxiv.org/abs/2411.10666 - ACL PDF §3.2/§3.4：static/dynamic 选择、`l_bias`、`l_threshold`。https://aclanthology.org/2025.acl-long.595.pdf - 官方实现 README 也说“according to suffix matching length”自动选择 retrieval draft 或 EAGLE/Token Recycling draft。https://github.com/hyx1999/SAM-Decoding **是不是把 SAM/ngram 作为树的一枝** 不是公开 SAM-Decoding 的设计。 更准确地说： - static SAM 自己可以生成 tree-structured draft； - EAGLE-2 自己也可以生成 tree draft； - SAM+EAGLE 是每轮选一个 draft provider，而不是把 SAM 候选挂到 EAGLE tree 的一个 branch 里联合排序/联合 verify。 - SuffixDecoding 的 hybrid 也一样：先算 suffix speculation tree 的 score，若 `score > tau` 用 suffix，否则 fallback 到 EAGLE-3。论文直接称 “dynamically selecting between suffix-based and model-based speculation”。 出处： - SuffixDecoding: Extreme Speculative Decoding for Emerging AI Applications，§3 “Hybrid Suffix Speculative Decoding”。https://openreview.net/pdf?id=uwL0vbeEVn **ngram-EAGLE hybrid** 我没看到主流 serving 框架公开提供“ngram + EAGLE 同一棵树联合分支”的实现。公开实现更像互斥 algorithm： -
