目前可确认的主线是：EAGLE-3 的最大训练侧收益来自“直接 token 分布蒸馏 + TTT + 多层特征融合 + 数据规模/目标模型再生成”，而不是单纯把旧 EAGLE 头多训几轮。接下来我会把这些证据按 ROI 和 MiniCPM-SALA 适配关系收束成结论。

> AGENT

**结论优先级**

1. **目标模型再生成 + 更贴近线上分布的数据，是最高 ROI。**  
   EAGLE-3 论文明确从“扩大数据但旧 EAGLE 收益有限”切到新架构后出现 scaling law；训练数据用 ShareGPT 约 68K + UltraChat-200K 约 464K，并且“调用 target model 生成 response”，DeepSeek-R1-Distill-LLaMA 8B 还额外加 OpenThoughts-114k-math，GSM8K 表现最好也被作者归因于此。SpecForge 文档也直接说数据质量影响 acceptance，生产环境建议用 target model regenerate assistant responses。  
   对 MiniCPM-SALA v4：不要只堆通用 ShareGPT。应优先生成“MiniCPM-SALA 自己会答的 response”，覆盖公开评测形态、中文、数学/代码、长上下文、AOI/长文定位、混合 batch 长短分布。acceptance 本质上是在拟合线上 target 分布，数据越像线上 decode，收益越直接。

2. **确认是 EAGLE-3 式 direct token objective + TTT，而不是旧 feature regression。**  
   EAGLE-3 去掉 feature prediction constraint，改成直接 token prediction，并在训练中模拟多步 draft。论文 ablation：LLaMA3.1-8B 上 MT-bench，EAGLE-2 speedup 3.16x，去 feature constraint 到 3.82x，再加 fused features 到 4.40x；GSM8K 也从 3.39x 到 4.48x。Speculators 文档写 EAGLE-3 训练目标是最小化相对 target logits 的 KL。  
   对 v4：重点检查训练 loop 是否真的把第 2/3 步 draft 自回归输入纳入 loss；`ttt_steps` 应和线上 `speculative-num-steps`/chain depth 接近。`ttt-step-loss-decay` 可作为小网格：`1.0`、`0.7`、`0.5`，指标看 step2/step3 acceptance，而不是只看 train loss。

3. **aux layer/feature 选择值得继续做系统搜索。**  
   EAGLE-3 证据很强：只用 top-layer 不够，因为 top-layer 更贴近 next-token，低/中/高层融合提供更丰富信息。SpecForge/Speculators 默认会选三层，Speculators 默认类似 `[2, num_layers//2, num_layers-3]`。  
   对 v4：现有 `[4,9,24]` 是合理起点，但 MiniCPM-SALA 的 hybrid linear attention / sparse-dense 结构可能让“信息峰值层”不同。高 ROI 做法是固定数据和训练步数，跑 3-5 组 aux layer 小模型：`[2, mid, last-3]`、`[4,9,24]`、`[early, mid, lm_head前-2]`，直接用 acceptance length 挑，不用只看 validation CE。

4. **response-only mask、chat template、thinking/非 thinking 状态要严格对齐。**  
   Speculators `prepare_data.py` 会生成 assistant/loss mask，并支持 `minimum-valid-tokens`、assistant pattern、turn dropout。RedHat 的 Qwen3-8B EAGLE3 模型卡特别说明：训练时 thinking disabled，且必须用 Qwen3 chat template 和 `/chat/completions`。  
   对 v4：训练 mask 应只覆盖 assistant continuation，长 prompt/system/user tokens 不应主导 loss。若评测是非 thinking 或固定输出格式，训练数据也要关掉/固定对应模式。模板错配会直接降低 acceptance。

5. **vocab truncation 是中高 ROI，尤其 draft LM head 成本明显时。**  
   Speculators 直接支持 `--draft-vocab-size 32000`，并用 `token_freq.pt` 选高频 token；这能减少 draft head 成本。最新 SpecVocab 方向也指出 LM head 常成为 draft 成本大头，并报告比 EAGLE-3 更高 acceptance length 的可能性，但这是更新、更实验性的路线。  
   对 v4：先用频率截断做工程 ROI：32K/48K/全词表三档，比较 `acceptance length / draft latency / tok/s`。如果 MiniCPM tokenizer 中文或数学符号长尾重要，不能只看英文频率，需用 v4 regenerate 数据统计频率。

6. **动态 draft tree 和线上 speculative 参数需要和训练一起调。**  
   EAGLE-2 的核心是用 draft confidence 近似 acceptance，动态构造/裁剪 tree，论文给出 3.05x-4.26x、比 EAGLE-1 快 20%-40%。EAGLE-3 也沿用 EAGLE-2 dynamic tree。SpecForge Llama4 实验固定 `topk=8`、`num_draft_tokens=10` 去扫 `speculative-num-steps`；SpecBundle 常用 SGLang 配置是 `steps=3, topk=1, draft_tokens=4`。  
   对 v4：不要只固定 `steps=2, topk=1, draft=3`。训练版定稿后扫：`steps 2/3/4`、`topk 1/4/8`、`draft_tokens 3/4/8/16`，看公开集 `ori_accuracy`、accept length、tok/s 三者。

**对 MiniCPM-SALA v4 的直接建议**

先做一版“线上目标再生成 + response-only + 当前 aux layers + TTT=3”的干净 baseline；然后只扫三件事：数据配比、aux layers、vocab size。每次验收记录 `acceptance length by position`、`tok/s`、`ori_accuracy`、长上下文坏例 index。对 SALA 这种长上下文和混合 attention 模型，最可能的增益不是把 draft 变大，而是让训练分布贴近 v4 的真实服务路径。
