> AGENT

结论先说：**training-free 地“换更高吞吐的新线性注意力模块”基本不可行；可做的是继续优化当前 Simple GLA 的等价 kernel / fusion。**MiniCPM-SALA 的 24 个 `lightning-attn` 层权重是按 Simple GLA 递推训练的，换成 KDA / DeltaNet / Mamba / RetNet 这类新模块会改变递推语义和权重解释，不满足 training-free。

**当前生产模块**
- 模型是 32 层：24 层 `lightning-attn` + 8 层 `minicpm4` sparse attention。
- GLA 路径在 [minicpm.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/models/minicpm.py:968)：`qkv_proj -> fused qk_norm+rope -> SimpleGLAAttnBackend -> output norm/gate -> o_proj`。
- 核心 backend 在 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:2254)：
  - decode：默认走 `simple_gla_decode_update_bk64_2k_fwd`，直接读写 recurrent state。
  - target verify：走 `_fused_recurrent_gla_launch`，把 draft 多步合到一个 kernel 并写 intermediate state。
  - prefill/extend：`seq_len >= 64` 走 FLA `chunk_simple_gla`。
- decode 专用 kernel 在 [simple_gla_decode_kernel.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/simple_gla_decode_kernel.py:1)，注释已经说明 BK128 更快但 reduction order 不 bit-exact，生产保留 BK64 bit-exact 路径。

**当前开销判断**
- 长上下文 prefill：现有 profile 记录 GLA 约 `120ms/chunk`，其中 `gla_qkv≈45ms`，`gla_chunk_kernel≈27-30ms`；但同一 chunk 里 MLP `133ms`、sparse FA `84ms` 也很重，GLA 不是唯一主热点。见 [docs/prefill/current.md](/user_4813494d/openbmb/docs/prefill/current.md:15)。
- decode：已落地 direct-state SimpleGLA，离线 `B1 14→6.66us`、`B8 34→14us`，B32 E2E `-19.59%`；2K variant 又把 B1 `7.17→4.11us`。见 [docs/decode/current.md](/user_4813494d/openbmb/docs/decode/current.md:147)。
- 已踩过的坑：GLA `o_buf.sum(0).to(bf16)` fusion、8/16 warps、verify BK64_2K direct output 都没保留，原因分别是 strided graph path 负收益、非 bit-exact 或 E2E 无收益。见 [docs/decode/history.md](/user_4813494d/openbmb/docs/decode/history.md:302)。

**外部新方案筛选**
- FLA / Flash Linear Attention：我们已经在用同类 FLA simple GLA chunk/recurrent 路线；training-free 可借鉴 kernel 实现，但不是“换模块”。来源：https://github.com/fla-org/flash-linear-attention
- FlashQLA：面向 Qwen/DeltaNet 类 gated linear attention 的高性能 kernel，数学形式不等同当前 Simple GLA，不能直接替换权重。来源：https://github.com/QwenLM/FlashQLA
- FlashKDA：面向 Kimi Linear 的 KDA 结构，属于另一套 learned linear attention，不是 Simple GLA 等价实现。来源：https://github.com/MoonshotAI/FlashKDA
- TFLA / ThunderKittens 类 tile kernel：可作为“重写同公式 kernel”的实现参考，但不是 drop-in；还要重新证明 sm_120、CUDA graph、strided slice、bit-exact 和 E2E。论文入口：https://arxiv.org/abs/2503.14376

**建议路线**
1. 不做“换模块”。training-free 下，KDA/DeltaNet/Mamba 这类都应判为需要训练或至少蒸馏。
2. 真正可推进的是 **Simple GLA 等价 kernel**：先做 isolated microbench，覆盖 prefill `T=8192,H=32,D=128` 和 verify `dtn=5/7`，再跑 bit-exact。
3. 优先级上，GLA 新 kernel 不是当前最高 ROI；更像研究候选。生产短线更应继续打 decode 文档里列的 `index_elementwise_kernel` / sparse-K 布局 / GEMM dispatch。  
4. 若要专门攻 GLA，唯一值得立项的是：重写 prefill `chunk_simple_gla` 的 sm_120 专用 CUDA/Triton kernel，并保留完全相同 recurrence、fp32 state、bf16 output 和 reduction order。现有记录显示 chunk_simple_gla 已有约 65% occupancy，所以预期收益不能按“换新模块”乐观估。

三路 subagent 和我本地复核的结论一致：**没有现成的 sm_120 SimpleGLA training-free 等价替换模块**。唯一数学等价的现成实现是 FLA `simple_gla`，但生产已经在 prefill/extend fallback 里用它；decode 和 target_verify 的 serving 语义已经靠本仓库自定义 kernel 补齐。

**当前等价约束**
MiniCPM-SALA 的 24 个 `lightning-attn` 层是 SimpleGLA：

`H_t = exp(g_gamma[h]) * H_parent + k_t[:, None] * v_t[None, :]`  
`o_t = sum_K(H_t * (q_t * scale)[:, None])`

生产 shape 是 `q/k/v = (1, T, 32, 128)`，state 是 fp32 `(pool, 32, 128, 128)`。decode 必须 in-place 读写 state；target_verify 必须保存每个 draft token 的 intermediate state，并按 tree parent 隔离 sibling。核心路径在 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:76)、[simple_gla_decode_kernel.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/simple_gla_decode_kernel.py:1)、[minicpm.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/models/minicpm.py:968)。

**外部模块筛选**
- FLA `simple_gla`: 数学最接近，已是当前 reference/prefill backend；没有 serving 所需的 decode in-place state 和 tree verify token-level intermediate state。https://github.com/fla-org/flash-linear-attention
- FlashQLA: GDN/gated delta rule，不是 SimpleGLA recurrence。https://github.com/QwenLM/FlashQLA
- FlashKDA: Kimi Delta Attention，不等价，且当前偏 `sm_90a`。https://github.com/MoonshotAI/FlashKDA
- cuLA: 值得观察，但目前示例/测试偏 KDA/Lightning，未见 SimpleGLA serving contract。https://github.com/inclusionAI/cuLA
- ThunderKittens/TFLA/mLSTM kernels: 可借鉴写法，不是可接入模块。https://github.com/HazyResearch/ThunderKittens / https://github.com/NX-AI/mlstm_kernels
- LeetDecoding: 形式部分接近 fixed decay linear attention，但缺 varlen/in-place state/tree verify/sm120 证明。https://github.com/Computational-Machine-Intelligence/LeetDecoding

**可执行优先级**
1. **继续挖 target_verify fused recurrent**  
   这是最高 ROI。当前 `_fused_recurrent_gla_intermediate_kernel` 已经把多步 draft 合并，但还可以只做等价小优化：parent lookup 特化、dtn/topk 专用 kernel、减少非必要 buffer/cast。预期 e2e 小于 1-2%，但风险最低。

2. **保守复核 state layout，不改 precision**  
   fp32 state 不能动，INT8/FP16 会累积误差。只允许尝试 layout/alias/preallocated view，目标是减少 state gather/scatter 或提高 coalescing。

3. **prefill chunk kernel 只作为研究项**  
   `chunk_simple_gla` 已记录约 65% occupancy；`chunk_size=128` 虽快但 `max_diff=0.25`，`fused_chunk_simple_gla` 更慢且不一致。要继续只能写形状特化等价 kernel，不能指望现成模块。

4. **decode direct-state 不建议大动**  
   当前 BK64/BK64_2K direct-state 已经是等价生产路径。BK128、8/16 warps等历史都因 reduction order 或 E2E 无收益失败。

验证门槛必须是：离线 bit-exact 或明确 ULP 边界、CUDA graph strided view、tree sibling parent 语义、`s8_stable_decode`/`b32_drain_decode`，最后再跑 spec/no-spec 答案或公开集 accuracy。此次只读调查，没有改文件、没有跑 bench。
