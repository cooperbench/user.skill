3	## 从 Medusa 到 EAGLE：推测解码在 MiniCPM-SALA 上的演进
4

9	**王致尧**：队长，华中科技大学人工智能专业大四本科生。

13	---
14	
15	很高兴再次和队友拿下第八周冠军。
16	
17	上一周的分享涉及量化方案与 Medusa 推测解码的初步适配。本文沿推测解码这条线索继续展开，讨论从 Medusa 迁移至 EAGLE 的过程，以及长上下文与高并发场景下观察到的若干问题。
18	
19	---
20	
21	## 01 推测解码简要回顾
22	
23	大模型 decode 阶段受 memory bandwidth 约束，每生成一个 token 需将全部权重矩阵从显存搬运一次，计算单元利用率极低。推测解码（Speculative Decoding）针对这一瓶颈，由轻量 draft 模型预先生成 K 个候选 token，再由 target 模型在单次 forward 中并行 verify，在保证输出分布严格不变的前提下，单次 forward 可产出多个 token。
24	
25	实际收益取决于 draft 每个候选的生成代价、候选被 target 接受的比例（accept rate）、以及 verify K 个候选引入的额外耗时，三者共同决定推测解码在具体部署条件下是否具有正收益。
26	
27	---
28	
29	## 02 Medusa：在主模型上附加预测头
30	
31	**Medusa**（Cai et al., ICML 2024）不引入独立 draft model，而是在 target 最后一层 hidden state 上附加 K 个轻量 MLP head，第 k 个 head 预测后续第 k 个位置的 token 分布：
32	
33	```
34	p_t^(k) = softmax( W₂⁽ᵏ⁾ · ( SiLU(W₁⁽ᵏ⁾ · h_t) + h_t ) )
35	```
36	
37	W₁ 初始化为零矩阵，训练初期各 head 输出与主模型等价，有利于收敛稳定性。Verify 阶段，各 head 的 top-s 候选经笛卡尔积构成候选树，配合 tree attention mask 在单次 forward 中完成验证。这一设计的工程优势在于参数增量小、无需 draft 自回归推理、训练流程简洁。
38	
39	但 Medusa 的结构性上限也源于此：各 head 独立预测，第 2 个 head 无法获知第 1 个 head 的预测结果，不存在 head 间共享的递推上下文。每个 head 本质上是对同一 hidden state 的浅层映射，预测位置越远精度衰减越显著。同时，K 增大时候选树规模指数膨胀，verify 开销的增长速率超过 accept rate 的提升。
40	
41	我们在 MiniCPM-SALA 上实现了 Medusa K=1，端到端取得正向收益，但随着 head 数量增加，accept rate 曲线迅速趋于平坦——这反映的是该架构固有的容量上限，而非实现层面的问题。
42	
43	---
44	
45	## 03 EAGLE：自回归 draft 模型
46	
47	**EAGLE**（Li et al., arXiv:2401.15077）在 draft 架构上做了根本性变更：draft 本身是一个自回归模型，输入为 target 的 hidden state 而非 token embedding。draft 接收 target 中间层已压缩的语义特征，以远小于 target 的参数量逼近其输出分布。与 Medusa 不同，draft 自身执行 K 步自回归推理，每步以上一步的输出作为输入，因此具备连贯的递推上下文——而这正是 Medusa 各 head 之间所缺乏的。
48	
49	从 Medusa 迁移至 EAGLE 后，accept rate 上限有实质性提升。
50	
51	---
52	
53	## 04 长上下文下的 accept rate 衰减
54	
55	我们在实测中观察到一个一致的现象：推测解码在长上下文条件下 accept rate 呈系统性下降。这并非某一种 draft 架构的特有问题，而是多个机制叠加的结果。
56	
57	其一是位置编码外推。draft 模型的训练通常以较短上下文为主（受训练成本约束），当推理时序列长度显著超出训练分布，位置嵌入进入外推区间，draft 的内部表示与训练阶段产生偏离，预测精度随之下降。
58	
59	其二是 draft KV 误差累积。draft 自回归执行 K 步推理时，每步均依赖前序步骤生成的 KV cache。短上下文条件下，这些 KV 与 target 之间的偏差尚在 verify 的容忍范围内；长上下文条件下 KV 序列增长，各步的微小偏差沿序列方向逐步放大，K 步执行完毕时 draft 的内部状态可能已显著偏离 target。
60	
61	---
62	
63	## 05 高并发下推测解码的收益回归
64	
65	推测解码的收益随 batch size 增大而递减，batch 足够大时转为负收益——这一点在学术文献中已有讨论（Sequoia, SpecInfer 等），但在工程部署中仍然容易被忽视。
66	
67	小 batch 条件下 GPU 计算资源严重闲置，target 处理 1 个 token 与处理 K+1 个候选的耗时差异极小，瓶颈在于 memory bandwidth 而非算力，verify 的边际代价接近零。中等 batch 条件下 GPU 利用率提升，verify 产生实际的算力开销，target 单次 forward 需并行处理 batch × (K+1) 个 token，额外耗时与 token 产出增益逐渐接近平衡点。大 batch 条件下 GPU 接近 compute-bound，forward 耗时与 token 总量近似线性，推测解码以 batch × (K+1) 的计算开销换取 ≤ K 个额外 token，当 accept rate 不足以覆盖该开销时，关闭推测解码反而是端到端更优的选择。

19	---
20	
21	## 01 量化：FourOverSix 自适应 block scale 选择
22	
23	### NVFP4 格式与标准量化的局限
24	
25	我们的基础量化路线是 GPTQ + NVFP4（FP4 E2M1 格式），decode 阶段使用 Marlin 做 W4A16 推理。NVFP4 的可表示值为 `{0, ±0.5, ±1, ±1.5, ±2, ±3, ±4, ±6}`，最大绝对值为 6。
26	
27	标准 NVFP4 量化时，每个 block 的权重会被归一化到 `[-6, 6]` 的完整 FP4 表示范围（即以 M=6 为上界缩放）。这个设计有一个结构性问题：FP4 在 `[4, 6]` 区间只有一个可表示值（6 本身），而在 `[2, 4]` 区间有两个（3 和 4）。当权重的最大值映射到 6 附近时，`66%~100%` 这段范围内的值都只能用 6 来表示，量化误差集中爆发。
28	
29	### FourOverSix 算法
30	
31	**FourOverSix**（Jack Cook, Junxian Guo, Guangxuan Xiao, Yujun Lin, Song Han；MIT + NVIDIA 联合工作，arXiv:2512.02010）提出：对每个量化 block 自适应地在两种归一化上界之间选择——M=6 或 M=4。
32	
33	当选择 M=4 时，block 的权重被缩放到 `[-4, 4]` 范围。此时 `[2, 4]` 区间内有三个可表示值（2、3、4），分布更均匀，对集中分布的 block 量化误差更小。代价是放弃了 FP4 的 `(4, 6]` 区间，对少数极大值的表示能力略有下降。
34	
35	选择规则是：对每个 block 分别用 M=6 和 M=4 量化一次，计算二者的反量化均方误差（MSE），取误差更小者：
36	
37	```python
38	# M=4 对应的 block scale 约为 M=6 时的 1.5 倍
39	scale_m4 = fp8(scale_m6.float() * 1.5)
40	mse_m6 = ((W_block - dequant(W_block, scale_m6)) ** 2).mean()
41	mse_m4 = ((W_block - dequant(W_block, scale_m4)) ** 2).mean()
42	final_scale = scale_m4 if mse_m4 < mse_m6 else scale_m6
43	```
44	
45	输出格式与标准 NVFP4 完全相同（4-bit 权重 + FP8 block scale），推理 kernel 无需任何修改，吞吐零损耗。
46	
47	### 我们的集成与实测
48	
49	我们将自适应 scale 选择嵌入 GPTQ 量化流程，在每个 block 的 scale 估算之后、GPTQ 权重优化迭代之前执行，使后续的 GPTQ 优化在已确定的 M 值框架下进行，避免二者冲突。
50	
51	实测发现，**约 40–43% 的 blocks 最终选择了 M=4**，MLP 层（gate/up/down proj）的占比明显高于 Attention 层的 QKV 投影。这符合直觉：MLP 权重经过更强的正则，分布较集中；QKV 权重包含更多离群值，M=6 的大范围更有优势。启用 FourOverSix 后，我们在各类评测任务上观测到稳定的量化精度提升。
52	
53	---
54	
55	## 02 推测解码：Medusa 在混合注意力架构上的适配
56	
57	### 推测解码的核心逻辑
58	
59	推测解码（Speculative Decoding）的基本思路是：用一个轻量 draft 预测若干后续 token，再让主模型并行 verify，从而在保证输出分布不变的前提下，以一次 verify 的代价换取多个 token 的产出。
60	
61	**Medusa**（Tianle Cai, Yuhong Li, Zhengyang Geng, Hongwu Peng, Jason D. Lee, Deming Chen, Tri Dao；ICML 2024）的核心创新是：**不引入独立的 draft model**，而是在主模型最后一层的 hidden state 上直接附加若干轻量预测头，每个头负责预测后续第 k 个位置。
62	
63	### Medusa Head 的结构
64	
65	每个 Medusa head 是一个带残差连接的单层变换，结构极其轻量：
66	
67	```
68	p_t^(k) = softmax( W₂⁽ᵏ⁾ · ( SiLU(W₁⁽ᵏ⁾ · hₜ) + hₜ ) )
69	```
70	
71	其中 `W₁` 是一个 `d×d` 的线性层，`W₂` 是投影到词表的输出层（复用主模型 LM Head 权重初始化），`hₜ` 是主模型最后一层的 hidden state。**W₁ 初始化为全零**，使得训练初期 Medusa head 的预测与主模型完全一致，训练过程更稳定。
72	
73	### Tree Attention Verify
74	
75	K 个 head 各自取 top-s 个候选，通过笛卡尔积构建一棵候选树（例如两个头各取 top-2，得到 4 条候选路径）。Verify 时，所有候选节点在**一次主模型 forward** 中并行处理，通过修改 attention mask 保证每个节点只能 attend 到其在树中的前驱路径，而非全部候选。验证完成后取最长的接受前缀，完成一次"以一次 forward 的代价验证多条候选"的推测解码循环。
76	
77	### MiniCPM-SALA 适配：GLA State 管理
78	
79	MiniCPM-SALA 是混合注意力架构，除标准 Multi-Head Attention 外，还有大量 GLA（Gated Linear Attention）递推层。GLA 的每步输出依赖一个递推 state `hₜ`：
80	
81	```
82	hₜ = exp(−γ) · hₜ₋₁ + kₜ · vₜᵀ
83	```
84	
85	这给 tree verify 引入了不同于标准 KV cache 的状态管理问题：树中的 sibling 分支必须从**同一 parent state** 出发，而非线性继承前一候选的 state，否则会引入错误的历史依赖。我们针对 verify 路径做了专门的 GLA state 分叉处理，确保混合架构下 tree verify 的语义正确性。
86	
87	此外，Medusa head 的训练数据分布与线上推理场景的匹配度对 accept rate 影响显著。我们基于验证集分布特征对训练数据做了加权采样，使训练集分布向实际推理场景对齐，accept rate 相比随机采样有可测量的提升。
88	
89	### 实验结果
90	
91	Medusa K=1 在 MiniCPM-SALA 上的 verify overhead 约为 0.39 ms，远低于一次正常 decode step 的耗时。各并发级别下 decode 阶段端到端吞吐均有稳定正向收益。
92	
93	---
94	
95	## 03 总结
96	
97	这两项工作的共同点：都需要深入理解目标模型的架构细节才能正确落地。FourOverSix 要求对 NVFP4 block scale 格式和 GPTQ 优化循环的交互有准确认知；Medusa 在混合架构上的适配，则要求理解 GLA 递推 state 与标准 KV cache 的语义差异。把论文里的方法在具体系统上跑通，往往比复现论文结果要难得多。
98	
99	感谢 SOAR 2026 组委会搭建的平台，感谢 SGLang 与 OpenBMB 的开源工作。也要感谢 Claude 和 ChatGPT——作为两个完全没有 infra 背景的本科生，很多系统层面的问题是在和 AI 反复讨论中才逐渐摸清楚的。同时感谢赛事中前几支队伍公开分享的技术博客，每篇都对我们的方向判断有所启发。比赛还在继续，期待与各位选手继续切磋。

39	
40	```
41	HMMA (tensor core):                48 条
42	HFMA2+HADD2+HMUL2 (CUDA core FP):  532 条

86	## 5. 已落地的 decode kernel-side 优化
87	
88	按合入顺序：
89	
90	### 5.1 SimpleGLA direct-state decode（commit `e922b76`）
91	
92	`demo-sala/sglang/python/sglang/srt/layers/attention/simple_gla_decode_kernel.py` 新增 `simple_gla_decode_update_fwd()`：直接从 `temporal[state_indices]` 读 recurrent state，kernel 内写回。同时 `BK=BV=128` decode tile 避免 FLA 默认 64×64 切 4 tile 后再 `sum(0)`。接入 no-spec decode（`SGLANG_SIMPLE_GLA_DIRECT_DECODE=1` 默认开），target_verify / spec 路径不动。
93	
94	CUDA graph replay：
95	
96	| batch | 旧 generic | 新 direct | speedup | output diff | state diff |
97	|---:|---:|---:|---:|---:|---:|
98	| 1 | 14.380 us | 6.164 us | 2.33× | 5.96e-08 | 0.0 |
99	| 8 | 34.860 us | 10.28 us | 3.39× | 6.1e-05 | 0.0 |
100	
101	bs=8 output diff 是 bf16 量级（K=128 单 tile 与旧 64×64 求和的累加顺序差异），state 完全 bit-exact。覆盖 trace 中 `vectorized_gather` + `fused_recurrent_fwd_kernel` + `index_put` 三段。
102	
103	### 5.2 compress_k head-parallel rewrite
104	
105	`minicpm_sparse_kernels.py`：原 kernel grid `(batch, chunk, head)` 但 history 路径只有 `head_idx==0` 处理所有 head，存在控制流冗余。改后每个 `head_idx` program 只负责自己的 head（padded / non-padded 两路同改）。
106	
107	| case | k | old graph | new graph | speedup |
108	|---|---|---:|---:|---:|
109	| bs=1, history=512 | k1 32/16 | 8.228 us | 4.129 us | 1.99× |
110	| bs=1, history=512 | k2 128/64 | 59.420 us | 32.809 us | 1.81× |
111	| bs=8, history=512 all rows | k2 128/64 | 58.152 us | 38.405 us | 1.51× |
112	
113	new compressed chunk 不是每步都有（k1 ~每 16 token 一次，k2 ~每 64 token 一次），是"去掉尖峰成本"而非稳定节省。
114	
115	### 5.3 Skip-fill `compress_k1/k2` -inf buffer（commit `5c83e4c`）
116	
117	旧逻辑每 decode step 把整段 replay buffer 填 `-inf` 再由 `compress_k_complete_kernel_new` 写有效区间。env `SGLANG_MINICPM_FILL_COMPRESS_BUFFERS=0` 跳过这批 BF16 `FillFunctor`。
118	
119	| 配置 | BF16 FillFunctor calls | total ms | per step |
120	|---|---:|---:|---:|
121	| fill-on | 288 | 1.480 ms | 0.0925 ms/step |
122	| skip-fill | 256 | 0.258 ms | 0.0161 ms/step |
123	| 差值 | -32 | -1.222 ms | -0.0764 ms/step |
124	
125	多出的 32 次 = 16 decode steps × 2 buffers，分别是 grid `[65536,1,1]` 和 `[16384,1,1]` 大 buffer fill。skip-fill 后剩 256 次小 fill（grid `[512,1,1]`）非目标。decode graph 总时间 155.107→153.462 ms / 16 steps，净 -0.103 ms/step。
126	
127	### 5.4 Decode pooling no-zero
128	
129	`infllm_v2.max_pooling_1d_varlen()` Python wrapper 先分配 `torch.zeros` 输出再调 kernel，但 C kernel 每个有效 `(head, q, out_block)` 都会被覆写。`minicpm_sparse_utils.py` 增加 `_max_pooling_1d_varlen_no_zero()` 用 `torch.empty`，只在 `max_seqlen_q == 1` 的 decode 启用。
130	
131	| case | zeros | empty | speedup |
132	|---|---:|---:|---:|
133	| S1 decode（70136） | 12.402 us | 8.158 us | 1.520× |
134	| S8 decode（135664） | 12.369 us | 12.440 us | 0.994× |
135	| verify（16384） | 6.998 us | 8.138 us | 0.860× |
136	
137	低风险小 patch，只覆盖 no-spec/S1/S8 decode pooling。完整 stage1 graph 后净 -1.0~1.4 us/call，不能替代 k1+k2 fused stage1。

168	### 7.1 stage1 k1+k2 语义（必须保持）
169	
170	`infllmv2_attn_stage1(q, k, v)` 里 `k=k1, v=k2`，**v 不是普通 attention 的 value**。CUDA kernel 分两段：第一段用 k2 跑 coarse softmax 得 row max/sum；第二段用 k1 调 `softmax_rescale_gt()` 复用 row max/sum，再通过 `hdim16_reduce()` 写 k1 score。**所以 k1-only fused topk 和 `split_stage1=True` 都是错的——官方 score 不是 `softmax(q @ k1)`，而是由 k2 coarse LSE 参与归一化后的 k1 score**。要保语义的真正融合应在 stage1 CUDA epilogue 里做（`hdim16_reduce()` 后直接做 block pooling/topk），而非外挂 k1-only TileLang kernel。

# LK Loss Formulas and Components

## Core Loss Functions

**Hybrid Objective with Adaptive Blending:**
$$\mathcal{L}_{\mathrm{LK}}^{\lambda}(p,q) = \lambda \cdot \operatorname{KL}(p\|q) + (1-\lambda) \cdot \operatorname{TV}(p,q)$$

**Likelihood-based Approach:**
$$\mathcal{L}_{\text{LK}}^{\alpha}(p,q) = -\log\sum_{x\in\mathcal{V}}\min(p(x),q(x))$$

**Standard KL Divergence (baseline):**
$$\operatorname{KL}(p\|q)=\sum_i p_i\log(p_i/q_i)$$

## Acceptance Rate Definition

The acceptance rate is expressed as: "α = ∑ₓ∈𝒱 min(q(x), p(x))" - the sum of probability overlap across all vocabulary items.

## Adaptive Lambda Schedule

The weighting parameter uses: "λ = exp(−η·sg[α]), η > 0" where sg denotes stop-gradient. This transitions from KL-dominated (λ→1 when α→0) to TV-dominated (λ→0 when α→1) optimization.

## TV-Acceptance Relationship

The document states: "α = 1 − TV(p,q)" connecting acceptance rate directly to total variation distance minimization, establishing that TV optimization directly maximizes acceptance.

# LK Losses: Key Formulas and Insights

## LK Loss Formula

The hybrid LK objective is: **"λ⋅KL(p∥q)+(1−λ)⋅TV(p,q)"** where λ adapts based on acceptance rate.

## What is Alpha?

Alpha (α) represents the acceptance rate in speculative decoding. It's defined as **"∑x∈Y min(p(x), q(x))"** — the total probability mass shared between the draft (q) and target (p) distributions. This quantity directly measures how many draft tokens the target model accepts.

## Lambda Computation

The weighting parameter λ is computed adaptively as: **"λ = exp(−η⋅sg[α])"** where η is a positive hyperparameter and sg denotes stop-gradient. This schedule prioritizes KL divergence early (when α is low) and shifts toward TV distance as alignment improves.

KL divergence shares the same global optimum as acceptance rate but "leads to different suboptimal solutions when model capacity is constrained."
