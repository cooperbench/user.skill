下面分四部分回答，结论都尽量钉在公式或源码上。 --- ## 1. `max_position_embeddings` 524288 → 1024：对位置 0..511 的 RoPE 有没有影响？ **在你当前配置下：没有影响（逐索引相等）。** ### 数学 标准 MiniCPM RoPE（`MiniCPMRotaryEmbedding`）里，对偶维频率为 \[ \omega_i = \theta^{-2i/d},\quad i=0,2,\ldots,d-2,\quad \theta=\texttt{rope\_theta}=10000 \] （实现里用 `inv_freq = 1 / (base ** (arange(0, dim, 2) / dim))`，等价。） 位置 \(p\) 上的相位为 \(\phi_{p,i} = p \cdot \omega_i\)，再经 `torch.cat((freqs, freqs), dim=-1)` 拼成与 LLaMA 一致的 128 维 embedding，最后 `cos`/`sin`。**这些量只依赖 \((p,\theta,d)\)，与缓存总行数 `max_position_embeddings` 无关**——`max_position_embeddings` 只决定预先算多少行 `[0, L_cache-1]`，不改变第 \(p\) 行的公式。 `MiniCPM-SALA` 的 `config.json` 里 **没有** `rope_scaling`，Lightning 侧走的是基类 `MiniCPMRotaryEmbedding`，不会触发 LongRoPE/NTK 等「用 `max_position_embeddings` 改频率」的路径： ```2144:2150:/root/shared-nvme/openbmb/models/MiniCPM-SALA/modeling_minicpm_sala.py def _init_rope(self): if self.config.rope_scaling is None: self.rotary_emb = MiniCPMRotaryEmbedding( self.head_dim, max_position_embeddings=self.config.max_position_embeddings, base=self.config.rope_theta, ) ``` 缓存构造为 `t = arange(seq_len)` 与 `inv_freq` 的外积，第 \(p\) 行即 \(p\) 固定： ```567:577:/root/shared-nvme/openbmb/models/MiniCPM-SALA/modeling_minicpm_sala.py def _set_cos_sin_cache(self, seq_len, device, dtype): self.max_seq_len_cached = seq_len t = torch.arange( self.max_seq_len_cached, device=device, dtype=self.inv_freq.dtype ) freqs = torch.outer(t, self.inv_freq) #
