## 我做了什么

1. **生成 terminfo 源文件**：用 `infocmp xterm-256color` 导出系统里已有的 `xterm-256color` 能力描述，把开头的名字改成 `xterm-ghostty`，保存为 `/tmp/xterm-ghostty.ti`。
2. **编译并安装**：`tic -x /tmp/xterm-ghostty.ti`，产物写到 `/etc/terminfo/x/xterm-ghostty`。从此 tmux/vim/less/ssh 等任何查 terminfo 的程序都认 `xterm-ghostty` 这个名字。
3. **清理**：删掉了之前加在 `~/.bashrc` 里的 `TERM` 兜底（已不需要）。

**本质**：给 Ghostty 这个名字注册了一个"别名条目"，能力等同于 `xterm-256color`。

## 这是不是最好的方法？

不是。这是**能立刻修好、但能力打折**的方案。

最好的方法是用 **Ghostty 官方的 terminfo**，因为它声明了一些 `xterm-256color` 没有的扩展能力（比如 `Setulc`/`Smulx` 彩色下划线、Kitty 键盘协议、更丰富的真彩色/图形协议等）。程序能感知到这些能力才会启用对应特性。

### 推荐做法（任选其一）

**方案 A：从本地 Ghostty 推到远程（最干净）**

在你本地装了 Ghostty 的机器上跑一次：

```
infocmp -x xterm-ghostty | ssh user_4813494d@<远程主机> -- tic -x -
```

会覆盖掉我装的这份别名条目，变成原生 Ghostty 能力。

**方案 B：让 ssh 自动带过去**

在本地 `~/.ssh/config` 里写：

```
Match host <远程主机> exec "infocmp -x >/dev/null 2>&1"
    SetEnv TERM=xterm-ghostty
    RemoteCommand ...
```

或者更简单，在本地 shell 里 `alias ssh='kitty +kitten ssh'` 类似的思路 —— Ghostty 可以配置登陆时自动传输 terminfo（查 `ghostty +show-config` 里和 `shell-integration` 相关的项）。

**方案 C：就用我装的这份**

如果你不在乎彩色下划线、Kitty 键盘协议这些细节，现在这份已经够用，不用再折腾。tmux 起来了，vim/less 也正常。
