vocab truncation：KL 用 draft vocab 内重新归一化的 `target_p`；acceptance/LK 用未重新归一化的 `target_p_on_draft = exp(draft_target_head - full_logsumexp)`，保留 full-vocab tail mass影响，见 [/user_4813494d/openbmb/research/lk_loss/SpecForge-pr-492/specforge/core/eagle3.py:727](/user_4813494d/openbmb/research/lk_loss/SpecForge-pr-492/specforge/core/eagle3.py:727)。 - [/user_4813494d/openbmb/eagle/train_v4/train_v4.py:126](/user_4813494d/openbmb/eagle/train_v4/train_v4.py:126) 的 `lk_lambda_loss` 用的是逐 token `lambda`，而 SpecForge PR 用的是每个 step 的 masked mean acceptance 标量来算一个 `kl_weight`。 - v4 的 `tv = 0.5 * abs(target_p - q).sum()` 是在重归一化后的 draft vocab 分布上算 TV；SpecForge 对 LK 的 TV 等价项用的是 `1 - acceptance_rate`，且 acceptance 使用 full-vocab 归一化下的 draft-vocab 概率质量。 - v4 的 `alpha = min(target_p, q).sum()` 使用的是 `_build_target_p()` 返回的重归一化 target 分布，见 [/user_4813494d/openbmb/eagle/train.py:383](/user_4813494d/openbmb/eagle/train.py:383)。这会系统性高估 acceptance，尤其当 target tail 或 draft-vocab 外质量不小时，导致 `lambda = exp(-eta * alpha)` 过小，过早偏向 TV。 - v4 训练数据只有 top-K logits，当前无法精确复现 SpecForge 的 `target_p_on_draft`，因为缺 full logsumexp。至少应在采集阶段保存 `target_logsumexp`，或用 top-K logsumexp 做近似下界。 - 另一个明显 bug：`load_v4_vocab_cache()` 只注册 `d2t/t2d/draft_idx_map`，没有像 v3 `build_vocab_mapping()` 那样用 `self._full_lm_head_weight[self.d2t]` 初始化 `lm_head`，见 [/user_4813494d/openbmb/eagle/train_v4/train_v4.py:174](/user_4813494d/openbmb/eagle/train_v4/train_v4.py:174) 对比 [/user_4813494d/openbmb/eagle/train.py:370](/user_4813494d/openbmb/eagle/train.py:370)。如果 vocab cache 存在，v4 的 head 很可能保持随机初始化。 **建议** 1. 先修 `load_v4_vocab_cache()` 的 lm_head 初始化，否则 LK 对比不可信。 2. 采集/数据格式补 `target_logsumexp`，把 LK 的 acceptance 改成未重归一化 `p_on_draft`。 3. 若目标是复现 SpecForge PR，`L^lambda` 改成 step 级 scalar acceptance/weight；若坚持逐 token lambda，需要单独做 ablation，不能声称等同 PR 实现。 4. 保留当前 `0.8 ** step` TTT decay；这和 SpecForge/TorchSpec 的 EAGLE3 接法一致。
