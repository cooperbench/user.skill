**主路径**
在 decode 非 extend 分支里，每轮固定是 `draft -> verify -> draft_extend_after_decode`：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:381)。按当前关注的 `steps=2/topk=2/dtn=5`，CUDA graph 开启后，真正值得看的是 graph 外的准备、verify 接受/rollback、post-accept、draft_extend 补 KV。

**可能热点 / 同步点**

1. `draft` graph 外仍有固定开销  
   [eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:463) `_draft_preprocess_decode` 每轮分配 draft KV slots；`page_size==1` 下按 `num_seqs * speculative_num_steps * topk` 分配：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:483)。但 `draft_forward` 注释已指出实际只需要更少 cache loc：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:754)。2/2/5 时这是每轮短 batch 都会发生的 allocator/assign 成本。  
   低风险方向：优先验证这个 TODO 是否能把 draft KV 临时分配从 `steps*topk` 缩到实际 forward 需要量，同时保持 verify 前释放语义。

2. `draft` CUDA graph 只包住 replay/forward，不包 tree 构造  
   graph replay 在 [eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:641)，随后 `build_tree_kernel_efficient` 仍单独执行：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:674)。2/2/5 下树很小，kernel launch 和少量张量组织可能比算术本身更显眼。  
   低风险方向：先用现有 NVTX `ED_tree_and_out` 单独确认占比；若明显，可考虑专门化 topk=2/steps=2/dtn=5 的 tree path，减少通用逻辑和中间张量。

3. verify 前后 allocator 开销密集  
   draft KV 在 verify 开头释放：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:818)。随后 `prepare_for_verify` 又为 target verify 分配 KV 并写 req_to_token：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:832)，具体在 [eagle_info.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:128)。  
   低风险方向：profile 里把 `EV_free_draft_kv`、`EV_prepare_for_verify`、allocator free/alloc 分开看。短 S1/S8 下这些固定成本很可能吃掉 EAGLE 收益。

4. verify accept 有硬同步到 CPU  
   `accept_index.tolist()` 和 `predict.tolist()` 每轮同步：[eagle_info.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:468)。之后 `accept_length.cpu().tolist()` 又同步/读取：[eagle_info.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:531)。这是短 batch 下最明确的同步点。  
   低风险方向：先不要大改语义；可评估是否复用第一次同步得到的信息，减少第二次 CPU read，或只在 finish/grammar 必需字段上做最小 CPU 搬运。

5. rollback page_size=1 路径仍有 boolean select  
   `page_size==1` 下不会走 topk>1 的 `move_kv_cache` rollback，但会做 `batch.out_cache_loc[evict_mask]`，代码注释直接标了 “boolean array index leads to a device sync”：[eagle_info.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:540)。2/2/5 + 默认 `page_size=1` 时，这就是主要 rollback 形态。  
   低风险方向：把 boolean mask select 改成专用 compact/free list kernel 是较明确候选，但需要 allocator free 接口能吃预生成 slot list。

6. post-accept 是小 gather，但每轮必跑  
   `logits_output.next_token_logits` 和 `hidden_states` 按 `accepted_indices` gather：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:916)。hidden_states 后续 draft 需要，不能简单删；但这个 gather 对 dtn=5、小 batch 是固定 kernel/索引成本。  
   低风险方向：只做 profile 确认；收益空间通常小于 CPU 同步和 allocator。

7. `draft_extend_after_decode` 是 post-accept 的固定尾巴  
   只要 `verified_id` 非空就会跑：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:402)。内部会 clone 备份 `seq_lens` / `seq_lens_cpu`：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:1221)，prepare extend 时还会重建 input/positions：[eagle_info.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:828)，再跑 draft_extend graph：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:1256)。  
   低风险方向：确认 `DEX_backup`、`DEX_prepare_extend`、`DEX_get_forward_batch` 是否在短 S1/S8 里显眼；若显眼，优先减少 clone/restore 和 Python list `extend_lens` 构造，而不是动 draft model forward。

8. 稀疏 cache 补分配是 decode 侧间歇开销  
   verify 后固定调用 `_alloc_sparse_for_new_positions`：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:934)。里面 CPU `tolist()` + per-req loop：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:1080)，跨 k1/k2 边界时触发 alloc/write：[eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:1112)。  
   低风险方向：这不是 prefill；短 S1/S8 decode profile 若有周期性尖刺，应把 `EV_alloc_sparse_new_positions` 单独看。

**优先级建议**
先看 `EI_accept_index_tolist` / `EI_predict_tolist` / `DC_verify_al_cpu`、`EI_free_unacc_page1_select`、`EV_prepare_for_verify`、`DEX_prepare_extend`。这些是 2/2/5、CUDA graph enabled、短 S1/S8 下最可能从 profile 里冒出来的 EAGLE/verify/rollback 固定成本。
