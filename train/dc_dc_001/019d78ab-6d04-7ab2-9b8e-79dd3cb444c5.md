> AGENT

调查结果：现在真正实用的 Codex hooks，优先级不是“花哨自动化”，而是防错、补上下文、自动复检。

- `PreToolUse`：最值得先上。它现在主要拦 `Bash`，很适合挡危险命令和错误运行方式，比如 `rm -rf`、`git reset --hard`、`sudo`、plain `conda run -n carla ...`，或者在旧 `CarlaUE4-Linux-Shipping` 还活着时阻止新实验启动。
- `UserPromptSubmit`：做提示词卫生和自动补上下文。适合扫误贴的 key/token，也适合在用户提到 `phase2`、`phase3`、`CARLA` 时自动补一段项目约束。
- `SessionStart`：做项目记忆加载。每次 `startup` 或 `resume` 自动注入仓库规则、机器特殊点、常用命令，实用性很高。
- `Stop`：做回合结束校验。适合“改了代码但没跑验证”“长实验没写 partial artifacts”“没清理遗留 CARLA 进程”这类场景；它可以要求 Codex 自动继续一轮。
- `PostToolUse`：做命令结果审查。适合识别 `Traceback`、`segfault`、CARLA server early exit、swap 爆掉、测试失败，然后补充上下文或要求再修一轮。

当前不建议优先做的：

- 指望 hook 拦所有工具。官方文档明确说现在 `PreToolUse`/`PostToolUse` 只对 `Bash` 生效，不拦 `Write`、`MCP`、`WebSearch` 等。
- 依赖多个同事件 hook 的顺序。官方说明同一事件的多个命令 hook 会并发启动。
- 很重的 hook。默认超时可到 600 秒，但太慢会拖累每个 turn。

对你这个仓库，我建议第一批只做 3 个：

- `SessionStart`：自动注入 CARLA 机器注意事项和 Phase 2/3 稳定运行策略。
- `PreToolUse`：拦 plain `conda run -n carla ...`、拦危险 git/sudo、拦未清理旧 CARLA 进程时的新启动命令。
- `Stop`：如果长验证没写出部分结果文件或没保存 partial artifacts，就要求继续补完。

- 首次续跑时：
  [never_stop.py](/home/user_0a329be7/Downloads/graduate/.codex/hooks/never_stop.py#L51)
- 已经被 Stop 续跑过一次时：


- hook 收到的是结构化状态 JSON
- 模型继续时收到的是你生成的 `reason` 文本
- `systemMessage` 更多是给 Codex UI / 事件流的提示，不是主要续跑指令

- `stdin` 给 hook：是“当前 stop 上下文”
