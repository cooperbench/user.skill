These complementary patterns remain invisible under fixed length calibration." 也就是说，不同长度的输入会激活不同的权重通道。固定长度校准的 Hessian 矩阵（AWQ 的 `X X^T` 激活统计）无法反映真实推理时多样的长度分布。4096 截断的 56K 文本，与真实 56K 推理的激活分布差异极大。 --- ### 二、行业标准校准数据集是什么 | 数据集 | 适用场景 | 使用方 | |-------|---------|-------| | `wikitext-2-raw-v1` | 通用语言模型基础能力 | GPTQ、AutoAWQ 默认 | | `c4` | 通用预训练模型 | MaCa 论文, LLM Compressor | | `ultrachat-200k` | 指令微调对话模型 | NVIDIA ModelOpt, LLM Compressor 官方推荐 | | `open-platypus` | 通用指令模型 | LLM Compressor | | `cnn_dailymail` | 通用英文文章 | 较常见 | | 训练数据子集 | 微调模型（最优）| NVIDIA 官方建议 | **LLM Compressor 官方文档**明确说明： > "It is useful to use calibration data that closely matches the type of data used in deployment. 如果用ue8m0 量化kvcache 能不能吃到deepgemm优化？

> AGENT

不能。这两件事完全不在一个维度上。 **DeepGemm** 是 GEMM kernel（矩阵乘法），作用于 **Linear 层**（权重 × 激活）。它要求的 "ue8m0 scale_fmt" 指的是 **NVFP4 权重的 block scale 格式**——每个 scale 用 unsigned 8-bit 纯指数（power-of-2），而不是标准的 FP8 E4M3。 **KV cache dtype** 作用于 **Attention**（Q @ K^T → softmax → @ V）。它决定的是 KV 存储精度，走的是 FlashInfer/FlashAttention 的 attention kernel，和 GEMM kernel 没有任何交集。 ``` Linear 层： x → [GEMM kernel] → y ← DeepGemm 管这里 Attention： Q,K,V → [Attention kernel] → O ← KV cache dtype 管这里 ``` 更关键的是：**DeepGemm 是 SM100（B200/GB200）专用**，不是 SM120（RTX 5090 / PRO 6000）。我们的 GPU 即使权重 scale 改成 ue8m0，DeepGemm 也不会在 SM120 上运行。那个警告从第一天起就是误导性的（issue #20776 已确认）。 所以结论： - 改 KV cache format 不影响 DeepGemm - 改权重 scale format 到 ue8m0 在 SM120 上也没用 - 两条优化路径互不干涉，各做各的
