## FP4/NVFP4量化对Lightning Attention层影响的研究分析

### 一、架构参数对比

先量化两种层的投影矩阵参数差异：

| 组件 | Standard Attention (8层) | Lightning Attention (24层) |
|------|-------------------------|---------------------------|
| Q投影 | 4096 → 4096 (32h×128d) | 4096 → 4096 (32h×128d) |
| K投影 | 4096 → 256 (2h×128d, GQA) | 4096 → 4096 (32h×128d) |
| V投影 | 4096 → 256 (2h×128d, GQA) | 4096 → 4096 (32h×128d) |
| O投影 | 4096 → 4096 | 4096 → 4096 |
| Z投影(gate) | 无 | 4096 → 4096 (output gate) |
| Norm | 无额外 | q_norm, k_norm, o_norm (RMSNorm) |
| MLP | gate_up: 4096→32768, down: 16384→4096 | 同左 |

**关键发现**：Lightning Attention层的K/V投影是标准层的16倍大（4096 vs 256维度），因此量化这些投影会影响更多参数。加上额外的z_proj（output gate），每个Lightning层比标准层**多约49M参数**用于attention部分。

### 二、核心研究发现

#### 2.1 来自NVFP4层敏感性论文的关键结论（2026年最新研究）

论文 "Diagnosing FP4 Inference" 对NVFP4和MXFP4进行了系统的分层分析，关键发现：

1. **MLP投影（up_proj, down_proj）是对FP4量化最敏感的组件**，在所有模型规模和格式中一致排名最高
2. **Attention投影（q_proj, k_proj, v_proj, o_proj）敏感度显著更低**
3. **Gate投影处于中间水平**
4. 敏感度排序在不同规模间保持**结构性稳定**

具体数据（Qwen2.5-7B, NVFP4）：
- down_proj: PPL改善 +0.11（最敏感）
- up_proj: +0.10
- gate_proj: +0.08
- o_proj: +0.04
- v_proj: +0.03
- k_proj: +0.02
- q_proj: +0.02（最不敏感）

#### 2.2 线性注意力的特殊数值特性

Lightning Attention使用**线性递归（linear recurrence）**替代softmax，这带来几个量化相关的风险因素：

1. **累积误差传播**：线性注意力维护一个递归状态 `S_t = S_{t-1} * gate + K_t^T * V_t`。每个时间步的量化误差会通过递归累积，随序列长度增长而恶化。这是softmax attention不存在的问题——softmax每次独立计算注意力权重。

2. **无softmax归一化的保护**：Softmax天然将注意力权重归一化到[0,1]区间，形成概率分布，对异常值有一定的抑制作用。线性注意力没有这种归一化，注意力计算中的值范围更大、更不可预测。

3. **Q/K/V全维度**：Lightning层的K/V是32头×128维=4096维（不使用GQA），参数量是标准层K/V的16倍。更多参数意味着量化误差的基数更大。

4. **gate机制的精度需求**：z_proj产生sigmoid gate（`o * sigmoid(z)`），sigmoid函数在接近0.5的区域对输入微小变化非常敏感，FP4量化可能导致gate值显著偏移。

5. **q_norm和k_norm的交互**：Lightning层使用RMSNorm对Q和K进行归一化。如果qkv_proj的输出已被量化引入误差，再经过norm后误差模式可能被放大或扭曲。

#### 2.3 SageAttention3对FP4注意力的研究

SageAttention3（2025 NeurIPS）研究了FP4在注意力计算中的应用：

- **FP4只有15个可表示的值**，动态范围极其有限
- 注意力图的值主要集中在[0,1]的小范围内，量化到FP4时缩放因子被迫进入极窄的动态范围
- **注意力比线性层有更重尾的激活分布和更多异常值**
- 在RTX 5090上使用微缩放（microscaling）FP4可实现5倍加速

但是：SageAttention3主要研究的是**注意力计算过程中QK^T和softmax的量化**，而非权重量化。NVFP4主要做的是**权重量化**（W4A16或W4A8），两者是不同的量化目标。

### 三、关键分析与推理

#### 3.1 Lightning Attention层对权重量化可能并不比标准层更敏感

理由：
1. **论文证据**：NVFP4论文明确表明attention投影（QKV+O）在FP4量化下敏感度**显著低于**MLP投影。这个结论在所有测试的模型规模中一致。
2. **权重量化vs计算精度**：NVFP4/modelopt_fp4做的是**权重量化**——将权重存储为FP4，但激活和计算通常仍在FP16/BF16进行。递归状态的累积误差主要来自**计算精度**而非权重精度。
3. **两种层共享相同的MLP结构**：无论是标准层还是Lightning层，MLP结构完全相同（gate_up_proj + down_proj），而MLP是最敏感的部分。

#### 3.2 但Lightning层有额外的风险点

1. **z_proj（output gate）**：这是一个额外的线性投影，其输出经过sigmoid后作为门控。虽然论文显示gate_proj敏感度中等，但sigmoid函数可能放大量化误差的影响。
2. **更大的QKV投影**：K/V投影尺寸4096→4096（vs 标准层的4096→256），更多参数参与量化。虽然单个投影的敏感度不高，但累积效应可能不同。
3. **递归状态精度**：如果K和V的量化误差被注入到递归状态，错误会在长序列中累积。但在实际推理中，NVFP4量化的是权重，K和V的**值**仍在FP16精度下计算（权重反量化后与FP16激活相乘），所以这个风险有限。

#### 3.3 MiniCPM-SALA已有量化版本存在的信号

搜索发现MiniCPM-SALA已经有AWQ 4-bit和8-bit量化版本在HuggingFace上，这说明4-bit权重量化在此模型上是**可行的**。

### 四、推荐策略

#### 方案A：全部层统一NVFP4量化（推荐优先尝试）

**理由**：
- NVFP4论文明确显示attention投影对FP4量化敏感度最低
- MiniCPM-SALA已有4-bit量化版本运行
- 权重量化不会直接影响线性注意力的递归计算精度（激活仍为FP16）
- 统一量化实现最简单，速度提升最大
- 比赛精度要求是97%（77.6/80），有一定容错空间

**实现方式**：直接使用 `--quantization modelopt_fp4` 或 `--quantization petit_nvfp4`，对所有层统一量化

#### 方案B：混合精度（如果方案A精度不达标的备选）

如果全FP4精度不够，按敏感度从高到低逐步保留FP16：

1. **第一步**：将MLP的down_proj排除FP4量化（最敏感组件）
2. **第二步**：将MLP的up_proj也排除
3. **第三步**：将Lightning层的z_proj排除（gate对精度敏感）
4. **第四步**：如果仍不够，将Lightning层整个排除FP4量化

**实现方式**：使用 `exclude_modules` 参数或 `is_layer_skipped` 机制选择性跳过：

```python
# ModelOptFp4Config 支持 exclude_modules
exclude_modules = ["down_proj"]  # 示例：排除所有层的down_proj
```

或更精细地按层index排除：

```python
# 排除特定Lightning层的特定投影
exclude_modules = [
    "model.layers.{i}.self_attn.z_proj"  # 排除所有Lightning层的gate
    for i in range(32) if i not in [0,9,16,17,22,29,30,31]
]
```

#### 方案C：MLP-only FP4（保守方案）

NVIDIA ModelOpt已提供 `nvfp4_mlp_only` 配置，只量化MLP层而保留attention投影为FP16。

**问题**：这可能过于保守。论文数据显示attention投影的FP4敏感度很低，不量化它们会损失显著的速度收益。

### 五、关键建议

1. **先尝试全FP4量化**（方案A），跑精度测试。鉴于比赛目标是97%准确率，且NVFP4论文显示attention投影敏感度很低，全量化大概率可行。

2. **如果精度不达标**，优先排除MLP的down_proj（最敏感），而非排除Lightning层——因为MLP在两种层中都存在且都是最敏感的。

3. **不要过度区分对待Lightning层和标准层的attention投影**。两者在权重量化下的行为应该是相似的——论文的核心发现是"attention投影不敏感"，这个结论不太可能因为是线性注意力就完全颠覆。

4. **真正需要注意的是MLP层**，尤其是down_proj。如果有精度问题，根据论文block-level敏感度分析，最后几层的MLP down_proj最为敏感，可以优先保留为FP16。

5. **递归状态的数值稳定性不是权重量化的问题**，而是计算精度的问题。只要推理计算在FP16/BF16下进行（NVFP4的标准做法），递归状态就不会受权重量化直接影响。
