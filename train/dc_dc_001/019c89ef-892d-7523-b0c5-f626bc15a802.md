**EMA 是什么（Exponential Moving Average）** - 核心想法：训练过程中参数会抖动，EMA 维护一份“更平滑”的参数副本，用它来做验证/保存/推理，等价于对最近一段时间的模型做了一个“权重空间的集成”。 - 更新公式（每次 `optimizer.step()` 之后做一次）： - `w_ema = decay * w_ema + (1 - decay) * w` - `decay` 通常很接近 1（0.99, 0.999, 0.9999），越大越“慢”，越像长期平均。 - 怎么用：训练仍用原模型 `w` 反传；验证/保存 ckpt 时临时把权重切到 `w_ema`（或直接维护一个 `ema_model`）。 - 为什么能涨：相当于给参数加了低通滤波，减少 mini-batch 噪声 + 强增强带来的方差，验证指标更稳，往往更容易拿到更好的“最好点”。 - 常见坑： 1. EMA 要在 `optimizer.step()` 之后更新（在 DDP 下每卡参数同步完才算真的 step 完）。 2. 初期不稳定时可以“延迟启用 EMA”（比如 warmup 结束后再开始更新），否则早期噪声会污染平均。 3. 额外显存：要多存一份参数（同等大小的模型）。 **SWA 是什么（Stochastic Weight Averaging）** - 核心想法：在训练后期取多个时刻的权重做“均匀平均”，得到 `w_swa`，倾向于落在更“平坦”的极小值附近，泛化更好。 - 更新公式（每隔一段时间/每个 epoch 取一次 snapshot）： - `w_swa = (k * w_swa + w) / (k + 1)` - 怎么用：一般在后 20% 到 40% 的训练里启用（例如从第 120 epoch 开始平均到 200）。 - 为什么能涨：不是平滑“最近”，而是把后期多个点平均，近似一个小型 ensemble。 - 常见坑： 1. SWA 更依赖后期能“走动起来”去采样多个点：如果学习率在尾段已经很小、权重几乎不动，SWA 收益会变小。 2. 经典 SWA 要“更新 BN 统计”（跑一遍数据重新计算 running stats），但你这里 `SegResNetDS(norm="instance")`（见 `src/scripts/train_patch.py:150`）主要是 InstanceNorm，BN 更新问题基本不重要。 **EMA vs SWA 怎么选** - 只想“少改动就让指标更稳、最好点更好”：优先 EMA。 - 训练跑得足够久，愿意在后期再多跑一段并做平均：再加 SWA（或只做 SWA）。 - 两者也能叠加，但工程复杂度更高，通常先做 EMA 就够。 --- ## 不换 backbone：数据增强怎么做才更“提升模型能力” 先把你现在的关键入口对齐一下： - patch 训练用的是 `get_train_transforms(mode='patch')`（`src/scripts/train_patch.py:128`，定义在 `src/data/augmentations.py:12`）。 - patch 采样逻辑在 `src/data/patch_dataset.py:95`，前景过采样是“选前景体素当中心点”。 下面按“最影响能力”的方向讲清楚。 ### 1) 采样策略本身就是最重要的“空间增强” 你现在的 oversample 前景逻辑（`src/data/patch_dataset.py:95`）是： - `force_fg=True` 时，中心点直接取 `label==1` 的坐标（`src/data/patch_dataset.py:117`）。 - 然后 patch 以这个中心裁剪（`src/data/patch_dataset.py:154`）。 问题：这会引入一个很强的“前景偏中心”的先验。模型会不自觉学到：前景更常出现在 patch 中央。推理滑窗时前景位置是任意的，这个先验会降低泛化。 更强的做法（nnUNet 常用思想）： - “保证包含前景体素”，但不要保证它在中心。 - 实现方式是：先选一个前景坐标 `p`，然后随机生成一个 `bbox_lbs`，满足 `bbox_lbs <= p < bbox_lbs + patch_size`，这样前景可以落在 patch 内任何位置（均匀/近似均匀）。 -
