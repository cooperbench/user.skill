## 4. "KL and CE differ only by a constant in classification" -- Is this standard?

**Verified: Yes, this is a standard and correct mathematical statement.**

The relationship is:

```
CE(p, q) = -sum p(x) log q(x) = KL(p || q) + H(p)
```

where H(p) = -sum p(x) log p(x) is the entropy of the true distribution p. Since p is the target distribution (fixed during training), H(p) is a constant with respect to the model parameters (which only affect q). Therefore, minimizing CE is equivalent to minimizing KL. This is textbook information confirmed by multiple authoritative sources.

## 5. The blog calls cross-entropy loss "plogp loss" -- Is this a recognized term? Is it technically correct?

**This is a recognized informal/code-level term in the EAGLE/speculative-decoding community, but it is technically a misnomer.**

**Where "plogp" comes from:** In the EAGLE codebase (SafeAILab/EAGLE), the cross-entropy loss is computed as a variable literally named `plogp`. The code does:

```python
out_logp = nn.LogSoftmax(dim=2)(out_head)   # log q (draft model)
plogp = target_p * out_logp                   # p * log q
cross_entropy_loss = -sum(loss_mask * plogp)
```

So `plogp` is the **variable name** in the EAGLE source code for the quantity `p * log q`. The blog (and apparently the EAGLE community) adopted this variable name as shorthand for the loss. This is confirmed by Chinese-language CSDN blog posts analyzing the EAGLE code.

**Why it is technically imprecise:** The expression `-sum p_target * log p_draft` is really `p * log q`, not `p * log p`. The name "plogp" is misleading because the two distributions p (target) and q (draft) are different. The quantity `p * log p` would be the negative entropy of p, which is something entirely different. A more accurate name would be "plogq" or simply "cross-entropy loss." However, because the EAGLE code literally uses the variable name `plogp`, the term has propagated as informal jargon within the speculative decoding community, particularly in Chinese-language ML discussions.

**Verdict:** The term "plogp loss" is used in practice (originating from an EAGLE code variable name), but it is a technically imprecise label. The blog's use of it is consistent with community convention.

    43	第一项约束 draft 中间表示与 target 中间表示接近，第二项约束 draft 的输出 token 分布与 target 一致。EAGLE-3 进一步把第一项去掉，只保留输出分布层面的拟合，本质上就是 `−Σ p_target · log p_draft`，EAGLE 代码里惯称 plogp loss——变量名如此，严格说是 p·log q（KL 与 CE 只差一个不依赖 q 的常数项 H(p)）。
    44	
    45	KL 是一个非常合理的训练目标——它和 α 共享全局最优解：当 `q ≡ p` 时 KL 取最小值 0，同时 `α = 1`。**问题在 "共享全局最优" 这件事其实没什么用**：小 draft 模型的容量远不足以让 `q = p`，训练过程必然停在某个局部最优，而 KL 的局部最优和 α 的局部最优**并不是同一个点**。
    46	
    47	---
    48	
    49	## 03 一个会被反复忽略的恒等式
    50	
    51	LK Losses（Samarin et al., arXiv:2602.23881, 2026.02）的出发点是一个早已存在但很少被用于训练的恒等式（最早见于 Leviathan et al., 2023）：
    52	
    53	```
    54	α(p, q) = 1 − TV(p, q)
    55	```
    56	
    57	其中 `TV(p, q) = (1/2) · Σ_x |p(x) − q(x)|` 是 total variation distance。证明只用一行代数：
    58	
    59	```
    60	Σ_x min(p, q) = Σ_x [p − (p − q)_+] = 1 − Σ_x (p − q)_+ = 1 − TV(p, q)
    61	```
    62	
    63	这条恒等式说明：**最大化 acceptance rate 等价于最小化 TV distance**。TV 连续、凸，计算只涉及绝对值求和，不含 log 或除法，数值上比 KL 稳定。直接把 KL 换成 TV 作为训练 loss：
    64	
    65	```
    66	L = TV(p, q)
    67	```
    68	
    69	论文的对比实验里有一个非常直观的例子：用一个 2 个参数（均值 μ、标准差 σ）的单高斯 draft 去拟合 mixture-of-Gaussian target。KL 优化收敛后接受率 50.2%，TV 优化收敛后接受率 60.2%——同样的模型容量，仅仅换 loss 函数就拿到 +10pp 接受率。
    70	
    71	---
    72	
    73	## 04 LK^λ：自适应混合
    74	
    75	只用 TV 在工程上有个小问题——训练早期 `q` 与 `p` 几乎不重叠时，TV 接近上界 1，梯度信号弱且 "扁平"。KL 在分布差异大时反而能给出更密集的梯度（penalty 随对数发散）。
    76	
    77	论文给的折中是一个自适应混合（LK^λ）：
    78	
    79	```
    80	L_LK^λ = λ · KL(p ‖ q) + (1 − λ) · TV(p, q)
    81	λ = exp(−η · sg[α])
    82	```
    83	
    84	`sg` 是 stop-gradient——λ 本身不参与反传。直观地：
    85	
    86	- 训练初期 α ≈ 0，λ ≈ 1，loss 退化为 KL，提供密集梯度做 warm-up
    87	- 训练后期 α 上升，λ → 0，loss 平滑过渡到 TV，直接对齐接受率
    88	
    89	整条切换由 α 自身控制，没有需要手调的 schedule。
    90	
    91	---
    92	
    93	## 05 落地观察
    94

    98	
    99	对我们来说，收获不只是一个 loss 函数：**当发现标准做法和真正想优化的指标之间隔了一层代理，先检查这层代理是不是必要的**。这次，绕过代理只需要一行代数。

    59	```
    60	Σ_x min(p, q) = Σ_x [p − (p − q)_+] = 1 − Σ_x (p − q)_+ = 1 − TV(p, q)
    61	```
    62	
    63	这条恒等式说明：**最大化 acceptance rate 等价于最小化 TV distance**。TV 连续、凸，计算只涉及绝对值求和，不含 log 或除法，数值上比 KL 稳定。直接把 KL 换成 TV 作为训练 loss：
    64	
    65	```
    66	L = TV(p, q)
    67	```
    68	
    69	论文里有个 toy problem：用一个 2 个参数（均值 μ、标准差 σ）的单高斯 draft 去拟合 mixture-of-Gaussian target。KL 优化收敛后接受率 50.2%，TV 优化收敛后接受率 60.2%——同样的模型容量，仅仅换 loss 函数就拿到 +10pp 接受率。
    70	
    71	---
    72	
    73	## 04 LK^λ：自适应混合
    74	
    75	只用 TV 在工程上有个小问题——训练早期 `q` 与 `p` 几乎不重叠时，TV 接近上界 1，梯度信号弱且 "扁平"。KL 在分布差异大时反而能给出更密集的梯度（penalty 随对数发散）。
    76	
    77	论文给的折中是一个自适应混合（LK^λ）：
    78	
    79	```
    80	L_LK^λ = λ · KL(p ‖ q) + (1 − λ) · TV(p, q)
    81	λ = exp(−η · sg[α])
    82	```
    83	
    84	`sg` 是 stop-gradient——λ 本身不参与反传。直观地：
    85	
    86	- 训练初期 α ≈ 0，λ ≈ 1，loss 退化为 KL，提供密集梯度做 warm-up
    87	- 训练后期 α 上升，λ → 0，loss 平滑过渡到 TV，直接对齐接受率
    88	
    89	整条切换由 α 自身控制，没有需要手调的 schedule。
    90	
    91	---
    92	
    93	## 05 落地观察
    94	
    95	LK^λ 在工程上几乎是零成本切换——计算复杂度与 KL 同阶，不引入额外 forward / backward。SpecForge（SGLang 官方 EAGLE 训练框架）的 PR #492 有现成的实现。我们在 MiniCPM-SALA 的 EAGLE draft 训练中把 loss 从 plogp 换成 LK^λ，acceptance length 确实有提升，趋势和论文一致。
    96	
    97	但 **LK^λ 不是"魔法"**。论文 ablation 里给出的提升幅度（接受长度 +4~10%，覆盖 4 种 draft 架构、6 个 target、8B~685B 参数规模）是稳定但一致的改进。
    98	
    99	回头看，training loss 和真正关心的 metric 之间隔着 KL 这层代理，大家用了很久也没觉得有问题——直到有人把那行代数写出来。
