**1. 当前 Kernel 路径**
- 普通 prefill / extend：Lightning 层先在 `MiniCPMLightningMixer.forward` 做 qkv、q/k norm、RoPE；生产默认开 OOP fused qk_norm+RoPE，一个 Triton kernel 输出 contiguous q/k/v，见 [minicpm.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/models/minicpm.py:997) 和默认 env [prepare_env.sh](/user_4813494d/openbmb/demo-sala/prepare_env.sh:524)。GLA core：`seq_len < 64` 走 FLA `fused_recurrent_simple_gla`，长 prefill 走 FLA `chunk_simple_gla`，见 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:2384)。
- decode：有效代码开关是 `SGLANG_SIMPLE_GLA_DIRECT_DECODE_BK64`，默认 `"1"`，见 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:48)。满足 CUDA、K=V=128、state fp32 时走自定义 `simple_gla_decode_update_bk64_2k_fwd`，直接读写 recurrent state，见 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:2284) 和 [simple_gla_decode_kernel.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/simple_gla_decode_kernel.py:546)。不满足时 fallback 到 FLA `fused_recurrent_simple_gla`，见 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:2401)。
- target_verify：Lightning/GLA 不走 standard attention backend，而走自定义 `_fused_recurrent_gla_intermediate_kernel`，一次处理每个 request 的 `draft_token_num`，并写每步 intermediate state 供 rollback/accept，见 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:76) 和调用点 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:2320)。standard attention 层的 TARGET_VERIFY 仍走 FlashInfer prefill wrapper `causal=True`，见 [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:2211)。

**2. SimpleGLA 数学 / Shape / Dtype / State**
- 生产模型：32 层里 24 个 `lightning-attn`，8 个 `minicpm4`；Lightning 配置 `lightning_nh=32`、`lightning_nkv=32`、`lightning_head_dim=128`、`lightning_scale=1/sqrt(d)`，见模型 config [config.json](/user_4813494d/models/openbmb/MiniCPM-SALA-gptq46-calib90-90k-NVFP4-det/config.json:28) 和层表 [config.json](/user_4813494d/models/openbmb/MiniCPM-SALA-gptq46-calib90-90k-NVFP4-det/config.json:34)。
- q/k/v shape：`qkv_proj` 后 split 成 q/k/v，各自 reshape 为 `(1, T, num_heads, head_dim)`；生产 TP=1 时是 `(1,T,32,128)`，见 [minicpm.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/models/minicpm.py:922) 和 [minicpm.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/models/minicpm.py:1059)。
- 核心递推：每 head 的 state 是 `H_t[K,V]`。kernel 里是 `H_t = exp(g_gamma[h]) * H_parent + k_t[:,None] * v_t[None,:]`，`o_t = sum_K(H_t * (q_t * scale)[:,None])`，见 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:168)。普通 decode/prefill 的 parent 是上一 token；target_verify tree 会按 `retrieve_parent_token` 取 parent state，见 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:143)。
- dtype 约束：q/k/v 是 bf16，`g_gamma` 是 fp32，recurrent state 必须 fp32；direct decode 显式拒绝非 fp32 state，见 [simple_gla_decode_kernel.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/simple_gla_decode_kernel.py:560)。state cache 默认 dtype 来自 `--mamba-ssm-dtype=float32`，见 [server_args.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/server_args.py:487)。SimpleGLA cache shape 是 `(num_heads/tp, head_dim, state_size)`，见 [mamba_utils.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/configs/mamba_utils.py:147)。

**3. 已失败 / 无收益的 GLA 优化**
- `chunk_simple_gla` 替换：`chunk_size=128` 更快但 `output max_diff=0.25`；`fused_chunk_simple_gla` 更慢且不一致，见 [docs/prefill/current.md](/user_4813494d/openbmb/docs/prefill/current.md:355)。
- GLA prefill kernel 重写方向：Triton warp_specialize/Gluon 在 sm_120 编译崩；FlashKDA/CUTLASS GLA 只适合 sm_90a，见 [docs/prefill/history.md](/user_4813494d/openbmb/docs/prefill/history.md:192)。
- `FLA_USE_FAST_OPS=1` / `tl.exp2`：sm_120 上比 `tl.exp` 慢 83%，见 [docs/prefill/history.md](/user_4813494d/openbmb/docs/prefill/history.md:188)。
- decode/verify 小优化未保留：GLA `o_buf.sum(0).to(bf16)`、sum+cast contiguous 初版、state copy block/warps sweep、parent index scalar load、BK64_2K direct output，都因 strided graph view、带宽受限、噪声级或 E2E 无收益被否决，见 [docs/decode/history.md](/user_4813494d/openbmb/docs/decode/history.md:302)。
- direct decode 8/16 warps：改变 `tl.sum` 归约顺序，out 不 bit-exact 且更慢，见 [docs/decode/history.md](/user_4813494d/openbmb/docs/decode/history.md:310)。

**4. Training-free 等价替换的验证门槛**
- kernel / metadata / state copy 必须先离线 bit-exact 或明确等价；固定 shape、seed、dtype 对拍输出，见 [verify/SOP.md](/user_4813494d/openbmb/verify/SOP.md:30) 和 [verify/SOP.md](/user_4813494d/openbmb/verify/SOP.md:41)。
- GLA target_verify 还必须覆盖 CUDA graph strided buffer view 和 padded replay；现有回归测了 sliced graph view / padded q，见 [tests/test_fused_gla_cuda_graph.py](/user_4813494d/openbmb/tests/test_fused_gla_cuda_graph.py:117)。
- tree verify 必须验证 sibling/parent state 语义，不能按线性链污染；现有测试构造 user_4813494d/children/grandchildren 对拍，见 [tests/test_simple_gla_tree_verify.py](/user_4813494d/openbmb/tests/test_simple_gla_tree_verify.py:34)。
- 上线前必须真实 server smoke + bench：completion tokens 不变、输出正常文本、D5/D7 不大退，见 [verify/SOP.md](/user_4813494d/openbmb/verify/SOP.md:54) 和 [verify/SOP.md](/user_4813494d/openbmb/verify/SOP.md:70)。
- Spec 改动不能只看 tok/s；必须对比 no-spec/spec 答案一致性或公开集分数，并连同 `ori_accuracy` 看，见 [AGENTS.md](/user_4813494d/openbmb/AGENTS.md:180) 和 [AGENTS.md](/user_4813494d/openbmb/AGENTS.md:198)。
