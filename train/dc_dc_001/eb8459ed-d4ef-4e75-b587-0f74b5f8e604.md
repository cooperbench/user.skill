# Phase1 代码库总结

## 1. `runtime/carla/executor.py`

**用途**：主执行器，负责单次 Phase1 仿真的完整流程。

**主要函数**：
- `run_phase1(config: Phase1Config) -> dict`：连接 CARLA、选路、挂载传感器、初始化 EKF、主循环、记录与清理
- `configure_logging(level)`：配置日志级别

**数据流**：
1. 连接 CARLA → 选路 → 挂载 GNSS/IMU/碰撞/车道入侵传感器
2. 用首帧 GNSS/IMU 初始化 `LocalENUConverter` 和 `ExtendedKalmanFilter`
3. 主循环：`world.tick()` → 取 GNSS/IMU → 转换 → EKF predict/update → 选控制状态（truth/ekf）→ 控制器 step → 应用控制 → 记录
4. 到达或碰撞时生成 summary 并写入输出目录

**控制器模式**：
- `stanley`：Stanley 横向 + PID 纵向，用 `RouteTracker`
- `pid_waypoint`：WaypointPID + PID 纵向，用 `WaypointPlan`
- `official_pid`：CARLA 官方 LocalPlanner，同时运行 shadow `WaypointPID` 做对比

**状态来源**（`state_source`）：
- `truth`：真值（`build_vehicle_state`）
- `ekf`：EKF 估计（`ekf.get_state()`）

---

## 2. `runtime/carla/session.py`

**用途**：CARLA 会话与仿真环境管理。

**主要函数**：
- `build_output_dir(config)`：按时间戳建输出目录
- `connect_world(client, config)`：连接并加载指定 town
- `persist_run_config(output_dir, config)`：保存 `config.json`
- `enable_sync_mode(client, world, config)`：开启同步模式、固定 dt、天气、随机种子
- `cleanup_world(...)`：恢复设置并销毁所有 actor

---

## 3. `runtime/carla/sensors.py`

**用途**：挂载并管理 CARLA 传感器。

**主要类**：
- `FrameSensorQueue`：按 frame 同步取传感器数据，`callback` 接收数据，`get(expected_frame, timeout)` 阻塞直到匹配
- `EventTracker`：记录碰撞/车道入侵事件，`on_collision`、`on_lane_invasion` 写入 `EventRecord`

**主要函数**：
- `zero_sensor_noise(blueprint)`：将 GNSS/IMU 噪声参数设为 0
- `attach_sensor_suite(world, vehicle, config)`：挂载 GNSS、IMU、碰撞、车道入侵传感器，返回 `(sensor_actors, gnss_queue, imu_queue, collision_tracker, lane_tracker)`

**GNSS/IMU 处理**：传感器噪声被置零，数据通过 queue 按 frame 同步，由 `conversion.py` 做坐标和物理量转换。

---

## 4. `runtime/carla/bootstrap.py`

**用途**：Carla Python API 路径初始化。

**常量**：`PROJECT_ROOT`（项目根目录）

**函数**：`bootstrap_carla_python(project_root)`：将 `carla-0.9.15/PythonAPI/carla` 加入 `sys.path`，以便导入 `agents.navigation` 等模块。

---

## 5. `runtime/carla/routing.py`

**用途**：路线规划、官方 LocalPlanner 构建、车辆参数估计。

**主要函数**：
- `estimate_vehicle_max_steer(vehicle, fallback)`：从车辆物理获取前轮最大转向角
- `choose_route(spawn_points, planner, ...)`：按 seed 选起点/终点，用 `GlobalRoutePlanner.trace_route` 规划，按 `route_len + 40*heading_change` 打分，优先满足 `route_min_length_m` 和 `route_min_heading_change_rad`
- `write_route_csv(path_points, output_dir)`：写 `route.csv`
- `build_official_local_planner(vehicle, world_map, route_trace, config)`：创建 CARLA `LocalPlanner`，使用 `waypoint_pid` 和 `pid` 的 Kp/Ki/Kd 等参数

---

## 6. `runtime/carla/conversion.py`

**用途**：CARLA 原始数据与领域模型的转换。

**主要函数**：
- `build_vehicle_state(vehicle, ref_location)`：用 `world_to_local_xy` 和 `carla_heading_to_local_yaw` 得到局部 `VehicleState`
- `gnss_measurement_from_carla(data, converter, heading, sensor_offset_x)`：经纬度 → 局部 ENU (x,y)，并补偿 GNSS 相对车辆中心的 x 偏移
- `imu_measurement_from_carla(data)`：罗盘 → heading，陀螺仪 z → yaw_rate，加速度 x → longitudinal_accel
- `build_local_route(route_trace, ref_location, target_speed)`：waypoint 转局部 PathPoint，去重（<0.25m），调用 `build_path_from_xyy`

---

## 7. `domain/localization.py`

**用途**：EKF 定位实现。

**类**：`ExtendedKalmanFilter`

**状态**：`[x, y, yaw, speed]`（4 维）

**主要方法**：
- `initialize(x, y, yaw, speed)`：设置初始状态
- `predict(yaw_rate, longitudinal_accel, dt)`：运动模型预测  
  - `x' = x + speed*cos(yaw)*dt`  
  - `y' = y + speed*sin(yaw)*dt`  
  - `yaw' = yaw + yaw_rate*dt`  
  - `speed' = speed + accel*dt`（限制在 0~40 m/s）  
  使用雅可比矩阵更新协方差，并加 process_noise 和 control_noise
- `update_position(meas_x, meas_y, measured_speed)`：GNSS 位置更新，观测矩阵 H 为 `[1,0,0,0; 0,1,0,0]`，yaw 保持预测值，speed 用 0.7×预测 + 0.3×测量融合
- `get_state()`：返回 `VehicleState`

**常量**：`MAX_SPEED_MPS = 40.0`

**配置**：`EKFConfig` 提供 process_noise、measurement_noise、initial_covariance 等。

---

## 8. `domain/control.py`

**用途**：纵向/横向控制器及组合。

**控制器**：
- `PIDLongitudinalController`：PID 速度控制，`step(target_speed, current_speed, dt)` → (throttle, brake)
- `StanleyLateralController`：Stanley 横向控制，`step(state, tracker)` → (steer_angle, tracking)
- `VehicleController`：Stanley + PID 纵向，使用 `RouteTracker`
- `EstimatedPIDLateralController`：基于 heading_error 的 PID 横向，带 steer_rate_limit
- `WaypointPIDVehicleController`：EstimatedPID 横向 + PID 纵向，使用 `WaypointPlan`

**控制器模式对应**：
- `official_pid`：CARLA LocalPlanner，内部用 truth
- `pid_waypoint` + `truth`：`WaypointPIDVehicleController` + `build_vehicle_state`
- `pid_waypoint` + `ekf`：`WaypointPIDVehicleController` + `ekf.get_state()`

---

## 9. `domain/pathing.py`

**用途**：路径表示与跟踪。

**类**：
- `RouteTracker`：沿路径找最近点，计算 CTE、heading_error、progress
- `WaypointPlan`：按 `base_min_distance_m + distance_ratio*speed` 推进目标点，`target(state)` 返回当前目标 `TrackingResult`

**函数**：`path_length`、`total_heading_change`、`build_path_from_xyy`

---

## 10. `domain/geo.py`

**用途**：坐标与角度转换。

**类**：`LocalENUConverter`：经纬度 → 局部 ENU (x_east, y_north)

**函数**：
- `carla_heading_to_local_yaw(carla_yaw_deg)`：Carla 航向 → 局部 yaw
- `compass_to_local_yaw(compass_rad)`：罗盘 → 局部 yaw
- `world_to_local_xy(world_x, world_y, ref_x, ref_y)`：世界坐标 → 局部 xy

**常量**：`EARTH_RADIUS_M` 在 `math_utils.py` 中定义。

---

- `StanleyConfig`、`WaypointPIDConfig`、`PIDConfig`：控制器参数
- `LoggingConfig`：output_root、save_csv、save_summary_json
- `Phase1Config`：汇总上述配置，含 `controller_mode`、`state_source`

# 架构与数据流概览

```
app/single_run.py / app/benchmark_run.py
        ↓
experiment/presets.py, scenarios.py, benchmark_suite.py
        ↓
runtime/carla/executor.py (run_phase1)
        ↓
session.py (connect, sync, cleanup) | routing.py (route) | sensors.py (GNSS/IMU)
        ↓
conversion.py (carla → domain types)
        ↓
domain/localization.py (EKF) ← domain/geo.py (ENU)
domain/control.py (controllers) ← domain/pathing.py (RouteTracker, WaypointPlan)
        ↓
report/recorder.py (trajectory, summary)
```

**EKF 流程**：GNSS/IMU → `gnss_measurement_from_carla` / `imu_measurement_from_carla` → `ekf.predict(yaw_rate, accel, dt)` → `ekf.update_position(x, y, gnss_speed)` → `ekf.get_state()` 供控制器使用。

**控制器模式**：
- `official_pid`：CARLA LocalPlanner，内部 truth，同时跑 shadow WaypointPID 做对比
- `pid_waypoint` + `truth`：WaypointPID + 真值状态
- `pid_waypoint` + `ekf`：WaypointPID + EKF 状态

**Benchmark 对比**：同一 route 下跑 official_truth、ours_truth、ours_ekf，比较 completed、tracking_error、progress、localization_error 等指标。
