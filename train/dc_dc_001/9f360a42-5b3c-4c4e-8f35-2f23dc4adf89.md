# Phase 2 / Phase 3 代码库总结

## 1. `src/graduate_phase1/attack/injector.py`

**路径:** `/home/[REDACTED]fromhust/Downloads/graduate/src/graduate_phase1/attack/injector.py`

**主要类/函数:**
- **`AttackInjector`**：攻击注入器
  - `__init__(self, config: AttackConfig)`
  - `apply(gnss, imu, elapsed_seconds) -> tuple[GnssMeasurement, ImuMeasurement, AttackTrace]`
  - `_is_active(elapsed_seconds) -> bool`
  - `_empty_trace() -> AttackTrace`

**逻辑概要:**
- 根据 `elapsed_seconds` 与 `t_start`、`duration` 判断是否处于攻击窗口
- 在攻击窗口内，按 `config.type` 修改 GNSS 和 IMU 测量
- 返回被篡改的 GNSS、IMU 以及 `AttackTrace`

## 2. `src/graduate_phase1/attack/guard.py`

**路径:** `/home/[REDACTED]fromhust/Downloads/graduate/src/graduate_phase1/attack/guard.py`

**主要类/函数:**
- **`SimpleAttackGuard`**：简单攻击守卫
  - `__init__(self, config: GuardConfig)`
  - `evaluate(innovation_statistic, predicted_speed, gnss_speed) -> GuardTrace`

**逻辑概要:**
- 基于 EKF 位置新息统计量 `innovation_statistic` 与 `innovation_gate_threshold` 比较
- 基于预测速度与 GNSS 速度残差 `speed_residual` 与 `speed_consistency_threshold_mps` 比较
- 任一超阈值则触发，并设置 `target_speed_scale = slowdown_factor`（默认 0.5）用于减速

## 实验配置与运行方式

**配置结构:**
- `AttackScenario`: 场景（town, seed, spawn_index, destination_index, target_speed_mps, max_steps）
- `AttackLocalizationVariant`: 定位模式（ekf / ekf_guarded / gnss_direct）及是否启用 guard
- `AttackConfig`: 攻击类型与参数
- `AttackExperimentPreset`: 组合 scenarios、variants、attacks

**运行流程:**
1. `run_attack_experiments(preset)` 遍历所有组合
2. 对每个组合调用 `run_phase1(build_attack_run_config(...))`
3. 单次运行由 `executor.run_phase1` 完成：连接 CARLA、选路、挂载传感器、主循环中注入攻击并记录
