**定位结果**

SpecForge PR #492 的真实实现：

- `specforge/core/lk_loss.py`
  - `expected_acceptance_rate`: `alpha_i = sum_x min(p_i(x), q_i(x))`
  - `compute_acceptance_rate`: 先算 token-wise alpha，再 mask mean；`log_acceptance_rate` 是 `mean(log(alpha_i))`
  - `compute_lk_loss`
    - `alpha`: `-log_acceptance_rate`
    - `lambda`: `w * KL + (1 - w) * (1 - acceptance_rate)`，其中 `w = kl_scale * exp(-kl_decay * acceptance_rate.detach())`
    - 这里没有 `eta` 参数，CLI 默认 `kl_scale=1.0`、`kl_decay=3.0`
  - URL: https://github.com/sgl-project/SpecForge/blob/4385d78a6366b766f3278b1c3674e1021c14c02a/specforge/core/lk_loss.py#L7-L99

- `specforge/core/eagle3.py`
  - KL 用 `target_p = softmax(full_logits[..., t2d])`，即 draft vocab 上重归一化。
  - acceptance 用 `target_p_on_draft = exp(draft_target_head - logsumexp(full_target_logits))`，即保留 full-vocab 概率质量，draft 外质量不会被重归一化掉。
  - loss mask 还会过滤 full-vocab argmax 不在 draft vocab 的位置。
  - URL: https://github.com/sgl-project/SpecForge/blob/4385d78a6366b766f3278b1c3674e1021c14c02a/specforge/core/eagle3.py#L41-L91  
  - target-p 处理: https://github.com/sgl-project/SpecForge/blob/4385d78a6366b766f3278b1c3674e1021c14c02a/specforge/core/eagle3.py#L727-L741

TorchSpec PR #29 的实现更接近你现在写的公式：

- `compiled_lk_lambda_loss`: `lambda_i = exp(-eta * alpha_i.detach())`，逐 token；`loss = mean(lambda_i * KL_i + (1-lambda_i) * TV_i)`，默认 `lk_eta=3.0`
- URL: https://github.com/lightseekorg/TorchSpec/blob/3823230f345bf4ee2dfebed1b147fc9a149bb500/torchspec/models/ops/loss.py#L102-L141
- vocab pruning 下它只算 `softmax(target_hidden @ lm_head[t2d])`，没有 SpecForge 那个 `target_p_on_draft/full logsumexp` 路径。
- URL: https://github.com/lightseekorg/TorchSpec/blob/3823230f345bf4ee2dfebed1b147fc9a149bb500/torchspec/models/eagle3.py#L266-L296

**和当前实现的差异**

当前 [train_v4.py](/user_4813494d/openbmb/eagle/train_v4/train_v4.py:126) 的 `lk_lambda_loss`：

- 公式基本等于 TorchSpec PR 的 LK^lambda：`KL + TV`、逐 token `alpha`、逐 token `lambda`。
- 但 `eta=5.0`，TorchSpec 默认是 `3.0`。
- 它不等价于 SpecForge PR #492 的 lambda 版；SpecForge lambda 是 `KL + (1-alpha)` 聚合版，参数叫 `kl_decay`，不是逐 token `TV` 版。

当前 [train.py](/user_4813494d/openbmb/eagle/train.py:383) 的 `_build_target_p`：

- 只用采集来的 top-256 logits scatter 到 draft vocab，然后 softmax。
- 这比 SpecForge/TorchSpec 都更近似：缺少 full draft vocab logits，也缺少 full-vocab `logsumexp`。
- 后果是 draft vocab 内非 top-256 token 被当成 0 概率，target 分布会偏尖；也无法像 SpecForge 那样让 alpha 感知 draft vocab 外的概率质量。

TTT loss decay：

- SpecForge 和 TorchSpec 都是多 TTT step loss 用 `0.8**i` 加权。
- 当前 [train_v4.py](/user_4813494d/openbmb/eagle/train_v4/train_v4.py:275) 也是 `self.loss_decay ** i`，默认 `0.8`，但 `TTT_STEPS=3`；SpecForge/TorchSpec 默认多见 `ttt_length=7`。

结论：当前 `lk_lambda_loss` 公式对齐的是 TorchSpec PR 的 LK^lambda，不是 SpecForge PR #492 的 lambda 实现；最大真实偏差在 `_build_target_p`，它的 top-256 scatter 近似没有实现 SpecForge 的 full-logits vocab truncation/acceptance 处理。
