**最小 fusion 修改点**

如果目标是“对当前 stage1 P 语义做 exact blockmax”，最小动点：

1. 在 [flash_fwd_kernel.h](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/csrc/flash_attn/src/flash_fwd_kernel.h:53) 旁边新增/替换一个 helper，比如 `hdim16_reduce_blockmax`。
2. 逻辑必须先保留 `hdim16_reduce` 的 16-Q-row sum aggregation，再对本 `kBlockN=64` columns 做 max，最后只写 1 个值。
3. 把两个调用点 [1664](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/csrc/flash_attn/src/flash_fwd_kernel.h:1664)、[1732](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/csrc/flash_attn/src/flash_fwd_kernel.h:1732) 从 `hdim16_reduce` 换成 blockmax helper。
4. 若只返回 blockmax，不返回 full P，则 [flash_api.cpp:960](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/csrc/flash_attn/flash_api.cpp:960) 的输出 shape 要从 `{num_heads_k, total_q/16, seqlen_k_rounded}` 改成 `{num_heads_k, total_q/16, ceil_div(seqlen_k_rounded, 64)}`，并相应把 `row_offset_p` 的 K offset 从 `+ (n_block_max - 1) * 64` 改成 `+ (n_block_max - 1)`。
5. 若还要保留 full P，则需要在 [flash.h:56](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/csrc/flash_attn/src/flash.h:56) 增加第二个 output pointer，API 多分配一个 blockmax tensor；这不是最小改法。

能不能同 kernel 内直接按 64-token block 做 max reduce：可以，前提是你的“64-token block”就是当前 stage1 K tile 的 `kBlockN=64` columns。因为 `softmax_rescale_gt` 后同一个 CTA 已经持有 `16 x 64` 的最终 normalized `acc_s`，没有跨 CTA 依赖。

但如果要严格复用现有 `max_pooling_1d_varlen` 的语义，它不是简单 64 列一组：Python wrapper 里 `block_size=64, stride=16` 会变成 C kernel 的 `stride=4, kernel_size=5, padding=1`，见 [max_pooling_1d.py](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/infllm_v2/max_pooling_1d.py:97) 和 [max_pooling_1d.cuh](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/csrc/max_pooling_1d.cuh:88)。这种 exact fusion 需要处理 tile 边界相邻列，不能只把当前 `kBlockN=64` tile reduce 成一个值。

**Tensor Shape**

离线 capture 已经存在：`SGLANG_MINICPM_STAGE1_CAPTURE_DIR=...` 会在 [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:86) 保存：

- `query_layer`: `[total_q, Hq, D]`
- `compressed_k1`: `[total_k1, Hkv, D]`
- `compressed_k2`: `[total_k2, Hkv, D]`
- `cu_seqlens_q`: `[B+1]`
- `cu_seqlens_k1`: `[B+1]`
- `cu_seqlens_k2`: `[B+1]`
- `cache_lens`: `[B]`
- `exact_topk_idx`: `[Hkv, total_q, sparse_topk]`

当前 `Hq = Hkv * groups`，MiniCPM 这里通常 `Hkv=2, groups=16`。stage1 wrapper 会把 Q reshape 成 `[total_q * groups, Hkv, D]`，见 [infllmv2_sparse_attention.py](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/infllm_v2/infllmv2_sparse_attention.py:556)。

**Block 映射**

K1 block score 的真实池化不是简单 64-token hard block。当前 `max_pooling_1d_varlen()` 里：

- `block_size=64`
- 传入 `stride=kernel_stride=16`
- wrapper 转成 `pooled_stride = block_size // stride = 4`
- `kernel_size = pooled_stride + 1 = 5`
- `padding = 1`

对应每个 64-token block `b`，从 K1 score 取：

```text
k1_index_range(b) = [max(0, 4*b - 1), min(k1_len, 4*b + 4))
```

代码位置：
- Python 参数转换：[max_pooling_1d.py](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/infllm_v2/max_pooling_1d.py:97)
- CUDA pool 实现：[max_pooling_1d.cuh](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/csrc/max_pooling_1d.cuh:88)

K2 每个 compressed token `c` 覆盖原始 token `[64*c, 64*c+127]`，所以天然对应两个 64 blocks：

```text
k2 c -> k1/block candidates {c, c+1}
target block b -> possible covering k2 {b-1, b}
```

候选扩展建议：

```text
expand(c, radius=r) = [c-r, c+1+r] clipped to [0, num_blocks)
```

**需要排除或单独报告**

init/local blocks 不是由 score 竞争出来的。pooling 直接把它们设成 `+inf`：

- [max_pooling_1d.cuh](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/csrc/max_pooling_1d.cuh:81)
- fused topk 同样设 `+inf`，见 [minicpm_fuse_kernel.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_fuse_kernel.py:321)

对每个 query token：

```text
off_bq = (q_local + cache_len[b]) // block_size
forced_init = blocks where block < init_blocks
forced_local = blocks where off_bq >= block and off_bq <= block + local_blocks
             = [off_bq - local_blocks, off_bq]
```

离线 recall 必须报告三项：

- `recall_all`: 包含 forced blocks
- `recall_nonforced`: 从 exact 和 candidate 两边都排除 init/local 后算
- `forced_hit_count`: exact topk 里有多少是 init/local

否则 K2 候选会被 init/local 的 `+inf` 污染。

**离线验证方案**

使用 capture 文件，做三套结果：

1. Ground truth：
   - 直接用 `exact_topk_idx`。
   - 或重算 full K1：`_infllmv2_attn_stage1(q, k1, k2, ...) -> max_pooling_1d_varlen -> topk`，对应 [compressed_attention()](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_sparse_utils.py:810)。

2. K2 coarse score：
   - 对每个 batch，计算 `q @ compressed_k2.T / sqrt(D)`。
   - reshape Q 为 `[Hkv, groups, q_len, D]`，K2 为 `[Hkv, k2_len, D]`。
   - 对 group 做 softmax 后 sum，得到 `[Hkv, q_len, k2_len]`。
   - K2 causal mask 要用 stage1 的 stride=64 语义，不要用普通 causal。参考 [mask.h](/user_4813494d/openbmb/kernels/infllmv2_cuda_impl/csrc/flash_attn/src/mask.h:273)。

3. Candidate -> K1 rerank：
   - `topk2 = torch.topk(k2_score, k2_budget)`
   - 展开成 K1 block candidate：`[c-r, c+1+r]`
   - union forced init/local blocks
   - 用 full K1 `block_score` 只在 candidate 上保留，其余置 `-inf`
   - topk 后和 exact topk 比 recall

**Sweep 建议**

固定 final `K = sparse_topk`，但报告非 forced 的有效 K。

Sweep：

```text
k2_budget in {ceil(K/2), K, 2K, 3K, 4K, 6K, 8K}
radius in {0, 1, 2, 3, 4}
```

每组报告：

```text
avg_candidate_blocks
p50/p95 candidate_blocks
recall_all
recall_nonforced
recall_nonforced_by_layer
recall_nonforced_by_context_bin: 0-8k, 8-32k, 32-64k, 64k+
miss_distance_to_nearest_candidate
```

如果目标是最高收益，优先看 `radius=1/2 + k2_budget=2K/3K`，因为 K2 token 本身跨两个 64 blocks，额外 radius 很可能比单纯加 K2 topk 更稳。

**最容易踩错的点**

1. K2 当前在 kernel 里是 denominator pass，不是独立候选分数；离线 K2 scorer 必须明确定义，不要以为现有 `compressed_attention()` 已经输出 K2 topk。
2. K1 block 映射是 5 个 K1 compressed positions 的 max，不是 4 个，也不是硬 `[4b,4b+4)`。
3. init/local blocks 是 `+inf` 强制入选，要单独报告。
4. `self.sparse_topk = hf_config.sparse_topk + local_blocks`，见 [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:491)，不要把 config topk 和实际 topk 混用。
5. prefill chunk 时 `cache_lens = seq_lens_k - seq_lens_q`，见 [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:1324)。block index 必须用 `q_local + cache_len`。
6. stage1 output P shape 是 `[Hkv, total_q, k1_rounded]`，但 `total_q` 已经是原始 Q，不是 `Q*groups`，因为 C++ 按 `m_block_dim=16` 聚合回来了。
