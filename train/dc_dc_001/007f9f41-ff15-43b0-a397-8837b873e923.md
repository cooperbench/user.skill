已定位到 kernel。核心逻辑在 `sgl-kernel/csrc/speculative/speculative_sampling.cuh:80`： ```cuda prob_acc += target_prob_single; if (coin <= prob_acc / threshold_acc || target_prob_single >= threshold_single) { // accept token } ``` ## 两个参数的含义 这是 SGLang 对 **relaxed / typical speculative sampling** 的实现（lossy 版的 speculative decoding），在标准 Leviathan-2023 的 rejection sampling 上加了两条放宽通道： ### `--speculative-accept-threshold-single`（单 token 直通阈值） - 含义：**只要 target model 给这个 draft token 的概率 p ≥ threshold_single，就无条件接受**，跳过 rejection sampling - 默认 `1.0`：几乎永远不触发（等价关闭） - 设 `0.5`：target 觉得这个 token ≥ 50% 就直接采纳 - 对应 `target_prob_single >= threshold_single` 这一支 ### `--speculative-accept-threshold-acc`（累积概率放大阈值） - 含义：把标准的"接受概率 = min(1, p)"放宽成 **`min(1, p / threshold_acc)`**（help 字符串原文） - 在 kernel 里体现为 `coin ≤ prob_acc / threshold_acc`，其中 `prob_acc` 是当前 tree 分支上兄弟节点累积的 target 概率 - 默认 `1.0`：严格 rejection sampling（分布 = target，lossless） - 设 `0.5`：接受概率放大 2 倍，更多 draft token 被采纳 - `cuh:191` 有防 0：`capped_threshold_acc = fmaxf(threshold_acc, 1e-9f)` ## 合法范围 `server_args.py` CHECK：两者都必须在 `[0, 1]` 之间（`cuh:121-124`）。 ## 两个都 = 0.5 的效果 - **accept length / token/s 上升**（draft 更容易被收下） - **代价是输出分布偏离 target model**（lossy），在 greedy/低温 MCQ 场景影响小，在长文生成/高温采样场景可能出现质量退化 - 这是标准的"加速换质量" knob，常见于 typical acceptance / MCSD 一类工作 ## 对 SALA 场景 SALA 评测走 greedy（temp≈0），target_prob 分布高度尖锐，top-1 的 p 经常 > 0.5： - `threshold_single=0.5` 会让 greedy 下 draft 的匹配 token 几乎必被接受，略过浮点比较的边界； - `threshold_acc=0.5` 放大 coin 通道但 greedy 下本身 coin 分支很少触发。 所以 greedy 评测里这俩参数的边际收益有限，更多是给 sampling 场景用的。要验证实际影响建议 A/B：默认 `1.0/1.0` vs `0.5/0.5`，看 `accept_length` 和 MCQ 准确率有没有动。
