**2. 低并发 S1 可调项**
- 优先调 `2/2 -> 2/3`，即只增 topk：正式默认行已支持 env override，`dtn 5 -> 7`，主要观察 `Accept length` 是否增长超过额外 draft/verify 成本。
- `3/3` 不作为低并发首选，`dtn=10` 对 S1 容易放大 draft 与 target verify 固定开销，除非 `2/3` 的 accept length 明显不够。
- 对比 draft：正式 `demo-sala/data/eagle_draft` vs `eagle/sglang_model_v3`。v3 aux layer 与 quant exclude 都不同，不能把 `3/3` 提升误归因给 spec 参数。
- 低 batch decode 重点看 `SGLANG_MARLIN_DECODE_THRESHOLD`。正式当前未导出，实验入口默认 48；这是一个必须单独记录的 confounder。
- 小 M 下可 A/B `SGLANG_SIMPLE_GLA_DIRECT_DECODE=1/0` 和 `SGLANG_SIMPLE_GLA_DECODE_WARPS=4/8/16`，来源分别是 [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:1795) 与 [simple_gla_decode_kernel.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/simple_gla_decode_kernel.py:20)。
- `EAGLE_FORCE_NO_ACCEPT=1` 只用于短 profile，把 accept 归零看纯 spec overhead，来源 [eagle_info.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:409)。

**3. 高并发 S8/Smax 可调项**
- 优先仍是 `2/2`、`2/3`；`3/3` 只做研究对照。更大 `dtn` 会增加保留 token，逻辑在 [tokenizer_manager.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/managers/tokenizer_manager.py:241)：保留 `max(topk*steps, dtn)`，即 `2/2=5`、`2/3=7`、`3/3=10`。
- `max-running-requests=64` 与 Smax 默认 64 条完全对齐；不要先上调。可做 `48 vs 64`，看排队、token usage、OOM/empty response。
- `mem-fraction-static=0.75` 可在高并发长上下文下试 `0.75/0.80`；只在没有 OOM 且 token usage 接近上限时评估收益。
- `chunked-prefill-size=8192` 是正式默认；高并发长 prompt 可试 `4096/8192/16384`，但每组都要跑 accuracy，因为长上下文回归风险高。
- `SGLANG_MINICPM_PLAN_CACHE=1` 应保持默认；关掉只用于定位 plan cache 是否引入异常，来源 [minicpm_attention_kernels.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_attention_kernels.py:300)。
- `SGLANG_ENABLE_B12X` 正式默认开、实验入口默认关。高并发矩阵必须记录它；否则 `eval/start_eagle.sh` 的结果不能代表正式提交。
