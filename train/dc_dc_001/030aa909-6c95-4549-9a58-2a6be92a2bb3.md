508	
509	**Snakes and Ladders: Accelerating SSM Inference with Speculative Decoding**（arXiv:2402.00550, NeurIPS 2024 Workshop, UCLA + AWS AI）
510	
511	两种 SSM state backtracking 方法：
512	- **Activation Replay**：缓存 SSM block 的输入激活，回溯时只重跑 state update kernel 到最后验证通过的 token
513	- **Joint Attainment and Advancement**：在验证当前 draft 的同时前进一步，恢复到最后验证通过的 token 的 SSM state
514	
515	与 SpecMamba 的 Plan I/II 方案互补，但仅处理纯 SSM target。

523	**SGLang MambaRadixCache + Speculative Decoding**（PyTorch Blog "Hybrid Models Meet SGLang"）

525	已在 Qwen3-Next（Gated DeltaNet + Gated Attention 混合）上验证的关键设计：

560	### 13.4 Cactus 完整算法
561	
562	**Cactus**（arXiv:2604.04987, ICLR 2026 Poster）
563	
564	约束优化目标：最大化接受率，约束 KL(h || q) ≤ delta。
565	
566	最优解（Corollary 5，KL 散度 + 二阶 Taylor 近似）：
567	```
568	gamma* = min{q(n) + sqrt(2 * delta * q(n) * (1-q(n))), 1}
569	```
570	
571	q(n) 是 target model 对 draft token n 的概率。gamma* 给 draft token n 一个 "bonus probability"，bonus 最大值在 q(n)=0.5 时取得。
572	
573	delta 典型值：0.01~0.05。
574	
575	对 tree verify：理论上可以嵌入（每条边的 gamma* 不同），但论文未做 tree verify 实验。
576

579	### 13.5 MARS 完整算法
580	
581	**MARS**（arXiv:2601.15498, ICLR 2026）
582	
583	对每个 draft token v_t：
584	1. **Exact Match**：如果 v_t = target top-1，直接接受
585	2. **Adaptive Relaxation**：如果 v_t = target top-2 且 `r_t > theta`，接受（视为 tie）
586	3. **Rejection**：否则拒绝
587	
588	核心度量 **Logit Ratio**：`r_t = z_{(2)} / z_{(1)}`（top-2 logit / top-1 logit）
589	
590	theta **固定 0.9**，ablation 在 [0.85, 0.95] 稳定。
591	
592	实验数据：
593

597	| Llama-3.1-8B | 3.24x / tau=4.82 | **4.00x / tau=6.61** |

## MARS: Margin-Aware Speculative Verification

MARS is a training-free and plug-and-play verification strategy that adaptively adjusts acceptance rigor based on the target model's logit margin. Recent research advances from lossless verification to lossy SD, trading negligible quality degradation for significant latency reduction.

The key insight behind MARS is addressing inefficiency in standard speculative decoding. Strict exact-match verification incurs substantial overhead in low-margin regimes where the target model exhibits weak decisiveness. By accepting plausible runner-up draft tokens in low-margin regimes, MARS significantly reduces unnecessary rollbacks while preserving generation quality. The method achieves near-complete recovery across tasks and model scales (98.1–100%), with 100% recovery on HumanEval and 99.2–100% on MBPP.

## DIVERSED: Dynamic Ensemble Verification

Another recent approach is DIVERSED (arxiv 2604.07622). DIVERSED learns an ensemble-based verifier that blends the draft and target model distributions with a task-dependent and context-dependent weight. The rigid verification step strictly enforces the accepted token distribution to exactly match the target model, and this constraint leads to the rejection of many plausible tokens, lowering the acceptance rate and limiting overall time speedup.

Both approaches represent recent progress in relaxing verification criteria in speculative decoding to improve efficiency while maintaining quality.

## FLy: Training-Free Loosely Speculative Decoding

FLy was published on April 20, 2026, and is a novel method that loosens the rigid exact-match criterion without requiring any additional training.

### Key Technical Components

The method employs a sophisticated two-tier mechanism:

1. **Entropy Gate**: An entropy gate rejects deterministic target predictions where h < θ, deferring ambiguous mismatches. It identifies whether the current token allows multiple plausible alternatives (high entropy) or is nearly deterministic, such as in mathematical calculations (low entropy).

2. **Deferred Window Validation**: A token-level deferral window (W = 6) then monitors for continued divergence.

### How It Works

FLy judges whether a draft-target mismatch remains semantically valid by leveraging the target model's inherent self-corrective behavior. If the target model can continue generating from the mismatched token without further divergence, the first divergent token is likely semantically correct and can be accepted.

### Performance

## ARC-Decode: Risk-Bounded Acceptance Speculative Decoding

ARC-Decode (Acceptance with Risk Control) is a training-free method that augments speculative decoding and requires no extra forward passes.

### The Problem It Addresses

Speculative decoding accelerates generation by letting a fast draft process propose tokens that the target model verifies in parallel. Yet under sampling, observed speedups consistently lag behind those under greedy decoding because verification expends compute on low-value branches, and the classical lossless verification rule rejects drafts that would induce only negligible changes in the next-step conditional distribution. A key limitation under sampling is the over-rejection of low-risk drafts, which depresses acceptance rates and limits acceleration.

### How It Works

The method ensures relaxed acceptance while guaranteeing that accepting non–top-1 drafts causes only negligible next-step distributional shifts, as measured by Jensen–Shannon divergence. ARC-Decode combines confidence-based pre-verification filtering that preserves high-probability branches while enforcing prefix closure and leaf safety, and a risk-bounded acceptance criterion using an analytic upper bound on the next-step distribution shift from embedding and logit differences.

### Performance Results

ARC-Decode is a training-free method that accelerates speculative decoding under sampling via entropy-aware pruning and risk-bounded acceptance, increasing accept length to achieve up to 1.6× speedup with negligible quality degradation. Integrated into the state-of-the-art EAGLE-3 pipeline, ARC-Decode increases accept length per cycle and reduces verification compute, achieving up to 1.6× end-to-end speedup.

# Calibrated Speculative Decoding: Key Technical Details

## (1) Exact Acceptance Criterion

The semantic consistency gating formula operates in logit space:

```
log(p_i^(T=1)(x̃_i) / p_i^(T=1)(t*)) = z_i(x̃_i) - z_i(t*) ≥ log(τ)
```

This avoids redundant softmax computations and remains invariant to sampling temperature.

## (2) Module Roles

**Online Correction Memory (OCM):** "maintains a compact memory of frequent divergence pairs to propose alternative candidates during rejections." It uses a two-phase approach—prior calibration on unlabeled corpora, then dynamic online evolution during inference with frequency thresholds.

**Semantic Consistency Gating (SCG):** Validates proposed candidates through confidence-based acceptance, filtering low-confidence substitutions that risk hallucination or contextual inconsistency.

## (3) Probability Ratio Threshold Default

The paper sets **τ = 0.01** as the primary threshold in main evaluations (γ=6, λ=6). For semantic baseline comparisons (γ=15), this parameter remains consistent.

# FLy: Training-Free Loosely Speculative Decoding — Detailed Analysis

## (1) Full Algorithm Pseudocode

The complete algorithm appears in **Appendix A**. Core flow:

1. **Draft phase**: Drafter generates K tokens sequentially
2. **Verify phase**: Target model runs single forward pass on draft tokens, producing logits
3. **Mismatch detection**: Identify positions where draft ≠ target output
4. **Entropy gate** (lines 23–30): For each mismatch at position j, compute normalized entropy hⱼ. If hⱼ < θ (deterministic), reject tokens from j onward (strict mode). Otherwise, proceed to deferral.
5. **Deferred window** (lines 31–40): For deferred mismatches, count additional mismatches Mw in next W tokens (typically W=6). If Mw=0 and j+W≤K, accept the mismatch. Otherwise reject.
6. **Output**: Concatenate accepted tokens and continue until EOS.

---

## (2) Entropy Computation

Entropy is computed over the **full vocabulary** using the target model's output distribution at position j:

> "hⱼ = −∑ᵥ∈𝒱 p_ℳT,j(v) log p_ℳT,j(v) / log|𝒱|"

This is **normalized entropy** [0,1] derived from softmax logits already computed during verification. **No sampling**—uses the full distribution from the target's forward pass.

---

## (3) What "Defer" Means Concretely

The paper clarifies that deferral is **temporal acceptance without sequence modification yet**:

> "Within this window, the mismatch is provisionally accepted. If another mismatch emerges, it signals the model's attempt to _course-correct_ an earlier error, and the initial token is retroactively rejected."

The draft tokens are **held provisionally** during the W-token look-ahead. If no further mismatches occur within W positions, the earlier mismatch is deemed semantically valid and **permanently accepted**. If another mismatch appears, the initial mismatch is **retroactively rejected** (line 38–39: token at j is replaced with target's yⱼᵗ).

No rollback of already-generated sequences; the decision is made before appending to output.

---

## (4) Sampling vs. Greedy

The algorithm works identically for both sampling and greedy decoding. The entropy gate and deferred window operate on the **target model's logits directly**—not on sampling probabilities. 

The paper notes: "FLy introduces _no additional forward passes_. Instead, it computes per-token entropy directly from the already-available logits."

Greedy or sampling in the **drafter** (lines 4) doesn't affect verification; the target always uses argmax (Eq. 1) for verification decisions.

---

# Calibrated Speculative Decoding (CSD) — Detailed Analysis

## (1) Online Correction Memory (OCM) Algorithm

OCM maintains a frequency table **𝒯** tracking divergence pairs (x̃ᵢ, t*) where draft and target tokens differ but recur systematically.

**Two phases:**
- **Phase 1 (Prior Calibration):** Lightweight offline pass on unlabeled corpus collecting co-occurrence statistics between draft/target models, initializing 𝒯 without parameter updates
- **Phase 2 (Online Evolution):** During inference, dynamically increments frequency for verified divergence pairs; proposes rescue candidates only when 𝒯[(x̃ᵢ, t*)] ≥ λ

The paper states: "OCM maintains a compact memory of frequent divergence pairs to propose alternative candidates during rejections."

---

## (2) Semantic Consistency Gating (SCG) — Exact Formula

**Core equation:**
```
log(pᵢ^(T=1)(x̃ᵢ) / pᵢ^(T=1)(t*)) = zᵢ(x̃ᵢ) − zᵢ(t*) ≥ log τ
```

Where:
- **zᵢ(·)**: raw logits from target model
- **τ**: semantic gating threshold (default 0.01)
- **T=1**: evaluation at temperature 1 (greedy logits)
- **t***: optimal token from residual distribution

This "Zero-overhead" computation avoids redundant Softmax and is "invariant to sampling temperature."

---

## (3) False Rejection Recovery Workflow

**When rejection occurs:**

1. Draft token x̃ᵢ fails standard acceptance test (Eq. 2: α < rand)
2. System samples correction token t* from residual distribution p' = norm(max(0, p−q))
3. **Rescue attempt triggered:**
   - Check if (x̃ᵢ, t*) exists in memory with frequency ≥ λ
   - Verify probability ratio: zᵢ(x̃ᵢ) − zᵢ(t*) ≥ log τ
   - If both conditions pass → **accept x̃ᵢ as rescued token**; continue speculation
   - Else → return t* and halt speculation

**Example from paper:** Math formatting mismatch where draft proposes `$$` but target prefers `\[`—if this pair recurs (≥6 times) and confidence ratio ≥ 0.01, the draft `$$` is recovered instead of forcing regeneration.

---

## (4) τ = 0.01 Definition

**τ is a log-ratio threshold** comparing draft token confidence to target model's optimal token confidence. The paper specifies: "Semantic Consistency Gating instantiates the Probability-Guarded Acceptance principle by implementing a context-aware verification mechanism." 

At τ = 0.01, tokens with probability ratios ≥ 0.01 (roughly 1% relative confidence) are admitted. The paper notes this is "relatively lenient," allowing "benign lexical variations."

---

## (5) Comparison with MARS Algorithm

**Not mentioned in this paper.** The document does not reference MARS or compare against it algorithmically. CSD's closest comparisons are against:

CSD claims advantage through "dynamic historical priors + confidence gating" versus static thresholds or learned routers.

# KL-Judge: Key Technical Details

## (1) Theoretical Claim

**Theorem 4.1** establishes a "Structural Correspondence of KL and Linear Classifiers":

> "KL Divergence as Quadratic Aggregation: Under a second-order expansion, the KL divergence acts as a weighted quadratic sum of the primitives Δᵢⱼ(x). [Trained Classifier as Linear Partitioning: The linear classifier identifies critical tokens by defining a linear decision surface in the space of primitives Δᵢⱼ(x)."

The core insight: both KL-based thresholding and learned judges operate on identical logit-gap primitives Δᵢⱼ(x) := (zₜ(i) − zₜ(j)) − (zₐ(i) − zₐ(j)), just with different aggregation (quadratic vs. linear).

## (2) Acceptance Rule Direction

**Accept if D_KL(Pₜ || Pₐ) < threshold**

The rule is: "when the target model exhibits high certainty (top-1 probability exceeds 0.9), the system defaults to standard speculative sampling to ensure precision, reserving the KL-based relaxation specifically for tokens where the model faces genuine uncertainty."

Lower KL = higher confidence in draft token.

## (3) Per-Token vs Per-Block

**Per-token** basis. The paper measures token-level KL divergence and compares it against AutoJudge's per-token criticality scores (Figures 1, 6).

## (4) Benchmarks & Results

Tested on:
- **GSM8K** (math reasoning)
- **MATH-500-Hard** (harder math)
- **LiveCodeBench** (code generation)
- **MMLU-Pro** (broad knowledge)

Model pairs: Llama-3.2-1B/3.1-8B and Llama-3.1-8B/3.1-70B.

**Key result (Table 1, GSM8K, 1B/8B pair):**
- KL thresholding: 1.26× speedup, 81.07% accuracy (threshold=0.40)
- AutoJudge: 1.23× speedup, 81.07% accuracy (threshold=0.40)
- Vanilla SD baseline: 82.50% accuracy

Baselines: Vanilla SD, Top-K, AutoJudge, Target-Entropy, Draft-Entropy.

**Fixed value, task-specific.** The paper reports results across multiple fixed thresholds (e.g., 0.10, 0.30, 0.40, 0.50, 0.90 for KL). No learned tuning described; thresholds are empirically swept.

## 1. FLy — Entropy Gate + Deferred Window

### 算法（紧凑版）

```
# Draft 生成 K tokens, target 一次 forward 拿到所有 K 位置的 logits
for j in 0..K-1:
    if draft[j] == argmax(z_target[j]):
        accept; continue
    # mismatch 位置 j
    h_j = entropy(softmax(z_target[j])) / log|V|    # 归一化 entropy ∈[0,1]
    if h_j < θ:  # θ=0.3, 低 entropy = 确定性位置
        reject from j onward; STOP
    else:        # 高 entropy, 暂接受
        count mismatches M_w in positions [j+1, j+W]  # W=6
        if M_w == 0 and j+W <= K:
            accept j (semantic ok)
        else:
            reject j; STOP  # target 后续在自纠错
```

### 我们场景的几个关键观察

| 观察 | 含义 |
|---|---|
| **deferred window 在同一个 draft chunk 内**，不要额外 forward | 工程成本低 |
| **W=6, 我们 dtn=7（D5）/ 13（D7）** | D5 chain 全长 7，能用的 window 只剩 ≤6 → 几乎只看末尾 1 token；D7 chain 13 才有合理 window |
| **算法假设 sequential chain**，论文只做 chain verify | EAGLE-3 是 tree（topk=2），每条 tree path 上独立跑 deferred window 需要重新推导 |
| **Greedy 完全兼容**，论文 Table 2/3 全部 T=0 explicit | OOD 2.74× / IND 2.88×（Llama-3.1-70B）|
| **0.45 ms / round overhead**（target verify 58.62 ms 量级）| 可忽略 |
| **没开源代码**，纯论文 | 自己实现 |

### Tree verify 怎么落

EAGLE-3 tree verify 上 deferred window 不平凡。三种选项：

1. **Path-wise**：tree 解开成 path（topk=2, depth=spec_steps=3，最多 2^3=8 path），每条 path 独立跑 deferred window。问题：每条 path 长度 = spec_steps = 3-5，太短没 window 空间。
2. **Depth-wise**：把 deferred window 改成"对所有 sibling 累积 mismatch 计数"，更松但失去原始定义的语义。
3. **只在 D7 dtn=13 + chain 模式启用**（topk=1，退化成 sequential），跳过 D5 tree。MARS 走 D5 tree，FLy 走 D7 chain，互相不冲突。

**Entropy gate 单独移植没有这个问题**：低 entropy 位置（target 高置信）拒绝 MARS 放宽 → 是 MARS 的"否决加严"，与 tree 完全无关。这是最值得先做的子集。

### 与 MARS 重叠 vs 正交

- MARS 看 **top-2 / top-1 logit ratio** — target 自己难分（两个候选接近）
- FLy entropy 看 **整个 vocab 分布的 flatness** — target 整体犹豫
- 这两个信号正相关但不完全等价。Entropy 低但 top-2 ratio 高的情况：top-1 + top-2 各占 0.5（高 entropy 但 ratio=1）。Entropy 高但 top-2 ratio 低：top-1=0.4，余下均匀分布（低 ratio 但高 entropy）。
- **结论**：entropy gate 与 MARS 加叠加 = "MARS top-2 接受 AND target entropy ≥ θ"，比单跑 MARS 严格。在高 entropy 区域保留 MARS 收益，低 entropy 区域回归 exact match。这条规则**单独移植值得 1 周工程量**。

## 2. CSD — Calibrated Speculative Decoding

### 算法（拆成两块）

**SCG (Semantic Consistency Gating)** — verify rule：

```
accept draft x̃ iff:  z_target(x̃) - z_target(top-1) >= log τ
                     # τ=0.01 → log τ ≈ -4.6
```

**OCM (Online Correction Memory)** — 频次表 𝒯[(x̃, t*)]：
- 离线 calibration 阶段在 unlabeled corpus 上跑 baseline SD，记录所有 reject 事件的 (draft_token, target_top1) pair
- 在线 inference 阶段，每次发生 reject 时查 𝒯：如果 (x̃, t*) 出现 ≥ λ 次（论文 λ=6），且 SCG gate 通过，则把 x̃ 当作"已知 benign substitution"接受
- 论文例子：math 格式 `$$` vs `\[` 这种系统性差异

### 关键比较：CSD 与 MARS 的关系

**CSD-SCG 是 MARS 的严格推广**：

| | MARS | CSD-SCG |
|---|---|---|
| 接受规则 | rank(x̃) ≤ 2 **AND** `z_(2)/z_(1) > θ` | (无 rank 限制) **AND** `z(x̃) - z(top-1) ≥ log τ` |
| 默认 τ/θ | θ=0.9（论文）/ 0.5（我们 D7）| τ=0.01 |
| 等价 logit gap | θ=0.5 → gap ≥ -log(2) ≈ -0.69 | τ=0.01 → gap ≥ log(0.01) ≈ -4.6 |
| 允许接受的 token | top-2 only | 任何满足 gap 条件的 token |

**两点结论**：

1. **CSD-SCG 的 gap 阈值（-4.6）比我们 D7 MARS（-0.69）宽松 7 倍**。如果直接照搬 τ=0.01，质量塌。论文不掉分是因为他们对比的 baseline 是 vanilla SD（chain），不是 MARS。
2. **保留 MARS rank ≤ 2 + 把 ratio 阈值换成 logit gap**，是个安全的小调整。把 D5 改成"top-2 AND gap ≥ -1"（对应 ratio ≈ 0.37），扫描比较。但这本质上是同一个公式参数化，没拿到 CSD 的真正增量。

**CSD 的真正增量是 OCM**：跨请求频次缓存。对我们这种"NVFP4 量化后特定 token 系统性偏移"的场景理论上有效——量化 noise 会让某些固定 pair 反复 mismatch（比如某 logit 临界 token），OCM 把它们记下来"白名单"。

### OCM 在 EAGLE-3 + NVFP4 上的工程问题

- **OCM 是 cross-request 状态**，跟 SGLang multi-request batched scheduler 怎么交互论文没说
- 表 𝒯 的 (draft_id, target_top1_id) pair 在 |V|=73448 词表下理论上 5.4B 项，实际 lambda=6 阈值后稀疏，但需要 LRU 淘汰策略论文没给
- **prior calibration 阶段需要在我们的 NVFP4 量化 target 上重跑** — 不能用论文的预算
- **论文没做 EAGLE / tree** — tree verify 上每条 path 各自查表也行，但 batch dispatch 复杂

## 3. KL Judge — Revisiting Judge Decoding

### 算法 + 理论贡献

**主要定理 4.1**：trained judge classifier 与 KL 阈值都依赖同一个 logit-gap primitive
$$\Delta_{ij}(x) := (z_t(i) - z_t(j)) - (z_d(i) - z_d(j))$$
区别只是聚合方式（quadratic vs linear）。

**Acceptance rule**：
```
if target_top1_prob > 0.9:   # high certainty
    exact match (vanilla SD)
else:
    accept iff D_KL(p_target || p_draft) < τ
```

### 为什么对我们没用

**T=0 greedy 时 KL 退化**：draft 是 one-hot（greedy argmax），target 输出 logits 通过 argmax 选 token。如果你算的是 target full-distribution 和 draft full-distribution（前提是 draft 出 logits 而非 only top-1 token）的 KL，那 draft 是 one-hot 分布，KL(p_t || p_d) 的项里有 `1 * log(1/p_d(target_top1))` — 当 draft top-1 ≠ target top-1 时是 +∞。等价于 exact match。

唯一拯救方法是让 draft 输出 soft distribution 而不是 greedy token，但我们整个 EAGLE-3 chain 是 greedy 的：

- draft 跑出 logits → topk=2 选两条分支 → 树展开
- verify 端比 token id，不比分布

要走 KL Judge 需要把 draft logit tensor 也送到 verify kernel，**改 9 个文件的 schema**（参考我们当年加 MARS 时改了 `eagle_utils.cu` / `common_extension.cc` / `sgl_kernel_ops.h` / `speculative.py` / `eagle_utils.py` / `eagle_info.py`），且接受率收益论文也没在 EAGLE/tree/T=0 测过。

**论文实测数据本身**（GSM8K，1B/8B chain SD）：1.26× vs AutoJudge 1.23×（提升 +2.4%）— 在我们 EAGLE-3 baseline 已经 3-4× 的基础上叠加这点不值得改 kernel。

**结论**：KL Judge 在 T=0 + EAGLE tree 上是死路。它的理论价值是证明 "AutoJudge 学到的 criticality 就是 KL"，这对我们 **如果将来转 sampling 路线** 有参考意义，目前 pass。

## 重新排 ROI（按提吞吐排序）

### 🟢 Tier 1：直接放宽 MARS（最低工程成本，预期收益最大）

**方案 A1 — MARS top-2 推广到 top-K**

我们当前规则：
```
accept x̃ iff x̃ ∈ {top-1, top-2} AND z_(2)/z_(1) > θ
```

放宽到：
```
accept x̃ iff x̃ ∈ {top-1..top-K} AND z_x̃/z_(1) > θ
```

K=3 或 K=4。直接覆盖更大一片"target 也觉得 OK 的近邻 token"。

- **改动**：`sgl-kernel/csrc/speculative/eagle_utils.cu` 的 `VerifyTreeGreedy` 加 top-3/4 排序（当前只取 top-2）
- **工程量**：~半天，schema 不变（只是新增一个 `mars_topk` 参数）
- **风险**：top-K rank 内 ratio 接近的概率随 K 增长而上升，θ 可能要重调
- **预期**：在 deepresearch / 长 context 等低 al 区间收益最大（target 越不确定 → top-3/4 越有概率与 draft 撞上）

**方案 A2 — 进一步降 θ**

我们 D7 已经 θ=0.5，D5 θ=0.75。论文 sweep 最低 0.84。继续下探：
- D7 θ=0.5 → 0.3 或 0.2
- D5 θ=0.75 → 0.6

代价 0 行代码，scan 一晚。但 D7 已经压到 0.5 没掉分意味着可能已经触底；继续下探边际可能为负。

### 🟡 Tier 2：CSD-SCG 替换 MARS 接受规则（1-2 周）

把 MARS 的"top-K rank + ratio"换成 CSD 的纯 logit gap：

```
accept x̃ iff z_target(x̃) - z_target(top-1) ≥ τ_gap
```

- **关键差异**：不限 rank，只限 logit 距离
- **τ_gap 起点**：从 MARS 等价点 τ_gap = -0.69（对应 ratio=0.5）开始扫到 -2.0
- **改动**：verify kernel 不取 top-2，直接对每条 tree path 的 draft token 算 `z(draft) - z(top1)`
- **比 Tier 1 多救的 case**：target 输出 top-1 logit 5.0，draft 选的是 top-7 但其 logit 是 3.5（gap=-1.5）—— MARS top-2 拒，CSD-SCG 接受
- **风险**：长尾上 logit 接近但语义无关的 token 增多（同音字 / 标点 / 罕见近邻）。需要 e2e bench 看 accuracy 是否塌

**这是 MARS 的"严格放宽超集"**，Tier 1 的 A1（top-K）只是它的 rank-bounded 特例。Tier 2 做完 A1 可以退役。

---

### 🟡 Tier 3：FLy Deferred Window（2-3 周，工程结构性改动）

正确理解：deferred window 是 **mismatch 后还看后续 W 个 token 不继续 diverge 就接受**。这是真正的放宽——MARS / CSD-SCG 都只看 mismatch 位置 *本身的* logit，FLy 用 mismatch *后面* target 自己生成的内容作"事后证据"。

我们的 dtn=7 / 13 上怎么落？

| 选项 | 思路 | 复杂度 |
|---|---|---|
| **D7-chain only** | 只在 dtn=13 + topk=1 退化成 chain 时启用 deferred window；D5 tree 仍走 MARS | 中等。需要在 spec_mode 切换时启停 |
| **跨 round 缓存 pending mismatch** | 一轮 target forward 发现 mismatch，标记为 pending，下一轮 forward 时回查 W token 决定接受/拒绝。无需多 forward | 高。`eagle_info.py` 状态机要扩 |
| **Tree path-wise** | tree 解开成 path，每条 path 独立 deferred window | 高。tree 越深越值，spec_steps=3 时 path 长 4 不够 W=6 |
| **加大 dtn 同时启用** | dtn 拉到 15-20 留出 deferred window 空间 | 中等。但 dtn 越大 verify forward 越贵，需 ROI |

FLy 在论文 chain 上是 **+59% over EAGLE-3**，是三个机制里理论增量最大的。但论文做的是 sequential chain，不是 tree——他们的 baseline EAGLE-3 估计是降级 chain mode。我们的 D5 已经 tree-3-2 拿了大头，FLy 在 D5 上的边际可能远没论文那么大。

**先在 D7 chain 上试**（选项 1，最低工程成本），如果 D7 收益显著再考虑跨 round 缓存方案。

---

### 🟠 Tier 4：CSD OCM 白名单（3+ 周，研究项）

NVFP4 量化引入 systematic logit bias —— 某些 token pair 反复 mismatch 但语义等价（比如标点选择、数字格式、subword 边界）。OCM 把这类 pair 缓存做白名单。

- **离线 calibration**：用我们的 NVFP4 量化 target + bf16 reference 跑一遍 corpus，记录 reject 的 (draft_top1, target_top1) pair
- **在线**：每个 reject 查表，命中且 SCG gate 通过则接受
- **数据结构**：frequency dict, LRU 淘汰
- **跟 MARS / SCG 都正交**，叠加

预期：长尾 +5-10%。但工程量大且收益要实测才知道。
