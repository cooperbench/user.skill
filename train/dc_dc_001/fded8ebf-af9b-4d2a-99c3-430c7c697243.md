### 关键注意事项

1. **网络与时间**：总数据量预计 100-300GB+，下载时间取决于网络速度，可能需要数小时。
2. **磁盘空间**：解压过程中需要额外空间（zip + 解压内容并存），脚本会在解压后删除 zip 以释放空间。
3. **断点续传**：Kaggle CLI 不支持原生断点续传，如果某个比赛下载失败，脚本会报错但继续下载下一个，之后可以单独重试失败的。
4. **已结束比赛**：部分早期比赛（如 2020 的 birdsong-recognition）可能已关闭数据下载，如果遇到 403 错误则跳过。
5. **Token 安全**：你的 `KAGGLE_API_TOKEN` 会作为环境变量使用，不会写入任何文件。

### 实际执行的核心脚本

我会创建一个 `download_all.sh` 脚本来自动化整个流程，核心逻辑如下：

```bash
#!/bin/bash
export [REDACTED]

COMPETITIONS=(
  "birdsong-recognition:birdsong-recognition-2020"
  "birdclef-2021:birdclef-2021"
  "birdclef-2022:birdclef-2022"
  "birdclef-2023:birdclef-2023"
  "birdclef-2024:birdclef-2024"
  "birdclef-2025:birdclef-2025"
  "birdclef-2026:birdclef-2026"
)

for entry in "${COMPETITIONS[@]}"; do
  SLUG="${entry%%:*}"
  DIR="${entry##*:}"
  mkdir -p "$DIR"
  echo "Downloading $SLUG -> $DIR ..."
  kaggle competitions download -c "$SLUG" -p "$DIR"
  # 解压所有 zip 文件
  for zipfile in "$DIR"/*.zip; do
    [ -f "$zipfile" ] && unzip -o "$zipfile" -d "$DIR" && rm "$zipfile"
  done
done
```

---

## BirdCLEF 2025 前五名方案深度分析

### 比赛核心挑战

这是一个**音频物种识别**比赛，目标是从录音中识别206个物种（涵盖鸟类 Aves、两栖类 Amphibia、昆虫类 Insecta、哺乳类 Mammalia）。评价指标是 **ROC AUC**。比赛提供了有标注的 `train_audio` 和**无标注的 `train_soundscapes`**，后者成为比赛胜负的关键战场。

---

### 一、所有方案的最大共识：伪标签/半监督学习是核心

正如第2名所说：*"2024年开始，范式已经从'额外数据为王'变成了'伪标签的兔子洞之旅'"*。

**五个方案全部使用了伪标签**，区别在于实现方式的精妙程度：

| 名次 | 伪标签策略 | 迭代次数 | 关键技巧 |
|------|-----------|---------|---------|
| 1st | Multi-Iterative Noisy Student + MixUp | 4轮 | **幂次变换**降低伪标签噪声 |
| 2nd | 置信度过滤 + OOF预测 | 2-3轮 | 阈值>0.5筛选，<0.1截断为0 |
| 3rd | 集成模型生成伪标签 | 未详述 | rank-aware后处理 |
| 4th | 半监督学习 | 未详述 | 配合自定义Soft AUC Loss |
| 5th | Self-distillation（自蒸馏） | train_audio上4-5轮 + soundscape上2轮 | 迭代补充缺失的二级标签 |

**第1名的核心突破**是发现了为什么简单拼接伪标签数据不行——必须通过**噪声注入**（MixUp + Stochastic Depth）让学生模型学到比教师更鲁棒的特征，这本质上就是 Noisy Student。并且他发现了一个关键trick：**对伪标签概率做幂次变换**（power > 1），能有效压制噪声标签，只保留高置信的信号，使得多轮迭代成为可能（4轮，Public LB从0.909一路涨到0.930）。

**第5名**的自蒸馏思路很有特色：他们发现训练数据中很多二级标签是缺失的（录音者只标注了目标物种，但背景中有其他鸟叫），所以用模型预测来补全这些标签，本质上是在修复标注噪声。

---

### 二、模型架构：惊人的一致性

**所有方案都是 Mel频谱图 → 2D CNN 的范式**，没有任何Transformer或1D模型胜出。

- **SED（Sound Event Detection）头**占据绝对主导：1st、2nd、4th、5th都用了SED头（源自BirdCLEF 2021第4名方案）
- **骨干网络高度趋同**：`tf_efficientnet` 系列和 `eca_nfnet_l0` 是最受欢迎的选择
- 第5名明确指出**纯CNN模型不work**，第4名也说**除了EfficientNet的其他模型都不行**

有意思的是：第3名用了一些非主流骨干如 `mnasnet_100`、`spnasnet_100`，但最终最好成绩是去掉它们只用6个模型实现的。

---

### 三、音频时长的分歧

这是方案间**最大的分歧点之一**：

- **1st place：20秒**——他做了大量实验，发现20秒对两栖和昆虫类的长周期重复叫声至关重要
- **2nd place：5秒**——延续传统做法
- **4th、5th place：10秒**
- 第1名的实验数据很有说服力：5秒→0.842，20秒→0.872，差距巨大

第1名分析认为，**Amphibia和Insecta的叫声具有长时间重复性**，较长的输入时长能让模型更好地捕捉这种特征。

---

### 四、各方案的独特亮点

**第1名（Private 0.935）—— Noisy Student 大师**
- 幂次变换压制伪标签噪声（真正的杀手锏）
- 单独训练一个 Amphibia/Insecta 模型，使用700个物种的Xeno-Canto数据
- 关于Insecta的有趣发现：科级标签（如Cicadidae）实际指向特定物种，直接用科级标签反而有害
- 推理时用**重叠帧预测平均**（类似图像中的滑窗分割），稳定提升0.002-0.003

**第2名（Private 0.924）—— 预训练为王**
- **来自乌克兰的团队**，开篇感谢乌克兰武装力量保护他们的安全
- 杀手级特征：在**大规模Xeno-Canto数据上预训练**（7400-7800个物种），然后迁移骨干到比赛任务。这一步直接从0.83-0.84跳到0.86-0.87
- 后处理trick：用文件内最高概率加权所有chunk预测，抑制弱信号

**第3名（Private 0.927）—— 验证集创新**
- 创造性地用**BirdCLEF 2023数据的20%作为验证集**，解决了大家都头疼的CV-LB不相关问题
- 用了最多的模型：20个模型的集成（10 CNN + 10 SED，5种骨干 × 2组梅尔参数）

**第4名（Private ~0.924）—— Soft AUC Loss**
- 最独特的创新：自定义 **Soft AUC Loss**，直接优化比赛指标
- 这个Loss对过拟合极其抗拒：CV分数比CE差很多，但LB分数好很多
- 单个 efficientnetv2_b0 模型从0.850提升到0.901（+0.051，极为显著）

## 一、与2025方案高度吻合的发现

### 伪标签依然是最大杠杆

报告中 v9→v24 的 +0.039 提升完全印证了2025的共识。但要注意几个关键差异：

**当前方案用 Perch 做 teacher，而2025冠军用的是自训练的强集成模型做 teacher。** Perch 是一个通用鸟声嵌入模型，用它做 teacher 有两面性：
- 优点：不需要先训练一个强 teacher，可以更早开始伪标签流程
- 风险：Perch 的特征空间未必针对本次比赛的物种分布最优，可能引入 domain gap

2025冠军的做法是**先用纯监督训练出一个强基线集成，再用它生成伪标签**——teacher 本身就是为这个任务优化的。当前方案如果在后续迭代中**用自己训练的强模型替代 Perch 做 teacher**，大概率能获得进一步提升。

### 数据过滤有害

Rating ≥ 3 过滤掉 -0.047，与2025第2名的经验一致——他们发现"假阳性"反而帮助了泛化。**在这类数据稀缺的比赛中，数据量几乎总是比数据质量更重要。**

### 大模型不一定比小模型好

V2S（22.4M）全面落后于 B0（6.2M），这与2025多个方案的发现一致：
- 第4名说"除了EfficientNet的其他模型都不行"
- 第1名在第一阶段用小模型（b0, regnety_008）就能达到很好的效果
- 第2名发现 ConvNeXt 失败了

但**不要太早放弃 V2S**——2025第2名的 `tf_efficientnetv2_s` 是他们最强的单模型（0.917 Public），关键是他们有**大规模预训练**。V2S 可能需要不同的训练策略。

## 二、当前方案可能遗漏的关键技术

### 1. 多轮伪标签迭代 + 噪声控制（最重要）

目前方案只做了 r4、r5 两轮伪标签，但2025冠军做了**4轮迭代**，核心诀窍是**幂次变换**。当前报告中没有提到任何伪标签去噪手段。

2025冠军的数据：

| 迭代 | 幂次值 | Public LB |
|------|--------|-----------|
| 1轮 | 1 | 0.909 |
| 2轮 | 1/0.65 | 0.918 |
| 3轮 | 1/0.55 | 0.927 |
| 4轮 | 1/0.6 | 0.930 |

每一轮都有显著提升。当前方案的 v30 尝试"合并 r4+r5 伪标签"，本质上是把更多伪标签塞进去，但**没有解决标签噪声随迭代累积的问题**。如果在合并伪标签之前先做幂次变换（`label = label ** power`，power > 1），大概率能进一步提升。

### 2. Noisy Student 训练范式

当前方案用的是 soft KD（知识蒸馏），student 直接拟合 teacher 的软输出。但2025冠军强调了一个关键点：**必须对 student 注入噪声**（MixUp + Stochastic Depth），否则 student 只会复制 teacher 的错误。

当前方案有 Mixup α=0.5 和 SpecAugment，但没有提到 **Stochastic Depth（drop_path）**。2025冠军发现 drop_path_rate=0.15 能稳定提升 0.005，且只在伪标签训练时有效。这个几乎是免费的提升。

### 3. 音频时长

报告中没有提到使用的音频 chunk 时长。2025冠军的实验表明20秒显著优于5秒（0.872 vs 0.842）。如果当前方案用的是5秒或10秒，**尝试更长的时长可能是一个重大提升点**，尤其是如果2026同样包含两栖/昆虫类物种。

### 4. 单独的弱势物种模型

2025冠军训练了一个**专门的 Amphibia/Insecta 模型**（700个物种，来自 Xeno-Canto），单独提供 +0.002-0.003。如果2026的数据集同样有严重的类别不平衡，这个策略值得尝试。

### 5. 推理时的重叠帧平均

2025冠军和第5名都使用了**重叠窗口推理**（类似图像分割的滑窗），而不是独立处理每个 chunk。这个 TTA 策略一致带来 +0.002-0.008 的提升。

## 三、对当前技术选择的一些建议

### PCEN 很重要——但2025方案都没用它

有意思的是，**2025前五名没有一个提到 PCEN**，他们全部使用标准的 Mel 频谱图 + 对数变换或 0-1 归一化。但当前方案的 v26 ablation 表明去掉 PCEN 后性能暴跌 -0.049。

这说明 PCEN 可能在当前 pipeline 中承担了**替代某些其他技术的角色**（比如更强的数据增强或更好的归一化）。值得思考：如果换成2025方案普遍使用的 `top_db=80.0` + `0-1 normalization`，配合更强的增强策略，是否效果相当甚至更好？

### ASL Loss 的选择

ASL（Asymmetric Loss）是一个不错的选择，但对比2025方案的多样性：
- 1st：CrossEntropy（带不归一化的多标签）
- 2nd：Focal + BCE
- 4th：**Soft AUC Loss**（最独特，抗过拟合极强）
- 5th：FocalLoss (γ=2)

特别关注第4名的 Soft AUC Loss——他单模型提升了 +0.051。如果比赛指标仍然是 ROC-AUC，直接优化 AUC 的 loss 在理论上是最优的。建议做一个 v_next 实验替换 ASL 为 Soft AUC Loss 试试。

### 集成多样性不足

当前方案几乎全部基于 B0，最终集成 `4×B0 soups + 5×B0 singles` 本质上是**同质集成**。2025的教训非常明确：

- 1st：efficientnetb3 + b4 + regnety016 + ecanfnetl0 + regnety008 + b0（6种不同骨干）
- 2nd：efficientnetv2_s + eca_nfnet_l0
- 5th：efficientnetv2_s + v2_b3 + b3_ns + b0_ns（4种骨干）

**骨干多样性是抵抗 shake-up 的关键**。2025冠军明确说"multi-stage models, diverse backbone architectures... 是 withstanding the shake-up 的关键部分"。建议至少加入 `eca_nfnet_l0`（2025第1、2名都用了）和一个 `regnety` 变体。

## 四、风险提醒

### 只有一个 LB 锚定点

目前只有 v9 = 0.892 这一个 LB 确认分数。**所有 val → LB 的推算都基于一个数据点**，这很危险。2025前五名都反复强调 CV 和 LB 之间的相关性很弱。建议尽快提交 v24 或 v28 获取第二个锚定点，否则可能在错误的方向上浪费很多 GPU 时间。

这个验证集太小了，方差会很大。2025第1名说"单模型在不同 seed 下 LB 分数波动很大"，13个文件的验证集只会更不稳定。2025第3名用 BirdCLEF 2023 的20%做验证集的思路值得借鉴。

## 总结

**当前方案的实验框架很好，但核心技术栈还停留在2025中游水平。** 要冲击前排名次，优先级建议：

Introduction 
BirdCLEF 2026 is a multi-label classification task: identify 234 wildlife species from 5-second segments of passive acoustic recordings in Brazil's Pantanal wetlands. Performance is measured by macro-averaged ROC-AUC over species that have at least one positive in the test ground truth. The submission notebook must run CPU-only within 90 minutes and without internet access.

Approach
Google's Perch v2 serves as a frozen feature extractor. No fine-tuning is performed; the 59 fully-labeled soundscape files provide enough signal to train lightweight linear probes on frozen embeddings in a few minutes on CPU.

Perch v2 (frozen)
    |
    +-- raw logits (234 classes, mapped from Perch's 14k-class vocab)
    |        |
    |        +-- site x hour Bayesian prior fusion
    |                 |
    |                 v
    |            fused logits  (base scores)
    |
    +-- 1536-dim embeddings
             |
             v
         PCA (64 dims) + per-class LogisticRegression probes
             |
             v
         final = 0.6 * base + 0.4 * probe -> sigmoid -> submission.csv

Settings

FNAME_RE = re.compile(
    r'BC2026_(?:Train|Test)_(\d+)_(S\d+)_(\d{8})_(\d{6})\.ogg'
)

def parse_labels(x):
    if pd.isna(x):
        return []
    return [t.strip() for t in str(x).split(';') if t.strip()]

def union_labels(series):
    return sorted(set(lbl for x in series for lbl in parse_labels(x)))

def parse_soundscape_filename(name):
    m = FNAME_RE.match(name)
    if not m:
        return {'site': None, 'hour_utc': -1}
    _, site, _, hms = m.groups()
    return {'site': site, 'hour_utc': int(hms[:2])}

Perch Inference 
The 59 fully-labeled training soundscapes are run through Perch to obtain raw logits and 1536-dimensional embeddings. If a compatible cache exists (V1 format: full_perch_meta.parquet + full_perch_arrays.npz), it is loaded directly and inference is skipped to save runtime.

Audio and Inference Helpers
def read_soundscape_60s(path):
    y, sr = sf.read(path, dtype='float32', always_2d=False)
    if y.ndim == 2:
        y = y.mean(axis=1)
    if len(y) < CFG.FILE_SAMPLES:
        y = np.pad(y, (0, CFG.FILE_SAMPLES - len(y)))
    return y[:CFG.FILE_SAMPLES]


def infer_perch_batch(paths, verbose=True):
    paths   = [Path(p) for p in paths]
    n_files = len(paths)
    n_rows  = n_files * CFG.N_WINDOWS

    row_ids    = np.empty(n_rows, dtype=object)
    filenames  = np.empty(n_rows, dtype=object)
    sites      = np.empty(n_rows, dtype=object)
    hours      = np.empty(n_rows, dtype=np.int16)
    scores     = np.zeros((n_rows, N_CLASSES), dtype=np.float32)
    embeddings = np.zeros((n_rows, 1536),      dtype=np.float32)

    write_row = 0
    itr = tqdm(range(0, n_files, CFG.BATCH_FILES), desc='Perch', disable=not verbose)

    for start in itr:
        batch  = paths[start:start + CFG.BATCH_FILES]
        bn     = len(batch)
        x      = np.empty((bn * CFG.N_WINDOWS, CFG.WINDOW_SAMPLES), dtype=np.float32)
        bstart = write_row

        for bi, path in enumerate(batch):
            audio = read_soundscape_60s(path)
            x[bi * CFG.N_WINDOWS:(bi + 1) * CFG.N_WINDOWS] = audio.reshape(
                CFG.N_WINDOWS, CFG.WINDOW_SAMPLES
            )
            meta = parse_soundscape_filename(path.name)
            row_ids[write_row:write_row + CFG.N_WINDOWS]   = [
                f'{path.stem}_{t}' for t in range(5, 65, 5)
            ]
            filenames[write_row:write_row + CFG.N_WINDOWS] = path.name
            sites[write_row:write_row + CFG.N_WINDOWS]     = meta['site']
            hours[write_row:write_row + CFG.N_WINDOWS]     = meta['hour_utc']
            write_row += CFG.N_WINDOWS

        out    = infer_fn(inputs=tf.convert_to_tensor(x))
        logits = out['label'].numpy().astype(np.float32)
        emb    = out['embedding'].numpy().astype(np.float32)

        scores[bstart:write_row, MAPPED_POS] = logits[:write_row - bstart, MAPPED_BC_INDICES]
        embeddings[bstart:write_row]          = emb

        for pos, bc_idx_arr in selected_proxy_pos_to_bc.items():
            scores[bstart:write_row, pos] = logits[:write_row - bstart, bc_idx_arr].max(axis=1)

        del x, out, logits, emb
        gc.collect()

    meta_df = pd.DataFrame({
        'row_id': row_ids, 'filename': filenames,
        'site': sites, 'hour_utc': hours,
    })
    return meta_df, scores, embeddings

Prior Fusion 
Raw Perch logits reflect global species probabilities from pretraining but ignore the deployment context. Bayesian prior tables are built from the soundscape metadata, covering site prevalence, hour-of-day prevalence, and their joint prevalence, each shrunk toward the global mean. The resulting logit offsets are added to the raw scores with class-type-specific weights.

Prior Table Construction
def fit_prior_tables(prior_df, Y_prior):
    prior_df = prior_df.reset_index(drop=True)
    global_p = Y_prior.mean(axis=0).astype(np.float32)

    site_keys = sorted(prior_df['site'].dropna().astype(str).unique())
    hour_keys = sorted(prior_df['hour_utc'].dropna().astype(int).unique())

    site_to_i, site_n, site_p = {}, [], []
    for s in site_keys:
        mask = prior_df['site'].astype(str).values == s
        site_to_i[s] = len(site_n)
        site_n.append(mask.sum())
        site_p.append(Y_prior[mask].mean(axis=0))
    site_n = np.array(site_n, dtype=np.float32)
    site_p = np.stack(site_p).astype(np.float32) if site_p else np.zeros((0, Y_prior.shape[1]), np.float32)

    hour_to_i, hour_n, hour_p = {}, [], []
    for h in hour_keys:
        mask = prior_df['hour_utc'].astype(int).values == h
        hour_to_i[h] = len(hour_n)
        hour_n.append(mask.sum())
        hour_p.append(Y_prior[mask].mean(axis=0))
    hour_n = np.array(hour_n, dtype=np.float32)
    hour_p = np.stack(hour_p).astype(np.float32) if hour_p else np.zeros((0, Y_prior.shape[1]), np.float32)

    sh_to_i, sh_n_list, sh_p_list = {}, [], []
    for (s, h), idx in prior_df.groupby(['site', 'hour_utc']).groups.items():
        sh_to_i[(str(s), int(h))] = len(sh_n_list)
        idx = np.array(list(idx))
        sh_n_list.append(len(idx))
        sh_p_list.append(Y_prior[idx].mean(axis=0))
    sh_n = np.array(sh_n_list, dtype=np.float32)
    sh_p = np.stack(sh_p_list).astype(np.float32) if sh_p_list else np.zeros((0, Y_prior.shape[1]), np.float32)

    return dict(
        global_p=global_p,
        site_to_i=site_to_i, site_n=site_n, site_p=site_p,
        hour_to_i=hour_to_i, hour_n=hour_n, hour_p=hour_p,
        sh_to_i=sh_to_i,     sh_n=sh_n,     sh_p=sh_p,
    )
Prior Logits and Score Fusion
def prior_logits(sites, hours, tables, eps=1e-4):
    n = len(sites)
    p = np.repeat(tables['global_p'][None, :], n, axis=0).astype(np.float32, copy=True)

    si  = np.fromiter((tables['site_to_i'].get(str(s), -1) for s in sites), np.int32, n)
    hi  = np.fromiter(
        (tables['hour_to_i'].get(int(h), -1) if int(h) >= 0 else -1 for h in hours),
        np.int32, n
    )
    shi = np.fromiter(
        (tables['sh_to_i'].get((str(s), int(h)), -1) if int(h) >= 0 else -1
         for s, h in zip(sites, hours)),
        np.int32, n
    )

    valid = hi >= 0
    if valid.any():
        nh = tables['hour_n'][hi[valid]][:, None]
        p[valid] = nh / (nh + 8.0) * tables['hour_p'][hi[valid]] + (1.0 - nh / (nh + 8.0)) * p[valid]

    valid = si >= 0
    if valid.any():
        ns = tables['site_n'][si[valid]][:, None]
        p[valid] = ns / (ns + 8.0) * tables['site_p'][si[valid]] + (1.0 - ns / (ns + 8.0)) * p[valid]

    valid = shi >= 0
    if valid.any():
        nsh = tables['sh_n'][shi[valid]][:, None]
        p[valid] = nsh / (nsh + 4.0) * tables['sh_p'][shi[valid]] + (1.0 - nsh / (nsh + 4.0)) * p[valid]

    np.clip(p, eps, 1.0 - eps, out=p)
    return (np.log(p) - np.log1p(-p)).astype(np.float32)


def smooth_cols(scores, cols, alpha=0.35):
    """Temporal smoothing: blend each window with its neighbours within the same file."""
    if alpha <= 0 or len(cols) == 0:
        return scores.copy()
    s    = scores.copy()
    view = s.reshape(-1, CFG.N_WINDOWS, s.shape[1])
    x    = view[:, :, cols]
    prev = np.concatenate([x[:, :1, :], x[:, :-1, :]], axis=1)
    nxt  = np.concatenate([x[:, 1:, :], x[:, -1:, :]], axis=1)
    view[:, :, cols] = (1.0 - alpha) * x + 0.5 * alpha * (prev + nxt)
    return s


def fuse_scores(base, sites, hours, tables):
    scores = base.copy()
    prior  = prior_logits(sites, hours, tables)

    if len(idx_mapped_active_event):
        scores[:, idx_mapped_active_event] += CFG.LAMBDA_EVENT * prior[:, idx_mapped_active_event]
    if len(idx_mapped_active_texture):

    if len(idx_selected_proxy_active_texture):
        scores[:, idx_selected_proxy_active_texture] += (
            CFG.LAMBDA_PROXY_TEXTURE * prior[:, idx_selected_proxy_active_texture]
        )
    if len(idx_selected_prioronly_active_event):
        scores[:, idx_selected_prioronly_active_event] = (
            CFG.LAMBDA_EVENT * prior[:, idx_selected_prioronly_active_event]

def seq_features_1d(v):
    x    = v.reshape(-1, CFG.N_WINDOWS)
    prev = np.concatenate([x[:, :1], x[:, :-1]], axis=1).reshape(-1)
    nxt  = np.concatenate([x[:, 1:], x[:, -1:]], axis=1).reshape(-1)
    mean_v  = np.repeat(x.mean(1), CFG.N_WINDOWS)
    max_v   = np.repeat(x.max(1),  CFG.N_WINDOWS)
    # [NEW] min: background noise level per file
    # [NEW] range: signal consistency within file (high = sporadic, low = constant)
    min_v   = np.repeat(x.min(1),  CFG.N_WINDOWS)
    range_v = max_v - min_v
    return prev, nxt, mean_v, max_v, min_v, range_v


# [NEW] Prototype cosine similarity helper
# Computes cosine similarity between each window embedding and the class prototype
# prototype[c] = mean(Z[Y[:,c]==1]) — inspired by ProtoSSM prototypical head
def cosine_sim_to_prototype(Z, prototype):
    """Z: (n, d), prototype: (d,) → (n,) cosine similarity"""
    Z_norm   = Z / (np.linalg.norm(Z, axis=1, keepdims=True) + 1e-8)
    p_norm   = prototype / (np.linalg.norm(prototype) + 1e-8)
    return Z_norm @ p_norm  # (n,)


def build_class_features(Z, raw_col, prior_col, base_col,
                          proto_sim_col=None, family_mean_col=None):
    """
    Features: Z(32) + raw + prior + base + prev + next + mean + max + min + range
              + proto_sim (optional) + family_mean (optional)
    """
    p, n, m, mx, mn, rng = seq_features_1d(base_col)
    parts = [
        Z,
        raw_col[:, None], prior_col[:, None], base_col[:, None],
        p[:, None], n[:, None], m[:, None], mx[:, None],
        mn[:, None], rng[:, None],          # [NEW] min + range
    ]
    if proto_sim_col is not None:
        parts.append(proto_sim_col[:, None])    # [NEW] prototype cosine sim
    if family_mean_col is not None:
        parts.append(family_mean_col[:, None])  # [NEW] family-level mean score
    return np.concatenate(parts, axis=1).astype(np.float32)

这是一个非常精妙的方案，和之前讨论的 SED 方案走的是**完全不同的技术路线**。让我拆解分析。

---

## 核心思路：一行总结

**不训练任何神经网络**。利用 Google Perch v2 预训练模型作为冻结特征提取器，只训练轻量线性探针（Logistic Regression），配合贝叶斯先验融合，在 CPU 上几分钟跑完全部推理。

---

## 一、为什么这个方案能得高分

### 1. Perch v2 本身就极强

Perch v2 是 Google 训练的鸟声分类器，词汇表覆盖 **14,795 个物种**。本次比赛 234 个目标物种中有 **203 个直接映射到 Perch 的输出类别**（203/234 = 87%），这意味着：

- 对于这 203 个物种，Perch 的 raw logit **本身就是一个很好的分类分数**，不需要任何训练
- 这相当于拿了一个在海量数据上预训练过的"万能鸟声识别器"直接用

### 2. 贝叶斯先验融合——利用元数据作弊（合法的）

这是方案最巧妙的部分。比赛数据包含了录音的**站点（site）**和**时间（hour）**信息。方案构建了三层先验表：

```
site 先验：某个站点出现过哪些物种
hour 先验：某个时间段出现过哪些物种  
site × hour 联合先验：某站点某时段出现过哪些物种
```

然后用贝叶斯收缩（shrinkage）把这些先验转为 logit 偏移，加到 Perch 的 raw score 上。本质上就是：**如果这个站点从来没出现过某物种，就把它的分数压低；如果某物种总在凌晨3点出现，那凌晨3点的录音中它的分数就被提升。**

而且方案对不同类别用了**不同的融合权重**：
- 鸟类（event）：`λ = 0.4`——因为 Perch logit 本身已经很准
- 两栖/昆虫（texture）：`λ = 1.0`——这些物种的出现更依赖于地点，Perch 对它们识别较弱
- 属级代理（genus proxy）：`λ = 0.8`——噪声更大，折中处理

这个 event vs texture 的区分与2025冠军的发现完全一致：**两栖和昆虫类需要特殊处理**。

### 3. 嵌入探针——榨取最后一点性能

对于 Perch 的 1536 维嵌入向量：
1. PCA 降到 32 维
2. 拼接上丰富的元特征：raw logit、先验 logit、融合分数、前/后窗口分数、文件级均值/最大值/最小值/范围、原型余弦相似度、科级均分
3. 对每个有足够正样本（≥8）的类别训练一个 LogisticRegression
4. 最终分数 = `0.6 × 融合基线 + 0.4 × 探针预测`

只有 **52/234** 个类别有探针模型（因为很多类别正样本不够），其他类别完全依赖 Perch + 先验。

### 4. 抗过拟合能力极强

整个方案中**最复杂的模型就是 Logistic Regression**。训练数据只有 59 个文件、708 个窗口。如果用神经网络训练，这个数据量完全不够，但线性探针不怕：
- GroupKFold 按站点分组，避免数据泄露
- OOF 元特征确保探针输入没有信息泄露
- L2 正则化（C=0.25）防止过拟合

## 二、与 SED 方案的对比

| 维度 | Perch Probe（本方案） | SED 方案（前面的实验报告） |
|------|---------------------|------------------------|
| 核心模型 | 冻结 Perch v2 + 线性探针 | 可训练 EfficientNet + SED 头 |
| 训练时间 | CPU 几分钟 | GPU 数小时/天 |
| 推理环境 | CPU-only 友好 | 需要优化（OpenVINO等） |
| 利用无标注数据 | 不直接使用 | 伪标签（核心技术） |
| 利用元数据 | 重度利用（site, hour） | 基本不用 |
| 对新物种的处理 | genus proxy（有限） | 可以端到端学习 |
| 过拟合风险 | 极低 | 较高（需要精心控制） |
| 性能天花板 | 受限于 Perch 的能力 | 理论上更高 |

**关键洞察**：前面实验报告中提到的最终集成方案是 `Perch=0.45 / SED=0.55 VLOM`，说明**这两条路线是互补的**。Perch 擅长利用预训练知识和元数据先验，SED 擅长从原始音频中学习精细特征和利用无标注数据。最终答案是**两者融合**。

## 三、方案中值得注意的细节

### OOF AUC 只有 0.487 但 LB 很高

这是因为验证集极小（59个文件，5个站点，GroupKFold 按站点分），当一个完整站点被排除时，先验表丢失了大量信息。**这个 OOF 分数完全不可信**，只能做相对比较。

### 31个未映射物种的处理

- 4个通过**属级代理**（genus proxy）获得分数——找到 Perch 14k 词表中同属的物种，取最大 logit
- 25个"texture"类（两栖/昆虫）完全依赖先验
- 2个不活跃的未映射物种直接设为 -8.0

这是方案的**最大弱点**：对于 Perch 不认识的物种，基本没有有效的识别能力，完全依赖"在这个地方/时间出现过"这样的统计规律。

### 时序平滑

方案用了两层平滑：
1. 先验融合时对 texture 类做邻窗平滑（α=0.35）
2. 最终提交前对所有分数做高斯平滑 `[0.1, 0.2, 0.4, 0.2, 0.1]`

与2025冠军的做法非常相似（他用了 `[0.1, 0.2, 0.4, 0.2, 0.1]` 完全相同的权重）。

## 四、对你参赛的启示

### 如果你要用这个方案

1. **直接用**作为强基线——它几乎不需要 GPU，几分钟出结果
2. **重点优化31个未映射物种**——这是最大的提升空间
3. **先验表可以更精细**——比如加入季节、天气等元数据

### 如果你要结合 SED 方案

这才是正确的方向。根据实验报告中的 VLOM 方案（`Perch=0.45 / SED=0.55`）：

1. Perch probe 提供稳定的基线分数，尤其对 Perch 认识的 203 个物种
2. SED 方案通过伪标签训练，提供对复杂音频场景的精细识别能力
3. SED 方案特别能补足 Perch 在 31 个未映射物种上的短板
4. 加权融合两个系统的预测

**本质上，这个 Perch probe 方案就是一个极其高效的"第一阶段 teacher"**——你甚至可以直接用它的输出作为 SED 伪标签训练的 teacher 信号，这正是实验报告中 v24 做的事情（用 Perch teacher 生成 soft KD labels），而且效果是全部实验中最好的（+0.039）。

---

## 总结

这个方案的精髓在于：**不要重新发明轮子**。Perch v2 已经在海量数据上学会了鸟声识别，直接用它的知识，再用简单的统计方法（先验融合 + 线性探针）适配到具体比赛场景。它牺牲了一些性能天花板，但换来了极高的效率和极低的过拟合风险。在实际比赛中，它是 SED 方案的完美互补——一个提供稳健的先验知识，一个从数据中挖掘新信号。
