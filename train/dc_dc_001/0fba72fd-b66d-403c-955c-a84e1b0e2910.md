**Rewind 的执行路径：**

1. 解析全部 7.5MB session JSONL → 构建 rewind 点列表（同步阻塞）
2. **尝试中断/等待所有正在运行的 background agent 干净退出**

## 根本原因（产品层 Bug）

这是 Claude Code 的一个 **Rewind + Background Agent 并发安全漏洞**：Rewind 路径没有对 in-flight API streaming call 设置超时，导致无限等待。用 `effortLevel: high` + 大 thinking budget 时，一次 call 的 streaming 窗口可以很长，完全阻塞 UI。

## 完整诊断结论

**根本原因：React 对象引用竞态条件 (Race Condition)**

Rewind 对话框冻结的机制如下：

```
1. 用户按 double-Esc → Rewind 对话框打开
   ↓ 此时对话框持有 messages 数组里各对象的引用快照
   
2. 后台事件触发 React 重渲染（file-history-snapshot / permission-mode /
   agent 通知等写入 JSONL，触发 e1.current 用新对象数组替换旧数组）
   ↓ 对话框 UI 仍然显示旧引用的消息列表
   
3. 用户选择消息 → 确认
   ↓ IOH(O$) 被调用，O$ 是旧数组里的对象
   
4. r$.lastIndexOf(O$) 在新数组里找不到旧引用 → 返回 -1
   ↓ 早期 return，但没有清理 isCancelActive 状态
   
5. 对话框卡在 "pending/loading" 状态，Cancel 按钮禁用，所有键盘输入失效
```

**为什么这个 session 每次都触发**：eagle session 有 119 条 `file-history-snapshot`、200 条 queue-operation、48 个分支节点——后台事件极其频繁，只要 Rewind 对话框开着稍等片刻就必然触发重渲染。

**进程状态确认**：
- PID 9498 当前 `State: S (sleeping)`, `ep_poll` — 进程活着，是 UI 状态冻结
- SIGINT/SIGTERM 均被进程捕获 (`SigCgt: 0x...` 包含信号 2 和 15)
- stdin → `/dev/pts/4`（pty，raw mode），键盘输入被 Ink UI 层拦截
