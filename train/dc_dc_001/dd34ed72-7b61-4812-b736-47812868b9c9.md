## 144K 外推 = AOI (Anchor-Offset Indices) 机制 来自 LongSpec 论文，核心是**用短数据训出长 position 的 RoPE 能力**。 ### 问题 训练数据 `mean_len=1377`，PACK 后单 sample 最多 4096 → position id 范围 `0..4095`。 但推理时 draft 要在长上下文工作，target 模型 `max_position_embeddings=524288`。 如果训练只见过 0..4095 的 RoPE 角度，推理碰到 position=50000 时 RoPE 从没见过 → 外推质量崩。 ### AOI 做的事（`train.py:156` 和 `packing.py:169`） 每个 sample（或 packed 模式下每个段）训练时随机平移到一个假装长上下文里的位置： ```python sink = randint(0, 4) # 保留的"开头锚点"数 offset = randint(0, AOI_CAP - seg_len) # 平移量，最大 ~144K - seg_len pos = arange(seg_len) # 原始 0..seg_len-1 pos[sink:] += offset # 锚点之后整体右移 offset ``` **举例**：一个 seg_len=1377 的样本，随机抽到 sink=2, offset=80000： - 实际喂给 attention 的 position_ids: `[0, 1, 80002, 80003, ..., 81376]` - 等价于模型"在 144K 上下文的第 80K 位置做了一次正常的 1377-token 预测" 每个 batch、每个 sample（每个 packed 段）都重新抽 sink/offset → 整个训练过程把 `[0, 144K]` 范围的 RoPE 角度全见过。 ### 144K 这个数字的来源 ``` AOI_CAP = 144000 # 训练 position id 最大值 ROPE_THETA = 144000.0 # RoPE 频率基数，与 AOI_CAP 配套 ROPE_MAX_SEQ ≈ 164K # = AOI_CAP + 4096×5 (留 TTT 偏移余量) ``` `rope_theta=144000` 不是 target 模型的原 theta（target 是 `rope_theta=10000` 加 RoPE scaling），是 draft 自己重新设置的。把 base 调大 → RoPE 在 144K 范围内不会绕回。 ### "外推" 还是 "插值"？ 严格说在 144K 之内是 **interpolation（分布内）**；超过 144K 才是真外推。 - 训练时见过 0–144K 的 RoPE → 推理时 0–144K 几乎不掉精度 - 推理 >144K（比如 524K 极端长上下文）才需要再做 NTK / yarn 等外推 bench 里最长的请求一般在十几 K 量级，远在 144K 内，所以 AOI 144K 的覆盖足够。 ### 验证：生产权重的 ood eval 距离训练分布 生产 `train_config: aoi_cap=144000, rope_theta=144000.0` → 训练时就是这个，所以 ood_step0=0.757 的接受率是在 AOI 144K 覆盖下达到的。**我们 v3mix 这次延续这个配置，没改任何超参，性能可比**。 要不要看 v3mix prompt 长度分布、确认 144K 是否还合适，或继续讨论训练量决策？
