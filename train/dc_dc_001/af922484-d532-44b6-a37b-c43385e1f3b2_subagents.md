完美！现在我有了完整的信息。让我为用户整理一份中文总结： ## 答案总结 Claude Code **支持手动限制上下文长度**，有以下配置方式： ### 1. **限制特定模型的上下文长度** **使用环境变量组合：** ```bash export CLAUDE_CODE_MAX_CONTEXT_TOKENS=200000 # 限制为 200K export DISABLE_COMPACT=1 # 必须同时设置 ``` **作用范围：** 全局（当前终端会话） **说明：** - `CLAUDE_CODE_MAX_CONTEXT_TOKENS` 告诉 Claude Code 应该假定的上下文窗口大小 - 仅当 `DISABLE_COMPACT` 同时设置时才生效 - 适用于通过 `ANTHROPIC_BASE_URL` 路由到的模型，且该模型的实际上下文窗口与内置大小不匹配的场景 --- ### 2. **限制整体上下文长度（推荐方案）** **使用 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 环境变量：** ```bash export CLAUDE_CODE_AUTO_COMPACT_WINDOW=500000 # 将 1M 模型视为 500K ``` **作用范围：** 全局（当前终端会话） **说明：** - 设置自动压缩计算时使用的上下文容量 - 默认值为模型的实际上下文窗口（200K 或 1M） - 值会被限制在模型的实际上下文窗口以内 - 例如在 1M 模型上设置为 `500000`，会让 Claude 将可用空间视为 500K --- ### 3. **调整自动压缩触发时机** ```bash export CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50 # 50% 时触发压缩（默认 95%） ``` **作用范围：** 全局 **说明：** - 百分比范围：1-100 - 默认在 **95% 容量** 时触发自动压缩 - 设置较低值可更早压缩，保持更多可用空间 --- ### 4. **禁用 1M 上下文窗口选项** ```bash export CLAUDE_CODE_DISABLE_1M_CONTEXT=1 ``` **作用范围：** 全局 **说明：** 移除模型选择器中的 1M 变体，强制使用标准 200K 窗口 --- ### 5. **通过模型名称后缀限制（最简洁方案）** 如果你想让 **Opus 4.7 永远使用 200K** 而非 1M： 在 `settings.json` 中配置： ```json { "env": { "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-opus-4-7" } } ``` 或在启动时： ```bash claude --model opus # 使用 200K 版本 /model opus[1m] # 使用 1M 版本 ``` > 注意：模型名称**不支持** `claude-opus-4-7[200k]` 这种语法，只支持 `[1m]` 后缀 --- ### 推荐做法 | 场景 | 方案 | |------|------| | 想在 1M 模型上限制为 500K | `CLAUDE_CODE_AUTO_COMPACT_WINDOW=500000` | | 想让 Opus 永远用 200K | 使用 `opus` 别名（无 `[1m]`） | | 想更早触发压缩 | `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50` | | 完全禁用 1M 支持 | `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` | 所有这些环境变量可通过 `settings.json` 的 `env` 字段持久化： ```json { "env": { "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "500000", "CLAUDE_AUTOCOMPACT_PCT_OVERRIDE": "50", "CLAUDE_CODE_DISABLE_1M_CONTEXT": "1" } } ``` Sources: -
