各 head 独立预测，彼此之间没有共享的 step-by-step 上下文——第 2 个 head 不知道第 1 个 head 预测了什么。本质上每个 head 都是从同一个 hidden state 做一次浅层映射，位置越靠后越吃力。 - K 增大时候选树指数膨胀，verify 开销涨得比 accept rate 快。 我们在 MiniCPM-SALA 上跑通了 Medusa K=1，端到端有正向收益。但继续加 head 的时候发现曲线很快趋平——这不是工程实现的问题，是结构本身的上限。 --- ## 03 EAGLE：让 draft 自回归地跑起来 **EAGLE**（Li et al., arXiv:2401.15077）做了一个关键改动：**draft 本身就是一个自回归的小模型**。两个设计要点： 1. **输入是 target 的 hidden state 而非 token embedding**。draft 直接拿 target 已经压缩过的中间特征做输入，用远小于 target 的容量就能比较好地逼近 target 的输出分布。 2. **draft 自己跑 K 步 autoregressive**。每步的输入来自上一步的输出 hidden，draft 内部有连贯的递推上下文——这恰好是 Medusa 各 head 之间缺的东西。 代价也很直接： - 需要独立训一个 draft model，存一份权重； - 训练数据必须由 target 自己生成。这一点 EAGLE 原文讲得很明确——draft 要学的是 target 的输出分布，不是数据集里的"标准答案"。我们一开始想偷懒直接拿 SFT 数据训，accept rate 怎么都上不去，后来回去仔细看论文才意识到这个约束； - 混合注意力架构（GLA + 标准 Attention）下，draft 的隐状态和位置编码要跟 target 对齐，verify 路径上 GLA 的递推 state 也需要正确处理。 accept rate 上限的提升是切实的。对我们来说，从 Medusa 到 EAGLE 不是"换一个更花哨的方法"，而是从"已经摸到天花板"切换到"上方还有空间"。 --- ## 05 长上下文下的 accept rate 衰减 实测中观察到一个一致的现象：**推测解码在长上下文下 accept rate 会系统性下降**。这不是某一种 draft 的问题，几条原因叠加在一起： **位置编码外推。** draft 训练时通常以较短上下文为主（长 ctx 训练成本太高），推理时序列长度超出训练分布后位置嵌入进入外推区间，draft 内部表示偏离训练时的分布。 **draft KV 误差累积。** draft 自回归跑 K 步时，每步都依赖自己前几步的 KV cache。短上下文下偏差尚在 verify 的吸收范围之内；长上下文下 KV 序列变长、每步的微小偏差沿序列方向逐步放大，K 步跑完时 draft 的内部状态可能已经偏离 target 较远。 --- ## 06 高并发下推测解码可能反向 还有一件在论文里讨论过、但工程上容易被忽略的事情：**推测解码的收益随 batch size 上升而衰减，batch 足够大时会变成负收益**。 原因不复杂： **小 batch 时**，GPU 算力严重空闲，target 处理 1 个 token 和处理 K+1 个候选的耗时几乎相同——瓶颈在权重搬运，不在计算。这时 verify 接近免费，spec_steps 越大越赚。 **中等 batch 时**，GPU 利用率上来了，verify 开始有真实的算力代价。target 一次 forward 要并行处理 batch × (K+1) 个 token，K 大了之后 verify 阶段的额外耗时开始跟 spec 带来的 token 产出打架。 **大 batch 时**，GPU 接近满载。target forward 的耗时跟处理的 token 总量近似线性。推测解码相当于用 batch × (K+1) 的计算量去换 ≤ K 个额外 token——如果 accept rate 不够高，这笔账算不过来，不如直接 decode。 --- ## 07 总结 回顾这段时间在推测解码上的工作，几点体会： - Medusa 适合快速出活，EAGLE 上限更高但工程投入也更大。节奏紧的时候先用轻量方案把收益跑出来，再换重量级的——这个顺序比一上来就上 EAGLE 更合理。 - draft 的训练数据必须由 target 自己生成，且分布要贴近实际推理场景。论文里写得清楚，但实际中很容易低估这件事的重要性。 - 长上下文的 accept rate 衰减和高并发下的反向风险，是两个比"选哪个 draft 架构"更本质的问题。前者是模型与数据的分布问题，后者是系统层面的资源分配问题。 EAGLE-3 是接下来要做的事。长上下文和高并发的处理也会继续推进。后面如果有阶段性的进展，再来分享。 感谢 SOAR 2026 组委会、SGLang 与 OpenBMB 的开源工作；感谢前几支队伍公开分享的技术博客让我们少走了不少弯路；也感谢 Claude 与 ChatGPT——作为两个没有 infra 背景的本科生，很多系统层面的认知确实是在和 AI 反复对话中逐渐建立的。比赛还在继续，与各位共勉。 严谨、认真的科学语句 和小学生作文一样的语言我不希望再出现 感谢的话 不要再讲了
