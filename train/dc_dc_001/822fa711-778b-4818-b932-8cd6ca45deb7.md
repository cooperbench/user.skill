## sglang 现成接口

`--kv-cache-dtype` 已存在（`server_args.py:2742`），choices = `auto / fp8_e5m2 / fp8_e4m3 / bf16 / bfloat16 / fp4_e2m1`。

## 但有两个数据风险，先列出来

### 1. 当前 target 模型没有 KV 校准 scale
`/user_4813494d/models/openbmb/MiniCPM-SALA-gptq46-calib90-90k-NVFP4/hf_quant_config.json` 里：
```json
"quant_algo": "NVFP4",
"kv_cache_quant_algo": null
```
→ `ModelOptFp8KVCacheMethod` 不会被装到 `RadixAttention` 上 → `layer.k_scale = None`。

`minicpm_backend.py:1054-1062` 的逻辑：
```python
if self.kv_cache_dtype_str != "auto" and layer.head_dim <= 256 and self.fa_impl_ver != 4:
    if layer.k_scale is not None:
        k_descale = layer.k_scale.expand(...)
```
→ k_scale=None 时 `k_descale` 保持 None，传给 flash-attn 的 KV scale 默认 1.0。**KV 量化会发生但 scale 不准**，对长上下文 logits 数值有影响（多大要 bench）。

### 2. EAGLE-3 draft 共享同一份 `kv_cache_dtype`
`model_runner.kv_cache_dtype` 是全局的，draft worker 也走 fp8 KV。Draft 的 KV 精度退化会直接打到 accept rate（draft 的 attention 输出影响 top-k 候选 → verify 通过率），这块要 bench 之后才知道净收益。
