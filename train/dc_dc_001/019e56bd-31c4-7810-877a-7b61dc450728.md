## 结构提纲

  **draft model 在训练长度远短于推理上下文时，如何获得大位置 token 的预测能力？**

---

### 1. 长上下文 acceptance 退化的训练侧成因
- 已知现象：长上下文下 accept rate 系统性下降
- 常见解释：RoPE 位置外推问题
- 补充解释：训练样本在 position 维度严重偏斜
- 核心判断：
  - 大 position token 几乎没有训练梯度
  - 即使修 RoPE，draft 在大位置上仍然欠拟合
- 直接拉长训练序列不可行：
  - attention 代价按 N² 增长
  - 4K 扩到 128K 成本过高

---

### 2. Anchor-Offset Indices：用短序列覆盖长位置空间
- 介绍 LongSpec 的 AOI 方法
- 核心做法：
  - 保持训练序列长度不变
  - 随机整体平移 position_ids
  - 让短序列覆盖长位置编号空间
- AOI 算法示意
- 解释为什么前 4 个位置不偏移：
  - attention sink
  - 需要稳定 anchor
- 重要约束：
  - AOI 只改 position_ids
  - draft 与 target 的 `rope_theta` 必须一致

---

### 3. Sequence packing 下的 per-segment AOI
- 指出论文方法与实际训练之间的差异：
  - 论文默认单条独立序列
  - 实际训练会用 sequence packing
- 朴素 AOI 在 packed sequence 上的问题：
  - 不同 document 的 position 连续
  - 模型可能误判跨 document token 为相邻上下文
- 解决方案：
  - AOI 下沉到 segment 粒度
  - 每个 segment 独立采样 sink 与 offset
- 完整隔离需要三件事：
  1. Per-segment AOI position_ids
  2. Cross-doc attention mask
  3. Segment-tail mask
- 说明缺一项都会污染训练信号
- 给出实现位置：
  - `eagle/training/sala_draft/packing.py`
  - `aoi_position_ids_packed`
  - `mask_segment_tail`

---

### 4. 配套的训练流水线优化
说明 AOI 解决位置覆盖问题，但训练效率仍然决定最终效果。

#### 4.1 NVFP4 forward GEMM
- 旧方案：fake-STE QAT，forward 仍是 bf16 GEMM
- 新方案：
  - forward 使用真 4-bit GEMM
  - backward 保留 bf16 master weight 与 STE
- lm_head 默认排除，避免分类噪声放大

#### 4.2 Async prefetcher
- 旧数据流程：同步构 batch + H2D
- 新流程：
  - CPU worker 提前 packing
  - pinned memory
  - main thread 非阻塞搬到 GPU
- 队列深度 2 即可遮蔽构 batch 延迟

#### 4.3 LR schedule
- 旧方案：warmup → plateau
- 问题：长训练后期指标停滞
- 新方案：
  - cosine schedule
  - 5% warmup
  - 衰减到 `LR_max × 0.05`
- 需要同步保存 optimizer state，保证 resume 正确

#### 4.4 AdamW 细节
- `fused=True`
- weight decay 排除 norm / bias
- 强调这些是标准但容易漏掉的训练配置

#### 4.5 Optimizer state 进 checkpoint
- 保存 AdamW 的一阶、二阶矩
- resume 时恢复完整 optimizer 状态
- 避免 fresh optimizer 导致前几百步不稳定

---

### 5. 方法论总结
- 第一层方法论：
  - 训练和推理在隐藏维度上分布不匹配时，可以直接构造训练呈现方式
  - AOI 本质上是让 4K 序列“扮演”长上下文序列
- 第二层方法论：
  - 工程优化不是新方法，但决定固定预算下能训练多少、训练多稳
