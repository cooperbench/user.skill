## d 的 spec（speculative decoding）参数全景

整体是 **EAGLE3** + **MARS verify** + **动态档位（NO_SPEC / D5 / D7 按 batch size 切换）** + 自定义 prebuilt sgl_kernel/speculative.py。

### 1. 启动期：写进 `SGLANG_SERVER_ARGS` 的"全局兜底"
```
--speculative-algorithm EAGLE3
--speculative-num-steps   ${SPEC_STEPS}     # 3
--speculative-eagle-topk  ${TOPK}           # 3
--speculative-num-draft-tokens ${DTN}       # 1 + topk*steps = 1 + 3*3 = 10
--speculative-draft-attention-backend flashinfer
--speculative-draft-model-path ${SCRIPT_DIR}/data/eagle_draft
```
- **算法**：EAGLE3
- **draft 模型**：本地 `data/eagle_draft`
- **draft 注意力 backend**：`flashinfer`（不是 sparse 路径）
- 全局默认 `topk=3`、`steps=3`、`dtn=10`（树状 draft 一次猜 10 个 token）
- `SGLANG_ENABLE_SPEC_V2=0` —— 显式关闭 sglang 新 spec v2 codepath，走老路径

### 2. 调试开关
```
EAGLE_FORCE_NO_ACCEPT=0     # =1 时强制丢掉所有 draft（用于对照 baseline 的 accept-rate）
EAGLE_TRACE_FILE=           # 写空 = 不开 trace；填路径就开
```

### 3. MARS verify 的 θ 阈值（每档不同）
```
EAGLE_MARS_THETA      = 1     # 默认全局
EAGLE_D5_MARS_THETA   = 0.75  # D5 档放松一些
EAGLE_D7_MARS_THETA   = 0.5   # D7 档最宽松
```
对应 G3b 那段把 `prebuilt/sgl_kernel_speculative.py` 拷进 venv 替换的 11-arg 版本 `verify_tree_greedy`，新增了 θ 阈值参数 → MARS（**M**emory-**A**ware **R**etention/**S**caling 之类的 verify 策略）按 θ 接受 draft，θ 越小越激进。

### 4. **核心：动态档位调度（DYNAMIC_MODE）**
```
EAGLE_DYNAMIC_MODE = 1      # 总开关
```
按"当前 running batch size"实时切档：

| 档位 | 触发 BS | 退出 BS | TOPK | STEPS | DTN | MARS θ | 说明 |
|---|---|---|---|---|---|---|---|
| **NO_SPEC** | bs ≥ 31 | bs ≤ 28 | — | — | — | — | 高并发时关掉 spec（GPU 已满，draft+verify 反而拖累） |
| **D5** | 28 < bs | (默认) | 3 | 3 | 10 | 0.75 | 中等并发的"5-token tree" |
| **D7** | bs ≤ 1 | bs ≥ 3 | 3 | 5 | **16** | 0.5 | 单请求/极低并发的"7-step tree"，最大化深度推测 |

DTN 公式 `1 + topk*steps`：
- D5: `1 + 3*3 = 10`
- D7: `1 + 3*5 = 16`
- 全局: `1 + 3*3 = 10`（与 D5 相同）

迟滞窗口（hysteresis）：进档与退档 BS 不同（如 NO_SPEC 31 进 / 28 退），避免在阈值附近抖动反复切换。

### 5. 工作时序
1. **请求来时**先看 running BS，决定 NO_SPEC / D5 / D7。
2. 选档后，draft 模型生成树形草稿（topk × steps）。
3. 主模型一次 `--speculative-num-draft-tokens` token 的 verify。
4. MARS 用本档 θ 判定接受到哪一深度。
5. BS 越界另一档触发线时切换。

### 与 a/b 的对比

| 参数 | a | b | d |
|---|---|---|---|
| TOPK (全局/D5/D7) | 2 | 2 | **3** |
| D5 STEPS | 3 | **4** | 3 |
| D5 DTN | 7 | 9 | **10** |
| D7 STEPS | 6 | 5 | 5 |
| D7 DTN | 13 | 11 | **16** |
| `--max-running-requests` | (b 是 36) | 36 | **64** |
| `--mem-fraction-static` | (b 是 0.75) | 0.75 | **0.7** |
| `--dense-as-sparse` | 在 | 在 | **移除** |
| MARS θ | 同 | 同 | 同 (1 / 0.75 / 0.5) |
| DYNAMIC_MODE | 在 | 在 | 在 |

**d 的 spec 哲学相对 b 的变化**：
- TOPK 全线从 2 升到 3 → **每步分支更宽**
- D7 把 `STEPS×TOPK` 从 5×2=10 推到 5×3=15（DTN 11→16） → **大并发以外的低 BS 段，更激进的树形猜测**
- D5 反而把 STEPS 从 4 调回 3（DTN 9→10，因 TOPK 增到 3）→ **不增加深度只增加宽度**，每步给主模型更多候选
- 配合并发上限 36→64、显存预留 0.75→0.7：**整体往"更高并发吞吐 + 更激进单请求 spec"的方向调**
