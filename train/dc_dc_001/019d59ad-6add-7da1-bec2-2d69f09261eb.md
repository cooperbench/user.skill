什么事网站逆向？ 可以做什么/

> AGENT

网站逆向，就是从一个已经做好的网站出发，反过来分析它“怎么运作”。

## 它通常在看什么

- 前端页面怎么渲染
- 浏览器发了哪些请求
- 接口参数怎么组
- 登录、验证码、签名怎么处理
- 数据是怎么分页、加密、缓存、存储的
- 某个按钮背后实际触发了什么逻辑

## 可以做什么

### 合法常见用途
- 排查网站 bug
- 分析前后端交互流程
- 做自动化测试
- 对接没有文档的内部系统
- 研究页面性能问题
- 做兼容性分析
- 做安全审计，找权限、认证、接口设计的问题
- 在授权前提下做数据提取、迁移、备份

### 安全研究里常见用途
- 看接口有没有越权
- 看登录态有没有问题
- 看前端隐藏功能是否真的受保护
- 看签名、加密、验证码是否只是表面防护
- 复现业务逻辑漏洞

## 常用方法

- 打开浏览器开发者工具看 `Network`、`Sources`、`Application`
- 分析 JS 代码和打包结果
- 观察请求头、Cookie、Token、Local Storage
- 跟踪按钮点击到请求发送的完整流程
- 复现接口调用
- 必要时做代码格式化、断点调试、运行时 Hook

## 结果一般会得到什么

- 接口列表
- 参数生成方式
- 鉴权逻辑
- 页面状态流转
- 数据来源
- 前端混淆或加密的还原方式
- 业务流程图

## 适合哪些场景

| 场景 | 是否适合 |
|---|---|
| 自己公司的系统排错 | 适合 |
| CTF / 靶场 / 授权测试 | 适合 |
| 学习前端与接口原理 | 适合 |
| 未授权抓取、绕过限制、攻击真实网站 | 不适合 |

## 一句话理解

正向开发是“把网站做出来”，网站逆向是“从成品倒推它怎么做的”。
