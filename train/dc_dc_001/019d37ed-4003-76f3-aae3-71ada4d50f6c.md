一般不会。 核心规则就一句话：目标网站看到的，是“最后一跳出口 IP”，不是你链路里经过了几层。 分情况看： 1. `你 -> VPS -> 住宅代理 -> 网站` 这时候网站通常看到的是“住宅代理”的 IP。 只要最后出口还是那个住宅 IP，它不会因为前面绕过 VPS，就自动变成机房 IP。 2. `你 -> 住宅代理 -> VPS -> 网站` 这时候最后出口变成 VPS。 网站看到的就是 VPS 机房 IP，那确实就不再是原来的住宅/原生出口了。 3. `你 -> VPS -> 网站` 这当然直接就是 VPS IP。 真正的风险不在“中转”两个字本身，而在这些地方： - 最后一跳是不是住宅 IP - 有没有 `DNS` 泄漏 - 有没有 `WebRTC` 泄漏 - HTTP 代理有没有乱加 `X-Forwarded-For` - 指纹浏览器本身的时区、语言、定位、ASN 风格是否和出口一致 所以结论是： - 如果你的架构是“VPS 只负责转发，最后出口还是 WebShare/住宅代理”，通常不会把它变成机房 IP - 如果 VPS 成了最终出口，那就会变成 VPS 的 IP 属性 - 对风控来说，即使出口还是住宅 IP，配置不干净也可能被看出“像代理链” 你现在之前那套 `dialer-proxy: Proxies -> webshare`，本质上就是“前面走机场/VPS链路，最后出口还是 webshare”。这种模式下，外部通常看到的仍然是 `webshare` 的出口属性，不是前面的中转机房。 如果你愿意，我可以下一步直接给你画一张“哪种链路保住宅属性，哪种会变机房属性”的小图。
