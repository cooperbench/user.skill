我按 SpecForge 官方文档/源码、EAGLE 三篇论文、EAGLE 官方仓库和 benchmark 资料对了一遍。没有改代码。 **核心结论** 对我们这条 MiniCPM-SALA 管线，**target-regenerated 是正确方向，而且比通用 SpecForge 更必要**。原因不是“原始答案质量差”，而是 draft 要拟合的是我们最终部署 target 的 token 分布、hidden state 分布、量化误差和 SGLang runtime 行为。SpecForge 官方也明确建议生产场景用 target model 重生成数据来提升 acceptance rate。 **实践原则** 1. 数据质量主要体现为 **prompt 分布质量**，不是原始 assistant 答案质量。target-regenerated 后，原答案只用于筛选/分桶/去重，训练标签应来自 target。 2. 数据规模对 EAGLE-3 明显重要。EAGLE-1 论文里 ShareGPT fixed data 和 target-generated 只差一点；但 EAGLE-3 的核心就是解除 feature-prediction 约束，让 draft 能吃到数据规模收益。 3. 训练数据要覆盖部署请求分布：中文、多轮、代码、数学/STEM、长上下文、总结、闲聊都要有。EAGLE 官方 README 也提醒：如果要跑中文这类非英文场景，需要相应语言数据。 4. 不要只看 token-level CE/NLL。EAGLE-2/EAGLE-3 都强调最终指标是 speedup、average acceptance length、acceptance rate；我们已有 v3 教训：probe NLL 好不等于 e2e acceptance 好。 5. 数据集越大，越要按 domain/token budget 控制，而不是简单拼接。SpecBundle 从 ShareGPT/UltraChat 规模扩到 PerfectBlend 1.4M，重点是多域，尤其 code/math。 **重生成是否必要** - EAGLE-1：不是绝对必要。论文 ablation 里 fixed ShareGPT 已经接近 target-generated，说明低成本路线可行。 - EAGLE-3/生产：建议必要。EAGLE-3 论文使用 ShareGPT + UltraChat，并调用 target 生成 responses；SpecForge docs 也推荐 production optimal performance 使用 target regeneration。 -
