## 1. 如何使用 nvidia-modelopt 将模型量化为 NVFP4 格式

### 核心 API

量化核心流程只需三步：加载模型 → `mtq.quantize()` → `export_hf_checkpoint()`。

```python
import torch
import modelopt.torch.quantization as mtq
from transformers import AutoModelForCausalLM
from modelopt.torch.export import export_hf_checkpoint

# 1. 加载模型
model = AutoModelForCausalLM.from_pretrained(
    "path/to/model",
    torch_dtype=torch.bfloat16,
    device_map="auto",
    trust_remote_code=True,
)

# 2. 选择 NVFP4 量化配置
quant_cfg = mtq.NVFP4_DEFAULT_CFG

# 3. 定义校准前向循环
def forward_loop(model):
    for batch in calib_dataloader:
        model(**batch)

# 4. 执行量化
model = mtq.quantize(model, quant_cfg, forward_loop=forward_loop)

# 5. 导出
with torch.inference_mode():
    export_hf_checkpoint(model, export_dir="./quantized_model")
```

### 可用的 NVFP4 配置变体

从 `hf_ptq.py` 源码中可以看到，modelopt 提供了多种 NVFP4 配置：

| 配置名 | 常量 | 说明 |
|--------|------|------|
| `nvfp4` | `mtq.NVFP4_DEFAULT_CFG` | 默认 NVFP4，W4A4 量化 |
| `nvfp4_awq` | `mtq.NVFP4_AWQ_LITE_CFG` | 带 AWQ 优化的 NVFP4 |
| `nvfp4_mse` | `mtq.NVFP4_W4A4_WEIGHT_MSE_FP8_SWEEP_CFG` | 基于 MSE 优化权重缩放 |
| `nvfp4_mlp_only` | `mtq.NVFP4_MLP_ONLY_CFG` | 仅量化 MLP 层 |
| `nvfp4_experts_only` | `mtq.NVFP4_EXPERTS_ONLY_CFG` | 仅量化 MoE expert 层 |
| `nvfp4_omlp_only` | `mtq.NVFP4_OMLP_ONLY_CFG` | 仅量化 attention output projection + MLP |
| `nvfp4_svdquant` | `mtq.NVFP4_SVDQUANT_DEFAULT_CFG` | SVDQuant 优化 |
| `nvfp4_local_hessian` | `mtq.NVFP4_W4A4_WEIGHT_LOCAL_HESSIAN_CFG` | 基于 local Hessian 的权重量化 |
| `w4a8_nvfp4_fp8` | `mtq.W4A8_NVFP4_FP8_CFG` | 混合 FP4 权重 + FP8 激活 |

### 官方命令行用法（`hf_ptq.py` 脚本）

NVIDIA 官方提供的 PTQ 脚本支持一行命令量化：

```bash
# 通过官方 shell 脚本
/path/to/TensorRT-Model-Optimizer/examples/llm_ptq/scripts/huggingface_example.sh \
    --model "path/to/model" \
    --quant nvfp4 \
    --tp 1 \
    --export_fmt hf

# 或直接用 Python 脚本
python hf_ptq.py \
    --pyt_ckpt_path "path/to/model" \
    --qformat nvfp4 \
    --calib_size 512 \
    --calib_seq 512 \
    --batch_size 1 \
    --export_path ./quantized_model \
    --kv_cache_qformat fp8_cast \
    --trust_remote_code
```

## 2. 校准流程详解

### 校准数据选择

从 `hf_ptq.py` 源码可以看到：

- **默认数据集**：`cnn_dailymail` + `nemotron-post-training-dataset-v2`（如果不指定 `--dataset`）
- **支持的数据集**：通过 `get_supported_datasets()` 获取，包括 `pile`、`wikipedia` 等
- **推荐样本数**：**128-512 个样本**（默认 `--calib_size 512`）
- **序列长度**：默认 `--calib_seq 512`

### 校准的 forward_loop 机制

```python
from modelopt.torch.utils.dataset_utils import create_forward_loop, get_dataset_dataloader

# 构建校准数据加载器
calib_dataloader = get_dataset_dataloader(
    dataset_name=["cnn_dailymail"],
    tokenizer=tokenizer,
    batch_size=batch_size,
    num_samples=[512],
    device=device,
)

# 创建前向循环（modelopt 内置工具函数）
calibrate_loop = create_forward_loop(dataloader=calib_dataloader)

# 量化
model = mtq.quantize(model, mtq.NVFP4_DEFAULT_CFG, forward_loop=calibrate_loop)
```

### 手动构建校准数据（不依赖 modelopt 内置函数）

```python
from datasets import load_dataset
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("path/to/model")
tokenizer.padding_side = "left"  # 左填充通常校准效果更好

dataset = load_dataset("cnn_dailymail", "3.0.0", split="train")

def preprocess(examples):
    return tokenizer(
        examples["article"],
        max_length=512,
        truncation=True,
        padding="max_length",
        return_tensors="pt",
    )

calib_dataset = dataset.select(range(512)).map(preprocess, batched=True)

def forward_loop(model):
    for i in range(0, len(calib_dataset), batch_size):
        batch = calib_dataset[i:i+batch_size]
        input_ids = torch.tensor(batch["input_ids"]).cuda()
        attention_mask = torch.tensor(batch["attention_mask"]).cuda()
        model(input_ids=input_ids, attention_mask=attention_mask)
```

### Batch Size 自动检测

`hf_ptq.py` 默认 `batch_size=0`，会自动调用 `get_max_batch_size()` 计算最大可用 batch size。AWQ/SmoothQuant 会使用 2x 内存倍率以避免 OOM。

## 4. `hf_quant_config.json` 格式

根据搜索到的实际样例和 vLLM 文档，格式如下：

```json
{
    "producer": {
        "name": "modelopt",
        "version": "0.41.0"
    },
    "quantization": {
        "quant_algo": "NVFP4",
        "kv_cache_quant_algo": null,
        "group_size": 16,
        "exclude_modules": [
            "lm_head",
            "model.layers.0.self_attn*",
            "model.layers.1.self_attn*"
        ]
    }
}
```

### 关键字段说明

| 字段 | 说明 |
|------|------|
| `producer.name` | 固定为 `"modelopt"` |
| `producer.version` | modelopt 版本号 |
| `quantization.quant_algo` | 算法标识：`NVFP4`、`FP8`、`NVFP4_AWQ`、`FP8_PB_WO` 等 |
| `quantization.kv_cache_quant_algo` | KV Cache 量化算法，可为 null |
| `quantization.group_size` | 量化分组大小，NVFP4 通常为 16 |
| `quantization.exclude_modules` | 排除的模块列表，支持通配符 |

### vLLM/SGLang 识别逻辑

vLLM 通过检测 `hf_quant_config.json` 中的 `quantization.quant_algo` 值来确定量化格式：
- `"NVFP4"` → 使用 `quantization="modelopt_fp4"` 加载
- `"FP8"` → 使用 `quantization="modelopt"` 或 `"modelopt_fp8"` 加载
- `"MXFP8"` → 使用 `quantization="modelopt_mxfp8"` 加载

## 5. 精度保持最佳实践

### 默认排除的层

`hf_ptq.py` 使用 `_default_disabled_quantizer_cfg` 排除关键层，通常包括：
- **`lm_head`** — 输出层对精度至关重要
- **`model.layers.0.self_attn*`** — 第一层 attention（部分模型）
- **MoE 的 router/gate 模块** — 路由决策层不量化
- **MTP 投机解码层** — 通过检测 `mtp_layer_prefixes` 自动排除

### 手动排除层的方法

```python
import copy

quant_cfg = copy.deepcopy(mtq.NVFP4_DEFAULT_CFG)

# 通过通配符排除特定层
quant_cfg["quant_cfg"]["*lm_head*"] = {"enable": False}
quant_cfg["quant_cfg"]["*layers.0*"] = {"enable": False}
quant_cfg["quant_cfg"]["*layers.1*"] = {"enable": False}

# 或使用 disable_quantizer API
# mtq.disable_quantizer(model, wildcard_or_filter_func="*lm_head*")
```

### 推荐策略

1. **校准数据集**：使用与目标任务相关的数据，512 样本通常足够
2. **左填充**（`tokenizer.padding_side = "left"`）通常校准效果更好
3. **AWQ 变体**（`nvfp4_awq`）比纯 NVFP4 精度更好，但校准时间更长
4. **KV Cache 量化**：默认 `fp8_cast`（不需要额外校准，使用常量 amax）
5. **低内存模式**：`--low_memory_mode` 可在加载时边量化，减少峰值内存
6. **验证量化效果**：量化后使用 `mtq.print_quant_summary(model)` 检查量化器分布

### 若 PTQ 精度不足

NVIDIA 推荐 **Quantization-Aware Distillation (QAD)**：
- 使用 BF16 教师模型蒸馏到 NVFP4 学生模型
- 通过 KL 散度损失恢复精度
- 在多个模型上验证可恢复至接近 BF16 精度

## 6. Blackwell (sm_120) GPU 已知问题与建议

### 关键发现

**Dense（非 MoE）模型的 FP4 在 sm_120 上正常工作**。MiniCPM-SALA 不是 MoE 模型，所以这些问题不影响你。

### 已知问题

| 问题 | 影响 | 与 SALA 的关系 |
|------|------|----------------|
| CUTLASS Grouped GEMM 产生垃圾输出 | 仅影响 MoE 模型 | **不影响** |
| TRTLLMGenFusedMoE 不支持 SM120 | 仅影响 MoE | **不影响** |
| SM120 **不支持 FP8 block scaling** | 影响 `fp8_pb_wo` 格式 | 不使用该格式则无影响 |
| FP8 KV Cache | 两架构都支持 | **正常可用** |
| 预量化模型不可用 | 需本地运行 ModelOpt | 已知 |

### SM120 vs SM100 支持矩阵

| 格式 | SM100 (B200) | SM120 (RTX 5090/PRO 6000) |
|------|-------------|--------------------------|
| NVFP4 Dense | 支持 | **支持** |
| NVFP4 MoE | 支持 | 有问题 |
| FP8 per-tensor | 支持 | 支持 |
| FP8 block scaling | 支持 | **不支持** |
| FP8 KV Cache | 支持 | 支持 |

### 建议

- 使用 `NVFP4_DEFAULT_CFG`（dense），在 SM120 上完全正常
- KV Cache 使用 `fp8_cast` 或 `nvfp4_cast`（常量 amax，无需校准）
- 本地 5090 和评测机 PRO 6000 均为 SM120，结果可直接迁移

## 7. 静态 vs 动态量化

### NVFP4 的量化机制

NVFP4 使用**层次化双级缩放策略（Hierarchical Two-Level Scaling）**：

- **权重量化**：静态的，在校准阶段确定缩放因子后固定
- **激活量化**：**动态的**，在推理时实时计算（每个 block 独立计算 amax）
- **Block 粒度**：将张量分为固定大小的 block（通常 group_size=16），每个 block 有独立的缩放因子

### 与其他格式对比

| 特性 | NVFP4 | MXFP4 | FP8 |
|------|-------|-------|-----|
| 权重量化 | 4-bit FP | 4-bit FP | 8-bit FP |
| 激活量化 | 4-bit FP（动态） | 仅权重 | 8-bit FP |
| 缩放策略 | 双级层次化 | 单级 block | per-tensor / per-channel |
| FLOPS 提升 vs BF16 | 4x | 2x | 2x |

### 在 `hf_ptq.py` 中的体现

```python
# 从源码第 558-562 行
use_calibration = need_calibration(quant_cfg)

if not use_calibration:
    warnings.warn("Dynamic quantization. Calibration skipped.")
```

对于 NVFP4，`need_calibration()` 返回 `True`，因为需要校准来确定最优的权重缩放因子。激活的缩放在推理时动态计算。

### KV Cache 的 cast vs calibration

```python
# fp8_cast / nvfp4_cast: 使用常量 amax，无需校准数据
# fp8 / nvfp4: 使用数据驱动的校准确定 amax

_KV_CAST_FORMATS = {"fp8_cast", "nvfp4_cast"}  # 源码第 126 行
```

## 总结：针对 MiniCPM-SALA 的量化方案

结合以上调研和你的项目情况，推荐的量化路径：

```python
import torch
import modelopt.torch.quantization as mtq
from modelopt.torch.export import export_hf_checkpoint
from transformers import AutoModelForCausalLM, AutoTokenizer

# 1. 加载 MiniCPM-SALA 模型
model = AutoModelForCausalLM.from_pretrained(
    "/root/shared-nvme/openbmb/models/MiniCPM-SALA",
    torch_dtype=torch.bfloat16,
    device_map="auto",
    trust_remote_code=True,
)
tokenizer = AutoTokenizer.from_pretrained(
    "/root/shared-nvme/openbmb/models/MiniCPM-SALA",
    trust_remote_code=True,
)
tokenizer.padding_side = "left"

# 2. 准备校准数据（512 样本）
from datasets import load_dataset
dataset = load_dataset("cnn_dailymail", "3.0.0", split="train").select(range(512))

def forward_loop(model):
    for i in range(0, 512, 4):
        texts = dataset[i:i+4]["article"]
        inputs = tokenizer(texts, max_length=512, truncation=True,
                          padding="max_length", return_tensors="pt").to("cuda")
        model(**inputs)

# 3. NVFP4 量化
quant_cfg = mtq.NVFP4_DEFAULT_CFG
model = mtq.quantize(model, quant_cfg, forward_loop=forward_loop)

# 4. 检查量化摘要
mtq.print_quant_summary(model)

# 5. 导出
with torch.inference_mode():
    export_hf_checkpoint(model, export_dir="./quantized_sala")
```

**但注意**：MiniCPM-SALA 是自定义架构（`MiniCPMSALAForCausalLM`），不是标准 HuggingFace 模型，直接用 `AutoModelForCausalLM.from_pretrained` + `mtq.quantize` 可能不兼容。更可能需要在 SGLang 内部通过已有的 `modelopt_fp4` 量化路径来处理（即在 `preprocess_model.py` 中集成 SGLang 的量化导出流程）。
