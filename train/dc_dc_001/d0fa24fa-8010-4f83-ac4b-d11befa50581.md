## 根因

日志里两条关键记录（[main.log:6790, 6796](Library/Logs/Claude/main.log)）：

```
[warn] [SettingsResolver] Ignoring defaultMode "bypassPermissions" from project tier
        — repo-committed settings can't default to bypassPermissions
[info] [CCD] Downgrading session ... bypassPermissions → acceptEdits at start
        — bypassPermissionsModeEnabled pref is off
```

1. **`bypassPermissionsModeEnabled` 这个 app 偏好是关闭的** ← 真正原因
   只要它关着，desktop 会：
   - 新会话启动时把 bypassPermissions 降级成 acceptEdits
   - 运行中点切换到 bypassPermissions 一律拒绝 → 你看到的 "Permission mode couldn't be changed"

2. **`~/.claude/settings.json` 里的 `"defaultMode": "bypassPermissions"` 被无视**
   因为 `/Users/user_0a329be7/.claude/settings.json` 被 SettingsResolver 当成"project tier"（项目级、可被仓库 commit 的配置）。安全策略禁止 project tier 默认成 bypassPermissions。这条只是噪音，但即使修了也无济于事 —— 上面第 1 条才是堵点。

## 修复

去 Claude app **Settings → Code**（或 Developer 一类的菜单）里找一个类似 **"Enable bypass permissions mode" / "Allow bypassing permissions"** 的开关，打开它。开了之后 `bypassPermissionsModeEnabled` 才会变成 true，权限模式选择器里的 bypassPermissions 才能切过去。

偏好不在 `Library/Application Support/Claude/Preferences`（我看过了），应该存在 app 自己的 IndexedDB/Local Storage 里，所以只能从 UI 改，不建议直接动文件。

## 附带提醒

`~/.claude/settings.json` 里有一行明文 HuggingFace token (`HF_TOKEN=hf_...`)，如果这个文件会被同步/备份/或者你将来 commit 类似目录到仓库，建议挪到环境变量或 keychain 里。

> AGENT

找到真正原因了。看这两个正在运行的 `claude` 子进程的启动参数：

```
PID 23772 (今早 8:44 启动): --permission-mode acceptEdits   ← 当前会话
PID 23733 (今早 8:44 启动): --permission-mode auto          ← 另一个会话
```

两个进程都**没有** `--dangerously-skip-permissions` 标志。配合之前的报错：

> Cannot set permission mode to bypassPermissions because **the session was not launched with --dangerously-skip-permissions**

## 真正的根因：时序问题

1. 你今早 08:44 启动 Claude code 会话时，`bypassPermissionsModeEnabled` 偏好还是 off → 子进程被以 `--permission-mode acceptEdits` 启动，没有 `--dangerously-skip-permissions` 标志
2. 之后（Local Storage 时间戳显示 08:47）你打开了 UI 上的开关
3. 但开关只影响**新会话的启动参数**，没法给已经在跑的子进程注射 `--dangerously-skip-permissions`
4. 所以你现在切 bypassPermissions 还是被 Claude Code 子进程拒绝 —— 因为它启动时就没拿到那个 launch flag

证据链：
- [main.log:6796](Library/Logs/Claude/main.log) `08:44:22` — "Downgrading bypassPermissions → acceptEdits at start — bypassPermissionsModeEnabled pref is off"（启动那一刻 pref 还是 off）
- Local Storage 最后修改时间 `08:47`（开关是 08:47 才被打开）
- `ps aux` 显示当前 PID 23772/23733 的命令行就是 `acceptEdits` / `auto`，不带 dangerous flag

## 修复

**关掉当前 Claude code 会话，新建一个**。新会话启动时 desktop 会读到现在已 ON 的 pref，给子进程加上 `--dangerously-skip-permissions`，之后才能在运行中切到 bypassPermissions。

验证方法：新会话起来后再跑 `ps aux | grep claude`，应该能看到 `--dangerously-skip-permissions` 出现在命令行里。

## 顺带说一下另一条无关日志

`[SettingsResolver] Ignoring defaultMode "bypassPermissions" from project tier` —— 你的 `~/.claude/settings.json` 因为 CWD 就是 `/Users/user_0a329be7`，被 resolver 当成 project tier（项目目录恰好就是 home 目录）。这条独立于上面的问题，即使解决了也没用 —— launch flag 必须由 desktop 的 toggle 触发，不能靠 settings.json 自带。建议把那个 `defaultMode` 从 settings.json 里删掉，避免混淆。
