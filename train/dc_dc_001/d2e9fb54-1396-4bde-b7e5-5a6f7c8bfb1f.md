Flat/Packed (Slab) - **问题**：模型有几千个小的 tensor，直接逐个 H2D 会产生几千次 copy 调度 - **方案**：离线把几千个小 tensor 打包成少数几个大块（slab，按 dtype 分） - **效果**：copy 调用从几千次 → 1~3 次 ### 2. Pinned Memory (Page-locked) - **问题**：pageable RAM 会走隐式 staging（CPU memcpy → pinned staging → DMA），吞吐低且抖动 - **方案**：使用 pinned memory 让 DMA 直接读写 host memory - **效果**：带宽从 ~2-13 GB/s → 18-24 GB/s（接近 PCIe 上限） ## 关键结果 | 方法 | H2D 带宽 | D2H 带宽 | |------|----------|----------| | per-tensor pageable | ~10-13 GB/s | ~2-3 GB/s | | per-tensor pinned | ~21 GB/s | ~18 GB/s | | slab + pinned | ~21-22 GB/s | ~19-20 GB/s | ## 验证结论 - **slab view 不拖慢 forward**：TE 和 DiT 的 forward 时间与 baseline 几乎一致 - **swap 误差 ≤ intrinsic noise**：DiT 本身是非确定性的，swap 后的差异（~0.06-0.15）不超过模型本身的噪声 - **allocation 不是瓶颈**：alloc_seconds ~0.03s，h2d_seconds ~1.87s ## 下一步建议 1. offload store 设计成长期 pinned，swap 热路径只做 DMA 2. slab 按 layer/chunk 切分，实现 prefetch/overlap 3. 参考 ComfyUI 的 `cudaHostRegister` + 预算控制 你们现在是在继续哪部分的工作？
