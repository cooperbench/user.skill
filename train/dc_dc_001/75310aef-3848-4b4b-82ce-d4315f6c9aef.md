> DEVELOPER

给我讲讲 claude 的/loop

> AGENT

`/loop` 是一个让你把某个提示或 slash command 按固定节奏反复执行的工具。 ## 两种用法 **1. 固定间隔模式** ``` /loop 5m /foo /loop 30s 检查构建状态 ``` 第一个参数是间隔（`30s` / `5m` / `1h` 等），第二个是要重复执行的内容。harness 会到点就把那段提示重新喂给我一次。 **2. 动态自定节奏模式（省略间隔）** ``` /loop 盯着这个后台任务，完成就告诉我 ``` 不写间隔，我自己用 `ScheduleWakeup` 决定下一次什么时候醒。每轮我评估"还要不要继续 / 多久后再看"，可以根据情况收紧或放宽。 ## 典型场景 - 轮询长跑任务：`/loop 2m 看看 bench 跑完没` - 周期性维护：`/loop 10m /babysit-prs` - 等一次性事件：动态模式更合适，事件来了就退出 ## 节奏选择（动态模式） Anthropic prompt cache TTL 是 5 分钟，所以选 `delaySeconds` 有自然分界： - **< 270s**：缓存还热，适合频繁查状态 - **>= 1200s**：反正要付一次 cache miss，干脆睡久点 - **避开 300s 这个甜区陷阱**：付了 cache miss 又没赚到长间隔 空闲巡检默认 1200–1800s。 ## 怎么停 - 固定间隔：`/loop` 不带参数，或者直接打断 - 动态模式：我不再调 `ScheduleWakeup` 就自然结束 ## 区分 不要和 `/schedule` 混：`/schedule` 是 cron 风格的远程定时 agent（比如每天 9 点跑一次），跑在云端；`/loop` 是当前会话里反复唤醒同一个我。

短答：**Claude Code 没有内置 `/goal`**。没有"设个目标，自己跑到收敛"的官方命令。 ## 现有能拼出来的最近似形态 | 原料 | 作用 | |---|---| | `/loop`（动态模式） | 反复唤醒同一个会话，自定节奏 | | 自定义 slash command（`.claude/commands/*.md`） | 把目标 + 评估准则固化成可复用提示 | | Agent / 子 agent | 跑独立子任务，结果回传主 agent | | 记忆 / 文件 | 跨轮持久化"已尝试方案、当前最佳分数" | | Hooks | 每轮结束自动触发评估 / bench | 把这些组合起来就能搭一个粗糙的 auto-research 循环，但要你自己写。 ## 一个最小骨架 ``` .claude/commands/goal.md # 定义目标 + 评估方式 + 改一步策略 runs/best.json # 当前最佳得分 + 配置 runs/history.jsonl # 所有尝试记录 ``` 调用方式： ``` /loop /goal 把 mini_bench S8 提到 9.0+ ``` 每一轮 `/goal` 做的事：读 `best.json` → 提一个改动假设 → 改代码 → 跑 bench → 写回 history → 如果更好就更新 best → 否则回滚。`/loop` 负责持续唤醒。 ## 为什么没现成的 Karpathy 那种 auto-research 的难点不在调度，而在 **可信的自动评估** 和 **搜索空间定义**。Claude Code 留这一层给用户自己定义是合理的——通用 `/goal` 没法知道你这个项目"更好"是什么意思（是 bench 数还是 mcq 准确率？是否允许显存涨？）。 ## 想真正做这件事 - 想轻量验证想法：`/loop` + 一个写好的 `/goal` 自定义命令足够 - 想正经做：用 **Claude Agent SDK** 自己写一个外层 loop，里面调 Claude Code 当 worker，外面控制评估、早停、预算上限。比硬塞进 Claude Code 干净 要不要我帮你在 `bench/` 那边写一个最小的 `/goal` 模板，专门盯 mini_bench 分数？
