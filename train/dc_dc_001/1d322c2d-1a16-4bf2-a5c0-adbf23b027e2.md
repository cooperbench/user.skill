明白——主会话 Opus 4.7 能跑，是因为你用 `--model "Claude Opus 4.7"` 直接把"显示名"喂给了网关，而这个网关（是个 one-api 中继）**只认显示名**，凡是规范 ID 都返 503。

刚才测的证据：

| 发给网关的 model | 结果 |
|---|---|
| `Claude Opus 4.7` / `Claude Sonnet 4.6` / `Claude Haiku 4.5` | 200 OK |
| `claude-opus-4-7` / `claude-sonnet-4-6` / `claude-haiku-4-5-20251001` | **503 "无可用渠道"** |

subagent 初始化失败的根因就是这个：Claude Code 在 spawn 子 agent 时，会按 agent 定义里的 `model: opus|sonnet|haiku` 走一次**模型别名解析**，解析结果是**规范 ID**（`claude-opus-4-7` 这种），不是你 `--model` 传的显示名。于是请求打过去就 503。内置 Explore/general-purpose 这些大多解析成 haiku/sonnet，所以几乎必挂；即使 subagent 明确写 opus，解析出来是 `claude-opus-4-7` 也一样 503。

这不是 API 生命周期问题，是网关的 model 映射缺失 + harness 别名解析路径绕过了你 CLI 传的显示名。
