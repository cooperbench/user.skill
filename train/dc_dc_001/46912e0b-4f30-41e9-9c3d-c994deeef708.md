## Flash Attention 3 / 4 与 Blackwell GPU 研究报告

### 1. Flash Attention 版本演进

| 版本 | 目标架构 | 状态 | 包名 |
|------|---------|------|------|
| FA2 (v2.x) | SM80 (A100), SM86, SM89 | 稳定 | `flash-attn` |
| FA3 (v2.x 分支) | SM90 (H100/H200 Hopper) | 稳定 | 集成在 `flash-attn` 和 `flashinfer` 中 |
| FA4 (v4.0.0.beta5) | SM80/SM90/SM100/SM120 (Blackwell) | **Beta** | `flash_attn_4` (独立包) |

### 2. FA3 是否支持 Blackwell (SM_120)？

**不直接支持。** FA3 专门为 Hopper (SM90) 设计，利用了 Hopper 独有的硬件特性：
- TMA (Tensor Memory Accelerator)
- WGMMA (Warpgroup Matrix Multiply-Accumulate)
- 异步流水线

SM_120 (Blackwell GeForce/PRO 6000) 没有与 Hopper 完全相同的指令集路径。SM_120 的 flash-attn 实现实际上是**基于 SM80 (Ampere) 的 MMA 指令** (`mma.sync.aligned.m16n8k16`)，而非 FA3 的 Hopper 优化路径。

### 3. FA3 相比 FA2 的性能提升

在 H100 (Hopper) 上：
- **FP16**: 1.5-2.0x 加速，达到 740 TFLOPS/s（75% 利用率 vs FA2 的 35%）
- **BF16**: 达到 840 TFLOPS/s（85% 利用率）
- **FP8**: 接近 1.2 PFLOPS/s，误差比基线 FP8 低 2.6x
- 精度：FP16 RMSE 1.9e-4，与 FA2 相同

**但这些数字仅适用于 Hopper，不适用于 Blackwell SM_120。**

### 4. Flash Attention 4 (FA4) — 真正的 Blackwell 方案

**FA4 确实存在！** 这是专门为 Blackwell 架构协同设计的版本：

- **最新版本**: `fa4-v4.0.0.beta5`（2026年3月23日发布，就在2天前）
- **SM_120 支持**: 前向/反向传播、varlen、Split-KV (FlashDecoding)、Paged KV Cache
- **性能**: 达到 1,605 TFLOPS/s，利用 Blackwell 71% 理论峰值
- 比 FA3 在对应架构上还有进一步提升（1.3x 超越 cuDNN）
- 使用 **CuTe DSL**（Python 域特定语言），编译时间比旧版快 20-30x
- 需要 **CUDA 13**

**关键限制**: FA4 目前是 beta 版，SM_120 实现基于 SM80 的 MMA 指令子类化，共享内存 99KB。FP4/FP8 的 attention kernel 支持在 FA4 中尚未明确文档化。

### 5. FA3/FA4 是否支持 FP4/FP8？

| 特性 | FA3 (Hopper) | FA4 (Blackwell SM_120) |
|------|-------------|----------------------|
| FP8 Attention | 支持（H100） | 未明确支持 SM_120 |
| FP4 Attention | 不支持 | 未实现 |
| BF16/FP16 | 支持 | 支持 |

**重要区别**: FP4/FP8 量化通常用于 **GEMM (权重矩阵乘法)**，而非 attention kernel 内部。你们的 NVFP4 量化方案量化的是 Linear 层权重，attention 的 QKV 计算仍然在 BF16/FP16 下进行。所以 attention kernel 是否支持 FP4 对你们的方案影响不大。

### 6. SGLang 是否支持 FA3/FA4？

**当前状态**:
- SGLang 使用 **flashinfer** 作为主要 attention backend
- FlashInfer 0.6.x 对 SM_120 的支持是**基于 FA2 模板**，不是 FA3
- SGLang 也有 `flashattention_backend.py`（直接调用 flash-attn 包），但 MiniCPM-SALA 使用的是自定义的 `minicpm_flashinfer` backend
- **SGLang 目前不支持 FA3 或 FA4 on SM_120**

### 7. FlashInfer 与 flash-attn 的关系

| 方面 | flashinfer | flash-attn (Dao-AILab) |
|------|-----------|----------------------|
| 定位 | 推理引擎的 attention backend | 通用 attention kernel 库 |
| 特色 | Paged KV Cache、Ragged Tensor、MLA 等推理优化 | 核心 attention 算法研发 |
| FA3 | 已在 SM90 上采纳 FA3 流水线设计 | FA3 原创者 |
| SM_120 | 基本支持（FA2 模板） | FA4 beta 支持 |
| SGLang 集成 | 主要 backend | 备选 backend |

FlashInfer 开发者明确表示会"学习 FA3 的流水线设计"，并已在 SM90 上实现了 FA3 backend。但 SM_120 上仍停留在 FA2。

### 8. 对我们 SOAR 比赛的影响分析

**结论：FA3/FA4 不是当前优先优化方向。** 原因：

1. **环境限制**: 官方镜像内置 flashinfer 0.6.1 和 sgl-kernel 0.3.21。要用 FA4 需要安装 CUDA 13 + CuTe DSL + flash_attn_4 包，这在 2GB 提交限制和 `prepare_env.sh` 时间限制下极难实现。

2. **架构兼容性**: MiniCPM-SALA 使用自定义的 `minicpm_flashinfer` backend + `hybrid_linear_attn_backend`（Lightning Attention）。即使装了 FA4，也需要大量代码改动才能对接。

3. **SM_120 的 FA 现状**: 无论是 flashinfer 还是 flash-attn，SM_120 上的实现都是基于 SM80 的 MMA 指令，并非真正利用 Blackwell 独有的 TMEM 和 5th-gen Tensor Core。性能提升有限。

4. **瓶颈不在 attention**: 对于推理服务，attention 只是计算的一部分。NVFP4 量化（加速所有 Linear 层 GEMM）和 EAGLE3 投机采样（减少解码步数）是更直接有效的优化手段。

### 9. 总结

| 问题 | 答案 |
|------|------|
| FA3 是否支持 Blackwell SM_120？ | **否**，FA3 专为 Hopper SM90 设计 |
| FA4 是否存在？ | **是**，v4.0.0.beta5（2026-03-23），支持 SM_120 |
| FA3/FA4 性能提升？ | FA3 在 H100 上 1.5-2x；FA4 在 Blackwell 上达 1605 TFLOPS |
| FA3/FA4 支持 FP4？ | **否**，attention kernel 暂无 FP4 |
| SGLang 支持 FA3/FA4？ | **否**，SM_120 上仍用 FA2 模板 |
| flashinfer vs flash-attn？ | 独立项目，flashinfer 面向推理优化，已采纳部分 FA3 设计 |
| 对 SOAR 比赛是否值得投入？ | **否**，环境限制大、改动多、收益不确定，优先做 NVFP4 + EAGLE3 |
