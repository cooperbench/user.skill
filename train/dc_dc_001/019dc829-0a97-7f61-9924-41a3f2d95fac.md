1. [eagle_info.py:667](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:667)

   风险：混合 batch 中某条请求 finish 后，未完成请求的 GPU seq_lens 可能滞后；后续 draft extend / verify rollback / mamba update 读 GPU seq_lens 时会错位，表现为 accept rate 掉、位置/缓存状态漂移，甚至坏答案。当前默认 topk=1 不触发，但这是 topk>1 的高风险正确性点。  
   离线验证：构造 `topk=2/4, page_size>1`，同 batch 放一个短 `max_new_tokens` 请求和一个长请求，让短请求在 verify 中 finish；每轮 assert `batch.seq_lens.cpu()==batch.seq_lens_cpu`，并对比 no-spec 输出和 spec 输出。

   热点：这是 per-token 强同步，且发生在 `EV_verify_accept` 后，直接阻断 target forward 后续 GPU work overlap。`draft_token_num` 很小，拷完整二维结构收益低。  
   建议：把“每 req accepted token ids + accepted count + finished flag”打包成小的 pinned CPU buffer，一次 async D2H 后再 Python loop；或者至少只拷 `accept_length` 和已接受 token id，避免 `predict.tolist()` 全量同步。  
   离线验证：用已有 NVTX `EI_accept_index_tolist` / `EI_predict_tolist` 采集 1/8/16 batch，比较同步时间、tok/s、`ori_accuracy`；再用固定 logits replay 确认输出 token 序列逐步一致。
