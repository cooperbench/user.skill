If FlashInfer CUDA graph replay or plan metadata still reads any stale suffix, target-verify attention can include pages from previous longer batches, lowering EAGLE accept rate.

2. [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:267): GPU parent construction is not semantically identical to the old CPU BFS.
   The old code only traversed nodes reachable from user_4813494d `0` and preserved the first seen parent. The new kernel scans every node `p` and assigns any child it finds, so disconnected/stale edges or duplicate child links can overwrite parentage. This parent map feeds topk>1 target-verify GLA state selection via the CUDA graph replay path at [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:852). Wrong parent state directly changes verify hidden states/logits and can reduce accept length.
   Minimal fix: make the Triton builder preserve user_4813494d-reachable BFS/seen semantics, or keep CPU fallback behind a correctness env for topk>1 until validated.
   Validation: unit-test GPU parent output against the old CPU builder for normal trees plus adversarial stale/disconnected/duplicate edges; then compare topk>1 verify logits/accept lengths eager vs CUDA graph.

3. [eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:1107): sparse table writes now address by `batch.reqs[i].req_pool_idx` instead of `batch.req_pool_indices[i]`.
   This is intended to avoid advanced indexing overhead, but it changes the source of truth. If EAGLE filtering, merge, padding, or rollback leaves `batch.reqs` and `batch.req_pool_indices` temporarily out of sync, k1/k2 sparse pages get written to the wrong request row. That can corrupt later sparse attention and indirectly reduce accept rate.
   Minimal fix: preserve old semantics by writing to `batch.req_pool_indices` values, but fetch them once to CPU if the goal is avoiding per-row GPU scalar indexing. At least add an assertion in this path that `int(batch.reqs[i].req_pool_idx) == int(batch.req_pool_indices[i].item())` under a debug env.
   Validation: mixed batch with one finished request plus continuing requests, then assert sparse k1/k2 row contents match the old `write_sparse_k*` path after verify/rollback.
