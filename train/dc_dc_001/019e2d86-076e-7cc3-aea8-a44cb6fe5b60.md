SpecForge 训练 loss 是 full draft-vocab soft target 的 LogSoftmaxLoss；我们用 topK + full logsumexp 的 `LK^lambda` acceptance proxy，更贴近 spec acceptance。见 [train.py](/user_4813494d/openbmb/eagle/training/sala_draft/train.py:197)。 4. SpecForge 默认 TTT 长度 7；我们当前训练 TTT=3，生产 D7 属于 stretch。见 [train.py](/user_4813494d/openbmb/eagle/training/sala_draft/train.py:122)。 5. 我们有 SpecForge 没有的 SALA 特化：AOI 长上下文位置、cross-doc packing、segment tail mask、NVFP4 forward GEMM、production quantized target/hook 对齐。 **我们做得好的** - 数据采集更贴近真实部署：不是 HF forward，不是纯 prefill，走量化 target + SGLang server hook，能暴露生产 decode/runtime 差异。 - 采集校验很严：长度、mask、prompt-last、generated prefix、hook 文件清理都有 gate。见 [collect.py](/user_4813494d/openbmb/eagle/pipelines/target_regen/collect.py:163)。 - 训练目标更工程化：response-only mask、AOI、LK loss、topK sparse target，和 MiniCPM-SALA 的长上下文/提交包目标更一致。 - packing 做得好：per-segment doc id、AOI、tail mask，解决短样本 padding 浪费，同时避免跨样本污染。见 [packing.py](/user_4813494d/openbmb/eagle/training/sala_draft/packing.py:1)。 **主要不足** - 扩数基础设施弱于 SpecForge：`collect.py` 只有单 `api-base`，没有官方那种多 server 地址调度；resume 也偏手工，缺全局 manifest。 - 数据源配比固定且池子偏小。现在 20K 可行，但 100K+ 时默认 `max_stem_zh/max_open_code/max_codeforces` 会卡住，需要引入更多源并按 token/domain 而不是样本数配比。 - 存储会先爆：脚本估算约 `25.4KB/token`，4096 tokens 最坏接近 100MB/sample；100K 最坏约 10TB，实际也可能 5TB 级。继续 flat `.pt` per sample 会遇到 inode/IOPS/索引成本。 - 评估选择仍偏 proxy：`OOD step0` 有用，但不能替代 D5/D7 runtime accept、公开集 accuracy、no-spec/spec 一致性。 - sparse topK=128 可能限制大规模收益。官方 full logits/target-head 路线没有这个截断；我们至少应记录 topK mass 并 A/B K=256/512。 - 多轮能力弱：我们的 target_regen 基本是 first user prompt；SpecForge 会逐个 user turn regenerate，保留 history。 **建议路线** 1. 先补规模化采集层：多 `api-base`、`--resume` 按 `source_id/rid` 跳过、atomic save、manifest、source/length/EOS/topK-mass 统计、分 shard 目录。 2. 先做 `100K` pilot，不直接上 500K。保持 20K prod 为 baseline，新增样本必须 source_id 去重，重建 vocab cache。 3. 数据混合改成“token budget + domain budget”：reasoning/STEM/code/general chat/long-context 分桶，按 heldout accept gap 动态调权。 4. 存储改造优先级很高：至少分组目录 + manifest；更好是 aux_hidden NVFP4 压缩、topK values fp16、indices int32，或 shard container，避免百万 `.pt`。 5. 训练侧先保 TTT=3 扩数，另开小实验做 TTT=5、EMA、HASS scheduled self-prediction。不要把这些和 100K 扩数混在一个变量里。 6. 每个候选必须跑四个 gate：`OOD step0/1/2`、public accuracy、D5/D7 accept/speed、no-spec/spec 输出一致性。 我建议下一步先落一个 `v2mix_100k` 的可复现数据计划和采集 manifest，再开始跑。当前工作区没有 `eagle/data` / `eagle/weights` 实物，所以这次没有复算真实长度分布或训练曲线，也没有改代码。
