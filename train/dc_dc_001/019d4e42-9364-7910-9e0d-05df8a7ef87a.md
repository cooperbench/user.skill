**比赛本质** 这场比赛比的不是“谁把 `train.csv` 拟合得最好”，而是“谁能让固定的 Nemotron 基础模型，更稳定地做这类看例子找规律的推理题”。 提交物不是答案表，而是一个 **LoRA adapter**。评测时，官方把你的 LoRA 挂到固定基础模型上，让模型现场做隐藏题，再按正确率计分。官方说明页：[Kaggle 比赛页](https://www.kaggle.com/competitions/nvidia-nemotron-model-reasoning-challenge)。 这点决定了策略重心： - `train.csv` 一共 9500 条，`test.csv` 只有 3 条。这个 `test.csv` 更像格式示例，不要当正式评测集。 - 每条题目内部都带了示例，模型不是空手解题，而是要先读 prompt 里的 few-shot 例子。 - 每类题的示例数不固定，大多在 3 到 5 个，bit 题更多，通常 8 到 11 个。 - 答案都很短：数字、二进制串、短词组、Roman numeral、符号串。 **这套数据真正训练什么** 它训练的是三层能力： 1. 看懂题里给的少量例子 2. 识别背后的规则 3. 给出干净、准确、格式稳定的最终答案 所以这不是知识问答，也不是开放生成。它更接近“上下文归纳能力”的比赛。 **对数据合成的判断** 这类题非常适合合成数据，因为大部分标签都能用规则直接算出来，天然干净，几乎不需要人工标注。 但不是所有题型的合成价值一样大。建议分三层看： | 优先级 | 题型 | 原因 | |---|---|---| | 高 | bit / text cipher / equation | 规则空间大，模型容易学到表面模式，最需要更广覆盖 | | 中 | gravity / unit conversion | 规则简单，但可以做边界、格式、四舍五入强化 | | 低 | numeral system | 公开训练集里几乎就是固定映射，扩充价值有限 | **怎么合成数据** **一类：直接可控、应大量合成** `gravity` - 每题随机采样一个隐藏 `g` - 给 3 到 5 个 `(t, d)` 示例 - 再问一个新 `t` - 统一保留两位小数 - 覆盖小数位、边界值、接近整数、接近舍入临界点 `unit conversion` - 本地数据看起来几乎就是每题一个固定比例 `y = kx` - 比例范围大约在 `0.5` 到 `2.0` - 可大量生成不同 `k`、不同小数精度、不同示例数 - 重点做“容易因为舍入出错”的题 这两类的价值不是增加“新知识”，而是增强模型对数字计算、读题、输出稳定性的掌握。 **二类：高价值，但必须严格控质量** `text cipher` - 应该用一个小型规则语言来生成 - 规则可由 `shift / rotate / xor / and / or / not / majority / choose` 等组成 - 每题随机采样一个程序，再自动生成若干输入输出对 - 关键不是能生成，而是要保证“示例足够区分这条规则，不会存在多种规则都解释得通” 如果不做这一步，模型学到的可能只是“某些输入长这样，输出常长那样”，不是规则归纳。 `equation transformation` - 公开集里其实混了两种东西： - 数字式变换 - 符号串变换 - 不建议混在一起乱造 - 应拆成若干小家族，每个家族有自己的生成器 - 例如： - 数字拼接 - 位数重排 - 自定义运算符 - 符号逐字符替换 - 局部删改或镜像 - 每个小家族单独控分布，最后再按比例混合 这类题最容易“看起来像同类，实际上规则完全不同”，不拆会把模型教乱。 **怎么验证合成数据** 原则只有一句：**合成数据必须先证明“规则正确”，再证明“分布像比赛”，最后证明“加进去能涨分”。** 建议把验证拆成 5 层。 1. 规则正确性验证 每条合成题都必须能被程序反算，答案唯一，不能靠模型打标签。 2. 可解性验证 题目给出的示例要足以推出答案，不能出现“示例不够，所以答案不唯一”。 3. 分布相似性验证 至少对齐这几件事： - 六大题型比例 - 每题示例数分布 - 答案长度分布 - 数值范围 - 小数精度 - 文本题句长与词表规模 - bit / equation 的规则复杂度 4. 独立验证集验证 不要只用随机切分。至少保留三套验证： - 原始训练集随机切分 - 按规则或参数范围切分的更难验证集 - 人工设计的边界题验证集 5. 提交环境验证 官方是生成文本后再抽答案。要单独验证： - 最终答案是否总在最后 - 是否总带 `\boxed{}` - 推理过程里有没有多余数字干扰抽取 - 输出会不会太长，导致答案没来得及出现 **哪些做法容易踩坑** 1. 只做“大量简单题” 会让模型更会套模板，但不一定更会归纳复杂规则。 2. 用模型生成答案，再把它当真值 这类比赛里，标签本来就应该可程序验证，没必要引入脏标签。 3. 合成分布偏得太远 例如 text cipher 全做简单字母移位，或 bit 题只做 xor 掩码，都会让模型学偏。 4. 只看训练损失 这类任务最常见的问题不是不会学，而是学会了错误捷径。 5. 忽视输出格式 官方会从生成文本里抽最终答案。答案对了，格式错了，照样丢分。 **怎么使用这些数据** 建议不是把所有数据混在一起一把训，而是分阶段用。 **阶段 1：先把基础模式学稳** -
