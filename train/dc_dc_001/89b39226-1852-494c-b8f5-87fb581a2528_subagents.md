3	2026-04-25 起。**暂判**为 draft 训练分布问题，非 runtime / 量化 bug。本文记录线索、诊断设施、实验数据、未排除的挑战面。结论留有回旋——见 §6。
4	
5	## 1. 现象
6	
7	线上偶发：单 req 在长生成中段，`accept_len` 严格落到 1.00（spec_steps + tree 全废，只剩 bonus 根 token），且持续 N 步不恢复。原始线索：
8	
9	```
10	[2026-04-25 16:28:45] Decode batch, #running-req: 1, #full token: 6015, ...
11	  accept len: 1.00, accept rate: 0.00, cuda graph: True,
12	  gen throughput (token/s): 99.36
13	```
14	
15	吞吐从 ~200 tok/s 跌到 99 tok/s，verify tree 仍按 dtn=7 跑（`#full token` 每 step +43），所以 spec decode 路径在跑、就是全部 reject。

65	## 5. 暂判结论
66	
67	**EAGLE-3 v3 draft 在 long-context markdown/code 转换、reasoning special token、特定论述连词处预测准度不足**。
68	
69	支持证据：
70	- Toggle 维度（FP4 / cuda graph）都不能消除 → 排除 runtime / 量化机制
71	- Hidden state norms 健康（120-190 区间稳定，无 NaN/Inf）→ target 喂给 draft 的输入是 healthy
72	- Target 在 collapse 期间持续输出 contextually 合理的 token（不是死循环）
73	- Draft 反复提议 1348/1358/1379/1467/2902 等低频常见子词 → 模式坍塌到 prior 高的 token
74	- 不同 ckpt（v2/v3）线下都报告过偶发——是 spec decode + 这个训练分布的共性问题
75	
76	非确定性观察：相同 seed prompt 重复跑，**触发 step 不一致**（kernel 累加顺序非确定性），但**触发文本特征一致**。决定性的是文本，不是 step。
77	
78	## 6. 未排除的挑战面
79	
80	判定写"暂判"是因为下面三条没有铁证：
81	
82	1. **可能是 target distribution 高熵 vs draft 弱**。Markdown heading 后的 token 选择本身分散度高，任何 draft 在这种位置都难匹配 target argmax。区分需要更大更强的 draft 做对比——目前没有。
83	2. **可能是 d2t / hot_token_id 覆盖不全**。Draft vocab 32K，target vocab 73448；`hot_token_id` 把 32K 映射到 target 子集。如果 collapse 处 target 的 argmax 不在该子集内，draft 数学上永远无法提议这个 token，就强制 reject。**未实测**——是一项 30 分钟的检查，能 hard-cut 这个分支。
84	3. **`<think>` 那个 case 可能是另一类问题**——special token 在 d2t 里完全没注册的情况。需要单独验证。
85
