dequant(W_block, scale_m6)) ** 2).mean()\nmse_m4 = ((W_block - dequant(W_block, scale_m4)) ** 2).mean()\n\nfinal_scale = scale_m4 if mse_m4 < mse_m6 else scale_m6\n```\n\n这一做法的好处是：\n\n- 输出格式仍然是标准 NVFP4：`4-bit 权重 + FP8 block scale`\n- 推理 kernel 不需要改动\n- 吞吐没有额外损耗\n\n---\n\n## 1.3 我们的集成方式\n\n我们将自适应 scale 选择嵌入 GPTQ 量化流程中：\n\n```text\n估算 block scale\n      ↓\n比较 M=6 与 M=4 的反量化误差\n      ↓\n选择误差更小的 scale\n      ↓\n进入 GPTQ 权重优化迭代\n```\n\n这样做的原因是：先确定每个 block 的 `M` 选择，再让后续 GPTQ 优化在这个框架下进行，避免 scale 选择与 GPTQ 迭代互相影响。\n\n---\n\n## 1.4 实测现象\n\n实测发现：\n\n- 约 **40–43%** 的 blocks 最终选择了 `M=4`\n- MLP 层的 `M=4` 占比明显高于 Attention 层的 QKV 投影\n- 启用 FourOverSix 后，各类评测任务上都能观察到稳定的量化精度提升\n\n这个现象符合直觉：\n\n| 层类型 | 权重分布特点 | 更常见选择 |\n|---|---|---|\n| MLP gate/up/down proj | 分布更集中 | 更容易选择 M=4 |\n| Attention QKV proj | 离群值更多 | 更容易保留 M=6 |\n\n---\n\n# 02｜推测解码：Medusa 在混合注意力架构上的适配\n\n## 2.1 推测解码的目标\n\n推测解码（Speculative Decoding）的基本思路是：\n\n> 用轻量 draft 先预测多个后续 token，再让主模型一次性 verify，从而用一次 verify 的代价获得多个 token 的输出机会。\n\n如果预测被接受，就能减少主模型 decode 的次数，提高吞吐。\n\n---\n\n## 2.2 Medusa：不引入独立 draft model\n\n**Medusa**（Tianle Cai, Yuhong Li, Zhengyang Geng, Hongwu Peng, Jason D. Lee, Deming Chen, Tri Dao；ICML 2024）的核心创新是：\n\n> 不额外训练一个独立 draft model，而是在主模型最后一层 hidden state 上增加多个轻量预测头。\n\n每个 Medusa head 负责预测后续第 `k` 个位置。\n\n结构如下：\n\n```text\np_t^(k) = softmax( W₂⁽ᵏ⁾ · ( state 分叉逻辑，保证每个分支都从正确的 parent state 开始。\n\n---\n\n## 2.5 训练数据分布对 accept rate 的影响\n\n除了模型结构适配，Medusa head 的训练数据分布也很关键。\n\n我们观察到：训练数据越接近线上推理场景，accept rate 越稳定。基于这一点，我们按照验证集分布特征对训练数据做了加权采样，让训练集更接近实际推理场景。\n\n结果是：相比随机采样，accept rate 有可测量的提升。\n\n---\n\n## 2.6 实验结果\n\n在 MiniCPM-SALA 上：\n\n- Medusa `K=1` 的 verify overhead 约为 **0.39 ms**\n- 该开销明显低于一次正常 decode
