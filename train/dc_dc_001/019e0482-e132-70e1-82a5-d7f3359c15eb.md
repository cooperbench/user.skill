**结论**
大 batch no-spec 不是一句“memory-bound”或“compute-bound”能概括：

- 短上下文 B32 decode：明显不是 KV memory-bound，主要还是 Marlin W4A16 GEMM / GLA / norm 等整步 compute 和权重路径。
- 长上下文 B32 decode：attention/KV 子路径开始 memory-bound，但整步仍是 mixed，Marlin GEMM 仍是最大项。
- FP8 KV 在 no-spec 下有积极意义，但边界很清楚：**短上下文没收益，长上下文/大 batch 有局部收益和容量收益；是否上生产必须过 accuracy gate**，因为模型不是 FP8 KV 条件下采集/训练的。

**实测**
FP8 KV server 启动确认：

- `speculative_algorithm=None`
- `kv_cache_dtype='fp8_e5m2'`
- 日志确认：`Using KV cache dtype: torch.float8_e5m2`

| longctx B32 E2E | `56.28 tok/s` | `63.84 tok/s` | 约 +13%，但含 prefill，不能全归因 decode |

| kernel family | BF16 KV | FP8 KV | 变化 |
