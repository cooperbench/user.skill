```159:172:/root/shared-nvme/openbmb/demo-sala/sglang/python/sglang/srt/managers/schedule_batch.py
class FINISH_ABORT(BaseFinishReason):
```

```2595:2611:/root/shared-nvme/openbmb/demo-sala/sglang/python/sglang/srt/managers/scheduler.py
    def abort_request(self, recv_req: AbortReq):
        # Delete requests in the waiting queue
        to_del = []
        for i, req in enumerate(self.waiting_queue):
            if recv_req.abort_all or req.rid.startswith(recv_req.rid):
                to_del.append(i)

        # Sort in reverse order to avoid index issues when deleting
        for i in reversed(to_del):
            # Abort method 1: directly pop from the queue
            # This only works for requests that have not started anything.
            # We still need to send something back to TokenizerManager to clean up the state.
            req = self.waiting_queue.pop(i)
            if self.enable_hicache_storage:
                # to release prefetch events associated with the request
                self.tree_cache.release_aborted_request(req.rid)
            self.send_to_tokenizer.send_output(AbortReq(rid=req.rid), req)
```

```2063:2097:/root/shared-nvme/openbmb/demo-sala/sglang/python/sglang/srt/managers/tokenizer_manager.py
    def _handle_abort_req(self, recv_obj: AbortReq):
        if is_health_check_generate_req(recv_obj):
            return

        state.finished = True

        abort_message = recv_obj.abort_message or "Abort in waiting queue"

        is_stream = getattr(state.obj, "stream", False)
        if getattr(state.obj, "return_logprob", False):

                meta_info,

                state.obj.top_logprobs_num,
                state.obj.token_ids_logprob,
                state.obj.return_text_in_logprobs
                and not self.server_args.skip_tokenizer_init,

        meta_info["completion_tokens"] = len(output_ids)
```

```1127:1163:/root/shared-nvme/openbmb/demo-sala/sglang/python/sglang/srt/managers/tokenizer_manager.py
                        finish_reason.get("type") == "abort"
                        and finish_reason.get("status_code") == HTTPStatus.BAD_REQUEST
                    ):
                        if not is_stream:
                            raise ValueError(finish_reason["message"])
                        else:
                            yield out
                            break

                    if finish_reason.get("type") == "abort" and finish_reason.get(
                        "status_code"
                    ) in (
                        HTTPStatus.SERVICE_UNAVAILABLE,
                        HTTPStatus.INTERNAL_SERVER_ERROR,
                    ):
                        # This is an abort request initiated by scheduler.
                        # Delete the key to prevent resending abort request to the scheduler and
                        # to ensure aborted request state is cleaned up.
                        if state.obj.rid in self.rid_to_state:
                            del self.rid_to_state[state.obj.rid]

                        # Mark ongoing LoRA request as finished.
                        if self.server_args.enable_lora and state.obj.lora_path:
                            await self.lora_registry.release(state.obj.lora_id)
                        if not is_stream:
                            raise fastapi.HTTPException(
                                status_code=finish_reason["status_code"],
                                detail=finish_reason["message"],
                            )
                        else:
                            yield out
                            break
                yield out
                break
```

要点：**仅当 `status_code` 恰好为 BAD_REQUEST，或 503/500 时**，非流式会 **抛错**；**`AbortReq` 构造的 `finish_reason` 没有 `status_code`**，或 **`FINISH_ABORT()` 默认 `status_code` 为 `None`** 时，会 **落到最后的 `yield out`**，上层仍按正常 Chat Completion **200** 组装。

## 3. 关于 `content = None` / `output_text` / `finish_reason` 的搜索说明

- 在 `sglang/srt` 下 **`content = None`** 几乎不对 Chat 层赋值；Chat 里是 **`content=text if text else None`**（见上）。
- **`output_text`** 主要出现在 **`serving_responses.py`（Responses API）**，与 **Chat Completions 的 `message.content`** 不是同一条路径。
- **`FINISH_ABORT`**：见 `schedule_batch.py`；**`finish_reason`** 在 OpenAI 协议与 `_build_chat_response` 中显式支持 **`"abort"`**。

## 4. Abort → `content: null` 因果链（归纳）

1. **Scheduler 终止请求**（例如：`abort_request` 对 waiting queue 发 **`AbortReq`**；或对 running req 设 **`req.to_finish = FINISH_ABORT()`** 等）。
2. **Tokenizer 侧收尾**：
   - **`_handle_abort_req`**：把 **`state.text`**（可能一直是 **`""`**）填入 **`out["text"]`**，并设 **`finish_reason`**（`AbortReq` 自带的路径里 **`finish_reason` 默认只有 `type`/`message`，没有 `status_code`**）。
   - 或经 **`BatchStrOutput`**：若此前未累积到可见正文，**`text` 仍可能为空**；且 **`FINISH_ABORT().to_json()` 的 `status_code` 可为 `None`**。
3. **`_wait_one_response`**：若 **`finish_reason["type"]=="abort"`** 且 **`status_code`** 不是 **400 / 503 / 500**，则 **不会** `raise`，而是 **`yield out`**，HTTP 层仍当成功响应处理。
4. **`serving_chat._build_chat_response`**：**`content=text if text else None`** → **`text==""` → `None`** → JSON **`"content": null`**，同时 **`finish_reason` 仍可为 `"abort"`**。

因此：**“abort”并不等价于“HTTP 错误”；在多种 abort 情形下正文为空是预期可能状态，而 Chat 层刻意把空正文映射成 `null`，于是出现 200 + `finish_reason: abort` + `content: null` 的组合。**
