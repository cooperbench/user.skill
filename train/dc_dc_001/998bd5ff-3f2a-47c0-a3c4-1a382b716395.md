## 树形 Draft 是什么，意义在哪里 ### 先从线性链理解问题 当前 Medusa K=1 的流程： ``` 目标模型已确认的 token: [..., T] Medusa 预测: d0 (argmax) 验证序列: [T, d0] 目标模型验证: T → 预测 P0 若 d0 == P0: 接受，输出 [d0, 目标校正] ✓ 若 d0 != P0: 拒绝，输出 [目标校正] ✗ ``` K=3 线性链： ``` 草稿: [d0, d1, d2]（头0预测d0，头1预测d1，头2预测d2） 验证序列: [T, d0, d1, d2] 接受规则（级联）: d0 接受 → 再看 d1 d0 被拒 → d1,d2 直接丢弃（无论对错） ``` **致命弱点**：d0 被拒时，d1 和 d2 完全浪费。即使 d1 猜对了，因为 d0 错了也白搭。 --- ### 树形 Draft 解决的核心问题 **核心思想**：与其押注一条路，不如同时押多条路，其中一条被接受就赢了。 ``` T（已确认） / \ d0_a d0_b ← Head0 top-2 候选 / \ / \ d1_a d1_b d1_c d1_d ← Head1 top-2 候选（共4个） / \ / \ / \ / \ ... ← Head2 top-2 候选（共8个） ``` topk=2, K=3 时，树有 1+2+4+8 = **15 个节点**，一次 forward 验证。 **验证逻辑**： ``` 目标模型对每个节点做预测: T → 预测 P_user_4813494d 若 P_user_4813494d == d0_a: 走左分支 d0_a → 预测 P_0a 若 P_0a == d1_a: 继续左... 若 P_0a == d1_b: 继续右... 若 P_user_4813494d == d0_b: 走右分支（d0_a 虽然错了，d0_b 救场！） ... ``` 关键：**任何一条从根到叶的路径，只要节点匹配就能接受**。 --- ### 用数字说话 假设每个 token 的接受概率 = 50%（greedy 匹配）： | 方案 | 每步期望 token 数 | 计算方式 | |------|------|------| | K=1 线性 | 1.50 | 1 + 0.5 | | K=3 线性 | 1.875 | 1 + 0.5 + 0.25 + 0.125（需全部串联） | | K=3 topk=2 树形 | **~3.2** | 树上有多条路径，任一路径接受就计数 | 为什么树形好这么多？ 线性链被拒链断，后面全废。树形**允许从备选分支救场**： ``` 线性链 d0 被拒 → 0 个额外 token 树形 d0_a 被拒 → d0_b 可能还在 → 不损失那条分支的后续 ``` --- ### 形象类比 **线性链**：买彩票，买一张，号码错一位全输。 **树形**：同时买15张彩票（共享一次对奖），只要有一张前N位对上就赢。 代价：目标模型 forward 一次要处理 15 个 token（而不是 4 个），但 GEMM 在 M=15 时的代价比 M=1 大不了 2x（带宽限制，不是计算限制）。 --- ### 为什么对 SALA 有意义 SALA 的 decode 瓶颈是 Lightning Attention 的 GLA 递推计算（串行，不能并行），**每多一个 token 就多一次递推**。 树形 verify 里，所有 15 个节点**一次 forward 完成**（利用中间 state 缓存，每个节点从父节点的 state 出发）。开销约 = 线性 K=3 的 4x，但平均接受 token 数约 3.2x（线性链 1.875x）。 **净收益为正**。 --- ### 一句话总结 > 线性链是单线押注，拒一个全输；树形是并行下注，多条路径同时验证，任何一条对就赢——代价只是一次稍胖的 forward，收益是大幅提升每步输出 token 数。
