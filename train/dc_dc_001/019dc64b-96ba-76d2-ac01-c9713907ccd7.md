只读审阅完成，未改文件。以下只覆盖 EAGLE target verify / CUDA graph replay metadata / tree-aware verify，不讨论普通 prefill。

**主要热点**

1. [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:2306): target verify replay 每次都会重建 FlashInfer prefill metadata。这里按 CPU `seq_lens_cpu` 算 `pages_per_req_cpu/max_pages/kv_indptr_cpu/total_pages`，再用 GPU gather 构造 `page_indices`，随后 Python `for i in range(bs)` 逐请求切片写 `kv_indices_buf`。热点在 [2313-2335](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:2313)。  
优化方向：把 `kv_indptr + kv_indices + last_page_len` 构建融合成一个 CUDA/Triton kernel，避免 Python per-request loop 和多次小 slice copy；`kv_indices_buf[:total_pages].zero_()` 在随后全覆盖时可评估去掉，只在 shrink suffix 清理。

2. [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:2393): `verify_wrapper.plan(...)` 每次 replay 前调用，且 `kv_last_page_len_cpu.to(self.device)` 每次新建/拷贝。FlashInfer plan 通常是 CPU plan/同步类开销的核心。  
优化方向：预分配 `verify_kv_last_page_len` GPU buffer，replay 只原地 copy；按 `(bs, draft_token_num, pages_per_req pattern/max_pages/page_size/head/dtype)` 做 plan cache 或 bucket。若 FlashInfer 允许，用固定 capacity plan + 只更新 registered buffers，减少每步 plan。

3. [minicpm_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:1115): 图内标准 attention target verify 已经只拿 `verify_prefill_wrapper.forward(...)`，没有每层重建 plan；这条路径本身相对干净。真正的 per-step 标准 attention metadata 成本主要在 replay prepare 的 [2306-2406](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/minicpm_backend.py:2306)，不是每个标准 attention layer。

4. [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:785): hybrid replay metadata 每步做 padding 处理、`req_pool_indices` 修正、`get_mamba_indices`、query_start_loc 拷贝。当前 topk=1 时这部分偏小；topk>1 时会额外复制 tree retrieve tensors 并构建 parent metadata，见 [828-841](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:828)。  
优化方向：topk=1 保持 fast path，不进入 retrieve 分支；padding 场景可以缓存 `query_start_loc` 的 padded variants，减少每步 copy。

5. [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:253): `_build_retrieve_parent_token` 是 topk>1 tree-aware verify 的明显 CPU 同步点：`retrieve_next_token.cpu().tolist()` 和 `retrieve_next_sibling.cpu().tolist()` 会拉 GPU 数据到 CPU，然后 Python BFS，再创建 GPU tensor，见 [261-287](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:261)。  
优化方向：用一个小 CUDA/Triton kernel 直接从 `retrive_next_token/retrive_next_sibling` 生成 `retrieve_parent_token`，并写入预分配 replay buffer。这样能去掉 topk>1 verify 前的 D2H 同步和 Python loop。

6. [hybrid_linear_attn_backend.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:1263): GLA/Mamba target verify 图内已是 tree-aware：`causal_conv1d_update` 传入 retrieve next/sibling/parent，`fused_recurrent_gated_delta_rule_update` 传入 parent token，见 [1280-1298](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:1280) 和 [1347-1363](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:1347)。Simple GLA fused path同理在 [2020-2047](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/layers/attention/hybrid_linear_attn_backend.py:2020)。  
优化方向：图内 kernel 路径方向是对的；优先优化图外 parent metadata 构建，而不是拆这些 fused kernels。

7. [eagle_worker.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:818): verify 上游/下游仍有非 graph CPU 同步：`seq_lens_cpu.clone()`、`prepare_for_verify` 分配 verify KV、`get_model_worker_batch(seq_lens_cpu_cache=...)` 后进入 target forward，见 [821-848](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_worker.py:821)。target forward 之后 accept 阶段有 `accept_index.tolist()`、`predict.tolist()`、`accept_length.cpu().tolist()`，在 [eagle_info.py](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:466) 和 [531-536](/user_4813494d/openbmb/demo-sala/sglang/python/sglang/srt/speculative/eagle_info.py:531)。  
优化方向：短期保留 Python req 状态更新，但把 tensor-to-list 次数压到一次；中期把 accept/evict/seq_len update 合并为 device kernel，CPU 只拿最终每请求 accepted length。
