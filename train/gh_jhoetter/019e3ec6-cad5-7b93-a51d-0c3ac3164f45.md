Short version: it looks less like a pure “evolutionary algorithm” and more like a hybrid of: 1. **Graph-based architectural model** 2. **Constraint solving** 3. **Iterative generation/search** 4. **Weighted scoring/ranking of candidate layouts** 5. **Adaptive reuse of prior plan libraries** Finch’s own language centers on the **“Finch Graph”**: rooms, walls, doors, furniture, facades, stairs, corridors, etc. are represented as nodes with relationships/edges. Their Medium post says the graph maps architectural relationships and is used both for generation and rule checking. Source: [Finch Graph Rules, Medium](https://medium.com/finch3d/introducing-finch-graph-rules-revolutionizing-the-design-process-for-architects-2082d7d127bb). The clearest technical clue is in their docs: each generated **iteration is scored** after satisfying “non-negotiables” such as corridor access, minimum width, and stairwell count. Users can change weights to prioritize unit size, daylight, unit ratio, etc. Source: [Finch Algorithm Theory](https://docs.finch3d.com/docs/projects-and-variants/story-editor/algorithm-theory). For floor plates, Finch exposes several generation modes: - **Generate Around Existing Circulation**: uses a predefined core/corridor and fills units around it. - **Generate Cores**: finds/places multiple cores and wraps units around them. - **Generate Corridors**: creates corridor/core layout from scratch using inputs like egress distance, core dimensions, and orientation. Source: [Generate Floor Plate Algorithms](https://docs.finch3d.com/courses/finch-101/finch-101-generate-floor-plate-algorithms). The patent application is also revealing. Archfinch’s US application describes a graph database of architectural nodes and connections, rule evaluation, filtering/ranking candidate outputs, constraints on geometry, and repeating loops. It explicitly mentions **Cassowary** as one solver used for constraint-based stretching/adaptation of points/walls. Source: [US20240265158A1](https://patents.google.com/patent/US20240265158A1/en). So my read is: ```text input massing / floor polygon / corridor / constraints -> build graph of spaces, objects, relationships -> generate candidate subdivisions / cores / corridors / units -> reject candidates violating hard constraints -> score remaining candidates against weighted objectives -> iterate/search for better candidates -> rank or present options -> allow architect to edit, then re-run/adapt
