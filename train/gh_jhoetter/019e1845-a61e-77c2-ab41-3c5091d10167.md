In BIM terms:

**Sheets** are for **presentation and documentation output**.  
They are the digital equivalent of drawing sheets/PDF pages: titleblock, scale, placed views, plans, sections, elevations, legends, notes, issue/revision data. A sheet answers: **“What do we publish or hand over?”**

Examples:
- A101 Ground Floor Plan
- A201 Elevations
- A301 Wall Sections
- Door/window legends placed onto drawing pages
- Permit or construction drawing set

**Schedules** are for **structured model data in table form**.  
They list, count, filter, sort, and QA model elements. A schedule answers: **“What is in the model, with which properties, quantities, and exceptions?”**

Examples:
- Door schedule: mark, width, height, fire rating, host wall
- Window schedule: type, sill height, glazing, dimensions
- Room schedule: room name, area, department, finish
- Wall schedule: type, length, height, material assembly
- Warning/QA-style tables: missing type, missing material, unhosted openings

The key distinction:

- **Sheet = composed drawing/document page**
- **Schedule = data table generated from the model**

They overlap because schedules can be **placed on sheets**. For example, a door schedule is a table, but when you put it on sheet A601, it becomes part of the published drawing set.

For the UX revamp, that means:

- **Primary sidebar** opens Sheets and Schedules as separate view types.
- **Sheet secondary sidebar** should manage sheet-level setup: titleblock, placed views, revisions, issue metadata.
- **Sheet ribbon** should handle publishing/review/placing views.
- **Schedule secondary sidebar** should manage table definition: category, fields, filters, sorting, grouping.
- **Schedule ribbon/table area** should handle row/column actions and inline review/editing.
