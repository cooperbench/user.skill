## O que faz: Map nginx Referer case-insensitive ### Contexto Item 3 (aplicado em 02/05) bloqueia bot fake-Firefox/142 que envia Referer literal sem trailing slash. O map atual lista 4 strings exatas: ```nginx map $http_referer $deny_bot_referer { default 0; "https://concertacaoamazonia.com.br" 1; "http://concertacaoamazonia.com.br" 1; "https://www.concertacaoamazonia.com.br" 1; "http://www.concertacaoamazonia.com.br" 1; } ``` ### Vulnerabilidade `map` no nginx é **case-sensitive por padrão**. Strings literais só batem se o caso for idêntico. **Bot adaptativo escapa do bloqueio com qualquer mudança de caso:** | Referer enviado | Bloqueia hoje? | |-----------------|----------------| | `https://concertacaoamazonia.com.br` | ✅ Sim (string exata) | | `https://Concertacaoamazonia.com.br` | ❌ **Passa** (C maiúsculo) | | `HTTPS://concertacaoamazonia.com.br` | ❌ **Passa** (HTTPS upper) | | `https://CONCERTACAOAMAZONIA.COM.BR` | ❌ **Passa** (tudo upper) | | `https://concertacaoAmazonia.com.br` | ❌ **Passa** (A camelCase) | Como **hostnames HTTP são case-insensitive por RFC**, browsers podem normalizar para lowercase mas bots NÃO precisam — são livres para randomizar. ### O fix Substituir 4 strings literais por 1 regex case-insensitive: ```nginx map $http_referer $deny_bot_referer { default 0; "~*^https?://(www\.)?concertacaoamazonia\.com\.br/?$" 1; } ``` **Decompondo o regex:** - `~*` — modificador nginx para regex case-insensitive - `^` — começo da string - `https?://` — http OU https - `(www\.)?` — www opcional - `concertacaoamazonia\.com\.br` — hostname literal (pontos escapados) - `/?` — trailing slash opcional (mata edge case onde bot manda `/` no fim mas mantém URL "raiz") - `$` — fim da string ### Por que importa **Custo:** zero (1 linha de regex substitui 4 strings, mesmo lookup speed do nginx) **Benefício:** se bot evoluir e começar a randomizar caso (defesa anti-pattern comum), não precisamos editar config + reload nginx em emergência. Já estamos protegidos. **Risco de falso-positivo:** nenhum. Browsers reais sempre incluem path (mesmo que `/`) — o regex exige raiz exata `^https?://host/?$`.
