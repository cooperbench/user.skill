게임의 점수 시스템, 리더보드 제출, 안티치트 메커니즘을 분석한 결과, **다층 방어 구조가 잘 구현**되어 있으나 **여전히 우회 가능한 벡터들**이 존재합니다. 아래는 현재 방어 상태와 각 공격 벡터별 상세 분석입니다.

## 1. 콘솔에서 점수/게임 상태 직접 조작

### 공격 코드 예시
```javascript
// 콘솔에서 실행 가능한 코드들
const scene = Phaser.GAMES[0].scene.getScene('GameScene');

// 점수 직접 조작
scene.score = 10000;

// 게임 오버 상태 조작
scene.gameOver = false;

// 난이도 변수 조작
scene.difficultyLevel = 10;

// 수집 통계 조작
scene.goldCollected = 999;
scene.diamondCollected = 999;
scene.topazCollected = 999;
scene.rainbowCollected = 999;

// 플레이어 위치 조작
scene.player.x = 200;
scene.player.y = 50; // 화면 최상단으로 이동시켜 충돌 불가능하게

// 타이머 제거
scene.spawnTimer.remove(); // 똥이 더 이상 생성되지 않음
```

### 현재 방어 상태
✅ **부분적 방어 있음** (점수 제출 시)  
❌ **실시간 게임 중 직접 조작은 무방비**

**방어 메커니즘**:
- **서버 세션 검증** (game-start): 게임 시작 시 서버에 세션 생성, start_time 기록
- **시간 기반 점수 검증** (leaderboard-submit):
  ```typescript
  // 점수 = 시간 기반 점수 + 보너스 점수
  const timeBasedScore = Math.max(0, score - bonusScore);
  const minRequiredSec = timeBasedScore * 0.1 * 0.5; // 50% 여유
  if (elapsedSec < minRequiredSec) → 거절
  ```

**우회 가능성**: ⚠️ **높음**

- 콘솔 조작으로 점수를 올린 후, **게임을 충분히 오래 플레이한 후에 제출**하면 시간 검증을 통과할 수 있음
- 예: 점수 5000 올리기 → 최소 25초(50% 여유) 기다린 후 제출
- **sessionId를 제공하지 않으면** 더 오래된 검증 방식(verification 필드)으로 폴백되는데, 이것도 우회 가능 (gameStartTime/gameEndTime 조작)

**공격 시나리오**:
```javascript
const scene = Phaser.GAMES[0].scene.getScene('GameScene');
scene.score = 3000; // 직접 올림
scene.goldCollected = 100;
scene.diamondCollected = 100;

// 30초 기다린 후
// 게임 오버 UI에서 제출 → 서버 검증 통과 (시간이 충분히 경과했으므로)
```

**방어 난이도**: 🔴 **매우 쉬움** (30초 대기만으로 가능)

## 3. 현실 시간(Date.now) 조작 공격

### 공격 코드 예시
```javascript
// Date.now 오버라이드 (느린 속도로 게임 진행)
const _origDateNow = Date.now;
Date.now = () => _origDateNow() * 0.5; // 시간을 절반으로 축소

// 게임 재로드 후 점수 증가 속도 감소
// 100ms당 1점 → 200ms당 1점으로 느려짐
```

### 현재 방어 상태
✅ **완전히 방어됨**

**방어 메커니즘**:
```typescript

export const realNow = (): number => _origDateNow.call(Date);

// GameScene.ts에서 사용

```

**우회 불가능**: ✅ **불가능**

## 4. rAF(requestAnimationFrame) 속도 조작

### 공격 코드 예시
```javascript
// rAF 슬로우-모션 (slow-motion 치트)
const _origRAF = requestAnimationFrame;
const slowFactor = 0.1; // 10배 느림
let lastTime = Date.now();
window.requestAnimationFrame = (callback) => {
  return _origRAF((time) => {
    const slowTime = lastTime + (time - lastTime) * slowFactor;
    lastTime = time;
    callback(slowTime);
  });
};

// 또는 단순한 방법: rAF 반복 지연
window.requestAnimationFrame = (cb) => setTimeout(cb, 100);
```

### 현재 방어 상태
✅ **감지 및 차단됨**

**방어 메커니즘** (레이어 2 - rAF 조작 감지):
```typescript
// GameScene.ts update() 메서드에서 5초마다 체크
if (now - this.lastCheatCheckTime >= 5000) {
  const realInterval = now - this.lastCheatCheckTime;    // 실제 시간 (Date.now 기반)
  const phaserInterval = this.time.now - this.lastPhaserCheckTime; // Phaser 시간
  const ratio = phaserInterval / realInterval;

  // 정상 범위: 0.70 ~ 1.30 (모바일 OS 스로틀 허용)
  if (ratio < 0.70 || ratio > 1.30) {
    this.cheatSuspicionCount++;
    if (this.cheatSuspicionCount >= 2) {
      this.handleCheatDetected(); // 게임 강제 종료
    }
  }
}
```

**우회 가능성**: ⚠️ **낮음-중간**

- 비율이 정상 범위(0.70~1.30)를 유지하면서 느리게 조작할 수 있음
- 예: 실제 5초 기다리고 Phaser 시간만 4초 경과하게 (ratio=0.8 → 정상)
- **하지만 연속 2회 탐지 시 차단되므로** 지속적 조작은 어려움

**공격 시나리오**:
```javascript
// 탭 전환을 반복하며 리셋 기준점을 초기화할 수 있음
// 하지만 이는 게임 플레이를 방해하므로 실질적 가치 낮음
```

**방어 난이도**: 🟡 **어려움** (이미 잘 구현됨)

**방어 메커니즘** (레이어 5 - 수동 AABB 충돌 감지):
```typescript
private checkManualPoopCollision() {
  if (this.gameOver) return;
  const px = this.player.x;
  const py = this.player.y;
  const HIT_X = 30;  // 반폭
  const HIT_Y = 40;  // 반높이

  for (const obj of this.poops.getChildren()) {
    const poop = obj as Phaser.Physics.Arcade.Sprite;
    if (!poop.active || !poop.visible) continue;
    
    // 스프라이트 좌표로 직접 거리 계산
    if (Math.abs(poop.x - px) < HIT_X && Math.abs(poop.y - py) < HIT_Y) {
      this.hitPoop(this.player, poop);
      return;
    }
  }
}
```

**우회 불가능**: ✅ **불가능**

스프라이트 좌표로 직접 계산하므로 body를 비활성화해도 감지됨.

## 8. fetch/XMLHttpRequest 오버라이드를 통한 점수 변조

### 공격 코드 예시
```javascript
// fetch 오버라이드 — 점수 제출 시 조작
const _origFetch = fetch;
window.fetch = function(...args) {
  if (args[0].includes('leaderboard-submit')) {
    // 요청 본문 조작
    args[1].body = JSON.stringify({
      score: 99999,  // 원본 점수 대신 높은 점수
      ...JSON.parse(args[1].body)
    });
  }
  return _origFetch.apply(this, args);
};
```

### 현재 방어 상태
✅ **부분적 방어** (서버 검증)

**방어 메커니즘**:
1. **sessionId 검증** (가장 강력):
   ```typescript
   // leaderboard-submit (Edge Function)
   if (sessionId) {
     const session = await db.update(game_sessions)
       .set({used: true})
       .where({id: sessionId, used: false, user_id, difficulty})
       .select('start_time')
       .single();
     
     // 시간 경과 검증
     const elapsedSec = (Date.now() - session.start_time) / 1000;
     const minRequiredSec = timeBasedScore * 0.1 * 0.5; // 50% 여유
     if (elapsedSec < minRequiredSec) → 거절
   }
   ```

2. **검증 데이터 체크**:
   ```typescript
   const bonusScore = 
     goldCollected*20 + diamondCollected*40 + 
     topazCollected*80 + rainbowCollected*90;
   const timeBasedScore = score - bonusScore;
   
   // 시간과 보너스의 합이 제출 점수와 일치하는지 검증
   ```

3. **SKOR 이중 검증** (skor-submit):
   ```typescript
   const rawSkor = 
     goldCollected*0.5 + diamondCollected*1.5 + 
     topazCollected*3.5 + rainbowCollected*10.0;
   // 보너스 아이템 개수와 무게가 일치하는지 체크
   ```

**우회 가능성**: ⚠️ **매우 낮음-불가능** (sessionId 있는 경우)

- sessionId가 제공되면: **거의 불가능** (서버 시각 기준 경과 시간으로 검증)
- sessionId 없으면: **가능** (시간 기반 검증만, 넉넉한 50% 여유)

**공격 시나리오** (sessionId 없는 경우):
```javascript
// gameStartTime/gameEndTime을 조작한 verification 데이터로 제출
// 예: 100초 게임 후 점수 5000을 제출
// → 시간: 100초, 시간 기반 점수: 1000 + 보너스 4000 = 총 5000
// → 검증 통과
```

**방어 난이도**: 🟢 **쉬움** (sessionId 있으면 완벽, 없으면 시간 기반 검증으로 대부분 차단)

## 9. SKOR 정제 금액 변조

### 공격 코드 예시
```javascript
// SKOR 제출 요청 변조
const _origFetch = fetch;
window.fetch = function(...args) {
  if (args[0].includes('skor-submit')) {
    args[1].body = JSON.stringify({
      score: 5000,
      goldCollected: 1000,      // 실제 값 대신 높은 값
      diamondCollected: 500,
      topazCollected: 100,
      rainbowCollected: 50,
    });
  }
  return _origFetch.apply(this, args);
};
```

### 현재 방어 상태
✅ **서버에서 검증됨** (클라이언트 검증 없음)

**방어 메커니즘** (skor-submit Edge Function):
```typescript
// 클라이언트가 제출한 보너스 아이템 개수 검증 없음
// → 클라이언트가 원하는 대로 금액 조작 가능
// 하지만 다음 두 가지로 제한됨:

// 1. 점수 기반 브래킷 캡
const bracketCap = getBracketCap(score); // 점수에 따라 게임당 최대 SKOR
const gameSkor = Math.min(rawSkor, bracketCap);

// 2. 퀘스트 진행도 누적 (무한정 늘릴 수 없음)
// quest_progress 테이블에서 누적값 추적
```

**우회 가능성**: ⚠️ **부분적** (금액 제한 있음)

- 아이템 개수는 조작 가능하나, **브래킷 캡에 의해 제한됨**
- 예: 점수 500 달성 → 게임당 최대 40 SKOR
  ```javascript
  // 실제: goldCollected=1, diamondCollected=0, ...
  // 제출: goldCollected=1000, diamondCollected=1000, ... (조작)
  // 계산: rawSkor = 1000*0.5 + 1000*1.5 = 2000
  // 하지만: gameSkor = Math.min(2000, 40) = 40 SKOR (최종 획득)
  ```

- **퀘스트 진행도는 누적이므로** 다수 게임을 통해 마일스톤 도달 가능
  ```javascript
  // 예: gold 퀘스트 300마다 5 SKOR
  // 실제 누적: 10개
  // 조작해서 제출: 310개
  // → 다음 마일스톤(330) 도달 가능, 5 SKOR 추가 획득
  ```

**방어 난이도**: 🟡 **어려움** (브래킷 캡으로 기본 게임 SKOR 제한, 퀘스트는 누적이지만 조작 가능)

```js
    // 레이어 5 우회: active=false → AABB 체크 skip
    scene.poops?.getChildren().forEach(p => {
      p.setActive(false).setVisible(false);
    });

    // 스폰 타이머 제거 (새 똥 생성 차단)
    if (scene.spawnTimer?.hasDispatched === false) {
      scene.spawnTimer.remove();
    }

  }, 16);

  console.log('%c[Shield] 무적 가동 중', 'color: #00ff00; font-weight: bold;');
})();
```

타이밍 문제네요. `setInterval`이 16ms마다 비활성화해도, Phaser의 `physics.overlap`은 그 사이 프레임에서 먼저 발동합니다. 스폰 자체를 막는 게 맞아요.

```js
(() => {
  const scene = Phaser.GAMES[0].scene.getScene('GameScene');

  // 1. 기존 똥 전부 즉시 제거
  scene.poops?.getChildren().forEach(p => p.destroy());

  // 2. 스폰 타이머 제거
  scene.spawnTimer?.remove();

  // 3. spawnPoop 오버라이드 → 타이머 재생성돼도 똥 안 나옴
  scene['spawnPoop'] = () => {};
  scene['spawnFeverPoop'] = () => {};
  scene['resetSpawnTimer'] = (cb) => { scene['spawnPoop'] = () => {}; };

  console.log('%c[Shield] 스폰 완전 차단', 'color: #00ff00; font-weight: bold;');
})();
```

`★ Insight ─────────────────────────────────────`
- **이전 스크립트 실패 이유**: `setInterval(16ms)` vs Phaser `update(16ms)` 경쟁 — 똥이 생성되는 순간 같은 프레임에서 `physics.overlap`이 먼저 `hitPoop`을 호출하고, 그 다음에야 interval이 `setActive(false)`를 실행
- **올바른 접근**: 사후 비활성화 대신 **스폰 함수 자체를 오버라이드** — 생성 시점을 막으면 충돌 자체가 발생하지 않음
- **TypeScript private의 한계**: 컴파일 후 런타임에는 그냥 일반 프로퍼티 → 콘솔에서 `scene['spawnPoop'] = () => {}`로 자유롭게 교체 가능
