**텍스처 아틀라스(Texture Atlas)** = 여러 이미지를 하나의 큰 이미지 파일로 합친 것입니다.

```
poop.webp        (40×40)

poops_atlas.webp  (하나의 큰 이미지에 5개 다 들어감)

┌─────────────────┐
│ 💩 👓💩 😎💩 │
│ 😎💩 😁💩      │
└─────────────────┘
```

**WebGL에서 왜 빠른가:**
- 지금: 프레임마다 GPU에 텍스처를 5번 바꿔가며 각각 그림 → **draw call 5개**
- 아틀라스: GPU에 이미지 1개 올려놓고 "이 부분 그려", "저 부분 그려" → **draw call 1개**

GPU는 텍스처를 바꾸는 게 느리고, 같은 텍스처에서 여러 스프라이트를 연속으로 그리는 건 빠릅니다.

**작업 내용:**
1. Shoebox / TexturePacker 같은 툴로 이미지들을 하나로 합쳐 `.webp` + `.json` 생성
2. `load.image()` → `load.atlas()` 로 변경
3. `setTexture('key')` → `setTexture('atlas', 'frame')` 로 변경

A+B에 비해 효과는 가장 크지만, 아틀라스 이미지를 직접 만들거나 빌드 툴로 자동화해야 합니다.

- Phaser는 400×600짜리 텍스처를 렌더링
- 그걸 macOS가 DPR×3으로 CSS 스케일링해서 화면에 합성

Phaser 코드로는 이 부분에 개입할 수 없습니다.

**실용적인 해결책:**
- 외부 모니터 연결 상태에서 게임할 때 **노트북 화면이 아닌 외부 모니터에** 브라우저 창을 옮겨보기 (합성 경로가 달라질 수 있음)
- macOS 시스템 설정 → 디스플레이 → 해상도를 조금 낮춰보기

- **클램쉘 모드** — 맥북 덮고 UHD 모니터만 사용 → GPU가 디스플레이 하나만 구동하면 되므로 가장 효과적
- **UHD 해상도 낮추기** — 시스템 설정 → 디스플레이 → 1920×1080으로 낮추면 부하 대폭 감소

코드 레벨에서는 이미 할 수 있는 건 다 했고, 근본 원인이 GPU 픽셀 처리 한계라 이 방법들이 가장 현실적입니다.

**30Hz = 최대 30fps**

브라우저의 `requestAnimationFrame`은 모니터 주사율에 맞춰 호출됩니다. 모니터가 30Hz면 Phaser가 60fps를 목표로 해도 **초당 30프레임밖에 못 그립니다.** 그게 버벅임으로 느껴지는 겁니다.

**해결책:**
- macOS 시스템 설정 → 디스플레이 → 해당 모니터 선택 → **주사율을 60Hz로 변경**
- 60Hz 옵션이 안 보이면 케이블 문제 — 맥북↔모니터 연결 케이블이 HDMI 1.4라면 4K@30Hz만 지원함. **HDMI 2.0 이상 또는 DisplayPort 케이블**로 교체하면 60Hz 가능

Samsung U32H85x는 60Hz 지원 모니터라서 케이블만 바꾸면 해결됩니다.
