- 퀘스트 진행: 금 진행(1%), 다이아 진행(10%), 토파즈 진행(10%), 무지개 진행(2%)

- 계산: 60(0.5) + 30(1.5) + 16(3.5) + 4(10) = 30 + 45 + 56 + 40 = **171 SKOR**
- 브래킷캡 적용: **110 SKOR** (캡 도달)
- 퀘스트 진행: 금 진행(20%), 다이아 진행(20%), 토파즈 진행(20%), 무지개 진행(8%)

### 2. 새 브래킷 캡 설계

**목표값 재정리:**

```
점수     | 일반(50%)  | 숙련(80%)
---------|-----------|----------
500      | 10        | ~17 (캡 불필요)
1000     | 40~50     | 70~80
1500     | 55~65     | 90~100
2000     | 70~85     | 110~130
2500     | 80~95     | 130~155
3000     | 100~120   | 160~185
4000     | 130~150   | 200~220
5000+    | 160+      | 250~300+
```

**설계 원칙:**
- 캡은 숙련 플레이어(80%)의 rawSkor보다 약간 낮게 설정 → 숙련 플레이어는 "거의 다 받되, 만점은 아닌" 느낌
- 일반 플레이어(50%)는 캡에 도달하지 않아 수집률에 따라 자연스럽게 차이 발생
- 3000점 이후 구간도 계속 증가 → 고득점 동기 부여 유지

**제안하는 7구간 브래킷 캡:**

```typescript
function getBracketCap(score: number): number {
  if (score < 500)  return 20;   // 초반 (rawSkor 10~17)
  if (score < 1000) return 45;   // 중반 진입 (rawSkor 27~44)
  if (score < 1500) return 75;   // 1000점대 (rawSkor 42~67)
  if (score < 2000) return 105;  // 1500점대 (rawSkor 57~91)
  if (score < 3000) return 145;  // 2000~2999 (rawSkor 70~135)
  if (score < 5000) return 195;  // 3000~4999 (rawSkor 113~182)
  return 260;                    // 5000+ (rawSkor 141~226)
}
```

단, 요구사항인 "3000점에서 ~200 SKOR"를 달성하려면 **퀘스트 보상이 핵심**이 됩니다. rawSkor만으로는 3000점에서 80% 숙련도로 134이므로, 퀘스트 보상으로 추가 50~70 SKOR를 얻어야 합니다.

### 3. 퀘스트 간격/보상 재설계

**현재 문제 분석:**

```
현재: 금 300개마다 5 SKOR → 3000점 게임 기준 총 획득 금똥 약 75개 × 50% = 37개
→ 37/300 = 0.12 → 거의 퀘스트 발동 안됨
```

즉, 현재 퀘스트는 누적 카운터 방식이라 수백 판을 해야 한 번 발동하는 구조입니다. 보상이 판당이 아니라 누적 기준이므로, 판당 기대 퀘스트 수익을 역산해야 합니다.

**판당 평균 퀘스트 수익 계산 (현재, 2000점 기준):**
- 금: 판당 평균 25개 획득 (50%) → 300개 기준 1회 퀘스트에 12판 소요 → 판당 기대치 = 5/12 ≈ 0.42 SKOR
- 다이아: 판당 10개 → 150개 기준 15판 → 0.53 SKOR
- 토파즈: 판당 5개 → 80개 기준 16판 → 0.63 SKOR
- 무지개: 판당 1개 → 50개 기준 50판 → 0.30 SKOR

**현재 판당 퀘스트 기대 수익: 약 1.9 SKOR (2000점 기준)**. 사실상 negligible.

**목표: 퀘스트 보상이 판당 15~30 SKOR 수준으로 실질적 기여**

판당 기대 퀘스트 수익을 20 SKOR로 설정하면, 2000점 기준 80% 수집 시 게임SKOR ≈ 90 + 퀘스트 20 = 110 SKOR. 3000점 시 135 + 30 = 165 SKOR. 5000점 시 226 + 50 = 276 SKOR. 목표치에 근접합니다.

**판당 기대 퀘스트 수익 역산:**

2000점 80% 수집 기준:
- 금 20개/판 → 발동 주기 `interval=20` 이면 매판 1회 발동 → `reward=8`이면 판당 8 SKOR
- 다이아 8개/판 → `interval=8`이면 매판 1회 → `reward=5`이면 5 SKOR
- 토파즈 4.4개/판 → `interval=4`이면 매판 1회 → `reward=4`이면 4 SKOR
- 무지개 0.8개/판 → `interval=5`이면 6판에 1회 → `reward=10`이면 판당 1.7 SKOR

합계 ≈ 18.7 SKOR/판 (2000점 80% 기준)

하지만 이렇게 interval을 너무 낮추면 중복 달성이 많아지고 밸런스가 깨집니다. interval이 작으면 한 판에 여러 번 달성 가능하므로, 적절한 중간값이 필요합니다.

**제안하는 퀘스트 설정:**

```typescript
const QUESTS = [
  { key: 'gold',    interval: 100, reward: 8  },   // 현재 300→5에서 완화
  { key: 'diamond', interval: 50,  reward: 12 },   // 현재 150→8에서 완화
  { key: 'topaz',   interval: 25,  reward: 15 },   // 현재 80→10에서 완화
  { key: 'rainbow', interval: 15,  reward: 25 },   // 현재 50→15에서 완화
] as const;
```

**검증 (2000점, 80% 수집, 누적 기준):**

누적 10판 플레이 시 (2000점 기준, 80%):
- 금 누적 200개 → 100 interval → 2회 달성 → +16 SKOR → 판당 1.6
- 다이아 누적 80개 → 50 interval → 1회 달성 → +12 SKOR → 판당 1.2
- 토파즈 누적 44개 → 25 interval → 1회 달성 → +15 SKOR → 판당 1.5
- 무지개 누적 8개 → 15 interval → 0회 (미달) → 판당 0

10판 기준 합계 ≈ 43 SKOR / 10판 = **판당 4.3 SKOR**

이 수치는 여전히 낮습니다. interval을 더 낮추거나, reward를 더 높이는 것이 필요합니다.

더 공격적인 설정으로 재계산:

```typescript
const QUESTS = [
  { key: 'gold',    interval: 50,  reward: 10 },
  { key: 'diamond', interval: 25,  reward: 15 },
  { key: 'topaz',   interval: 12,  reward: 20 },
  { key: 'rainbow', interval: 8,   reward: 30 },
] as const;
```

**재검증 (2000점, 80%, 누적 10판):**
- 금: 200개 / 50 = 4회 → +40 → 판당 4.0
- 다이아: 80개 / 25 = 3회 → +45 → 판당 4.5
- 토파즈: 44개 / 12 = 3회 → +60 → 판당 6.0
- 무지개: 8개 / 8 = 1회 → +30 → 판당 3.0

판당 평균 **17.5 SKOR** (2000점 80% 기준)

3000점 80% 기준 (누적 10판):
- 금: 300개 / 50 = 6회 → +60 → 판당 6.0
- 다이아: 120개 / 25 = 4회 → +60 → 판당 6.0
- 토파즈: 64개 / 12 = 5회 → +100 → 판당 10.0
- 무지개: 12개 / 8 = 1.5회 → +45 → 판당 4.5

판당 평균 **26.5 SKOR** (3000점 80% 기준)

**종합 수익 (게임 + 퀘스트 합산, 80% 숙련):**

| 점수 | 게임 SKOR | 퀘스트 SKOR/판 | 합계     | 목표        |
|------|----------|--------------|---------|------------|
| 1000 | ~44      | ~8           | ~52     | 70~100     |
| 1500 | ~67      | ~12          | ~79     | 70~100 ✓   |
| 2000 | ~90      | ~18          | ~108    | 100~180 ✓  |
| 3000 | ~134     | ~27          | ~161    | ~200       |
| 5000 | ~225     | ~45          | ~270    | 300+       |

3000점 목표 ~200에 약간 못 미칩니다. 두 가지 조정 옵션:

**옵션 A: 무지개 퀘스트 보상 상향**
```typescript
{ key: 'rainbow', interval: 8, reward: 40 }
```
→ 3000점 판당 +6 SKOR 추가 → 합계 ~167 (여전히 부족)

**옵션 B: 브래킷 캡 3000점 구간 상향 조정**
```
3000~4999 구간 캡: 195 → 215
```
→ 3000점 80%에서 게임 SKOR ~160 + 퀘스트 27 = ~187. 아직 약간 부족.

**옵션 C (권장): 브래킷 캡 + 퀘스트 보상 동시 조정**

브래킷 캡을 아래와 같이 조정하고:
```typescript
if (score < 3000) return 160;  // 145→160
if (score < 5000) return 215;  // 195→215
return 280;                    // 260→280
```

그러면 3000점 80% 수집 시 게임 SKOR = min(134.8, 160) = 134 (캡 미달, 자연값 유지)
→ 합계 134 + 27 = **161 SKOR**

캡이 안전망이 되고 있는 구조에서, 목표 200에 도달하려면 사실 수집률 자체가 중요합니다. 아주 잘 하는 플레이어(90%+, 피버타임도 잘 활용)를 기준으로 재계산:

3000점 90% 수집:
- 금 67.5개 × 0.5 = 33.75
- 다이아 27개 × 1.5 = 40.5
- 토파즈 14.4개 × 3.5 = 50.4
- 무지개 2.7개 × 10 = 27

rawSkor ≈ **151.65** → 캡 160 미달이므로 실수령 ~151

퀘스트 판당 ~30 SKOR 추가 시 **181 SKOR**. 목표 200에 근접.

200 SKOR를 달성하려면 피버타임 활용이나 연속 생존 보너스 같은 추가 메커니즘이 없다면 수치적으로 어렵습니다. 현실적으로 "3000점 최고의 플레이 = 180~200"으로 목표를 약간 완화하거나, 또는 퀘스트 보상을 조금 더 높이는 것을 권장합니다.

**안전성 분석**:

- 예: `gold` 간격이 300→50으로 단축되어도

  - 이후: `Math.floor(250 / 50) = 5`, `Math.floor(350 / 50) = 7` → 달성 2회
  - 계산식 `7 - 5 = 2`는 정확함
- **반복 달성 처리** (`achieved * quest.reward`)도 다중 달성 처리 가능 ✅

  - 이전 진행도 조회 없이는 달성 계산 불가능

- **불필요한 중복 요청 없음** ✅

  - select와 upsert 분리 = 트랜잭션 기반 원자성 처리
  
- **개선 가능 여지**:
  - Supabase Realtime이나 Batch API로 select 2개를 단일 다중쿼리로 가능 (성능 미미)
