84	# Cloudflare Sandbox
85	
86	::left::
87	
88	Containers と同じ microVM 基盤の上で動く、**ephemeral・per-request** な隔離実行環境です。
89	
90	Containers との対比:
91	- Containers = **常駐サービス**（dbt / バッチ / 長時間処理）
92	- Sandbox = **per-request の隔離環境**（LLM 生成コードの実行 / ユーザースクリプト）
93	
94	典型用途は **AI が書いたコードを安全に走らせる場**です。
95	- LLM が出した Python / JS / Bash を一時環境で実行
96	- ファイル書き込み / プロセス起動 / ネットワーク制御を SDK で操作
97	- 実行が終われば破棄、state を持たない
98	
99	::right::
100	
101	```typescript
102	import { getSandbox } from "@cloudflare/sandbox";
103	
104	export default {
105	  async fetch(req, env) {
106	    const { prompt } = await req.json();
107	
108	    // 1. LLM にコード生成を依頼
109	    const { response: code } = await env.AI.run(
110	      "@cf/meta/llama-3.3-70b-instruct",
111	      { messages: [{ role: "user", content: prompt }] }
112	    );
113	
114	    // 2. ephemeral Sandbox を取得
115	    const sandbox = getSandbox(env.SANDBOX, crypto.randomUUID());
116	
117	    // 3. 生成コードを書き込んで隔離 microVM 内で実行
118	    await sandbox.writeFile("/tmp/main.py", code);
119	    const { stdout } = await sandbox["exec"]("python /tmp/main.py");
120	
121	    return Response.json({ stdout });
122	  }
123	};
124	```
125	
126	<!--
127	Sandbox は Containers と同じ microVM 基盤を使うが、用途と寿命が異なる。
128	Containers が長期サービス向け、Sandbox は短命・per-request の隔離実行向け。
129	
130	コード上の sandbox["exec"] は Cloudflare Sandbox SDK のメソッド呼び出し
131	(microVM 内で隔離実行)。Node の child_process.exec とは無関係。
132	登壇前に developers.cloudflare.com/sandbox/ で
133	package 名 (@cloudflare/sandbox) / getSandbox / exec / writeFile の最新を確認。
134	書き換え: 公開時は sandbox.exec(...) のドット記法に戻して可。
135	
136	典型 use case:
137	- AI Agent が生成したコードの実行 (code interpreter パターン)
138	- ユーザーが投稿したスクリプトの安全な実行
139	- ad-hoc なデータ加工 (DuckDB / pandas など)
140	
141	データ基盤との接続: R2 SQL では JOIN / WINDOW が未対応なので、複雑なクエリを
142	Sandbox 上の DuckDB に逃がすハイブリッド構成も組める。
143	-->

9	# Effect
10	
11	> TypeScript's Missing Standard Library
12	
13	[Effect](https://effect.website/) は、本番品質の TypeScript アプリケーションを構築するための包括的なフレームワーク兼エコシステム。エラー処理・並行性・依存注入・観測可能性などを統一された API で提供する。
14	
15	## 一言で
16	
17	**`Effect<A, E, R>` という型で「成功値」「エラー」「依存」を全部 type-safe に表現する**ことが核心。Promise や try/catch では表現できない情報を型レベルに持ち上げる。
18	
19	```ts
20	// number を返し、Error で失敗する可能性があり、依存はない
21	Effect<number, Error, never>
22	```
23	
24	「コンパイルが通れば動く (if it compiles, it works)」を強く志向する設計。
25	
26	## なぜ使うか
27	
28	通常の TypeScript の関数は「成功するか throw するか」の二択で、**どんなエラーが出るかが型に出ない**。大規模になると hidden error path が増えて壊れやすい。Effect はこれを解決する。
29	
30	具体的に Effect が一括で提供するもの:
31	
32	- 値としてのエラー (typed errors)
33	- async/Promise の置き換え (合成可能)
34	- リトライ・バックオフ・タイムアウト
35	- リソースの確保と解放 (Scope)
36	- 構造化並行性 (fiber) と中断 (interruption)
37	- 依存注入 (Service / Layer)
38	- ストリーム処理 (Stream)
39	- OpenTelemetry ベースの tracing/metrics
40	- スキーマ定義・バリデーション (Schema)
41	- HTTP / SQL / RPC / CLI / AI などのフレームワーク
42	
43	ライブラリを個別にかき集める代わりに、**一貫した API でこれらを束ねた標準ライブラリ**として使う。

48	
49	純粋な値で、実行されるまで何もしない (lazy)。`Effect.runPromise` などで実行。`pipe` や `Effect.gen` (generator 構文) で合成する。

53	
54	const program = Effect.gen(function* () {
55	  const a = yield* Effect.succeed(1)
56	  const b = yield* Effect.succeed(2)
57	  return a + b
58	})
59	
60	Effect.runPromise(program) // 3
61	```
