# Snowflake Git Integration を Pulumi で管理する

## Context

`snowflake/*.sql` を Snowflake から直接参照・実行できるようにしたい。Snowflake の Git Integration 機能を使い、GitHub リポジトリを Snowflake 内のリポジトリステージとして登録する。リポジトリは public なので認証（Secret）は不要。

Pulumi Snowflake Provider v2.12.0 の制約:
- `snowflake.GitRepository` → ネイティブリソースとして利用可能
- `snowflake.ApiIntegration` → `git_https_api` プロバイダー**未対応**（ドキュメントに明記）
- → API Integration は `snowflake.UnsafeExecute` で生SQL実行が必要

## 変更対象ファイル

| ファイル | 変更内容 |
|---------|---------|
| `infrastructure/pulumi/snowflake.go` | Database `ADMIN`、API Integration（UnsafeExecute）、Git Repository 追加 |
| `infrastructure/pulumi/main.go` | 新しい Output（`snowflakeGitRepositoryName`）をエクスポート |

## 設計判断

- **Database `ADMIN`**: Git Repository は特定のDB.Schemaに属する必要がある。RAW（データ用）とは分離し、管理ツール系の専用DBを作成
- **Schema `PUBLIC`**: ADMIN DBのデフォルトスキーマで十分
- **UnsafeExecute**: ApiIntegration が `git_https_api` 未対応のため唯一の手段。Execute/Revert で冪等性を確保
- **認証不要**: リポジトリが public のため Secret なし、`GIT_CREDENTIALS` パラメータ省略
- **DependsOn**: Git Repository は API Integration と ADMIN DB に依存

## 使い方（デプロイ後）

```sql
-- リポジトリを最新に同期
ALTER GIT REPOSITORY ADMIN.PUBLIC.DATA_ENGINEERING FETCH;

-- ファイル一覧
LS @ADMIN.PUBLIC.DATA_ENGINEERING/branches/main/snowflake/;

-- SQL 実行
EXECUTE IMMEDIATE FROM @ADMIN.PUBLIC.REDACTED.sql;
```
