## Puppini Bridge（Unified Star Schema） **Puppini Bridge** は、Francesco Puppini が考案した **Unified Star Schema (USS)** の中核となるテーブルです。従来のスター・スキーマのファン・トラップやキャズム・トラップを構造的に防ぐためのアプローチです。 --- ### 従来のスター・スキーマの問題 **Fan Trap（ファン・トラップ）** ``` orders ──→ products ──→ price_history（1:N） ``` products に対して price_history が複数行あると、JOIN で行が膨張し、`SUM(order_amount)` が不正に膨らむ。 **Chasm Trap（キャズム・トラップ）** ``` orders ──→ products ←── shipments ``` 2つのファクトが間接的に多対多で接続され、両方のメジャーが膨張する。 --- ### Puppini Bridge の構造 通常のスター・スキーマではファクトとディメンションを直接 JOIN するが、Puppini Bridge では**すべてのテーブルのキーを1つの Bridge テーブルに集約**する。 ``` dim_customer ↑ fct_orders → BRIDGE ← dim_product ↓ fct_shipments ``` Bridge テーブルの構造: | STAGE | customer_key | product_key | order_key | shipment_key | |---|---|---|---|---| | orders | C-001 | P-001 | O-001 | NULL | | orders | C-001 | P-002 | O-002 | NULL | | shipments | NULL | P-001 | NULL | S-001 | | shipments | NULL | P-002 | NULL | S-002 | | customers | C-001 | NULL | NULL | NULL | **特徴:** - カラム数 = DWH内のテーブル数（Fact + Dim）+ 1（STAGE列） - 行数 = 全テーブルの行数の合計（`UNION ALL` で構築） - Bridge からの JOIN はすべて **多対一** になるため、行の膨張が起きない --- ### 今作った Data Vault の Bridge との違い | | Data Vault Bridge | Puppini Bridge | |---|---|---| | **目的** | 多ホップ JOIN の事前計算 | Fan/Chasm Trap の防止 | | **スコープ** | 特定のパス（Patient → Medication） | DWH全体のキーマッピング | | **構造** | HK のリスト | 全テーブルの PK + STAGE列 | | **結合方向** | Bridge → Hub/Link/Sat | Bridge → 全 Fact/Dim | | **用途** | クエリパフォーマンス最適化 | セルフサービスBI、セマンティックレイヤー | Data Vault の Bridge は「クエリ高速化」のための事前JOIN、Puppini Bridge は「結合の安全性」のためのアーキテクチャパターンという位置づけです。 --- Sources: -
