durable objects って何？

> AGENT

Durable Objects は Cloudflare の**ステートフルなサーバーレスプリミティブ**です。今のプロジェクトの `DataAgent` がまさにこれです。 ## 普通の Workers との違い ``` Workers（ステートレス）: リクエストA → Worker インスタンス① → レスポンス ← 次のリクエストでは別インスタンスかも リクエストB → Worker インスタンス② → レスポンス ← 前の状態を知らない Durable Objects（ステートフル）: リクエストA → DO "user-123" → レスポンス ← 常に同じインスタンス リクエストB → DO "user-123" → レスポンス ← 前の状態を覚えている ``` **要するに「名前付きの、状態を持てる単一インスタンス」** です。 ## なぜ「Durable」なのか 3つの永続性があります： | 特性 | 意味 | |------|------| | **単一インスタンス保証** | 同じ ID の DO は世界中で1つしか存在しない | | **SQLite 内蔵** | インスタンス内に SQLite DB を持てる（メッセージ履歴等） | | **Hibernation** | アイドル時にメモリから退避し、リクエストが来たら復帰。状態は保持 | ## 今のプロジェクトでの使われ方 ```typescript // agents/src/agent.ts export class DataAgent extends AIChatAgent<Env> { // this.messages → SQLite に自動永続化された会話履歴 // WebSocket 接続も DO が管理 async onChatMessage(onFinish) { const result = streamText({ messages: await convertToModelMessages(this.messages), // ← 過去の会話を覚えてる tools: createTools(this.env.DB), }); return result.toUIMessageStreamResponse(); } } ``` `★ Insight ─────────────────────────────────────` - `AIChatAgent` は内部で Durable Object を継承しており、会話の永続化・WebSocket 管理・ストリーム再開を全て DO の仕組みで実現している - DO の「世界で1つのインスタンス」という保証は、分散ロックや排他制御を不要にする。チャットの整合性が自然に保たれる理由はここにある - 対して `slack.ts` の方は通常の Worker として動いており、DO を経由していない。だから会話履歴を持てず、毎回ステートレスに処理している `─────────────────────────────────────────────────` ## 身近なアナロジー ``` Workers = コンビニのレジ（誰が対応するかわからない、前回の客を覚えてない） Durable Objects = 担当制の窓口（「田中さん担当」は常に同じ人、過去のやりとりも記録済み） ``` 今のプロジェクトだと、WebSocket 経由の Chat UI は DO（担当窓口）を使っていて会話を覚えるけど、Slack 側はレジ方式で毎回忘れる、という構造になっています。
