## 产出总结

### Direct contract / Boundary guards

**Direct contract**: AGENTS.md, execution charter, target structure, system architecture, feature boundaries, interaction matrix, quality rules, review checklist, frame/connection/receive designs 及其 public API。

**Boundary guards**:
- send owns 单帧发送生命周期（构帧 → target 解析 → transport write → 结果输出）
- send 不拥有 frame definition truth、connection transport lifecycle、task lifecycle、SCOE 语义
- send 不继承旧 store 组织，不硬编码 SCOE target
- send ≠ task；send 执行单帧，task 编排调度

### Design 全文

`codestable/features/rewrite-send/rewrite-send-design.md`

核心设计决策：
1. **Owner scope**: 构帧、发送请求处理、target 路由、写入队列、SendResult 输出、send statistics read model
2. **Core types**: SendRequest / FrameBuildInput / FrameBuildOutput / SendResult / TargetResolution / SendStatistics / QueueModel — 定义了职责分类但不冻结字段 schema
3. **Service contract**: validate → resolve frame → build → resolve target → write → emit result → update stats，任何步骤失败提前返回
4. **State shape**: runtime facts + statistics read model + result history + UI snapshot，selector 不暴露可变引用
5. **跨 feature 契约**: frame 只读 snapshot 构帧；connection public service 写字节；task 通过 public service 调用 send；status/result/storage 通过 event/selector 消费结果
6. **Fake adapter**: FakeFrameSnapshotProvider + FakeConnectionWriter，验证 send 逻辑不依赖真实平台

### Checklist

`codestable/features/rewrite-send/rewrite-send-checklist.yaml` — 10 implementation steps + 16 checks

### Open questions

1. **send-task 边界**: write queue 归属、SendResult 同步/异步、send instance 配置持久化、send 是否了解 task、send failure 是否影响 task lifecycle
2. **expression runtime**: send 是否执行 expression，还是只接受 resolved values — 建议后者
3. **checksum 策略完整列表**: 需实现阶段从 legacy 补齐
4. **receive trigger 与 send**: 建议所有发送经 send public service，触发方是 task/runtime 不是 receive

### 实现前必须确认的问题

1. task design 确认 send-task 调用方式
2. expression runtime 归属
3. send instance 配置持久化方案
4. connection bridge ready 状态
5. checksum 策略完整列表
6. 旧 send instance JSON 样例可用性
7. queue 行为 runtime 证据需求

### 与 task feature 的边界建议

- task owns 调度/编排/序列/pause/resume/stop/retry
- send owns 单帧执行（build → write → result）
- task await SendResult 推进 progress
- send 不了解 task 存在，只接收 SendRequest + context
- task 不 import send internal state
- 建议后续 task design 为 send 定义最小调用契约
