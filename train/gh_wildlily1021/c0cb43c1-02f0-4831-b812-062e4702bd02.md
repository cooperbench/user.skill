187	### 2.2 编排层
188	
189	#### 构帧管线（6 步 → 10 步）
190	
191	**现状**：
192	
193	```
194	validate → resolve frame → build frame → resolve target → transport write → emit result
195	```
196	
197	**变化**：
198	
199	```mermaid
200	graph TD
201	    A[1. validate] --> B[2. resolve frame<br/>direction='send']
202	    B --> C[3. resolve field values<br/>用户>表达式>默认>zero]
203	    C --> D[4. apply factor<br/>value / factor]
204	    D --> E[5. build byte buffer<br/>按 dataType+length+endian]
205	    E --> F[6. post-build patch<br/>checksum回填+length回填]
206	    F --> G[7. resolve target<br/>targetId → connectionId]
207	    G --> H[8. transport write<br/>直接写入]
208	    H --> I[9. emit SendResult<br/>+ update stats]
209	```
210	
211	任何步骤失败都提前返回对应 kind 的 SendResult。
212	
213	#### 步骤 3：resolve field values（新增核心步骤）
214	
215	对每个字段按优先级确定最终值。configurable 标记控制用户值层级是否生效：
216	
217	```
218	对 frame.fields 中每个 field：
219	  if field.configurable && request.userFieldValues[field.id] exists → 使用用户值
220	  else if field.expressionConfig exists → 纳入表达式批量求值
221	  else if field.defaultValue exists → 解析默认值
222	  else → zero fill + 记录 warning
223	```
224	
225	非 configurable 字段的用户输入被静默忽略，不产生 warning/error。configurable 是 UI 层概念（控制是否展示输入框），不是 send 服务层的校验规则。
226	
227	表达式字段逐字段处理（使用 `compileConditional` + `evaluateConditional`）：
228	
229	`ExpressionDefinition` 的结构是 `{ expressions: ConditionalExpressionDefinition[]; variables: ExpressionVariableDefinition[] }`，含多条件分支。实际帧数据有多分支条件（如 `速度>0` / `速度<=0`，`速率==0` 到 `速率==4`），不能在编译时静态选择分支——条件匹配依赖运行时变量值。
230	
231	直接使用 `shared/expression` 的 `compileConditional` + `evaluateConditional`，无需手动展平分支：
232	
233	1. 合并变量源：`request.variables` ∪ `variableProvider.getVariables()` ∪ 解析后的 `expressionConfig.variables[]`（按 sourceType 解析）
234	2. 按字段顺序逐个处理有 `expressionConfig` 的字段（含跨字段依赖时按依赖拓扑排序）
235	3. 对每个字段：`compileConditional(field.expressionConfig.expressions)` → `evaluateConditional(compiled, mergedVariables + 已解析字段值)` → 取 `result.value`
236	4. 求值成功：字段值加入 fieldValues，同时加入变量池供后续字段引用
237	5. 求值失败：zero fill + 记录 error 到 buildIssues
238	
239	#### 步骤 4：apply factor（新增）
240	
241	对非 bytes 类型且 factor ≠ 1 的字段：`rawValue = resolvedValue / factor`。
242	
243	当前实际帧数据中发送帧 factor 全为 1，此步骤是 no-op，但代码必须实现以支持未来 factor ≠ 1 的发送帧。
244	
245	#### 步骤 6：post-build patch（合并 checksum + length 回填）
246	
247	build buffer 之后的统一缓冲区修改步骤。Checksum 和 length 都是"build 后、transport 前的缓冲区回写"，模式相同，合并为一个步骤。
248	
249	**Checksum 回填**（触发条件：`frame.options.autoChecksum === true`）：
250	1. 遍历 fields，找到 `validOption.isChecksum === true` 的字段
251	2. 按该字段的 `validOption.startFieldIndex` 和 `validOption.endFieldIndex` 确定 buffer 范围
252	3. 按 `validOption.checksumMethod`（字段级唯一来源）选择算法
253	4. 对 buffer 对应范围计算 checksum
254	5. 将 checksum 结果编码写入该字段在 buffer 中的位置
255	6. checksum 值超出字段字节宽度时返回 build-error
256	
257	**Length 回填**（触发条件：`frame.options.includeLengthField === true`）：
258	1. 通过 `frame.options.lengthFieldId` 找到 length 字段
259	2. 将 buffer 总长度值按该字段的 dataType + length + endianness 编码写入其 buffer 位置
260	3. 若 `lengthFieldId` 未配置或指向不存在的字段，跳过 + buildIssues 记录 warning
261	
262	**前置**：frame-real `FrameOptionsDefinition` 需新增 `lengthFieldId?: string`（仅阻塞 length 回填部分，checksum 回填不受影响）。
263	
264	#### 步骤 8：transport write
265	
266	**现状**：直接调用 `transportWriter.writeBytes(connectionId, bytes)`。
267	
268	**变化**：保持直接写入。FIFO 队列移出本期——当前唯一调用方 task runtime 是串行执行 step 并 await Promise\<SendResult\>，无并发写入场景。队列作为后续独立补充，在并发调用方出现时再加。
269	
270	**变化**：在 write 前加入轻量 FIFO 队列：
271	
272	- 内部 `Map<targetId, PendingWrite[]>`
273	- 同一 target 串行写入，不同 target 可并行
274	- 当前写入完成后自动处理队列中的下一个
275	- 队列深度和溢出策略等 runtime 证据（checklist c16 deferred）
276	
277	#### 步骤 2：resolve frame 扩展
278	
279	新增 direction 检查：获取 frame 后验证 `frame.direction === 'send'`，不匹配则返回 build-error。

383	
384	shared/ 要求零 Vue 依赖(CLAUDE.md)，所以拆为两层:
385	
386	**shared/persistence/json-persistence.ts**（纯 TS，无 Vue 依赖）:
387	
388	```typescript
389	interface JsonPersistenceOptions {
390	  readonly filename: string;
391	  readonly debounceMs?: number;      // 默认 500ms
392	}
393	
394	function createJsonPersistence<T>(
395	  readFile: (path: string) => Promise<string>,
396	  writeFile: (path: string, content: string) => Promise<void>,
397	  options: JsonPersistenceOptions
398	): {
399	  load(): Promise<T | undefined>;
400	  save(data: T): Promise<void>;
401	}
402	```
403	
404	**各 feature composable 内部**各自封装 Vue 响应式:
405	
406	```typescript
407	// 例: send/composables/use-send-instances.ts
408	const persistence = createJsonPersistence(
409	  platform.readFile, platform.writeFile,
410	  { filename: 'send-instances.json' }
411	);
412	const data = shallowRef<SendFrameInstance[]>([]);
413	const isLoaded = ref(false);
414	async function load() { data.value = await persistence.load() ?? []; }
415	async function save() { await persistence.save(toRaw(data.value)); }
416	```
