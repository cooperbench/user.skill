## 交付摘要

### Direct contract / Boundary guards

- **Direct contract**: 13 份文档，以 target structure 为 canonical 基线，task/send/receive/storage design + 两份 compound 决策为上游合同。
- **Boundary guards**: result owns 内部结果事实；≠ report、≠ storage、≠ northbound；不冻结外部 schema；不直接消费独立 send/receive event。

### Design 全文要点

1. **Owner scope**: result owns 用例结果判定（CaseResult）、任务结果摘要（TaskResultSummary）、结果归因（CaseStepDetail）、聚合规则（ResultAggregationRule）和结果查询（ResultReadModel）。Not owner: 报告生成、对外交付、外部格式。

2. **Core types**:
   - **CaseResult**: kind (passed/failed/stopped/partial)、verdictSource (auto/manual)、summary、stepDetails、lifecycle
   - **CaseStepDetail**: per-step outcome + rootCause 归因（transport-error / build-error / target-unavailable / condition-timeout）
   - **ResultAggregationRule**: stepFailurePolicy (any-fail/all-fail/threshold) + skipPolicy + timeoutPolicy + stoppedPolicy
   - **TaskResultSummary**: per-task 聚合（totalCases、per-kind counts、lastResult）

3. **关键设计决策: result 不直接消费独立 send/receive event**。所有素材经 TaskInstanceCompletion + TaskStepResult 包装后统一进入 result。send/receive 的原始事实粒度太细，直接消费会导致 result 需要自己聚合和关联。task 已完成 step 级包装。

4. **交互契约**:
   - task → result: TaskInstanceCompletion event (唯一素材入口)
   - send/receive → result: 经 task step 间接消费
   - SCOE → result: 经 task 统一消费，不区分 triggerSource
   - result → report: 只读 CaseResult selector/event
   - result → status: 只读 result statistics
   - result → northbound: 只读 CaseResult 投影
   - result → storage: 请求持久化

### Open questions

1. 手动发送结果是否进入 result → 首轮否，留在 send selector
2. result statistics vs status global stats 边界 → 后续 status design 锁定
3. 多 iteration 结果判定 → 首轮 CaseResult 覆盖整个 completion，per-iteration 保留在 stepDetails
4. TaskDefinition 变更后结果关联 → 记录执行时快照

### Result / Report / Northbound 边界

| 层 | 定位 | owns | does not own |
|---|---|---|---|
| result | 内部事实层 | CaseResult、aggregation rules、result read model | 报告文件、外部格式、交付动作 |
| report | 文件/格式层 | 报告对象生成、素材归集、文件准备 | 内部 truth、HTTP/FTP 交付 |
| northbound | 对外交付层 | 外部投影、交付、错误语义转换 | 内部 truth、报告生成 |

**核心原则**: 三段分离，不互相穿透。northbound 从 result 投影不冻结内部 schema。
