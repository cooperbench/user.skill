  ## 本阶段目标

  在 receive 解析管线中集成表达式引擎，替换当前 field-parser 中硬编码的 factor 换算。

  ### 具体产出

  1. **类型扩展**：`receive/core/types.ts` 的 `ReceiveParsedFieldValue` 增加 `expressionApplied: boolean` + `expressionError?: string`（迁移策略：field-parser 产出时设 `expressionApplied: false`）
  2. **预编译**：`receive-service.ts` 的 `refreshFrameReferences` 增加表达式预编译逻辑，缓存为 `Map<string, CompiledGroup>`（注意：`ExpressionDefinition.expressions` 实际是
  `ConditionalExpressionDefinition[]`，不是 `Map<string, string>`，需先转换）
  3. **表达式求值 pass**：新增独立纯函数，在 field-parser 后执行。输入：compiled + 当前帧 raw 值 + read model 跨帧值（先用简单 Map 存根）+ globalParams（先用空 Map）。输出：复用 `GroupEvalResult`
  4. **单测**：用 expression-engine-brainstorm.md 中的真实样本做 fixture，覆盖：编译失败帧、求值失败字段降级、无表达式字段(factor only)保持 expressionApplied=false

  ### 关键代码位置
  - 表达式引擎 API：`rewrite/src/shared/expression/index.ts`（compileConditional / compileGroup / evaluateGroup / evaluateConditional）
  - 帧类型：`rewrite/src/features/frame/core/types.ts`（ExpressionDefinition = ConditionalExpressionDefinition[] + ExpressionVariableDefinition[]）
  - 当前 field-parser：`rewrite/src/features/receive/core/field-parser.ts`（applyFactor 在 ~行 39）
  - 当前 processor：`rewrite/src/features/receive/core/processor.ts`
  - 当前 service：`rewrite/src/features/receive/services/receive-service.ts`

  ### 约束
  - expression engine 是纯函数，变量全部外部传入
  - receive core 不依赖 Vue/Pinia/Electron
  - 求值失败字段保留 raw value，不阻断其他字段
  - 编译失败帧标记为 config-error，不阻断其他帧
  - read model 本阶段用简单 `Map<string, Map<string, VariableValue>>` 存根，完整实现留阶段 2
