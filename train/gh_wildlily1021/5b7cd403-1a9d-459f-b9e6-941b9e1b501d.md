#### [HIGH] `buildVariableMap` 对 `current_field` 只查 raw values，不查已解析值

**File:** `rewrite/src/features/receive/core/expression-pass.ts:202-206`

```typescript
case 'current_field':
  if (def.fieldId) {
    value = currentFrameRawValues.get(def.fieldId);
  }
  break;
```

`current_field` 仅从 `currentFrameRawValues` 查找。如果 field A 依赖同帧内 field B（两者都是 expression 类型），而 B 在 evalOrder 中先于 A 已被求值，那么 B 的已解析值已存入 `currentFrameResolvedValues`，但 `current_field` 分支不会去查它。

对比同文件 `frame_field` 分支（line 209-211）对同帧内字段做了 `currentFrameResolvedValues.get(...) ?? currentFrameRawValues.get(...)` 的回退查找，`current_field` 缺少这个逻辑。

实际影响：当用户在帧定义中使用 `current_field` 引用同帧内另一个已求值的表达式字段时，变量查找会失败（返回 undefined），该字段会静默降级为 raw value 而非使用正确的已解析值。

**Fix:** 对 `current_field` 分支加上与 `frame_field` 同帧分支一致的回退逻辑：

```typescript
case 'current_field':
  if (def.fieldId) {
    value = currentFrameResolvedValues.get(def.fieldId)
      ?? currentFrameRawValues.get(def.fieldId);
  }
  break;
```

#### [MEDIUM] `ExpressionCompileCache` 类型与 roadmap 合同有偏差 -- 用 `FrameExpressionCompiled` 而非 `CompiledGroup | CompiledConditional`

**File:** `rewrite/src/features/receive/core/types.ts:227-237` 对比 roadmap ss4.2

type ExpressionCompileCache = ReadonlyMap<string, CompiledGroup | CompiledConditional>;

#### [LOW] `compileSingleFrame` 任一字段编译失败即标记整帧失败

**File:** `rewrite/src/features/receive/core/expression-pass.ts:72-74`

```typescript

```

如果帧内有 10 个表达式字段，其中 1 个语法错误，其余 9 个正常的字段也会被跳过。更优的策略是为每个编译失败的字段单独降级，成功的正常求值。
