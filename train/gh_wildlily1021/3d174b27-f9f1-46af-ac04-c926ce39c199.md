Lane B: 全局身份标识与映射冗余审计

  ## 目标
  全局扫描 rewrite/src/features/ 和 rewrite/src/runtime/ 中所有 feature，找出：
  1. 同一概念在不同 feature 中使用不同名称/类型的所有情况
  2. 不必要的映射转换层（像 display→frameId 这种本该直接用却被包装的情况）
  3. 类型重复定义（同一结构在不同 feature 各定义一次）
  4. bridge/selector 中可以做 pass-through 但做了多余转换的代码

  产出：问题清单 + 优先级排序 + 修复建议（不实现代码）

  ## 直接合同
  - rewrite/src/features/（全部 feature 代码）
  - rewrite/src/runtime/（bridge + wiring + routing-tick）
  - rewrite/src/shared/（共享类型和工具）

  ## 边界护栏
  - CLAUDE.md（feature 归口、selector 不可变、shared/ 提取规则）
  - codestable/architecture/rewrite-feature-boundaries.md
  - codestable/architecture/rewrite-target-structure.md

  ## 子 agent 派发策略（18 agent，3 批）

  ### 批次 1：逐 feature 标识模型审计（9 个 explore agent 并行）

  每个 agent 读一个 feature 的全部代码，提取该 feature 使用的所有标识概念。

  **Agent 1：frame 标识审计**
  - 读 rewrite/src/features/frame/ 全部文件
  - 提取所有标识字段：frameId、fieldId、direction、expressionId 等
  - 标注：哪些是该 feature 拥有的权威定义，哪些是从别处引用的
  - 这是基准 — frame 是帧定义的唯一 owner

  **Agent 2：receive 标识审计**
  - 读 rewrite/src/features/receive/ 全部文件
  - 提取所有标识字段：ReadModel 里的 key、MatchedField 里的标识、ReceiveEvent 里的标识
  - 标注：哪些直接复用 frame 的标识，哪些自己定义了新标识
  - 重点关注：processor.ts 产出物中的标识映射

  **Agent 3：send 标识审计**
  - 读 rewrite/src/features/send/ 全部文件
  - 提取所有标识字段：SendRequest 里的 frameId、target 标识、step 标识
  - 标注：哪些复用 frame，哪些自创

  **Agent 4：storage 标识审计**
  - 读 rewrite/src/features/storage/ 全部文件
  - 提取所有标识字段：channel、recordId、timestamp 等
  - 重点关注：channel 标识的定义 — 是否直接用 frameId+fieldId，还是自己搞了一套

  **Agent 5：display 标识审计**
  - 读 rewrite/src/features/display/ 全部文件（已改为 frameId/fieldId）
  - 验证：统一后是否还有残留的独立标识概念
  - 检查：ChartSeriesProjection.fieldId 是否还有歧义

  **Agent 6：status 标识审计**
  - 读 rewrite/src/features/status/ 全部文件（已改为 frameId/fieldId）
  - 验证：统一后是否干净

  **Agent 7：task 标识审计**
  - 读 rewrite/src/features/task/ 全部文件
  - 提取所有标识字段：taskId、stepId、executionId、trigger 标识
  - 标注：step 中引用 frame 的方式，trigger 中引用 receive 数据的方式
  - 重点关注：是否有独立于 frame 的"指令帧"标识

  **Agent 8：command-ingress 标识审计**
  - 读 rewrite/src/features/command-ingress/ 全部文件
  - 提取所有标识字段：command 标识、protocol 标识、consumer 标识
  - 标注：与 task 的关系 — 是否有重复标识

  **Agent 9：connection 标识审计**
  - 读 rewrite/src/features/connection/ 全部文件
  - 提取所有标识字段：connectionId、port 标识、adapter 标识
  - 标注：connectionId 在其他 feature 中的使用方式

  ### 批次 2：跨 feature 映射层审计（5 个 agent 并行）

  **Agent 10：runtime bridges 全量审计**
  - 读 rewrite/src/runtime/bridges/ 全部文件
  - 对每个 bridge：
    - 输入类型是什么（来自哪个 feature）
    - 输出类型是什么（去往哪个 feature）
    - 映射逻辑是什么（identity pass-through / 字段重命名 / 复杂转换）
  - 标注：哪些是 pass-through（好）、哪些做了多余转换（可疑）、哪些确实需要复杂映射（合理）

  **Agent 11：routing-tick + feature-wiring 数据流审计**
  - 读 rewrite/src/runtime/routing-tick.ts
  - 读 rewrite/src/runtime/feature-wiring.ts
  - 画出数据在 feature 间流动时的完整类型变化链
  - 标注：每个类型转换点的位置和原因

  **Agent 12：selector 跨 feature 引用审计**
  - 搜索所有 selector 文件中 import 其他 feature 类型的代码
  - 对每个跨 feature import：
    - import 了什么类型
    - 是否直接使用还是做了映射
    - 是否可以通过对齐类型定义消除映射
  - 这能发现"selector 层的隐式映射"

  **Agent 13：service 跨 feature 调用审计**
  - 搜索所有 service 文件中调用其他 feature public API 的代码
  - 对每个跨 feature 调用：
    - 调用了什么 API
    - 返回值是否直接使用还是做了转换
    - 转换是否必要
  - 这能发现"service 层的隐式映射"

  **Agent 14：shared/ 类型复用审计**
  - 读 rewrite/src/shared/ 全部类型定义
  - 对比各 feature 自己定义的类型，找出：
    - 相同结构但不同命名的类型（如 AFeatureId vs BFeatureKey）
    - 相同枚举但重复定义的情况
    - 可以提取到 shared 但散落在各 feature 的通用类型
  - 同时检查：是否有不该在 shared 的东西（违反 shared 提取规则）

  ### 批次 3：综合分析与收口（4 个 agent）

  **Agent 15：问题汇总与分级**
  - 输入：批次 1 + 批次 2 所有 agent 的发现
  - 按严重程度分级：
    - HIGH：同一概念三个以上不同名称，或映射链超过 2 层
    - MEDIUM：同一概念两个不同名称，有不必要的映射层
    - LOW：命名风格不统一但不影响功能
  - 排除：确实必要的映射（如 domain→presentation 转换、privacy 过滤等）

  **Agent 16：修复方案与影响面**
  - 对每个 HIGH/MEDIUM 问题，给出：
    - 推荐的统一命名（以 frame 为基准）
    - 需要改的文件清单
    - 是否影响已通过验收的测试
    - 实施时机：现在 / display UI 实施时 / 后续集中清理

  **Agent 17：shared/ 提取建议**
  - 基于批次 2 Agent 14 的发现
  - 对每个可提取类型，按 CLAUDE.md shared/ 提取规则判断：
    - 是否在 2+ feature 中使用（必要条件）
    - 是否是纯工具/类型，不含业务逻辑
    - 提取后的 import 路径和文件组织
  - 只建议明确该提取的，不搞预防性提取

  **Agent 18：反向验证**
  - 对每个建议的修复，模拟以下场景：
    1. 修改后是否引入新的循环依赖
    2. 修改后 selector 返回类型变化是否影响消费方
    3. 修改后测试断言需要更新哪些
    4. 是否有正在进行的 feature 实施会被冲突
  - 输出：每个建议的安全等级（安全改 / 需协调改 / 不建议改）
