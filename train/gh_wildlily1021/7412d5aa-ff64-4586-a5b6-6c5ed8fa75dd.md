## 怎么确保不返工

1. **Service Readiness Audit** — 在设计前把 service gap 全扫出来，改代码在先，写 UI 在后

3. **设计文档与代码双向锁定** — design doc 用代码实际存在的字段名，不用将来时的术语。新增功能标注 Phase 分层

## 汇总规则

每个 agent 的产出格式：

```
### [Feature 名]

| # | 待办项 | 来源 | 涉及文件 | 工作量 | 依赖 | 状态 |
|---|--------|------|---------|--------|------|------|
| 1 | ... | audit §X.Y / design checklist #Z | file1.ts, file2.ts | 小/中/大 | 无 / #N | 未开始 / 部分完成 |
```

主对话汇总所有 agent 产出后：
1. 去重（同一文件被多处引用的合并）
2. 按依赖拓扑排序（无依赖的优先）
3. 按执行阶段分组（A: 代码修复 → B: 精简清理 → C: Service gap → D: UI 前置基础设施）
4. 写入 `codestable/quality/pre-ui-implementation-checklist.md`

## 边界

- 这个对话只做整理，不做任何代码修改
- 不做新的设计或 brainstorm
- 不处理 UI 实施本身（那是后续对话）
- 对于已经完成的项，标注"已完成"但不展开
- focus 在"还没做完的"和"需要做的"
