235	- Missing resource, port unavailable, socket error or cleanup failure can be normalized by connection, but this document does not freeze error code names.

173	| UI snapshot | pages / feature composables / widgets | UI can filter, group, throttle, paginate, and display; UI cannot write runtime facts. | UI components only. | UI preference persistence belongs settings only when explicitly designed. |
174	
175	Rules:
176	
177	- Static config, runtime facts, transport read model, UI snapshot must stay separate.
178	- `connection` read model cannot expose mutable internal state references.
179	- Runtime facts are reset by connection lifecycle rules, not by UI unmount alone.
180	- send / receive / task / SCOE must not infer connection facts by importing connection store internals.
181	- Transport counters may exist as connection read model, but business statistics belong to the corresponding feature owner.
182	
183	## 5. Platform / preload / main / renderer boundary
184	
185	Renderer:
186	
187	- Uses only `rewrite/src/platform` facade for desktop capability access.
188	- Does not access `window.electron`, Electron, Node, `ipcRenderer`, `fs`, `path`, `net` or `serialport`.
189	- Does not subscribe directly to raw transport events from preload.
190	- Pages and widgets call connection public service, feature composables, or runtime page-level entry, not platform transport primitives.
191	
192	Platform facade:
193	
194	- Lives in renderer and hides preload details from features.
195	- Exposes capability categories only after corresponding foundation / feature design accepts the capability.
196	- Can expose transport primitives to connection adapters, not to arbitrary pages or features.
197	- Does not own connection config semantics, target identity, receive parsing, send result semantics, task lifecycle, SCOE protocol, result/report/northbound meaning.
198	
199	Preload:
200	
201	- Exposes a minimal typed bridge.
202	- Does not expose raw `invoke/send/on`, arbitrary channel subscription, or all-in-one `window.electron`.
203	- Does not expose `receive` business processing, high-speed storage business rules, history/report semantics, or task/SCOE commands as platform abilities.
204	- For transport, preload may bridge bounded lifecycle, byte I/O and bounded event delivery only after the connection design fixes the capability category.
205	
206	Main process:
207	
208	- Owns platform resources: serial port handles, TCP sockets, TCP server handles, UDP sockets, resource cleanup, app lifecycle, and necessary OS-level I/O.
209	- May retain platform-side buffering, batching, throttling, queueing, stream/file writing and backpressure when tied to platform resources or performance pressure.
210	- Must not define frame parsing, receive classification, task state transitions, SCOE completion, result attribution, report generation, northbound error conversion or business device identity.
211	- Any main-side exception must record why renderer / TypeScript core cannot reasonably own it, what main retains, where business semantics live, and how validation is done.
212	
213	Connection feature:
214	
215	- Is the renderer-side transport domain owner.
216	- Consumes platform transport primitives through adapters.
217	- Normalizes platform facts into transport facts.
218	- Publishes only public service, read-only selector, explicit event, or runtime-facing capabilities.
219	- Does not expose internal state to receive / send / task / SCOE.
220	
221	## 6. Connection public API necessity
222	
223	`connection` needs a public API because receive, send, task, SCOE, status, pages and runtime all depend on transport availability. This public API is a boundary rule, not a required file shape and not a schema definition.
224	
225	Allowed capability categories:
226	
227	- Lifecycle command category: request connect, disconnect, reconnect attempt, resource cleanup, and lifecycle recovery. This does not define method names.
228	- Config query / update category: read or update transport static config through controlled entry; settings may provide defaults, but connection owns transport meaning.
229	- Target selector category: read target availability, target route, connection kind, and status snapshot as immutable read model.
230	- Byte input category: expose incoming transport byte batches or normalized transport input events to receive through runtime or explicit event.
231	- Byte output category: accept transport-level write requests from send / SCOE through public service or runtime; return transport-level acceptance or failure, not business send result.
232	- Error / lifecycle event category: publish transport-level lifecycle and error events for status, pages and runtime.
233	- Test adapter category: allow fake transport adapter injection in tests without exposing platform/main objects.
234	
235	Rules:
236	
237	- Public API must not leak mutable connection state, platform resource handles, raw Electron objects, raw socket instances or serialport instances.
238	- Public API must not freeze DTO, channel names, error code names or enum values in this document.
239	- Public API must not make receive / send / task / SCOE depend on connection store implementation.
240	- If a future feature has no external connection consumer, no extra public API is required for that feature.
241	- If a future flow requires cross-feature write or lifecycle progression, it must state owner, caller, input/output boundary, failure handling and validation level in its feature design.
242	
243	## 7. Runtime involvement
244	
245	`runtime/` is needed only as an application composition and cross-feature orchestration layer.
246	
247	Runtime may:
248	
249	- Create and release connection service, transport adapters and platform subscriptions at application startup and shutdown.
250	- Wire platform facade events into connection service.
251	- Route connection byte batches to receive without letting receive import connection internals.
252	- Route send / SCOE transport write requests to connection public service when the flow spans feature boundaries.
253	- Coordinate lifecycle cleanup when pages close, app exits, user switches profiles, or hardware disconnects.
254	- Register boundary exceptions such as high-frequency buffer / batch / backpressure, high-speed storage short-circuit, SCOE fixed source/target, packaged data path or optional HTTP/FTP transport.
255	- Combine read-only connection snapshot with status or page view model.
256	
257	Runtime must not:
258	
259	- Parse receive bytes.
260	- Build send frames.
261	- Own task lifecycle.
262	- Interpret SCOE protocol.
263	- Define result, report or northbound semantics.
264	- Become a global service locator or hidden event bus.
265	- Directly access Electron, Node, `serialport`, socket handles or file system.
266	
267	## 8. High-frequency data principles
268	
269	Target high-frequency flow:
270	
271	```text
272	platform resource
273	  -> main-side buffer / batch / queue / backpressure when justified
274	  -> typed preload bridge
275	  -> platform facade
276	  -> connection adapter and connection read model
277	  -> runtime route or explicit event
278	  -> receive / send / storage / SCOE public boundary
279	  -> feature read model delta
280	  -> throttled UI snapshot
281	```
282	
283	Rules:
284	
285	- Main may batch, buffer, throttle, queue or apply backpressure for platform-resource reasons.
286	- Main may not classify bytes as receive result, task result, SCOE command success, report material, or northbound delivery status.
287	- Connection may normalize transport-level data availability and transport stats; it does not parse frames or define business result.
288	- Receive consumes byte batches, not raw unbounded per-packet renderer events.
289	- UI consumes throttled snapshots and read-only selectors; UI does not subscribe to raw serial/network events.
290	- Backpressure and overflow policy must be declared in future connection / receive design; this document does not set queue depth, window size, sampling rate or timeout thresholds.
291	- High-speed storage short-circuit is a boundary exception candidate. It must state whether data bypasses normal receive/display/trigger, which feature owns the decision, and what runtime/hardware evidence is required.
292	- Transport-level counters must not become global business statistics. Business stats belong to receive/send/task/SCOE/result/status owners as appropriate.
293	
294	## 9. Disconnect, reconnect, errors, and lifecycle events
295	
296	Principles:
297	
298	- Disconnect and error facts are transport-level facts owned by connection.
299	- Automatic reconnect is not assumed. If added, it must be explicit connection behavior with retry policy, cancellation, UI visibility and validation plan.
300	- A failed send should not itself decide task lifecycle. send may report transport failure; task decides task lifecycle through task-owned rules.
301	- A transport error should not define result/report/northbound failure semantics. result/report/northbound may consume transport facts through public projections.
302	- Close, cleanup and app shutdown must be idempotent and observable enough for runtime/manual validation.
303	- Connection lifecycle events should be low-frequency read model updates; high-frequency data flow should use batch/delta channels separately.
304	
305	Legacy evidence guard:
306	
307	- 旧网络 connect 对已有连接采取先 disconnect 再重建，未体现自动 retry 策略。`src-electron/main/ipc/networkHandlers.ts:33`
308	- 旧 TCP client 的 `error/close/timeout` 主要是状态更新和清理。`src-electron/main/ipc/networkHandlers.ts:120`, `src-electron/main/ipc/networkHandlers.ts:128`, `src-electron/main/ipc/networkHandlers.ts:132`
309	- 旧任务发送失败后才查询 target availability 并暂停任务。`src/composables/frames/sendFrame/useSendTaskExecutor.ts:229`, `src/composables/frames/sendFrame/useSendTaskExecutor.ts:233`

311	## 10. Cross-feature communication
312	
313	Allowed patterns:
314	
315	- Public service: send, SCOE, task or pages call connection-owned command/query capabilities through explicit public entry.
316	- Runtime orchestration: runtime coordinates connection + receive or connection + send/SCOE when a flow crosses feature boundaries.
317	- Explicit event: connection emits declared transport-level events for receive/status/runtime consumers when async decoupling or batching is needed.
318	- Read-only selector: status/pages/widgets consume immutable snapshots or view models.
319	
320	Prohibited patterns:
321	
322	- receive / send / task / SCOE import connection internal `state`.
323	- receive / send / task / SCOE import connection internal adapter or private service implementation.
324	- connection imports receive/send/task/SCOE internal state to push business side effects.
325	- connection writes task status, send stats, receive parse result, SCOE command record, result truth, report file state or northbound transaction.
326	- pages/widgets subscribe to raw platform transport event streams.
327	- status reads raw connection internals instead of public snapshot.
328	
329	Feature consumption boundaries:
330	
331	| Consumer | May consume from connection | Must not do |
332	| --- | --- | --- |
333	| `receive` | incoming byte batches, source snapshot, lifecycle/error events relevant to input availability | import connection state, decide target availability, own transport lifecycle |
334	| `send` | target availability, transport write capability, transport-level write failure | own connection lifecycle, hardcode SCOE/northbound targets, define task result |
335	| `task` | target availability snapshot, explicit send/transport failure material via send result | import connection state, decide low-level retry by reading raw transport |
336	| `scoe` | declared fixed source/target availability through runtime exception, transport write capability | hardcode generic send internals, make connection own SCOE semantics |
337	| `status` | read-only connection summary and lifecycle events | own transport truth or raw platform resources |
338	| `northbound` | only internal projection if later needed through status/task/result/report; no direct transport target = deviceId mapping | treat serial/network target as customer device identity |

124	| `preload` | 最小 typed bridge，把 platform 允许的 transport capability 接到 main；IPC invoke 包装和 event subscription 管理；renderer 隔离边界 | 裸 `invoke/send/on`、任意 channel 订阅、`window.electron` 大包、业务 API |
125	| `platform` facade | renderer 侧 transport primitive 入口；discovery（枚举串口）、lifecycle command（connect/disconnect/cleanup）、byte I/O（write request）、event drain（拉取 main 缓冲事件）、backpressure query | 连接配置语义、target identity 语义、receive parsing、send result、task lifecycle |
126	| `connection` real adapter | 遵守 `ConnectionTransportAdapter` port；调用 platform facade transport primitive；把 platform technical material 映射为已有 connection service 输入；不暴露 platform resource handle | platform resource handle 直接暴露、API schema 定义权、业务帧解析 |
127	| `connection` service/state/core | 不变——real adapter 通过同一 port 接口接入，service/state/core 无需修改 | 任何因 real adapter 而增加的平台依赖 |
128	
129	### 3.2 Key split
130	
131	- main owns live resource facts needed to operate handles。
132	- connection owns canonical renderer-side connection facts。
133	- platform/preload own the bridge boundary, not business interpretation。
134	- runtime owns wiring and exception visibility。

137	
138	Real adapter 必须遵守 `ConnectionTransportAdapter` port 接口，不修改 port 定义。
139	
140	### 4.1 Port compatibility rules
141	
142	| Adapter method | Real adapter behavior | Fake adapter equivalent | Compatibility constraint |
143	| --- | --- | --- | --- |
144	| `connect(config)` | 通过 platform facade 调用 main IPC，main 创建 native resource | 内存 Map 记录 config | 接受相同的 `TransportConfig` 四种 kind；返回相同 `ConnectionAdapterCommandOutcome` |

146	| `write(request)` | 通过 platform facade 发送 bytes 到 main | 记录到 writes Map | 返回 `write-accepted` 或 `write-failed`；携带 `byteLength` |

170	## 5. Event model
171	
172	### 5.1 Event classification
173	
174	Transport events 分为三类：lifecycle、data、backpressure/signal。
175	
176	| Category | Events | Frequency | Producer | Consumer | Design lane |
177	| --- | --- | --- | --- | --- | --- |
178	| Lifecycle | connected、disconnected、error（open-failed、connect-failed、listen-failed、bind-failed、timeout、close-failed、resource-unavailable、stale-event、invalid-config） | Low | main resource handler -> preload bridge -> platform facade -> connection adapter -> connection service | connection state、status read model、pages | Direct event delivery，no batching needed |
179	| Data | data（incoming bytes with connectionId、byteLength、source target） | High | main byte input handler -> batching in main -> preload bridge -> platform facade -> connection adapter drainEvents | connection service -> runtime route -> receive | Batched delivery，main-side buffer，separate from lifecycle |
180	| Backpressure/Signal | queue-full、queue-drained、write-backpressure（write queue full） | Low-Medium | main buffer management | connection adapter、runtime、status | Event-based signal，不自动转成业务错误 |
181	
182	### 5.2 Event flow
183	
184	```text
185	Main process:
186	  native resource event (serial data / socket data / socket close / socket error)
187	    -> main-side per-connection buffer:
188	       - lifecycle/error: immediate -> bounded lifecycle event queue
189	       - data: accumulate in byte batch buffer until window or flush trigger
190	    -> backpressure check:
191	       - if batch buffer exceeds threshold: emit queue-full signal
192	    -> typed event delivery to preload bridge
193	
194	Preload bridge:
195	  receives main events via IPC
196	  -> lifecycle events: immediate forward
197	  -> data events: forward batch as single event
198	  -> backpressure signals: forward as event
199	
200	Platform facade (renderer):
201	  wraps preload bridge API
202	  -> exposes drainEvents() for connection adapter
203	  -> exposes lifecycle command methods (connect/disconnect/write/cleanup)
204	
205	Connection real adapter:
206	  implements ConnectionTransportAdapter port
207	  -> drainEvents() pulls from platform facade
208	  -> maps platform events to ConnectionAdapterEvent[]
209	  -> no platform handle leakage
210	
211	Connection service:
212	  consumes adapter events via existing service logic
213	  -> routes data events to runtime for receive
214	  -> updates connection state for lifecycle events
215	  -> updates transport counters for all events
216	```
217	
218	### 5.3 Event ordering rules
219	
220	- 同一 connectionId 的 lifecycle 和 data 事件必须保序。
221	- 不同 connectionId 的事件可以交错，不需要全局序列号。
222	- `connected` event 必须在 data event 之前到达 service。
223	- `disconnected` event 后不应有同 connectionId 的 data event；若出现，connection service 标记为 `stale-event`。
224	- `write-accepted` 和 `write-failed` 是 command response 的一部分，不是异步 event queue 内容。
225	- Backpressure signal 不中断事件顺序，只是状态标记。
226	
227	### 5.4 Subscription lifecycle
228	
229	```text
230	Runtime startup:
231	  -> create connection service with real adapter
232	  -> adapter subscribes to platform facade event channel
233	  -> platform facade registers preload event listener
234	
235	Connection connect:
236	  -> service calls adapter.connect(config)
237	  -> adapter calls platform facade connect command (IPC invoke to main)
238	  -> main creates native resource, starts buffering
239	  -> main emits 'connected' event via preload bridge
240	  -> adapter drainEvents() picks up 'connected'
241	
242	App shutdown / page close:
243	  -> runtime calls service.cleanup()
244	  -> adapter calls platform facade cleanup command
245	  -> main drains all resources, closes handles
246	  -> platform facade removes event listener
247	  -> stale events after cleanup are discarded by adapter
248	```
249	
250	## 6. Queue / backpressure / batching principles
251	
252	### 6.1 Principles
253	
254	本节只定原则和验证点，不写最终参数。
255	
256	| Principle | Rationale | Verification point |
257	| --- | --- |--- |
258	| Main-side per-connection byte batch buffer | 减少 IPC 消息数量，避免旧系统的逐包穿透 | 验证 serial 115200 baud 和 TCP 高频场景下 IPC 消息速率下降 |
259	| Bounded batch buffer with flush trigger | 防止 batch buffer 无界增长 | 验证 buffer 达到上限时自动 flush，不等待时间窗口 |
260	| Time-window flush for low-frequency data | 低频数据不应因 batch 而延迟过长 | 验证空载或低频场景下 data event 在合理时间内到达 renderer |
261	| Bounded async event queue with overflow signal | eventQueue 不可无界 | 验证 queue 超限时 backpressure signal 到达 connection adapter |
262	| Overflow must be observable transport material | 丢弃不是静默行为 | 验证 overflow event 包含丢弃的 connectionId 和 byte count |
263	| Per-connection queue isolation | 一个连接的背压不应阻塞其他连接 | 验证 serial 和 TCP 同时高频时，serial 背压不影响 TCP 事件 |
264	| Main does not classify bytes | main 只做 buffer/batch/queue，不判断 frame content | 验证 main handler 代码不包含 frame matching、SCOE rule 或 receive classification |
265	| Overflow must not auto-convert to business error | 丢弃是 transport material，receive/send/task 自己决定业务含义 | 验证 overflow event 不进入 receive 作为 parse failure |
266	
267	### 6.2 Batch buffer design lane
268	
269	```text
270	Main per-connection byte input:
271	  native data callback
272	    -> append to per-connection byte buffer
273	    -> if buffer size >= maxBatchBytes: flush immediately
274	    -> else if time since last flush >= maxBatchWindowMs: flush
275	    -> flush: emit single 'data' event with accumulated bytes + source info
276	    -> if event queue depth >= maxQueueDepth: emit queue-full signal, apply drop policy
277	    -> drop policy candidate: drop oldest batch (latest data is more relevant for real-time systems)
278	```
279	
280	具体参数（maxBatchBytes、maxBatchWindowMs、maxQueueDepth）在 implementation 阶段根据 runtime evidence 和 hardware testing 确定。
281	
282	### 6.3 Write queue design lane
283	
284	```text
285	Main per-connection write:
286	  write request from renderer
287	    -> if native resource is live: write bytes directly
288	    -> if write callback indicates backpressure (drain event): queue subsequent writes
289	    -> if write queue exceeds threshold: return write-backpressure to adapter
290	    -> on drain: flush queued writes
291	```
292	
293	Write queue 与 input queue 独立管理，互不影响。
294	
295	### 6.4 What must NOT happen
296	
297	- 不可让 main 根据 byte content 决定 data 是否进入 renderer（旧 high-speed storage short-circuit 模式）。
298	- 不可让 batch window 导致低频数据无限延迟。
299	- 不可让 eventQueue 无界增长（旧 receiveFramesStore 模式）。
300	- 不可让一个连接的背压阻塞其他连接的事件传递（旧全局 processingLock 模式）。
301	- 不可让 renderer-to-main 的 IPC round-trip 成为每包处理的瓶颈（旧 receiveHandler invoke 模式）。

304	
305	### 7.1 Lifecycle state mapping
306	
307	| Native event | Main emits | Adapter maps to | Connection lifecycle status |
308	| --- | --- | --- | --- |
309	| Serial port open success | connected event with target snapshot | `ConnectionAdapterEvent { kind: 'connected' }` | `connected` |
310	| TCP socket connect success | connected event with target snapshot | `ConnectionAdapterEvent { kind: 'connected' }` | `connected` |
311	| TCP server listen success | connected event with listener target snapshot | `ConnectionAdapterEvent { kind: 'connected' }` | `connected` |
312	| UDP bind success | connected event with local bind target | `ConnectionAdapterEvent { kind: 'connected' }` | `connected` |
313	| TCP server client accepted | connected event with client target snapshot | `ConnectionAdapterEvent { kind: 'connected' }` + new target | `connected` for server, new target available |
314	| Native resource close | disconnected event | `ConnectionAdapterEvent { kind: 'disconnected' }` | `disconnected` |
315	| Native resource error | error event with error kind | `ConnectionAdapterEvent { kind: 'error' }` | `error` |
316	| User disconnect request | disconnected event after resource close | `ConnectionAdapterEvent { kind: 'disconnected' }` | `disconnected` |
317	| App shutdown | cleanup drains all resources | multiple `disconnected` events | all `disconnected` |
318	| Stale event after cleanup | discarded by adapter | not mapped | no change |
319	
320	### 7.2 Error kind mapping
321	
322	| Native error | Main emits error kind | Adapter maps to `TransportErrorKind` |
323	| --- | --- | --- |
324	| Serial port not found | `resource-unavailable` | `resource-unavailable` |
325	| Serial open rejected by OS | `open-failed` | `open-failed` |
326	| TCP connect refused/timeout | `connect-failed` or `timeout` | `connect-failed` or `timeout` |
327	| TCP server bind failed | `listen-failed` | `listen-failed` |
328	| UDP bind failed | `bind-failed` | `bind-failed` |
329	| Write to closed socket | `write-failed` + `resource-unavailable` | `write-failed` |
330	| Socket unexpected close | `disconnected` + optional error | `disconnected` |
331	| Serial device unplug | `disconnected` + error | `disconnected` + error |
332	
333	### 7.3 Error boundary rules
334	
335	- Transport error 只作为 connection fact 或 consumer input material。
336	- Write failure 只向 send/SCOE 提供 transport-level material，send/task/SCOE 自己决定业务含义。
337	- Disconnect 或 timeout 是 connection fact，不直接定义 result/report/northbound failure。
338	- Error visibility 属于 connection pages/status read model；UI 显示 sanitized summary，不泄漏 platform resource internals。
339	- 不让 main 根据 error kind 决定 task lifecycle、SCOE completion 或 report semantics。

145	## 5. API surface shrink list
146	
147	### 5.1 Delete
148	
149	- 删除目标架构中的 `window.electron` 大包暴露方式；旧 `src-electron/preload/index.ts` 只能作为证据。
150	- 删除或停止扩展 `src/api/common/index.ts` 这类万能 renderer API barrel。
151	- 删除 renderer 侧直接 Electron/Node 入口：`src/utils/common/ipcUtils.ts`、`src/utils/common/fileUtils.ts`、`src/utils/common/dialogUtils.ts` 的当前归口形态不能进入新 renderer 树。
152	- 删除 `timerManager.onCustomEvent` 这类任意 channel 订阅能力；后续如需事件，只能由 runtime/feature design 声明固定边界。
153	- 删除 `src/composables/common/useFileDialog.ts` 与主 file dialog flow 重复的直连/fallback 路径。
154	- 删除 `systemApi.electronAPI` 这种兼容兜底对象在目标架构中的正式地位。
155	
156	### 5.2 Merge
157	
158	- 合并 window/menu/app shell 能力：app shell 只消费一条 platform shell capability path，不再让 `useWindowControls` 和 `systemApi.windowAPI` 并行。
159	- 合并 files/path/dialog 能力：保留一条 app shell file dialog + platform file/path + feature adapter 路径，不保留 `dialogUtils`、`fileDialogManager`、`useFileDialog` 多套 fallback。
160	- 合并 file/path 的平台实现：platform 只表达受控文件、受控路径和打包态能力；storage/report/frame/settings 各自拥有业务语义。
161	- 合并 scheduling 能力：main timer、preload timer、renderer wrapper 和 composable 统一为 platform scheduling facility + feature consumer，不复制局部 timer manager。
162	- 合并 IPC tooling 到 main platform tooling；renderer `src/utils` 不再持有 `ipcMain` helper。
163	
164	### 5.3 Migration evidence only
165	
166	- `src/api/common/*Api.ts` 是旧能力清单和 fallback 行为证据，不是新 platform 命名或接口合同。
167	- `src-electron/preload/api/*` 是旧 bridge 形态证据，不是目标 preload 暴露清单。
168	- `src-electron/main/ipc/*` 是平台资源、业务泄漏和高频风险证据，不是目标 main 责任边界。
169	- 旧 `path.getDataPath()` 指向开发/打包路径的行为只能作为 packaged data path 风险证据，不能冻结为长期路径策略。
170	- 旧 high-speed storage short-circuit 是必须解释的行为证据，不能默认成为新 receive/storage 数据流。
171	
172	### 5.4 Feature-owned
173	
174	- `receiveApi` 不能迁成 `platform/receive`。receive matching、mapping、cache、stats、result output 归 `features/receive`。
175	- `dataStorageApi`、`historyDataApi`、`highSpeedStorageApi` 不能都原样迁成 platform API。storage/history/high-speed 的数据模型、清理口径、导出语义、rule matching 和统计含义归 `features/storage` 或对应 feature design。
176	- serial/network 的 connection status、target route、target availability 和 transport identity 归 `features/connection`；northbound device identity 归 `features/northbound`。
177	- timerManager 的 timed send、task lifecycle、SCOE wait/completion、status polling meaning 分别归 `task`、`scoe`、`status`，不归 platform scheduling。
178	- file import/export validation、旧 JSON migration、history/CSV/report material、report generation 和 northbound delivery closure 都归 feature。
179	
180	### 5.5 Deferred
181	
182	- `autoLaunch` 后置到 settings/app shell 需求确认；无用户可见需求前不作为目标 platform surface。
183	- `menuAPI` 后置到 app shell/menu UX 确认；当前无上游调用证据时不主动暴露。
184	- raw `path.resolve` 与最终 `getDataPath` 语义后置到 packaged data path design 和 runtime evidence。
185	- serial/TCP/UDP 事件模型、batch/backpressure 参数、queue/window/overflow 策略后置到 connection/receive design 和 runtime evidence。
186	- HTTP/FTP transport 后置到 northbound phase-one/customer assets；本轮只保留 optional platform capability category。
187	- high-speed storage short-circuit 是否保留、何时短路普通 receive/display/trigger 链，后置到 storage/receive/high-frequency design。
188	
189	### 5.6 Runtime exception registry required
190	
191	后续触达以下能力时必须登记 runtime boundary exception，而不是隐式沉积在 platform/main handler 中：
192	
193	- high-frequency buffer/batch/backpressure for serial/network data.
194	- high-speed storage short-circuit or direct file write path.
195	- packaged data path and writable data root.
196	- temporary main-side receive processing if any migration step cannot remove it immediately.
197	- SCOE fixed source/target/completion boundary.
198	- optional HTTP/FTP northbound delivery transport.
199	- scheduling assumptions that rely on main timers, multi-window target, drift control, or cleanup ordering.

201	## 6. Special reduction decisions
202	
203	- `receiveApi` 不能迁成 `platform/receive`。receive 是 feature-owned domain; platform 只提供 transport input、必要 batch/backpressure 和 typed boundary。
204	- `dataStorageApi/historyDataApi/highSpeedStorageApi` 不能都原样迁成 platform API。它们必须拆成 platform file/path/high-frequency facility 与 storage/history/high-speed feature semantics。
205	- `timerManagerApi` 不能变成万能跨进程调度中心。platform scheduling 只负责 timer facility；feature 必须声明用途、取消策略、owner 和验证。
206	- `serialApi/networkApi` 只能保留 transport 能力。connection/status/target/device identity 语义不归 platform；northbound `deviceId` 不等同 serial/network target。
207	- file/path/dialog/window 能力必须合并重复入口，删除静默 fallback 和绕行路径，不保留多套并行 file dialog 或 window control path。

209	## 7. Runtime Boundary Exception Registry Template
210	
211	本文只定义登记格式，不登记具体实现。后续任何 exception record 必须按此模板补齐。
