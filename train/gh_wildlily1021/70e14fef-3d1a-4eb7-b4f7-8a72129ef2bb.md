  ## 审计方法

  1. 启动 dev server：`pnpm -C rewrite dev`
  2. 逐页面截图并分析：
     - `/` Home 页面
     - `/connection` 连接管理
     - `/frames` 帧定义列表
     - `/frames/editor/test` 帧定义编辑
     - `/send` 帧发送
     - `/tasks` 任务管理
     - `/command-ingress` 指令接入
  3. 每个页面截图后，逐条对照 conventions.md 和 checklist.md 检查

  ## 审计维度

  按以下 pattern 分组记录问题：

  ### P1: 表单 pattern
  - 是否使用 QForm + QInput/QSelect 组件（不要手搓表单）
  - 表单项间距是否用 UnoCSS utility class（gap-2/gap-3 等）
  - 表单项 label 位置是否统一
  - 表单校验是否接入 QForm validation

  ### P2: 弹窗 pattern
  - 弹窗宽度是否用 token class（rw-dialog-sm/md/lg）
  - 弹窗是否有完整的头部/内容/底部按钮
  - 弹窗内表单是否遵循 P1 规范
  - 缺失的功能（比如某些弹窗只有空壳）

  ### P3: 工具栏 pattern
  - 搜索框是否和操作按钮在同一行
  - 搜索框宽度是否合理（不要独占一行）
  - 筛选/排序入口是否统一

  ### P4: 表格 pattern
  - 表格列宽是否合理
  - 操作列是否统一（编辑/删除按钮位置）
  - 空状态是否有占位提示
  - 分页是否统一

  ### P5: 布局/间距
  - 页面内各区块间距是否一致
  - 是否有硬编码 px/rem 值（应使用 token 或 UnoCSS class）
  - 卡片/面板 padding 是否统一

  ### P6: 状态展示
  - 状态 badge 是否使用 StatusBadge widget
  - 颜色是否通过语义 class 消费 token
  - 空状态是否有图标 + 文字提示

  ## 输出格式

  页面：[页面名]

  P1 表单

  - [P1-01] 问题描述 | 文件:行号

  P2 弹窗

  - [P2-01] 问题描述 | 文件:行号

  ...

  最后汇总：
  - 各 pattern 的问题数量
  - 跨页面共性问题（一次修复所有页面的）
  - 页面特有问题（单页修复）
  - 建议的修复优先级

  - 只审计记录，不做任何代码修改
  - 交互类 bug 标注为 [INTERACT-xx]，用户会自行补充
  - 所有静态问题必须标注具体文件和行号
