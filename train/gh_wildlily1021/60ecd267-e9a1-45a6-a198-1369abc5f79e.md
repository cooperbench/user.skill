  ### 修复 1：FrameDetailPanel props 未处理 null

  文件：features/frame/components/FrameDetailPanel.vue

  当前 props 定义 `frame: ReadonlyFrameAsset` 是必填，但父组件 FrameListPage 在 `detailFrame` 为 null 时通过 `v-if` 隐藏了整个面板。

  改法：props 改为 `frame?: ReadonlyFrameAsset`（可选），template 中加 `v-if="frame"` 保护内部渲染。
  这比依赖父组件 v-if 更防御——如果未来其他消费方忘记 v-if，组件不会崩溃。

  ### 修复 2：tableRows computed 违反 P4（引用稳定）

  文件：pages/FrameListPage.vue

  当前：
  ```ts
  const tableRows = computed<TableRow[]>(() =>
    frameList.value.map((frame, index) => ({ ...frame, _index: index + 1 })),
  );
  const selectedRows = computed<TableRow[]>(() =>
    tableRows.value.filter((row) => selectedFrameIds.value.includes(row.id)),
  );

  问题：每次 computed 依赖变化时都产生全新数组引用，触发下游全量 diff。

  改法：tableRows 改为 shallowRef + watch(frameList, ...) 手动更新。selectedRows 同理改为 shallowRef + watch。
  QTable 消费 shallowRef 时整组替换是正确模式（P2 已覆盖）。

  const tableRows = shallowRef<TableRow[]>([]);
  const selectedRows = shallowRef<TableRow[]>([]);

  watch(frameList, (list) => {
    tableRows.value = list.map((frame, index) => ({ ...frame, _index: index + 1 }));
  }, { immediate: true });

  watch([tableRows, selectedFrameIds], ([rows, ids]) => {
    selectedRows.value = rows.filter((row) => ids.includes(row.id));
  }, { immediate: true });

  注意：这里 frameList 数据量小（帧列表 < 100），性能影响可忽略。但作为模式示范——
  后续页面（任务列表、命令日志、HEX 记录）数据量可能更大，应从一开始就使用正确模式。

  如果还没跑，先检查 ImportFrameDialog.vue 中的 class="rw-dialog-md" 是否生效——
