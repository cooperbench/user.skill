### 4. IPC Channel Naming Convention

**Pattern:** `transport:<action>-<target>`

| Channel | Purpose |
|---------|---------|
| `transport:enumerate-serial-ports` | List serial ports |
| `transport:serial-connect` | Connect serial port |
| `transport:serial-disconnect` | Disconnect serial |
| `transport:serial-write` | Write to serial |
| `transport:cleanup` | Cleanup all serial |
| `transport:network-connect` | Connect network (TCP/UDP) |
| `transport:network-disconnect` | Disconnect network |
| `transport:network-write` | Write to network |
| `transport:network-cleanup` | Cleanup all network |
| `transport:event` | Event channel (renderer ← main) |

### Summary

The platform facade pattern follows this architecture:

1. **Types Layer** (`platform/bridge-types.ts`): Shared TypeScript interfaces
2. **Facade Layer** (`platform/transport.ts`): Factory to create facades
3. **Access Layer** (`platform/index.ts`): Renderer access to exposed bridge
4. **Preload Layer** (`preload/index.ts`): IPC bridge implementation
5. **Handler Layer** (`main/*-handlers.ts`): Main process IPC handlers
6. **Main Entry** (`main/index.ts`): Registers handlers with window lifecycle

The pattern provides type safety across the boundary, clean separation of concerns, and batched event delivery for performance.
