120	### 4.4 Public API necessity
121	
122	后续实现只在真实消费者存在时声明最小允许入口，不机械创建同构 `public.ts`。
123	
124	需要 storage service/selector 的消费者：
125	
126	- frame：需要通过 storage adapter/app shell 完成本地 frame asset 的导入导出、legacy JSON material 读取和 migration fixture 管理；frame JSON 语义仍归 frame。
127	- settings：需要持久化设置值或读取 storage-related config snapshot，例如记录开关、保存间隔、默认导出路径；settings 仍是配置事实 owner。
128	- receive：需要把显式 receive output 或 local record material 交给 storage 写入 history/local record；receive 仍 owns 解析事实和接收 read model。
129	- pages/storage/history：需要读取 history hour list、storage read model、CSV export 进度和 local file result；页面只消费 UI snapshot 和公开 selector。
130	- runtime：启动加载、flush、shutdown、cleanup、边界例外登记时可调用 storage 公开服务。
131	- report：未来如需读取 local material，只能由 report design 声明 selector/service 边界；本轮不建立长期 report contract。
132	
133	不需要 storage public API 的对象：
134	
135	- connection/serial/network 不能直接调用 storage 内部规则；高速存储短路必须经 runtime exception 和后续 design。
136	- result 不通过 storage 定义内部结果 truth。
137	- northbound 不直接读取 history/CSV/local export 作为 delivery closure。
138	- widgets 不直接读取 storage internals 或 platform files/path；只吃 page/runtime/feature 传入的 view model。
139	- platform 不调用 storage 业务规则；platform 只执行受控文件、路径、对话框、流式写入等能力。
140	
141	禁止形态：
142	
143	- 不暴露任意路径读写、动态 data type CRUD 或旧 `window.electron.dataStorage/historyData/highSpeedStorage` 形态。
144	- 不暴露可变 storage state、内部 store、adapter 实例或文件系统路径拼接 helper。
145	- 不让 report/northbound 通过 storage API 跳过 result/report owner。
146	
147	root public API 口径以 `rewrite/src/features/storage-local-baseline/index.ts` 为准：
148	
149	- 保留公开：`createStorageLocalService`、`createStorageLocalReader` 及其类型；`LocalMaterialAdapter`、`LocalMaterialAdapterError` 等 adapter port 类型；本地记录、history、CSV、legacy material、validation result 等只读或材料类型；`STORAGE_LOCAL_RECORD_SOURCES`、`STORAGE_MATERIAL_BUCKETS`、`getStorageHourKey`、`queryStorageLocalRecords`、`cleanupStorageLocalRecords`、`summarizeStorageHours`、`createStorageCsvMaterial` 等确定性 core helper。
150	- 上述 core helper 仅作为纯函数 public utility，用于本地记录筛选、小时汇总、CSV material 生成和候选枚举复用；它们不是 mutable state、platform API、path helper、adapter 实例或跨 feature 写入口。
151	- 视为内部：`createStorageState`、state container、fake adapter、clone/normalize/merge/createIssue/legacy classify 等 feature 内部装配和校验细节，以及 selector 的独立函数出口。外部默认通过 service/reader 读取 projection；若后续有真实消费者需要独立 selector，必须再经 root index 显式升级为 public API。

153	### 4.5 Runtime involvement
154	
155	storage-local-baseline 需要 runtime 参与，但 runtime 只做装配、生命周期和边界路由。
156	
157	runtime 可以负责：
158	
159	- 应用启动：按顺序装配 storage service、settings snapshot、frame/settings 等 source feature 的加载入口。
160	- flush：为 history/local records 建立显式批量 flush 或触发保存时机；flush 的记录语义归 storage，source facts 归对应 feature。
161	- shutdown：应用退出前触发 storage flush、释放文件 adapter、记录未完成写入的可见错误。
162	- cleanup：周期性或用户触发的本地历史清理、过期数据删除、local export 临时状态清理。
163	- exception registry：登记 packaged data path、高速存储 short-circuit、main-side file stream/rotation、未来 HTTP/FTP local material access 等例外。
164	
165	runtime 不得负责：
166	
167	- local record 字段含义、history/CSV 语义、legacy JSON migration 规则。
168	- receive 解析、send 构帧、task 状态推进、SCOE 协议、result truth、report object、northbound delivery/error 语义。
169	- 原生文件系统、路径拼接或 native dialog 细节。
170	
171	### 4.6 Platform involvement
172	
173	platform/app shell 是 files/path/dialog 的能力 owner；storage 是本地持久化语义 owner。
174	
175	platform/main/preload 可以承接：
176	
177	- 受控文件选择、保存对话框、目录选择和对话框结果。
178	- 受控读取、写入、删除、列出、元数据读取、目录准备。
179	- 受控 data path category、packaged state 查询和路径类别解析。
180	- 与平台资源绑定且性能压力明显的文件 stream、rotation、batch、backpressure。
181	
182	platform/main/preload 不得承接：
183	
184	- `DATA_PATH_MAP` 动态业务类型生命周期。
185	- history/local record model、CSV 字段选择和导出语义。
186	- high-speed rule matching、connectionId 业务解释、stats interpretation。
187	- report delivery success、northbound FTP/HTTP 交付闭环。
188	
189	打包态 data path 是本 feature 的 runtime blocker。旧 `process.resourcesPath/public` 或开发态 `path.resolve()/public` 只能登记为风险和 migration evidence，不能成为新长期写入策略。
