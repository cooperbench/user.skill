392	以下变更必须在 UI 实施前完成。UI 层不做任何补丁适配，所有能力缺口在 service 层修复。
393	
394	### S1: Frame Service 暴露单帧操作
395	
396	**当前问题**：service 只暴露 `replaceFrames`（全量替换），但 UI 所有操作都是单帧级别。迫使 UI 写读-改-写模板代码。
397	
398	**变更**：
399	- `FrameAssetService` 新增 `upsertFrame(frame: FrameAsset): FrameAssetOperationResult`
400	- `FrameAssetService` 新增 `removeFrame(frameId: string): FrameAssetOperationResult`
401	- 内部实现委托给 `FrameStateContainer.upsertFrame` / `removeFrame`（state 层已有）
402	
403	**UI 消费方式**：
404	```ts
405	// 收藏切换 — 直接调，不读全量
406	await service.upsertFrame({ ...frame, isFavorite: !frame.isFavorite })
407	// 删除 — 直接调
408	await service.removeFrame(frameId)
409	```
410	
411	`replaceFrames` 保留，仅用于导入等全量替换场景。
412	
413	### S2: Connection Service 类型修正
414	
415	**当前问题**：`connect(config: unknown)` 接收 unknown，类型安全全靠消费方自觉。
416	
417	**变更**：
418	- 签名改为 `connect(config: TransportConfig): Promise<ConnectionOperationOutcome>`
419	- 内部 `normalizeTransportConfig` 不变，只是入参类型收紧
420	
421	### S3: Connection Service 原子化 connect
422	
423	**当前问题**：`connect` 在 `adapter.connect()` 之前就 `upsertConfig`，失败后幽灵 config 留在 state 中。UI 层无法清理（service 没有 removeConfig）。
424	
425	**变更**：
426	- `connect` 内部流程改为：先 adapter.connect()，成功后才 upsertConfig + applyEvent
427	- 失败时不写入任何 state，直接返回失败结果
428	- 如需记录失败信息，通过单独的 error event（不绑定 config）
429	
430	### S4: Connection Reader 暴露 discoverResources
431	
432	**当前问题**：`discoverResources` 只在 `RealSerialAdapter` 上，UI 需穿透到 adapter 层调用。
433	
434	**变更**：
435	- `ConnectionReader` 接口新增 `discoverResources(): Promise<readonly ConnectionResourceCandidate[]>`
436	- `createConnectionService` 内部委托给已注册的 serial adapter
437	- 无 serial adapter 时返回空数组
438	- UI 只调 `service.discoverResources()`，不引用 adapter

443	
444	### C1: Composable 抽取
445	
446	实现时必须抽取以下 composable，页面组件只做编排和渲染：
447	
448	| Composable | 位置 | 职责 | 消费页面 |
449	|---|---|---|---|
450	| `useFrameList` | `features/frame/composables/` | query 组合 + shallowRef + watch + refreshList | FrameListPage |
451	| `useFrameEditor` | `features/frame/composables/` | workingFrame + dirty tracking + save + route guard | FrameEditorPage |
452	| `useFieldEditor` | `features/frame/composables/` | fieldEditorOpen + editingIndex + openAdd / openEdit / saveField / removeField | FrameEditorPage |
453	| `useAsyncOperation` | `shared/composables/` | operatingIds + execute(fn, id) + notify，通用防重入 | FrameListPage, ConnectionPage |
454	
455	**注意**：不需要 `useFrameMutations`（S1 后单帧操作直接调 service）和 `useConnectionPage`（discoverResources 和 connect 已归口 service，不需要 composable 层适配）。
456	
457	**useAsyncOperation 签名**:
458	```ts
459	export function useAsyncOperation() {
460	  const operatingIds: Readonly<Ref<Set<string>>>
461	  function isOperating(id: string): boolean
462	  async function execute<T>(
463	    id: string,
464	    fn: () => Promise<T>,
465	    opts?: { onSuccess?: (r: T) => void; onError?: (e: unknown) => void }
466	  ): Promise<T | undefined>
467	}
468	```
469	
470	### C2: 组件结构约束
471	
472	**provide/inject 替代 prop drilling**:
473	- `FrameEditorPage` provide `{ frameId, allFields }` context
474	- `FrameFieldExpressionConfig` inject 消费，不再透传过 FrameFieldList / FrameFieldEditorDialog
475	
476	**autoConnect QToggle 提到 v-if 块外**:
477	- `NewConnectionDialog` 中 autoConnect 是所有连接类型共享的字段，放在类型特定字段下方，不随 v-if 重复
478	
479	**字段编辑对话框脏保护**:
480	- `FrameFieldEditorDialog` 内部维护 `fieldDirty` ref
481	- 对话框打开且有脏修改时：点关闭 → 确认丢弃；点其他字段 → 确认切换
482	- `onBeforeRouteLeave` 检查 `isDirty || fieldEditorDirty`
483	
484	### C3: 生命周期管理
485	
486	**连接页 UI 刷新**:
487	- `ConnectionPage.vue` 使用独立的 `setInterval` + `service.getSnapshot()` + `selectConnectionSummaries()` 轮询连接状态
488	- `onMounted` 启动 interval，`onBeforeUnmount` 清除
489	- 不使用 `runtime.startTickDriver()`（tick driver 是全局数据路由引擎，不属于单页面）
490	
491	**operatingIds 覆盖所有按钮**:
492	- 连接卡片 operating 后，该卡片所有按钮（连接/断开/删除/autoConnect toggle）全部禁用
493	- 防止同一连接的并发操作

496	- 所有 async 操作使用 `disposed` flag，`onUnmounted` 设为 true
497	- 回调中检查 `if (disposed) return`

499	### C4: 错误处理边界
