> DEVELOPER

Lane B: 全局 UI 架构设计（brainstorm → design）

  ## 目标
  设计 rewrite 应用的整体页面结构、导航体系、布局骨架、共享 widget 规范和路由体系。
  这是所有页面详细设计的基础——定好框架后，后续逐页面设计都在这个框架内做。
  本对话不定单个页面的细节布局，只定共用模式和整体结构。

  ## 直接合同
  - codestable/quality/rewrite-frontend-conventions.md（前端规范，必须遵守）
  - codestable/quality/rewrite-frontend-checklist.md（自检清单）
  - rewrite/src/css/（已有 token 基线）
  - rewrite/uno.config.ts（UnoCSS 配置）

  ## 边界护栏
  - CLAUDE.md（rewrite 总原则、UI 样式规则、Electron 边界、Quasar 使用规则）
  - codestable/architecture/rewrite-target-structure.md（目录结构）
  - codestable/compound/2026-05-07-runtime-next-phase-global-planning.md（Wave 7 定位）
  - rewrite/src/pages/（已有页面结构）
  - rewrite/src/widgets/（已有 widget）
  - rewrite/src/app/（已有 app 壳）

  ## 子 agent 派发策略（15 agent，4 批）

  ### 批次 1：现状与旧行为探索（5 个 explore agent 并行）

  **Agent 1：旧系统页面清单与入口**
  - 搜索旧系统 src/ 下的所有页面/路由定义
  - 提取：有多少个页面、每个页面叫什么、入口在哪
  - 标注：哪些是核心页面（高频使用）、哪些是辅助页面
  - 只看用户可见的页面入口，不看内部组件

  **Agent 2：旧系统导航与布局结构**
  - 读旧系统的主布局组件、侧边栏、导航栏
  - 提取：导航方式（侧边栏/顶部标签/下拉）、布局分区、页面切换方式
  - 标注：用户反馈好的交互、不方便的地方

  **Agent 3：新系统已有 UI 代码**
  - 读 rewrite/src/pages/ 全部文件
  - 读 rewrite/src/widgets/ 全部文件
  - 读 rewrite/src/app/ 全部文件
  - 提取：已有哪些页面、已有哪些 widget、AppShell 当前状态
  - 标注：哪些是骨架、哪些有实质内容

  **Agent 4：CSS token 与 Quasar 主题现状**
  - 读 rewrite/src/css/tokens/ 全部文件
  - 读 rewrite/src/css/ 主入口
  - 读 rewrite/quasar.config.ts 中的 Quasar 配置和 brand 设置
  - 提取：已定义的 token（颜色、间距、字体、阴影、圆角、z-index）
  - 提取：Quasar 组件配置（哪些组件全局注册、brand 色、dark mode 支持）

  **Agent 5：旧系统共享 UI 模式**
  - 搜索旧系统中的通用表格组件、通用表单组件、通用对话框
  - 提取：哪些模式被多个页面复用
  - 标注：哪些写得好可以借鉴思路、哪些写得差必须避免
  - 特别关注：表格（用户说之前写得不好）

  ### 批次 2：参考项目 UI 模式（3 个 agent 并行）

  **Agent 6：参考项目页面结构**
  - 读 refactor/docs/conventions/frontend.md 中关于页面布局的部分
  - 读 refactor/docs/quality/frontend.md 中关于布局规范的部分
  - 提取：参考项目的页面结构模式、布局约定
  - 标注：哪些适用于 Electron 桌面应用、哪些是 Web/SSR 特有不适用

  **Agent 7：参考项目共享组件模式**
  - 搜索参考项目中跨页面复用的组件模式
  - 提取：表格包装器、表单包装器、对话框模式、工具栏模式
  - 标注：哪些可以直接借鉴

  **Agent 8：Electron 桌面应用 UI 最佳实践**
  - 搜索 Quasar + Electron 的推荐布局模式
  - 关注：窗口尺寸管理、响应式在桌面应用的适配策略、多窗口 vs 单窗口多标签
  - 提取：适用的模式和建议

  ### 批次 3：设计分析（4 个 agent，基于批次 1+2 产出）

  **Agent 9：导航体系设计**
  - 输入：Agent 1（旧页面清单）+ Agent 2（旧导航）+ Agent 3（新系统现状）
  - 分析：
    - 导航方式：侧边栏 vs 顶部标签 vs 混合
    - 页面分组：按业务域（帧/连接/收发/任务/存储/设置）还是按工作流（配置/运行/分析）
    - 多设备场景：同一类型页面多个实例还是标签切换
    - 快捷入口：收藏页、最近使用、全局搜索
  - 给出 2-3 个方案对比

  **Agent 10：布局骨架设计**
  - 输入：Agent 3（新系统现状）+ Agent 4（token）+ Agent 6（参考项目）
  - 分析：
    - AppShell 结构：header/sidebar/main/footer 的分区
    - 内容区布局：单栏/双栏/可调整分栏
    - 工具栏模式：页面级工具栏统一规范
    - 状态栏：全局状态展示（连接状态、运行状态）
  - 给出 ASCII 布局图

  **Agent 11：共享 widget 清单设计**
  - 输入：Agent 5（旧系统共享模式）+ Agent 7（参考项目组件）+ 前端规范
  - 分析：需要哪些跨页面共享的 widget：
    - 数据表格（参数表、帧列表、任务列表等复用）
    - 表单布局（连接配置、任务编辑等复用）
    - 对话框（确认、输入、选择）
    - 状态指示器（连接状态、运行状态）
    - 工具栏组件
    - 空状态/loading 组件
  - 每个 widget：职责、props 接口草案、适用的页面

  **Agent 12：路由与页面入口设计**
  - 输入：Agent 1（旧页面清单）+ Agent 9（导航体系）
  - 分析：
    - 路由结构设计
    - 页面入口与导航的映射
    - 页面间跳转场景
    - 嵌套路由需求（如帧列表 → 帧编辑器是否为子路由）
    - 404/错误页

  ### 批次 4：自检与收口（3 个 agent）

  **Agent 13：前端规范合规检查**
  - 用 codestable/quality/rewrite-frontend-checklist.md 逐项检查设计方案的每个维度
  - 标注合规状态，列出冲突点

  **Agent 14：旧功能覆盖度检查**
  - 逐项检查旧系统每个页面入口在新导航/路由设计中是否有对应
  - 标注：覆盖/合并/删除+原因

  **Agent 15：过度设计审查**
  - 按 CLAUDE.md 过度设计审查 5 维度检查：
    - 导航复杂度是否匹配实际页面数量
    - widget 抽象是否过早（有没有只被一个页面用的"共享"widget）
    - 布局骨架是否过于灵活导致实现复杂
    - 是否有"未来可能需要"的设计决策
    - 与 Quasar 原生能力是否重复造轮子

  ---

  ## brainstorm 产出要求

  brainstorm 文档结构：

  1. **旧系统页面全景**：每个页面的入口、核心交互、使用频率
  2. **新系统页面清单**：需要哪些页面，按业务域分组，标注优先级
  3. **导航体系决策**：选定的方案 + 原因 + 放弃方案的原因
  4. **布局骨架**：ASCII 布局图 + 各区域职责
  5. **共享 widget 清单**：每个 widget 的职责、适用页面、依赖
  6. **路由结构**：路由树 + 页面间跳转场景
  7. **自检结果**：覆盖度 + 规范合规 + 过度设计检查

  ## design 产出要求

  - 只写结论和变化
  - 包含：导航结构图、布局骨架图、widget 清单表、路由树、token 使用规范
  - checklist.yaml 格式的验收清单
  - 标注：哪些可以 Vitest 覆盖（widget 逻辑）、哪些需要 manual validation（布局/交互）

  ## 设计范围

  本次设计覆盖的页面：
  1. 主布局/导航/AppShell
  2. 帧定义管理（列表 + 编辑器）
  3. 连接管理（列表 + 配置）
  4. 接收/展示（数据表格 + 图表 — 已有设计，本对话只确认其嵌入方式）
  5. 发送（发送界面）
  6. 任务（列表 + 编辑器）
  7. 指令接入/SCOE（指令界面）
  8. 存储/历史（浏览 + 导出）
  9. 设置（应用设置）
  10. 状态/仪表盘

  ## 硬约束

  - 所有设计必须符合 rewrite-frontend-conventions.md
  - 使用 Quasar 组件优先，不造轮子（Quasar 有 QTable/QForm/QDialog/QLayout/QDrawer 就直接用）
  - Widget 只抽取确认被 2+ 页面复用的模式
  - 不设计响应式（这是桌面应用，固定窗口尺寸范围即可）
  - 不引入新的 CSS 框架或 UI 库
  - 不讨论单个页面的详细字段排列（那是后续逐页面设计的事）
  - 本次不定代码实现细节，只定设计决策
