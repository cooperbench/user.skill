The concern is that if a future code path bypasses the boolean-to-number conversion, `StorageRecordField.value` would accept `boolean` but `ReceiveParsedFieldPrimitive` would not produce it, creating a subtle contract mismatch.

Fix: This is acceptable as-is for now. If desired, add a comment noting that `ReceiveParsedFieldPrimitive` never produces `boolean` (expression pass converts them to `0 | 1`), so the `StorageRecordFieldValue` superset is safe.
