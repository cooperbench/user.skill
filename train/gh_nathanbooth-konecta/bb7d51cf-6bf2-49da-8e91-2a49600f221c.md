Perfect! I found the exact JSON format you need. Here's the correct schema for a `postToolUse` hook that triggers on Edit and Write tool usage:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "/path/to/your/script.sh"
          }
        ]
      }
    ]
  }
}
```

**Key details:**

1. **Top-level key**: `"hooks"` (in your `settings.json`)
2. **Event type**: `"PostToolUse"` (note: capital P and T, camelCase)
3. **Matcher**: `"Edit|Write"` - this is a regex pattern that matches either the Edit or Write tool
4. **Nested structure**: The matcher is in an array of matcher groups, and each matcher group has its own `hooks` array
5. **Hook handler fields**:
   - `type`: `"command"` (the type of handler)
   - `command`: the shell command or script path to execute

**Full example in settings.json context:**

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/lint-check.sh",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

**Additional optional fields** you can add to the hook handler:
- `timeout`: seconds before canceling (default: 600 for command hooks)
- `statusMessage`: custom spinner message while the hook runs
- `async`: if `true`, runs in background without blocking

The hook input will be JSON on stdin containing:
- `tool_name`: either "Edit" or "Write"
- `tool_input`: the parameters (file_path, content, old_string, new_string, etc.)
- `tool_response`: the result of the tool execution
- Plus common fields like `session_id`, `cwd`, `permission_mode`

This configuration goes in either `~/.claude/settings.json` (all projects) or `.claude/settings.json` (single project).
