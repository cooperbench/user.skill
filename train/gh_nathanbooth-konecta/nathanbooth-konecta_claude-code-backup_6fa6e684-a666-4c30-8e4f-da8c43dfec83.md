The problem is the `BeforeHookCreation` delete policy on line 20 and 87.

Here's what happens on every ArgoCD sync:

1. ArgoCD runs PreSync hooks
2. `BeforeHookCreation` means: **delete the existing hook resource before creating a new one**
3. So every sync deletes the cloud-sql-proxy Deployment + Service, then recreates them
4. This causes a pod restart and brief database connectivity loss

`BeforeHookCreation` is designed for one-shot Jobs (where you need to clean up the old completed Job before running a new one). For a long-running Deployment like cloud-sql-proxy, it's the wrong policy.
