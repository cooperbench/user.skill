Here's how it works: **`entire trail enable` does NOT create a trail itself.** It only flips the setting — it removes the `strategy_options.trails` key from settings (restoring the default "enabled" state). That's all it does. **Auto-creation happens later**, on the next `TurnStart` event (i.e., when an agent session starts a new turn). The flow is: 1. Agent hook fires `TurnStart` → `handleLifecycleTurnStart()` (`lifecycle.go:112`) 2. At the end, it calls `autoCreateTrailOnTurnStart()` (`lifecycle.go:148`) 3. That function checks: trails disabled? On default branch? Already has a trail? 4. If none of those apply, it calls `AutoCreateTrail()` which creates one with `in_progress` status **So for existing branches:** yes, it works — but only when the next agent turn starts on that branch. If you run `entire trail enable` on a branch that already exists but has no trail, the trail will be auto-created the next time you send a prompt to your agent on that branch. It won't be created immediately by the `enable` command itself. There's no "backfill" — branches that existed while trails were disabled won't get trails until someone starts an agent session on them.
