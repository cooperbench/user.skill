Here's the key difference:

## Storage Architecture

| Agent | Session Storage | Resume/Rewind |
|-------|-----------------|---------------|
| **Claude Code** | JSONL files on disk | Write file → Claude reads it |
| **Gemini CLI** | JSON files on disk | Write file → Gemini reads it |
| **OpenCode** | **SQLite database** | Write file + **import into SQLite** |

## Claude Code / Gemini CLI (simple)

```go
// WriteSession just writes a file - that's all these agents need
func (c *ClaudeCodeAgent) WriteSession(session *agent.AgentSession) error {
    // ... validation ...

```

The agent reads the transcript file directly when resuming.

## OpenCode (complex)

```go
func (a *OpenCodeAgent) WriteSession(session *agent.AgentSession) error {
    // 1. Write JSONL file (for Entire's internal checkpoint use)
    os.WriteFile(session.SessionRef, session.NativeData, 0o600)

    // 2. If we have export data, import the session into OpenCode's SQLite DB
    //    This enables `opencode -s <id>` for both resume and rewind.
    if len(session.ExportData) > 0 {
        a.importSessionIntoOpenCode(session.SessionID, session.ExportData)
    }
}
```

OpenCode stores sessions in a SQLite database, not files. So for resume/rewind to work:
1. Entire must capture the **export data** (SQLite dump) when checkpointing
2. Entire must **import** that data back into SQLite when restoring

That's why the `ExportData` field was added and why the rewind code has special handling - it needs to pass that extra data through to `WriteSession` so OpenCode can reimport it into its database.

```typescript
// On session.created - just sets the ID, doesn't load history
case "session.created": {
```

**`writeExportJSON()` uses `messageStore`** which only contains events accumulated since the plugin started listening. If you resume an existing session with 10 messages and add 1 more, the export would only have that 1 new message.

```typescript
const response = await client.session.message.list({ path: { id: sessionID } })
```

**Using `opencode export` fixes this entirely** - it reads from SQLite which always has the complete session history, regardless of when the plugin started listening.
