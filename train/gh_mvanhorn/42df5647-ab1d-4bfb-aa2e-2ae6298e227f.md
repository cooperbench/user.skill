3. **No `TokenCalculator` implementation** - Other JSONL agents implement this for token usage tracking.

how does the claude integration store temporary state between hook invocations?

> AGENT

The state between hook invocations is stored entirely on disk across **three locations**:

### 1. Session state — `.git/entire-sessions/<session-id>.json`
Long-lived, persists for the session's entire lifetime. Tracks:
- `Phase` (idle/active/ended) — the state machine
- `BaseCommit`, `WorktreePath`, `WorktreeID`
- `CheckpointTranscriptStart` — transcript offset for incremental extraction
- `TurnID`, `TurnCheckpointIDs` — for coordinating mid-turn commits with the final stop
- `StepCount`, `FilesTouched`, `TokenUsage`, `PromptAttributions`
- `TranscriptPath`, `AgentType`, `FirstPrompt`, timestamps

### 2. Pre-prompt state — `.entire/tmp/pre-prompt-<session-id>.json`
Short-lived. Created at `user-prompt-submit`, deleted at `stop`. Tracks:
- `TranscriptOffset` — line count at prompt time (so `stop` knows where the turn started)
- `UntrackedFiles` — git untracked files at prompt time (so `stop` can detect new files)
- `LastTranscriptIdentifier` — UUID of last transcript entry

### 3. Pre-task state — `.entire/tmp/pre-task-<tool-use-id>.json`
Short-lived. Created at `pre-task`, deleted at `post-task`. Same pattern scoped to a subagent invocation.

### The flow

```
user-prompt-submit:
  1. Snapshot transcript position + untracked files → .entire/tmp/pre-prompt-*.json
  2. Load/create session state → .git/entire-sessions/*.json
  3. Fire TurnStart (IDLE→ACTIVE), generate TurnID, save

stop:
  1. Read pre-prompt state to get TranscriptOffset
  2. Extract prompts/files from transcript since offset
  3. Save checkpoint (shadow branch commit via WriteTemporary)
  4. Fire TurnEnd (ACTIVE→IDLE), save session state
  5. Delete pre-prompt state

post-commit (git hook, not agent hook):
  1. Read session state, fire GitCommit event
  2. Condense shadow branch → entire/checkpoints/v1
  3. Append checkpoint ID to TurnCheckpointIDs
  4. Save session state

session-end:
  1. Fire SessionStop (→ENDED), save session state
```

Every hook is a fresh subprocess — there's no in-memory state. The `TranscriptOffset` in pre-prompt state is the critical coordination point: it lets `stop` extract only the incremental changes since the last prompt.
