`★ Insight ─────────────────────────────────────`
- **Test parallelism strategy**: `TestDetectPresence` cannot use `t.Parallel()` because `t.Chdir()` modifies process-global state (Go's test framework panics if you call `t.Chdir` after `t.Parallel`). All other tests are parallel since they operate on independent temp dirs or pure functions.

- **Stub method testing**: Even though `GetSessionDir`, `ReadSession`, and `WriteSession` are stubs returning `"not implemented"` errors, testing them documents the current contract and will catch regressions if someone accidentally removes the error return or changes the behavior.

### Overview

The goal is to add comprehensive integration tests for the Factory AI Droid agent, mirroring the patterns established for Claude Code and Gemini CLI. This involves modifying 3 existing files and creating 1 new file in `/Users/alisha/Projects/devenv/cli/cmd/entire/cli/integration_test/`.

### Key Design Observations

**Droid transcript format is different from both Claude Code and Gemini.** Factory AI Droid uses a wrapped JSONL format where each line has `{"type":"message","id":"...","message":{"role":"assistant|user","content":[...]}}`. The existing `TranscriptBuilder` in `transcript.go` produces Claude Code format (`{"type":"user","uuid":"...","message":{"content":"..."}}`). For Droid integration tests, a new `DroidTranscriptBuilder` is needed that generates the Droid envelope format.

**ReadSession/WriteSession/GetSessionDir are stubs.** These return "not implemented" errors. This means agent+strategy composition tests cannot go through `ag.ReadSession()`. Instead, they must rely entirely on the hook-based flow (UserPromptSubmit, Stop) where the lifecycle dispatcher reads the transcript directly via the `TranscriptAnalyzer` interface.

**Hook routing uses `entire hooks factoryai-droid <verb>`.** The hook runner needs to route commands to `"hooks", "factoryai-droid", hookName` (not `"hooks", "claude-code"` or `"hooks", "gemini"`).

**No project dir env var needed.** Unlike Claude Code (`ENTIRE_TEST_CLAUDE_PROJECT_DIR`) and Gemini (`ENTIRE_TEST_GEMINI_PROJECT_DIR`), Factory AI Droid does not use a project dir for session resolution. The `GetSessionDir` method is a stub, so there is no env var to pass.

### Droid Transcript Builder Details

The `CreateDroidTranscript` method on `FactoryDroidSession` must produce the Droid envelope format. Each JSONL line follows this pattern:

**User message:**
```json
{"type":"message","id":"m1","message":{"role":"user","content":[{"type":"text","text":"Fix the bug"}]}}
```

**Assistant text message:**
```json
{"type":"message","id":"m2","message":{"role":"assistant","content":[{"type":"text","text":"I'll fix it"}]}}
```

**Assistant tool use:**
```json
{"type":"message","id":"m3","message":{"role":"assistant","content":[{"type":"tool_use","id":"toolu_1","name":"Write","input":{"file_path":"main.go","content":"..."}}]}}
```

**Tool result (user):**
```json
{"type":"message","id":"m4","message":{"role":"user","content":[{"type":"tool_result","tool_use_id":"toolu_1","content":"Success"}]}}
```

This is critical because the `ParseDroidTranscript` function specifically looks for `type:"message"` at the outer level and extracts `role` from the inner message. If we use Claude Code format, the transcript analyzer will not parse any lines.
