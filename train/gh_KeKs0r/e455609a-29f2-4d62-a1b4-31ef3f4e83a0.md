The CLI uses a **browser-based login flow** with a local callback server, similar to `gh auth login` or `gcloud auth login`. Here's the summary: ## Login Flow 1. **`rudel login`** starts a temporary HTTP server on `127.0.0.1:<random-port>` and generates a CSRF `state` token 2. Opens the browser to the web app (`https://rudel.numia.workers.dev`) with `cli_callback` and `state` query params 3. User authenticates in the browser (email/password, Google, or GitHub OAuth) 4. Once authenticated, the web app fetches `GET /api/cli-token` (cookie-authenticated) which returns the `better-auth` session token 5. The browser redirects to `http://127.0.0.1:<port>/callback?token=<token>&state=<state>` 6. The CLI validates the `state`, then validates the token by calling `POST /rpc/me` with `Authorization: Bearer <token>` 7. On success, credentials are saved to **`~/.rudel/credentials.json`** (file mode `0o600`, directory `0o700`) ## Token Storage ```typescript // ~/.rudel/credentials.json { token: string, apiBaseUrl: string } ``` ## Authenticated Requests All API calls include `Authorization: Bearer <token>` in the headers. The API server uses `better-auth`'s `bearer()` plugin to resolve the session from this header — the same session token that backs browser cookies works as a Bearer token. Two patterns are used: - **Direct `fetch`** for `whoami` (`POST /rpc/me`) - **oRPC client** with `RPCLink` for uploads (`client.ingestSession()`) ## Logout Purely local — just deletes `~/.rudel/credentials.json`. No server-side session invalidation. ## Key Details - **Session expiry**: 365 days (`apps/api/src/auth.ts:33`) - **Login timeout**: 120 seconds for the browser callback - **Config dir override**: `RUDEL_CONFIG_DIR` env var (used in tests) - Callback hostname is validated to be `127.0.0.1` in the web app as a security check
