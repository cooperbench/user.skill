### 4. STATE MANAGEMENT - POTENTIAL DUPLICATE DISPLAY

**File:** `/home/achildrenmile/bosarsalog/client/src/pages/ExercisePage.tsx` (lines 50-75)

The WebSocket handlers in ExercisePage push new reports to the array without checking for duplicates:

```typescript

  refreshStats();
});
```

**Problem:** The `report_created` handler just prepends. If a local component already called `onReportCreated` and the server broadcasts the same report back, it could end up in the state twice with the same ID. However, looking at the code flow:

1. Client calls POST `/exercises/:id/reports` 
2. Server returns report with ID
3. Client calls `onReportCreated(report)` which calls `setReports(prev => [report, ...prev])`
4. Client emits Socket event: `socket.emit('report_created', { ...report, exercise_id: id })`
5. Server broadcasts to other clients via `socket.to(...).emit(...)`
6. The **same client does NOT receive the broadcast** because it uses `socket.to()` which excludes the sender

So this is actually safe — no local duplicate from the same user. But if multiple tabs/windows are open for the same user, they could both see the creation event.
