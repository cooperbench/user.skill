`★ Insight ─────────────────────────────────────`
**WaitFor settle mechanics**: The tmux WaitFor implementation works by matching a regex, then waiting for content to be "stable" (unchanged) for 2 seconds. This is elegant for most agents where the prompt pattern only appears when truly idle. But Cursor's TUI is different — `/ commands` is always visible as a hint in the status bar. The fix uses a pattern that's *exclusively* a completion signal (`Add a follow-up`), not a persistent UI element. This is a common pitfall when testing TUI apps: status bar text that doubles as a "ready" indicator during startup can falsely signal "done" during processing.

**Per-session config isolation pattern**: This mirrors how Claude Code E2E tests use `CLAUDE_CONFIG_DIR` — each parallel test gets its own config namespace. The key insight is that even pre-seeding a shared config file isn't enough when the application does atomic write-then-rename, because the temp file itself becomes the contention point.
