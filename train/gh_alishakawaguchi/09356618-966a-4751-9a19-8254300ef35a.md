Here's what you can explore: `★ Insight ─────────────────────────────────────` **How the attribution system works at a high level:** 1. **Three-tree model** — Attribution compares `baseTree` (session start), `shadowTree` (last checkpoint on the shadow branch), and `headTree` (worktree at commit time). The shadow branch is an internal branch (`entire/<hash>-<worktreeHash>`) that captures snapshots without touching your working branch. 2. **Two-phase data collection** — User edits are captured *before* each agent run via `CalculatePromptAttribution()` (with per-file line counts in `UserAddedPerFile`). Final attribution runs at commit time via `CalculateAttributionWithAccumulated()`, which combines all accumulated prompt data with post-checkpoint diffs. 3. **LIFO heuristic** — The key innovation. When a user removes lines, the naive approach assumes all removals target agent code (unfairly penalizing the agent). The per-file pool heuristic instead assumes users modify their own recent additions first: `selfMod = min(removals, userPriorAdds)` per file. This preserves agent credit when users refactor their own code. `─────────────────────────────────────────────────` ### Playground features: - **5 scenarios** in the sidebar (keys 1-5): Agent Only, Mixed, Heavy Editing, Self-Modification, Multi-File - **Step through the timeline** with arrow keys or clicking steps to see code evolve - **Code View** — color-coded lines (blue=human, green=agent) with the full calculation breakdown - **Git Trees** tab — visualizes the three-tree model and diffs between them - **LIFO Demo** tab — click lines to "remove" them and compare with/without per-file tracking Try the **Self-Modification** preset (key 4) — it best demonstrates why LIFO matters (66.7% vs incorrect 46.7%).
