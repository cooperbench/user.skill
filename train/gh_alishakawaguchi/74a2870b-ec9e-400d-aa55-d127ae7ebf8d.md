This introduced several vestigial methods (not on any interface, no production callers), a redundant pass-through function, and duplicated branch logic. These simplifications reduce noise, improve consistency with other agents, and remove dead code.

**Scope: factoryaidroid package only** (+ one subtest removal in integration_test).

### 5. Simplify `addHookToMatcher()`

The `matcherName == ""` branch is identical to the general case because `matcher.Matcher == ""` equals `matcher.Matcher == matcherName` when matcherName is `""`.

Simplify from 32 lines to ~8 lines:

```go
func addHookToMatcher(matchers []FactoryHookMatcher, matcherName, command string) []FactoryHookMatcher {
    entry := FactoryHookEntry{Type: "command", Command: command}
    for i := range matchers {
        if matchers[i].Matcher == matcherName {
            matchers[i].Hooks = append(matchers[i].Hooks, entry)
            return matchers
        }
    }
    return append(matchers, FactoryHookMatcher{Matcher: matcherName, Hooks: []FactoryHookEntry{entry}})
}
```

`★ Insight ─────────────────────────────────────`
**Why the `addHookToMatcher` simplification works:** The original had two branches — one for `matcherName == ""` and one for non-empty. But both branches did the same thing: find a matcher where `matchers[i].Matcher == matcherName`, append to it, or create a new one. When `matcherName` is `""`, checking `matchers[i].Matcher == matcherName` is equivalent to `matchers[i].Matcher == ""`. The two branches were identical in behavior, just written out separately — a common artifact of copy-evolve development.

**Removing `removeEntireHooksFromMatchers`:** This pass-through existed "in case" the PreToolUse/PostToolUse matcher structure diverged from simple hooks. But Factory's hook format uses the same `[]FactoryHookMatcher` for all hook types, so the separate function just added a layer of indirection that confused readers.
