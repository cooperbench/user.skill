Skills are stored in SKILL.md files with YAML frontmatter that includes a `name` field and a `description` field.

**name**: The skill identifier, using lowercase letters, numbers, and hyphens only. The readable skill name is optional—if omitted, the folder name is used.

**description**: A short and objective description of what the skill does and when to use it (appears in menus), which is used by the agent to decide when to apply the skill.

## Plugin Manifest Structure

The only required file for a Cursor plugin is .cursor-plugin/plugin.json, which includes fields like name, version, description, author, and paths to commands, skills, and rules directories.

## Skills in Plugins

Skills are SKILL.md files in named subdirectories — the agent invokes them based on task context. If you don't specify paths in plugin.json, Cursor auto-discovers components from the default directory names, and explicit paths override auto-discovery.

## Local Installation Path

For local installation, you need the full ~/.cursor/plugins/<n>/ path. More specifically, don't install under ~/.cursor/skills/ only, as skills get loaded but commands don't register; you need the full ~/.cursor/plugins/<n>/ path plus the .claude/ registration.

# Cursor Plugin Structure & Installation

## Required Structure

A Cursor plugin needs this layout:

```
my-plugin/
├── .cursor-plugin/
│   └── plugin.json        # Required manifest here
├── rules/
├── skills/
├── agents/
├── commands/
└── README.md
```

The manifest file **must live inside `.cursor-plugin/`**, not at the repo root.

## plugin.json Fields

**Required:**
- `name`: kebab-case identifier (e.g., `my-plugin`)

**Optional (relevant to your question):**
- `skills`: "Path(s) to skill directories"
- `rules`, `agents`, `commands`: Similar path specifications
- `hooks`, `mcpServers`: Configuration paths or inline objects

The `skills` field accepts "string or array" values pointing to directories containing skill files.

- Marketplace submission via [cursor.com/marketplace/publish](https://cursor.com/marketplace/publish)
- Repository hosting requirements

## Path Handling

The submission checklist states: "All paths in manifest are relative and valid (no `..`, no absolute paths)." This indicates relative paths work, though the documentation doesn't explicitly demonstrate `./plugins/foo/skills/` syntax.

For component discovery without explicit manifest paths, the system uses **automatic folder-based detection** in default locations like `skills/`, `rules/`, etc.

# Local Cursor Plugin Installation

## Installation Steps

To install a Cursor plugin locally, follow these steps:

1. **Copy plugin files** to `~/.cursor/plugins/<plugin-name>/`

2. **Register in `~/.claude/plugins/installed_plugins.json`** with an entry like:
   ```json
   {
     "plugins": {
       "plugin-name@local": [
         {
           "scope": "user",
           "installPath": "/Users/you/.cursor/plugins/plugin-name"
         }
       ]
     }
   }
   ```

3. **Enable in `~/.claude/settings.json`**:
   ```json
   {
     "enabledPlugins": {
       "plugin-name@local": true
     }
   }
   ```

4. **Verify third-party plugin setting** is enabled in Settings > Features

## Key Points

- Use **absolute paths** for `installPath`—relative paths are unreliable
- The plugin directory structure requires `.cursor-plugin/` (not `.claude-plugin/`)
- "The `@local` suffix appears to signal a locally-installed plugin"
- Restart Cursor fully after installation; "Reload Window sometimes works, full restart is safer"

## Common Issues

The article notes these typical problems:
- Using `.claude-plugin/` instead of `.cursor-plugin/`
- Installing under `~/.cursor/skills/` only (commands won't register)
- Plugin registered but not enabled in both JSON files
- Incomplete restart of the IDE

**Note:** The article covers macOS specifically; Windows/Linux paths differ.

## Verified facts from Cursor's spec

Cursor's plugin manifest schema is at `github.com/cursor/plugins/schemas/plugin.schema.json`:
- `name` is **required** and must match `^[a-z0-9]([a-z0-9.-]*[a-z0-9])?$` (kebab-case).
- `additionalProperties: false` — unknown keys fail validation.
- `skills` accepts a string or string array of paths/globs.
- The manifest must live at `<plugin-root>/.cursor-plugin/plugin.json`.

A SKILL.md file needs YAML frontmatter with both `name:` (kebab-case) and `description:`. Cursor preloads `name`+`description` into the agent's system prompt.

For a multi-plugin repo (like `cursor/plugins`), the layout is `.cursor-plugin/marketplace.json` at the repo root plus a nested `<plugin>/.cursor-plugin/plugin.json` per plugin. `marketplace.json` has a different required shape (`name`, `plugins[]` with `name`+`source`).

Official docs don't document `~/.cursor/plugins/local/` as an auto-load path. Community guides (Medium, dredyson.com) say the working convention is `~/.cursor/plugins/<name>/` (often via symlink) with a full Cursor restart — no `local/` subdirectory.
