**BREAK 2: `_call_tool_with_resilience` is `async` but decorated with synchronous `@tu_breaker` — Potential Runtime Compatibility Issue (FIX-B15)**

`_call_tool_with_resilience` is defined as `async def` at line 336 of `/services/protocol-processor-service/src/protocol_processor/tools/tooluniverse_client.py`. The `@tu_breaker` decorator from `pybreaker` wraps it.

`pybreaker`'s `CircuitBreaker.__call__` is designed for synchronous callables. When applied to an `async def`, `pybreaker` 1.x wraps the coroutine function and the decorator stacking works differently depending on the pybreaker version. The verified behavior in Phase 40-02 was tested with `uv run python -c` direct calls only, not through the actual pipeline's async invocation chain.

The retry decorator `@retry` from tenacity is outer-wrapped by `@tu_breaker`. If `pybreaker` does not properly propagate the coroutine through its wrapper, `_call_tool_with_resilience` may execute synchronously inside the breaker, breaking the async pipeline.

**Severity:** If the pybreaker version installed supports async (pybreaker 1.2+), this is fine. If not, ground_node will hang or fail on ToolUniverse calls. Needs runtime verification against the actual installed pybreaker version.

**Affected requirements:** FIX-B15 (resilience wiring), FIX-B3, FIX-B4, FIX-B5 (grounding flow depends on this working)
