## Root Causes

### 1. Full-page redirect instead of popup (Frontend)

### 2. Wrong `postMessage` targetOrigin (API)
The callback HTML did `window.opener.postMessage(data, window.location.origin)`. In the popup, `window.location.origin` is the API's origin (e.g., `https://api-xxx.run.app`), but the opener is the frontend (e.g., `https://frontend-xxx.run.app`). **Fix:** The `/auth/login` endpoint now captures the frontend origin from the `Referer` header and stores it in the session. The callback uses that stored origin as the `postMessage` targetOrigin, so the message reaches the frontend window.

The `user.id` was passed as-is (could be an integer from the DB). The frontend `User` interface expects `id: string`.

**Fix:** Added `str(user.id)` in the popup payload.
