Found the root cause. The `OutboxProcessor.start()` polling loop (line 159) runs every `poll_interval` (1 second). It uses `run_in_executor` with a `ThreadPoolExecutor`. During test `TestClient(app)` context manager exit, the lifespan shutdown calls `processor.stop()` which sets the event and calls `self._executor.shutdown(wait=False)`. Then `await asyncio.gather(*_running_tasks)` waits for the `start()` coroutine to finish.

The issue: the `poll_and_process` call runs in the thread executor against `engine` from `api_service.storage` — **not** the test's in-memory DB. The conftest overrides `get_db` but not `engine` used by OutboxProcessor. So it's likely hitting the real `DATABASE_URL` or failing on each poll cycle, plus the 1-second sleep loop adds latency on every test fixture setup/teardown.

**The fix:** The `test_client` and `unauthenticated_client` fixtures create `TestClient(app)` which triggers the full lifespan including the outbox processor. For tests that don't need the outbox, this is pure overhead. The simplest fix is to set `raise_server_exceptions=False` — no, better: disable the outbox processor during tests by patching the lifespan or adding an env var guard.

The cleanest approach: skip the outbox background task when a `TESTING` env var is set.
