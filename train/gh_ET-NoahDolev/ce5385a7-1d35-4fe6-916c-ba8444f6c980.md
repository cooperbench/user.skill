Per MLflow 3.9.0 docs: "If any of children spans are not ended, they will be ended forcefully with the status `TRACE_STATUS_UNSPECIFIED`."
   102→
   103→**Critical insight from live inspection:** `mlflow.start_span()` is a context manager that auto-sets `ERROR` status when the `with` block raises an exception. However, if `asyncio.run()` is interrupted (process killed, container restart mid-run), the ContextVar carrying the active span reference is destroyed without calling `__exit__`. The `finally` block + explicit `end_trace()` is the defense.
   104→
   105→**When to use:** Any pipeline span that crosses an `asyncio.run()` boundary.
   106→
   107→```python
   108→# Source: Verified against mlflow 3.9.0 installed package
   109→# File: services/protocol-processor-service/src/protocol_processor/trigger.py
   110→
   111→async def _run_pipeline(graph, initial_state, config, payload):
   112→    if not _ensure_mlflow():
   113→        return await graph.ainvoke(initial_state, config)
   114→
   115→    import mlflow
   116→
   117→    mlflow.langchain.autolog()
   118→    trace_id: str | None = None
   119→
   120→    with mlflow.start_span(name="protocol_pipeline", span_type="CHAIN") as span:
   121→        try:
   122→            trace_id = mlflow.get_active_trace_id()  # capture immediately
   123→            span.set_inputs({
   124→                "protocol_id": payload.get("protocol_id", ""),
   125→                "title": payload.get("title", ""),
   126→                "file_uri": payload.get("file_uri", ""),
   127→            })
   128→            result = await graph.ainvoke(initial_state, config)
   129→            span.set_outputs({
   130→                "status": result.get("status"),
   131→                "error": result.get("error"),
   132→                "error_count": len(result.get("errors", [])),
   133→            })
   134→            return result
   135→        finally:
   136→            # Guarantee span closure even if process is interrupted mid-run.
   137→            # If the with-block __exit__ runs normally, end_trace is a no-op
   138→            # (MLflow docs: "If the trace is already ended, this method will
   139→            # have no effect").
   140→            if trace_id:
   141→                try:
   142→                    mlflow.MlflowClient().end_trace(trace_id, status="ERROR")
   143→                except Exception:
   144→                    logger.warning(
   145→                        "Failed to force-close MLflow trace %s", trace_id
   146→                    )
   147→```
   148→
   149→**Note on `finally` placement:** The `finally` is INSIDE the `with` block (not outside), so it runs before `__exit__`. When the span closes normally via `__exit__`, `end_trace()` is called first — but since the trace is already being closed, MLflow treats this as a no-op. This is the pattern recommended for guaranteed cleanup.

   151→### Pattern 2: ToolUniverse Error-Dict to Exception Conversion
   152→
   153→**Critical finding:** ToolUniverse SDK catches all HTTP exceptions internally (`requests.exceptions.RequestException`) and returns `{"error": "..."}` dicts. The UMLS REST tool source (`umls_tool.py:97`) confirms this. This means `tenacity` and `pybreaker` cannot intercept 502/503 failures via exception handling — they must inspect the response dict.
   154→
   155→**The solution:** In `_call_tool()`, detect error dict responses and raise a custom exception that tenacity and pybreaker can act on.
   156→
   157→```python
   158→# Source: Verified by reading tooluniverse/umls_tool.py source
   159→# File: services/protocol-processor-service/src/protocol_processor/tools/tooluniverse_client.py
   160→
   161→class ToolUniverseError(Exception):
   162→    """Raised when ToolUniverse returns an error dict response.
   163→
   164→    Enables tenacity retry and pybreaker circuit breaker to intercept
   165→    failures that ToolUniverse SDK catches and returns as dicts.
   166→    """
   167→    pass
   168→
   169→
   170→class ToolUniverseUnavailableError(ToolUniverseError):
   171→    """Transient error (502/503) — eligible for retry."""
   172→    pass
   173→```

   175→### Pattern 3: Circuit Breaker + Retry for async ToolUniverse Calls
   176→
   177→**What:** Wrap `_call_tool` with (1) tenacity retry for transient errors and (2) pybreaker circuit breaker for sustained failures.
   178→
   179→**pybreaker async support:** The `@cb` decorator works on `async` coroutines (verified by live test — `asyncio.run(decorated())` returns `'ok'`). The `call_async()` method uses Tornado coroutines and is NOT compatible with asyncio. Use the decorator form.
   180→
   181→**tenacity async support:** `@retry` decorator works natively on `async def` functions (uses `AsyncRetrying` internally, verified by live test).
   182→
   183→**Decorator order matters:** Apply `@tu_breaker` (outer) then `@retry` (inner). This means: retry first (3 attempts), then if all fail, count as 1 circuit breaker failure. After 10 such failures, the breaker opens.
   184→
   185→```python
   186→# Source: Verified tenacity docs + pybreaker live test
   187→# File: services/protocol-processor-service/src/protocol_processor/tools/tooluniverse_client.py
   188→
   189→import asyncio
   190→from shared.resilience import tu_breaker  # new singleton to add to resilience.py
   191→
   192→# After _call_tool raises ToolUniverseUnavailableError, retry up to 3 times
   193→# with exponential backoff before letting pybreaker count a failure.
   194→@tu_breaker
   195→@retry(
   196→    retry=retry_if_exception_type(ToolUniverseUnavailableError),
   197→    stop=stop_after_attempt(3),
   198→    wait=wait_exponential(multiplier=1, min=2, max=10),
   199→    before_sleep=before_sleep_log(logger, logging.WARNING),
   200→    reraise=True,  # re-raise so pybreaker sees the final failure
   201→)
   202→async def _call_tool_with_resilience(
   203→    tu: ToolUniverse,
   204→    system: str,
   205→    tool_name: str,
   206→    query: str,
   207→    max_results: int,
   208→) -> dict[str, Any]:
   209→    raw = await _call_tool_raw(tu, system, tool_name, query, max_results)
   210→
   211→    # Detect error dict: ToolUniverse returns {"error": "..."} for all HTTP failures
   212→    if isinstance(raw, dict) and "error" in raw:
   213→        error_msg = str(raw["error"])
   214→        # 502/503 patterns from UMLS REST tool: "Request failed: ..."
   215→        if "502" in error_msg or "503" in error_msg or "Service Unavailable" in error_msg:
   216→            raise ToolUniverseUnavailableError(f"Transient error: {error_msg}")
   217→        # Other errors (auth, 404, etc.) — not transient, don't retry
   218→        raise ToolUniverseError(f"Non-transient error: {error_msg}")
   219→
   220→    return raw
   221→```

   248→### Pattern 5: SHA-256 Content Deduplication
   249→
   250→**What:** Before saving an uploaded file, compute SHA-256 hash of bytes. Use hash as the blob path key. If a file with that hash already exists, return the existing URI.
   251→
   252→**Why SHA-256:** Standard library (`hashlib`), deterministic, 256-bit collision resistance is appropriate for this use case.
   253→
   254→```python
   255→# Source: Python stdlib hashlib docs
   256→# File: services/api-service/src/api_service/gcs.py
   257→
   258→import hashlib
   259→
   260→def _content_hash(data: bytes) -> str:
   261→    """Compute SHA-256 hex digest of file content."""
   262→    return hashlib.sha256(data).hexdigest()
   263→
   264→def local_save_file_deduplicated(data: bytes, original_filename: str) -> str:
   265→    """Save with content-hash-based deduplication. Returns blob_path."""
   266→    content_hash = _content_hash(data)
   267→    # Use hash as directory to avoid collisions with filename variants
   268→    blob_path = f"{content_hash}/{original_filename}"
   269→    file_path = _LOCAL_UPLOAD_DIR / blob_path
   270→
   271→    if file_path.exists():
   272→        logger.info("Dedup: file already exists at %s (SHA-256: %s)", file_path, content_hash[:8])
   273→        return blob_path
   274→
   275→    file_path.parent.mkdir(parents=True, exist_ok=True)
   276→    file_path.write_bytes(data)
   277→    return blob_path
   278→```

   308→### Pattern 7: Sentence-Length Query Extraction (Claude's Discretion)
   309→
   310→**Decision context:** The user wants "Patient must have confirmed diabetes mellitus type 2" → extract "diabetes mellitus type 2" before sending to ToolUniverse. No heavy NLP library required — a simple heuristic regex approach is appropriate.
   311→
   312→**Recommendation:** Use a lightweight regex-based heuristic in `_call_tool` before dispatching:
   313→
   314→```python
   315→import re
   316→
   317→# Threshold: queries over 40 chars AND containing 4+ words are "sentence-like"
   318→_SENTENCE_WORD_THRESHOLD = 4
   319→_SENTENCE_CHAR_THRESHOLD = 40
   320→
   321→# Clause-starting words to strip from beginning
   322→_PREAMBLE_PATTERN = re.compile(
   323→    r'^(?:patient(?:s)?\s+(?:must|should|may|with|who|have|has|had|are|is)\s+'
   324→    r'|(?:has|have|had|is|are|must|should|may)\s+(?:a|an|the|confirmed|known|documented|active|history\s+of)\s+'
   325→    r'|(?:history\s+of|presence\s+of|absence\s+of|diagnosis\s+of)\s+)',
   326→    re.IGNORECASE,
   327→)
   328→
   329→def _extract_term_from_sentence(query: str) -> str:
   330→    """Extract searchable medical term from a sentence-length query.
   331→
   332→    If the query looks like a natural language criterion sentence,
   333→    strip preamble phrases and return the core medical term.
   334→    Returns the original query if it doesn't look sentence-like.
   335→    """
   336→    stripped = query.strip()
   337→    word_count = len(stripped.split())
   338→
   339→    if word_count < _SENTENCE_WORD_THRESHOLD or len(stripped) < _SENTENCE_CHAR_THRESHOLD:
   340→        return stripped  # Short query — pass through as-is
   341→
   342→    # Try stripping known preamble patterns
   343→    cleaned = _PREAMBLE_PATTERN.sub("", stripped).strip()
   344→
   345→    # If stripping removed something useful, use the cleaned version
   346→    if cleaned and cleaned != stripped and len(cleaned) >= 3:
   347→        logger.debug("Extracted term '%s' from sentence '%s'", cleaned, stripped[:60])
   348→        return cleaned
   349→
   350→    # Fallback: take last N words (the term usually appears at the end)
   351→    # e.g. "Patient must have confirmed diabetes mellitus type 2" → "diabetes mellitus type 2"
   352→    words = stripped.split()
   353→    # Take the last 4 words as the likely medical term
   354→    return " ".join(words[-min(4, len(words)):])
   355→```
   356→
   357→**Confidence:** MEDIUM — this is a heuristic and will miss edge cases. The user acknowledged this is Claude's discretion. Given the existing MedGemma entity decomposer (`entity_decomposer.py`) that handles medical term extraction from full criteria, this simpler approach is appropriate for query pre-processing.

   359→### Anti-Patterns to Avoid
   360→
   361→- **Putting retry OUTSIDE circuit breaker:** `@retry(outer) @tu_breaker(inner)` means each retry attempt opens/closes the breaker independently. Instead, retry inside the breaker — the breaker sees the final outcome of the retry sequence.
   362→- **Using `pybreaker.call_async()`:** This is Tornado-specific (uses `gen.coroutine`), not asyncio. Use `@tu_breaker` decorator on an `async def` function instead (verified working).
   363→- **Adding `try/finally` OUTSIDE the `with mlflow.start_span():` block:** The span object is only accessible inside the `with` block. The `finally` must be INSIDE the `with` block.
   364→- **Using `raise_for_status()` to detect ToolUniverse errors:** ToolUniverse SDK catches HTTPError internally and returns error dicts. The `raise_for_status()` call in `umls_tool.py:83` is caught at `umls_tool.py:97`. The caller (`_call_tool`) receives `{"error": "Request failed: ..."}` — not an exception.
   365→- **SHA-256 filename collision:** Don't use `hash + original_filename` as the sole path — two different files with the same name but different content would collide. Use `{content_hash}/{original_filename}` so the hash is the directory.

   367→## Don't Hand-Roll
   368→
   369→| Problem | Don't Build | Use Instead | Why |
   370→|---------|-------------|-------------|-----|
   371→| Circuit breaker state machine | Custom open/closed/half-open logic | `pybreaker.CircuitBreaker` (already in shared/resilience.py) | Thread-safe state machine, Redis backing option, listener hooks |
   372→| Retry with exponential backoff | `time.sleep()` loop with manual backoff | `tenacity @retry` with `wait_exponential` | Jitter support, `before_sleep` logging, `stop_after_attempt` |
   373→| MLflow span cleanup | Custom span tracking registry | `mlflow.get_active_trace_id()` + `MlflowClient().end_trace()` | Official MLflow API; no-op if already closed |
   374→| Content deduplication | Hash registry in DB | `hashlib.sha256` + filesystem path convention | Filesystem IS the deduplication index via path `{hash}/{filename}` |
   375→
   376→**Key insight:** All required resilience primitives (tenacity, pybreaker) are already installed. The work is wiring them into the ToolUniverse call path correctly, accounting for the SDK's unusual error-dict pattern.

   378→## Common Pitfalls
   379→
   380→### Pitfall 1: ToolUniverse Error Detection Gap
   381→**What goes wrong:** Retry and circuit breaker fire only on Python exceptions, but ToolUniverse SDK returns `{"error": "..."}` dicts for all HTTP errors including 502/503. The existing `_call_tool()` already returns `{}` on any exception — this means ALL failures are silently swallowed as empty results.
   382→**Why it happens:** `umls_tool.py:97` wraps `requests.exceptions.RequestException` and returns an error dict. The ToolUniverse `_run_async` dispatcher may add another layer of try/except.
   383→**How to avoid:** The fix requires a two-step approach: (1) change `_call_tool` to return the raw dict (not `{}`), and (2) add error-dict inspection logic that raises `ToolUniverseUnavailableError` for transient HTTP errors before tenacity/pybreaker see the result.
   384→**Warning signs:** If circuit breaker never trips despite obvious API failures, or if retry count is always 0.
   385→
   386→### Pitfall 2: MLflow Trace ID Lost in finally Block
   387→**What goes wrong:** `mlflow.get_active_trace_id()` returns `None` in the `finally` block because the span context has already been cleaned up.
   388→**Why it happens:** If `__exit__` of the `with` block runs before `finally`, the ContextVar holding the trace ID is cleared.
   389→**How to avoid:** Capture `trace_id = mlflow.get_active_trace_id()` IMMEDIATELY after entering the `with` block (before `await graph.ainvoke()`), store it in a local variable, and use that stored value in `finally`. The local variable persists regardless of ContextVar state.
   390→**Warning signs:** `trace_id` is `None` in the finally log message.
   391→
   392→### Pitfall 3: Relative Path for LOCAL_UPLOAD_DIR Causes Cross-Service Mismatch
   393→**What goes wrong:** `gcs.py` defaults to `"uploads/protocols"` but `pdf_parser.py` defaults to `"./uploads"` — these resolve to different directories inside the container, creating a path mismatch where `gcs.py` writes to `/app/uploads/protocols` but `pdf_parser.py` reads from `/app/uploads`.
   394→**Why it happens:** Each service independently defined the default. The env var unifies them, but only if BOTH services receive the same `LOCAL_UPLOAD_DIR` value.
   395→**How to avoid:** Both `api` service and `protocol-processor-service` (if run in the same container) must have `LOCAL_UPLOAD_DIR=/app/uploads` in their environment. Confirm the `local://` URI format: `gcs.py` generates `local://protocols/{blob_id}/{filename}` and `pdf_parser.py` reads at `LOCAL_UPLOAD_DIR + "/" + blob_path` where `blob_path = file_uri[len("local://"):]` = `protocols/{blob_id}/{filename}`. So the full read path would be `/app/uploads/protocols/{blob_id}/{filename}`. The bind mount target must match this.
   396→**Warning signs:** `FileNotFoundError: Local PDF not found at ...` in pipeline logs after container restart.
   397→
   398→### Pitfall 4: pybreaker fail_max is CONSECUTIVE Failures, not Total
   399→**What goes wrong:** Breaker trips after 3 failures (the existing `_FAIL_MAX = 3` in resilience.py), not 10 as specified for `tu_breaker`.
   400→**Why it happens:** The existing `_FAIL_MAX = 3` constant is shared by all breakers in `resilience.py`. The new `tu_breaker` needs its own `fail_max=10`.
   401→**How to avoid:** Create a NEW `tu_breaker = CircuitBreaker(fail_max=10, reset_timeout=60, name="tooluniverse", listeners=[_mlflow_listener])` in `resilience.py`. Do NOT reuse `umls_breaker` — that was the legacy UMLS MCP breaker.
   402→**Warning signs:** Circuit opens after 3 failures instead of 10.
   403→
   404→### Pitfall 5: Docker Bind Mount Host Path Must Exist
   405→**What goes wrong:** `docker compose up` fails with permission error or silently creates an empty mount if `./data/uploads` doesn't exist on the host.
   406→**Why it happens:** Bind mounts (unlike named volumes) are NOT auto-created by Docker Compose. If the host path doesn't exist, Docker creates it as root, which may cause permission issues.
   407→**How to avoid:** Add `./data/uploads/.gitkeep` to the repository so the directory exists before `docker compose up`. Add `./data/uploads/**` to `.gitignore` (keeping `.gitkeep`).
   408→**Warning signs:** `Permission denied` writing to `/app/uploads` in api service logs.
   409→
   410→### Pitfall 6: React Query Stale Cache Not Served When Circuit Open
   411→**What goes wrong:** When circuit is open and API returns 503, React Query throws, `isError` becomes true, and the combobox shows nothing — not even cached results.
   412→**Why it happens:** React Query does not automatically serve stale data on errors by default — it requires `placeholderData: keepPreviousData` or checking `data` alongside `isError`.
   413→**How to avoid:** In `useTerminologySearch.ts`, use `data ?? []` (already done) which returns stale data from previous successful queries stored in React Query's cache. The 5-minute `staleTime` and 10-minute `gcTime` mean cached results are available for 10 minutes after the last successful fetch. When circuit is open, the UI shows cached results + an "unavailable" indicator.
   414→**Warning signs:** Combobox shows empty when circuit should be serving cached results.

    97→### Pattern 1: MLflow Span Closure with try/finally
    98→
    99→**What:** Capture the `trace_id` immediately after entering the `with mlflow.start_span()` block, then close it explicitly in a `finally` block.
   100→
   101→**Why it works:** `mlflow.get_active_trace_id()` returns the current trace ID. `mlflow.MlflowClient().end_trace(trace_id, status="ERROR")` forcibly closes a trace even if the context manager is abandoned. Per MLflow 3.9.0 docs: "If any of children spans are not ended, they will be ended forcefully with the status `TRACE_STATUS_UNSPECIFIED`."
   102→
   103→**Critical insight from live inspection:** `mlflow.start_span()` is a context manager that auto-sets `ERROR` status when the `with` block raises an exception. However, if `asyncio.run()` is interrupted (process killed, container restart mid-run), the ContextVar carrying the active span reference is destroyed without calling `__exit__`. The `finally` block + explicit `end_trace()` is the defense.
   104→
   105→**When to use:** Any pipeline span that crosses an `asyncio.run()` boundary.
   106→
   107→```python
   108→# Source: Verified against mlflow 3.9.0 installed package
   109→# File: services/protocol-processor-service/src/protocol_processor/trigger.py
   110→

   112→    if not _ensure_mlflow():

   114→

   116→
   117→    mlflow.langchain.autolog()
   118→    trace_id: str | None = None
   119→
   120→    with mlflow.start_span(name="protocol_pipeline", span_type="CHAIN") as span:
   121→        try:
   122→            trace_id = mlflow.get_active_trace_id()  # capture immediately
   123→            span.set_inputs({
   124→                "protocol_id": payload.get("protocol_id", ""),
   125→                "title": payload.get("title", ""),
   126→                "file_uri": payload.get("file_uri", ""),
   127→            })
   128→            result = await graph.ainvoke(initial_state, config)

   176→
   177→**What:** Wrap `_call_tool` with (1) tenacity retry for transient errors and (2) pybreaker circuit breaker for sustained failures.
   178→
   179→**pybreaker async support:** The `@cb` decorator works on `async` coroutines (verified by live test — `asyncio.run(decorated())` returns `'ok'`). The `call_async()` method uses Tornado coroutines and is NOT compatible with asyncio. Use the decorator form.

   198→    wait=wait_exponential(multiplier=1, min=2, max=10),
   199→    before_sleep=before_sleep_log(logger, logging.WARNING),
   200→    reraise=True,  # re-raise so pybreaker sees the final failure

   248→### Pattern 5: SHA-256 Content Deduplication
   249→
   250→**What:** Before saving an uploaded file, compute SHA-256 hash of bytes. Use hash as the blob path key. If a file with that hash already exists, return the existing URI.
   251→
   252→**Why SHA-256:** Standard library (`hashlib`), deterministic, 256-bit collision resistance is appropriate for this use case.
   253→
   254→```python
   255→# Source: Python stdlib hashlib docs
   256→# File: services/api-service/src/api_service/gcs.py
   257→
   258→import hashlib
   259→
   260→def _content_hash(data: bytes) -> str:
   261→    """Compute SHA-256 hex digest of file content."""
   262→    return hashlib.sha256(data).hexdigest()
   263→
   264→def local_save_file_deduplicated(data: bytes, original_filename: str) -> str:
   265→    """Save with content-hash-based deduplication. Returns blob_path."""
   266→    content_hash = _content_hash(data)
   267→    # Use hash as directory to avoid collisions with filename variants
   268→    blob_path = f"{content_hash}/{original_filename}"
   269→    file_path = _LOCAL_UPLOAD_DIR / blob_path
   270→
   271→    if file_path.exists():
   272→        logger.info("Dedup: file already exists at %s (SHA-256: %s)", file_path, content_hash[:8])
   273→        return blob_path
   274→
   275→    file_path.parent.mkdir(parents=True, exist_ok=True)
   276→    file_path.write_bytes(data)
   277→    return blob_path
   278→```

   308→### Pattern 7: Sentence-Length Query Extraction (Claude's Discretion)
   309→
   310→**Decision context:** The user wants "Patient must have confirmed diabetes mellitus type 2" → extract "diabetes mellitus type 2" before sending to ToolUniverse. No heavy NLP library required — a simple heuristic regex approach is appropriate.
   311→
   312→**Recommendation:** Use a lightweight regex-based heuristic in `_call_tool` before dispatching:
   313→
   314→```python
   315→import re
   316→
   317→# Threshold: queries over 40 chars AND containing 4+ words are "sentence-like"
   318→_SENTENCE_WORD_THRESHOLD = 4
   319→_SENTENCE_CHAR_THRESHOLD = 40
   320→
   321→# Clause-starting words to strip from beginning
   322→_PREAMBLE_PATTERN = re.compile(
   323→    r'^(?:patient(?:s)?\s+(?:must|should|may|with|who|have|has|had|are|is)\s+'
   324→    r'|(?:has|have|had|is|are|must|should|may)\s+(?:a|an|the|confirmed|known|documented|active|history\s+of)\s+'
   325→    r'|(?:history\s+of|presence\s+of|absence\s+of|diagnosis\s+of)\s+)',
   326→    re.IGNORECASE,
   327→)
   328→
   329→def _extract_term_from_sentence(query: str) -> str:
   330→    """Extract searchable medical term from a sentence-length query.
   331→
   332→    If the query looks like a natural language criterion sentence,
   333→    strip preamble phrases and return the core medical term.
   334→    Returns the original query if it doesn't look sentence-like.
   335→    """
   336→    stripped = query.strip()
   337→    word_count = len(stripped.split())
   338→
   339→    if word_count < _SENTENCE_WORD_THRESHOLD or len(stripped) < _SENTENCE_CHAR_THRESHOLD:
   340→        return stripped  # Short query — pass through as-is
   341→
   342→    # Try stripping known preamble patterns
   343→    cleaned = _PREAMBLE_PATTERN.sub("", stripped).strip()
   344→
   345→    # If stripping removed something useful, use the cleaned version
   346→    if cleaned and cleaned != stripped and len(cleaned) >= 3:
   347→        logger.debug("Extracted term '%s' from sentence '%s'", cleaned, stripped[:60])
   348→        return cleaned
   349→
   350→    # Fallback: take last N words (the term usually appears at the end)
   351→    # e.g. "Patient must have confirmed diabetes mellitus type 2" → "diabetes mellitus type 2"
   352→    words = stripped.split()
   353→    # Take the last 4 words as the likely medical term
   354→    return " ".join(words[-min(4, len(words)):])
   355→```
   356→
   357→**Confidence:** MEDIUM — this is a heuristic and will miss edge cases. The user acknowledged this is Claude's discretion. Given the existing MedGemma entity decomposer (`entity_decomposer.py`) that handles medical term extraction from full criteria, this simpler approach is appropriate for query pre-processing.

   359→### Anti-Patterns to Avoid
   360→
   361→- **Putting retry OUTSIDE circuit breaker:** `@retry(outer) @tu_breaker(inner)` means each retry attempt opens/closes the breaker independently. Instead, retry inside the breaker — the breaker sees the final outcome of the retry sequence.
   362→- **Using `pybreaker.call_async()`:** This is Tornado-specific (uses `gen.coroutine`), not asyncio. Use `@tu_breaker` decorator on an `async def` function instead (verified working).
   363→- **Adding `try/finally` OUTSIDE the `with mlflow.start_span():` block:** The span object is only accessible inside the `with` block. The `finally` must be INSIDE the `with` block.
   364→- **Using `raise_for_status()` to detect ToolUniverse errors:** ToolUniverse SDK catches HTTPError internally and returns error dicts. The `raise_for_status()` call in `umls_tool.py:83` is caught at `umls_tool.py:97`. The caller (`_call_tool`) receives `{"error": "Request failed: ..."}` — not an exception.
   365→- **SHA-256 filename collision:** Don't use `hash + original_filename` as the sole path — two different files with the same name but different content would collide. Use `{content_hash}/{original_filename}` so the hash is the directory.

   369→| Problem | Don't Build | Use Instead | Why |

   378→## Common Pitfalls
   379→
   380→### Pitfall 1: ToolUniverse Error Detection Gap
   381→**What goes wrong:** Retry and circuit breaker fire only on Python exceptions, but ToolUniverse SDK returns `{"error": "..."}` dicts for all HTTP errors including 502/503. The existing `_call_tool()` already returns `{}` on any exception — this means ALL failures are silently swallowed as empty results.
   382→**Why it happens:** `umls_tool.py:97` wraps `requests.exceptions.RequestException` and returns an error dict. The ToolUniverse `_run_async` dispatcher may add another layer of try/except.
   383→**How to avoid:** The fix requires a two-step approach: (1) change `_call_tool` to return the raw dict (not `{}`), and (2) add error-dict inspection logic that raises `ToolUniverseUnavailableError` for transient HTTP errors before tenacity/pybreaker see the result.
   384→**Warning signs:** If circuit breaker never trips despite obvious API failures, or if retry count is always 0.
   385→
   386→### Pitfall 2: MLflow Trace ID Lost in finally Block
   387→**What goes wrong:** `mlflow.get_active_trace_id()` returns `None` in the `finally` block because the span context has already been cleaned up.
   388→**Why it happens:** If `__exit__` of the `with` block runs before `finally`, the ContextVar holding the trace ID is cleared.
   389→**How to avoid:** Capture `trace_id = mlflow.get_active_trace_id()` IMMEDIATELY after entering the `with` block (before `await graph.ainvoke()`), store it in a local variable, and use that stored value in `finally`. The local variable persists regardless of ContextVar state.
   390→**Warning signs:** `trace_id` is `None` in the finally log message.
   391→
   392→### Pitfall 3: Relative Path for LOCAL_UPLOAD_DIR Causes Cross-Service Mismatch
   393→**What goes wrong:** `gcs.py` defaults to `"uploads/protocols"` but `pdf_parser.py` defaults to `"./uploads"` — these resolve to different directories inside the container, creating a path mismatch where `gcs.py` writes to `/app/uploads/protocols` but `pdf_parser.py` reads from `/app/uploads`.
   394→**Why it happens:** Each service independently defined the default. The env var unifies them, but only if BOTH services receive the same `LOCAL_UPLOAD_DIR` value.
   395→**How to avoid:** Both `api` service and `protocol-processor-service` (if run in the same container) must have `LOCAL_UPLOAD_DIR=/app/uploads` in their environment. Confirm the `local://` URI format: `gcs.py` generates `local://protocols/{blob_id}/{filename}` and `pdf_parser.py` reads at `LOCAL_UPLOAD_DIR + "/" + blob_path` where `blob_path = file_uri[len("local://"):]` = `protocols/{blob_id}/{filename}`. So the full read path would be `/app/uploads/protocols/{blob_id}/{filename}`. The bind mount target must match this.
   396→**Warning signs:** `FileNotFoundError: Local PDF not found at ...` in pipeline logs after container restart.
   397→
   398→### Pitfall 4: pybreaker fail_max is CONSECUTIVE Failures, not Total
   399→**What goes wrong:** Breaker trips after 3 failures (the existing `_FAIL_MAX = 3` in resilience.py), not 10 as specified for `tu_breaker`.
   400→**Why it happens:** The existing `_FAIL_MAX = 3` constant is shared by all breakers in `resilience.py`. The new `tu_breaker` needs its own `fail_max=10`.
   401→**How to avoid:** Create a NEW `tu_breaker = CircuitBreaker(fail_max=10, reset_timeout=60, name="tooluniverse", listeners=[_mlflow_listener])` in `resilience.py`. Do NOT reuse `umls_breaker` — that was the legacy UMLS MCP breaker.
   402→**Warning signs:** Circuit opens after 3 failures instead of 10.
   403→
   404→### Pitfall 5: Docker Bind Mount Host Path Must Exist
   405→**What goes wrong:** `docker compose up` fails with permission error or silently creates an empty mount if `./data/uploads` doesn't exist on the host.
   406→**Why it happens:** Bind mounts (unlike named volumes) are NOT auto-created by Docker Compose. If the host path doesn't exist, Docker creates it as root, which may cause permission issues.
   407→**How to avoid:** Add `./data/uploads/.gitkeep` to the repository so the directory exists before `docker compose up`. Add `./data/uploads/**` to `.gitignore` (keeping `.gitkeep`).
   408→**Warning signs:** `Permission denied` writing to `/app/uploads` in api service logs.
   409→
   410→### Pitfall 6: React Query Stale Cache Not Served When Circuit Open
   411→**What goes wrong:** When circuit is open and API returns 503, React Query throws, `isError` becomes true, and the combobox shows nothing — not even cached results.
   412→**Why it happens:** React Query does not automatically serve stale data on errors by default — it requires `placeholderData: keepPreviousData` or checking `data` alongside `isError`.
   413→**How to avoid:** In `useTerminologySearch.ts`, use `data ?? []` (already done) which returns stale data from previous successful queries stored in React Query's cache. The 5-minute `staleTime` and 10-minute `gcTime` mean cached results are available for 10 minutes after the last successful fetch. When circuit is open, the UI shows cached results + an "unavailable" indicator.
   414→**Warning signs:** Combobox shows empty when circuit should be serving cached results.
