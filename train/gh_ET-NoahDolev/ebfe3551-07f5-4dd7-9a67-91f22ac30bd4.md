   113→
   114→**What:** Convert ground_node's sequential `for` loop to process entities in parallel, using a semaphore to cap concurrency at 4.
   115→
   116→**When to use:** When the unit of work (entity grounding) is I/O-bound (ToolUniverse HTTP + Vertex AI HTTP) and independent between units.
   117→
   118→**Current sequential pattern (in ground.py lines 302-387):**
   119→```python

   122→    result = await _ground_entity_with_retry(entity, router, criterion_text)
   123→```
   124→
   125→**New parallel pattern:**
   126→```python
   127→import asyncio
   128→
   129→_GROUNDING_SEMAPHORE = asyncio.Semaphore(4)  # module-level, created once
   130→
   131→async def _ground_entity_parallel(entity, router, criterion_text, entity_num, total):
   132→    """Wrapper that acquires semaphore, times execution, grounds entity."""
   133→    import time
   134→    async with _GROUNDING_SEMAPHORE:
   135→        start = time.monotonic()
   136→        logger.info(
   137→            "Grounding entity %d/%d: '%s' (type=%s)",
   138→            entity_num, total, entity.get("text", "")[:50], entity.get("entity_type", "")
   139→        )
   140→        try:
   141→            result = await _ground_entity_with_retry(entity, router, criterion_text)
   142→            elapsed = time.monotonic() - start
   143→            logger.info(
   144→                "Entity '%s' grounded in %.1fs: code=%s, conf=%.2f",
   145→                entity.get("text", "")[:50], elapsed, result.selected_code, result.confidence
   146→            )
   147→            return result, None  # (result, error)
   148→        except Exception as e:
   149→            elapsed = time.monotonic() - start
   150→            logger.error(
   151→                "Entity '%s' failed in %.1fs: %s",
   152→                entity.get("text", "")[:50], elapsed, e
   153→            )
   154→            return None, str(e)  # (result, error)
   155→

   157→tasks = [
   158→    _ground_entity_parallel(entity, router, criterion_text, idx, len(entity_items))
   159→    for idx, entity in enumerate(entity_items, 1)
   160→    ...

   162→outcomes = await asyncio.gather(*tasks, return_exceptions=False)  # errors handled in wrapper

   202→### Pattern 3: MLflow Orphan Trace Cleanup on Startup
   203→
   204→**What:** On service start (trigger.py is imported and the graph is first constructed), find IN_PROGRESS MLflow traces older than 1 hour and force-close them as ERROR.
   205→
   206→**Placement recommendation (Claude's Discretion):** Place in `trigger.py` as a module-level call in an `_cleanup_orphan_traces()` function invoked when the module is first imported. This runs exactly once per process start without requiring Docker entrypoint changes.
   207→
   208→```python
   209→def _cleanup_orphan_traces() -> None:
   210→    """Find IN_PROGRESS MLflow traces older than 1 hour and close as ERROR.
   211→
   212→    Runs once at module import (service startup). Idempotent — safe to call
   213→    multiple times. Only closes traces older than 1 hour to avoid closing
   214→    currently-running pipelines.
   215→    """
   216→    import time
   217→    tracking_uri = os.getenv("MLFLOW_TRACKING_URI")
   218→    if not tracking_uri:
   219→        return
   220→    try:
   221→        import mlflow
   222→        client = mlflow.MlflowClient()
   223→        cutoff_ms = int((time.time() - 3600) * 1000)  # 1 hour ago in milliseconds
   224→        # MLflow search_traces with filter for IN_PROGRESS status
   225→        # Note: MLflow 3.x search_traces API — verify exact filter syntax
   226→        traces = client.search_traces(
   227→            filter_string="status = 'IN_PROGRESS'",
   228→            max_results=50,
   229→        )
   230→        closed = 0
   231→        for trace in traces:
   232→            if trace.info.timestamp_ms < cutoff_ms:
   233→                try:
   234→                    client.end_trace(trace.info.trace_id, status="ERROR")
   235→                    closed += 1
   236→                except Exception:
   237→                    pass  # Trace may have already closed
   238→        if closed:
   239→            logger.info("Startup orphan cleanup: closed %d stale IN_PROGRESS traces", closed)
   240→    except Exception:
   241→        logger.debug("Orphan trace cleanup failed (non-fatal)", exc_info=True)
   242→
   243→# Call at module level:
   244→_cleanup_orphan_traces()
   245→```
   246→
   247→**IMPORTANT:** Verify the MLflow 3.x `search_traces` API filter syntax before implementing. The filter string `"status = 'IN_PROGRESS'"` is a guess based on MLflow SQL-like filter syntax. Check MLflow 3.8+ docs for correct syntax.

   267→### Anti-Patterns to Avoid
   268→
   269→- **Creating asyncio.Semaphore at module level:** Semaphore belongs to the event loop that creates it. `asyncio.run()` creates a NEW event loop each call — a module-level Semaphore from a previous event loop will raise "got Future attached to a different loop".    270→- **Using `gather(return_exceptions=True)` without checking results:** If `return_exceptions=True`, exceptions appear as values in the result list — easy to miss. The tuple pattern `(result, error)` from the wrapper is cleaner.
   271→- **Modifying `_PREAMBLE_PATTERN` or `_extract_term_from_sentence` logic** for the unit tests: The tests must verify existing behavior, not new behavior. Read the existing implementation carefully before writing tests.

   304→### Pitfall 3: asyncio.Semaphore event loop binding
   305→
   306→**What goes wrong:** `asyncio.Semaphore(4)` created outside an event loop (e.g., at module import time) will be bound to a specific event loop. When `asyncio.run()` is called (which creates a NEW event loop), using the old semaphore raises `RuntimeError: got Future <Future pending> attached to a different loop`.
   307→
   308→**Why it happens:** Python's asyncio primitives (Semaphore, Lock, Event) are bound to the running event loop at creation time. `asyncio.run()` creates a fresh event loop each invocation.
   309→
   310→**How to avoid:** Create the Semaphore inside the `async def ground_node()` function, not at module level. This ensures each pipeline run gets a fresh semaphore in the correct event loop.
   311→
   312→**Warning signs:** `RuntimeError: got Future attached to a different loop` in logs during grounding.
   313→
   314→### Pitfall 4: MLflow search_traces API syntax
   315→
   316→**What goes wrong:** MLflow's `client.search_traces()` or equivalent API for finding IN_PROGRESS traces may have different filter syntax or method names in MLflow 3.8+. Using incorrect syntax silently returns empty results (no orphans cleaned up) or raises an exception.
   317→
   318→**Why it happens:** MLflow's Python client API has evolved across versions. The `search_traces` method and its filter syntax need to be verified against the actual installed version (mlflow>=3.8.1).
   319→
   320→**How to avoid:** The orphan cleanup function should be wrapped in a broad `try/except Exception` so that failures are logged but do not crash the service. Verify the actual API by checking MLflow 3.x documentation or the installed package's source.
   321→
   322→**Warning signs:** Service fails to start; or startup log never shows "closed N stale IN_PROGRESS traces" even when orphans exist.
