## Overview

This deprecation warning occurs for swigvarlink and related types like SwigPyPacked and SwigPyObject, and it appears when upgrading certain packages that use SWIG-generated bindings.

## Root Cause

The issue stems from how PyType_Spec are filled for these types in pyrun.swg, where SWIG_name is defined after the code fragments that need it. The warnings appear because SWIG is not setting the module attribute on its builtin types.

## Solution - SWIG 4.4+ Fix

In May 2025, SWIG fixed this issue by moving the SwigPyObject, SwigPyPacked, and SwigVarLink support Python types to the SWIG runtime module, and also addressed the DeprecationWarning when using 'python -Walways' or certain type operations. # Python 3.13 SQLite ResourceWarning: Cause and Fix

## Cause

Python 3.13 introduced a new warning mechanism for SQLite connections. According to the article: "A ResourceWarning is now emitted if a Connection object is not closed explicitly."

This change was implemented to catch resource leaks that might not be obvious during development but can cause problems in production applications.

## The Problem

Leaving SQLite database connections open without explicitly closing them triggers this warning. While this may seem minor in test suites, the article notes it can become critical in running applications—the author previously experienced an "too many open files" error in a Flask app after accumulating unclosed connections.

## The Fix

The solution is straightforward: **explicitly close all SQLite connections** after use.

The article references the recommended Flask pattern for handling this:

# Close the database at the end of each request

# SQLAlchemy Python 3.13 ResourceWarning Fix

## The Problem

Flask-SQLAlchemy tests were failing on Python 3.13.0 with `ResourceWarning: unclosed database` errors in SQLite connections during pytest teardown. The warnings were being caught by pytest's `PytestUnraisableExceptionWarning` handler.

## Root Cause

The issue stems from weakref behavior changes in Python 3.13. During interpreter shutdown, SQLAlchemy's event system attempts to access a weakref dictionary that has already been garbage collected, triggering the resource warning for unclosed database connections.

## The Solution

According to maintainer David Lord's analysis, this is not directly fixable in Flask-SQLAlchemy code itself because: "Connections are created from the SQLAlchemy engine/pool, and returned when the session is closed at the end of the app context... the underlying DBAPI still has open connections during pytest/interpreter shutdown."

**Recommended approach**: Suppress the warning in test configuration by adding this to your pytest configuration:

```
[pytest]
filterwarnings =
    ignore::pytest.PytestUnraisableExceptionWarning
```

A pull request (#1380) was created to add this filter directly to the Flask-SQLAlchemy test suite configuration, acknowledging that the warning occurs during Python's shutdown sequence and cannot be meaningfully addressed in application code.
