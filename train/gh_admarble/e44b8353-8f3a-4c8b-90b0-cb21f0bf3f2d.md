> DEVELOPER

was this best practice and portable?

> AGENT

Good question. Short answer: **yes for this context, with one caveat.** **`|| true` is portable** — it's POSIX-compliant, works in bash/zsh/sh/dash, and is the standard idiom for "don't care about exit code." **The caveat:** `|| true` masks *all* errors, not just "no matches." If grep fails for a real reason (bad regex, permission denied, file not found), that error is silently swallowed too. The more surgical alternative: ```bash grep pattern file || [[ $? -eq 1 ]] ``` This only swallows exit code 1 (no matches) and lets exit code 2 (real errors) propagate. But it's bash-specific (not POSIX) and adds complexity. **For these SKILL.md templates, `|| true` is the right call because:** - They're instructional patterns for an AI agent, not production scripts - The commands use placeholders like `<issue-number>` — they're never run verbatim - The primary failure mode is "0 matches" which is normal/expected - Simplicity matters more than surgical error handling in templates - `|| echo "0"` for `grep -c` patterns was the right variant (preserves numeric semantics) If these were actual shell scripts in `scripts/`, I'd recommend the `[[ $? -eq 1 ]]` approach or wrapping in a `safe_grep()` helper. But for skill templates, `|| true` is appropriate.
