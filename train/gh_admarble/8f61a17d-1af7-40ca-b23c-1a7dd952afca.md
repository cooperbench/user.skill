> DEVELOPER

whats best practice here?

> AGENT

Strict semver says major bump, but in practice most Node.js projects treat engine drops as a **minor** release when the dropped version is already EOL. Examples: ESLint, Prettier, and most ecosystem tools bumped minors when dropping Node 14/16. **1.20.0** is the right call here. The public API hasn't changed — no user code breaks unless they're on a dead runtime. Want me to run `/release`?

> DEVELOPER

1.20.0 then. Again, this wont hurt any users with an older version of node?

> AGENT

Correct — it won't hurt anyone: - **Users on Node 20+**: `npm update sequant` works fine, they get the new deps - **Users on Node 18**: `npm update sequant` will **skip** 1.20.0 and keep 1.19.0 installed. npm respects the `engines` field and won't install an incompatible version (unless they use `--ignore-engines`) Their existing 1.19.0 install continues working. They just won't get new versions until they upgrade Node. Want me to run the release?
