13	## What It Does
14	
15	My First Commit helps you find the first public GitHub commit for any user. It searches GitHub's public commit index, shows the earliest result first, and includes the next several commits so the timeline feels like a small origin story rather than a single raw link.

17	The app is intentionally small: no accounts, no database, and no server-side storage of searches. Successful searches are saved only in the user's browser as recent-search shortcuts.

58	## Privacy
59	
60	- Usernames entered into the search field are sent to GitHub to retrieve public commit data.
61	- `GITHUB_TOKEN` is used only server-side and is never exposed to the browser.
62	- Recent searches are stored only in the user's browser under `my-first-commit:recent-searches`.
63	- Vercel Analytics records page views and privacy-safe product events; analytics events do not include searched usernames.
64	- The app does not store searches on a server.

66	## Limitations
67	
68	- GitHub commit search can lag behind newly pushed commits, so very recent history may not appear immediately.
69	- Only public commits indexed by GitHub are searchable. Private commits, deleted repositories, and private forks are never included.
70	- Squashed, rebased, rewritten, or force-pushed history can make a user's earliest visible public commit differ from their actual first commit.
71	- Renamed users, changed author emails, bot-authored commits, and missing author metadata can affect which commits GitHub returns for an author search.
72	- GitHub's public search index can miss older commits or return duplicate commit SHAs across forks and mirrored repositories.
73	- Unauthenticated GitHub requests have stricter rate limits. A server-side `GITHUB_TOKEN` improves reliability but does not make private data searchable.

## Root cause found

The failed-deployment emails are **not** from your PRs — every PR preview builds fine. They're from a second, hidden branch that the **Entire CLI** pushes to your GitHub remote on every checkpoint:

```
refs/heads/entire/checkpoints/v1   →   commits titled "Checkpoint: <sha>"
```

Vercel's Git integration deploys **every branch it sees a push on**. So each time Entire saves a checkpoint and pushes it to `origin`, Vercel spins up a preview build for that checkpoint commit, it fails, and you get an email.

### Evidence

Pairing each Preview deployment with its commit and status:

| Deploy status | Commit |
|---|---|
| ✅ success | `chore(repo): polish spec…` (PR #61) |
| ❌ **failure** | `Checkpoint: e9ec8d08…` |
| ✅ success | `refactor(app): tidy search internals` (PR #60) |
| ❌ **failure** | `Checkpoint: ae596b06…` |
| ✅ success | `chore(tooling): add Prettier…` (PR #59) |
| ❌ **failure** | `Checkpoint: 109d83cd…` |
| ✅ success | `fix(app): bound commit search cache` |
| ✅ success | `fix(app): harden search and release flow` |

Every real commit succeeds; every `Checkpoint:` commit fails. The failures begin exactly at **PR #57 "add Entire CLI hook configuration"** — i.e., the moment Entire started pushing that branch. The branch genuinely exists on origin (`git ls-remote` confirms `refs/heads/entire/checkpoints/v1`), and `.entire/settings.json` has `"enabled": true`.

*(I didn't pull the build logs — that needs `npx vercel inspect … --logs` with Vercel auth — but the cause is independent of why each checkpoint build errors: you simply don't want ephemeral checkpoint snapshots deployed at all.)*

## How to fix it

Three options, depending on whether you want to keep checkpoints backed up to GitHub:

1. **Tell Vercel to skip that branch (in-repo, recommended).** Add a `vercel.json`:
   ```json
   {
     "git": { "deploymentEnabled": { "entire/checkpoints/v1": false } }
   }
   ```
   Reviewable, versioned, no dashboard access needed. Keeps checkpoints on GitHub; just stops the deploys. Downside: exact branch name (would need a bump if Entire ever goes to `v2`).

2. **Vercel dashboard → Ignored Build Step** (most future-proof). Set the command to skip anything under `entire/`:
   ```bash
   case "$VERCEL_GIT_COMMIT_REF" in entire/*) exit 0 ;; *) exit 1 ;; esac
   ```
   Globs the whole `entire/*` namespace, but lives in Vercel settings, not the repo.

3. **Stop Entire pushing to origin at all** — keeps Vercel untouched but loses the off-site checkpoint backup. This is an Entire-config change, not a Vercel one.

My recommendation is **#1** (clean, in-repo, verifiable on the next checkpoint push), optionally plus **#2** for future-proofing.
